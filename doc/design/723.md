### The decision: an edit to the recipe is not a `fix`

`fix` is documented as *"The command that fixes it, one per line, a `lingtai env set …` a person can run as written"* (`doctor.ts:177-180`). Most remedies in this list are not commands. They are edits to the recipe file at `recipePath(project)`:

- `agentRemedy`: *"Name runtime.agent: … in ${recipePath(project)}"* (`:2020-2025`).
- `limitsRow`'s *"The lever is runtime.agent … or write runtime.limits.turns: unbounded"* (`:2180-2184`).
- `codexRoleRow`'s `codex_text` and `triage.tools` remedies (`:2489-2493`).
- The *"or name a runtime this machine has at …"* half of `dispatchedAuthRow` (`:2465-2468`).

**None of these gets a `fix`.** The remedy stays in `detail`, on line 2. The title says what is wrong, not what to edit, and the title may not contain a path. The ticket's *Watch out* row rules out a `fix` that is prose pretending to be a command.

**No signed-in row gets a `fix` either.** Nothing in the codebase records a runtime's login command: there is no `loginCommand` or similar on `RuntimeCapabilities`, and `codex login` appears nowhere in `src`. Claude Code's sign-in is interactive (`claude`, then `/login`), so it is not one line. If the agent writes a sign-in command from memory, that is exactly the guessed fix the *Watch out* row forbids. Title only, for example `"<project>'s runtime, claude-code, is signed out"`.

Only two checks get a `fix`:

- **`env: <project>`** when `agentEnv.missing.length > 0` (`:2580`): one `lingtai env set ${project} ${name}` per name in `agentEnv.missing`. That is the form `extensionOutcome` uses (`:2380`) and the usage `commands.ts:242` documents (`lingtai env set <project> KEY`). The detail's per-name `←` list moves to line 2. The catch branch (`:2655`) gets a title only, because its message may be a `ProductionValueError`.
- **`base: <project>`**: `lingtai add ${slug} --base ${baseOf(resolved.recipe)}`, built in doctor from the same two values `baseDivergence` splices into its sentence (`packages/recipe/src/resolve.ts:339`). Give it only when `project.owner !== null` (`:2697-2702`). Do not parse it out of the returned sentence, and do not edit `baseDivergence`: its text is the refusal `runOnce` and `add` share. The title says the rules and the merge target are on different branches. It cannot carry the slug, because the slug contains `/`.

**`steps: end ran on what landed`** gets the fix the ticket names: one `lingtai end replay ${f.project} --issue ${f.issue}` per entry in `found` (usage at `cli.ts:656`), with duplicate lines removed. Line 1 of the detail becomes the count. The `say(titles, …)` list goes to line 2, and so does the sentence about issues never being closed.

### Smaller decisions

- **`triage: <project> limits`** is always `warn` on that route (`:2624-2630`). Its remedy is a choice in the recipe (`triage.tools`), so it gets a title only. Example: `"triage on the Codex CLI ignores turn and dollar limits for <project>"`. Check that it stays under 60 characters with a long project name. Shorten the fixed words rather than truncating the name.
- **`recipeRow`** has two fail branches: the wrong-agent branch and the unresolved branch, `f.problem` (`:2066`). Give each its own title. Line 1 of the wrong-agent detail should end at the refusal sentence, with `agentRemedy` on the next line (it is currently joined by `. `, at `:2043-2044`).
- **`codexRoleRow`** has three fails: no config, `createRuntime` throwing, and the model differing (`:2484`, `:2494`). Give each its own title. The error message goes to line 2.
- **Duplicate fixes.** `env: <project>` and `env: <project> extensions` may both name the same variable. `toFix` merges only fix strings that are identical. A partial overlap is drawn twice. That is accepted here and needs no merging.
- **Restart.** `formatFailures` prints ``${r.name}: ${r.detail}`` (`restart.ts:1495`). The line-1 rule is what keeps that output readable. Do not touch `restart.ts`.

### Tests

Write each test as in #722: assert `name` unchanged, the title passes `PLAIN`, and `fix` is either exact or `toBeUndefined()`. Make the `undefined` assertion for every no-fix row above, because that assertion is how this decision is pinned down. For `end replay`, use two items from two different projects, so the test catches a fix built from the wrong field. For `env:`, use two missing names. For `base:`, use one owned project and one `--local` project, and assert that only the first has a fix.

Then update any detail assertions in `doctor.test.ts` and `apps/cli/integration/doctor-recipe.test.ts` whose line 1 moved, without loosening them. Run `pnpm typecheck`, `HOME=/nonexistent pnpm test`, and `apps/cli/integration/doctor.test.ts` on its own.
