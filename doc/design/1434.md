## Design note: #1434. The process projection pool keeps idle connections for `KEPT_IDLE_MS`

### Where it goes

There are three edits in `packages/` and one new unit test. None of it is IO, so nothing in `effect-ratchet.baseline.json` moves.

1. **`packages/event-store/src/index.ts:45-56`**: add `KEPT_IDLE_MS` to the existing `export { … } from './queries.ts'` block. The constant stays where it is (`queries.ts:218`), and so does its comment. That comment is the argument for the number: *"`head` took p50 432 ms after 35 s idle, so a pool that drops its connections between two board renders gives the cost back. Minutes, not hours"*. Do not import it through the `./queries` subpath (`package.json:12`). The projector already imports from the root (`choose.ts:22`, `import { closableOnceEffect, … } from '@lingtai/event-store'`), and the ticket asks for the export there.

2. **`packages/projector/src/postgres.ts`**:
   - Add `idleTimeoutMillis?: number` to `PostgresProjectionStoreOptions` (`postgres.ts:219-226`).
   - In `makePostgresProjections` (`postgres.ts:310-315`), spread it into the `pg.Pool` config only when it is defined, the same way `allowExitOnIdle` is spread today. A caller that passes nothing then still builds `{ connectionString, max }` and keeps pg's default. This covers `createPostgresProjectionStore` (`postgres.ts:241`), the one-off stores, and `integration/projection.test.ts:205`.
   - Add a **second, optional parameter** `create: (config: pg.PoolConfig) => pg.Pool = (c) => new pg.Pool(c)` and build the pool through it. This is the injected factory the ticket's `Done when` asks for. It copies `makePostgresPools(create)` (`queries.ts:247`). It is a parameter and not an option field because `PostgresProjectionStoreOptions` is also what `createPostgresProjectionStore` accepts from callers, and a factory is a test seam, not a choice a caller makes. `listenForIdleErrors(pool)` must still run on whatever `create` returns.

3. **`packages/projector/src/choose.ts`**:
   - Add `idleTimeoutMillis?: number` to `ProjectionStoreOptions` (`choose.ts:28-44`) and pass it through in `openProjections` (`choose.ts:62-66`), conditionally, like `max`.
   - **The decision that isn't obvious from the ticket:** move the process store's options out of the inline call at `choose.ts:90` into an exported constant, for example `export const PROCESS_PROJECTIONS: ProjectionStoreOptions = { max: 4, allowExitOnIdle: true, idleTimeoutMillis: KEPT_IDLE_MS }`, and pass it as `openProjections(PROCESS_PROJECTIONS)`.

     Why the constant is needed: `process_` is a module-scope `closableOnceEffect`, and the comment there says *"Built at import and running nothing"* (`choose.ts:84-93`). A test can only see what it asks for by running it. Running it goes through `chosenStore()` (`choose.ts:59`), and under `HOME=/nonexistent` that resolves to whatever the test environment picks, not to a Postgres pool whose config can be inspected. The exported constant is what lets a unit test check that the process store asks for `KEPT_IDLE_MS` with `allowExitOnIdle` still on.
   - Extend the comment above `process_` (`choose.ts:82-88`) with one clause saying why the idle time is `KEPT_IDLE_MS`. Reference #1434 and `queries.ts`'s comment; don't repeat its numbers. The existing *"`allowExitOnIdle` as well as the explicit close, for a script that never closes anything"* is now the reason the longer idle time is safe, so keep it next to the new clause.

### The test

Add one new file, `packages/projector/unit/process-pool-idle.test.ts`. It must not import `pg` itself: `on-postgres.test.ts` only scans `integration/` files (`on-postgres.test.ts:24-35`), but a unit file that reaches a server is still wrong. It needs three cases:

- `makePostgresProjections({ url: 'postgres://x/y', idleTimeoutMillis: 300_000 }, create)` hands `create` a config with `idleTimeoutMillis: 300_000`. Building the pool opens no connection, and the fake that `create` returns only needs `on` (for `listenForIdleErrors`).
- Without the option, the config has no `idleTimeoutMillis` key. This pins the ticket's point that only the process store changes.
- `PROCESS_PROJECTIONS` equals `{ max: 4, allowExitOnIdle: true, idleTimeoutMillis: KEPT_IDLE_MS }`. Import `KEPT_IDLE_MS` from `@lingtai/event-store` so the test also proves the root export exists.

The pass-through from `openProjections` to `makePostgresProjections` is three lines with no unit-level witness unless `chosenStore` is stubbed. Don't stub it. The `allowExitOnIdle` line beside it has gone untested the same way since #793.

### What stands in for the production check

The Jaeger check, where a home render after a 40 s pause has no `db.acquire` over 100 ms, happens after the merge and is done by a person. Before the merge, the third test case above is the evidence: the process store asks for 5 minutes. Nothing in `pnpm test:integration` adds to that, so there is no reason to run it.

### Not touched

- The one-off `max: 1` stores. They go through `withStoreFrom`'s `open(options)` with their caller's options (`choose.ts:106-114`) and pick up no idle time.
- The sqlite branch of `openProjections` (`choose.ts:68-70`), which ignores the new option, as it already ignores `max`.

No ADR is contradicted. #1431 added the constant with no ADR, and this ticket reuses it.

### PR body

Say what the daemon holds: up to 4 projection connections plus the store's own pools, each kept for 5 minutes. That covers the `createDb` pool (`event-store/src/choose.ts:102`) and one shared pool per URL (`queries.ts:247-259`). State `max` for each, read from the code, rather than repeating the ticket's "10".
