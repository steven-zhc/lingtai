## Shape for #967: `@lingtai/setup` and the two lists that have to learn its name

Most of this is a move, as the ticket says. Two unit tests keep a list of workspace packages, though, and each turns red the moment the new package exists. `propose.ts` also exports more than `proposeRecipe`. Those three things are what this note covers.

### The package

- **`packages/setup/package.json` and `tsconfig.json` are copies of `packages/repo`'s.**
  - Copy the `exports` style, the `typecheck` script and the dev dependencies. The tsconfig is `{"extends": "../../tsconfig.base.json", "include": ["src", "unit", "integration", "test"]}`.
  - The runtime dependencies are only what the moved file imports: `smol-toml` and `yaml` (`apps/cli/src/detect-setup.ts:13-14`). It imports no workspace package.
- **`exports: { ".": "./src/index.ts" }`, with `src/index.ts` doing `export * from './detect-setup.ts'`.** Don't point `.` at the file directly: the next child (`recipe-flow.ts`, out of scope here) adds a second module behind the same entry.
- **`smol-toml` leaves `apps/cli/package.json`; `yaml` stays.** `smol-toml`'s only `apps/cli` importer is `detect-setup.ts:13`. `yaml` is still imported by `apps/cli/src/init.ts` and `apps/cli/src/github-auth.ts`.
- **Run `pnpm install` once** so the lockfile and the `node_modules/@lingtai/setup` link exist. It writes `pnpm-lock.yaml`, and that file belongs in the commit.

### The move

- **The test file moves byte for byte:** `apps/cli/unit/detect-setup.test.ts` becomes `packages/setup/unit/detect-setup.test.ts`.
  - Its import is `'../src/detect-setup.ts'` (`:7`), and that relative path resolves the same from the new place.
  - The unit project's glob `{apps,packages}/*/unit/**/*.test.ts?(x)` (`vitest.config.ts:72`) picks it up with nothing added.
  - If you find yourself editing a line in it, the move has gone wrong.
- **Seven `apps/cli` importers change their specifier to `'@lingtai/setup'` and nothing else.** Each keeps `import type` where it has it:
  - `src/add-github.ts:31`, `src/first-project.ts:79`, `src/init.ts:149`, `src/recipe-flow.ts:42`, `src/setup-build.ts:22`
  - `unit/add-github-gh.test.ts:9`, `unit/add.test.ts:5`, `unit/first-project.test.ts:16`, `unit/recipe-flow.test.ts:12`, `unit/recipe-summary.test.ts:10`, `unit/setup-build.test.ts:10`
  - `git grep "detect-setup.ts'" apps` returning nothing is the check.
- **Board:** add `"@lingtai/setup": "workspace:*"` to `apps/board/package.json`, and `'@lingtai/setup'` to `transpilePackages` in `apps/board/next.config.ts:15-22`. Its comment says that list is *"Every workspace package the board reaches. They ship as TypeScript source with no build step … so Turbopack compiles them here."*
  - Nothing on the board imports it yet, so nothing in reach of a pass checks that entry. Only the Next build in `apps/release/integration/build.test.ts` would, and that is the integration half.
  - Add it now anyway, so the next child's first import doesn't find out after the merge.

### Trap 1: the effect ratchet's key list is pinned, not only its numbers

`packages/domain/unit/effect-ratchet.test.ts:202` asserts `Object.keys(baseline).sort()` equals `PACKAGES` (`:24-35`). The comment on it reads *"Pinned here: a baseline that could drop a key would be a way out."* So a `packages/setup` key added only to `effect-ratchet.baseline.json` is red. The package has to go into `PACKAGES` as well.

- Change the test title and the file comment from *"the ten packages"* (`:3`, `:202`) to eleven.
- The numbers:
  - `detect-setup.ts` has 12 `async` functions: lines 38, 41, 105, 142, 218, 296, 346, 379, 482, 609, 702 and 772.
  - It has no `Effect` import, so `run` is 0.
  - Set `"packages/setup": { "async": 12, "run": 0 }` and lower `apps/cli` from 438 to 426. The total stays 1,067.
- The check also fails when a package is *below* its baseline (*"asks for it lowered when below"*, the test at `:206`). So exact numbers are required, not just numbers that aren't higher. If they're off, the red prints the JSON to paste; check that the sum still matches before pasting.
- Leaving `packages/setup` out of the ratchet altogether would lower the total by 12 without converting anything. That is the way out the comment names, so don't do it.
- `packages/recipe` is not in `PACKAGES`, so deleting `propose.ts` moves no number.

### Trap 2: `doc/tamper-watch.md` has to name the package

`packages/actions/unit/tamper-watch.test.ts:112` is *"holds every workspace package the conductor and the CLI load"*. It walks the `workspace:` dependencies from `apps/cli` and asserts each one is held by the watch list it reads out of `doc/tamper-watch.md`. Once `apps/cli` depends on `@lingtai/setup`, that test is red until `- "packages/setup/**"` is in the list there (`doc/tamper-watch.md:17-35`, beside `packages/repo/**`).

This is a doc edit inside a code ticket, and it is required. CLAUDE.md says that test *"reads the list from that file"*.

### Deleting `propose.ts`: all of its exports go, not just `proposeRecipe`

`packages/recipe/src/propose.ts` exports these names:

- `RepositoryReader` (`:27`), `FoundScript` (`:32`), `Found` (`:44`), `Proposal` (`:58`), `ProposeOptions` (`:64`)
- `PROPOSED_KINDS` (`:74`), `PROPOSED_EXCLUDE` (`:80`), `proposeRecipe` (`:125`), `envNames` (`:359`)

`git grep -nw` for each name finds code use only in that file and `packages/recipe/unit/propose.test.ts`. Delete the file, that test, and `export * from './propose.ts'` (`packages/recipe/src/index.ts:6`).

The many `Proposal` hits on the board (`apps/board/unit/history.test.ts:2` and others) are a different type, `@lingtai/domain`'s. The name only matches, so they are untouched.

After the deletion, `@lingtai/recipe` may no longer use `@lingtai/env`, which `propose.ts:18` imports for `PREFIX`. Check with `git grep "@lingtai/env" packages/recipe/src`. If nothing is left, leave the dependency anyway: removing it changes what the tamper walk above reaches, and the ticket doesn't ask for it.
