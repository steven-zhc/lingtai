# The conflict rule: design note for #1273

**Where the rule goes.** It is a third arm in the reply ternary at `packages/conductor/src/run-attempt.ts:1823-1844`. It comes after `land-again` and the rerun, and before `yield* replyFor(...)`. Keep it a `{ _tag: 'Selected', candidate: 'fix-lines', why }`, which is the shape the comment at `:1811-1812` asks for: *"A `Selected` reply, because `routeMove` replays this route and refuses a `Selected` decision paired with anything else."* Everything below that point already does the rest, and none of it changes:

- `decideRoute` / `routeNext` turn the candidate's `next` into the `FixRefusal{ to: 'implement', conflict }` that `respond.ts:709-712` built.
- The block at `run-attempt.ts:1869-1879` then merges `offer.proposal.baseSha` through `mergeForConflict`.

So the change in the conductor is a selection and a sentence. The nested ternary is already two arms deep. Pulling the three rule arms into one small pure function is a fair tidy-up if you want it, for example `ruleReply(offer, …): JudgeReply | null`, with `replyFor` called only on `null`. Don't change what the first two arms produce.

**The condition, exactly:**
- `offer.proposal._tag === 'MergeConflict'`
- `offer.proposal.baseSha !== null`
- `offer.available` contains `fix-lines` with `next._tag === 'FixRefusal'` and `next.conflict !== undefined`

Read the round number K from that `next.conflict`. Read the bound from `policy.conflictResolutions`, the same field `respond.ts:707` compares against; `policy` is already in scope at `:1842`. Don't recompute either one.

When the rounds are spent, `fix-lines` is in `unavailable` (`respond.ts:706-707`), the rule doesn't match, and the attempt falls through to `replyFor`. In practice `replyFor` returns `NotAsked` without calling the judge, because `if (offer.available.length < 2) return { _tag: 'NotAsked' }` (`proposed-route.ts:172`). The ticket wants *"spent reaches a person without asking the judge"*, so a test must pin that the judge stub is never called. Don't trust the fall-through to do it silently.

**`paths` can be null.** `proposal.ts:370` reads `paths: conflict?.paths ?? null`. The `why` therefore needs a wording for null. Use *"a merge conflict with main is the agent's to resolve (0108 §8), round K of N"*, and when paths are present, *"a merge conflict in a.ts, b.ts is …"*. A null `paths` is not a reason to withhold the rule; only `baseSha` is.

**Existing tests.** `unit/a-conflict-round-starts-merged.test.ts:122` stubs a judge answering `implement` for every conflict case. Those tests still pass, because the rule picks the same route. But they no longer exercise the judge, so don't read them as proof of the new behaviour.

The case at `:194`, *"goes to a person when the lane named no base sha, without asking the port"*, is the null-`baseSha` edge. Under the rule it still reaches the judge (which answers `implement`) and then fails at `run-attempt.ts:1874-1875`. Leave it as it is. The ticket's *"`baseSha` null does not take the rule"* is a new assertion: the judge **is** called there.

Put the three new tests beside these and reuse that file's harness. A judge stub that records its calls and throws if asked is the cheapest way to prove *"without calling the judge"*.

**The ADR is edited in place.** 0108 is in `doc/decisions/` (it is numbered 0100 or later), and the rule there is one ADR per topic: *"A decision that changes is an edit to its topic's ADR, not a new file beside it."* So §8 (`0108:187-188`) and §12's `conflict` row (`0108:435`) become the ticket's sentences, in the same commit. No superseding file is needed.

Check whether 0108's *Not built yet* list (`0108:586-615`) or any other part of the ADR still mentions `CONFLICT_ROUND_HUNKS` as the conflict bound. If it does, change that line to match. The constant stays where triage and the Waiting card read it (`triage.ts:33`, `wait.ts:788-825`); that is out of scope.

**What settles it after the merge.** On the next conflict there should be:
- a `RouteTaken` whose `why` starts with *"a merge conflict"*, with `reply._tag: 'Selected'` and `candidate: 'fix-lines'`;
- no judge run or spend between the lane's `conflict` refusal and that route;
- then a `proposed` visit whose `head` is the `--no-commit` merge.

Every check here is unit-level. Nothing needs `pnpm test:integration`.
