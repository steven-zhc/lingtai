# #1290: design note

## Where the figures come from

Almost every number on the card already exists on the task page. Two things need deciding: where the step times come from, and how the fix-rounds cell is worded. The rest is layout inside `RunningPanel` (`apps/board/src/app/standing.tsx:263-330`).

### The fix-rounds cell uses the existing `held` sentence

The task page already computes `describeHeld` for the attempt the state names (`apps/board/src/lib/task.ts:2197-2205`). That attempt includes a running one, because `named` is only null when there is no progress. The page hands the result to `Standing` as `held: budget` (`standing.tsx:893`).

Today only the rail draws it, and never while live. `rail.tsx:249-259` says: *"Never where `live` is true … a budget beside it would say the same fact twice."* Passing `budget` into `RunningPanel` is not a second copy of the fact. The rail still hides it while live, and the facts row becomes the one place it is shown.

- Use the sentence exactly as it comes: *0 of 6 rounds · 2 restarts left*, not the mock's *0 of 6 · 2 restarts left*.
- Do not write a second formatter. `describeHeld`'s own doc says: *"One function, so the card and the task page cannot word one hold's budget two ways"* (`apps/board/src/lib/progress.ts:485-487`).
- When `budget` is null, leave the cell out.
- `m.round.of` (`apps/board/src/lib/running.ts:68-75`) said *round n of N* inside the round meter. Drop it from the step cell, because the fix-rounds cell now says it.

### Step times are worked out on the board, from the stream it already reads

`StepProgress` carries no time (`progress.ts:148-160`). `AttemptState` keeps only the step in flight, `step: { step; round; since }` (`packages/domain/src/attempt.ts:195`, set at `:609` from `StepStarted`'s `event.at`).

**Do not add durations to the domain reducer.** That would change the reducer that `stream_snapshots` are versioned on (0124). Every cached snapshot would be voided to buy a label.

`readAttempts` already holds every attempt's full event list as `streams` (`task.ts:1853-1858`). Add a pure function in `apps/board/src/lib/`, say `stepTimesOf(events): Partial<Record<Step, number>>`:

- Pair each `StepStarted` (`d.step`, `event.at`) with the next `StepEnded` whose `d.outcome.step` is the same step (`attempt.ts:669`).
- Keep the **latest completed pair** for each step. After a fix round, an earlier round's review time describes a verdict that has since been replaced.
- Hand the result to `Rail` through a new optional prop, set only where `standing.tsx:1296-1302` draws the live rail on the task page. `Segs` (`rail.tsx:137-165`) prints the time under `slab` when there is one.
- Home cards and every other caller of `Rail` pass nothing and do not change.

Some steps get no time:

- **The step in flight.** The ticket says *each finished step's time*, and the meta line and the step cell already carry it.
- **`claim`.** It gets no step events (#463, `progress.ts:395-397`), so it has no time even though the mock draws one. A step whose log has no pair gets no time; never make one up.

`apps/board/unit/running.test.ts` is the place for unit tests of `stepTimesOf`:

- a rerun step;
- a `StepStarted` with no `StepEnded`;
- `claim`.

### The meta line

For `standing.state === 'running'`, `readout` (`standing.tsx:1176-1186`) currently shows `stateWord` plus the age of `standing.since`. Replace that with three parts:

1. The chip, moved from `standing.tsx:273-281`. It reads `implement · fix round N` during a fix round (the step in a fix round is `implement`, `running.ts:105`), and *between steps* when `head.step` is null.
2. `step <Since iso={meters.round.since}>`, left out when `meters.round` is null.
3. `attempt <Since iso={meters.attempt.since}>`.

Use `Since`, as `Meters` does (`:234`), so both clocks tick. `inWords(now - …)` would freeze at render time. Other states keep today's readout. `standing.running` reaches the header through `standing`, so no new data path is needed.

## The card

Order inside the card:

1. **Head:** the step and its purpose (today's plan line, `:283-298`), with `LastEvent` (`apps/board/src/app/last-event.tsx:44`) on the right.
2. **Facts row.**
3. **Findings or evidence**, when present.
4. **The live area.**

Then, after the card, the discussion line.

Delete from `RunningPanelView` in `running.ts`, together with their tests:

- `ask`, set at `:157`;
- `then`, worked out at `:132-154` from the `anchor` calculation;
- the `triage-then` paragraph that drew it (`standing.tsx:317-324`).

A field the panel no longer reads should not stay behind for the next ticket to wonder about.

### The facts row

`Meters` becomes five cells:

| Cell | Value | Small text |
|---|---|---|
| this step | round `Since` | `of {budget}` when a budget is set |
| this attempt | attempt `Since` plus turns | the `behind` text when there is one |
| cost so far | cost text | the `behind` text when there is one |
| fix rounds | `budget` | — |
| limits | *none set* | — |

- Show the limits cell only when `m.round.budget`, `m.attempt.ceiling` and `m.cost.ceiling` are all null.
- When any of them is set, drop the limits cell. Each ceiling then goes in its own cell's small text, worded as today: *at most N turns a run*, *at most $X a run*. 0118 §2: *"The ceilings are for one agent run, never the attempt"* (`running.ts:19`). The *a run* is what keeps that true.
- `meters === null` (no `ctx`, `task.ts:983`): draw the fix-rounds cell when `budget` is there, and no other cells.
- The row is a CSS grid with `repeat(auto-fit, minmax(…))`, so it wraps to two rows on a narrow window.

### The live area: no new tail, and the open state survives the end of the run

The watch-out about sockets is already answered in the code. `tailRule` is `live || open` (`apps/board/src/lib/said.ts:53-56`), so while the run is live the tail is already followed with the log folded. Showing it open subscribes to nothing new. Do not add a `useLogTail` and do not change `tailRule`.

- **Running placement.** Drop the `<details>` toggle from `RawRunLog where="running"` (`apps/board/src/app/run-log.tsx:473-527`) and draw the body always open. Keep:
  - the pin-to-bottom scroll effect (`:483-490`);
  - the one-line `gone` and `trouble` text, so an unreadable log is never an empty box;
  - `say(…)` for the header's count (`:532`).

  The *follows live when open* text (`:502`) goes. Do not invent a route for the mock's *open the whole log ↗*: `run-log.tsx` has no such link today, and what the log serves is out of scope.
- **What happens when the run ends.** In `FollowedLog`, record the live run as opened (`setOpened(shown)` when `live` becomes true). The ended placement then opens the same log by the existing `openFor` rule (`said.ts:58-61`). Without this, the log a reader was watching folds shut the moment the run ends, which undoes #152 (`run-log.tsx:465-469`).
- **The two columns.** Add one component in `run-log.tsx`, say `LiveLog`. It works out `saidLast(f.lines, f.tags)` once, then draws either:
  - the log at full width, while `said` is empty or the state is `gone`; or
  - a two-column grid, *agent said* on the left and the log on the right.

  `SaidLast` (`:419`) becomes the left column and renders nothing when `said` is empty. With it go *Nothing said yet in this round.* (`:440`), *Nothing said in the last N lines* and the `gone` paragraph; the log's own `gone` line says that once. The columns stack on a narrow window. Doing the switch in one component avoids a CSS `:has()` check on whether a sibling rendered.

### Fix round and refusal

The findings list (`standing.tsx:304-312`) and `RawEvidence` (`:313-315`) stay unchanged, placed between the facts row and the live area. They are not folded and not trimmed.

### The discussion line

Only the slot is restyled to one line (`:326-328`). Its words come from `discussionContext` (`apps/board/src/app/discussion.tsx:405`: *Ask about this ticket*) and the note at `:112` (*reads the log, the ticket and the code — it cannot run anything*). Those strings are shared with the other states, and the discussion's behaviour is out of scope. Lay out what is there; do not reword it on this ticket.

## Edges the ticket leaves to the design

- **Between steps:** the head says *between steps*, the meta line has no step clock, and the facts row draws what `meters` has (`round === null` drops *this step*).
- **A stale page:** both clocks are `Since` against `serverNow`. The step times come from the server render and change only when the page next renders, like the rail's segments.
- **A `StepStarted` with no `StepEnded`:** the step is still running, or the run died part way. It gets no time and no error.
- **Two attempts:** times come only from the stream of the run the state names (`standing.runId`, the same index `task.ts:1941` uses), never from an earlier attempt.
