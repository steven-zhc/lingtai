## How the client reads the list

The mock's rule is that *the drawing and the list cannot disagree* (`:304-309`). Keep it: the client component does not hold its own copy of the words.

- On mount it reads `.fp-item[data-key]`, `.fp-say`, `.fp-what`, `.fp-bound` and `.fp-ext` from the server-rendered list through a ref on the section (`closest('section')`), as `:657-665` does.
- The SVG path shapes (`P.api` … `P.limit`) are drawing, not copy, so they live in the client file.

Doing it this way also means the copy is only in the server HTML, where `renderToStaticMarkup` in `page.test.tsx` can see it.

## Without script, and before script runs

The mock's `.no-js` class (`:224-225`) assumes something on the root toggles it. Nothing in the site does that today, so don't add a root class. Do this instead:

- The server renders the stage wrapper with `hidden` and the list with `open`.
- The client component's first effect removes `hidden` from the stage, removes `open` from `.fp-all`, closes every `.fp-item`, and runs `choose('api', false)`.

With script off, the page is then the open list, with no CSS trick involved. A test can assert this from the static markup: `hidden` is on the stage, and `open` is on `.fp-all`.

## The numbers test (`apps/site/unit/failure-paths.test.tsx`)

The constants are real and live on `main`. Import them in the **test only**; the site already depends on `@lingtai/domain` (`apps/site/package.json`). Render `HomePage`, take the text of each `data-key` item, and assert each number below appears in it as written, naming the item and the constant:

| Copy | Source |
|---|---|
| `api`: *3 tries*, *1, 5, then 15 minutes* | `BOUNDS.stepRedos` and `BOUNDS.stepRedoWaits` (`packages/domain/src/failure/respond.ts:579-583`) |
| `main`: *10 merges* | `BOUNDS.baseBranchMerges` (`:587`) |
| `unclear`: *5 stops* | `BOUNDS.personAsks`, which is `PERSON_ASKS = 5` (`packages/domain/src/wait.ts:605`) |
| `big`: *Split once* | `BOUNDS.ticketSplits` (1) |
| `big`: *at most 8* | `TRIAGE_SPLIT_CHILDREN_MAX` (`packages/domain/src/triage.ts:48`) |
| Edge line: *asks once more* | `BOUNDS.triageRetries` (1) |
| Question card: *Up to 5 questions*, *2 to 4 choices* | `TRIAGE_QUESTIONS_MAX` (`triage.ts:36`), `TRIAGE_ANSWERS_MAX` (`:38`), and 2 as a literal |
| `review` and `flaky`: *6 fixes* | recipe default `refusalFixes: 6` (`packages/recipe/src/recipe.ts:3361`) |
| `review` and `flaky`: *at most twice* | recipe default `newAttempts: 2` (`:3381`) |
| `flaky`: *One rerun only* | No constant. `process-action.ts:224-232` reruns a non-zero exit exactly once by construction (*"The rerun is only for a command that exited non-zero"*, #1222). The test writes the 1 as a literal beside that citation and 0108 §17. |

**Recipe defaults: read them from the parsed schema.** `@lingtai/recipe` is not a site dependency. Either:

- import the recipe schema relatively, which has precedent: `apps/site/src/lib/events.ts:4` imports `../../../../packages/domain/...`; or
- add `@lingtai/recipe` as a `devDependency`.

Whichever you pick, parse an empty `runtime.limits` and read `refusalFixes` and `newAttempts` off the result. Don't copy the 6 and the 2 into the test as literals, or the test pins nothing.

**English number words need a map.** `stepRedos: 3` appears in the copy as *3 tries* and *the third wait*; `newAttempts: 2` appears as *twice*. Map these words in the test: `{1: 'once', 2: 'twice'}` for the counts that read as words, and digits everywhere else. That way a bound change fails with the item named.

## CSS

- Prefix every class in the new block with `fp-`.
- The mock's question card also uses `.moves`, `.btn`, `.pri`, `.rec`, `.tag` and `.ill`. Several of those are board classes as well, and the ticket's list of four does not cover them. Rename them `fp-ask-moves`, `fp-ask-btn` and so on.
- Extend `apps/site/unit/home-css.test.ts` with a second `it` that slices the new block from its opening comment to the next block's comment. It runs the same `classesOf` intersection with the board stylesheet and expects `[]`.

## The page test

`apps/site/unit/page.test.tsx:29-31` and `:54-62` forbid *log* above the books kicker. Once the counts are dropped, the mock's copy does not contain the word. The existing test enforces that, and needs no change for it.

## Blocked chips

The ticket says a chip is drawn only once its behaviour is built. The numbers test is how that shows: a chip whose constant is missing on `main` fails to compile. If that happens, the agent stops and says which chip is missing. It does not invent a literal.

## Not checkable inside the pass

The visual pairs are a person's check at the PR. Don't use `pnpm test:integration` as the stand-in for the Next build. Two unit-level claims stand in for it:

- The client file's imports are only `react` and relative paths. Assert this in the new test by reading the file's import lines.
- `pnpm typecheck` passes.
