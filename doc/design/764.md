# #764 — the shape

The ticket already names every file and line. This note covers only what the ticket leaves open, plus three things in the code that would push the change the wrong way.

## 1. `stateWord` is a `Record`, not a switch

Write `const STATE_WORD: Record<StandingState, string>` beside `StandingState` (`apps/board/src/lib/task.ts:383`) and export `stateWord(s) = STATE_WORD[s]`. If someone adds a seventh state later, typecheck then forces them to give it a word, so nothing ever falls back to printing the raw enum. The only place to change is `standing.tsx:647` (`<span className="sstate">{standing.state}</span>`). The `onyou` class and the `.sstate` hue are not touched.

## 2. The held card: one condition, and the controls stay

`waitWords` returns a non-null `short` only for `SignoffRequired`. In `packages/domain/src/wait-words.ts:326` it is `short: 'ready to land'`, and every other branch sets `short: null` (`:92`, `:101`, `:117`, `:149`, `:204`, `:317`). So `card.short !== null` is the whole test for "held for approval". Do not add a second check on `wait.reason._tag`.

In the waiting branch of `Card` (`apps/board/src/app/page.tsx:171-208`), when `short` is set:

- The new badge line takes the place of the whole `cause ? … : triage ? … : fallback ? …` chain (`:183-192`).
- `waiting-advised` (`:193-197`) and `<TriageMove>` (`:198-206`) are left as they are. They are controls, not lines. A card's only Approve can be a `TriageMove` (`moveOf`'s `'Approve'` arm, `apps/board/src/lib/board.ts:614-617`), and removing a button is not what "nothing else" in the ticket means.
- Draw the badge line even when `card.progress` is null and no `Rail` is drawn (`:182`).

The `Rail` prop should be a boolean such as `line?: boolean` (default `true`). When it is false, `Rail` draws `<Segs …/>` and nothing under it.

- That means none of the three branches: `snow` (`rail.tsx:272-290`), `refused` (`:301-307`) or `nothing running` (`:331-337`). A signoff's `now` is normally set, so the `snow` branch is the one that would be drawn (see `held`'s doc, `rail.tsx:247-249`: "a sign-off was requested, and its `now` persists with no clock on it"). But a prop that hides only one branch would leak the other two on the first odd fold.
- The other callers keep the default and so keep their line: `standing.tsx:701` and `:765`, `task/[id]/page.tsx:871`, and `page.tsx:378`.

The age is `inWords(Date.now() - Date.parse(card.updatedAt))`, the same expression as the pill at `page.tsx:264`. `inWords(360_000)` is `'6m'` (`packages/conductor/src/queue.ts:159`). The badge uses its own class with colour `var(--signal)`. Do not reuse `.cause-chip`, whose colours belong to triage causes.

`short` goes on `BoardCard` as `short: words?.short ?? null`, next to `note` at `board.ts:682`. `words` is already computed at `:660-661`. Any `BoardCard` literal in tests or in `apps/board/test/visual-waiting.ts` will then need the new field. Typecheck will list them.

## 3. `describeHeld` has more readers than the card

The function is also drawn on the task page, through `Rail`'s `held` at `standing.tsx:701` and `:765` and `task/[id]/page.tsx:871`, and in `apps/board/test/visual-waiting.ts:477`. Dropping the 0/0 segment therefore changes those surfaces as well. That is intended, since a 0/0 ceiling is meaningless there too, and the 0118 §4 edit should say "anywhere the budget is drawn", not "on the card".

The guard is exactly `restartsOf === 0 && restarts === 0`:

- `restartsOf: 0, restarts: 3` still prints `no restarts left`. That case is pinned at `apps/board/unit/progress.test.ts:330` and should stay.
- `restartsOf: null` is unchanged.

When the segment is dropped there are no empty `·` gaps, because it is a `join(' · ')` over an array (`progress.ts:706-707`). Build the array without the segment rather than filtering out an empty string afterwards.

## 4. The backtick renderer is not markdown, and it must not live in `markdown.tsx`

`apps/board/src/app/markdown.tsx:4-8` states the rule: "Nothing on this page passes text to a renderer directly — it passes a source, and `DocumentBody` decides." `apps/board/src/lib/markdown.ts` classes "a sentence an agent printed" (`RunAwaitingInput.prompt`) as `log`, which is rendered `never`. A wait sentence includes `reason.question`, which an agent or a recipe wrote. So "render it with `DocumentBody`" is the wrong turn here. So is "add a `wait-sentence` source to `DocumentSource`", because that table is about markdown, and `_`, `#` and `{}` must stay literal in these sentences.

Put it in its own file, `apps/board/src/app/code-spans.tsx`. It exports one pure `codeSpans(text: string): ReactNode[]` that returns strings and `<code key=…>` elements only, so React escapes every byte and no HTML or markup path exists. Its doc comment should cite `lib/markdown.ts` and say in one sentence why this is not that rule:

- the only change is to drop matched backtick pairs and set what they enclosed in monospace;
- nothing else is interpreted, and nothing is removed except the delimiters.

Matching:

- Single backticks, scanning left to right, and pairing each opening backtick with the next one.
- An empty pair (two backticks in a row) stays as two literal backtick characters.
- A trailing unmatched backtick stays a character.
- No multi-backtick fences.

It goes inside the existing elements at the four sites (`page.tsx:190`, `page.tsx:380`, `standing.tsx:837`, `standing.tsx:841`), so `className`s and wrappers are unchanged. `page.tsx:380` is the non-waiting card's `card.note`, which may be `t.note` rather than a wait sentence. Applying it there anyway is harmless and is what the ticket asks for.

## Tests

Write new tests where the existing tests for each thing already are, not in a new file per point:

- `stateWord` and the drawn `.sstate` go in `apps/board/unit/standing.test.tsx`.
- The held card goes in the file that already renders waiting cards; check `moves-by-wait.test.tsx` and `rail.test.tsx`. Assert on the parts with `renderToStaticMarkup`, the way `markdown.test.tsx` does. Do not add a snapshot; `unit/__snapshots__/` exists, and a whole-card snapshot is the cost to later tickets that the ticket's edges rule out.
- `codeSpans` gets a pure test: a pair, an odd count, an empty pair, and a string with no backticks returning one string.

Before guessing, grep `apps/board/unit` and `apps/board/unit/__snapshots__` for `no restarts left` and for `>blocked<`. Any snapshot that has either baked in changes here once.
