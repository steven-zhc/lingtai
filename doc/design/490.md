# #490: where the prefixes live, and the decisions the ticket leaves open

## Shape

Everything new goes in `packages/domain/src/streams.ts`. `domain` "imports nothing, so everything can import `domain`" (`streams.ts:9-10`), and every package that has a site already depends on `@lingtai/domain`: `packages/agent/package.json:15`, `packages/daemon/package.json:20`, `apps/cli/package.json:18`, `packages/conductor/package.json:43`. `index.ts:20` re-exports the file wholesale, so you don't need to touch the barrel.

Follow the file's own convention. `CHAT_STREAM_PREFIX = 'chat-'` and `PROJECT_STREAM_PREFIX = 'prj-'` carry their trailing dash (`streams.ts:36, 54`), so the new constants do too:

- `WORK_ITEM_STREAM_PREFIX = 'wi-'`. It keeps the *work item* name because #489 renames the code names later; the ticket keeps `workItemStream` as it is, and this constant goes with it.
- `PASS_STREAM_PREFIX = 'run-'`. The ticket asks for a "pass-stream constructor", and the stream is the pass's in #450's vocabulary, so *pass* is right for new names here.
- `workItemStreamsOf(project)` returns `` `${WORK_ITEM_STREAM_PREFIX}${project}-` ``. Three sites use exactly this string: two pass it to `projectStreams` (`apps/cli/src/source.ts:246`, `packages/conductor/src/ticket-store.ts:265`), and `reconcile.ts:459` puts `%` after it. Have `workItemStream` build on it too, so the prefix is written once.
- `isWorkItemStream(id)` and `isPassStream(id)` are plain `startsWith` checks. They replace `streams.ts:27, 138, 140` and `apps/cli/src/subscribers.ts:117`.
- `passStream(id: string)` returns `` `${PASS_STREAM_PREFIX}${id}` ``. It takes the uuid as an argument rather than calling `crypto.randomUUID()` itself, so `domain` stays a package that decides nothing and generates nothing. `conduct.ts:905` becomes `passStream(crypto.randomUUID())`.
- The inverse, for `conduct.ts:1681`: `passIdOf(runId)` returns the part after the prefix, and nothing more.

## Decisions the ticket leaves open

**`packages/agent/src/claude-code.ts`: delete `newRunId`.** The ticket's `:737` is now `:761-763` (`export function newRunId(): string { return \`run-${randomUUID()}\` }`). It has **no caller**. Grepping `packages/` and `apps/` for `newRunId` finds only its definition, its barrel export at `packages/agent/src/index.ts:34`, and an unrelated local variable of the same name in `packages/conductor/test/one-pass.ts:120`. So the "second constructor" mints nothing today.

- Delete the function and the export together, and drop the `randomUUID` import if nothing else uses it.
- Write in the commit body that it had no caller, so `conduct.ts:905` is the only constructor.
- This follows `043680f5` (*triageRuns is gone — no caller ever wired it*).

That makes the comment at `conduct.ts:1677` ("`runId` always starts `run-` (its one constructor, above)") true. Rewrite it to name `passStream` and `passIdOf` instead of the literal.

**`WIP_COMMIT_PREFIX = 'wip: run-'` (`packages/domain/src/vocabulary.ts:82`) stays a literal and is not a stream id.** The ticket's grep pattern does not catch it: the `run-` follows a space, not a quote. It is a git commit subject, and `packages/repo/src/integrate.ts:448` matches branch commits against it.

- Building it from `PASS_STREAM_PREFIX` would make #464 change what the integration check looks for on branches already in flight. That is #464's decision to make, not a side effect of this ticket.
- `conduct.ts:1681` becomes `` `${WIP_COMMIT_PREFIX}${passIdOf(runId)} stopped by …` ``. The message stays byte-identical today and keeps working whatever #464 does to either prefix.
- Say in the commit body that this coupling exists, so #464 sees it.

**`end-step.ts:206`, `splitWorkItem`: keep the function and replace its body with a call to `parseWorkItemStream`.** It is not a pure copy:

- It returns `issue: number` and refuses a non-integer issue (`end-step.ts:210-211`). Keep that conversion and check on top of the parsed result. Its one caller (`end-step.ts:248`) wants a number.
- On malformed ids nobody writes, the result changes: `wi--5` returned `{project:'', issue:5}` and `wi-x-` returned `issue: 0` (since `Number('') === 0`); both become `null` through `parseWorkItemStream` (`streams.ts:32`). No unit test calls `splitWorkItem` directly (a grep of `packages/conductor/unit` finds none). Note the change in the commit body.
- `parseWorkItemStream`'s other quirk stays: an id *without* the prefix is parsed anyway (`streams.ts:27`: `id.startsWith('wi-') ? id.slice(3) : id`). Change the test to the predicate and leave the fallback as it is.

**SQL `like` patterns:**

- `converge.ts:290` becomes `` `${WORK_ITEM_STREAM_PREFIX}%` ``.
- `reconcile.ts:459` becomes `` `${workItemStreamsOf(n)}%` ``.
- `projectStreams` already appends the `%` itself (`event-store/src/queries.ts:219`, `sqlite.ts:473`), so the two `projectStreams` callers pass `workItemStreamsOf(project)` with no wildcard.
- A `_` in a project name is still a `like` wildcard, as it is today. Don't fix that here; the strings must not change.

**`hook-config.ts:201`: build it, as `passStream('smoke')`.** The value goes into `LINGTAI_HOOK_RUN_ID` for a hook pointed at a socket that does not exist, so it never reaches the log. Building it costs one import, and then the *Done when* grep comes back clean with no exception to explain in a commit body.

## `envelope.ts`'s `StreamId`

Today it is `/^(wi|run|int|prj|ctl|chat|ext|bkl)-[\w.-]+$/` (`envelope.ts:31-32`).

- Build it with `new RegExp(...)`, stripping the trailing `-` from each constant you use: `wi`, `run`, and also `chat` and `prj`, since their constants exist. `int`, `ctl`, `ext` and `bkl` have no prefix constant, so they stay literal inside the alternation.
- **Keep the alternation order exactly as it is.** Then the built pattern's `.source` is identical to today's, and a test can pin that equality outright.
- Export the `RegExp` (for example `STREAM_ID_PATTERN`) so the test can compare `.source` without reaching into zod.
- The comment block at `envelope.ts:33-` is history and prose; leave it alone.

There is no test of `StreamId` today; a grep of `packages/*/unit` finds nothing. Add `packages/domain/unit/stream-id.test.ts` with:

1. The equality: `STREAM_ID_PATTERN.source` equals the old literal's source.
2. A table of literal ids through `StreamId.safeParse`. Accepted: one per prefix, plus a dotted `int-lingtai-feat.x`. Refused: `wi-`, `run-` with an empty body, `xyz-1`, `wi lingtai`, and an uppercase `WI-1`.

Literal ids belong in that test; it is what #464 rewrites mechanically.

## Out of scope

`packages/event-store/test-support/teardown.ts:162-190`'s `^(wi|run|int|prj)-` is SQL text for Postgres's `~` operator, written three times. Replacing it is not a one-line change, so leave it for #464 as the ticket allows.

## Check

Everything here is unit-reachable. The strings are byte-identical, and two things stand in for "no event changes":

- the `.source` equality above;
- the existing suites, which assert on literal ids: `packages/domain/unit/work-item.test.ts`, and the conductor's `conduct-*` tests, which read `run-…` streams from the memory store.

Nothing needs `pnpm test:integration`. The two `like` sites (`converge.ts`, `reconcile.ts`) are only exercised against a real store there; the unit-level claim that covers them is that the pattern strings equal today's, which a reviewer can read off the diff.
