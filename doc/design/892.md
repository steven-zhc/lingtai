# Design: #892 — Approve on a `DiffTooLarge` wait reviews the clipped diff

## The one decision the ticket leaves open: what keys the clipped read, and where it is computed

The continuation is never written to the log. `conduct.ts:1105-1115` says it is *"read fresh off the log rather than trusted from the caller … computed here, at the moment this claim is about to be made"*, built from the approved wait's `reason` and `reduced.lifecycle`.

So `readClipped` is computed there too. Do not add it to any event. It is:

- **Accumulated across approvals on the same head, like `waive` through `waivedActionsAt` (`wait.ts:571-590`).** `conduct.ts` sets `readClipped` when any `Approve` on this run is on a `DiffTooLarge` wait raised at the step being resumed with `onSha` equal to the head now approved. A later approval on that head (a human signoff after the clipped review) therefore keeps it; an earlier head's approval (a fix round's new head) matches nothing, so the new head is measured again.
- **Keyed to `lifecycle.onSha`.** That is `Approve{onSha}` (`wait.ts:246`, *"refused if the branch moved off `onSha`"*), which `checkApprove` has already proved equals the head the wait was raised on (`resolve-wait.ts:511-535`).

Because nothing new reaches the log, the restart edge holds by construction. If someone has to check what happened, two things on the log settle it: the ticket stream's `WaitResolved` carrying `Approve.onSha`, and the run's `StepEnded` at `review`, whose verdict action is `Completed` with `assessment.clipped`.

## The hops, in order

1. **`wait.ts`**
   - `Continuation` (`:470-473`) gains `readonly readClipped?: true`.
   - In `continuationOf`'s `ProposedEscalated` switch, move `DiffTooLarge` out of the `return null` group (`:524-532`) into its own arm: `{ step: proposal.from, waive: null, readClipped: true }`. `proposal.from` is the step the stop was raised at: `review`, `proposed` or `merge`, as `attempt-next.ts` allows.
   - In `tableResolutions` (`:340-343`), the row becomes `['Approve', 'Requeue', 'EditBodyAndRequeue', 'Split', 'Close']`. Rewrite the comment, which today says *"there is nothing to approve past (#892 is that)"*.
   - `continuationOf`'s doc says it returns `null` *"exactly where `allowedResolutions` does not offer `Approve`"* (`:476-478`). Both change together, and `approve.ts:267` relies on that to refuse `not-offered`. `GrantFixRound` stays unoffered: `grantCriterion` is unchanged.
2. **`conduct.ts:1132-1149`.** When `next.readClipped`, add `readClipped: { onSha: approvedOnSha }` to the continuation object. At `:4236-4244`, spread it into `from` the way `landedOnBase` is spread.
3. **`run-attempt.ts`**
   - `AttemptOptions.from` (`:934-965`) gains `readClipped?: { readonly onSha: string }`.
   - At `:1922-1925`, apply the same first-visit gate as `waived`: `options.from?.step === spec.step && !reached.some(...)`. If it passes, put `readClippedAt: options.from.readClipped.onSha` on the pipeline `context` (`:1944`).
   - This gate is the first half of *"a fix round's new head is measured again"*. A fix round's `review` is never the first visit. `waived` uses the same gate, documented at `:936-943`: *"a fix round that sends it back through `step` on a new head is not the head the approvals were about"*.
4. **`ActionContext` (`packages/actions/src/action.ts:471`)** gains `readClippedAt?: string`. It goes on the context rather than the spec, for the reason `recheck` gives at `:495-498`: it is a fact about this run of the pipeline.
5. **`agent-action.ts:623`.** Skip the stop only when `context.readClippedAt === context.onSha`. This is the second half of *"keyed to the head sha"*: a context that kept the field onto another head is measured again.
   - When it skips, dispatch exactly as today. `buildReviewPrompt` already clips (`:401-403`).
   - The result carries `clipped: { read: deps.limits.diffBytes, of: diff.length }` on every return path that comes from a completed reading: passed, refused with findings, refused with no findings. These are the same paths as `summary` (`:910`).
   - The `unreadable` path (`:885-890`) and an interruption become `AnswerUnreadable` / `Interrupted`, and those have no `Assessment`. They carry nothing.
   - The units match `size`/`limit`: UTF-16 code units, per `clippedAt`'s own doc (`:383-387`).
6. **`ActionResult`** (`action.ts:~125`, beside `summary`), the `results` entry (`:672`), and the spread at `:880`.
7. **`step-outcome.ts:126`.** Spread `clipped` beside `summary` into all three `Completed` arms: `passed`, `failed` non-unreadable, and `needs-approval`.
8. **`Assessment` (`packages/domain/src/action.ts:30-35`)** gains `clipped: z.object({ read: nonneg int, of: nonneg int }).optional()`.
   - This step is required. Zod `z.object` strips unknown keys, so leaving it out loses the field on parse, silently.
   - A row written before this has no key, and that means *not clipped*.
9. **`reviewSummaryOf` (`action.ts:397-409`)** returns `clipped` from the same last completed verdict action that `summary` comes from.
   - **Decision:** a clipped review with no summary must still be readable to #893–#895. So the return type becomes `{ summary?: string; clipped?: { read; of } } | null`, and it is `null` only when neither is present.
   - The one production reader, `conduct.ts:4515`, uses `?.summary ?? null`, so it is unaffected. The existing tests (`domain/unit/action.test.ts:454-476`, `conductor/unit/review-summary-trip.test.ts`) stay green as written.
   - Replace `clipped?: boolean` and the *"left unset until #892"* comment.

## No note: `checkApprove`

The review action's `failed` is reduced as `'failed'` (`attempt.ts:267`), on the same sha. So `refusingOn` (`resolve-wait.ts:81-86`) returns `['review']`, and today's check (`:540-550`) asks for a reason.

The fix is narrow. Pass the wait's `reason` into `checkApprove` (called at `:341`, where `block.reason` is in scope). For `ProposedEscalated{DiffTooLarge}`, drop `proposal.from` from `refusing` before testing `!note`.

Do not skip the check entirely: a refusal on any other step on that sha still asks for a reason. The board's `Decide` is told `refusing` from `standing.failed` (`standing.tsx`), so the task page passes `refusing=false` for a `DiffTooLarge` wait and the click goes straight to the server, which asks for nothing.

## The copy

`RESOLUTION_COPY` is `Record<Resolution['_tag'], …>` and has no wait in hand (`apps/board/src/lib/resolution-copy.ts:6`).

- Add `resolutionCopyFor(tag, reason)` beside it. It returns the existing entry, except Approve on `ProposedEscalated{DiffTooLarge}`, which gets:
  - title: *Review the first N anyway* (N = `proposal.limit`)
  - consequence: one sentence saying the reviewer reads the first N of M, nothing is waived, and the review records it read only part. Do not use the generic *"Any refusal at this hold is waived"*, which is false here.
- Use it wherever a wait's reason is available when rendering:
  - `standing.tsx:935`
  - the card's move label at `decide.tsx:862`, through the props the card already has; if its `move` lacks the reason, add the reason rather than guessing
  - `page.tsx`'s card

## Tests (unit half only; all reachable with `createMemoryEventStore`)

- **`domain/unit/wait.test.ts`:** `allowedResolutions` offers Approve for `DiffTooLarge`; `continuationOf` returns `{ step: 'review', waive: null, readClipped: true }`.
- **`actions/unit/agent-action.test.ts`:**
  - with `readClippedAt === onSha` and an oversized diff, the runtime is dispatched once, the prompt contains `[diff truncated at`, and the result has `clipped`
  - with `readClippedAt` set to another sha, it returns `diffTooLarge` and dispatches nothing
- **`conductor/unit`:** take the shape of `conduct-continuation-remembers-every-checkrefused-waiver.test.ts`.
  - Approve on the wait continues at `review`, and the run's `StepEnded` at `review` carries `assessment.clipped`.
  - A refused clipped review that buys a fix round, whose new head is still over the limit, raises `DiffTooLarge` again.
- **`resolve-wait`:** Approve on a `DiffTooLarge` wait with no note succeeds. The `reason-required` path for other waits is unchanged.

No ADR is contradicted: 0108 §14 (2026-11-05) is what this builds.
