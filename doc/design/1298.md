# #1298: the shape of the change

The ticket already says how the ACP runtime behaves. This note covers the decisions the ticket leaves open: where `copilot` is a legal name, which modules the code may import, and four places where adding a `RuntimeId` breaks something the compiler will not report.

## 1. `copilot` is legal as a step `agent:` at `implement`, and nowhere else

Adding `copilot` to `RuntimeId` (`packages/domain/src/events.ts:144`) widens more than `implement`:

- `agentPlugin.fields.agent` is `RuntimeId` (`packages/recipe/src/recipe.ts:370`). Its `at` also serves `design`, `review`, `proposed` and `merge` (`:380–430`).
- `JudgeName = z.enum([...BUILT_IN_JUDGES, ...RuntimeId.options])` (`:1387`). That makes `judge: copilot` legal with no further edit.
- `runtime.agent: RuntimeId.default('claude-code')` (`:3300`).

The ticket puts review, judges and the schema in the prompt out of scope. It also sets `acceptsOutputSchema: false`, and the cold reviewer depends on that schema (`runtime.ts`: *"sent by the cold reviewer (#369) and by triage (#582)"*). So you must refuse every other place by name when the recipe resolves. Do not let any of them reach dispatch. Add the check to the existing `Recipe.superRefine` (`recipe.ts:~3488`), which loops over every step and action. That is the one place that sees `steps`, `runtime` and `sandbox` together.

- An `agent: copilot` at any step other than `implement` is refused. So are `judge: copilot` and `runtime.agent: copilot`. Each refusal is one sentence naming the step or key, e.g. *"`steps.review`'s "…" names `copilot`, which runs only at `implement` until review on an ACP agent is built."* `runtime.agent` is refused because it is the conductor's dispatched runtime (`agentRefusal`, `packages/conductor/src/conduct.ts:~499`), and that runtime also serves triage and the fallback reviewer.
- **The sandbox refusal goes here too.** It is pure, with no host to ask. If `recipe.sandbox?.enabled` is true and any action names `copilot`, refuse with *"… copilot cannot run sandboxed yet"*. Use the same sentence shape as `SANDBOX_REQUIRED_REFUSAL` (`packages/recipe/src/sandbox.ts:31`). Test `enabled`, not `required`. An enabled block means each run is handed `RunRequest.sandbox` (`runtime.ts:~139`, *"Claude Code reads it; Codex does not yet"*), and the ACP runtime ignores it. Without this refusal the run would go unwrapped with nothing saying so. Do not add it to `checkSandboxBlock`: that function exists for host facts.
- Define the set once in `packages/recipe` as an exported constant, e.g. `IMPLEMENT_ONLY_AGENTS = ['copilot'] as const`. The refusal and §2 both read it.

`DiscussAgent` (`recipe.ts:2919`) stays `['claude-code', 'codex']`, as the ticket says.

## 2. The setup wizard must not propose `copilot` by itself

`defaultAgents` (`packages/setup/src/propose-setup.ts:103–107`) picks the writer as the first signed-in id in `RuntimeId.options` order. It picks the reviewer as *any other* signed-in id. On a machine signed in to Claude Code and Copilot but not Codex, the wizard would write `copilot` as the reviewer. §1 then refuses that recipe, so the wizard would produce a broken file.

Filter `IMPLEMENT_ONLY_AGENTS` out of both picks. Filter the offered choices in `apps/cli/src/agents.ts:207` (`offeredRuntimes`) the same way. Naming `copilot` at `implement` is something a person writes by hand in this ticket.

`doctor` (`apps/cli/src/doctor.ts:1478`, `:3134–3206`) walks `RuntimeId.options` and `everyRuntime()`. It picks up an account row for `copilot` with no change. Leave that as it is.

## 3. Where the code lives, and what it may import

- **`auth.ts` may not import the runtime.** Its header explains why `AUTH_PROBES` is a second table (`packages/agent/src/auth.ts:296–303`): reaching a runtime loads `hook-socket.ts`, which loads `@lingtai/event-store`, *"whose client is built at module scope and throws without a database URL."* So split the code in two:
  - `acp-session.ts`: spawn, the SDK connection, `initialize` → `session/new`, and the profile type. It imports only `node:*`, the SDK and `effect`.
  - `acp.ts`: the `Runtime`. It may import anything.

  `AUTH_PROBES.copilot` calls a `copilotAuthEffect` built on `acp-session.ts`. Amend `auth.ts`'s header line *"importing nothing but Node built-ins"* so it names the SDK as an allowed import.
- **The hook-socket client is your own, about 20 lines in `acp.ts`.** Do not import `packages/hook/src/lingtai-hook.ts`: it is a script with top-level `await` and `process.exit` (`:88–112`). The framing is one JSON line out and one JSON line back, `{ runId, payload }` → `{ allow, reason? }` (`lingtai-hook.ts:55–80`). Read the socket path and run id from `request.env.LINGTAI_HOOK_SOCKET` and `LINGTAI_HOOK_RUN_ID`. The conductor puts them there (`hook-config.ts:176`). If either is missing, fail `crash`, the same as an unreachable socket. `lingtai-hook` treats a missing pair as wrong wiring too (`:89–93`). Give it a timeout; one second is enough, and `lingtai-hook` has its own `TIMEOUT_MS`.
- **The payload is shaped like a Claude Code hook.** Set `hook_event_name`, `tool_name` and `tool_input`, because that is all `decide` reads (`hook-socket.ts:213–219`). A mutation is recorded only when `MUTATIONS[tool_name]` matches (`Write`/`Edit`/`MultiEdit`/`NotebookEdit`, `:116–121`) and `tool_input.file_path ?? tool_input.path` is set (`:262`). So an ACP `edit` is sent as `tool_name: 'Edit'` with `tool_input: { file_path }`. Every other kind is sent with a `tool_name` that is not a `MUTATIONS` key, e.g. the ACP title or `acp:<kind>`. It still appears in the run log trace through `onDecision` (`:263`) and never counts as a touched file.
- **Send `PostToolUse` when the tool call finishes, not when it is first announced.** Keep a map from `toolCallId` to its `kind` and path, filled by `tool_call` and merged with each `tool_call_update`. Send once, when the status reaches `completed` or `failed`. Send `Edit` only for `completed`.

  This narrows the ticket's *"for each `tool_call` whose `kind` is `edit`"*, on purpose. A permission-gated edit is announced before it runs, and the socket's own comment rules out recording an edit that never happened: *"a plausible fiction is worse than a gap"* (`hook-socket.ts:254–256`). Claude Code's `PostToolUse` also fires after the tool has run.

  Take the path from `locations[0].path` first and `rawInput.path`/`file_path` second. Experiment 019 does not record which fields Copilot fills, so the fake agent in the tests sends both. A `tool_call` that never finishes before the turn ends is traced as unfinished and never recorded as touched.

## 4. Two tables that break without a type error

- **`ToolsCannotBeDenied`'s message is about Codex for every id** (`runtimes.ts:76–81`). The `copilot` row must throw it for `tools: 'none'`; 019 E2 found neither ACP agent can be given no tools. `apps/cli/unit/discuss-agent.test.ts` asserts that the ids which do *not* throw are exactly `DiscussAgent.options` (`recipe.ts:2911–2917`), so not throwing turns that test red. Make the sentence depend on the id: keep the Codex text for `codex`, and say *"copilot cannot be given no tools: its ACP agent has no tool-free mode (experiment 019 E2)"* for `copilot`.
- **`effect-ratchet.baseline.json` is 0/0 for `packages/agent`.** No `async` function and no `Effect.run*` may appear anywhere in the package (`packages/domain/unit/effect-ratchet.test.ts:1–17`). The SDK's handler callbacks (`onRequest` for `session/request_permission`, the session-update handler) must therefore return a value or a promise without using `async`.
  - Where a callback must run an Effect, use `Effect.runPromiseWith(services)`, with the services taken once from `yield* Effect.context()` in `run`. The ratchet does not count that form (`effect-ratchet.test.ts:105–112`).
  - `checkAuth` returns a `Promise` (`runtime.ts:281`). Write it the way Codex does: a `copilotAuth` face in `auth.ts`, whose body is exactly `return Effect.runPromise(copilotAuthEffect(…))`. Add a matching entry to `effect-ratchet.faces.json` beside `codexAuth` (`"until": "0101 §7"`). Adding a face is not raising the baseline. Anything else in that body is counted.

## 5. The process

`codex.ts` already uses the group kill: `detached: true` (`:1597`), `process.kill(-child.pid, signal)` (`:1686`), and the injectable `sendSignal` in `claude-code.ts:326,500`. Follow it, including the injectable kill, so the *"process group gone"* test does not wait on real signals.

Hand the SDK the child's stdio as web streams (`Readable.toWeb` / `Writable.toWeb`). `RunRequest.signal` aborting is the same path as the wall: `session/cancel`, at most 5 s, then `SIGTERM` to the group, then `SIGKILL`, and the outcome is `timeout`.

Keep the last ~4 KB of stderr for the early-exit `crash` detail.

`invocation()` returns `{ command: 'copilot', args: ['--acp'] }`. The prompt goes over the protocol, not on argv, so there is nothing to elide.

## 6. Tests

All the new tests are unit tests in `packages/agent/unit/acp.test.ts`.

- **The scripted agent** is a small `.ts` fixture under `packages/agent/test/` that speaks ACP on stdio and does what the test tells it, through an env var or argv. Pass it in as `RuntimeOptions.binary`.
- **The hook socket is real**: a `node:net` server on a temp path, recording what it receives.

Both a spawned process and a socket are integration under 0060 §1 (CLAUDE.md: *"a spawned `node` is still a process"*). Look at where `codex.test.ts` and `claude-code.test.ts` spawn their stand-ins. If they are in `unit/`, follow them; if not, put these in `integration/`. In that case one test cannot run inside a pass: the one that drives the real process group. Then cover the logic with unit tests instead:

- the outcome classifier, as a pure function from `{ stopReason, text, exit, wallHit, sessionNewError }` to `failure`;
- the profile's failed-turn match;
- the tool-call map in §3;
- the hook payload builder.

Add the claims from §1 to `packages/recipe/unit/`:

- `copilot` resolves at `implement`;
- it is refused at `review`, as a `judge:`, as `runtime.agent`, and under `sandbox.enabled`;
- it is refused at a discussion, by `DiscussAgent`.

`packages/agent/unit/runtimes.test.ts` already asserts that both tables cover every id, so it covers `copilot` once the rows exist.
