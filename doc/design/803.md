# #803 — the shape

## Where it goes

**Put the seven illustrations in their own module, `apps/site/src/app/home-minis.tsx`, not inline in `page.tsx`.** The ticket's *Fix* row says inline. The reason for the change is the tests. `Home` is an async server component that reads the snapshot (`page.tsx:10-11`), so a test cannot render it. Every test of the page today reads the source text instead (`unit/page.test.tsx:14-17`, `prose()`). The two new `Done when` cases need to count rendered labels and check the shape of the log lines, so they need markup they can render. `BuildsItself` already works this way: it is its own module and is rendered by `renderToStaticMarkup` at `page.test.tsx:151`. Export one small component per illustration (or one component with seven variants), and export the worktree illustration's lines as a `const` array so the test can check them directly. `page.tsx` only places the components.

The CSS goes in `home.css`, under the existing comment blocks `/* The loop, one stop at a time. */` (`home.css:141`) and `/* Beside the loop, and the six. */` (`home.css:157`). Use `home-`-prefixed class names: `home-mini`, `home-mini-t`, `home-qrow`, `home-logline`, `home-rail`, `home-ans`, `home-cause`, `home-srow`, `home-lanes-mini`, and so on. Port each rule from the design's stylesheet: `.mini` and `.mini-t` (`doc/design/home-page.html:96-98`), `.ans`, `.cause`, `.srow`, `.ceil`, `.bar-meter` and `.lanes-mini` (`:99-116`), and `.qrow`, `.logline` and `.rail` (`:179-189`). The design uses unprefixed names like `.mini` and `.rail`. Prefixing them avoids clashes with `site.css`, and `page.test.tsx:71-77` already keeps page sections off generic class names. The site already has every token these rules use, including `--signal`, `--signal-soft`, `--pass` and `--pass-soft`; `home.css:105-107,154-155` uses them today. So dark mode needs no new colours.

## Layout

- **Stops.** Each stop `<li>` in `.home-stops` gets a wrapper with two children: a text column holding the existing `h3`, `.home-what` and `.home-seedo`/`.home-fork`, and the illustration. This is the design's `.stop-grid`: `minmax(0,1.2fr) minmax(0,.8fr)`, gap 32px, with `margin-top: 6px` on the illustration (`home-page.html:163-164`). Leave `.home-pin` outside the wrapper; it is absolutely positioned. **Remove `max-width: 52rem` from `.home-stops > li` (`home.css:144`).** It was there to make a text-only stop look intentional, and with it a two-column stop squeezes the illustration to nothing.
- **Stop 04** holds two illustrations stacked in one wrapper: the waiting card, then the landed card. The landed card has auto height (`.mini.short`, `home-page.html:177`).
- **Beside cards.** The illustration is the first child of each `article.home-card.home-hl`, before the `h3`, as the design has it (`home-page.html:389-403`). Give `.home-hl h3` a top margin, since it now follows something (design: `.hl h3{margin:22px 3px 8px}`, `:93`).
- **Breakpoint.** Follow the ticket, not the design: stack at `max-width: 1080px`. The design stacks at 800px (`home-page.html:207-210`), but the ticket says ≤1080px. Add a new `@media (max-width: 1080px)` block. Do not move the existing 1100px block (`home.css:184`). The beside grid already becomes one column at 800px (`home.css:194`), and nothing more is needed there.
- **Fixed height.** The design's `.mini` is `height: 230px; overflow: hidden`. Use `min-height` instead on the site. A fixed height clips content at 700px wide, and clipping is not the scroll the ticket allows. **The worktree lines wrap, they do not scroll:** use `white-space: pre-wrap` (see below), so nothing scrolls sideways at 700px.

## Labels and accessibility

Every illustration's header row has `ILLUSTRATION` as its right-hand label. The design sometimes puts something else there: `→ WHY, AND WHAT NEXT`, `EXAMPLE FIGURES`, `→ SEVERAL AT ONCE`, and `0.11` on the worktree illustration (`home-page.html:318,365,390,402`). Replace each of those with `ILLUSTRATION`. Keep the left-hand titles: QUEUED, `$ lingtai start`, STEPS, WAITING ON YOU, LANDED, /SPEND, SEVERAL AT ONCE, THE AGENT'S ENVIRONMENT. Drop the design's `LINE FORMAT IS ILLUSTRATIVE` footer: the lines will now follow the real format, and the header already carries the label.

Do not copy the design's `aria-hidden="true"`. Use the hero diagram's pattern instead: `role="img"` plus `aria-label="Illustration: …"`, with one sentence saying what it shows (`page.tsx:425-426`). A screen reader then hears one honest line rather than made-up ticket rows. The unit test counts these.

## Copying the design is not enough

- **`0.11` must not appear anywhere.** The design has `<span class="v">0.11</span>` badges throughout (`home-page.html:314,318,331,354,371`). `page.test.tsx:120` asserts `expect(text).not.toMatch(/\b0\.11\b/)`, and that check reads only `page.tsx`. Once the illustrations live in `home-minis.tsx`, the new test has to apply the same rule to that file, or the guard goes blind.
- **The worktree lines use #766's format, which the design gets wrong.** The design breaks each line in two with `<br>` and puts one space after the ticket number. The real line is built by `endingLine` (`apps/cli/src/conduct.ts:629-648`) and `takingLine` (`:611-613`):
  - `taking #12  Fix a failing test`: **two spaces** before the title (`start-one-line.test.ts:112`).
  - `#12  Fix a failing test — implement ✓ build ✓ review ✓ · $0.84 · landed in 3f9c2a1`: steps joined by spaces, then ` · ` parts, `landed in` and a seven-character sha (`conduct.ts:640,645`, `start-one-line.test.ts:47,75`).
  - `#15  Add retry to uploader — implement ✓ build ✓ review ✗ · $1.20 · waiting for you: lingtai approve my-app --issue 15`. Drop the design's `(or the board)`. `the board` appears only when there is no wait reason (`conduct.ts:642`).

  JSX and HTML both collapse the double space. Keep the lines as JS string literals in the exported array, render them with `{line}`, and style them `white-space: pre-wrap`. The shape test applies regexes to that array, something like `/^taking #\d+ {2}\S/` and `/^#\d+ {2}.+ — (\w+ [✓✗] )*\w+ [✓✗] · \$\d+\.\d{2} · (landed in [0-9a-f]{7}|waiting for you: lingtai \w+ \S+ --issue \d+)$/`. **Do not import from `apps/cli`.** `@lingtai/site` depends only on `@lingtai/domain` and `@lingtai/projector` (`apps/site/package.json:13-14`), and making one app depend on another is a bigger change than this ticket.
- **The Queued illustration drops the design's `On hold · agent:hold` row** (`home-page.html:302`). The copy beside it says `agent:hold` keeps a ticket *out of* the queue (`page.tsx:77-78`), so a held ticket shown in the Queued column contradicts it. Keep the `blocked by #15` row: *a blocked ticket counted as blocked, not lost* (`page.tsx:71`).
- **The landed card reads `landed · issue closed`** with no version badge. This matches `page.tsx:160`.
- **The checks rail** keeps the design's five rows (`home-page.html:338-343`). You may add a `base is red` row, which the ticket allows (#744, `page.tsx:136-137`). Use `--signal` for it, not `--fail`, because it holds rather than fails.
- **The environment card's `LINGTAI_* · never` row** (`home-page.html:419`): I found no line in `packages/agent-env/src` that strips every `LINGTAI_*` variable. The narrower claim, that an agent is never given `LINGTAI_DATABASE_URL`, is the project CLAUDE.md's, not the code's. Find the filtering line before keeping the row. If you can't find it, write the row as `Lingtai's own settings · never`, which is the copy's own claim: *no Lingtai setting* (`page.tsx:221-222`).
- **Invented ticket names and dollar figures** are fine, because each sits under an `ILLUSTRATION` label (the ticket, `page.test.tsx:64`). Unknown costs read `unknown`, never `$0.00`, which is the rule `costWords` follows (`conduct.ts:615-620`).
