## Design note for #1303: the docs must describe what the code allows today, not what the ticket's Fix lists

This is a documentation-only change. The one decision that isn't obvious from the ticket: **the ticket's Fix says something the merged code does not.** The ticket's own Edge decides which wins: *"every sentence about behaviour is checked against the merged tickets … a difference is a finding against the doc"*. So the doc describes the code.

### Where `copilot` and `antigravity` may be named

The Fix says *"every step for all four"*. The code allows them in one place only: as the `agent:` of an action at `implement`.

- `packages/recipe/src/recipe.ts:1384-1390`, `IMPLEMENT_ONLY_AGENTS = ['copilot', 'antigravity']`. Its comment reads: *"The agents a recipe may name at `implement` and nowhere else yet (#1298): the mandatory ACP hook … is wired only on the implement path, so review and judges would fail at dispatch, triage is excluded by `DiscussAgent`"*.
- `recipe.ts:3592-3599` refuses them as `runtime.agent`: *"runs only at `implement` until the ACP hook is wired at review and judges (#1300) — name it as `agent:` at `implement`"*.
- `recipe.ts:3611-3615` refuses them as any `judge:`, and as an `agent:` at any other step.

The "where each may be named" table in `doc/reference.md` therefore has these rows, each quoting the refusal a person will see:

| | `claude-code`, `codex` | `copilot`, `antigravity` |
|---|---|---|
| `runtime.agent` | yes | refused |
| `agent:` at `implement` | yes | yes |
| `agent:` at `design` / `review` | yes | refused |
| `judge:` | yes | refused |
| `discuss.agent` / triage | yes | refused |

- Say that #1300 is the follow-up, as a ticket number. Do not say it will happen.
- Do not write "every step" anywhere.
- The milestone (`doc/milestone/0.16.0/0.16.md:22,70`) describes where this is going, not what is built. It is not a source for these sentences.

### `doc/reference.md`: three places, all stale today

1. **`## runtime — 2` (`:1823`).** It should be `— 4`. The source is `RuntimeId` at `packages/domain/src/events.ts:144`, not `:78` as the page says now.
2. **The `agent:` row in the step-plugin table (`:1159`).** It says the field *"is an enum of the ones Lingtai can start — `claude-code`, `codex`"*. Name all four there and point to the new table.
3. **`runtime.limits.run.usd` (`:352`).** Add that a `copilot` or `antigravity` run is unpriced: `costUsd: null` (`packages/agent/src/acp.ts:323`). `run.usd` never stops it; `turns` and `wall` bound it. The day's ceiling does not see Copilot (no model) but counts an estimate for Antigravity where a rate was fetched (`spend.ts:231`, `doctor.ts:2832`).
   - Before writing *"`lingtai doctor` and the resolve say so"*, grep for the sentence. `0.16.md:73` makes that claim, but this design did not find the line. If nobody finds it, leave the claim out.

**`model:`** goes in the same new subsection, citing `acp.ts:370-380` and `packages/agent/src/acp-session.ts:104,120`:

- Copilot is set through `session/set_model`. It advertises no model, so the value is an id the account may use, and a wrong one comes back as the reply's text (019 E9, quoted at `acp-session.ts:111`).
- Antigravity takes a `model` config option. The value is one of the models it offers.

**Leave the triage table at `:447` as it is.** It describes triage routes, and neither new agent may be one. A single sentence under it saying so is enough.

### `doc/safety.md`: extend the existing *The Copilot token*, don't add a second one

That section already exists at `:138-151`, from the Copilot-sandbox ticket. Add to it; do not write a new section beside *The Claude token*. What it is missing:

- The token is fine-grained and owned by your own account, with only the *Copilot Requests* permission.
- `copilot.github_token` is the file key.
- Why not `gh`'s login: it can reach your repositories, and the token cannot (`0.16.md:116-125`).

Add the other sandbox facts from `packages/agent/src/sandbox-facts.ts:25-35` and `packages/sandbox/src/policy.ts`, using the hosts and folder from the `COPILOT_NETWORK` and `COPILOT_HOME_FOLDER` constants rather than from the ticket:

- Under *What the sandbox refuses and allows*: a Copilot run, and no other, also reaches `*.githubcopilot.com` and writes `~/.copilot`, and its telemetry host is refused.
- Under *What the sandbox does not cover* (`:183`): **the Copilot token is readable to a Copilot run**, matching the Claude and Codex bullets already there.
- Under *When the host cannot sandbox* / *Without the sandbox*: Antigravity cannot run sandboxed on any host (`UNSANDBOXABLE_RUNTIMES`, `events.ts:147-151`).
  - With `required: false` it runs unsandboxed and is marked.
  - With `required: true` the recipe is refused, with the text at `recipe.ts:3617-3622`. Quote it.

Ignore the comment at `recipe.ts:1386` that says *"it is not sandboxed yet"*. It is stale for Copilot: `sandbox-facts.ts:27-33` and `packages/agent/src/copilot-sandbox.ts` are the code. Leave the comment alone, because code is out of scope.

### `doc/guide.md` and `doc/requirements.md`

**`guide.md`.** The place is *Choose a model for each role* (`:103`), not a first-run section: the guide has none. Add one paragraph headed *Copilot or Antigravity at `implement`*. It covers:

- the three limits, by name: implement only, unpriced, Antigravity unsandboxed;
- sign-in:
  - Copilot: `copilot login` or `gh`'s login when unsandboxed; `lingtai token copilot` when sandboxed.
  - Antigravity: `agy acp --login`, and Lingtai running in your GUI login session, not over ssh, because of the keychain (019 E10, `0.16.md:75`).
- the versions and date from experiment 019, copied from that file and not from the ticket.

**`requirements.md`.** It is where a person checks what to install. It says *"One of Claude Code or Codex"* (`:21`) and has binary rows at `:59-60`. Add `copilot` and `agy` rows and soften `:21`. Each new row says *"only when a step's `agent:` at `implement` names it"*. This is a doc file outside the ticket's three, but it is where the Done-when's *"where a person choosing it reads"* lands.

`doc/operating.md:879` is about narrowing Claude Code and Codex through their own configuration. Nothing was measured for ACP, so add one sentence saying that and nothing more.

### Edges

- **Generated pages.** `scripts/the-pass.py` does not exist (`scripts/` holds `the-attempt.py`), and `doc/the-pass.html` names neither runtime. There is nothing to regenerate.
- **Tests that read these files.**
  - `packages/domain/unit/retired-names.test.ts` parses `reference.md`'s *retired name* section.
  - `apps/site/unit/docs.test.ts` checks the guides' sections, links and the safety page.
  - Neither touches the sections above. Keep the existing headings, because links point at their anchors, and run `pnpm test`.
- **`pnpm lint`** is `oxlint` (`package.json:18`) and reads no markdown. The checks that actually guard the docs are the two `pnpm test` files above.
- **The cost to later tickets.** When #1300 lands, the table's implement-only column is the one line to change. Keep the restriction in that one table and link to it from the other pages; don't repeat it in prose on each page.
