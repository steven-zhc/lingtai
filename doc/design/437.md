## Shape for #437

**One file changes, and one directory and one test are added.** `apps/board/src/app/layout.tsx:2,17-29` swaps two `next/font/google` calls for two `localFont(...)` calls from `next/font/local`. Nothing else in the board changes. Every font file sits in `apps/board/src/app/fonts/` beside the `OFL.txt` that covers it, and the test goes in `apps/board/unit/`.

### Where the files come from: fetch them once, never add a dependency

`node_modules` has no IBM Plex package installed today. Do not add `@fontsource/ibm-plex-*` (or anything like it) to `apps/board/package.json`. That would change the lockfile only to copy seven files into the tree. The ticket wants the files to be part of the repository, not something resolved later.

Fetch them once from one of these and commit the result:
- the `@fontsource/ibm-plex-sans` / `@fontsource/ibm-plex-mono` tarballs (`npm pack` into a scratch directory outside the worktree). Each has `files/ibm-plex-{sans,mono}-latin-{weight}-normal.woff2` and a `LICENSE` that is the OFL.
- or IBM's own `IBM/plex` release.

That gives seven woff2 files: sans 400/500/600/700 and mono 400/500/600, normal style only. The current call asks for no italics, so ship none.

**Keep upstream's file names unchanged.** That lets a reader trace each file back to where it came from without a separate note. Include IBM's copyright line in `OFL.txt` (`Copyright © 2017 IBM Corp. with Reserved Font Name "Plex"`); a bare OFL template is not enough. Fetching the files needs the network once, while the work is being done. The finished board never fetches anything.

### The call

```ts
const sans = localFont({
  src: [
    { path: './fonts/ibm-plex-sans-latin-400-normal.woff2', weight: '400', style: 'normal' },
    …
  ],
  variable: '--font-sans',
  display: 'swap',
})
```

Every `path` has to be a **string literal**, for two reasons:
- `next/font/local` reads them at compile time and refuses an expression.
- The unit test finds them with a regex over the source text. A computed path is one the test cannot check.

Keep `variable` and `display` exactly as they are today (`layout.tsx:20-21,27-28`), and leave `className={`${sans.variable} ${mono.variable}`}` at `layout.tsx:55` untouched. Rewrite the doc comment at `layout.tsx:6-16`. Its claim, *"it copies the files into the build, so the board still renders as designed on a machine with no network"*, was only true for the built output. Dev and build time fetched from Google. The new comment should say the files are in the repository, cite #437, and note that `OFL.txt` has to move with them.

### The released binary needs no change

`next/font/local` writes its output under `.next/static/media`. `apps/release/src/build.ts:73` already copies all of `.next/static` into the standalone tree, and its comment at `:39` explains why. Leave `apps/release` alone.

### The test

Add `apps/board/unit/fonts.test.ts`. Reading checked-in source with `readFileSync(new URL('../src/app/…', import.meta.url))` already has a precedent in `unit/`: `apps/board/unit/bar.test.ts:188` reads `globals.css` exactly that way. So this is not the temp-directory filesystem use that the suite's rule sends to `integration/`.

The test asserts:
1. `layout.tsx` does not contain `next/font/google`.
2. Every `path: '…'` resolves, relative to `src/app/`, to a file that exists and is not empty.
3. Each `variable:` value appears exactly as `--font-sans` and `--font-mono`, and `globals.css` reads both. This ties the name the call writes to the name the CSS reads, which is the silent `system-ui` fallback the ticket warns about.
4. `fonts/` contains an `OFL.txt` that mentions `SIL Open Font License`.
5. Every `.woff2` in `fonts/` is named by some `path`, so no unused file is left in the directory.

### What only runs after the merge

The claim that matters, *Turbopack resolves this in `next dev` and in `next build`*, is checked only by `apps/release/integration/build.test.ts`, which runs after the merge. The unit test above stands in for it: files exist, paths are literals, variable names are unchanged. Running `pnpm --filter board exec next build` by hand once is cheap and is worth doing, but it is not a "Done when" item.
