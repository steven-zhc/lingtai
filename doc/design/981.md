# #981: where the ticket's shape needs deciding

The file to change is `apps/board/src/app/recipe/[project]/recipe-form.tsx`. The ticket's `edit/form.tsx` moved in #980. `yaml-editor.tsx` goes beside it.

**Not verifiable from here:** the CodeMirror packages are not installed in this worktree. The grammar facts in §4 come from upstream `main` of `lezer-parser/yaml`, `src/highlight.js`, so confirm them against the installed version.

## 1. The textarea is not `next/dynamic`'s `loading`

The ticket's fix reads as if it could be, but it cannot.

- `loading` receives only `{ isLoading, pastDelay, error: null }` (`next/dist/shared/lib/lazy-dynamic/loadable.js`, `LoadableComponent`). It never gets the caller's props, so it cannot see `draft` or `setDraft`.
- `dynamic()` has to be called at module scope. Called in render, it makes a new component each time and remounts the editor on every keystroke, because each keystroke re-renders the form. So `loading` cannot close over the state either.

The shape instead:

- `RecipeForm` holds `editorReady` (false at first) and renders its own controlled textarea while that is false.
- `RecipeForm` always renders `<YamlEditor>` as well, from a module-scope `dynamic(…, { ssr: false })` with no `loading`.
- `YamlEditor` calls `onReady` from the effect that creates the view, and `RecipeForm` then stops rendering the textarea.

## 2. A failed chunk needs its own catch

`loadable.js` passes the loader straight to `React.lazy` with no catch. A rejected import therefore throws during render and takes the page to the nearest error boundary, instead of leaving the textarea as the ticket's first edge requires.

Catch it in the loader: `import('./yaml-editor').catch(() => ({ default: () => null }))`. The null component never calls `onReady`, so the textarea stays and saving works. No error boundary and no extra state are needed.

## 3. `name="text"` appears exactly once

`saveRecipe` reads `form.get('text')` (`apps/board/src/app/actions.ts:928`), which returns the first entry.

- The hidden `<input type="hidden" name="text" value={draft} />` is always rendered.
- The textarea loses its `name` (it has one at `recipe-form.tsx:24`).
- Keep the hidden input `type="hidden"`. A `type="text"` input strips newlines from its value.

**The editor is seeded once and never fed back.**

- Its props are `initial` and `onChange`. The view is created once, from the `initial` of the render in which the chunk arrived. That is how text typed during the load carries over.
- After that, `draft` only ever changes because the editor reported it, so there is no value-to-dispatch sync to write. That also satisfies "never reset by a completed action", and the no-`key` note at `recipe-text.tsx:10-11` still holds.
- Destroy the view in the effect's cleanup, since a dev double-mount will otherwise leave two editors.
- Report only on `update.docChanged`.

## 4. Numbers and booleans cannot be styled by tag

The ticket's editor section asks for a style on them, but the YAML grammar has no such tags. Upstream's `styleTags` has `Literal: t.content`, `QuotedLiteral: t.string`, `BlockLiteralContent: t.content`, `"Key/Literal Key/QuotedLiteral": t.definition(t.propertyName)` and `Comment: t.lineComment`. A `tags.number` or `tags.bool` rule would compile and match nothing.

Drop that rule and do not add regex decorations for it. The reviewer's bar in *Out of scope* is keys, strings and comments.

There are three rules:

- `tags.definition(tags.propertyName)` for keys.
- `[tags.string, tags.content]` as one colour for values. Nearly every value in a recipe is an unquoted `Literal`, so `tags.string` alone would leave almost all of them uncoloured.
- `tags.lineComment` in `--muted` for comments.

## 5. The chrome uses the board's variables too

The board goes dark through `prefers-color-scheme` (`apps/board/src/app/globals.css:49`), while CodeMirror's default gutter and cursor are fixed for a light page. A black cursor on a dark surface would be a bug rather than the out-of-scope "dark theme".

One `EditorView.theme` covers it: background `--surface`, text and cursor `--ink`, gutter `--surface-2` and `--muted`, border `--rule-2`, font `--mono`. No extra theme code is needed beyond that, because the variables already switch.
