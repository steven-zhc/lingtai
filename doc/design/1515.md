## Design note: #1515. Both panels on the task page in every state

This is a CSS change in `apps/board/src/app/globals.css`, plus one markup change in `TicketContext` (`apps/board/src/app/standing.tsx:719-770`). `TotalsStrip` and `Cell` need no changes. The ticket leaves four things undecided, and they are decided here.

### 1. The ticket panel: remove the page-class scope from the rules

Today these rules apply only under `:is(.detail--waiting, .detail--resolved, .detail--framed)` (`globals.css:1406-1452`):
- `.topening`
- `.tcontext`
- `.tcontext-field`
- the `.md` reset ("*A cell is a sentence, so it reads as one: no second box inside the first.*")
- the `@media (max-width: 46rem)` block

Rewrite each one as the bare selector (`.tcontext`, `.tcontext-field + .tcontext-field`, …). Do not add `.detail` to the list. `.tcontext` and `.topening` appear in exactly one place, `TicketContext` (`standing.tsx:736`, `:744`, `:754`), so scoping them adds nothing. Taking the scope off is what "every state" means.

Some rules stay where they are:
- `.detail--framed .topening` / `.detail--waiting .topening { max-width: none; … }` (`globals.css:1384-1389`) moves to bare `.topening`. `max-width: none` replaces the default `max-width: 62rem` at `globals.css:1240`, because the ticket wants full content width in every state.
- The `.swant`, `.swhere` and `.sbody` rules in the same run (`globals.css:1402`, `1453-1460`) keep their scope. They are out of scope for this ticket.
- `panel-css.test.ts` asserts `.detail--{waiting,queued,running}` only for `triage-*`, `sreading--advised` and `band-facts` (`apps/board/unit/panel-css.test.ts:21-32`). None of those changes, so that test stays green as it is.

### 2. Equal columns: count the fields with the class that already exists

Today `.tcontext` has `grid-template-columns: repeat(3, minmax(0, 1fr))` (`globals.css:1416`). With two fields, that leaves an empty third column on a waiting page too.

Only *Watch out* can be absent. `ticketOpening` returns null unless `problem`, `want` and `fix` are all present (`standing.tsx:709-712`), and only `watchOut` is nullable (`:713-716`). That field already has its own class, `tcontext-field--watch` (`standing.tsx:754`). So:

- `.tcontext` keeps `repeat(3, …)`.
- Add `.tcontext:not(:has(> .tcontext-field--watch))` with `repeat(2, …)`.

This is preferred over a `data-fields={n}` attribute because it needs no markup change. `:has()` is already used in this file (`globals.css:1401`).

### 3. *The whole ticket ↓* moves inside `.tcontext`, and the pending skeleton does too

Today the `Link` is a sibling after `.tcontext` (`standing.tsx:765-767`), styled by `.topening > a` (`globals.css:1241`). The new structure:

- **With an opening:** render the `Link` as the last child of `.tcontext`, wrapped in an element with its own class (e.g. `tcontext-more`). That element gets:
  - `grid-column: 1 / -1`
  - padding 8px 16px
  - `border-top: 1px solid var(--rule)`
  - `--fs-sm`

  `grid-column: 1 / -1` works because the column count is explicit (point 2). Do not use `grid-auto-flow: column` here, because `1 / -1` does not span implicit tracks.
- **Without an opening (`opening === null`):** the `Link` stays where it is, as `.topening > a`, a plain line.
- **Pending:** today the fallback is `TicketContext opening={null} … pending` (`standing.tsx:1284`), which draws a bare `<Skeleton shape="lines" count={3} />` (`:737`) and then the plain link. Instead, when `pending` is set, draw `.tcontext` with the skeleton in a `grid-column: 1 / -1` cell and the link row under it. The panel then looks the same before and after GitHub answers.
- **Read failed:** the `problem` paragraph (`:738-742`) stays a child of `.topening`, above `.tcontext`. The existing `.topening > p { margin: 0 0 0.65rem }` (`globals.css:1410`), once unscoped, gives it its spacing.

The test at `apps/board/unit/standing.test.tsx:2217` slices from `class="tcontext"` up to the history `href`. That still works, because the link is still after the fields. Read it again anyway once the link has moved.

### 4. The figures panel: every rule is `.meters.facts[data-totals]`, and the prefix is required

The running card's `<dl className="meters facts">` (`standing.tsx:240`) has no `data-totals`. The strip's `<dl>` does (`totals-strip.tsx:55`). So any selector that contains `[data-totals]` cannot match the running card.

**The trap is specificity.** The shared rules include `.meters.facts .meter dd.sub` (`globals.css:3727`), at (0,4,1). A bare `[data-totals] .meter dd.sub` is (0,3,1). It loses, the sub-line stays `--fs-xs` instead of `--fs-2xs`, and nothing reports it. So write every new rule as `.meters.facts[data-totals] …`.

The rules:

- **Container:** `background: var(--surface)`, `border: 1px solid var(--rule)`, `border-radius: var(--radius)`, `gap: 0`. Columns are `grid-auto-flow: column; grid-auto-columns: minmax(0, 1fr)` with `grid-template-columns: none`. That replaces the shared `repeat(auto-fit, minmax(9rem, 1fr))` (`globals.css:3724`), so one to four cells always make one equal row. The fixed column count from point 2 isn't needed here because this panel has no full-width row.
- **Cells:** `.meter` padding 12px 16px. `.meter + .meter` gets `border-left: 1px solid var(--surface-2)`.
- **Under 46rem:**
  - `grid-auto-flow: row; grid-template-columns: repeat(2, minmax(0, 1fr))`
  - `.meter:nth-child(odd)` gets `border-left: 0`
  - `.meter:nth-child(n+3)` gets `border-top: 1px solid var(--surface-2)`
- **Text:**
  - `dt`: weight 600, `letter-spacing: 0.08em`, on top of the shared `--fs-xs`, uppercase and `--muted`
  - `dd:not(.sub)`: `--fs-lg`, `--mono`, `--ink`
  - `dd.sub`: `--fs-2xs`, `--mono`
- **Colour of *Of which answering*:** it is an inline `style={{ color: 'var(--signal)' }}` on the span (`totals-strip.tsx:64`), and it stays. A `dd` colour rule does not override it.

All the variables exist: `--fs-2xs` / `--fs-xs` / `--fs-sm` / `--fs-lg` (`globals.css:16-20`), `--radius` (`:24`), `--surface` / `--surface-2` / `--rule` (`:26-31`, dark at `:90-95`), `--mono` (`:59`). Spacing in `px`/`rem` is not a literal colour or font size, so the *Done when* item about literals is not affected.

**The 12px gap.** The strip sits in a different parent depending on the state:
- **Framed (blocked, queued, running, approved):** `.swaiting-head`, whose `gap: 0.75rem` (`globals.css:1371`) is already 12px.
- **Every other state:** `.standing`, with `gap: 0.4rem` (`globals.css:1180`).

So set the strip's own `margin: 0` (the shared rule gives it `0.5rem 0`, `globals.css:3724`). Then add the difference only in the non-framed case, e.g. `.standing > .meters.facts[data-totals] { margin-bottom: 0.35rem }`. The framed strip is a child of `header`, not `.standing`, so that rule does not reach it. When `TotalsStrip` returns null (`totals-strip.tsx:35`), there is no element and so no gap.
