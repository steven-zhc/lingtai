**The guard test reuses the walker that `pr-colours.test.ts` already has.** `apps/board/unit/pr-colours.test.ts:15-44` exports `scan`. Its comment says: "Walks every block at any depth … so nested CSS (`.pr-card { &:hover { … } }`) is covered as well as `@media` wrappers." It also strips comments and returns each rule's `selector`, `body` and `chain`. Two problems with using it as it stands:
- Importing a `*.test.ts` from another test file registers that file's `describe` blocks a second time.
- The PR-prefix filter is baked into it.

So split it in two:
- Move the prefix-free walker (it returns every rule with its chain) to `apps/board/test/css-rules.ts`. CLAUDE.md says `test/` holds "the shared contract suites and fixtures that are not themselves tests". `apps/board/test/` already exists.
- In `pr-colours.test.ts`, keep the prefix filter and the `LITERAL` check, built on that import. Its four existing cases must stay green and unchanged.
- `card-radius.test.ts` uses the same walker.

Don't write a fourth regex parser next to the walker, `panel-css.test.ts:13-19`'s regex and `fonts.test.ts`.

**What `card-radius.test.ts` checks:**
- **Radius.** For every rule whose body declares `border-radius`, the value must be exactly `var(--radius)`, `999px` or `50%`, or the selector must be in `MARKS`.
  - `MARKS` is a list of `{ selector, why }` with one entry per selector in the ticket's "marks, bars and shapes" list. Key it on selector text exactly as written in the CSS (for example `.rp-legend i, .rp-kind i` is one key).
  - Compare the whole value as a string, so `3px 3px 7px 7px` on `.sbx-skeleton` is matched as one value.
  - `0` is not allowed. `.waiting-card` stops using it.
- **Stale marks.** Every `MARKS` selector must still be present with a `border-radius`, so the list can't quietly outlive its rules. The cost: deleting a mark's CSS rule also means deleting its entry, in the same diff. That's intended, and the test's failure message should say so.
- **Tokens.** Select `:root` by its chain:
  - Light is the `:root` whose chain has no `@media`. It must contain `--radius: 3px` and the four unchanged light values.
  - Dark is the `:root` whose chain includes `prefers-color-scheme: dark`. It must hold exactly the four new values.
  - Don't regex for the first `--surface:`. Both blocks use the same names, and the first match is always the light one.
- **No `--pr-line`.** The text `--pr-line` appears nowhere in the stripped source. That one check covers both the declarations and any use.
- **The guard can fail.** Add planted-input cases like `pr-colours.test.ts:52-58`, for example `scan('.x { border-radius: 6px }')`, showing the guard flags a bad radius and accepts a listed mark.

The guard reads only `globals.css`, as the ticket's Done-when says. `markdown-preview.ts:223`'s `.md-code` is changed by hand and is not guarded. Don't widen the guard to `.ts` files.

**Do the `--pr-line` borders and the two deletions in one commit.** Deleting the declarations first leaves `var(--pr-line)` undefined, so the borders fall back to `currentColor`. `pr-colours.test.ts`'s `LITERAL` check passes either way, because `var(--rule)` is not a literal.

**`kindDot` needs its comment updated, not just the constant.** Today the comment at `kind-colour.ts:55` reads "The dark card surface is `#131e22` (luminance 0.012), so `(L + 0.05) / …". `#18262b` has luminance ≈ 0.0176, which gives a 3:1 floor of `L ≥ 0.1527`. Set `LUM_MIN = 0.153` and rewrite the comment with the new surface and luminance so the derivation still checks out. Two other lines use `LUM_MIN` and need no edit: `:79` and `:84` (the `LUM_MIN + 0.005` nudge). Change `DARK` at `kind-colour.test.ts:18` to `'#18262b'`.

- Nothing in `pnpm test` or `pnpm test:integration` checks that a dark divider doesn't now read as a frame, or that corners look 3 px. That's the person's look at the pages in the ticket's last Done-when box. Leave it unticked in the commit; don't claim it was done.
