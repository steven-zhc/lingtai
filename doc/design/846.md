## The test: details the ticket leaves open

- **The walk.** `readdir` over `apps/` and `packages/`, then each `src/` found, recursively. Skip the directory names `node_modules`, `.next` and `dist`, and the one path `packages/domain/src`. The rule lives in the test. A new package is counted with no edit, which is how *"cannot drop a directory"* is met here. Fail if the walk finds no files at all.
- **`.tsx` files.** Pass the real file name to `ts.createSourceFile`, so the script kind comes from the extension. Reuse `effect-ratchet.test.ts`'s `parse`, which passes the name and throws on parse diagnostics (`:52-60`). A `.tsx` file parsed as plain TS would throw there, and so would not count as zero.
- **What counts as a comparison.** `===` and `!==` only. The other side must be an `Identifier` named `type`, or a `PropertyAccessExpression` whose `name.text === 'type'`. The literal may be on either side.
- **What counts as a `case`.** Any `CaseClause` whose expression is a string or no-substitution template literal in the event set, whatever the discriminant is. The grep found no non-event `switch` using an event name: `tell.ts:175-195` and `:409-424` are not event names.
- **Naming the function.** Walk `node.parent` up to the first of the four named kinds the ticket lists. A `MethodDeclaration` uses `name.getText()`, which gives `apply` for `async apply(events, ctx)`. Use `<module>` if none is found.
- **Duplicate keys** in the JSON fail with the key printed.
- **How a red prints.** It prints the full corrected list as one JSON array, sorted by `file`, then `function`, then `type`. Keep the existing reasons, and set `"reason": ""` on new entries. One paste then fixes both directions, missing and stale. Keep the JSON in that sort order, so a later diff shows only the line that moved.

- **A read that fails or does not parse.** It throws with the path and is never counted as zero (`parse`'s throw).

- **A run stream that fails to reduce.** It throws, in both readers, as the ticket decides.
- **The cost to every later ticket.** Adding, removing or moving a branch is a one-paste edit to the JSON, and a reason is written by hand.
