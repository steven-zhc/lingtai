**Design note: #1276. A normal `AgentFailed` ending keeps its dirty tree**

The change goes in `packages/conductor/src/conduct.ts` only. It sets one marker word in two places and re-reads the head in one. Nothing changes in `keepUncommittedWork`'s guard, in `decideImplementOutcome`, or in the redo walk. The line numbers in the ticket are stale; the ones below are the current tree's.

### The decision: a new marker word, `agent-failed`

`keepUncommittedWork` decides whether to look from `stoppedBy` alone: `if (stoppedBy === null || stoppedBy === 'no-commits' || inConflictRound) return` (`conduct.ts:2615`). Do not change that guard. Give a normal ending decided `AgentFailed` its own word, `'agent-failed'`, so the guard lets it through.

- Do not reuse `'no-commits'`. That is what the ticket's *Watch out* forbids, and the guard skips it.
- Do not reuse `'interrupted'` or a `RunFailed.kind`. Those words mean the runtime cut the agent off.

The word reaches the log. It is written to `RunKeptUncommitted.stoppedBy`, which is `z.string()` (`packages/domain/src/events.ts:942`), so the schema needs no change. Update that field's doc comment, which today reads *"`RunFailed.kind`, `'no-commits'`, or `'interrupted'` — why the agent stopped mid-run"*, to add `'agent-failed'`. It also reaches the WIP message (`wip: run-… stopped by agent-failed`, `conduct.ts:2660`) and the next attempt's brief (`attempts.ts:484`, `:504`: *"it stopped (${kept.stoppedBy})"*). Those read correctly with the new word and need no change.

This is the rule 0108 §21 already states: its table's `AgentFailed` row says *"WIP committed if any (§20), then `redoStep`"* (`doc/decisions/0108-a-refusal-buys-a-round.md:496`). §20's bullet still words the exception as *"ends abnormally"* (`:466-470`). Edit that bullet in place so it also covers an `AgentFailed` ending. That is an edit to the topic's ADR, not a new file. Nothing here contradicts the decision.

Key the change on `decided._tag === 'AgentFailed'`, nothing wider. `Disputed`, `Unclear` and `AlreadyDone` go to the router and not to `redoStep` (0108 §21 table). A not-moved `Unclear` keeps `'no-commits'` as today.

### First dispatch (`conduct.ts:5126-5165`)

- **Line 5141 today:** `stoppedBy = moved ? null : 'no-commits'`. Make it `'agent-failed'` when `decided._tag === 'AgentFailed'`, whether or not the head moved. The moved case is the ticket's scenario: the agent committed once and left edits. The unmoved case is the ticket's *`Implemented` that moved nothing* edge. Otherwise, use the expression as it is.
- **Order:** leave `recordDiff(branch, head)` where it is and with the pre-keep `head`. `RunProducedDiff` counts the agent's own commits, not the WIP (comment at `conduct.ts:2570`: *"WIP on top of it … two different counts"*). Call `yield* keepUncommittedWork()` after it, inside the `decided._tag !== 'Implemented'` branch and only for `AgentFailed`.
- **Re-read HEAD after the keep**, the way the abnormal path does (`conduct.ts:5058-5059`: `left` / `kept = left === startedAt ? {} : { head: left }`). Use that read for the returned `head` instead of `...(moved ? { head } : {})`. Without it, the stored outcome's receipt (#1250) misses the WIP, and an unmoved run whose edits were kept would report no head at all.

### Fix round (`conduct.ts:5438-5446`)

- **Line 5445 today:** `stoppedBy = fixed.failure ? fixed.failure.kind : null`. Make it: the failure's kind if there is one; otherwise `'agent-failed'` when `decidedFix?._tag === 'AgentFailed'`; otherwise `null`. The `keepUncommittedWork()` on the next line then does the work. No new call is needed.
- **The returned head** already re-reads after the keep (`:5448-5449`).
- **Conflict rounds** stay unkept through the guard's `inConflictRound`. Do not add a check of your own.
- **Leave line 5471 alone.** It is the committed-`Implemented` path, which does not redo.

### Edges the ticket leaves open

- **A failed keep refuses the reset. Do not let it reset anyway.** With `stoppedBy` now set, a failed keep leaves it set (`conduct.ts:2607`: *"a failed one leaves `stoppedBy` set so the finalizer asks again"*). The redo's `resetToHead` asks again, and then refuses: *"Never reset over work that was not saved (0108 §20, #1245)"* (`conduct.ts:5716-5720`). `run-attempt.ts:1716-1717` turns that refusal into `cannot(...)`. That is the abnormal-stop behaviour today, and it is what *"said as today"* means here. The ticket's *"the redo still runs"* must not be read as resetting over the edits; that would break §20.
- **A clean tree, or only the planted env file dirty:** the keep returns early, `stoppedBy` stays `'agent-failed'`, and the reset's own keep finds it clean again (`:2627`, `:2634`). Nothing changes.
- **Process dies halfway:** the commit and the `wips` entry are already one uninterruptible region (`:2652`). `publishWhatIsCommitted` calls the keep again (`:2830`), and on a clean tree that second call does nothing.
- **A retry:** each redo of the step sets `stoppedBy` again from its own decision, so a second `AgentFailed` keeps its own WIP on top of the first.
- **Cost to later changes:** none in shape. Tests that assert *no* `RunKeptUncommitted` after a no-outcome normal ending with a dirty fake tree will now go red. Change their expectation; do not change the code back.
