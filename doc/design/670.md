# Design: #670, demoting findings outside the diff's hunks

## Where it goes

**The helper** goes in a new file, `packages/actions/src/diff-hunks.ts`, as one pure function: `hunksOf(diff: string)`. It returns a `Map<string, Set<number>>` (path → new-side lines), or `null` when it cannot read a hunk header it has found. Also put a small `isInsideHunks(finding, hunks)` beside it, so the tests can check the rule without running a review. Nothing in `packages/` parses hunks today, so this has no neighbour to follow.

**The demotion** goes inside `reviewAnswer` (`agent-action.ts:657`), between the parse (`:768-769`, `normaliseAnswer` / `parseFindings`) and `const verdict = verdictFor(findings)` (`:780`). `reviewAnswer` currently takes only `outcome`, so give it two more parameters: `reviewAnswer(outcome, diff, log)`. The call site is `agent-action.ts:640`, and there `diff` is the same variable that was handed to `buildReviewPrompt` at `:591`. That variable is the whole diff from `context.mergedOnto ?? moved?.toSha` (`:540-541`). The clipping to `diffBytes` happens only inside `buildReviewPrompt` (`:346-347`), on a local copy called `clipped`. So passing `diff` on gives you the unclipped diff the ticket asks for, with nothing else to change. Do not call `deps.diff()` a second time.

- **The `mergedOnto` test** works by asserting which `from` the `deps.diff` fake was called with, and then that a finding inside that diff's hunks stays a blocker. No real git is needed, so it stays in `unit/`.
- **An unreadable diff** (the helper returns `null`): call `log?.note('review', …)` and leave every finding as reported.

## `reachableBecause` goes in two schemas, and they are not the same shape

This is the decision the ticket does not spell out.

- **`Finding`** (`vocabulary.ts:127`) gets `reachableBecause: z.string().optional()`. That is what lets stored `StepEnded` findings from before this change still parse.
- **`ReviewAnswer`** (`events.ts:1078`) must **not** inherit it as optional. Its comment says:

  > All-required, and `about` is required but nullable rather than optional … `codex exec --output-schema` is OpenAI structured output, whose strict mode refuses an optional property.

  `packages/domain/unit/review-answer.test.ts:40-41` pins the finding's `required` list at exactly five. If you add an optional key to `Finding`, `Finding.strict()` carries it into `REVIEW_ANSWER_JSON_SCHEMA`. Codex would then refuse the whole schema, and that failure only shows up at run time.
- **So:** build `ReviewAnswer`'s item as `Finding.extend({ reachableBecause: z.string().nullable() }).strict()`. That makes it required but nullable, like `about`. Update the test to expect six required keys and to say why.

## Reading the field

`normaliseAnswer` (`agent-action.ts:404`) rebuilds each finding field by field (`:411-424`). Any key it does not copy is dropped, and that would include `reachableBecause`, for both the schema path and the prose path.

Copy it there, and only when it is a string that is non-empty after trimming. `null`, `""` and whitespace become an absent key, using a spread like `about` uses. Leave it on the recorded finding when it is present, so the log keeps why the finding was not demoted.

## The rule

A finding is **inside** when either:

- its `file` is a key in the map and its `line` is in that key's set; or
- its `line` is `null` and the file is a key with at least one line.

A finding stays as reported when any of these holds:

- it is inside;
- it carries `reachableBecause`;
- it is already `minor`;
- the file appears only as a deletion (`+++ /dev/null`).

To make the deletion case work, the helper has to remember deleted paths. Key them by their `--- a/` path, with an empty set, and treat that as a mark that keeps the finding, not as "no hunks".

Every other finding becomes `{ ...f, severity: 'minor', claim: \`pre-existing — was ${f.severity}: ${f.claim}\` }`. The `failureScenario` is left untouched, because the recheck block quotes it word for word (`:233-247`).

It says that a finding on a line the diff does not touch is recorded as a pre-existing minor, unless `reachableBecause` says how this diff makes that code reachable. ## Edges the ticket leaves open

- **A demoted minor on a review that still fails** because of another blocker goes into `recheck` with everything else. `conduct.ts:3673` takes `brief.context.recheck` whole, and `:3688` says *"a passing review's minor findings ride on `recheck`"*. That is the behaviour today and it stays; narrowing what travels belongs to #669-A.
- **A re-raised finding whose claim already starts with `pre-existing — was`**: do not add the prefix twice. Check for it before adding.
