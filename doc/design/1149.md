## Decisions the ticket does not make

**1. The reader returns `Redacted<string> | undefined`, not `string`.**
- Use Effect's `Redacted`. Its `String()` and `JSON.stringify` print `<redacted>`.
- That makes *never in a log, a trace or an error* hold by the type, not by every later caller remembering it.
- Only S4b, setting `CLAUDE_CODE_OAUTH_TOKEN` on the run, calls `Redacted.value`. Nothing in this ticket does.
- Normalisation:
  1. Trim the outer whitespace, since a pasted token often carries a newline.
  2. Answer absent if the result is empty or contains any whitespace (`/\s/`).
  3. Check nothing else about it.
- It stays a sync function like `codexTextConfig`. It is not `async`, so the ratchet does not move.

**2. When the file is unreadable, do not repeat the parser's message.**
- `machineFile` builds `unreadable` as `` `${path} could not be parsed as YAML: ${(err as Error).message}` `` (`index.ts:156`).
- The YAML library's message includes an excerpt of the offending line. A token pasted unquoted onto the line that breaks the parse would be printed by the error itself.
- So the Claude reader fails with a sentence that names the path and says it could not be read or parsed, and carries nothing from `file.unreadable`.
- `codexTextConfig` (`:192`) and doctor's own config row have the same exposure. That is a backlog finding, not this ticket's.

**3. The path convention lives in `packages/conductor`, not `packages/agent`.**
- Add `claudeConfigDirFor(home, runId) = join(home, 'runs', runId, 'claude')` in `packages/conductor/src/run-log.ts`.
- That puts it beside `settingsPathFor`'s `runs/<runId>/settings.json` (`hook-config.ts:75-77`).
- Reasons:
  - `RunRequest`'s comment: *"`packages/agent` must not learn where `~/.lingtai` is"* (`runtime.ts:91`).
  - `@lingtai/daemon` depends on `@lingtai/conductor` and not on `@lingtai/agent` (`packages/daemon/package.json:19-25`), so the sweep can import it without a new edge.
- S4b uses the same function, so the sweep and the run cannot disagree about the name.
- `runs/` also holds `runs/<project>/<runId>.log` (`run-log.ts:59`). A project directory never contains a directory named `claude`, so the finder matches only `runs/*/claude` entries that are themselves directories.

**4. What `prepareClaudeRunDirectory` takes.**
- Signature: `(dir, { source, settings, trace }, fs)`.
  - `source` is the operator's Claude directory, passed in for the same reason as `dir`. The caller in S4b decides it is `~/.claude`.
  - `settings` is the value from `renderSettings`, written as `<dir>/settings.json` with mode `0600`. This is the Want's *the hook settings Lingtai writes*.
  - `trace` is a `(line) => void`, like reconcile's `log`.
- Note for S4b, not this ticket: a run handed both that file as `CLAUDE_CONFIG_DIR` user settings and `--settings` would fire each hook twice. Choosing one is S4b's job.
- Make the directory with `0700`.

**5. Scope shape.** `Effect.acquireRelease`:
- **Acquire is only the directory creation:** make the parent recursively, then `dir` exclusively. `EEXIST` refuses by name.
- **Release** is `rm -rf dir`.
- **Copies and the settings write run after acquire,** so a failure in them still triggers the release.
- **A refused acquire never runs the release.** That is what stops one run deleting another's directory, and a test should assert it.
- **A release that fails** traces the path and the error code and does not fail. The next daemon start's sweep is the backstop.

**6. "Read-only copies" means the run cannot write them. It does not mean chmod here.**
- S4b's `denyWrite` gives that (ticket *Related*: S4b *"makes the copies read-only"*).
- A chmod in this ticket would make the release need to chmod back, and make the fake filesystem model permissions, for nothing.

**7. The copy logic is in the function, not delegated to `fs.cp({ dereference: true })`.** Otherwise dereferencing and the dangling-link rule would sit in the live adapter, which no unit test reaches.
- The port is small: `lstat`, `stat` (follows links), `realpath`, `readdir`, `readFile`, `writeFile`, `mkdir`, `rm`. The live adapter wraps each in `Effect.tryPromise`, with no `async` function anywhere.
- How each entry is decided, at the top level and recursively inside `skills/` and `agents/`:
  - `lstat` gives `ENOENT`: absent, so skip it.
  - `lstat` says it is a link and `stat` gives `ENOENT`: dangling, so skip it and write one trace line naming the path.
  - Otherwise, copy what `stat` describes.
- Keep a set of visited `realpath`s. A directory reached twice fails by name. *Out of scope* asks that a loop fail rather than be handled, and without the set the recursion never ends.
- A read error is anything other than `ENOENT`. It fails with the path and the error code. File contents never go into an error.

**8. The sweep: one finder, two modes.** `findOrphanClaudeDirsEffect(options)` reports one finding per directory, with `stream: runId` and `action: dryRun ? 'reported' : 'removed'`, removed through the existing `removeOne`.
- **When not a dry run** (the daemon start, under the lock), it removes every one, on the ticket's reasoning that no run is live then.
- **When a dry run** (doctor, possibly beside a live daemon), it skips the directory of a run that is still live.
  - It finds the ticket the way `findOrphanLogsEffect` does (`reconcile.ts:390-393`).
  - It treats the run as live with the same check as the worktree scan: `claimed && life.runId === runId` (`:345`).
  - Without this, S4b's live runs would show up in doctor as leftovers.
- `reconcileEffect` adds it to `scanned` (`:735-740`).
- For the fake filesystem the Done-when asks for, add `fs?: { readdir; rm }` to `ReconcileOptions`, defaulting to `node:fs`. `removeOne` takes its `rm` from there.
- The removals reach the `Reconciled` event (`:786-800`) as paths and run ids, which carry no secret.

**9. Doctor.**
- The reach member is `claudeToken?: () => Effect<boolean, unknown>`. It answers *whether*, never the value, so doctor never holds the token.
- The row is named `claude: long-lived token`.
  - **Set:** `ok`, detail *set*.
  - **Not set:** `ok`, detail *not set — `claude setup-token`, then `claude.oauth_token` in `~/.lingtai/config.yml`*.
  - It stays `ok` either way because nothing needs the token until S4b. A warning on every machine would be noise, and S4b raises it to a failure when a recipe requires a sandbox for `claude-code`.
- **Unreadable file:** the row fails with decision 2's sentence.

**10. The leak test.** Use a fake token such as `sk-ant-oat01-FAKE-…`.
- Put it in the fake environment, then in the fake file, then in a fake file whose YAML is broken on the token's line.
- Drive the reader, the doctor row, a preparation that fails, and the sweep.
- Assert the string appears in no `trace`, `log`, error message or row detail.
- Assert `String(redacted)` does not contain it.
