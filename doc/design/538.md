## Design note — #538

Keep the change in the waiting page’s `TriageBand` and its styles. The band already selects content by cause, derives disagreement, and leaves absence, progress, and failure on separate paths (`apps/board/src/app/standing.tsx:75`, `apps/board/src/app/standing.tsx:110`, `apps/board/src/app/standing.tsx:167`). ADR 0118 says, “The parts belong to the cause” and “None of them is repeated beside the cause” (`doc/decisions/0118-a-hold-explains-itself.md:350`). Build the hierarchy from those existing parts; leave cause labels and resolution actions to their owners.

Load a self-hosted IBM Plex Serif face beside Sans and Mono in `layout.tsx`, then use it for the advised summary and the prominent question or comparison text. The layout comment says the fonts are self-hosted because fetching them at build time failed, and that `OFL.txt` must accompany the files (`apps/board/src/app/layout.tsx:6`). The current layout loads only Sans and Mono (`apps/board/src/app/layout.tsx:19`, `apps/board/src/app/layout.tsx:30`, `apps/board/src/app/layout.tsx:62`); the current summary rule sets size but no serif face (`apps/board/src/app/globals.css:1312`). Follow the type scale in `Outcomes.dc.html:68` and `Conflict.dc.html:70`.

Render fixes as one ordered white list on the triage surface, with separate number, location, and `what` columns. A null line should show the path alone: `LineFix.line` is nullable (`packages/domain/src/wait.ts:516`). For conflicts, show `total` and distinguish listed mechanical hunks from divergent hunks with labeled groups or rows. A mechanical hunk has only path and nullable line; a divergent hunk alone carries a question (`packages/domain/src/triage.ts:56`, `packages/domain/src/triage.ts:64`). Give mechanical rows no empty disclosure. Keep divergent questions open and reuse `TriageChoices`, preserving each question’s existing divergent index so answer selections still match the draft (`apps/board/src/app/standing.tsx:142`, `apps/board/src/app/triage-picks.tsx:29`). ADR 0118 requires the page to “list every hunk with its status and open only the ones that need the person” (`doc/decisions/0118-a-hold-explains-itself.md:473`). When `total` exceeds 20, the schema requires an empty hunk list (`packages/domain/src/wait.ts:534`); show the count and existing new-base explanation, with no per-hunk status or question. An empty zero-total list needs no invented rows.

For disagreement, retain the two comparison panels but make each reading scan as a labeled choice and its available explanation. Use the judge’s recorded `chose`, optional `why`, and existing raw evidence; use triage’s cause, summary, and cause-specific evidence on the other side (`packages/domain/src/wait.ts:588`, `apps/board/src/app/standing.tsx:183`). The mockup’s quoted diagnoses, round history, snippets, and prices are illustrative; `TriageResult` contains cause, resolution, summary, and `want`, but no such comparison fields (`packages/domain/src/wait.ts:571`). Keep the panels side by side at desktop widths and stacked at narrow widths, as the existing responsive rule does (`apps/board/src/app/globals.css:1383`).

Compare the rendered fixtures at both widths against the two references. The fixture source already supplies FixableLines and mixed ConflictingHunks cases (`apps/board/test/visual-waiting.ts:39`, `apps/board/test/visual-waiting.ts:50`); add or adapt a disagreement fixture and unit assertions for null lines, empty lists, and the past-limit result. Run the ticket’s four build checks, without the integration suite.
