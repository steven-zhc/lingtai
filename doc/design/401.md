# #401 — design note

## The shape

There are five routes under `apps/board/src/app/setup/`, and they come out three ways:

| Route | Fate | Why |
|---|---|---|
| `github-app/page.tsx`, `github-app/start/route.ts`, `github-app/created/route.ts` | **kept**; only the copy in `page.tsx` changes | This is the manifest flow. `start/route.ts:106` sends GitHub `redirectUrl: …/setup/github-app/created`, and the terminal opens `/setup/github-app` (`apps/cli/src/github-app.ts:110`, pinned by `apps/cli/unit/github-app.test.ts:130`). |
| `repository/installed/route.ts` | **kept, untouched** | See the decision below. |
| `repository/page.tsx` | **reduced** to one screen that names `lingtai add` | Something still opens it (see below). |
| `wizard/page.tsx` | **reduced** to the same one screen | `/setup/repository` linked to it with `?repo=` (`repository/page.tsx:316`). A bookmarked URL should answer something rather than 404. |
| `wizard/wizard.tsx`, `wizard/finish.ts` | **deleted** | Nothing outside `setup/wizard/` imports them except `apps/board/unit/wizard.test.tsx:16-17`. Delete that test file with them. |

## The decision the ticket does not make: `/setup/repository` stays as a URL

GitHub has more than one way to send a browser to the repository pages, and the terminal has one more:

1. **Every App this board ever created carries a setup URL.** `start/route.ts:107-109` puts it in the manifest: *"Installing comes back to the repository picker (#168)"*, `setupUrl: …/setup/repository/installed`. That URL now sits in Apps on GitHub's side, where nothing in this repository can change it. `installed/route.ts` then sends a 303 to `/setup/repository` (`installed/route.ts:29-31`, and `packages/conductor/src/pick-repository.ts:382` builds the target). Delete either route and installing an App lands on a 404. That is the same class of break as the callback the ticket warns about. It is one hop later, and no test would see it.
2. **`lingtai init` opens `/setup/repository` in a browser** (`apps/cli/src/init.ts:593`, `:621`) and prints it (`:604`). `apps/cli/integration/init.test.ts:419,451,652` assert it. Those are integration tests, so nothing in this pass can re-run them if init's URL changes.
3. The board's own `+` sends there (`apps/board/src/app/projects.tsx:58`), and `apps/board/unit/projects.test.tsx:42,51,108` pin that href.

So **keep the path and replace the screen**. Leave `installed/route.ts`, `start/route.ts`, `init.ts` and `projects.tsx` as they are. Rewriting init's handoff belongs to the CLI and to #400, not to this ticket ("Keep removals inside the pages being removed"). What it costs: `init` will open a browser onto a page that says "run `lingtai add`". That is redundant but true, and `init.ts:611` already prints the same sentence. Say so in the commit body and leave it there.

## What the reduced screen says

Both `repository/page.tsx` and `wizard/page.tsx` render the same server component:

- the bar used by every other setup page, as in `github-app/page.tsx:50-56`;
- one `note`: choosing a repository and writing its recipe happen in the terminal, `pnpm lingtai add`, which picks from what the App can see (#394, `apps/cli/src/add.ts:2-4`). `lingtai add <owner>/<repo>` is the form for one you already know.

Put that component in one small file, for example `setup/terminal.tsx`. It has no `'use client'` and imports only `next/link`. **It reads no `searchParams` and makes no call to GitHub, the env or the log.** `?installed=` and `?requested=1` still arrive from `setupReturn` and are ignored.

- **No `'use client'`:** with the wizard gone, `wizard.tsx` is the only `'use client'` file under `setup/`, and deleting it removes the one graph a server-only import could reach. A replacement that adds a client component or a new package import brings back the risk that only `apps/release/integration/build.test.ts` sees after the merge (#230). The stand-in check you can run now is that the new file's imports are `next/link` and nothing else.
- **No `searchParams`:** a screen that rendered the `?repo=` text back would be inventing a slug check it doesn't do.

## The copy in the kept App page

`github-app/page.tsx` sends the person on to the picker in three places: `:223-224` (*"GitHub brings you back to the repository picker"*), `:254-255` and `:259-260`. Rewrite each so the next step is `lingtai add`. Keep the install links (the `installUrl`, and `https://github.com/apps/<slug>/installations/new`), because installing can only happen on GitHub's screen in a browser. Change nothing else in that file. `offerCreation`, `Create`, `Unfinished`, `Unanswered` and `Unreadable` are the flow.

## Tests

- **`apps/board/unit/github-app.test.tsx` must pass with only additions.** It is the unit-level check for the first *Done when*. The full exchange — a code from GitHub returns `GitHubAppCreated`, then the key file, then `config.yml` — is checked in `packages/conductor/integration/create-app.test.ts`, which is out of reach here. That is acceptable only because none of `create-app.ts`, `start/route.ts` or `created/route.ts` changes, so keep it that way. A diff that touches any of them can't be verified before the merge.
- **Add to `github-app.test.tsx`:** render `Created` (an `outcome.ok` offer) and `Configured` (both `installUrl` branches). Each names `lingtai add` and neither contains `/setup/wizard`.
- **Replace `apps/board/unit/pick-repository.test.tsx`** (it imports `RepositoryScreen`, `:14`) with a test of the new screen. It renders, names `lingtai add`, and contains no `<form` and no `?repo=`. That covers the second *Done when* for both reduced routes.
- **Delete `apps/board/unit/wizard.test.tsx`.** What it asserted about `editExisting` goes with the file.

## Leave alone

These look dead once the pages go, but they aren't, and `pnpm typecheck` won't flag them either way:

- `@lingtai/conductor/pick-repository` and `/wizard`: the terminal uses them (`apps/cli/src/add-github.ts:212`, `apps/cli/src/first-project.ts:51,613`).
- `setupReturn`: `installed/route.ts:30` still calls it.
- `@lingtai/conductor/wizard-page`: its import guard (`packages/conductor/unit/wizard-page.test.ts:705-718`) names `wizard.tsx` only in a comment, and stays correct whether or not that file exists. Leave the module where it is.

## Comments and docs that name the deleted files

Update these, because each one cites code that will no longer exist:

- `apps/board/src/lib/recipe.ts:420`: *"as `setup/wizard/page.tsx` already does"*. Drop the comparison.
- `doc/reference.md:98-100`: it names `apps/board/src/app/setup/wizard/finish.ts` as where `startOnboarding` is called. That is now the terminal, through `apps/cli/src/add-github.ts`.
- `doc/operating.md:652-653`: it describes the `+` as reaching the picker.
- `repository/page.tsx:29`: its header says *"the wizard (#164), or `lingtai add`"*. It goes when the file is rewritten.

Leave the `doc/design/*.md` notes for #375, #314, #393 and #394 alone: they are records of their own tickets. No accepted ADR is contradicted. 0114 (`doc/decisions/0114-a-github-app-not-a-token.md:60`) names only `/setup/github-app`, and that page stays.

## Checks

Run `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test` and `HOME=/nonexistent pnpm test`. Each of them reaches every file this change touches. The Next build is the one check they can't stand in for, and the no-new-imports rule above is what keeps it from being needed.
