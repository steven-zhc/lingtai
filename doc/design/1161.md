# Design note for #1161: the Sandbox tab

## The decision the ticket leaves open: where the fold lives

S8 appends `SandboxBoundaryRecorded` and `SandboxConnectionsRefused` (`packages/domain/src/events.ts:965`, `:986`). Nothing reduces them yet: neither type appears in `packages/domain/src/attempt.ts`. Only `apps/board/src/lib/history.ts:363-364` uses them, and only to write history lines. The ticket says *by the attempt stream's own reducer*, so:

- **Add `sandbox` to `AttemptState`** (`attempt.ts:150-218`, with `emptyAttempt` at `:220`). Use an ordered list of invocations keyed by **`commandId`**: `{ commandId, step, action, runtime?, runId, version, at, boundary, refusals: null | read }`. Add two `case`s to `reduceAttemptEvent` (`:411`). `SandboxBoundaryRecorded` adds the row. `SandboxConnectionsRefused` sets `refusals` on the row with the same `commandId`. A refusal whose `commandId` has no boundary still gets a row, with `boundary: null` and the step, action and runtime from the event's own keys, so it is never dropped.
- Key on `commandId`, not on `runId` or step/action. The schema states that `commandId` names one invocation (`events.ts:952`). `sandbox-record.ts:10-11` says *"`runId` is per attempt, so an invocation is keyed by step and action … and by the wrap's `commandId`"*. Step and action repeat across fix rounds, so `commandId` is the only key that cannot collide.
- **Bump `attemptReducer.version` from 4 to 5** in `packages/domain/src/run-codec.ts:176`, with a comment line like the others: *"a version-4 snapshot was cut by a reducer that ignored the sandbox events."* Make sure `parseStored` (`:134`) accepts the new field. The board folds with `reduceAttempt` directly (`apps/board/src/lib/task.ts:1744`), but the daemon snapshots this reducer (0124). A v4 snapshot read by the new code would be missing the field. The version check makes such a snapshot void rather than wrong.
- Read `states[n-1].sandbox` from `readAttempts` (`task.ts:1744`, `:1809`). That is the one fold. Do not `readTypes` and do not filter `streams` by type in the board.

## The view: one pure function, one component

- `apps/board/src/lib/sandbox-view.ts` holds a pure function `(invocations, lifecycle, endedSteps, project) → SandboxView`, with no React and no reads. It takes the `AttemptState` slice, not events and not a recipe. It returns the three parts, the rows and the Blocked groups. The test for *the view's inputs are events only* is the function's signature: its unit test builds `AttemptState` by running `reduceAttempt` over fixture envelopes and passes nothing else. Add one assertion that the module imports nothing from `@lingtai/recipe` except `isNetworkEntry`.
- `apps/board/src/app/sandbox-panel.tsx` is the component S9b reuses. It takes `SandboxView` as props and imports nothing from `@/lib/task`. That is the ticket's cost-to-later-tickets edge. Keep it a server component, or at least never import `node:*` into it. The view module below imports `@lingtai/sandbox`'s `policy.ts`, which imports `node:path` (`packages/sandbox/src/policy.ts:1`). Only the Next build (`apps/release/integration/build.test.ts`) catches a server-only import reaching a `"use client"` graph, and that runs after the merge (CLAUDE.md, #230).
- The route is `apps/board/src/app/task/[id]/sandbox/page.tsx`. It has `searchParams: Promise<{ attempt?: string }>`, parsed with `attemptOfSegment` (`apps/board/src/lib/tabs.ts`, last function). Absent or invalid means the newest attempt; a number this ticket does not have means `notFound()`. Model it on `attempt/[n]/page.tsx`: `guarded(...)`, with `TabFailed` on a failed read (`apps/board/src/app/tab-view.ts:12-19`). It must **never call `loadTask`** (layout comment, `layout.tsx:33-37`). Add `loadSandboxTab(taskId, n)` beside `loadAttemptTab` (`task.ts:2064`), calling `readAttempts` and nothing else, and in particular not `recipesFor`.
- Live updates come free: `<Follow>` wraps the layout's children (`layout.tsx`, the default export), so an append refreshes this segment as it does the attempt tab.

## Tabs

`TabKey` becomes `{ attempt: number } | 'ticket' | 'sandbox'` (`tabs.ts:10`). Then:

- `tabPath` gains `/task/<id>/sandbox`.
- `sameTab` (`:32`) must stop assuming *not ticket ⇒ attempt*. It currently reads `a.attempt` whenever neither side is `'ticket'`, so compare the string keys first.
- `selectedOf` in `record-tab-row.tsx:29-34` maps the `sandbox` segment.
- `visibleAttempts` (`tabs.ts`, `selected !== 'ticket'`) must also exclude `'sandbox'` before reading `.attempt`.
- `defaultTabOf` does not change, and the test asserts it never returns `'sandbox'`.

Put the Sandbox link in `RecordTabRow` after the Ticket. The attempt switcher inside the tab is a list of `<Link>`s to `?attempt=<n>`, not a client-side select (#885).

## Rules the code has to settle

- **Built-in vs recipe.** The recorded `policy.allowedDomains` carries no source (`events.ts:927-935`), although the ticket's S8 contract says it does. Do not change S8's event in this ticket. Instead:
  - Mark a domain *built in* when it is in `BUILT_IN_DOMAINS` (`packages/sandbox/src/policy.ts:53`), and *recipe* otherwise. The other additions are `project_additions` and `caller_additions` (`policy.ts:149-150`), so *recipe* is the honest word for the project's own.
  - Add `"./policy": "./src/policy.ts"` to `packages/sandbox/package.json` exports, and `@lingtai/sandbox` to the board's deps. Do not import `.` — the index re-exports `live.ts`.
  - Write in a comment that this classifies against today's built-in list, and that the domain set itself is the recorded one.
- **State of a row**, from `boundary`:
  - `sandboxed` → *Sandboxed*
  - `unsandboxed`/`off by choice` → *Off by choice* (muted)
  - `unsandboxed`/`degraded` → *Degraded* (signal, with `why`)
  - `refused` → *Stopped* (fail, with `why`)
  - no boundary → *not recorded*

  These are the four states in `doc/milestone/0.14.0/0.14.md:324-329`. `policy.weakerNetworkIsolation` adds the words *weaker network isolation*; it is not a state (`0.14.md:331-332`).
- **When "none refused" is true.** `SandboxConnectionsRefused` is appended *"only when something was refused, the read failed or entries were lost"* (`events.ts:982-983`, `worthRecording` at `packages/sandbox/src/refusals.ts:103`). So the absence of the event means *none* **only once the read has happened**. The read is the finalizer inside the wrap's scope (`sandbox-record.ts:4-7`, `process-action.ts:146-147`). That scope closes inside the action, before the step ends. The rule, by the state of the refusal read and the run:

  | Refusals | Step ended? | Run (`lifecycle`) | The row says |
  |---|---|---|---|
  | recorded | — | — | the refusals |
  | none | a `StepEnded` for the same `outcome.step` at a version after the boundary's | — | *none refused* |
  | none | no | `running` | *refusals are read when the run ends* |
  | none | no | over | *refusals were not read: the run ended inside this step* (fail colour) |

  Never draw zero in either of the last two. For this the reducer must also keep the versions of `StepEnded` per step (`StepOutcome.step`, `packages/domain/src/action.ts:246-250`), or record on each invocation that its step ended. Do the latter in the same `case 'StepEnded'`, so the view needs nothing else. Whether a refusal ever lands after its `StepEnded` is settled by the stream's versions on a real attempt (`SandboxConnectionsRefused.version < StepEnded.version` for the same step). If it does, the rule above shows the refusal anyway, because recorded refusals take precedence.
- **Blocked:**
  - Group by `host ?? line`, so an entry with no host or port is grouped by srt's raw line (`SandboxRefusedEntry`, `events.ts:971-978`).
  - Sum `count`, take the earliest `firstAt`, and list the commandIds it came from.
  - Exclude `telemetry: true` from both the groups and the count.
  - Any invocation with `read.kind === 'unreadable'` or `complete: false`, or in either of the last two table rows above, puts a fail-colour sentence above *Blocked* naming it. The list still draws what it has.
- **Allow link.** Offer it when `host !== null && isNetworkEntry(host) && !METADATA.has(host)`, where `METADATA = ['169.254.169.254', 'fd00:ec2::254', 'metadata.google.internal']` is a constant in `sandbox-view.ts`. Neither `@lingtai/recipe` nor `@lingtai/sandbox` has one today: no match for `169.254` in either package. `isNetworkEntry` already rejects both IPs (its `HOSTNAME` regex has no colons, and `169.254.169.254` passes the regex, so the explicit set is what stops it). Build the href as `/recipe/${encodeURIComponent(project)}?edit=1&allow=${encodeURIComponent(host)}#sandbox`.
- **Limited.** `denyRead` and `denyWrite` come from the recorded policy. The authentication sentence appears only when some row's `runtime === 'claude-code'`. The three *Not covered* lines are fixed text.

## The mark on the attempt tab

`AttemptTab` gets the attempt's `sandbox` slice. Today it reads `detail.run`, whose `presentAttempt` row is built from `states[i]` (`task.ts:1749`), so carry it on that row or on `AttemptTabDetail`.

In `.acts` (`apps/board/src/app/attempt-tab.tsx:315-342`), beside each `name`, draw the mark of the **latest** invocation (by version) whose `step === p.step && action === name`. Draw nothing when there is none. Put the mark in its own small component, e.g. `SandboxMark`, in `sandbox-panel.tsx`, so S9c can reuse it. Its accessible name is the state word, never *safe*.

## Edges the ticket did not settle

- **A failed read**: `guarded` already turns any throw into `TabFailed` (`tab-view.ts:12-19`), so the tab never draws an empty *Blocked* from a failed read.
- **An attempt with no sandbox events at all** (before S8): every planned action reads *not recorded*. The rows come from `resolved.steps` (`attempt.ts:179-182`) where there is a plan, so the tab says *not recorded* rather than drawing nothing.
- **The ratchet** (`packages/domain/unit/effect-ratchet.test.ts`): `loadSandboxTab` sits beside `loadAttemptTab`, which is `async`. Add no new `async` function. Write it as an Effect, and run it only at the page, which is a host edge. Do not raise `effect-ratchet.baseline.json`.
