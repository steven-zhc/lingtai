## What "allows" means: from `filesystemFor`, not from the ADR

`packages/sandbox/src/policy.ts:120-146` is the source for the *allows* half:

- **Reads:** a run may read everything except `denyRead` plus the project's `deny`. The worktree, the mirror and `~/.lingtai/cache/<project>/` are allowed back inside the denied state directory (`allowRead`, `:127`). The comment there, *"allowRead overrides denyRead"*, is why a `deny` inside the worktree or the mirror is refused.
- **Writes are an allowlist:** the worktree, the mirror, the temp roots (`tempRoots`, `:105-111`: `/tmp`, `/private/tmp` on macOS, and `$TMPDIR`), the cache directory, and the project's `write`.
- **Never writable:** the mirror's `config`, `hooks/` and `info/`, and the hook-socket directory (`denyWrite`, `:136-145`).
- **Network:** `BUILT_IN_DOMAINS` plus `network.allow` (`runDomains`, `:154-156`).
- **Unix sockets:** Linux gets `allowAllUnixSockets: true`; macOS allows only the hook-socket directory (`:160-162`).
- **macOS** also gets `enableWeakerNetworkIsolation` (`:165`).

0127 §12 says the deny list is *"unreadable and unwritable"*. In code, the built-in list is only `denyRead`. Those paths can't be written because they are not on the write allowlist. Write it that way: *a run writes only where this list says*. Don't present a deny-write list that isn't in the code.

## Shape of the page

Keep lines 1–3 as they are: `# Safety`, a blank line, then an italic subtitle. `apps/site/unit/docs.test.ts:442-460` checks that the title is `Safety`, that line 3 matches `^\*[^*].*\*$`, and that the lede is neither empty nor the subtitle. Put **"from v0.14.0"** in the lede itself, together with the fact that a v0.13 install has none of this.

Suggested sections, in order:

1. **What the sandbox refuses and allows.** One boundary, `srt` `0.0.83`. Then the read, write and network lists above, each naming its file. Then telemetry: refused like any other host, recorded on the run, and kept out of what a person is shown (§17).
2. **Turning it on.** Cover the four states and what each one does. A new project gets `sandbox: { enabled: true }` from setup (`packages/setup/src/setup-answers.ts:140-145`, and *"Never `required`"*). An existing project's recipe is not touched (`:103-105`), and an absent block is off.

   Then show one complete block with a comment on each key giving its §13 rule. Use values the schema accepts:

   ```yaml
   sandbox:
     enabled: true
     required: true
     network:
       allow: [pypi.org, files.pythonhosted.org]
     write: [~/work/fixtures]
     deny: [~/secrets]
   ```

   Then name what is refused at resolve, in the sentences `refusalSentence` uses: a `write` that is, lies inside or contains a protected path, or that is or contains `$HOME`; and a `deny` inside the worktree or the mirror.

   Then say that `runtime.tier` is refused and give its replacement by value, quoting `packages/recipe/src/resolve.ts:295-305`. A reader of the old page will have written `tier: sandboxed`.
3. **The Claude token.** `lingtai token claude`, the two sources and which wins. The token sits inside the run, so it belongs on the §18 list too.
4. **Checking the host.** `lingtai doctor`'s two row kinds and the canary.
5. **On the board.** Name the surfaces only: the Sandbox tab on the task page, the recipe page's section, the shield, and the *degraded*/*stopped* banners. Cite the tickets (#1161, #1162, #1183, #1167), not component files. Add that a refused connection stops the step for a person with no fix round (0127 §14), and that refused connections are on the attempt's stream while refused file reads are not (§2).
6. **When the host cannot sandbox.** `required: false` runs unsandboxed and marked; `required: true` refuses the project. Under `required: true`, a host that loses the sandbox mid-attempt fails the attempt (§14).
7. **What the sandbox does not cover.** All **six** items of §18, including the one the ticket left out: *on macOS a run can read other processes' command lines, and so for a moment another run's network id, which gives that project's allowlist*. Also include `gh` being closed (§5) as something the operator should know.
8. **Without the sandbox.** For projects that are off or degraded, keep the current runtime table and its measured cells and sources. Drop the *"Lingtai gives it no filesystem sandbox"* wording: say *"with the sandbox off"*. Drop the `guarded`/`sandboxed` tier paragraph and line 59 entirely. Keep the two `operating.md#what-your-own-runtime-configuration-can-narrow` links. That heading exists, and `docs.test.ts:355-385` fails on any anchor that lands nowhere.
9. **What to do / reporting a vulnerability.** As now.

**Measured.** The only new measured facts available are experiment 017's (`doc/milestone/0.14.0/017-srt-under-lingtai.md`), which 0127 cites. For example, *"the denied whole and the allowed back are measured in 017"* (§12). Cite 017 by name wherever the page says "measured". Everything else on the page is *"the code does X"*.

## Where code and ADR disagree (PR body, not the page)

- 0127's status reads *"not yet built"* and *"Not built: the code still carries the tier"* (`:3`, `:15`). But `resolve.ts:281-305` refuses `runtime.tier`, and `resolve.ts:155-161` writes `tier: 'guarded'` back only for `configHash`. The page follows the code: there is no tier to write.
