## Decisions the ticket does not make

### 1. `readUnheldFixLandings`: get candidates from the integration events, not from `landingsStarted`

There are two traps in the ticket's wording, "the ticket ids `landingsStarted` names".

- **The ids are stream ids, not issue numbers.** An integration event's `ticketId` is the ticket's stream id. `landingsInFlight` reads it directly with `store.read(started.ticketId)` (`pr.ts:571`). `PrFixLanded.ticket` and `pr.tickets[].ticket` are the issue, as the comment at `packages/conductor/src/ticket/commands.ts:935` says: *"`PrDraftTicketAdded.ticket` is the issue … never the stream's id."*
  - Convert each id with `parseTicketStream` (`packages/domain/src/streams.ts:36`).
  - Drop any id that does not parse or whose `project` is not this one.
  - Read the ticket with `ticketStream(project, issue)`, exactly as today.
- **`landingsStarted` drops tickets that did land.** It keeps only each ticket's *last* integration event, and if that event is a refusal other than `unexpected` it emits nothing for the ticket (`packages/domain/src/pr.ts:1171-1180`). So a ticket that succeeded on the PR branch and was later re-attempted and refused (for example `no-commits`) disappears. Today's code still finds that ticket, because `reduceTicket(...).landed.base === pr.prBranch` decides it (`pr.ts:741`). That breaks the Done-when promise that the result "equals today's".
  - **Decision:** the candidates are the distinct `ticketId`s of every `IntegrationAttempted`, `IntegrationRefused` or `IntegrationSucceeded` event on `integrationStream(project, pr.prBranch)`. This is one read, and no other stream is read.
  - Everything after that stays as it is today: the `pr.tickets` skip, `state.landed.base !== pr.prBranch`, `landedSeq`, and the sort.
  - A ticket that was refused or is still in flight is skipped by its own stream, as the ticket's Edges section says.
  - Add a unit case for the success-then-refusal sequence, beside the read-counting test.

`landedSeq` **stays**: `readUnheldFixLandings` still uses it (`pr.ts:742`). `teamSince` (`domain/src/pr.ts:1093`) is only used by `readDraftOn` (`pr.ts:686`), so it goes.

### 2. `landNow` stops asking GitHub

At `conduct.ts:4002`, `options.client.listOpenIssues()` exists only to build the candidate list for `readUnheldFixLandings`. Delete it along with the list.

This changes two things, and both are wanted:
- A GitHub outage no longer turns the mend into `notMerged: 'unreachable'`. Only the store can fail it now.
- A fix ticket whose issue was closed after it landed is now mended. Today it is not, because closed issues are not "open issues".

### 3. The board's `readDraftOf` reads the draft itself and no longer checks the other PRs

`readProjectPrs` skips a PR in `draft`: `if (pr.status === 'draft') continue` (`apps/board/src/lib/prs.ts:78`). So the draft cannot be derived from the `prs` the board already holds.

- `readDraftOf(project)` calls `readDraftTickets(project, eventStore)`.
- Drop its `recipe` and `prs` parameters. All four callers (`:152`, `:203`, `:329`, `:458`) already check `modeOf(recipe) !== 'team'` before calling it.
- Drop the `unread` short-circuit (`:103-104`). It existed because the computed draft treated every PR's tickets as held. The draft is now one stream's state, and a lower PR that could not be read is drawn as its own error card.
- Keep `Effect.catch` → `{ error }`. A failed read of a PR stream or a title still means "could not be read".
- `listPrs` walks the PR streams a second time on these pages. The ticket's Out of scope section accepts that cost.

### 4. `readDraftTickets(project, store)`

- Put it in `packages/project/src/pr.ts`, beside `readDraft`, as an `Effect.gen`. Do not add `async` and do not raise the ratchet.
- For each entry, read `ticketStream(project, t.ticket)`, run `reduceTicket`, and return `{ ticket, mergeCommit: t.mergeCommit, title: state.title ?? '#' + ticket }`. `PrDraftTicketAdded` already carries `mergeCommit` (`domain/src/pr.ts:44-45`), so `PrDraftTicket` (`pr.ts:584`) keeps its shape.
- **Order changes.** The order is now the order on the stream (`draft` is *"in the order they joined"*, `domain/src/pr.ts:44`), replacing `readDraftOn`'s sort by landing time (`pr.ts:719-720`).
  - Landings join in landing order.
  - A closed PR's handed-back tickets (`ticketsHandedBack`, `domain/src/pr.ts:1043`, appended at `pr.ts:526`) come after the tickets already there.
  - Accept this; it is not a change to what is shown.

### 5. The team → solo refusal

- In `change.ts:190-192`:
  - keep `(yield* listPrs(project, store)).filter(isOpen)`, because `modeSwitchMessage` takes a list;
  - replace `readDraftOn` with `readDraft(project, store)`. The message uses only `t.ticket` (`change.ts:98`), so it needs no titles.
- Narrow `modeSwitchMessage`'s `draft` parameter to `readonly { readonly ticket: string }[]`.
- `personalOf` (`:71`) stays for the message's wording. Its comment mentions `readPrDraft`; reword it.
- Delete `ChangeOptions.candidates` (`:59-65`) and the refusal at `:182-188`, which says *"this caller cannot read what has landed"*.
- In `apps/board/src/app/actions.ts:1169-1176`, remove the `candidates` closure and the `EVERY_LANDED_ROW_DAYS` and `readTasksEffect` imports at `:78`, if nothing else in that file uses them.
