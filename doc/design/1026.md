## Design note: #1026, one mirror write at a time

### The decision the ticket leaves open: the list is short of its own *Want*

The *Want* says **every** git command that writes a mirror. The *Evidence* list covers only `worktree.ts` and `integrate.ts`. `packages/conductor/src/conduct.ts` also writes the mirror. Its `gitAsked` runs in the attempt's worktree (`conduct.ts:1828`), and a worktree shares the mirror's refs and `worktrees/` metadata (the comment at `conduct.ts:1928` says so: *"`gitAsked` runs in the worktree, which shares the mirror's refs"*). Wrap these too, keyed by `mirrorPathFor(project, home)` (`mirror.ts:31`):

- `keepHead`'s `update-ref` (`conduct.ts:1934`) and `dropKept`'s `update-ref -d` (`:1943`), which write `refs/lingtai/unpushed/…`.
- The landing's drop of kept refs, `update-ref -d` in the loop at `conduct.ts:4732`. Wrap each command separately; the `for-each-ref` before them is a read.
- The base check's tree: `cut`'s `worktree add` (`conduct.ts:3167`) and `remove`'s `worktree remove` (`:3181`). The `submodule update` after the cut runs in the new tree and is not held.
- `removeWorktree`'s `worktree prune` (`worktree.ts:227`). It is a mirror write the ticket's list misses, and it is the `repo.remove` finalizer every pass runs (`conduct.ts:1822`).

**Not held**, and the code should say why in a comment:
- `ownChangeStart`'s fetch (`conduct.ts:322`) and `mergeBase`'s fetch (`:3116`) are `fetch origin refs/heads/<base>` with no destination. They write only the worktree's own `FETCH_HEAD` and objects. The mirror has no `refs/remotes/origin/*` to update (`worktree.ts:70-72`: *"this mirror is bare and fetches `+refs/heads/*:refs/heads/*`, so there is no `refs/remotes/origin/*`"*).
- Pushes, from the agent's worktree or the integrator's (`integrate.ts:664`), also write no mirror ref.

Object writes are safe concurrently in git; ref and `packed-refs` locks are what §6 is about.

### `ensureMirror` holds the presence check too

This is the one place a read goes inside the hold. Today two provisions on a project with no mirror can both read *absent* at `worktree.ts:114`. Serialising only the clone does not fix that: the second waits, then runs `rm(path)` (`:125`) on the mirror the first just cloned, possibly after the first's `worktree add`.

So the `rev-parse --git-dir`, then *fetch* or *rm + clone + `remote set-url`*, is **one** hold. It is one decision about the mirror and one write. The `mkdir` of the parent directory can stay outside.

### The primitive: `packages/repo/src/mirror-lock.ts`

Shape it like `landing-lane.ts:34-63`: a `Map<string, Promise<void>>` of tails keyed by `resolve(path)`, with the key deleted when its chain drains. Leave out `holder` and `onWait`, which nothing here needs.

Write it without the `async` keyword. The baseline is `"packages/repo": { "async": 15, "run": 1 }` (`effect-ratchet.baseline.json:6`).

- **`acquire(path): Promise<() => void>`** is the core. It resolves with a release function once everything queued before it has settled.
- **`withMirrorWrite(path, run)`** is `acquire(path).then((release) => Promise.resolve().then(run).finally(release))`. Do not write `run().finally(release)`: a `run` that throws synchronously never reaches `.finally`, and the permit leaks.
- **`mirrorWrite(path, effect)`** is `Effect.acquireUseRelease(Effect.promise(() => acquire(path)), () => effect, (release) => Effect.sync(release))`.

**Why `mirrorWrite` is not an Effect `Semaphore`:** the promise callers would then need `Effect.run*` to take it, and that raises the `run` count. One map serves both forms, and it has to: a provision (promise) and a landing (Effect) contend for the same mirror.

**The trap is an interrupt while waiting.** `acquireUseRelease`'s acquire is uninterruptible. An interrupt that arrives while `mirrorWrite` is queued therefore waits for the grant, runs no `use`, and releases. That is correct, and it costs only a wait behind a holder, which is already the no-timeout rule. Do **not** make the acquire interruptible (`Effect.raceFirst`, an abortable `Effect.promise` signal, `Effect.interruptible`). An abandoned queued promise would still be granted the permit later, nobody would release it, and that mirror would be wedged until the conductor restarts.

Export `withMirrorWrite` and `mirrorWrite` from `packages/repo/src/index.ts` so `conduct.ts` can reach them.

### At the call sites in `integrate.ts`

Wrap the `at(…)` in place: `mirrorWrite(mirror, at([...], mirror))`, and put `Effect.ignore` *outside* the wrap where it is already present. This covers the lane fetch (`:494-497`), the lane-ref deletes inside the `acquireRelease` release (`:471-472`), every sweep write (`:412`, `:417`, `:428-429`) and the base's compare-and-swap (`:683`).

For the worktree pair (`:514-516`), wrap the *acquire* and the *release* separately. The scope between them, which holds the merge, tests and push, holds no permit. That is the ticket's main *Watch out*.

The sweep's `rm` of a directory (`:413`) is filesystem work, not git, and stays outside.

The key strings differ but meet. `integrate.ts` builds `${home}/repos/${project}.git` (`:452`), and `worktree.ts:87` uses `join(home, 'repos', …)`. `resolve` makes the two equal; one test case should prove it.

### Tests (all unit; nothing here needs `test:integration`)

- **The primitive:** writers on one path run in FIFO order; writers on two paths overlap; a throw releases (both the promise form and a synchronous throw); an Effect interrupted while queued releases, and the writer behind it runs; the map is empty after it drains. Use deferreds, never timers.
- **`integrate`:** `packages/repo/unit/integrate.test.ts` already has a fake git port (`fakeGit`, `:31`). Hold `withMirrorWrite(mirrorPath, …)` open from the test. Assert the lane's `fetch` is not called until it is released, and that holding a different project's path does not delay it. Assert from the recorded `calls` that no permit is held while `merge` runs.
- **`provisionWorktree`:** `worktree.ts:18` imports `git` directly and the function touches `node:fs/promises`. Use `vi.mock` for `../src/git.ts` and `node:fs/promises` to keep it unit (no disk, per 0060 §1). Do not add a git port to `ProvisionOptions`: #790's `repo` conversion reshapes that signature, and a port added now is one more thing it has to carry. Assert `worktree add` waits for a held permit on the same mirror and not for one on another path. Also assert that two concurrent `ensureMirror`s on an absent mirror clone once (the second sees it present).
- **`conduct.ts` sites:** no new harness. A reviewer checks them by reading the diff, as the ticket's third *Done when* says.

### What would show it working after the merge

Production `events` are not readable from a pass, and §6 has no event of its own. On the conducting machine, the signal is the failures it removes: fewer `IntegrationRefused` with `reason: "unexpected"` whose detail carries `cannot lock ref` or `packed-refs.lock`, and fewer run-log notes of a failed provision fetch. Neither can be checked before the merge.
