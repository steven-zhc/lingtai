## Design note

Make the existing `subject` in `Standing` the ticket section, and place it before the state readout. Pass it the body and the current wait’s `want` from `TaskBody`; do not add another title. This changes the current order: `Standing` draws the state before `subject` (`apps/board/src/app/standing.tsx:286`, `:305`). The accepted decision is explicit: “The page is in this order: the ticket, where it is, triage, the resolutions, the record” (`doc/decisions/0118-a-hold-explains-itself.md:278-282`). Adjust the standing layout and its order assertions accordingly.

Derive `want` while `loadTask` has the ticket’s events and current wait. Its `StandingView.reason` is set only for a blocked lifecycle, while `waitId` can also remain on an approved one (`apps/board/src/lib/task.ts:493-501`, `:765-766`). For a blocked wait, use `triageFactsOf(own, waitId)` and pass those facts through `triageStatus`; read `result.want` only from `Done` with `TriageAdvised`. `triageFactsOf` takes “only the latest attempt’s result” for the named wait (`packages/domain/src/read-model.ts:102-109`), matching the projector’s facts (`packages/projector/unit/task-view-triage.test.ts:40-52`). This keeps the sentence paired with the wait folded for this page. The event fields that settle it are `WaitStarted.waitId`, `TriageStarted.attempt`, and `WaitTriaged.result.want`. Render the result in a labelled text node: the design says the sentence is “labelled as triage’s reading, never as the ticket’s words” (`doc/design/task-detail-page.md:16-19`).

Cut the body at a fixed physical line boundary before passing the cut to `DocumentBody source="ticket-body"`; put that rendered opening inside a closed `<details>` below the subject. Link a longer body to `#record-ticket`: `RecordTabs` selects the panel named by a fragment (`apps/board/src/app/record-tabs.tsx:31-59`, `:75-92`). Keep the full body in the Ticket panel (`apps/board/src/app/task/[id]/page.tsx:642-651`), where the existing `Ticket` uses `DocumentBody` (`:93-97`). The renderer’s comment calls the body “untrusted input” and requires sanitisation (`apps/board/src/app/markdown.tsx:10-29`); the opening must use that same policy.
