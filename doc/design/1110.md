# #1110: design note

The ticket covers the shape. This note covers five choices it leaves open or gets slightly wrong. Line numbers are this worktree's.

## 1. `waitForAppEffect` uses `Effect.raceAllFirst`, not `Effect.raceAll`

The ticket says the two "are equivalent here". In effect 4.1.2 they are not.

- `raceAll` is first *success* wins: *"Early failures do not finish the race; `raceAll` keeps waiting until one effect succeeds or every effect has failed"* (`node_modules/.pnpm/effect@4.1.2/node_modules/effect/dist/Effect.d.ts:8662`).
- `raceAllFirst` (`:8717`) is first *settled* wins. That is `Promise.race`, which is what `github-app.ts:129-133` does today.

Under `raceAll`, a `pressed` that rejects would no longer fail the wait. It would sit until the App appeared or the timeout fired, and the rejection would never be reported. The ticket's own Fix says "a rejection keeps its own message", which needs `raceAllFirst`.

The three entrants:

- `Effect.tryPromise({ try: (signal) => world.appeared(signal), catch: (e) => e })`, mapped to `{ made }`.
- The same for `world.pressed`, mapped to `'skipped'`.
- `Effect.sleep(waitMs)`, mapped to `'timedOut'`.

The `AbortController` and the `finally` at `:122-140` go away. Interrupting a loser aborts the `signal` that `tryPromise` handed it, and an interrupted `sleep` clears its own timer. That is what the comment at `:136-138` asks for (*"a signal left live would leave `pressed`'s raw mode never undone"*). The `open` call and the two log lines (`:115-120`) stay before the race, in the same order. `open` is lifted the same way.

Done-when test: `appeared` never answers, `pressed` answers. Expect `{ skipped: true }`, and `appeared`'s signal has `.aborted === true`. Add a second case: `pressed` rejects with `new Error('tty gone')`. Expect `waitForAppEffect` to fail with that message. This pins `raceAllFirst` against `raceAll`.

## 2. The `pollForApp` face rejects once its signal aborts. Today it never settles.

Today `pollForApp(signal)` (`app-check.ts:35`) just stops polling and leaves its promise pending. The face `Effect.runPromise(pollForAppEffect(), { signal })` *rejects* with an interruption once `signal` aborts.

Both callers only use it to fill `appeared` (`init.ts:1235`, `first-project.ts:1315`), and the only consumer of `appeared` is the race in §1. That race lifts it with `tryPromise`, which attaches a handler, so the rejection lands on a fiber that has already been interrupted. Nothing reports it and it is not an unhandled rejection. No change is needed at either caller. Say so in the face's `why`, so CLI-21 does not read the rejection as a bug.

Polling: `checkAppEffect` runs once immediately, then repeats with `Schedule.spaced('2 seconds')` until it answers `configured && ok`. `spaced` waits after each check finishes, which matches today's `setTimeout(poll, 2000)` set after each `await checkApp()` (`:41-46`).

## 3. `tryTheBuild` catches `TrialInterrupted` by name, not by tag

Today the catch is `err instanceof Error && err.name === 'TrialInterrupted'` (`setup-build.ts:339`). Any other error is rethrown (*"Anything else is a bug and propagates"*, `:338`).

- Type `Trial.run`'s error channel as `TrialInterrupted` (`packages/setup/src/trial-build.ts:42`).
- Catch it with `Effect.catchIf((e) => e instanceof Error && e.name === 'TrialInterrupted', …)`. Using the same predicate as today means a fake that fails with a plain `Error` named `TrialInterrupted` still works, so the fakes really change "only to return Effects".
- Everything else propagates as it does now. Do **not** use `catchCause` here: that would turn a bug into a refusal.

Wrap only `trial.run(…)` in the catch and keep the wall time measured around it, as at `:330` and `:344`. The Ctrl+C ownership is already right: `liveTrialEffect` holds the `SIGINT` listener in `acquireRelease` (`trial-build.ts:311-317`). Removing the face changes none of that.

## 4. `printSetupEndEffect`: the `threw` message comes from the squashed cause

Today the ready line's `threw` is `(err as Error).message || String(err)` (`setup-end.ts:55`). `setup-card.ts:216-225` prints it unchanged. That string is #1061's tutorial text.

With `Effect.catchCause`, build the same string from `Cause.squash(cause)`. A `liftDoctor` that keeps the rejection value as-is (`catch: (e) => e`) then gives the identical message for a rejection. A defect gets its message rather than `[object Object]`.

`liveSetupDoctorEffect`:

- Import `./doctor.ts` and `./steps.ts` with `Effect.promise(() => import(…))`. A failed dynamic import is a defect, which is correct for a missing module.
- Wrap `doctorReportEffect` in `Effect.ensuring(Effect.sync(() => progress.clear()))`. That is the `finally` at `:28-30`.
- Do not add a static import: `setup-end.ts:5-6`.

## 5. `github-auth.ts`

`write` (`:139-146`) turns a `writeAuth` failure into `{ refused: \`${message}. ${kept}\` }`. Lift `writeAuth`, use `catchCause`, and take the message from the squashed cause, as in §4.

The `SIGINT` ignore around `gh` (`:193-200`) becomes `Effect.acquireUseRelease`:

- acquire: `process.on`
- use: lift `world.github.gh!(…)`
- release: `process.off`

This keeps *"init ignores its own copy and comes back to the choice"* true on every exit, an interruption included. `ghStatus` is lifted where it is called (`:136`, `:201`). No `Effect.catch` appears anywhere in the five files. A `try/catch` becomes `catchCause` (or `catchIf` for §3's one typed failure).

## Checks

Every claim here is unit-level: the §1 tests, the existing `setup-card`/`setup-build`/`github-app` tests, and `packages/setup/unit/trial-build.test.ts` (`:126-139`, `:220`, which already run `liveTrialEffect` directly). Nothing here needs `pnpm test:integration`.

No log event is involved: setup appends nothing in these files, so no event can settle the behaviour.
