# #407: what the three texts say

The work is three places of words and their tests. The ticket says where they are. This note covers two things the ticket leaves open: **which ref the brief tells the agent to merge**, and **how far the rewrite of `conflictHalf` goes**.

## The ref: `<base>` as it is, not `origin/<base>`, and no fetch

The agent's worktree is a worktree of the project's bare mirror. It is cut with `git worktree add --force --detach path baseSha` with `cwd: mirror` (`packages/repo/src/worktree.ts:169-172`). The merge lane uses that same mirror: `` `${home}/repos/${options.project}.git` `` (`integrate.ts:319`). Its header says *"It is cut from the same bare mirror the…"* (`integrate.ts:23`). Every worktree of a repository shares its refs. So `refs/heads/<base>` is the same ref in the agent's tree as it is in the lane's.

Just before it refuses, the lane fetches the moved base into that ref: `fetch --prune origin +refs/heads/${base}:refs/heads/${base}` (`integrate.ts:336-345`). When the fix round's agent starts, `<base>` in its own tree already names the tip that did not merge. The command to give it is `git merge <base>`, the bare name.

Two names look right and are wrong:

- **`origin/<base>` does not exist.** `worktree.ts:60-63`: *"this mirror is bare and fetches `+refs/heads/*:refs/heads/*`, so there is no `refs/remotes/origin/*`"*.
- **Don't tell it to fetch.** A plain `git fetch origin` has no refspec to follow, because the bare clone is set up only with `remote set-url` (`worktree.ts:111-113`). An explicit refspec fetch needs the token that the conductor passes through `run.token` (`worktree.ts:103`), and the agent may not have it. The brief already says *"The base can move again while you work. If it does, this comes back around"* (`fix.ts:661-662`). That sentence covers a stale `<base>`, so keep it, and keep the test that pins it (`fix.test.ts:1498-1500`).

Say that the tree is detached at the commit it was cut from. `git status` names no branch (`worktree.ts:158-163`). The agent commits on `HEAD`, which is what gets pushed (`HEAD:refs/heads/<branch>`, same comment).
