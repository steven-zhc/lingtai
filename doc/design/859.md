# Design: #859, the generated stream section

## Where the rendering runs

`pnpm events:generate` already runs in two processes. The parent archives HEAD into a temporary directory. A child, the snapshot's own copy of the script, writes `events.json` (`packages/domain/scripts/events.ts:507-512`). The parent then copies that file into `doc/` (`:550`).

**Render the section in the parent, after that copy, from the `doc/events.json` it just wrote. Never render it in the `--emit` child.** The child's working directory is the throwaway snapshot, and that snapshot holds only `apps` and `packages` (`:538`), so it has no `doc/reference.md` to splice into.

The parent's `PREFIXES` and `MULTI` are the working-tree copy. They still equal HEAD's, because the run refuses a dirty `apps`/`packages` (`:527-533`). So the section and the manifest come from one commit's tables.

Export two pure functions from `scripts/events.ts`, so that the test and the parent share them:

- `renderStreams(doc: EventsDoc): string` returns the text between the markers, heading included.
- `spliceStreams(markdown: string, section: string): string` throws, naming `doc/reference.md`, unless each marker occurs exactly once and `begin` comes before `end`.

The parent then does three things: it reads `doc/reference.md`, splices the section in, and writes the file back only if the text changed.

`renderStreams` must not read `doc.sha` or anything that depends on time. `sha` changes on every run (`:519`), so a section that used it would fail both *"a second run changes nothing"* and the test.

## The markers enclose the heading

`<!-- streams:begin -->` goes directly above `## stream — …`, and `<!-- streams:end -->` goes after the table and the `MULTI` lines. The hand paragraph about `ctl-github-app` and `ext-subscribers` (`doc/reference.md:172-175`) stays below `end`.

The heading must sit inside the markers because the generator owns the count. The site drops the comments: `react-markdown` *"drops HTML nodes unless `rehype-raw`"* (`apps/site/src/app/docs/document.tsx:124`). No doc in `doc/*.md` uses a comment today, so these will be the first.

The heading's GitHub anchor changes from `stream--7-…` to `stream--8-…`. Nothing in `doc/` or `apps/site/src` links to `#stream…`.

## Links in the generated Markdown are relative

Write `[RunSpent](events.json#RunSpent)`, not `/docs/events/#RunSpent`. A site-absolute path is a dead link to anyone reading the file on GitHub. The site already rewrites the relative form: `if (rel === 'events.json' && isPublicSlug('events')) return \`/docs/events/${suffix}\`` (`apps/site/src/lib/docs.ts:438`). The `#Name` anchor is the `id` each entry already carries (`events-body.tsx`, `<div className="ev" id={event.name}>`).

The glossary's states table has no heading of its own. Its nearest heading is `## The log and its states` (`doc/glossary.md:33`), so the State column links to `glossary.md#the-log-and-its-states`.

## `PREFIXES` and `MULTI`

`PREFIXES` maps each prefix to `{ onePer, state }`. Give `onePer` the id shape the glossary's Stream column uses, for example ``attempt, `pass-…` ``, ``issue, `ticket-{project}-{issue}` `` and ``finding, `bkl-{project}-{key}` ``. That keeps what the old Example column told the reader within the ticket's four columns.

`ctl-` has two streams with different answers, so give its state a short text:

- `ctl-conductor` reduces to `ControlState`.
- `ctl-github-app` is reduced by nothing.

Write the state's name as the glossary writes it. `bkl-`'s state is **Finding state**, with a space (`doc/glossary.md:91`). Use #855's words throughout: *attempt*, never *run (one attempt)*, which `:164` still says.

`MULTI` is `Partial<Record<EventType, string>>`. Its only row today is `RunSpent`: spend is recorded on the stream of whatever spent it, whether an attempt, a discussion or a ticket-level agent. Check that reason against the append sites `events.json` lists for `RunSpent` before writing it. `renderStreams` throws if a type is on two or more prefixes and has no `MULTI` row. It also throws if a `MULTI` row names a type on fewer than two, so the table cannot go stale in that direction.

**Types on no stream.** `OutboxDelivered` and `OutboxFailed` have `stream: []` (`scripts/events.ts:282-283`), so no prefix row would list them. Render one line under the table, *On no stream:* followed by those two, marked retired. Then all 66 types appear somewhere in the section, and a reader does not take the missing two for a gap.

## The test

Put it in `packages/domain/unit/streams-section.test.ts`. Reading committed files there has a precedent in the unit half: `events-json.test.ts:147` reads `doc/events.json`. The test asserts three things:

1. `spliceStreams(reference, renderStreams(committed)) === reference`. On failure the message says *run pnpm events:generate*.
2. The keys of `PREFIXES` equal the prefixes in `STREAM_ID_PATTERN.source` (`packages/domain/src/envelope.ts:44-46`): the group between `^(` and `)-`, split on `|`, with `-` appended. Compare `STREAM_ID_PATTERN`, not `StreamId`: the pattern is the exported `RegExp` the schema is built from.
3. The union of `stream` over the manifest equals the keys of `PREFIXES`.

The hand-made red checks the ticket asks for are made by editing the span and editing the regex, each once.

## The site

`apps/site/src/lib/event-filter.ts` must keep importing nothing (`:4-6`). So `byStream` cannot know `StreamPrefix`'s order. Make it list streams in the order they first appear, as `byGroup` does (`:38-43`), and put a final `none` bucket for types whose `stream` is empty.

Add `stream: readonly string[]` to `Indexed` (`:11-15`). The page's prefix order will then differ from reference.md's, which is acceptable. Do not import a value from `scripts/events.ts` into the site. It imports `typescript` and `node:fs` (`:16-21`), and `events-body.tsx` imports only its type.

**Duplicate ids.** Each entry renders with `id={event.name}`. Rendering `RunSpent` in full under three prefixes would give the page three `#RunSpent` elements, and the scroll in `events-filter.tsx:62-65` would pick whichever comes first. So in stream view:

- The full entry appears once, under its first prefix in `STREAMS` order (`pass-`).
- Under each other prefix, show a one-line `<a href="#RunSpent">` cross-reference.

That still counts as *appears under three*. Section ids are `stream-<prefix without dash>`, distinct from `groupId`'s `group-…`.

**`?by=`.** Parse it the way `parseStep` parses `?step=`: any value other than `stream` means group view. `write` (`events-filter.tsx:163-168`) edits only `step` through `URL.searchParams`, so a second writer for `by` keeps the other parameter. Under `?by=stream`, the step filter hides entries within each stream exactly as it does within each group.

The first render stays unfiltered and in group view. *"The first render is always unfiltered, so the exported HTML holds every entry"* (`:20-21`) still holds. Stream view is a client-only regrouping after mount.

Cover `byStream` and the `?by=` parser in `apps/site/unit/events.test.tsx`, which already imports `event-filter`.

## Not checkable before the merge

Only the Next build sees whether a server-only import reaches the `"use client"` graph of `events-filter.tsx`. That build is `apps/release/integration/build.test.ts`, in the integration half. The unit-level stand-in is to keep `event-filter.ts` import-free and pass `stream` through `Indexed`.
