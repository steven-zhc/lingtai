# #876: how the change is shaped

## 1. Choose the snapshots where the store is chosen, and pass them down

Every ticket site except `runOnce` receives a store that has already been resolved. In those sites, `store === undefined` is never true, so that test can't decide whether to use snapshots:

- `runOnce` resolves `const store = options.store ?? eventStore` (`packages/conductor/src/conduct.ts:667`). It then passes that `store` to `continueTicket(ticketId, runId, { store })` (`:2358`), `claimTicket` (`:2361`), `releaseTicket(…, store, cause)` (`:1398`) and `editEndedWaits({ store, … })` (`:2397`).
- `releaseTicket` defaults its store as a positional parameter, `store: EventStore = eventStore` (`claim.ts:254`).
- `conductWork` resolves `const store = options.store ?? eventStore` (`apps/cli/src/conduct.ts:216`) and passes it to `stillOwed(store, name, c)` (`:406`).

If a site works out "default store → `log.snapshots`" for itself, it gets one of two wrong answers. Testing `options.store === undefined` means no site ever snapshots in the daemon. Testing `store === eventStore` means the answer depends on object identity, which works only by coincidence.

**Decision:** compute the choice once, at the place where the store is chosen, and pass it down explicitly.

- In `runOnce`, the existing line `const controlSnapshots = options.store === undefined ? theLog.snapshots : undefined` (`conduct.ts:669`, commented *"The default log's snapshots belong to the default store; a store passed in has none of its own"*) already answers this. Rename it to `snapshots`, or reuse it as it is. Pass `{ snapshots, writer: options.snapshotWriter }` to the four calls above.
- `claimTicket`, `continueTicket` and `editEndedWaits` each get optional `snapshots?` and `writer?` fields on the options object they already take.
- `releaseTicket` gets a trailing `options: SnapshotReadOptions = {}`. Don't reorder its positional parameters.
- If `snapshots` is absent, the site reduces the whole stream from `emptyTicket`, as it does today. That covers `tell.ts:545` (the `tell` command) and every test that hands in a store. Neither of those callers changes.
- `stillOwed(store, project, row, options?: SnapshotReadOptions)`:
  - In `conductWork`, use `options.store === undefined ? log.snapshots : undefined`. That is the same rule as `apps/cli/src/day-ceiling.ts:102`, `snapshots: store === undefined ? log.snapshots : undefined`.
  - In `run.ts:517`, use the same rule on `options.store`, with **no writer**. `lingtai run` reads snapshots and never writes them (0124 §5).

## 2. How the writer reaches the pass

The daemon already hands one writer to `conduct` as `controlWriter` (`apps/cli/src/daemon.ts:619`). It is the same object that ticket offers need: one writer per process (#875), keyed by `(streamId, reducer, reducerVersion)`.

**Decision:** don't build a second writer and don't add a second `ConductOptions` field.

- Inside `conduct`, pass `options.controlWriter` to `conductWork` as `snapshotWriter`.
- From there it goes into `common` (the object built at `apps/cli/src/conduct.ts:252` and `:277`), and so into `RunOnceOptions.snapshotWriter`. That is a new optional field beside `store?` at `packages/conductor/src/conduct.ts:479`.
- `stillOwed`, called inside `conductWork`, uses the same `snapshotWriter`.

The field's doc comment says it is given only inside the daemon. `apps/cli/src/run.ts`'s `world.runOnce` calls (`:554`, `:641`) and `schedule.ts`'s (`:281`, `:342`) pass no writer.

## 3. The helper the ratchet allows

Put it in a new file, `packages/conductor/src/snapshot-state.ts`, and export it from `packages/conductor/src/index.ts` so that `apps/cli/src/continuing.ts` can import it:

```ts
export async function readState<S>(store, reducer: Reducer<S>, streamId: string,
  types: readonly EventType[] | 'all', options: SnapshotReadOptions = {}): Promise<S>
```

This is the one `async` and the one `Effect.runPromise` in it. Write it as `Effect.runPromise(Effect.either(readThroughSnapshot(…)))`, then throw `result.left` unchanged.

**Why `either`:** a bare `runPromise` rejects with a `FiberFailure` that wraps the error. The ticket's edge says *"it fails as it does today at each site"*. Each call site has a `catch` that sees the rejection, and today that rejection is the store's own error:

- `editEndedWaits`'s `try` (`tell.ts:456`)
- `run.ts:518`'s `catch: (err) => refuse(… (err as Error).message)`
- `conduct.ts:1398`'s `.catch`

The same `either` pattern is already in `packages/conductor/src/day-ceiling.ts:143-144`.

`claim.ts`, `tell.ts` and `continuing.ts` call this helper and add no `async` and no run of their own. `stillOwed` is already `async`, and `apps/cli` doesn't rise.

In `runOnce`, replace `conduct.ts:1088-1089` with `const reduced = yield* readThroughSnapshot(store, ticketReducer, ticketId, 'all', { snapshots, writer }).pipe(Effect.orDie)`. That is the same treatment as the control read at `:966-968`, whose comment says *"A failure is a defect, as it was inside `Effect.promise`"*.

## 4. `before` disappears; `priorAttempts` needs a stream id

Once `before` is gone, the helpers that took the event array have to take the state. The ticket lists `waitsOf`, `grantedAdviceOf`, `priorAttempts`, `nextPrompt` and `armFor`.

- Each helper that only reduces `before` gets `reduced`, or a field of it. Check each one's body: it may already have, or need, a `…FromState` sibling.
- `priorAttempts` reads `itemEvents[0].streamId` (`attempts.ts:163`). Give it `ticketId` directly.

**Don't keep a full `store.read(ticketId)` alive just to feed one helper.** That breaks the "Done when" box *"None of the six sites … calls `store.read(ticketId)` to reduce a ticket"*.

If a helper turns out to need a raw event that isn't in `TicketState`, stop. Say so in the commit and leave that one read in place. Don't widen `TicketState`: widening it changes the codec, and therefore the version-table row.

## 5. The reducer and its decode

Put `ticketReducer` in `packages/domain/src/ticket-codec.ts`, not in `ticket.ts`. The codec imports only *types* from `ticket.ts` (`ticket-codec.ts:18`). Putting `ticketReducer` in `ticket-codec.ts` takes the values (`emptyTicket`, `reduceTicketEvent`) one way only, and keeps `ticket.ts` free of the zod schema.

`decodeTicket` always ends its message with *"run \`lingtai projection rebuild ${projection}\`"* (`ticket-codec.ts:137-139`), and the ticket's edge says the reducer's decode must not.

**Decision:** split the parse and the wording.

- Move everything from `JSON.parse` through `firstDifference` into an unexported function that returns `TicketState` or the `what` string.
- `decodeTicket` keeps its wording exactly. `task_view`, `ticket_report` and their tests keep reading it.
- `ticketReducer.decode` throws `TicketCodecError(\`ticket snapshot: the stored state is not today's shape (${what})\`)`. It has no subject, because `Reducer.decode` takes only the state. `readThroughSnapshot` logs the decode failure once, as `ticket snapshot decode failed, reducing from version 1: …` (`snapshot-read.ts:32`), and that log line supplies the context.

## 6. `'all'` in `readThroughSnapshot`

- Widen the `store` parameter to `Pick<EventStore, 'readTypes' | 'read'>`.
- Route all three reads (`:46`, `:70`, `:76`) through one local function: `types === 'all' ? store.read(streamId, from) : store.readTypes(streamId, types, from)`. `fromVersion` is inclusive for both (`event-store.ts:348`, `:366`), so `start + 1` stays as it is.
- Update the file's header line *"reads with `readTypes` only"* to match.

Every existing caller passes a full `EventStore`, so widening the `Pick` breaks none of them. Check the test fakes in `packages/event-store/unit` and `packages/daemon`, which may build a bare `{ readTypes }`.

## 7. Where the "Done when" claims are checked

All of them are unit tests on `createMemoryEventStore()` plus a memory `SnapshotStore`. Use whichever one #873's own `snapshot-read` test uses; don't write a new one.

- **The concurrency check.** Plant a snapshot below the head, read with `'all'`, then `append` at `state.version`. Do it twice from the same state, so the second append gets `ConcurrencyError`. If `version` had come from a typed tail, the first append is what would fail, which is exactly the trap in the ticket's Watch out. This check is the evidence for the claim; no integration test is needed.
- **The ignored-type history.** Use a real `EventType` that `reduceTicketEvent` has no case for. Pick one from `events.ts` by reading the reducer's `switch` at `ticket.ts:426`. Don't invent a type: the memory store validates payloads on append.
