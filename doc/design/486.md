# Design: #486, the daemon reads through the read model

## The daemon folds nothing, so the move is a list of names

None of the four files reads a `Hold` or folds a retired event. Below is every place they name an event type, set against 0120's appendix (`doc/decisions/0120-a-reason-is-a-type.md:628-655`):

| Site | What it names | Retired by the appendix? |
|---|---|---|
| `converge.ts:288-292` `candidates()` | `store.streams({ prefixes: ['wi-%'], types: ['WorkItemClaimed', 'WorkItemBlocked', 'WorkItemReleased', 'WorkItemLanded', 'WorkItemUnblocked'] })` | `WorkItemBlocked` → `WaitStarted`, `WorkItemUnblocked` → `WaitResolved`. `WorkItemReleased` only "adds `cause`" and keeps its name. |
| `work-loop.ts:93-113` `COMPLETION_EVENTS` | the wake list | the same two. `IntegrationRefused` keeps its name and only loses three fields. |
| `converge.ts:342-352` | `EndActionsResolved`, `IssueUpdated`, `IssueUpdateFailed` | no ("Unchanged: … `EndActionsResolved` … and the rest of `EVENTS`") |
| `control.ts:292` | `ConductorStarted` | no |
| `work-loop.ts:369,551` | `PluginFailed`, `DiscussionRequested` | no |
| `control.ts:10` | `ApprovalGranted`, in a comment | removed (`WaitResolved{Approve}`) |
| `daemon.ts:85` | `WorkItemBlocked`, in a comment | see the first row |

So `waitsOf`, `routesOf`, `stepOutcomesOf` and `releaseCauseOf` have nothing to fold here. `converge.ts:324-326` decides drift with `reduceWorkItem(events)` and `labelState(item.lifecycle.status)`. That reducer is domain's, and it is not one of the four files. **Do not invent a use for the read-model functions.** #481 made the same call for `routesOf` (`doc/design/481.md`, "Do not invent a use for `routesOf`"). Leave `reduceWorkItem`, `labelState`, and its `'blocked'` case alone (`converge.ts:214-224`): that case is `WorkItemStatus`, not an event type and not `Hold`.

## The decision: the read model owns the names of the wait events

0120 says "at the switch only the read model and the builders change" (`0120…md:588`). Two retired names sit inside daemon lists, so those lists would have to change at #464. Move just those two names into the read model.

**In `packages/domain/src/read-model.ts`**, next to `READ` (`:53`):

```ts
/** The types that start and resolve a wait: 0118's `WaitStarted`/`WaitResolved` at #464. */
export const WAIT_EVENTS = ['WorkItemBlocked', 'WorkItemUnblocked'] as const
```

- Do not rewrite `waitsOf`'s own filters (`:1170,1174,1198`) or `READ` onto it. That is #464's file to change, and this ticket only adds an export.
- Leave the unchanged names (`WorkItemClaimed`, `WorkItemReleased`, `WorkItemLanded`, `IntegrationRefused`, the control types) spelled out in the daemon. Done-when asks for *old* types to go, and a constant named after every work-item move would need its own justification.

**`converge.ts:290`** becomes `types: ['WorkItemClaimed', ...WAIT_EVENTS, 'WorkItemReleased', 'WorkItemLanded']`. `StreamQuery.types` is a set ("A stream qualifies if it holds at least one event of one of these types", `store.ts` `StreamQuery`), so order does not matter. Import it from `@lingtai/domain`, which `converge.ts:70-78` already imports from. Do not take it from a deep path.

**`work-loop.ts:93`**: replace the two names with `...WAIT_EVENTS` and keep `as const`. `triggers` is `readonly string[]` (`:250`), and `new Set<string>(…)` (`:318`) does not care about order. `COMPLETION_EVENTS` is re-exported (`index.ts:17`), and nothing outside reads it as a tuple: the only other mentions are comments in `packages/repo/src/integrate.ts:118` and `integration/integrate.test.ts:264,316`.

**`control.ts:10`**: reword the analogy so it names no event type, for example "the same shape as a person approving a merge". **`daemon.ts:85-87`**: say "a wait recorded in the payload shape from before #445's reset", not `WorkItemBlocked`.

**`daemon.ts`'s `LogPredatesHoldError` / `logPredatesHold` / `predatesHold` / `'log-predates-hold'` stay.** They are #451's old-log guard, the same guard phase 2's reset uses (`0120…md:594-595`). They come from `@lingtai/event-store` (`daemon.ts:35`), and `apps/cli/src/restart.ts:464` and `apps/cli/unit/log-predates-hold.test.ts:136` match the reason string. Renaming them changes a contract across packages and touches no reader of `Hold`. `grep -w Hold` does not match them, and that grep is the Done-when check.

## The pin: `packages/daemon/unit/decisions-over-a-recorded-stream.test.ts`, committed before any `src` change

Unit by 0060 §1: `createMemoryEventStore()` (`@lingtai/event-store/memory`), injected clients and projects, no disk. Every event comes from `@lingtai/domain/test/events` (`package.json` exports `./test/events`). Assert on **labels the test chooses, never on type names**, so that #464, where the builders emit new types, can leave the assertions alone. Say in the header that the daemon's existing old-type tests are all integration, so this file is the only check of these decisions inside the pass.

**Half 1: what wakes the loop.** Make a list of `[label, Envelope[]]` for one item, using the builders:

- `aClaim`
- `aRun(r).aStepEnded(...)` for a passing `build` and a refused `review`
- `aWait(item, { _tag: 'OwnQuestion', … })` and `aWait(item, AgentQuestion)`
- `anAnswer`, `aResolution(item, { _tag: 'Requeue' })`, `aWithdrawal`
- `aRoute(run, { from: 'review', to: 'implement' })`
- `aRoute(run, { from: 'proposed', to: 'claim' }, item)`
- `aRelease`, `anIntegrationRefusal`, `aLanding`

Compute `woken = rows.filter(([, es]) => es.some((e) => new Set<string>(COMPLETION_EVENTS).has(e.type))).map(([l]) => l)` and assert the whole array with `toEqual`. That reproduces `work-loop.ts:553`'s `triggers.has(event.type)`, which this ticket does not touch. Driving `createWorkLoop` itself needs `processLog()` or a waker, which is the integration half's job.

Note in a comment that the `claim` route row does not wake today. At #464 the appendix gives a restart a `WorkItemReleased{cause: Restart}`, so that row is where #464 has to decide. It is not this ticket's concern.

**Half 2: what `findIssueDrift` finds.** Inject a `daemonStore` whose `streams(query)` **applies** `query.prefixes` (strip the `%`) and `query.types` to the streams you appended. Do not hand back a fixed list the way `converge-refs.test.ts:47` does: the type filter is the decision being pinned. Pass `store` (the memory log; `logOf`, `converge.ts:283-285`), `projects` (copy `converge-refs.test.ts:35-44`), and `clients` with a `getIssue` that records each call and answers fixed labels. One `wi-lingtai-<n>` per case:

- **Claimed and wearing nothing**: the running label is wanted.
- **Waiting** (`aClaim` then `aWait` AgentQuestion), wearing the running label: it should move to the waiting label.
- **Waited, then requeued** (`aWait`, then `aResolution` Requeue), with an `IssueUpdated{change: 'labels', detail: …}` written before the wait: stale (`converge.ts:363`). This is the case where only `WorkItemUnblocked` and `WorkItemBlocked` explain the stream.
- **Released after a claim**, with a stale label.
- **Landed**.
- **A `wi-` stream holding only `IssueUpdated`**: not a candidate. Assert `getIssue` was never called for that issue.

Append each builder envelope as `{ type, actor, data }` (`contract.ts:150`'s mapping, as #481 used). `IssueUpdated` and `EndActionsResolved` are unchanged types, so they may go through `makeStream` (`@lingtai/domain/test/support`), as #480 and #481 allowed.

Take the expected `Divergence[]` with `toMatchInlineSnapshot()` run against today's `converge.ts`, and **never `-u` it after a `src` change**. Write that rule in the file header. A red pin means the reader changed. Fix the reader, not the snapshot.

## Moving the daemon's tests onto the builders

The hand-written old types are all in the integration half. `pnpm typecheck` is the only check of these inside the pass, and the pin above stands in for them. Do not run `pnpm test:integration`.

- `integration/work-loop.test.ts:70-76`: `WorkItemBlocked{hold: Question}` becomes `aWait(makeStream(id), { _tag: 'OwnQuestion', question: '?', by: 'conductor' })`, mapped to `{ type, actor, data }`. `holdOf` turns `OwnQuestion` into `Question` (`adapters.ts:363-364`).
- `integration/reconcile.test.ts:180-186`: `{ _tag: 'Asked', run, step: 'merge', question }` is a hold at `merge`, and `AgentQuestion`'s own `step` is `Step.extract(['design', 'implement'])` (`wait.ts:70-75`) — `merge` does not typecheck there. `SignoffRequired`'s `step` is `Step.extract(['proposed', 'merge'])` (`wait.ts:78-84`), so the row becomes `aWait(…, { _tag: 'SignoffRequired', run: { runId: waiting }, step: 'merge', action: '--no-merge', question: 'merge it?' })` (`adapters.ts:367-374`). `reconcile`'s own check (`reconcile.ts:270,469`) reads `life.status`, never the hold's `_tag`, so this is still "blocked on a person" to the test.
  - Both append at version 0 to a stream they create, and the claim in `reconcile` sits in the same append. Build that stream with one `makeStream` so the claim and the wait share its versions, and append the claim through `aClaim` from the same stream function.
- `integration/work-loop.test.ts:376` (`IntegrationRefused`) and `integration/converge.test.ts:174` (`WorkItemReleased`) are unchanged names and may stay. Move them onto `anIntegrationRefusal` / `aRelease` only if it is free.
- `unit/start.test.ts:65`'s test name says "the Hold event". It is about the guard, so leave it.
