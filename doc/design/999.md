# #999 design: retire `ConductorShutdownWithdrawn`, and stop `resume` from lifting a drain

#998, #1001, #1002 and #992 have all landed in this worktree. `controlReducer.version` is `3` (`packages/domain/src/control.ts:368`). `ConductorStarted` ends a drain (`control.ts:220-223`). In `apps/`, the only uses of `withdrawShutdown` are gone: what is left is the board's history label and a read-only filter in `apps/cli/unit/upgrade-drain.test.ts:32`. The ticket's line numbers have moved. The current ones are below.

## Three traps the ticket does not name

### 1. Retiring the event also means emptying its `EVENT_AT`

`packages/domain/unit/event-at.test.ts:8` asserts `EVENT_AT[type].length === 0` exactly when `RETIRED.has(type)`. Today `ConductorShutdownWithdrawn: ['outside']` is at `events.ts:2543`.

- Keep the key, but change its value to `[]`. That is how `PassRouted: []` (`:2537`) and `TicketLinked: []` (`:2507`) were retired.
- When the ticket says to "keep its `EVENT_AT` entry", it means the key, not `'outside'`.
- Leave the stream-prefix row in `packages/domain/scripts/events.ts:287` (`['ctl-']`) in place. `PassRouted` keeps its row there too (`:281`).
- `RETIRED` is now at `events.ts:2606-2611`.

### 2. A retired type cannot be appended, not even in a test

Both stores throw `RetiredEventTypeError` for a retired type:
- `packages/event-store/src/event-store.ts:316`
- the memory store, `packages/event-store/test/memory.ts:152`

So every test that **appends** a withdrawal through a store must stop doing so or be deleted. A test that **reduces** a hand-built envelope is unaffected:
- `packages/domain/unit/control.test.ts:272,288,314` reduces envelopes directly.
- `packages/domain/test/histories.ts:379,1415` builds stamped envelopes.

These stay, and they are what proves "a withdrawal already in the log still lifts the request it named".

Tests to change:

- **`packages/daemon/unit/control-head.test.ts:47-65`** (*withdrawShutdown fails the first append…*) is a unit test of the deleted function. Delete it, and drop `withdrawShutdown` from its import at `:11`. The ticket's Done-when grep would find it otherwise.
- **`packages/daemon/integration/shutdown.test.ts:438`** (*keeps force with the request the withdrawal does not lift*) goes through `storeOf([...])`. Check whether that appends. If it does, the test now throws. Either move the case into `control.test.ts` as a direct reduce, or delete it. It is integration either way, and only a unit test can check it here.
- **`packages/daemon/test/contract.ts:348`** calls `withdrawShutdown`. Rewrite it to end the drain with a start (`recordStart`). This file runs only in the integration half, as the ticket says. Nothing can run it inside this pass, so `pnpm typecheck` is the check that stands in for it.

### 3. The day ceiling's guard loses its reason

`packages/conductor/src/day-ceiling.ts:151-159` (`liftOwnPause`) skips lifting its own pause when `control.shutdown !== null`. The reason it gives is: *"`ConductorResumed` also withdraws a standing shutdown request (reduceControl), and an unrelated shutdown is not ours to withdraw"*. After this ticket that reason is false.

**Decision: keep the guard and rewrite only the comment.** The rewritten comment should say:
- A drain is in flight, so this daemon exits at the end of the pass.
- The next start's ceiling check lifts the pause then.
- Lifting it now buys nothing.

The test `packages/conductor/unit/day-ceiling.test.ts:204` (*a raised figure does not withdraw a standing shutdown request*) still passes. Rename it to say what it now protects: *does not resume while a drain stands*.

Dropping the clause would change how the ceiling pause behaves. The ticket's Out of scope puts the pause half, `ceilingWaivedUntil` included, in later #675 tickets. So the code stays as it is.

## Fix §4: #992's bare `resume` (`apps/cli/src/project-pause.ts:112-146`)

- At `:120`, change the condition from `!control.paused && control.shutdown === null` to `!control.paused`.
- Delete the `lifted a shutdown request by …` line at `:140`.
- The error text at `:133`, *"could not lift the conductor-wide pause"*, is already correct.

`apps/cli/unit/project-pause.test.ts:103-131` (*reports the pause it lifted… when the ceiling pauses in between*) sets up with `requestShutdown` at `:108`. The comment there says *"A standing shutdown request is read"*. The race in that test does not depend on the request:
- The stubbed `head()` appends the ceiling's pause before `readControl` runs.
- So the first read already sees a pause, and the append at the stale head fails and is retried.

Keep the `requestShutdown` call and fix the comment. Then add the Done-when assertions to the same test, which proves both halves of the new rule at once:
- The output does not contain `shutdown request`.
- `readControl(...).shutdown` is still non-null after the resume.

Add a separate test for *only a shutdown standing*. It should assert that the stream gains no `ConductorResumed` and that the output is `nothing to resume`.

## The reducer version and its fixture

`reducers.test.ts:2-6` hashes the encoded state after every prefix of `late_everyControlEvent` (`packages/domain/test/histories.ts:1407`). In that fixture the only `ConductorResumed` (`:1412`) comes **before** any `ConductorShutdownRequested`. While it is reduced, `shutdown` is already `null`, so dropping `shutdown: null` does not change the hash. That leaves version 4 hashing the same as version 3, so the version table would not show that anything changed.

**Decision:** the fixture is *"frozen for a version — it changes only in the commit that raises the version"* (`histories.ts:1403-1404`), and this is that commit. So:
- Add `c('ConductorResumed', { by: 'steven' })` after the last `ConductorShutdownRequested` (`:1416`). Under version 4 the request then still stands after the resume, and that state goes into the hash.
- Commit the row `"4"` that the test prints.
- Leave row `"3"` as it is.
- Update `histories.hashes.json` for any history whose result changes. Keep the added `ConductorResumed` together with the new row, so a reader can see why the version went up.
