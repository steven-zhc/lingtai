# #1267: shape of the change

## Where the one decision lives

`packages/domain/src/wait.ts` holds the four renamed schemas (`:246-262`). It also holds the mapping the ticket asks for. Write it as a `Record<TriageAdvice, Resolution['_tag']>`, plus one exported function that reads it (for example `adviceResolution(advice)`). A `Record` keyed by the enum is total by type, so the *every advice maps to a member of `Resolution`* test becomes one line over `TriageAdvice.options`. The Done-when grep allows the old spellings only in the upcaster, `TriageAdvice` and this mapping, so this table is the one place outside `upcast.ts` where they appear as keys.

The type assertion at `wait.ts:293-297` (`_triageAdviceCoversResolution`) compares `TriageAdvice` with `Resolution['_tag']` directly, and it stops holding once the tags rename. Rewrite it over the mapping's **values**: the values must cover `Exclude<Resolution['_tag'], 'AnswerQuestion' | 'RedoStep'>`. Keep the comment that says why `RerunStep` (now `RedoStep`) is left out (#1218).

## Readers that index by advice: the ones the compiler will not explain

Each of these places takes a `TriageAdvice` and treats it as a `Resolution` tag. Today that works only because the two share spellings. After the rename each one is a type error, and each must go through the mapping. Do **not** fix them with a cast:

- `wait.ts:772-790` (`recommendedResolution`). `advised` is advice, and the code calls `allowed.includes(advised)` and returns it. Map it first.
- `apps/board/src/app/standing.tsx:574,581,582`, `apps/board/src/lib/history.ts:727` and `apps/board/src/app/page.tsx:256` all do `RESOLUTION_COPY[<advice>]`.
- `apps/cli/src/status.ts:119` (`rec === 'GrantFixRound' && result.resolution !== 'GrantFixRound'`). `rec` is a resolution and `result.resolution` is advice. Compare `rec` with the advice's mapped value.

The mapping does not touch these, and they stay exactly as they are:
- `apps/cli/src/triage.ts:808`: the `resolution: 'Requeue'` in the mechanical advice is a `TriageAdvice` value.
- The triage prompt in `packages/conductor/src/triage.ts:91,137-160` lists advice values.
- The `ContinueConflict → 'GrantFixRound'` rewrite in the `WaitTriaged` upcaster (`upcast.ts:163-175`) produces an advice value.

The grep in Done-when is about tags, and these do not need renaming.

## Words versus identifiers

**Copy tables:** `RESOLUTION_COPY` (`apps/board/src/lib/resolution-copy.ts:6-40`), `RESOLUTION_WORDS` (`packages/conductor/src/report.ts:371-380`) and `tell.ts:430`'s `resolutionWords`. Rename their **keys** and leave every string value byte-for-byte. The same goes for `ticket.ts:948-951`: the `TicketReleased.reason` sentence *"Requeued by … with an edited body"* stays as it is. Only the `how` literal union at `ticket.ts:935` follows the tags.

**Raw tag echoes:** some places print a tag verbatim rather than through a copy table:
- `packages/conductor/src/resolve-wait.ts:481` (`${refusal.resolution} is not offered …`)
- `apps/cli/src/status.ts` (`recommends ${rec}`)
- the anchor `resolution-${move.resolution}` (`decide.tsx:971`) and its target id
- `data-resolution={tag}` (`standing.tsx:1498`)
- any `--json` field that carries a tag

These **follow the tag**. They print the identifier itself, and the Done-when grep leaves no other way to spell it. Keeping the old spelling there would need a second table of old names. List each one in the PR body as *an identifier echo, not copy*, so the reviewer can tell them apart from a changed word.

**The trap is CSS.** `apps/board/src/app/globals.css:1640,1688,1694` select on `[data-resolution='EditBodyAndRequeue']`. Neither `tsc` nor vitest reads CSS. If you leave those selectors alone, two things change visibly and silently: the empty edit-body card stops hiding, and the recommended button loses its styling. Rename the selectors to `EditBodyAndStartNewAttempt`.

## The stale-page edge: the case does not arise

No board action accepts a resolution tag from the client. `continueFixingCard` and `rerunStepCard` build theirs on the server from `{waitId, onSha}` (`apps/board/src/app/actions.ts:185-254`). `requeueCard`, `editBodyAndRequeueCard` and `closeCard` take no tag at all (`:329,364,413`). A page loaded before the deploy therefore has no old tag to post. What protects it is the stale check that already exists: `waitId` and `onSha`, refused with *"stale: reload this page …"* (`:131,195,239`).

Do **not** add a tag parameter just so something can refuse it. Meet the fourth Done-when with a unit test showing that a stale `onSha` is refused with *reload this page* and nothing is resolved. Say in the PR body that no action receives a client-supplied tag, citing the lines above.
