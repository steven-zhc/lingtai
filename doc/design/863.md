# Design note: #863, the board serves `board.host`

## The decision the ticket leaves implicit: where a bad `board.host` may throw

`board.port` already has two rules, and `board.host` has to follow both:

- **The board is the subject** (`lingtai board`, `lingtai init`'s board, `apps/board/serve.ts`): a bad value is refused by name before anything listens.
- **The board is not the subject** (the daemon, `lingtai service`, card links): a bad value is a fact carried along, never a throw. `boardPortOrWhy` (`apps/cli/src/board.ts:74-91`) says why: *"one typo in a UI setting threw before `serviceCommand` was entered (#187): `lingtai service shutdown "moving the database"` drained nothing."* `boardAddress` (`apps/cli/src/subscribers.ts:55-72`) says the same: *"A link, and never a throw … a conductor that never claims a ticket is worse."*

Once `boardUrl()` reads the host, a bad `board.host` reaches every caller that reaches `boardUrl()`. So each read of the host goes beside an existing read of the port, and inherits that read's rule.

## The sites the ticket does not list

All five are the same trap: either a URL formatted from the bind host, or a `127.0.0.1` that becomes wrong when `board.host` names one address.

1. **`init.ts:1260`** is `return { url: \`http://${host}:${port}\` }`, built from the bind host. Once `host` is `boardHost()`, `lingtai init` prints `http://0.0.0.0:17820`. Use the reach URL here.
2. **`daemon.ts:124` and `:139`** are `url: \`http://127.0.0.1:${port}\``, and `:140` is `answering: () => boardAt(port)`. They are in `boardOptions()`, which is built for every `service` verb and for `restart`. With `board.host: 192.168.1.5`, the service's board leg would probe loopback, find nothing, and report the board missing.
3. **`first-project.ts:1108`** is `boardUrl: () => boardAt(boardPort())`. This is `lingtai add`, where the board is the subject, so it may throw.
4. **`subscribers.ts:70`**: `boardAddress`'s fallback stays `http://127.0.0.1:${BOARD_PORT}` on any throw. A good port with a bad host also falls back to the default port. That is acceptable: it is a link, and the board's own commands refuse the bad value by name.
5. **`serveBoard`'s `listening(options.host, …)`** (`board.ts:138`) connects to the bind host. Connecting to `0.0.0.0` works on macOS and Linux but not elsewhere, and connecting to `::` behaves the same way. Keep `portIsFree(options.host, …)` (`:132`) on the bind host, because that is a listen. Change `listening` to connect to the reach host.

## Shape

**In `packages/env/src/index.ts`:**
- `machineBoardHost(from, file)`: a copy of `machineBoardPort` (`:824-849`), with `Config.string('host')` nested in `board`, checked with `isIP(v) !== 0`.
  - `import { isIP } from 'node:net'` is safe here: the file already imports `node:fs` and `node:os` (`:1-2`).
  - An exported `LINGTAI_BOARD_HOST=''` comes back from `Config.string` as `Some('')` and fails `isIP`. Check that it is refused rather than treated as absent.
- `boardHost()`: `machineBoardHost() ?? '0.0.0.0'`.
- `boardReachHost(host)`: pure, as the ticket says.
- `boardOrigin(host, port)`: the **only** formatter of a board URL. It brackets when `isIP(host) === 6`.
- `boardUrl(from)`: `boardOrigin(boardReachHost(boardHost(from)), boardPort(from))`. Rewrite its comment (`:927`, *"Loopback: 0008 gave it no authentication"*) to cite 0111 §2.

**`boardAt(port)` becomes `boardAt(origin: string)`**, or `boardAt(port, reachHost)` with no default, so that `pnpm typecheck` lists every caller: `board-world.ts:25`, `daemon.ts:140`, `first-project.ts:1108` and `init.ts:1230`. Do not give it a default that reads `boardHost()`. That hides a throw inside a function the daemon calls.

**`boardPortOrWhy` widens** to return the port, the bind host and the reach origin, or `{ why }`. One function, so `boardOptions()` keeps its single `'why' in asked` branch, and a bad host becomes the board leg's `missing`, exactly as a bad port does. Its no-port fallback URL (`daemon.ts:124`) stays `http://127.0.0.1:${BOARD_PORT}`.

**`BoardWorld` gets a `reach` field** beside `host` (`board.ts:373`). `liveBoardWorld(host)` takes the host as an argument rather than reading it:
- `liveBoardRunner` (`cli.ts:369-375`) reads `boardHost()` in the same `try` as `boardPort()` and refuses through `failed('board', …)`. That makes a bad host a refusal of every `board` verb, as a bad port already is when no `--port` is given.
- `liveBoardWorld` sets `reach: boardReachHost(host)`.
- `bound` connects to `world.reach`.
- The three URLs in `board.ts` (`:459`, `:526`, and the refusal at `:552`) use `boardOrigin(world.reach, port)` or `world.reach`.

**`serveBoard`** derives the reach host itself from `options.host`, so `BoardOptions` is unchanged and init's call (`init.ts:1246`) needs nothing beyond `host = boardHost()`.
- `init.ts:1232` reads `boardHost()` inside the `board:` callback, before `tryLock`. A throw there is returned as `{ refused }`, the same way `serveBoard`'s throws are (`:1255-1258`). Wrap it rather than letting it escape the callback.
- Rewrite the comment at `board.ts:105-107` (*"The host is always set: 0008's board has no auth, and Next's default is `0.0.0.0`"*) to say 0111 §2.

**`apps/board/serve.ts`** reads `boardHost()` inside its existing `try` and passes `-H`.

## Why `bound` must use the reach host, not just for portability

On macOS, Node's listen sets `SO_REUSEADDR`, which lets a socket bind the wildcard address while another holds `127.0.0.1` on the same port. So `portIsFree('0.0.0.0', 17820)` can pass beside a board an older Lingtai left on loopback, and requests to `127.0.0.1` would keep going to the old one.

The lock (`boardLock(port)`) covers a board of this machine's. `bound(port)` probing `127.0.0.1` (`board.ts:547`) covers anything else. Both run before `serve`, so `board start` refuses either case today. Keep that order.

## Tests

All of these are unit tests. None needs `pnpm test:integration`.
- **`machineBoardHost`**: pass `from` and a `MachineFile` directly, as the `machineOtlpEndpoint` unit tests do. Do not use a temporary `config.yml`, which would make it an integration test (0060 §1).
- **`boardReachHost` and `boardOrigin`**: plain tables of values.
- **`board.test.ts`**: the fake world at `:47` gains `reach: '127.0.0.1'`. Add one case with `host: '0.0.0.0', reach: '127.0.0.1'` asserting that the printed and status URLs are `http://127.0.0.1:<port>`.
- **`boardPortOrWhy`**: add a case where the port is good and the host is bad, giving `{ why }` that names `board.host`.
- **Leave alone:**
  - `packages/env/integration/board-port.test.ts:28,45` still holds (`boardUrl` is `127.0.0.1` under the default).
  - Its `:88` scan is untouched.
  - `BOARD_JOB.argv` (`service.ts:172`) carries no host, so no service test pins one.

## `config.example.yml`

Under `board:` at `:71-75`, add `host` as a comment carrying the default:

```yaml
# host: 0.0.0.0
```

The comment says:
- the default is every address, with no authentication (0111 §2);
- `127.0.0.1` keeps the board to this machine;
- the value must be an IP literal, so a hostname is refused;
- changing it takes a restart of the board.

Leave `host` commented, so a person copying the file gets the default from the code and not from the file.
