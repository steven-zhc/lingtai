## What is still wrong in 0118

No `Resolution` carries them now: `GrantFixRound` is `{ onSha, ref }`, at `:231`. Drop *"or a conflict's base and head"*. Keep the `onSha` claim.

2. **`:287-301`, the `GrantFixRound` criterion bullet.** It lists findings, a disagreeing fixer, red build or verification, and a check refusal. It then says *"A reason with no criterion is never offered it."* A conflict is missing from that list, yet the table at `:267` offers `GrantFixRound` on `MergeConflict`. The code gives it a criterion unconditionally, at `packages/domain/src/wait.ts:357-361`:
   > `// A conflict always has a criterion: merge the base, resolve, commit.`

   Add a merge conflict to the "offered for" sentence, and add to the `grantCriterion` enumeration that `MergeConflict` always has one. Its brief is `step: 'merge'` with the paths as detail. Also check that sentence's *"with work preserved on a recorded remote ref"* still holds for the conflict case. The unpushed rule at `:276` drops it the same way for every variant, so it should.

3. **`:308-311`, the no-`Approve` bullet**: *"a conflict needs a confirmed behavior and another build and review."* Change it to say a conflict needs resolving, and then another build and review. Drop the word *confirmed*.

4. **§8's second bullet, `:527-533`**: *"…triage presents the hunks, its proposed behavioral resolution and a question for each hunk … The page lists every hunk with its status and opens only the ones that need the person."* Triage does still list the hunks, and the page does still draw them:
   - the triage prompt is at `packages/conductor/src/triage.ts:118-126` and `:264`;
   - the board groups them as Mechanical and Divergent, with each Divergent hunk's question, at `apps/board/src/app/standing.tsx:164-208`.

   **Keep that, but make it advice**, because nothing a person picks there reaches the grant. The conflict brief is built from the base and the paths alone (`conflictHalf(base, paths)`, `packages/conductor/src/fix.ts:641`). The picks feed the triage draft (`apps/board/src/app/triage-picks.tsx:155-170`). That draft is used by `EditBodyAndRequeue`, which the table does not offer on a conflict. Rewrite the bullet to say:
   - triage lists the hunks and the questions for a person to read;
   - the page also shows the wait's paths and GitHub's compare view (`ConflictEvidence`, `standing.tsx:425-462`). If no compare URL is known, the page shows the two shas instead;
   - the answer is the grant, whose brief tells the agent to stop and ask. The stop-and-ask is `STOP_AND_ASK` in the brief at `fix.ts:677`.

   Do not repeat the compare-link sentence that `ed0281a6` already put in the third bullet (`:540-541`). Move it into this bullet or leave it there, but say it once.

5. **§8's last bullet, past 20 hunks (`:545-547`): keep it.** The grant ticket did not remove it:
   - `MERGE_HUNKS_ONE_BY_ONE = 20` is still at `packages/domain/src/triage.ts:26`;
   - `wait.ts:656-664` still enforces it;
   - the board still prints *"start over from the new base"* (`standing.tsx:205-206`).

   Tidy only its last sentence. *"there is no per-hunk confirmation to supply"* explains the rule by contrast with the old design, and an ADR states the current decision with no history. End it at *"The answer is the same `GrantFixRound`."*, or say what the grant brief carries.
