## Shape

The ticket's six steps are right. The trouble is in four places the ticket does not name. Each one would show up as a red test or a refusing page halfway through, so they are decided here.

### 1. `implement` uses the same two schemas, and it still asks in prose

`InputNeeded` and `AgentQuestion` are not design-only:
- `commitFellShort` builds `InputNeeded{from: 'implement', question: action.result.question!}` (`packages/domain/src/attempt-next.ts:263`).
- The shell's own `asked` path builds it for either step from `ending.detail` (`packages/conductor/src/run-attempt.ts:2339`).

Implement's `Unclear` is #1250 and out of scope here. **So `said` is not just a field for old rows. It is the prose question.** An `implement` question is written as `questions: [], said: <text>`, which is the same shape the upcaster produces. Give both schemas a refinement: `questions` non-empty, or `said` present. Neither may be empty. Nothing ever writes `questions: []` with no `said`.

### 2. One function turns questions into text, and every text reader calls it

The question string is read in more places than the page:
- `evidence`. The comment at `agent-action.ts:1729-1734` says it is *"the sentence a person reads off the card, the evidence a judge weighs, and … `SentBack.asked`, which is quoted verbatim into the next design prompt"*.
- `wait-words.ts:236` and `:350` (`judgement(stepLine(…, 'asked', proposal.question), …)`).
- The GitHub comment at `tell.ts:758`.
- `history.ts`.
- The CLI.

Add one pure function in `packages/domain`, for example `askedText({ questions, said })`. It returns `said` where there are no questions, and otherwise a numbered list with each answer and the recommended one marked. Every one of those readers calls it.

`draftAnswer` (`agent-action.ts:1741-1750`) keeps `evidence` as a string: `askedText(questions)`, plus the draft under the rule, as it does today. The structured copy rides beside it on `ActionResult.questions`. That keeps the judge, `sentBackTo` (`run-attempt.ts:2590-2598`) and the run log working with no change.

### 3. The questions follow the existing path out of the pipeline

There are two paths to `InputNeeded`, and both must carry the questions:

- **Through `nextOf`:**
  - `step-outcome.ts:249-255` builds `Asked{question: outcome.evidence, draft: null}` and should add `questions: outcome.questions`.
  - The stored `Asked` (`packages/domain/src/action.ts:188`) gets `questions: z.array(TriageQuestion).optional()`.
  - `Asked` is inside `StepEnded.outcome` (`events.ts:1437-1440`). An optional field *"needs no bump and no upcaster, and a row written before it reads as the field absent"* (`events.ts:18-21`), so `StepEnded` stays at version 1.
  - `designFellShort` (`attempt-next.ts:283`) builds `InputNeeded{from: 'design', questions}` when `questions` is non-empty, and `said: question` when it is absent (an old `StepEnded`).
- **Through the shell:**
  - `PipelineResult.askedAt` is `{ action, detail }` (`packages/actions/src/action.ts:762`, set at `:1256`) and gets `questions?`.
  - `StepAsked` (`run-attempt.ts:428-434`) gets it too, through `endingOf` (`:2969`).
  - `:2339` then builds the same `InputNeeded` as the `nextOf` path.

`routeNext` (`routing.ts:178-182`) copies `questions` and `said` onto `AgentQuestion`.

`attempt.ts:416-441`'s `questionOf` stays a string. It feeds `run.steps[].evidence`, so it returns the stored `Asked.question`, which is already the text from §2.

### 4. Schema versions: these types are already at 2, and there is a nested reason

- **`BUMPED` already says** `ProposalRouted: 2`, `PassRouted: 2`, `WaitStarted: 2` (`events.ts:2915-2919`, #1241). Each moves to **3**, and the upcaster goes in `UPCASTERS` under key `2:` (`upcast.ts:155-170`).
- **`ProposalRouted` and `PassRouted`.** `InputNeeded` is stored whole: it is not in `COPIED` (`proposal.ts:245-254`), and `StoredProposal` lists it unpartialled (`:271`). The upcaster rewrites `offer.proposal` when `_tag === 'InputNeeded'` and `question` is a string. `PassRouted` is in `RETIRED` (`events.ts:2939`) but is still read, so it gets the same step.
- **`WaitStarted` has three places to rewrite, not two:**
  - `reason` as `AgentQuestion`;
  - `reason` as `ProposedEscalated` whose `proposal` is `InputNeeded`;
  - **`reason` as `AgentCrashed` whose `standing.reason` is either of those.** `StandingReason` includes `AgentQuestion` and `ProposedEscalated` (`wait.ts:188-200`), and a crash carries one as `standing: { waitId, reason }` (`wait.ts:225`).
  
  The existing 1→2 step does not go into `standing` (`upcast.ts:166-169`). This one must. It is one level deep and never recursive (`wait.ts:185-186`).
- **Snapshots and projections hold the reason too.**
  - `ticketReducer` stores `WaitReason` (`ticket-codec.ts:31`). Bump its `version` with a comment line, as #1267 did (`ticket-codec.ts:168-172`).
  - Bump `attemptReducer` from 12 to 13 (`run-codec.ts:197-209`), because it folds `StepEnded` and routes.
  - `parseStored` refuses a stored state whose re-encoding differs (`ticket-codec.ts:146-151`). Any `task_view`, `spend` or `ticket_report` row holding an old `AgentQuestion` will therefore throw `TicketCodecError` until somebody runs `lingtai projection rebuild <name>`.
  - This is the same deploy step #1267 (`8f1b7126`) needed. Say so in the PR body. No code can do it from inside a pass.
  - **What settles whether it bites:** any `WaitStarted` whose `reason._tag` is `AgentQuestion`, or whose `reason.proposal._tag` is `InputNeeded`, on a ticket that is still open.

### 5. `.min(2)` goes on the writer side, not on `TriageQuestion`

The ticket says to check the stored `WaitTriaged` rows first. A pass cannot do that: the agent is never given `LINGTAI_DATABASE_URL`. So take the side of the ticket's `if` that is safe either way:

- Add `AskedQuestion = TriageQuestion` with answers ≥ 2 in `triage.ts`, plus `.min(1).max(TRIAGE_QUESTIONS_MAX)` for the array.
- Use it in design's `parseDraft`.
- Use it as a check after `TriageResult.safeParse` in `conductor/src/triage.ts:432`. Triage's output schema is `z.toJSONSchema(TriageEnvelope)` (`wait.ts:978`) and stays as it is.
- `TriageQuestion` and every schema stored inside an event are unchanged. Nothing on the log can become unreadable because of this.

### 6. The board: the agent's picks are kept apart from triage's

The ticket says to pass `cause = {UndecidedQuestion, questions}` to `TriagePicks`. **Do not swap it into the existing `cause` slot.** Here is why:
- Triage also runs on `AgentQuestion` waits (`wait.ts:1058` → `statusOfFacts`).
- `requeueCard` sends `shared.picks` (`decide.tsx:604`), and the server checks them against *triage's* cause: `triageAnswersText(triage.cause, options.picks)` (`resolve-wait.ts:433`).
- If the agent's picks went in that slot, picking an answer and then pressing *Start over* would be refused as `stale` ("question 0 is not one triage asked"). Worse, a triage `UndecidedQuestion` on the same wait would quietly receive the agent's answer ids.

So:
- `TriagePicks` takes `asked: TriageQuestion[] | null`, taken from the wait's own reason, and keeps a **second** pick map for it.
- `TriageChoices` takes `source: 'triage' | 'asked'`, with `'triage'` as the default so `standing.tsx:485` and `:542` are unchanged.
- The `text` the body box is prefilled from (`decide.tsx:391`) is `triageAnswersText({ _tag: 'UndecidedQuestion', questions: asked }, askedPicks)` when `asked` is non-empty. Otherwise it is triage's, as today.
- `picks` stays triage's only. The answer travels as `EditBodyAndStartNewAttempt`'s written text (`resolve-wait.ts:429-430`, `writtenSection`), so the server needs no change.
- Draw the choices where `decide.tsx:409` draws the paragraph today. Where `questions` is empty, draw `said` as that paragraph.

### 7. The fence

Keep the label ```` ```question ```` so `OPENS_A_QUESTION` and `CLOSES_THE_FENCE` do not change. Only what `parseDraft` does with the text between them changes (`agent-action.ts:1576-1582`):
- `JSON.parse` fails → `unreadable`.
- `AskedQuestion` array fails → `unreadable`.
- Otherwise → `{ kind: 'question', questions, draft }`.

`ASKING_BLOCK` should show one complete JSON example with `id`, `text`, `answers[{id, text}]` and `recommended`. Keep its *"a question is not a doubt"* bar word for word.
