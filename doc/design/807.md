# Design note — #807

The ticket says which lines to delete. This note covers four things it leaves open: how the menu navigates, where it goes in the bar, what happens to each test case, and the CSS that removing the hero's second column requires.

## 1. The Docs menu: plain `<a>`, not `Link`, and no ARIA menu roles

`Bar` is not in the layout. Each page renders it itself (`docs/[...slug]/page.tsx:98`, `docs/page.tsx:32`, `docs/events/page.tsx:21`, `page.tsx:25`). Going from one `docs/[...slug]` page to another is a client navigation inside the same component, so React keeps the same `<details>` element. Its `open` state belongs to the DOM, not to React, so **with `next/link` the menu would still be open over the page you just went to.** With no client script there is nothing to close it.

So the eight menu items are plain `<a href="/docs/<slug>/">`, which is a full page load and comes back closed. Leave the brand link and the rest of the bar alone. Use `<details className="docs-menu"><summary>Docs</summary><div>…links…</div></details>`. Do not put `role="menu"` or `menuitem` on it: v3 has them (`home-page-v3.html:2659-2661`), but those roles promise arrow-key handling that only a script can provide. `<summary>` already opens and closes from the keyboard. Clicking outside or pressing Escape will not close it. That is the cost of having no script, and it is accepted. There is only one menu, so *closes when another is opened* never comes up, and the `name` attribute isn't needed.

Keep the list as data in `chrome.tsx`: an exported `DOCS_MENU` of `{ slug, label, note? }`, in the ticket's order. Copy v3's grouping (`:2661-2669`): Tutorial *One ticket, start to finish*, Concepts *The steps of a pass*, Requirements *What it needs*, then an `<hr />`, then Recipe, CLI, Plugins, Events, Coming from Symphony. Leave out v3's *What an agent can touch*, because it has no public slug. Leave out the *Replay* and *Its own books* links too, because their anchors arrive with later tickets.

**Where it goes:** directly after the brand, as in v3 (`:2657-2658`), then `.spacer`, then GitHub. That keeps Events before GitHub. Remove `Bar`'s `note` prop and its `.chip` line (`chrome.tsx:22,30`): `page.tsx:25` is the only caller and it stops passing one.

**Styles** go in `site.css` beside `.bar a` (`site.css:75-77`), not in `home.css`, because docs pages use the menu too. Both files are loaded globally (`layout.tsx:17-18`), but `site.css` is the bar's home. Use v3's `.menu-list` look (`home-page-v3.html:251-300`), positioned absolutely under `summary`. Hide the marker the way `.doctree summary::-webkit-details-marker` does (`site.css:333`) and add `list-style: none` on `summary`.

## 2. The hero becomes one column in CSS too

`.home .hero` is a two-column grid at every width (`home.css:14-17`) and only drops to one column at ≤1100px (`home.css:223`). If `RunDiagram` is deleted and the CSS left alone, the copy sits in the left half beside an empty column. Make the base rule one column. The ≤1100 override then has nothing to do, but leave it in place for #815, which brings the second column back.

Delete the `home.css` rules whose classes no longer appear in any `.tsx` under `apps/site/src` (the pass diagram, the loop, the minis, beside-the-loop, six-more-things, `.home-evidence`, `.hero-note`, `.hero-actions .second`, `.setup-steps ul/li li`, and so on). Grep each class before you delete it. `snapshot-board.tsx` stays (it is out of scope), so keep whatever it uses.

The new setup reuses `.home-setup`, `.setup-lead` and `.setup-steps` (`home.css:113-123`) with `.command` for the two commands, as the page does now (`page.tsx:373-375`). Step 2 has no command, only a sentence, and `lingtai ticket new` goes in a `<code>` inside it. The edges line keeps `.home-edges` (`home.css:132`) but drops the bold *Know the edges:* prefix, because the ticket's copy has none.

## 3. `page.tsx` after the cut

After the cut, `readSnapshot`, `stamp`, `landedCount`, `NoSnapshot`, `SnapshotBoard`, `BuildsItself`, the minis and the `ISSUES` const (`page.tsx:1-18`) are all unused. Remove them, because `pnpm lint` fails on unused imports. `Home` then no longer awaits anything. Make it a plain function unless something else needs it to be async.
