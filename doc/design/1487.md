## Design: #1487, asking how this machine reaches GitHub before `add` reads the repository

### Where it goes

Everything happens inside `askBeforeGithubAddEffect` (`apps/cli/src/add-github.ts`). The only outside changes are one new field on `AskedBeforeAdd` and one line in `add.ts`. `askGithubAuthEffect` (`github-auth.ts:80`) is called as it is, with no change.

**1. The new dep.** Add `githubAuth: (flags: Record<string, string>) => Effect.Effect<GithubAuthAnswer, unknown>` to `AskBeforeGithubAddDeps` (`add-github.ts:141`).
- `liveDeps` (`:176`) builds a `GithubAuthWorld` from what it already has: `ask: liveAsk`, `spin: liveSpin`, and `log` going to `console.log`. Its `github` field is:
  - `auth: () => githubAuthKind()`;
  - `ghStatus: () => ghStatusEffect()`;
  - `writeAuth`: the same `writeGithubAuth(liveMachineText(), join(home, 'config.yml'), kind)` that `liveFirstProjectWorld` uses (`first-project.ts:1587-1588`);
  - `gh: liveGh`, as `init` passes it (`init.ts:1311`). This dep is only called where `deps.interactive()` is true, so the sign-in offer (`github-auth.ts:147-187`) has a terminal to hand over.
- Call it as `askGithubAuthEffect(world, flags, false, ADD_KEPT)`.
  - `appConfigured` is always `false` at this point. `deps.auth()` is `githubAuthKind()`, and `electGithubAuth` returns `'app'` whenever an App's id and key are configured (`packages/env/src/index.ts:1629-1631`). So `kind === null` already means "no App here".
  - `ADD_KEPT` is `'Nothing was written and nothing was registered'` (`recipe-flow.ts:53`).
- A test stub that doesn't provide the dep must not ask. Make `githubAuth` optional, as `claudeToken?` and `sandboxHost?` are (`:167-171`). If it is absent, behave as today: `kind` stays `null`.

**2. When it is asked.** Replace `:290-294` with:
- `kind === null && authFlag === 'gh'`: set `kind = 'gh'`. This is unchanged.
- `kind === null && authFlag === undefined && !deps.interactive()`: refuse with *no GitHub auth is configured here — pass --github-auth gh or --github-auth app, or run lingtai init. Nothing was written*.
- `kind === null && authFlag === undefined && deps.interactive()`: call `deps.githubAuth(flags)`.
  - `{ refused }`: print it and return 1. Cancelling ends here, and nothing has been written yet: `writeAuth` runs only after a `gh` answer (`github-auth.ts:118-122`, `:142`).
  - `{ auth: 'gh' }`: `askGithubAuthEffect` has already written `github.auth: gh`. Set `kind = 'gh'`, and the existing `ghAccess` block at `:304` runs unchanged.
  - `{ auth: 'app', pending: true }`: `kind` stays `null`. Note in a local that `app` was chosen (see 4).
- Any other `--github-auth` value (`app`, or something invalid) is not asked about here. It continues as today, and `chooseFirstProject` validates or refuses it later (`github-auth.ts:88-90`).

**3. The seed's read keeps its error.** At `:383-397`:
- Split `defaultBranchOf` (`:80-91`) into:
  - `readDefaultBranch(owner, repo, reach): Effect<string, unknown>`, which is the current body without the `recovering`;
  - `defaultBranchOf`, which is that read plus the existing `recovering(() => Effect.succeed(null))`.
- Cache the read once as an Either: `Effect.cached(readDefaultBranch(...).pipe(Effect.either))`. Map it to `string | null` for the `defaultBranch` that `askRecipe`'s land default and `liveGithubReader`'s ref use (`:62-73`). Those two callers keep treating a failure as `null`, still from one request per run, which is what the comment at `:380-382` asks for.
- The seed alone looks at the `Left`:
  - **`reach === undefined` and no `--main`:** don't read at all. This is a `kind === null` run with an `app` answer or `--github-auth app`, or a half-configured App (`kind === 'app'` but `hasGitHubApp()` false). Refuse with *no GitHub App is configured here yet to read `<slug>`'s default branch — pass --main <branch> (the App is created after these questions), or --github-auth gh. Nothing was written*. A read here would only reach `githubApp()`'s throw (`:85-86`) and report it as a defect message.
  - **`reach` is set and the read failed:** say what failed, then where to go: *could not read `<slug>`'s default branch — `<errorText(err)>`. Pass --main <branch>, or fix that and run this again. Nothing was written*. Use the error's own message. Don't classify it into the ticket's four causes. `checkInstallation` and `ghAccess` have already ruled out "not installed" and "no access" before this point, so what reaches here is the transport's own sentence.
- Keep `recipePath`'s *does not exist* prefix from `:395` in both refusals, so the person still sees which file was missing.

**4. An `app` answer must not be asked twice either.**
- The ticket's double-ask argument (`github-auth.ts:93-110`: once auth is set, it only prints its line) covers a `gh` answer only. An `app` answer is `pending` and writes nothing (`github-auth.ts:44-49`).
- So `app` plus `--main` would get through the questions, and then `chooseFirstProjectEffect` would ask again (`first-project.ts:1270`, where `set` and `given` are both null).
- Fix: add `githubAuth?: 'app'` to `AskedBeforeAdd` (`add-github.ts:201-209`). Set it on that path. In `add.ts:214`, pass `{ ...flags, 'github-auth': 'app' }` to `chooseFirstProjectEffect` when it is present.
- With that flag, `askGithubAuthEffect` returns `{ auth: 'app', pending: true }` without asking (`github-auth.ts:111`), which is exactly what the person's answer would have produced.
- Copy the flags object; don't mutate it. `add.ts:188` and `:214` receive the same object.

### What the ticket leaves open, decided here

- **"Nothing was written" after a `gh` answer.** The add can still be refused after `github.auth: gh` is written, for example by `ghAccess` at `:313` or by the seed. The refusal sentences stay as they are. 0114 §1 makes the auth the machine's choice, not the project's, and the ticket's edge keeps it chosen.
  - Update the comment at `add.ts:192-193` (*"`askBeforeGithubAdd` above has written nothing"*) to name the one exception: `github.auth`, which is the machine's.
  - Update the comment at `add-github.ts:267-273`. *"The questions below still run and still write"* now holds only with `--main`. The no-terminal case is now refused with the flag named.
- **Where the question prints.** Print through `console.log`, like every other line this function prints. Don't use `world.log`; this function has no `world` until `:364`.

### Tests

All tests are unit tests, in `apps/cli/unit/add-github.test.ts` / `add-github-gh.test.ts`, plus one in `apps/cli/unit/add.test.ts` (which already stubs `githubDeps`, `:217`).

- **No double ask.** This has to be an `add.ts`-level test, because the second ask can only happen in `chooseFirstProjectEffect`.
  - Use one mutable `auth` value shared by `githubDeps.githubAuth`'s world and `project.github.auth`, and have `writeAuth` set it.
  - Count how many questions named `how this machine reaches GitHub` are asked. It should be exactly 1, once for the `gh` answer and once for the `app` + `--main` answer.
  - This stands in for the integration claim (*a real `config.yml` write is read back by `githubAuthKind()` on the next call*). That claim is true by `packages/env/src/index.ts:1636-1637` (the file is read on every call), and only `pnpm test:integration` would exercise it.
- **The seed's error.** The App-machine test needs `readDefaultBranch` injectable. It calls `githubApp()` and `createGitHubClient` directly (`:80-91`).
  - Inject it through the existing `reader` dep's neighbour: add an optional `defaultBranch?: (owner, repo, reach) => Effect<string, unknown>` that defaults to the live read.
  - Don't stub `githubApp`.
- **Ratchet.** The baseline must not move. All new IO goes through `Effect.gen`/`lift`, with no `async` and no `Effect.run*`.
