# Design: #362, the tutorial and the front page open on the interactive `lingtai init`

## The decision: the tutorial takes the `local` answer all the way to the end

The ticket asks only for a new opening. That is not enough. *Before you start* may no longer ask for GitHub, but today's Steps 2 and 4 cannot be done without it: *"select the repository where the GitHub App is installed"* and *"On GitHub, add one of the eligible labels"*. If only the opening changes, the tutorial drops GitHub as a prerequisite and then needs it two steps later.

So the whole tutorial follows a project that lives on this machine:

`init` → answer `local` → `lingtai ticket new` → `lingtai status` → `lingtai start` → `lingtai approve`

GitHub appears once, in Step 1, as the other answer to the project question. That paragraph says `github` creates the App and that `lingtai add <owner>/<repo>` then asks the same recipe questions at the terminal, as `init.ts:613-615` prints. It does not walk through the App.

Every command on that path exists for a project whose tickets are `db`:

- `ticket new` opens `$EDITOR` on a form with *"a title, a labels: line, then the body"* (`lingtai.ts`, USAGE).
- `ticket.ts:12-16` says it never builds a GitHub client: *"exactly the machine a `db`-ticketed project runs on"*.
- `askTickets` never asks a local project where its tickets come from: *"there is one legal answer (`db`)"* (`source.ts:79-80`, `:134`).

### New headings, and the test that pins them

`apps/site/unit/docs.test.ts:93-111` checks the exact list of `##` headings and a limit of 1400 words. Change the test in the same commit. The new list:

1. `Before you start`
2. `Step 1 — Set up this machine`: install and `lingtai init`, the questions in order, and the printed recipe.
3. `Step 2 — Open one ticket`: `lingtai ticket new --project <name>`, with a kind label on its `labels:` line. This replaces *Add one repository* and *Label one issue*.
4. `Step 3 — Check the queue, then start`
5. `Step 4 — Read the result`
6. `Next: make it yours`

Make sure the test still fails if the tutorial grows back into a reference manual, so keep the word limit. The new Step 1 is longer than the old one, so cut elsewhere. *If it waits on you* can shrink to `lingtai approve` and `lingtai requeue`, with a link to `operating.md`.

## What Step 1 quotes, and where each line comes from

Quote the strings from the source, not from #400's design. Several strings changed after that design was written. The order of what `init` prints:

1. **`looking before asking`** (`init.ts:354`), then the `git`, runtime and `home` rows (`:356-362`).
2. **The store.** The prompt is `a Postgres URL for the log — empty for SQLite` (`init.ts:809`). Postgres is mentioned here only as something you may paste.
3. **The project.** The prompt is `a GitHub project, or one on this machine only` with choices `github`/`local` (`first-project.ts:215-217`). **Its fallback is `github`**, so Enter picks GitHub. The tutorial must tell the reader to type `local`.
4. **The directory, then the base branch.**
   - `the directory of the repository on this machine` (`first-project.ts:331`).
   - `the branch this project's recipe governs and merges into`, offering the detected branch (`:407`).
5. **`use every default?`**, `yes`/`no`, fallback `yes` (`recipe-flow.ts:146-153`).
6. **If the answer is `no`, the recipe questions follow.** Each section first prints its `SAID` heading (`recipe-flow.ts:72-84`). The questions:
   - the agents (`agents.ts:179`, `:200`, `:232`);
   - the install command and the build checks (`setup-build.ts:195`, `:295`);
   - the kinds;
   - the landing: `land this on which branch, or "hold" to hold every pass for a person` (`landing.ts:155`);
   - rounds, wall and budget (`landing.ts:221-265`).
7. **The end of the run** (`init.ts:582-586`, `:635-655`):
   - `project      local — <name>, registered with its own origin as repo.remote`;
   - the recipe path, then the file printed exactly as written;
   - doctor's report;
   - `no board was started — lingtai board starts it`.

A prompt is shown as `<prompt> [<default>]: ` (`question.ts:117-120`). When you quote one in a code block, use that form.

### *Hold every pass for me* is not what the defaults give you

**This is the trap.** If the reader answers `yes` to `use every default?`, `acceptingDefaults` answers `''` to the landing question (`question.ts:88-98`). `''` takes the question's current value, which is the base branch (`landing.ts:146`). **So the default lands passes on the base branch with nobody approving them.**

To try it safely, the reader answers `no` and then types `hold` at the landing question. A script can pass `--defaults --land hold` instead: a flag always wins over a default (`question.ts:110-114`).

The tutorial should give the interactive path and give that pair of flags as the version with no terminal. It replaces today's `--project local` paragraph (`tutorial.md:59-66`). The `--github-app` flags in that paragraph go.

After answering `hold`, quote these:

- the confirmation line `landing       hold — every pass stops at proposed for a person` (`landing.ts:179`);
- the entry it writes under `steps.proposed`: `name: hold every pass` / `human: "Land this? The setup was answered 'hold'."` (`packages/recipe/src/answers.ts:26`, `:71`).

The entry is what the reader sees in the printed recipe. Step 4's `lingtai approve` is the answer to it.

### Capture the real output; do not rebuild it from the source

The ticket says **quote what the command prints**. It costs nothing to run, because nothing in `init` dispatches an agent (#391, and `doc/design/400.md` §*Nothing here spends money*). Run it against a scratch home and a scratch repository:

- Set `LINGTAI_HOME` to a fresh `mktemp -d` (`packages/env/src/index.ts:97-105`).
- Make a throwaway `git init` with one commit and an `origin`. A bare repository made beside it is enough.
- Answer at a TTY: `local`, `no`, `hold`.

**Do not run `lingtai start` against it.** It dispatches a real agent and spends money.

Without a TTY, the source above and `apps/cli/unit/init.test.ts` are the evidence:

- The test *"prints the recipe path, the file exactly as written, then doctor"* pins the order of the end of the run.
- `expect(logged.at(-1)).toContain('no board was started')` pins its last line.

Shorten the printed recipe to its `steps.proposed` block, and say that it is shortened. `emitRecipe` writes every schema default, including all ten steps (`doc/design/400.md`), and the full file would use up the word budget.

## *Before you start* names three things, and the third is the trap

- **Git.**
- **Claude Code or Codex, installed and signed in.** `runLocalBranch` refuses before writing anything when no runtime is signed in (`first-project.ts:416-419`).
- **A repository with an `origin` remote. Say this, because it is the first refusal a new reader will hit.** `runLocalBranch` refuses a directory with no `origin`. The reason: *"The merge lane pushes to the repository's own origin (packages/actions/src/merge-action.ts:47)"* (`first-project.ts:344-351`). The remote does not have to be GitHub: `resolveRemote(origin, toplevel)` takes a path. A bare repository on the same disk works.

Keep the existing line saying there is no database to provision. Remove the line requiring permission to install a GitHub App.

## The front page: the setup section only

`apps/site/src/app/page.tsx` is hand-written (0112). Its three steps are at `:170-208`; the ticket's `:113-133` is out of date. Rewrite them to match the tutorial:

- **01 `lingtai init`.** It looks before asking. It asks for the store (empty for SQLite), then GitHub or a repository on this machine, then the recipe questions. It prints the recipe it wrote. Answering `hold` stops every pass for you. Remove *"creates the GitHub App from a manifest"*.
- **02 `lingtai ticket new`**, with a kind label. This replaces *Review the proposed rules*, which describes the board wizard that a local project never opens.
- **03 `lingtai doctor` / `lingtai start`.** Replace *"Label an issue"* with words that do not assume GitHub.

`page.test.ts` checks the order of section headings, `<section className="home-setup"`, and that the page above *The work, in the open* never mentions logs or `Postgres sequence`. **Keep the setup copy's mention of Postgres to "or a Postgres URL"**, below that point, as it is today.

**Leave the hero lede (`:19-22`, *"picks up labeled GitHub issues"*) alone.** It describes what Lingtai does, not the setup, and the ticket's fix names only the setup steps. Open a follow-up if it should change.

## Also in `doc/tutorial.md`

- **Remove `img/machine.svg` from Step 1.** Its `aria-label` and caption say *"reads your labelled GitHub issues … merges back through the GitHub App"*. No script generates it, and drawing a new one is not this ticket.
- **Keep `queue.svg`.** Its *kind label, no hold label, no open blocker* filters apply to `db` tickets as well. But rewrite the `blocked-by` bullet: it currently says *"GitHub says an open issue blocks it"*.
- **Do not claim the board shows a local project's tickets** unless you have checked it. CLAUDE.md says *"The board's Queued column asks GitHub on render"*. Use `lingtai status <project>` (or `lingtai ticket list`) for the queue.
