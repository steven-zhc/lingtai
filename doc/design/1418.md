# #1418 — design note

## The decision the ticket leaves out

As written, the rule `.cards-in > p.empty { margin: 0; padding-top: 0; }` misses one case the ticket expects it to cover. It also breaks a case the ticket never mentions. Both come from the markup, so the change is still one rule in `apps/board/src/app/globals.css`, but with a different selector.

### 1. It misses the Waiting column's note

The ticket's edge says the Waiting note "is a `p.empty` inside `.cards-in` too, so it aligns as well". It is inside `.cards-in`, but not as a direct child. `HandledPart` is wrapped in a `div`:

```tsx
<Suspense key={`handled:${projectKey}`} fallback={<Skeleton shape="handled" count={1} />}>
  <div className="arrive">
    <HandledPart ... />
```

That is `page.tsx:1100`, and `HandledPart` returns `<p className="empty">{note}</p>` when `readHandled` gives back null (`page.tsx:1001`). So the DOM is `.cards-in > div.arrive > p.empty`, and the child combinator does not match it. `.arrive` sets only an animation (`globals.css:3681`: `.arrive { animation: card-arrive 200ms ease-out; }`). It adds no box offset, so once the `<p>` loses its margin and top padding, the note sits at the top of the column like the others.

The other empty-note sites are direct children, through fragments, and the ticket's selector already reaches them:
- Queued: `empty` is rendered bare inside the fragment returned at `queued-stream.tsx:447-459`.
- Landed: the `<p className="empty…">` inside `<>…</>` at `page.tsx:1125-1131`.
- Every other lane: the bare `<p>` returned at `page.tsx:1151-1156`.

Do not widen the selector to a descendant one (`.cards-in p.empty`). That would reach any `.empty` drawn inside a card. Name the one wrapper instead.

### 2. It strips the top padding from the fault box

`.empty.broken` is the red box saying "the queue could not be listed". It is a `p.empty` that sits directly in Queued's `.cards-in` (`queued-stream.tsx:45`, rendered at `:451-452`). Its padding is its own:

```css
/* An empty column says nothing in muted grey. A column that could not be filled
   has to read as a fault, or it is the empty column again (#76). */
.empty.broken {
  ...
  padding: 10px 9px; border-radius: 3px;
}
```

That is `globals.css:409-416`. `.cards-in > p.empty` has specificity (0,2,1) and `.empty.broken` has (0,2,0), so the ticket's rule wins. The fault text would then touch the top edge of its red box.

- **Zero margin is right for the box.** Its top edge then lines up with the cards beside it, as the ticket's Want asks of "the first thing in every column".
- **Zero top padding is wrong for the box.** It must not apply to `.broken`.

### The rule

Margin goes to zero for every `p.empty` that is a direct child of `.cards-in`, or a child of its `.arrive` wrapper. Top padding goes to zero only for those that are not `.broken`. That is two declarations in one place, next to `.empty` at `globals.css:401-407`, which itself stays unchanged.

Shape:

```css
.cards-in > p.empty, .cards-in > .arrive > p.empty { margin: 0 }
```

plus the same two selectors with `:not(.broken)` for `padding-top: 0`.

## Knock-on effects in Queued, and they are right

- **The `github.notes` lines** (`queued-stream.tsx:453-457`, `<p className="empty">project: reason</p>`) are also direct children of `.cards-in`. They lose their 12px margin and top padding and are then spaced only by the flex `gap` (`globals.css:400`). This is the same rule as the ticket's edge for a note after a `why nothing runs` card. In a flex column the margins never collapsed, so these lines used to sit 12px + gap + 14px apart. They will now sit at `gap` like everything else.
- **`.empty.held`** (`globals.css:407`) sets only a colour, so it is affected the same way as plain `.empty`.
