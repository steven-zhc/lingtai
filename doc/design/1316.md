# #1316: design note

The ticket says what to build. This note settles five things it leaves open, which would otherwise be found one review round at a time.

## 1. Step outcomes need a fifth event: `PrStepDone { step, headSha }`

Fix 2 lists four events. Fix 5 says the walk starts *"from the first step not recorded since the latest `PrInProgress`"*. Done-when says *"Every recorded step outcome carries `headSha`"*. None of the four events records a step that answered `done`, so that event has to be added:

- `PrStepDone { step: string, headSha: string }`: `['pr-']` in `STREAMS`, `['outside']` in `EVENT_AT`, with an `@summary`.
- Make `headSha` required in the schema. That is how *"a `done` that does not carry `headSha` is refused"* holds: it is refused by the decode, before the reduce ever sees it.
- Give `PrWaiting` a `headSha` too. A wait is an outcome, and the evidence names the commit it ran on.
- `again` records nothing, as the ticket says.

The reduce keeps `steps: { step, headSha }[]` and clears it on every `PrInProgress`, so a later pr-fix pass or retry runs the list again. The walk's "next step" is the first entry of `IN_PROGRESS_STEPS` whose name is not in `state.steps`.

**The step rows.** This ticket has no PR page; that is #1319 and #1320. The Done-when row is met by a pure function that the page will call:

- `prStepRows(names: readonly string[], state: PrState)` → `{ step, status: 'done' | 'waiting' | 'pending', headSha | null }[]`, in `packages/domain/src/pr.ts`.
- `IN_PROGRESS_STEPS` in `packages/conductor/src/pr.ts` exports its names. `apps/board` already depends on `@lingtai/conductor` (`apps/board/package.json:22`).
- The unit test passes `[...names, 'dummy']` and expects one more row.

## 2. The walk is tracked by the loop, not by the handler

`deliver` (`packages/daemon/src/work-loop.ts:438`) is fire-and-forget, and it arms a ten-minute timer that records `PluginFailed`. The handler has no way to reach `passesInFlight` (`:397`). So `PR_EVENTS` does not go through `deliver`. Give `makeWorkLoop` a `pr?: { serve(event), resume() }` option:

- **On a `PR_EVENTS` event:** call `passesInFlight.track(Effect.runPromiseWith(services)(pr.serve(e)))`. Attach a rejection handler that goes through `recorder.record('pr', …)`, but with **no timer**.
- **At the end of `start()`:** track `pr.resume()` the same way. This serves every PR whose state is `requested` or `in-progress`, and replaces the startup call. Discussions make that startup call in `apps/cli/src/daemon.ts:836`, outside the loop. Don't copy that placement, because an untracked startup walk is exactly what `restart` kills.
- `passesInFlight` counts these walks in `size`. Check that nothing reads `size` as "passes in flight" for slots (`createSlots` is separate, `daemon.ts:668`). If something does, add a second `createInFlight()` and have `stop()` wait on both. Don't share the slot count.

**Test:** `makeWorkLoop` with a fake `pr.serve` that waits on a deferred. Call `stop()` and assert it has not resolved; resolve the deferred and assert it has.

## 3. One walk per project inside the serve

The startup `resume()` and a live `PrSubmitRequested` can arrive together. So can two events for the same project, such as a request appended while a freeze is running. `packages/conductor/src/pr.ts` keeps a module-level `Map<project, Semaphore(1)>` (an Effect `Semaphore`). Each serve:

1. takes the permit;
2. re-reads the PR stream;
3. stops if the state is no longer `requested` or `in-progress`.

Every append is a transition at the version it read (`transitionPr`). That makes a second serve that slips past the permit (another process, say) harmless, as Edges says.

## 4. Testing "landed after the project last became team" by seq

`TicketState.landed` is `{ mergeCommit, base }` and has no time (`packages/domain/src/ticket.ts:301`). Don't add one: that bumps the snapshot codec version (`ticket-codec.ts:194`) for a field only this read needs.

`readPrDraft` already has to read each candidate's own stream (0129 §6). Inside that read:

- take the `seq` of the **last** `TicketLanded` envelope whose `data.base` equals the recipe's `branch.personal` (`Envelope.seq`, `packages/domain/src/envelope.ts`);
- take the `seq` of the latest `ProjectRecipeChanged` on `prj-{project}` whose `source` resolves to `modeOf(...) === 'team'` (`packages/recipe/src/settings.ts:255`) and that follows one that did not;
- keep the ticket only when the first seq is greater than the second.

Both seqs come from one log, so the comparison is total. Wall-clock `at` is not.

If the project's whole history is team (the first `ProjectRecipeChanged` is already team), the boundary is that first event's seq. If a `source` fails to resolve, treat it as not team. That can only shrink the draft. It must never fail the read: an unreadable old recipe is history, not an error.

## 5. Where each refusal comes from

- **The CLI:** `requestSubmit(latestPr, modeOf(recipe))` refuses `solo` and `open-pr` synchronously and appends nothing (Done-when 2).
- **The serve:** `nothing-landed`, `personal-missing`, `git` and a late `solo` are found only during the freeze. They become `PrSubmitRefused` on the PR's own stream.
- **What `lingtai pr submit` prints:** while it waits for `PrInProgress` (60 s), it also watches for `PrSubmitRefused` on the same stream. If one arrives, it reports `outcome: refused` with that `reason`/`detail` and exits non-zero, instead of printing *in progress*.

## Checks

Everything here can be checked at unit level: a memory store, a fake git port for `rev-parse` and `merge-base` that answers by exit code, and the fake `pr` handler over `makeWorkLoop`.

Only the real mirror's `rev-parse`/`merge-base` against a real repository would be an integration test. Leave that out. The fake git's exit-code contract (0 = yes, 1 = no, anything else = `git`) is the unit claim that stands in for it.

`effect-ratchet.baseline.json` must not rise. Write the serve, the walk and the reads as `Effect.gen`. The loop's own `Effect.runPromiseWith(services)` already exists at its delivery sites, and that is the only place a promise is made.
