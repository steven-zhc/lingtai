# Shape for #1513: the *Where it is* panel on a team ticket

## The decision the ticket leaves implicit: one read, three places

The streamed read now decides three things that sit in three parts of the tree:

1. **The heading's tag.** `<h2 className="ssectiontitle sec-h">Where it is</h2>` is drawn outside any boundary today (`apps/board/src/app/standing.tsx:1471`).
2. **The panel.** This is the only part that streams today: `<Suspense fallback={null}><OnYourBranch …/></Suspense>` (`standing.tsx:1475-1479`).
3. **The `who` sentence.** It is drawn about a hundred lines further down, at the end of `.sbody`, inside another boundary: `<Gh g={g} pending={pending} fallback={soWhatLine()}>` (`standing.tsx:1568-1571`).

Today `OnYourBranch` both reads and renders (`on-your-branch.tsx:83-104`), so only the panel can see what the read returned.

**The shape:**

- Split `OnYourBranch` into a read and the views that use it. The read is `whereItIs(project, ticket, landing): Promise<WhereOnBranch | null>`. It holds the one `Effect.runPromise(readOnBranch(project))` that is at `on-your-branch.tsx:92` now. Move that call; do not add a second one. The `Effect.run*` count in `effect-ratchet.baseline.json` must not rise, and raising the baseline is a blocking finding.
- In `StandingPage`, start the read once, under the same condition as today: `standing.state !== 'queued' && standing.landedOn && project !== null && issue !== null` (`standing.tsx:1475`). The result is a promise or `null`. Call it `panelRead`.
- **Heading and panel go in one boundary.** When `panelRead !== null`, replace the static heading and today's `<Suspense>` with one boundary:
  - It goes where the `Suspense` is now.
  - Its fallback is the bare `<h2 …>Where it is</h2>`.
  - Its child is an async component that awaits `panelRead`. When the read returns `null` it draws that same bare heading. Otherwise it draws `<h2 …>Where it is <span class="…">{small}</span></h2>` followed by the `.obs` panel.
  - Moving the heading into the boundary costs nothing in position: `.ssectiontitle { order: -2 }` (`globals.css:1235-1237`) puts it first in the `.swhere` grid wherever it sits in the markup. `Suspense` adds no DOM, so `.obs` stays a direct child of `.swhere`.
- **The sentence gets its own boundary on the same promise.** When `panelRead !== null`, wrap the `soWhatLine()` call at `standing.tsx:1569-1570` in `<Suspense fallback={null}>`. Its async child awaits `panelRead`, draws nothing if the read returned a panel, and draws `soWhatLine()` if it returned `null`. Keep the `Gh` wrapper around it as it is. When `panelRead === null` (solo project, or `landedOn` null), the code path is the one that exists today, byte for byte.
- **Why two boundaries are safe.** Both await one promise, so they can never disagree about the read's result. If the sentence's boundary resolves first, it only does so after the read resolved, and then it is already correct. While the read is pending, both show their fallback, which is the ticket's rule: heading without a tag, no sentence.

Do not use React `cache()` to dedupe two reads instead. Passing one promise is simpler, and it is the only way to be certain there is exactly one read.

## The rule under the sentence

The rule the ticket means is `.sbody`'s `border-top: 1px solid var(--rule)` (`globals.css:1249-1261`). `.sbody` still holds `.swhy`, the `Reason` and the run log when the sentence is gone, so do not remove the element.

Instead, when the panel is there, drop the border in CSS: `.swhere:has(> .obs) > .sbody { border-top: 0; padding-top: 0; }`. The panel's own border separates the sections. This follows the `:has` pattern of the quiet variant (`globals.css:1397-1400`).

The rule then appears only when there is no `.obs`: solo projects, and a read that returned `null`. Done-when 3 asks for exactly that.

## The tag

- The tag's text is `where.small.toLowerCase()`. Lower-case `small` itself in `task.ts:1086-1172` rather than in the view: the ticket allows changing the case and nothing else, and a lower-case value means the tests assert the text the page shows.
- `IN <name>` must not lower-case the branch name. Build it as `` `in ${name}` ``, not by lower-casing the whole string.
- Colours already exist as tag classes. `.ltag-branch` is `--accent-soft` with `--accent-ink`, and `.ltag-merged` is `--pass-soft` with `--pass` (`globals.css:942`, `:945`). Read the block around those lines and reuse its base class and its two variants. Add one `--fail-soft` / `--fail` variant for *not on your branch* only if none exists there. The variant is chosen from the `small` value's kind, not from its text: add a `tone: 'branch' | 'merged' | 'off'` beside `small` in `WhereOnBranch` (`task.ts:991`), or derive it in the view from a `switch` on the cases. Either way it is one `switch`, not a regex over the words.

- Copy the panel's frame from #1515's `.tcontext`: the same `--surface`, `--rule`, `--radius` and full width. Copy its `46rem` collapse too (`globals.css:1446-1451`): one column, and `border-left` becomes `border-top: 1px solid var(--surface-2)`.

- `.obs-sketch`: remove `max-height`, keep `width: 100%`, and add `preserveAspectRatio="xMinYMin meet"` on the `<svg>` (`branch-sketch.tsx:12`). The default value is the centring the ticket describes.

## The sketch's box

Today the box is `boxRight = Math.max(250, x(dots.length - 1) + 40)` (`branch-sketch.tsx:9`). Change it to the largest of three widths:

- 250;
- the dots' extent;
- `120 + text.length * 6.2 + 20`, where `text` is the string drawn at `:39-40` (label plus ` · + N more`). The 120 is the text's `x` at `:38`.

Build `text` once and use it both for the `<text>` and for the width, so the two cannot drift.

The `viewBox` is `640` wide (`:14`) and the lines run to `632`. Clamp the box at `632` rather than widening the `viewBox`, since today's longest label fits easily.

The unit test, in `where-on-branch.test.tsx`, renders `in the draft · not submitted` with one dot and `more > 0` through `renderToStaticMarkup`. It reads the `<rect width>` and asserts that the width is greater than `label.length × 6.2 + 20`. That reads one attribute and no positions, which is within what the comment at `:5` allows.
