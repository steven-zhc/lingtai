# Design: #693, a hint about price at the end of setup

## Read the models back from the file, at the summary, not from what `askAgents` returns

The ticket's Fix says to take the model from `modelChanges` and fall back to the recipe. That misses cases, because `askAgents` puts a model in three different places:

- **An action that already exists.** The model is in `modelChanges`. A blank answer is written as `value: undefined`, which clears the model rather than keeping the old one (`agents.ts:313-317`, `:327-331`).
- **No action yet** (an absent file, or a file with no implement or review action). There is **no `modelChanges` entry at all**. The model sits inside the new action object in `changes`: `if (writerModel !== '') action['model'] = writerModel` (`agents.ts:318-322`, `:332-335`). A check that only reads `modelChanges` would treat every brand-new project's model as "kept from the recipe", and there is no recipe yet to keep it from.
- **`reviewer === 'none'`.** This writes `steps.review: []` (`agents.ts:325-326`), so there is no reviewer to check.

On the absent path, nothing is on disk right after `askAgents` either. The answers are only collected, and they are written once at `recipe-flow.ts:317-332`.

So do the check where the file is already read back. `summariseRecipe` (`recipe-flow.ts:143-164`) resolves the written file "the way the pass will read it — never the answers held in memory". `askRecipe` calls it last, with the comment *"Last, and read back from the file: every registration follows this function (#542)"* (`recipe-flow.ts:351`). Make two changes there:

- **Extend `Summary`** with `models: { role: 'writer' | 'reviewer'; model: string | null }[]`. Take it from the first action carrying `agent:` in `steps.implement` and in `steps.review`, the same way `review` is already found at `recipe-flow.ts:155`. `null` means the action names no model. Presets come through `resolveSource`, so a preset's own steps are covered without extra work.
- **Print the hint lines right after `world.log(renderSummary(...))`** (`recipe-flow.ts:354`) and before the confirm at `:362`, so the confirm is still the last thing on screen. Use `world`, not `askWorld`, the same as the summary.

This still meets the ticket's edges:

- If `askAgents` refuses, nothing is printed, because the function returns at `:257`.
- Flags-only runs and kept models are covered, because the file holds whatever they ended up as.
- **The one new case:** a refusal in a later section (tickets, kinds, landing, limits) now also prints nothing. That is fine, because nothing has been registered yet.

`summariseRecipe` is exported. Before changing its return type, grep for other callers of `summariseRecipe` and `renderSummary`, so the new field does not break one.

## One pure function holds all the logic

Export something like `priceHints(models, snapshot: readonly RateRow[]): string[]` from `recipe-flow.ts`, or from a small new file beside it:

- **The check:** a model counts as priced if `shipped(model)` (`packages/domain/src/rate-card.ts:110`, *"any row for `model`, at any mode or date"*, which covers the fast-mode-only edge) or `snapshot.some(r => r.model === model)`.
- **Repeats:** remove duplicates by model name, so a writer and reviewer on the same unpriced model give one line.
- **Roles with no model:** however many there are, they give **one** line.

All four `Done when` tests can be written against this function, with `askRecipe` checked once end to end.

## How the snapshot gets in: injected, with the real reader as the default

Add `rates?: () => readonly RateRow[]` to `RecipeAt`. It defaults to `() => readRateSnapshot()` from `@lingtai/projector`. `apps/cli` already imports that package (`day-ceiling.ts:11`), and `package.json:28` lists it.

- **Tests need the injection.** Under vitest with no `LINGTAI_HOME`, `rateDir` returns `null` and the snapshot reads as empty (`packages/projector/src/rate-snapshot.ts:16-20`, *"no test prices from the developer's real one"*). So the "only in the snapshot" test has to pass `rates`. Planting a real `rates.json` would touch the filesystem, which makes it an integration test under 0060 §1.
- **The callers need nothing.** `first-project.ts:85` and `add-github.ts:33` leave `rates` unset and get the real snapshot.
- **Don't build the reader's env from `at.home`.** `readRateSnapshot` already finds `stateDir` from the environment. Joining `at.home` into it would make unit tests check for a file at a made-up path.

## Wording: one line covers both "no file" and "unreadable file"

`readRateSnapshot` gives back the same `[]` for both: *"Absent or malformed reads as none, never a throw"* (`rate-snapshot.ts:37`). Don't add an `existsSync` to tell them apart. Write one line that is true in both cases, along these lines:

> `<model>` is not priced yet — the shipped rate card does not list it and no fetched price for it is on this machine. The conductor fetches prices when it starts; check `lingtai doctor` after the first run.

> a role with no model is priced by the model its runtime reports on the first run

Two rules for the wording, from the ticket's Watch out:

- Never say *cannot* or *unknown for ever*. `init` does not fetch: *"models the shipped rate card does not list stay unknown until the conductor starts"* (`doctor.ts:1083`).
- Use `paint.muted` or plain text, never a warning colour. Nothing is refused.

## What existing tests will feel

Any unit test in `recipe-flow.test.ts`, `first-project.test.ts` or `add-github.test.ts` that checks the exact logged lines, and whose recipe names no model, now gets the runtime-default line. A test whose recipe names a made-up model gets the not-priced line.

- **Fix:** give the fixtures a shipped model (`claude-sonnet-5`, `rate-card.ts:46`), or have the test look for a line in the output rather than compare the whole list.
- **Don't fix it** by injecting a stub `rates` that prices everything. That hides the behaviour these tests are meant to show.

## Verification

All of this can be checked by the unit half: `pnpm test`, `pnpm typecheck`, `pnpm lint` and `pnpm fmt:check`. Nothing is written to the event log, so no event settles it, and nothing depends on `pnpm test:integration`.
