# Design: #1198, a judge declared at `nothing-produced`

The `offerFor` cell is the small part of this. The work is in three other places, and the ticket names none of them:

- the judge's `said` comes from somewhere other than the ticket implies;
- the judge prompt's other sections are wrong for this reason, not only *What to weigh*;
- the fix brief, as it stands, would tell the round's agent the opposite of what this round is for.

## 1. The offer: `packages/domain/src/failure/respond.ts:635`

Today the cell is `round('fix-lines', 'implement', false); restart(false)`. Change it to the `FixerDisagrees` criterion from `:640`: `said !== null && said.trim() !== ''` for the round, and keep `restart(false)`. Leave `BUILT_IN_FOR` alone. The rule that keeps an undeclared recipe free is `replyFor`'s `built === null → NotAsked` (`packages/conductor/src/proposed-route.ts:171-172`). Nothing calls an agent before `judgeDeclaredAt` (`conduct.ts:3306-3309`: `if (declared === null) return Effect.succeed({ noJudge: true })`).

## 2. What the judge is shown: two fields from two places

**The implementer's message comes off the proposal, not the evidence.** `whatArrived` reads `evidence` only from an ending with a `detail` (`attempt-steps.ts:593`). The `implement` visit that proposed this cleared, so `arrived.evidence` is `''`. `replyFor` already holds `offer.proposal` (`proposed-route.ts:156-160`). When it is `NothingProduced`, put its `said` on `Judging`. Do not touch `whatArrived`: its comment pins `evidence` to the refusing step's printed output.

**The ticket comes from `took`, in conduct.ts's `judge` closure.** `took` is in scope there (`conduct.ts:1756`, *"The item, once `claim`'s `queue:` action has taken it"*). It is set with `ticket: { ref, title, body: issue.body }` at `:2873-2876` on both the claim path and the continuation path (`:2791`). The fix round reads the body from the same place (`:4801-4803`). In `judge` (`:3306`), when `on.when === 'nothing-produced'`, spread `ticket: took?.ticket ?? null` onto `on` before `askTheAgent`. `run-attempt.ts` and `replyFor` do not see the ticket, so there is nothing to thread through them.

Both fields are optional on `Judging` (`attempt-steps.ts:350`) and absent for every other reason. A `findings` `Judging` stays the same object it is today.

**No clip on the body.** `runtime.budget` has `evidence`, `attempts`, `findings` and `diff`, and no key for a body (`packages/recipe/src/recipe.ts:3404-3415`). The implement brief and the fix brief both pass the body unclipped (`conduct.ts:4802`). Clip `said` the way `judgePrompt` clips evidence: `slice(0, 8_000)` (`judge-agent.ts:89`).

## 3. The prompt: each reason gets a row, and the row covers more than *What to weigh*

For `nothing-produced`, three parts of `judgeText` (`judge-agent.ts:109-162`) say false things, not just one:

- *"The cold reviewer raised no findings."* / *"The step printed nothing beyond that."* (`:119-129`). No reviewer ran, and what matters is the implementer's message plus the ticket.
- `MEANS.implement` is *"…for when the diff is the right approach and some of its lines are wrong"* (`:53-55`). There is no diff here. The round is *continue the work*.
- *What to weigh* (`:141-145`) is about findings.

So add one total record, `Record<JudgeWhen, …>`, with these parts in each row:

- **arrived:** a function from `Judging` to text;
- **means:** optional overrides of `MEANS`;
- **weigh:** text.

Every reason except `nothing-produced` points at one shared row whose text is cut verbatim from today's `judgeText`. `JudgeWhen` has 14 members (`packages/domain/src/proposal.ts:26-40`), so a fifteenth does not compile without a row. #1199 replaces the `fixer-disagrees` row.

The `nothing-produced` row:

- **arrived:** the ticket's title and body, then *"the implementer committed nothing; its last message:"* with `said`. Write it so a null ticket still renders, as *"the ticket could not be read"*, rather than throwing.
- **means:** `implement` means *"one more round in the same worktree, told what it said — for when the work is unfinished and the ticket is clear"*.
- **weigh:** 0108 §18's two readings. Is the ticket unclear, meaning a person has to say what is missing (`waiting`)? Or is the work unfinished, meaning the message names what is left (`implement`)?

**Write the byte-identical test first, on today's code.** Fix the `findings` prompt from an existing `judge-agent.test.ts` fixture as a literal string, check it is green, then refactor. A test written after the refactor proves only that the refactor agrees with itself.

`judgePromptParts` (`:100-107`) returns `[judgePrompt(on)]` whenever evidence is blank (`:102`), which it always is here. So the record writes the body out in full. Making the body a `TicketBody` ref, as `fixBriefParts` does, is out of scope.

## 4. The round: today's fix brief contradicts this round

Without a change, the route back reaches `fixRound` (`conduct.ts:4703`) like this:

- `from = again.printed?.step ?? 'proposed'` → `'proposed'`, because `printed` is null (`run-attempt.ts:2146-2154`: the arriving `implement` visit has no `detail`).
- `said = … ?? again.why` → the judge's words alone.
- `refusal = { on: 'output', output: why }` (`:4713-4748`).

`fixBriefParts` (`fix.ts:473`) then renders:

- *"The proposed action refused this change, and you are the fix"*;
- *"**You are not given the implementer's reasoning.**"*;
- the ticket as *"context for the refusal, not the job… the findings are still the criterion"*;
- *"Change nothing else."*

Every one of those is wrong when the job is to finish the ticket from where the implementer stopped.

The fix has three parts.

**`SentBack` gains `said: string | null`** (`packages/actions/src/action.ts:487`). `sentBackTo` (`run-attempt.ts:2134`) fills it when `arrived.step === 'implement'` and `route.to === 'implement'`. It reads `arrived.outcome`, which is the visit's own `StepOutcome` (`run-attempt.ts:569-583`). Compute it by **exporting `lastCommitEvidence`** from `packages/domain/src/attempt-next.ts:444` and calling it there. Do not write the filter a second time: its skip of a kept `run:`'s *"nothing to commit"* (`:436-442`) is exactly the subtle part. A route back to `implement` from `build` or `review` has `arrived.step !== 'implement'`, so `said` is null and nothing changes for those routes.

**`fixBriefParts` gains a fourth `refusal` arm**, `{ on: 'unfinished'; said: string; why: string }`. It needs its own header, evidence and criterion:

- *you are continuing an implementation that stopped before committing*;
- the implementer's last message, verbatim;
- the judge's `why`;
- the ticket body as **the job**, not as context.

Keep the decline section. A round that commits nothing is round > 0, so it proposes `FixerDisagrees` (`attempt-next.ts:140`), as the ticket's Edges say. `fixRound` picks this arm when `again.said !== null` and `findings.length === 0`. Pass `action: 'implement'`, not `from`, so no header says `proposed`. The other three arms must render byte-for-byte as before, and `fix.test.ts` already pins their sentences.

**The fix session id stays `${runId}:fix:${round}`** (`conduct.ts:4752-4755`). It does not resume the implementer's session. That is why `said` has to be in the brief: it is the only account the new agent gets of where the work stopped.

Not covered: a person granting a `nothing-produced` wait. That `SentBack` comes from `options.from.grant` (`run-attempt.ts:2319-2324`) with no `said`, so it renders the `output` arm as today. That is a person's grant, not this ticket's judge.

## 5. Tests: all unit-level, none needing the integration half

| Done-when line | Where |
|---|---|
| The offer, with and without `said` | `packages/domain/unit/routing.test.ts`, where the `NothingProduced` expectation changes |
| Undeclared → `NotAsked`, no agent | `replyFor` with a `judge` that answers `{ noJudge: true }` and counts its calls. Plus a `conduct-a-whole-attempt.test.ts`-style run with an empty `proposed:` whose fake runtime records zero judge dispatches |
| Declared → dispatched once, prompt contents | The pattern in `conduct-the-judge-is-in-the-fiber.test.ts`: a recipe with `judge: claude-code` at `when: nothing-produced` and a fake runtime that captures the prompt. Assert it contains the body, `said` and the new row, and **does not** contain *"whether the lines are wrong or the approach is"* |
| `findings` prompt byte-identical | `judge-agent.test.ts`, with the literal fixed before the refactor (§3) |
| Round 1, same worktree, brief has `why` + `said` | Same conduct test, with the judge answering `implement`: the second dispatch's prompt contains both, and `PassRouted.next` is `FixRound{round: 1}`. Unit stand-ins: `fixBriefParts` on the new arm in `fix.test.ts`, and `sentBackTo` on a visit list. It is not exported; test it through `run-attempt.test.ts`'s existing route-back cases |

In the log, the claim *the round spent one of `rounds`* is settled by `PassRouted.data.next._tag === 'FixRound'` with `round: 1`, followed by a `RunSpent` with `for._tag === 'Judge'`, `when: 'nothing-produced'`.

Everything new is pure functions or lives inside an existing `Effect.gen`. There is no new `async` and no new `Effect.run*`, so the ratchet does not move.
