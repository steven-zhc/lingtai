# Design note — #520

Use the current wait as the shared boundary. The task page must pass the `waitId` it rendered; the CLI must read the blocked lifecycle’s `waitId` from the ticket stream immediately before calling `editBodyAndRequeue`. The conductor checks that id and `allowedResolutions` before writing, then writes the body before resolving the wait (`packages/conductor/src/edit-body.ts:184-228`). This follows 0118 §11’s rule, “By the wait, not the ticket,” and §6’s rule, “The body is written first.” A CLI read that becomes stale is a refusal, not a reason to select a newer wait.

Add the page control through `movesOf`, which already takes the result of `allowedResolutions(standing.reason)` and is the moves row’s sole list (`apps/board/src/app/standing.tsx:361-380`, `:803-831`). The current worktree already exposes `reason` from the blocked lifecycle in `StandingView` (`apps/board/src/lib/task.ts:504-514`, `:744-775`); that part of the ticket needs no second implementation. Put the text box in its own page control, initially empty. Keep it mounted with its text on either refusal, and display the conductor’s `detail` verbatim. After a write followed by a refused requeue, that detail already names the ticket’s **current lifecycle state** (`packages/conductor/src/edit-body.ts:211-232`). Show success only when `ok` is true. 0118 §6 says, “If the requeue is refused after the write, the page says what the item’s state is now.” Keep this control on the task page: 0118 §2 says, “The card on the board carries only the number, the title, the rail and the hunk it is about.”

Make `--into-body` an explicit CLI mode: its presence selects `editBodyAndRequeue`, while absence retains the existing `requeue` call and output (`apps/cli/src/requeue.ts:40-65`). Require a value for the new flag, since the shared parser represents a valueless flag as `''` (`apps/cli/src/add.ts:48-75`). Obtain the issue channel via `projectClient`, as `closeCommand` does (`apps/cli/src/close.ts:45-69`), and pass it to the conductor. Keep the command’s projector and actor behavior (`apps/cli/src/requeue.ts:50-64`). Print the conductor’s detail and use its `ok` for the exit code, so “written, but not requeued” remains a failure with its precise state. Give the CLI branch a narrow injected store and client seam for the requested memory-store unit test; the production path supplies the real ones.

Test the composed page gating with `WaitReason → allowedResolutions → movesOf`, including the six named reasons; test that a refused page action leaves the text and conductor sentence visible. Test the CLI mode’s section and `WaitResolved{EditBodyAndRequeue}`, plus the unchanged plain requeue path. The unit-level claim covers the behavior available before merge; CLAUDE.md says the integration half takes 803 seconds and is run separately after merge.
