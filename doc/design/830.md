# #830 — the shape

The ticket already settles almost everything. This note covers only what the code adds: three places the fixture helpers will build the wrong history without complaint, and two small type issues.

## `applyTicket` (`packages/domain/src/ticket.ts:233`)

**Add the stream-id half before the guard, without touching the cases.** The `closed` guard at `ticket.ts:249` returns `{ ...state, ...at }`, and so does every case. If you give `project`/`externalRef` a fresh `state` before the guard, every path keeps them and no case changes:

```ts
const own = state.project === null && isTicketStream(event.streamId) ? parseTicketStream(event.streamId) : null
const s = own === null ? state : { ...state, project: own.project, externalRef: own.issue }
```

Then use `s` everywhere below that point. Don't reassign the parameter. Two things depend on this ordering:
- The `WaitResolved` case (`ticket.ts:407`) reads `state.externalRef` from that same `s`.
- So does the `WaitStarted` comment (`ticket.ts:341-344`). Its text, *"null only for a question asked before `TicketDiscovered`"*, is false after this change. Rewrite it to say the externalRef is null only on a stream that is not a ticket's.

**Read the title only in `TicketClaimed`, not in the shared `TicketContinued` case.** That case (`ticket.ts:268-269`) casts both event types to `PayloadOf<'TicketClaimed'>`. On a `TicketContinued` that cast makes `d.title` type as `string | null`, but at runtime it is `undefined`. Write:

```ts
title: event.type === 'TicketClaimed' ? (d.title ?? s.title) : s.title
```

and the same for `kind`. Put both in the claimed return, not before the continuation-of-an-unclaimed-run early return at `:272-274`. An old-form continuation carries nulls anyway (`claims.ts`'s rule), so nothing is lost.

**`TicketDiscovered`**: stop setting `project`/`externalRef`. Make `title`/`kind` follow the same latest-non-null rule (`d.title ?? s.title`), so a discovery with a null title arriving after a claim doesn't blank it. `source` and `labels` stay as they are.

## The fixtures (`packages/domain/test/histories.ts`)

**Order of the fixtures.** The module's `seq` counter (`histories.ts:56-62`) is consumed when `lateHistories`' values are evaluated (`:722-746`), after `histories` and `scenarios`. So:
1. Turn each `lateHistories.run` entry into a module-level `const`, in the same textual order, placed just above `lateHistories`.
2. Add the two new ticket consts after those.
3. Then make `lateHistories` reference them under `run:` and a new `ticket:` key.

The existing hashes in `unit/histories.hashes.json` must come out byte-identical. The test never writes that file; a red prints the new `ticket.*` entries for you to paste.

**Three helper traps:**
- **`aClaim` writes `title: null, kind: null` and nothing else** (`test/events.ts:158-160`). `titledByClaims` has to write its claims directly: `t('TicketClaimed', { runId, worker: 'conductor:1', title, kind })`.
- **No `aWaitId()`**: it is a global counter, and the module header forbids it (`histories.ts:15-16`). Use the module's `wait('9108-escalated')` literal and pass it to both `aWait` and `aResolution`.
- **The note goes in `aResolution`'s fifth argument**: `aResolution(t, w, { _tag: 'Requeue' }, 'steven', 'not this way')`.

**Issue numbers.** The ticket-kind histories use 9101–9106, and the highest number anywhere is 9303. Take 9107 for `titledByClaims` and 9108 for `escalatedThenRequeued`. That way the D4 answer test can assert the literal `agent/9108 is waiting on you.`.

**Why `escalatedThenRequeued` records an answer.** `ProposedEscalated` + `Requeue` is not the `OwnQuestion` early return (`ticket.ts:366-368`), so it reaches the `answers` append at `:399-415`.

The `COVERS.ticket` list doesn't change, because no new event type is folded.

## The board (`apps/board/src/lib/task.ts`)

- `loadTicket` (`:1507`) takes `const t = reduceTicket(own)` and uses `t.title` and `t.kind`. For labels it needs `[...t.labels]`: `TicketView.labels` is `string[]` (`:165`) and `TicketState.labels` is readonly.
- `standingOf`'s fallback (`:846-848`) becomes `item.externalRef`. Remove `isTicketStream` and `parseTicketStream` from the imports only if nothing else uses them; `:1448` and `:1508` still use `parseTicketStream`.
- The `loadTicket` doc comment (`:1498-1505`) says a title is *"recorded on `TicketClaimed`"*. That is still true; leave it.
