The fold needs one guard beyond the ticket’s “not older” wording: **`WaitTriaged` should write a result only when its attempt equals the row’s `triage_attempt`**. The existing stream reader says a result without a matching `TriageStarted` “is never read” (`packages/domain/src/read-model.ts:101-107`), and the accepted ADR says “`WaitTriaged` carries the same attempt, and only the latest attempt’s result is read” (`doc/decisions/0118-a-hold-explains-itself.md:337-343`). A result from a higher, unstarted attempt would otherwise make `toCard(...).triage` disagree with `triageFactsOf`. Use a guarded update for each triage fact so a wrong `waitId` or attempt changes no columns, including `updated_at` and `updated_seq`; use `event.at` for the start, following the projection’s “Every timestamp comes from `event.at`” rule (`packages/projector/src/task-view.ts:22-28`).

Guard on the **current waiting state** as well as `wait_id`. `waitOf` documents that some transitions leave a stale `wait_id` after moving the row off `waiting` (`packages/projector/src/task-view.ts:997-1007`). Both `toCard` readers should expose empty triage facts and a null head whenever `waitOf` returns null, even if those stored columns are temporarily present. This keeps the card’s reading aligned with the ADR’s rule that triage is shown “only while that wait is the current one” (`doc/decisions/0118-a-hold-explains-itself.md:451-458`).
