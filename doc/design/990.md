## Design note: #990

The ticket gives the shape of the change. These are the few points the code confirms or decides that the ticket leaves implicit.

**The flex chain has no hidden wrapper.** `FileView` returns a fragment (`file-view.tsx:16-21`). So in the read view, `.rfile`'s direct children are `FileBar`'s `.rfile-bar`, then the `<pre className="s2-yaml">` or the `YamlView` host `<div ref={host} />` (`yaml-view.tsx:42`). In edit mode the only child is `form.redit` (`recipe-form.tsx:53`), whose children are three hidden `<input>`s, the bar, the optional `.rfile-said`, the `<textarea>` and the editor host (`yaml-editor.tsx:100`). Hidden inputs have no box, so they don't affect the flex layout. No other element needs a class.

**The maximum height needs no border correction.** `* { box-sizing: border-box; }` (`globals.css:80`) applies to every element. `max-height: calc(100vh - 28px)` on `.rfile` therefore already includes its 1px border, so don't subtract 2px.

**Put the shrink rules in `globals.css`, scoped under `.rfile`, and not in `baseTheme`.** That means `.rfile .cm-editor { min-height: 0; flex: 0 1 auto; }`, next to `.rfile .s2-yaml` (`globals.css:3312`).
- The reason: `baseTheme` (`yaml-editor.tsx:23-31`) is shared by every place that mounts these extensions. Only the panel should know it is height-limited, and the ticket says the limit lives on `.rfile` alone.
- CodeMirror makes `.cm-editor` a flex column itself, and `baseTheme` already gives `.cm-scroller` `overflow: auto` (`yaml-editor.tsx:25`). So once `.cm-editor` can shrink, the scroller takes up the difference. Nothing more is needed inside CodeMirror.
- `.cm-editor` has no `overflow` of its own, so without `min-height: 0` its minimum size is its content and it won't shrink. Don't leave that out.

**The `<pre>` keeps its 80vh outside the panel.** Inside `.rfile`, set the `<pre>`'s height cap to `none` and let flex shrink it: `.rfile .s2-yaml { max-height: none; min-height: 0; flex: 0 1 auto; }`. Leave the bare `.s2-yaml` rule (`globals.css:3305`) alone; dropping 80vh is only required inside the panel.

**`.s2-right` stays as it is.** Its `align-self: stretch` (`globals.css:3306`) makes the right column as tall as the left one, which is what gives the sticky panel room to travel (#984). The panel's maximum height sits on `.rfile`, not the column, so the column needs no change.

**The 900px override goes in the existing media query.** Write `.s2.s2-even { grid-template-columns: 1fr; }` inside `@media (max-width: 900px)` at `globals.css:3349`, next to the `.s2` rule already there.

**No test needs to change:**
- `unit/task-page.test.tsx:462` finds the task page by the exact string `class="detail-body"`. Because the new modifier is added only on the recipe page, that string stays exact on the task page.
- `unit/recipe-editor.test.tsx:59-60` pins `rfile-edit` and the absence of `rfile-said`. Adding a class to the editor host keeps both true.
- No test pins `maxHeight`.

**Checking it:** `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` cover what can be checked automatically. Nothing at unit level can see a computed height, so the height claims rest on the ticket's manual checks in a browser. This change raises no number in the effect ratchet (`effect-ratchet.baseline.json`), and it touches no ADR.
