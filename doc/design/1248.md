# #1248 design note: where `replay` is declared and checked

## Where the code goes

**`plugin.ts` is where `replay` is declared, and where the import-time check runs.**
- Add `REDO_STEPS = ['prepared', 'design', 'implement', 'review'] as const satisfies readonly Step[]` next to `ANY_STEP` (`plugin.ts:156`). It goes here and not in `recipe.ts` because `definePlugin` needs it, and `recipe.ts` already imports from `plugin.ts` (`recipe.ts:24`). Going the other way would make an import cycle.
- Add a `Replay = 'safe' | 'external'` type.
- Add `readonly replay: Replay` to the `Plugin` interface (`plugin.ts:260-275`). It must be required on the interface as well as in the declaration, because the resolve-time check reads it off whatever `Plugin` it is handed.
- Widen `definePlugin`'s declaration (`plugin.ts:355`) to `{ fields, at, replay }`, and return `replay` in its result object (`plugin.ts:384`).

**`definePlugin` makes two checks, in this order, both after the existing `at`-key loop (`plugin.ts:358-366`).**
1. Throw on any `replay` that is neither `'safe'` nor `'external'`. Its own doc comment says why: *"a declaration reaching here from JavaScript has had no compiler"* (`plugin.ts:186-187`).
2. If `replay === 'external'`, throw when `servesStep({ at }, s)` is true for any `s` in `REDO_STEPS`. Use `servesStep` (`plugin.ts:192`) and not a key lookup, so that `"*"` is caught by the same line: `servesStep` answers true for `ANY_STEP in plugin.at`. The throw names the plugin, the step it found, 0108 §23, and the fix: serve `end`, or declare `safe`. Follow the format of the existing `at` throw.

**The resolve-time check goes inside `whyNoKindAt`, not beside it.** Today the function returns `null` as soon as the plugin serves the step (`recipe.ts:2001-2002`). Split that line:
- When the plugin is found and serves the step, and also `plugin.replay === 'external' && REDO_STEPS.includes(step)`, return a refusal.
- Otherwise return `null`, as it does now.

The real resolver already passes this result through `kindRefusedAt` (`recipe.ts:2318-2321`). The refusal therefore reaches every recipe with no second call site, and `stage: "recipe"` carries it to a daemon unchanged. The sentence:
- says the action writes outside the attempt's worktree and branch;
- says that a redo of `<step>` (0108 §12) would make it happen twice;
- cites 0108 §23;
- says it belongs at `end`.

`whyThatPair` (`recipe.ts:2043ff`) is not touched. This is a new answer for a pair the plugin *does* serve, not a new branch for a pair it does not.

## The decision the ticket does not spell out: the two checks never meet on one plugin

`definePlugin` throws at import on exactly the plugin the resolve-time check exists to refuse. So the `whyNoKindAt` test **cannot build its plugin with `definePlugin`**. It hands in a plain object literal typed `Plugin`, for example:

```ts
{ key: 'merge', schema, declares: ['name', 'merge'], secrets: [], at: { implement: … }, serves: ['implement'], replay: 'external' }
```

Then it calls `whyNoKindAt('implement', 'merge', [thatPlugin])`. Using an existing kind such as `merge` keeps `ActionKind` happy without a cast. That literal is the second guard working as defence in depth, and the test should say so in a comment. Do not loosen `definePlugin` to make the test reach the resolver. Do not touch any `at`, as the ticket's *Watch out* says.

The two halves can be tested in two places:
- `packages/recipe/unit/plugin.test.ts`: the `definePlugin` throws (one at `implement`, one at `"*"`) and a legal `external` at `end`.
- Either `packages/recipe/unit/plugin.test.ts` or `packages/conductor/unit/step-matrix.test.ts`: the `whyNoKindAt` refusal, plus a listing test, `PLUGINS.map(p => [p.key, p.replay])` `toEqual` the ticket's table in `PLUGINS` order (`recipe.ts:1527-1542`).

The existing `definePlugin(…, { fields, at: {} })` calls in `plugin.test.ts` (lines 81, 102, 346-372) and any in `step-matrix.test.ts` now fail to compile until they gain `replay: 'safe'`. That is the one-line cost the ticket's *Cost to later tickets* edge already accepts.

## Already done

**`end`'s once-per-outcome test already exists.** `packages/conductor/unit/end-step.test.ts:73` is titled *"resolves once per outcome, from the item's own stream"* and asserts `resolveEndActions(stream, [CLOSE], 'landed')` is `[]`. That Done-when item is met as it stands: cite the test in the commit and do not write a duplicate. `end-step.ts` is not touched.

## Doc comments

- **`runPlugin`** (`recipe.ts:123`) gets one paragraph. It is `safe` because Lingtai cannot see into a person's command, so a `run:` written at a redo step must be safe to run twice (0108 §23). Nothing checks that.
- **`queuePlugin` and `humanPlugin`** get one line each on why they are `external`: a claim and a person's question are both writes outside the worktree.
- **`definePlugin`'s own doc block** (`plugin.ts:334-352`) already names its two throws, so add `replay` there as a third. Without it, the paragraph saying *what it throws on* goes stale.

## What verifies it

Everything here is unit-level: `pnpm typecheck` catches a plugin with no `replay`, and `HOME=/nonexistent pnpm test` covers the rest. Nothing depends on the integration half. No ratchet or baseline number moves, because nothing here is IO.
