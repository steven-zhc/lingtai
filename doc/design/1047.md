# Design note: #1047, projector read faces become Effects

The ticket gives the shape. This note covers the four places where the code as it stands forces a choice the ticket does not spell out. The first projector ticket (#1046) and ES3-1 have landed in this worktree, so every name below exists already.

## 1. Building the port: call the `make…` makers, and change `one-store.test.ts`'s strings in the same diff

`openProjections` returns a `ProjectionsPort`. The promise twins are only `promiseProjectionStore` wrapped around the makers:
- `createPostgresProjectionStore` at `postgres.ts:240-242`
- `createSqliteProjectionStore` at `sqlite.ts:425-427`

If `choose.ts` kept calling them, it would have to unwrap a face to get back to the port. That is the Effect → face → Effect path the ticket forbids, and `store-face.ts:9-12` forbids it too: *"A moved caller is never handed a face."* So `openProjections` calls `makePostgresProjections` (`postgres.ts:247`) and `sqlite.makeSqliteProjections` (`sqlite.ts:433`).

Once it does, `choose.ts` no longer names either `create…` string. `unit/one-store.test.ts:88-94` would then find no file at all and go red. Take the ticket's second option: in the same diff, change the two `includes(…)` strings to `makePostgresProjections` and `makeSqliteProjections`.
- Keep the test's comment. Its rule is still true: exactly one file names both.
- Check that no other file under `src/` names both `make…` names. Today only `postgres.ts` and `sqlite.ts` each name their own.

## 2. Making the open lazy, and what a failure becomes

The open has to be an `Effect.gen` (or `Effect.suspend`) whose body runs only when something runs it.

**Postgres branch.** Call `chosenStore()` inside the body, never as an argument evaluated when `openProjections(…)` is built:
- Today `chosenStore()` throws the 0056 refusal synchronously inside an `async` function (`choose.ts:53`), which turns it into a rejection.
- Here it must become a defect carrying the same object. That means `Effect.sync` or a `yield*` inside the generator, not a typed failure.
- `runPromise` "rejects with the squashed cause: … else the `Die`'s defect itself" (`store-face.ts:6-7`). So callers see the same object they see today, and the board's `.catch` paths do not change.
- `makePostgresProjections` is synchronous and can throw: `new pg.Pool`, and `postgresUrl()` when `url` is missing. Keep the call inside the same lazy body.

**SQLite branch.** Keep it as `yield* Effect.promise(() => import('./sqlite.ts'))`, then `makeSqliteProjections(openSqliteProjections(choice.path))`. This is the same shape as `packages/event-store/src/choose.ts:145`.

**Building `process_`.** Write it as `closableOnceEffect(openProjections({ max: 4, allowExitOnIdle: true }), (p) => p.close(), () => new ProcessProjectionsClosedError())`. It is only valid at module scope if `openProjections(…)` does nothing until run (#179).
- `closableOnceEffect` already promises this for itself: "Nothing is allocated or run when this is called — it is built at module scope" (`closable.ts:40`).
- It also remembers a failed open: `Deferred.done(cell, exit)` at `closable.ts:62`. So the 0056 refusal repeats on every later read without being retried, which is the ticket's watch-out, and the shape gives it for free.
- `openProjections` itself may be an `Effect.fn('projector.openProjections')`. A traced fn returns a fresh Effect value on each call and runs nothing, so this holds either way.

## 3. The test seam

The bound form is `withStoreEffect(options, fn)`, and it delegates to an unexported-from-`index.ts` seam:

```
withStoreFrom(shared: ClosableOnceEffect<ProjectionsPort>,
              open: (o) => Effect<ProjectionsPort>,
              options, fn: (p) => Effect<A, E>)
```

Reuse the name `withStoreFrom` or pick another; the ticket only requires that the promise one is gone.

**Without a `url`:** `Effect.flatMap(shared.get(), fn)`.

**With a `url`:** `Effect.acquireUseRelease(open(options), fn, (p) => p.close())`. `fn` is a port method, so the read Effects have `E = ProjectionShapeError` for `tasks` and `landed` (`store.ts:402,407`) and `never` for the rest. That error passes through unchanged; nothing catches it here.

**Interruption** of a shared read stops only that fiber. `get()` restores interruptibility around waiting and around nothing else (`closable.ts:58-63`).

**Rewriting `unit/shared-store.test.ts`.** Build `fake()` as `open: () => Effect.sync(…)` returning `{ close: () => Effect.sync(() => counts.closed++) } as unknown as ProjectionsPort`. Build `shared` with `closableOnceEffect(open(), (p) => p.close(), () => new ProcessProjectionsClosedError())`, and drive each case with `Effect.runPromise`.
- The four cases are those the ticket's *Done when* lists. The fifth test, *an idle pool error is written*, is unrelated, so keep it.
- The refusal case asserts `rejects.toBeInstanceOf(ProcessProjectionsClosedError)`. That holds because `get()` dies with `refuse()` (`closable.ts:57`) and `runPromise` rejects with the defect itself.
- Once this is done, the test no longer imports `closableOnce` from `@lingtai/event-store`.

## 4. The faces, and what happens to `closableOnce`

`projectionStore(o)` becomes `return Effect.runPromise(Effect.map(openProjections(o), promiseProjectionStore))`. That counts as one `runPromise`, so the ratchet reads it as a face. The runner (`projection.ts:145`) and `the-written-choice.test.ts:221` still get a `ProjectionStore`.

`closeProcessProjections()` becomes `return Effect.runPromise(process_.close())`.

Each read Effect is `Effect.fn('projector.<name>')(function* (o) { return yield* withStoreEffect({ url: o.url, max: 1 }, (p) => p.<x>(…)) })`. The arguments are passed through exactly as the current bodies pass them (`task-view.ts:999-1008`, etc.). Keep `projectionLag`'s and `readLag`'s current argument handling (`projection.ts:299-313`) unchanged.

After this change nothing in `packages/projector` calls `closableOnce`. The `closableGetFace` / `closableCloseFace` rows in `effect-ratchet.faces.json:104-115` name projector as their reason (`"packages/projector choose.ts's shared store holds a promise closableOnce"`), and that reason becomes false.
- Leave the functions alone. Deleting them touches `packages/event-store`, which the `git diff --stat` box forbids.
- Nothing in `effect-ratchet.test.ts` checks a face's callers (`:271-298` checks only shape), so they stay green.
- Since the faces file is in scope, correcting those two `why`s to *"no caller since #1047; deleted with `closableOnce`"* is allowed but not required. Say so in the commit body either way, so the deletion becomes a backlog entry.
