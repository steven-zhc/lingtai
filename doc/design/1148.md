# Design note for #1148: the triage wall on Effect's clock

## The change in `apps/cli/src/triage.ts`

`waitTriage` (`:735-751`) keeps its shape: it builds the `AbortController`, gives `wall.signal` to `waitTriageWithin`, and passes the deadline on. Only two things change.

- **The timer.** `setTimeout`/`unref`/`clearTimeout` (`:743-744`, `:747`) become a child fiber: `Effect.sleep(Duration.millis(wallMs))` followed by `Effect.sync(() => wall.abort())`. Fork it with `Effect.forkChild` (Effect 4's name for `fork`), inside the `Effect.gen` that runs `waitTriageWithin`. A child fiber is interrupted when its parent ends, so the cleanup that `ensuring(clearTimeout)` did now happens on its own. If you want it stated in the code, `Effect.ensuring(Fiber.interrupt(wallFiber))` is fine too.
  - The fiber has to **call `wall.abort()`**. The ticket's trap is ending the Effect without aborting the signal, and that would break this chain:
    - every port gets `signal` (`:762`);
    - `guardedBy` races on that signal's `abort` event (`:592-606`);
    - the checkout's `tap` reads `signal.aborted` to clean up a late clone (`:1223`).

  Interrupting the parent instead would skip all three.
- **The deadline.** `startedAt` (`:745`) and the round check `wallLeft = deadline - deps.now()` (`:1029`) both move to `yield* Clock.currentTimeMillis`. After that nothing else reads `deps.now`, so delete it:
  - `now(): number` from `TriagePorts` (`:565`);
  - `now: Date.now` from the production ports (`:502`);
  - `now: () => 0` from `fakeDeps` (`apps/cli/unit/triage.test.ts:192`);
  - the override at `:1556`.

  This keeps the "Out of scope" line on `deps.now()` elsewhere, because there is no elsewhere. `tsc` will find any other fake that sets `now`.

## The trap the ticket doesn't name: `:1551` breaks quietly

*"the first call's limits equal triageCallFor(triage)"* (`triage.test.ts:1551-1562`) asserts `requests[0].limits` `toEqual` the full `wallMs`. It holds today only because `now` is a constant 1 000.

On the live `Clock`, `wallLeft` is `wallMs` minus however many milliseconds the reads took. The test would then be another load-dependent red, the very kind this ticket exists to remove. Run it on `TestClock` as well: frozen time makes the equality exact. Do the same for any other test that `toEqual`s `limits.wallMs`. `:1534`'s `toBeCloseTo` on `usd` is unaffected.

## How the tests are driven

Effect 4's `TestClock` is `import { TestClock } from 'effect/testing'`. The idiom already in the repo is `packages/daemon/unit/start-effect.test.ts:10,117,127`: write the test body as one `Effect.gen`, run `Effect.runPromise(program.pipe(Effect.provide(TestClock.layer())))`, and inside it call `Effect.forkChild(waitTriageEffect(...))`, then `TestClock.adjust`, then `Fiber.join`. Each test in the group builds its own program; the file's `waitTriage` wrapper (`:27`) stays for the rest of the file.

**Wait until the fake reached its call, then adjust the clock — never adjust first.** The wall sleep is registered as soon as `waitTriage` starts, but the fakes are promises that settle on microtasks, which `TestClock` does not schedule. If you `adjust` straight after the fork, the wall fires before `refSha` or `prepareCheckout` is ever called. That is #1146's race again, just in logical time instead of real time. So every test where the point is a specific read hanging should have that fake resolve a `Deferred` (or a plain promise) the first time it is called. The test awaits that, then moves the clock:

- **"hands the mirror a signal the wall aborts"** (`:1271`)
  1. Wait for `refSha` to be entered.
  2. `adjust('20 millis')`.
  3. Join the fiber.
  4. Assert `seen[0]?.aborted === true`.

  The `toBeDefined()` check now holds because of this ordering, not because the call happened to start fast.
- **"cleans up a checkout that lands after the wall"** (`:1193`)
  1. Wait for `prepareCheckout` to be entered. Its `Effect.sleep('150 millis')` is now on the `TestClock`, because forked fibers, including `guardedBy`'s `forkDetach` (`:598`), inherit the clock from the context.
  2. `adjust('50 millis')`, then join, and assert the timeout result and `requests` empty.
  3. Assert `cleanup` has not been called yet.
  4. `adjust('100 millis')`, then await a `Deferred` that the `cleanup` fake completes, and assert it was called once. Awaiting it replaces the real 250 ms sleep; vitest's own test timeout is the bound.
- **"ends as a timeout when a mirror read never settles"** (`:1168`): wait for `listAt` to be entered before adjusting 50 ms. Delete the `Date.now()` bound (`:1178`, `:1188`); the fiber having joined after the adjust is the claim.
- The `SHORT` tests (`:1225-1269`, `:1291`) follow the same pattern, each waiting on whichever fake it makes hang (`refSha`, `issue`, `conflictedPathsAt`, or the runtime's `run`).
- **"lets the next queued triage run once the first one hit its wall"** (`:1309`) runs `waitTriage` through `enqueueTriage`. Provide `TestClock.layer()` around the enqueued Effect and adjust after `refSha` is entered. Otherwise `SHORT`'s 20 ms still fires on the real clock: correct, but outside the ticket's "no real time in the group".

## Edges this decides

- **Production timing.** The daemon runs with the default `Clock`, so the wall fires when it does today.
- **`timer.unref`.** Its job was to keep a finished wall from holding the process open. An interrupted child fiber holds no handle at all, so there is nothing to replace it with.
- **The caller's own abort.** `request.signal` is still merged with `wall.signal` through `AbortSignal.any` (`:762`), and the `aborted` vs `timeout` choice (`abortedWhy`, `:766`) is unchanged.
- **Ratchet.** Nothing in this adds an `async` function or an `Effect.run*` call to `src`.
- **Checks.** `pnpm test` covers all of it, including the `:1551` test.
