# Design note for #887: event rows as sentences

## Where the change goes

There are four places, and nothing new reaches the database:

- `apps/board/src/lib/history.ts`: the formatters, the fallback, the actor in words and the header.
- `apps/board/src/lib/task.ts`: `groupHistory` and the two tab loaders.
- `apps/board/src/app/history-row.tsx`: the order of the columns.
- `apps/board/src/app/globals.css`: the column styles.

## 1. `summarise` and `toLine` take one context object

Today `summarise(event, branch?)` (`history.ts:554`) and `toLine(event, branch?)` (`:672`) pass `branch` as a loose second argument. Replace it with a single object:

```ts
interface LineContext {
  attempts: ReadonlyMap<string, number> // run id (= attempt stream id, `pass-…`) → N
  branch?: string                       // as today, for PassRouted (#505)
  claim?: 'claim' | 'continuation'      // set only on TicketClaimed / TicketContinued
}
```

The formatters get it as their second parameter, where `branch` sits now. Make `attempts` required. That way the type checker finds every caller, and the ticket's *an empty map is a bug* is enforced by tsc rather than by memory.

**The map's keys are attempt stream ids.** `groupHistory` looks them up by `attempts.get(e.streamId)` (`task.ts:1341`), and `loadAttemptTab` builds the map as `new Map([[run.runId, n]])` (`:1887`). So a run id, the `runId` in `TicketClaimed` and the part of an `agent:<pass-id>` actor after `agent:` are the same string. One lookup answers all three. Today `runShort` cuts that id down to 8 hex characters (`history.ts:122-124`). After this change it should only be used for the `title`.

## 2. Telling a continuation from a claim needs state, so `groupHistory` works it out

`summarise` looks at one event at a time. A continuation, though, is defined by what came before it: `claimShapeOf(event, claimed)` (`packages/domain/src/claims.ts:22`) says *"A `TicketClaimed` whose `runId` an earlier `TicketClaimed` on the same stream already carried is the old form of one."*

`groupHistory` already walks the events in seq order (`task.ts:1323`). Have it keep a running `Set` of claimed run ids for each stream, call `claimShapeOf`, and put the result in `ctx.claim`. Add to the set only on `TicketClaimed`, as that file's comment says. Do not compute this inside `summarise`.

## 3. Where the attempts map comes from

- **`loadTicketTab`** (`task.ts:1905-1910`) passes `new Map()` today. That is the bug the ticket names: every `TicketClaimed` on the Ticket tab would read *an attempt of another ticket*. Build the map from `reduceTicket(own).claims`, as `claims.map((c, i) => [c.runId, i + 1])`. `own` has already been read, so this costs no extra read. Use the same reduction `readAttempts` uses (`:1607-1608`); that keeps the numbering identical to the tab labels.
- **`loadAttemptTab`** (`:1887`) passes only its own run. Pass the full map built from the same `claims`: `readAttempts` already holds `runs`, and `runs[i]` lines up with `claims[i]` (`:1629`). Without it, any event on attempt 2's stream that names attempt 1 would read as *another ticket*.
- Group labels don't change. `groupHistory` labels a group by its own stream id, and a ticket stream's id is never in the map. On `apps/board/unit/task.test.ts:311`, follow the ticket's own instruction: change the labels only if #885 left one rendering.

## 4. The fallback

Do not print `describePayload` in the row any more. Its last three uses in `summarise` (`history.ts:567`, `:571`, `:584`) become `recorded ${event.type}; open for its fields`. The open row's `raw` already comes from `splitPayload`, so the fields are not lost.

`StepEnded` with `actions: []` is the case at `:567`, where `said` is empty. Give it a real sentence, such as *`<step>` ended with nothing to run*. Do this in its `FACT_FORMAT` entry, or by branching on `facts.length === 0` for that type before the join. It must not fall through to the fallback. Keep `describePayload` exported only if something outside `history.ts` imports it; check with `git grep`.

## 5. The three formatters that throw

- **`StepStarted`**: `stepAt` (`:137-139`) calls `need(d, 'action')`, and a `StepStarted` payload has no `action` field. Give `StepStarted` its own formatter that reads only `step`. Leave `stepAt` alone for the rows that do carry an action.
- **`TriageStarted`** with `model: ""`: `need(tagged, 'model')` (`:387`) throws on the empty string. For the `Agent` arm, write *triage run N* and leave the model out of the sentence when it is empty. Write *triage N (mechanical)* for the other arm. Never write *Attempt N* here. This `attempt` counts triage's own tries, which is the ticket's watch-out.
- **`WaitTriaged`** (`:506-507`) follows the same `attempt` rule. Name the move as `RESOLUTION_COPY[result.resolution].title` (`apps/board/src/lib/resolution-copy.ts:6`), never the tag. `history.ts` is pure, and `resolution-copy.ts` only imports a type, so the import is safe.

## 6. Money in `RunSpent`

Import `billText` and `unknownBill` from `apps/board/src/lib/spend.ts`. That file imports `@lingtai/projector` (`spend.ts:28`), so this pulls the projector into `history.ts`'s import graph. That is acceptable for two reasons:

- `task.ts` already imports `spend.ts`.
- No `"use client"` file imports `history.ts` or `history-row.tsx`. Its only importers are `task.ts`, `ticket-tab.tsx` and `attempt-tab.tsx`, and none of those carries `"use client"`.

The Next build is the only check that would catch a server-only import reaching the client bundle, and it is in the integration half (CLAUDE.md, #230). So confirm with `git grep -l "use client"` over the importers that this is still true when you finish. Do not assume it.

Build the reported bill the way `billOf` does (`spend.ts:141`):

```ts
{ reportedCents: Math.round(costUsd * 100), reportedRuns: 1, estimates: [], unknown: 0 }
```

When `costUsd === null`, use `unknownBill(1)`.

The subject comes from `for._tag` (`packages/domain/src/events.ts:881-892`):

- `Action` → the attempt's agent, with its step
- `Judge` → *the judge*
- `Triage` → *triage*
- `Discussion` → *a discussion*

The same switch answers the actor-in-words rule for `RunSpent` written as `conductor`.

## 7. Paths

Strip with `/^.*\/worktrees\/[^/]+\/[^/]+\//` and leave a path unchanged when the pattern does not match. Use this in `RunTouchedFile` and anywhere else a formatter prints a path, which includes `RunStarted`'s worktree if you show it at all.

## 8. Keep `FORMAT` as `Partial`; the test makes it total

`FACT_FORMAT` already covers the types `boardFactOf` owns, so a total `FORMAT` would mean writing those types twice. Rewrite the header's two rules (`history.ts:14-24`) to say:

1. Every type has a sentence.
2. The fallback is a sentence that points into the open row, and it exists only so a throw costs a sentence and not the page.
3. **The catalogue test, not the type, is what holds rule 1.**

## 9. The catalogue test

There is no fixture of sample payloads per event type anywhere in the repo; `git grep "Record<EventType"` finds none. Write one in `apps/board/unit/history.test.ts` as a total record over the catalogue:

```ts
const SAMPLES = { … } satisfies { [K in EventType]: PayloadOf<K>[] }
```

Each type gets a list, so that `StepEnded` with `actions: []`, `TriageStarted` with `model: ""` and a `TicketClaimed` continuation can each sit beside an ordinary sample.

Inside the test:

- Run every sample through `EVENTS[type].parse` so it is shown to be schema-valid. `EVENTS` is at `packages/domain/src/events.ts:2243`.
- Assert that the summary does not start with `recorded `.

A new event type then breaks typecheck in this test file and nowhere in the board's source. That is the cost the ticket accepts, without bringing back the header's *the renderer is behind the catalogue* problem.

Keep the existing `{}` / `null` / unexpected-shape loop (`:54-59`), with its assertion changed to expect the fallback sentence. It now covers the *a formatter that throws must not break the page* line in the Done-when list.

## 10. The row

`HistoryLine` gains `who: string`, computed in `toLine` from `ctx`. `shortActor` (`history.ts:594`) has no remaining reason to exist once the row prints `who`; remove it if nothing else imports it.

In `HistoryRow`, the order inside the summary becomes: when, then `.sum`, then `.who`, then `.what`. Keep `title={line.actor}` on `.who`. `hmeta` and `hraw` stay where they are, inside the open row.

## Checks

Everything here can be checked in the unit half: `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`. Update the strings pinned in the files the ticket lists. In `what-an-attempt-shows-today.test.tsx`, fallback rows turning into sentences is the point of the ticket, so rewrite those expectations to the new output rather than loosening them.
