## Design: #315, naming the predecessor's arm in the brief

### The ticket gets the ordering wrong, and following it gives the wrong answer

The ticket says to ask the mirror, because "`provisionWorktree` already reads `refs/heads/<branch>` … so the mirror is there and current by the time a brief is built." That is not the order things happen in:

- The brief is settled **before the claim.** `conduct.ts:818-825` calls `priorAttempts(before)`, reads the last run and calls `nextPrompt(...)`. That is where `failure` and `promptVersion` are decided. `prompt.ts:19-21` says why: *"It needs the version before it claims — the claim is what consumes the edit."*
- The mirror is fetched later. That happens only in `ensureMirror` (`packages/repo/src/worktree.ts:105`, `fetch --prune origin +refs/heads/*:refs/heads/*`), which `provisionWorktree` calls, and the conductor provisions after the claim (`conduct.ts:1701`, `lease = provisioned.right.remoteHead`).
- The previous attempt's arm was pushed **from its worktree straight to origin** (`conduct.ts:1489`, `+HEAD:refs/heads/${arm}`, and `:1497`). That writes nothing under the mirror's `refs/heads`.

So at brief time the mirror holds every arm except the one from the attempt just before. That is exactly the arm this ticket exists to offer, so reading the mirror would give a confident "no arm" every time.

**Ask GitHub instead.** `GitHubClient.matchingRefs(prefix)` (`packages/github/src/client.ts:150`, implemented at `:437-447`) returns every arm of a branch in one request. Its docblock matters here: *"Nothing matching is a 200 and an empty array … so an error here is never an absence."* `sweepRefs` already uses it the same way (`tell.ts:251-262`), with `armPrefix(branch)`. The prefix ends in `-attempt-`, so `agent/31` does not pick up `agent/314`'s arms (`branches.ts:66-73`).

By the time the agent runs, `provisionWorktree` has fetched the mirror. So an arm that origin had at brief time is a local ref in the worktree, and `git show agent/314-attempt-1:<path>` works as 0072 §4 says it does.

### Why not read the log for this

The log does record a push: `RunRefsPublished.arm` and `.outcome`, and `RunProducedDiff.branch`. But `nextPrompt` reads only the **last** run's stream (`prompt.ts:109-111`, and `attempts.ts:91-94`: *"conduct.ts fills exactly the last"*). The table has one row per earlier attempt.

The log is also not reliable proof. `events.ts:488-496` says a missing `RunRefsPublished` *"is evidence and not proof"*, because a store that refuses the row is swallowed on purpose. Use the remote for every row, and don't make the ref depend on `outcome`.

### The shape

**`attempts.ts` stays pure.** `attemptBrief(attempts, budget)` (`attempts.ts:339`) gains a third argument:

```ts
arms: { branch: string; onOrigin: ReadonlySet<string> } | null
```

For each shown row it derives `armBranch(arms.branch, a.n)` and prints the ref only when that name is in `onOrigin`.

- Import `armBranch` from `./branches.ts`. That module imports nothing (`branches.ts:16`), so `attempts.ts` still costs only `@lingtai/domain` (`attempts.ts:45-47`).
- `null` means **nobody asked**. It renders the same as an empty set: no ref on any row. This is the "null says nobody looked" convention `prompt.ts:90-93` already uses for `lastRun`.
- `a.n` is the same number the arm was pushed under. `nextPrompt` returns `attempt: attempts.length + 1` (`prompt.ts:139`) from the same fold, and `conduct.ts:830` pushes `armBranch(branch, next.attempt)`. `branches.ts:33` says the name is the attempt ordinal.

**The row.** Add a fourth column to the table at `attempts.ts:354-360`, e.g. `| # | run | how it ended | its commits |`. Put the ref in backticks, or leave the cell empty when the arm is not on origin. The ref and the ending share a row, as 0072 §7 requires.

The `… N earlier attempt(s), omitted` row gets no ref. The `budget.attempts` bound (`attempts.ts:24-28`) is about what gets printed, and it covers refs too.

**One sentence under the table**, and only when at least one row has a ref. It should:

- say those attempts' commits are readable from this worktree (`git show <ref>:<path>`, `git diff <ref>`);
- say to read them against how that attempt ended;
- leave using them or ignoring them to the agent.

It must not say *build on*, *continue from*, *start from* or *cherry-pick*. That would be the accretion 0072 §5 refuses, and "What this does not decide" says *"The brief offers; it does not instruct."*

Leave the existing `### What attempt N produced` paragraph (`attempts.ts:377-394`) alone. It is already an offer ("if it does not, ignore them"), and #82 is "a column and nothing else."

**`nextPrompt`** (`prompt.ts:95`) gains the same `arms` field and passes it to `attemptBrief` at `:133`. The field changes `failure`, so it changes `promptVersion` too. That is intended: `promptVersionFor` hashes the failure block (`attempts.ts:478-483`), so an attempt that was offered a ref and one that wasn't get different versions on the log. No event changes.

### The lookup, and both callers need it

Add one small function that takes a structural `{ matchingRefs(prefix): Promise<readonly string[]> }` and a branch, and returns `{ branch, onOrigin } | null`:

- strip `heads/` from what `matchingRefs` returns (`client.ts:447` leaves it on);
- keep only names that start with `armPrefix(branch)`;
- turn any throw into `null`.

Put it in its own file that imports only `branches.ts`, and export it the way `@lingtai/conductor/branches` is exported (`packages/daemon/src/converge.ts:62`). `branches.ts:5-19` tells the story of a type import that pulled `spawn` code into `apps/board`'s Next program, and the board needs this function too. Do not put it in `prompt.ts`, which "will not fetch" (`prompt.ts:15`).

- **Conductor:** call it at `conduct.ts:818-825`, **only when `previous` exists**, with `options.client` and `branch` (from `:784`). A first attempt makes no request, and `attemptBrief` returns `""` before it ever looks at `arms` (`attempts.ts:340`). That is what keeps attempt 1 byte-identical. Log one line when the lookup returned `null`, so a missing column has a stated reason.
- **Board:** `apps/board/src/lib/prompt.ts:152` calls `nextPrompt` too, and must pass the same thing. Otherwise the page shows a prompt without the column while the run gets one, which is the lie `prompt.ts:9-12` exists to prevent. `task.ts` already has `githubClientFor(state)` (`:1296`, `:1380`), and `outgoingFor` is called at `task.ts:1464`. Add an `arms` input to `outgoingFor` and fill it there.

### Known limit, deliberately not handled

An arm name is unique only within one log. After a reset (experiments 007 and 010), or a store switch (0055 §3), a new attempt *k* can find an old `agent/<n>-attempt-<k>` on origin that it never pushed, and the brief would offer it. `matchingRefs` returns only names, and the log holds a head sha only for the last run.

This needs a reset **and** standing arms, and declaring `refs:` now sweeps arms on every landed ticket. Leave it alone and say so in the new function's docblock.

### Tests: all unit, no integration needed

- **`packages/conductor/unit/attempts.test.ts`, beside the existing brief tests (~`:299-350`):**
  - an arm in `onOrigin` appears on the same line as that attempt's ending;
  - an attempt whose arm is absent has a row with no `-attempt-` in it, in a test named for "pushed nothing";
  - `null` and an empty set render identically;
  - `attemptBrief([], BUDGET, anything)` is still `""`;
  - the offer sentence appears only when some row has a ref, and a regex over the whole rendered brief finds none of *build on / continue from / start from / cherry-pick*. That regex is the check that catches the wording drifting.
- **The lookup function:** a fake channel like `sweep-refs.test.ts`'s `fakeRefs`. Check that it filters by prefix (use `agent/24` next to `agent/240`, as `sweep-refs.test.ts:112-116` does), strips `heads/`, and turns a throw into `null` rather than an empty set.
- `pnpm test` and `pnpm typecheck` are enough. The GitHub call sits behind a structural port, so nothing here needs the integration half.
