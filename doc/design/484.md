# Design: #484, the board's history, progress strip and task fold read one per-event fact, not today's event types

## The decision: one per-event export in the read model, and none of the four slice functions

The ticket says the four files read through `stepOutcomesOf`, `routesOf`, `waitsOf` and `releaseCauseOf`. **They cannot, if #482's pins are to pass unedited, and the pins win.** That is #480's ruling (`doc/design/480.md`: *"byte-identity wins over the literal 'from `routesOf`/`releaseCauseOf`/`waitsOf`'. The read model gets one more export that answers per event."*). #481 and #487 made the same call, and that is why `findingsRaisedOf` and `attemptFactOf` exist.

Each of the four readers renders or folds **one event at a time**, using that event's own `at` and payload text:

- **`history.ts`** produces one row per event. `toLine` (`history.ts:620`) takes `summary` from that event's payload. The pin's `historyOf` compares `{type, actor, summary}` for every line.
- **`progress.ts`** opens `now` at each event's own `at` (`progress.ts:426-530`). For the 'pending' state it relies on `StepRequested`, which no slice function reads.
- **`task.ts` `foldRun`** writes `evidence ?? detail` and `findings` for each verdict event (`task.ts:1090-1110`).

The slice functions give up exactly what these readers need. The read model says so itself:

- `RunStepOutcome` carries no `seq`/`at`.
- `stepOutcomesOf` skips any action that `shapeFor` cannot place, which covers `build`/`review`/`proposed` when there is no `StepsResolved` (`read-model.ts:1445-1448`). The strip would lose those segments.
- `cardFactOf`'s header explains why the slice functions *"are not callable on the one event a fold is folding at a time"* (`read-model.ts:1308-1316`).

This follows 0120 *Two phases*: *"Readers are written once, against the new types; at the switch only the read model and the builders change."* No ADR is contradicted.

### Why not reuse `cardFactOf`

`cardFactOf` is `task_view`'s, and its semantics differ from what the board reads in three places:

- **`FixApplied`.** It answers `null` when `costUsd === null` (`read-model.ts:1382`). `progress.ts:439` clears the fixing phase on *every* `FixApplied`, and `history.ts`'s `FixApplied` row prints a round that cost nothing.
- **`ApprovalGranted`.** `VERDICT` maps it to `'approved'` (`read-model.ts:1292`). `task.ts:949` and `progress.ts:521` draw it as `'passed'`.
- **`StepRequested`.** It does not own it. `task.ts:932` and `progress.ts:468` both read it.

Widening `cardFactOf` to cover these would change what `task_view` folds, and that is #480's pin.

## `boardFactOf(event: Envelope): BoardFact | null`, in `packages/domain/src/read-model.ts`

It goes in its own section after `attemptFactOf`, and its header comment follows that function's pattern: who reads it, and why it is not one of the slice functions. It answers `null` for any type it does not own.

**Rule: copy, never default.** Every field is the payload's own value, unconverted. Do not write `?? ''`, `Number(...)` or `String(...)`. `history.ts`'s `need()` throws on a missing or empty field, and `summarise` falls back to the raw payload (`history.ts:108`, `:520-532`). The fallback survives only if a field the payload lacked is still missing on the fact. Type the fields with `PayloadOf<…>`, and let the board keep its own defensive reads (`Array.isArray`, `typeof … === 'number'`).

Variant names use 0120 appendix's *Becomes* column where it gives one:

| Variant | Owns | Carries |

`read-model.ts:25` imports `type { Hold }`. It becomes a value import for `safeParse`.

**Names that are not old and stay as direct matches:** `StepStarted` (it *Becomes* `StepStarted`), `WorkItemReleased`, `IntegrationRefused`, `PassRouted`, `RunFinished`, `StepsResolved`, `RunPrompted`. Leave them out of the Done-when grep. That grep is the appendix's *Today* names that are renamed or removed (`doc/decisions/0120-a-reason-is-a-type.md:631-650`), plus `Hold`, as #483 used it.

Test it in `packages/domain/unit/read-model.test.ts` with the existing builders: one case per owned type, `null` for an unowned type, and one case where a missing payload field stays `undefined` on the fact.

## The four files

**`progress.ts`.** `foldProgress`'s switch (`:426-530`) keeps `RunStarted`, `RunFinished`, `StepsResolved` and `StepStarted` as direct cases. Every other case moves to `switch (boardFactOf(event)?._tag)`:

- `StepEnded` maps `ending` to its `StepState` (`Passed`→`passed` and so on).
- `SignoffGranted` maps to `passed`, not `approved`.
- `RunEnded` shares `RunFinished`'s agent-phase clear.

`keyOf(fact)` works unchanged because the fact carries `step`/`action`. Rewrite the comments that name old types (`:414-423`, `:497-520`) in 0118's words, keeping the issue numbers.

**`task.ts`.**

- `LIFECYCLE_MOVES` (`:503-509`) spreads `WAIT_EVENTS` (`read-model.ts:83`, *"0118's `WaitStarted`/`WaitResolved` at #464"*) in place of the two literals.
- `claimsOf` (`:972`) checks `boardFactOf(e)?._tag === 'RepairBought'`.
- `foldRun`'s `VERDICT` table (`:932-951`) and its approval cases (`:1076-1088`) become a single fact switch:
  - Keep `StepStarted` → `running` as the only direct match.
  - Read `evidence: fact.evidence ?? fact.detail ?? null` and `findings: fact.findings ?? []` exactly as `:1104-1105` do today.
- **`StandingView` and `BlockDiagnosis` stay as they are.** Changing that prop means editing `standing.tsx`, which the ticket gives to #483. That overrides `doc/design/483.md`'s *"#484 rewrites `BoardCard`/`StandingView`"*. `whoWaits`'s `life.runId === null` (`:691`) reads domain's reducer, which #483 left alone too, so leave it.
- The comments at `:213`, `:221`, `:395`, `:500`, `:529`, `:625` and `:959` are rewritten, not dropped.

**`history.ts`.**

- `summarise` (`:520`) tries `boardFactOf(event)` first. If it returns a fact, the sentence comes from a second table, `FACT_FORMAT: { [K in BoardFact['_tag']]?: (f) => string }`. The bodies are today's formatters, moved unchanged, reading the fact through the same `need`/`clip`/`sha` helpers. If it returns `null`, `FORMAT[event.type]` runs as today.
- The row's `type` stays `event.type`. #482 pins it, and the stored type is what a log row is.
- Delete the old-type keys from `FORMAT`, and the `Hold`/`legacyColumns` import at `:31`.
- `StepEnded`'s formatter branches on `ending` to keep five different sentences. The pins check each of them.
- Rewrite the comment at `:579`.

**`markdown.ts`.** Only the comment at `:11` changes: *a failed run's detail, a retired repair's detail*. There is no code change.

## Watch out

- **#230.** Every one of these files already value-imports `@lingtai/domain` (`progress.ts:33`, `history.ts:31`, `task.ts:3`), and the barrel re-exports `read-model.ts` (`index.ts:11`). The only `"use client"` module that reaches any of the four files is `discussion.tsx:59`, and it does so with `import type`. Keep it that way. Do not turn any type-only import from `@/lib/*` into a value import. Only the Next build would catch that (`apps/release/integration/build.test.ts`), and it runs after the merge.
- **Retired words.** `retired-names.test.ts` (part of `pnpm test`) counts `gate`/`gates`/`point`/`points` per file against `doc/reference.md:592`, whose allowlist is empty. Rewritten comments and moved code say *step*. A comment moved into `read-model.ts` takes its words with it.
- **Builder hold drift**, as in #483: `aWait` goes through `holdOf`. Where its hold differs from a hand literal in a field an assertion reads, use `aLegacyHold` (`test/events.ts:442`) and leave the assertion alone.
