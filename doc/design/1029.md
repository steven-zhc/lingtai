# Design note: #1029, retry a landing when origin can't be reached

## Where the code stands (it's partly ahead of the ticket)

- **#1019 has already landed, so `RepoFailed.stderr` exists.** It is defined at `packages/repo/src/git.ts:90` and filled in from `execFile` at `git.ts:137-148`. `mirror.ts:230` already reads `err.stderr ?? ''`. The classifier reads `stderr ?? detail`. You don't need to wait for a `stderr` that is already there.
- **`step-outcome.ts` is in `packages/conductor`, not `packages/domain`.** The file is `packages/conductor/src/step-outcome.ts:53-65`. **Remove the trap; don't just add a value to it.** Today the list is written by hand. Build it from the enum instead: `RefusalReason.options.filter((r) => r !== 'conflict' && r !== 'base-moved')`, typed as `RefusalReasonNoConflict[]`. Then the next reason anyone adds can't silently turn into `unexpected` either (`:67-71`).
- **No unit test in `packages/repo/unit` or `packages/conductor/unit` uses `TestClock`.** I grepped both directories. They run on a real runtime through `Effect.runPromise`, and `landNow` reaches git and the lane through two separate `Effect.runPromise` calls (`conduct.ts:1828`, `:3055`). The `TestClock` installed by an outer test would reach neither. So **the waits are a parameter, not a clock**: see the next section.

## The shape

### `packages/repo/src/network.ts` (new, exported from `index.ts`)

- `isUnreachable(text: string): boolean`, as the ticket specifies. A text that matches `PUSH_REJECTED` or `BASE_PROTECTED` is never unreachable. Both constants are module-private in `integrate.ts:218` and `:227`. Move them into `network.ts` and export them, so there is one copy, and have `integrate.ts` import them.
- `isUnreachableFailure(err: RepoFailed)` returns `isUnreachable(err.stderr ?? err.detail)`.
- `UNREACHABLE_WAITS = ['10 seconds', '30 seconds']` as `Duration.Input[]`. The number of tries is `waits.length + 1`, so "3" is never written separately from the list.
- `retryUnreachable(effect, waits = UNREACHABLE_WAITS)` is `Effect.retry` with a schedule built from `waits`, plus `while: isUnreachableFailure`. It does not use `async` or `Effect.run*`.
  - When the retries run out, it fails with the last `RepoFailed`. Its `detail` gets a suffix: `(after N tries)`.
  - Callers classify that failure with `isUnreachableFailure`. They don't need a second error type.

### `integrate.ts`

- **Add `unreachableWaits?: readonly Duration.Input[]` to `IntegrateOptions`**, beside `git?` (`:79-115`). It defaults to `UNREACHABLE_WAITS`.
- **Lane fetch (`:483-489`): put the retry outside `mirrorWrite`**, like this: `retryUnreachable(mirrorWrite(mirror, at([...fetch], mirror)), waits)`. Each try then takes its own permit and releases it, and the sleep runs with no permit held (0122 §6, #1026). Writing it the other way round, `mirrorWrite(…, retryUnreachable(at(…)))`, would sleep 40 s while holding the mirror. That is the ordering the ticket's Watch out row forbids.
- **Base push (`:657`): use `Effect.result(retryUnreachable(at([...push], cwd), waits))`.** This push holds no permit today, and it still holds none.
- **The refusal belongs in the one existing `catchTag('RepoFailed')` (`:698-700`), not at each call site.** Branch there: if `isUnreachableFailure(err)`, call `refuse('unreachable', …)`; otherwise keep `refuse('unexpected', …)` as today. The fetch and the push both reach that catch already. The push gets there through `Effect.fail(pushed.failure)` at `:665`, because `isUnreachable` gives way to both rejection patterns, so `BASE_PROTECTED` and `PUSH_REJECTED` are tested first, unchanged.
  - One catch covers both sites, and no network call added to `attempt` later can bypass it.
  - The other `at` calls are local (`worktree`, `status`, `merge`, `rev-parse`) and don't produce this stderr.
- **An `unreachable` result comes back from `attempt` as a terminal, never as `LostPush`.** The `for push` loop (`:745-750`) therefore returns it at once. It does not spend a `LOST_PUSHES` retry on it.

### `conduct.ts`

- **Give `ConductOptions` an `unreachableWaits?`** next to `gitEnv?` (`:525`). Pass it to `repo.integrate` at `:3056-3070`.
  - Tests set it to `['0 millis', '0 millis']`. Production leaves it unset.
  - `approve.ts` calls `integrate` itself and gets the default. That is correct.
- **`gitAsked` takes an optional second argument** and stays the same single `Effect.runPromise`:

  ```ts
  gitAsked = (args, retry?: readonly Duration.Input[]) =>
    Effect.runPromise(Effect.result(retry ? retryUnreachable(gitHere(args), retry) : gitHere(args)))
  ```

  Every existing caller is unchanged. The ratchet counts `Effect.run*` call sites, and there are no new ones. `landNow` is already `async`, so it adds nothing there either.
- **`landNow` (`:3038-3046`)**:
  1. Call `gitAsked([push…], waits)`.
  2. On failure, if `isUnreachableFailure(pushed.failure)`, return `{ notMerged: { reason: 'unreachable', detail } }`.
  3. Else if the stderr says `stale info`, check whether the push landed after all (see the next section). Run `gitAsked(['ls-remote', 'origin', `refs/heads/${branch}`])` with no retry.
     - If the sha it reports equals `on.onSha`, the push is done: fall through to `lease = on.onSha`.
     - If the `ls-remote` itself fails with an unreachable error, return `unreachable`.
  4. Anything else returns `push-rejected`, as today.

  The `stale info` check runs whenever that wording appears, not only after a retry. If origin already holds our sha, the push's purpose is met however we got there. Checking unconditionally means the combinator doesn't need to report whether it retried.

### `packages/domain`

- Make the ticket's changes to `vocabulary.ts`, `INTEGRATION_OWNER` and `REFUSAL_READING`, using `'base-checked-out'` as the pattern: owner at `attribution.ts:142`, reading at `:296`.
- **`wait-words.ts` `mergeRefusedColumns` (`:107-126`): drop the recommendation whenever `run.unpushed` is set *and* `reading.recommendation`'s action is `approve`.** Don't special-case `unreachable`. Here is why:
  - `allowedResolutions` drops `Approve` for any run with `unpushed` set (`wait.ts:482-485`, `...(unpushed ? table.filter((tag) => tag !== 'Approve') : table)`).
  - That makes `base-checked-out`'s card recommend a move it can't offer today, the same bug as `unreachable` would have.
  - The general rule fixes both, and the test in the ticket's Done when covers `unreachable`.

## Edges the ticket states that don't match the code

- **A second Ctrl+C does not interrupt the wait in `landNow`.** The ticket says it does. `gitAsked` and the `repo.integrate` call each start their own fiber with `Effect.runPromise`. Interrupting the pass's fiber doesn't reach them, and today it doesn't reach the git child either. So the bound on a drain is the retry bound itself: about 3 × git's own timeout plus 40 s, per site. Write that in the comment rather than claiming the interrupt reaches the wait. Making the sleep interruptible would mean turning `landNow` into an Effect, which is #790's work, not this ticket's.
- **When a lost base-push reply is followed by another landing, the result is `no-commits`.** The ticket marks this Out of scope, and nothing here changes it.

## What checks it

Everything is unit-level:
- `network.test.ts` for the classifier.
- `integrate.test.ts` with the fake `git` port (`IntegrateOptions.git`) and `unreachableWaits: ['0 millis', '0 millis']`. Assert the number of fetch or push calls, and check the event stream for exactly one `IntegrationAttempted`.
- A conductor test that overrides `ports.repo.git` for `push`, using the pattern at `conduct-a-whole-attempt.test.ts:743-744`, and `ports.repo.integrate`, using the pattern at `one-landing-at-a-time.test.ts:45`.

None of these needs `pnpm test:integration`.

**What only a real outage can confirm**: that git's stderr really matches the list under `LC_ALL=C` on this machine. The next time it happens, the log shows it in an `IntegrationRefused` event with `reason: "unreachable"` and a detail ending `(after 3 tries)`, or in a `ProposalRouted` whose proposal is `MergeRefused{reason:"unreachable"}`. Before this change, the same failure appeared as `push-rejected` (seq 30768).
