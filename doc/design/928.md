## Where the change goes, and the decisions the ticket leaves open

#927 has landed in this worktree, so the groundwork exists: `composePrompt`, `expandPrompt`, `markerOf`, `PromptRef` with `TicketBody` and `Diff` (`packages/domain/src/prompt-ref.ts`), the recorder (`packages/conductor/src/record-prompt.ts`) and the resolver (`packages/conductor/src/prompt-refs.ts`). This ticket adds one ref kind and one new kind of part, and moves one writer.

### 1. A `StepValue` ref is found by the recorder, not named by the caller

Rule 2 says the ref is made by searching *the read `recordPrompt` already does*. `composePrompt` is pure and cannot read: *"Pure, and no `node:` import: the board's client components import this package"* (`prompt-ref.ts:18-19`). So the caller cannot build a `StepValue` ref itself. It does not know the version, and nothing in `conduct.ts` holds the design's `StepEnded` version. `brief.design.document` is a bare string (`conduct.ts:3789`).

Add a third `PromptPart` shape, beside `string` and `{ text, ref }`:

```ts
{ readonly text: string; readonly find: { readonly field: 'evidence' | 'document'; readonly trimmed?: true } }
```

- **`composePrompt`** treats a `find` part as plain text in both `handed` and `recorded`. A prompt that is never recorded is therefore unaffected.
- **`ComposedPrompt`** keeps its `parts`, so the recorder can compose again.
- **`recordPrompt`** today does `store.read(stream).then((have) => store.append(stream, have.length, …))` (`record-prompt.ts:43-44`). Between the read and the append:
  - It maps each `find` part to `{ text, ref: { _tag: 'StepValue', stream, version, action, field, trimmed? } }`. It does this by walking `have` from newest to oldest and stopping at the first `StepEnded` that has an action whose value is `===` the part's text.
    - For `document`, the value is `outcome.actions[i].result.design.document` (`step-outcome.ts:238-240`, `action.ts:39-43`).
    - For `evidence`, it is `outcome.actions[i].evidence` (`action.ts:135`).
    - Apply `.trim()` to the value first when `trimmed` is set.
  - Where nothing matches, the part stays plain.
  - Then it calls `composePrompt` again and hashes as it does today.
- **The version the append expects** is `have.length` from that same read, so nothing new is raced.
- **`recordPrompt`'s `prompt` parameter** stays `string | ComposedPrompt`. A caller hands over `composePrompt(parts)`, the way `fix.ts:604` and `agent-action.ts:773` already do.
- **The action is named by `name`,** and the resolver takes the first action with that name. Build the search the same way: a ref is made only when the *first* action of that name matches. Then a step with two actions of the same name can never get a ref that the resolver reads off the other one.

### 2. The domain changes

- **`PromptRef`:** add a union member `{ _tag: 'StepValue', stream, version, action, field, trimmed?: true }`. This is additive. Every event already on the log still parses, so `RunPrompted: 2` (`events.ts:2505`) needs no bump and no upcaster.
- **`markerOf`** is a two-way ternary today (`prompt-ref.ts:146-148`). Make it a `switch` over `_tag` with no `default`. The new marker is `⟪lingtai:step <stream>@<version> <action>.<field> · N bytes⟫`.
- **The `Diff` check** at `prompt-ref.ts:139` and anything else that tests a tag the same way must still be exhaustive. Let `pnpm typecheck` find them.
- **The resolver** (`prompt-refs.ts`) gets a `StepValue` branch:
  - Read `stream`. The event at `version` must be a `StepEnded`, and it must have an action named `action`.
  - Take `evidence`, or `result.design.document` when the result is `Drafted`, and apply `.trim()` when `trimmed` is set.
  - Anything else is `unresolved`, with a reason. The resolver keeps its contract: *"It never throws and never invents text"* (`prompt-refs.ts:16`).

### 3. The implementer: one slot pass, built from parts

Today `renderPrompt` does six `replaceAll` calls one after another (`prompt.ts:238-244`).

- **Add a parts form,** `renderPromptParts(template, ticket, checks, failure, design, at)`:
  - It splits the template once with a single regex over the six slot names. Each slot becomes a part, so inserted text is never scanned again and never read as a `$`-pattern.
  - `at` is `{ bodyAt?: { stream, version } }`.
  - `{{body}}` becomes a `TicketBody` ref part when `bodyAt` is set.
  - `{{design}}` becomes the `designBrief` heading (`prompt.ts:360-372`) as a string, then `{ text: design.trim(), find: { field: 'document', trimmed: true } }`.
  - The appended tail (`prompt.ts:250-256`) uses the same parts. The tail's condition is still `template.includes('{{design}}')` on the *template*.
- **`renderPrompt`** becomes `composePrompt(renderPromptParts(…)).handed`, keeping its signature for the board (`apps/board/src/lib/prompt.ts`).
- **`alsoSays`** (`conduct.ts:3635-3636`) becomes a function over parts that appends one string part.
- **`bodyAt`** is `took.ticketId` and `took.claimVersion`, which `conduct.ts:3263-3271` already builds for the actions. Take it from there rather than spelling it a second time.

In `firstDispatch`:

- Hoist the prompt to `const implementPrompt = composePrompt(…)`.
- Record it between the `StepsResolved` append (`conduct.ts:3737-3745`) and the `server.register` call (`:3747-3750`), using:
  - `{ for: { _tag: 'Action', step: 'implement', name: spec.name, round: 0 }, promptVersion, prompt: implementPrompt }`
  - `promptVersion`, which is `next.version` (`conduct.ts:1257`).
- Wrap it in `Effect.promise(() => recordPrompt(store, runId, …, log))`. It never rejects (`record-prompt.ts:22-26`).
- Hand `implementPrompt.handed` to `dispatched.run`.
- Spell the `for` once and reuse it for the two `RunSpent` sites the ticket names.

**The design document must be found on `runId`'s stream.** `run-attempt.ts:1532` emits `StepEnded` with `runId: options.context.runId`, but which stream `emit` appends to is not something I could confirm from that line. The whole-attempt test settles it: assert that the record's `refs` contains a `StepValue` for the design. If the document's `StepEnded` turns out to be on another stream, the search does not reach it, and the design is written out in full. That is correct but saves nothing, and the test would show it.

### 5. The reducer and the stored row

`attempt.ts:417` is `if (d.for !== undefined) return state`. Replace it with a predicate: `d.for === undefined || (d.for._tag === 'Action' && d.for.step === 'implement' && d.for.round === 0)`.

- **Match on step and round, not on the name.** The name is the recipe's, and a renamed `implement` action is still the implementer.
- **The state gains `promptRefs`,** which is `d.refs ?? null`. Reset it to `null` when a record has none, for the same reason the comment at `:418-420` gives for `prompt`.
- **`run-codec.ts`'s strict row** gets `promptRefs` as `.optional()`, so a `task_view` row written before this still decodes.
- **`task.ts:1176`** passes it through, and nothing renders it. Expanding it on the page is out of scope.

### 6. The other three prompts

- **Design agent.** Add a `buildDesignPromptParts`, where `${issue.body}` (`agent-action.ts:1091`) becomes a `TicketBody` part when `issue.bodyAt` is set. This copies `agent-action.ts:459-461` exactly. `buildDesignPrompt` becomes its `.handed`. - **Judge.** Today the prompt is built as a string from `judgePrompt(on)` (`conduct.ts:2719`). Give it a parts form in which `on.evidence.slice(0, 8_000)` is `{ text, find: { field: 'evidence' } }`, with no `trimmed`.
  - When the slice cut the evidence, nothing matches and the part is written out. Section 1's `===` handles that case with no special code.
  - `promptVersion: judge@${length}` stays as it is, measured on `.handed`.
- **Fix brief.** `outputHalf` (`fix.ts:805-811`) returns `evidence` as a string. Make that half return `PromptPart[]`: the fence opener, `{ text: output.trim(), find: { field: 'evidence', trimmed: true } }`, and the fence closer. `fixBriefParts` (`fix.ts:518`) then spreads it in where it now interpolates `${evidence}`. `findingsHalf` and `conflictHalf` stay strings.

### Decisions the ticket did not make

- **Section 1's `find` part** is this design's choice. The ticket says the recorder searches, but not how a caller asks it to.
- **An empty or whitespace-only design** is `drafted === ''` today, so no part is made at all. That matches the ticket's *"A design that is `''` inserts nothing and gets no ref"*.
- **A `$` or a `{{slot}}` in the title** is corrected along with the body, because the single pass covers every slot. The byte-identical test should use a title and a body with neither.
