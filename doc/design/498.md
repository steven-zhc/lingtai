## One pure function decides what a figure says

All three readers render through a single pure classifier and summariser. Put it in `apps/board/src/lib/spend.ts`, not in a fold:

```ts
type Purpose = 'Work' | 'Answering' | 'Judge' | 'Triage' | 'Discussion'
// Action round 0 → Work; Action round ≥ 1 → Answering; else the tag (the ticket's rule)

interface Bill { reportedCents: number; reportedRuns: number; estimates: number[]; unknown: number }
function billOf(rows: readonly SpendRow[], price: (r: SpendRow) => number | null = noRateCard): Record<Purpose, Bill>
```

- **Each row goes to exactly one arm.** `costUsd !== null` makes it reported. Otherwise, if `price(row)` returns a number, it is an estimate. Otherwise it is unknown. `noRateCard` always returns `null` and cites #208. It is a parameter so the unit test can exercise the estimate arm. Do not write a rate-card reader; that is #208.
- **Keep the board's cents discipline.** `ledger`'s doc says *"the total is the sum of the rows as printed"* (`board.ts:1205-1210`). Round each row's reported figure to cents once, and build every footer by adding those cents.
- **The reviewer and the designer land in *Work* at round 0.** Today `cost_usd` is implement alone, assigned by `RunFinished` (`task-view.ts:495-502`). The ticket's split is by round, not by action name, so Work gets bigger: it now holds the review spend that 0110's *Not built yet* says was only in prose. That is the fix working, not a regression. Do not filter on `action === 'implement'` to keep the old number.

Every reader formats a `Bill` through one helper, so the wording is the same everywhere:

| reported runs | unknown runs | text |
|---|---|---|
| 0 | 0 | `—` |
| >0 | 0 | `$3.10` |
| >0 | >0 | `$3.10 + 2 unknown` |
| 0 | >0 | `unknown (2 runs)` |

Estimates go after it as `~$x est.` and never into the figure. **No path through the helper prints `$0.00` for a bill that has unknown runs.** That is the line the *Done when* test checks.
