## Design note — #916: the running panel's meters

### Where the meters are computed: one call site of two

`runningPanelOf` is called in two places:

- `standingOf`, at `apps/board/src/lib/task.ts:889`. This call has no spend rows and no recipe limits.
- `readAttempts`, at `task.ts:1757-1761`. This call runs after `spend` has been read (`:1701-1709`) and after `planFor` has returned (`:1726-1732`). Its result replaces the first call's whenever `standing.running != null`.

So give `runningPanelOf` a second parameter:

```ts
runningPanelOf(run, ctx: { rows: readonly SpendRow[]; currency: SpendCurrency; rounds: number | null } | null)
```

- `RunningPanelView.meters` is `null` when `ctx` is null.
- The `:889` call passes `null`.
- The `:1760` call passes three things:
  - `rows`: `spend.filter((row) => row.pass === enriched.runId)`. This is the same filter as `:1751`, so the bill and the turns come from the same rows.
  - `currency`: `spendFold.currency`.
  - `rounds`: `limits?.rounds ?? null`.

Do not make the parameter optional. A future caller that forgot it would then draw a panel with no meters and no compile error.

`grantedOf(rows)` (`apps/board/src/lib/spend.ts:279`) is the grant lookup for *round N, granted*. It is the same call `namedGranted` makes at `task.ts:1947`. A round is granted when some entry's `round === now.round`.

Read the fix round from `run.stepNow`. The panel already takes `head.round` from there (`running.ts:28-30`). `progress.now.label` is a string (`progress.ts:446`), so do not parse the round out of it.

### `sinceText` cannot go in `running.ts`

The ticket puts `sinceText` in `running.ts`, and `<Since>` is `'use client'`. But the meters need `billText` and `grantedOf` as values from `apps/board/src/lib/spend.ts`. That module value-imports `readLag` and `readSpend` from `@lingtai/projector` (`spend.ts:28`) and `timed` (`:31`). Once `running.ts` imports them, `since.tsx` importing from `running.ts` would pull the projector into the client graph.

Only `apps/release/integration/build.test.ts` catches that, and it runs after the merge (#230 is what that looks like).

**So put `sinceText` in `apps/board/src/lib/progress.ts`, beside `elapsed` (`:256`).** That module has two imports:

- a type-only import from `@lingtai/conductor/filter` (`:1`);
- an import from `@lingtai/domain` (`:35`), which client components already value-import (`apps/board/src/app/triage-picks.tsx:3`).

`since.tsx` imports only from `@/lib/progress`. `elapsed` already clamps to `0s` (`Math.max(0, …)`, `:257`), so the *now before iso* case is free.

Inside `running.ts`, use `import type` for `SpendRow` and `SpendCurrency`.

### `serverNow` already exists on the page

`Standing` takes `now = Date.now()` (`apps/board/src/app/standing.tsx:784`), and the layout passes it (`apps/board/src/app/task/[id]/layout.tsx:207`). `QueuedPanel` already receives it (`standing.tsx:1351`).

- Pass that same `now` to `RunningPanel` at `:1362` as `serverNow`.
- Do not call `Date.now()` again inside `RunningPanel`.
- `standing.tsx` is a server component (it has no `'use client'`), so `RunningPanel` can render `<Since>` directly.

Key each `<Since>` by `` `${runId}:${iso}` ``:

- *this round* uses `progress.now.since`;
- *the attempt so far* uses `progress.since`.

When the phase changes, the round's clock remounts; the attempt's clock keeps its timer. `RunningPanelView` has no run id today, so carry `runId` and the two ISO strings on `meters`. That keeps the component free of any lookup of its own.

### Shape of `meters`

Make it words plus the ISO strings, so the unit test of `runningPanelOf` asserts text and never calls a clock. For example:

```ts
meters: {
  round: { since: string; budget: string | null; of: string | null }          // of: 'round 1 of 4' | 'round 2, granted' | 'round 1' | null
  attempt: { since: string; turns: string; ceiling: string | null }
  cost: { text: string; ceiling: string | null; behind: string | null }
} | null
```

- `meters.round` is `null` when `progress.now` is null (between steps). The attempt and cost meters still draw: `progress.since` is `state.openedAt` (`progress.ts:412`) and is always set.
- Write the budget with `inWords`, as the rail does (`rail.tsx:323`, imported from `@lingtai/conductor/queue` in `standing.tsx:1`). Compute it in `running.ts`. Do not compute it in the client component.

### Spend that is behind, or a read that fails

- **A failed read.** `currentSpend` throws inside the `Promise.all` at `task.ts:1701`, so a failed spend read rejects `readAttempts` and no panel is drawn at all. This ticket adds no `catch`. That would be a second way of reading spend on one page, and #885's comment at `:1681` exists to prevent exactly that.
- **Spend behind the log.** When `spendChip(ctx.currency).current` is false (`spend.ts:243`), set `meters.cost.behind` to the chip's `label` (for example `behind 3`), and show it under both the turns and the cost. Rows that are behind make a low count, not a wrong-but-confident one, and the label says so.

### The turns and cost texts

- **Turns** is the sum of `row.turns` over `rows`. `SpendRow.turns` may be null on some rows: check `packages/projector/src/spend.ts:306-330` for its type before summing. If any row's turns is null, print the sum with *at least*, and never treat null as 0 (0110 §7).
- **Cost, with no rows**: print *nothing billed yet: no agent run has ended*. With rows, print `billText(totalBill(billOf(rows)))`. Never call `unknownBill`; that branch is `:1752`'s and stays there for the attempt tab.
- **Ceilings** come from `run.limits` (the new `AttemptView.limits`):
  - turns: *at most N turns a run* when `limits.turns` is set;
  - cost: *at most $X a run* when `limits.usd` is set (format it as `billText` formats money);
  - otherwise `null`, which the panel draws as *no limit*.

### Tests

These are all unit tests: no clock, no database.

- **`running.test.ts`**: build `AttemptView`s as the existing tests do, and pass a `ctx` with hand-made `SpendRow`s and a `currency` of `{ lag: 0 }`. Add one case with `{ lag: 3 }` that asserts `behind 3`.
- **`sinceText`**: lives in `progress.ts`, so test it next to `elapsed`'s existing tests if there are any, or in `running.test.ts`.
- **Static markup**: `renderToStaticMarkup(<Since iso serverNow />)` renders the initial state with no effects, so the hydration claim is exactly *the markup equals `sinceText(iso, serverNow)`*. Extend `apps/board/unit/standing.test.tsx` for the panel. It must stay a unit test: no `Date.now()` in the assertion. Pass `now` explicitly.

### Unchanged

- The rail's line (`rail.tsx:318`).
- `presentAttempt`'s output apart from `limits`.
- The `costUsd` that `readAttempts` already attaches.
- No ADR is touched: 0118 §2 already says *at most T a run* and *nothing billed yet*.
