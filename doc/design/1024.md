# #1024: design note

The ticket gives the shape. This note covers two things it leaves to whoever does the work: which order the commits go in, and what exactly the rename may touch.

## The commits, in order

1. **The errors commit keeps the identifier `GitHubError`.** The class becomes `class GitHubError extends Data.TaggedError('GitHubFailed')<…>`, so it already has its new tag, `detail`, `rateLimited` and the message rule. Only the TypeScript name stays the same. `NotInstalledError`, `BodyChanged` and `PermissionDenied` change in this commit too.
   - **Why:** CLAUDE.md § *Commits* lets a rename commit into `.git-blame-ignore-revs` only if it contains *"nothing but a scripted rename of identifiers and words"* and *"`pnpm typecheck` and `pnpm test` were green across it"*.
   - If this commit already named the class `GitHubFailed`, then every importer outside the package would fail `pnpm typecheck` until the next commit. That includes `apps/board/src/lib/task.ts:90`, `packages/conductor/src/onboard.ts:44`, `apps/cli/src/add-github.ts:29` and the nine test files. A shim (`export { GitHubFailed as GitHubError }`) would avoid that, but the rename commit would then have to delete the shim, which is a hand edit.
   - Keeping the identifier keeps both sides of the rename green with no shim.
   - In this commit, `asLinkCall` (`client.ts:541`) swaps `/rate limit/i.test(err.message)` for `err.rateLimited`.
2. **The rename commit:** a `\bGitHubError\b` → `GitHubFailed` substitution over `packages/` and `apps/`, and nothing else.
   - It covers comments and words as well as code: for example `client.ts:46`'s *"A `GitHubError` still, so an `instanceof GitHubError` check…"* becomes `GitHubFailed` in both places, and the ticket's first Done-when grep would otherwise still find it.
   - **It does not touch `doc/`.** `doc/decisions-archive/` is kept unchanged, and an ADR changes only by an edit to its topic's ADR, never by a sweep. The Done-when grep already excludes `doc` for this reason.
   - After the substitution, run `pnpm typecheck` and `pnpm test` before committing. A red means something other than the identifier changed.
3. **The `.git-blame-ignore-revs` line goes in a separate commit after the rename**, because the rename's hash does not exist until it is committed. Copy the format of the line already in that file.
4. **The `gh.ts` / `manifest.ts` / `gh-reader.ts` commit:** the three Effects, the three faces, the `faces.json` entries and the lowered baseline, as the ticket says.

## Faces: what the check accepts

`checkFaces` in `packages/domain/unit/effect-ratchet.test.ts:200-262` refuses a face unless:

- its body is exactly one `return`;
- the first argument to `Effect.runPromise` is a call expression, as in `ghTokenEffect(run)`;
- the second argument, if present, is an object literal with only `signal` in it (`:244-256`).

`return Effect.runPromise(ghTokenEffect(run), { signal })` passes as written, and `signal` may be `undefined`. The face has to be an `export function` declaration, as the ticket writes it.

Every entry in `effect-ratchet.faces.json` carries a `"file"` key next to `fn`, `until` and `why`, and the test reads it (`effect-ratchet.test.ts:527`). The ticket's §7 leaves it out:

- `ghToken` and `ghStatus`: `"file": "packages/github/src/gh.ts"`
- `convertManifest`: `"file": "packages/github/src/manifest.ts"`

## `PermissionDenied` and the message rule

`PermissionDenied` (`client.ts:53-63`) passes its long sentence to `super` as the third argument, so after the change that sentence is its `detail`. That sentence quotes `denied.message`, which already has the `403 on <path>: ` prefix. The final `message` therefore stays byte for byte what it is today: one prefix from the outer `super`, one nested in the sentence.

`rateLimited` on a `PermissionDenied` reads that `detail`, but `asLinkCall` only builds one after `rateLimited` was false, so nothing reads the two together. No new rule is needed.

## What stands in for the integration half

`packages/conductor/integration/wizard.test.ts` changes only by the rename, and nothing can run it before the merge. The unit-level claim that covers it is the rename commit's `pnpm typecheck` being green: the file's only edit is an identifier that `tsc` resolves.
