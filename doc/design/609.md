## The path remote holds today

These are the parts of the code the new setup goes through. Re-check each one and put what you ran in the PR body.

- **`init --local` reads `origin` and requires it to exist.** `apps/cli/src/first-project.ts:344` runs `git remote get-url origin` and refuses only when there is none (`:345-351`). It does not check what kind of remote it is.
- **A relative path is resolved for you.** `resolveRemote` at `first-project.ts:317-319` returns `isUrlOrScpLike(remote) ? remote : resolvePath(top, remote)`. So `../chapter-garden.git` set as `origin` is stored as an absolute path. Use an absolute path in the tutorial anyway, so the reader can see exactly what `repo.remote` will hold.
- **The schema accepts a plain path.** `packages/recipe/src/recipe.ts:3039-3043` says: *"Not parsed as a URL… a directory project (#394) writes an absolute path here."*
- **The mirror clones from it.** `ensureMirror` at `packages/repo/src/worktree.ts:111,120` runs `git clone --bare <remote>` with whatever `remote` is. A path is fine for git.
- **The merge lane pushes to it.** `packages/actions/src/merge-action.ts:47` does this. `packages/repo/integration/integrate.test.ts:54` already sets up its origin with `git clone -q --bare work originPath`.
- **The base branch is checked in the checkout**, with `git rev-parse` (`first-project.ts:21,28`). `main` exists there right after the clone.

**The check you can run inside a pass:**

1. Run the single file `pnpm vitest run packages/repo/integration/integrate.test.ts`. One file is quick. The whole integration half is not, and it is out of reach.
2. Run the tutorial's own setup commands in a temp directory with a throwaway `LINGTAI_HOME`, ending in `lingtai init --store sqlite --local <dir> --base main --defaults …`.
3. Read back `repo.remote` from the recipe that step wrote. It should be the bare repo's absolute path.

A real agent run needs Codex, so the full end-to-end pass cannot be checked here. Say that in the PR body rather than implying it was run.

## Decisions the ticket leaves open

**1. Make the bare repo from the checkout, not from GitHub.**

```
git clone https://github.com/steven-zhc/chapter-garden.git "$CHAPTER_GARDEN_DIR"
git clone --bare "$CHAPTER_GARDEN_DIR" "$CHAPTER_GARDEN_DIR.git"
git -C "$CHAPTER_GARDEN_DIR" remote set-url origin "$CHAPTER_GARDEN_DIR.git"
```

- This downloads the repository once, not twice.
- A bare clone of a checkout carries only its local branches, which here is just `main`.
- The `.git` sibling name explains itself, so the tutorial needs no new variable.

**2. `--base main`, and the tutorial branch goes.** The bare repo belongs to the reader, so there is no protected `main` to keep away from. Delete:

- the `tutorial_branch` lines and the `git push -u` in all three shell blocks;
- the `--base "$(git … branch --show-current)"` substitution in Step 1;
- the "fork it first" paragraph (`tutorial.md:24-27`);
- the `--base ...` row's *"Uses your tutorial branch"* wording (`:121`). Replace it with "merges into `main` of the bare repository beside your checkout".

**3. Landing goes into the bare repo, and the reader's checkout does not move.** Step 4 currently says *"the checked change reached your tutorial branch"* (`:211-212`). Change it to say the change reached the bare repository's `main`, and give the one command that shows it: `git -C "$CHAPTER_GARDEN_DIR" pull`. Without that line a reader looks at their checkout, sees no new chapter, and decides the landing failed.

**4. Remove "Optional Step 5 — Open a pull request".** It only works because a branch exists on GitHub, and after this change none does. Opening a PR from a bare repo means making a fork and pushing to it, which is the GitHub setup this ticket moves to Part 2.

- The H2 list in `apps/site/unit/docs.test.ts:115-124` pins `'Optional Step 5 — Open a pull request'`, so delete that entry in the same commit, or `pnpm test` goes red.
- Put a single sentence at the end of Step 4 instead, pointing to Part 2 for getting work onto GitHub.

**5. "Before you start".**

- **Chapter Garden row (`:13`):** keep only Node.js and npm. Drop SSH and "permission to push a branch".
- **Part 2 row (`:14`):** it already asks for a fork the reader owns. **Do not add an SSH requirement there.** Nothing in Part 2 uses it: `add` clones through the App over HTTPS (`worktree.ts:111`'s default `https://github.com/<owner>/<repo>.git`), and Part 2 never runs a `git push` by hand. The ticket says SSH "moves to Part 2", but writing down a requirement no step uses is exactly the kind of row this ticket is removing. Say so in the PR body.

## Watch out

- **Word caps** (`docs.test.ts:110-112`): Part 1's prose must stay under 1100 words, Part 2's under 600, and the whole page under 2000. Keep the three shell variants (`export` and `$(...)` behave differently in fish). They each lose three lines, which leaves room for the `pull` sentence.
- **Fish:** write `"$CHAPTER_GARDEN_DIR.git"` the same way in all three blocks. Fish expands `$VAR.git` correctly inside double quotes.
- **`pnpm lint` and `pnpm fmt:check` scan `doc/`.** The table in "Before you start" is padded to column width, so run `oxfmt` rather than editing the padding by hand.
