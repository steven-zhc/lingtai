# Design: #320 — the election, taken from `cbd2713` and made strict

## Where to start

`packages/env` has not changed between `cbd2713`'s base (`f3735bf`) and `HEAD`: `git diff --stat f3735bf HEAD -- packages/env` is empty. So this slice is exactly `cbd2713`'s three `packages/env` files, and they check out without a conflict:

- `packages/env/src/index.ts`
- `packages/env/unit/github-app-source.test.ts`
- `packages/env/integration/env.test.ts`

`agent/308` already exists locally, so no fetch is needed. Take nothing else from that commit. `create-app.ts`, `init.ts`, the board page and `doctor.ts` belong to the other slices.

`cbd2713` already does most of what the ticket asks:
- `machineGithub` reads the file under `machineChoiceFile` (`index.ts:411`), which makes the doctor finding free.
- `githubRecordFromSection` resolves a relative path against `stateDir(from)`.
- The machine source is pushed last.
- `source` is labelled through `realEnvironment` (`:398`).
- `unreadable` is appended to the not-set error.

The note below covers only what changes on top of it.

## The decision: the owner answers every name, with no fallback

`HEAD`'s election is "owner first, then the rest". The owner is found at `:1071`, and at `:1072` it is prepended to the other sources, which stay in the list. The docblock says so outright (`:1053-1054`): *"the source that names the id is asked first for every other name, and the rest only for what it does not say."*

`cbd2713`'s `electGithubSource` kept that rule. The rule is the Major finding. Its own unit test asserts the mismatch: *"lets an env file that names the id win over the machine file for every name"*. In that test the env file names App 222 and says nothing about the secret, and it expects `get(WEBHOOK)` to be `"machine-secret"`, which is App 111's secret. The same fallback pairs a key the same way.

**Change `electGithubSource` so `get` reads `owner.values[name]` and nothing else.** With no owner, `get` returns `undefined` for every name. Its signature stays the same. Invert that test's secret assertion to `toBeUndefined()`, and keep a case where the owner does name the secret.

What this deliberately gives up, and why each loss is acceptable:

- **An exported id with the key only in a file.** This used to work and now refuses with *"Neither … PRIVATE_KEY_PATH nor … PRIVATE_KEY is set"*. That is the ticket's point: a pair nobody configured. Where `from === process.env`, dotenv has already merged `.env.local` into `process.env` at import (`:39-52`, `:56`). So a checkout whose file carries the whole App still has `"environment"` as a complete owner, and the ordinary case loses nothing.
- **A webhook secret with no App id anywhere.** `githubWebhookSecret()` now answers `undefined`, and `/api/webhook` returns its existing 503, *"webhooks are not configured"* (`apps/board/src/app/api/webhook/route.ts:33-36`). The only writer of the secret is the setup page, and it writes the id beside it. A secret with no App cannot be verified against any delivery that App sends.

Rewrite the `appValues` docblock (`:1046-1058`) to say *"only the source that names the id is asked, for every name"*, and drop *"and the rest only for what it does not say"*.

**The integration test that has to change:** `env.test.ts`'s *"lets a variable in the environment win over the file"* (`packages/env/integration/env.test.ts:115-124`). It hands in `{ LINGTAI_GITHUB_APP_ID: "2" }` with a file that holds `ID=1` and `PRIVATE_KEY=from-file`, and expects `privateKey` to be `"from-file"`. That is App 2 signed with App 1's key, the pairing this ticket forbids.

Rewrite it so the environment carries its own inline key, and add an assertion that the file's key is not used. Edit the expectation of the `"is silent about a config.yml it cannot parse"` case only if it stops holding.

This file is the integration half (`pnpm test:integration`, 803s), so nothing in the pass runs it. Edit it by reading, and let the unit tests below stand in for it.

## One more thing `cbd2713` gets wrong: an unquoted `app_id`

`githubRecordFromSection` skips anything that is not a string (`typeof value !== "string"`). In YAML, `app_id: 123456` without quotes parses as a **number**. A hand-written section therefore reads as *not set*, with no reason given, even though the file looks right.

Fix: accept a finite integer for `app_id` and store `String(value)`. Keep refusing other types silently, as now.

Add a unit case for it, feeding in the object `{ app_id: 123456 }` rather than YAML text.

## Silence versus a reason

`machineGithub` in `cbd2713` returns `{}` for **every** `readFileSync` failure. A missing file should be silence (`ENOENT`, and `ENOTDIR` under a home that is not a directory). Any other read error, such as `EACCES`, should set `unreadable` the way a parse failure does. Otherwise a `config.yml` at mode `000` reports *"not set"*, which is the exact report the Done-when forbids.

In both cases the election still sees nothing from the file. Unreadable never becomes an error there, which matches `:1061`.

## The unit tests that carry the pass

All of these go in `packages/env/unit/github-app-source.test.ts`, on plain objects, with no file anywhere:

1. The machine record names id `222` and key path `/machine/key.pem`. The environment record carries only `/stale/key.pem`. Expect the machine's key path and `source === <config.yml path>`. `cbd2713` already has this test; keep it.
2. The reverse: the env-file record names id `222`, a key path, and **no secret**. The machine record names id `111`, a key path and a secret. Expect the env file's id and key path, `source` equal to the env file's path, and `get(WEBHOOK) === undefined`. That last assertion is the one that proves *one election, one winner, every name*.
3. The owner names the secret, and the secret comes back from it.
4. `githubRecordFromSection` with a relative `private_key_path` resolves against the `home` it is handed. `cbd2713` has this too. The claim that `home` is `stateDir()` and not `root` sits in `machineGithub`'s one call site, so read that line, since no unit test reaches it.
5. The numeric `app_id` case above.

The following are proved only by `env.test.ts`, after the merge (T11):
- *config.yml alone, no env files*;
- *unparseable file named in the refusal*;
- *`source` is `"environment"` only when `realEnvironment` names the id*. `realEnvironment` reads the module's `exported` snapshot, so it cannot be driven from a unit test without `process.env`.

Say so in the commit message rather than leaving it to be discovered.

## What not to touch

- The order of `sources`: environment, then `files`, then machine. The environment goes first because `process.env` is how a deployment wins (`:1056-1057`).
- `keySource` keeps its meaning.
- `doctor.ts`. Reporting `source` in its `ok` detail (`:772`) and changing its skip text (`:758`) belong to the `init` and doctor slice. The doctor finding is fixed here entirely by `machineChoiceFile`.
- `GitHubAppCredentials` is built only inside `packages/env` (`git grep keySource:` finds nothing outside it but the two integration expectations). So making `source` required breaks no other package's typecheck.
