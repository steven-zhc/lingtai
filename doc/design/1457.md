# #1457: the shape

## The one decision the ticket leaves wrong: the base selector's specificity

The ticket writes the base rule as `a, a:visited`. Do not write it that way. `a:visited` has specificity (0,1,1), and almost every selector in the opt-out list is a single class at (0,1,0): `.navlink`, `.tab`, `.ti`, `.iss`, `.lmeta`, `.ltag`, `.ctbtn`, `.pr-btn`, `.pr-name`, `.pr-slip-title`. Once a link is visited, `a:visited { color: var(--accent); text-decoration: underline }` would beat those rules on both properties:

- a visited `.iss` would stop being "the colour of its line" (`.iss { color: inherit; text-decoration: none; }`, `globals.css:814`);
- a visited `.navlink` and a visited card `.ti` would turn teal.

The underline itself would not come back, because browsers apply only colour properties under `:visited`. The colour change alone still breaks the opt-out on any page a person has already clicked through. Nothing catches this: the screenshot pass in *Done when* runs in a fresh browser with no history. Today the problem does not exist, because the base rule is a bare `a { color: var(--accent-ink); }` (`globals.css:153`, which has moved from the ticket's `:144` since #1456 landed).

**Write the base rule as `a, a:where(:visited)`.** Both selectors are then (0,0,1). `:visited` stays named, as the ticket intends, and every class rule still beats it. A bare `a` would also work, since author styles beat the UA's `:visited` colour. The `:where` form keeps the ticket's intent visible to the next reader.

`links.test.ts` should assert this exact selector string. Add one comment in the CSS saying why it is `:where`. This differs from the ticket's literal *Done when* only in the selector text, and the four values are unchanged.

The PR card header already uses the explicit form, `.pr-head a, .pr-head a:visited { color: var(--pr-on-fill); }` (`globals.css:3553`, `:3561`). Those rules are (0,1,1)/(0,2,1) and come later in the file, so they win either way. Leave them alone.

## What each edit to a classed text link removes, and what it keeps

Remove three things only:

1. `text-decoration: none`.
2. `color: var(--accent-ink)`, so `--accent` comes through.
3. A `:hover` rule whose only job is to add the underline back.

Keep every other declaration: font family, size, margins, `white-space`, `letter-spacing`. For example, `.hfr-feed .h a` keeps `letter-spacing:.04em` (`:3420`), and `.handled-f a` keeps mono and `nowrap` (`:3467`). A rule that ends up with no declarations is deleted.

Specific cases:

- **`.whynot a{color:inherit;text-decoration:underline;text-underline-offset:2px}` (`:3369`):** delete the whole rule. The ticket counts it among the "four looks" of one kind of link, so it becomes teal.
- **`.hfr-hero b a, .hfr-hero .side a` (`:3384`) and `.hfr-t td.n a` (`:3405`):** both carry `border-bottom:1px dotted var(--rule-2)`. The ticket says the hero's goes. `td.n a` is listed as a text link, so its border goes too; otherwise it would show two underlines. Its `color: var(--ink)` also goes.
- **Links on a coloured ground:**
  - `.pbanner .what a` (`:3856`) loses only `text-decoration: none` and keeps `color: var(--held)` and weight.
  - The sandbox banner's colours are set together with its text (`.sbanner .sbx-stopped .what a { color: var(--fail) }`, `:3293-3294`) and need no edit: they never said `none`.
  - Check `landing-line.tsx:20`'s flaky link the same way.

## What the opt-out list must hold

The inventory, plus one class of thing the ticket only gestures at: **any link whose rule sets no `text-decoration` today and is not a text link.**

- Grep `globals.css` for every selector that targets an `a` or a class used on an `<a>`.
- Check each against the ticket's inventory. `.pr-slip-id`, `.ld-filter a`, `.rp-seg a`, `.sbswitch a`, `.eg-n`, `.bk`, `.addp`, `.rtab`, `.wiz-primary`, `a.btn` are the easy ones to miss.
- **`.btn` (`:945`) is a class on `<button>` and `<a>` alike.** Opt out `a.btn`, not `.btn`, so the guard's list says what it means.

- **Hover rules on opt-out links stay:** `.ti:hover`, `.waiting-card .ti:hover`, `.iss:hover`, `.lmeta:hover`, `.ltag-pr:hover`, `.rp-table td.t a:hover`. The guard forbids `text-decoration: none` outside the opt-out rule; it does not forbid `underline`.

## The guard (`links.test.ts`)

Three assertions over `rulesOf(css)`:

1. **The base rule.** Exactly one rule has the selector `a, a:where(:visited)`, and its body has the four declarations.
2. **One place for `none`.** Every rule whose body contains `text-decoration: none` (also match the minified `text-decoration:none`; the `.hfr-*` rules at `:3384-3437` are minified) is the opt-out rule or `.bk.done .bst`.
3. **The required selectors.** The opt-out rule's selector, split on commas, contains each of the ticket's thirteen selectors.

Write the test before the CSS edit so it fails first. It is unit-level and reads a file shipped in the repository, which `card-radius.test.ts` and `section-heading.test.ts` already do, so it belongs in the unit half (0060 §1).
