The ticket already gives the shape. This note adds only what the ticket leaves open: where the tests go, and two things the code makes easy to get wrong.

## Where the tests go

The pinned assertions sit in **`packages/conductor/integration/tell.test.ts:170-176`**, which is in the integration half. `pnpm test` (`--project unit`) never runs it. Do not add the new tests there: the `build` step would not run them. Leave that file alone. The `Done when` line asking for its assertions to stay green is met by not touching it.

- **The `foreignLabels` and `OWN_LABELS` tests** go in a new `packages/conductor/unit/labels.test.ts`. Both are pure functions, so they belong in the unit half by 0060 §1. For the "nothing else" half of the set test, compare `OWN_LABELS` against `new Set(LABEL_STATES.flatMap(labelsFor))` and against the literal `['lingtai:waiting', 'lingtai:working']` (sorted). The literal is what catches a set that has silently become empty. Without it the test is the definition compared with itself.
- **The tell test, kept in the unit half:** drive `tellGitHubEffect` (`packages/conductor/src/tell.ts:169`) with an `IssueChannel` (`tell.ts:42`) whose `getIssue` answers `['bug', 'lingtai:hold', 'lingtai:working']`, and record what `setLabels` receives. The `labels` arm is at `tell.ts:240-246`. No existing unit test sends a `labels` change through the tell (`git grep "kind: 'labels'" packages/conductor/unit` finds nothing), so look at how `packages/conductor/unit/sweep-refs.test.ts` or `trace-an-attempt.test.ts` build their fake channel and memory store, and copy that.
- **The converge test:** copy `packages/daemon/unit/converge-approved-label.test.ts`. Its header reads *"a memory log, a fake `DaemonStore` naming one stream, and a GitHub client that is a set of labels — no Postgres, no network"*, and it calls `findIssueDriftEffect` (`packages/daemon/src/converge.ts:342`). Make the issue carry `lingtai:hold` beside a stale `lingtai:working`. Then assert that the found divergence's target keeps `lingtai:hold` and drops `lingtai:working`. Add it to that file or put it in a sibling file, `converge-foreign-label.test.ts`.

## Two things that look like edits and are not

- **`LINGTAI_LABEL_PREFIX` stays exported and stays in use.** `labelsFor` builds both of its labels from it (`labels.ts:38`, `:40`), and `index.ts:108` re-exports it. Only its comment changes (`labels.ts:22`, *"Everything else is somebody else's"*). Nothing outside `labels.ts` reads the prefix to decide ownership; `git grep LINGTAI_LABEL_PREFIX` finds only `labels.ts` and `index.ts`.
- **Converge imports from the subpath `@lingtai/conductor/labels`** (`converge.ts:63`), not from the package index. `OWN_LABELS` must therefore be exported from `labels.ts` itself; adding it to `index.ts:108` alone is not enough. Converge does not need to import `OWN_LABELS` at all, because it only calls `foreignLabels`.

## The set's definition

`labels.ts` already imports `LabelState` as a type from `@lingtai/domain` (`labels.ts:20`). `LABEL_STATES` is a runtime value (`packages/domain/src/streams.ts:167`), so it needs a value import, not `import type`. Build the set below `labelsFor` in the file. A `const` initialised above the function it calls compiles, but it reads backwards.

`OWN_LABELS` is computed once, when the module loads. Per the CLAUDE.md, a running daemon keeps the module it loaded at start, so #1309's `lingtai:landed` reaches a running daemon only on restart. That is the same as any other change to `labelsFor`, and this change needs no handling for it.

No ADR is contradicted. 0116 §5 names the prefix's members and does not say that everything under the prefix is Lingtai's to drop. The rule this changes lives only in the `labels.ts` header (`:16-17`).
