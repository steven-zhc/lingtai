# Design: #1186, the sandbox section and the `~/.ssh` answer

## Where it goes

The new `<section className="sandbox-pitch">` goes in `apps/site/src/app/page.tsx`. It sits after `<ReplayReceipt />` closes its wrapper (`page.tsx:157-158`) and directly before `<section className="why">` (`page.tsx:160`). It is a sibling of `.why`, not nested inside the replay `div`. It picks up `.home section { padding: 88px 0; }` (`home.css:5`, 64px on phones at `:77`). Give it its own rules in `home.css`, placed next to the `.why` block (`home.css:214-223`). Follow `.why-head`'s pattern for the head, so the kicker, `h2` and sub line sit like their neighbours: centred, `max-width: 640px`, `text-wrap: balance`. Give the points and the image their own `.sandbox-pitch …` rules rather than borrowing `why-*` class names, so later edits to `.why` don't move this section.

## The image needs no plumbing

`/img/docs/sandbox.svg` is already served. `apps/site/src/app/img/docs/[name]/route.ts` statically exports every file in `doc/img/` that `imageType` accepts (`generateStaticParams`, route.ts:21-24). `sandbox.svg` is in `doc/img/` and matches `/^[a-z0-9-]+\.(svg|png)$/` (`src/lib/doc-images.ts:9`). Don't copy it into `public/`; the route's comment explains why that is the failure. Size it with `width: 100%; height: auto`, capped at the section's content width.

The SVG handles dark mode itself: `@media (prefers-color-scheme:dark)` inside its `<style>` (`doc/img/sandbox.svg:4`). The site switches on the same media query (`site.css:45`), so the `<img>` follows the page and needs no dark-mode CSS. Check it in a browser anyway; that is already in Done when.

For `alt`, use the SVG's `aria-label` (`sandbox.svg:1`) copied into a constant in `page.tsx` with its last sentence corrected (the SVG says every refused connection is shown on the board; the board leaves telemetry hosts out, 0127 §17). The test can then assert the constant is non-empty and appears in the rendered `alt`.

`/docs/safety/` is public while `DOCS_PUBLIC` is `false` (`src/lib/docs.ts:53`). The `PUBLIC_SLUGS` comment says: *"`safety` is the page the home page's honest answer about `~/.ssh` sends a reader to (#809)"*. Both links work without changing that file.

## The trap: existing tests already constrain the copy

`apps/site/unit/page.test.tsx` holds three things the new copy has to fit:

- **No "log" above the books kicker.** At `:53-62`, *does not lead with internals or event-log claims*, the rendered page above `The work, in the open` must not match `/\blogs?\b/i`, nor `event-source|append-only|projection`. This section is above books, so "every refused connection is **logged**" or "in the **log**" turns the suite red. Write *recorded* and *shown on the board*, which is also the ticket's own wording. Don't weaken the test.
- **No "guarded".** At `:162`, `expect(html).not.toMatch(/\bguarded\b/i)` covers the whole page.
- **The section order.** The `order` list at `:74-80` is the place to pin it. Add the new `h2` text between `'The agent got it wrong. Twice.'` and `'Why not just give the agent the issue?'`. That gives you the "immediately before `why`" assertion without a second ordering test.

The FAQ test at `:143-163` keeps all of its assertions except `:161`. That line pins `'By default, yes'` before `'not a sandbox'`, which is exactly the sentence this ticket removes. Replace it with assertions on the new answer:

- it contains `~/.ssh`, `HONEST ANSWER` and `href="/docs/safety/"`, which are already asserted;
- it does **not** contain `not a sandbox`;
- it names the token case and the case of a project with no `sandbox` block or `enabled: false`.

The count of six `<details>` stays at six.

Put the three Done-when assertions for the new section (`from v0.14.0`, the `/docs/safety/` link, and `src="/img/docs/sandbox.svg"` with a non-empty `alt`) in a new `describe` in the same file. Find the section in `renderToStaticMarkup(<HomePage books={null} />)` by slicing from `class="sandbox-pitch"` to its `</section>`, the way `:145-146` slices out the FAQ.

## What the copy may claim

Each point maps to one line of code, and none goes past what it cites:

| Point | Source | Do not say |
|---|---|---|
| Can't read `~/.ssh`, cloud keys, GitHub/npm/Docker logins, or Lingtai's own state | `denyRead`, `packages/sandbox/src/policy.ts:89-102` (`stateDir` whole, `.claude/.credentials.json`, `Library/Keychains` on darwin) | "your secrets", "anything private", "only its worktree" |
| Network reaches only an allowlist plus the hosts you add | `BUILT_IN_DOMAINS`, `policy.ts:59-73`; `network.allow` | "offline", "no internet" |
| Every refused **connection** is recorded; the board shows them except telemetry hosts (`sentry.io`) | 0127 §2, §17, #1161 (the task page's Sandbox tab) | "every refused connection is shown": telemetry is recorded but left out of the board; "every refusal": refused file reads are **not** reported (0127 §18) |
| New projects are sandboxed by default; one `sandbox` block in the recipe configures it | `sandboxChanges`, `packages/setup/src/setup-answers.ts:140-142` writes `sandbox: { enabled: true }` | "every project": existing recipes aren't touched (`setup-answers.ts:103`, *"`null` where it was not asked — an existing recipe, which this never touches"*) |

The fourth row is why the section and the FAQ must both make the unsandboxed case conditional on the recipe, not on how old the project is. An existing project gets a sandbox only once somebody writes the block.

## The FAQ answer

Keep the `<summary>`, its `faq-tag`, the `details.faq-item.honest` class and the closing link exactly as they are; only the `<p>` text changes. Use three short sentences in the page's voice:

1. *From v0.14.0, not in a sandboxed project*: `~/.ssh` is on its deny list.
2. What's still readable: the agent's own login token for the run.
3. A project whose recipe has no `sandbox` block, or `enabled: false`, runs as your user, as before.

Then the existing `What an agent can touch →` link. For sentence 2, say "the agent's own login token", not "Claude token": 0127 §18 names both the Claude token and Codex's login. Leave Unix sockets on Linux to `/docs/safety/`, as `doc/safety.md` already covers it (`e1b58c45`).
