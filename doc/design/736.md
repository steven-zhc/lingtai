## Design note: #736

The ticket's shape is right. Three things it leaves open, each checked against the worktree:

**1. `pnpm docs:cli` writes two files, and both must be committed.** `doc/cli.json` carries the same four lines (`doc/cli.json:34, 36, 678, 680`). `apps/cli/unit/cli-doc.test.ts:23-29` checks both files: *"commits the manifest it would write"* compares `cli.json`, then *"commits the page it would write, rendered from the manifest alone"* renders `cli.md` from it. The ticket names only `cli.md`, but leaving `cli.json` out turns the first test red.

**2. The new help text will not fit on one line, so use the two-line layout already in that block.** The short entries put the description at column 32 (`commands.ts:69-72`): `"  --model <name>               the writer's model"`. A longer flag spelling such as `--model <name>, or --model ''` reaches past that column. When that happens, the same list puts the flag alone on its line and indents the description by six spaces underneath (`--land <branch|hold>` at `commands.ts:78-79`, `--base`, `--tickets`). Use that layout for both model flags, and make the `init` copy (`commands.ts:472-474`) identical to the `add` copy. One line of description is enough, for example `the writer's model; '' for the runtime's own default` and the same for the reviewer.

**3. Copy the precedent's wording exactly, with no `=` and no keyword.** Use `flag: "--model <name>, or --model ''"` at `agents.ts:201` and `flag: "--reviewer-model <name>, or --reviewer-model ''"` at `agents.ts:280`. This matches `setup-build.ts:225` (`'--install <command>, or --install none'`). `question.ts:119-120` interpolates `q.flag` into `` `${q.name} needs an answer: pass ${q.flag}` ``, so the refusal and the code read the same string. Write these in double quotes so the `''` needs no escaping. The other way to fix it, special-casing the refusal sentence in `question()`, would change the refusal for every question. Don't.

**No existing test pins the old wording.** `git grep` for `pass --model`, `model <name>` and `reviewer-model <name>` finds only `agents.ts`, `commands.ts`, the two generated docs and `doc/experiments/016/round-b.md`. Leave `round-b.md` unchanged: it is the record of what the run printed.

**Where the new tests go.** The refusal test should take its expected text from the same `flag` string rather than retyping it, so a later wording change only has to be made once. To find the reviewer-model refusal, the test has to pass `--reviewer` with a runtime other than `none`, because the reviewer's model question is only asked when `reviewer !== 'none'` (`agents.ts:269`).
