# Design note — #1479

## Where it goes

Three places, plus the doc row:

1. **`packages/agent/src/hook-config.ts`**: the verdict, and the spawn that is now its own.
2. **`packages/conductor/src/conduct.ts`**: the two call sites say *where* the smoke runs. They no longer say *how* it is spawned.
3. **`apps/cli/src/doctor.ts`**: a `bunRow` beside `nodeRow`, fed through `reach`.
4. **`doc/requirements.md:66`**.

## The decision the ticket leaves open: the port carries *where*, not a spawner

Today the smoke's IO is the `run` callback. It has the type `(bin, env, stdin) => Promise<{code, stderr}>` (`hook-config.ts:203`, `ports.ts:93-103`), and conduct.ts passes it in as `runBinary` (`conduct.ts:709-722`). That shape cannot take the sandbox, for two reasons:

- The env the wrap needs is made *inside* the smoke (`LINGTAI_HOOK_SOCKET: nowhere`, `hook-config.ts:209`). `WrapInput.env` has to be known before `wrap` runs (`packages/sandbox/src/sandbox.ts:38-48`). So the conductor cannot wrap first and hand over a Promise runner.
- Turning a scoped `wrap` Effect into a Promise runner needs an `Effect.run*`, and the ratchet counts that. The rule is *"Never raise a number in `effect-ratchet.baseline.json`"*.

It also fails the third `Done when` box. A fake host handed a real spawner cannot assert `cwd` or the wrap without spawning, and spawning is integration under 0060 §1.

**So change the port to `smokeTest(hookBinary, where)`**, with this shape:

```ts
where: {
  cwd: string
  wrap?: (input: { command: readonly string[]; env: Record<string, string> }) =>
    Effect.Effect<{ argv: readonly string[]; env: Readonly<Record<string, string>> }, { message: string }, Scope.Scope>
}
```

`smokeTestFailClosedEffect(hookBinary, where, spawn = liveSmokeSpawn)` then does four things:

1. Builds the env.
2. If `where.wrap` is present, wraps `[hookBinary]`.
3. Spawns with `cwd`, inside `Effect.scoped`. Wrapped means `wrapped.argv` with `wrapped.env` *only*. Unwrapped means `{ ...process.env, ...env }`, as `conduct.ts:715` does today.
4. Maps a wrap failure to `AgentHostFailed({ operation: 'smokeTest', detail: message })`.

Step 4 is what makes a failed wrap come out at the existing `Result.isFailure(smoke)` branch (`conduct.ts:5106-5108`, `:5565-5567`) as `the hook's smoke test did not run: <wrap's sentence>`. That is the edge the ticket asked for, and it needs no new branch.

Supporting changes:

- `runBinary` moves out of conduct.ts and becomes the default `spawn`, gaining `cwd`. Write it as `Effect.tryPromise` around a `new Promise`, not an `async` function.
- `live.ts:70` binds `smokeTest: (bin, where) => smokeTestFailClosedEffect(bin, where)`.
- The fake at `packages/conductor/test/one-attempt.ts:941` records `where`. The conduct test asserts `where.cwd === tree.path` at both sites, and that `where.wrap` is defined exactly when the invocation's decision is `sandboxed`.
- The `hook-config` unit tests inject `spawn` and `wrap` stubs. No test spawns a sandbox, so the ticket's cost edge holds.

## Which wrap, and which decision

**Call `api.wrap` directly, not through `sandboxOf`/`recordingWrap`.** Both append to the attempt's stream:

- `recordingWrap` appends `SandboxBoundaryRecorded` before the child and `SandboxConnectionsRefused` after (`packages/conductor/src/sandbox-record.ts:117-160`).
- `sandboxOf`'s unsandboxed branch appends a boundary through `recordUnwrapped` (`conduct.ts:1068`).

`invocationAppends.before` also calls `observeTheSandbox` (`conduct.ts:1010-1020`). Going through either path would record the smoke as a second invocation of `implement` on every dispatch. It would also change what the board and `what-an-attempt-writes-today.test.ts` see.

The ticket says the smoke "appends nothing", and that stays true. Build the `where.wrap` closure next to `sandboxOf` with the same `options.sandbox` service and the same error-to-sentence mapping (`conduct.ts:1086-1102`), minus `recordingWrap`.

The `WrapInput` it builds:

- `project`, `mirror: mirrorPathFor(project, home)`, `worktree: tree.path`.
- `project_additions` from the decision.
- `caller_additions: { read: [options.hookBinary] }`. Without that read the sandbox may refuse to exec the binary at all. The agent's own wrap carries it as `read: [run.settingsPath, ...sandbox.read, ...copied]` (`packages/agent/src/claude-sandbox.ts:205-209`), with `sandbox.read` being `[options.hookBinary]` (`conduct.ts:1085`).

**Leave the operator's carried denies out of the smoke's wrap.** The failure is a deny on a directory *above* the worktree. A carried deny that contains the worktree is already refused by `collidingDenies` (`claude-sandbox.ts:129-134`; the check is `within(n, prefix)`). So the base policy is what produces the Foundry case, and the smoke has it.

**Narrow the decision per runtime, as the agent's wrap does.** Use `invocationDecision(implementDecision, runtimeId)` (`packages/recipe/src/sandbox.ts:91-94`; `sandboxOf` does this at `conduct.ts:1064`). Otherwise a runtime that cannot be sandboxed gets a sandboxed smoke and an unsandboxed agent.

`dispatched` is computed after the smoke today (`conduct.ts:5115`). Hoist the runtime id, `spec.agent ?? options.runtime.capabilities.id`, above the smoke. At the fix round, `dispatched` is in scope from the same expression; check that before reusing it.

## The socket path handed in

Move the smoke's socket from `join(stateDir(), 'sockets', …)` (`hook-config.ts:205`) to the directory the real socket uses: `socketPathFor(\`smoke-${Date.now()}\`, home)`, which is `join(tmpdir(), 'lingtai', …)` (`hook-config.ts:61-63`).

The reason is the stderr check:

- On darwin the policy allows unix sockets only under `socketDirs(host)` (`packages/sandbox/src/policy.ts:187`, `allowUnixSockets: socketDirs(host)`), and the worktree's `~/.lingtai` parent is read-denied. A connect under `stateDir()` from inside the sandbox may answer `EPERM` or `EACCES` rather than `ENOENT`.
- The only connect error *measured* to quote the path is `connect ENOENT /nonexistent/x.sock` (ticket evidence).
- In the real socket directory, a missing socket is a plain `ENOENT`, and the smoke exercises the same allowance the agent's hook needs.

This keeps the per-run unique name (0122 edge) and the `SUN_PATH_MAX` throw. Map that throw to `AgentHostFailed` the way `writeHookWiringEffect` does (`hook-config.ts:157`).

## The verdict

`ok` requires `code === 2 && stderr.includes(nowhere)`. Use the exact string, not a regex.

The `ok: false` detail has to tell three cases apart:

| Case | Detail |
|---|---|
| Exit 2 and the path is missing | The hook *fails closed but read nothing*. Name both variables and quote the stderr, clipped. |
| Any other exit | The existing fail-open text. |
| Either way | Quote the stderr. |

The conductor prefixes the sentence with `the hook did not fail closed:` (`conduct.ts:5109`, `:5568`). That prefix is wrong for the first case. Make the smoke's detail carry the whole sentence and drop the prefix, or change the prefix to `the hook's smoke test failed:`. Either way, one wording at both sites.

Rewrite the doc comment at `hook-config.ts:197-198` (*"runs the real binary against a socket path that does not exist and requires exit 2"*) to say it requires exit 2 *and* the path in stderr, run where the agent's hook runs.

## Doctor

Follow `sea`, not a free spawn. `sea: () => SeaProbe` is a **required** key on `DoctorReach` (`doctor.ts:1299-1307`, *"required rather than optional … a caller can omit `sea` and spawn Node for real (#212)"*). The live probe is wired at `:4372`.

- Add `bun: () => Effect<{ answered: string } | { failed: string }>` the same way, required, and picked through `runDoctor`'s `Pick`.
- The pure `bunRow(answer)` parses `^(\d+)\.(\d+)\.(\d+)` from the trimmed output and compares against `1.3.6`.
- A failed run or unparseable output is `fail`, with what `bun` said.
- The `ok` detail says the row reads `bun --version` and not the binary. A hook built before an upgrade is caught by the smoke test before every dispatch, not here.
- Push the row in the non-SEA branch beside `nodeRow` (`doctor.ts:4049-4063`). In the `isSea()` branch (`:4027-4048`), push a `skip`.

The ticket's doctor line numbers have drifted. `nodeRow`'s *"take strings"* comment is now `:3754-3756`, and the SEA branch is `:4027`, not `:3978`.

## What nothing here can verify before the merge

That a bun 1.2.22 hook under a real `sandbox-exec` fails the new smoke is a claim about srt and Bun. Only a spawned sandbox shows it, and that is integration and out of reach inside a pass. The unit claims that stand in for it:

1. **Verdict:** `smokeTestFailClosedEffect` with exit 2 and the *"are not set"* stderr is `ok: false`.
2. **Placement:** both conduct sites pass `cwd: tree.path` and a `wrap` exactly when `invocationDecision(...)` is `sandboxed`.
3. **Reads:** the wrap closure's input carries `caller_additions.read` containing the hook binary.

After the merge, the log settles it. A sandboxed attempt that reaches the agent appends `SandboxBoundaryRecorded` for the `implement` invocation with `boundary.kind: 'sandboxed'`, and the attempt has more than 0 turns. A broken hook instead ends the attempt before any boundary, with the stop reason quoting `are not set`.
