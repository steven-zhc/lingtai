# Design note — #539

Make the grant a **distinct wait resolution and a one-use continuation instruction**. Add `GrantFixRound { onSha }` to `Resolution` in `packages/domain/src/wait.ts`, and fold `WaitResolved` into a continuation owed to the same run. Keep the resolution tag in the ticket lifecycle so the conductor can distinguish a grant from `Approve`: today `WaitResolved{Approve}` enters `approved` and `continuationOf` chooses a step and possible waiver (`packages/domain/src/ticket.ts:352-360`; `packages/domain/src/wait.ts:319-361`, “Where `Approve` continues the run, and what it waives there”). A grant enters at `implement` with **no waiver**. `Requeue` retains its documented “new pass, from the base” meaning (`packages/domain/src/wait.ts:206-208`).

Resolve eligibility in two stages. Extend `allowedResolutions` for actionable review findings and check output, including `ReviewFindings`, `BuildRed` and `VerifyRed`; require a recorded criterion and a recoverable head before appending the grant. Triage may advise the tag but never supply or authorize its SHA. This follows 0108 §4, “Only a refusal with a criterion buys an agent,” and 0118 §1, “Triage advises a resolution by its kind alone.” Do not route a wrong-approach judgement into a grant automatically.

The grant handler should read the open wait’s run, the saved head and its publishing evidence from the log, then check the corresponding remote ref at that exact SHA while holding the decision lock. Do not infer that `run.headSha` is on `agent/<n>`: `RunRefsPublished.branchCarries` says whether the branch carries `headSha`, and `RunKeptUncommitted` identifies a WIP commit kept only on an arm (`packages/domain/src/events.ts:570-625`, “this commit must never be offered” as the normal diff head). Refuse absent evidence, an unpushed or moved branch, or work available only as WIP; name the recorded ref and the needed recovery in the refusal. The conductor must repeat the remote-head guard when it re-cuts the tree. Its existing `at` path already refuses a moved ref (`packages/repo/src/worktree.ts:143-154`, “refuses rather than silently taking it”). Carry the original diff base from the held run’s `admit` outcome, as `diffBaseShaOf` prescribes (`packages/conductor/src/attempts.ts:246-269`, “never `RunStarted.baseSha` alone”).

The subtle loop change is that jumping to `implement` does **not** itself create a fix brief: `sentBackTo` currently finds one only after a `proposed` route in the current walk (`packages/conductor/src/pass.ts:1580-1602`, “read off the visits”). Pass the grant’s recorded refusal evidence into the first continued `implement` visit explicitly, so it calls the existing fix dispatch and records `RunSpent`, rather than treating the visit as a first dispatch or inventing a `PassRouted` decision. Seed its round number from the latest recorded `implement` round, including earlier human grants, then increment once. Keep `ceilings.rounds` at the recipe value: today the loop offers another back edge only while `roundsSpent` is below that ceiling (`packages/conductor/src/pass.ts:1140-1145,1219-1231`). Thus a spent pass receives this one call and, if checks refuse again, waits for another decision. The continued walk proceeds through build, review and merge checks; its diff remains against the original base.

Add the CLI command through the same locked, current-wait resolution path as approval, with an optional displayed SHA guard and no branch or commit argument. Cover the fold, source-ref and stale-ref refusals, WIP-only refusal, first and repeated grants, fix brief and round accounting, original-base diff, and a second refusal with no automatic round. Unit tests must establish those decisions; the git-backed re-cut is an integration boundary, so it cannot be the only check before merge. Run the ticket’s specified unit and type checks, not the integration suite.

The ticket’s `GrantFixRound` name supersedes 0118 §1’s accepted `ExtraRound` spelling (“one human-granted round on the preserved branch”). Record that naming change in a **superseding ADR file**, leaving the accepted decision append-only.
