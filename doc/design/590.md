# Design: #590, the conflict wait's paths and compare link

## Where it goes

There is no separate "Waiting page". The wait is the `Standing` block on the task page: `apps/board/src/app/task/[id]/page.tsx:814` renders `<Standing standing={task.standing} …>`. The dev gallery at `apps/board/src/app/dev/waiting/` draws the same component from the fixtures in `apps/board/test/waits.ts`. That file already has a `MergeConflict` fixture with `paths: ['a.ts'], baseSha: 'base1', headSha: 'head1'` (`waits.ts:173-177`), so the gallery shows the new block without a new fixture.

`Standing` already has the wait: `standing.reason` is `life.reason` while the ticket is blocked (`apps/board/src/lib/task.ts`, `reason: blocked ? life.reason : null`). Read `reason._tag === 'ProposedEscalated' && reason.proposal._tag === 'MergeConflict'` there, the same way `decide.tsx:331` reads `InputNeeded`. The wait carries `paths`, `baseSha` and `headSha` (`packages/domain/src/proposal.ts:67-72`), and all three are `nullable()`. A proposal built without a conflict object sets all three to `null` (`proposal.ts:222-230`).

What the component cannot know is the owner, the base and the tickets source. Those come from the project, so the URL is built in `loadTask`/`loadTicket`, which already loads `state` and `tickets` (`task.ts:1581-1606`). It reaches `Standing` as a new prop, `compareUrl: string | null`. `Standing` stays a component that is handed facts and draws them.

## The builder

Add `compareUrl` to `apps/board/src/lib/board.ts`, directly under `issueUrl` (`board.ts:1464-1472`), and make it follow `issueUrl`'s rule:

```
issueUrl: if (owner === null || tickets !== 'github') return null
```

So the signature is `compareUrl(owner, project, base, branch, tickets)`. It returns null when the owner is null, when `tickets !== 'github'`, or when `base` is null. Otherwise it returns `https://github.com/${owner}/${project}/compare/${base}...${branch}`.

- **Each argument's source:**
  - **Owner:** `state.owner`, the GitHub owner. It is null for a project that has none, and that is the "local origin" case in the ticket's Watch out. Nothing else in the code marks a non-GitHub origin.
  - **Base:** `state.base` (`packages/domain/src/project.ts:31`).
  - **Branch:** `agentBranchOf(item.externalRef)`. It is the same call `standingOf` already passes to `waitWords` (`task.ts:773-776`). Do not hand-write `agent/<n>`.
- **Encoding:** encode each `/`-separated segment of `base` and `branch` with `encodeURIComponent` and keep the slashes. `agent/590` has to stay `agent/590`, not become `agent%2F590`.
- **Why the `tickets` rule and not just the owner:** the ticket's Watch out names `--tickets db` as a case with no link. `issueUrl`'s doc comment gives the reason: *"A dead link is worse than none, so an unknown source gets no link."* That makes a null `tickets` (a recipe that won't parse, caught to `null` at `task.ts:1603-1605`) mean no link too.

**The decision the ticket doesn't make: an unpushed branch gets no link either.** `standing.unpushed` is set when the branch was not pushed (`wait-words.ts:41-42`, `unpushedSuffix`; the page already draws `<UnpushedBanner>` at `page.tsx:812`). In that case GitHub's `agent/<n>` is not the head that conflicted, and the compare view would show some other diff or a 404. So pass `compareUrl: null` when `task.standing.unpushed !== null`, and the page falls back to the shas. Keep this check in `loadTask`, outside the builder, so the builder stays a five-argument pure function.

Use the branch name, as the ticket asks, rather than `baseSha...headSha`. What a person grants a round against is the branch as it is now, and `headSha` comes from the lane's local branch in the mirror (`packages/repo/src/integrate.ts:499`, `rev-parse laneBranch` in `mirror`). The shas are the fallback text, not the link.

## Where it renders

Rank 2, inside `<div className="swhy" data-rank="why">` in `standing.tsx`, directly after the `what` line (`standing.tsx:849`). It is the evidence for why the ticket stopped. It must not go in rank 3: `soWhat` is one sentence in one element, and the comment at `standing.tsx:866-869` says *"a sentence a later ticket wants on this page goes to rank 2 or to the record, and the snapshots in `task-page.test.tsx` make it say which (#152)."*

The block has three parts:

1. **The paths:** a list, each one in `<code>`, drawn only when `paths` is non-null and non-empty.
2. **The link:** when `compareUrl !== null`, a link in the same shape as `subjectRef`'s (`standing.tsx:645`: `target="_blank" rel="noreferrer"`, text ending `↗`).
3. **The shas:** when `compareUrl` is null and either sha is non-null, the two shas as text: base `baseSha`, head `headSha`.

If all three fields are null (an older wait), draw nothing extra. The page then looks exactly as it does today.

The paths are already on the page in a way: for a conflict, `raw` is `proposal.output`, which is `` `${branch} does not merge into ${base}:\n${paths.join('\n')}` `` (`integrate.ts:500-503`). While blocked it is drawn by `TriageBand`'s `RawEvidence` (`standing.tsx:851`, `883`). Leave that quote alone. It is git's words; the list is the wait's own field. Don't parse paths out of `raw`.

**Not in scope:** hunks, `git merge-tree` output, and any resolution UI. The ticket records the 2026-10-24 decision: the link is the whole of it.

## Tests (unit half only)

- **The builder:** `issueUrl`'s cases sit in `apps/board/unit/weight.test.ts:187-215`. Put `compareUrl`'s cases beside them (or in a small new `unit/` file):
  - a GitHub project gives the URL with `agent/590` unencoded;
  - an owner of `null` gives `null`;
  - `'db'` gives `null`;
  - a `tickets` of `null` gives `null`;
  - a base of `null` gives `null`.
- **The render:** in `apps/board/unit/standing.test.tsx`, render the `MergeConflict` wait from `test/waits.ts` twice:
  - with a `compareUrl`: the paths and the link are drawn;
  - with `compareUrl: null`: the paths and both shas are drawn, and no `a[href*="/compare/"]` exists.
- **Snapshots:** `task-page.test.tsx`/`visual-waiting.test.tsx` snapshots that draw the conflict fixture will change. Update only those, and check that the diff is the new rank-2 block and nothing else.

The build step runs `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`, and all four have to pass. `loadTask` reads `loadProject` and the recipe, which the unit half can't reach. So test the wiring at the edges: the builder as a pure function, and `Standing` given the prop. Don't add an integration test.

What settles whether a real conflict wait carries the fields is the `WaitStarted` event whose `reason.proposal._tag` is `MergeConflict`, in its `paths`/`baseSha`/`headSha` fields. Whether the head was pushed is `reason.run.unpushed`.

No ADR is affected.
