## Design for #565

Keep `codex exec` as the `tools: 'full'` path. Route `tools: 'none'` through a separate, model-only Responses API adapter that sends **no tool definitions** and sets `tool_choice: "none"` ([Responses API reference](https://developers.openai.com/api/reference/resources/responses/methods/create)). The Codex row already records why `-s read-only` cannot serve this role: it “forbids writes and forbids nothing else” (`packages/agent/src/runtimes.ts:94-112`). A CLI version gains this route only after its no-tools behavior has been proved; an unknown version must fail by name before dispatch.

Make the API route an explicit machine configuration and billing choice. Add its credential, model and spending parameters through the two configuration sources in ADR 0117, and pass the resolved configuration to `createRuntime`; never borrow `codex login` or an agent’s environment as API authorization. `createRuntime('codex', { tools: 'none' })` must continue to throw `ToolsCannotBeDenied` when that configuration is absent or incomplete. Implement and test the route before enabling it on a machine; record the API credential and billing implications on #565 and obtain the ticket’s required human approval before enabling it. The current construction seam is `RUNTIMES`, whose comment says a runtime is dispatchable “because it has a row here and for no other reason” (`packages/agent/src/runtimes.ts:1-12`).

Keep the existing `Runtime.run` request and outcome shape (`packages/agent/src/runtime.ts:74-125,159-187`). Bound each API request by the supplied wall clock and cancellation signal, one response per turn, an output-token ceiling, and a conservative preflight bound on input and output spend. Across read rounds, Waiting triage must debit that bound before another call: its current loop carries `usdLeft` into each request but increments `costSpent` only when `costUsd` is reported (`apps/cli/src/triage.ts:654-711`). Preserve `costUsd: null` if the API reports tokens but no dollars; ADR 0110 says “`null` when the runtime did not say,” with pricing at display time. Reject a call whose remaining budget cannot cover its bound. Preserve text, usage, failure and cancellation reporting so Discussion and triage can keep their existing parsers and `RunSpent` handling (`packages/conductor/src/discuss.ts:550-580`; `apps/cli/src/triage.ts:680-735`).

Once the route is usable, add `codex` to `DiscussAgent` and update its parity test. The recipe comment says that enum is handwritten to avoid importing runtime adapters, and `apps/cli/unit/discuss-agent.test.ts:1-25` checks it against `createRuntime(..., { tools: 'none' })` (`packages/recipe/src/recipe.ts:2821-2845`). Adjust that check to distinguish configured support from the deliberate refusal on an unconfigured machine. Leave the `full` Codex assertions in `packages/agent/unit/runtimes.test.ts:107-116`.

Use an injected HTTP transport for a unit-level negative-capability test: give the model prompts seeking shell execution, host-file contents, MCP calls and web access; assert every outbound request has an empty tool set and `tool_choice: "none"`, no subprocess or host-file read is reachable from this adapter, and a plain text response yields a bounded result. Assert malformed tool-bearing responses fail closed. The 803-second integration suite cannot be this change’s only pre-merge check; the unit claim is that the adapter offers no executable tool channel and rejects one if returned.

This changes ADR 0106 §6, which says “Codex throws `ToolsCannotBeDenied`,” so update that topic's ADR in place with the new conditional route.
