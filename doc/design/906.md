# #906 — the shape

## Three facts that moved since `9c0276dc`

**1. The footer sits outside `<main>`, not at its end.** #905 landed `68ed59a8`, and `/` mounts the footer after `</main>` (`apps/board/src/app/page.tsx:932-934`): *"Outside `<main>`: a `<footer>` inside it has no `contentinfo` role."* The ticket's "end of `<main>`" was written before that. Read every mount in the ticket's table as **directly after `</main>`**:
- On `/spend` (`spend/page.tsx:138`), `/report` (`report/page.tsx:148`), `/backlog` (`backlog/page.tsx:119`) and `/recipe/<project>` (`recipe/[project]/page.tsx:154`), the page's return becomes a fragment: `<><main …>…</main><FooterFetched …/></>`.
- On the task page, `TaskBody` returns a bare `<main>` (`task/[id]/layout.tsx:146-226`). Give it the same fragment, with `<FooterFetched>` after `</main>`. It stays inside `TaskBody` and so inside `<Follow>` (`:258-262`). The element sits at a fixed position in the tree with no `key`, so `router.refresh()` reconciles it and keeps its state. That is what the Watch out relies on.
- The Done-when grep for `<FooterFetched` still holds.

**2. `Footer` lives at `apps/board/src/app/footer.tsx`, not in `lib/`.** Its header already promises #906 (`footer.tsx:6-10`): *"Pure, with no import but React, `next/link` and types: #906 mounts it in a client component."*
- Keep that true. The currency line goes in this file, and so does anything else it needs.
- `landed` becomes optional (`landed?: number`). When it is absent, the `/landed` link (`footer.tsx:77-79`) is not drawn at all. Do not draw `0 landed`.
- `lib/footer.ts` (the ticket's `loadFooter`) is a separate, server-only file. Nothing under `app/footer*.tsx` imports it as a value.

**3. `ProjectionLag` cannot be sent as JSON.** Its fields are `lastSeq`, `headSeq` and `lag` as `bigint`, and `updatedAt` as `Date | null` (`packages/projector/src/store.ts:203-212`). `Response.json` throws on a bigint, and that throw happens inside the route, after `loadFooter` has already "never thrown". So `loadFooter` returns a wire shape, not `ProjectionLag[]`:

```ts
// lib/footer.ts — server only
export interface FooterLag { name: string; lag: number | null }   // null: no checkpoint row
export interface FooterReading { day: DaySpendReading; lags: FooterLag[] | null }
export function footerLags(rows: ProjectionLag[]): FooterLag[]     // pure, unit-testable
export async function loadFooter(): Promise<FooterReading>
```

`FooterLag` and `FooterReading` are types, so `footer.tsx` and `footer-fetched.tsx` may `import type` them from `@/lib/footer`. `DaySpendReading` is already plain JSON (`lib/day-spend.ts:11-20`; `DaySpend` is numbers and arrays, `packages/conductor/src/day-ceiling.ts:39-50`). `/` passes `footerLags(rows)` too, so the server and client paths draw from one shape.

## Which projections the line names

`projectionLag()` returns only projections that have a checkpoint row (`projection.ts:292-303`: *"Lag for every projection with a checkpoint"*). A projection that was never built does not appear, so listing only what came back would read *projections current* with one missing. That is the silence the ticket is about.

- `footerLags` therefore walks a fixed list of the four names and gives a missing one `lag: null`. The line says it as *`<name>` not built*, with the same rebuild `title`.
- The list is `PROJECTION_NAMES` in `apps/cli/src/commands.ts:33`, which the board cannot import. Copy it as a constant in `lib/footer.ts`, with a comment naming the CLI's copy.
- Add a unit test that reads `commands.ts` and asserts the two lists are equal, so a fifth projection cannot be added to one and not the other.

The line is then:
- *projections current* when all four are `lag === 0`;
- otherwise one fragment per projection that is not at 0, joined by ` · `: *spend behind 3*, *ticket_report not built*. Each fragment is its own `<span title="lingtai projection rebuild <name>">`;
- *projections unreadable* when `lags === null`.

It is faint type, on a line of its own under the existing row inside the same `<footer>`, so the spend row's layout does not change. Use one new class beside `.footer`'s rules (`globals.css:154`), for example `.footer .currency`, with `color: var(--faint)` or whatever faint token the file already uses. Check it in both themes.

## `loadFooter`

```ts
const [day, lags] = await Promise.all([
  readDayReading(),
  projectionLag().then(footerLags, () => null),
])
```

`readDayReading` already never throws (`day-spend.ts:35-49`). The `.then(…, () => null)` covers the other read. The Done-when test that mocks both reads to throw has to mock `readSpend` and `machineDayCeiling` *under* `readDayReading`, not `readDayReading` itself, otherwise it tests nothing.

Wrap each read in `timed('footer.day', …)` and `timed('footer.lags', …)` inside a `measure(…, { label: '/api/footer' })`, like the other reads.

The route sits beside `api/search/route.ts`, which is the house shape: `export const dynamic = 'force-dynamic'`, then `GET` returns `Response.json(await loadFooter())`. There is no storeChoice branch: the footer is not mounted on the store-refused screen, and a refused store already comes back as both reads failing.

## `footer-fetched.tsx`

- It is `"use client"`. Its imports are `react`, `./footer.tsx` and `./skeleton.tsx` as values, and `@/lib/footer` and `@/lib/day-spend` as types only. The Done-when test has to tell `import type` apart from a value import, because a test that bans the `@/lib/` string outright fails on the type imports.
- The effect is `useEffect(() => { … }, [])`. `project` is read from the closure and is not a dependency. It only builds link hrefs, and a project that changes means a different page.
- Use the counter the ticket's Edges asks for: a `useRef` sequence number, so an answer is dropped unless its number is still the latest. Under StrictMode the effect runs twice, and the later answer wins.
- While it waits, draw `<footer className="footer"><Skeleton shape="lines" count={1} label="reading today's spend…" /></footer>`. The landmark is there from the first paint and the row does not jump.
- If the fetch fails or the response is not `ok`, draw the same `<footer>` holding *the footer could not be read*. Never leave the skeleton standing.
- A successful answer draws `<Footer day={…} lags={…} project={project} />`, with no `landed`.
- `project` on the task page is `task.project`. Check that field name on `TaskDetail` before using it.
