## The decision that isn't obvious: the operator sequence

The ticket says *rebuild after the restart*. If the operator does that literally, both steps are refused.

- **A rebuild refuses while a daemon holds the lock.** CLAUDE.md: *"a rebuild takes that lock and refuses while a daemon holds it"*.
- **The restart refuses too.** After the merge, the CLI's doctor compares the old table with the new DDL. `shapeIn` counts a live column that is no longer declared as drift: `const unexpected = [...have].filter((c) => !columns.includes(c))` (`packages/projector/src/shape.ts:204`), described as *"no longer declared: tier"* (`packages/projector/src/store.ts:115`). The `projections: shape` check then fails with the fix `lingtai projection rebuild task_view` (`apps/cli/src/doctor.ts:913-921`). That check has no `restartAnswers`, so `gatingFailures` (`apps/cli/src/restart.ts:1520-1521`) counts it, and `planRestart` refuses unless `--despite-doctor` is passed (`restart.ts:311-317`).
- **Forcing the restart costs `task_view` its follower.** A daemon started onto that drift keeps running, but `task_view` stops following on its own (`packages/daemon/src/daemon.ts:299-312`, #839: *"stop that projection alone and bring the daemon up with the rest"*).

So the merge note should give this order:

```
pnpm lingtai shutdown "#1165 drops task_view.tier"   # appends the request and returns at once
pnpm lingtai doctor --verbose | grep -A1 'conductor: lock'  # repeat until the line under it says: nobody holds it
pnpm lingtai projection rebuild task_view            # needs the lock; refuses while the daemon still holds it
pnpm lingtai restart "picking up #1165"              # doctor is green again, so nothing is waived
```

Plain `lingtai doctor` cannot show the wait finishing: its `conductor: lock` row is always `ok`, held or free (`apps/cli/src/doctor.ts:1840-1857`), and the default report prints only rows to fix, so the one thing it would show is the `projections: shape` remedy to rebuild, which is refused while the lock is held. `--verbose` prints every row, including `conductor: lock`, whose detail (`held by …` or `nobody holds it`) is on the indented line *under* the name (`doctor.ts:4138-4140`), so the command keeps that line with `grep -A1` rather than the name alone. Do not run the rebuild until that row says nobody holds it.

`lingtai shutdown` only appends the request and returns; the daemon finishes the pass in flight (up to `runtime.limits.wall`) before it exits and releases the lock. The rebuild must wait for that, or it is refused. Under `lingtai service`, use `service shutdown` / `service start` instead. Put this sequence in the commit body, in place of the ticket's one line. Do not name the issue next to a closing verb (CLAUDE.md, *Commits*).

## Why the gap is safe

Between the merge and the rebuild, any process may be on either code against the old table:

- **New code, old table.** The reads use `select t.*` (`postgres.ts:454`), so a column the new code doesn't name is simply ignored. Writes leave `tier` out, and the column's `default 'guarded'` fills it. Nothing throws. `columnOf` (`packages/projector/src/store.ts:148`) only raises on a *missing* column, never an extra one.
- **Old code, new table.** This can't happen before the rebuild, and after it the old daemon has already exited.

The only thing an operator will see in the gap is doctor's red `projections: shape` line, and that line names its own fix. Do not add a migration or an `alter table`. `reset` drops the table on purpose (`task-view.ts:248-252`: *"Dropped, not truncated. This table's shape is expected to change"*). This shape is 0100 §13 as it stands, so no ADR changes.

## What can be checked inside a pass

- **The DDL.** `declaredShape` recovers the columns by running `create` against a recording context (`shape.ts:161-174`), so a unit test can assert that `task_view`'s declared columns don't include `tier`. Check `packages/projector/unit/` for an existing shape test and extend it if there is one.
- **Live tables.** That both stores' tables actually lack the column after a rebuild is only checked by `pnpm test:integration`, which a pass doesn't run. The unit-level stand-in is the declared-shape assertion above, plus `tsc` refusing any remaining `row.tier` once the row type loses the field.
