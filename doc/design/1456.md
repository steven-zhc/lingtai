## Where the new rules go, and why it matters

Put `.sec-h`, `.sec-h.wait`, `.sec-h.fail`, `.sec-h.wait:has(.ct.zero)` and the child reset together in one block near the top of `globals.css`. That means after `:root` and the base element rules, and before the first page section. The position is load-bearing:

- **The reset rule outranks more than it looks like it should.** `.sec-h :is(.ct, .pr-n, .when, .src, .hfact, small, a)` scores **(0,2,0)** on every element it matches, even `a` and `small`. That is because `:is()` takes the specificity of its most specific argument.
- **Several child rules the ticket says to keep have exactly that specificity:**
  - `.hfr-k .when { color: var(--muted); letter-spacing: .06em }` (`:3388`)
  - `.handled-k .when { … letter-spacing: 0.06em; }` (`:3454`)
  - `.ctbtn .lbl { … letter-spacing: 0.04em; text-transform: none; font-weight: 500; }` (`:450`)
  - `.col-h .ct { font-family: var(--mono); … }` (`:448`)
- **The tie is settled by source order.** With the reset early in the file, those later rules win and "stays as written" holds. Placed at the end of the file next to the PR or report rules, the reset would quietly flatten them.
- **The mono font for counts is its own rule:** `.sec-h :is(.ct, .pr-n) { font-family: var(--mono) }`. The reset itself sets no `font-family`, because a `.when` or a link inside a heading should not turn mono.
- `.col.hot .col-h .ct` (`:458`, 22px, weight 500) is (0,3,0). It beats the reset wherever it sits, and keeps its own rule as the ticket says.

## The guard test

Build `apps/board/unit/section-heading.test.ts` on `rulesOf` and `stripComments` from `apps/board/test/css-rules.ts`, the way `card-radius.test.ts` does. That helper already strips comments and walks nested blocks and `@media` blocks.

**How to match a selector:**
1. Split each rule's `selector` on top-level commas. Split only at depth 0: commas inside `:is(…)` and `:has(…)` belong to their parentheses.
2. Normalise the whitespace.
3. A part matches a listed selector when it is **equal to it, or ends with `' ' + listed`**.

That covers each of these:
- `.detail--waiting .triage-label`
- `.detail--waiting .triage-hunk-group h3` (`:1676`)
- `:is(.detail--waiting, …) .tcontext-field--watch h2` (`:1549`)
- `.col.hot:has(.col-h .ct.zero) .col-h` (`:3449`), which the ticket replaces with `.sec-h.wait:has(.ct.zero)`

It must **not** match `.col-h .ct`, `.col.hot .col-h .ct`, `.hfr-k .when`, `.hfr-k svg path` or `.col > .col-h`. The selector has to end with the listed one, so a rule that only contains it does not count. `.col > .col-h` is the exception: it does end with `.col-h`, but it declares only `min-height`.

**How to read declarations:** parse each body into `property → value`. Treat `font` as forbidden, because the shorthand is what `.sandbox .sbh` and `.handled-k` use today.

**For `.sec-h` itself:** find the rule whose selector is exactly `.sec-h`. Its declarations must be exactly those six:

| property | value |
|---|---|
| `font-family` | `var(--sans)` |
| `font-size` | `var(--fs-xs)` |
| `font-weight` | `600` |
| `text-transform` | `uppercase` |
| `letter-spacing` | `0.08em` |
| `color` | `var(--muted)` |

`--fs-xs: 11px` is declared at `globals.css:17`.

**Plant both directions, as `card-radius.test.ts` does:**
- These must be caught:
  - `.x .pr-col h2 { color: red }`
  - `.sec-h { font-size: 11px }`
  - `.sec-h.wait { font-weight: 700 }`
- These must pass:
  - `.col.hot .col-h .ct { font-size: 22px }`
  - `.pr-col h2 { margin: 0 }`

Do not add a "keep every listed selector live" check. Some of these rules will rightly shrink to layout only, or disappear.
