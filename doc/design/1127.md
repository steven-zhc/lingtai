# #1127: the shape

## Where the configured figure comes from: a value, read once by the caller

`raiseTransition` gains `configuredUsd: number | undefined`. `raiseDayCeiling` (`packages/daemon/src/control.ts:194-216`) also gains `configuredUsd: number | undefined` and passes it through. It takes a plain **value**, not a thunk. That way the attempt after a `ConcurrencyError` (`:215`) compares against the same figure the first attempt did. The second attempt still re-reads the state, so it still sees another person's raise.

**Both callers already reach `machineDayCeiling`, the function the guard reads.** The guard's port is `configuredUsd: ports.ceiling ?? machineDayCeiling` (`apps/cli/src/day-ceiling.ts:84`).

- **CLI** (`apps/cli/src/ceiling-raise.ts:37`): pass `spend.configuredUsd`. `readDaySpendTrusted` already returns it (`day-ceiling.ts:168`) from `ports.ceiling ?? machineDayCeiling`, and it already refuses an unreadable figure by name: *"could not read limits.day_usd: …"* (`:165-166`). Nothing new to read.
- **Board** (`apps/board/src/lib/locks.ts:296-323`): give `continueTodayWith` a port `configuredUsd: () => number | undefined`. In production, `continueToday` (`apps/board/src/app/actions.ts:579`) passes `machineDayCeiling` from `@lingtai/env` (`packages/env/src/index.ts:979`). Call it inside `Effect.try`. If it throws, answer `{ ok: false, detail: "could not read limits.day_usd: <message> — nothing raised" }` and append nothing.
  - **Do not take the figure from `readDayReading()`'s `ceilingUsd`.** `configuredCeiling()` swallows the throw and returns `undefined` (`apps/board/src/lib/day-spend.ts:60-66`). A malformed `day_usd` would then be refused as *no ceiling configured*, which is a false sentence. `machineDayCeiling`'s own comment says this case must not go quiet: *"a ceiling that quietly became no ceiling reads as a guarantee it is not"* (`env/src/index.ts:976-977`).
  - Use `Effect.try` around a synchronous call, not a new `async` function. The ratchet (`packages/domain/unit/effect-ratchet.test.ts`) must not move.

## `raiseTransition`, in order

1. `configuredUsd === undefined` → refuse `no-ceiling`. This **replaces** `not-reached` in `RaiseRefusal` (`ceiling-lock.ts:133`), so the old name is gone, not kept unused. Suggested sentence: *"no daily ceiling is configured — nothing to raise; to set one, edit limits.day_usd"*. It refuses even when a lock still stands: a lock with no configured figure is the guard's to lift as `config-removed` at its next look (`ceiling-lock.ts:113-114`).
2. `today = todaysCeiling(state, now, configuredUsd)` (`:31-35`).
3. `cents(toUsd) <= spentCents` → `not-above-spend`. Unchanged.
4. `cents(toUsd) <= cents(today)` → `not-above-ceiling`. Its sentence (`:140`) still says *"the ceiling that was reached"*. Change it to *today's ceiling*, because nothing may have been reached.
5. Otherwise, write `DayCeilingLifted { day: localDay(now), why: 'person', by, toUsd, fromUsd: today }`.
   - The day is **always** `localDay(now)`, never `reached.day`.

These cases come out of that order with no special handling. None of them changes the reducer (`packages/domain/src/control.ts:237-251` sets `reached: null` and records `raised` for any person's lift):

- **Lock standing today, `limits.day_usd` raised above it, guard not yet run:** step 4 compares against the larger figure, so `fromUsd` is today's figure rather than `reached.ceilingUsd`. That is what the ticket asks for.
- **Yesterday's lock still standing** (guard not yet run): today's figure is the configured one. The raise is written for today, and the reducer clears the stale lock. This is the same outcome as the guard's `new-day` lift followed by the raise. It used to be `not-reached`. The domain test at `packages/domain/unit/ceiling-lock.test.ts:119-124` becomes a test that it raises and names today.

**`fromUsd` changes meaning, so fix its readers' words.** The comment on `CeilingFacts.raised` says *"`fromUsd` is the figure that was reached"* (`ceiling-lock.ts:43`). It becomes *"today's figure when the raise was made"*. Run `git grep -n fromUsd -- apps packages` and reword any reader sentence that says *reached*. Do not change the event schema; the field is already optional (`control.ts:246`).
