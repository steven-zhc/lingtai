# Design note: #1100, the `ticket`, `backlog`, `end replay` and conductor-note conversion

The ticket's shape holds. Two of its premises do not match the worktree, and one trap is not in its Watch out. All three are below, followed by the rule that settles every `try`/`catch` in these files.

## 1. `processTicketSqlEffect` is not exported; export it, and keep the `processTicketSql` face

`packages/event-store/src/choose.ts:106` reads `const processTicketSqlEffect = () => Effect.map(process_.get(), (o) => o.tickets)`. It has no `export`, and `index.ts:29` exports only the promise `processTicketSql`. Its neighbours are exported Effect values: `processLogSql` `:247`, `processQueries` `:233`, `processSnapshots` `:257`.

- **What to do:** make it `export const processTicketSqlEffect: Effect.Effect<TicketSql> = Effect.map(process_.get(), (o) => o.tickets)`, and keep `processTicketSql` calling `Effect.runPromise(processTicketSqlEffect)`. Export it from `packages/event-store/src/index.ts`.
- **The ratchet is unaffected.** This adds no `async` and no `Effect.run*`.
- **Do not delete the `processTicketSql` face.** The ticket expects to, but `packages/conductor/src/ticket-history.ts:28` and `ticket-store.ts:232` still await it, and `closable.test.ts:44` tests it.
- Change only its `why` at `effect-ratchet.faces.json:598-600`: drop `apps/cli ticket.ts`. The `TicketSql` entries at `:642` and `:690` also name `apps/cli ticket`; drop that from each.
- `defaultTicketsFor` becomes `(project) => Effect.map(processTicketSqlEffect, (sql) => makeDbTickets(sql, project))`.

## 2. `ticketsFor` hands back `DbTicketsEffects`, and its members are Effects

`makeDbTickets` returns `DbTicketsEffects` (`packages/conductor/src/db-tickets.ts:204-219`), not `DbTickets`. So the seam is `ticketsFor?: (project: string) => Effect.Effect<DbTicketsEffects>`.

- Every `await tickets.X(…)` in `ticket.ts` becomes `yield* tickets.X(…)`: `:254-255`, `:347`, `:358`, `:581`, `:660`, `:705`, `:752`.
- In `ticket.test.ts`, the store the tests seed with `await tickets.createIssue(…)` (`:109-113`, `:138-144`) has two options:
  - keep it as `dbTickets(freshSql(), 'p')` for seeding and give the seam `makeDbTickets` over the **same** `sql`; or
  - build `makeDbTickets` once and seed with `Effect.runPromise`.
  
  Either is fine as long as the seeded rows are the rows the verb reads. Two `makeDbTickets` on one `:memory:` handle share the tables, because `ensureReady` is per-store but the DDL is idempotent.

## 3. The trap: these Effects' store failures are defects, so `Effect.catch` misses them and *"your text is kept at …"* is lost

`DbTicketsEffects` says *"a store failure is a defect (0101 §6)"* (`db-tickets.ts:201-202`). `createIssue` is `Effect<Ticket>`, with no error channel at all.

Today, `ticketNew`'s `try { … createIssue … } catch` (`ticket.ts:657-663`) and `ticketEdit`'s around `updateFields` (`:751-764`) catch a rejected driver and print `<message> — your text is kept at <path>`, exit 1. Translated literally into `Effect.catch` / `Effect.either`, a SQLite or Postgres failure there escapes as a defect instead. The handler then prints its own *message, exit 1*, and the path to the person's text is never said. That is the Watch out's own line, broken silently, and no unit test covers it today: the fakes only fail with typed errors.

`newFromFlags`'s `Effect.tryPromise(… createIssue …)` at `:580-585` has the same problem once it yields an Effect.

**Rule for every place `ticket.ts`, `backlog.ts` and `end.ts` catch today: recover the whole cause, not just the typed failure, and let interruption through.** The house pattern is `install.ts:359-360`:

```ts
Effect.catchCause((cause) =>
  Cause.hasInterruptsOnly(cause) ? Effect.failCause(cause) : /* today's line */ (Cause.squash(cause) as Error).message)
```

`packages/conductor/src/backlog.ts:191-192` does the same with `hasInterrupts`. Wrap it in one local helper, for example `attempt(eff): Effect<{ok:true,value}|{ok:false,why:string}>`, and use it at each of these:

- **`ticket.ts`:**
  - `getIssue`, `:347` and `:705`;
  - `createIssue`, `:581` and `:660`;
  - `updateFields`, `:752`;
  - `edit` at `:722`, so a failing `mkdtemp` still prints its message and exits 1.
- **`end.ts`:** the per-item `try` around `projectClientEffect` / `currentRecipeEffect` / `appendEndActionsEffect` / `tellGitHubAboutEffect` (`:93-123`). `appendEndActionsEffect`'s error channel is `unknown` (`end-step.ts:167`), and *"Named and carried on"* has to hold for a defect too, or one bad project stops the replay.
- **`backlog.ts`:** `finish`'s `readLagEffect` catch, `:235-240`, which swallows everything today.

Add one unit case that pins this: a `ticketsFor` whose `createIssue` is `Effect.die(new Error('disk I/O error'))`. It should assert the *"— your text is kept at"* line and exit 1, and that `discards` stays 0. This is not a string change; it is the existing line, now for a cause that was untested.

A `ticketClose` whose `closeIssue` dies stays uncaught today (`:358` has no `try`), so it goes to the handler. Leave it that way.

## 4. `defaultEdit` and `discard`

- `mkdtemp` and `writeFile` go in `Effect.tryPromise`. Today's caller catches them, so they surface through `attempt` as above.
- The editor runs as `Effect.sync(() => spawnSync(…))`. A non-zero status becomes `Effect.fail(new Error(<today's sentence>))`, and `readFile` is a `tryPromise`.
- `discard` is `Effect.promise(() => rm(dir, { recursive: true, force: true }))`, yielded only on the two success paths (`:665`, `:766`), as today.

## 5. `conductorNote`

- `holder` stays `() => Promise<string | null>`.
- `bound` becomes `<T>(op: Effect<T>, ms) => Effect<{ok:true,value:T}|{ok:false,why:'timeout'|'abort'}>`. The default is `Effect.timeoutOption(ms)` mapped to `'timeout'`.
- `'abort'` remains reachable only through an injected `bound`, which `conductor-note.test.ts:32-38` does.
- Fiber interruption replaces `signal` for the real path. Keep `signal` on `ConductorNoteWorld` only if a remaining caller passes one: run `rg -n "signal" apps/cli/src` over the CLI-10 verbs before deleting it.
- Lift the holder once, with `Effect.tryPromise({ try: holder, catch: (e) => e })`. Then recover with `catchCause` (letting interruption through) into today's *could not tell … (EACCES)* sentence.
- Keep `boundReal` exported, unchanged, for `approve.ts`.

## 6. Counting and landing

- Recount with `effect-ratchet.test.ts` rather than trusting the 20. `rg -c async` on the four files reads 12/5/2/1, but a nested `async` inside an `Effect.promise(() => …)` arrow counts too, so introduce none.
- The baseline reads `apps/cli: 213` here. Per the operator's order note, the target is main's figure at the start of this attempt minus what this removes.
- Expect conflicts on `cli.ts`, the baseline line and `faces.json` against CLI-12. Resolve as the note says: the lower number wins, and faces are the union minus deletions.
- **Faces to delete:** `appendEndActions` and `tellGitHubAbout`, but only if `rg` finds no caller outside tests after this change. `endedWithoutEndActions` stays for `doctor.ts`. `processTicketSql` stays, per §1.
