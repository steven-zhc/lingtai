## Design note: #952, deleting `/spend`

Most of this is plain deletion. Five things are not in the ticket: two tests that break, two exports that lose their only reader, and one wrong file reference.

### 1. Two tests still point at the page, not only `spend-table.test.tsx`

- `apps/board/unit/footer-fetched.test.tsx:48` lists `'app/spend/page.tsx'` in `mounted` and reads that file. Once the file is deleted, that test goes red. Remove the entry and leave the other four in place.
- `apps/board/unit/bar.test.ts:23` imports `ledger` from `board.ts`. Four cases (around lines 396–458) test it: *keeps answering's spend out of the work's*, *puts every card in exactly one row*, *prints a column that adds up*, and *nothing to say about a board with nothing on it*. See §2.

### 2. `ledger` and `LedgerRow` go too, with their four `bar.test.ts` cases

`ledger` (`apps/board/src/lib/board.ts:1649`) and `LedgerRow` (`:1615`) were written for this page. The doc comment says so: *"What the board's cards cost, per repository and in all — the `/spend` page"*, and *"the `/spend` page's own claim is 'the cards the board is showing', not a window over the log"*. The only callers are `spend/page.tsx:59` and `spend-table.tsx:10`. This is the cards-only count the ticket's Problem row says should go, so delete it rather than leave it unread. Also delete the four cases from §1, the `ledger` import, and the line in the file's header comment (*"The spend that left the bar is a ledger now…"*, `bar.test.ts:13-14`). The health-dot half of that file stays.

The ticket's Out of scope protects `lib/spend.ts`, which includes `billOf`, `totalBill`, `PURPOSES` and `billText`. `ledger` is in `board.ts`, not `spend.ts`, so it is not covered.

### 3. `Board.limits` and `Board.spend` lose their only reader

`spend/page.tsx:57-59` is the only place that reads `board.limits` or `board.spend`. A grep found no `board.limits` or `board.spend` in `app/page.tsx`. The returned object fills them at `board.ts:1310` (`limits: queued.limits`) and `:1321` (`spend`).

- **`limits`**: remove the field from `Board` (`board.ts:351`) and from the return. Keep `queued.limits` itself, because `loadBoard` still reads it at `:1264` (`limitsByProject`) to set each card's rounds and restarts.
- **`spend`**: remove the field from `Board` (`:404-408`, whose doc says it is there for *"`/spend`'s `ledger`"*) and from the return. Keep the local `spend` read inside `loadBoard`, because each card's bill comes from those rows.

Let `pnpm typecheck` confirm that nothing else reads either field. If something does, keep that field and reword its doc comment to name the new reader.

Also reword the `AttemptLimitsView` comment at `board.ts:314-320`, *"**On `/spend`, and no longer on the bar.**"*. The standing permission now appears on the recipe page as *an attempt* (`apps/board/src/lib/recipe.ts:897-905`), as the ticket's Watch out row says. The comment should point there.

### 4. `fetchedNote`: `day-ceiling.ts:130` is in `packages/conductor`, and it stays

`day-ceiling.ts` is not a board file. It is `packages/conductor/src/day-ceiling.ts`, and line 131 is `export const fetchedNote = …`. `daySpendText` (`:111-114`) and `billText` (`apps/board/src/lib/spend.ts:27,186`) both use it, and both are covered by `packages/conductor/unit/day-ceiling.test.ts:90` and `apps/board/unit/spend.test.ts:176`. Leave the conductor function and `billText`'s option alone, because the ticket puts `billText` out of scope.

The board-side option is a different matter. After the deletion, nothing in `apps/board/src` calls `readDayReading({ fetchedNote: true })`. The report calls `readDayReading()` with no option (`apps/board/src/app/report/page.tsx:67`), and so does the home page (`page.tsx:698`). So, following the ticket's own Edges rule:

- Drop the `options` parameter from `readDayReading` (`apps/board/src/lib/day-spend.ts:37-38`) and from `dayReading` (`:28-31`). `dayReading` then calls `daySpendText(day, ceilingUsd)`.
- Rewrite `apps/board/unit/day-reading.test.tsx`. Its header says *"the fetched-prices note is `/spend`'s `text` alone (#677)"*, and lines 25 and 33 pass `{ fetchedNote: true }`. Keep the half of the test that asserts the note is **absent** from the reading's text, and delete the half that asserts it is present, since that half only described `/spend`.
- Leave `daySpendText`'s `fetchedNote` option in conductor. The conductor test still covers it, and removing it is a change to a package this ticket does not need to touch.

### 5. Comments to reword (the ticket names three; there are more)

These comments describe `/spend` as a place that exists. Each should say where the thing lives now: the report for the money, the recipe page for the limits.

- `apps/board/src/app/page.tsx:719` and `:811-812` (*"spend and the pass limits are on `/spend`"*)
- `apps/board/src/app/report/page.tsx:4` (*"`/spend` sums the board's window and stops there"*): this becomes a sentence about the report alone
- `apps/board/src/lib/day-spend.ts:25-26`
- `apps/board/src/lib/spend.ts:6` (*"Three readers — `/spend`, the card and the task page"*)
- `apps/board/src/lib/board.ts:314`, `:405` and `:1623`, if their code survives §2 and §3
- `apps/board/unit/spend.test.ts:203` (*"`/spend`'s ledger"*)

`git grep -n "/spend" apps/board` should end up finding nothing that describes a live page. A mention in a historical sentence (*"#498 split `/spend` by purpose"*) is fine. The ticket's Done-when grep only looks for the quoted `'/spend'`, which only `search.ts:39` contains today.
