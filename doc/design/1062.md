## Design note: #1062. A placeholder is its shape alone

The ticket already gives the shape. This note covers only what the ticket leaves for you to decide.

### `Skeleton` after the change

`apps/board/src/app/skeleton.tsx:12-47` loses `label` and the `<p className="empty asking">` at `:26`. The outer `<div className="skeleton">` gets `aria-busy="true"` and no name: no `aria-label` and no `role`. The outlines keep their `aria-hidden="true"` (`:28`, `:36`, `:42`). The rest of the component stays exactly as it is. That includes the `cells` branch's `Math.max(1, count)` for `--steps` and the `Math.max(0, count)` loop. Replace the prop comment at `:19-21` (*"0 draws the label alone"*, *"Said to a reader of the text, once"*) with one line citing 0111 §15: *no words, for anyone*. Remove `.skeleton .asking` at `apps/board/src/app/globals.css:3227`, and leave `.skeleton { display: grid; gap: 8px; }` (`:3226`) alone.

Do not build a visually-hidden text node to replace the label. 0111 §15 says *"no label saying what is being asked, visible or for a reader of the text"*. A `.sr-only` span would be the same label in another place.

### Expected layout change

Every skeleton gets shorter by the label's line plus one 8px grid gap. At several call sites a one-line skeleton sits inside text-sized slots: `standing.tsx:108` is `asking`, which is reused in `.triage-cause` (`:123`), `.triage-summary` (`:131`) and `<span className="fv">` (`:187`). There, `count={1}` now draws a single `.sk-line` where it used to draw a label plus a line. That is closer to the height of the answer, not further from it, so do not adjust any count to make up for it. The counts are #1038's, and the ticket puts them out of scope.

Leave `src/lib/progress.ts:23` and `src/lib/task.ts:1568` alone. They say "asking GitHub" as a verb, not as a quoted label.

### Health pulse

### Tests

The ticket names the files. The rule to apply to each assertion that keys on a label:

- **Present while waiting**: assert that the rendered HTML contains `class="skeleton"` together with the shape's outline class: `sk-card` for columns and Queued, `sk-line` for lines, `sk-cell` for cells. `class="skeleton"` alone is not enough, because `count` 0 still draws that container.
- **Gone once answered** (`home-streams.test.tsx:178-181` and any similar check): assert that `sk-card` (or `sk-line`) is absent, **and** in the same test assert something positive that only the answer draws, such as a card's id or *nothing queued*. Absence on its own passes against a render that drew nothing.
- `ASKING_COLUMN` is exported (`queued-stream.tsx:33`) and imported by tests. Delete the export, and let `pnpm typecheck` find every importer. Do not leave the constant behind for the tests.
- Add a new `unit/skeleton.test.tsx`. Render `Skeleton` with `renderToStaticMarkup` for `card`, `lines` and `cells`, each at count 2 and at count 0. Assert:
  - the outline classes and their number;
  - `aria-busy="true"` is present;
  - there is no `aria-label`;
  - the markup with tags stripped is the empty string. Strip with `.replace(/<[^>]*>/g, '')`.

  That last assertion is the "no text node" claim in *Done when*, and it can only be checked at unit level.

Run `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`. Nothing in this change reaches the integration half. The Next build test (`apps/release/integration/build.test.ts`) is not affected, because no `"use client"` import changes.
