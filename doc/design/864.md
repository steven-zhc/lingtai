# Design: #864, cutting `doc/guide.md` to a TL;DR and seven short sections

This is a prose-only rewrite of one file. Three things outside the page depend on its text, and the ticket doesn't name any of them. Each one breaks silently, or turns `pnpm test` red, if the cut is made without knowing about it.

## 1. A unit test parses one sentence on this page. Keep it word for word.

`packages/conductor/unit/step-matrix.test.ts:1361-1397` reads `doc/guide.md` and runs this on it:

    /(\w+) action kinds, of\s+which ([\s\S]*?)\n\(\[reference\]/

It then checks two things:
- the number word equals `PLUGINS.length`;
- the number words in the buckets add up to the same total.

The sentence it matches is at `doc/guide.md:272-275`, in *Gate what has failed*. It reads *"Fourteen action kinds, of which four produce a verdict, two run for effect, one keeps what a step made, one reads it back, and six are names for code the pass calls itself and no step yet reads"*, and it is followed by a newline and `([reference](…))`.

The test's own comment explains why it exists: *"nothing in `pnpm test` read that file"* (#300).

So this sentence survives the cut, and it is **in addition to** that section's one figure:
- Keep every number word.
- Keep the line break immediately before `([reference]`.
- If the sentence is cut or reflowed, `pnpm test` goes red with *"doc/guide.md no longer says how many action kinds there are"*.

Do not edit the test to fit the page. The ticket's own Edges say: *"change the snapshot, not the rule"*. This is a rule, not a snapshot.

The sentence just before it ("Ten steps, closed forever — …", `:270-272`) may be shortened. The action-kinds sentence must still begin a line or follow on directly.

## 2. Keep an intro paragraph, below the TL;DR

The site takes the page's description from its first paragraph:
- `ledeOf` (`apps/site/src/lib/docs.ts:374-383`) takes the first block after the `# ` title.
- It skips blocks that start with `#`, `|`, a code fence, `>`, `-` or `*`.
- That text becomes the docs-index line (`apps/site/src/app/docs/page.tsx:87`) and the page's meta description (`apps/site/src/app/docs/[...slug]/page.tsx:66`).

If the TL;DR goes directly under the title and the intro paragraph is deleted, the lede becomes the first **The rule.** paragraph, which is about `prompts/ticket.md:5`. That is wrong in both places.

The layout is therefore:
1. `# Best practices`
2. `## TL;DR`
3. Seven `-` bullets. **Not** a numbered list: `ledeOf` does not skip `1.`, so the first TL;DR line would become the lede.
4. The intro paragraph, then the first `##` section.

Shorten the intro paragraph, and drop *"the evidence follows"*, which stops being true. Keep its link to `reference.md#policy--every-number-that-decides-behaviour`.

The TL;DR heading slugifies to `tldr` (`slugify`, `docs.ts:482-488`: lower case, punctuation dropped, each space becomes a hyphen). The seven section anchors are the titles run through the same rule, for example `#write-the-ticket-as-the-prompt` and `#size-it-for-one-pass`. No title contains punctuation, so each anchor is simply the title in lower case with hyphens.

## The template in the first section

`doc/guide.md:34-61` is a fenced ticket template.

The `##` lines inside the fence are not real headings: the site's heading reader skips fenced blocks (`docs.ts:511-531`). So *"no `###` subsection remains"* is not violated by them. GitHub's renderer skips them as well.

The template is about 80 words. Cut it. The *Do this* bullets of that section already name each part, and CLAUDE.md is where the full template lives. This counts as dropped material, not moved material.

- **Count words with `wc -w`, including the code spans.** The ticket's 1800-word limit is measured that way, so measure the same way.
- **The "one figure" lives in the evidence sentence.** A **The rule.** paragraph keeps any `file:line` and `#issue` it already has. That is the rule's meaning, not a second figure. Check each one against the current line, not from memory: `conduct.ts:3929` and `discover.ts:205` are both in the first section.
