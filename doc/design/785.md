## Where it goes

All of it stays in `packages/domain/unit/retired-names.test.ts`. Nothing outside the file changes, and no other file needs to know.

## The decision: cache what is read from disk, keyed by path, and leave the pure functions alone

`tokens(src, name)` (`:175-179`) and `entries(src, name)` (`:181-184`) are called two ways:

- **On a real file**, from `count` (`:461-467`) and from the scan at `:714`.
- **On a string written in the test, under a made-up name**: `tokens('const re = /gates/;\nconst s = "gate";\n', 'f.ts')` at `:959`, and the run of `const read = tokens(` from `:849` onward.

Only the first kind repeats work. So do not memoise `tokens`, `entries` or `readEntries` themselves. A cache keyed by `name` would serve one test's `'f.ts'` string to the next test that also uses `'f.ts'`. Leave those three functions exactly as they are, because the synthetic tests are what pin them.

Add one function that sits where the disk is read:

```ts
const reads = new Map<string, Promise<{ tokens: string[]; entries: string[] }>>()
function read(file: string) { /* get-or-set the promise for this repo-relative path */ }
```

On a miss it does `readFile(\`${root}${file}\`, 'utf8')` once, then:

- **`.css`:** `entries = tokens = classes(src)`. That is the same thing both functions already return for a stylesheet (`:176`, `:182`).
- **Otherwise:** `entries = readEntries(src, file)` once, and `tokens = entries.join('\n').match(/[A-Za-z_$][A-Za-z0-9_$]*/g) ?? []`. That is exactly `scannable` (`:151-153`) followed by `tokens`' regex (`:177`), done without the second parse.

Write the `.ts`/`.tsx` branch by calling `scannable`'s join on `entries`, not by copying the regex a second time. If you do copy it, add a comment on it saying it must stay identical to `:177`. A second copy of the regex that drifts is the "cache of one shape served as the other" failure the ticket warns about.

**Why the path is enough of a key.** The ticket asks for the key to cover *the file and what is read of it*. The repo-relative path carries its own extension, and the extension decides both things the ticket names: `classes` versus `readEntries`, and `ScriptKind.TSX` versus `TS` (`:139`). Every value also holds both shapes (`tokens` and `entries`) and is always built with `name = file`. So there is no second key component to get wrong.

Store the **promise**, not the resolved value. `:714` runs `Promise.all` over every source at once, and caching only after the read finishes would let all of those reads start before any of them is cached.

## Callers

- **`count`** (`:461-467`): replace the `readFile` and the two calls with `const { tokens, entries } = await read(file)`. Do not change anything after that: the `exempt`, `glued`, `retired` and `pairs` logic is applied per call, outside the cache. That is what keeps `violations(g)` and `violations(elsewhere)` (`:648-649`) separate readings.
- **`:714`**: `(await Promise.all((await sources()).map(async (f) => (await read(f)).tokens))).flat()`.
- **`halves()` via `count`** (`:1495`): it goes through `read` too, and that is safe. Its paths (`…/unit/…`, `…/test/…`) never collide with a `src/` path, so sharing the `Map` mixes nothing.

## The directory walk

Memoise `everything()` (`:253`) and `halves()` (`:271`) as two separate module-level promises. Do not memoise `under(dirs)` with a key built from `dirs`; two named promises are simpler, and they keep the two lists apart, as the ticket's Edges require. `sources()` stays a filter over `everything()`, because `:816` reads the non-`READS` part of the same walk.

Hand callers the cached array. None of them mutates it: `:774-790` only calls `.filter`, and `count` only iterates. If you would rather make that impossible than just true today, return a `readonly string[]`, and `tsc` will hold every caller to it.

## Showing each file is parsed once

Increment a module-level miss counter in `read`'s miss branch only, so the synthetic `tokens(…, 'f.ts')` calls never count. Then add one new `it` that:

1. calls `violations(g)` once,
2. records the counter,
3. calls `violations(g)` again,
4. asserts the counter has not moved,
5. asserts it is not greater than `(await sources()).length + (await halves()).length`.

This test does not depend on which tests ran before it, so it holds under `.only` and under reordering. It adds an assertion and changes none of the existing ones, so it stays inside *Every assertion and expected value in the file is unchanged*.

## What this leaves alone

- **`root`** and how paths are prefixed with it: unchanged.
- **The glossary read at `:408`**: one `readFile` of `doc/reference.md` per call, which is not where the time goes. Out of scope.
- **Failed reads**: a file that fails to read rejects its promise, and the rejection stays cached. That is the same failure as today, raised once instead of in every test, and the ticket says this edge does not apply.
