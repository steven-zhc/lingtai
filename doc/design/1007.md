## Design for #1007: ceiling marks on cards, Running and the footer

### What is already in place (and so is not built again)

- **Every project's entry in the lock map already includes the ceiling lock.** `readProjectLocks` runs `locksOn({ project, control: state })` for every registered project (`apps/board/src/lib/locks.ts:76-77`). `locksOn` adds the `ceiling` lock whenever `dayCeiling.reached` is set (`packages/domain/src/locks.ts:37-49`). So `projectLocks.get(card.project)` (`page.tsx:886,909,935`) already reaches `Card`, and the card case needs no new parameter.
- **The control-read edge comes free.** When the control read fails, `state` is `undefined` (`locks.ts:76`). The map then holds no ceiling lock, so cards and Running stay unmarked. If `readProjectLocks` itself fails, `lockMap` gives an empty map (`lock-marks.ts:16-18`).
- **The card's dim comes free.** `page.tsx:270` adds `paused-card` for any `standing.state === 'paused'` while the conductor-wide pause is off. A ceiling standing that uses state `'paused'` gets the class with no change.
- **#995 left the old shape.** `emptyNote` still takes `pausedInScope: readonly string[]` (`board.ts:526`). **`emptyHeld` (`board.ts:544-555`) takes the same parameter, and the ticket does not mention it.** The reshape the ticket asks for has to cover both functions, because the held colour is decided there (`page.tsx:921`).

### `lock-marks.ts`: one new kind check

Add `ceilingToday(locks, now: Date): Extract<Lock, {kind:'ceiling'}> | null`, beside `isPaused`. It returns the lock when `lock.day === localDay(now)`, using `localDay` from `@lingtai/domain` (`ceiling-lock.ts:21`). The file's header says it is *"the only place this ticket looks at a kind"*, and that later kinds add *"a case beside `isPaused`, never a new parameter"* (`lock-marks.ts:5-7`). Keep it that way: `board.ts` imports `ceilingToday` and does not compare `kind` itself.

**A reached lock from today is marked even after a raise the guard has not acted on yet.** The guard's next `ceilingCheck` appends `DayCeilingLifted{why:'config-raised'}` (`ceiling-lock.ts:113-120`). Until then the log still holds the lock. `locks.ts:33-34` (domain) says: *"whether yesterday's is lifted is the guard's to append, never a reader's to compute"*. The same applies today: no reader-side check of `todayUsd > lock.ceilingUsd`. With no conductor up, the board shows "reached" and "raised" together. That is true to the log, and `DayCeilingLifted` is the event that clears it.

### `queuedStanding` (`board.ts:1751`)

Insert the ceiling case between the conductor-wide `paused` block (:1762) and `isPaused(projectLocks)` (:1768). Convert with `ceilingToday(projectLocks, new Date(now))`, since `now` is a number. Use the ticket's text and title. Update the doc comment above it (:1740-1749) to give the order.

### `emptyNote` / `emptyHeld` (`board.ts:522`, :544)

- Replace `pausedInScope: readonly string[]` with `locksInScope: LockMap` in both, and keep `everyProjectPaused`.
- At `page.tsx:677`, build the scoped map with `new Map([...projectLocks].filter(([p]) => only === undefined || p === only))`.
- Inside, paused names come from `pausedNames(locksInScope, undefined)`.
- Order in Running:
  1. conductor `paused`;
  2. any `ceilingToday` in scope → ``Nothing here yet. Today's spend reached the $${lock.ceilingUsd} ceiling — see the banner.``, held;
  3. the pause sentences, unchanged.
- Format the figure exactly as the footer formats `of $x`: the raw number (`$200`), not `toFixed(2)`. The mock reads `$200`.
- With zero registered projects the map is empty, so Running carries no ceiling mark. The footer still says it. Accept that.
- The Queued column's own `emptyNote(col.id, control.paused, only)` call (`page.tsx:915`) does not pass the map, so it stays 3-argument.

### `day-spend.ts`: today's figure and the footer's ceiling

`readDayReading(now = new Date(), control?: ControlState | { unread: string })`. When `control` is absent, `ceiling` is left off the reading, not set to `{unread}`. Otherwise every caller that was never asked would get the *could not be read* title. One such caller is `continueTodayWith`'s `readSpend` (`locks.ts:207-214`).

- **Build the facts with `ceilingFacts(state, now, configured)`** (`ceiling-lock.ts:56`). Do not call `todaysCeiling` beside it a second time. `ceilingUsd = facts?.todayUsd ?? configured`. `ceilingFacts` returns `undefined` when nothing is configured and nothing stands, so `ceilingUsd` stays `undefined` there, as it is today.
- **Make `fromUsd` optional in the wire shape.** `CeilingFacts.raised.fromUsd` is absent on a raise written before the event carried it (`ceiling-lock.ts:43`, `control.ts:160,307`). The footer then reads `today only, raised by you at 16:40`. Never write `from $undefined`, and never fall back to the configured figure: the raise may have been from an earlier raised figure.
- **`byShown` is computed here.** Compare `raised.by === actor()` (`actor.ts:15`). `day-spend.ts` is server-only, so importing `node:os` through `actor.ts` is safe. `footer.tsx` must still import only `type DaySpendReading` from it (`footer.tsx:7-14`).
- **`at` is `HH:MM` on the server's clock**, built from `raised.at` as `sinceLabel` builds it (`locks.ts` `two`/`sinceLabel`). A raise is only kept for today. Doing this on the server is what keeps the footer from showing the browser's timezone.
- **Compute `ceiling` before the spend `try`** (`day-spend.ts:31`), and keep it on the catch branch as well. A failed spend read still carries the control facts. Note that `machineDayCeiling()` can throw inside that `try` today; wrap it the way `configuredCeiling` does (`locks.ts:59-65`), so that a bad config only removes the figure.
- **Change `dayReading(day, ceilingUsd)`'s signature only by adding an optional third argument**, `ceiling`. `day-reading.test.tsx` calls the pure half.
- Give `nearCeiling` (:50) no change of its own.

### Callers

- **`page.tsx:664`**: `readDayReading(undefined, control)`. Here `control` comes from `readControlOnce()` at :661, which is uncaught on purpose (:639-642), so it is always a `ControlState`.
- **`loadFooter`** (`footer.ts:46`) and **`report/page.tsx:69`**:
  ```ts
  readControlOnce().then((s) => s, (e) => ({ unread: messageOf(e) }))
  ```
  then pass the result. `FooterReading` itself is unchanged, because the ceiling travels inside `day`. `FooterFetched` passes it through unchanged.

### `footer.tsx`

- Read `day.ceiling`:
  - `reached` with `!passed` → `.spend` gets `at-ceiling`, and ` · reached the ceiling` goes after the figures;
  - `raised` → `<span className="raised">` after `of $x`;
  - `unread` → a `title` on the `of $x` text.
- Draw the reached suffix only on the figures branch (:75). When spend is unread, the footer says only that, as the ticket's edge requires.
- The CSS goes beside `globals.css:173`:
  - `.footer .spend.at-ceiling > span:first-child, .footer .spend.at-ceiling .of { color: var(--fail) }`;
  - `of $x` must become its own `<span className="of">` to be coloured;
  - `.footer .raised` is muted.
- Use no `--signal` and no amber, so `bar.test.ts` stays green.

### Checks

Everything here is unit-level: pure functions in `board.ts`, `lock-marks.ts` and `day-spend.ts`'s `dayReading`, plus a static render of `Footer`. Nothing depends on `pnpm test:integration`.

- For `day-reading.test.tsx`'s `byShown` case, stub `actor` with `vi.mock('@/lib/actor')`. A real username differs from machine to machine and under `HOME=/nonexistent`.
- `effect-ratchet`: `readDayReading` is already `async` (`day-spend.ts:30`). Adding a parameter adds no function. Do not add a new `async` helper for the footer's control read; use the inline `.then` above.
- The one fact the log settles is whether the marks were right on a given day. That is `ctl-conductor`'s `DayCeilingReached.data.day` / `.ceilingUsd` and `DayCeilingRaised.data.{toUsd,fromUsd,by}`, against what `/` drew at that time.
