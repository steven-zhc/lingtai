# #908: the ⌘K palette

The ticket gives the files and the behaviour. This note covers where the logic goes so that a unit test can reach it, and settles six points the ticket leaves open.

## 1. Most of the logic goes in `lib/search.ts`, which has no imports

The route, the dialog component and the tests all import `apps/board/src/lib/search.ts`. That makes it the only `@/lib/` file a client file may import, so its own imports must be types only:

- `import type { TaskCard, TaskState } from '@lingtai/projector/task-view'`. That is the subpath `board.ts:54-62` uses, and its comment explains why the barrel is avoided.
- Nothing else. **Do not import `stateWord` from `@/lib/task`.** `task.ts` brings `@lingtai/conductor/*` and `@lingtai/daemon/control` with it (`task.ts:1-6`). It also maps the wrong type: `StandingState` (`task.ts:391`), not the card's `TaskState`, which has `verifying` and `waiting` (`board.ts:538-546`).

`search.ts` exports these:

- **`PAGES`**: the fixed page list (`/`, `/spend`, `/report`, `/backlog`). The route returns it, and the route-list test imports it from here. A test cannot import a `route.ts` without bringing in the store.
- **`TICKET_WORD: Record<TaskState, string>`**: a word for each card state, in the glossary's words. It is a `Record` so that a new state fails `tsc` and never shows the raw enum. That is the same reason `task.ts:396-398` gives for `STATE_WORD`. The values follow `task.ts:400-407` (`blocked → 'waiting on you'`). `TaskState`'s `waiting` gets the same words, and `verifying` reads *running*.
- **`buildIndex({ tasks, projects, app })`**: pure, and the whole of the route's logic.
  - `tasks` is `TaskCard[] | Error`, and so is `projects`. An `Error` becomes a `problems` sentence and its group is left out.
  - `projects` is the deduplicated union of the projects the log has cards for (`readTaskProjects`) and the register (`loadProjects`). The log's names are needed because *"a card can outlive its project"* (`page.tsx:627-633`).
  - Each project gives one Projects entry and one Recipes entry.
  - *Add a repository* points to `/setup/github-app` when `app` is false, as `projects.tsx:59-60` does.
- **`search(index, query)`** and **`paletteKey(state, key)`**, as the ticket describes them.

That leaves `route.ts` with four jobs: read, catch each read separately, call `buildIndex`, and return `Response.json`. Everything a test can check sits in pure code.

## 2. The route checks for a refused store first

`page.tsx:647-648` calls `storeChoice()` before any read, because a refused store makes the reads throw. The route does the same. On `'refused' in choice` it returns **200** with `buildIndex({ tasks: Error, projects: Error, app })`. So the palette on `not-set-up.tsx` still lists the pages, and `problems` carries the refusal sentence (`choice.refused`). Use a non-200 only when the route itself breaks. Everything else is a `problems` entry, because a bare HTTP error would leave the palette with only *the board could not be asked*.

An unbuilt projection is not a problem. `readTasks` goes through `emptyIfUnbuilt` and `readTaskProjects` through the same `does not exist` test. Both are in `board.ts:1365-1383`. `onBoardProjects` is not exported, so export it rather than writing it a second time. `emptyIfUnbuilt` is already exported.

Call `readTasks({})`, which reads every project. That is the read `loadBoard` makes at `board.ts:1221`.

## 3. The state `PaletteView` is drawn from

`PaletteView`'s props are `{ index: Index | 'pending' | null, query, selected, problems }`:

- `'pending'` draws `<Skeleton shape="lines" count={…} label="reading the log…" />`. Pick the count with `skeletonCount` if it fits (`page.tsx:20`); otherwise use 3.
- `null` means the fetch failed, and `problems` holds *the board could not be asked*.

`selected` is an index into the **flat** list that `search` returns, taken in group order. Group headings are not options and cannot be selected.

- Option ids are `palette-opt-${i}`. The listbox id is `palette-list`.
- `aria-activedescendant` is omitted when the list is empty.
- An empty result for a non-empty query says *nothing matches "…"*. That is the only time an empty list is drawn.

`paletteKey(state, key)`:

- `state` is `{ query, selected, count }`. `key` is `{ key, metaKey, ctrlKey, isComposing, keyCode }`, which is a plain object, so a test needs no DOM.
- It returns `{ state, effect }`, where `effect` is `{ go: href, newTab: boolean } | { close: true } | null`. To produce the `href`, `paletteKey` also needs the flat results, so pass them in rather than `count`.
- **A change to the query always sets `selected` back to 0.** The input's `onChange` does that, and `paletteKey` does not see typing.

The opening key is a second pure function in `search.ts`, `isOpenKey(key, isMac)`:

- On macOS it is `metaKey` with `k` and no `ctrlKey`. Elsewhere it is `ctrlKey` with `k`. Compare `key.toLowerCase() === 'k'`, because Shift gives `K`.
- It returns false while composing: `isComposing` or `keyCode === 229`, as `discussion.tsx:363-366` already does.
- `Palette` works out `isMac` once, from `navigator.userAgentData?.platform ?? navigator.platform`.

Add the `isOpenKey` cases to the `paletteKey` Done-when test.

## 4. Closing has one path

A modal `<dialog>` closes itself on Escape and fires `cancel` and then `close`. So `paletteKey`'s Escape effect calls `dialog.close()`, and **the work after closing lives in the dialog's `close` listener only**:

- restore focus to the element saved from `document.activeElement` before `showModal()`;
- clear the query;
- set `index` back to `'pending'`.

Pressing ⌘K again while open goes through the same `close()`. Two separate paths would have Escape restore focus and ⌘K not, or the other way round.

On Enter:

- Call `close()` first and then `router.push(href)`. `useRouter` comes from `next/navigation`, which is allowed under the import rule.
- ⌘/Ctrl+Enter is `window.open(href, '_blank', 'noopener')`, and the palette stays open.

The window `keydown` listener goes on `window` in the capture phase. Then a text field that stops propagation, such as the discussion box, cannot swallow ⌘K.

## 5. The stale-answer counter is a ref

Keep `useRef(0)`. Each open does `const n = ++opens.current`. A response is dropped when `n !== opens.current` at the time it arrives. A close also increments the counter, so an answer that arrives after closing is dropped too. Fetch with `cache: 'no-store'`. Do not use an `AbortController` alone: the ticket requires the counter, and an abort that loses the race is still an answer.

## 6. Pages the route-list test leaves out

The test walks `apps/board/src/app/**/page.tsx` and skips any path with a `[segment]`. Today that leaves `/`, `/backlog`, `/report`, `/spend`, `/setup/github-app`, `/setup/repository`, `/setup/wizard` and `/dev/waiting`. The last four are not in `PAGES`, for these reasons:

- `/setup/github-app` and `/setup/repository` are the target of *add a repository*, and the server chooses between them.
- `/setup/wizard` is a bookmark kept so that old links answer something (`setup/wizard/page.tsx:3-9`).
- `/dev/waiting` is a developer page.

Write them as an `EXCLUDED` map from path to reason in the test. The test also fails when an `EXCLUDED` path no longer exists, so the list cannot go stale in either direction. The *add a repository* entry has the label *add a repository* and comes after `PAGES` in the Pages group.

## The import test

Extend the pattern in `unit/not-set-up.test.tsx:71-80` in a new `unit/palette.test.tsx`:

- read `palette.tsx`;
- require `/^['"]use client['"]/m`;
- reject any non-`type` import of `@lingtai/` or of `@/lib/` other than `@/lib/search`;
- allow `./skeleton`;
- check that `skeleton.tsx` and `lib/search.ts` themselves have no value imports.

A blocked package can be reached through `skeleton.tsx` or `search.ts`, not only through `palette.tsx` directly. So the test must hold those two files to the same rule, not just `palette.tsx`.

## Where the rest goes

- **CSS**: in `globals.css`, beside the `.skeleton` rules, using the existing tokens.
  - `dialog.palette::backdrop` is a token tint, not black.
  - Under `@media (prefers-reduced-motion: reduce)`, the palette's transitions are `none`. Follow the existing rule at `globals.css:90`.
- **Mount**: `layout.tsx:69-71` becomes `<body>{children}<Palette /></body>`. `layout.tsx` stays a server component, which is allowed to import a client component.
- **What a unit test cannot check**: the `showModal` focus trap, focus coming back, and the result surviving `router.refresh()`. These are the person's line in Done when. `apps/release/integration/build.test.ts` is the only place a server import into the client graph would show up, and the import test above stands in for it inside the pass.

## Edges this decides

- **A route opened by somebody else, or a tab left open overnight:** nothing is cached between opens, and the counter drops stale answers. Nothing else is needed.
- **The daemon is down:** the index is whatever the projections say, and nothing marks it stale. The bar's health dot already says that, so the palette does not repeat it.
- **No ADR changes.** `doc/design/the-bar.md:42-43` already names the key.
