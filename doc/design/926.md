The ticket already describes the whole change, so this only says where the tests go and what has moved since the ticket was written.

- **Where the conduct tests go.** `packages/conductor/unit/conduct-a-whole-pass.test.ts`, which CLAUDE.md names, does not exist in this worktree. The nearest homes are:
  - `conduct-what-a-claim-leaves.test.ts` for the claim case: `TicketClaimed.body` is `===` the body the implementer's prompt was rendered from, and the fake `getIssue` is called once.
  - One of the `conduct-continuation-*.test.ts` files for the continuation case: the fake returns a different body on the second fetch, and `TicketContinued.body` carries the new one.

  Copy the fake `Tickets`/`getIssue` setup those files already use rather than writing a new harness.
- **Only one `issue.body` value.** `conduct.ts:2368` reads it, and both `continueTicket`/`claimTicket` (`:2377`–`:2387`) and `took.ticket.body` get that same value. `continueTicket`'s options are an inline type at `claim.ts:209`, not `ClaimOptions`, so add `body?: string` in both places.
- **Leave the key out when there is no body.** Build the payload with `...(options.body !== undefined ? { body: options.body } : {})`, not `body: options.body`. Two reasons:
  - A key set to `undefined` breaks the `toEqual` and "no `body` key" checks in Done when.
  - The `title ?? null` pattern next to it (`claim.ts:167`) is the wrong model here: 0109 §1 says an absent body means *not recorded*, which is a different fact from `null` or `''`.
- **The reducer test.** Fold one stream with `body` on the `TicketClaimed` and one without, and assert `toEqual` on the two states. The ticket reducer lives beside `claims.ts` in `packages/domain`. Putting the test in `packages/domain/unit` keeps it a unit test, because it needs no store.
- **`doc/events.json` is checked by a test.** `packages/domain/unit/events-json.test.ts` holds the file to the schemas, so the new field fails `pnpm test` until you run `pnpm events:generate` and commit the result. `apps/site/unit/events.test.tsx` and `apps/cli/unit/events.test.ts` also read the generated catalogue. Look at them if they go red after the regenerate, before you change any expectation.
- **No integration-only check.** Everything above is checked by `pnpm test` and `pnpm typecheck`.
