# Design: #885 — the record becomes one tab per subject

## The shared reduction is one `cache()`d function keyed by `taskId`

The ticket asks for one function that both `loadTask` and `loadAttemptTab` call. Make it `readAttempts = cache(async (taskId: string) => …)` in `src/lib/task.ts`. It does three things:

- **Reads:** `events.task`, `events.run` for every claim, and `spend.read`.
- **Reductions:** `reduceTicket`, `reduceAttempt` per claim, `presentAttempt`, `standingOf`, and the last attempt's `progressOf` with `planFor`'s plan. It also attaches each run's `costUsd`. That code moves as-is from `task.ts:1577-1601`, `:1614-1621`, `:1631`, `:1756-1760` and `:1770-1794`.
- **Returns:** `own`, `claims`, `streams`, `states`, `runs` (presented, with progress and cost), the folded `standing`, and `spendFold`.

Why the key is the string and not the arrays: React's `cache` memoizes on argument identity. A function handed `own` or `streams` would never hit, because each caller builds its own arrays. Caching the bare `eventStore.read` as well is harmless, but the string-keyed function is what shares the reduction too.

**The project comes from `parseTicketStream(taskId)`** (`task.ts:1357`), never from `loadTicket`. That is how `loadAttemptTab` gets `planFor`'s project without `github.issue`. It is also the same condition `loadTask` uses today: `ticket !== null` (`:1745`, `:1756`) holds exactly when `parseTicketStream` parsed, because `loadTicket` returns `null` only there (`:1357-1358`). An unregistered project still yields `undefined` from `planFor` (`:1474-1475`), just as before.

**Two things a test cannot show:**

1. Outside the `react-server` condition, `cache` is a passthrough. `node_modules/react/cjs/react.development.js:917-921` is `return function () { return fn.apply(null, arguments) }`. Under vitest, a test that counts `eventStore.read` across the layout and the child will see two calls. Don't write that test. *One read each* is checked in Jaeger, not by unit tests.
2. A cached promise runs inside the `measure` scope of whichever caller started it first (`timing.ts:27`, `AsyncLocalStorage`). On a full load, the `events.*` spans sit under whichever of `page /task` and `page /task tab` asked first, and the other span shows none. On a soft navigation only the child renders, so the reads are under `page /task tab`, which is what the ticket's Jaeger check looks at.

## What leaves `loadTask`

- **`history`** (`task.ts:988`, `:1826`). Nothing above the record reads it except `TaskBody`'s `unknown` check (`page.tsx`, *`task.history.length === 0 && …`*). Every stream in history is a claim on `own`, so an empty history is the same as `own.length === 0`. Replace the field with `events: number`, set to `own.length`. It serves the `unknown` check and the Ticket tab's event count.
- **`recipesFor`** (`:1757`). Its only reader is `RecipeGiven` (`page.tsx:342`), which moves into the attempt tab. `grep recipe src/app/standing.tsx` finds no reader of `run.recipe`. So `loadTask` stops calling it, and `loadAttemptTab` calls it with `[runs[n-1]]`. `unit/timing-load-task.test.ts:101` expects `'recipe.run'` in `loadTask`'s timings, so drop that entry there.

This is not *faster reads in `loadTask`* (out of scope). It removes a read that only the record consumed, which is the ticket's own rule: *another tab is read only when it is opened*.

`loadTask` keeps everything that adds to `standing`: triage, `fixWork`, split, mirror, `held`, `outgoing` and `queued` (`:1614-1735`). `loadAttemptTab` never sees those; it renders from the folded `standing`. The deciding attempt's reasoning needs only `standing.diagnosis` and `standing.saidBy`. Both come from `standingOf` (`task.ts:873`, `:884-887`), so no triage read is needed in the child.

## The default tab is the deciding attempt only while the ticket is blocked

`decidingOf` names an attempt even when nothing is being decided. When the named run has no refusal, it walks back through earlier attempts (`task.ts:756-760`). So a ticket whose attempt 1 refused and whose attempt 2 landed with no `outcome.detail` has `deciding.attempt === 1`. Read literally, the ticket's rule would open a landed ticket on its old failure. The same walk-back makes a running ticket open on an earlier refused attempt rather than the run in flight.

The rule is therefore:

- `standing.state === 'blocked' && standing.deciding !== null` → that attempt;
- otherwise the newest attempt;
- with no attempts, `ticket`.

Put it in one pure exported function, `defaultTabOf(standing, runs): TabKey`, with `TabKey = { attempt: number } | 'ticket'`. `page.tsx` uses it to pick what to render, and the layout uses it to tell the tab row. The *reasoning* block keeps its own condition: it shows when `diagnosis?.raw` is set (today's `page.tsx:689`), which is non-null only while blocked (`standingOf`, `:812-819`).

The Done-when test for the default tab uses a blocked ticket for the *deciding* case. Add a second case: a landed ticket with an earlier refused attempt opens on its newest attempt.

## The tab row decides its visible set on the client

**The layout does not re-render on a soft navigation**, which is the point of the split. So the layout cannot compute "the one open" from the URL: on a tab switch its HTML is the HTML from the first load. The set of attempts that get a tab of their own must be worked out where the selection is known.

The layout therefore passes a client component (`src/app/record-tab-row.tsx`, `"use client"`) the following:

- every attempt's tab fact: `attempt`, `outcome.state` and `billText(costUsd)`, a few bytes each;
- `deciding?.attempt`;
- the Ticket tab's event count;
- the default key from `defaultTabOf`;
- `taskId`.

That component reads `useSelectedLayoutSegments()`:

- `[]` → the default;
- `['attempt', n]` → attempt `n`;
- `['ticket']` → Ticket.

It then forms *three newest ∪ deciding ∪ selected* and puts the rest under *earlier attempts*. Each tab is `<Link scroll={false} href={/task/${encodeURIComponent(taskId)}/attempt/N}>` with `aria-current` on the selected one. Keep the set arithmetic in a pure helper in `lib/` so the Done-when test for more than three attempts is a plain function test.

## Where things live

- **`app/task/[id]/layout.tsx`:**
  - `measure(() => loadTask(id), { label: '/task' })`, then `notFound()` on null.
  - `<TimingMeta>`.
  - `<Follow>` around `TaskBody` and `children`.
  - Exports `TaskBody` (bar and `Standing`, as the ticket says) and the tab row.
  - The old-fragment redirector (a small client component) goes where `<Reveal />` is today (`page.tsx:822-828`).
- **`app/task/[id]/page.tsx`, `attempt/[n]/page.tsx`, `ticket/page.tsx`:** each is a thin `measure(…, { label: '/task tab' })` around its loader, then the view.
- **`src/app/attempt-tab.tsx` (new):** `AttemptTab`, `RecipeGiven` and `FromHeadSays` (moved from `page.tsx:342-506`), and the Prompt section. A route file then holds no component a test imports except `TaskBody`.
- **`src/app/ticket-tab.tsx` (new):** `Ticket` (moved from `page.tsx`) plus the ticket stream's `HistoryRow`s.
- **Tests:** `unit/task-page.test.tsx:27` imports `Record` and `RECORD_TABS`. Both are deleted, so rewrite those tests against `AttemptTab` and `TicketTab`.

The Events section is `groupHistory(streams[n-1], new Map([[runId, n]]))[0]?.lines`. That is `groupHistory` with one stream, so the run's branch is still derived for `toLine` (`task.ts:1319-1324`). The Ticket tab's events are `groupHistory(own, new Map())`.

**`attempt/[n]`** accepts `/^[1-9]\d*$/` with `n <= claims.length`; anything else is `notFound()`. Do that check before the `try`.

**A failed read in a child loader** goes through `try { … } catch { <p className="empty refusal">…</p> }` in the child page, never through the layout. The message names the read, never the error text: the rule in `timing.ts:20` and `:98-100` is that an error's message may carry a URL or a token.

## Smaller decisions

- **Run log:** render `<RunLog runId live={running} />` directly. Its own `useLatch(live, live)` (`run-log.tsx:281`) is the latch the ticket wants kept. Keep `followed` exactly as `page.tsx:708` computes it: `standing.state === 'running' && standing.runId === run.runId`.
- **Changes, repository-relative paths:** `AttemptState.worktree` is set from `RunStarted.worktree` (`packages/domain/src/attempt.ts:104`, `:394`; `events.ts:560`). In `presentAttempt`, strip `${worktree}/` from each `files[].path`. A path that is not under the worktree is shown as recorded rather than guessed at.
- **The pointers in `Standing`** (`standing.tsx:280`, `:1188`, `:1272`, `:1325`, `:1334`) are plain `<a href="#…">` today. Make them `<Link scroll={false}>` to the absolute tab path built from `Standing`'s existing `taskId` prop. `LastAttempt` and the deciding pointer (`:854`, `:861`) need `taskId` threaded through to reach them.
- **The old-fragment redirector:** `useEffect` reads `location.hash`. `#attempt-N` becomes `router.replace(…/attempt/N, { scroll: false })`, `#record-ticket` becomes `…/ticket`, and any other `#record-*` becomes `/task/<id>`. Run it once on mount; `hashchange` cannot happen on this page any more because nothing links to a fragment.
- **Two `<meta name="lingtai-timing">` tags** on a full load, one from each `measure`. Nothing in `src` reads them; the only reader is `unit/timing.test.tsx:25`, which renders the component alone. Leave both.
