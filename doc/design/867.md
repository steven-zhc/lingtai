# Design: #867, the control reducer gets a name, a version and a codec

## Where it goes

| File | What |
|---|---|
| `packages/domain/src/reducer.ts` (new) | `interface Reducer<S> { name; version; initial; reduceEvent(s, e); encode(s): string; decode(stored: unknown): S }` and `reduceAll(r, events)`. Nothing else. |
| `packages/domain/src/control-codec.ts` (new) | `encodeControl`, `decodeControl` and `ControlCodecError`. It imports only `type ControlState` from `control.ts`, so the runtime has no import cycle. |
| `packages/domain/src/control.ts` | `export const controlReducer: Reducer<ControlState>`, made from `emptyControl`, `reduceControlEvent` and the codec. `reduceControl` (`:319-321`) becomes `evaluateControl(reduceAll(controlReducer, events), now)`. |

| `packages/domain/test/histories.ts` | One new fixture history, appended at the end of the file (see below). |
| `packages/domain/unit/reducer-versions.json` (new) | `{ "control": { "1": "<sha256 hex>" } }`. It sits beside `histories.hashes.json`. |
| `packages/domain/unit/reducers.test.ts` (new) | The version-table test, the fixture-coverage test, and a check that each `REDUCERS` key equals that reducer's `.name`. |
| `packages/domain/unit/control-codec.test.ts` (new) | The round trip and the refusals. It copies `ticket-codec.test.ts:15-33`. |

## Decision 1: the version is hashed over one named fixture, not over every control history

Do not hash over all of `histories.control` plus `lateHistories.control`. `test/histories.ts:5-9` makes that fixture file append-only on purpose: *"a later reduce change that needs a new cell adds a new named history."* If the hash covered every control history, then any later ticket that adds a control cell would change the hash. It would then have to raise `controlReducer.version` even though the reducer had not changed. That is the wrong cost for every later ticket.

Add one history, `everyControlEvent`, which holds every type in `CONTROL_FOLD_TYPES` (`control.ts:32-40`) on one stream. The version table hashes that history and nothing else. The round-trip test still runs over every control history, as the ticket asks.

**Where the history is built.** `stamp` (`test/histories.ts:61-64`) hands out `seq` and `at` from module-level counters. A history built anywhere except after the last existing `stamp`/`bundle` call shifts every later locked `seq`. The last call today is `late_requeueOfRunWait`, just above `export const lateScenarios` (`:1306`).

`lateHistories` is declared at `:1098`, before that point. An object literal there cannot name a `const` that is defined later in the file (TDZ). So build the history at the end of the file and export it on its own:

```ts
export const reducerFixtures = { control: { everyControlEvent: late_everyControlEvent } }
```

The shape is kind → name → events, the same as `histories`.

Then add `reducerFixtures` to the `singles` spread in `unit/histories.test.ts:61-67`. That brings it under the existing `shape` test (`:120-128`: one stream, versions 1…n, before `NOW`) and under the hash lock (`:202-226`). Add its line to `histories.hashes.json`, and only add: the test prints the entry to paste (`:220-224`).

The effect is that the trap in the ticket's Watch-out is caught by two tests. Editing the fixture fails `histories.hashes.json` first, and the version table second. Check that the new slot is still before `NOW` (`:48`, `2026-09-01`). Each `stamp` takes a 6h slot from `2026-08-01`, and the `shape` test fails if the slot is not before `NOW`.

**What the history must contain** for the hash to mean anything:

- a `ConductorPaused` with `cause: 'day-ceiling'` and an ISO `until`;
- a person's `ConductorResumed`, so `ceilingWaivedUntil` becomes a non-null `Date` (`control.ts:216-219`);
- a second `ConductorPaused` with a non-null `until`;
- a `ConductorShutdownRequested`, then a `ConductorShutdownWithdrawn` whose `version` equals the request's own stream version, so the withdrawal takes effect (`:202-213`);
- another `ConductorShutdownRequested`;
- a `RunRequested`, a `ContinueRequested`, and two `DiscussionRequested`, one with `attempt: 1` and one with no `attempt` (`null`, `:267`).

The payload literals can follow `shutdownRequestedThenWithdrawn` (`:376-383`) and `requestsQueued` (`:385-397`).

## Decision 2: what the hash covers

The hash is `sha256` of the encodings of the state after each prefix of the fixture, from `initial` through the full history, joined with `\n`.

It is not the hash of the final state alone. `ConductorResumed` clears `paused`/`until`/`cause`/`shutdown` (`:220-233`), so in the final state a change to what `ConductorPaused` writes could be wiped out by a later resume and never reach the hash. Hashing every prefix is still *"the hash of the encoded result"* (0124 §3), taken at each step, so it does not contradict the ADR and needs no superseding file. Record this in the test's header comment.

**The fold is `reduceAll` only, with no `evaluateControl` and no `NOW`.** 0124 §2 says *"A reducer's state is a function of the events alone."* The clock belongs to whoever reads the state, so it is not part of what is versioned.

## Decision 3: the codec

Copy `ticket-codec.ts:14-160`:

- the schema is a `z.strictObject` for `ControlState` and each nested object;
- `IsoDate` (`:21`) for `until` and `ceilingWaivedUntil`;
- `PauseCause.nullable()` (`events.ts:1374`) for `cause`;
- `z.number().nullable()` for `timeoutMs` and `attempt`;
- the same parse-then-re-encode check, with `firstDifference` imported from `./ticket-codec.ts` as `run-codec.ts:28` does.

`ControlState` (`control.ts:64-129`) has no `bigint`, so `encodeControl` can be a plain `JSON.stringify`. Keep the bigint replacer anyway: it costs nothing, and it is what a future field would need. `ControlState` also has no optional fields, so "absent vs null" comes down to this: a missing key is a missing required key, and the strict schema refuses it. Do not use `.optional()` anywhere.

**`decode(stored: unknown)` takes one argument.** `decodeTicket(stored, projection, subject?)` (`ticket-codec.ts:132`) puts *"run `lingtai projection rebuild`"* in its message, because a projection stores that state. Nothing stores control state yet. A snapshot of another shape is void rather than rebuilt (0124 §3: *"A snapshot whose `(name, version)` is not the reducer's current one is never read"*), and that is child 3's to handle.

So the message names the reducer and the path, and does not name a command:

```
control: the stored state is not today's shape (shutdown.force: …)
```

Copy the `refuse` and path formatting from `:133-151`, with `control_state` as the root path name.

## The tests

**`unit/reducers.test.ts`.** It has a local map `FIXTURE = { control: reducerFixtures.control.everyControlEvent }`. For each entry of `REDUCERS`:

- **The fixture exists.** A registered reducer with no `FIXTURE` entry fails, naming it, so child 5 cannot register the ticket reducer without one.
- **The fixture covers the types.** It must contain every type in `COVERS[reducer.name]` (`test/histories.ts:1321-1361`). The failure lists the missing types by name.
  - The chain is already in place: `histories.test.ts:86-96` holds `COVERS.control` to `CONTROL_FOLD_TYPES` and to the `case` labels of `reduceControlEvent`. Reuse it; do not parse the source again.
  - If `COVERS` has no key for a reducer's name, that fails too, by name.
- **The hash matches the row.** If `versions[name][reducer.version]` is missing or differs from the built hash, the test fails with:

  > `control` (version 1): its result over its fixture changed. Raise `controlReducer.version`, add a row `"2": "<built hash>"` to reducer-versions.json, never edit an existing row (0124 §3).

  Print the built hash in that message, the way `histories.test.ts:220-224` prints its entries.
  - Also fail if the table has a row above the current version. That would mean the version was lowered.
  - Never write the JSON file from the test.

**`unit/control-codec.test.ts`.**

- Every prefix of every history in `histories.control`, `lateHistories.control` and `reducerFixtures.control` must round-trip with `toStrictEqual`, as a string and as `JSON.parse` of it, starting from `emptyControl`.
- Refusals:
  - not JSON;
  - a missing key (`shutdown`);
  - an extra key at the root and one inside `requested.0`;
  - `until: "yesterday"`;
  - `cause: "nobody"`;
  - `discussions.0.attempt` absent rather than `null`.

  Each asserts `ControlCodecError` and that the field's path appears in the message.

## Watch out

- **Wrap the step reducer when folding.** `Array.prototype.reduce` passes `(acc, e, index, array)`. Write `reduceAll` as `events.reduce((s, e) => r.reduceEvent(s, e), r.initial)` so that a later `reduceEvent` with an optional third parameter cannot quietly receive the index.
- **The interface uses method-shorthand declarations.** `reduceEvent(s: S, e: Envelope): S`, `decode(stored: unknown): S`. That keeps `Reducer<ControlState>` assignable without variance errors. Avoid a `Reducer<unknown>` registry type: `REDUCERS` stays `as const` and the test iterates `Object.entries`.
- **`reduceControlEvent` and `emptyControl` stay exported, under the same names.** They have callers outside `reduceControl`, so check them with a grep before you touch anything. `controlReducer` is added beside them and does not replace them.
- **Lint.** `pnpm fmt:check` and `pnpm lint` run at `build:`, so give new JSON the same formatting as `histories.hashes.json`. `unit/effect-ratchet.test.ts` holds a baseline (`effect-ratchet.baseline.json`). New plain-TS modules should leave it untouched, but run it.

Every check here is a unit test; nothing in this change needs `pnpm test:integration`.
