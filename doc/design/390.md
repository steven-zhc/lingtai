## Design note for #390, attempt 4: build on `e2afdff`

The triage already gives the shape. Reset and clean before the command and again when it fails. Exclude `plantAt` from both the clean and the add. Keep no baseline. Branch `agent/390-attempt-3` at `e2afdff` already implements all of that. This note only adds two facts the triage doesn't state.

### 1. Bring `e2afdff` onto today's `HEAD` with a merge

The two have a common ancestor at `a3e5cf0`, and `HEAD` (`bf1e3f2e`) is 35 commits ahead of it. Those 35 commits touch only one file that `e2afdff` also touches: `doc/plugins/run.md`, a two-line change on `main`.

Among the code `e2afdff` changes, `main` touched only `packages/recipe/src/`. The files changed there are `answers.ts`, `emit.ts`, `index.ts`, `presets.ts` and `write.ts`, and none of them is `recipe.ts`. Nothing on `main` touched `packages/actions/` or `packages/conductor/src/` (`git diff --stat a3e5cf0 HEAD` over those paths).

So `git merge e2afdff` should conflict in `doc/plugins/run.md` at most. Resolve that file by keeping `main`'s two lines as well as the new `implement` row. Don't redo the wiring: `runPlugin.at`, `from-recipe.ts`, `conduct.ts`, `pass.ts` and the step-matrix cell on that branch are the parts the triage endorses.

`main`'s change to `presets.ts`, `emit.ts` and the new `answers.ts` (#398, #399) carries the setup's preset recipes. The 0104 §14 note in `19e54e80` points the same way: the preset's check sits at `build`. Do not add a `run` at `implement` to any preset. That belongs in the operator's own recipe, after the restart (*After it lands*), not in what `lingtai add` writes.

### 2. The typecheck failure is a single `as const`

`packages/actions/unit/from-recipe.test.ts` on `e2afdff`, in the `describe` that starts *"a run: at implement needs the git port"*, has this line:

```ts
const action = { name: 'format', run: 'pnpm fmt', timeout: '5m', env: [] as const }
```

`as const` makes `env` `readonly []`, and the action type wants `string[]`. That one declaration is behind all three TS2322 errors the triage lists, because the three `actionsFromRecipe('implement', [action], …)` calls each pass `action`.

The fix is to change the declaration to `env: [] as string[]`, or to type `action` as the recipe's action type. Don't change the action type to `readonly string[]` to get around it: that widens a public type in `packages/actions/src/action.ts` for a test's convenience.

### Checks

Run `pnpm typecheck` after the merge, not before. Some types in `packages/recipe` changed under `e2afdff`'s `recipe.ts` edits, and only `tsc` will show whether the merged tree still agrees. Then run `pnpm fmt:check`, `pnpm lint`, `pnpm test` and `HOME=/nonexistent pnpm test`, and commit as the work stands.

Nothing here needs `pnpm test:integration`. The commit, clean and add go through the `keptRun` port that `from-recipe.test.ts` fakes. `kept-run-action.test.ts` covers the clean-and-commit behaviour against that port. That is the unit-level claim in place of a real `git` run, so say so in the commit body.
