## The publish is uninterruptible where it is defined, not where it is called

It runs from two places:

- the ending, `const notPushed = outcome === 'landed' ? null : yield* Effect.promise(publishWhatIsCommitted)` (`:4755`);
- the scope's finalizer, `Effect.addFinalizer(() => (didLand ? Effect.void : Effect.promise(publishWhatIsCommitted)))` (`:2483`).

The comment above `:4755` says the finalizer *"is the only thing that covers a crash or an interruption between here and the end of the scope, and on the paths that reach this line it finds the head already published and writes the `already-published` row"*.

That second run is only correct if the first one finished its bookkeeping. The push succeeds at the `gitAsked(['push', …])` around `:2376`, and `published = branchHead` and `armPublished = head` are only assigned after it, around `:2438-2441`. An interruption that lands between the push and those assignments leaves `published` and `armPublished` stale. The finalizer would then miss the `branchHead === published && head === armPublished` short-circuit (`:2339`) and push a second time. Today `Effect.promise` hides this, because a promise cannot be cut. Once the body is a chain of `yield*`, each `yield*` is a point where the interruption can land.

So define it as a value:

```ts
const publishWhatIsCommitted: Effect.Effect<string | null> = Effect.uninterruptible(Effect.gen(function* () { … }))
```

Both call sites then get the protection, and a later caller cannot forget it. Finalizers already run uninterruptibly, so the wrap only matters for `:4755`, but put it in one place. The finalizer becomes `() => (didLand ? Effect.void : publishWhatIsCommitted)`. `didLand` must still be read inside the thunk, as it is now.

## The `try`/`catch` becomes `Effect.catchDefect`, with `headRead` per run

Today's `catch (defect)` (`:2468-2480`) is where a defect after the head was read keeps that head at `keptRef`. It is guarded by `headRead !== cutBase && headRead !== armPublished` (#421).

Write it as an outer `Effect.gen`:

1. Declare `let headRead: string | null = null` in the outer gen, so each run of the Effect gets a fresh one. A module-level `let` would carry over from the ending's run into the finalizer's run.
2. `yield*` the inner body piped through `Effect.catchDefect((defect) => …)`. The handler runs the same `keepHead`, `runLog.note` and `noteRefs('refused', null, why)` and returns `why`.

Use `catchDefect` and not `catchCause`. A cause also carries interruption, and an interruption must never become a `refused` row. The repository already uses this idiom at `:1045`, `:3000` and `:4349` (Effect is 4.1.2).

The `worktree === null` check (`:2257`) stays inside the gen, so it is read when the Effect runs, not when it is built.

## The interruption test

Use `a-claim-is-not-split-by-an-interrupt.test.ts` as the template:

- fork the pass;
- `Effect.forkChild(Fiber.interrupt(pass))` once the fake push has been entered;
- complete the `Deferred`;
- `Fiber.join` the interrupter.

Pick an ending that reaches `:4755` rather than a landing; a fixture from `conduct-what-a-claim-leaves.test.ts` that ends at a person will do. The fake's `push origin …agent/<n>` returns `Deferred.await(gate)` for the first call only.

Assert three things:

- exactly one `push` of that head was recorded;
- the `RunRefsPublished` rows read `published` and then `already-published`, the finalizer's row;
- no `refused` row.

If you remove the outer `uninterruptible`, the test should fail with a second push or a missing `already-published` row. Check that once by hand and say in the test's doc comment that you did.
