# Design: #992, `pause` and `resume` take a project

## Where it goes

Make one new module, `apps/cli/src/project-pause.ts`. It holds three Effects, `pauseProjects`, `resumeProjects` and `refuseIfLocked`. Each one takes a store and a `log` the way `pauseCommand` does (`apps/cli/src/pause.ts:17-20`: *"The suite passes a memory store and a collector"*). The tests drive these Effects directly against `createMemoryEventStore()`. The `controlCommand` stubs in `daemon-cli.test.ts` cannot see the appends.

`controlCommand` keeps its signature for `shutdown`. Its `pause` and `resume` branches (`apps/cli/src/daemon.ts:792-806`) become two lines that run the new Effects with `runEffect` from `first-project.ts:1256`. That file's comment says *"`runPromiseWith` is the run the ratchet does not count"*. Do not use `Effect.runPromise`, and do not add a new `async function`. `apps/cli` sits at `"async": 413` (`packages/domain/unit/effect-ratchet.baseline.json:2`). The project appenders are already Effects (`packages/daemon/src/control.ts:693,702`). The existing promise APIs (`loadProjects`, `readControl`, `resumeConductor`, `requestRun`) are wrapped in `Effect.tryPromise` at the call site and are not rewritten.

`pauseCommand` and `pause.ts` lose their only caller. `RUN_UNDER_A_PAUSE` is still used by `doctor.ts:1225` and `run.ts`. Delete `pause.ts` only together with the part of `run-pause.test.ts` that drives it. Keep the half of that test that pins `run`'s own refusal. `pauseConductor` stays, as the ticket says.

## Validate the name before appending

`pauseProject` must never be called on a name that is not registered. If `prj-x` holds no `ProjectRegistered`-style state, then `state.project === null`. `pauseTransition` returns null (`packages/domain/src/locks.ts:29`), and `pauseProject`'s answer callback then dereferences `state.paused!.at` (`packages/daemon/src/control.ts:698`). That throws a TypeError rather than answering. So `loadProjects()` (`packages/conductor/src/projects.ts:81`) is read first, once, and the name is checked against `p.project` (`ProjectState.project: string | null`). This gives three things:

- the unknown-name refusal, with exit 2
- the list printed with that refusal
- the iteration for the bare form

`loadProjects` returns folded `ProjectState`s, `paused` included. Even so, the bare form still calls the appender for every project and lets the appender answer. The appender re-reads at head, so its answer is the one that is true after a race. Do not pre-filter on the `paused` value that was loaded. One exception: bare `resume` should skip projects that `loadProjects` reported unpaused. That way it prints nothing for them, and "nothing to do" can be detected.

## The output, per answer

- `pauseProject` returns `{kind:'appended'}` or `{kind:'already', since, by}` (`control.ts:658`). `already` carries the standing pause's `by` and `since` from the head the appender read, so the line names one pause and not two. Do not take `by` from the earlier project list: a resume and a new pause between the two reads would name the old actor.
- Print one trailing sentence after a pause of any kind: *an attempt already in flight finishes; nothing new starts*. This replaces `renderVerdict('paused', …)`. Keep the `renderVerdict` framing only if it fits a multi-line body; one plain line per project is fine.

## Bare `resume` lifts the conductor-wide pause after the projects

Run the order as stated in the ticket: projects first, then `readControl()`. If `paused || shutdown !== null`, call `resumeConductor(by, store, head)`.

`by` must stay `human:$USER`. The ceiling waiver depends on it: `state.paused && state.cause === 'day-ceiling' && str('by') !== 'lingtai'` (`packages/domain/src/control.ts:242`).

Read the control stream and append `ConductorResumed` at the head that read was taken at (`resumeConductor(by, store, head)`); a `ConcurrencyError` means a pause landed in between, so read again (bounded). Print the lifted lines, including the waiver when `cause === 'day-ceiling'`, from the read the append was made against, and name `until` from it: that is the value `ceilingWaivedUntil` takes (`:243`). A read taken before a head-less append could describe a different pause than the one cleared.

`resume <project>`, with a name, never touches the control stream.

## `lingtai now`: ask the guard, not `locksOn`

Use `makeGuard({ store }).locksFor(project)` and then `lockSentence` (`packages/daemon/src/guard.ts:40-46`, `packages/domain/src/locks.ts:22`). Do not hand-roll a `prj-` read and a `locksOn` call. The guard's own comment says:

> *"the day ceiling and the account limit arrive later as checks run inside `locksFor`"*

So `now` built on the guard refuses on those locks too when they land, with no edit here. Built on `locksOn`, it silently would not.

- Do not use `lockedBy`. It turns a failed read into a sentence (`guard.ts:57-66`), and `now` must say *read failed* rather than *locked*. Call `locksFor` and branch: error → exit 1 with `could not read whether <p> is paused — <message>`; non-empty → exit 1 with `lockSentence(...) + ' — lingtai resume <p> first'`.
- `lockSentence` prints `since` as ISO (`locks.ts:24`). Accept that rather than adding a local-time formatter.
- `nowVerdict` (`apps/cli/src/now.ts:13`) is `async` and returns `Answered`. Changing its body adds no new `async`. Run the guard Effect inside it with `runEffect`.
- Add a `guard` parameter defaulting to `makeGuard({ store: eventStore })`, beside the existing `request` parameter, so the unit test injects a memory-store guard. Export `makeGuard` from `@lingtai/daemon` if the index does not already export it.

## `doctor`

Add a separate row, not a clause on `daemon: liveness`. Name it `daemon: paused projects` so `areaOf` files it under *Daemon* (`doctor.ts:3398`). Give it status `info` when anything is paused (a status in `STATUS_ORDER` at `:3413`). With none paused, return no row at all (`results.push(...rows)` with an empty array). `info` takes no part in the fail/warn tiering at `:3502`, so the exit code is unchanged.

The input is `loadProjects()`'s `paused` field, so there is no extra read. A failed read gives one `warn` row saying the project list could not be read. That is the ticket's *says which read failed*; doctor reports and does not exit 1.

The step has to be added on **both** paths: the `reach` path at `:3223` and the default path at `:3268`. Add a `projects` member to `DoctorReach` (`:1129`) beside `pause`, so the suite hands in a memory store's projects.

## Tests (unit, memory store)

`daemon-cli.test.ts:177-199` keeps only the argument-parsing claims:

- `pause` and `resume` take an optional positional
- `--reason` is gone
- the empty-reason exit 2 is gone

The behaviour moves to a new `apps/cli/unit/project-pause.test.ts` that drives the Effects over `createMemoryEventStore()`. It asserts on `store.read(projectStream(p))` and the `control` stream, which covers every *Done when* except doctor and `now`. Those two get their own cases through the injected `projects` reach and the injected guard. Plant the registered projects through whatever `loadProjects` accepts, or pass a `load` parameter as `passRefusals` does (`doctor.ts:1474`: `load: typeof loadProjects = loadProjects`).

None of this needs `pnpm test:integration`. Then run `pnpm docs:cli` and commit `doc/cli.json` and `doc/cli.md`.
