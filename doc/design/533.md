# Design note — #533

Add a development-only route under `apps/board/src/app/__visual/waiting/`, with a gallery index and stable URLs for each scenario. Render the exported `Card` and `TaskBody` inside the board’s normal layout so the comparison uses the production components, stylesheet and local fonts. The existing component boundaries are intentional: the card comment says it carries “the rail and one cause line” (`apps/board/src/app/page.tsx:41`), while `TaskBody` is “apart from the route so a test can render the whole arrangement without a database” (`apps/board/src/app/task/[id]/page.tsx:741`). The preview route should call neither `loadBoard` nor `loadTask`.

Build the preview data from `apps/board/test/waits.ts`, whose header says its events are shared by the card and task-page pins (`apps/board/test/waits.ts:1`). Fold those events into the card and detail views as the existing tests do, then add fixed triage facts for the named scenarios. Keep the current wait ID and triage attempt paired: the event contract says a `WaitTriaged` result finishes the matching `TriageStarted` attempt (`packages/domain/src/events.ts:1882`). Supply fixed ticket text, timestamps and a render clock; any clock seam added to the components should default to live time outside the preview. Use the ADR’s status and resolution rules rather than hand-picking visible buttons: “Triage is not an input” to `allowedResolutions` (`doc/decisions/0118-a-hold-explains-itself.md:244`).

Make the route read-only at its boundary. Keep previewed cards and controls visually intact but inert, with separate gallery links for switching scenarios; a preview click must not reach a task route or server action. Return 404 outside development, and add no link from normal navigation. This preserves the ADR’s distinction that triage “advises; it never moves the item” (`doc/decisions/0118-a-hold-explains-itself.md:12`).

Document `pnpm --filter @lingtai/board dev`, the gallery URL, each scenario URL, and screenshot viewports of **1200px desktop** for task pages, **440px** for the board column, and **390px narrow**. The references specify 1200px for the advised page (`doc/decisions/0118/Hold.dc.html:25`) and 440px for the column (`doc/decisions/0118/Main.dc.html:19`). Ask reviewers to link captured before/after images in later visual tickets; markup assertions can check fixture wiring, while rendered screenshots establish color and layout. Run the four ticket gates, including `HOME=/nonexistent pnpm test`; the integration suite is outside this pass.
