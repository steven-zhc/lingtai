## Decision 1: keep the thrown value itself as the failure

`convergeIssues` builds its failure record from the raw thrown value:

- `sweepFailure(err, gone)` at `converge.ts:524`;
- `(err as Error).message` at `:526`.

`currency.ts` likewise puts `(err as Error).message` into `unknown` (`:157`, `:248`).

So every `Effect.tryPromise` in `converge.ts` uses `catch: (e) => e`, the shape `reconcile.ts:121`'s `attempt` uses. It must not wrap the error, or the `IssueUpdateFailed.error` text changes. The recorded error is `IssueUpdateFailed.data.error`, and that field would show the difference in the log.

`gitEffect` needs no translation. `RepoFailed.message` is `detail` (`packages/repo/src/git.ts:95-97`, *"So a face's rejection reads as `execFile`'s own error did"*), and `detail` is `err.message` from the `execFile` callback (`git.ts:147`). Catching `RepoFailed` and reading `.message` gives the same `unknown` string as today.

`gone` stays a mutable array declared before the uninterruptible step, and is pushed to after each `deleteRef` succeeds. The failure branch reads it, as now.

## Decision 2: `clientFor` keeps converge's own default

Today's default is `createGitHubClient({ auth: githubClientAuth(), owner: p.owner!, repo: p.project! })` (`converge.ts:153-155`), gated by the injected `hasAuth` (`:158`, `:177`).

`clientForSeam(undefined)` would substitute `githubClientForEffect`, which:

- re-checks `hasGitHubAuth()` against the real process and ignores `options.hasAuth` (`filter.ts:266`);
- fails on a missing owner.

That is a behaviour change, however small, in a function the ticket says must not change.

So `clientsForProjectsEffect` takes `clientFor?: ClientForEffect`, defaulting to `createGitHubClient` lifted with `Effect.tryPromise`. The face lifts a promise `clientFor` once, the same way `clientForSeam` does for an injected one. Lifting the injected one with `clientForSeam(options.clientFor)` itself is fine; only the `undefined` arm must stay converge's default. `recipeFor` defaults to `currentRecipeEffect` and `ticketsOf` to `ticketsForEffect`, so `recipeForSeam` and `ticketsOfSeam` are exactly right for those two.

The three swallows in `clientsForProjects` (`:163`, `:178`, `:185`) each become `Effect.catchCause` with interrupts passed through:

- the two that today `push` to `unresolved` take the message as `messageOf` does (`reconcile.ts:124`, `Cause.squash`), so a defect also lands in `unresolved`, as the `try` does today;
- the `clientFor` one becomes `continue`, meaning that project is skipped.

`clients-for-projects.test.ts` pins each of these.

## Decision 3: `withDaemonStore` is lifted with `Effect.promise`, and `convergeIssuesEffect` cannot fail

The store open at `converge.ts:320` is the only read in converge that today fails out of `convergeIssues`. It reaches reconcile through `Effect.promise` (`reconcile.ts:801`), so in `reconcileEffect` it is a **defect**.

If converge lifted it with `attempt`, the same fault would arrive as a failure in `reconcileEffect`'s error channel instead. Nothing in the ticket asks for that change.

So `findIssueDriftEffect` lifts `withDaemonStore(…, candidates)` with `Effect.promise`, with a comment saying *lifted until DAEMON-7a*. Both `findIssueDriftEffect` and `convergeIssuesEffect` are then `Effect<…, never>`. Every other read in converge is caught to a value, and `loadProjectsEffect` is already `never`. `reconcile.ts:800` becomes a plain `yield* convergeIssuesEffect({…})`, and the error type of `reconcileEffect` does not move.

`candidates` stays the function `withDaemonStore` is handed, so it remains a function returning a promise. The `async` is dropped by making it `store.streams(…).then((s) => new Set(s))`, or by moving the `Set` construction out to the caller. Either way it is no longer counted. This lift goes away with the others in DAEMON-7a.

## The write and its record

`convergeIssuesEffect` handles each divergence in one `Effect.uninterruptible` step:

1. the write, through `Effect.tryPromise`;
2. on success, `record('IssueUpdated')`, the push to `converged` and the `paint.pass` log line;
3. on failure, `record('IssueUpdateFailed', sweepFailure(err, gone))` and the `paint.fail` log line.

The failure branch uses `Effect.catch` on the write's failure, not `catchCause`. Today a write that throws is caught by the `try` at `:495`, and through `tryPromise` that is a failure, not a defect. The step never fails outward.

**The `comment` skip and the missing-client skip** (`:489-491`) stay outside the step.

**`record`** wraps its read and append in `Effect.tryPromise`, then applies `Effect.catchCause`: an interrupt-only cause is passed through, and anything else becomes `Effect.void`. Inside an uninterruptible region an interrupt cannot arrive, so in practice everything is swallowed, which is what the `try` at `:540` does.

`record` uses `Effect.tryPromise`, not `Effect.promise`. With `Effect.promise`, a rejected append would become a defect, and `Effect.catch` would let it through. The catch must be on the cause, because a test will hand in an `append` that throws synchronously, or a store method that dies.

## Interruption: how the unit test can complete

`Effect.tryPromise` inside an uninterruptible region does not abort its promise. The fiber waits for `closeIssue` to settle, then appends, then ends interrupted.

Write the test with no timer:

1. Make two `Deferred`s:
   - `called`, which the fake `closeIssue` completes when it is entered;
   - `release`, which the fake `closeIssue` awaits before it resolves.
2. Fork `convergeIssuesEffect` and `Deferred.await(called)`.
3. **Fork** `Fiber.interrupt(fiber)`. `Fiber.interrupt` waits for the fiber to end, so calling it inline deadlocks the test.
4. `Deferred.succeed(release)`, then join the interrupter.
5. Assert that the converge fiber's `Exit` is interrupted, and that the store holds `IssueUpdated` for that ticket. `createMemoryEventStore()` from `@lingtai/event-store/memory` is enough.

Use one divergence with `change: 'closed'`. Get it from a seeded ticket stream whose last `closed` outcome is `failed`, as `converge-refs.test.ts` seeds the `refs` case, or hand the fake store's stream in directly.

## Edges this note decides beyond the ticket

- **The store will not open** (`withDaemonStore` rejects): this is a defect out of `convergeIssuesEffect`, exactly as through today's `Effect.promise` at `reconcile.ts:801` (decision 3).
- **A defect from a GitHub write** (a fake that throws synchronously, for example): `Effect.tryPromise` turns a synchronous throw from `try` into a failure, so it becomes `IssueUpdateFailed`, as the `try` at `:495` does today.
- **A defect from `recipeFor` or `ownerlessClient`:** the project goes to `unresolved` with `Cause.squash`'s message, the same as a thrown `Error` today.
- **No ADR is contradicted.** 0101 §6 and §7 cover the faces, and 0042 covers *unknown* being a refusal.
