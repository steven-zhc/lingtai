# #779: the queued page's panel

## Where it goes

There are four seams. Each one is local, and none of them is shared with a state other than queued.

1. **`lib/queued.ts`: a new `runNowCaption(view): string | null`** next to `holding` (`lib/queued.ts:345`). It uses the same three tests in the same order (`notOffered` → `paused` → `runnableAt` → null) and returns the ticket's three phrases. Don't put the phrases inline in `standing.tsx`. The doc comment above `holding` says the precedence is *"the one a person acts on, most permanent first"* (`queued.ts:331`). A second copy of that ladder in the page could drift, and keeping it beside `holding` means `unit/queued.test.ts` can pin both together. The caption takes no `now`. `skips the backoff` names no time, so the old reason to pass the clock is gone. `standing.tsx:1038` passes `holding={runNowCaption(queued)}` to `RunNow`. The prop name and `decide.tsx:827` stay as they are. Renaming the prop is not in scope.
   - Under `queued.problem`, the three hold fields are still populated (`runnableAt`, `paused` survive beside `problem`), but the hold is unknown, so the function checks `problem` first and returns null: no caption is drawn, which is what the ticket's edge asks for. A unit case pins it.

2. **The so-what line, at the call site only.** The ticket's lines have drifted by about 5 since it was written. The variable is now `const soWhatText = soWhat(standing)` at `standing.tsx:682`, and it is drawn at `:871`. Make it `standing.state === 'queued' && stopped !== null ? null : soWhat(standing)`. `soWhat` (`:1117`) and `whoWaits` (`lib/task.ts:766-787`) are not touched. `stopped` is null when `queued.problem` is set, so `who`'s sentence still draws there. That is today's behaviour, and the ticket does not ask for it to change.
   - **The drawing is overruled here, on purpose.** `doc/design/queued-page.html` draws a so-what (*"Nothing is asked of you. When the backoff ends…"*) and the caption *"skips the **9m** backoff"*. The ticket's *Fix* and *What to build* say no so-what under a hold, and `skips the backoff` with no time in it. Follow the ticket. The prototype is labelled *"Prototype, not the page."*

3. **`Deciding.evidence`, in `lib/task.ts`.** Make it a **required** `evidence: string | null` on the interface (`task.ts:376-383`), not an optional field. A required field makes `tsc` find every literal that builds a `Deciding`:
   - `unit/standing.test.tsx:642`
   - `unit/standing.test.tsx:1038`
   - the `deciding: null` fixtures need nothing.

   Set it in each of `refusalOn`'s branches as the ticket says: `never.evidence`, `unfinished.evidence`, `question.evidence` and `refused.evidence`, each verbatim and never passed through `oneLine`. On the failed branch, when `refused.evidence` is null, empty or whitespace-only (the same cases `line` falls back on), use `run.outcome.detail`. On the last branch (`:732-734`), use `run.outcome.detail`. Every `line:` expression stays exactly as written; the unit cases assert this.

   **Add one more field: `fromStep: boolean`.** It is true on the four step branches and false on the outcome branch. The label needs it. On the outcome branch, `source` is `run.outcome.state` (`task.ts:734`): one of `failed | finished | released | running | claimed` (`task.ts:1441-1448`). `stopped at released` is not a sentence. Sniffing `source` for `' / '` would break the next time a step name changes. With the field, the label reads `· stopped at <source>` when `fromStep` is true and `· <source>` when it is false (`the last pass, attempt 2 · released`). Like `evidence`, `fromStep` is an added field, so the ticket's *Watch out* still holds: `line` and `oneLine` do not move, and the blocked page's `Reason` fallback (`standing.tsx:1259-1271`) reads only `source`, `line` and `attempt`.

4. **The panel: a new `LastPass` component used only on queued pages. Do not add a branch inside `Reason`.** On a queued ticket `diagnosis` is always null, because `words` is computed only when `blocked` (`task.ts:824-831`). So today a queued page always goes through `Reason`'s `!diagnosed` branch (`standing.tsx:1258`), and running, approved and landed pages go through that same branch. A `state === 'queued'` test inside `Reason` would put the queued wording in front of three other pages' tests. Branch at the call site instead (`standing.tsx:852`): queued renders `<LastPass deciding={standing.deciding} last={standing.attempts} />`, and everything else renders `Reason` unchanged.
   - `LastPass` renders nothing when `deciding` is null, which is the same as `Reason` does today.
   - When `evidence?.trim()` is non-empty: `<RawEvidence raw={evidence} said={label} />`. `RawEvidence`'s summary slot is `said ?? 'what refused, verbatim'` (`standing.tsx:1309`), so the label goes into the slot the attribution already uses. The line count comes free, and `.sraw` handles length.
   - Otherwise, show the existing `sevidence` paragraph with `sstep` = label and `sline` = `deciding.line`. A blank box is never drawn.
   - Keep `↓`, the pointer to `#attempt-${deciding.attempt}`, in both cases.

## The label when the refusal is not the last attempt's

`decidingOf` walks back through earlier attempts (`task.ts:753-765`). Its comment cites *"ticket-lingtai-89's second attempt finished with exit 0 and no commits"*, which is the case where the refusal on screen is attempt 1's. Writing *the last pass, attempt 1* under a bar that says attempt 2 would be false. So:

- When `deciding.attempt === standing.attempts`, the label is `the last pass, attempt N · …`.
- When it is lower, the label is `attempt N · …` with "the last pass" dropped, so it never claims to be the last.

This follows the ticket's edge (*"names the attempt it actually came from"*) to its conclusion; it is not a second reading of the ticket.

## The bar

In `Coords` (`standing.tsx:1182-1186`), the word becomes `standing.state === 'queued' ? 'after' : 'from'`. Nothing else in that span changes.

## Tests

Everything here is unit-level and nothing needs `pnpm test:integration`.

- **Queued cases** are in `unit/queued.detail.test.tsx`, `unit/standing.test.tsx` and `unit/task-page.test.tsx`. `unit/__snapshots__/task-page.test.tsx.snap` contains two of the strings that change (`from attempt` and *waiting for a conductor*). Read the snapshot diff before updating it: only queued output may move.
- **The once-only check** is a `split(sentence).length - 1 === 1` over the rendered HTML of a backing-off fixture. Rendering the panel or the moves row on its own would hide the duplicate.
- **`refusalOn` is not exported.** Test it through `standingOf(...).deciding`, which is how the existing fold tests reach it.
- **The blocked-page cases** in `standing.test.tsx` must pass with no edits apart from adding `evidence` and `fromStep` to the two `deciding` literals.
