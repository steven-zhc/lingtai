## Design: one rule for the sha an Approve is about

### Where it goes

Add `approvalSha` to `packages/domain/src/attempt.ts`, near `AttemptLifecycle` (`:68`). It takes `Pick<…, 'lifecycle' | 'headSha'>` of the attempt state, the interface that holds `headSha: string | null` at `:113`. `packages/domain/src/index.ts:17` already re-exports `./attempt.ts`, so the barrel needs no edit. Put its unit test in `packages/domain/unit/`, next to the other attempt-reducer tests.

It has two callers:

- `packages/conductor/src/approve.ts:241-242`. Replace the inline ternary. The doc comment above it (`:235-240`) already states the rule, so move that comment onto `approvalSha` and leave a one-line pointer here.
- `apps/board/src/lib/task.ts:1176`, in `presentAttempt`. Leave `:883` alone: `blocked ? (run?.awaitingSha ?? null) : null` is still the reason a run that is still running offers nothing. The test *asks nothing of anybody while a run is still in flight* (`apps/board/unit/standing.test.tsx:619-627`) pins it.

### Empty strings

The two copies don't agree today. The board writes `state.lifecycle.onSha || null` (`task.ts:1176`), so an empty `onSha` becomes null. The conductor takes `run.lifecycle.onSha` as it is (`approve.ts:242`), so an empty string passes its `onSha === null` check and goes on to be approved.

Make the shared rule:

- **`awaiting-approval`:** `onSha || null`.
- **Otherwise:** `headSha || null`.

An `awaiting-approval` whose `onSha` is empty does **not** fall back to `headSha`. That signoff is asking about a commit nobody recorded, and approving the head instead would be approving something different from what was asked. With null, the conductor refuses with `not-awaiting-approval` and the board prints *nothing to approve*.

This changes the conductor only for an empty sha. `onSha` is typed `string` (`attempt.ts:74`) and comes from `action.onSha` (`:524`), so an empty one is degenerate either way. Give it its own case in the domain test.

### The comments that would become false

Two doc comments describe the old rule. Rewrite both, or the next reader will put the old rule back:

- **`AttemptView.awaitingSha` (`task.ts:308-316`).** It says *"The sha an open approval is asking about, and null when nothing is asked… The same rule `task_view.awaiting_sha` reduces"*. After this change it is no longer the same rule as `task_view`, on purpose: the ticket's Watch out row says why `task_view` keeps its own (`packages/projector/src/task-view.ts:911-925`). Keep the #92 paragraph, since the signoff's sha still beats the head when there is a signoff. Replace the last sentence: this field is now *the sha `lingtai approve` would approve* (`approve.ts`), which `task_view.awaiting_sha` deliberately is not.
- **The `(D3)` line at `task.ts:1175`.** *"Offered only while the lifecycle still awaits it"* is no longer true. Replace it.

`StandingView.awaitingSha`'s comment (`task.ts:504-508`) still holds: *"what Approve must send, and null when there is nothing Approve could do (#84)"*. Leave it.

### Existing tests that stay as they are

- ***has nothing to approve once the approval was spent*** (`standing.test.tsx:607-617`). Its fixture has no `RunProducedDiff`, so `headSha` stays null and it still passes. Don't add a head commit to it to "make it realistic". A real spent approval followed by a conflict is a `MergeRefused` wait, which offers `Approve` (`wait.ts`), and approving `headSha` is then what the conductor already does. The test now covers the *nothing was produced* case, and that is correct.
- ***sends the sha the run is asking about, not the one it produced*** (`:592-603`) pins the signoff side. It must stay green unchanged.

### The rendering test

`standingOf` and `render` both exist in `standing.test.tsx`. Use the `describe('the move the block ends in')` block (`:579`) as the pattern:

1. Build a run with `presentAttemptEvents` from a `RunProducedDiff` carrying `headSha: SHA`.
2. Block it with a `WaitStarted` whose reason is `{ _tag: 'FixerDisagrees', run: { runId }, said: null }` (the same shape as `:921`).
3. Assert `standing.awaitingSha === SHA`.
4. Render it and assert two things: the output contains the `Decide` form's `onSha`, and it does not contain `nothing to approve`.

All of this is unit level. No integration test is needed.
