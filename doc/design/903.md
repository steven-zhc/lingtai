## Shape for #903

The change is `projects.tsx` and a rule block in `globals.css` beside `.filter` (`globals.css:223-236`), plus the tests the ticket lists. The ticket covers the markup. Below are the four places where the obvious version breaks something already in the repo.

### 1. The docstring rewrite must keep the four-object phrase

The ticket asks for the first paragraph of `projects.tsx:1-46` to be rewritten. That paragraph (`:4-9`) holds the phrase `filter, reading, health, headline`. `projects.test.tsx:171` checks for it:

```ts
expect(said(read('../src/app/projects.tsx'))).toContain(four)
```

Out of scope gives that phrase to #904. So the new paragraph still names the four, with that exact string, and adds that the filter is now one control: the summary names the project in view, and `recipe` and *add a repository* are entries in its menu (the-bar.md *Since 2026-11-05*). The paragraphs at `:11-37` argue that `+` and `recipe` "add a tab to a list". Cut those down to one line each saying both are now menu entries (#216, #218). `:39-45` (*where it lands*) stays as it is.

### 2. The global `<details>` style already draws a triangle

`globals.css:762-773` styles every `details > summary`:

```css
details > summary { cursor: pointer; display: flex; gap: 6px; align-items: center; font-size: 11px; color: var(--muted); list-style: none; }
details > summary::before { content: "▸"; color: var(--rule-2); }
details[open] > summary::before { content: "▾"; }
```

The ticket wants a trailing `▾` that is `aria-hidden`. Without an override the bar would show `▸ lingtai ▾`.

- Add `.filter > summary::before { content: none; }`.
- Give the summary the `.tab` look: mono, 10.5px, `--muted`, and `--ink` on hover. The global rule sets 11px.
- Write the `▾` as `<span aria-hidden="true">▾</span>` inside the summary, so it never becomes part of the accessible name.

### 3. The menu is absolutely positioned, so the row doesn't move

`.bar` and `.rail` both use `flex-wrap: wrap` (`globals.css:93`, `:150`). A menu in normal flow would grow `.filter` when it opens and push the rail onto a second line, which the ticket's *Narrow windows* edge forbids.

- `.filter`: `position: relative`.
- The menu (a `<div>` or `<nav>` after the `<summary>`): `position: absolute; top: 100%; left: 0`, a column of the existing `.tab` links, a `--surface` background, a `--rule` border, and a `z-index` above 2. The only `z-index` in the file is the run band's sticky `2` (`globals.css:2485`), which isn't on `/`, but stay above it anyway.
- Nothing in `.bar` sets `overflow`, so nothing clips the menu.

Two rules need rewriting:

- `.filter { display: flex; … flex-wrap: wrap }` was written for a row of tabs. The `<details>` now contains a summary and one positioned menu.
- `.filter .add { margin-left: 5px }` separated `+` from the project names in a row. In a column, make it a `border-top` or `margin-top` that sets the add entry apart from the list.

Rewrite the comment at `globals.css:217-222` and `:231-235` to match.

Colours: `.tab.on` uses `--accent` (teal, `:21`), not `--signal` (amber, `:24`). Keep it that way, and don't let a new rule refer to `--signal` anywhere. `bar.test.ts:249-262` counts any selector whose last compound uses only bar classes, scoped or not.

### 4. Write class names in a form the amber guard can read

`bar.test.ts:231` collects bar classes only from `className="…"` and ``className={`…`}``. A `className={x ? 'tab on' : 'tab'}` is invisible to it, so a class written that way could paint amber unseen. Keep the template-literal form `projects.tsx:86` uses today (``className={`tab${only === p ? ' on' : ''}`}``).

Put every new class (the menu's, the summary's if it has one) in the list at `bar.test.ts:269`. Keep `add` as the add entry's class (`class="tab add"`) so `:269` and `projects.test.tsx:179` keep their claims unchanged. Keep `filter` on the `<details>`.

### Decisions the ticket leaves open

- **The summary in each state.** With 1 project it is the project's name. On `all` it is `all projects`. On `<p>` it is `<p>`. `inView` (`projects.tsx:64`) already holds the name for the 1-project and on-`<p>` states, so keep it.
- **`aria-current="page"`.** It goes beside `.on`, on the same link. With 1 project no entry is current, because the project itself isn't an entry in the table.
- **The add entry's label.** The visible text is `add a repository` whatever `app` says. Keep `title={why}` (`:60`) so a board without an App still says it is step 0 on hover. Drop `aria-label`: the text says the same thing, and a label repeating it adds nothing.
- **No new text with `reading` in it.** `projects.test.tsx:180` asserts that the 1-project markup contains no `reading` anywhere, including titles.
- **The menu has no `onToggle` and no `open` prop.** It stays a server component. `run-log.tsx:291` and `outgoing.tsx:160` keep open state in client state, and that isn't wanted here: the ticket accepts that a live re-render may close the menu.

### Tests

Make the new order test check each `href`'s position with `indexOf` against the table, as `:52` already does for the add entry. Add a check that the 0-project state renders no `<details` and keeps exactly one `href` (`:60`).
