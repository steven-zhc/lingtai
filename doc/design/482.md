## Where #461's rows come from: mirror them, don't import them

Row 1 is at `:182–:200`: `WorkItemClaimed, IssueUpdated, WorkItemLanded, IssueUpdated` on the item, and `StepRequested … RunFinished, RunProducedDiff, RunProposedCompletion …` on the run. Rebuild each sequence as one work item plus one run stream:

Use the real data shapes from the conductor test's events (step names, actions, `onSha`), not invented ones. A wrong payload still renders a sentence, so a test built on it would pass while pinning nothing real.

## What each row pins, and where in the code

Pin at the **pure functions the page calls**, and route each through a **single helper in the test file**:

- **History**: `historyOf(events)` returns `groupHistory(events, attempts)` (`src/lib/task.ts:1242`) mapped to `{ label, lines: [{ type, actor, summary }] }`. Leave out `at`, `seq` and `raw`, which are clock and log noise, not something a person reads as meaning. `attempts` is `Map([[runStreamId, 1]])`.
- **Strip**: `stripOf(runEvents, plan, landed)` returns `renderToStaticMarkup(<Segs steps={foldProgress(runEvents, plan, landed)?.steps ?? []} at={null} labels />)`. `Segs` is at `src/app/rail.tsx:135` and `foldProgress` at `src/lib/progress.ts:349`. Use `labels` because the task page draws it with labels (`src/app/task/[id]/page.tsx:264`). Pass `landed = true` only for the rows whose item stream has `WorkItemLanded`. `foldProgress`'s comment is the reason: *"Passing it is what turns a point that recorded nothing from `pending` into `never-ran`."* Use one `StepPlan` (`@lingtai/conductor/filter`) for the whole file, matching the steps the fixture runs.

**Why the helpers matter, and the decision that isn't obvious from the ticket:** #484 is likely to move the task page off `foldProgress`/`groupHistory` and onto `stepOutcomesOf`/`routesOf`. If the expected literals sit next to direct calls, #484 has to edit the pin to make it compile. Then the pin no longer proves anything. With the helpers, #484 rewrites two helper bodies and leaves every literal alone. Say this in the file's header comment, the same way `waiting-card.test.tsx`'s header says *"never regenerated after the `src` change"*. For the same reason, don't pin through `foldRun`/`standingOf`/`TaskBody`. The card file's header already excludes those: *"their props are `StandingView`/`RunView`, which are #483's and #484's to rewrite."*

Write the expected values as **inline literals**, not `toMatchSnapshot()`. A snapshot is easy to refresh with `-u` when #484 lands, which is exactly what the ticket is meant to stop. Generate the literals from today's code once, read them to check they make sense, then paste them in.
