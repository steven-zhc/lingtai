## Design: keep a stopped run's uncommitted work (#468)

### Where it goes: in `conduct.ts`'s publish, not in `live.ts`

The ticket names `removeWorktreeEffect` (`live.ts:32`). That is only the port. The removal is registered at `conduct.ts:1399`, `yield* Effect.addFinalizer(() => repo.remove({ project, runId, home }))`, and the publish is registered after it at `conduct.ts:1629`, `(didLand ? Effect.void : Effect.promise(publishWhatIsCommitted))`. Finalizers run in reverse order, so the publish already runs **before** the removal on every ending that did not land. It also runs inline at `conduct.ts:3207`, after the walk and before any question is asked.

So the WIP commit is the first thing `publishWhatIsCommitted` (`conduct.ts:1539`) does. Put it ahead of its `rev-parse HEAD`. Leave the repo port and `live.ts` alone: `repo.remove` knows nothing about how the run ended, and it shouldn't.

This placement also gives the most important guarantee by construction. The publish runs after `runPass` has returned, so **no step of this pass ever sees the WIP commit**. `build` doesn't, `review` doesn't, and `merge` (the lane) doesn't. Say that in the comment, because it is half of why the commit can't reach `main` from the pass that made it.

### When it fires: a closure flag set by the dispatch, not the pass's ending

`publishWhatIsCommitted` runs on every ending that did not land, including a red build or a hold at `proposed`. A dirty tree on those endings must **not** be committed. The flag should be set by the agent's own stop, not by whatever the pass ended with.

Add `let stoppedBy: string | null = null` beside `ceilingHit` (`conduct.ts:1262`). Set it at the three places an agent returns without a commit:

- **Implement failure**, `conduct.ts:2754` (`if (outcome.failure)`): set it to `outcome.failure.kind`. That covers `out-of-turns`, `out-of-usd`, `timeout`, `crash` and the rest.
- **Implement, nothing committed**, `conduct.ts:2834` (`if (head === startedAt) return { stopped: 'the agent produced no commits', … }`): set it to `'no-commits'`. This is the `StepDidNotFinish` at `implement` that the ticket names, and it is exactly #237's case.
- **Fix round**, `conduct.ts:2991` (`if (!committed)`): set it to `fixed.failure?.kind`. A fixer that declined (`declined`, no failure) is not a stop, so leave the flag `null` there.

Also set `stoppedBy = 'interrupted'` immediately before each dispatch, and clear it to `null` when the dispatch returns with a commit. A conductor that is interrupted mid-agent then keeps the work as well: only the finalizer reaches the publish on that path, and the flag says an agent was running. This costs one assignment.

Never set it at `never-started`. That agent touched nothing.

### What the WIP commit is, and the order of the git calls

When `stoppedBy !== null`:

1. Run `git status --porcelain`. Empty means do nothing more. That is the "a clean tree writes nothing" line in Done when.
2. Remember `parent = rev-parse HEAD`.
3. Run `git add -A`. It honours `.gitignore` and `info/exclude` by default, which covers "do not stage ignored files" without any extra code. The hook wiring is written under `~/.lingtai/runs/<runId>/` (`hook-config.ts:75`), outside the worktree, so it won't be swept in.
4. Commit as the conductor, with nothing that can fail on this one commit:

   ```
   git -c user.name=Lingtai -c user.email=… -c commit.gpgsign=false commit --no-verify -m "wip: <runId> stopped by <stoppedBy>"
   ```

   - The explicit identity is there because #467's agent never committed in that worktree, so nothing shows that an identity is configured there.
   - A signing failure is a failed hook by another name, so turn signing off too.
5. Store `wip = { sha, parent, stoppedBy }` in a closure variable, next to `published` and `armPublished`.

If any of these git calls fails, write it to the run log and to the `detail` of the `RunRefsPublished` row, then publish what is committed exactly as today. **A failed WIP must never cost the publish of real commits.** This is `noteRefs`' rule: *the account never costs the thing it is an account of* (`conduct.ts:1469`).

The publish is called twice on most endings: inline, then from the finalizer. On the second call the tree is clean and `HEAD` is the WIP sha. That is why `wip` lives in the closure, and why the refspecs below must read from it rather than from `HEAD`.

### Where the WIP sha goes: the arm, and only the arm

Today the push is one command: `HEAD:refs/heads/${branch}` plus `+HEAD:refs/heads/${arm}` (`conduct.ts:1583-1589`). With a WIP:

- **The arm** `agent/<n>-attempt-<k>` gets `+${wip.sha}`.
- **The branch** `agent/<n>` gets `${wip.parent}`, under the same lease, and only if `wip.parent !== tree.baseSha`. If the agent never committed, leave `agent/<n>` alone entirely.
- **`published`** is set to `wip.parent`, or left alone if the branch wasn't pushed.
- **`armPublished`** is set to `wip.sha`.
- **The `already-published` check** at `conduct.ts:1576` compares against those two values, not against one `head`.

The ticket requires that `agent/<n>` never carries a WIP. `approve()` "takes the held run's own `headSha` and merges that" (`approve.ts:23`), and the lane fetches `refs/heads/<branch>` (`integrate.ts:392`). So the branch is the ref that gets landed, and the arm is never fetched by the lane.

### Record it on a new event, not on `RunProducedDiff`

This is the decision the ticket doesn't make, and getting it wrong is how a WIP reaches `main`. Whatever `RunProducedDiff.headSha` holds becomes `reduceRun`'s `headSha` (`domain/src/run.ts:236-242`). That value is what `approve()` merges (`approve.ts:23`) and what `waive()` binds a waiver to (`approve.ts:611`, `onSha: run.headSha`). It is also task_view's `head_sha` (`task-view.ts:526-533`), which the card renders.

If the WIP sha were written there, a person approving or waiving the held run would be offered the WIP commit to land.

So:

- **`recordDiff` is unchanged.** It records `wip.parent` on the branch, and only when the agent committed something.
- **The WIP gets its own additive event**, e.g. `RunKeptUncommitted { arm, sha, parentSha, stoppedBy, files, insertions, deletions }`. Count it with `numstat` over `parent..sha`.
  - Append it with `appendAt` and swallow a refusal, like `noteRefs`.
  - Append it **after** the push succeeds, never before. A sha named on the log must be fetchable.
- **`RunRefsPublished`** keeps its enum. If the branch wasn't pushed because nothing was committed and the arm took the WIP, that is `outcome: 'published'` with `headSha` set to the arm's head. Put the branch's absence in `detail`.
  - Do **not** reuse `arm-only` for this. The schema defines `arm-only` as origin *rejecting* the branch (`events.ts:518`).

Register the event in `events.ts` and let `pnpm typecheck` find the exhaustive switches. It should not get a `task_view` column: a column is a schema change plus `lingtai projection rebuild task_view`, and nothing on the board needs one for this ticket. Listing it in the history at `apps/board/src/lib/history.ts` is enough for the card.

### The next brief: take the files, not the commit

`attemptBrief` (`attempts.ts:397-411`) currently prints *"Nothing. It committed no change…"* when `produced === null`. With a WIP on the log that sentence is false.

- Read the new event into `AttemptOutcome` as `kept`.
- When `kept` is present, say how many files, which arm, which sha, and what it stopped on. Say the work was **never built or reviewed**.
- Say to take its contents with `git diff <parent> <sha> | git apply`, **not** with `git checkout <sha> -- .` or `git reset --hard <sha>` — both overwrite every path the WIP's tree holds, including whatever the worktree's base has gained since.

The reason: an agent that resets onto the WIP puts a `wip:` commit into `agent/<n>`'s history, and the lane guard below refuses that commit. 0109 §9 ("the cut does not move") still holds, because the brief offers the work and the agent decides whether to use it.

### The lane guard: a second line, in `integrate.ts`

The structural guarantees above cover the pass that made the WIP. The lane check covers a *later* agent that committed on top of one.

- Put it in `integrate.ts` right after the `no-commits` check (`integrate.ts:435-438`).
- Run `git log --format=%s ${laneBase}..${laneBranch}` in the mirror. Refuse if any subject starts with the WIP prefix.
- Add a `RefusalReason`, `'wip-commit'`. The enum is additive by its own comment: "Additive to the enum. No stored event is rewritten and no version is bumped" (`vocabulary.ts:66-68`).
  - It is not a `JudgeWhen`, so a person is next, which is right.
  - `diagnoseRefusal` and the other exhaustive sites will fail typecheck until each one has a sentence for it.
- Put the prefix in `@lingtai/domain` as one constant that both `conduct.ts` and `integrate.ts` read.
  - It can't live in `@lingtai/repo`: `conduct.ts` "imports **types only** from `repo`" (`live.ts:4-5`).
  - Keep the prefix specific enough that a person's own commit message doesn't collide with it, e.g. `wip: run-`.

### Tests (all unit)

- **`packages/conductor/unit/conduct-what-a-claim-leaves.test.ts`** already drives the wall through `fakePorts` (`test/one-pass.ts:781`). That fake answers `''` to every verb it doesn't know, so `status --porcelain` reads as clean by default and the existing cases don't change. Add cases that:
  - **Dirty tree, nothing committed:** override `status` to answer a dirty line and `rev-parse` to move after `commit`. Assert, in order, `git add`, `git commit` (with `--no-verify` among the args), then a push whose refspecs include the arm and **not** `refs/heads/agent/7`, then `append RunKeptUncommitted`.
  - **Dirty tree, agent committed:** assert the branch refspec carries the parent, not the WIP sha.
  - **Clean tree:** no `git commit` at all.
  - **Red build:** `stoppedBy` stays `null`, so a dirty tree after a red build writes nothing.
  - **`RunProducedDiff` never carries the WIP sha.** This is the unit-level claim that stands in for "approve cannot land it".
- **`packages/repo/unit/integrate.test.ts`** has a fake git port (lines 24-30). Add a `log` answer with a `wip: run-…` subject and assert `wip-commit` is returned before any `merge` call. That is the "the merge lane cannot land a `wip:` commit" checkbox.

The real-git version of these checks belongs to `pnpm test:integration` after the merge, and nothing above depends on it.

### The ADR

0109 §6 says *"Every claim that committed anything publishes two refs… A head still at the base publishes nothing,"* and §7 says the worktree is deleted with no warning. Both stop being true here. The repository's rule is that a current ADR in `doc/decisions/` is edited in place: "a decision that changes is an edit to its topic's ADR, not a new file beside it". So edit `doc/decisions/0109-the-core-takes-a-ticket.md` §6 and §8 to say the following, and do not write a superseding file:

- A stopped agent's dirty tree is committed as a WIP on the arm alone.
- It is recorded on its own event, never on `RunProducedDiff`.
- The lane refuses it.
