# Design: #1095 — the control verbs and the restart become Effects

Line numbers are from this worktree. CLI-07a has landed: `packages/domain/unit/effect-ratchet.baseline.json:2` reads `"apps/cli": { "async": 281, "run": 6 }`. The ticket's line numbers still match.

## 1. Most of the existing catches will stop catching

The Effects you will yield fail in two different ways, and that difference decides how every catch is written:

- **Typed failure (`E = unknown`):** `readControlEffect` (`packages/daemon/src/control.ts:117-120`) and `requestShutdownUnlessStandingEffect` (`:270-277`).
- **Defect (`E = never`, a store failure kills the fiber):** `controlWatermarkEffect` (`:152`), `startAfterEffect` (`:391-394`), `readStatusEffect` (`:717`), `codeIdentityEffect` (`currency.ts:232`) and `doctorReportEffect` (`doctor.ts:3556-3558`).

`Effect.catch` only sees typed failures. Today's `facts.watermark().catch(() => null)` (`restart.ts:946`, `:1152`, `:1193`, `:1214`), `facts.startAfter(mark).catch(…)` (`:893`, `:1230`) and the `try { await facts.daemonUp() }` around `readStatus` (`:819-836`) would therefore stop recovering. A beacon read that fails would crash the restart instead of refusing with *whether a daemon is up could not be read*.

**The rule:** every `.catch(f)`, `.then(ok, f)` and `try/catch` on a fact in `checkBeforeTheDrain`, `checkAfterTheWait`, `prepareRestart` and `restartSupervised` becomes one helper:

- It uses `Effect.catchCause`.
- It re-fails a cause that holds only interrupts (`Cause.hasInterruptsOnly`, as `inFlightEffect` does at `control.ts:461-463`).
- Any other cause gets today's fallback.
- Where today's code prints the error's text, it uses `Cause.squash(cause)` and then the existing `err instanceof Error ? err.message : String(err)`.

Write the helper once in `restart.ts` and use it at every one of these sites. If one site uses `Effect.catch` instead, the restart stops refusing on that failure.

## 2. The ports

All members of `RestartFacts` (`restart.ts:705-727`) return `Effect.Effect<…, unknown>`. That lets a fake fail with a typed error and the real one fail with a defect, and §1's helper treats both the same.

`liveFacts()` (`:728-744`) uses:

| Port | Filled with |
|---|---|

| `doctor` | `doctorReportEffect()` |

## 3. `waitForTheLock` is the one place a fiber is started, and it carries the caller's context

`waitForTheLock` stays `async` until CLI-08a. Its `how.ask` and `how.held` are promise thunks (`restart.ts:1332-1336`), and `prepareRestart` passes it `facts.holder` and `facts.inFlight` (`:1041-1042`). Those two are Effects now, so something has to run them.

**Do it this way:** inside `prepareRestart`'s `Effect.gen`:

```ts
const run = Effect.runPromiseWith(yield* Effect.context<never>())
```

Then pass `ask: () => run(facts.holder())` and `held: () => run(facts.inFlight())`, and call the wait with `yield* lift(() => waitForTheLock(...))`.

Why this is safe and allowed:

- CLAUDE.md sanctions it: *"A run that must start a fiber of its own carries its caller's services with `Effect.runPromiseWith(yield* Effect.context())`, which the ratchet does not count"*. `board.ts:180` does the same.
- The ratchet's `RUN` regex skips `*With` runs (`effect-ratchet.test.ts:64-69`).
- It does not break the ticket's rule against `Context.empty()`.
- `runPromiseWith` rejects with `causeSquash(exit.cause)` (`node_modules/.pnpm/effect@4.1.2/node_modules/effect/src/internal/effect.ts:5852-5855`). That is the original typed error or the defect itself, so `waitForTheLock`'s *could not ask who holds the lock — ${message}* (`:1371-1373`) prints the same words as today.

Do **not** add promise twins of `holder` and `inFlight` to `RestartFacts` to avoid this: the fake that a test hands the wait must be the same fake the checks read.

## 4. Call sites and the remaining promise edges

- **`cli.ts`:** `:1105`, `:1114`, `:1185` and `:1221` change from `yield* lift(() => controlCommand(…))` and `yield* lift(() => restartCommand(…))` to `yield* controlCommand(…)` and `yield* restartCommand(…)`. The dynamic `import('./daemon.ts')` stays lifted.
- **`controlCommand`:** pause and resume become `pauseProjects(...)`/`resumeProjects(...)` (`project-pause.ts:64`) wrapped in §1's catch, which prints the message and answers 1. Shutdown yields `requestShutdownEffect` and is **not** caught, because today its rejection reaches `cli.ts`'s handler (`daemon.ts:830` sits in no `try`).
- **`restartSteps`:** `serviceCommand`, `daemonCommand` and `keeper()` are reached the same way as today. The first two go through `lift`. The `drain.ask` inside the options handed to `serviceCommand` (`daemon.ts:928-930`) is a promise port of `service.ts`'s and stays `requestShutdownUnlessStanding`. CLI-08b changes it.

## 5. The unit test

Add `apps/cli/unit/restart-order.test.ts`. It builds `RestartFacts` from `Effect.succeed`/`Effect.fail` closures that record each call into an array. Each refusal case asserts the recorded order: no `ask` before the refusal.

- **Dirty worktree:** `identity` returns a dirty `Identity`, and `args.dirty` is false.
- **Red doctor:** a result with `status: 'fail'` and no `restartAnswers`.
- **Each refusal path** (dirty, red doctor, failed `holder`, failed `daemonUp`): `prepareRestart` and `restartSupervised` both answer non-zero, `ask` and `how.service` are never called, and the log holds `not restarting:`.
- **Interrupted wait:**
  - Make `holder` answer `'human:x'` and call `process.emit('SIGINT')` on its second call. That is an in-process event: no signal is sent, and `waitForTheLock`'s own listener sees it. Set `pollMs: 1`.
  - Assert `{ ok: false, code: 130 }` (`:1065`), exactly one `ask`, no `startAfter`, and the log line *"The shutdown asked by … is still standing"*.
  - Set `process.env.USER` and restore it afterwards: `by` reads it at `:923`.

Put the `controlCommand('pause')` *store dies* case in the same file. Use `vi.mock('../src/project-pause.ts')` to return `Effect.die(new Error('boom'))`, then assert exit code 1 and that `console.error` received exactly `'boom'`.

No unit test runs the real `liveFacts()`: it reaches the lock file and the store. That stays `integration/restart.test.ts`'s job, after the merge.

## 6. Counting

Remove 8 `async` and no `Effect.run*`. `daemonIsUp` is one of the 8, removed by folding it into the `daemonUp` port. The `runPromiseWith(context)` from §3 is not counted. Set the baseline to `273`/`6`. If the ratchet still reads higher, an `async` arrow was added somewhere, for example an `async () =>` inside a fake or port in `src/`. Remove it. Do not raise the number.

`unit/daemon-cli.test.ts:14-27` mocks `restartCommand`, `controlCommand` and `daemonCommand` as `async` functions. The first two become `() => Effect.succeed(0)`. That file is under `unit/`, which the ratchet does not count, but the `cli.ts` call sites now `yield*` those mocks, so a promise there breaks the test.

## 7. Edges the ticket leaves to the design

- **Interruption mid-wait:** a fiber interrupted while `lift(() => waitForTheLock(...))` is pending does not cancel the promise. Its `SIGINT` listener is removed in its own `finally` (`:1395-1397`). That is today's behaviour and stays so; the ticket says Ctrl+C is not an Effect interruption.
- **Spinner:** `restartCommand`'s `finally` (`daemon.ts:886-889`) becomes `Effect.ensuring(Effect.sync(() => { if (!started) steps.end() }))`. Leave the closing `not restarted` line outside the `ensuring`, as today: it prints on a non-zero code and not on a throw.
