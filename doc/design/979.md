# Design: #979, `/recipe/<project>` in the add page's shape

The ticket's layout stands. These are the points where the code gives a different or more specific answer than the ticket.

## The file's text is already in hand, so nothing new is read

`currentRecipe` returns `source`, *"The raw file, kept so a diff against a later version is possible"* (`packages/recipe/src/resolve.ts:72-73`). It is the same string `resolveLocalRecipe` read and resolved (`packages/recipe/src/local.ts:304`, `:353`, returned by the spread at `:450`).

`projectRecipe` adds `text: resolved.source` to its `ok: true` branch (`apps/board/src/lib/recipe.ts:468-476`). Do not call `diskFiles.read`, for three reasons:

- `readIfThere` rethrows everything but `ENOENT` (`packages/recipe/src/write.ts:35-42`), and `projectRecipe` is documented *"Never throws"* (`recipe.ts:436`). A second read would need its own guard.
- The ticket's edge, *the file cannot be read while the recipe resolved*, cannot happen with this source. A resolved recipe always has its text, and an `ok: true` view with no text does not exist. So write no branch for it and no test for it. `text` is a `string`, not `string | null`.
- The race listed under Out of scope also goes away, and there is no new IO for the Effect ratchet to count.

The edit page already shows this same text, and `write.ts:47-48` records that *"a recipe carries no credential"*, so this exposes nothing new.

## Where `recipeLines` is called, and why there is no import cycle

`recipeLines` needs the `an attempt` sentence. Get it from `readRecipe(recipe).find(row => row.name === 'an attempt')` rather than building a second `attemptCeiling` call: `readRecipe` is the place that sentence is built (`recipe.ts:898-903`), and rebuilding it is what `attemptCeiling` exists to stop.

So `recipe-lines.ts` imports `./recipe`, and `recipe.ts` must not import `recipe-lines.ts`. That decides the wiring:

- The `ok: true` branch also carries `recipe: resolved.recipe`.
- The `Recipe` component calls `recipeLines(view.recipe, view.ref)`.
- `projectRecipe` does not compute the lines.

A unit test can import this: `apps/board/unit/attempt-recipe.test.tsx:18` already imports `lib/recipe.ts`.

`recipeLines` stays synchronous and adds no `async` function.

## Three places the ticket's field names are not the right read

- **`kinds` and `held by` use `kindsOf(recipe)` and `excludeOf(recipe)`, not `source.kinds` and `source.exclude`.** A `queue:` action at `claim` overrides both (`packages/recipe/src/settings.ts:302-305`, `:312`, `:325`). `readRecipe` (`recipe.ts:879`, `:884`) and the provenance map (`local.ts:400-401`) read through the helpers, so the raw fields could disagree with the fold on the same page. Add a unit case with a `queue:` at `claim`.
- **The "neither `run` nor `agent`: skipped" edge applies to `install`, `checks`, `agent` and `reviewer`, not to `end`.** `end` holds `close`, `labels` and `refs` actions, which have neither field, and the ticket reads that line by `name`. Every action has a `name` (`packages/recipe/src/plugin.ts:358`). Applying the skip to `end` would make it read `nothing` on a recipe that closes tickets.
- **Pick actions with `kindOfAction`** (`packages/recipe/src/recipe.ts:1586`), as `describeAction` does (`recipe.ts:562`), and use it for the `human` test on `steps.proposed` too.

`String(limits.turns)` already reads `unbounded`, because the value is `number | 'unbounded'` (`recipe.ts:44`). It needs no branch.

## Markup

- **The two long labels are not `.s2-line`s.** `.s2-k` is an 80px column (`apps/board/src/app/globals.css:3296`), and *A person approves the merge?* would wrap to four lines in it. Draw them as the add page does, with `<h3 className="s2-h">` and the value under it (`setup-form.tsx:314`, `:331`):
  - `Yes` or `No` as text;
  - the four limits in `.s2-limits`;
  - the sentence in `<p className="note">`.

  `recipeLines` returns these two as their own fields rather than as lines. The test asserts their values either way.
- **A read-only line** is `Line`'s markup without the button (`setup-form.tsx:32-35`). `.s2-note` spans columns 2 to 4 (`globals.css:3298`) and the third column is `auto`, so it closes up on its own. Leave the note span out when there is nothing to say. Values get `className="mono"`, as they do on the add page.
- ***Also set* is `view.rows` minus a named set of the four rows already covered** (`picks up`, `excludes`, `an attempt`, `agent`). Use exclusion rather than a list of the six, so a row added to `readRecipe` later appears here without an edit. It must be `view.rows` and not `readRecipe`, because the `NOT READY` Codex readiness text is only on the former (`recipe.ts:508-518`). The note slot reads `← {sourceOf(row, view.provenance) ?? 'not said'}`, as `page.tsx:85` does today.
- **`.rread.sourced` (`globals.css:2503`) has no user after this, so delete that one rule.** `.rread` stays: the attempt recipe still draws `<dt>` rows (`attempt-recipe.test.tsx:231`). `.rfrom` and `.prov` stay too, for the fold.

The closed `<details>` needs no new CSS (`globals.css:844-855`). `page.tsx`'s header comment changes with the page, and its claim that nothing here writes stays true.

## Tests in `apps/board/integration/recipe.test.tsx`

Besides `:126`, these need attention:

- **`:254`** asserts `not.toContain('<dt>picks up</dt>')`. Once that markup is gone the assertion passes on every page and proves nothing. Change it to assert `s2-line` is absent, so it still means *no rows pretending the recipe said nothing*.
- **`:127`** expects `bug &gt; tech-debt (in priority order)`, the `picks up` wording, which is no longer drawn. Assert `bug, tech-debt` on `kinds`.
- **Keep unchanged:** `:128`, `:130`, `:133`, `:137`, `:215-218` and `:238-240`. Each still holds through the *held by* line, *Also set*, the limits note or the fold, whose contents `renderToStaticMarkup` emits even when closed. `:218`'s `← preset pnpm-workspace` is what pins the *Also set* note slot.
- **`renders nothing to press`** (`:397`) is the guard on the rule against copying the *change* button.

That file is integration, so per the ticket it is run alone. `recipeLines`' unit test is what `pnpm test` sees. The layout itself has no automated check, and the side-by-side screenshot is that check.
