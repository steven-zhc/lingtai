## Design note — #531

Keep the change in `apps/board`. The Waiting branch of `Card` already renders the issue number, task link, rail, and a single cause paragraph (`apps/board/src/app/page.tsx:161–173`); its file comment says, “A waiting card carries the rail and one cause line. Its resolutions and the rest of the wait’s detail are on the task page (0118 §2)” (`apps/board/src/app/page.tsx:41`). Retain that content boundary. ADR 0118 §2 says the card carries “only the number, the title, the rail and its line, and triage’s cause with one sentence,” with resolutions on the linked page.

The decision needed for the reference’s cause chip is to keep **advised cause and summary as separate presentation values**. `card.cause` currently flattens them into `` `${status.result.cause._tag}: ${status.result.summary}` `` (`apps/board/src/lib/board.ts:558–561`), so styling it as one paragraph cannot give the cause its own emphasis. Carry the two values from the existing `TriageAdvised` result, and render a labelled cause beside the summary only for that result. For every other triage state, render the wait’s first line as an unlabelled fallback; the current Waiting branch already chooses `card.note` when `card.cause` is null (`apps/board/src/app/page.tsx:162`). ADR 0118 §1 says a result for the current wait is `Done` even if the recipe no longer declares triage, so preserve the existing `triageStatus` decision in `boardCard` (`apps/board/src/lib/board.ts:534–537`).

Scope the visual work to the Waiting column and its cards in `globals.css`: give its heading/count, card padding, title, rail, and cause row the reference’s hierarchy at a 440px column width, then allow text to wrap or clamp within that width. The existing column markup already marks Waiting as `hot` (`apps/board/src/app/page.tsx:730–739`); the existing rail is shared with the task page, as the import comment says: “one rail, two surfaces, and never a copy” (`apps/board/src/app/page.tsx:25–28`). Use Waiting-specific selectors for rail density and responsive adjustments rather than changing shared rail rules or the other lanes. Preserve the current card’s task link and absence of resolution controls, and use a triaged fixture alongside the untriaged fallback to verify the two distinct treatments.
