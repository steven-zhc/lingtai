# #1409: design note

## Where the change goes

The change is almost all in `prBoard` (`apps/board/src/lib/pr-board.ts`). That function is pure, and every frame from 02 to 04 can be checked with a unit test in `apps/board/unit/pr-board.test.tsx`. Three small changes support it:

- the fold gains two times;
- `prs.ts` passes a tri-state instead of a sentence;
- `pr-buttons.tsx` gets a pending label.

Nothing here needs `pnpm test:integration`. No event is added, and nothing reads the log in a new way.

## 1. The queued card's tickets come from the draft read, not from `pr.tickets`

This is the decision the ticket leaves unstated. A `requested` PR has no tickets of its own. `PrState.tickets` is set by `PrInProgress` (`packages/domain/src/pr.ts:267-275`). Until the freeze, the tickets are only the computed draft: `readDraftOf` → `readPrDraft` (`apps/board/src/lib/prs.ts:97-116`, `packages/project/src/pr.ts:581`). Tickets that land while the PR is queued go to the same stream. ADR 0131 §1 says: *"The target is the highest PR while it is in `draft` or `requested`"*, and `addDraftTicket` says *"while there is no PR yet, in the draft, or asked to submit"* (`packages/domain/src/pr.ts`, above `addDraftTicket`).

So while `latest.status === 'requested'`:

- **Queued card.** It goes in *In progress*. It is built with `cardOf(requested, …)` for the key, href and name, but its `slips`, `more` and `count` come from `draftTickets`, which today's Draft card already uses (`pr-board.ts:297`). `slipsOf(pr)` would draw it with no tickets.
- **Draft column.** `cards: []` and `count: 0`, whatever `draftTickets.length` is, because those tickets belong to the queued PR. `empty` reads *Nothing has landed since PR n was submitted. Tickets that land now join PR n until it starts, then the next PR.*
- **If `draftError !== null`.** The Draft column keeps today's failed card (`pr-board.ts:294-295`). The queued card is still drawn, with no slips, `count: null` and a meta line `tickets: unknown`. It is never drawn as zero tickets.
- **Strip.** `strip.notInPr` (`pr-board.ts:485-488`) reads `PR n queued`. When a PR is open and `draftTickets` is empty, it reads `PR n in progress` (frame 03). Otherwise it stays as today.
- **Frame 03's Draft sentence.** With a PR in progress and an empty draft, the Draft column's `empty` reads *Nothing has landed since PR n started.* instead of *Lingtai keeps taking tickets…*.

You do not need to change `chipsOf` for the chips. `running` is only computed when `pr.status === 'in-progress'` (`pr-board.ts:195-196`), so every chip on a `requested` PR is already pending. Keep the `topup` skip as it is.

## 2. `servedWords` becomes a tri-state, and the words move into `pr-board.ts`

The pid comes from interpolating the holder: `` `${holder} is freezing it` `` (`prs.ts:214-219`). Replace `PrBoardInput.servedWords: string` (`pr-board.ts:238-239`) with `daemon: 'running' | 'none' | 'unknown'`.

- Map it in `prs.ts:157-161`: `null` → `none`, `'unknown'` → `unknown`, any other string → `running`.
- Delete `servedWords`. Its only caller is `prs.ts:178`, and the CLI has its own copy (`apps/cli/src/pr.ts:281-289`, per `doc/design/1319.md:59`), which is out of scope.
- The holder's string then never reaches the view, so neither the pid nor the word *freezing* can appear on the PRs board.

What each state draws on the queued card:

| `daemon` | Card line | Extra |
|---|---|---|
| `running` | `waiting for the daemon to start it` | none |
| `none` | no "waiting" part | *No daemon is running, so nothing will start it. Start one:* with `lingtai start` drawn as code |
| `unknown` | no "waiting" part | *could not tell whether a daemon is running —* with `lingtai doctor` drawn as code, then *says* |

The `command` button kind already draws `label: <code>command</code> — note` (`pr-buttons.tsx:27-30`), so use it rather than putting backticks into a `sub` string.

**Pause and drain:** the lock holder cannot tell a paused or draining daemon from a running one, so the card shows frame 02's words. Do not add a second read for this; the ticket allows that fallback.

## 3. The fold gains `requestedAt` and `startedAt`

The fold keeps no times today. `const at = { version, lastSeq }` (`packages/domain/src/pr.ts:237`) carries none. `ended.at: Date` (`PrState.ended`) is the precedent for taking a time from `event.at` (`packages/domain/src/envelope.ts:96`).

- **`requestedAt: Date | null`:** set from `event.at` on `PrSubmitRequested` (`pr.ts:253-262`), and set again on every request. After a `PrSubmitRefused` (`pr.ts:264-266`) the PR returns to `draft`, and the next submit's time is the one that matters.
- **`startedAt: Date | null`:** set from `event.at` on `PrInProgress`, **only while it is null**. `PrInProgress` is written again for a pr-fix or a restart (see the `lastPushed` and `fixOwed` comments in `PrState`). Frame 03's *started* means the first start, not the latest.
- **Snapshots:** the PR fold is not cached as a snapshot. `reducePr` is called on the events directly (`packages/project/src/pr.ts:79`, `:171`, `:784`), so no reducer version needs to change.
- **Tests:** add both fields to `emptyPr`, and pin them in a `packages/domain/unit/pr-*.test.ts` test.

## 4. The confirmation line is a field of the view, drawn by `pr-columns.tsx`

Add `submitted: { n: number; at: Date | null; href: string } | null` to `PrBoardView` (`pr-board.ts:100-105`). Set it only when `latest.status === 'requested'`, and draw it above `.pr-strip` (`pr-columns.tsx:122`).

- When `daemon === 'running'` it reads *✓ PR n submitted at HH:MM — it starts when the daemon next looks for work. Open PR n*. Otherwise it reads *✓ PR n submitted at HH:MM. Open PR n* (frame 04).
- When `at` is null, drop *at HH:MM*.
- `PrButtons` must keep ignoring `result.ok`'s detail (`pr-buttons.tsx:19-21`). The line has to come from the log, or a CLI submit would never show it.

## 5. The card's lines

**Queued:** `submitted HH:MM by you` or `by <name>`, then ` · waiting for the daemon to start it` when `daemon === 'running'`.

- *by you* when `requestedBy === viewer`. Add `viewer: string` to `PrBoardInput`, passed from `actor()` (`apps/board/src/lib/actor.ts:15`). `prBoard` stays pure.
- Otherwise show the name without its `human:` prefix.
- If `requestedBy` is null, omit *by*.
- If `requestedAt` is null, omit the time.

**In progress:** prepend `submitted HH:MM · started HH:MM · frozen at <7-char frozenSha>` to the existing sub lines (`pr-board.ts:365-366`), leaving out each part the fold lacks. Change the pill from `'CI'` (`pr-board.ts:365`) to `'in progress'`, as frame 03 shows.

**Times:** use the PR page's format, `day()` (`apps/board/src/lib/pr-page.ts:242`, UTC from `toISOString`). Move it somewhere both files import, so the card and the PR page print the same time. Do not use the server's local time zone.

**PR page:** it prints *submitted* from `events[0]?.at` (`pr-page.ts:498`, `:637`), which is the stream's first event, the first ticket's landing, and not the submit. Change that line to `pr.requestedAt`; otherwise the card and the page give two different submit times for one PR. That is the only edit to the PR page.

**Header:** the queued header is one shade lighter (`.pr-card.queued .pr-head` in the mock). Either add `'queued'` to `Tone`, or add a class next to `progress`. Either works.

## 6. The button

`PrButtons` disables every button for the whole transition (`pr-buttons.tsx:40`). Record which button was clicked. While `pending`, the clicked submit button:

- reads **Submitting…** with a spinner;
- keeps its `primary` class and carries `aria-busy`;
- has CSS for `.pr-btn.primary[aria-busy]` so it is not greyed.

The other buttons keep today's disabled look.

`submitPrNow` calls `revalidatePath` before it returns (`actions.ts:709`), so the transition ends together with the new board. When it succeeds, the Draft card and its button are gone, so the label needs no reset. On a refusal it returns to *Submit PR* with the refusal under it (frame 05, unchanged).

## Tests and docs

**Tests:**

- `pr-board.test.tsx:105-110` asserts the opposite of this ticket. Rewrite it to check four things:
  - the `progress` card has pill `queued`, with every chip pending;
  - the Draft column has `count: 0`, no cards, and the sentence;
  - `view.submitted` is set;
  - no `pid` and no `freezing` appear anywhere in the view.
- Its fixture `servedWords:` (`:43`) becomes `daemon:` and `viewer:`.
- Add one case each for `none`, `unknown`, `requestedBy: null` and `requestedAt: null`.
- Add an `in-progress` case that checks `started`/`frozen at`, and checks that `submitted` is null.

**Docs:**

- **ADR 0131 §2** already says *Submit … moves it to In progress*. The change agrees with it, so the ADR needs no edit.
- **`doc/design/1319.md:59`** says the opposite (*"The Draft card, not In progress"*). It is that ticket's design note, so add a line there pointing to #1409 rather than rewriting its table.
- **Remaining `doc/` hits:** run `git grep -n "freezing it\|Submit PR" doc/` for any others. The milestone mock is the source this ticket draws from.
