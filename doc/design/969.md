## Shape for #969: one `listRepositories` in `@lingtai/setup`, and where `lingtai add` offers it

The move and the `gh` branch are the ticket's. This note covers three things the ticket does not decide: what the function returns, how the token is reached without a new `async`, and where `lingtai add` actually asks. Today `lingtai add` with no slug lists nothing on **either** kind of machine; it exits 2 with *no repository was picked* (`apps/cli/src/add.ts:87-95`).

Today it has no workspace dependency at all (`packages/setup/package.json`). Neither `github` nor `domain` depends on `conductor` or `setup`, so this makes no cycle. Run `pnpm install` once and commit the lockfile.
- **Tests.** The `describe('listRepositories')` block in `packages/conductor/unit/pick-repository.test.ts:88-250` moves to `packages/setup/unit/list-repositories.test.ts`, and its fake `AppReader` moves with it. ### The return type: a union, with `Picker` left as it is

```ts
type RepositoryList =
  | { kind: 'app'; picker: Picker }
  | { kind: 'gh'; login: string; repositories: ListedRepository[]; more: boolean }
```

- `Picker` keeps its exact shape, wrapped rather than given a new field. So `choose(picker, …)` and `alreadyOnboarded(picker, …)` still take what they take today, and none of their tests change.
- `livePicker` (`apps/cli/src/first-project.ts:1018`) is still what `add-github.ts:284` calls for `choose()`'s refusal sentence. That path is App-only (`kind !== 'gh'`, `add-github.ts:264`). It unwraps `kind === 'app'`.
- **Errors are the Effect's failure channel, not a field.** The ticket wants *an error sentence, never an empty list*. An empty `repositories` together with `more: false` therefore always means *this login can push to nothing*. A failed read never produces that value.
- The App branch keeps its existing per-installation `unanswered` (`pick-repository.ts:79-84`). Only a failure of `GET /app/installations` itself fails the whole Effect, which is the same as today.

### `onboarded` on the `gh` list

Run the same `onboardedAs` over the `gh` list:

- `owners` is built from the listed repositories, as at `pick-repository.ts:151-157`.
- `everyAnswered` is `!more`. A capped list cannot vouch that one account owns a name, which is exactly what `unrecorded` exists for (`:61-66`).

### The `gh` read: a GET-only reader in `@lingtai/github`, written as an Effect

**Do not build it on `createGitHubClient({ auth: { kind: 'gh' } })`.** That client is scoped to one `owner`/`repo` (`packages/github/src/client.ts:371-393`), and `/user/repos` belongs to no repository.

Instead, add `createGhReader(run?: GhRun)` beside `createAppReader` (`packages/github/src/app.ts:319-345`):

- It has one method, `request<T>(path)`, GET only.
- The token comes from `ghToken(run)` (`gh.ts:80`) on each call. That is the same route `checkGhAccess` reaches through `createGitHubClient`'s `tokenFor` (`client.ts:393`).
- `gh` is spawned through `execFile` with an argv array and no shell (`gh.ts:63-64`). So the token lives only inside the closure that builds the `authorization` header. It is never a shell variable, never interpolated into a message, and never passed to `log`.
- `ghToken`'s own errors already pass stderr through `withoutTokens` (`gh.ts:73-85`). Reuse them. Do not build a new sentence from anything that holds the token.

Two constraints on how it is written:

- **It must be an Effect, not `async`.** `packages/github` sits at exactly `"async": 37` in `effect-ratchet.baseline.json`, and that number may only go down (CLAUDE.md, *the ratchet only goes down*). Wrap `ghToken` and the fetch in `Effect.tryPromise`. `githubJson` is a private `async` at `app.ts:125`. Either export it and call it through `Effect.tryPromise`, or give the reader its own `fetch` inside `Effect.tryPromise`. Do not add a second `async` copy.
- **Give each page a timeout**, `Effect.timeout('15 seconds')`, matching `gh.ts:23`'s `TIMEOUT_MS`. `githubJson`'s `fetch` has no signal and no timeout today (`app.ts:125-138`). The ticket's *times out* edge needs this to be an error rather than a hang.

### `listRepositories` itself

- **Input:** `{ projects, auth: 'app' | 'gh', app?: { reader: AppReader; installUrl }, gh?: { status: () => Promise<GhStatus>; reader: GhReader } }`. The CLI passes `githubAuthKind()` in; the function does not read env. The fakes inject `status` and `reader`. `status` is wrapped in `Effect.tryPromise`.
- **`gh` branch, in this order:**
  1. **Status first.** If `!status.ok`, fail with `` `${status.detail} — run \`gh auth login\`` ``, the exact sentence at `onboard.ts:355-356`. Then check `ghScopeGap(status)` (`onboard.ts:358`) and fail with its sentence. A missing `repo` scope makes private repositories silently vanish from `/user/repos`, which would look like a short list rather than an error.
  2. **Pages.** Page through `/user/repos?affiliation=owner,collaborator,organization_member&per_page=100&page=N` and stop when a page returns fewer than 100. This uses the page-length rule `installationRepositories` uses (`app.ts:383-397`), so there is no `Link` parsing. It is also why the reader can return a body only.
  3. **The cap.** The cap counts **fetched** entries: at most 10 pages, 1000 repositories, 10 requests. If page 10 is full, set `more: true` and stop. Do not throw the way `MAX_PAGES` does at `app.ts:362`: the ticket wants the list shown together with a sentence.
  4. **The filter, after fetching:** keep an entry only if `archived !== true && permissions?.push === true`. Archived is checked first, as at `onboard.ts:395-399`. A null `permissions` fails `=== true` and is left out.
- **`ListedRepository` for `gh`:** `owner: owner.login`, `repo: name`, `private`, `slug`, plus `onboardedAs`. This is the same shape as the App's entries.

### Running the Effect from the CLI without a new `Effect.run*`

`apps/cli` is at `"run": 6`. A `livePicker` that calls `Effect.runPromise` makes it 7, and a raised baseline is a blocking finding. Use the pattern CLAUDE.md names, `Effect.runPromiseWith(yield* Effect.context())`; the ratchet's `RUN` regex excludes `…With` (`effect-ratchet.test.ts:55`):

- The `add` handler at `apps/cli/src/cli.ts:160-174` is `Effect.promise(async () => …)` today. Make it an `Effect.gen` that takes `const run = Effect.runPromiseWith(yield* Effect.context<never>())` and hands `run` into `liveAddWorld(run)`.
- `liveAddWorld` passes `run` down to wherever the list is read.
- `livePicker` stays the one `async` it already is (it is counted), and calls `run(listRepositories(…))`.
- **Add no new `async` keyword in `apps/cli/src`**, arrows included. `"async": 426` is exact, and the check also fails when a count goes *below* its baseline. `packages/conductor` must drop from 202 to exactly 201, since the moved `listRepositories` was `async`. Paste the numbers the red prints, and check that the sum still holds.

### Where `lingtai add` offers the list: at the exit 2, then add the picked slug as if it had been typed

**The pick cannot go inside `chooseFirstProject`.** `askBeforeGithubAdd` asks the recipe questions and runs the `gh` access check, and it runs only when `add.ts` already holds a slug (`add.ts:71-76`). `add.ts:123`'s card needs `asked !== null`. A slug picked inside `first-project.ts:833` or `:927` would skip both.

**The pick also cannot come before `chooseFirstProject`.** The GitHub-or-local question (`first-project.ts:306-320`) and the auth question are asked inside it.

So the list goes where the refusal is now, `add.ts:87-95`:

- When `result.project === 'github' && result.slug === undefined` **and** `world.githubDeps.interactive()` **and** no App outcome is pending (a skipped or abandoned App creation still exits 2 as today):
  1. Read the list.
  2. Ask through `question()` with `choices`: offerable slugs (`onboarded === null`), then a last choice, `type owner/repo`, which falls through to a text question.
  3. Call `addFlow({ ...flags, github: picked }, world)` again.

  The second pass is exactly `lingtai add owner/repo`: the access check, the recipe questions and the card. Nothing about the slug path is written twice. The auth question was already settled and persisted on the first pass (`first-project.ts:916-921`), so it is not asked again.
- When `more`, print *more not shown — type owner/repo* above the choices.
- When the read fails, print the error sentence and offer only `type owner/repo`. The list's failure never blocks typing.
- On an App machine with an empty `picker.installations`, print `installUrl` and keep exit 2. Installing is out of scope.
- **Non-interactive:** unchanged, exit 2 with the same sentence. A script never sees a prompt.
- Answering *on both machines* is what `listRepositories` promises, so the App machine gets the same offer. The App list is the existing one, flattened across installations.

### Edges this note decides

- **A failed or timed-out page partway through:** the whole read fails with that page's sentence. A partial list is not shown as though it were the list.
- **`gh` signs out between `status` and the token:** `ghToken`'s own sentence, as the comment at `onboard.ts:388` already expects.
- **Restart, pause, two passes:** do not apply. Nothing here writes, and nothing touches `events`. This is the module's existing rule (`pick-repository.ts:21-25`).
- **Cost to later tickets:** the two exact ratchet numbers above. `doc/tamper-watch.md` already holds `packages/setup/**` (#967), so nothing changes there.
