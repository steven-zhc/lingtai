### The one guard to add

§6 already says *"A test that binds a fixed port is a defect at N > 1."* Today that is prose, and nothing enforces it. Make it a unit test, in the same style as `packages/event-store/unit/on-postgres.test.ts`, which holds a list to the code. The test reads every `{apps,packages}/*/{unit,integration}/**/*.test.ts?(x)` file as text and fails on a `.listen(` whose first argument is a non-zero numeric literal or a constant bound to one. Reading test files as text is pure, so it belongs in the unit half. Put it in `packages/event-store/unit/` beside its sibling, or in `apps/cli/unit/`; the agent can choose. Its claim has to stand in for the integration half, which a pass cannot run, so cite it from §6 by its path.

### The two-worktree check

This is the "Done when" item that is easiest to fake, so be specific about it:

- Make the second checkout in a fresh `mktemp -d`, as a detached worktree of `HEAD`, then run `pnpm install --frozen-lockfile --offline` there.
- If the agent's tier refuses the `git worktree add`, because it writes the shared bare repo's `worktrees/` (`codex.ts:894-932` describes exactly that refusal), use an APFS clone of this worktree instead (`cp -cR`) and say so in the PR.
- Start `HOME=/nonexistent pnpm test` in both at the same moment, in the background, writing to two log files, then wait for both. Quote the two vitest summary lines in the PR. The ticket asks the PR to report what collided, and "nothing" with both summaries is the expected answer.
- Remove the second checkout afterwards: `git worktree remove` if it was a worktree.
- Do not run `pnpm test:integration` in either checkout. That half is where the ports and the Postgres sharing actually live, but it takes 803s and a pass cannot reach it. The port guard above is the unit-level claim that stands in for it.
