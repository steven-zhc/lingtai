# Design: #1112, `first-project.ts` becomes Effects over Effect ports

Line numbers below are from this worktree. They have moved a few lines from the ticket's `8abc8613`. For example, `runEffect` is at `:1260`, `livePicker` at `:1248`, and `writeAuth` at `:1350`.

## 1. A face is exactly `return Effect.runPromise(call(...))`, not `runEffect`

The ratchet recognises a face by its shape. The comment at `effect-ratchet.test.ts:10-15` says: *"A face is an exported function whose whole body is `return Effect.runPromise(<call>)` … The shape is checked, not trusted"*. `face()` (`:167-268`) refuses:
- a body with more than one statement;
- a run whose name is not `runPromise`;
- a first argument that is not a call.

`RUN` at `:69` excludes the `*With` runs, so a face written as `return runEffect(x(...))` is refused with *"does not return a call to `Effect.runPromise`"*. Write the five faces this way:

```ts
export function chooseFirstProject(world, flags, buildFlags = [], deferRecipeFlags = false) {
  return Effect.runPromise(chooseFirstProjectEffect(world, flags, buildFlags, deferRecipeFlags))
}
```

Write `liveGit`, `pathExists`, `liveRepositoryList` and `livePicker` the same way. Defaults are allowed in the parameter list, but nothing may come before the `return`.

The callers see the same rejection they see today. `runPromise` throws `causeSquash(exit.cause)` (`node_modules/.pnpm/effect@4.1.2/.../dist/internal/effect.js:2579`), so `init.ts:649` and `add.ts:221` get the same error object. A defect raised inside, such as a failed `loadAllProjectsEffect`, also reaches them as its own error, as `loadAllProjects()`'s rejection does now.

## 2. One helper for the nine `try` blocks, and it is `Cause.squash`, not `Cause.pretty`

Copy the pattern of `doctor.ts:251-262` (`recovering`) into a local function in `first-project.ts`. Call it something like `refusingOn(effect, (err) => …)`. It is `Effect.catchCause` where:
- `Cause.hasInterruptsOnly(cause)` passes the cause on through `failCause`;
- everything else becomes `onFail(Cause.squash(cause))`.

It has to be `squash` because the sentences depend on the error being the same object the old `catch` saw:
- `errorText(err)` (`:482`) reads `.message`.
- `:977` tests `err instanceof SetupWriteError` to decide whether to add `keptSentence(path)`.
- `:1151` reads `(err as Error).message`.

`squash` returns the failure for a failed cause and the defect for a died one. That is exactly what `runEffect` rejected with, so every sentence keeps the same text. Use the helper at all nine sites, including `pathExists`'s code check (`:132-134`) and `liveGit`'s `{ ok: false }` (`:1218-1221`). That keeps a single rule in the file, and nobody has to argue site by site that `Effect.catch` happens to be safe.

**The trap is at `:963-967`.** That is the second read of `world.projects()` inside `exclusiveAdd`. Today it is `Effect.tryPromise({ …, catch: (err) => new SetupWriteError(\`could not read the projects: …\`) })`. Once `projects` is `loadAllProjectsEffect()`, the error type is `never` (`packages/conductor/src/projects.ts:74`), so a store failure arrives as a **defect**. Keeping a `.pipe(Effect.mapError(...))` there would see nothing. The defect would then reach `:977` as a plain `Error`, and the refusal would gain the ` — <keptSentence>` tail.

Map it with the same `catchCause`, so a store failure still produces `could not read the projects: <message>` with no tail.

`liveInFlight` over `readTasksEffect` (`task-view.ts:1016`) is the same case. Its store failure may be a defect, and `:743` must still say `could not read the board to check for an attempt of … — <message>`. That is the Done-when test.

## 3. Which members become Effects

The ticket's list leaves out one member, and four members stay as they are:

- **`github.picker`** (`:202`, read at `:1159`) is IO and becomes `() => Effect<Picker, unknown>`. The live one is `livePickerEffect()`, and `livePicker` is its face.
- **`files: RecipeFiles`** stays a promise port. It is `@lingtai/recipe`'s seam (`packages/recipe/src/write.ts:24-33`), handed straight to `previewSetup`/`applySetup`/`readRecipeKey`. The direct reads at `:605`, `:699` and `:808` become `Effect.tryPromise({ try: () => world.files.read(p), catch: (e) => e })`. Each of those three is outside any `try` today, so a rejection there still fails the Effect and reaches the caller through the face, as it does now.
- **`github.auth`** stays synchronous. `locker` is passed through unchanged. `setupReader` is already an Effect reader (CLI-20, `:1280-1286`).
- `readRecipeKey` (`:539`, `:570`) and `resolveLocalRecipe` (`:928`) are yielded as `readRecipeKeyEffect` (`write.ts:204`) and `resolveLocalRecipeEffect` (`local.ts:305`). `resolveLocalRecipeEffect`'s `options.read` is still a promise reader, so `:933` stays as it is (it uses `Promise.resolve`, not `async`). Leave those two faces' entries alone: their `why` already names the whole apps/cli setup group.

`register` stays exactly as it is passed to `applySetup` today: an Effect, with the rejection mapped to an `Error` (`:946-957`). It now returns the port's own Effect, `addLocalEffect(...)` live. Keep the `instanceof Error ? err : new Error(String(err))` mapping on the lifted side only, which is `init.ts` and the tests.

`github.writeAuth`'s live member is `async` around a **synchronous** throw from `writeGithubAuth` (`:1350-1352`). Make it `Effect.try({ try: () => writeGithubAuth(...), catch: (e) => e })` so the failure is typed. The helper would catch it as a defect anyway; `Effect.try` just makes the intent visible.

## 4. `spunEffect` goes in `question.ts` beside `spun` (`:45-48`)

```ts
export const spunEffect = <A, E, R>(world: { spin?: QuestionWorld['spin'] }, label: string, effect: Effect.Effect<A, E, R>) =>
  world.spin === undefined
    ? effect
    : Effect.gen(function* () {
        const ctx = yield* Effect.context<R>()
        return yield* Effect.tryPromise({ try: () => world.spin!(label, () => Effect.runPromiseWith(ctx)(effect)), catch: (e) => e })
      })
```

The pattern is `approve.ts:77`'s, and the ratchet does not count it. It has two users here: `:1074` and `:1185`, both `world.github.add`. The `tryPromise` catch receives the *squashed* error from the inner run, so the outer error type is `unknown`. That is fine, because neither site catches; both let it propagate as today. The inner run starts inside `spin`'s `fn` and ends there, and `liveSpin`'s `finally` (`prompt.ts:133-…`) still clears the spinner.
