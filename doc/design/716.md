# #716: the shape

## 1. Timing goes into `runDoctor` through one local `step`, and `ms` is stamped by index range

Today every row goes in as `results.push(await …)`, `results.push(...(await …))` or a plain `results.push({...})` (`apps/cli/src/doctor.ts:2617-2795`). Some calls return one row, some return an array (`schema`, `projectRecipes`, `declaredEnvironment`, `recipeGovernsItsBase`), and some return nothing (`projectFiltersOnce`, `issueTitles`). So `step` should not inspect the return value. It should watch `results`:

```ts
const step = async <T>(label: string, run: () => T | Promise<T>): Promise<T> => {
  const from = results.length
  reach.onProgress?.({ label, phase: 'start', done: from })
  const t0 = performance.now()
  const value = await run()
  const ms = Math.round(performance.now() - t0)
  for (let i = from; i < results.length; i++) results[i] = { ...results[i], ms }
  reach.onProgress?.({ label, phase: 'end', done: results.length })
  return value
}
```

The push stays **inside** the step: `await step('GitHub', async () => results.push(githubCredentials(env)))`. A step that returns a value (`filters`, `titles`) pushes nothing, so it stamps nothing and `done` does not move. That is how "rows from one call share that call's `ms`" falls out without a special case.

**Every push goes through a step, the synchronous ones included.** That covers the SEA literals, `packages load`, `storeRow`, `envResult`, `postgresOnlyRows`, the `postgres` skip and the `DEFERRED` loop. The ticket's first Done-when says *every result carries `ms`*, and a row that skipped the wrapper would be the one exception to that test. A synchronous row stamps `0` and renders as ` <0.1s`, which is true. Labels are short nouns for `checking <label>`: `Node`, `the store`, `recipes`, `the log`, `projections`, `the daemon`, `spend`, `GitHub`, `runtimes`, and so on. Rows may share a label across steps.

**A step that throws emits no `end` and stamps nothing.** The rejection goes up to the `cli.ts` handler as it does today, and that handler's `finally` clears the line. Do not put `end` in a `finally` inside `step`: it would draw one more frame for a pass that is already dead.

The step order is the push order and stays that way. `--json`'s `checks` is *"in the order they ran"* (`doctor.ts:3013`).

## 2. Types

- `CheckResult` (`doctor.ts:150`) gains `ms?: number`, optional. Every row a check builds today has no `ms`, and `runDoctor` adds it, so none of the check functions change.
- `DoctorReach` (`doctor.ts:944`) gains `onProgress?: (p: DoctorProgress) => void`. Export the type `DoctorProgress = { label: string; phase: 'start' | 'end'; done: number }`.
- `doctorReport(opts: { onProgress?: … } = {})` (`doctor.ts:2824`) has to pass a **whole** reach: `{ sea: probeSeaBuild, onProgress: opts.onProgress }`. **Trap:** today it passes no reach, so the default `{ sea: probeSeaBuild }` applies (`doctor.ts:2615`). Handing over `{ onProgress }` alone fails `tsc`, because `sea` is required through `Pick` on purpose (`doctor.ts:965-972`, #212). A cast here would spawn nothing extra, but `sea` would be `undefined` and `reach.sea()` would throw.
- `restart.ts:689` and `world.ts:293` still call `doctorReport()` with no argument, which is unchanged, as the ticket's Edges say.

## 3. The renderer lives on the CLI side, never in `doctor.ts`

`doctor.ts` is what `restart` gates on, and it must not draw anything. Put a new export in `apps/cli/src/steps.ts`, which already owns `Spinner` and `oraSpinner` (`steps.ts:28-53`):

```ts
export function doctorProgress(how: {
  stdout: { isTTY?: boolean }
  stderr: { isTTY?: boolean }
  json: boolean
  spinner?: () => Spinner
} ): { onProgress: (p: DoctorProgress) => void; clear(): void }
```

- `live = !json && stderr.isTTY === true && stdout.isTTY === true && coloured(stderr)`. `coloured` takes `{ isTTY?: boolean }` (`packages/env/src/colour.ts:57`), so a fake stream works, and the caller passes the real streams.
- When not live, both methods are no-ops and no spinner is ever built.
- The spinner is built on the first `start`. A `start` moves the message to `checking ${label} · ${done} done`, and an `end` moves only the count. Pass `phase` through to the fake spinner calls so the test can count them.
- `clear()` calls `spinner.clear()` and is idempotent.
- The default spinner is `oraSpinner(process.stderr)`.
- Importing `DoctorProgress` from `./doctor.ts` must be **type-only** (`import type`). `cli.ts` loads `doctor.ts` lazily in the handler (`cli.ts:99`), and a value import from `steps.ts` would defeat that.

Nothing here installs a listener, touches stdin or exits. `oraSpinner` already turns off the two options that would (`steps.ts:34-41`), and 0121 §10 says: *"A spinner … never installs a signal listener and never calls `process.exit`."*

## 4. The `cli.ts` handler

Around `cli.ts:100-108`, the progress object is created before `doctorReport`, and its `clear()` goes in a `finally` that encloses both calls:

```ts
const progress = doctorProgress({ stdout: process.stdout, stderr: process.stderr, json: args.json })
try {
  const report = await doctorReport({ onProgress: progress.onProgress })
  // release: the same start/end, timed here, stamped on the one row
} finally { progress.clear() }
// render or printJson after the finally — the line is gone before the report prints
```

- **The release row gets its `ms` in the handler.** `releaseCheck` runs outside `runDoctor` on purpose (`cli.ts:102-105`), and it is the one network fetch. Emit `{ label: 'releases', phase: 'start', done: report.results.length }`, time it, and push it as `{ ...row, ms }`.
- `printJson` and `renderDoctor` must run **after** `clear()`. Otherwise ora's last frame and the report interleave on a terminal.
- The existing outer `try`/`catch` (`cli.ts:97`, `:114`) stays where it is. The new `finally` sits inside it, so `failed('doctor', …)` prints after the line is cleared.

## 5. `init`

The call is in `liveInitWorld`'s `doctor` callback (`init.ts:1104-1108`), not in `runInit`. Wrap it there the same way: `doctorProgress({ stdout: process.stdout, stderr: process.stderr, json: false })`, `try`/`finally clear()`. `init` takes no `--json`, so `false` is literal. The `InitWorld.doctor` signature (`init.ts:239`) is unchanged, and so is every fake world in the init tests.

Nothing else draws while that call is in flight. The lines before it are `world.log`, which is `console.log` (`init.ts:1029`), and `liveSpin` is not running there. So two spinners never overlap.

## 6. Rendering the time

- **`renderDoctor` (`doctor.ts:2941`), verbose branch only (`:2986-2992`).** Append the time to the name line: ``${marker(r.status)}  ${r.name}${r.ms === undefined ? '' : paint.muted(` ${seconds(r.ms)}`)}``. `paint.muted` is dim (`colour.ts:107-108`). `seconds` gives `<0.1s` when ms < 100, otherwise `(ms / 1000).toFixed(1) + 's'`.
- The short view (`:2960-2985`) gets nothing. That is also what `init`'s `formatReport` uses (`:3010`), so the init text is unchanged too.
- **No `ms`, no suffix.** That keeps `doctor-render.test.ts:155-159` green as it stands, because its fixture rows carry no `ms`. Add a separate case beside it with an `ms` on a row, under `NO_COLOR=1`.
- **`doctorJson` (`doctor.ts:3020`)**: spread `...(r.ms === undefined ? {} : { ms: r.ms })`. That way the `toEqual` fixture at `doctor-render.test.ts:50` stays as it is. Do not write `ms: r.ms ?? null`: that would change every pinned document for no reader.
