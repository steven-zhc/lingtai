# Design note: #918, the running panel's *last event* line and *possibly stuck* warning

Code cited at `3aa2a29a`. That commit already contains #916 (meters) and #917 (quoted lines), so this change has nothing to wait for. The ticket's line numbers are from `9c0276dc`. Where they have moved, the ones below are current.

## Where it goes: the panel view, not a new `loadTask` prop

The ticket says `loadTask` hands the panel `lastEvent`. The running panel is not built in `loadTask`. It is built in `readAttempts`, at `apps/board/src/lib/task.ts:1764-1773` (`standing.running = runningPanelOf(enriched, {...})`). Every stream is in scope there (`streams`, read at `:1707-1712`). So the data goes on `RunningPanelView` (`apps/board/src/lib/running.ts:29-52`), next to `meters` and `said`. It does not become a separate prop threaded through `loadTask`.

Add one field: `watch: RunningWatch | null`. It holds what `stuckOf` needs that the panel does not already carry:

```ts
interface RunningWatch {
  runId: string
  lastEvent: { at: string; sentence: string } | null
  /** progress.now: since and budgetMs as numbers. Meters.round only has budget in words (running.ts:24). */
  phase: { since: string; budgetMs: number | null } | null
  /** run.stepNow, reduced to what the rule reads. */
  step: Step | null
}
```

`runningPanelOf` takes the newest envelope as a new optional argument, because it is pure and has no stream. `task.ts` passes `streams[runs.indexOf(enriched)]?.at(-1)`. Index the stream by the claim, not by the `runs` position, if those can differ: `readAttempts` builds `states` with `claims.map((_, i) => reduceAttempt(streams[i] ...))` at `:1718`, so the claim index is the one to use.

For the sentence, call `summarise(envelope, { attempts })` (`apps/board/src/lib/history.ts:768`). `LineContext` needs only `attempts` (`history.ts:101-114`); the other fields are optional. Build `attempts` as `new Map(claims.map((c, i) => [c.runId, i + 1]))`, which is how the tabs are numbered at `task.ts:1723`. A `ProposalRouted` as the newest event has no `endedAt`, so it will say its evidence was not found. That is acceptable here.

The other call site, `task.ts:894` (`runningPanelOf(run, null)`, the home/card path), passes no envelope and gets `watch: null`. The ticket puts the home card out of scope.

## `stuckOf` reads the watch, not `AttemptView`

`stuckOf({ now, watch, writing }): Stuck | null` goes in `running.ts`, pure. It returns a discriminated union `{ kind: 'unwritten' } | { kind: 'overdue'; overMs; budgetMs } | { kind: 'quiet'; quietMs }`, which the component turns into words. The unit test then pins kinds and numbers, never sentences, as the ticket asks.

`phase` comes from `progress.now`. `budgetMs` is non-null only for the agent (`AGENT`) and a fix round (`apps/board/src/lib/progress.ts:452`, `:459`). It is null for the merge-lane wait (`:447`), for an approval (`:442`), and for every other step (`:460`). So the ticket's *Overdue only where there is a budget* falls out without a step check.

`Quiet` keys on `step === 'implement'`. That covers round 0 and fix rounds, because a fix round is `implement` with `round > 0` (`running.ts:99`).

## The non-obvious part: `writing` is dropped today

`FollowedLog` destructures only `{ lines, state }` from the tail (`apps/board/src/app/run-log.tsx:384`), and `FollowedContext` carries no `writing` (`run-log.tsx:338-349`). The ticket assumes `writing` is already available from the shared tail. It is not.

- Add `writing: boolean | null` to `Followed` and pass it into the provider.
- Expose it as `live ? writing : null`. When `shown` is a run that has ended (`heldRun`, `run-log.tsx:322`), the tail is about a log nobody holds any more. Reading `false` from it must never produce `Unwritten` on a page that has left `running`.

`useLogTail` already parses `event: writer` into `writing` (`run-log.tsx:159`, `:194`). The route already sends it. There is no route change.

## The component

Make a client component, `LastEvent` or similar, in `run-log.tsx`. It must sit inside `FollowedLog`'s context, and `run-log.tsx` is where that context is consumed (`SaidLast`, `RawRunLog`). Draw it in `RunningPanel` directly under `<Meters …/>` (`apps/board/src/app/standing.tsx:297`), with `view.watch` and `serverNow` as props.

- **Clock:** copy `Since`'s pattern (`apps/board/src/app/since.tsx`). Start at `serverNow` so the server render and the first client render agree, then switch to `Date.now()` on mount and tick once a second. One `now` state drives both the age text (`sinceText(lastEvent.at, now)`) and `stuckOf`. Do not nest a `<Since>` beside a second interval for the warning; one interval keeps the age and the warning on the same second.
- **Key:** use `` key={`${watch.runId}`} ``. Do not key by `lastEvent.at`. An append changes the props and the age is recomputed from the new `at`. The interval survives.
- **Warning:** render `<p className="refusal">Possibly stuck: …</p>`. That class is the existing refusal style (`standing.tsx:191`). Never use an `--advised` or amber class.
- **Not following:** read `useFollowing()` (`apps/board/src/app/live.tsx:258`, used the same way in `apps/board/src/app/discussion.tsx:325`). When it is false, append *(this page is not following the log)*.

`Done when` asks for "a fake clock moved forward changes the text without new props". `renderToStaticMarkup` runs no effects, so that test needs a client render: whatever the board's existing `.tsx` unit tests use for hooks, with `vi.useFakeTimers()`. Check for an existing test of `Since` first and follow it. If the board has no DOM-rendering unit test at all, the stand-in is this: export the pure `(watch, writing, now) → { text, stuck }` function the component calls, test that, and say so in the commit.

## Edges the ticket leaves to the implementer

- **The newest envelope is `RunFinished` or `StepEnded` of the last step while the page still says running.** That happens in the window before the claim is released. `watch.step` is null between steps, so `Quiet` cannot hold. Only `Unwritten` can, and that is true there too.
- **Seconds versus minutes.** `sinceText` decides the wording, so a 40-second age reads however the meters read it. Do not add a second formatter.

No ADR is touched. The 0118 §2 running bullet already names this line, and the ticket's 0111 §13 reading of the `writer` bit is the operator's (2026-11-05).
