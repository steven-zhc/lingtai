## Design note — #765

**Where the tables go.** Put them in `packages/conductor/src/report.ts`, next to `PURPOSE_WORDS` (`:343-349`, which is not exported yet). Export `PURPOSE_WORDS` together with three new tables: `REASON_WORDS`, `RESOLUTION_WORDS` and `CAUSE_WORDS`. Type each new one as a `Record` over the domain tag union (`WaitReason['_tag']`, `Resolution['_tag']`, `RootCause['_tag']` from `@lingtai/domain/wait`), so a missing row is a `pnpm typecheck` failure.

Read the tables through one small exported helper per table, taking `string` and falling back to the tag itself. The values handed in are strings, not unions: `sentenceOf`'s parameter is `waits: { reason: string }[]` (`report.ts:359`). The existing tests feed it tags that aren't wait reasons at all, so the fallback is not hypothetical:
- `packages/conductor/unit/report.test.ts:326` expects `waited once (X)`.
- `report.test.ts:280,315` and `apps/cli/unit/report.test.ts:246` use the *cause* tag `FixableLines` as a `reason`.

Keep `:326` passing unchanged as the unknown-tag test: `X` must still print `(X)`. The other two need real reason tags once their expected strings are in words.

**`sentenceOf`.** Change only the line that maps a reason to its label (`report.ts:371`). Use `for ${words(r)}` instead of `r`, and keep the `×n` suffix and the count-then-sort order exactly as they are. The board shows `t.sentence` unchanged (`apps/board/src/app/report/panels.tsx:220`, whose header says "the top eight's sentence is `TopTicket.sentence`, unchanged (0123 §4)"). So the board picks up the new sentence with no edit of its own.

**CLI** (`apps/cli/src/report.ts`):
- **Survival headers (`:203`):** only the header strings change. `s.censored` stays the field name, because it is also `--json`'s key.
- **"most fix rounds" (`:241`):** filter into a local variable, then test that variable's length instead of `r.top.length`. That way an empty result leaves out the heading too, not just the rows.
- **`spent on:` (`:250`):** look up `PURPOSE_WORDS`.
- **Wait line (`:252-255`):** write it as `waited for <reason>`, then ` · triage: <cause>` only when `cause !== null`, then ` · <resolution or 'still waiting'>`. After this change `DASH` (`:117`) is used only by the number formatters, so leave it in place.

**Board.** `panels.tsx:223` and `:228` read the same helpers. The wait × cause table at `panels.tsx:88-127` also prints raw tags (`{c ?? 'no triage cause'}` at `:107`, and the reasons as row labels). The ticket's Out of scope names only the two lines, so leave that table alone.

**The agreement test goes in `apps/board/unit/`, not `packages/conductor/unit/`.** The board depends on the conductor (`apps/board/package.json:16`, `"@lingtai/conductor": "workspace:*"`), not the other way round. A conductor test importing `apps/board/src/lib/triage-cause.ts` would create a reverse dependency.

`CAUSES` in that file is not exported (`triage-cause.ts:10`). Use `presentCause({ _tag })` (`:19`) for each key of `CAUSE_WORDS`, and assert that `label.toLowerCase()` equals the word. Iterate over `CAUSE_WORDS`'s keys: its `Record` type already guarantees that every `RootCause` tag is there.

**Tests that assert today's strings and must change in this commit:**
- `apps/cli/unit/report.test.ts:256-257` (`spent on: Answering 75% · Work 25%`, `wait: FixableLines · cause …`).
- `packages/conductor/unit/report.test.ts:318`, the `FixableLines ×2` sentence.

Also grep `apps/board/unit/report-panels.test.tsx` for `waited for` before you finish. Its fixture at `:147` uses `ReviewFindings`, which is not a reason tag, so if anything asserts on it, it will print as the fallback.

**ADR.** `0123` is in `doc/decisions/`, the edited-in-place series ("a decision that changes is an edit to its topic's ADR", CLAUDE.md). So the right change is an edit, not a superseding file. Change §4 (`doc/decisions/0123-the-report-counts-what-the-log-holds.md:145-153`) in two places:
- Its first sentence should say that the terminal lists only tickets with at least one fix round, while the board's list, sortable by cost, still holds every ticket.
- Its example should read `waited 3 times (for a call between the fixer and the reviewer ×2, for a decision on a refused merge)`, or any example that uses real reason tags. The current example uses cause tags as reasons, which is the same mix-up as the tests.

**Verification.** Every claim here is checked by the unit half: `pnpm test`, `pnpm typecheck`, `pnpm lint` and `pnpm fmt:check`. Nothing needs the integration half or the log.
