## Design note for #919: the history strip

**The code has moved since `9c0276dc`, and three of the ticket's instructions now point at the wrong thing.** Read the ticket for what to build. Read this note for what to read it from.

### 1. Read refusals and rounds through `boardFactOf`, not through `verdictOf` and `routeNext`

`boardFactOf(event, endedAt)` (`packages/domain/src/read-model.ts:286`) is now the domain's single per-event reading of everything the strip keeps from a run stream:

- **Refused.** For a `StepEnded` it returns one `StepEnded` fact per reached action. The fact carries `ending: 'Failed'` and `findings` taken from the verdict's assessment (`read-model.ts:270-283`). `findings` is `undefined` for an action that does not yield a verdict, and that is the ticket's *<step> failed*.
- **Round.** For a route it returns `RoundOpened { round }` when `routeMove` answers `FixRound` (`read-model.ts:310-331`).
- **Both route shapes.** It reads **both** `PassRouted` and `ProposalRouted`. `ProposalRouted` is the #932 form, which does not repeat the proposal and names its `StepEnded` by `offer.ended.version` instead (`events.ts:1456-1480`). A strip that switches on `PassRouted` alone, as the ticket's Fix says, draws no round for any route written since #932, and nothing on the page would show that anything is missing.

`history.ts`'s `read` already goes through `boardFactOf` first for exactly this reason (`apps/board/src/lib/history.ts:735-751`).

**Pass it each run stream's own `endedAt`**: `stepEndedsOf(stream)` (`packages/domain/src/attempt.ts:667`), built once per stream as `groupHistory` does (`apps/board/src/lib/task.ts:1389`).

- The strip does not need the round's findings, because the refused item before it already counts them.
- Without the right `endedAt`, every `ProposalRouted` round comes back with `findingsUnknown` set. That is harmless here, but it is wrong.
- `routeMove` throws `ImpossibleRouteError` on a triple it cannot replay. The ticket says not to catch it, so don't. `reduceAttempt` already throws on the same stream (`attempt.ts:516-524`), so the page could not render without it anyway.

**Do not call `boardFactOf` for the waits.** Its `WaitStarted` branch runs `waitWords` to build a question the strip does not print (`read-model.ts:349-361`). `WaitStarted` and `WaitResolved` are read from their payloads (`events.ts:339-358`).

### 2. A continuation is also `TicketContinued` now

`claimShapeOf` answers `continuation` for a `TicketContinued` by type. It answers the same for the old form, a repeated `runId` on `TicketClaimed` (`packages/domain/src/claims.ts:22-28`; the event is `events.ts:244`).

Keep a per-stream `claimed` set exactly as `groupHistory` does (`task.ts:1408-1416`): only a `claim` adds to it. Then neither form of continuation becomes an *Attempt N*. Add one fixture of each form to the Approve test, because the ticket's Done-when only names the old one.

### 3. The attempt map is the one the tabs are numbered by

Pass `new Map(runs.map((r, i) => [r.runId, i + 1]))`, as `loadAttemptTab` does (`task.ts:2044`). `runs` comes out of `readAttempts` (`task.ts:1694`).

The ticket's own events need an attempt to link to:

- `TicketClaimed`, `TicketContinued` and `TicketReleased` carry a `runId`. Look that up in the map.
- Every other ticket-stream item (`WaitResolved`, `TicketLanded`, `TicketClosed`, a `WaitStarted` that is not on a run stream) takes the **last attempt the walk has emitted**.
- An item before any claim has `attempt: null` and no link. This is the ticket's *an attempt* edge, reached from the other side.

### 4. One fact, one item: restarts and requeues are written twice in the log

A restart decided at `proposed` appends `ProposalRouted { decision: Selected{restart} }` on the run stream. It **also** appends `TicketReleased { cause: Restart{restart} }` on the ticket stream (`events.ts:1474-1476`), and `boardFactOf` answers `Restarted` for the route (`read-model.ts:333-339`). A person's requeue is a `WaitResolved` followed by `TicketReleased { cause: ByPerson{waitId} }` (`events.ts:265-270`).

Decision:

- **Ignore the `Restarted` fact.** The `TicketReleased` is the one *ended* item.
- **A `ByPerson` release draws nothing.** The *decided* item just before it already says what happened, and the next *Attempt N* says what followed.
- **Word the remaining releases from `cause`, not from `reason`:**

| `cause` | Item text |
|---|---|
| `Restart` | *started over (restart N)* |
| `NeverStarted` | *never started* |
| `ClaimUnconfirmed` | *claim not confirmed* |
| `null` (older events) | *released: \<reason, clipped\>* |

Fixture test: a review refusal, a route to restart, then attempt 2. It must show exactly one *started over* between the refusal and *Attempt 2*.

### 5. A step with several refused actions

`boardFactOf` returns one fact per action. Emit one item per action whose `ending` is `'Failed'`:

- Word it *\<step\> refused…* when it is the only failed action in that `StepEnded`.
- Word it *\<step\> · \<action\> refused…* when it is not, the way `history.ts`'s `stepAt` names one (`history.ts:215-217`).

Count the majors as findings whose `severity` is SEVERITIES' most severe value (`packages/domain/src/vocabulary.ts:122`). Do not write a severity name into the code.

### 6. Where it lives and how it reaches `Standing`

- **The function.** `historyStripOf` sits in `task.ts` beside `groupHistory`, as the ticket says. `task.test.ts` already imports `groupHistory` from there.
- **The data.** `loadTask` computes the strip from `shared.own`, `shared.streams` and `runs`, which it already destructures (`task.ts:1868`). It returns the strip on `TaskDetail` (`task.ts:980`). No read is added.
- **The prop.** `Standing` takes `strip?: readonly StripItem[]`, defaulting to `[]` like its other optional props (`apps/board/src/app/standing.tsx:808-833`). The dev waiting gallery and every existing render test then stay unchanged. Only `task-page.test.tsx.snap` moves, and only where its fixture has history.
- **The *now* item.** It is computed in `Standing` from the running attempt's `stepNow` (`task.ts:332`). Use the same test the running panel uses for a fix round: `step === 'implement' && round > 0` (`apps/board/src/lib/running.ts:68`, `:106`). The text is *now: fix round N* or *now: \<step\>*. #919 assumed `stepNow` would land first, and it has.
- **The drawing.** It goes inside `<header className="swaiting-head">`, after the `<Gh>` block that draws the rail (`standing.tsx:1199-1238`). Put it outside `Gh`: the strip is the log's, not GitHub's, so it must not wait on GitHub or vanish into the skeleton fallback (0118 §2: *no GitHub in it*, quoted at `task.ts:1860`). Links go to `/task/<id>/attempt/<n>`, the route at `apps/board/src/app/task/[id]/attempt/[n]/page.tsx`.

### 7. What moves

- Key each item by `seq`.
- On re-render, React keeps the DOM nodes whose keys it already has, so a mount animation fires only on an appended item. Reuse `.arrive`'s keyframes (`apps/board/src/app/globals.css:3098-3100`), which already sit under `prefers-reduced-motion`. Don't add a second animation.
- The whole strip fades in once, on the render where it first qualifies. That is one new thing, and it is allowed to move.

### 8. The hold

The precondition is still open. `doc/decisions/0118-a-hold-explains-itself.md` does not contain the word *strip* (`grep -i strip` finds nothing there or under `doc/decisions/0118/`). If that is still true when the hold is lifted, stop. Naming the strip in 0118 §2 is the operator's step together with the mock, and this ticket must not do it itself.

### Checks

All of this is unit-level: the `historyStripOf` fixtures and the `Standing` render tests. Nothing here needs `pnpm test:integration`.
