**The shape for #786**

**One lag reader in `@lingtai/projector`, beside `readSpend`.** Nothing that reads one projection's lag is exported today without a runner. `projectionLag()` (`packages/projector/src/projection.ts:279-283`) is `store.lags()` for every checkpoint. `runner.lag()` (`:266-268`) is the only per-name reader. Add `readLag(name, options?)`. It is `withProjectionStore({ url, max: 1 }, (s) => s.lag(name))`, shaped like `readSpend` (`spend.ts:318-322`). Export it from `index.ts` next to `projectionLag`. Use `store.lag(name)` and not `lags()`, because only `lag(name)` answers for a projection that has no checkpoint row. Postgres reaches it through `from (select 1) one left join checkpoints` (`postgres.ts:284-297`), and SQLite through `allOrEmpty` on the checkpoint (`sqlite.ts:628-643`). A projection nobody registered therefore reads as `lag = head`, not as missing. The board converts with `Number(r.lag)`, as it does today.

**`currentSpend` runs two parallel reads inside `spend.read`.** They are `timed('spend.lag', () => readLag('spend'))` and `timed('spend.rows', () => readSpend(query))`, run with `Promise.all` because neither waits on the other. The `spend.read` span stays where the callers put it (`task.ts:1879`, `board.ts:1129`), so the two new spans nest under it with no change to the callers. Only the lag read is caught: a throw becomes `{ lag: null, error }`. A throw from the rows read still propagates, as the ticket says. Each reader opens its own store. Do not merge them into one `withProjectionStore` to save a connect, because that loses `readSpend` as the seam the tests mock.

**The missing-table edge is already handled. Add no catch for it.** On a table nobody built, both stores' `spend()` already return `[]`. Postgres catches `42P01` at `postgres.ts:405-409` (*"A database no projector has ever started has no table, and that is no spend rather than a failure"*). SQLite reads through `allOrEmpty` (`sqlite.ts:447-454`, `:744`). The ticket's *"if it throws today on a missing table, catch it"* therefore resolves to *it does not throw*. The lag half is what keeps the result honest: with no checkpoint, `readLag` answers `lag = head`, so the chip says `behind N`. `rows: []` with `lag: 0` happens only on a log that has no events, and then it is true. Do not invent an `error` for this case.

**`report.ts`:** delete `foldToHead` (`:145-162`). `currentReport` (`:174`) runs `readLag('ticket_report')` and `readLag('spend')` through one helper that catches each to `{ lag: null, error }`. Put that helper in `spend.ts`, e.g. `lagOf(name): Promise<SpendCurrency>`, and have `currentSpend` use it too, so the two pages cannot word one failure two ways. `/report` has no `timed` today; adding spans there is optional and not asked for.

**`backlog.ts` is in scope, even though the ticket never names it.** `currentBacklog` (`apps/board/src/lib/backlog.ts:27-45`) is the third `createProjectionRunner` in `apps/board/src`, and both the Fix (*"No runner is started anywhere in `apps/board`"*) and the first Done-when grep count it. The ticket's reason covers it too: `withProjector` follows `finding_backlog` as a secondary (`apps/cli/src/projector.ts:185`, `:257`). Convert it the same way: `readLag('finding_backlog')` plus `readBacklog()`. Keep the page's rule that *nothing open* shows only at `lag === 0`; with that rule kept, reading the table directly is safe.

**Three `behind N` titles change, not one.** `spendChip` (`spend.ts:264`), `reportChip` (`report.ts:209`) and `backlogChip` (`backlog.ts:73`) each say *"arrived after this page folded … — reload to fold them"*. Each one changes to *the table catches up when something next appends with a projector, or `lingtai projection rebuild <name>`*. The `error` titles (*"could not be brought to the head"*, `spend.ts:250`, `report.ts:201`, backlog's equivalent) also describe a fold. Reword them to *could not read <name>'s lag*. Labels and tones stay as they are.
