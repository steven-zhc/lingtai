# Design: #319, telling the agent to commit first and not wait for checks the gate doesn't run

## The decision the ticket doesn't make: the gate's commands come from the recipe, not the prompt text

Both briefs go to agents working on **every** managed project, not only this repository:

- **The implement brief is `prompts/ticket.md`**, not `prompt.ts`. It is one file at Lingtai's own root, used for every project. See `packages/env/src/index.ts:1012`: *"the template is `prompts/ticket.md` at this root — the same file `conduct.ts` reads to run one"*. It is loaded at `apps/cli/src/conduct.ts:106` and at `apps/board/src/lib/prompt.ts:138`. Its wording is project-neutral: *"Run the project's own checks before you finish"* (step 3).
- **`fixBrief` (`packages/conductor/src/fix.ts:439`) is project-neutral too.**

`pnpm typecheck && pnpm test` is not a property of either brief. It is this project's recipe: `~/.lingtai/lingtai/recipe.yml:271`, `run: pnpm typecheck && pnpm test`, under `build:`. If you write `pnpm` into the template, every other project's agent is told a bar that isn't theirs. The agent can't look the bar up either: since #180 the recipe sits outside the worktree.

So **render the bar from `recipe.steps.build`**. Take the `run` string of each action there that has one, narrowing with `"run" in action` the way `conduct.ts:314` narrows `"agent" in action`. For this repository that renders exactly `pnpm typecheck && pnpm test`, which meets the first Done-when without hard-coding it. The recipe is already in scope at every call site:

- implement: `conduct.ts:2601`, beside `recipe.runtime.budget.diff`, which is used at `:2796`
- fix: `conduct.ts:2790`
- board preview: `filter.recipe`, at `apps/board/src/lib/prompt.ts:150`

## One function writes the block, and both briefs use it

Add `checksBrief(commands: readonly string[]): string` to `packages/conductor/src/prompt.ts`. It is pure, like `designBrief` (`prompt.ts:289`). It writes the ticket's two sentences in generic form:

1. **The bar.** *"What the build step runs is `<commands>`, and that is the whole of what this pass is checked against."* Anything else the project has (a slower suite, an integration half, another app's build) is not this pass's to run, and its result is not something this pass owes. Leave the 803 s and 600 s figures in `CLAUDE.md`, because they are true of one project only. If `commands` is empty, say that no check is declared at `build:` and keep sentence 2.
2. **Commit before you verify.** This is the sentence that matters, and it has to name the mechanism `#308` actually hit. Its log shows `ScheduleWakeup` at 02:24:54 and the receipt at 02:25:11: the agent scheduled a wakeup and the run ended under it. So the sentence says: **there is no later turn.** The run ends with your final message. Nothing you start in the background or schedule will wake you. The worktree is released with whatever is uncommitted in it. Commit first; a commit can be amended. Never wait on a background task while the change is uncommitted.

**Implement side.** Add a `{{checks}}` placeholder. Put it in `prompts/ticket.md` in place of step 3's *"Run the project's own checks before you finish"*, which is the vague sentence that let `#249` decide for itself what "the project's checks" meant. Step 4's *"Commit as the work stands"* stays; the new block says *why waiting* is the version of not committing that loses the work.

In `renderPrompt`, `{{checks}}` gets the same rule as `{{failure}}` and `{{design}}`: substituted where the template has the slot, **appended where it doesn't** (`prompt.ts:268–271`). The doc comment at `prompt.ts:215–220` explains why an instruction the agent must receive can't depend on a project's template having the slot. Add it as a parameter, and pass it at **all three** call sites:

- `conduct.ts:2601`
- `apps/board/src/lib/prompt.ts:176`
- `apps/board/src/lib/prompt.ts:187`, the `composed` render. If only one of the board's two calls gets the block, `lineDelta` counts the block as a person's edit.

If the board's preview omits the block, it shows a prompt that is not the one that runs, which is the trap the comment at `prompt.ts:9–12` describes.

**Fix side.** Give `fixBrief` a `checks: readonly string[]` input and put `checksBrief(checks)` right after *"Commit what you fix."* Reusing the same words is fine under 0039 §2: the header and the decline are already shared text, and only the evidence and the criterion differ between prompts.

**The trap on the fix side.** `fixBrief` also says *"If this is not yours to fix, change nothing and commit nothing"*, and that empty commit is how a decline reaches a person (`fix.ts:428–436`). A bare *"commit first"* contradicts it. The fix-side wording must be conditional: **once you have changed anything**, commit before you verify. A round that declines still commits nothing.

## What this does not touch

- **The gate.** The `build:` commands are read, not changed. 0060 is untouched.
- **The prompt version.** It is `ticket@${template.length}` plus the `failure` and `human` hashes (`prompt.ts:150`). Editing `ticket.md` moves the version once. A later change to the recipe's `build:` would change the rendered text without moving the version. Note that limit in the comment rather than widening `promptVersionFor` here.

## Tests (all unit-level; nothing needs the integration half)

- **`packages/conductor/unit/prompt.test.ts`:**
  - Rendering with `["pnpm typecheck && pnpm test"]` contains that command, the "whole of what this pass is checked against" sentence, and the "no later turn" / commit-first sentence.
  - Rendering a template **without** `{{checks}}` still contains them, because the block is appended.
  - Rendering with `[]` still contains the commit-first sentence.
  - The byte-identical first-attempt assertion at `:93` has to change, since the block always renders now. Change that line on purpose and say why in the test.
- **`packages/conductor/unit/fix.test.ts`, "what the fixer is told" (`:194`):** assert the same two sentences in the rendered `fixBrief` separately, plus the conditional wording, so a later edit can't turn it into an unconditional "commit".
- **`prompt-placeholders.test.ts:32`** walks the placeholders, so `{{checks}}` joins that walk.
- **Done when:** `pnpm test` and `pnpm typecheck` green.
