# Design: #1114, `init` becomes an Effect

The ticket's **Fix** row covers the order of the edits. This note covers what the ticket does not: four things it gets wrong or leaves open, and how the golden test is built.

## 1. The golden test comes first, in its own commit

Write `apps/cli/unit/init-golden.test.ts` and its fixture while the base still has `initCommand`, and commit them before any `src` change.

- **The fixture is JSON, imported the way the ratchet imports its baseline.** Use `{ "code": 0, "lines": [...] }`, imported as a module like `import baseline from './effect-ratchet.baseline.json'` (`packages/domain/unit/effect-ratchet.test.ts:25`).
  - Do not read it with `readFileSync`. Under 0060 §1 a filesystem read makes it an integration test, and nothing runs that half before the merge.
  - Do not use `toMatchFileSnapshot` either. `-u` would silently rewrite the reference this ticket exists to hold.
  - Produce the fixture by printing one run's `logged` on the base, pasting it in, then removing the print.
- **Drive it with `ask: acceptingDefaults(...).ask` and flags `--local <FAKE_DIR>` only.** The `--defaults` flag is not enough on its own. It is applied only inside `chooseFirstProject` (`first-project.ts:679`). The store question in `chooseStore` goes through `world.ask` directly (`init.ts:986` `question(world, …)`), so with `--defaults` and no TTY it refuses. That is not the tutorial (#1061), which is `init --local chapter-garden` and Enter at each question.
- **Copy the world's shape from `harness` in `unit/init.test.ts:87-196`.** It is not exported, so write a separate copy in the golden file. Keep its lockfile trick: `setupReader.has('pnpm-lock.yaml')` is true. The comment at `init.test.ts:123-128` explains it: *"`askInstall` … refuses an empty answer outright"*, and under `acceptingDefaults` a repeated prompt answers `null` (`question.ts:117-124`). Without a detected lockfile the golden would record a refusal, not the card.
- **Give the fake world a `spin` that logs `· <label>` and then runs `fn`.** `acceptingDefaults` passes `spin` through (`question.ts:131`), so the golden also checks that every `spun` became a `spunEffect` around the same step, in the same order.
- **Keep the fakes as promises in commit 1.** In commit 2, change only the call (`Effect.runPromise(initCommandEffect(...))`) and lift the world once, with a `liftInitWorld` beside `apps/cli/test/first-project-world.ts:39` (`liftPort`). The fixture's inputs then stay byte-for-byte the same between the two commits.
- **Compare raw lines, without stripping colour.** `paint` writes plain text under vitest, as every existing `init.test.ts` string assertion already depends on.

**What the golden does not cover:** the local path never starts a board (`init.ts:516-519`: *"a local project never calls it at all"*), only `boardAt` at the end (`:764`). One extra unit test stands in for the ticket's board trap:

- Take the `app.configured` path (`:727-738`) with a fake `board` whose release sets a flag.
- Run `initCommandEffect` to completion through `Effect.runPromise`.
- Assert the flag is still false.

## 2. `appeared` and `pressed` change `AppWaitWorld`, not just `InitWorld`

`pollForApp` has a second caller: `liveFirstProjectWorld` (`first-project.ts:1363-1366`, `appeared: pollForApp`). Both reach `waitForAppEffect` through `AppWaitWorld` (`github-app.ts:80-86`), which types the two ports as `(signal) => Promise`.

To delete the face:

- Change `AppWaitWorld.appeared` and `.pressed` to `() => Effect`.
- The race at `github-app.ts:130-133` then yields the two ports directly, instead of `Effect.tryPromise({ try: (signal) => world.appeared(signal) })`.
- `liveFirstProjectWorld` and `liveInitWorld` both fill:
  - `appeared: pollForAppEffect` (`app-check.ts:44`; it already stops when interrupted);
  - `pressed: () => Effect.tryPromise({ try: (signal) => waitForKeypress(process.stdin, signal, …), catch: (e) => e })`.
- Keep the third argument `first-project.ts:1366` passes.

Interruption hands the lifted keypress an aborted signal, so raw mode is still undone (the comment at `github-app.ts:127-128`). The fakes in `unit/github-app.test.ts:165-189` change shape, but no expected string changes.

## 3. `database` uses `recovering`, because the schema fails as a defect

`createSchemaEffect` has type `Effect<SchemaOutcome>` and *"every failure is a defect"* (`packages/event-store/src/schema.ts:185-188`). An `Effect.catch` would let a broken schema escape as a crash and skip the `chooseStore` sentence.

`apps/cli/src/exit.ts:24-34` `recovering` is the helper the ticket's **Watch out** asks for: *"`catchCause` that lets an interruption through … `Cause.squash` is the object `runPromise` threw, so a message read off it is the one it always was"*. Use it, so `why` stays `err.message || String(err)` as at `init.ts:1238`.

To make the Done-when test reachable without Postgres, split it like this:

- `databaseCheck(url, open)` is exported. `open` is `(url) => Effect<Queryable & { connect; end }>`, and the body is `acquireRelease(connect, end)` around `createSchemaEffect`, then `recovering`.
- `liveInitWorld.database` is `databaseCheck(url, pgClient)`, and `pgClient` does `Effect.tryPromise({ try: () => import('pg'), … })` inside it, so the import stays lazy.
- The `end` release ignores its own failure, as `.catch(() => {})` does at `:1240`.

The unit test hands `databaseCheck` a client whose `query` throws synchronously. That is a defect. The test asserts `{ ok: false, why }`, and that `chooseStore`'s settled-store line prints (`:931-939`).

## 4. The board's release stays a defect, with no `Effect.promise`

`serveBoardEffect` (`board.ts:312`) is not scoped. It starts the server and installs the signal handler that runs `options.release` (`:178-180`), and it takes `release: Effect<void>` (`:106`). So `board` yields `serveBoardEffect({ …, release })` with no `acquireRelease` and no `Effect.scoped` around it.

The release today is the face's `Effect.promise(options.release)` (`:316`): a rejected lock release is a defect. Keep that meaning without `Effect.promise`:

```ts
lift(() => kept?.release() ?? Promise.resolve()).pipe(Effect.orDie)
```

Then set `kept = null` as today (`:1273-1276`).

`entry.ts:46-55`'s `process.exit` on an `init` refusal is outside this ticket. Leave it alone.
