## Design for #569

### Most of what this ticket documents has already landed, and one doc is already done

The runtime (#567) and the recipe/doctor/board half (#568) are on `main`. The only text that is still false is ADR 0118 §3. Here is what is true today, which is what the text has to match:

- **Selection.** `Triage.tools: z.enum(['none','full']).default('none')`, refined so that *"tools: full needs agent: codex — only the Codex CLI runs against a checkout"* (`packages/recipe/src/recipe.ts:2961-2962`, `:2989-2992`). `Discuss` is a `z.strictObject` with no `tools` key (`recipe.ts:2905`), so Discussion cannot select tools at all.
- **Dispatch.** `full = agent === 'codex' && tools === 'full'`, and the call is `deps.runtime(agent, { tools: full ? 'full' : 'none' })` (`apps/cli/src/triage.ts:706`, `:732`). The commit is the recorded attempt head, or the base when no head was recorded (`triage.ts:708`). A missing commit fails the triage (`:709-713`).
- **The checkout** (`apps/cli/src/triage-checkout.ts:33-73`):
  - It is made under a `mkdtemp` root in `tmpdir()`.
  - It is a `git clone --no-hardlinks --dissociate --no-checkout` of the bare mirror.
  - `origin` is removed and `core.hooksPath` is set to `/dev/null`.
  - It checks out a detached HEAD, verified against the SHA.
  - The settings file is `{}`.
- **The environment** (`triage-checkout.ts:10-30`): `runnableEnv({})` plus a private `HOME` and `GIT_CONFIG_NOSYSTEM=1`. **`CODEX_HOME` is the user's real one, on purpose.** The comment says *"Codex rotates its refresh token in place, so a copy discarded at cleanup would leave `~/.codex/auth.json` holding a token the server has already spent"*. It also says *"No `LINGTAI_*` value … survives `runnableEnv`"*.
- **Cleanup** (`triage.ts:971-979`):
  - The root is removed on every exit path.
  - **Except** when the runtime reported `process cleanup incomplete` (`triage.ts:883`, from `packages/agent/src/codex.ts:1327`, `:1403`). Then the checkout is **kept** and only logged: *"checkout kept — a tool process may still be running in it"*.
  - A failed removal turns the result into `TriageFailed 'cleanup failed: …'`.
- **Limits:**
  - **The wall is enforced.** Codex `enforces: ['wall']` (`codex.ts:230`), and the triage wall covers the reads too (`triage.ts:521-530`).
  - **Turns are not enforced inside one CLI call.** The remainder is passed in, and `out of turns` is checked between read rounds (`triage.ts:833-839`).
  - **USD is not observed.** `costSpent` grows only from `spendBoundUsd` or a non-null `costUsd` (`triage.ts:896-897`), and the CLI receipt is `costUsd: null`. So `out of usd` (`:827-829`) never fires on this route.
- **Doctor** (`apps/cli/src/doctor.ts:2205-2236`):
  - The CLI route writes `triage: <p> signed in`, asked with the `CODEX_HOME` the run is given. Its detail is *"…disposable checkout of the attempt's head, billed to the Codex login; codex_text is not read"*.
  - It also writes `triage: <p> limits` as `warn`, saying exactly the three limit facts above.
  - The model-only route writes `triage: <p> codex ready` through `codexRoleRow`, which on failure names `tools: full` as the alternative (`:2098-2122`).
- **`config.example.yml:73-97` already shows both bounded triage examples**, with the billing sentence. Leave it as it is unless a fact below contradicts it; I found none. Nothing parses that comment block, so check the two examples by hand against `Triage` (both carry `limits` within the schema).

### Edit ADR 0118 in place. Do not supersede it.

`doc/README.md:77` is the rule for `decisions/`: *"One ADR per topic, each stating what is decided now. A decision that changes is an edit to its topic's ADR."* #565 changed 0106 §6 the same way. Three other places say to supersede instead, and none of them governs this ADR:

- `doc/design/567.md`'s last paragraph (*"needs a superseding file"*) was written against the archive convention. Ignore it.
- So was `README.md:60`, which is the archive row's description.
- So is the pass template's "append-only" line: that rule is the archive's.

Archived 0033 is not touched, and neither is any `decisions-archive/` file.

Make three changes to 0118:

1. **§3, the bullet at `0118:357-359`** (*"off the pass, without the lock, reading the mirror, with no tools"*). Replace it with two routes chosen by `triage.tools`. Keep *off the pass, without the lock* for both.
   - **`none`, the default.** This is the original sentence, unchanged. Claude Code denies every tool. Codex reaches the model-only Responses route, separately billed under `codex_text` (cite 0106 §6 rather than restating it).
   - **`full`, Codex only.** This route is the Codex CLI with its shell, run in a private clone of the mirror at the attempt's head (or the base). State the boundary as **what the checkout protects**:
     - the mirror, its refs and origin cannot be written;
     - no Git hook runs (Codex hooks in the real `CODEX_HOME` still do), and there is no push, merge lane or claim;
     - edits die with the directory.

     Then state **what it does not** protect:
     - host files remain readable by absolute path (`packages/agent/src/runtimes.ts:95-114`);
     - the real `CODEX_HOME` (the login) is in reach by design;
     - the network is whatever Codex CLI's own sandbox gives;
     - a checkout whose tool processes could not be confirmed dead is left on disk rather than deleted.

     Say plainly that this is **not Discussion's containment**. Discussion keeps no tools, and the recipe cannot ask otherwise.
2. **§3's wall bullet (`:398-402`), or a new sentence next to it.** On the CLI route only the wall stops the agent. Turns are checked between rounds, and the dollar limit never fires because the receipt reports none. **The log does not record which route ran.** `WaitTriaged.by` is `Agent { runtime, model }`, and `RunSpent.costUsd` is `null` on both Codex routes (568.md). The route is read from the recipe in force, and doctor and the board say which one it is. Do not write anything implying the event distinguishes the routes.
3. **The Status line.** Add `· §3 amended 2026-10-24 with tool-enabled Codex triage (#569)`, in the same form as the existing *types settled* clause.

Leave the Context's description of Discussion (`0118:26-33`) alone, because it describes Discussion, which has not changed.
