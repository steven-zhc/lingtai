## 1. The plan list goes inside `QueuedBand`, not into its `children`

`QueuedBand` already handles the three cases the list needs:

- `resolved === false`: this is `QueuedPanel`'s `Gh` fallback (`:196-203`). The band already draws `asking` skeletons in that branch (`:98`).
- `view === null`: the band already says *"Its place in the queue could not be read."* (`:116`).
- `view.plan`: the plan itself.

Give `QueuedBand` two new props: `next: number` (`standing.attempts + 1`) and `outgoing: OutgoingView | null`. Draw in this order: `band-facts`, then **What Attempt N will do**, then the closed prompt, then `children` (`LastAttempt`, which stays last). How each case draws:

- **Unresolved:** `<Skeleton shape="lines" count={1} />` where the list goes. No prompt row.
- **`view === null`:** nothing for the plan. The summary has already said it.
- **`view.plan === null`:** `<p className="empty">{UNREADABLE}</p>`, said once. Export `UNREADABLE` from `rail.tsx:381`.
- **A plan:** `<ol className="planlist">` with:
  - one `PlanStep` for each step whose `skipped` is false;
  - one muted `<li>` reading *nothing configured at:* followed by the skipped step names joined with `, `, drawn only when there are any;
  - `<li className="lim">{limits(plan)}</li>`.

Both the list and the prompt sit inside `QueuedPanel`'s existing `Gh`, so they wait for GitHub together and no new boundary is needed.

`planStepLine` and `PlanStep` are exported from `rail.tsx` beside `limits()` (`:425`), because #901 imports them. `PlanStep` takes `{ step, actions, skipped }` and returns `null` when `skipped`.

## 3. Split `Outgoing` into a reader and an editor, without a second copy

`Outgoing` (`outgoing.tsx:53-235`) is one component holding the editor's state (`draft`, `busy`, `refusal`, `run`, `send`). Make two exports out of it, and have `Outgoing` compose them so the blocked and approved pages render exactly as they do now:

- **`OutgoingEditor({ taskId, outgoing, sendable, onEdit? })`** is the code at `:168-232`: the `outedit` line, Edit / Change the edit / Remove the edit, the `outbox`, the refusal, and all of that state. `Outgoing` passes `onEdit={() => reduced && setOpened(true)}` to replace today's inline `if (reduced) setOpened(true)` (`:181`).
- **`OutgoingPrompt({ outgoing, next })`** is stateless. It draws `<details className="asec closedrow">` with no `open`. Its summary is *Prompt for Attempt {next}* · *{bytes} bytes* · *closed: read only to check or edit*, and inside it is `<pre className="outtext">`. It has no `title`, so no version string appears anywhere. When `outgoing.problem !== null`, it draws the existing refusal sentence (`:133`) instead.

The add button's class becomes `sendable ? 'btn' : 'btn go'` (`:220`). That also changes the approved page's editor once it is opened. That is intended, since it is the same palette rule (`globals.css:1-2`). No approved render test sees it, because the draft state only exists after a click.

## 4. The moves are a `sresolutions` section on queued

The section at `standing.tsx:1231-1237` picks `sresolutions` only for `blocked`. Extend that to `queued`:

- aria-label *Moves*;
- `<h2 className="ssectiontitle">Moves</h2>`;
- one `sresolutiongrid` holding three `ResolutionCard`s (`triage-picks.tsx:171`), each with `recommended={false}`, `className="sresolution"`, and a `data-resolution` of `RunNow`, `EditPrompt` or `Close`.

Delete the queued `smoves` row (`:1404-1418`), and skip the bottom `spair` (`:1447-1471`) entirely when `queued`. The approved `smoves` (`:1428`) stays.

**Every card's head and consequence are drawn at once. Only the card's `sresolutionaction` is inside a `Gh`**, with a `Skeleton shape="lines" count={1}` fallback. That way the grid does not reflow when GitHub answers, and Close's card is never late. The three actions:

- **Run it now:** `RunNow` with `primary={false}` and a new `go` prop. Its button becomes `primary ? 'btn pri' : go ? 'btn go' : 'btn'` (`decide.tsx:814`). Keep the `primary = true` default, because other callers rely on it. `runNowCaption(a.queued)` stays as `holding`. When `a.queued === null`, today's page draws no `RunNow` (`:1408`). Keep that: the action is a muted *its place in the queue could not be read*, with no button.
- **Edit the prompt:** `OutgoingEditor` with `sendable={false}`. When `a.outgoing === null` or `a.outgoing.problem` is set, draw a muted sentence and no button.
- **Close the ticket:** `RESOLUTION_COPY.Close.consequence`, then `<Close … waitId={null} />` exactly as at `:1417`, outside every `Gh`.

New CSS:

- `.btn.go` and its `:hover:not(:disabled)`, unscoped. This is the mock's rule and #901 will use it.
- `.planlist`, `.bandsub` and `.closedrow`, also unscoped, because the running panel reuses them. None of them exist today.

`sresolution--draft` and the `EditBodyAndRequeue` `:empty` rules (`globals.css:1540-1541`) do not touch these cards.
