# Design: #505, complete sentences on the history rows, and the signoff back in the mirror

Everything goes in `apps/board`: `src/lib/history.ts`, `src/lib/task.ts` and `unit/what-a-pass-shows-today.test.tsx`. Do not touch `packages/domain`. `boardFactOf` (`packages/domain/src/read-model.ts:489`) is shared with `progress.ts` and its sibling `cardFactOf` feeds the projector (`packages/projector/src/task-view.ts:580`), so a change there is outside what the ticket allows.

## 1. The `PassRouted` wait row: get the subject from the run's own `RunStarted`

**Where the subject comes from.** The formatter can't get a branch from the payload alone. `PassRouted` is `{runId, offer, reply, decision}` (`packages/domain/src/events.ts:1132`) and goes on the run's stream (`pass-…`), which `parseWorkItemStream` can't parse. `RunStarted` is on that same stream and carries `ticketId: z.string()` (`events.ts:402`); the fixture's value is `'ticket-purecheck-7'` (`what-a-pass-shows-today.test.tsx:269`).

**How it reaches the formatter.** `groupHistory` (`task.ts:1316`) already walks every event in seq order. Use that pass to record a branch per run stream: when it sees a `RunStarted`, store `streamId → agentBranchOf(parseWorkItemStream(ticketId).issue)`. Both helpers are exported from `@lingtai/domain` through `streams.ts`. Then hand the branch through `toLine(e, branch)` to `summarise(event, branch)`. Make the new argument optional so `history.test.ts`'s existing `summarise(e(...))` calls keep compiling. Since `RunStarted` is always the first event on a run stream, the branch is recorded before any `PassRouted` needs it.

**Why not take it from the item stream in the same list:** `historyOf` is sometimes handed a run stream without the item stream. Row 13b's `PassRouted` row (`:8113`) has no item-side partner, so a branch found by "any `ticket-` event in the list" would leave that row blank. `RunStarted` is on every run stream; the fixture has 34 of them.

**How the formatter uses it.** In `history.ts:280`, call `legacyColumns(next.reason, { branch, base: '', findings: [] })`, which is the same call `boardFactOf` makes at `read-model.ts:532`. Read the branch with `need`, so a row with no branch throws and falls back to the payload (rule 2, `history.ts:14-17`). It must not render `— is waiting on you`. `FORMAT`'s `Formatter` type is `(d) => string`. The smallest change is to widen it to take a second argument that every other entry ignores. Don't special-case `PassRouted` inside `summarise`.

Leave `base` empty. `subjectOf` drops `into {base}` when base is `''` (`legacy-columns.ts:61`), so the row says `agent/7 is waiting on you. …`, word for word the same as the `WaitStarted` row above it (`:2850`).

## 2. `RoundOpened`: drop the action from the sentence

`boardFactOf` always sets `action: ''` (`read-model.ts:517`), and nothing on the board can fill it. The destination is `FixRound.to` (`pass-next.ts:52`), and only domain code can see it. So the action isn't a missing value that `need()` should fall back over; it is never present. If you used `need()`, every bought round would render as the raw dump of `offer`/`reply`/`decision`, which is worse than any sentence.

Use `round ${round} — ${n} finding(s)`. Also delete the `for ${action}` clause outright; don't make it conditional on a value nothing produces. Leave the `action` field on the type, because that lives in domain. The next row is already `StepStarted … step=implement round=1`, so the destination is still on the page. Change the comment above the formatter (`history.ts:436-443`) to say why the action is gone, in the same style as its *No denominator since #502* paragraph.

## 3. The signoff `StepEnded` in the mirror

**What the writer appends.** See `conduct.ts:3931-3955`. The event is one `StepEnded` on the run stream, with:

- `outcome.step = stopped?.step ?? 'proposed'`
- `round = roundsSpent`
- a single action with:
  - `plugin: 'conductor'`
  - name `'conductor:unfixed'` when stopped at `merge`, otherwise `'conductor:judge'`
  - `onSha: headSha`
  - `evidence: question`
  - `yields: 'signoff'`
  - `result: {_tag: 'Completed', requested: {question}}`

The names are namespaced since #503. The review's `proposed · judge` is out of date, so pin whatever the writer actually writes.

**Copy the payload, don't compose it.** In the writer test, each sequence puts this event between `PassRouted` and the next `RunRefsPublished` (`packages/conductor/unit/what-a-pass-writes-today.test.ts:568, 877, 957, 1063, 1307`). The mirror's header says every payload is "captured by actually running that file's own fixtures once … and copying the full payloads back" (`:11-14`). Do the same: temporarily dump the run stream from those five `it`s, copy the payloads into `RUN_5`, `RUN_9`, `RUN_10a`, `RUN_10b` and `RUN_13` at the same position, and remove the dump before committing. That gets `step`, `round`, `name` and `onSha` right for each row, which no hand-written guess will.

**What changes besides the history row.** Expect three changes, and check each against `history.ts` rather than just accepting what the test prints:

- **History:** a new row. `FACT_FORMAT.SignoffRequested` (`history.ts:432`) renders `${step} · ${action} — ${question}`.
- **Strip:** `stripOf`'s output for those rows. `boardFactOf`'s `SignoffRequested` makes `foldProgress` set `now` and a `pending` verdict on the stopping step (`progress.ts:494`). That is what the review's finding 4 says the fixture currently can't see, so the new strip state is the assertion the ticket asks for, not noise.
- **Documents:** possibly `documentsOf`, if the captured `question` has a newline in it. `splitPayload` lifts any string containing `\n` (`history.ts:587-620`).
