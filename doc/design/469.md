# #469 design: realistic fakes at the three head-bearing steps

## What decides the shape

A fake has two parts, and today's code reads only one of them:

- **`yields` can't be seen today.** Only `adapters.ts` reads it, through `actionOf` → `outcomeOf` → `StepReached.outcome`. The doc at `pass.ts:536-541` says *"Nothing reads it yet but the proof against #461's fixture … #467 is what puts `nextOf` in charge"*. So changing a fake from `yields: 'verdict'` to `'commit'` / `'worktree'` / `'design'` moves no assertion on today's code.
- **`head` can be seen today.** `headFrom` (`pass.ts:1886-1889`) takes the last `ActionResult.head` whatever its `yields`, and `record` advances `onSha` from it (`pass.ts:1343`). So every new `head` changes the `onSha` of every later visit.

Both are needed: `headOf` (`domain/src/action.ts:333`) only counts a `head` on a `commit`, `worktree` or `design` action. A `canned(...)` fake has `yields: 'verdict'` (`pass.test.ts:57-62`), so a `head` on it is invisible to `changedNothing`. The two tests at `pass.test.ts:1694-1725` already set `head` on `canned` fakes, and under #467 they would read as "changed nothing" for exactly this reason.

**So pick heads that keep churn small:**

- **`admit`: `head` is the `onSha` the action was handed** (`context.onSha` in `run`). The real worktree action reports where the tree was cut (`work-action.ts:13-16`: *"`admit`'s head is where the tree was cut"*), and the cut is the base. That is realistic and moves no sha.
- **`implement`: one fixed new sha per file**, e.g. `const COMMITTED = 'c0ffee0'`. A real agent's commit is a new sha (`work-action.ts:150-156` returns `head: answer.committed`). This is where literals move, and each moved literal goes in the commit body.
- **`design`: a `document`, and no `head`.** The drafting agent never sets `head` (`adapters.ts:296-299`, `headOf`'s doc at `action.ts:329-331`), and `designOf` reads `Drafted`, which needs `yields: 'design'`. Only a `file:` destination carries a `head`, and only the tests about `file:` need one.

## Implement's head belongs on the action, not the body

The real bodies return a bare pass: `admit` and `implement` are both `async () => ({ ending: 'passed' })` (`pass-steps.ts:1067`, `:1172`). The head comes from the default action `conduct.ts` builds when the recipe declares nothing: `defaultsAt` returns `createWorktreeAction` at `admit` and `createWorkAction` at `implement` (`conduct.ts:2803-2826`).

Two consequences in `pass.test.ts`:

1. **A recipe that declares nothing at `implement` still gets an agent in real life.** Today `watchingActions` maps `[]` to `[]` (`pass.test.ts:133-141`), which gives an empty `implement` step, and `changedNothing` returns `true` for an empty step (`action.ts:357-358`, *"An `implement` with no actions answers `true`"*). Do what `pass-steps.test.ts:449-459` already does for `defaultsAt`:
   - When nothing is declared at `admit`, the fake returns a cutting fake.
   - When nothing is declared at `implement`, it returns a committing fake.
   - When something is declared at `implement`, it returns committing fakes in place of `canned(..., PASSED)`.
   - Every other step stays as it is.
2. **Fake bodies that return `head`** (`pass.test.ts:1618`, `:1665`) move that head onto the `implement` action and return a bare `{ ending: 'passed' }`. The assertions stay the same: today the body's head wins over the plugins' (`pass.ts:1622-1627`), so the same sha on the action gives the same `onSha` downstream. `judging()` (`:155-182`) builds one `check` action for every step. Have it build a commit-yielding check at `implement` whose result carries the head the test asks for, through `answering`.

`watchingActions` records `ran` from the actions it builds (`:137`). An `implement` that now appears in `ran` where it didn't before is the fixture changing, not the behaviour. If a test asserts `ran` exactly, give the default action a name that already appears in it, or name it `'write the change'` as `defaultsAt` does. Then list it in the commit body.

## The helpers, per file

Write one small builder per yield in each file, close to `canned`:

- `committedSomething(name, head = COMMITTED)`: `kind: 'agent'`, `yields: 'commit'`, returns `{ ...PASSED, evidence: 'committed …', head }`.
- `cutAt(name)`: `kind: 'worktree'`, `yields: 'worktree'`, returns `{ ...PASSED, head: context.onSha }`.
- `drafted(name, document)`: `kind: 'agent'`, `yields: 'design'`, returns `{ ...PASSED, document }`.

The rest of the files are already close:

- **`pass-steps.test.ts`** already builds the real actions over fake ports when nothing is declared (`writing()`, `cutting()`, `drafting()` at `:375-430`, with `working` answering `{ committed: COMMITTED }` at `:320-330`). Only the `actions.length > 0` branch (`:455`) and the `options.actions` overrides need the helpers.
- **`step-matrix.test.ts`** already answers `committed` and `head` through real ports (`:220-223`). Expect nothing to change there.
- **`what-a-destination-costs.test.ts`**'s `answering` (`:88-91`) gives the `design` action's `yields` to every step. At `implement`, give it `committedSomething` instead of a `kept` that yields `design`.
- **`conduct-*`, `a-locator-…` and `what-a-pass-writes-today`** go through `conduct.ts`'s real `defaultsAt` with fake ports, or through `carry` / `once()` (`test/one-pass.ts:513`, *"An agent that says it committed something"*). Read each one and confirm that. Edit only a fake port that answers without a `committed` or `head`. **Don't touch `test/one-pass.ts`**: #461's rows are built from it.

## Leave these as they are

Some tests are about the head *not* moving, so they must stay headless:

- `pass.test.ts:1646`, *"leaves the head alone when no step says it moved the tree"*, which asserts every `onSha === 'abc1234def'`.
- `:469`, an `implement` check that fails with *"no diff"*.
- Any test whose `implement` is meant to have done nothing, such as the `committedNothing` cells and `asked` (`:696`).

Under #467 those become `NothingProduced` / `FixerDisagrees` (`pass-next.ts:105-111`), and that is the behaviour #467 decides. If the shared default would give one of them a head, pass it an override that keeps the fake headless, and leave a comment saying why.
