## Decisions the ticket leaves to you

**1. The ticket's value table wins over `doc/milestone/0.15.0/sandbox-ui/index.html`.** The mock's CSS is useful for layout: grid areas, how the summary's three columns sit, the star glyph. Its values do not always agree with the ticket, though. The mock's `.chip` uses `border:1px solid var(--rule-2)` (`index.html:54`), and `.chip.tok` and `.chip.own` use the literals `#fff` and `#bcdcde` (`:55-56`). The ticket says `color-mix(in srgb, var(--rule) 60%, transparent)`, `--surface` and "no colour is written as a literal". Wherever the two differ, use the ticket's value. The mock also elides in the middle of a label (`/var/folders/y7/…/T`, `:201`). Do not build that: the ticket asks for CSS `text-overflow: ellipsis` only.

**2. Scope the shield restyle to `.sbsummary`.** `.sbx-mark`, `.sbx-shield` and `.sbx-<state> .sbx-mark` (`globals.css:3154-3163`) are shared. The bar draws the same `SandboxShield` (`bar.tsx:105`), and so does every run's `SandboxMark` (`sandbox-mark.tsx:12`). Write the 38×38 tinted square and the 20px glyph as `.sbsummary .sbx-…` rules. The summary already carries the state class `sbx-${TONE_SHIELD[…]}` (`sandbox-panel.tsx:118`), so the tint hangs off it. That class is `sbx-off` for both `off` and `none`, which gives `--ground` for both. That is right.

**3. Headings get a class, not a global `h3` change.** The ticket keeps the global `h3` out of scope. Keep the `<h3>` elements, because render tests find sections by `aria-label` and by text (`sandbox-view.test.tsx:781`). Give each a class, e.g. `sbh`, and style that. "Where the policies differ" is a `<p className="sbhead">` today (`sandbox-panel.tsx:478`). Give it the same class so all four headings look alike, and keep it a `<p>`.

**4. The Blocked box tints only around the table.** Today `<div className="sbblocked">` wraps `BlockedList` unconditionally (`:422`), and `.sbblocked:has(> p.empty)` (`globals.css:3185`) undoes the tint when the list is empty. That breaks when there are caveats and no hosts: `BlockedList` draws the caveat `<p>`s and no `p.empty` (`:228-231`), so the box stays tinted around plain text. Put the tinted class on a wrapper inside `BlockedList`'s host branch, around the `<table>` only, and delete the `:has` rule. Add the header row `<thead>` with Host, Refused, By, First and an empty fifth `<th>` there too. The Allow link's `className` is `'sbbtn'` only when `time === 'clock'` (`:250`). Keep that condition; just restyle `.sbbtn` to the Allow-link row of the table.

**5. Figures become blocks with the count above its label.** `SummaryBar` draws `<b>{s.sandboxed}/{s.total}</b> runs sandboxed` inline (`:126-131`), and the refused figure is one `<b>` holding `refusedFigure(...)`, which is the whole sentence (`:132-134`). Wrap each figure's number in its own block element and its label in another. Do not change the strings. If `refusedFigure` returns one string with the number and the words together, split it at the first space inside the panel, or draw the whole string in the number's place. Do not change what `refusedFigure` returns, because #1196's tests assert that text. The `hold` class on a non-zero or unknown refusal becomes `--signal` for the number.

**6. The boundary pill is CSS on what `SandboxMark` already draws.** The boundary cell is `<SandboxMark mark={r.mark}/>`, followed by `why`, srt and *weaker network isolation* spans (`:171-174`). `.sbmark` (`:39`) already carries `TONE_CLASS[mark.tone]`. Style `.sbrows .sbmark` with the tone classes as the pill. Draw the 6px dot with `::before`, so the text a test reads does not change. `.sbmark` is also used outside this panel (`globals.css:3458`), so qualify the selector with `.sbrows`.

**7. The `/private` twin.** In `chipsOf` (`sandbox-view.ts:549-557`), build the lookup from slash-stripped paths with the existing `trimSlash` (`:516`), mapping each stripped spelling back to its recorded one. Skip `/private/x` when stripped `x` is present. The chip's `label` is `shortNameOf` of the stripped short spelling. `fulls` keeps both spellings exactly as recorded, slashes and all, so the `title` still shows what srt wrote. A path whose stripped form has no twin is drawn as it is, slash included. Do not merge `/a/` with `/a` when neither has `/private`; the ticket only asks about twins. Use `fulls[0]` as the React key (`sandbox-panel.tsx:269`); after this change it is the shorter spelling, and it stays unique.

**8. `<run dir>` works like `<worktree>`.** It is a segment rule, not a candidate prefix.
- Match `${lh}/runs/` followed by one non-empty segment, and set `prefix = ${lh}/runs/<segment>`. This mirrors the `<worktree>` branch (`:526-532`) and does not depend on the project name.
- Bare `${lh}/runs/<segment>` is the bare token `<run dir>`.
- Bare `${lh}/runs` stays `<lingtai home>/runs`.

This changes one assertion #1196 wrote: `sandbox-view.test.tsx:564` expects `<lingtai home>/runs/a1/claude`, and it now becomes `<run dir>/claude`. Edit that line. It is the change the ticket asks for. The ticket's "#1196's tests unchanged" is about the tests on wording (unknown refusals, `none recorded`, telemetry), as its *Watch out* row says. Leave every other assertion as it is.

**9. The legend sentence.** `legendOf` (`:560-567`) returns `{ token, paths }`, and the panel prints the token and then the prefixes (`sandbox-panel.tsx:487-498`). Add a fixed description for `<run dir>` only, *the attempt's own run directory*, and draw the prefix after it. Leave the other tokens as they are, because changing their text is outside the ticket. Keep the description in `sandbox-view.ts` as a constant map beside `shortNameOf`, so a unit test can reach it.

**10. Folding is a pure function over `Chip[]` and is applied only in `PolicyDifference`.**
- Add `foldChips(chips: readonly Chip[]): Chip[]` to `sandbox-view.ts`.
- Group by the parent directory of `trimSlash(fulls[0])`. That is the full recorded path, not the label, matching `reachOf`'s rule: "compared by their full recorded form … never by their short names" (`:593-596`).
- A group of 3 or more becomes one chip:
  - `label`: the shortened parent plus `/… (N)`, where the shortened parent is `shortNameOf(parent, roots).label`. So `foldChips` takes `roots` too.
  - `fulls`: every member's `fulls`, flattened.
  - `token` and `prefix`: the members' own.
  - A new optional field `folded: number`.
- Groups smaller than 3 pass through unchanged, in their original order. Put a folded chip where its first member was.
- In `ChipList`, the title is `fulls.join(' = ')` today (`:269`). For a folded chip, join one path per line, and keep each member's twin as `a = b` on its line. Carry the members as `members: readonly Chip[]` rather than the flat `fulls` so the twin pairing is not lost. `fulls[0]` stays the key.
- Apply it per relation in `PolicyDifference` (`:344-363`): *also writes*, *also cannot write*, *does not write*, *does not deny writing*, *does not deny reading*, *also cannot read*. For *also re-allows reading*, fold each root's own `except` list separately, because each list is drawn under its own root (`:356-361`).
- Do not fold the common reach boxes. The ticket's folding rule is about a policy's difference.
- `drawn` keeps receiving the unfolded chips from `name()` (`:396-400`), so the legend still lists every prefix a folded member used.

Assert on text and structure only, never on class names or values. This is the ticket's own rule under *The cost to later tickets*. The look is checked by the person's screenshot comparison after landing, and nothing in `pnpm test` stands in for that.
