## Design note: #1332, making the filter's link reader lazy

The ticket already says how to do this, and the fix it describes is the right one. This note adds three points the ticket does not make.

**1. The template string is the only thing that touches the client early.** `projectFilterEffect`'s GitHub branch (`packages/conductor/src/filter.ts:422-427`) passes `ghClient` to `ticketLinksOf`. There, `ticketLinksOf` checks `(tickets as unknown) === gh` (`filter.ts:223`). Comparing a Proxy with `===` does not call its `get` trap, so that check is safe to keep as it is. The only early read is the template on `filter.ts:224`. Turn `repository` into a getter on that object literal (`get repository() { return \`${gh.owner}/${gh.repo}\` }`). Don't change the `TicketLinks` type at `filter.ts:213-216`: a getter still satisfies `repository: string`, so no caller has to change. Leave the `db` branch (`filter.ts:226`) alone. Its `repository` is `project`, which is not a read from GitHub.

**2. Nothing copies `links` today, and that is what keeps the getter lazy.** Spreading the object (`{...links}`), passing it through `structuredClone`, or `JSON.stringify` on the filter would call the getter immediately, and the bug would come back. I searched `apps/` and `packages/` outside `unit/` and found no spread or serialisation of a `links` value. Put a one-line comment on the getter saying it must not be copied, and quote doctor's *"any question it is asked is a bug, said so"* (`apps/cli/src/doctor.ts:2383`) as the reason.

**3. Doctor's offline client stays exactly as it is.** Don't change `offlineClient` (`apps/cli/src/doctor.ts:2384-2390`), and don't change its `then`/symbol carve-out either. The unit test should build its own Proxy the same way: return `undefined` for `then` and for symbol keys, and throw on every other key. If it throws on `then` as well, the Effect's promise lift fails for a reason that has nothing to do with this bug. Put the test in `packages/conductor/unit/filter.test.ts`, which already covers `links`. Pass a `clientFor` that returns the Proxy, plus a `recipeFor` and a `ticketsOf` that return without reading it; `ticketsOf` should hand the client back so that `tickets === gh`. Then assert:
- the filter resolves `ok: true` while the throwing Proxy is in place;
- with an ordinary client, `links.repository` reads `owner/repo`;
- with the throwing client, reading `links.repository` throws `(owner)`.

The third assertion is the ticket's **A read that fails** edge, which keeps the error but moves when it happens. To prove the test fails on the current code, run it once before changing `filter.ts:224`.

The two integration files in **Done when** are the only end-to-end check on doctor, and nothing in the `build` step runs them. The unit test above is what has to stand in for them before the merge.
