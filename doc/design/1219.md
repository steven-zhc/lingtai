# Design note for #1219: the *Rerun this step on the saved work* card

> **History.** Board addresses in this note (`/task/<id>`, `/pr/…`, `/recipe/…`, `?project=`) are the ones that existed when it was written; they no longer resolve. The current forms are in [1502.md](1502.md).

The ticket's shape holds. Two things in the code are not what the ticket assumes. Both change what you build, so they come first.

## 1. `rerunWork` reads `rerunHeadOf`, not `savedFixWork`, and it has three outcomes, not two

The ticket's Edges say the refusal comes from "`savedHeadOf`'s answer … as `GrantFixRound`'s card does". **Don't reuse `savedFixWork`** (`apps/board/src/lib/saved-fix-work.ts:17-37`). It refuses `WipHead` and the nothing-committed `NoSavedHead`, and #1218's server accepts both of those for a rerun.

The server's check is `rerunHeadOf(state)` (`packages/domain/src/attempt.ts:809`). Its doc comment says: *"The conductor's re-cut and the person's `RerunStep` ask this one table, and the board asks it to say whether the move can be made."* Its type is `RerunHead` (`attempt.ts:803-806`), and it has three cases:

- **`{ at, atRef, carry }`**: the head is `at`.
  - If `atRef !== null`, run the same remote check `fixWork` runs (`apps/board/src/lib/task.ts:1987-2005`): `client.refSha(`heads/${atRef}`)` must equal `at`. Otherwise the refusal is the sentence the server would give (`packages/conductor/src/resolve-wait.ts:404-411`). A thrown read becomes `{ refusal: 'The saved ref could not be checked: …' }`, the same as `fixWork`'s.
  - If `atRef === null` (a kept WIP; `attempt.ts:828`), **skip the remote check and skip building a GitHub client.** The server skips it too (`resolve-wait.ts:394`). Without this, a crash that kept only a WIP would show a refusal the server would never give.
- **`{ atBase: true }`**: there was nothing committed. The head is the attempt's own base commit, `diffBaseShaOf(runEvents)`, exported from `@lingtai/conductor` (`packages/conductor/src/attempts.ts:261`; the board already depends on that package, `apps/board/package.json:22`). It is `null` when there is no `admit` outcome. In that case refuse with the server's sentence (`resolve-wait.ts:371-378`). There is no remote check.
- **`{ cannot }`**: refuse with `Run ${runId} has no saved head a rerun can continue: ${cannot}. Requeue for a fresh attempt.` This is the server's wording (`resolve-wait.ts:362-368`).

So the field is `rerunWork?: { head: string; ref: string | null } | { refusal: string } | null` on `StandingView`, next to `fixWork` (`task.ts:482`). It is computed under its own guard: `allowedResolutions(standing.reason).includes('RerunStep') && standing.runId !== null`.

**Why this matters for the Watch out row:** the `onSha` the button sends has to be the same `at` the server computes. The server compares them with `matchHead` (`resolve-wait.ts:380-387`). If the page showed `savedHeadOf`'s head on a WIP crash, every click would fail as `stale`.

Put the pure part in a function next to `savedFixWorkFromState`, for example `rerunWorkFromState(runId, state, runEvents)` in `saved-fix-work.ts`. It returns either `{ head, ref }` or `{ refusal }`, plus an "a remote check is needed" marker. The loader then only adds the I/O. A unit test can call that function directly with built events (`Saved` / `WipHead` / nothing-committed / `BranchDiverged`) without a client. The loader is plain `async` today, like the `fixWork` block. Add no new `async` function and no `Effect.run*`; extend the loader inline, as `fixWork` does, so `effect-ratchet.baseline.json` does not move.

The two loader blocks share the same project-client lookup (`task.ts:1987-1995`). Pull it into one lazily resolved client, so that a wait offering both moves builds it at most once. A wait can offer both today (`BuildRed` with nonempty output, or `CheckRefused` at `proposed` with evidence, offers `GrantFixRound` and `RerunStep`), so the single lookup matters, not just tidiness.

## 2. Grid order: `allowedResolutions` puts `RerunStep` last, so the board has to reorder it

`allowedResolutions` returns `[...table, GrantFixRound?, RerunStep?]` (`packages/domain/src/wait.ts:508-516`). For a crash that stands in for a wait, the table is `[...tableResolutions(standing), 'Requeue', 'Close']` (`wait.ts:311`), so `RerunStep` comes after *Start over from base* and after *Close*. The grid draws `drawable` in that order (`apps/board/src/app/standing.tsx:1002-1021`). So the ticket's ordering does not happen by itself.

**Fix this in the board, not in `allowedResolutions`.** That function's order is "0118 §1's table, column order" (`wait.ts:303-304`). The CLI and triage read it too, and changing it is #1218's business. In `standing.tsx`, after `drawable` is built and before the recommended-first sort, move `'RerunStep'` so it sits immediately after `'GrantFixRound'` if that is present, and otherwise first. Do this in a small exported function, so the "a test reads the order" Done-when checks the function rather than rendered markup.

The recommended-first sort (`standing.tsx:1009-1012`) still runs afterwards. Triage can never advise `RerunStep` (`wait.ts:295-300`), so the card is never moved ahead of a recommended card.

## 3. The action and the button

- **The action:** add `rerunStepCard` to `apps/board/src/app/actions.ts`, shaped like `continueFixingCard` (`actions.ts:184-229`).
  - Refuse when `waitId` or `onSha` is missing, with `stale: reload this page before rerunning`.
  - Build the client as that action does.
  - Call `resolveWait` with `{ _tag: 'RerunStep', onSha: input.onSha, ref: null }`.
  - Revalidate `/task/<id>` and `/`.
  - Report `step rerun on saved work`, or `… — continuation was not scheduled (${unscheduled}); click again to schedule it`.
  - Send `ref: null` to match the CLI (`apps/cli/src/rerun.ts:55`). The schema allows either (`packages/domain/src/wait.ts:254-258`), and the server replaces the resolution with its own `{ onSha: at, ref: atRef }` (`resolve-wait.ts:416`), so this choice changes nothing.
  - **The server needs a client only when `atRef !== null`**, and refuses with `no-client` otherwise (`resolve-wait.ts:395-401`). Still build and pass one exactly as `continueFixingCard` does. If the action skipped the client whenever it guessed a WIP, a GitHub App missing on the board machine would show up as a misleading refusal.
- **The button:** use the `ContinueFixing` component's pattern. Find where it is defined and import it from there; keep `primary={false}`, since triage never advises this move. Give it its own action and label, *Rerun this step*. Don't add a mode flag to `ContinueFixing`; a sibling component keeps the grant's test untouched.
- **The grid branch** (`standing.tsx:1472-1545`), written like `GrantFixRound`'s:
  - When `rerunWork` has a head, render the button with `onSha={standing.rerunWork.head}`.
  - Otherwise render `<p className="refusal">` with the refusal, or *Saved work could not be verified; reload this page before continuing.* when the field is missing.
  - For the heading and consequence, extend `fixUnavailable` to a per-tag unavailable check. When unavailable, the heading is *Cannot rerun on saved work* and the consequence is *The saved head must be available before this step can be rerun.* When available, the copy is `RESOLUTION_COPY.RerunStep` (`apps/board/src/lib/resolution-copy.ts:16-20`), which already exists.
  - Name the head on the card, as the ticket asks: put the short sha in the button's label or next to it, the same way the grant card shows its head.

## Tests that stand in for the integration half

All of these are unit tests. Every check below runs under `pnpm test`.

- **`rerunWorkFromState`:** one case for each `RerunHead` arm, including WIP → head is the carry's parent with `ref: null`, and nothing committed → `diffBaseShaOf`'s sha.
- **The order function:** `[..., 'Requeue', 'Close', 'RerunStep']` with `GrantFixRound` absent → `RerunStep` first. With `GrantFixRound` present → `RerunStep` directly after it.
- **The action:** with `resolveWait` stubbed the way the existing `continueFixingCard` tests stub it (find them under `apps/board/unit/`), the call carries `_tag: 'RerunStep'` and the shown `onSha`. An empty `onSha` never reaches `resolveWait`. A `{ ok: false, reason: 'stale' }` comes back as the card's detail.
- **The rendered grid** (`apps/board/unit/standing.test.tsx` already renders this grid): on an `AgentCrashed` standing with `rerunWork` set and no `fixWork`, the RerunStep card has a button, not the refusal. This is the Watch out's "`fixWork` only for `GrantFixRound`" trap.
