# #1102: design note

The ticket already describes the shape. This note covers the one thing it leaves implicit. Today two places cross a promise boundary, and each of those boundaries catches more than its code seems to. If they become `yield*` with the obvious catch, defects that are recovered today start killing the loop.

## Catch defects where the promise used to

`Effect.runPromise` turns every failure into a rejection, defects included. In effect 4.1.2, `runPromiseWith` does `throw causeSquash(exit.cause)` (`node_modules/.pnpm/effect@4.1.2/.../internal/effect.ts:5853`). `causeSquash` returns the first `Fail`'s error, or else the first `Die`'s defect (`:290-298`). So a store failure inside `runOnce` is a defect by 0101 §6. Today it reaches the code above the run as an ordinary rejection with the original `Error`, and two places recover it:

1. **`conductProjects`'s `try/catch`** (`conduct.ts:812-834`). It turns *anything* thrown by `options.work` into a `refused` row plus `${name}: ${message}`, and it calls `record` only when `!looked`. Once the awaited passes become `yield* world.runOnce(…)`, that defect arrives as a `Die` and `Effect.catch` will not see it. Write it as `Effect.catchCause` and let a cause that is only interruptions pass through (`Cause.hasInterruptsOnly(cause) ? Effect.failCause(cause) : …`). Take the error with `Cause.squash(cause)`. That is the same object `runPromise` threw, so `(err as Error).message` and every sentence stay byte-identical. Keep the `looked` check exactly as it is.

2. **The work loop's drain** (`packages/daemon/src/work-loop.ts:527-528`). Today this is `attempt(() => Promise.resolve(options.pass(reason, started))).pipe(Effect.catch(… tell(\`turn failed: …\`)))`. `attempt` is `Effect.tryPromise` (`:492`), so it catches rejections and synchronous throws alike, and a defect anywhere in `conductorTurn` is told as `turn failed: …`. When `pass` returns an Effect:
   - Wrap the call in `Effect.suspend(() => options.pass(reason, started))`, so a throw while the Effect is being built is still caught.
   - Replace `Effect.catch` with the same `catchCause` that lets interruptions through, using `Cause.squash` for the message.

   If you only swap `attempt` for `yield*` and keep `Effect.catch`, the first store hiccup dies the look's fiber. The ticket's *Watch out* names this exact outcome: every ticket stops until a person notices.

`record` (`conduct.ts:846-862`) follows the same rule. It swallows store failures today, which are defects once yielded, so it needs `catchCause`.

The detached pass needs nothing new here. It stays a promise (`runPromiseWith(services)(…).then(report, onFailure)`), and `onFailure` already receives the squashed error. Keep the handover order exactly as `conduct.ts:402-421` has it: run, then `.then(report, onFailure)`, then `.finally(leave)`, then `slots.started(…)`.

**Unit test standing in for the integration half:** a `conductProjects` whose `work` is `Effect.die(new Error('x'))` gives one `refused` row with detail `x`. A work loop whose `pass` is `Effect.die(new Error('x'))` tells `turn failed: x` and takes the next kick. Neither expected string exists today, so these are new assertions and not edits to existing ones.

## Ports: a rejected promise stays a defect

`schedule.ts:205-206` lifts `paused`/`locked` with `Effect.promise`, so a rejected promise is a defect there today. Type the new ports as never-failing (`Effect<string | null>`), and in `stopIfPaused` write `yield* asked` and `yield* askedLock(name)`. At `daemon.ts:632`, `paused: Effect.promise(claiming)` keeps that meaning. Give `Effect.promise` a thunk: `Effect.promise(() => claiming())`, or pass `claiming` as the evaluate function. A promise built once at wiring time would be read once and replayed. This applies to anything else adapted from a promise port.

The work loop's own `paused` (`work-loop.ts:221`) is a different port, stays a promise until CLI-14, and is not touched here.

## The span test needs no exporter

On Effect 4 the parent span is a `Context` reference (`schedule.ts:173-178` says so for the tracer). So `Effect.context()` taken inside the look carries it into `runPromiseWith`.

- Wrap the call in `Effect.withSpan('turn')`. In the fake `runOnce`, `Effect.withSpan('pass')(Effect.currentParentSpan)` (`Effect.ts:17436`) and compare its `spanId` with the outer span's, which you get from `Effect.currentSpan` inside the outer `withSpan`.
- Do this once for the awaited pass and once for the detached one. Read the detached result after the test completes the `Deferred` and awaits the promise handed to `started`.

## Take `services` inside the look's generator

Call `yield* Effect.context()` once at the top of the look's `Effect.gen` and close `launch` over the result. Do not take it at module level or in `conductWork`'s outer (non-Effect) closure: there is no fiber there, and you would get exactly the `Context.empty()` the ticket forbids.
