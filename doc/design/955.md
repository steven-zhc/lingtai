## The conductor half: `label` is decided in `considerIssue` and copied at the one push

- **`Considered`** (`packages/conductor/src/discover.ts:196-200`) gets `label: string | null`. **Every return in `considerIssue`** (`:207-247`) sets it:
  - `null` for `closed`, `epic`, `no-kind`, `blocked-by`, the assignee reasons, and the runnable `skip: null`;
  - the label itself only on the `excluded-label` return (`:202-203` in the ticket; the code is now at `:229-230`).
- **The match keeps the recipe's spelling.** Today the code lowercases `queue.exclude` into a `Set` and asks `labels.some(...)`, so the spelling and the order are both lost there. Replace that with `queue.exclude.find((x) => labels.includes(x.toLowerCase()))`. `labels` is already lowercased at `:215`. If the result is not `undefined`, return `{ issue, skip: 'excluded-label', label: found }`. Take the order from `source.exclude` and never from the issue's own labels, which is the *two excluded labels* edge.
- **`Offered.skipped`** (`:283-301`) gets the same required field. Its one writer is the push in `runnableNow` (`:440-448`), which copies `label` from what `considerIssue` returned. **Do not change `passedOver` (`:376`)**: `lingtai status` and `wizard.ts:109` keep printing every skip, `excluded-label` and `epic` included.
- **The cost of making it required.** Every hand-written `skipped` literal stops compiling until it says `label: null` (or a label). They are in `apps/board/unit/{render-cost,queued-stream,blocked-skips,ask-project-ownerless}.test.ts(x)`, the conductor's unit tests, and `apps/cli/integration/status-preview.test.ts`. That last one is in the integration half and cannot be run inside a pass, but `pnpm typecheck` reaches it. Let `tsc` give you the list rather than grepping for it. Leave `packages/actions/src/queue-action.ts:66` alone: it reads only `skip`.

## The board half: widen `held`, add `epics`, filter the note

In `githubQueue` (`apps/board/src/lib/board.ts:1036`):

1. **Widen `held` instead of adding a list beside it.** `GithubQueue.held` (`:1022`) is refs only today, and #960 built it so a blocker can read *held*. Make each entry `{ project, ref, title, kind, kindColor, label: string }`. `kindColor` comes from `offered.kindColors[kind]`, the same way `blocked` gets it at `:1069`. `blockerChip` declares its parameter as `readonly { project: string; ref: number }[]` (`blocker-state.ts:51`) and reads only those two fields at `:68`, so it compiles and behaves as before. `label` is a `string` on the board side: an `excluded-label` skip always has one. If one arrives `null`, which is unreachable, show it as `held`.
2. **Add `epics: { project, ref, title, kind, kindColor, closed: number, total: number }[]`**, filled from `reason === 'epic'`. Read `closed` from `subIssues.completed` and `total` from `subIssues.total`. `isEpic` (`discover.ts:74-75`) guarantees `subIssues` is non-null for this reason, but the type still allows null, so skip an entry whose `subIssues` is null rather than drawing `0/0`. The kind is known even for an epic: `runnableNow` computes `matched` (`:431`) before it calls `considerIssue`.
3. **The note** (`:1076`): change the filter to drop `blocked-by`, `excluded-label` and `epic`. Write the three as one named set, e.g. `DRAWN_SKIPS`. Reword the comment at `:1074-1075` to say the column counts only the skips it does not draw. In `render-cost.test.ts:224`, the fixture's skips become *all* drawn, so that note disappears and only `DEPENDENCIES_UNREAD` is left. Add a `no-kind` skip to that fixture so the test still asserts a note, and assert `held` and `epics` through the same `ask` seam.
4. **No `known` drop for either list.** This is unlike `blocked` (`:1068-1070`). A row in the fold is a line, not a card, so a ticket that has a log card and also carries a hold label is not drawn twice. It is still held, which is the fact the fold exists to name. `held` also keeps feeding `blockerChip` exactly as #960 left it.
