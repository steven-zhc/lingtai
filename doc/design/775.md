## Design note — #775

### Where the pieces go

| File | What it holds |
|---|---|
| `packages/env/src/index.ts` | `machineOtlpEndpoint(from, file)`, placed next to `machineBoardPort` (`:824`) |
| `apps/board/src/lib/telemetry.ts` (new) | the filtering processor and `installTracing(from, file, exporter?)` |
| `apps/board/src/instrumentation.ts` (new) | `register()`, which only branches on the runtime and delegates |
| `apps/board/src/lib/timing.ts` | `timed` opens a span |
| `apps/board/serve.ts`, `apps/cli/src/board.ts` | the start-time refusal |
| `apps/board/unit/telemetry.test.ts` (new) | the `register`/filter/span tests |
| `packages/env/unit/…` | the reader tests |
| `config.example.yml` | the `telemetry:` block |

The board's source sits under `src/` (`apps/board/src/app`, `src/lib`), so Next looks for `instrumentation.ts` in `src/` and not next to `next.config.ts`. Next 16.3.3 (`apps/board/package.json`) needs no config flag for it.

### Decision 1: `register()` takes no arguments; `installTracing` is what gets tested

Next calls `register()` bare. The ticket's "`register` takes `from` and `file` and an optional exporter" therefore lands on `installTracing(from, file, exporter?)` in `lib/telemetry.ts`, and `register()` is only this:

```ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== 'nodejs') return
  const { installTracing } = await import('./lib/telemetry.ts')
  await installTracing(process.env)
}
```

`instrumentation.ts` has **no top-level imports**, not even `@lingtai/env`. Next compiles this file for the edge runtime as well, and `@lingtai/env` reads `node:fs` (`machineFile`, `index.ts:126`). The SDK packages are `import()`ed inside `installTracing`, and only after it has an endpoint, using literal specifiers so the standalone trace can follow them.

`installTracing`'s steps:
1. Read `machineOtlpEndpoint(from, file)`.
2. If that throws, or returns `undefined`, return having installed nothing and printed nothing.
3. Otherwise build `BasicTracerProvider({ spanProcessors: [new OnlyScope('lingtai-board', new BatchSpanProcessor(exporter ?? new OTLPTraceExporter({ url })))] })`, then call `trace.setGlobalTracerProvider` and `context.setGlobalContextManager(new AsyncLocalStorageContextManager().enable())`.
4. Return the provider so a test can `forceFlush()` it.

**Tests use `machineFileFrom(path, text)`** (`index.ts:147`), never `machineFile`. It builds the file from a string, so the test stays a unit test: no filesystem (0060 §1, CLAUDE.md's line between the halves).

`OnlyScope` implements `SpanProcessor`:
- `onStart` is a no-op.
- `onEnd` forwards only when `span.instrumentationScope.name === scope`. Check that property name in the installed `.d.ts`; 1.x called it `instrumentationLibrary`.
- `forceFlush` and `shutdown` delegate to the inner processor.
- The fields are assigned in the constructor body. **No parameter properties**: 0101 runs the source strip-only.

### Decision 2: the reader refuses with fixed sentences, never Effect's error text

`machineBoardPort` interpolates `exported.left` / `written.left` (`index.ts:831-832`, `:843-844`). **Don't copy the shape.** Read with `Config.option(Config.nested(Config.string('otlp_endpoint'), 'telemetry'))`, not `Config.url`, then validate by hand: `URL.canParse(v)` and `new URL(v).protocol` in `http:`/`https:`. The four outcomes:

| Source | Value | Result |
|---|---|---|
| Variable | bad | throw `` `${PREFIX}TELEMETRY_OTLP_ENDPOINT is not an http or https URL, so no endpoint was read — unset it or correct it` `` |
| File | bad | throw `` `${file.path} sets telemetry.otlp_endpoint to something that is not an http or https URL, so no endpoint was read` `` |
| Variable | absent | fall through to the file |
| Both | absent | `undefined` |

Both refusal sentences are fixed: no value and no error text.

**`file.unreadable` is a choice the ticket left open.** Its text is the YAML parser's message (`index.ts:154`), which can quote the offending line. So this reader throws `` `${file.path} could not be read, so telemetry.otlp_endpoint could not be read` ``, without the `unreadable` text. On the start path `boardPort()` runs first and already prints that parse error (`serve.ts:23-29`, `cli.ts:371`), so the person still sees why. Fixing that leak in the port reader is not this ticket.

### Decision 3: the start-time checks

- **`serve.ts:23-29`**: call `machineOtlpEndpoint()` inside the same `try` as `boardPort()`. Same `console.error(message)` and `exit(1)`.
- **`serveBoard`** (`apps/cli/src/board.ts:123`): call it right after the `existsSync(entry)` refusal, before `portIsFree`, and let it throw. The callers already turn a `serveBoard` throw into a refusal and release the lock (`board.ts:141-142`: *"on a failure the caller releases the lock itself"*). Checking inside `serveBoard` rather than in `cli.ts` also covers `init.ts:1246`, the second caller.
- **Not in `boardPortOrWhy`** (`board.ts:85`): #187 decided the board's own configuration must not stop the conductor's commands.

### Decision 4: how `timed` opens its span

Wrap the whole body in `trace.getTracer('lingtai-board').startActiveSpan(name, async (span) => …)`:

- **The span opens whether or not a `measure` scope is present.** The early `return fn()` (`timing.ts:84`) moves inside the span callback, so the existing *"records nothing outside a measure"* test (`unit/timing.test.tsx:29`) still holds. `measure`'s list and the span are independent.
- **`startActiveSpan`, not `startSpan`**, so a `timed` inside another `timed` (e.g. `mirror.ref` within the triage path) gets the outer one as its parent.
- **On failure** — a throw, or `options.failed?.(value)` true: `span.setStatus({ code: SpanStatusCode.ERROR })` and nothing else. No message, no `recordException`, no `err` read. Rethrow `err` untouched, exactly as now.
- **On success**, if `options.desc` matches `/^\d+$/`, `span.setAttribute('lingtai.count', Number(options.desc))`. That gives the count without a new option or touching the callers: only `events.run` and `events.chat` pass a numeric `desc` (`task.ts:1852-1854`, `:1874-1876`).
- `span.end()` goes in a `finally`.

`timing.ts` imports only `@opentelemetry/api`. That package is safe on a client graph too, but `timing.ts` is server-only already because of `node:async_hooks` (its header comment).

### The tests' global state

Each test that installs calls `trace.disable()` and `context.disable()` in `afterEach`. The span-name test (one `measure`, two `timed`) and the failure test run against an installed `InMemorySpanExporter`, and read it after `await provider.forceFlush()`.

The "no endpoint" test asserts `trace.getTracer('lingtai-board').startSpan('x').isRecording()` is false, **and** that nothing was registered globally (the tracer provider is still the API's proxy with no delegate). The second assertion is what catches an `installTracing` that registers before reading the key.

### What nothing before the merge can check

`pnpm test` does not see whether `next build`'s trace copies the `import()`ed SDK into `.next/standalone`, or whether `apps/release`'s bundle carries it. That shows up only in `apps/release/integration/build.test.ts`, after the merge (the #230 shape).

The unit test that covers the most of that ground: `installTracing` with an endpoint really loads all three SDK modules through the same `import()` specifiers `register()` uses. Write the specifiers once in `telemetry.ts`, so the test and production cannot diverge.

**The lockfile:** `pnpm add --filter @lingtai/board` with the four packages at one matching 2.x / 0.2xx line. Commit `pnpm-lock.yaml` with the change.
