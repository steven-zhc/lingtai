# Design: #1345, the "Handled for you" footnote under waiting cards

## Where it goes: inside `CardsPart`'s last branch, as a nested boundary

`CardsPart` already decides the case. The empty Waiting column returns early at `apps/board/src/app/page.tsx:1030`. Landed returns at `:1050`. Every other column with cards falls through to the `col.cards.map(...)` fragment at `:1051-1063`. Add the footnote to that fragment only when `id === 'waiting'`, after the cards:

```tsx
<Suspense key={`handled-foot:${projectKey}`} fallback={null}>
  <HandledFootPart only={only} />
</Suspense>
```

- **Why here and not in the column map at `:1249-1285`:** the board read has already decided that there are cards. That map would have to await `ctx.reads.board` a second time just to find out whether to render anything.
- **Why the boundary is keyed by `projectKey`:** the page's own rule is *"A boundary around a read is keyed, and its key contains `projectKey`"* (#1037, the comment above `Page`). Without the key, switching project keeps the old project's footnote until the new read resolves.
- **The fallback is `null`, not a `Skeleton`:** the empty card's boundary uses `<Skeleton shape="handled">` (`:1032`), but the ticket says to draw nothing while the read is pending.
- **The cards are never delayed:** the cards' own boundary (`:1267`) resolves as soon as `CardsPart` returns. The nested boundary then streams in on its own.

## One read, shared with `HandledPart`

Don't copy `HandledPart`'s read. Move its body (`page.tsx:921-944`) into one helper in `page.tsx`. It returns `{ handled: HandledToday; todayHref: string; weekHref: string } | null`, where `null` covers every case where nothing can be shown:
- the read throws;
- the currency has an `error`;
- the lag is not 0;
- `handledToday` returns null.

`HandledPart` turns `null` into its `empty` note. `HandledFootPart` turns `null` into nothing. The rule *"a read that fails or whose lag is unknown shows the note, never a zero"* (`page.tsx:917-919`) then lives in one place.

`currentReport` is IO, so the helper cannot be unit-tested. Put the pure part in `apps/board/src/lib/handled-today.ts` as a separate function. It takes the currency (`{ error?, lag }`) and the reduced `report().handled`, and returns `HandledToday | null`. That function is what the *read fails or lags* unit tests cover.

`apps/board` is a host and has no row in `effect-ratchet.baseline.json`. The new async server component therefore moves no count, as `HandledPart` doesn't today.

## The short labels

- **In `HandledRow`:** add an optional `short?: { one: string; many: string }` (`apps/board/src/lib/handled.ts:14-22`). It is absent on `asked` and `setup`, the same way `did` is.
- **The helper:** add `handledShort(kind, count): string | null` beside `handledRow` (`:203`). It returns `"5 review fixes"`, or `null` when the kind has no short label.
- **Unknown kinds:** the fallback row (`:205-209`) carries no `short`, so `other` and any unknown kind come back `null`. The footnote leaves them out of the words, and they stay counted in `solved`.

The file's header says the wording *"is frozen: change it there first"*, meaning `doc/design/handled-for-you.html`'s third tab (`handled.ts:4-5`). Add the eight short labels to that tab's copy table in the same commit, as well as the one line the ticket asks for about the footnote.

## The component

Put `HandledFootnote({ today, todayHref })` in `apps/board/src/app/handled-card.tsx` and reuse the card's ✓ SVG (`:21-31`). Pull the SVG into a small local component so it is defined once.

- **When it draws nothing:** it returns `null` when `today.solved === 0`. That keeps the *solved is 0* rule testable without IO.
- **The words line:** `today.kinds`, each passed through `handledShort`, nulls dropped, joined by `' · '`. When `today.more` is not null, add `+{more.kinds} more` with `title={more.hint}`. Leave the `more` fields alone; they already exclude nothing.
- **When the words line is empty:** if every shown kind lacks a label and `more` is null, leave the `<p>` out. Never draw an empty line.
- **The link:** `see them →` goes to `todayHref` without `#handled`. The ticket says *"to today's `/report`"*. The card's own links add `#handled` (`handled-card.tsx:76`, `:91`), so this is a choice; adding the anchor too is acceptable.
- **No inline `style` anywhere in the footnote.** The card sets one `background` per kind (`:57`, `:67`). Leaving out inline styles altogether is what the *no background colour per kind* test checks: assert that the markup contains no `style=` and no `background`.

## The CSS: the column has to become a flex column

`.col` is not a flex container (`globals.css:388`, `.col { flex: 1 1 0; … }`), so `margin-top: auto` alone does not push the footnote down.

- **Scope it to `.col.hot`, the Waiting column:** make it `display: flex; flex-direction: column`, and give `.col.hot .cards` and `.col.hot .cards-in` `flex: 1`.
- **The footnote's rules** follow the mock (`doc/milestone/later/handled-footnote.html:30-33`): `margin-top: auto`, a 1px `--rule-2` top border, muted 12.5px text, the link in `--accent` with `margin-left: auto`.
- **Don't change other columns.** `.cards, .cards-in` are shared (`:410`), and the other columns don't need to stretch.
- **A tall Waiting column:** if Waiting is the tallest column, the footnote simply follows the last card.

## Tests (unit, `renderToStaticMarkup`, as in `apps/board/unit/handled-today.test.tsx`)

- **The fixture's words:** the ticket's fixture gives `5 review fixes · 3 re-merged · 2 combined · 1 restarted` then `+1 more`. Two kinds tie at 1 (`stopped` and `build`), so which one is shown depends on `PROBLEM_KINDS` order (`packages/domain/src/problems.ts:26`): the sort is stable (`handled-today.ts:25`). Build the fixture so the expected words follow from that order, and don't hard-code an order the list doesn't give.
- **Singular and plural:** `1 build fix` and `5 review fixes`.
- **Absence:** the pure gate returns null for a currency with an error, a lag above 0, and a `handled` with nothing raised. `HandledFootnote` returns `''` for `solved: 0`.
- **Unknown kinds:** an `other` kind among the shown four is omitted from the words, and `solved` still counts it.
- **No colour:** the markup has no `style=`.
- **The column itself:** the async page parts are not unit-tested today, so the column-level claim is the component test plus the pure gate. Don't add a test that renders `page.tsx`.

## Edges the ticket doesn't settle

- **Live re-renders:** every live refresh while something waits re-runs `currentReport`. The keyed boundary doesn't re-suspend on a same-project refresh (`page.tsx:1276-1278`), so the footnote doesn't flash. It costs one `ticket_report` read per render, which the ticket already accepts.
- **The last card leaves, or the first one arrives:** the two branches read the same `ctx.reads.board`, so one render never shows both the card and the footnote.
