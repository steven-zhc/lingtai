## Design note: #1066

The ticket already gives the shape. This note pins down three details it leaves loose.

**1. Where the face goes in `effect-ratchet.faces.json`.** `checkFaces` sorts entries by file and then by fn, and refuses one that is out of order (`packages/domain/unit/effect-ratchet.test.ts:294-296`). `closeRunLogFile` sorts before `openRunLog`. So insert it as the entry just above `packages/agent/src/run-log.ts` / `openRunLog`, which is at `effect-ratchet.faces.json:44-49`, not below it. Two faces in one file are allowed. The check that refuses a second `Effect.run*` (`effect-ratchet.test.ts:264-266`) only looks inside each face's own span, and the file already has `openRunLog` (`run-log.ts:249-251`). Use the shape from the ticket's Faces section: a bare `return Effect.runPromise(closeRunLogEffect(handle, tail, path, fate))`, with no `{ signal }` argument.

**2. What `closeRunLogEffect` takes.** Declare the parameters as `handle: FileHandle`, `tail: Promise<unknown>`, `path: string`, `fate: 'keep' | 'delete'`. `tail` is typed `Promise<unknown>` in the module (`run-log.ts:187`). Build each step as `Effect.promise(() => x.catch(() => {}))`. That reproduces the three swallowed awaits at `:237-239` exactly, and the Effect's type is `Effect<void>` with no error channel. Don't use `Effect.tryPromise` plus `orElse`: it does the same thing in more code, and a reader would assume a failure is being mapped. Write it as a plain `Effect.gen`, not as `Effect.fn('agent.runLog…')`, because the ticket asks for no span (#791 edge). Put both functions after `openRunLogEffect`, between it and `openRunLog` (`:248-251`), so the open and close faces sit together.

**3. The method stays an arrow that reads `tail` when it is called.** Write `close: (fate) => closeRunLogFile(handle, tail, path, fate)` inside the object literal at `:236`. That expression reads the closure's `let tail` each time `close` runs. Never copy `tail` into a `const` when the log is opened: `push` reassigns it on every write (`:191-192`), so a copy taken at open would only wait for the header write. The method is not `async`, so the ratchet stops counting it.

**What checks it before the merge.** `pnpm test` runs `effect-ratchet.test.ts`. That test checks the face's shape and the baseline line, which must read `packages/agent` `{ "async": 1, "run": 0 }` (it is `2` at `effect-ratchet.baseline.json:7`). It also catches a sort-order mistake. The close's behaviour (wait, close, then `rm` on `delete`) is only exercised by `packages/agent/integration/run-log.test.ts`, which runs after the merge. Before the merge, what stands in for it is that the body is a line-for-line move of `:237-239` and that `RunLog.close`'s type is unchanged (`:120-126`), so `pnpm typecheck` still passes in `conduct.ts` and `discuss.ts`.
