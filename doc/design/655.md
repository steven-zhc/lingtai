# Design: #655 — an account wall met mid-run pauses the conductor

## Where it goes: `conduct.ts`, not `pass-next.ts`

The ticket's Fix row points at `interruptedAs` (`packages/domain/src/pass-next.ts:336-353`). That function is pure domain code. It returns `{ _tag: 'WaitOnPerson', reason: { _tag: 'AgentCrashed', … } }`, has no store, and cannot append anything. **Leave it exactly as it is.** That it is untouched is the proof the ticket asks for in its Watch out row: the ticket's wait, its resolutions and its rounds do not change.

The pause goes in `conduct.ts`, inside the `// ---- blocked: a person now holds it` branch (`conduct.ts:4358`, `if (outcome === 'blocked')`). It runs after the wait has been written, and it does nothing except add a pause. Every agent in a pass that crashes ends up in that branch as `pass.end.reason._tag === 'AgentCrashed'`. That covers the implementer, the drafting agent (`draftAnswer`, `packages/actions/src/agent-action.ts:1113-1131`, `did-not-finish`), the reviewer (the same file, `did-not-finish`), and a fix round (`conduct.ts:3798-3820`). Doing the check once there replaces a check at each dispatch site.

Two facts make reading `reason.detail` safe at that point:

- **The runtime's sentence is embedded in the detail, not the whole of it.** A fix round's detail is `the fixing agent did not finish (crash: <runtime's words>), so …` (`conduct.ts:3806`). The design agent's is `the design agent did not finish (crash): <words>` (`agent-action.ts:1124`). So the matcher looks for the sentence as a substring, never as the whole string.
- **The unanswered path.** `unansweredEnd` (`packages/conductor/src/pass.ts:1585-1601`) builds `AgentCrashed{cause: 'crash', detail: detailOf(ending)}`, and `detailOf` returns the ending's own `detail`. Read `reason.detail` off `pass.end` and both paths are covered. Do not branch on `pass.unanswered`.

Gate the check on `reason.cause === 'crash'`. A `timeout` or `aborted` is the conductor's own doing, not the runtime's words.

**The judge is the one agent that does not reach `AgentCrashed`.** `askTheAgent` turns any failure other than `never-started` into `held(...)`, which is `{next: 'waiting', …}` (`conduct.ts:2502`, `2622-2627`). So it needs a second call to the same helper, right beside that `held`: a judge's `outcome.failure.kind === 'crash'` whose detail matches. The ticket's *"review or triage run"* edge is this case plus the reviewer above. Nothing in `triage.ts` dispatches a runtime (`grep -n "\.run(" packages/conductor/src/triage.ts` finds nothing), so there is no third site.

## The matcher

Put it in `packages/conductor/src/never-started.ts`, beside `parseResetAt`, as a pure exported `metTheAccountWall(detail: string): boolean`. That file's header (`never-started.ts:14-23`) is the argument for why reading this text is allowed only for a pause. Add one paragraph to that header saying: *this reading is a verdict, and is safe only because a pause is the one thing it can decide. A false match idles the conductor; a miss is today's behaviour.*

Its patterns are the runtimes' own sentences and nothing looser:

- Claude Code: `/\bYou've hit your [a-z ]*limit\b/i`. The quoted message says *monthly spend limit*, and the session and weekly limits use the same opening. `/\byour session limit resets\b/i` is the fallback.
- Codex: `/\bYou have hit your usage limit\b/i`, quoted at `packages/agent/src/codex.ts:339` and `:621`.

The `limit`-only test in Done when holds this boundary, and it should include a near miss such as `rate limit exceeded` and `the recipe allows no limit` (`claude-code.ts:369`'s own wording).

**Do not change either adapter's `kind`.** If `claudeClose` (`packages/agent/src/claude-code.ts:394-407`) or `codexClose` (`codex.ts:644-654`) reclassified these runs as `never-started`, the item would be released instead of waiting. That breaks *"The ticket keeps its crash wait"*, and it gives the classification the second home that `agent-action.ts:667-674` warns against.

## The sentence: a new `NeverStarted` variant

`standDown` already returns `until` (reset parse, falling back to `backoffMs`) and the `reason`. Reuse it whole; do not re-derive the reset. But all four existing variants of `subject()` (`never-started.ts:270-299`) open with *never started*, and that is false about a run that took three turns and cost $0.82. `NeverStarted`'s own doc (`never-started.ts:240-245`) says *"A variant stretched over a case it is false about is `#133`."*

So add `{ readonly of: 'mid-run'; readonly step: string }`, with an opening like *"the {step} step's agent met the account's usage limit after it had started and been paid for; the ticket waits on its crash as usual"*. `standDown`'s tail (*"Every queued item would meet the same thing…"*) is still true. The type is now a misnomer, which is acceptable; renaming it is out of scope.

## Appending

In `conduct.ts`, extend `standDownConductor` (`conduct.ts:1343-1365`) to accept the new variant. Its `it` label and log line need the mid-run wording. The rest it already does correctly for every edge the ticket lists:

- `pauseConductorOnce` (`conduct.ts:877-909`) reads `CONTROL_STREAM`, appends nothing when `reduceControl(...).paused`, and logs and swallows a failed append. That covers *a pause already holding* and *two passes at once*.
- The pause is written `holdsAcrossStarts: false`, as `never-started` writes it (`conduct.ts:1356-1359`).
- It lifts nothing, so a drain or shutdown in progress is left standing.

Call it **after** the wait is appended in the blocked branch. Its `'failed'` result never reaches the `RunOnceResult`. The ticket's wait must not depend on whether the pause was written.

## Tests (unit only)

- `packages/conductor/unit/` already tests `standDown`/`parseResetAt`; find the file with `grep -rln standDown packages/conductor/unit`. Add `metTheAccountWall` cases there over the quoted strings:
  - The #637 Claude Code line, through `standDown({what: {of: 'mid-run', …}, zone: 'America/Chicago', now: <12:33:31 that day>})`, gives `until` equal to 12:50 Chicago.
  - Codex's sentence with no reset gives `now + backoffMs`.
  - The `limit` near misses give `false`.
- The *already paused → nothing appended* claim is a property of `pauseConductorOnce`, which sits inside `conduct`'s generator. Check whether `packages/conductor/unit/conduct-a-whole-pass.test.ts` can drive a pass whose implementer crashes with the #637 detail, using `createMemoryEventStore()` and a control stream that already holds a `ConductorPaused`. If it can, assert two things there: exactly one `ConductorPaused`, and the ticket's wait is the same `AgentCrashed` it is without the match. If that harness cannot reach the blocked branch, say so in the PR rather than moving the test to `integration/`, which no pass runs.

## Docs

`doc/decisions/0108-a-refusal-buys-a-round.md` is a topic ADR in `doc/decisions/`, so this is an edit to it, not a superseding file. Two places:

- **§11** (`:142-152`): add the started-run case. It pauses the same way and with the same `until`, but the item is **not** released; it keeps the crash wait.
- **§12** (`:154-161`): this paragraph currently says a crash *"does not pause the conductor, because a crash is local"*. That sentence becomes false, so it needs an exception for a crash whose detail is the runtime's account-limit sentence. Edit it, or §12 contradicts §11.
