Before you start, there is one trap the ticket does not name.

## Where `held` is null: it follows `foldProgress`, not the new inputs

At present the held line only exists where `foldProgress` returned something. Both callers test that before calling `describeHeld`: `board.ts:702-704` (`progress === null ? null : describeHeld(…)`) and `task.ts:2059-2062` (`named === null ? null : …`). `foldProgress` returns null for an empty stream (`progress.ts:380`, `if (!first) return null`).

The new inputs never return null. `reduceRun([]).roundsOpened` is `[]`, `grantedOf([])` is `[]`, and `spentOf([], [])` is `0`. If the new `rounds` argument is built without checking first, a card with no progress gets a held line it never had, `0 rounds · 0 restarts left`.

So every place that builds `rounds` builds it only where it has a non-null progress for the same run:

- **`laneProgress`** (`board.ts:1012-1016`): when `foldProgress` returns null, return null for `roundsOpened` in that tuple too. Do not return `[]`. The `headOnly` branch (`:1022-1027`) and the `catch` branches return null for it as well. `loadBoard` builds `toCard`'s `rounds` from it only when it is non-null.
- **`loadTask`**: keep the `named === null` check at `task.ts:2059-2061` exactly as it is. Only reduce the named stream for `roundsOpened` after that check passes.
- **`rail.test.tsx`'s `card` helper** (`:406-423`): it passes `foldProgress(events, plan, over)` today. It must pass `rounds` only when that call is non-null.
- **`rail.test.tsx`'s `asBoard`** (`:444-448`): it already passes null progress when `railCandidates` gives no candidate. It must pass `rounds: null` in that case too.

None of the fixtures in `rail.test.tsx` carry a `RunSpent`, so `grantedOf([])` is correct there. The held lines at `:718`, `:753`, `:848`, `:871` and `:889` should all stay the same.

## Where the new parameter goes

`toCard`'s parameter list is positional, and it has callers with up to nine arguments: `triage-move.test.tsx:85` and `triage-context.test.ts:82`. Put `rounds` last, after `fixHead`, as the ticket says, so no existing call changes.

For now, `toCard` still takes `progress` for the rail. Only `held` stops reading it.

`reduceRun` comes from `@lingtai/domain`, and `board.ts` and `task.ts` are both server modules. Import it there. Never import it into `progress.ts`, which is in the client graph.
