## The decision the ticket leaves implicit: which words name the tiers

The chapter and the guide name the middle tier in two different ways:

- The chapter says *A rule / One quick AI look / You* (`when-it-fails.md:9-13`).
- The guide says *A rule / A cause the system acts on / A person* (`guide.md:201-210`).

The ticket says to use *a rule first, then an AI judge, a person last … those words*. The board uses the same wording: the disputed row reads `did: 'AI judge decided'` with the hover text *"An AI judge read both sides and chose the next step"* (`apps/board/src/lib/handled.ts:75-78`).

So the three tiers become **A rule**, **An AI judge** and **A person**, in that order. Use the same words wherever the table's *Who* column names a tier: `Rule`, `AI judge`, `You`/`A person`. Drop "one quick AI look" everywhere it appears, including the bold *one-look rows* paragraph at `:36`.

Carry over the one idea from the guide that the chapter lacks, in one sentence: the judge (or triage) **names a cause and never an action; Lingtai picks the action**. This is ADR 0108 §16: *"an agent names a cause but never acts … what the system does with it is the table's, not the agent's. A person is asked only where the table ends in `askPerson`: `limit`, `unclear` or `environment`."* State the person tier using those three kinds. Nothing here contradicts 0108, so no ADR changes.

## Getting from 1,150 to at most 800 words while absorbing the guide

Most of the words are in the table, so cut there. Decisions:

1. **Drop every `file:line` citation from the table and the prose** (`respond.ts:581-583`, `recipe.ts:3361`, `handled.ts`, `board.ts:534` …). These citations are case (c): the reader of #1295 ran the tutorial, not the source. The numbers stay protected by `apps/site/unit/when-it-fails.test.ts:12-17`, which reads them from `BOUNDS`/`TRIAGE_SPLIT_CHILDREN_MAX`. That test is the check now, and line numbers drift without anything noticing. Also drop the sentence at `:19` about why the values are fixed (*"a value somebody can set is a value somebody can set to a loop"*); that is a design reason, case (c).
2. **Keep the five rows the test pins, word-for-word at the start of each row.** The test finds a row by `l.startsWith('| ' + start)`. The starts are `The API is down`, `The ticket is unclear`, `The ticket is too big`, `Someone else changed main` and `Origin refused`. Each row must still contain its assertion text: `${stepRedos} tries`, `${personAsks} stops`, `at most ${N} parts`, `${baseBranchMerges} merges` and `${landingRetries} times`. With that, the test passes without being edited.
3. **Cut the long cells down to one clause.** *Origin refused the landing* (`:30`) becomes: transient errors retry 3 times; any other refusal goes to a judge if one is declared, otherwise to you. *The Claude limit ran out* (`:32`) becomes: held until the limit lifts, then taken again, with nothing counted. Move what the cut text explains, such as the monthly-cap backoff and the mid-step cutoff, behind the existing one-line link to `reference.md`. Do not restate it.
4. **The read-it-in-this-order list from the guide (`guide.md:223-238`) becomes a short numbered list under *Where you see it*.** The newcomer steps are:
   1. The attempt's row on `/task/<id>`. Read the outcome word first; `never-started` is Lingtai's failure, not the ticket's.
   2. The refusing check's evidence, through the row's pointer.
   3. The run log, through `lingtai attach <runId>`, linked as `cli.md#lingtai-attach` (`doc/cli.md:184`). This is case (a): don't spell out the command's behaviour. *A run that landed has no log* may stay as a clause.
   4. Triage's summary, which is a cause.

   Drop the following, each as case (c): the 2026-09-08 anecdote and the 0032 link, the `#89`/$13.04 line, "read `events` and cite the seq" (operator practice for this repo, not something a chapter-7 reader needs), and the `disagreement`/`Disputed` sentence. The board's *Handled for you* hover already explains the disputed case (`handled.ts:78`).
5. **Rewrite *What you can change in the recipe* (`:46-50`) as one line that links `recipe.md`.** All three bullets already point there or to `reference.md`, so they are case (a).

Nothing moves into `cli.md`, `plugins/` or `requirements.md`. Every fact in the guide section that a reader would look up already has a home: `attach` in `cli.md`, and the limit keys in `reference.md`.
