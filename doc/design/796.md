## Design: a typed read for the control fold (#796)

### The store method: a required sibling, `readTypes`, not an options argument on `read`

Add this to `EventStore` (`packages/event-store/src/event-store.ts:335-357`):

```ts
/** One stream's events of `types` only, in version order, from `fromVersion` (inclusive, default 1). */
readTypes(streamId: string, types: readonly EventType[], fromVersion?: number): Promise<Envelope[]>
```

Make it a separate method and make it **required**. Do not overload `read(streamId, fromVersion?)`, for two reasons:

1. **The type checker finds every fake.** About a dozen test files build a hand-rolled `EventStore` object literal with only `append`/`read`/`readAll`. Some of them feed `readControl`: `packages/daemon/integration/shutdown.test.ts:42-46` (`read: async () => envelopes`) and `:197-210`. Those are in the integration half, which nothing runs inside a pass. If the new method were optional, or a widened second argument to `read`, those fakes would compile and then fail, or silently ignore the filter, only after the merge. A required method makes `pnpm typecheck` list each one, and `packages/daemon/tsconfig.json` includes `integration` and `test`, so the check reaches them. In each fake, implement it as a filter over that fake's own `read`. Do not cast the fake to silence the error.
2. **The ticket's watch-out stays visible at the call site.** `store.read(CONTROL_STREAM).length` is the version idiom (`daemon/control.ts:132`, `:136`). A method with a different name can't be mistaken for it in review. An options bag on `read` can.

Implementations:

- **Postgres** (`event-store.ts:391-397`): `read`'s query plus a `type IN (…)` condition, still ordered by `version`, still through `toEnvelope`.
- **SQLite** (`sqlite.ts:204`, `:255-257`): prepare one statement next to `readStream`. Pass the list as a single JSON parameter, `… AND type IN (SELECT value FROM json_each(?)) ORDER BY version`, so the statement doesn't change with the list's length. `json_each` is already used in this file (`sqlite.ts:405`). Map rows through `toEnvelope` exactly as `read` does.
- **Memory** (`packages/event-store/test/memory.ts:203-208`): `read`'s filter plus `types.includes(r.type)`, through `decodeRow`.
- **Deferred** (`choose.ts:152-158`): forward it like the other three. Its comment says *"Every method forwards"*. Any other wrapper the type checker finds gets the same treatment.

**Empty `types` returns `[]` without querying**, in every implementation. `IN ()` is a syntax error in both SQL dialects, and the contract asks for "an empty type list returns nothing".

The contract cases go in `packages/event-store/test/contract.ts`, next to `'reads one stream in version order, and only that stream'` (`:139`). The fixture should interleave asked-for and other types across two streams. Compare the result against `(await store.read(s)).filter(e => types.includes(e.type))` with `toEqual`. That one assertion covers "only the asked types", "version order", "versions kept, with gaps" and "the same envelope as `read`". Add a separate case for `fromVersion` and one for `[]`.

**Only the memory run is checked before the merge.** The Postgres and SQLite runs of this suite are `integration/event-store.test.ts` and `integration/sqlite.test.ts`. The unit-level stand-in is `unit/memory.test.ts` running the same cases. Run the SQLite one by hand if it finishes in reasonable time (`pnpm vitest run --project integration packages/event-store/integration/sqlite.test.ts`), but don't make the commit wait on it.

### The type set, and the test that keeps it honest

In `packages/domain/src/control.ts`, next to `CONTROL_STREAM` (`:19`), export:

```ts
export const CONTROL_FOLD_TYPES = ['ConductorPaused', 'ConductorResumed', 'ConductorShutdownRequested',
  'ConductorShutdownWithdrawn', 'ContinueRequested', 'DiscussionRequested', 'RunRequested'] as const satisfies readonly EventType[]
```

These are the seven `case` labels in `reduceControl` (`control.ts:142-221`). Also correct the docstring at `control.ts:127`, which says *"Cheap: it is a handful of events, not a history"*.

**The test has to make every handled type change the state.** Otherwise a type that is missing from the set folds to the same `ControlState` either way and the test passes anyway. Empty payloads do not achieve this:

- `ConductorShutdownWithdrawn` breaks unless `d.version` equals the standing request's version (`:178`).
- `ConductorResumed` on an empty state changes nothing (`:185-195`).

Build it like this, in `packages/domain/unit/control.test.ts`:

1. **Base history:** one `ConductorShutdownRequested` at version 1, with `by` set.
2. **For every catalogue type `T`:** take the keys of `SCHEMA_VER` (`packages/domain/src/events.ts:2280`) and append one `T` at version 2. Give it one universal payload that satisfies every case: `{ by, reason, project, issue, runId, chatId, ticketId, question, attempt: 1, version: 1 }`. Then each handled type moves the state:
   - `Paused` sets `paused`.
   - `Resumed` and `Withdrawn` clear `shutdown`.
   - `ShutdownRequested` moves `shutdown.version` to 2.
   - The other three push to their lists.
3. **Assert:** for each `T`, `reduceControl(all, now)` equals `reduceControl(all.filter(e => CONTROL_FOLD_TYPES.includes(e.type)), now)`. Pass a fixed `now`.

Write it with `it.each` over the catalogue so a failure names the type. These envelopes are built by hand and never pass through `parsePayload`, so the universal payload doesn't need to validate.

### The callers

- **`readControl`** (`daemon/control.ts:116-123`): change only the first line, to `store.readTypes(CONTROL_STREAM, CONTROL_FOLD_TYPES)`. The `e.version > since` filter (`:118`) still works on gapped versions, and both folds use the same list.
- **The task page** (`apps/board/src/lib/task.ts:1878`): same substitution, keeping the `timed('events.control', …)` span name so the before-and-after shows in Jaeger, and keeping `.catch(() => [])`. Rewrite the comment at `:1862-1865` (*"it is a handful of events, not a history"*). It is now false, and the reason the stream is read typed belongs there instead.
- **Leave the full `read` in place** at `controlWatermark` (`:132`), at `append` (`:136`), and at every other site the ticket lists. `controlWatermark` returns a `.length` that a starting daemon later compares against `version`. It would be wrong with a filtered list, and nothing in the type system says so.

**Fakes that feed `readControl` and aren't hand-rolled literals**, such as `packages/daemon/test/contract.ts`'s `store.events` and the upgrade-drain/run-pause unit tests, are `createMemoryEventStore`. They pick up `readTypes` from the memory store with no change.

### What settles it after the merge

Two checks:

- **Board span:** the `lingtai-board` span `events.control` should fall from p50 ≈1.3 s.
- **Store measurement:** the ticket's byte measurement, re-run with the seven types. It should be on the order of 50 KB rather than 1.1 MB, and it should not grow when a `Reconciled` is appended.

The test suite can't show either of these. The contract and fold tests are what stand in for them before the merge.
