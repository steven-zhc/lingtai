## One renderer, two views

Keep one renderer in `renderDoctor` and add a second argument: `renderDoctor(report, { verbose = false, next = true } = {})`. The point of this layout is that both views share the same grouping and area ordering. That ordering is the `groups`/`areas` block at `:2949-2963`. Do not write a second copy of it.

- **`verbose: true`** is today's body, unchanged, including today's summary wording (`2 check(s) FAILED — …`, `… 1 to note …, 0 failed`). The only change is in `marker`: `warn` becomes `slot('!', '!')`. That is plain, padded to 4 like the other markers, and not `paint.*`. The comment above that case should then say `!`, not `note`. With that, the ticket's Done-when line *"today's output with `!` in place of `note`"* is literally true. Do not reword the old summary.
- **`next: false`** exists only so `formatReport` can return `renderDoctor(report, { next: false }).join('\n')`. That is the init tail (#702). `cli.ts:108` passes `{ verbose: args.verbose }`.

## Area order: decided, not a question

"Today's area order" means the order the `areas` sort produces today: areas with a failure first, then areas with a warning, then the rest, each tier in `AREA_OF` order. Use the same sort in the short view. Today's comment explains why: *"sections with a failure first and then those with a note"* (`:2943-2944`). The short view filters that list after sorting:

- drop `NOT_IMPLEMENTED`;
- drop any area whose rows are all `skip`.

`Other` is listed like any other area.

## What the short view prints

Plain text, in this order:

```
doctor                                   ← heading('doctor'), as today
                                         ← blank line
34 ok · 2 need attention · 0 failed · 1 not checked here · 3 not implemented yet
                                         ← blank line
✗ Store and log
  ✗     environment                      ← today's row format: `${marker}  ${name}`
        <detail lines, at 8 spaces>        and the detail at today's indent
! Daemon
  !     daemon: currency
        running 8f3a1c2 — 3 commit(s) behind …
✓ Machine
✓ Runtimes
                                         ← blank line, only if next: follows
next: lingtai doctor --verbose           ← only if warned + failed > 0, and only when next !== false
```

**The area line** is the area's worst glyph, one space, then `heading(area)`:

- `symbol.fail()` if any row is `fail`;
- otherwise plain `!` if any row is `warn`;
- otherwise `symbol.pass()`.

`skip` rows do not count toward the glyph, so an area with only `ok` and `skip` rows draws `✓`. Do not pad the area glyph through `marker`. That would push the area name to column 6 and the rows would look misaligned.

**The expanded rows** under each area are only its `fail` rows and then its `warn` rows, in that order (`STATUS_ORDER` without `ok` and `skip`). Indent them two spaces, as `section()` does (`apps/cli/src/output.ts:73-75`), so that `'  ' + marker + '  ' + name` and the detail at `' '.repeat(6)` come out at the same columns as today. The simplest way is to build the rows exactly as `:2967-2970` does and hand them to `section()`, with the glyph-prefixed title in place of the area name.

## The summary line

The summary always has all five counts, in the ticket's order, joined with ` · `:

- `ok` (labelled `ok`)
- `warned` (labelled `need attention`)
- `failed` (labelled `failed`)
- `notChecked` (labelled `not checked here`)
- `deferred` (labelled `not implemented yet`)

No count is left out at zero. Today's `notes` fragment is dropped at zero (`:2974`); that does not carry over to the short view. #214's rule is the comment at `:2929-2941`, which says *"neither is hidden when it is zero"*. That now applies to every count. Keep the comment and add a sentence saying the short view extends the rule to `need attention` and `failed`.

The short view has one form with the same words whether anything failed or not. There is no `FAILED` form. On colour:

- when `failed > 0`, paint only the `N failed` fragment with `paint.fail`;
- when `failed === 0`, paint only `N ok` with `paint.pass`;
- `need attention` is never painted.

The reason is that only `fail` is bold, and amber is `signal`, *"waiting on you, and nothing else"* (0121 §2).
