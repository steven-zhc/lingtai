The shape is the ticket's: add one declaration, `margin-inline: auto`, to the `.detail-body` rule at `apps/board/src/app/globals.css:904-915`, and change nothing else.

**Keep `width: 100%` in that rule.** `.detail` is a column flexbox (`globals.css:898-902`). An item with auto inline margins is not stretched, so without an explicit width it would shrink to its content. With `width: 100%` and `max-width: 82rem`, the two margins share only the space beyond 82rem, so a window narrower than that looks as it does today.

**Leave the waiting and resolved variant alone.** `:is(.detail--waiting, .detail--resolved) .detail-body` (`globals.css:1272-1277`) already sets `margin-inline: auto` and its own `max-width: 75rem`. Its margin declaration becomes redundant, but removing it is the merging of rules the ticket puts out of scope.

**Checks:** no unit test can see this, so the ticket's check in a browser wider than 1400px is the only direct evidence. `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` only show that nothing else broke. I read the CSS but did not re-check the ticket's list of pages that use the class, and the fix does not depend on that list.
