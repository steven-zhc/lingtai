# Design note: #1005, what `status` and `doctor` say holds new work

#1004 is merged into this worktree (`653d10de`). Use the code as it is, not the ticket's guessed names. Four things in the code differ from the ticket or are left open by it. Each is decided below, and the rest of the ticket holds as written.

## What #1004 actually shipped

- **The ceiling lock** (`packages/domain/src/locks.ts:15-26`) is `{ kind: 'ceiling'; since; day; reportedUsd; estimatedUsd; ceilingUsd; until }`. `until` is *"The local midnight after `day`"*. It has no `passed` field. `locksOn` returns a `reached` from any day: *"whether yesterday's is lifted is the guard's to append, never a reader's to compute"* (`locks.ts:29-34`). So `passed` is the reader's to *say*, from `reached.day !== localDay(now)`. That is what 0126 §8 wants, so add no field to `Lock`.
- **`ControlState.dayCeiling.raised`** was `{ day; toUsd; by; at }` (`packages/domain/src/control.ts`). The reducer clears `reached` on every `DayCeilingLifted`, so after a raise nothing in the fold remembered the figure it was raised from.
  - **Decision:** `DayCeilingLifted`'s person variant gains an optional `fromUsd`, the `reached.ceilingUsd` that `raiseTransition` already holds when it builds the event. The fold carries it into `raised`, and `ceilingFacts` into `raised.fromUsd`.
  - A raise written before the field existed has none, and says `raised to $X` without a *from*: a figure the log does not hold is not printed. Optional, so it needs no upcast.
- **`lockSentence`** (`locks.ts:71`) joins private `oneSentence`s. It prints `since` as ISO, and its paused line names no remedy (`locks.ts:55-57`). Its own caller adds ` — lingtai resume <project> first` (`apps/cli/src/project-pause.ts:161-163`).
  - **Decision:** `status` does not use `lockSentence`. It uses its own pure `lockLine(project, lock, now)` with the exhaustive switch the ticket asks for, and writes the words in the ticket: `HH:MM` when `since` is today, otherwise the date and the time. The board's `sinceLabel` (`apps/board/src/lib/locks.ts:59`) is the model. `apps/cli` cannot import it, so copy the three lines.
  - `lockSentence` stays as it is. The guard and `lingtai now` read it.
- **`@lingtai/domain` exports only `.`, `./wait` and `./rate-card`** (`packages/domain/package.json`). `ceilingFacts` goes in `ceiling-lock.ts` and is re-exported from `src/index.ts` the way `todaysCeiling` and `locksOn` already are. Add no subpath.

## `status`

- **Where the project state comes from.** `readStatus` already holds each `ProjectState` from `loadProjects()` (`apps/cli/src/status.ts:345`). The board does the same: `locksOn({ project: state })` on that same list (`apps/board/src/lib/locks.ts:38-41`). So the pause costs no new read. The only new read is `readControl()`, made once (`packages/daemon/src/control.ts:135`).
- **Order inside `readStatus`.**
  - Read the control state once, before the project loop, kept as `ControlState | { unread: string }`.
  - Call `spendLine(control)` with it. Widen `StatusReading.spendLine` to `(control: ControlState | null) => Promise<…>`. Existing tests pass `() => …`, and fewer parameters still typecheck.
  - `daySpendLine` (`apps/cli/src/day-ceiling.ts:181-192`) takes `control` and passes `todaysCeiling(control, now, ceilingUsd)` to `daySpendText`. With `null` it keeps the configured figure.
- **A per-project lock list that cannot be fully known.** Any failure of `loadProjects` already fails the whole command. So a project's list can only be partly unknown, and only when the control read failed.
  - **Decision:** that project's `locks` is `{ unread: <the control read's message> }` in the report and in `--json`. It is never a list holding only the pause. A script reading one place per project must not see "pause only" and conclude the ceiling does not hold.
  - The text still prints `could not read what holds <project> — …`.
  - The pause line is not printed in that case, because the report does not carry it. That costs a line on an already-broken read, and it keeps one shape.
- **`ceilingFacts(control, now, configuredUsd)`**
  - Pure. It returns `undefined` when `configuredUsd === undefined` and `reached === null`.
  - `configuredUsd` comes from `machineDayCeiling()`, which throws on a malformed figure (`packages/env/src/index.ts`; `readDaySpend` calls it at `day-ceiling.ts:176`). Catch that in `readStatus` and pass `undefined`, so a `reached` in the log still prints.
  - `raised` is shown only when `raised.day === localDay(now)`.
- **`now`.** Add `now?: () => Date` to `StatusReading`. A test then pins `passed` and the HH:MM without a fake clock. `renderStatus` stays pure: `passed` is computed in `readStatus`, and the HH:MM is formatted from the `Date` the report carries. Build test dates with local `new Date(y, m, d, h, min)`, as `locksOn` does for `until`. A test then stays green in any time zone.
- **The Queue head** is `status.ts:611`: `` section(`Queue  ${p.runnable.length} runnable${elsewhereSays ? …}`) ``.
  - Append ` — nothing starts: <kinds>` after any `elsewhereSays`.
  - Kinds are the distinct `lock.kind`s, with a passed ceiling left out.
  - With `locks: { unread }`, append ` — what holds it could not be read`. A count printed without it reads as *N will start*.
- **`--json`.** `statusJson` (`status.ts:647`) maps `Date`s to ISO by hand. Write a `lockJson(lock)` beside `rowJson`, using the same exhaustive switch, so `account` breaks `tsc` there too. Do not spread the lock object as it is, which would leave `Date`s for `JSON.stringify`.

## `doctor`

- **The control port must report its error, and the ports it could borrow do not.**
  - `DoctorReach.pause` is `() => Promise<ControlState | null>` (`apps/cli/src/doctor.ts:1135`).
  - `daemonLiveness`'s default swallows the error to `null` (`doctor.ts:1215`).
  - **Decision:** `spendToday(read, control)` takes `control: () => Promise<ControlState>` that throws.
    - In `runDoctor`, wire it as `() => reach.pause().then(s => s ?? Promise.reject(new Error('the control stream could not be read')))`. That is the most `reach` can say.
    - On the default path (`doctor.ts:3294`), pass `() => readControl()` directly, so the real message survives.
  - Do not change `reach.pause`'s type. `daemonLiveness` is out of scope.
- **Existing tests call `spendToday(read)` with one argument** (`apps/cli/unit/doctor.test.ts:550,556`; `doctor-titles.test.ts:130,133`).
  - A default of `readControl` would make those unit tests read the machine's store. Under `HOME=/nonexistent` the read fails, so every detail would gain the could-not-read line.
  - **Decision:** give the parameter no default that reads. Update those four call sites to pass `async () => emptyControl` (`packages/domain/src/control.ts:173`). The default path at :3294 passes the real reader explicitly.
- **Ordering inside `spendToday`.**
  - The control read happens in its own `try`, and is never inside the spend `try` (`doctor.ts:1907-1922`). A control failure must never turn into the row's `fail`, *"today's spend could not be read"*.
  - The reached or passed line is built from `control.dayCeiling.reached`. It does not need the spend read to succeed. So on a spend `fail`, add the reached line to that row's detail too: the row stays `fail`, which is the spend's status, but it says the ceiling holds.

## The ratchet

`apps/cli` stands at `"async": 411` (`packages/domain/unit/effect-ratchet.baseline.json:2`).

- Every new function here is pure: `ceilingFacts`, `lockLine`, `lockJson`, the text builders.
- The one new IO is a call inside functions that are already `async` (`readStatus`, `spendToday`, `daySpendLine`).
- **Add no `async` helper.** If a reader wrapper seems needed, pass `() => readControl()` inline.

## What only the log settles

Whether a raised day prints `of a $40.00 ceiling` in production depends on two things:

- the daemon has been restarted onto #1004;
- `ctl-conductor` holds a `DayCeilingLifted { why: 'person', toUsd }` with today's `day`.

Unit tests stand in for both, because a reducer-built `ControlState` is the input. No integration test is needed.
