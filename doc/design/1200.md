## #1200 — design note

The ticket has the shape right, and every edge on the list is decided. This note covers the parts that are not obvious from the ticket.

### 1. The conflict bound is its own field on `RoutingPolicy`, filled with the recipe's `rounds`

`RoutingPolicy` is `{ rounds: number; restarts: number }` (`packages/domain/src/routing.ts:36`). Add `conflictRounds: number` to it.

There is one caller, `run-attempt.ts:1525-1534`. It passes `{ rounds: roundLimit, restarts: restartLimit }`, and `roundLimit` is capped by a grant (`:1364`). Fill the new field from `ceilings.rounds`, not from `roundLimit`. That is the whole of the *person's grant* edge.

In `offerFor`'s `MergeConflict` case (`packages/domain/src/failure/respond.ts:578-587`), compare `spent.conflictRounds ?? 0` with `policy.conflictRounds` in place of `CONFLICT_ROUNDS_LIMIT`. Keep the `round: spent.rounds` and the `conflict` numbering as they are. Every test fixture that builds a `RoutingPolicy` by hand now needs the field; `tsc` will list them.

`TRANSIENT_RETRIES_LIMIT` and `TRANSIENT_WAITS` go beside `BASE_MERGES_LIMIT` in that file's `// ─── What a failure buys` block (`respond.ts:485`). Rewrite `BASE_MERGES_LIMIT`'s doc comment (`:486-491`, *"At most this many base merges per pass"*) to say *per attempt*. They reach other packages through `failure/index.ts:3`'s `export *` and `src/index.ts:2`. That is the one export path, so add no second one.

### 2. The reducer: keys stay absent until raised

The three counters are optional on `AttemptState`. **`emptyAttempt` (`attempt.ts:270-281`) does not gain them.** Two reasons:
- An encoded row would carry `baseMerges: 0`.
- Every `toEqual` on a reduced state in the unit suite would change for no reason.

`sandbox` is the precedent: *"absent until a sandbox event is reduced"* (`run-codec.ts:139`).

In the `ProposalRouted`/`PassRouted` case (`attempt.ts:585-605`), the move comes from `routeMove(d.offer, d.reply, d.decision)`. Both numbers are already on the stored move: `MergeBase.merge` (`attempt-next.ts:86`) and `FixRound.conflict` (`attempt-next.ts:59`). So:
- **`MergeBase`:** set `baseMerges: Math.max(state.baseMerges ?? 0, next.merge)`.
- **`FixRound` with `next.conflict !== undefined`:** set `conflictRounds: Math.max(state.conflictRounds ?? 0, next.conflict)`.
- **Leave alone:** what a conflict `FixRound` already does to `implementRound` and `roundsOpened` (`:601-602`). Its `round` is the unchanged `spent.rounds`, so `max` keeps `implementRound` the same.
- **`transientRetries`:** declare it on the type and in the codec, and nothing sets it.

In `run-codec.ts`, add three `z.number().int().optional()` keys after `sandbox` (`:140`). Also set `version: 6` with a comment line in the style of `:190-196`: *6: route moves fold into `baseMerges` and `conflictRounds` (#1200); a version-5 snapshot was cut by a reducer that ignored them.*

### 3. Two hops carry the counters, and the first becomes a pure function

`roundsSpent` reaches the walk in two steps:
- `conduct.ts:1347` builds the continuation from `runState`, using `continuationRound(runState, granted)`.
- `conduct.ts:5139` copies it into `from`.

The counters take the same route. Add `baseMergesSpent?` and `conflictRoundsSpent?`:
- to the `from` type, beside `roundsSpent` (`run-attempt.ts:988-993`);
- to the continuation's own type (wherever `continuation.roundsSpent` is typed);
- to both hops.

Then seed them in `runAttemptEffect` (`run-attempt.ts:1355-1363`) as `options.from?.baseMergesSpent ?? 0`, and the same for conflict rounds. Replace the comment at `:1356-1360` with what is now true: *"per attempt (0108 §8), so an `Approve` over a spent `base-moved` reaches a person again at the next move, and `Requeue` is the way to start over."*

**Extract the read from `runState` as a pure, exported function next to `continuationRound` (`conduct.ts:738-740`)**, for example `continuationSpent(run: AttemptState) => { baseMerges, conflictRounds }`, with absent read as 0. The reason is testing. The Done-when *"a continuation whose stream holds ten `MergeBase` routes"* runs from the stream to the offer, and the path through `conduct.ts` is integration-shaped. Three unit tests cover the same claim:
- the reducer over ten `MergeBase` routes reads `baseMerges: 10`;
- `continuationSpent` of that state answers 10;
- `runAttemptEffect` with `from.baseMergesSpent: 10`, on a `BaseMoved`, routes with `CeilingReached { ceiling: 'base-merges' }`.

No test anywhere covers the line in `conduct.ts` that calls `continuationSpent`. Keep it a single line.

A grant on a conflict wait (#1120) still pays through `roundsSpent` (`continuationRound`). That path is unchanged and is not a conflict round.

### 4. `ceiling.ts` imports from `@lingtai/domain`

The product needs `TRANSIENT_RETRIES_LIMIT`, so `ceiling.ts` imports it from `@lingtai/domain`. The constant is not passed in as an argument, because every one of the seven callers would then pass the same number.

The file header (`ceiling.ts:1-8`) says it is *"alone in a file with nothing to import but arithmetic"*, written so that a browser could compute it. Both board importers are server-only today:
- `apps/board/src/app/setup/repository/read/actions.ts:1` is `'use server'`;
- `apps/board/src/lib/recipe.ts:14` imports `node:os`.

`setup-form.tsx:457` only shows `preview.ceiling`. Rewrite the header so it no longer promises that. The import cannot be checked before the merge: only `apps/release/integration/build.test.ts` would see a server-only import reaching a `"use client"` graph, and that test runs after the merge. The check that stands in for it is the grep above: no `"use client"` file imports `@lingtai/conductor/ceiling`.

### 5. The sentence

Let `perAttempt = 2 × rounds + 1 + TRANSIENT_RETRIES_LIMIT`.
- Replace both `rounds + 1` factors (`ceiling.ts:86-87` and `:100`) with `perAttempt`. The restart tail becomes `runs = attempts × perAttempt`.
- `$` goes through `dollarsAt(usd, perAttempt)`.
- Keep `${at}${elsewhere}` where they are now, after *"… each"*.
- The `rounds === 0` branch (`:82-83`) becomes *"up to 4 agent runs — the work, and up to 3 reruns of a run an API error cut off. …"*, and it keeps the `, so at most …` clause.
- The `restarts === 0` endings at `:95-96` do not change.

Spell out the conflict clause with the recipe's number (*"up to 2 more for merge conflicts"*), so the arithmetic can be checked against `rounds` on the same line.
