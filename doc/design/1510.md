# #1510: design note

## Where it goes

There are five edits, and each follows a pattern already in the code:

1. **`packages/projector/src/store.ts:287`**: add `stream?: string | readonly string[]` to `SpendQuery`, beside `ticket` and in the same form. The `ticket` field's doc comment says *"One ticket, or several — a board render asks for every card at once."*
2. **`packages/projector/src/postgres.ts:534`**: add a fourth clause in the existing `where` builder: `stream_id = any($n::text[])`, written like the `ticket` clause at `:534–:536`. In Postgres an empty array matches nothing, so `[]` gives zero rows without any special case.
3. **`packages/projector/src/sqlite.ts:796`**: add the same clause, written like `:796–:799`. **An empty array must not reach `tickets.map(() => '?').join(', ')`**, because that would build `in ()`. If the stream list is empty, push the literal `0 = 1` instead. Don't return `[]` early. The `where` stays one `and`ed list, and the read still goes through `read(() => allOrEmpty(…))`, so a missing table still counts as no spend.
4. **`packages/projector/src/spend.ts:127–:128`**: add a third line, `create index if not exists spend_stream_idx on spend (stream_id)`, under the comment that already explains why these indexes exist: *"without these, every board render scans every row ever to bill the handful of cards on screen."* Add `readSpend({ stream })` to that comment's list of filters.
5. **`apps/board/src/lib/prs.ts:137–:146`** (`spendByPr`):
   - If `ns.length === 0`, return `Effect.succeed(new Map())` before calling `tracedEffect('spend.read', …)`. That way the empty case doesn't open a span either.
   - Otherwise ask `readSpendEffect({ project, stream: ns.map((n) => prStream(project, n)) })`.
   - Keep the in-memory grouping, but replace the nested `for (const n of ns)` loop with a `Map<streamId, n>` built once. The rows now come only from those streams, so the inner scan has no purpose.
   - Leave the `costUsd === null` skip and the *absent means unknown* rule (`:136`, `:142`) as they are.

## The trap the ticket doesn't name: `readSpendEffect` rebuilds the query field by field

`packages/projector/src/spend.ts:386–:390`:

```ts
export const readSpendEffect = Effect.fn('projector.readSpend')(function* (options: ReadSpendOptions = {}) {
  return yield* withStoreEffect({ url: options.url, max: 1 }, (p) =>
    p.spend({ ticket: options.ticket, project: options.project, since: options.since }),
  )
})
```

`ReadSpendOptions extends SpendQuery` (`:376`), so once `stream` is on `SpendQuery`, `readSpendEffect({ project, stream })` typechecks. But `stream` is then **silently dropped**: the store gets `{ project }` and reads every row of the project, which is today's behaviour.

`spendByPr` filters in memory anyway, so its result would still be correct, and a test that compares only the Map would pass. The ticket's whole purpose would be lost, and no test would go red.

So `:389` must pass `stream: options.stream` along. The better fix is to destructure (`const { url, ...query } = options`) and pass `query`, so a fifth field can't be lost the same way. `store-face.ts:81` already forwards the whole `query` and needs no change, but check it.

## How each "Done when" item is checked before the merge, and which can't be

- **The contract additions and the index existing after `create`.** `packages/projector/test/contract.ts` is run only from `packages/projector/integration/projection.test.ts` (Postgres) and `packages/projector/integration/sqlite.test.ts`. Both are in the integration half, so `pnpm test` never runs the new cases. Write them anyway, beside `:828` *"reads spend filtered by ticket and project, oldest first"* and using its fixture:
  - a `stream` filter that keeps only those streams' rows, in `seq` order;
  - `stream: []` gives `[]`;
  - `stream` with `project` applies both;
  - the index exists after `create`. Read `pg_indexes` in Postgres and `pragma index_list('spend')` in SQLite. If it is simpler to keep one store-neutral test, branch on the store's kind as the suite already does.

  These are verified only after the merge. Say so in the commit.
- **The unit-level stand-in, in the board.** `apps/board/unit/request-reads.test.ts:93–:96` already mocks `@lingtai/projector`'s `readSpendEffect` as `() => Effect.succeed([])`. Add a unit test (in that file or a sibling) that makes it a `vi.fn` and asserts:
  - `spendByPr(project, [])` never calls it and returns an empty Map;
  - `spendByPr(project, [1, 2])` calls it once with `{ project, stream: [prStream(project, 1), prStream(project, 2)] }`;
  - given rows on those streams, one with `costUsd: null`, and no rows for one `n`, the Map has the summed cost, skips the null, and has no key for the PR with no rows.
- **That `readSpendEffect` forwards `stream`.** No unit test reaches the stores' SQL. That part is checkable only in review and by the integration contract after the merge, so keep the forwarding change at `spend.ts:389` small enough to see at a glance.

## Decided here

- **The empty case is handled in two places:** an early return in `spendByPr`, and `0 = 1` in SQLite. The early return is what "reads nothing" needs. The SQLite clause is what the store contract needs, because other callers may pass `[]`.
- **The `seq` order is unchanged.** Postgres can satisfy `stream_id = any(…)` through the new index and then sort the few rows it finds. A composite `(stream_id, seq)` index isn't needed for a handful of PR streams.
- **The PR page also benefits.** `prs.ts:379` calls `spendByPr(project, [n])`, so it gets the filter with no edit. Its `orElseSucceed(() => null)` keeps a failed read as `null`, never `$0`. The PR page's other read at `:298` (`ticket: ticketStream(…)`) is out of scope.
- **No ADR is touched.** The index adds no column, and `shape.ts:161` compares columns only.
