# #878: design note

## 1. Put the reducer in `run-codec.ts` and copy #876's decode split

Put `attemptReducer` in `packages/domain/src/run-codec.ts`, beside the codec, the same way #876 put `ticketReducer` in `ticket-codec.ts:170`.

- `run-codec.ts` imports only the *type* of `AttemptState` (`run-codec.ts:16`).
- `attempt.ts` imports nothing from the codec (`attempt.ts:18-22`).
- So bringing in the values `emptyAttempt` and `reduceAttemptEvent` creates no cycle and leaves zod out of `attempt.ts`.

The decode needs the same split #876 made:

- `decodeRun` always ends with *"run \`lingtai projection rebuild ${projection}\`"* (`run-codec.ts:124-127`). The ticket's edge says a snapshot decode must not suggest a rebuild.
- Move everything from `JSON.parse` through the `StoredRun.safeParse` failure into an unexported `parseStored(stored): { ok: true; state } | { ok: false; what }`. This copies `ticket-codec.ts:132`.
- `decodeRun` keeps its wording byte for byte, so `task_view` and its tests are unaffected.
- `attemptReducer.decode` throws `RunCodecError(\`attempt snapshot: the stored state is not today's shape (${what})\`)`. This matches `ticket-codec.ts:176-180`.
- `readThroughSnapshot` adds the one log line.
- Register it as `attempt: attemptReducer` in `packages/domain/src/reducers.ts:5`.

`openedAt`, `version` and `lastSeq` are already in `StoredRun` (`run-codec.ts:89`, `:104-105`), so the codec needs no new field.

## 2. Test-side rename: re-key the hash lock, keep the hashes

`histories.hashes.json` is keyed `${h.kind}.${h.name}`, and each value is a hash of the events only (`packages/domain/unit/histories.test.ts:174-180`). Renaming the `run` kind to `attempt` therefore changes every `"run.…"` key and none of the values.

- Rename the keys in `histories.hashes.json`, and in any `CELLS` entry in that test that names `run.…`.
- **Do not paste new hashes.** If a value changes, the rename touched an event, and that is the bug.
- `histories.run` is imported by nine test files: `projector/unit/task-view-run`, `event-store/unit/snapshot-read`, `conductor/unit/{claim-snapshot,resolve-wait,ticket-snapshot-readers}`, `domain/unit/{attempt,run-codec,verdict-ladder}` and `board/unit/present-attempt`. `tsc` finds them all.

`everyAttemptEvent` goes under `histories.attempt`, beside the existing histories. To reach every `COVERS.attempt` type, it can concatenate events from the existing attempt histories on one stream with renumbered versions. Whatever it contains, the hash lock needs one new key for it.

## 3. One helper, at every promise-shaped site

Promise-shaped sites call `readState(store, attemptReducer, runId, 'all', { snapshots, writer })` (`packages/conductor/src/snapshot-state.ts:14`).

- `apps/*` and `reconcile`-style callers import it from the `@lingtai/conductor/snapshot-state` subpath (`packages/conductor/package.json:9`), never from the barrel.
- Every site is already inside an `async` function, so `effect-ratchet.baseline.json` does not move.
- `readState` rethrows the store's own error unwrapped (`snapshot-state.ts:21-22`). So `runSubject`'s rule still holds: *"The read's rejection is left to reach `createSubscriber`'s `deliver`"* (`apps/cli/src/subscribers.ts:86-90`). So does the board's `catch` → `null` (`board.ts:1033-1035`).

**`runOnce` is the exception.** It already runs inside `Effect.gen` and reads the ticket as `readThroughSnapshot(store, ticketReducer, ticketId, 'all', ticketSnapshots).pipe(Effect.orDie)` (`conduct.ts:1098`).

- Replace `lastRun`'s `Effect.promise(() => store.read(previous.runId))` (`conduct.ts:1230`) with `readThroughSnapshot(store, attemptReducer, previous.runId, 'all', ticketSnapshots).pipe(Effect.orDie)`.
- `ticketSnapshots` (`conduct.ts:676`) already pairs this log's snapshots with `options.snapshotWriter`. A snapshots value is per log, not per reducer, so reuse it and don't build a second one.
- `orDie` keeps the defect `Effect.promise` gave.

## 4. Where each site gets its snapshots and writer

The rule is #877's: *a store passed in has none of its own* (`packages/daemon/src/control.ts:141-142`).

- **Board, `board.ts:1022-1043`.** It always uses the default `eventStore`. Pass `{ snapshots: log.snapshots, writer: await boardWriterOrNone() }`, importing from `../lib/snapshot-writer.ts` as `actions.ts:78` does. Call `boardWriterOrNone()` once before the `Promise.all`, not once per card.
- **Board, the railed and head-only branches.** Both read the same `attemptReducer` state.
  - The railed branch uses one `readState` for `progressOf`, `roundsOpened` and the head.
  - Change `headOf` to take `(task, state)`.
- **`createSubjectResolver`, `subscribers.ts:105`.**
  - Its signature becomes `(store?: EventStore, options: SnapshotReadOptions = {})`.
  - Inside, compute `snapshots: options.snapshots ?? (store === undefined ? log.snapshots : undefined)`.
  - That test needs the parameter's own `undefined`, so drop the `= eventStore` default from the parameter and resolve `store ?? eventStore` in the body.
  - `daemon.ts:541` passes `createSubjectResolver(undefined, { writer: writer ?? undefined })`. The daemon's `writer` is in scope (`daemon.ts:229`).
  - `runSubject` gains the options and passes them through.
- **Triage.** `CatchUpTriagePorts` already has `snapshots`/`writer` and passes `deps` to `readState` (`triage.ts:170`). Sites `:182` and `:467-468` become `readState(deps.store, attemptReducer, runId, 'all', deps)`.
  - At `:467`, `runEvents` is used only to reduce. Check that nothing else below reads `runEvents`. If something does, that read stays raw and the commit says why.
- **`lingtai status`, `status.ts:209` and `:240`.** Both use `eventStore`, so pass `{ snapshots: log.snapshots }` with **no writer** (0124 §5). `hasSavedHead`'s `catch` → `unreadable` is unchanged.
- **`resolve-wait.ts:415` and `:502`.**
  - `resolveWaitHolding` already holds the resolved `options.snapshots` and `options.writer` (`resolve-wait.ts:181`, `:220-223`).
  - `savedHead(store, ticketId, runId)` (`:409`) gains a trailing `SnapshotReadOptions = {}`, and the call at `:307` passes `{ snapshots: options.snapshots, writer: options.writer }`.
  - `checkApprove` (`:486`) gets the same treatment. The board's writer thereby reaches the attempt read through `resolveWait`, which `actions.ts` already calls with a writer.

## 5. `savedFixWork` and `nextPrompt`: widen, don't fork

- **`savedFixWork(runId, events)`** (`apps/board/src/lib/saved-fix-work.ts:9`) is called with raw events by `task.ts:1686`, `test/visual-waiting.ts:453` and `unit/standing.test.tsx:1334`.
  - Add `savedFixWorkFromState(runId, state: AttemptState)` and move the switch into it.
  - The existing function becomes `savedFixWorkFromState(runId, reduceAttempt(events))`.
  - `board.ts` calls the `FromState` form. The task page keeps its full read and its existing call.
- **`nextPrompt`'s `lastRun`** (`packages/conductor/src/prompt.ts:106`). The Done-when says *"The prompt tests are unchanged"*, and `prompt.test.ts` passes `lastRun: []` and event arrays (`:222`, `:271`, `:298`).
  - Widen the type to `readonly Envelope[] | AttemptState | null`.
  - At `:121`, use `Array.isArray(input.lastRun) ? reduceAttempt(input.lastRun) : input.lastRun`.
  - That keeps the tests and the board preview (`apps/board/src/lib/prompt.ts:168`) untouched.
  - The doc comment at `:94-97` says that `null` means *not read* and that an empty array means *committed nothing*. Keep that distinction and add that a state is the same stream already reduced.
  - Do not add a second field: two inputs for one fact is an invitation to set both.

## 6. Tests (unit-only; nothing here needs the integration half)

- **`reducers.test.ts`** gets the registration, coverage, round-trip and version-row checks. The new `"attempt": { "1": … }` value comes from that test's red output.
- **The shared read.** Extend `packages/event-store/unit/snapshot-read.test.ts`, where #876 put the ticket case. For every prefix of every `histories.attempt` history, plant a snapshot at each version, plus a void one and an undecodable one. `readThroughSnapshot(…, attemptReducer, …, 'all')` must `toEqual` `reduceAttempt(whole)`, `version`, `lastSeq` and `openedAt` included.
  - The undecodable case asserts the logged line contains no `projection rebuild`.
- **Sites.** One test in the shape of `packages/conductor/unit/ticket-snapshot-readers.test.ts`:
  - plant an attempt snapshot below the head on `createMemoryEventStore()`;
  - call `resolveWaitHolding` (the `GrantFixRound` and `Approve` paths) and `createSubjectResolver(store, { snapshots })`;
  - assert each answer equals the no-snapshot answer.
  - Spy on `log.snapshots.latest` so it throws, and assert a store passed in with no `snapshots` never touches it.
- **Prompt tests.** The unchanged `prompt.test.ts` covers the array form. Add one case asserting that `nextPrompt` with `lastRun: reduceAttempt(events)` gives the same text as with `lastRun: events`.

`pnpm typecheck`, `pnpm lint`, `pnpm fmt:check` and `HOME=/nonexistent pnpm test` cover all of this.
