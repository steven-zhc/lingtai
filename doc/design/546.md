## The decision that isn't in the ticket: one ticket, two loops, two kinds of "again"

The page's structure is the Watch-out row. Draw the diagram as **one Chapter Garden ticket** going along the ten steps in `STEPS` order (`packages/domain/src/vocabulary.ts:22-33`: claim, admit, prepared, design, implement, build, review, proposed, merge, end). It has **two return arrows, visibly different**:

1. **Inside the pass**: a red `build` or a refusing `review` goes back to `implement` in the *same worktree*, on the *same branch*. That is a **fix round**, bounded by `runtime.limits.rounds`. It is not a new pass.
2. **Outside the pass**: the ticket goes back to the queue, and a *new pass* starts from the base branch in a fresh worktree. That is a **restart** when the machine does it (bounded by `runtime.limits.restarts`) and a **requeue** when a person does it.

At `proposed`, draw the wait as a fork:

- **Continuing the saved work:** *Approve and continue*, or *Continue fixing current work*.
- **Starting over:** *Start over from base*, or *Add to the ticket and start over*.

The ending outcomes: landed, closed, or still waiting.

Every claim here already exists in `doc/glossary.md`'s two-column table ("Continues the saved branch" / "Cuts a new branch from the base"), which is #541's settled language. **Write the concepts page from that table, not from memory**, and carry these points over:

- A person's continuation **still starts a pass at `admit`/`prepared` and then jumps** to the step it resumes at (glossary bullet citing `packages/conductor/src/pass.ts`). Do not call it "a new pass from base", and do not call it "the same run carrying on". *A pass resumed on the saved branch* is accurate.
- A requeue **spends no restart**. Use the board's own sentence: *"This neither spends nor refunds an automatic restart."* (`apps/board/src/lib/resolution-copy.ts:4`).
- A requeued pass is told about earlier attempts and can reuse their commits, **but it is new development and goes through build and review again** (glossary, citing `prompt.ts`'s `attemptBrief`). This is the sentence that keeps "requeue" from reading as "continue".
- Use the button labels exactly as `RESOLUTION_COPY` gives them (`resolution-copy.ts:7-41`). For the newcomer page, use the four above plus *Answer the question* and *Close the ticket*. Leave *Split* out; it is not part of the newcomer path.

## The glossary on the page

Keep it small: one row per object the ticket lists (project/repository/base branch, ticket and kind label, recipe, pass, attempt, agent run, worktree, checks/review, wait, landing, event log/board). Each row gives one plain sentence plus the Chapter Garden example ("the story ticket you opened in Step 2", "the `npm test` the recipe runs at `build`"). **No event type names and no file paths.** The Done-when says the page has to be readable without them. That is the difference from `doc/glossary.md`, which cites code on every row.

**Do not publish `doc/glossary.md`, and do not merge the two files.** That file is written for a repository reader. Its job, linked from `doc/the-pass.html:453`, is to say which code each word maps to. The concepts page restates the same seven words for a different reader. To keep the two from drifting, the unit test below pins the labels to the board's copy, not to either document.

## Links out

Link `the-pass.html`, `architecture.html`, `glossary.md` and `operating.md` as plain relative links, the same way the tutorial does. While `DOCS_PUBLIC` is false, `resolveHref` sends all four to GitHub (`docs.ts:426-427`), and the test at `docs.test.ts:237` pins that for the HTML. When the switch flips they become site routes with no edit. The cost: an `.html` link opens as source on GitHub today. Accept that here. Publishing `the-pass.html` alone would mean carving a public subset out of `scripts/doc-assets.ts:26`'s all-or-nothing copy and `prune-hidden-docs.ts:21`'s `rm` of `out/doc`. It would also bring a broken link with it: the-pass.html's relative `glossary.md#what-happens-next` (`scripts/the-pass.py:270`) would 404 under `/doc/`. That is a separate ticket, not this one.

Do not link `reference.md` as if it were on the site. It is private, and `docs.test.ts:199` asserts that it stays so.
