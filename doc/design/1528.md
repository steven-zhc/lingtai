## The decision the ticket does not show: two names already exist in `@lingtai/setup`

`packages/setup/src/index.ts` re-exports every file with `export *`. Two of the names this ticket moves are already exported from the package, and their wording is different:

- **`personalRefusal`** is at `packages/setup/src/personal-branch.ts:35`, with the signature `(name, main)`. It is the board's check, used by `setup-answers.ts:144` and `conductor/src/add-from-page.ts:388`. Its sentences are *"`<name> <why>`"* and *"`<name>` is the main branch — the personal branch must be a different one"*. The CLI's version (`apps/cli/src/team.ts:89`) takes `(name, main, fallback)` and says *"git refuses … — use `<safe>`?"* and *"… is the same branch as …, ignoring case — name a different one for your own work"*. If a second `personalRefusal` goes into `project-checks.ts`, `export *` makes the name ambiguous and `pnpm typecheck` fails. The two can't be merged either: the refusal text must move word for word, and new wording is out of scope.
  **Decision:** the CLI's check moves as **`personalBranchRefusal(name, main, fallback)`**, beside `madeSafe`. Leave `personal-branch.ts` alone. Don't touch `personalFix` either: it is a different algorithm from `madeSafe`, so the two can't share code. Two wordings for the personal branch are a fact today, and this ticket must not change words. Joining them is a backlog entry, not this ticket.
- **`GITHUB_LOGIN`** is already at `packages/setup/src/setup-answers.ts:39`, as the same regex as `team.ts:20` (its comment: *"(the CLI's `GITHUB_LOGIN`)"*). **Decision:** delete `team.ts:20`. `loginRefusal` in `project-checks.ts` imports `GITHUB_LOGIN` from `./setup-answers.ts`. Don't move the regex a second time, and change that comment to name `loginRefusal`.

## Shapes

- **`runtimeRefusal(answer, { signedIn, runtimes, kept, orNone })`** is pure and returns `string | null`. Today the closure returns `Effect.succeed` (`agents.ts:230-239`) but does no IO, so the caller wraps it. `signedIn` is the list that has already been filtered (`agents.ts:218`, without the implement-only agents), and `choiceList` is built from it in that order. `orNone: true` stands for both halves of today's reviewer call (`agents.ts:319`): it accepts `'none'`, and it appends `', or none'` to every refusal. That way #1529's descriptor gets the whole check, not one half with the `'none'` branch left at the caller.
- **`leftoverRefusal(steps, signedIn, editedInPlace, fullyReplaced, keptRuntimes)`** returns `{ refused: string | null; log: string[] }`. Today it logs and then refuses (`agents.ts:111-130`), so `log` holds the lines from before the first refusal, in the order they occur. The caller (`agents.ts:363`) logs every line and then returns the refusal, which keeps the output order. `steps` is what `at.draft.get(['steps'])` returns (`unknown`); the null and non-object guard at `:95` moves inside the function.
- **`sourceClashRefusal({ given, project, history, current, kept })`** returns the sentence at `source.ts:117-121`, or `null` when `history` is empty, `given` is `null`, or `given === current`. The log line at `:123-127` stays in `source.ts` and imports `DIFFERENT_SOURCE_CLASH`. Change three imports at the same time: `apps/cli/unit/plain-output.test.ts:20` (an import, not an assertion, and that file is not on the no-change list), the comment at `packages/setup/src/propose-setup.ts:228`, and `landing.ts:39`, which takes `ROUNDS_RETIRED` from `@lingtai/setup` directly. Only `init.ts:172` and `first-project.ts:118` go through the `wizard-options.ts` re-export, as the ticket says.
- **`wallRefusal`** is pure, with `try/catch` around `parseDuration`. Import it from `@lingtai/recipe/duration`, the subpath `setup-answers.ts:31` already uses, not from the package root.
- **`wholeNumberRefusal`** replaces the two identical lambdas at `landing.ts:258` and `:276`.

All of these are pure except `branchOnGithubRefusal`. It returns `Effect<string | null>` and maps `'unreadable'` to *"could not read whether `<answer>` exists on GitHub"*, never to `null`. Nothing here adds `async` or `Effect.run*`, so `packages/domain/unit/effect-ratchet.baseline.json` cannot go up.
