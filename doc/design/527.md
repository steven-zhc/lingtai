## Design note for #527

Work in `TriageBand` and the Waiting page’s styles after #526’s shared layout. Keep one band location between “where it is” and resolutions, with distinct visual treatments for advice, failure and conflict evidence. `NotDeclared` and `NotNeeded` should leave that location empty; the stopping step’s words remain in “where it is.” This follows 0118 §3: “Where it is not declared, nothing runs, and the page shows the ticket, where it is, and the stopping step’s own words” (`doc/decisions/0118-a-hold-explains-itself.md:330-344`). The existing status switch returns `null` for both absent states and renders failure separately from advice (`apps/board/src/app/standing.tsx:58-76`); preserve that distinction while styling the band.

Put long text and control wrapping at the elements that own them: triage summaries and questions, hunk summaries containing paths, answer labels, and the resolutions row. Keep each hunk’s status and path together and its divergent question readable beneath it. The component currently uses `<details>` for each hunk and opens divergent ones (`apps/board/src/app/standing.tsx:109-132`); 0118 §8 says the page “lists every hunk with its status and opens only the ones that need the person.” Do not add the mockup’s code columns: 0118 says its mockups “illustrate the decision and do not extend it” (`doc/decisions/0118-a-hold-explains-itself.md:600-606`). Bound any intrinsically wide child so it cannot widen the page; the existing `.sbody` comment records that an uncapped grid track once made a 1425px page 7754px wide (`apps/board/src/app/globals.css:965-978`).

Use the four fixtures named in `doc/design/task-detail-page.md` for desktop and narrow screenshots, comparing the five-part reading order as well as clipping. Record any already-satisfied case with its screenshot. Keep checks at presentation level: 0118 §1 says `allowedResolutions` decides the available resolutions and triage “advises and never moves the item” (`doc/decisions/0118-a-hold-explains-itself.md:251-258`); a newly discovered behavior gap belongs in a separate functional ticket.
