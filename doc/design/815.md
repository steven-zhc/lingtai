# Design: #815 — the replay receipt

## Where each piece lives

- **The scene copy goes in `page.tsx`, not in the client component.** Both the order case and the `log` guard read `page.tsx`'s source through `prose()` (`unit/page.test.tsx:14-17`), and the order case looks headings up with `text.indexOf(heading)` (`:58-66`). If *The agent got it wrong. Twice.* lived in `replay-receipt.tsx`, the order case would not find it. Keep the five scenes in `page.tsx` as server markup, each a `<div className="rp-scene" data-step="N" id="sN">`, followed by the mock's empty `rp-end` sentinel with `data-step="6"` and `aria-hidden` (`doc/design/home-page-v3.html:2751`, styled at `:2300-2304`). Step 6 means "past the last scene" only because that sentinel is there.
- **`ReplayReceipt` renders only the `<aside className="tale-side">`.** In a `useEffect` it finds the scenes with `document.querySelectorAll('.rp-scene[data-step]')` and observes them the way the mock's script does (`:3249-3266`): scenes with `rootMargin: '-48% 0px -48% 0px'`, and a second observer on `.hero` at `threshold: 0.6` that shows step 0. It does not wrap the scenes. That way the page stays a server component, and `copy-command.tsx:10-11` still holds: *"A client component for the one thing that needs the browser; the rest of the home page stays static."* If `IntersectionObserver` is undefined, the effect returns and the receipt stays at state 0.
- **`receipt.tsx` has no `'use client'` and no server-only import.** `replay-receipt.tsx` imports it and renders `<Receipt {...receiptAt(step)} />`, and the books ticket renders it directly from server code. A component with neither marker works on both sides. Do not add `import 'server-only'`, because the client import would break. That break shows up only in the Next build (`apps/release/integration/build.test.ts`), which this pass does not run.
- **The server render is state 0 because of `useState(0)` and nothing else.** `renderToStaticMarkup(<Home />)` already renders client components with their initial state and runs no effects (the existing guard at `unit/page.test.tsx:50` depends on this). The page-markup unit case can assert *Queued*, four `—` values, no `now` class and no landed class directly on that render. Do not start from a "final" state and rewind in an effect.

## Decisions the ticket leaves open

- **Row values are strings, not ReactNode.** `receiptAt` returns plain data, so the tests can check "every row is `—` at 0" and "cost never decreases" with no rendering. Write the check line as `'✗ → ✓ after 1 round'`, and have `Receipt` wrap each `✗`, `✓` and `→` it finds in `<span class="no|yes|dim">`. That is the mock's markup (`:3159-3161`) without `innerHTML`. Put the dimmed *waiting…* on the row as a `muted: true` field rather than markup. Keep cost as a number in cents, or as a string the test parses, so the monotonic check really compares numbers.
- **Mapping the status pill.** The mock uses `wait` (`--signal`) for *Fix round 1/2* (`:3192`, `:3200`). `site.css:242-244` says `--signal` *"on the board means a person is being waited on now"*. Following that rule: step 0 → `queued`, steps 1-4 → `running` (`--accent-soft`/`--accent-ink`, as at `:2274-2277`), step 5 → `waiting` (`--signal`), step 6 → `landed` (`--pass`). `closed` uses `--held`, which `site.css:242` already uses for "ended without landing". This is the one place where the page will look different from the mock. Say so in a comment, so the person comparing it to the mock knows why.
- **The footnote changes with each step.** The mock's `lr-hint` (`:3170-3224`) has one sentence per state. Treat it as the receipt's `footnote` prop, always preceded by the `ILLUSTRATION` tag. State 0's sentence is *Scroll — the receipt fills in as it happens.*
- **Text that changes on scroll is not covered by the `log` guard.** The guard reads `page.tsx` and the server render (`unit/page.test.tsx:48-55`), so it never sees states 1-6 in `replay-receipt.tsx`. Add a unit case that serializes `receiptAt(0..6)` (status, values, footnote) and asserts no `/\blogs?\b/i`, the same regex the guard uses. The mock's hints are clean today, but that check is what keeps them clean.
- **The hero's second action** is the ticket's *See a receipt fill in ↓* → `#replay`. Do not use the mock's *Watch the 2-min run* (`:2698`).
- **The `.tale` grid wraps both `<section>`s inside the existing `.wrap`** (`page.tsx:9`). Keep `.home .hero` as it is, but drop its `padding-bottom` and its `max-width` override in favour of the mock's `.tale .hero h1` (`:2143-2145`). `.home section { padding: 88px 0 }` (`home.css:5`) now also applies to `#replay`, which is intended. Take the CSS from the mock's *second* `.tale` block (`:2131-2155`, with the 1080px query at `:2185-2194`). Ignore the earlier `.tale` at `:1184`, which is an unrelated older layout. Put every transition and the stamp animation (`:2286-2296`) inside `@media (prefers-reduced-motion: no-preference)`, so a reader who asked for reduced motion gets the end state with no animation.
- **`aria-live`.** Keep the mock's `aria-live="polite"` on the aside, but put it on the status pill and cost only, not on the whole receipt. Otherwise every scroll step reads out the entire receipt again.

## Out of reach in this pass

The scrolling behaviour (fills in, rewinds, stamped last) is checked only by the person in `Done when`. No unit test covers the observer, because the unit project runs without a DOM (`vitest.config.ts:72`), and that is acceptable. The unit tests stand in for it: `receiptAt` gives the stamp only at 6 and a cost that never decreases, and the server render is state 0.
