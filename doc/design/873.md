# Design note — #873

## Where the generic read goes

Put it in a new file, `packages/event-store/src/snapshot-read.ts`, and export it from `src/index.ts` beside the `./snapshots.ts` exports (`index.ts:21-27`). It takes `(store, reducer, streamId, types, { snapshots?, writer? })` and returns `Effect<S, unknown>`, where `S` is the unevaluated state.

- It never reads `log` from `index.ts:78`. It uses only the `snapshots` it was handed. Who passes which store stays a caller's decision, as the ticket's Watch out requires.
- The body is `control.ts:136-177`, with three changes:
  - `controlReducer` becomes `reducer`.
  - `CONTROL_STREAM` becomes `streamId`.
  - `CONTROL_FOLD_TYPES` becomes `types`.
- With `snapshots === undefined` it is just `readTypes(streamId, types)` reduced from `reducer.initial`. This replaces the separate early return at `control.ts:135`, so `readControl` has one path.
- `sayOnce` and its flags (`control.ts:187-192`) move with the read.
  - Keep the message byte-identical by building it from `reducer.name`: `` `${reducer.name} snapshot ${kind} failed, reducing from version 1: …` ``. `controlReducer.name` is `'control'` (`domain/src/control.ts:330`), so today's line comes out unchanged.
  - Key the once-flags by `reducer.name` + kind, not kind alone. Otherwise child 5's ticket reducer would silence the control reducer's first log.

**Error channel.** Each store or snapshot call is wrapped as `Effect.tryPromise({ try, catch: (e) => e })`. The failure is the original rejection, never `UnknownException`. The swallowed failures (`latest` and the second `latest` at `:157`) stay swallowed inside, exactly as now. Only a failed `readTypes` reaches the error channel. That is the "events read fails" edge.

## The daemon: one run, and the two appends go through `readControl`

The ratchet allows `packages/daemon` exactly `run` +1 and `async` +0 (`effect-ratchet.test.ts` counts every `async` modifier on a function, arrow or method, and every `Effect.run*`, `:88-110`). So `requestShutdownUnlessStanding` and `withdrawShutdown` cannot each run the Effect, and a new private `async` helper is also a raise. They must therefore call **`readControl` itself**:

- `readControl(store, since, cache)`: for `since <= 0`, compute `snapshots` as today (`:134`). Then:
  ```
  const r = await Effect.runPromise(Effect.either(snapshotRead(...)))
  if (Either.isLeft(r)) throw r.left
  ```
  Then return `evaluateControl(r.right, new Date())`.
  - Rethrow `left` rather than letting `runPromise` reject with a `FiberFailure`. `pausedSentence` prints `(err as Error).message` (`apps/cli/src/day-ceiling.ts:119-121`), and today's callers see the store's own error object.
  - This is the one `run`.
- In the loops (`control.ts:283`, `:411`):
  - First `const at = await store.head(CONTROL_STREAM)`.
  - Then `const control = await readControl(store, 0, { snapshots: store === eventStore ? log.snapshots : undefined })`.
  - Then append at `at` rather than `events.length`.
- Why `store === eventStore`, and not `=== undefined`: both functions take `store: EventStore = eventStore` as a default parameter, so `undefined` cannot be seen inside them. Identity with the default store says the same thing as `readControl`'s `store === undefined`. A test's memory store is never `eventStore`, so it never gets `log.snapshots`.
- `reduceControl(events)` evaluates at `new Date()` (`domain/src/control.ts:321`). `evaluateControl` touches only `paused`/`until`/`ceilingWaivedUntil` (`:289-306`), never `shutdown`. So `readControl(...).shutdown` gives the same answer the loops read now.

## The conductor

**`pauseConductorOnce` (`conduct.ts:951`).** Rewrite the `Effect.promise(async () => …)` as `Effect.gen`:

1. `Effect.promise(() => store.head(CONTROL_STREAM))`.
2. `yield* snapshotRead(store, controlReducer, CONTROL_STREAM, CONTROL_FOLD_TYPES, { snapshots: controlSnapshots }).pipe(Effect.orDie)`.
3. `evaluateControl(state, new Date())`.
4. The append in `Effect.promise`, at the head from step 1.

The **`Effect.orDie` is load-bearing**. Today a failed read or a `ConcurrencyError` throws inside `Effect.promise`, so it is a defect, and `Effect.catchAllDefect` turns it into `{ kind: 'failed' }` (`:980-985`). A typed failure would slip past `catchAllDefect` and fail the pass instead. This is the "behave on a conflict exactly as today" edge.

The rewrite removes one `async` arrow from `packages/conductor`. The ratchet then requires that count to be **lowered** in `effect-ratchet.baseline.json`, not left at 201. Run the ratchet test and write the number it reports.

**Snapshots in `conduct.ts`.** Compute them once, next to `const store = options.store ?? eventStore` (`:665`):
```
const controlSnapshots = options.store === undefined ? theLog.snapshots : undefined
```
- **`log` is already taken in that scope.** `:667` declares `const log = options.log ?? (() => {})`, the line logger. Import the event-store's log under another name: `import { type EventStore, eventStore, log as theLog } from '@lingtai/event-store'` (`:70`).
- Read `theLog.snapshots` lazily, on the `options.store === undefined` branch only. The Done-when test has a throwing stub on `log.snapshots`, so it must never be touched when a store is passed.

**`liftOwnPause` and `dayCeilingPause` (`day-ceiling.ts:141`, `:170`).**
- Add `snapshots?: SnapshotStore` to `DayCeilingOptions` (`:152`) and pass it on to `liftOwnPause(store, now, snapshots)`.
- Each function:
  1. Reads `head`.
  2. Runs the generic read once, with the same `Effect.either` + rethrow shape as `readControl`.
  3. Calls `evaluateControl(state, now)` with its own `now`, not `new Date()`.
  4. Appends at the head.
- That is two runs, the conductor's +2.
- `dayCeilingPause` must not reuse `liftOwnPause`'s read. Each append needs a head read taken before its own state read.

The **only** caller of `dayCeilingPause` is `apps/cli/src/day-ceiling.ts:98`. There, pass `snapshots: store === undefined ? log.snapshots : undefined`, decided on the parameter `store` and not on `store ?? eventStore`. `conduct.ts` does not call it.

## The CLI

`answerOutstanding` (`apps/cli/src/discuss.ts:444`) becomes `readControl()` from `@lingtai/daemon`. `apps/cli` already depends on it (`apps/cli/package.json:23`). Drop the now-unused `eventStore`/`CONTROL_STREAM`/`reduceControl` imports only if nothing else in the file uses them. `pnpm lint` will complain otherwise.

## Tests

- **#871's equality test** must pass unchanged. If it imports anything from inside `readControl`, only the import path changes.
- **Generic read.** A unit test in `packages/event-store/unit/` on `createMemoryEventStore()` (`@lingtai/event-store/memory`), using a non-control reducer, shows the function really is generic: a planted snapshot plus a tail gives the same state as reducing from version 1.
- **The concurrency test.** Wrap a memory store so that its first `readTypes` call appends a `ConductorPaused` (or any control event) to the real store before returning. That event lands after `head` was read and before the append.
  - `requestShutdownUnlessStanding` / `withdrawShutdown`: the first append throws `ConcurrencyError` and the second try succeeds. Assert the stream holds both events.
  - `pauseConductorOnce`: the answer is `{ kind: 'failed' }`, as a `ConcurrencyError` gives today.
- **`log.snapshots` stub.** Use `vi.mock('@lingtai/event-store', …)` (spread the real module, override `log` with an object whose `snapshots` getter throws). Then run a pass on a passed-in memory store far enough to call `pauseConductorOnce`.
  - If driving `conductPass` that far is heavy, a cheaper test is acceptable: have it assert that the store's `readTypes`, not `log.snapshots`, is what got asked.
  - The getter-throws stub is what the ticket asks for, so prefer it.
- **Done-when grep.** `store.read(CONTROL_STREAM)` and `eventStore.read(CONTROL_STREAM)` must not appear in the six functions. Other `read(CONTROL_STREAM)` call sites in those files are the `head` ticket's or out of scope. Leave them.
