# #1469: the shape of `scripts/doc-images.ts`

## Where the code goes, and why it is not quite where the ticket says

The entry point is `scripts/doc-images.ts`, as the ticket says. It is run as `node scripts/doc-images.ts <upload|download|list>`, and three root scripts sit beside `"docs:cli": "node scripts/cli-doc.ts"` (`package.json:24`). Three facts about this worktree shape the rest:

1. **Nothing runs a test that sits under the root `scripts/`.** The unit project's include is `'{apps,packages}/*/unit/**/*.test.ts?(x)'` (`vitest.config.ts:70`). `pnpm typecheck` is `pnpm -r --if-present typecheck` (`package.json:15`), and the root has no `typecheck` script of its own, so no tsconfig covers `scripts/` either. `scripts/cli-doc.ts` gets around this by being a thin wrapper: its own header says `apps/cli/unit/cli-doc.test.ts` fails when the output drifts (`scripts/cli-doc.ts:1-4`). **The test goes in `apps/site/unit/doc-images-sync.test.ts`** and imports `../../../scripts/doc-images.ts`. Site's `tsc` follows that import, so `pnpm typecheck` checks the script through it (`apps/site/tsconfig.json` includes `unit`). Pick `apps/site` because the next ticket, the site falling back to R2, lands there.
2. **The file name `apps/site/unit/doc-images.test.ts` is already taken.** It tests `imageType` in `apps/site/src/lib/doc-images.ts:8`, which serves *"an SVG diagram or a PNG screenshot, and nothing else. A name with a separator … has no type"* (`:1-4`). Do not reuse `imageType` and do not widen it. It rejects `.gif` and any nested path on purpose, for the route. The sync script keeps its own extension → content-type table: png, jpg/jpeg → `image/jpeg`, gif, webp.
3. **The root cannot import `effect` today.** Root `node_modules` holds only `oxfmt`, `oxlint`, `oxlint-tsgolint`, `typescript` and `vitest` (`package.json:34-40`). `effect` is a dependency of the packages only (`packages/env/package.json:15`: `"effect": "^4.1.2"`). The ticket's *Cost to later tickets* line says *one dev dependency*. **It is two**: `@aws-sdk/client-s3` and `effect` at `^4.1.2`, the same range the packages use so the lockfile keeps one copy. Without the second, `node scripts/doc-images.ts` fails on the import, and the Effect requirement (0101 §6) cannot be met at the root.

The script must be importable without running. Put the command under `if (import.meta.main)`: Node is v26.5.0, and `@types/node` declares it (`apps/site/node_modules/@types/node/web-globals/importmeta.d.ts`). `Effect.runPromiseExit` runs there and nowhere else, and it sets `process.exitCode` from the exit. `scripts/` is not in the ratchet's `PACKAGES` (`packages/domain/unit/effect-ratchet.test.ts:38-52`), so the baseline cannot move either way. Write it as Effects anyway, as the ticket asks.

## The seams the tests need

- **`plan(local, remote)`**: a pure function. `local` is `{ path, md5 }[]` and `remote` is `{ key, etag }[]`. It returns `upload`, `replace`, `skip`, `download` and the `list` rows (*both*, *local only*, *remote only*, *differs*). It has no delete output at all, so "nothing is ever planned for deletion" holds by the type, and the test asserts it too.
  - Normalise the ETag before comparing: strip the quotes and lower-case it. S3 returns `"abc…"` with the quotes.
  - An ETag with a `-N` suffix comes from a multipart upload, for example through the dashboard. It never equals an MD5, so it plans *replace*. Rerunning converges, because this script's `PutObject` is single-part.
- **`credentials(env)`**: takes `Record<string, string | undefined>` and returns either the three values or a tagged failure that carries **only the missing names**.
  - An empty string counts as missing.
  - It reads `process.env` at the edge and nothing else. Do **not** go through `@lingtai/env`: CLAUDE.md says that package reads `~/.lingtai/config.yml` as well as the environment, and the ticket says *never read a file for them*.
- **A `Bucket` interface**: `list`, `put(key, body, contentType)` and `get(key)`, each an Effect. The command takes a `makeBucket(creds)` factory. The real factory builds `S3Client({ region: "auto", endpoint: https://${account}.r2.cloudflarestorage.com })` and wraps `send` in `Effect.tryPromise`. In the credentials test:
  - the factory is a spy that must never be called;
  - the other two variables are set to sentinel strings;
  - the failure's message must contain neither sentinel.
- **Pagination**: lives in the real adapter. Take `send` as a parameter so a fake returning two pages, the first with `IsTruncated` and `NextContinuationToken`, covers the 1,000-key edge without the network. `Done when` does not require this test; it is cheap, so add it.

`pnpm images:list` exiting non-zero without credentials (`Done when` item 3) means spawning `node`. That is a process, so it is integration under 0060 §1 (`vitest.config.ts:9-12`). Check it by hand. The unit-level claim that stands in for it is the `credentials` test plus the spy factory never being called.

## Decisions the ticket leaves open

- **A download writes `<dest>.part` and renames it into place.** If a process dies mid-download, a truncated file is left behind. Without the rename, that file would count as present locally: `download` would never fix it, `list` would call it *differs*, and the next `upload` would **replace the good remote copy with the truncated bytes**. Remove stale `*.part` files in the walk, and never upload them. Their extension already fails the filter, so only the cleanup needs code.
- **Remote keys pass the same filter as local paths**: one of the five lower-case extensions, `/` separators, and no `..`, empty or absolute segment. A key that fails is printed once as *ignored*. It is never downloaded, so no key can write outside `doc/`. Being ignored is not a failure.
- **Keys** are `path.relative(docRoot, file)` split on `path.sep` and joined with `/`. Do not follow symlinks.
- **MD5** is `createHash('md5')` over the bytes from `readFile`. The whole set is 11.4 MB, so there is no reason to stream.
- **Errors are printed as `<path>: <name> <httpStatusCode?>: <message>`**, never as the error object. An SDK error carries `$response` and request headers, and the `Authorization` header's `Credential=` holds the access key id. As a second guard, replace any occurrence of the three credential values in that string with `***` before printing. A failed path is collected, the other paths carry on, and the exit is non-zero at the end.
- **Concurrency**: use `Effect.forEach(…, { concurrency: 4 })` for both puts and gets. Two runs at once are harmless, as the ticket says.
- **An unknown or missing subcommand** prints the three verbs and exits non-zero before it reads any credentials.

## What the build sees

- `pnpm fmt` and `fmt:check` only cover `packages/**`, `apps/**` and `vitest.config.ts` (`package.json:16-17`). The new test is formatted; `scripts/doc-images.ts` is not, the same as `cli-doc.ts`. Leave the globs alone; widening them is not this ticket.
- `pnpm lint` runs on the whole tree (`package.json:18`), so the script is linted.
- `HOME=/nonexistent pnpm test` is safe, because nothing on the import path reads `$HOME` or opens a socket. Construct the `S3Client` inside the factory, never at module scope.
