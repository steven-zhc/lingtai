# Design: the shield drawing on the home page's sandbox band (#1264)

## Where it goes

- **`apps/site/src/app/sandbox-shield.tsx`** holds a server component that takes no props, `SandboxShield`. It renders the whole `<figure>`: the SVG and the legend under it.
- **`page.tsx:203-290`** becomes `<SandboxShield />`. The `sandbox-small` telemetry line at `page.tsx:291-293` stays where it is, under the figure, inside `.sandbox-side`.
- **`home.css`** loses `.home-sbx*` at `home.css:229-243` and gains the drawing's rules in the same place. Change the track at `home.css:219` to `minmax(0, 34rem)` and its `align-items` to `center`.
- **Narrow screens:** add the narrow rule (`max-width: 34rem; margin-inline: auto` on the figure) inside the existing `@media (max-width: 860px)` block at `home.css:247-249`. Don't open a second block for it.

## How to copy the mock

Copy `doc/milestone/0.15.0/home-shield/index.html:76-109` element for element. **Use its precomputed numbers and do not recompute them.** The mock already holds every connector curve, halo, cap and chip width as a literal. One example is `<path class="ray" d="M167.0 55.0 Q174.6 79.6 197.6 91.3"/>` at line 84. Deriving those numbers from the ticket's formulas ("44 + 7.25 per character", "bowed 10px sideways") is redrawing by eye with extra steps, and that is how #1196 went wrong.

Where the ticket's table and the mock disagree, the mock wins, because the ticket names it as the specification. Example: the dots are at `cy` 180/212/244 in the mock (line 94), while the table says rows at y 184. That 184 is the text baseline, not the dot.

The markup is static JSX, with no arrays or `.map` over a data table. The test reads text, so a list adds nothing it would check. The only JSX changes are attribute names: `textAnchor`, `markerEnd`, `stopColor`, `stopOpacity`.

## Decisions the ticket leaves open

**1. Prefix every class with `home-shield-`. The mock's names cannot be used as they are.**
- The site loads the board's stylesheet globally (`apps/site/src/app/layout.tsx:16`, `import '../../../board/src/app/globals.css'`). That file defines `.chip` at `apps/board/src/app/globals.css:134`, so the mock's `.chip` would pick up the board's chip border and background.
- `.sandbox-shield` is also taken. It is the left column's small icon (`page.tsx:170`, `home.css:221`). The figure's class is `home-shield`, and that is the class the test asserts. Do not use `sandbox-shield` for the class.
- Scope the rules under `.home-shield`. The rest of the mock's names (`dot`, `run`, `file`, `legend`, `ray`, …) are too generic to leave global.

**2. Prefix the SVG ids.** The mock's `shieldFill`, `aura` and `arrow` become `home-shield-fill`, `home-shield-aura` and `home-shield-arrow`. They share one document namespace with every other SVG the site draws.

**3. Only the shield's two gradient stops are colour literals.** The mock also hard-codes `#54c6cc` in the aura stops and `#61be86` in the arrow marker's fill (lines 79-80), which the ticket forbids.
- Give those elements classes and set `stop-color: var(--accent)` and `fill: var(--pass)` in CSS. Both properties resolve custom properties from a stylesheet.
- The `stop-opacity` values .16 and 0 stay as presentation attributes.

**4. Write `ILLUSTRATION` in upper case in the source.** The mock's legend writes `Illustration` and upper-cases it with `text-transform` (line 109, `.legend .t`). `renderToStaticMarkup` does not apply CSS, so the test's `toContain('ILLUSTRATION')` (`page.test.tsx:173`) would go red. Keep the `letter-spacing`; drop the transform.

**5. Accessibility: follow the ticket, not the mock.**
- The mock puts `role="img"` on the `<svg>` (line 76). Use `aria-hidden="true"` instead.
- The `aria-label` sits on the `<figure>`. Use the mock's wording, which is the agreed one: *A shield around the agent's run; the keys and config on the machine stay outside it*.
- The legend is `aria-hidden` too. The ✕ and ✓ glyphs mean nothing read aloud without the drawing.

**6. Motion.**
- The mock's `@keyframes pulse` and the `.dot` animation (mock lines 55-57) go inside a new `@media (prefers-reduced-motion: no-preference)` block next to the receipt's block at `home.css:189`.
- Name the keyframes `home-shield-pulse`, since keyframe names are global too.
- Outside that query the dots are static at opacity 1.

**7. No `'use client'`.** The component has no state and no effect. Keep it a server component like the rest of `page.tsx`.

## The test

Rewrite the band test at `page.test.tsx:163-181`:

- **Keep** the assertions on `from v0.14.0`, the safety link, telemetry, `On for new projects`, `ILLUSTRATION`, and the three `not.toContain`.
- **Replace** `class="home-sbx"` with `class="home-shield"`.
- **Drop** the loop over `Blocked`/`Allowed`/`Reachable`/`Limited`/`Cannot be read`. Assert instead that `home-sbx` is absent.
- **Assert present:** the six paths, `api.anthropic.com`, `pastebin.com`, and the figure's `aria-label`.

To hold the "every path is on the deny list" claim, add one unit check that maps each drawn path to its `denyRead` prefix: `~/.ssh/id_ed25519` → `~/.ssh`, and so on. Do it with a literal list in the test, not an import from `@lingtai/sandbox`; importing it would make the site depend on that package. `~/.lingtai` is the `stateDir` entry (`policy.ts:114`), not a `home` join. Say so in a comment, because a reader looking for `.lingtai` in that list will not find it.

The test at `page.test.tsx:158` runs on a different block, the FAQ. Its `expect(block).not.toContain('~/.ssh')` is unaffected.

`pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover all of this. Nothing in the change needs the integration half. The Next build (`apps/release/integration/build.test.ts`) is out of reach, but this component imports nothing server-only, so it adds no risk there.
