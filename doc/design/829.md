## Design note: #829

The ticket gives the shape. This note covers four things in `ticket.ts` that the ticket does not say, plus one place where the ticket's text is out of date.

### 1. `since`'s first-event default goes at the top of `applyTicket`, not in a case

`applyTicket` returns early in two places before its switch:
- the closed guard at `packages/domain/src/ticket.ts:284`;
- the continuation of an unclaimed run at `:303-305`.

Every case also builds its result from `state`, set at `:267`. So put the default where `state` is built: `since: prior.since ?? event.at`. Every return path then carries it, with no per-case code.

The lifecycle overrides then go in their own cases:
- the claim/continuation case (`:301`);
- `TicketReleased` (`:356`);
- `WaitStarted` (`:376`);
- `WaitResolved`, `TicketLanded` and `TicketClosed` (`:508`).

The unclaimed-continuation early return at `:303-305` has to set both `since` and `lastAttemptAt` itself. It has to set nothing else.

`LIFECYCLE_EVENTS` (`:256-264`) is the checklist. Every type in it sets `since`, and no other type does. A `describe` that loops over the set to check this would catch a case forgotten when a later ticket adds an eighth event. That is a choice, not a requirement.

### 2. `closed` absorbs the ending events too

The guard at `:284` absorbs everything in `LIFECYCLE_EVENTS`, and that includes `TicketReleased` and `WaitStarted`. So once a ticket is closed, no event changes a claim's `ended`.

Today's `priorAttempts` (`packages/conductor/src/attempts.ts:162-203`) has no such guard. A release appended after a close would word the attempt there, but not in the new fold. The conductor never asks about a closed ticket, because `claim.ts:127` refuses anything not `backlog`. So `armFor`'s numbering cannot move. Note it in `priorAttempts`'s comment and in the D6 test, which should also assert that `ended` does not change.

### 3. Use one rule for when the claim case appends

Inside the claim case, append a `TicketClaim` exactly when `claimShapeOf(event, state.runs) === 'claim'`.

Do not test `!state.runs.includes(d.runId)` separately. The two agree today, because `state.runs` only grows here and an unclaimed continuation never reaches this line. But `claimShapeOf` is the rule that `claims.ts:1-11` says both folds share. Using it keeps `priorAttempts`'s old dedupe (`attempts.ts:180`, `claimShapeOf(event, byRun.keys())`) and the fold on the same rule.

The `runs` line at `:318` stays as it is.

### 4. "Held here" is already one field

`WaitStarted` stores `runId` on the blocked lifecycle (`ticket.ts:385`: `runId: 'run' in d.reason ? d.reason.run.runId : null`). So `loadTask`'s check can be:

```ts
lifecycle.status === 'blocked' && lifecycle.runId === claim.runId
```

There is no need to narrow `reason` again as the ticket's text does. An `OwnQuestion` hold has `runId: null`, so it matches no claim, which is what the ticket's edge asks for.

### 5. The branch in `endedWords`

`waitBranchOf` (`packages/domain/src/read-model.ts:35-38`) reads only `event.streamId`. Every event on one ticket's stream therefore gives the same branch. `waitBranchOf(itemEvents[0])` with `''` for an empty stream gives the same answer as today's per-event `waitBranchOf(event)` at `attempts.ts:172`. `prompt.test.ts` and the `priorAttempts` cases need no change.

### What the ticket says that is already true

The *Watch out* rule says to add a `ticket:` key and turn every `lateHistories.run` entry into a const first. Both are already done:
- every `lateHistories.run` entry is a module-level `late_*` const (`packages/domain/test/histories.ts:893-908`);
- `lateHistories.ticket` exists (`:909-914`), with entries `titledByClaims`, `escalatedThenRequeued`, `githubLedger` and `bodyBeforeAnotherWait`.

Do not rename or reorder them. Put the three new consts after the last history built, which is `late_twoAsksTwoAnswers` at `:883`. If that is no longer last when you start, use whatever is last then. Add the three new entries at the end of `lateHistories.ticket`.

### Construction sites

Only `ticket.ts` builds a `TicketState` literal: `emptyTicket` at around `:240`. No test needs a literal updated for the three new fields.
