# #1006 — design note

All four blockers are in this tree: `locksOn({ project, control })` (`packages/domain/src/locks.ts:35`), `ceilingFacts` and `raiseTransition` (`packages/domain/src/ceiling-lock.ts`), `raiseDayCeiling` (`packages/daemon/src/control.ts:203`, reachable as `@lingtai/daemon/control`), and #994's banner (`apps/board/src/app/lock-banner.tsx`, `apps/board/src/lib/locks.ts`). The ticket's shape holds. This note covers what the ticket does not say.

## 1. The ceiling in every project's locks breaks `pauseSlot`. Fix that first.

`pauseSlot` decides the bar's button with `paused={inScope(read.held, project).length > 0}` (`lock-banner.tsx:34`). `readProjectLocks` pushes any project whose `locks.length > 0` (`locks.ts:41-42`). Once `locksOn` is given `control`, a reached ceiling puts every registered project in `held`. Every project's button would then read **Resume** although nobody paused it, and pressing it gives `not paused`.

- Change `pauseSlot` to `isPaused(inScope(read.held, project)[0]?.locks)`, using `isPaused` from `apps/board/src/lib/lock-marks.ts:21`. That file says of itself: *"The only place this ticket looks at a kind."*
- Add a unit test: a ceiling-only `held` row gives a Pause button, not Resume.
- `lockMap`, `pausedNames`, `everyPaused` (`lock-marks.ts:16-36`) and `projects.tsx` already go through `isPaused`, so the cards and the filter are unaffected.
- The existing `LockRows` loop already skips non-`paused` kinds (`lock-banner.tsx:54`). `bannerRows` replaces that loop, and the comment at :53 goes with it.

## 2. The shape of `readProjectLocks`

Keep the type a union, so a failed register read is still `{ ok: false }` (#77). Widen the ok arm:

```ts
{ ok: true; held: readonly HeldProject[]; ceiling: CeilingFacts | undefined; controlProblem?: string }
```

- **Read in parallel.** `readRegistered()` and `readControlOnce()` run together. Wrap the control read in its own try, so its failure only sets `controlProblem` and falls back to `locksOn({ project: state })`. The paused rows survive that way.
- **The configured figure.** `machineDayCeiling()` throws on an unreadable file or a bad value (`packages/env/src/index.ts:979-995`). Catch it to `configuredUsd: undefined`; never let it fail the control read. With an undefined configured figure, `ceilingFacts` still returns `reached` when a lock stands (`ceiling-lock.ts:61-62`), so the row still draws. This matches 0126 §4: *the row shows as holding until the guard looks*.
- **`passed` comes from the render's `new Date()`** inside `ceilingFacts`, and is never recomputed on the client.

`readControlOnce` belongs in `apps/board/src/lib/locks.ts`, which already imports `@lingtai/daemon/control`.

- `page.tsx:663` becomes `timed('events.control', () => readControlOnce())`. It stays outside any catch, and the comment at :641-644 stays.
- `task.ts:1701` has its own `.catch`. Leave it alone.

## 3. The suggested figure needs no spend read

The banner sits on seven pages, so it does not call `readDayReading()`.

- The suggestion is `suggestedRaise(reached.ceilingUsd, reached.reportedUsd + reached.estimatedUsd)`, all from `CeilingFacts`.
- That spend is the figure at the moment the ceiling was reached. It is a lower bound, and that is enough: if spend has grown past the suggestion since, `raiseTransition` refuses `not-above-spend` and the sentence says so.
- The function keeps the ticket's signature `(reachedUsd, spentUsd)`, so its tests are unchanged.

Only the action reads today's spend, because `raiseDayCeiling` needs `spentCents` (`control.ts:200-201`: *"It is handed `spentCents` rather than reading spend"*).

## 4. The testable part lives in `lib`, not in `actions.ts`

`actions.ts` is `'use server'` and pulls in the whole board. #994's seam is a pure Effect over a store, `setProjectPaused(store, …)` (`locks.ts:76`), wrapped by a two-line action (`actions.ts:538-546`). Copy that seam.

`continueTodayWith({ store, toUsd, by, now, readSpend })` is an `Effect` in `apps/board/src/lib/locks.ts` or a new `lib/continue-today.ts`. It does three things:

1. Refuses a non-finite or non-positive `toUsd`.
2. Calls `readSpend()`, which is `readDayReading` in production. If `day === null`, it refuses with `today's spend could not be read — nothing raised`.
3. Calls `raiseDayCeiling({ toUsd, by, spentCents, store, now })` and maps `Raising` to `ActionResult`.

The action `continueToday` is then the same few lines as `projectLock`:

- `Effect.runPromise(continueTodayWith({ store: eventStore, … }))`;
- `revalidatePath('/', 'layout')`;
- a catch that returns `{ ok: false, detail }`.

The Done-when tests run against `continueTodayWith` with `createMemoryEventStore()` and a stubbed `readSpend`.

- Put the stall/rebuild argument from the ticket's Edges in this function's comment. The CLI's version refuses on an untrusted spend (`apps/cli/src/ceiling-raise.ts:6-8`), and the board's must say why it does not.
- `apps/board` is not counted by the effect ratchet (`packages/domain/unit/effect-ratchet.baseline.json` has no `apps/board` row). The action's `async` costs nothing there. Nothing in `packages/` gains an `async`.

## 5. The refusal sentences move to the domain

The sentences are `REFUSALS` in `apps/cli/src/ceiling-raise.ts:26-31`, typed `Record<RaiseRefusal, string>`. Move the record beside `raiseTransition` in `packages/domain/src/ceiling-lock.ts`, export it as `RAISE_REFUSALS`, and make `ceilingRaise` read it. The board shows the same string.

`not-reached` currently ends *"to change the figure for every day, edit limits.day_usd"*. That reads correctly on the board too, so do not fork the wording.

## 6. Row wording

`apps/cli/src/ceiling-words.ts` holds the CLI's sentences for the same facts:

- `reachedLine`, `:22-25`: *"reached on … — it lifts when the conductor next looks"*;
- `ceilingUnreadLine`, `:31`.

Reuse its `sinceLabel` shape, but not its sentences: the board's are the mock's, as the ticket gives them. The board already has its own `sinceLabel` (`locks.ts:59`).

The figures in the `reached` title use `toFixed(2)` dollars, as `lockSentence` does (`locks.ts:56`).

## 7. Order inside `LockRows`

`LockRows` takes the output of `bannerRows`, so `renderToStaticMarkup` tests need no store. `apps/board/unit/locks.test.tsx` already renders `LockRows` with `{ ok: true, held }` (:24-45). Those call sites gain `ceiling: undefined`. Their assertions stay as they are.

Rows still draw only when the ok arm has something: a ceiling, a `controlProblem`, or a paused project in scope. With none of the three, `LockRows` returns `null` as before (`lock-banner.tsx:48`).
