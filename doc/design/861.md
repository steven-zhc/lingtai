## Design note for #861: ask the claiming hook a second time after the queue read

The ticket already gives the shape. This note fixes where the second ask goes, so both branches get it from one call.

**Where.** Put the second ask on the line right after `if (queue.length === 0) return finish('empty')` (`packages/conductor/src/schedule.ts:235`) and before `if (options.slots) {` (`:237`). Both the slots branch and the sequential branch (`queue.find(...)`, `:310`) come after that point, so one call covers both. Don't add a call inside either branch.

**The local function.** Lift `:193-200` into a closure next to `finish` (`:174`), since it needs `log`, `told` and `finish`. One way to write it: `const stopIfPaused = function* () { … }`, which returns `finish('paused')` or `undefined`. Both call sites then read `const stop = yield* stopIfPaused(); if (stop) return stop`. Inside, it stays `if (options.paused)`, so a missing hook still skips both asks (the ticket's null edge).

**Order relative to `max`.** Keep the second ask after the empty check, as the ticket says. Don't move the `options.max` check (`:201`). A pass that is both full and paused already ends at the first ask, as it does today.

**What this does not close, so nobody reopens it in review:**
- In the slots branch, `readFixFiles` awaits GitHub once per candidate (`:251`) before `set.enter` (`:261`).
- `runOnce`/`take` awaits again before the claim.

Neither one re-reads `task_view`, so the rows the pass acts on are still the ones read while `task_view` was following. Out of scope lists both. The comment at the second ask should say why the stop is checked after `selectRunnable` and not before the claim: `take`'s `runnableNow` reads GitHub only (`conduct.ts:2326`), and the read a stop makes stale is `readTasks` (`queue.ts:77`).

**Loop paths that already re-ask.** The non-integer `continue` (`:315`) and the slots `continue` (`:300`) both go back to the top, where the first ask runs again. They need nothing new.

**Tests.** `packages/conductor/unit/schedule-pause.test.ts` and `schedule-slots.test.ts` are both unit tests, so the claim is checkable with `HOME=/nonexistent pnpm test`. Integration doesn't stand in for anything here.
- The fake `paused` answers `null` and then the sentence.
- Assert all of these: `stopped === 'paused'`, the sentence reached `log` and `failed`, `took` was never called, and `ran`/`started` is empty or 0.
- For slots, also assert that `started` (the handover) was never called and `set.of(name)` is empty.
- Any existing fake that counts `paused` calls now sees two per turn that reaches a non-empty queue, and one per turn that ends `empty`. Update those counts to match.
