# Design: #1150, sandboxed Claude Code runs

Line numbers were read at `19052a0d`. S4a (`d38b93c2`, `c81afed2`) and #1147 (`73ff4e81`, `079c7fb3`) have landed. The ticket says what to build. This note covers where the pieces go and the decisions the ticket leaves open.

## 1. Who decides, and when

Nothing calls `sandboxDecision` today. It is defined at `packages/recipe/src/sandbox.ts:87`, and a grep outside `unit/` finds no caller. Its own comment says *"S4–S6 call it once per run, before the run starts"* (`sandbox.ts:83`). The decision is `sandboxDecision(recipe.sandbox, yield* verdictOf(hostHere), host.home)`:

- `verdictOf` is at `sandbox.ts:62`.
- `hostHere` is at `packages/conductor/src/projects.ts:220`. It is cached for a minute and loads srt only when first asked.
- `host` is `readHost` from `@lingtai/sandbox/host`, which `projects.ts:33` already imports.

**Make the decision where that run's settings file is written, not where the run starts.** The `--settings` file has to agree with the run: it carries `sandbox.enabled: false` only for a sandboxed run (§4). The writers run before the runs:

| Run | Settings written at | Run starts at |
|---|---|---|
| Reviewer and design agent (one shared file) | `conduct.ts:2867` (`admit`) | read later through the getter at `conduct.ts:3925-3927` |
| Judge | `conduct.ts:3028` | `:3064` |
| Fixer | `conduct.ts:4630` | `:4697` |
| Implementer | hook wiring, before `:4427` (`wiring` at `:4283`) | `:4427` |

Keep each decision beside the path it produced: `reviewSettingsPath` gets a `reviewDecision` next to it, and so on. The reviewer and the design agent share one decision because they share one file. That is the only place where "per run" really means "per file".

## 2. Where `wrap` comes from

`wrap` must come from one `Sandbox` service per conducting process, never one per run:

- `makeSandbox` adds a finalizer that calls `srt.reset` (`packages/sandbox/src/sandbox.ts:104`). A per-run scope would reset srt's single instance under every other live run, which breaks two passes running at once (0122).
- `live.ts`'s own comment says this: *"its scope resets srt's one instance when it closes, which a resolver asking per recipe read must never do under a run that is wrapping"*.

**Build it lazily**, for the reason `projects.ts:216-218` gives: *"srt is imported on that first ask and not before, so a process whose recipes have no such block never loads it"*.

Shape:

- `ConductOptions` gains `sandbox?: Effect.Effect<SandboxApi, SandboxUnavailable>`.
- The host's edge builds it. `apps/cli/src/conduct.ts` passes it in both `common` blocks (`:270-281`, `:302-313`).
- It is an `Effect.cached` of `import('@lingtai/sandbox/live')` followed by building `SandboxLive` into the outermost scope of the conducting process. For `lingtai run` that is the `Effect.scoped` at `apps/cli/src/run.ts:710`; the daemon has its equivalent.
- Unit tests hand in a fake `SandboxApi`.
- If the option is absent and the decision is *sandboxed*, the run crashes by name (*no sandbox service in this process*). It never runs unwrapped.

The conductor then closes over the service and puts `wrap` on the request. `packages/agent` sees only a function.

## 3. `RunRequest.sandbox` and where its fields come from

- **Set it only when the decision is `sandboxed` or `refused`.** For `unsandboxed`, leave it absent. That keeps "byte-for-byte today's" structural: the existing path is never entered.
- **Dependency.** `packages/agent` adds a dependency on `@lingtai/sandbox` (the root export only) for `WrapInput`, `Wrapped`, `CallerAdditions` and the relation helper in §6. The root does not load srt: srt is imported only in `live.ts`. The ticket's import test forbids `/live`, not the root, and nothing cycles: `@lingtai/sandbox` depends only on `env` and `effect` (`packages/sandbox/package.json:14-17`).
- **Fields:**
  - `decision`
  - `project`
  - `mirror`: `mirrorPathFor(project, home)`, already imported at `conduct.ts:219`
  - `worktree`
  - `runDir`
  - `operatorClaudeDir`: `join(host.home, '.claude')`
  - `hostHome`: used for `~` expansion
  - `read`: the conductor-known paths that must be readable, which are `request.settingsPath` and `hookBinary` (`conduct.ts:530`)
  - `wrap`
- **`runDir` is `claudeConfigDirFor(home, <this run's own runId>)`** (`packages/conductor/src/run-log.ts:68`), never the pass's id:
  - `prepareClaudeRunDirectory` refuses a directory that already exists (`claude-run-dir.ts:118-126`), and each run's scope removes its own directory.
  - Every site already has a distinct id: judge `conduct.ts:3071`, fixer `:4622-4625`, reviewer `agent-action.ts:917`, design `:1616`, implementer the pass `runId`.
- **The reviewer and the design agent** are built in `packages/actions`, which does not depend on the conductor (`packages/actions/package.json:15-21`). Their deps get `sandboxFor?: (runId: string) => RunSandbox | undefined`, written beside the `settingsPath` getter at `conduct.ts:3921-3927`. The action calls it with `reviewId` or `draftId`.
- **The judge with no worktree** uses `runDir` as both `cwd` and `WrapInput.worktree`, so the one directory it starts in is writable.
- **Codex ignores `sandbox` in this ticket.** That is S5. Nothing is wrapped today, so a Codex run under a sandboxed recipe is not a regression.

## 4. Settings: two files, different contents

- **The `--settings` file** (from `renderSettings` or `writeUnhookedSettingsEffect`) gets `sandbox: { enabled: false }` only when the decision is sandboxed. Add `sandboxed?: boolean` to:
  - `RenderOptions` (`hook-config.ts:79`), used by `renderSettings` at `:94-115`
  - `writeUnhookedSettingsEffect` (`:236`), passed through `host.unhookedSettings`

  Absent means today's file, byte for byte. The key has to be in this file because only `--settings` outranks a managed repository's `.claude/settings.json`; the user-level file does not.
- **`<runDir>/settings.json`** is written by `prepareClaudeRunDirectory` (`claude-run-dir.ts:130-132`). Hand it `{ sandbox: { enabled: false } }` and **no hooks**:
  - With `CLAUDE_CONFIG_DIR` set, this file is the user-level settings.
  - Putting the hook file's contents there too would register the hooks a second time, and would give the hookless reviewer, judge and fixer a hook.
  - Edit that module's comment, which says *"`renderSettings`'s value"* (`:68`).
- **The argv is unchanged.** `--settings` still points at `request.settingsPath`, which is under the state directory. That is why it goes on `read`.

## 5. Policy: `CallerAdditions.read` and `denyWrite`

In `packages/sandbox/src/policy.ts:31-35` and `filesystemFor` (`:108-131`):

- `read` goes on `allowRead` and `denyWrite`.
- `denyWrite` goes on `denyWrite` only.

`allowRead` overriding the state directory's `denyRead` is what makes the settings file and the hook binary readable. The comment at `:116` says *"allowRead overrides denyRead (017)"*. Also remove `platform.claude.com` from `BUILT_IN_DOMAINS` at `:54`.

**Only paths that exist go on `read`.** `prepareClaudeRunDirectory` skips an item that is absent or a dangling link (`claude-run-dir.ts:159`, `:171-174`). Change it to return the top-level paths it actually wrote, typed as `Effect<readonly string[], …>` instead of `void`. The caller then adds exactly those paths plus `<runDir>/settings.json`. This is why the directory must be prepared **before** `wrap` is called.

The hook binary is a single compiled file (`apps/release/src/build.ts:41-43`, `bun build --compile`), so one `read` entry is enough.

## 6. The operator's `denyRead`

Read `<operatorClaudeDir>/settings.json` inside `claudeCodeRun`, through a port on `ClaudeCodeOptions`, beside the `spawn` port at `claude-code.ts:326`. Doing it there means every refusal leaves through the one outcome path rather than five sites.

- Absent: carries nothing.
- Unreadable, not JSON, an entry that is not a string, or a relative entry after `~` expansion: refused by name. Name the path; never quote the file's contents (the same rule as `claudeOauthToken`'s comment, `packages/env/src/index.ts:250-253`).

**The collision check needs a new export.** `refuseProtected` checks against `protectedEntries`, which is the wrong set. Export the relation from `protect.ts` (`staticPrefix` plus `within`, `:52-62`) as a pure helper, and check each carried entry against:

- the worktree, the mirror and `runDir`, as the ticket asks;
- **also** `request.settingsPath` and the hook binary. A deny that contains either would be silently voided by their `allowRead` (`policy.ts:116`), which is the same trap the ticket names.

Carried entries go on `caller_additions.deny`.

## 7. Inside `claudeCodeRun` (`claude-code.ts:447`)

1. **`sandbox` absent, or decision `unsandboxed`:** today's code, untouched.
2. **`refused`:** return a failure before anything else runs.
3. **Otherwise, in one `Effect.scoped` that encloses the existing `Effect.callback`:**
   1. Read the token through an `oauthToken` port, defaulting to `claudeOauthToken`. It throws on an unreadable file; turn that into the refusal sentence.
   2. Read and check the operator's denies (§6).
   3. Prepare the directory, using a `RunDirFs` port.
   4. Call `wrap` with:
      - `command: [binary, ...args]`
      - `env: spawnEnvFor({ ...request.env, CLAUDE_CODE_OAUTH_TOKEN: Redacted.value(t), CLAUDE_CONFIG_DIR: runDir })`. Ours come last, so a recipe cannot override them.
   5. Spawn `wrapped.argv[0]` with `wrapped.argv.slice(1)`, `env: wrapped.env`, `shell: false`, and the existing `detached: true` (`:482`).

**The scope must enclose the callback.** The callback's interruption already waits for the process group to exit (#587, `:440-443`). Enclosing it means srt's cleanup and the directory's removal happen only after the agent is gone, never while it is still running.

**Every pre-spawn refusal and every wrap failure is `kind: 'crash'`, never `'never-started'`.** `never-started` stands the whole conductor down as an account fact (`conduct.ts:3126-3136`, 0031), and the reviewer maps it to `never-ran` (`agent-action.ts:1100`). A missing token or a deny collision is about this host's setup and must reach a person.

**Where the token may appear.** `Redacted.value` is called in exactly one object literal. The `Spawned` record carries argv only (`claude-code.ts:212-215`), and srt is handed `quoteArgv(command)`, never the env (`sandbox.ts:150`). So the token is never in a trace or an error. The test asserts that with a fake token.

## 8. Things that change at the edges

- **`lingtai doctor`'s orphan sweep.** The dry-run mode (`packages/daemon/src/reconcile.ts:780-790`) reads the stream named by the directory. For a sub-run such as `abc:review:…` that stream is empty, so a live reviewer's directory is reported as orphaned. Look the stream up by the part before the first `:`. The non-dry start-up sweep still removes every directory, which is correct: nothing is live under the lock.
- **ADR.** Edit 0127 §16 (`doc/decisions/0127-what-an-agent-can-reach.md:127-130`) in place, as the ticket says and CLAUDE.md allows for `doc/decisions/`. Claude Code runs carry `sandbox.filesystem.denyRead`; the Codex profile is S5b's.
- **What can be checked before the merge.** All of this is unit-level: fake `wrap`, token, filesystem and settings ports, and srt is never loaded. `HOME=/nonexistent pnpm test` must stay green, so no default port may be reached by a unit test. The one claim no test can make, whether srt plus Claude Code actually start with the hook firing, is the operator's check after the merge, as `Done when` already says.
- **The `/live` import test** belongs in `packages/sandbox/unit/`. It scans `packages/agent`, `packages/actions` and `apps/board` source for `@lingtai/sandbox/live`.
