# Design: one guard for a log that predates the Hold event (#451)

## 1. The guard reads rows without decoding them, so the store needs a new query

You cannot find a bad row through `EventStore`. `decodeRow` (`packages/event-store/src/event-store.ts:191-216`) runs `parseStoredPayload` on every row it reads, so a bad row throws before any caller sees it. The memory store has the same problem on the way in: it parses on append (`packages/event-store/test/memory.ts:114-115`, `data: parsePayload(e.type, e.data)`), so a unit test cannot put an old row into it at all. Two changes follow from that.

**(a) Add `rowsOfType(type: EventType): Promise<{ seq: bigint; schemaVer: number; data: unknown }[]>` to `LogQueries`** (`packages/event-store/src/queries.ts:91`). Return rows in seq order and leave `data` raw.
- Implement it next to `typeCounts` in all three places: Postgres (`queries.ts:236`), SQLite (`sqlite.ts:484`) and the deferred wrapper (`choose.ts:152`).
- Add a case to `test/queries-contract.ts`. That contract runs only in the integration half, so nothing inside a pass checks the two SQL implementations. The unit claim that stands in for them is the guard run against the memory store in (b).

**(b) Give `createMemoryEventStore` two test-only additions:**
- `plant(row)`: pushes a row with a given `type`, `schemaVer` and `data` and skips `parsePayload`. It is the only way a test can hold a row this build cannot read. Say that in its doc comment, and say that nothing else may use it.
- `rowsOfType(type)`: so the memory store satisfies `Pick<LogQueries, 'rowsOfType'>`.

Its `read`/`readAll` currently hand back stored envelopes as they are. Make them pass planted rows through `decodeRow`, which is already importable from `../src/event-store.ts` (`memory.ts:70`). A planted row then throws on read exactly as it would in the real store. Keep the import narrow and never go through the barrel; the comment at `memory.ts:66-69` explains why.

## 2. One predicate, one error, one guard

- **Predicate, in `@lingtai/domain`:** `blockPredatesHold(schemaVer, data)` returns
  `schemaVer !== SCHEMA_VER.WorkItemBlocked || !WorkItemBlocked.safeParse(data).success`.
  - Use `!==`, not `> 1`. #445 dropped the `BUMPED` entry (`events.ts:2269-2275`), so the supported version is 1, and a stored v2 row takes `upcast`'s `schemaVer > supported` branch.
  - The ticket cites `events.ts:2349-2353` for that branch, but it is actually `upcast.ts:221`, and the message comes from `upcast.ts:197-199`: *"the writer is newer than the reader"*. That message is wrong here, and is the reason a row must never reach `upcast` unguarded. `events.ts:2299-2303` says the same about lowered numbers.
- **Error, in `@lingtai/event-store` next to `SchemaVersionUnsupportedError`:** `LogPredatesHoldError(seq)`. It is the one place the message lives:
  `this log predates the Hold event (WorkItemBlocked at seq N); reset it — doc/operating.md, "Resetting the log"`.
  - That section does not exist yet: `doc/operating.md` has no heading containing *reset*, because it is #448's to write. Point at it anyway; the ticket asks for that.
  - Never use the word *upgrade*. Before 1.0 the log is reset, with no upcaster (`events.ts:261-263`, 0118 §1).
- **Guard:** `logPredatesHold(queries: Pick<LogQueries, 'rowsOfType'>): Promise<LogPredatesHoldError | null>`. It returns the first failing row in seq order.
  - **Return the error, don't throw it.** Doctor needs a row it can show, daemon start needs a result arm, and rebuild needs an exit code.

**`decodeRow` throws the same error.** In its `catch` (`event-store.ts:201-206`), when `row.type === 'WorkItemBlocked'`, throw `LogPredatesHoldError(row.seq)` for either a `MissingUpcasterError` or a `ZodError`. That is the ticket's *"any other command that folds the whole log"*: `status`, the board and `run` then refuse by name without anyone having to list them. The explicit guard calls below exist to refuse **before** anything is done, not as the only line of defence.

## 3. The three call sites

- **Daemon start** (`packages/daemon/src/daemon.ts:94`):
  - Add a seam `predatesHold?: () => Promise<LogPredatesHoldError | null>`, shaped like `watermark`/`acquire` (`:57-60`). Its default calls the guard on the process log's `queries`.
  - Run it **first**, before the watermark and before the lock. A refusal then takes no lock and reads no control stream.
  - Add the arm `{ ok: false; reason: 'log-predates-hold'; detail: string }` to `DaemonStart` (`:61-76`).
  - `openDaemon` in `apps/cli/src/lingtai.ts` (called from `:654-669`) has to print `detail` and return **non-zero**, unlike `already-running`, which exits 0 by design (`:632-639`). `lingtai restart` goes through the same `start`, so it inherits this.
  - Test: extend `packages/daemon/unit/start.test.ts` the way its existing cases assert order. Expect `['predates-hold']` with neither `watermark` nor `acquire` called.
- **`lingtai doctor`:** add a `fail` row `log: predates the Hold event` next to `readableTypes` in both branches (`apps/cli/src/doctor.ts:2362` and `:2401`). In each branch, pass it the same `queries`/`audit` that `readableTypes` gets. If the guard itself rejects (no log yet), answer `ok` the way `readableTypes` does at `:1249-1250`.
- **`lingtai projection rebuild`** (`apps/cli/src/lingtai.ts:395-418`):
  - Call the guard **before** `createProjectionRunner` / `runner.rebuild()`. The comment at `:411-412` says it all: *"Drop the table, reset the checkpoint, replay."* A refusal partway through the replay leaves a person with an empty board.
  - Extract the subcommand body into `rebuildProjection({ name, queries, runnerFor })`, so a unit test can pass a fake runner and assert `rebuild` was never called.

## 4. The Done-when test

Write one unit file (in `apps/cli/unit/`, which can reach all three call sites) with a memory store that has two `plant`ed rows:
- a v1 `WorkItemBlocked` with `{question, needsFrom: 'human', runId: null}`;
- a v2 one with `{…, needs, diagnosis}`.

Run each of the three callers against it and assert:
- the refusal text is `LogPredatesHoldError`'s message;
- for rebuild, `rebuild` was never called.

Add one case each for "v1 only" and "v2 only", so both ways an old row fails are covered. Add a `decodeRow` case: reading the planted stream through `store.read` throws `LogPredatesHoldError`, not a `ZodError`.
