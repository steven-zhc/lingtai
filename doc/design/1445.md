# #1445: shape

Both changes go in `apps/board/src/app/globals.css`. No TSX file changes and no tests change. The two decisions below are not stated in the ticket, and the operator's preview missed both.

## 1. The gutter selector must skip the banner as well as the bar

`<main className="detail pr-page">` has more direct children than the bar and the content. After `RecipeBar` comes `<LockBanner project={name} />` (`pr/[project]/[n]/page.tsx:102`, `pr/[project]/page.tsx:103`). That component returns a fragment (`lock-banner.tsx:44-49`), so the elements it renders become direct children of `main`:

- `<div className="pbanner">` (`lock-banner.tsx:165`, `:176`)
- `<div className="pbanner sbanner">` (`sandbox-banner.tsx:36`)

`.pbanner` is a full-width band with its own gutter: `padding: 7px 16px; background: var(--held-soft); border-bottom: 1px solid var(--held)` (`globals.css:3803`). The previewed `.pr-page > :not(.bar) { padding-inline: 16px }` matches it. Its text would move to 32 px, and its coloured band would still run edge to edge. You won't see this unless a lock or a sandbox fault is active, and the operator's check on 2026-11-25 didn't have one.

So the rule is:

```css
.pr-page > :not(.bar, .pbanner) { padding-inline: 16px; }
```

Put it on the line after `.pr-page { background: #f2f4fa; }` (`globals.css:3492`; the ticket's `:3486` has since moved). Here is what that selector matches in `main`:

- **The bar:** `Bar` renders one `<div className="bar">` (`bar.tsx:43`), and the place line sits inside it, so it is excluded.
- **`.pr-refusal`:** gets the gutter, which is what we want.
- **The Suspense fallbacks:** the board's skeleton and `.prp` (`pr-detail.tsx:144`) get the gutter. The detail fallback is `null`.

Padding `.prp` adds to its `margin: 0.75rem 0 2rem` (`globals.css:3420`) without changing it. The `.prp-grid` stack under 820 px (`globals.css:3488`) is inside `.prp`, so the gutter applies there too, as the ticket's narrow-window edge asks.

## 2. Write the base rule as bare `a`, not `a, a:visited`

Put the rule after `body` (`globals.css:88-94`):

```css
a { color: var(--accent-ink); }
```

Do not add `a:visited`. Its specificity is (0,1,1), which beats every single-class rule set on the link element itself. Two examples:

- `.ctbtn { … color: var(--accent-ink) }` (`globals.css:390`)
- `.navlink:hover`, `.navlink.on` (`globals.css:167-168`)

Bare `.navlink` and `.ctbtn` are (0,1,0), and so is every other single-class link rule. Once a person had visited such a link, it would take the base colour instead of its own. Bare `a` is (0,0,1), so it loses to all of them. It already covers visited links: the browser's own `:visited` colour comes from the user-agent stylesheet, and any author rule beats that whatever its specificity. That meets the ticket's edge "`a` and `a:visited` the same" without a second selector.

The white links on coloured ground are safe. `.pr-head a, .pr-head a:visited { color: #fff; }` (`globals.css:3502`) is (0,1,1) and (0,2,1), so both beat a bare `a`. `.pbanner .what a` (`globals.css:3805`) and the `.sbanner` link rules (`globals.css:3242-3243`) are (0,2,1) or more. No link inherits its colour from a parent today, because the user-agent link colour already overrides inheritance. So any link that isn't `rgb(0, 0, 238)` now has an author rule on the `a`, and that rule outranks the new one.

## Verification

Nothing in `pnpm test` reaches CSS, and no unit-level claim stands in for the checks a person does in the browser in the ticket's *Done when*. To make those checks meaningful:

- When checking the gutter, also load a PR page while a lock is held, or set a spend ceiling the day has passed. The banner's text should stay at 16 px, not 32 px.
- When checking link colour, also check one `.navlink` or `.ctbtn` that has been visited. It should keep its own colour.

`pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` should be unaffected. No ADR covers this, and `effect-ratchet.baseline.json` is not involved.
