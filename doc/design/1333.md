## 2. `integrate.test.ts`: the head the build ran on

The code is right. `packages/repo/src/integrate.ts:468-473` says *"The lane lands the commit the steps checked and nothing else: a branch on origin that is anything other than `headSha` is refused, never merged and never retried."* The `base()` fixture at `integrate.test.ts:75-85` still passes the constant `headSha: '0'.repeat(40)`.

- **Remove `headSha` from `base()`.** Each call site supplies the tip of the branch it is about to integrate, read with `git rev-parse <branch>` in `originPath`. The first test already reads it as `branchHead` (`:115`).
- **Use a small helper.** Make it `headOf(branch)`. Don't have `branchWith` return the sha: some tests push again after `branchWith`, and the head they mean is the one at the moment of the call.
- **Leave alone any test that moves the branch on purpose after the "build".** It should pass the earlier sha and assert `head-moved`. That is the decision under test.
- **The unreachable-store test (`:322-338`).** It fails before the head check, so any sha works. Use the real tip anyway, so the test does not depend on the order of the checks.
- **The commit names 8ccb4e6f.**

**Confirm before editing.** Run the one file and read `seen.lines` from a failing case. The line printed should start `--rounds is gone`.
