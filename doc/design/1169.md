# Design note: #1169, the Claude Code token written through setup

## Where the pieces go

**1. The write lives in `@lingtai/setup`, in a new `packages/setup/src/claude-token.ts`, exported from `index.ts`.** It has three parts:

- **A file port.** Move the `MachineText` interface into this file as the one shared definition. Today it sits at `apps/cli/src/github-auth.ts:54-57`, with `read: (path) => string | null` and `write: (path, text) => void`. Export it so `github-auth.ts` imports it instead of declaring it. Leave `liveMachineText` (`github-auth.ts:63-76`) in `apps/cli`. The board needs its own live writer, so move `liveMachineText` into `@lingtai/setup` too. Its comment already gives the reason: written *"beside, then renamed over … `0600`, because a database URL carries its password"*. Both hosts then import one writer. `packages/setup/package.json` already depends on `yaml`. It does not depend on `@lingtai/env`; add that. `@lingtai/env` depends only on `effect` and `yaml`, so this creates no cycle.
- **`claudeTokenState(env, file, path)`** returns `{ environment: boolean; file: boolean } | { unreadable: string }`. Build it on the reader rather than writing a second rule. `environment` is `claudeOauthToken(env, machineFileFrom(path, null)) !== undefined`. `file` is `claudeOauthToken({}, machineFileFrom(path, text)) !== undefined` (`packages/env/src/index.ts:159-170`, `:254-266`). That way *is it set* means exactly what a run will see, including the rule that *"empty, or with whitespace inside it"* counts as absent. A file that does not parse gives `unreadable`, never *not set*. Use the reader's own sentence: it *"names the path and nothing the parser quoted … which may be the token itself"* (`:250-252`).
- **`setClaudeTokenEffect(file, path, token, env)`.** It returns `Effect<{ saved: true; environmentWins: boolean }, ClaudeTokenRefused>`. It validates first, then edits the document the way `writeGithubAuth` does (`github-auth.ts:78-90`): `parseDocument`, refuse on `doc.errors` or a non-map, `doc.setIn(['claude', 'oauth_token'], token)`, then `file.write`.

**Do not copy `writeGithubAuth`'s refusal text.** It interpolates `doc.errors[0]!.message`. For a YAML error on the line that already holds an old token, that message quotes the token. Use the reader's rule: the sentence names the path and quotes nothing.

The token is a `Redacted<string>` from the moment it is read off a prompt, a child's stdout or a form field. Unwrap it in exactly one place, the `setIn` call. `ClaudeTokenRefused` carries a sentence and nothing else. It never has a `cause` that wraps the input.

**Validation:**
1. Trim the token.
2. Refuse it if it is empty or has whitespace inside.
3. Refuse it if it does not start with `sk-ant-oat01-`.

Each refusal names the rule it broke, never the value.

The writer is stricter than the reader, which checks no prefix (*"whether it works is Claude Code's to say"*, `index.ts:248`). That is deliberate: setup can refuse an obvious mispaste, and the run-time reader stays permissive.

**Write the step as an Effect, not as an `async` function** (0101 §6, `effect-ratchet.baseline.json`). The port is synchronous, as `MachineText` already is, so wrap it in `Effect.try`.

**2. The condition for asking is a pure function in `@lingtai/setup`.** It is `needsClaudeToken(recipe, state)`: the sandbox is enabled, `claude-code` is among the recipe's runtimes, and neither `state.environment` nor `state.file` is set.

- **Sandbox on** means `recipe.sandbox !== undefined && recipe.sandbox.enabled`. The block is optional, and absent means off (`packages/recipe/src/recipe.ts:3440-3443`). Its `enabled` defaults to `true` once written (`sandbox-block.ts:36-37`: *"Writing the block is asking for it"*).
- **Names `claude-code`** is answered by `runtimesOf` (`packages/conductor/src/runtimes-of.ts:11`). It walks `runtime.agent`, each step's `agent:` and each judge that is not built in. `@lingtai/setup` cannot import it: `@lingtai/conductor` depends on `@lingtai/setup` (`packages/conductor/package.json:65`). Move `runtimesOf` into `@lingtai/recipe`, which already exports `isBuiltInJudge`, the one thing it needs. Leave a re-export at the old path so `conduct.ts` and #1150's refusal keep one definition. Do not write a second walk.
- **Not new** is not part of this predicate. Each caller already knows whether it is registering a new project.
- **Unreadable** means the flows do not ask. They say the `unreadable` sentence once and carry on. The add does not fail over a token.

**3. In the CLI, ask once the recipe is final, not right after the runtime probe.** The ticket's *"right after the runtime question"* cannot be built literally. `world.runtimes()` (`first-project.ts:712`) only probes what is installed. The runtime a recipe uses is chosen later, inside `askRecipeEffect`. Whether the recipe has a sandbox is known only once `previewSetup` has run: `finalRecipe = resolveSource(previewed, path, path).recipe` at `first-project.ts:948`.

So put one helper in `apps/cli`, `askClaudeTokenEffect(world, recipe)`, and call it in two places:

- **`first-project.ts`**: after `:948` and before registering.
- **`add-github.ts`**: at the matching point after its own preview.

That puts the token question right after the last recipe question, which is the earliest point the condition can be known. A refusal, a skip or a failed write from this helper never refuses the add. The token belongs to the machine, not the project, so the helper logs one sentence and the flow continues.

**The CLI's own source of the token** is `apps/cli/src/claude-setup-token.ts`, with an injected spawner port. Wrap it in an Effect; no `async`.

- Spawn `claude setup-token` with `stdio: ['inherit', 'pipe', 'inherit']`.
- Buffer stdout and split it on `\n`. Only a whole line is masked and echoed, so a token split across two chunks is never printed half unmasked. Flush the final partial line at exit through the same mask.
- Collect matches of `/sk-ant-oat01-[A-Za-z0-9_-]+/g` across all lines.
- Exactly one match, on exit code 0, is the token. Every other outcome returns `{ fallback: '<one line why>' }`: missing binary (`ENOENT`), a non-zero exit, zero matches, or two or more matches.
- Do not run this under `spunEffect` (`question.ts:52-70`). A spinner and a child that owns the terminal for a browser sign-in will fight over the screen.

**The paste prompt needs a new shape.** `AskShape` (`question.ts:21-35`) has no way to say *draw this hidden*. Add `secret?: true`. Have the live front end in `prompt.ts`, which wraps `@clack/prompts` (`prompt.ts:10`), draw `clack.password` for it. A readline front end that cannot hide input refuses a `secret` question rather than echoing it.

- **No flag carries the token, ever.** The `Question.flag`/`given` route (`question.ts:72-77`) does not apply, because argv is readable in `ps` and in shell history.
- **Without a terminal** (`interactivity`, `prompt.ts:15-20`), the flows skip and print the skip sentence. The standalone command refuses, saying it needs a terminal and naming `claude.oauth_token` in `~/.lingtai/config.yml` as the other way.
- **Choosing to skip.** The prompt offers skipping by an empty answer. Ctrl+C keeps its existing meaning: the whole command stops.

**4. The standalone command is `lingtai token claude`**, a new entry in `apps/cli/src/commands.ts` beside the others (`add`, `env`, … at `:44`-`:455`). It runs the same helper without the recipe condition:

- **No token set:** ask.
- **A token set:** ask *replace* or *keep*. Keep writes nothing.
- **Unreadable file:** refuse with the reader's sentence.

Regenerate `doc/cli.md` and `doc/cli.json`; `apps/cli/unit/cli-doc.test.ts` holds them to the definitions. Change doctor's not-set detail at `apps/cli/src/doctor.ts:3060` to name `lingtai token claude`, and the comment at `config.example.yml:139-142` to name it too. Leave the row `ok` either way. Its comment says why: *"nothing needs it until a recipe requires a sandbox … a warning on every machine would be noise"* (`:3045-3047`).

**5. On the board, one server action in a new `apps/board/src/app/setup/claude-token/actions.ts` (`'use server'`), drawn in two places.**

The action:
- Takes `FormData`, reads one field and wraps it in `Redacted` immediately.
- Calls `setClaudeTokenEffect` with `@lingtai/setup`'s live writer, `join(stateDir(), 'config.yml')` and `process.env`.
- Returns `{ ok: true; environmentWins: boolean } | { ok: false; say: string }`. The value is never in the return.
- Handles *keep* by not posting at all.

Follow the house pattern of `repository/actions.ts`: one exported `async` action at the host's edge, with `Effect.runPromise` inside. That is the edge 0101 §6 allows. Check that the ratchet counts it, and if it does, take the count down elsewhere rather than raise the baseline.

Where it is drawn:
- **`/setup`** gets a section that always shows *set* or *not set*. It reads `claudeTokenState` on every render and never caches it. The section has a password field and the sentence *run `claude setup-token` in a terminal and paste what it prints*.
- **`repository/added/`** (the board add flow's landing page) shows the same section only when `needsClaudeToken` holds for the project just added. Read the project's recipe from disk on render.

Do not thread the field into the add form itself (`repository/read/setup-form.tsx`). The form posts before the recipe exists, so the condition cannot be known there. The CLI reaches the same point by asking right after the last recipe question, and the board reaches it on the page right after the add.

Use `<input type="password" autoComplete="off">`. After a post, the client component clears the field. It does not return the value in state.

## Edges the ticket leaves open, decided

- **Writing while the variable is exported.** The CLI says *saved* and adds one line: `LINGTAI_CLAUDE_OAUTH_TOKEN` is set in this process's environment and a run reads it first. The board says the same about the **board process's** environment, so the sentence names whose environment it read.

  This is also true of the daemon, which reads the variable from its own start environment. Doctor does not show that difference today. Leave it alone; it belongs to `doctor`, not to this ticket.
- **A daemon already running.** The file is read on every call (CLAUDE.md: *"The file is read per call, so what the setup page writes there is seen at once"*). Say nothing about a restart.
- **Two writers at once.** The last rename wins. `liveMachineText`'s partial file is named by pid (`github-auth.ts:68`). The board's writes all come from one pid, so two board posts at once share one partial path. Make the board's partial name pid plus a random suffix inside the moved writer. That fixes it for every caller.
- **The event log.** Nothing is appended, on any outcome. The step is a machine-config edit like `writeGithubAuth`, which appends nothing either.

## How the secret is kept out of everything

All of these are unit tests with one shared fake token, for example `sk-ant-oat01-FAKE_TOKEN_must_not_appear_0123456789`. Each test asserts the token is absent from every collected string:

- **The `@lingtai/setup` step**, with a fake `MachineText` that records reads and writes. Assert:
  - the file holds the key;
  - every other key and comment is byte-for-byte unchanged;
  - the write went through the port;
  - a refused unparsable file was not written, and the refusal sentence lacks the token even when the broken line holds an old token;
  - `environmentWins` is reported correctly.

  Checking `0600` and the rename means touching the filesystem, which belongs in the integration half. The unit claim that stands in for it: the step writes only through the port, and the port is the one writer.
- **The spawner**, with a fake child emitting scripted chunks. Cover:
  - one match, including a token split across two chunks;
  - zero matches;
  - two matches;
  - exit code 1;
  - `ENOENT`.

  Capture every echoed line and log line, and assert each holds no unmasked token.
- **The flows**, with fake `QuestionWorld` (`question.ts:37-43`) ports. Cover each condition on its own (not new, sandbox absent, `enabled: false`, no `claude-code`, environment set, file set, unreadable), plus skip, which prints the sentence exactly once. Collect `log`, `ask` prompts and `said` lines.
- **The server action**, called directly with a fake writer: saved, refused (bad prefix) and `environmentWins`. Assert the serialised return holds no token.
- **Doctor:** `claudeTokenRow` (`doctor.ts:3049-3067`) over a `read` built from the step's written text gives `detail: 'set'`.

Do not use snapshot tests anywhere in this change. A snapshot is a file that could capture the value.
