# Design: #461 — what a pass writes today, one row per ending

## Where it goes, and what drives it

Put it in one new file, `packages/conductor/unit/what-a-pass-writes-today.test.ts`, and drive it with **`once()` from `packages/conductor/test/one-pass.ts`. Do not call `runPass`.** `runPass` appends nothing, as `pass.ts:1069` says: *"the pipeline does not touch the store"*. Every event this fixture records is written by `conduct.ts` around the pass (`PassRestarted` at `conduct.ts:3361`, `WorkItemBlocked` at `:3468`, `RunFinished`/`RunFailed` at `:2747–2795`). So `runOnce` is the seam #467 must leave unchanged, and it is the one to pin.

Use the harness's `memoryStore()` rather than `createMemoryEventStore()`. The run stream's id is minted inside the pass, and `streams(store)` (`one-pass.ts:71`) is how the existing tests find it: `[...streams(store)].find(([id]) => id.startsWith('run-'))`, as at `conduct-a-whole-pass.test.ts:727`.

**Give a row its knobs by overriding a port inside the test, not by adding parameters to `fakePorts`.** The house pattern is `conduct-a-whole-pass.test.ts:684–698`: reassign `ports.repo.integrate`, and wrap `ports.repo.git` so `rev-parse` answers a new head once a round has been bought. With that pattern `test/` stays untouched and the `git diff --stat main` check stays trivially true.

## Shape of a row

Use `it.each` over a row record of this shape:

- `recipe`: a string. Reuse `RECIPE`, `JUDGED`, `JUDGED_BY_AN_AGENT` and `HUMAN_BEFORE_THE_LANE`, or write it inline.
- `runtime`: a `Runtime`.
- `merge`: whether the run may merge.
- `tweak(ports)`: adjusts the fake ports.
- `expected`:
  - `result`: `ok`, `stage` or `step`.
  - `item`: the ordered event types on `wi-purecheck-7`.
  - `run`: the ordered event types on the run stream.
  - `hold`: the `_tag` of `WorkItemBlocked.data.hold`, plus that tag's discriminating fields, or `null`.

**Assert with `toEqual` on the whole ordered arrays, never `toContain`.** The fixture exists so that #467 fails on a reordered or added event. Write the arrays inline rather than as snapshots, so the diff in #467's review reads as a sentence.

**Do not assert run ids, shas, timestamps or `seq`.** Payload assertions cover only what a fold reads:

| Ending | Fields to assert |
|---|---|
| Hold | `_tag` and its discriminant: `step` / `when` / `reason` / `kind` (`hold-of.ts:108–234`) |
| Restart | `PassRestarted.restart` and `.of` |
| Release | `WorkItemReleased.reason` |
| Fix round | `FixApplied.said` |

**Fill in `expected` by running the row and copying what it wrote.** Do not write it from 0120. Where what you copy looks wrong, keep it, put a comment on the row, and list it in the commit body.
