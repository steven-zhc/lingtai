## Each ending of `publishWhatIsCommitted`, decided

| Ending | Line | Keep | `kept` becomes |
|---|---|---|---|
| `rev-parse HEAD` failed | `:1843-1851` | nothing | unchanged (null on the first call) |
| `nothing-committed` | `:1880-1884` | nothing (the head is the base) | unchanged |
| `already-published` | `:1904` | `dropKept()` | null |
| `arm-only` | `:1954-1972` | `dropKept()` (a no-op unless an earlier call wrote one) | `{ _tag: 'Arm', ref: \`refs/heads/${arm}\`, sha: head }` |
| `refused`, both pushes failed | `:1974-1988` | `keepHead(head)`, **before** `runLog.note` and `noteRefs` | Mirror, or unchanged if `update-ref` failed |
| `published` | `:1990-2018` | `dropKept()` | null |
| `catch` | `:2019-2024` | `keepHead(headRead)` only if `headRead !== null && headRead !== tree.baseSha && headRead !== armPublished` | Mirror, or unchanged |

Two decisions in that table go beyond what the ticket says:

- **`arm-only` deletes the run's kept ref.** The ticket says to delete only on `published`/`already-published`. The case it misses is a first call that ended `refused` (mirror ref written) followed by a finalizer call that ends `arm-only`. The work is then on origin, and the ticket's rule is that *the mirror never holds a ref for work that is already on origin*. So the rule is: delete the kept ref on every ending where `head` reached origin.
- **The `catch` needs a hoisted `let headRead: string | null = null`.** `head` is a `const` inside the `try`, so the `catch` cannot see it. Assign `headRead` right after `at` succeeds (`:1852`). The `armPublished` guard stops a defect thrown *after* a successful push (for example in `recordDiff`) from writing a Mirror ref for work that is already up.

Keep `head`, never `branchHead`, in both `keepHead` and `Arm.sha`. When a WIP exists, `head` is the WIP and its parent is `branchHead` (`:1877`), so a ref at `head` reaches both. When `branchHead === null` (only a WIP was committed), `head` is the only work there is.

## Reading it, and the landing

**`runRef` (`:3838-3841`).** Spread `keptAt: kept` into `unpushed` only when `kept !== null`. `runRef` is built after the inline call (`:3793`) and before the finalizer's second call, so the `WaitStarted` reports what the inline call left. If the finalizer's call then publishes, it deletes the ref, and the wait's `keptAt` goes stale in the same way its `unpushed` already does today. That is out of scope here.

**Landing (`:3880-3907`).** After the `appendNow` of `TicketLanded` succeeds and before `didLand = true`:

1. Run `gitAsked(['for-each-ref', '--format=%(refname)', `refs/lingtai/unpushed/${options.issue}/`])`.
2. Run `update-ref -d` on each line.
3. Note a failure only.

The worktree still exists at that point, because `repo.remove` is a finalizer (`:1511`). The landing path skips the publish finalizer (`:2028`, `didLand ? Effect.void : …`), so this step is the only place a landing cleans up. It deletes the refs of earlier runs of the ticket as well as this one. That is intended, and it is the only place another run's ref is ever deleted.

**One loss that stays.** The mirror refresh deletes and re-clones the mirror when `rev-parse --git-dir` fails (`worktree.ts:113-118`), which takes the kept refs with it. Its `fetch --prune` touches only `refs/heads/*` (`:114`), so it is safe. Do not add `refs/lingtai/*` to that refspec.

## Tests

All of them can live in `packages/conductor/unit/conduct-what-a-claim-leaves.test.ts`, using `hitTheWall`'s pattern of wrapping `ports.repo.git` (`:110-121`). The base fake (`packages/conductor/test/one-pass.ts:748-779`) has two limits the tests have to work around:

- **It records only `git <verb>` for anything that isn't a push** (`one-pass.ts:755-759`). A test that asserts the ref name and sha has to wrap `git` and push the full argument list onto `did` itself. The order test is then `did.indexOf('git update-ref refs/lingtai/unpushed/7/<runId> bbbb…') < did.indexOf('remove <runId>')`.
- **It answers `''` for every other verb** (`one-pass.ts:779`). So `update-ref` succeeds as it is, and the landing test has to wrap `for-each-ref` to return two ref names and assert a `-d` for each.

Use these fakes for the remaining cases:

- **Push succeeds on the finalizer's call:** a counter that refuses the first two `push` calls (the combined push and the arm on its own, `:1951`) and lets the rest through.
- **`rev-parse` fails:** fail `rev-parse` with `repoFailedWith` (`:67`).

`hitTheWall` passes `issue: 7` (`:127`), so `<n>` is `7`.

Every claim above can be checked by `pnpm test` with these fakes. Nothing here needs the integration half. The one thing only real git proves is that a ref written from a worktree lands in the mirror, and that is git's documented behaviour for linked worktrees, not this code's.

## What would settle it after the merge

Two places show the outcome:

- `WaitStarted.data.reason.run.unpushed.keptAt` on the ticket stream.
- The run stream's `RunRefsPublished` rows (`outcome` and `headSha`).

For a refused run, the wait's `keptAt.sha` should equal the `headSha` of the first `refused` row, or the `armSha` on that row where a WIP was kept.
