**Design note — #751**

The change is the two `BUILD_ORDER` rows the ticket gives (`apps/cli/src/detect-setup.ts:68-73`). The loop at `:192-196` takes the first name in `names` that the scripts contain, so `names: ['typecheck', 'check']` makes `typecheck` win when both scripts exist, and nothing else in that loop has to change. Leave the skip logic alone too. If the chosen name was skipped, the loop `continue`s and does not fall back to the next name (`:194`). Neither `typecheck` nor `check` matches `INTEGRATION_NAME` (`:76`), so a skip only happens through the command, and then dropping the key is the right outcome. Update the doc comment above the table (`:67`, *"In the order the ticket's table asks for: format, lint, typecheck, test."*) so it lists `build` last.

**The one decision the ticket doesn't make: `yarn check` is a Yarn built-in.** `runFor` spells a script as `` `yarn ${name}` `` (`:83`). In Yarn 1, a built-in command beats a script with the same name, so `yarn check` runs Yarn's own dependency check and never touches the project's `check` script. Detection would propose a typecheck that type-checks nothing and passes, and nothing would ever show it. The lockfile can't tell Yarn 1 from Yarn Berry (`yarn.lock` either way, `:64`), so spell this one `yarn run check`, which works on both. Do it inside `runFor`, keyed on a short constant of the names that collide with Yarn built-ins (just `check` for now), and leave every other spelling alone:

- `pnpm check` is not a pnpm built-in, so it stays `pnpm check`.
- `build` collides with nothing, so it stays `yarn build` / `pnpm build` / `npm run build`.
- npm already uses `npm run` for everything (`:84`).

Pin this in `detect-setup.test.ts`. Next to the existing yarn/npm spelling assertions (`:66-70`), add a case with a `yarn.lock` and a `check` script that expects `yarn run check`. Otherwise the next tidy-up turns it back into `yarn check`.

**The `because` text** stays as it is (`:196`). It already names the real script, so `` `check` runs `astro check` `` comes out with no extra work.

**Tests**, all in `apps/cli/unit/detect-setup.test.ts`, which is unit-level (a pure reader, `pkg()`/`reader()` helpers). `pnpm test` covers it, and nothing here needs the integration half:

- the `{check, build, test}` case from Done when, asserting the full `build` array: names, runs and order `typecheck`, `test`, `build`;
- the both-`typecheck`-and-`check` case;
- the yarn `check` case above.

Leave the cases at `:49` and `:113` untouched. Neither has a `build` script, so both stay green as they are.
