## Shape

The change splits on `when`. Everything below applies to `when: 'findings'` only. A judge at any other `when` keeps `{next, why}` from beginning to end. The built-ins never pass through any of it, because `replyFor` answers them from `MECHANICAL_WANTS` (`packages/conductor/src/proposed-route.ts:188-195`).

### 1. Domain: the judge's answer and the stored cause

- **Export the recorded cause schema.** In `packages/domain/src/wait.ts:967`, `RecordedCause` is a `const` that is not exported, and only `type Cause` leaves the module. Export it under one name; `routing.ts` already imports from `./wait.ts` (`routing.ts:27`), so this adds no import cycle. Then add `cause: RecordedCause.optional()` to `Selected` (`routing.ts:93`). `JudgeReply` is shared by `PassRouted` and `ProposalRouted` (`events.ts:1611-1616`), so old rows of both read with the field absent. No `SCHEMA_VER` bump is needed: *"Adding an optional field is not changing one: it needs no bump and no upcaster"* (`events.ts:18-21`).
- **Add a `JudgeAnswer` schema.** Put it in `wait.ts` next to `TriageAnswer` (`wait.ts:994`): `z.strictObject({ cause: <union of UndecidedQuestion, FixableLines, WrongApproach>, summary })`. Build it from the same three sub-schemas and `answerParts.summary`, not from copies. Leave out `want`, as the ticket says. Export a `JUDGE_CAUSES` tuple of the three tags beside it; both the parser and the prompt read from that tuple. These three shapes are identical in `TriagePlanAnswer` and `TriagePlan` (only `TicketTooBig` differs, `wait.ts:930-937`), so a parsed judge cause can be stored as a `RecordedCause` without conversion.

### 2. `judge-agent.ts`: prompt and parser

- **Prompt.** `judgeText` (`judge-agent.ts:205`) branches on `on.when === 'findings'`. The findings branch removes the *"## The choices"* section and the `next` sentence at `:243`. In their place it lists the three causes, each with one line saying what it means (the wording of the `wait.ts` doc comments: *"Specific edits, and the approach is sound"*, *"Patching will not converge"*, *"Questions only a person can answer"*), and the answer shape `{"cause": {...}, "summary": "..."}`. Every other `when` keeps the text it has today. Remove the `"waiting"` escape hatch from the findings branch: `UndecidedQuestion` is how a judge hands over now.
- **Do not change `Judging`.** It keeps `offering`. The key-set assertion described at `attempt-steps.ts:384-389` (*"`Object.keys` of the brief is exactly `evidence`, `findings`, `offering`, `when`"*) must stay as it is. `fixer-disagrees` still needs `offering`; for findings the prompt simply does not print it.
- **Parser.** Add a `causeIn(text): { cause } | { refused: string } | null` next to `chosenIn`. Leave `chosenIn` alone; the non-findings path still uses it.
  - Read candidates with `jsonCandidates` from `read-step.ts:73`, as `parseTriage` does (`conductor/src/triage.ts:371`).
  - Skip any candidate object that has no `cause` key (`triage.ts:390-395`).
  - If `cause._tag` is one of the seven cause tags but not one of the judge's three, return `refused` naming the tag. This is the ticket's *returned, not dropped*.
  - Apply the same #1253 bar triage applies (`triage.ts:~452`, using `triageQuestionsOf`, `packages/domain/src/triage.ts:148`): an `UndecidedQuestion` with a question that has fewer than two answers is refused. Otherwise the judge has a looser contract than triage over the same type.
  - If `JudgeAnswer.safeParse` fails, return `null`.
  - Do not repair anything (*"An unreadable reply is not repaired into an answer"*, `triage.ts:358`), and do not retry (`judge-agent.ts:265-268`).

### 3. `Judged` gets a new arm; the `{next}` arm stays

Add `{ cause: Cause; named: string; why: string }` to `Judged` (`attempt-steps.ts:411`), with `why = summary + spent`, the same suffix built at `conduct.ts:3557`. Keep the `{next, named, why}` arm: `fixer-disagrees` still answers with it. Do not reuse the `next` arm with an optional `cause`, because `replyFor` dispatches on `'next' in answer` (`proposed-route.ts:182`).

In `askTheAgentBody` (`conduct.ts:3606-3625`), branch on `on.when`:
- `findings` uses `causeIn`.
- `refused` and `null` both become `{ unreadable: { named, raw } }`. `raw` starts with a sentence and then carries the model's text, cut at 2,000 characters as today. For a refused cause the sentence is *"the "X" judge answered `TicketTooBig`, which a judge at `findings` may not answer (0118 §5)"*; for `null`, *"…was not readable as one cause"*.

This reuses `JudgeReply.Unreadable` → `UnreadableReply` (#462) and needs no new escalation tag. It also satisfies the Done-when line *"reaches a person with the judge's raw answer in the sentence"*.

### 4. The route: `actionFor` in `replyFor`, using the offer's own numbers

**This is the decision the ticket does not make.** `actionFor` must see exactly the counters that built the offer, or the two disagree. The grant path is where they would diverge: under a grant, `offerFor` is handed `restartLimit = ceilings.newAttemptsSpent` (`run-attempt.ts:1476`), not the recipe's `newAttempts`. If `actionFor` were handed the recipe's number, it would answer `startNewAttempt` while the offer had already excluded `restart` with `CeilingReached`.

So in `run-attempt.ts:1733-1750`, hoist the `policy` and `spent` literals into two consts, pass them to `offerFor` as now, and also give them to `replyFor` (`run-attempt.ts:1838`) as a new parameter: `bounds: Record<CauseBound, CauseCounter>`. Build it with one small pure function, `causeBoundsFor(policy, spent, personAsks)`:

| Bound | `used` | `allowed` |
|---|---|---|
| `refusalFixes` | `spent.rounds` | `policy.refusalFixes` |
| `newAttempts` | `spent.newAttempts` | `policy.newAttempts` |
| `personAsks` | ticket's count | `BOUNDS.personAsks` (`respond.ts:589`) |
| `ticketSplits`, `stepRedos`, `conflictResolutions` | whatever the spend says | whatever the policy says |

For the last row, write the values honestly; the judge's three causes never reach those bounds. The `personAsks` count has to be carried in: add `personAsksSpent` to `Ceilings` (`run-attempt.ts:~820`, beside `newAttemptsSpent`), reduced in `conduct.ts:1772` with `personAsksFromState(reduced)`. That function is already imported there (`conduct.ts:83`, used at `:4396`). Add `0` to `NOTHING_SPARE` (`:824`).

In `replyFor`, add a branch before the `'next' in answer` line: `'cause' in answer` → `actionFor(answer.cause, 'other', bounds)`. Map the action to a candidate id:

| Action | Candidate |
|---|---|
| `fixRefusal` | `fix-lines` |
| `startNewAttempt` | `restart` |
| `askPerson(*)` | `hand-to-person` |

Return `Selected{ candidate, why, cause }`. For `askPerson(limit)`, `why` names the bound and the count: *"the judge read lines to fix; `refusalFixes` is spent, 6 of 6 used"*.

If the mapped id is not in `offer.available`, the action is withheld for want of a criterion. Return `hand-to-person` with that reason in `why`. Do not return the excluded id; the ticket asks for `hand-to-person`, and the `NoCriterion` case is defensive anyway. With no criterion, `offerFor` excludes both `fix-lines` and `restart` (`respond.ts:~730`), `available.length < 2`, and the judge is never asked (`proposed-route.ts:166`).

Keep the existing cause→action and action→candidate logic out of `routing.ts`'s `decideRoute`. It must keep reading only the offer and the reply (*"Never the policy or what was spent"*, `routing.ts:126-130`). Replay therefore runs `decideRoute`/`routeNext` over the stored `candidate` and never re-runs `actionFor`. That is what makes the absence of `cause` on an old row harmless.

**What the person sees changes for a spent bound, and that is the intended result.** A `Selected{hand-to-person}` becomes `ProposedEscalated{JudgeHandedOver{why}}` (`routing.ts:164-175`). It does not become `CandidateUnavailable{CeilingReached}`, so `RouteTaken.ceiling` (`run-attempt.ts:1890`, `ceilingOf(chose, offer)`) is `null` and `chose` is `waiting`. The card's sentence comes from `why` (`wait-words.ts:189`), which is why `why` has to name the bound and the counts itself. Do not try to route the limit case through `CandidateUnavailable` to keep the old wording. The ticket says `askPerson(limit)` → `hand-to-person`, and 0108 §6 makes the table the one place the action comes from.

### 5. Readers

`routedLine` in `apps/board/src/lib/history.ts:745-760` and the CLI's route line read `reply.why` today. Where `reply.cause` is present, prefix the cause in words (one small exhaustive switch over the three tags, placed in `packages/domain/src/wait-words.ts` so the board and the CLI share it). Where it is absent, print today's words. `read-model.ts:312` needs no change: it reduces the decision, not the cause.

## Ratchet

`causeIn`, `causeBoundsFor` and the `replyFor` branch are pure and synchronous. `replyFor` is already an `Effect.gen`. Nothing here should add an `async` function or an `Effect.run*` call, so `effect-ratchet.baseline.json` must not change.

## No ADR

0108 §6 (*"a cause … never an action … The action is the system's, from one table in `respond`"*) and 0118 §5 already describe this change. Nothing here contradicts an accepted ADR.
