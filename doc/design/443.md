# Design: #443, `waitWords` and the six event-side readers

Line numbers are from `dae16df9`. The ticket's numbers came from `058450d2`, and some have moved. Reader 4 is now at `conduct.ts:4078`, not `:3988`.

## Where it goes

`waitWords` and its type go in `packages/domain/src/legacy-columns.ts`, next to `legacyColumns`. Don't put them in a new file. `index.ts:5` already does `export * from './legacy-columns.ts'`, so nothing has to change for `@lingtai/domain` to export them. #522 deletes `legacyColumns` and can rename the file when it does. A new file now would split the helpers both functions share (`stepLine`, `subjectOf`, `said`, `diagnoseRefusal`'s callers) across two modules for one ticket's lifetime.

```ts
export interface WaitWords {
  line: string
  needs: 'judgement' | 'acknowledgement'
  diagnosis: BlockDiagnosis | null
}
export function waitWords(reason: WaitReason, pass: { branch; base; findings } = { branch: '', base: '', findings: [] }): WaitWords
```

The default `pass` is the same one `legacyColumns` has (`legacy-columns.ts:302`).

## What moves into `waitWords`

The helpers all build a `LegacyColumns` today: `judgement`, `acknowledgement`, `mergeRefusedColumns`, `budgetExhaustedColumns`, `routedRefusalColumns` and `escalatedColumns` (`legacy-columns.ts:76-292`). Change them to return `WaitWords`: rename `question` to `line`, and remove `runId`, `asked` and `needsFrom`. Leave every string expression exactly as it is. That covers the `.slice(0, 400)` at `:110`, the `said(…, 400)` calls and the `unpushedSuffix` appended to `diagnosis.what`. The ticket says *moved and not rewritten*, and this is all that means.

## The wrapper is a non-obvious decision

The three fields `waitWords` drops are not sentences. Each one can be computed from the reason without touching the per-variant code:

- **`runId`**: `null` for `OwnQuestion` (`:310`). For every other variant it is `reason.run.runId`, because every helper is passed `reason.run` (`:320-367`). `attempts.ts:163` already relies on this with `'run' in card.reason ? card.reason.run.runId : null`.
- **`asked`**: `true` only for `OwnQuestion` (`:311`). Every helper sets `false`.
- **`needsFrom`**: `'human'` in every branch. There is no `'external'` anywhere in the file.

So the body of `legacyColumns` becomes:

```ts
const w = waitWords(reason, pass)
return { question: w.line, needs: w.needs, diagnosis: w.diagnosis,
         runId: 'run' in reason ? reason.run.runId : null,
         asked: reason._tag === 'OwnQuestion', needsFrom: 'human' }
```

Don't keep a second `switch` in `legacyColumns`. The whole point of the ticket is that only one place computes these values. `packages/domain/unit/legacy-columns.test.ts:13` asserts the complete `OwnQuestion` object with `toEqual`. That test stays unchanged and is how you know the wrapper still gets `runId`/`asked`/`needsFrom` right.

## The readers

1. **`read-model.ts:289-298`** (`cardFactOf`). Keep `legacyColumns` out of this case and call `waitWords` once. Set `card: { question: w.line, needs: w.needs, diagnosis: w.diagnosis }`. This is the same thing `cols` provides today, so `task_view` still gets the same three values (`task-view.ts:583-591`), and the ticket's "keep the call" requirement is about those *columns*, not this function. Change the fact's type at `:250` from `Pick<LegacyColumns, …>` to `{ question: string } & Pick<WaitWords, 'needs' | 'diagnosis'>`. Keep the field name `card.question`, because `task-view.ts` reads it and renaming it is #522's job. After this, `read-model.ts` no longer imports `legacyColumns`/`LegacyColumns`.
2. **`read-model.ts:509-520`** (`boardFactOf`). Replace the call with `waitWords`, using `w.line` and `w.diagnosis?.recommendation ?? null`. Pass the same `branchOf(event)` as today.
3. **`ticket.ts:335`**. Leave it alone. It needs `needsFrom` and `runId` for the lifecycle (`:347-349`), which is exactly what the wrapper exists for.
4. **`conduct.ts:4078`**. Change it to `waitWords(reason, { branch, base, findings }).line` and use that string at `:4139` and `:4141`. This is the only reader that passes a real `base` and real `findings`. Pass all three through unchanged, because `SignoffRequired`'s recommendation depends on `findings` (`legacy-columns.ts:319-322`) and `subjectOf` depends on `base` (`:61-63`). Remove `legacyColumns` from the import at `:32`.
5. **`attempts.ts:162-168`**. **This is the trap.** The *blocked, asking:* line in the prompt is built today with `branch: branchOf(event)` (`read-model.ts:290`). If you call `waitWords(card.reason)` with the default `pass`, `branch` is `''`. Every `ProposedEscalated` sentence and every `review`/`proposed` `AnswerUnreadable` sentence would then start `"is waiting on you."` where it now starts `"agent/N is waiting on you."` (`subjectOf`, `legacy-columns.ts:61`). No test in `attempts`'s suite pins that subject, so the mistake would pass silently.
   - **Fix:** export `branchOf` from `read-model.ts`. Rename it `waitBranchOf`, since it is about to become public and its doc comment at `:25-30` already says what it is. Then `attempts.ts` calls `waitWords(card.reason, { branch: waitBranchOf(event), base: '', findings: [] }).line`.
   - `card.card.question` would also be correct, since reader 1 makes it the same string. But the ticket asks for this reader to name `waitWords` directly, and it should keep naming it after #522 changes the card.
6. **`apps/board/src/lib/history.ts:299`**. Change it to `waitWords(next.reason, { branch: branch ?? '', base: '', findings: [] }).line`. Keep the guard at `:300` as it is. Update the comment at `:294` that names `legacyColumns`.

Update the doc comments that name `legacyColumns` as the composer of these readers' sentences: `legacy-columns.ts:53`, `read-model.ts:29` and `history.ts:275`. Leave the ones in `fix.ts:212`, `board.ts:915` and `task-view.ts:145`, because #521 and #522 cover those files.

## Tests

- **New:** a `describe('waitWords')` in `packages/domain/unit/legacy-columns.test.ts`, or a sibling `wait-words.test.ts` in the same `unit/` directory.
  - Use one example of each of the twelve `WaitReason` tags. Reuse the reasons that file already builds, and add the variants it doesn't have yet.
  - For each one, assert `waitWords(r, pass)` is `toEqual` to `{ line: legacyColumns(r, pass).question, needs: …, diagnosis: … }`. Use a `pass` that has a non-empty `branch` and `base`, so that `subjectOf` is exercised.
  - Include one `SignoffRequired` at `merge` with `findings: []` and one with a finding, so both recommendation branches are covered.
  - Also assert a literal `line` for at least the `ProposedEscalated` case. If the only assertion is equality with `legacyColumns`, a change that edits text in both functions at once still passes, because the wrapper now delegates.
- **Moved:** in `domain/unit/read-model.test.ts:148`, the test's subject is now `waitWords`, so rename its title. Its expected text does not change. The `conduct-*.test.ts` and `what-a-pass-writes-today.test.ts` files read `legacyColumns(...).question` off a `WaitStarted` they produced. Leave them as they are: those values are still identical, and #522 is where they have to change.
- **Unchanged:** no expected literal anywhere changes. If any snapshot or string in `waiting-card.test.tsx`, `legacy-columns.test.ts` or the conductor suites moves, the move was a bug.

No projection's fold output changes, so there is no rebuild. Every claim here is checkable at unit level with `pnpm test`, and none of it depends on the integration half.
