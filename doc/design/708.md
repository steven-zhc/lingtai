# #708: design note

## What's already built, and what this ticket reuses

- **The client takes `gh` auth.** `createGitHubClient({ auth: { kind: 'gh' }, owner, repo, gh? })` skips the installation lookup (`packages/github/src/client.ts:377-380`, *"No installation: the saved login is a person's, and each call asks `gh` afresh"*). Its `gh?: GhRun` option (`:361`) is the test seam.
- **`githubClientAuth()`** (`packages/env/src/index.ts:1421-1423`) returns `{ kind: 'gh' }` or `githubApp()`, and *"`githubApp()` is not called there"*. Every place on the add path that writes `auth: githubApp()` switches to it:
  - `add-github.ts:56`, `:84` and `:310` (the trial build's `token`);
  - `onboard.ts:372`.
- **`ghStatus`** (`packages/github/src/gh.ts:102`) returns `{ ok, login, scopes }`, or a `reason` and a `detail`.
- **Doctor already has the scope rule.** `ghLogin` (`apps/cli/src/doctor.ts:841-857`) computes `missing = ['repo','workflow'].filter(...)` and builds the sentence *"gh is signed in as X without … — run `gh auth refresh --hostname github.com --scopes …`"*. Don't write that sentence twice:
  - Move it into `@lingtai/github` as `ghScopeGap(status): string | null`.
  - Have `ghLogin` call it.
  - Keep doctor's text byte for byte, so its tests don't move.

## Decision 1: branch on `=== 'gh'` only; everything else is today's code

The rule is that an App machine sees no change. The simplest way to guarantee that is to leave the App code where it is and add a `gh` branch ahead of it. Don't restructure the two into one.

**The seam.** Add `githubAuthKind(from)` to `@lingtai/env`:

- It returns `'app' | 'gh' | null`.
- It throws only where `github.auth` is refused. Today `githubAuth()` throws for both refused and unconfigured (`index.ts:1395-1405`), and `githubAuthElection` isn't exported.

**`askBeforeGithubAdd`'s deps gain:**

- `auth: () => 'app' | 'gh' | null`;
- `interactive: () => boolean`; the live one is `interactivity(false)`'s two TTY flags (`prompt.ts:14-16`);
- `ghAccess`: the check in Decision 2.

**What it does with them:**

- **`gh`:** it runs `ghAccess` where `if (hasGitHubApp())` stands today (`add-github.ts:195`), and never enters that block.
- **Refused:** it prints the throw's message plus `Nothing was written`, and exits 1.
- **`null` with no terminal:** it refuses with `no GitHub auth is configured here — run lingtai init. Nothing was written`. This is ADR 0114 §1: *"otherwise no project can be added from GitHub, and the refusal says to run `lingtai init`"*.
- **`null` at a terminal:** it falls through to today's App-creation offer, unchanged. #710 replaces that offer with its question.

**`runGithubBranch` (owned here).** Add an **optional** `auth?: () => 'app' | 'gh' | null` to `FirstProjectWorld['github']` (`first-project.ts:142-148`). `liveFirstProjectWorld` sets it (`:783`). `init.ts:513` doesn't, because `init` is child 5's. When it is absent, it reads as "not `gh`", so `init` and every existing `harness()` fake keep today's behaviour with no edits.

Under `gh`, `runGithubBranch` does this, after the two flag refusals (`:531-563`):

- It refuses `--github-app` with any value but `skip`. It uses the same sentence shape as `:578-584`, naming `github.auth is gh` in place of the configured App.
- It doesn't call `world.github.app()`, `boardUrl()`, `waitForApp()` or `picker()`. These are `:566`, `:587-617` and `:620`, and `livePicker` calls `githubApp()` at `:700`.
- With no slug, it returns `{ ok: true, project: 'github', app: 'already' }`.
- Otherwise it calls `world.github.add({ slug, installation: undefined, base })` exactly as `:645-654` does.

`chooseFirstProject`'s `kind === null` branch (`:253`) treats `gh` like a configured App that answers. It goes to `askProjectKind`, not `askFirstProject`, because there's no App to offer to create.

## Decision 2: one access check, in `onboard.ts`, beside `checkInstallation`

`checkGhAccess(slug, log, deps)` goes in `packages/conductor/src/onboard.ts`. It has the same contract as `checkInstallation` (`:273-307`): it logs its lines and returns null having refused. Its deps are `status: () => ghStatus()` and `repository: (owner, repo) => client.request('GET', /repos/…)`. It runs these steps in order and stops at the first refusal:

1. **Status not ok.** Log `status.detail` plus `` — run `gh auth login` ``, the same way `ghLogin` does at `:846`. This covers signed out, no account, missing and too-old.
2. **A scope missing.** Log `ghScopeGap(status)`. Missing only `workflow` names `--scopes workflow`.
3. **Read the repository with `GET /repos/{owner}/{repo}`.** The repository isn't read until 1 and 2 pass. Without the `repo` scope, a private repository answers 404, and that would say "cannot see it" when the real cause is the scope.
4. **Classify the answer:**
   - **`archived: true`:** "archived". Check this **before** `permissions.push`, because an archived repository can still report the caller's role as push.
   - **`permissions.push !== true`:** "you (`<login>`) cannot push to owner/repo".
   - **A `GitHubError` with status 404:** "owner/repo is not visible to `<login>`".
   - **A 403 whose message matches `/OAuth App access restrictions/i`:** the ticket's organisation sentence with `--github-auth app`.
   - **A 403 matching `/SAML/i`:** "authorise gh's token for the `<owner>` organisation's SAML single sign-on on GitHub, then run this again".
   - **Any other 403:** "cannot see it", with GitHub's own message quoted, so a rate limit reads as itself.
   - **A 5xx, or any non-`GitHubError`** (a failed fetch, or `ghToken`'s own throw if `gh` signed out between steps 1 and 3): "could not read owner/repo — `<message>`". Never treat it as access.

   `GitHubError.message` is `` `${status} on ${path}: ${github's message}` `` (`packages/github/src/app.ts:82`), so match against `err.message` and don't add a field.
5. **On success, return `{ login, defaultBranch: response.default_branch }`.**

**`defaultBranch` costs nothing more under `gh`.** `askBeforeGithubAdd` seeds its memoized `defaultBranch` (`add-github.ts:243`) from the check's `default_branch`. It doesn't call `defaultBranchOf`.

**`defaultBranchOf` and `liveGithubReader`** take `reach: { kind: 'app'; installation: Installation } | { kind: 'gh' } | undefined` instead of `installation` (`:55`, `:80-90`). `undefined` still means `EMPTY_SETUP_READER`. The `reader` dep's type and the trial build's guard at `:302` follow, so `tryBuild` is offered under `gh` too, with its `token` from `githubClientAuth()`.

**`onboard.add` under `gh`:**

- It calls `checkGhAccess` **again** in place of `checkInstallation`, and builds its client with `{ kind: 'gh' }`. This mirrors the App path, where `add()` re-runs the check that `askBeforeGithubAdd` already made (`add-github.ts:189-193` explains why the early one prints nothing on success).
- It makes `add()` safe for every caller, not only `lingtai add`.
- It gets an optional third `deps` parameter: `auth`, `checkGh` and `check`. A unit test can then show that under `gh` a refusing check returns 1 and `checkInstallation` is never called, before `resolveLocalRecipe` reaches the disk.
- The rest of `add()` (the recipe, `refSha`, `warnIfProtected`) needs the filesystem, so it's covered only by the integration half. That's out of reach in a pass, so the unit claim above stands in for it.

`recheck` (`onboard.ts:149`) still calls `installationForRepo(githubApp(), …)`. That's the board's path and stays out of scope.

## Edges not in the ticket

- **A refused `github.auth`** (for example `auth: foo`): refused by name before anything is written (Decision 1). It doesn't fall through to the App path.
- **A machine with a full App and `auth: gh`** is a `gh` machine (`electGithubAuth`, `index.ts:1365-1370`). The `gh` branch never calls `hasGitHubApp()`.
- **Cost to later tickets:**
  - `add-github.test.ts`'s `countedDeps` (`:67`) gains `auth`, `interactive` and `ghAccess`, with defaults `'app'`, `true` and an `ghAccess` that throws if called, so the App tests keep proving that `gh` is never touched.
  - Fakes of the `reader` dep change their third argument to `reach`.
  - Every new test is unit-level, with a fake `GhRun` and a fake `repository`. Nothing needs `pnpm test:integration`.
