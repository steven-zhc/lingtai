Writing the design note now. I've checked the record path, the two diff call sites and where the claim version is lost.

## The shape

### Where each piece goes

| Piece | Package | Why there |
|---|---|---|
| `PromptRef`, `RunPrompted.refs`, `composePrompt`, `expandPrompt`, `markerOf`, `DIFF_FLAGS` | `@lingtai/domain` | Must be pure. The board imports this package. |
| The resolver, sha256 of each inserted value | `packages/conductor` | It needs `node:crypto`, the store, git and the mirror. |
| `buildReviewPrompt` → parts | `packages/actions` | Unchanged location. |
| `fixBrief` → parts | `packages/conductor/src/fix.ts` | Unchanged location. |

`DIFF_FLAGS` goes in the domain because `packages/actions` needs it too, and the actions package should not import the conductor's resolver. It is a `readonly string[]` constant, so no `node:` import is involved.

### Decisions the ticket leaves to the implementer

**1. The sha256 check is the resolver's job, and the record carries the hash.** The ticket wants expansion to refuse a value that has the right size but different content. `expandPrompt` is in the domain and cannot hash: `node:crypto` is out, and `crypto.subtle` is async. So:

- Add `sha256: string` to each `refs` entry.
- The resolver gets the **whole entry**, not just the `PromptRef`. It hashes what it produced. On a mismatch it returns `{ unresolved: "the value's sha256 differs from the record's" }`.
- `expandPrompt` checks only the marker and `bytes`. It computes `bytes` with `new TextEncoder().encode(text).length`, which is a global in both Node and the browser.
- Do not add a pure-JS sha256 to the domain.

**2. `composePrompt` returns the inserted values in memory as well.**

- Its result is `{ handed, recorded, refs, values }`.
- `refs` entries carry `start`, `end`, `ref` and `bytes`.
- `values[i]` is the text that `refs[i]` stands for. It is never persisted.
- The recorder (`record-prompt.ts`) needs `values` to compute `sha256` and add it to each entry before it appends.
- `recordPrompt`'s `call` changes from `{ prompt }` to the composed result. `bytes` becomes the UTF-8 size of `handed`. `prompt` becomes `recorded`. `refs` is written only when non-empty, so an event with no references still looks like one written before this ticket.
- The discussion caller (`discuss.ts:566`) and the triage/judge caller (`conduct.ts:2700`) keep passing a whole string. Accept `string | Composed` there, or wrap the string with `composePrompt([s])`. Either way, none of those callers changes behaviour.

**3. `ActionContext.prompted` is widened, not duplicated.** Today it is `(promptVersion: string, prompt: string) => Promise<void>` (`packages/actions/src/action.ts:479`), and the pipeline forwards it at `action.ts:848`.

- Change it to take the composed result instead of the string.
- `createAgentAction` calls it with `composed` and hands `composed.handed` to `runtime.run` (`agent-action.ts:695`).
- `promptVersion` stays `review@${handed.length}` and `fix@${handed.length}`. It is a length of what was handed, as now.
- The design action's call (`agent-action.ts:1281`) passes `composePrompt([prompt])`.

**4. `buildReviewPrompt` and `fixBrief` keep their string signatures.**

- Add `reviewPromptParts(...)` and `fixBriefParts(...)`, which return the parts array.
- Reduce the existing functions to `composePrompt(parts).handed`.
- That keeps `fix.test.ts`'s sentence pins (`fix.ts:466-468`) and every `buildReviewPrompt` caller on today's text.
- The new tests assert `parts → handed` equals the old function's output for one fixture.

**5. `alsoSays(fixBrief(...), spec.prompt)` (`conduct.ts:3959-3971`) appends a written-out string part to the parts.** It is not applied to the finished string afterwards. Otherwise every recorded offset sits before the appended text, which works by luck rather than by construction.

### The diff deps return their shas, not just text

This is the change the ticket does not spell out.

**Neither diff call has two shas today:**

- The reviewer's `diff` dep runs `` `${from ?? (await heldBaseMerge()) ?? baseShaOr('HEAD')}...HEAD` `` (`conduct.ts:3256-3264`).
- The fix delta calls the same dep with `context.reviewedSha` (`agent-action.ts:660`) and then records `toSha: context.onSha` (`:664`). That sha was not what the diff ran against: the diff ran against `HEAD`.
- The fixer runs `` `${continuation?.diffBaseSha ?? tree.baseSha}...HEAD` `` (`conduct.ts:3949`).

**The fix, in both places:**

1. Change `AgentActionDeps.diff` (`agent-action.ts:127`) to `(from?: string) => Promise<{ text: string; from: string | null; to: string | null }>`.
2. In `conduct.ts`, write one helper used by both the dep and the fixer's line 3949. It runs `git rev-parse --verify <from>^{commit}` and `git rev-parse --verify HEAD^{commit}` first, then `git diff ${DIFF_FLAGS} <fromSha>...<toSha>`.
3. If either rev-parse fails, the helper falls back to today's ref-based command and returns `null` shas. The insert is then written out, as the ticket's table says.
4. `ReviewDelta` takes its `fromSha` and `toSha` from the result, not from `context`. Those shas are also what `deltaBlock` prints, which is what makes the text and the ref name the same pair.

The `from...to` three-dot form stays as it is. The resolver runs the identical three-dot command, so merge-base semantics match by construction.

**The empty-diff check moves to `.text`:**

- The reviewer's `!diff.trim()` short-circuit (`agent-action.ts:609`) and `clippedAt` (`:620`) read `.text`.
- An empty diff never reaches composition. In general, an insert that is `''` is a plain string part.

**Existing fakes of `deps.diff` in `packages/actions/unit/` have to change shape.** Return `{ text, from: null, to: null }` where a test does not care, so those tests keep asserting a written-out prompt.

### Where the body's version comes from

`took` is `{ ticketId, kind, ticket }` (`Claimed`, `packages/conductor/src/attempt-steps.ts:164-170`). It drops the version that `claimTicket` and `continueTicket` return (`claim.ts:175`, `:234`).

- Add `readonly claimVersion?: number` to `Claimed`.
- Set it at `conduct.ts:2448` from the claim/continue result.
- Set it **only when that call was given a `body`**. Both pass `body: issue.body` today (`conduct.ts:2378`, `:2387`), and the event records it only when `options.body !== undefined` (`claim.ts:172`).

**Readers:**

- The reviewer's `issue` closure (`conduct.ts:3235`) widens to `{ ref, title, body, bodyAt?: { stream, version } }`. `ReviewIssue` gains the same optional field. `reviewPromptParts` emits a `TicketBody` part only when `bodyAt` is present and `body !== ''`.
- The fixer reads `brief.ticket` (`conduct.ts:3966`). That is `took.ticket` (`conduct.ts:4123`), so the same version applies. Pass it into `fixBriefParts`.

`ticket.body` is exactly the string the claim event recorded: both are `issue.body` from the same fetch. That identity is what makes a `TicketBody` ref sound. Do not re-fetch or trim the body anywhere on this path.

### The marker

`markerOf(ref)` is in the domain and is the single spelling:

- `⟪lingtai:body <stream>@<version> · N bytes⟫`
- `⟪lingtai:diff <from7>...<to7> · N bytes⟫`

`expandPrompt` checks `prompt.slice(start, end) === markerOf(entry.ref, entry.bytes)`, so the size is part of the marker. Spans must be strictly increasing and non-overlapping. The first entry that breaks this, or runs past `prompt.length`, makes the record malformed. Return `{ text: prompt, unresolved: [{ index, ref, why: 'malformed refs' }] }` and do not substitute anything. Substitute from the last span to the first, so earlier offsets stay valid.

### The resolver

Put it in `packages/conductor/src/prompt-refs.ts`:

```ts
resolvePromptRefs(
  entries,
  { readStream, git, mirrorPath },
) => Promise<PromptValue[]>
```

- **`TicketBody`:** read the stream and find the event whose `version === ref.version`. It must be `TicketClaimed` or `TicketContinued` and have a string `body`.
- **`Diff`:** first run `cat-file -e <sha>^{commit}` for each end, so a missing object reads `"<sha> is not in the mirror"` rather than git's stderr. Then run `diff ...DIFF_FLAGS from...to` with `cwd: mirrorPath`.
- **For each value:** if `bytes` differs, it is unresolved. If the sha256 differs, it is unresolved.
- **Never throw.** Every error becomes that entry's `unresolved`.
- **Inject the git runner** as `(args, cwd) => Promise<Either<…, string>>`, matching `gitAsked`'s shape, so the unit test needs no binary.
- **Nothing in a pass calls it in this ticket.** It exists for the board ticket, so it is exported but not wired in.

### What settles it after the merge

In the log, compare a `RunPrompted` that has `for: {_tag:'Action', step:'review'}`:

- `data.bytes` against `data.prompt.length`
- `data.refs[*].bytes`

`bytes` minus the UTF-8 length of `prompt` should be roughly the sum of `refs[*].bytes`.

A missing `TicketBody` ref on a pass that should have one can mean either of two things:

- `took.claimVersion` was not set.
- The `TicketClaimed`/`TicketContinued` at that version has no `body` field.

The second is the claim ticket's field, so check that event before suspecting the composer.
