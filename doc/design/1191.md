# Design note: #1191, the all-time landed figure

## The one decision the ticket leaves open: the object has three fields

The ticket says to write `landedAllTime: { count, asOf }`, and then says to render *"since <first merge date>"*. Neither of those two fields holds that date. Write **`landedAllTime: { count, since, asOf }`**:

- `since` is the `YYYY-MM-DD` of the earliest counted merge, taken from `%cI`.
- `asOf` is the run's `now`, the same instant as `capturedAt` (`scripts/books.ts:102`).

This is still one key, so it stays within the operator's exception.

## Where each piece goes

**Counting has no I/O and goes in `scripts/take-books.ts`, beside `takeBooks`.** That file's header says *"no I/O, no clock (#811)"* (`take-books.ts:7`), and `unit/books.test.ts:5` already imports from it.

- Add a function shaped roughly `landedAllTime(merges: {subject, committedAt}[], closed: ReadonlySet<number>, asOf: Date)`.
- It returns the figure, or a refusal when no merge matches. Zero matching `^Merge branch 'agent/(\d+)'` subjects means the wrong checkout or a missing `origin/main`, and the ticket says never to write `0`.
- The four counting cases in *Done when* are unit tests of this function. They need no git and no network.

**The reads go in `scripts/books.ts`, in the style of `head()` (`books.ts:59-65`).** Use `execFileSync` for both:

- `git log origin/main --merges --format=%H%x00%s%x00%cI`.
- `gh api --paginate 'repos/steven-zhc/lingtai/issues?state=closed&per_page=100' --jq '.[] | select(.pull_request | not) | .number'`. The `pull_request` filter is what drops PRs.

Use the operator's `gh` login, not `@lingtai/github`:

- `@lingtai/site`'s dependencies are `conductor`, `domain` and `projector` only (`apps/site/package.json:13-16`). `packages/github` expects the App's credentials.
- `apps/site` is not in the Effect ratchet's `PACKAGES` (`packages/domain/unit/effect-ratchet.test.ts:38-50`). So these sync calls cost the ratchet nothing. Don't add an `async` helper anyway: make the reads synchronous, like `head()`.

**When a read fails, refuse; don't omit the key.** Either `execFileSync` throwing, or `origin/main` missing, goes through `refuse([...])` (`books.ts:73-77`) with a line naming what failed, and nothing is written. That is the file's existing rule: *"It refuses and writes nothing, rather than a partial file"* (`books.ts:24`).

The ticket's *"the key is absent"* edge is about the reader, not the script. The `books.json` committed today (`81d58409`) has no such key and must still parse and render.

- Do not run `git fetch` from the script. It writes refs.
- Say in the header comment and in `release.yml`'s comment that the operator fetches first.
- Do the reads before `takeBooks`, so that one refusal path covers everything.
- Add the figure to the `books:` summary line (`books.ts:137`) so the operator sees it before committing.

## `parseBooks`

`parseBooks` currently requires an exact key count:

```ts
keys.length !== KEYS.length || !KEYS.every((k) => k in value)
```

(`src/lib/books.ts:136`). Change it to three rules:

1. Every name in `KEYS` must be present.
2. The only other key allowed is `landedAllTime`.
3. When `landedAllTime` is present, it must pass `shaped(v, { count: num, since: str, asOf: str })`.

On the `Books` type, the field is `landedAllTime?: { count: number; since: string; asOf: string }`. Make it optional, not `| null`: the ticket says *absent*, and an absent key keeps old files valid.

Rewrite the comment at `books.ts:14-16` so it still refuses totals in general. It should name this one figure as the exception, with the reason: the operator's decision of 2026-11-15, and #1191. Also rewrite the matching sentence at `take-books.ts:20`, *"There is no total"*. That sentence stays true of `takeBooks`, but the new function sits beside it.

Unit cases:

- A file with the key parses.
- A file without it parses (the existing fixture, `unit/books-fixture.ts`).
- A wrongly shaped `landedAllTime` is refused.
- Any other extra key, for example `totalCost`, is still refused.

## Rendering

The figure goes in `.books-head` (`books-section.tsx:151-160`), as the first and largest number. Render it only when `books.landedAllTime` is present, and render nothing in its place otherwise.

- Write the count with the locale format the section already uses for its other figures (see the `num` helper near the top of `books-section.tsx`).
- The wording comes from the ticket: *N issues closed by Lingtai's own merges, since `since`*. Show `asOf` as a date (*as of …*), because the window line beside it is a different date range, and a reader must not take the figure for the window's.
- The head is a two-column grid (`home.css:314`, single column at `:347`). The figure needs its own block in that head, not the `.fig` / `Figure` component (`books-section.tsx:70`), which is sized for the row below.

**Name any new class with a `books-` prefix.** The site loads the board's stylesheet first, so a site class with the same name as a board class inherits the board's rules. That is #1189 (`unit/home-css.test.ts:6-9`), and that test only guards the sandbox block. Check a new name against `apps/board/src/app/globals.css` yourself.

The render test goes in `unit/books-section.test.tsx`. It covers the fixture with `landedAllTime`, where the count and the date appear, and the fixture without it, where neither appears.

## What nothing in a pass can check

The real count can only come from running the script, which needs `gh` auth and a fetched `origin/main`. The ticket gives that to a person (*"A person checks the home page after running the script"*). The agent should not run `pnpm --filter @lingtai/site books`, and should not commit a regenerated `books.json`. The release step writes that file, and the pure function's tests stand in for the run.
