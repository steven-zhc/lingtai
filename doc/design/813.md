I've read the two pages and the code behind them; here is the design note.

---

The shape is the ticket's: six passages in two files, and nothing else. Two facts the ticket leaves for you to find are below, with their lines, so the new rows can cite code the way the rest of `requirements.md` does.

**What a `gh` project pushes with (passage 4).** It pushes with the person's own `gh` login, fetched again on every `git` call:
- `createGitHubClient` sets `tokenFor = (signal) => ghToken(run, signal)` when auth is `gh` (`packages/github/src/client.ts:379-382`). The comment there says *"No installation: the saved login is a person's, and each call asks `gh` afresh"*.
- `ghToken` runs `gh auth token --hostname github.com` (`packages/github/src/gh.ts:80-81`).
- That function is the client's `token` (`client.ts:579`), and the conductor hands it to every git invocation as `token: () => client.token()` (`apps/cli/src/conduct.ts:281`).
- `gitInvocation` sends it the same way in both modes, as an `extraheader` through `GIT_CONFIG_*` and never on argv (`packages/repo/src/git.ts:51-70`).

So the row should say: an App project pushes with an installation token of the App; a `gh` project pushes with the token `gh auth token` gives. Neither needs a personal SSH key for a run's own push. Keep `git.ts:47` as the citation and add `client.ts:382`.

**The doctor column for the new account row(s).** The tutorial names two checks (`doc/tutorial.md:269`): `github: gh login` (`ok`, naming the account) for `gh` mode, and `github: app credentials` for App mode, which reads `skip` under `gh`. Put those in the doctor column rather than copying the App row's *"None"*. The column now says *"`lingtai add` checks the App's permissions before it records a repository"*; keep that on the App row only. Which mode is in force comes from `githubAuth(env).kind` (`packages/env/src/index.ts:1514`, `apps/cli/src/doctor.ts:944`).

**Decisions made here:**
- **Passage 3 becomes two rows**, one for the signed-in `gh` and one for the App, not one row with both. The columns (*Needed when*, *Why*, doctor check) differ for each. Two rows keep the table at five columns, which is the edge the ticket names. Put the `gh` row first, because `init` defaults to it. Its *Needed when* is *a GitHub project with `--github-auth gh`, the default*, with scopes `repo` and `workflow` (`tutorial.md:241`). The App row's *Needed when* names a team, citing 0114 as a GitHub link to `doc/decisions-archive/0114-…`, the way these pages already link ADRs.
- **Passage 2: delete the bullet.** Do not move it. The table row at `:45` is where the reader comparing the two tools looks, and once that row states the condition, a second statement elsewhere adds nothing. Fill row `:45` from 0122 and `apps/cli/src/conduct.ts:330-332`: `runtime.concurrency`, which takes effect only when a daily ceiling is set, and is otherwise one pass at a time. Linear (#340) is then the only item left under *What Lingtai does not have yet*, and a one-item list is fine.
- **Passage 5:** write the three ways as one bullet, matching the other bullets' form: `--local` needs no GitHub at all; `gh` needs a signed-in `gh` with `repo,workflow`; an App needs one created and installed. The base must take direct pushes from whoever pushes (`tutorial.md:251`). That fact is true but out of scope, so leave it out.
- **Passage 6:** add a clause to the *Needed when* cell, and change nothing in the other columns.
