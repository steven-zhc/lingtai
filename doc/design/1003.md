# Design: #1003 — the day's ceiling as a lock of its own

The ticket gives the shape. This note covers only the points where the existing code forces a choice the ticket does not spell out.

**Where #999 left things.** `controlReducer.version` is already 4 (`packages/domain/src/control.ts:365`), and `reducer-versions.json` has rows `"1"` to `"4"`. So 5 is the next row and nothing waits on #999. The ticket's line numbers in `control.ts` are from before #998 and #999: `ControlState` now runs to about :140, `emptyControl` to :152, and the reducer starts at `reduceControlEvent` :192. Find code by name, not by those numbers.

## Every comparison is in integer cents

`ceilingCheck` and `raiseTransition` take `reportedCents` and `estimatedCents`, but the figures they compare against are dollars: `configuredUsd`, `raised.toUsd` and `reached.ceilingUsd`. Convert each figure once, with `Math.round(usd * 100)`, exactly as `ceilingReached` does:

> `day.reportedCents + day.estimatedCents >= Math.round(ceilingUsd * 100)` (`packages/conductor/src/day-ceiling.ts:135-136`)

Then compare cents with cents. If you compare floats, a $25.00 ceiling against 2500 cents can come out either way.

- "Reached" is `>=`, as in `ceilingReached`.
- Both "above" refusals in `raiseTransition` are strict `>`, because 0126 §7 says *"A `toUsd` not above the day's spend is refused"*.
- On the event, `reportedUsd` and `estimatedUsd` are cents divided by 100. They are never re-summed from rows.

## `ceilingCheck` returns `ToAppend`s the way `turnTransition` does

Follow `turnTransition` (`packages/domain/src/project.ts:193-215`): an object literal with `type`, `actor: 'conductor'` and `data`. The system's events use `actor: 'conductor'`; the person's lift uses its `by`.

The `ELSEWHERE` rows are matched by an `anchor` string that must appear verbatim in the named file (`packages/domain/scripts/events.ts:129-151`). Each anchor is one line such as `"type: 'ProjectRefused',"`. Format the literals in `ceiling-lock.ts` so that `type: 'DayCeilingReached',` and `type: 'DayCeilingLifted',` each sit on a line of their own, and point both rows' `file` at `packages/domain/src/ceiling-lock.ts`.

`DayCeilingLifted` also has a real append site in `raiseDayCeiling`. If `events-json.test.ts` finds that site through the payload in `packages/daemon/src/control.ts`, `DayCeilingLifted` needs no `ELSEWHERE` row. Run the test before adding one.

`raiseTransition` returns a discriminated union: `{ ok: true, event }` or `{ ok: false, refused: 'not-reached' | 'not-above-spend' | 'not-above-ceiling' }`. The event's `day` is `reached.day`; after the `not-reached` check that is the same as `localDay(now)`. Check the refusals in the ticket's order, so a raise when nothing stands always answers `not-reached`, whatever figure it names.

`localDay` builds the date from `getFullYear` / `getMonth` / `getDate`, zero-padded, so it is the same day `startOfLocalDay` opens (`packages/conductor/src/day-ceiling.ts:53`). Never use `toISOString().slice(0, 10)`: that is the UTC day, which is a different day for part of every evening west of Greenwich.

## The reducer stores `seq` as a number

`Envelope.seq` is a `bigint` (`packages/domain/src/envelope.ts:83`). The stored snapshot is JSON through `StoredControl`, which is a strict object, so keep `reached.seq` as `Number(e.seq)` and declare it `z.number()` in the codec. Decode `at` the same way the codec already decodes other dates.

Apply the reducer's own rule to an unparseable payload too: *"An unparseable one is the same answer as none"* (`control.ts`, in the `ConductorPaused` case). So:

- A `DayCeilingReached` whose `day` is not a string, or whose figures are not numbers, leaves the state as it was.
- A `DayCeilingLifted` always clears `reached`, but sets `raised` only when `why === 'person'` and `toUsd` and `by` are present.

The reducer reads no clock. `evaluateControl` (`control.ts:302-330`) gets no new branch: the day check belongs to `ceilingCheck`, as the ticket says.

## `raiseDayCeiling` is an Effect, and it copies the retry it already has

`requestShutdownUnlessStanding` (`packages/daemon/src/control.ts:230-250`) is the precedent: read `store.head(CONTROL_STREAM)`, then `readControl(store, 0, …)`, decide, append at the head read, and retry on `ConcurrencyError`. Use that order. Read the head first, so a change that lands between the two reads makes the append fail rather than slip through.

It must not be another `async function`, because `effect-ratchet.test.ts` counts those. Write it as `Effect.gen` with `Effect.tryPromise` around `store.head`, `readControl` and `store.append`. Don't call the private `append` helper (:160); call `store.append(CONTROL_STREAM, at, [toAppend])` directly. Do not use `Effect.run*` inside it; the CLI's edge runs it.

Retry exactly once, as the ticket says, not the four times the shutdown loop allows:

- **Second `ConcurrencyError`:** the Effect fails with it.
- **Refusal:** the Effect succeeds with a refusal value, not a failure, so the verb can print the sentence and exit 1.

Take `now` as a parameter that defaults to `new Date()`, so the memory-store test can fix the day. `readControl` calls `evaluateControl(state, new Date())` internally (:146); that is harmless here, because nothing in `dayCeiling` is evaluated against the clock there.

The ticket's Edges say a `day_usd` that does not parse makes the appender refuse. In fact the appender is never given the configured figure, because `raiseTransition` compares against `reached.ceilingUsd` and not against the configuration. So the throw from `machineDayCeiling` (`packages/env/src/index.ts:992-996`) can only surface in the verb's success sentence (*"the configuration still says $25.00"*). Catch it there and print *the configuration's figure could not be read* rather than failing a raise that already appended.

## The verb

- Use `projection` (`apps/cli/src/commands.ts:569`) as the model for a two-word verb, and `resume` in `daemon.ts` for how a control verb is dispatched.
- The spend read and its trust checks are the same calls `dayCeilingStop` makes in `apps/cli/src/day-ceiling.ts`. Factor out the "read today's spend or refuse by name" part so both use it, rather than copying it. Leave `dayCeilingStop`'s behaviour byte-for-byte as it is.
- The stubbed-port test belongs in `apps/cli/unit/`, using the memory store, so it never touches the filesystem.
- Parse `<usd>` with `Number(arg)`, accepting only finite values above 0. `parseFloat` would accept `"40abc"`.

## What stands in for the integration half

Every claim in this ticket can be checked in the unit half:

- the pure functions;
- the reducer and codec;
- `raiseDayCeiling` against `createMemoryEventStore()`;
- the verb with stubbed ports.

Nothing here needs Postgres. If a test seems to need one, the code is reading the real store where it should be taking a parameter.
