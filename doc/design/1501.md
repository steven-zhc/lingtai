# #1501: design note

## The old routes are not folders

`apps/board/src/app/` has no `task/`, `pr/` or `recipe/` folder, so the Fix's "delete the old route folders" step has nothing to delete. Since #1498, one function answers every old URL. It is the proxy, `apps/board/src/proxy.ts:14-25`:

```ts
const moved = legacyRedirect(pathname, searchParams)
if (moved !== null) return NextResponse.redirect(new URL(moved, request.url), 308)
…
matcher: ['/', '/task/:path*', '/pr/:path*', '/recipe/:path*', '/landed', '/backlog'],
```

`legacyRedirect` lives in `apps/board/src/lib/legacy.ts`. It is "a pure function of the URL … A hit is answered 308" (`legacy.ts:2-4`). Removing the redirects means:

- Delete `src/lib/legacy.ts` and `unit/legacy.test.ts`.
- Delete the `old(...)` block in `unit/paths.test.ts:62-75`.
- Cut `proxy.ts` down to its 307 for a bare `/`. Its matcher becomes `['/']`, and its header comment loses the 308 half.

Keep `ticketRefOf` in `paths.ts`. `p/[project]/ticket/[n]/layout.tsx:213,338` still use it.

Once the proxy stops matching them, `/task/…`, `/pr/…` and `/recipe/…` are 404s with nothing else changed, because no page lives there.

## `?project=` handling, per page

**`/`**: the page takes no `searchParams` (`app/page.tsx:1214`, `export default async function Page()`). Two places still read `project`:
- `legacyRedirect` (deleted above).
- `remember.ts:24`, `if (search.has('project')) return null`. Delete this line too.

After that, `/?project=lingtai` is just `/`. With a remembered project it gets the 307, otherwise it shows all projects. Rewrite `unit/remember.test.ts:17-20` ("passes through any request that names a project") to say so.

**`/backlog`**: nothing to do. `BacklogPage` already passes `project: undefined` (`backlog/page.tsx:77`).

**`/landed` is where it would fail silently.** Here is the current path:
- `LandedPage` passes the whole query string on: `LandedBody({ project: undefined, params: await searchParams })` (`landed/page.tsx:34`).
- `LandedBody` reads `first(params.project)` for the menu (`:43`).
- `landedQuery` reads `project: first(params.project) || null` (`lib/landed.ts:59`).

So with the redirect deleted, `/landed?project=x` would quietly serve a filtered page, and the old URL would keep working by accident. That is exactly what the ticket's Problem row describes.

Change it so the `project` argument is the only source of the project:
- `LandedPage` drops `project` from the params before calling `LandedBody`.
- `LandedBody` and `landedQuery` stop reading `params.project`.
- `/p/[project]/ticket/landed/page.tsx:15` already passes the project in from the path.
- Rewrite the `:37` comment ("a path segment wins over a stray `?project=`") because the stray parameter is now ignored.

Add a unit test: the global page, handed `{ project: 'x' }`, builds an unfiltered query.

## What "gets no page" means for `/?project=lingtai`

That URL can't be a 404 because `/` exists. Making a query parameter return a 404 would take code that names the old form, which is what this ticket removes. **Decision:** for `/?project=` and `/landed?project=`, "no page" means *no redirect and no filtering*: the request is answered as if the parameter were absent.

## The route-table test

A unit test can't reach Next's router. The one thing that sees the real route table is `apps/release/integration/build.test.ts`, the Next build. It belongs to the 803-second half and runs only after the merge.

The unit stand-in has three parts, in a new `apps/board/unit/no-old-routes.test.ts`:
1. Read the `src/app` tree the way `unit/remember.test.ts:38` already reads source with `readFileSync`. Match `/task/ticket-lingtai-1`, `/pr/lingtai/1` and `/recipe/lingtai` against its folders, treating `[param]` as a wildcard and `(group)` as transparent. Assert none resolves to a `page.tsx`.
2. Assert `proxy.ts`'s `config.matcher` equals `['/']`.
3. Assert that `proxy()` answers each of the four URLs, `/?project=lingtai` with no cookie included, with no `location` header.

Say in the PR that the build test is the real check and it runs after the merge.

## The scan test

Put it in `apps/board/unit/no-old-url.test.ts`. It walks every file under `apps/*` and `packages/*` (skipping `node_modules`, `.next`, `dist`) and fails, with `file:line`, on these patterns:

- `/task/`. No file path in the repository contains it; every current hit is a URL.
- `/pr/` and `/recipe/` only when the preceding character is not a word character or `]`. This keeps `/p/p/pr/1`, `p/[project]/recipe/${file}` (`unit/recipe-editor.test.tsx:44`) and `packages/recipe/…` passing. `recipe.yml` is `/recipe.` and never matches.
- `?project=` only after `'/`, `` `/ ``, `"/`, `/landed` or `/backlog`. A plain `?project=` would also match `/report` and `/setup`.

Build the patterns from fragments, or skip the test's own path, so the test doesn't match itself. Reading source files counts as unit here: `remember.test.ts:38` already does it.

The ticket accepts the cost: any later comment that writes `/task/` fails the suite. The failure message should name the new form to write instead.
