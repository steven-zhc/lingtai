# #897: skeleton cards in Queued, and `arrive` on GitHub's cards

The ticket's Fix section is close to the whole design. Four things are not obvious from it.

## 1. `arrive` reaches `Card` through `ListQueued`, not through `BoardCard`

`QueuedAnswered` cannot add the class itself. It draws cards only through the `list` callback (`queued-stream.tsx:25`, `:97`). `Card` and `Queued` are kept out of this file on purpose: *"`Card` and `Queued` live in `page.tsx`, which may export nothing but the page"* (`queued-stream.tsx:11-12`).

- Give `ListQueued` a fourth argument, `arriving: ReadonlySet<string>`, a set of `taskId`s.
- `QueuedAnswered` passes `new Set(github.cards.map(c => c.taskId))`. `QueuedFallback` passes an empty set.
- `Queued` (`page.tsx:548`) hands each `Card` an `arrive` boolean. `Card` adds the class only on its queued branch, the `<article className={\`card ${accent(card)}\`}>` at `page.tsx:248`. The waiting-card branch at `:200` never sees a GitHub card.
- Both `list={…}` lambdas in `page.tsx:919-928` and `:936-945` forward the new argument.

Don't add a field to `BoardCard`. `githubQueue` builds every card by hand, field by field (`board.ts:962-1000`), so a new field would be a shared type changed only to carry one CSS class.

The test stub in `unit/queued-stream.test.tsx:25-26` prints its arguments. Add the arriving ids to what it prints, and the *GitHub's cards only* assertion becomes a string match. Every existing assertion on that stub's output has to be updated in the same change.

`known` makes "GitHub's cards" a set disjoint from the log's. *"A task released back to the queue has a row and is offered by GitHub… The row wins"* (`board.ts:916-918`), and the loop skips it (`known.has(r.taskId)`, `:961`). So a released ticket never fades in.

## 2. The remembered count, decided

Put a `lastOffered = new Map<string, number>()` beside `lastKindColors` (`board.ts:884`). Write it on the same line that writes the colours (`board.ts:955`), with the number of cards this project added to `cards` after the `known` filter. That is the count of cards that will actually take the skeletons' place.

- **Unanswered project:** write nothing, the way the `continue` at `:946` already skips the colours. The last good count stands. The ticket says what the reader sees in that case: the problem line, no skeleton.
- **Reader:** `skeletonCount(projects: readonly string[]): number`.
  - Sum the entries for the projects in view and cap the sum at 3.
  - If **none** of those projects has an entry, return 2.
  - If some have entries and some don't, sum the ones that do. This is my decision; a newly added project costs at most one wrong-sized wait.
- **Projects in view:** the `askable` the page already holds (`page.tsx:653`). It comes from `loadBoard(only)` (`:629`, `:662`), so the `?project=` filter is already applied. Don't recompute it from `onBoard`. That set is *"What the cards say, not what is registered"* (`:686-687`), and a project with no log card would be missed.
- **Test reset:** add a `forgetSkeletonCounts()` next to `forgetKindColors` (`:887`).

Computing `n` belongs in `page.tsx`. Pass it to `QueuedFallback` as a plain `count` prop, so the component stays *"Pure over their arguments"* (`queued-stream.tsx:7`). The Done-when test for 3, 0 and 2 is then written against literal props, plus one unit test on `skeletonCount` and the map.

Order is safe. The fallback is rendered in the same render that starts `githubQueue` (`page.tsx:676`), and the map is written only after `await Promise.all` (`:934`). So the fallback always reads the previous answer, never a half-written one.

## 3. Reduced motion is already global; still write the local rule

`globals.css:90` already turns everything off: `@media (prefers-reduced-motion: reduce) { * { transition: none !important; animation: none !important; } }`. The shimmer and the fade are covered without any new code.

The Done-when still asks for a rule the test can find. Follow the local precedent, `.caret` at `globals.css:1996-1997` and `.scell.t-run` at `:557-558`: put `@keyframes`, then the `@media (prefers-reduced-motion: reduce) { .skeleton…, .card.arrive { animation: none; } }` line, right beside the new rules. Have the test read `globals.css` the way `unit/bar.test.ts:192` and `unit/fonts.test.ts:14` do, and check that the reduced-motion block names the skeleton's class.

Keep the `@keyframes` names unique. `seg-live`, `standing-live` and `caret-blink` already exist (`:557`, `:961`, `:1996`).

## 4. `Skeleton` is generic; the label is its own element

`Skeleton` lives in `app/skeleton.tsx` and takes no import from `@/lib/board`. #898 is the next caller, and it will draw `lines`.

- The label is a `<p>` with the class `empty asking`, the same as today's line, followed by `count` placeholder blocks.
- Mark the placeholders `aria-hidden`, so a screen reader hears the label and not the outlines.
- With `count={0}` it renders the label alone.

Keeping the label's text and class means the existing assertions on `ASKING_COLUMN` (`unit/queued-stream.test.tsx`) pass unchanged, as the ticket's Cost line expects.

`.asking` has no rule today. Give it the small type the ticket asks for, scoped as `.skeleton .asking`, so other `.empty` notes don't change.

A card skeleton should match `.card`'s box (`globals.css:321`): same padding, border and radius, with placeholder bars for the id line, a title line and the rail's strip. Otherwise the skeletons and the cards that replace them differ in height, and the column jumps anyway.

## The count dot

`QueuedCountPending` renders `<span className="ct">{logCount}<span className="pulse" aria-hidden /></span>`, and `QueuedCountAnswered` (`queued-stream.tsx:107-109`) stays as it is. Use `.pulse`'s own keyframes and add it to the same local reduced-motion line as above.

## Checks

Everything here is unit-level. `renderToStaticMarkup` and a read of `globals.css` cover every checkbox except the person's restart-and-reload. No part of this needs `pnpm test:integration`.

This shape doesn't contradict any accepted ADR. 0111 §15 is the rule it implements.
