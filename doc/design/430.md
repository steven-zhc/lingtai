# #430: the design note

## The decision, which is already written

0101 §1 already holds the decision. Do not write a new ADR, and do not edit 0101:

> **TypeScript throughout, on Node `>=26`** … The version is written once, in `.node-version`: `engines`, every workflow and the machine building binaries read it from there, because a floor below the Node the repository is actually run on is a floor nothing tests (#430).

(`doc/decisions/0101-typescript-packages-effect-unbuilt.md:30-33`.) `.node-version` already contains `26`. This ticket makes the code match a decision that is already accepted.

## Workflows: one key, four files

- In each of `check.yml:37`, `deploy-site.yml:39` and `release.yml:40`, replace `node-version: …` with `node-version-file: .node-version`. Every one of them already runs `actions/checkout` before `setup-node`, which matters: the file has to exist when `setup-node` reads it. In `release.yml`, keep the comment above the key (*"`node --build-sea` is 25.5 and later; the binary carries this Node"*). It still explains why the floor cannot go lower.
- In `lock.yml:33`, delete the whole `node:` axis, not just its `22.13.0` entry. The matrix becomes `runner` only, and `node-version-file: .node-version` replaces `${{ matrix.node }}` at `:40`. Keep `runner: [ubuntu-24.04, macos-15]`. That matrix exists for a per-platform claim (`lock.yml:9-11`), and that claim does not depend on the Node version.

## The doctor row

**Where.** Put it first in `runDoctor` (`apps/cli/src/doctor.ts:2201`), next to `packages load under Node`. That row is already this command's claim about the Node it runs on, and it is hardcoded `ok`.

**Shape.** Write an exported pure function, `nodeRow(running: string, declared: string | undefined): CheckResult`:

- `running` is `process.versions.node`.
- `declared` is the trimmed text of `.node-version`, or `undefined` when the file cannot be read.

`runDoctor` does the file read and passes the result in. It reads `join(repoRoot(), '.node-version')`, where `repoRoot` is `packages/env/src/index.ts:1016`, the anchor for *"the checkout Lingtai is running from"*.

**Why the read stays outside the function.** Under 0060 §1, a test that reads a file is integration (*"A temporary directory is still the filesystem"*). With the read outside `nodeRow`, the unit test can pass strings in and stays in `pnpm test`.

**Statuses.** Compare majors only. Take the leading integer of each value, so that `26`, `v26.5.0` and `26.5` all parse.

- Running major below declared → `fail`. The detail names both versions and the remedy: install Node `<major>` (the version `.node-version` names), then rerun.
  - Do not set `restartAnswers`. This failure should gate `lingtai restart` (`gatingFailures`, 0042), because a daemon started on this Node is a daemon on the version CI no longer tests.
- At or above → `ok`, naming both versions.
- `declared` is `undefined` or does not parse → `fail`, naming the file. A checkout without it has lost the one place the version is written.

**In a binary.** When `isSea()` is true (see `apps/cli/src/version.ts:1,19` for the import), do not read the file. A binary has no checkout beside it, and it carries the Node that built it, which `release.yml` now takes from `.node-version`. Return `ok` with a detail that says this, for example *"node vX — the binary carries the Node it was built with"*, and do not call `nodeRow`.

**What the row cannot do.** Do not claim it covers every old Node. `pnpm lingtai` is `node apps/cli/src/entry.ts` (`package.json:22`), and a Node that cannot strip types unflagged dies on that `.ts` before doctor loads. 22.13 is one of those, so the row speaks for the Nodes between that point and 26. Below that, the only thing that speaks is `engines`. Put one sentence about this in `nodeRow`'s docstring, so that nobody later reads the row as the whole guarantee.

**Test.** Add a `describe` to `apps/cli/unit/doctor.test.ts`, or a sibling unit file, that calls `nodeRow` directly:

- `('22.13.0', '26')` → `fail`, and the detail contains `26` and the remedy.
- `('26.5.0', '26')` → `ok`.
- `('27.0.0', '26')` → `ok`.
- `('26.0.0', undefined)` → `fail`, naming `.node-version`.

Do not go through `runDoctor` for this. Its first rows would make the assertion depend on `process.version`, which on the conducting machine is 26 and would never take the failing branch.

## The other places that still say 22.13

After `engines` says `>=26`, these become false:

- **Comments.** `packages/env/src/lock.ts:170` and `packages/event-store/src/sqlite.ts:80` both say *"unflagged from 22.13, which is why `engines` says so"*. The `node:sqlite` fact is still true. The *"which is why `engines` says so"* part is not. Change each comment to say the floor is 0101's, and that `node:sqlite` is below that floor.
- **Runtime messages.** `lock.ts:176`, `event-store/src/sqlite.ts:86` and `projector/src/sqlite.ts:62` each say *"Node 22.13 or later has it"*. That is a remedy that sends a person to the exact version this ticket stops supporting. Change each to name 26. Leave the guard logic as it is.
- **Tests of those messages.** `packages/event-store/integration/sqlite.test.ts:301,303,357` assert the old text and must change with it. They are integration tests and nothing runs them inside the pass. Before committing, run `git grep -n '22\.13'` over `packages/` and `apps/`. The only hits left should be `file-lock.test.ts:223`, which is about 22.16 behaviour and stays.
- **Docs.** `doc/design/installing.md:16,239` says *"Node 22.13+"*; change both to Node 26. Leave `doc/design/365.md`: it is the design record of that ticket.

Do not touch the SQL that fails on 22.13. That is the ticket's own *Watch out*, and nothing above requires it.

## What cannot be checked before the merge

`check.yml` going green is the claim this ticket makes, and only the push to `main` can show it. That Done-when box is not one the pass ticks. Inside the pass, these stand in for it:

- the `nodeRow` unit test;
- `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test`;
- `git grep -nE 'node-version: |matrix\.node'` over `.github/workflows/` coming back empty.
