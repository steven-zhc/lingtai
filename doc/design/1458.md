## 1. Size is a class the component chooses. A context rule never sets it.

The ticket gives one button different sizes depending on where it sits. Close is small on a queued home card and regular on the task page. TriageMove is small on a waiting card. PrButtons is small on `/pr/<project>` and regular on a PR's page. Do not write `.card .btn { font-size… }` for this: the guard test below would fail on that rule, and that rule is exactly the kind of override (`.sresolutionaction .btn`, `.detail--waiting .chatask .btn`) this ticket removes. Instead:

- Add `small?: boolean` to `Close` (`decide.tsx:752`), `TriageMove` (`decide.tsx:1064`) and `PrButtons`. Each one turns it into `btn sm` / `btn pri sm`.
- Pass `small` from `page.tsx:484` (queued card), `page.tsx:270` (waiting card) and `pr-columns.tsx:81`.
- Buttons that are small everywhere hard-code `sm`. These are `evidence.tsx`, `pending.tsx`, `paused.tsx`, the backlog row, the banners, `.s2-change`, sandbox, report and `LandedCount`.

`.btn.sm` sets only `font-size` and `padding`. `.btn.pri` sets only colours. That way `btn pri sm` composes in any class order, and no `.btn.pri.sm` rule is needed.

## 3. `text-decoration: none` stays out of `.btn`

The ticket's Edges section says *"the button rule sets `text-decoration: none`"*. `links.test.ts` (#1457) fails on that: *"text-decoration: none is said in the opt-out rule and nowhere else"*, and its filter names one other exception. `a.btn` is already in that opt-out rule (`globals.css:163-165`), so button-styled links are covered.

- Remove `.ctbtn`, `.pr-btn`, `.sbbtn` and `.wiz-primary` from the opt-out selector, because those classes no longer exist.
- Drop `.ctbtn` and `.pr-btn` from `links.test.ts`'s `REQUIRED` (`:33-34`) and add `a.btn` in their place.
- Every former link class that becomes a button must actually render as `<a className="btn…">` or `<Link className="btn…">` so that `a.btn` matches it. This applies to `ctbtn`, the PR link, the sandbox `Link`, `wiz-primary` and the pick-repository Next link.

## 4. The guard test copies `card-radius.test.ts`

Write `apps/board/unit/button-css.test.ts` the way `unit/card-radius.test.ts` (#1455) is written:

- Read the stylesheet with `readFileSync(new URL('../src/app/globals.css', import.meta.url))`.
- Walk it with `rulesOf` from `test/css-rules.ts`, which sees nested rules and `@media` blocks.
- Keep a named exception list with a reason for each entry.

The rule is:

- **Selectors in scope:** any selector naming `button` or a class ending in `btn`.
- **Properties checked:** `background*`, `border*` (including `border-color`), `padding*` (including `padding-inline`) and `font`/`font-size`.
- **What passes:** after you strip pseudo-classes and attribute selectors, the compound must be exactly `.btn`, `.btn.pri` or `.btn.sm`.

Two allowances follow from that:

- `.btn.pri[aria-busy='true']:disabled` belongs to the family. It is where `.pr-btn.primary[aria-busy='true']:disabled` (`globals.css:3591`) moves.
- `.sresolutionaction .btn` and `.smoves .btn` pass because after this change they set only layout (`width`, `max-width`, `white-space`, `overflow-wrap`, `text-align`).

The exception list starts with one entry, `.wiz-tabs button` and `.wiz-tabs button[aria-selected='true']` (`globals.css:3250-3251`), with the reason *"a segmented tab, `role="tab"`"*. Running today's file through this rule flags those two plus every rule the ticket deletes, so after the change the exception list should be the only thing standing between the test and green.
