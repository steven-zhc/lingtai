The ticket already decides how this change is built; this note adds only two things it leaves open.

**1. Don't copy `uninterruptible` from the nearest example.** The Effect code closest to this change is `append` in `packages/event-store/src/event-store.ts:422-434`. It wraps its transaction in `Effect.uninterruptible`: *"an interrupted caller waits for the commit or the rollback rather than leaving with the transaction undecided."* This ticket wants the opposite: an interruption while `fn` is suspended should roll back and give up the permit. That is what the "Done when" interruption test checks: the next `transact` on the same `:memory:` store commits. So don't make the use phase uninterruptible. Only the acquire step (permit, then `BEGIN`) and the release step should be uninterruptible, and `acquireUseRelease` already makes them so. In the release step:
- **SQLite:** run `ROLLBACK` before letting go of the permit, so a waiting `transact` never sees an open transaction. The comment at `sqlite.ts:425-432` says why that ordering matters: `BEGIN` inside an open transaction.
- **Postgres:** run `rollback`, then `client.release()`.

**2. How interruption reaches a suspended `fn` on SQLite.** The callback runs as a fiber of its own, forked inside `inside.run(…)` with `Effect.runForkWith(context)`, and the use phase joins it with `Effect.onInterrupt(() => Fiber.interrupt(fiber))`. `Fiber.interrupt` waits for the fiber to end, finalizers included, so the rollback and the permit come only after nothing of `fn` can still write. An `Effect.promise((signal) => …)` is not enough: the outer fiber does not wait for the promise to settle after the abort. `transactFace` wraps a promise reducer in `Effect.promise(() => …)` with no signal, so interrupting a face does not wait for the promise reducer either: it may still write through `ctx` after the rollback. Nobody interrupts a face today, and the runner ticket replaces that path.

The ALS check, permit ordering, error handling and the 16 faces need nothing beyond what the ticket says. `packages/event-store/src/store-face.ts` and `queries.ts:384` (`acquireUseRelease`) are the templates. For the faces' file layout, copy `store-face.ts`, not `event-store.ts`.
