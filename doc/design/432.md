# Design: #432, an absent recipe is created once, with `said`

## Where it goes

There are three places to change, plus the tests:

- **`packages/recipe/src/write.ts`**: `setRecipe` gets `options.said`.
- **`apps/cli/src/recipe-flow.ts`**: `askRecipe` collects changes when the file is absent. The `SAID` map lives here.
- **The two callers**: they stop writing their own seeds and hand them to `askRecipe`.
  - `first-project.ts:437-451`
  - `add-github.ts:239-252`

`askRecipe` currently says it is for *"a project whose recipe file already exists"* (`recipe-flow.ts:2-4`), and that each answer *"is written with `setRecipe` the moment it is given"* (`:10-12`). That stays true for an existing file. An absent file gets the second path described below. Rewrite the header so it states both paths.

## `setRecipe(project, changes, { home, files, said })`

`said` is used only when `existing === null`. Build the text exactly as today:

1. `widenStepsIfNeeded`, then `editedText(null, …)` (`write.ts:178-179`). This keeps the `ZodError → RecipeInvalidError` naming in `editedText` (`write.ts:81-95`).
2. Emit it again: `emitRecipe(Recipe.parse({ runtime: {}, ...parseYaml(text) }), said)`. `{ runtime: {} }` is how `editRecipe` checks it (`emit.ts:119`).
3. Run `resolveSource` on the emitted text, as `write.ts:181` does today, then call `files.replace`.

The `resolveSource` call is the unit-level guard that the emitted file round-trips. The test that proves `Recipe.parse(parse(emitRecipe(r))) == r` is `packages/recipe/integration/emit.test.ts:413-416`, and it runs only after the merge.

When the file exists, ignore `said` entirely. 0104 §14 governs from then on: *"a key or an item that a change removes or replaces goes with its comments"*. Add nothing that protects a comment.

## `askRecipe`: two paths, chosen by one read

At the top, read `recipePath(at.project, at.home)` through `at.files ?? diskFiles`. Add `seeds: readonly RecipeChange[]` to `RecipeAt`.

- **The file exists.** Write `seeds` first, as their own `setRecipe` call. Then run today's flow unchanged.
- **The file is absent.**
  1. Run `askAgents`, `askInstallAndBuild`, `askTickets` and `askKinds`. Collect their changes after `seeds`, in that order.
  2. Make one `setRecipe(project, collected, { …, said: SAID })` call.
  3. Then run `askLanding` and `askLimits` as today. They need a file that resolves (`landing.ts:141`, `resolvedFile`).

### Details of the absent path

- **`modelChanges` is always empty on an absent file.** `askAgents` creates the action outright, with `model` inline, when no action exists (`agents.ts:305-307`, `:318-320`). So concatenating `changes` and `modelChanges` is safe here. The two-call split in `agents.ts:11-17` only matters when an action already exists.
- **`source.tickets` must be written explicitly on create.**
  - It is `TicketSource.optional()` with no default (`recipe.ts:1108`). So `Recipe.parse` does not fill it.
  - `askTickets` returns `{ changes: [] }` when the answer equals `current`, and on an absent file `current` is `'github'` (`source.ts:93`, `:139`).
  - So a GitHub project that presses Enter has no `source.tickets` key, and `emitRecipe` throws *"said names "source.tickets", which the recipe does not have"* (`emit.ts:83`). This is the ticket's Watch out, reached through an optional field rather than a missing default.
  - The fix: on the absent path, if no collected change touches `['source','tickets']`, append `{ path: ['source','tickets'], value: 'github' }`.
  - This is safe. The schema comment's objection (`recipe.ts:1082-1090`) is that a schema default would change every existing project's `configHash`. A new file has no earlier hash, and `ticketSourceOf` reads an absent key as `github` anyway.
- **`source.kinds` is no longer a seed.** On an absent file `askKinds` has `currentKinds === null`. It falls back to `SETUP_KINDS` and always returns a change (`source.ts:186-192`, `:203-206`). Drop `source.kinds` from the local seeds at `first-project.ts:444`. Keep `env.plantAt`, which has no question.
- **`kept` splits in two.**
  - A refusal before the creation write leaves nothing on disk. On that path it must say *Nothing was written*, or the caller's own pre-write `kept`. That is `question.ts:43-49`: *"Defaults to "Nothing was written", which is only accurate for the first question a caller asks"*.
  - After the write it says what the write left: `seededKept` (`first-project.ts:458`) or `ADD_KEPT`.
  - Add `keptBeforeWrite` to `RecipeAt`. Use it for the absent path's first four questions. `kept` stays as the clause used after a write.

## `SAID`, and the headings

`SAID` is one `Record<string, string>` in `recipe-flow.ts`, with these keys:

`runtime`, `steps.implement`, `steps.review`, `steps.prepared`, `steps.build`, `source.tickets`, `source.kinds`, `repo`, `env`, `steps.proposed`, `runtime.limits`

Each of those exists after `Recipe.parse`:

- All ten steps: `StepMap.default`, `recipe.ts:3060-3071`.
- `runtime.limits`: `.default({...})`, `recipe.ts:3231`.
- `repo` and `env`: the seeds.
- `runtime`: `askAgents` always writes `runtime.agent` (`agents.ts:296`).
- `source.tickets`: the explicit write above.

`askRecipe` prints each section's sentences with `world.log` before calling that section, on both paths, so the words on screen and in the file are the same constant:

| Sentences | Printed before |
|---|---|
| `runtime`, `steps.implement`, `steps.review` | `askAgents` |
| `steps.prepared`, `steps.build` | `askInstallAndBuild` |
| `source.tickets` | `askTickets` |
| `source.kinds` | `askKinds` |
| `repo`, `steps.proposed` | `askLanding` |
| `runtime.limits` | `askLimits` |
| `env` | the creation write; there is no question for it |

## The callers

**Local (`first-project.ts`).** Delete the `setRecipe` at `:449`, and pass its changes as `seeds`:

- `repo.base` and `repo.remote` always.
- `env.plantAt: '.env.local'` only when `existingText === null`, as today.

Pass `keptBeforeWrite: world.kept`. The re-read at `:478` and `register` below it stay as they are.

**GitHub (`add-github.ts`).** Delete the absent-file branch at `:247-252`, including the `--agent needs a recipe` refusal. When `existing === null`:

- **The seed base** is `base ?? await defaultBranch()`, the memoized one at `:275`. If it is null, refuse before any question:
  > *`<path>` does not exist and there is no base branch to write into it: pass --base <branch>. Nothing was written*

  Return 1.
- **The seeds** are `repo.base` and `env.plantAt: '.env.local'`.
  - The ticket lists only `repo.base`, but `env` is a required `z.strictObject` and `plantAt: z.string()` has no default (`recipe.ts:2991`, `:3054`). Without it, the one write is refused as `RecipeInvalidError` on every new GitHub file.
  - Put `'.env.local'` in one exported constant that both callers use.
- **The `extends` notice** (`:256-266`) applies only to an existing file. Leave it under that branch.

Two deps must move into `AskBeforeGithubAddDeps` before a unit test can reach `askRecipe` on this path:

- **`runtimes`** (today `askRuntimes()` is called directly, `:270`).
- **`history`** (today `liveHistory` opens the event store, `source.ts:216`).

`doc/design/400.md` already asks for `runtimes` to be threaded through. With no App configured, `defaultBranchOf` returns null without a request: `githubApp()` throws inside its `try` (`add-github.ts:49-57`). So the "no `--base`, no default branch" test needs no new seam, only the refusal placed before `deps.runtimes()`.

## Tests

`apps/cli/unit/recipe-flow.test.ts` (new) drives `askRecipe` directly. It uses an in-memory `RecipeFiles` that counts `replace` calls, and a `QuestionWorld` that answers `''` to everything.

- **Local, absent.** Pass the three local seeds.
  - Assert exactly one `replace`.
  - Assert the file resolves, and carries `runtime.agent`, both steps, `source.tickets: db`, `source.kinds` and `repo.base`.
  - Assert each `SAID[k]` appears as the comment above `k`. Reuse the assertion shape in `integration/emit.test.ts:418-433`.
  - With every answer at its default, `askLanding` and `askLimits` must write nothing. A second `replace` here is a bug in "unchanged answers write nothing" (400.md), not a reason to loosen the count.
- **Existing.** Pre-write a file carrying one hand-written comment, and answer one question differently.
  - Assert the hand comment survives.
  - Assert no `SAID` sentence was inserted.
  - Assert the number of `replace` calls equals the number of changed answers.

`apps/cli/unit/add-github.test.ts`:

- **Replace the test at `:233`.** With no App configured, `{ base: 'main' }` and injected `runtimes`/`history`, an absent file is written once, carries `source.tickets: github`, and the `SAID` comments are present.
- **Add the refusal test.** No `--base` and no App gives exit 1, *pass --base* in the error, zero writes, and zero asks.

Scripted answer orders in `unit/first-project.test.ts` shift. Its absent-file tests now see one write where they saw several.
