## Decisions

**1. An `info` row counts like `ok` everywhere a section is ranked.** `tier()` at `:2999-3000` puts a section first if it has a `fail`, next if it has a `warn`, and otherwise with the green ones. Leave it as it is, so a section whose only non-`ok` row is `info` stays tier 2. Do the same for the short view's section glyph at `:3017-3021`. The Runtimes section on the operator's machine then draws as `✓ Runtimes`, not `!`. If it showed `!`, the summary would still say "needs attention", just without the count.

**2. In the short view, the `note` lines get their own block. They are not part of any section.**
- `shown` at `:3022` keeps `['fail', 'warn']` as it is, so `info` rows stay out of their section.
- After the section loop and before the `next:` push at `:3031`, push one blank line. Then, for each `info` row in `report.results` order, push `` `note  ${r.detail.split('\n')[0]}` ``. The check's name is not printed.
- Draw no blank line and no block when there are no `info` rows.
- Leave the `next:` condition alone (`report.warned + report.failed > 0`). That covers the ticket's *only `info` rows* edge.
- `formatReport` (`:3056`, used by `init`) draws the notes too. That is intended: they are part of the short view.

**3. The short view's counts line does not get an `info` count.** The `#214` comment at `:3008` ("hides no count at zero") is about counts that would otherwise go unseen. Every `info` row is already drawn as its own `note` line, so the count would repeat what is on screen. The layout of that row also belongs to #717. `--json` and the verbose summary do carry the number.

**4. In `--verbose`, `warn` rows stop being called "to note".** Today the verbose summary says `, ${report.warned} to note` (`:3042`). Next to a `note` marker that now means `info`, that wording would describe the wrong rows. Make the verbose summary say:
- `, N need attention` for `warned`, the same words as the short view (`:3011`);
- `, N noted` for `info`.

Both are shown only when greater than zero, as `notes` is today. Update the strings pinned at `apps/cli/unit/doctor-render.test.ts:175` and `:178`. `apps/cli/unit/init.test.ts:166` is a stub string passed to a fake `doctor` and does not need to change.

**5. `marker('info')` is `slot('note', 'note')`.** `note` is exactly four cells wide, so it fills the slot with no padding. Draw it plain:
- Not muted, because muted means `skip`, a check that did not run (`:2958`).
- Not amber or bold, following the comment at `:2952`: "amber is a person being waited on, and nothing else (0121 §2)".

`switch (status)` has no `default`, so the compiler will enforce this case. It will not enforce `STATUS_ORDER`, as the ticket says. Make it `['fail', 'warn', 'info', 'ok', 'skip']`.

**6. The new settings detail has two lines, and only the first is ever drawn on its own.**
- Line 1: `` `~/.claude/settings.json also applies to every run (${carries.join(', ')})` ``.
- Line 2: the existing explanation at `:783-785`, starting at "Lingtai cannot set HOME …".

The short view draws only line 1. `--verbose` and `--json` keep the reason. Leave the `ok` branch (`:776`) and the `warn` branch for a file that does not parse (`:765`) as they are.

**7. The count field is `info`, in both `DoctorReport` and `tally`.** That is the key name the ticket gives for `--json`.
- Add `info: number` to `DoctorReport` (`:989-1013`) with a one-line docstring pointing at `CheckStatus`.
- Extend the `CheckStatus` docstring at `:131-138` with what `info` means and how it differs from `warn`. `warn` says *you should know anyway*. `info` says *it is true and there is nothing to do*.
- In `doctorJson`, put `info` next to `warned`. Do not change `JSON_VERSION`.

## What does not move

`releaseCheck` (`apps/cli/src/install.ts:718`) declares its own union, `'ok' | 'warn' | 'skip'`, and is out of scope.
