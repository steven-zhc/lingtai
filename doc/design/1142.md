## Design note: #1142, ADR 0101 §6–§7 as the code stands

Only `doc/decisions/0101-typescript-packages-effect-unbuilt.md` changes, lines 102–163. The ticket's grep commands are the right ones. Four things they turn up go against the ticket's own wording. The code wins each time. The ticket says *"every sentence about the code carries a file you grepped"*, so a claim the grep contradicts does not go in.

### 1. Which packages: the eleven the test pins, and `telegram` moves to §7

§6's list today names `telegram` (`:107`). Leave it out. The ratchet's `PACKAGES` (`packages/domain/unit/effect-ratchet.test.ts:37-49`) lists eleven packages, and these are the ones §6 should name: `apps/cli`, `event-store`, `projector`, `github`, `repo`, `agent`, `actions`, `conductor`, `daemon`, `setup`, `recipe`. All eleven read `{ "async": 0, "run": 0 }` in `effect-ratchet.baseline.json`. The test calls that list *"0101 §6's list. Pinned here"* (`:32`), so the prose and `PACKAGES` must name the same set.

`telegram` does IO but stays plain on purpose. The test's comment at `:33-35` gives the reason: it is *"deliberately free of `effect` (`packages/telegram/src/cli.ts:12-17` …), so converting it would break both."* Two things in `apps/cli` sit outside the count:

- `apps/cli/src/notify.ts` is an extension that runs as its own process and imports only `node:` and `packages/extension` (`NOT_COUNTED`, `:77-84`).
- `apps/cli/src/prompt.ts` is the `@clack/prompts` wrapper (`:71-76`).

Put all three into §7 ("what stays plain"), each with its file. Write the reason as a present-tense rule: *a notifier a third party could write imports nothing but `node:` and `extension`*. Do not write *"decided when #790 ended (#1116)"*: that is history, and #790 must not appear anywhere.

### 2. The edges: one program run, not one per command

The ticket lists "the daemon's entry, each CLI command's entry". The code has a single CLI run, `apps/cli/src/entry.ts:28`, commented *"The program's one run (0101 §6)"*. That is the only entry in `HOST_EDGES` (`effect-ratchet.test.ts:88-90`). The daemon is a command under that same run, and `packages/daemon/src` contains no root run other than its listed faces.

So §6 names these edges:

- **The CLI:** `entry.ts`'s one `runPromise`, which covers every command including `daemon`. Keep the `runMain` reason from `entry.ts:26-27` if you want a *why*: the first Ctrl+C is a drain.
- **The board:** Server Components, server actions and route handlers, e.g. `apps/board/src/app/actions.ts:541`, `apps/board/src/lib/board.ts:979`, `apps/board/src/app/setup/repository/read/actions.ts:32`.
- **A test.**

`rg -n "Effect\.run" apps/site apps/release` finds nothing, so the site is not an edge. Do not name it. The ratchet scans only `src/`, so `apps/cli/scripts/rung-1.ts` is not counted. Leave it out, or call it a script edge if you mention it at all.

### 3. `*With` runs get a sentence of their own

There are many `Effect.runPromiseWith(services)` calls inside counted packages: `packages/daemon/src/work-loop.ts:444,485,564`, `packages/conductor/src/run-attempt.ts:1080`, `packages/conductor/src/conduct.ts:3669`, `apps/cli/src/conduct.ts:416` and others. A reader who sees only "runs only at the edge" would read these as violations.

The rule is in the test at `:102-111`. A `*With` run carries the caller's context, including its tracer, and is not counted. A `*With` over `Context.empty()` or `Context.make(…)` *is* counted, because it is a root run under another name.

§6 already mentions `schedule.ts`. Widen that sentence so it is the rule, not one example: a fiber started inside backend code is a `*With` run over `yield* Effect.context()`, never a bare run. Cite `run-attempt.ts:1074`'s *"Never `Effect.runPromise`: that would drop the pass's span"*.

### 4. Faces: the shape, the file, and who reads them

`effect-ratchet.faces.json` has 90 entries, and every one has `until: "0101 §7"`. None names an issue, so the ticket's "one exception" edge does not arise. Do not invent one.

Two places define a face, and the ADR should match both:

- The test's definition (`:10-15`): an exported function whose whole body is `return Effect.runPromise(<call>)`, or the generic `return Effect.runPromise(<param>, { signal })`. Only `runPromise` qualifies. A face that inspects an `Exit` or uses `runSync` is counted.
- The ticket's version: one implementation, kept for a host, listed in the JSON with its `why`.

The `why` fields show the readers are the board and the board's own tests. For example, `approveHolding`'s `why` cites `apps/board/unit/schedule-continuation-stale.test.ts`, and every `projector/src/store-face.ts` entry cites `apps/board/unit/waiting-card.test.tsx`. So write "a host or the host's tests", not "the board" alone.

Put the face rule in §7's board paragraph (`:154-158`). That paragraph already has the promise-face sentence, and the JSON's `until` points at §7. Keep the label "§7" stable, because 90 entries cite it. Do not renumber or move the faces sentence into §6.

### 5. `@clack/prompts` and `ora`: one sentence

`prompt.ts` is excluded as a wrapper (`NOT_COUNTED`, `:72-75`, *"kept promise-shaped by the operator"*). Its callers reach it through `Effect.tryPromise`. `apps/cli/src/question.ts:66` shows the pattern: `try: () => spin(label, () => Effect.runPromiseWith(ctx)(effect))`.

`ora` is imported at `apps/cli/src/steps.ts:14`. Before writing "called through `Effect.tryPromise` at the call site" for `ora`, confirm it is true of `steps.ts`. If `ora` is only driven synchronously from inside an Effect, say that instead. Do not repeat the ticket's phrasing unchecked.
