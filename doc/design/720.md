## Where it goes

**`badge` is a separate export in `colour.ts`, beside `paint` and not a key on it.** `packages/env/unit/colour.test.ts:97` checks that every `paint` value is the identity when colour is off: `for (const ink of Object.values(paint)) expect(ink('hello')).toBe('hello')`. A badge returns `[word]` in plain mode, so putting it on `paint` breaks that test. `:117` would also start comparing badges against inks. Write it as a function that calls `coloured()` (`colour.ts:57`) and returns either the escaped ` WORD ` or `[word]`. It cannot be built on `ink` (`:67-72`), because `ink` returns the text unchanged when colour is off.

**`badge` gets a fourth kind, `muted` (`2`), for `NOTE` and `NEXT`.** This is my decision; the ticket's Fix row names only three kinds. A fourth kind keeps the `[word]` fallback in one place, so `doctor.ts` never builds the brackets itself. ADR 0121 §2 says `NOTE` and `NEXT` are "padded like the others, no background, `muted`", so `muted` is an existing hue and no new hue is added. The other three use the ticket's codes: `fail` → `41;97`, `warn` → `7`, `fix` → `46;30`. Nothing maps to `33`. Add a `colour.test.ts` case that pins all four codes and the plain fallback.

## The label column in `renderDoctor`

- **Pad using the plain word's width, never the rendered string's.** `' PROBLEM '` and `'[problem]'` are both 9 columns wide, `' FIX '` and `'[fix]'` are 5, and `NOTE` and `NEXT` are 6. The left pad is `9 - (word.length + 2)` spaces, put before the badge. Calling `padStart` on the badge's output counts the escape bytes and misaligns the column in colour mode only. The plain-mode equality test cannot catch that, so the colour-on test should also check that the `FIX` line, with escapes stripped, starts at the same column as in plain mode.
- **Keep `fixLines` (`doctor.ts:3135`) as it is, because `--verbose` calls it at `:3112` with `fix  ` and an indent of 6.** The default view gets its own lines: the `FIX` label then the first command, and every later line indented 10. Every one of those lines is wrapped in `paint.accent`, prose continuations included. Don't add a parameter to `fixLines`. `--verbose` is out of scope, and a shared helper is how that layout would change by accident.
- **The detail line is `' '.repeat(10)` followed by the first line of `t.detail`**, as `:3083` does today. It stays uncoloured.
- **The title is `badge(fail|warn, 'problem')`, a space, then on a `fail` `symbol.fail()` and a space** (`output.ts:64`, bold red). Then come the title and the muted area tag. Keep two spaces before `·` (`:3082`), because the ticket's exact layout has two. ADR 0121 §1's inline example (`[problem] ✗ environment · store and log`) has one, but the unit test asserts the ticket's layout.
- **Counts line (`:3074-3078`)**: in the `todo.length > 0` branch, `${report.ok} passed` becomes `paint.pass(...)`. Leave everything else on that line alone.
- **`NOTE` and `NEXT`** replace `note  ` at `:3086` and `next: ` at `:3087`. Leave the gating as it is: `next` decides whether `NEXT` is drawn at all, which keeps `formatReport` (`:3179`) without a `NEXT` line for free, and `report.warned + report.failed > 0` still decides when.
- `heading('doctor')` and the counts line stay flush left. The column starts at the first block (0121 §1).
