# Design: #711, connecting GitHub through `gh` first in the docs

## The constraint that shapes everything: the tutorial is out of words

`apps/site/unit/docs.test.ts:124-130` caps `doc/tutorial.md` at **under 2000 words in total**. The file is at 1990 now (`wc -w`). The same test caps Part 2's prose (from `## Part 2` to the end, fences removed, tables counted) at **under 600**, and it is at about 536. So adding the `gh` path beside today's App walkthrough turns `pnpm test` red.

**Decision: in the tutorial, the `gh` path replaces the App walkthrough.** It does not sit beside it. Part 2 becomes the `gh` path, plus a short closing paragraph: *for a team, use a GitHub App*, linking to [doc/github.md](doc/github.md) and to `doc/operating.md#connecting-github`. The App walkthrough moves out of the tutorial, and so does its manifest-permissions table (`tutorial.md:257-264`). `operating.md` already carries a full App walkthrough (`:278-352`). The board's one-click path is in `operating.md:252`.

Other things the same tests hold:
- The level-2 headings must stay exactly as they are (`docs.test.ts:131-144`). Keep `## Part 2 — Move the project to GitHub` word for word. Use `###` for anything inside Part 2.
- `apps/site/unit/tutorial-tabs.test.tsx:35` expects **exactly two** `shell-tabs` groups (the POSIX/Fish pairs) in the whole tutorial. Part 2's commands go in plain `sh` fences, as they are today, not in a new POSIX/Fish pair. If something has to differ for Fish, say so in one sentence.

## The command is not bare `gh auth login`

A default `gh auth login` gives `repo`, `read:org` and `gist`, with no `workflow`. Both `lingtai add` and `init` refuse that login: `ghScopeGap` (`packages/github/src/gh.ts:146`) requires `['repo', 'workflow']`, and `checkGhAccess` refuses on the gap before it reads the repository (`packages/conductor/src/onboard.ts:362-366`). The command Lingtai itself prints is:

```
gh auth login --hostname github.com --scopes repo,workflow
```

(`apps/cli/src/github-auth.ts:89`, `const LOGIN`). Every place in the docs that shows a sign-in uses that exact string. For somebody who is already signed in, add one clause with the remedy Lingtai prints (`gh.ts:149-150`): `gh auth refresh --hostname github.com --scopes workflow`.

## Tutorial Part 2: the sequence, checked against the merged code

```sh
gh auth login --hostname github.com --scopes repo,workflow
export LINGTAI_HOME="$HOME/.lingtai-github-tutorial"
lingtai init --store sqlite --project github --github-auth gh
lingtai add <you>/chapter-garden --base main   # plus Step 1's recipe flags, as today
lingtai doctor
```

- **`init` with `--github-auth gh` and no repository registers nothing.** It writes `github.auth: gh`, then returns `{ ok, project: 'github', app: 'already', auth: 'gh' }` at `apps/cli/src/first-project.ts:625`. That is why the `add` that follows is still needed. Do not pass `--github-app`: alongside `gh`, anything other than `skip` is refused (`first-project.ts:197-201`).
- **`init` signs `gh` in itself when the login is missing or short a scope.** That is #712's embedded sign-in (`github-auth.ts:166-180`). Mention it in one clause at most. The explicit `gh auth login` line stays first, because it is what the ticket's Want asks for.
- **`add` prints nothing from the check when it passes** (`onboard.ts:341-343`: *"logs nothing on success"*). So the tutorial's "the second `add` proves the installation by printing `permissions: …`" is App-only and goes. On this path the proof is `lingtai doctor`'s row **`github: gh login`** with `gh is signed in to github.com as <login> with repo and workflow` (`apps/cli/src/doctor.ts:854`). `github: app credentials` reads **`skip`** under `gh` (`doctor.ts:858-862`). Say that this is expected, as the current text already says of `skip` (`tutorial.md:288`).
- **Which repository.** "Installing an App needs admin" becomes the push requirement. `add` refuses a repository you cannot push to with `you (<login>) cannot push to <slug>` (`onboard.ts:399`). A fork of your own satisfies that.
- **Base protection.** The sentence "must accept direct pushes from the App" becomes "from your account".
- **Keep the board instruction.** Keep "stop Step 3's board first" and the fresh `LINGTAI_HOME`: Part 2 is still a second start. The App-specific reason ("create the App in the old home") goes away with the App walkthrough.
- **The identity sentence** comes from 0114 §8, the fourth bullet (`doc/decisions/0114-a-github-app-not-a-token.md:176-185`): labels, comments, pull requests and pushes appear as the signed-in account, and commits are authored by the machine's git identity (`user.name`/`user.email`), which Lingtai does not set. The interactive prompt says the first half in its own words (`github-auth.ts:160-161`). Use the ADR's sentence, not a paraphrase of a paraphrase.

Keep the tail as it is: tickets are issues with a kind label, and you look on GitHub instead of running `git pull`.

## README (both languages)

- **Quickstart.** The ticket's "Quickstart's GitHub variant" does not exist: Quickstart is local-only (`README.md:24-101`). Add one short paragraph at the end of Quickstart, before `## What an agent can reach`: the `gh auth login --scopes repo,workflow` line, `lingtai init --project github --github-auth gh` and `lingtai add <owner>/<repo>`, the identity sentence, and *a team uses a GitHub App instead*, linking to `doc/github.md`. Do not add a new `##` heading. The ticket says the headings are Install, Quickstart, What an agent can reach, Next. Make the Chinese README's paragraph a translation, with the commands byte-identical.
- **What an agent can reach.** Add one sentence to the Claude Code bullet under **Not contained** (`README.md:123`; the Chinese README's `:90`). Under `gh`, the person's `gh` login is on the machine, and an agent without a sandbox can run `gh` as that person. The source is 0114 §8's last bullet (`0114:188-191`): *"The person's `gh` login is on the machine already … keeping an agent from using it is the runtime's own sandbox."* Do not say Lingtai hands the agent a token. It does not (§8, the second bullet: the token *"is never written to … an agent's environment"*).

## `doc/github.md`

- **`## One App, and it is not a person`** (`:6`). This opening now has two ways. Rename and reword it: `gh` for one person, the App for a team. Keep the App rationale that follows; it is still true for the App.
- **Permissions table** (`:30-36`). The four rows become the five in 0114 §3 (Issues, Contents, Pull requests, **Workflows**, Metadata), with the same names and levels as the ADR table. That table is what `manifest.test.ts` reads, so this one cannot drift silently from it, but it should match anyway. The `Webhooks | issues, push` row is not a permission, and keeping it would make six rows. Move it into a sentence under the table, and note that under `gh` there is no webhook and the sweep finds work (0114 §8, the "No webhook" bullet).
- **`## The agent is given nothing`** (`:175`). Add the same sentence as the README. The section's claim, *"the agent has no credential"*, stays true of what Lingtai gives it. The new sentence covers what is on the machine anyway.
- Read `## Identity separation is half-built` (`:222`) and `## What this cannot do yet` (`:241`). Edit them only where they say the App is the only way.

## `doc/operating.md`

Change only `## Connecting GitHub`'s opening (`:242-250`). It says *"Lingtai talks to GitHub as a GitHub App, not as a personal access token."* Lead with the choice `init` asks (`gh` or `app`), give the two-line `gh` path, then say *for a team, the App*, followed by the existing App steps unchanged. The 403 story is about a PAT, not `gh`. Keep it as the App's rationale. Do not touch other App mentions (`:43` and so on); the ticket limits this file to setup.

## The 0114 ADR's stale line

`0114:214-216`, *"Not built yet — `github.auth`, `--github-auth`, the `gh` token source … today only the App exists"*, is false since #703, #710 and #712. It contradicts every page this ticket edits. Delete the bullet and its heading, and do the same in the Chinese ADR (`doc/decisions/zh/0114-…md:76`, `## 尚未实现`), if that section holds nothing else. ADRs in `doc/decisions/` are edited in place (CLAUDE.md: *"A decision that changes is an edit to its topic's ADR"*), so this is an edit, not a superseding file.

## Edges

- **A command that does not run as written.** Everything above is cited from code merged at HEAD, which includes #709 (`f7934f64`), #710 (`39ac9d6e`, `2cd53bec`) and #712/#703 (`15c0934d`). Do not invent a success line. Where the code prints nothing, the doc says to run `doctor`.
- **An organisation that blocks the GitHub CLI's OAuth app.** `add` refuses and names `--github-auth app` (`onboard.ts:373-377`). One clause in `doc/github.md` covers it. The tutorial uses a personal fork and does not need it.
- **Cost to later tickets.** The tutorial's caps leave little room: about 10 words in total. Leave room if you can, because the next doc ticket inherits whatever is left.
