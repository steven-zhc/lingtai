The mark is a third consumer of what #1163 built. It has no new read: it reuses the register every page already loads, and the `.sbx-*` look the bar's icon already has. Two things are not obvious from the ticket. In two of its three places the mark sits inside a link, so it cannot be a link itself. And the new prop has to be optional, or `projects.test.tsx` cannot stay green unchanged.

## The data: one map, built from a read the page already makes

- **Add a pure `sandboxStates(projects: readonly ProjectState[]): ReadonlyMap<string, SandboxState>`** to `apps/board/src/lib/sandbox-state.ts`. It is the loop that `readSandboxMark` runs today (`lib/sandbox-read.ts:15-19`): skip `project === null`, then `sandboxState(sandboxFactsOf(p))`. Then rewrite `readSandboxMark` as `worstOf(sandboxStates(...))` with the project filter applied, so the icon and the marks cannot drift apart.
  - Keep it in `sandbox-state.ts`, which "imports no store, so `Bar`, the filter and the cards (#1166, #1167) can all import it" (`sandbox-state.ts:7-8`).
  - It must not go in `sandbox-read.ts`, which imports `locks.ts`.
- **Home page.** `startReads` already holds `registered = readRegistered().catch(() => [])` (`app/page.tsx:649`). `readRegistered` is `cache(() => loadProjects())` (`lib/locks.ts:42`, "read once however many places of one render ask"), and `loadProjects` returns `ProjectState[]` (`packages/project/src/state.ts:138`).
  - Build the map once in `lockShape` (`page.tsx:699`), which `readMenu` (`:728`) and `CardsPart` (`:875`) both already call with `registered`, and return it as `sandbox`.
  - This is the "one read per render": no `readSandboxMark` per card and no `Suspense` per mark.
  - A failed register read is already `[]`, which gives an empty map and so no mark. That is the ticket's *A read that fails* row. Do not add a catch of your own.
- **Recipe page.** `RecipeBar` → `Projects` → `ProjectRows` (`recipe/[project]/recipe-bar.tsx:34`) is the filter menu too. The page already holds `projects = await readRegistered()` (`recipe/[project]/page.tsx:365`) and builds `bar` at `:379`. Add `sandbox: sandboxStates(projects)` there, and a `sandbox` field to `RecipeBarFilter` (`recipe-bar.tsx:16`).
- **Optional everywhere, defaulting to no mark.** `Projects`/`ProjectRows` take `sandbox?: ReadonlyMap<string, SandboxState>`. `Card` and `LandedRow` take `sandbox?: SandboxState`: the one project's state, looked up by the caller the way `projectLocks.get(card.project) ?? []` already is (`page.tsx:893`, `:954`).
  - The "one read" rule makes the map the obvious prop shape. The reason it must be *optional* is that `projects.test.tsx:22,27` render `<Projects … locks={…}>` with no sandbox prop and must stay green unchanged.
  - `close.test.tsx`, `rail.test.tsx`, `waiting-card.test.tsx` and `dev/waiting/[name]/[surface]/page.tsx:16` render `Card`/`LandedRow` the same way.
  - Thread the state through `Landed` (`page.tsx:563`) to `LandedRow`, and through the `list` closure (`page.tsx:883`), so Queued cards get it as well.

## The component: a span, never a link

- **Put it in a new `apps/board/src/app/sandbox-mark.tsx`** and name it something like `ProjectSandboxMark`. Do not call it `SandboxMark`: that name is already the worst-of *type* (`sandbox-state.ts:74`).
  - It renders `<span className="sbx sbx-<state> sbx-row" role="img" aria-label={sentence} title={sentence}>`, with the glyph inside in `.sbx-mark`.
  - It imports only `sandbox-state.ts`, never `sandbox-read.ts` or anything that reaches a store. `projects.tsx` is imported by the unit half.
- **It is not interactive.** In the filter, the row is itself a `<Link className="tab prj">` (`projects.tsx:89-98`), and a link inside it would be a nested `<a>`. That is why the bar's `SandboxIcon` (`bar.tsx`, the `Link`/`details` branches) cannot be reused here.
  - No `tabIndex`: one tab stop per card or row is the existing rhythm.
- **Reuse the glyphs and colours, don't fork them.** Export `GLYPH` from `bar.tsx` and import it. If that drags a client import into the wrong place, move it beside `SENTENCES` in `sandbox-state.ts` and have `bar.tsx` import it from there.
  - The colours are already `.sbx-sandboxed/-degraded/-stopped/-off/-unknown/-unreadable .sbx-mark` (`globals.css`, the block headed "*off is grey and dashed, never an alarm*"). `--warn` is degraded's own, because "*--signal is the headline's alone (bar.test.ts)*".
  - Add only an `.sbx-row` rule. It overrides `.sbx`'s `cursor: pointer` (wrong on a non-link), shrinks the mark to about 12px, and adds a small horizontal margin.
  - Give *off* no extra emphasis: it is the same weight as `.pause-tag` (`globals.css:291`), grey and dashed.

- **`Card`**: two places, because the waiting card returns early (`page.tsx:217-261`).
  - In both `.id` lines, put the mark right after `{showProject ? <span className="proj">…}` and before `IssueRef`.
  - Draw it whether or not `showProject` is set. The ticket says *each card*, and with one project the mark is the only per-card cue.
  - `KindDot` stays first on the line (`page.tsx:281`, "*so the dots line up down a column*").
- **`LandedRow`**: after `.lseq` and `.proj`, before `IssueRef` (`page.tsx:545-547`), and outside the `lmeta` `Link`.
- **Not `/landed`.** Its rows render `landed/view.tsx`'s own `Card`. The ticket's targets are `page.tsx:190` and `:498`, so leave `view.tsx` alone; `landed/page.tsx` already has the bar's icon.

## Edges the ticket left implicit, decided here

- **`unreadable` and `unknown` are drawn**, with `?` and their sentences. They are states of one project (`sandbox-state.ts:58-59`), not a failed read. A failed *read* is the empty map, and draws nothing.
- **A card whose project is no longer registered** (`page.tsx:675`, "*a card can outlive its project*") has no entry in the map, so it gets no mark. It is never *sandboxed*.
- **Loading and staleness**: the marks arrive in the same streamed parts (`MenuRows`/`FilterSlot`/`CardsPart`) as their rows, and add no fallback of their own.
