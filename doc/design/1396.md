# #1396: where the draft passages actually are

## The ticket's map is out of date, and this is the decision that matters

The ticket lists five documents with line numbers. Three of those references no longer point at what they describe. Go by what the passage says, not by the line number.

- **`doc/concepts.md` has no "A PR's life" section.** The file is 57 lines long, and `grep -n "Draft\|draft" doc/concepts.md` finds nothing. Leave it alone. The PR walkthrough now lives in `doc/team.md`; `doc/upgrading-to-0.16.md:161` links to it as `[A PR's life](team.md)`.
- **`doc/team.md` already says the model.** It is the voice to copy, and it needs no edit:
  - `:45-46`: "The draft is the project's next PR, not yet submitted. It holds the tickets landed on `lingtai-base` since the last PR was frozen."
  - `:57-58`: "With nothing landed, or with a PR already open, it refuses and says why. A refused submit returns the PR to the draft."
- **`doc/connect-github.md:77-86` says the same** in its own chapter ("The draft is the project's next PR, not yet submitted… A submit with nothing landed is refused, and a refused submit returns the PR to the draft."). Leave it too.
- **`doc/upgrading-to-0.16.md:158-163` only links and says nothing about the draft.** It falls under "where a passage says only something these do not change, it is left alone."

So three places actually change: the glossary, the command text that generates the CLI pages, and one bullet in `github.md`. The "five documents" in Done-when means: of the five the ticket names, the ones that still describe the draft wrongly are fixed, and the others are confirmed already right. Say that in the commit body so a reviewer does not count files.

## 1. `apps/cli/src/commands.ts:144-174`, then `pnpm docs:cli`

**`doc/cli.md` is generated too, not just `doc/cli.json`.**
- `scripts/cli-doc.ts:1-4` says: "Writes `doc/cli.json` and `doc/cli.md` from the command definitions and the parser (#545)… Run: `pnpm docs:cli`."
- `doc/cli.md:5` says "Do not edit — run `pnpm docs:cli`."
- `apps/cli/unit/cli-doc.test.ts:24-29` fails `pnpm test` when either committed file differs from what the script would write.

The ticket's "`doc/cli.md:153-180`" is therefore an edit to `commands.ts`, followed by regeneration. Hand-edit neither generated file.

Edit the `usage` lines of the `pr` command. Keep the two-space indent and the roughly 72-column width of the lines around them.

- **`:151-152`**: replace "The tickets landed on branch.personal that no PR holds" with the draft as the next PR, not yet submitted, holding the tickets landed since the last PR was frozen. Keep "and the open PR: its number, its state…".
- **`:155-157`** (`pr submit`): add, in one or two lines:
  - it is refused when nothing has landed, and records nothing;
  - tickets the frozen commit does not hold stay in the draft for the next PR;
  - a submit the conductor cannot carry out returns the PR to the draft, keeping its number, and says why.

  Keep "Refused while another PR is open, saying which". It is still true (ADR 0131 §10, "*Submit* is refused, saying which PR is open, until that one is merged or closed").
- **`:165-166`** (`pr back`): "The tickets stay on the personal branch" becomes "its tickets join the draft". That is statement 5. The code stays on the branch, which ADR 0131 §10 also says ("The code stays on `branch.personal`; nothing is reverted").

There are two traps in this file:

- **`cli-doc.test.ts:54-65` fails on any `--flag` in usage prose that the parser does not take.** Write `lingtai pr back` in prose; do not introduce a flag name.
- **`apps/cli/src/cli.ts:453`** (`'take the PR back to Draft: close the draft pull request'`) is the parser's subcommand description. `grep -c "close the draft pull request" doc/cli.json` returns 0, so it does not feed the generated pages, and the ticket's ".ts out of scope" rule covers it. Leave it.

`task` at `:147` ("what a team project's draft holds, and where its open PR is") is already right.
