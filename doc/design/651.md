## Design: #651 — the events.json staleness test compares only event-level facts

### Where it goes

Two files change: `packages/domain/scripts/events.ts` and `packages/domain/unit/events-json.test.ts`. After those, `doc/events.json` is regenerated. Nothing outside `packages/domain` reads `ELSEWHERE` or `EventsDoc`.

### 1. `ELSEWHERE` rows: `{ event, why, file, anchor }`

Today a row is `site: 'path.ts:line'`, and `generate` splits it on the last `:` (`events.ts:396-399`). The new row has two fields in its place:

- `file`: the repository-relative path.
- `anchor`: a substring of **one line**, with no `\n`, that occurs exactly once in `file`. It must sit on the line that names the event.

Export a single pure function, `anchorLines(text: string, anchor: string): number[]`. It returns the 1-based line of every occurrence. Both `generate` and the test call it, so the generator and the test cannot disagree about what "once" means.

In `generate`, a row whose `anchorLines` result does not have exactly one entry **throws, naming the event, the file and the count**. It never takes the first match. That error also turns the staleness test red, because that test calls `generate` (`events-json.test.ts:56`). That is acceptable, since the anchor test reports the same row by name.

**Choosing anchors: the event name alone is never unique.** Every event name in `ELSEWHERE` appears more than once in its file:

| Event | File | Occurrences |
|---|---|---|
| `'ConductorShutdownRequested'` | `control.ts` | 2 (lines 183 and 219) |
| `'SplitStarted'` | `split-ticket.ts` | 3 |
| `'PassRouted'` | `conduct.ts` | 2 |
| `'RunProducedDiff'` | `conduct.ts` | 2 |
| `'ProjectRecovered'` | `project.ts` | 3 |
| `'EndActionsResolved'` | `end-step.ts` | 3 |

So the anchor is a longer slice of the site's own line, for example `` await append('ConductorShutdownRequested', { by, reason, timeoutMs, force }, store, events.length) `` for `control.ts:219`.

Some lines are not unique even in full, such as `type: 'PassRouted' as const,` (`conduct.ts:4055`). If no slice of such a line is unique:

- **Do:** append a short trailing comment to that source line, such as `// events.json: PassRouted`, and use the comment as the anchor.
- **Don't:** let the anchor span lines, or point it at a neighbouring line. Either one breaks rule (3) of the ticket.

Two constraints carry over from today's code:

- **Quotes:** `bootstrap.mjs:54` names its event in double quotes (`"TicketDiscovered"`). The "names the event as a quoted string" check must accept both quote styles, as it does today (`events-json.test.ts:44`).
- **Location:** a row's `file` must stay under `apps/` or `packages/`. The generator reads from a `git archive` of only those two directories (`events.ts:444`), and `bootstrap.mjs` qualifies because it is under `packages/`.

Rewrite the header comment at `events.ts:37-43`. Today it says `site` is `path.ts:line` and *"that line must hold the event's name"*; it should describe the anchor rule instead.

### 2. Staleness: compare by event name, not by diff

Do not keep `normalised` (`events-json.test.ts:22-24`) and simply strip more from it. Replace the comparison with a function that returns **the names of the events that differ**. The ticket requires that "an event added without regenerating must still fail by name", and a `toEqual` diff over sixty objects does not give a name.

Put these two functions in the test file. They are the test's own idea of what "current" means, and the generator has no use for them.

- `eventLevel(e)` returns the event with `definition` removed and `sites` replaced by `sites.length`.
  - Use a **deny-list**: remove only those two fields and compare everything else.
  - The reason: a field added to `EventsDoc` later is then compared by default, which errs toward red. An allow-list would let a new field drift silently.
  - Do not keep site paths, not even sorted. The ticket's Watch-out says a file move is an unrelated refactor.
  - `sha` is on the document, not on each event, so working per event drops it without any special handling.
- `staleEvents(committed, fresh): string[]` keys both documents by `name`. It returns:
  - every name present in only one of the two;
  - every name whose `eventLevel` values are not deep-equal (use `node:util`'s `isDeepStrictEqual`).

The real test then reads `expect(staleEvents(committed, fresh), 'doc/events.json is out of date — run pnpm events:generate …').toEqual([])`. The failure prints the event names.

### 3. The Done-when tests use no temp directory

Under 0060 §1, as CLAUDE.md applies it, a temporary directory is the filesystem, and that makes a test integration. Every fixture here is a value in memory:

| Done-when item | How the unit test builds it |
|---|---|
| **Blank line stays green** | Take `fresh = generate({ root, sha })`. Copy it: change the sha, add 1 to every `#L(\d+)` in the permalinks, and rename one site's path. Assert `staleEvents(fresh, shifted)` is `[]`. Separately, for the anchor half: `anchorLines(src, a)` and `anchorLines('\n' + src, a)` both return one line, and the second is one higher. |
| **Event added without regenerating** | Remove one event from a copy of `fresh` to stand in for the stale committed file. Assert `staleEvents(copy, fresh)` equals `[thatName]`. `EVENTS` cannot be mutated from a unit test. Dropping the event from the committed side is the same comparison. |
| **Anchor that occurs twice** | Run `anchorLines` on a two-line fixture string that holds the anchor twice, and assert two lines come back. Also run the row check (factor it out of the `it` so it takes rows and a reader) on one fake row, and assert the failure message contains the row's event and file. |

### 4. Regenerating: commit the code first

`pnpm events:generate` refuses to run while anything under `apps/` or `packages/` is uncommitted (`events.ts:433-440`). `scripts/events.ts` is itself under `packages/`, so the order is:

1. Commit the script, the test and any source-line comments.
2. Run `pnpm events:generate`.
3. Commit `doc/events.json` on its own.

Running the generator before the first commit produces only the refusal.

### Nothing to supersede

No accepted ADR covers this. #629's line-pinned check was a test, not a decision.
