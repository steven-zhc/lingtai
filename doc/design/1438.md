## Shape of #1438

> **History.** Board addresses in this note (`/task/<id>`, `/pr/…`, `/recipe/…`, `?project=`) are the ones that existed when it was written; they no longer resolve. The current forms are in [1502.md](1502.md).

The whole change is in `apps/board/src/app/globals.css`: two or three rules placed after `.place .crumb` (`globals.css:288`). No `.tsx` changes and no test changes.

### 1. The brand's size is 12px, not 13.5px

The ticket's Evidence says the brand sits "at the body's `font: 13.5px/1.5 var(--sans)`" (`globals.css:92`). It doesn't. `.bar` sets its own size:

```css
.bar { … font-size: 12px; color: var(--muted); }   /* globals.css:100-105 */
.bar .brand { display: inline-flex; …; font-weight: 600; color: var(--ink); letter-spacing: -0.01em; }   /* globals.css:109-112 */
```

`.brand` sets no size of its own, so `Lingtai` renders at 12px. The ticket's Want says "the bar's size", so go by that. On the project name, set `font-size: inherit` rather than a number; it then follows `.bar` if that ever changes. Do not write 13.5px. Copy `letter-spacing: -0.01em` from `.brand` too, so the two 600-weight words match.

### 2. On the PR and recipe pages the project name is a `.crumb`, not the summary

The Fix row gives 600 and ink only to `.place .filter > summary`, and makes `.place .crumb` sans and nothing more. But the first Done-when asks for "the project name in sans 600 ink" on the PR page and on `/recipe/<project>`. Neither page has a menu:

- `recipe/[project]/page.tsx:297` and `:427` call `<PlaceLine project={…} views={…} here="recipe" />`, with no `menu`.
- `recipe/[project]/recipe-bar.tsx:46-50` passes `project` and `tail`, with no `menu`.

So `PlaceLine` draws the name as `<span className="crumb">{project ?? 'all projects'}</span>` (`place-line.tsx:110`). The tail uses the same class: `<span className="crumb">{tail}</span>` (`place-line.tsx:140`). A rule on `.place .crumb` alone can't make the name 600 without also making `PR 12` 600.

**Decision:** target the project's slot by its position, in CSS only. `PlaceLine`'s first child is always the leading `/` (`place-line.tsx:106-108`), and the project slot always comes straight after it. So `.place > .slash:first-child + .crumb` matches the plain project name and never the tail, because the tail always follows a later slash. Give that selector the same declarations as the summary.

`all projects` with no menu then reads in the same style as a project's name, as the Edges ask for the summary. Add a comment on the rule that says why it is positional.

Adding a class such as `crumb name` in `place-line.tsx:110` would also work. But the ticket says CSS only, and the selector is exact given the markup above.

### 3. The rules

- **`.place .filter > summary`**: `font-family: var(--sans); font-size: inherit; font-weight: 600; color: var(--ink); letter-spacing: -0.01em`.
  - Its specificity is 0,2,1, so it beats `.filter > summary` (0,1,1, `globals.css:250`) regardless of order.
  - Keep `padding: 2px 7px` and the transparent border from the shared rule, so the hit area doesn't change.
  - The `▾` is a bare `<span aria-hidden>` inside the summary (`projects.tsx:112-116`), so it picks up the sans font too. That matches the mock's `<b>chapter-garden ▾</b>` (`nav-final.html:73`).
  - Hover: the shared `.filter > summary:hover { color: var(--ink) }` (`globals.css:256`) is now a no-op on this line. That's acceptable, and the Edges already allow it.
- **`.place > .slash:first-child + .crumb`**: the same five declarations.
- **`.place .crumb`** (edit the rule at `globals.css:288` in place, since it is already scoped): `font-family: var(--sans)`, and drop `10.5px` to `font-size: inherit`, which is the bar's 12px. Keep `color: var(--muted)` and the padding. This is the tail's style.

**Leave these alone:**

| Rule | Location |
|---|---|
| `.filter > summary` | `globals.css:250-253` |
| `.tab` | `globals.css:263-267` |
| `.filter .menu …` | `globals.css:270-274` |
| `.place .slash` | `globals.css:287` |
| `.place .more > summary` | `globals.css:301` |

The `.more > summary` rule is already sans 13px; don't sweep it into the new rules.

### 4. The skeleton needs nothing extra

The loading summary `filterSummary(<Pulse />)` is drawn inside a `<PlaceLine views={[]} menu={…}>` (`page.tsx:1276-1283`). It is a `.place .filter > summary` like the real one, so the new rule already covers its font, size and padding.

What changes when the name arrives is the width: a 5px dot (`.ct-pulse`, `globals.css:3676-3682`) becomes a word, and the skeleton has no views (`views={[]}`), so the line gets longer. That was true before this ticket. Read "no jump" in the Done-when as no change in height and no vertical shift.

The height stays fixed if the summary's `line-height` is the same in both states. Both inherit the body's `1.5` (`globals.css:92`) at the same `font-size: inherit`, so they match.

### 5. How to check it

No test reads a font. The proof is a person looking at the production build, as the Done-when says. `pnpm typecheck` and `HOME=/nonexistent pnpm test` can't go red from a stylesheet edit and won't touch the ratchet. Run `pnpm fmt:check` too, because `oxfmt` formats `.css`.

For the 1280px edge: the name gets wider, since 12px sans 600 is wider than 10.5px mono. Check the home page with the longest registered project name before committing. `.bar .place` is `flex-wrap: nowrap` (`globals.css:286`), so if the name is too long the views overflow to the right; the line doesn't wrap.
