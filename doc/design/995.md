## Decision 1: the reading of the map goes in a new pure module, not in `locks.ts`

Add `apps/board/src/lib/lock-marks.ts`. It holds only `import type { Lock } from '@lingtai/domain'` and four pure functions:

- `lockMap(read: ProjectLocks): ReadonlyMap<string, readonly Lock[]>`
  - returns `new Map(read.held.map(h => [h.project, h.locks]))`;
  - returns the empty map when `!read.ok`.
  - Use `import type` for `ProjectLocks` from `locks.ts`.
- `isPaused(locks: readonly Lock[] | undefined): boolean`. This is the only place this ticket looks at a kind.
- `pausedNames(map, project: string | undefined): string[]`
  - sorted names whose locks `isPaused`;
  - narrowed to `project` when one is given, with the same rule as `inScope` (`locks.ts:44`).
- An `emptyRunningPause(pausedNames, registeredCount)` helper, if you want one. Otherwise put that logic inside `emptyNote`.

**Why not `locks.ts`:**

- `locks.ts` imports `@lingtai/conductor/projects` and `@lingtai/daemon/control` as values (`locks.ts:12-13`).
- `projects.tsx` sits next to `filter-menu.tsx`, which is `'use client'`.
- A server-only import that reaches a client graph is the failure that only `apps/release/integration/build.test.ts` sees. That test is in the integration half, which runs after the merge, and #230 is what it looks like when it is caught late. `tsc` cannot see it.

Keeping the functions that read locks free of IO-carrying imports removes that risk, and lets the unit tests import them with no store.

**Where `board.ts` gets `isPaused`.** `board.ts` already imports conductor packages (`board.ts:1-7`), so importing `isPaused` from `lock-marks.ts` there costs nothing new.

## Decision 2: build the map once in each server page and pass it down

- **On `/`:** `const projectLocks = lockMap(await readProjectLocks())`, next to where `only` is computed (`page.tsx:663`).
- **On `/recipe/[project]`:** do the same, and add `locks` to `RecipeBarFilter` (`recipe-bar.tsx:14`) so it travels with `filters`, `registered` and `app`. That object is already the filter's bundle, and putting it there keeps `RecipeBar`'s signature from growing a stray argument.

**No component reads a stream or the store.** `Projects` takes `locks: ReadonlyMap<string, readonly Lock[]>` as a required prop, so typecheck catches a page that forgets it. Do not give it a default: an empty default would quietly mark nothing on a page that forgot to pass the map, and nothing would show that the page is wrong.

## Decision 4: what the empty Running line says

### `emptyNote`'s signature

Use `emptyNote(column, paused, project, pausedInScope: readonly string[] = [], everyProjectPaused = false)`.

`emptyNote` cannot tell for itself whether every project is paused: `held` lists only projects that have a lock, so it does not know how many are registered. So the page passes a boolean.

`everyProjectPaused` must count **registered** projects, not the filter's `filters`, which also includes projects that only appear in the log (`page.tsx:672` comment). Compute it as:

```
registered.length > 0 && registered.every(p => isPaused(projectLocks.get(p)))
```

### Which text wins, in order

1. **Running with the conductor-wide pause:** `Paused — nothing will start.`, unchanged (`:516`).
2. **Running, with `pausedInScope` not empty:**
   - with a project selected: `Nothing here yet. <p> is paused.`;
   - with *all projects* and `everyProjectPaused`: `Nothing here yet. Every project is paused.`;
   - otherwise: list the names, joined with `, ` and with ` and ` before the last, then `is`/`are paused; the others are taking work.`
3. **Everything else:** unchanged.

### What the line looks like and how to test it

**Every case except the all-projects line with others still taking work carries the `held` class.** That is, the conductor-wide line, the one-project line and the every-project line get `held`; the line where only some projects are paused stays plain, because most of the board is still working. `page.tsx:902` decides the class today, so give it a small `emptyHeld(...)` predicate, kept next to `emptyNote`, so the sentence and its colour come from one place.

**The Queued column's `empty` at `:897` keeps its current arguments.** The new cases are for `running` only.

**Rewrite the doc at `:507-513`.** Today it says *the pause is not narrowed — `ctl-` is one stream*. Now:

- `ctl-` is the one pause for the whole installation, and the filter leaves its sentence alone;
- a person's pause is per project, and follows the filter.

**Update the test at `columns.test.ts:160-162`, don't delete it.** It asserts that, under a filter, the Running line is *the filter's to leave alone*. That stays true for the conductor-wide pause; change its title to say so, and put the new cases beside it.

## Decision 5: the filter rows

- Show the tag only when `isPaused(locks.get(p))`: `<span className="pause-tag">paused</span>`, placed after the name and before the `phint`.
- Change `hint` to return:
  - `'recipe · resume'` when the project is registered and paused;
  - `'recipe · pause'` when it is registered and not paused;
  - `null` when it is not registered.
- **An unregistered project gets no tag and no hint.** It has no project stream, so it can hold no lock, and there is nothing to pause.
- The CSS goes in `globals.css` next to `.phint` (`:275-276`), using `var(--held)` and `var(--held-soft)`. `.card.paused-card { opacity: .72 }` goes there as well.
- **`bar.test.ts` reads `projects.tsx`.** It fails on a second amber on the bar, so check that nothing new uses `--signal`.
- **Update the doc block of `projects.tsx` (`:8-10`).** It currently says the hint names `recipe`. It should say the hint now names the action too, and that the tag is a mark only: the action itself is C1's button on the bar (0126 §8, *mark, never explain twice*).

## Edges this note decides

- **A failed read.** `lockMap` returns the empty map. Nothing is marked, and `everyProjectPaused` is false because `isPaused(undefined)` is false. The filter hint still reads `recipe · pause`, which offers an action without asserting a state; the banner says that the read failed.
- **No projects registered.** `everyProjectPaused` is false, so the line never says *Every project is paused* about an empty register.
- **A paused project that only appears in the log.** This cannot happen: a project that is not registered has no stream to hold a lock.
- **Cost to later tickets.** The ceiling and account tickets add a branch to `isPaused`'s neighbours in `lock-marks.ts`, and a case each in `queuedStanding` and `emptyNote`. Nothing that is passed around changes shape.
