# Design note for #1137: rates and the beacon become Effects, plus the unreferenced-face check

## 1. The new check comes first, and today's file passes it

I ran a rough check: a whole-word grep over `apps/` and `packages/` (`*.ts`/`*.tsx`, skipping `node_modules`/`.next`), for each `fn` in `effect-ratchet.faces.json`. Only 34 of the 92 entries have no reference outside their own file. Each of those 34 has exactly two whole-word occurrences in its own file: the declaration and one more. Three spot-checks confirmed that the second occurrence is a call in code:
- `packages/event-store/src/store-face.ts:49`: `append: (…) => appendFace(events, …)`
- `packages/projector/src/store-face.ts:128`: `transact: (fn) => transactFace(p, fn)`
- `packages/recipe/src/files.ts:86`: `diskFiles: RecipeFiles = { read: readFileFace, replace: replaceFileFace }`

The other 31 were not opened. If one of them turns out to be a comment, the parser check will name that entry. The only two whose second occurrence is the dead pair are `refreshOnce`, whose other use is `rate-snapshot.ts:125` inside `refreshRates`, and `beaconBeatFace`, whose other use is `control.ts:632` inside `startBeaconOn`. Removing those two calls is what the rest of the ticket does.

So the "calls in the same file count" rule is load-bearing. If the check only looked outside the declaring file, it would refuse about 30 `store-face.ts` entries. Do not tighten it.

### Shape
Add one pure function beside `checkFaces` in `packages/domain/unit/effect-ratchet.test.ts`, with the same no-filesystem style. Roughly `unreferenced(entries, sources: Map<file, text>): string[]`.
- **Corpus:** every `.ts`/`.tsx` under `apps/` and `packages/` (all of `src`, `unit`, `integration`, `test` and `scripts`). Skip `node_modules`, `dist` and dot-directories. The JSON is not TypeScript, so the entry's own line is excluded without any special case.
- **Matching:** run a plain `text.includes(fn)` prefilter first, then `parse()` (`effect-ratchet.test.ts:115`) only the files that pass it. That keeps the cost to a handful of parses.
- **What counts as a reference:** any `ts.Identifier` whose `.text === fn`, except the declaration's own name node:
  - `FunctionDeclaration.name`, or
  - `VariableDeclaration.name` of the arrow form, in `entry.file`.
- **Comments and strings:** these never produce `Identifier` nodes, so they are excluded without extra code.
- **Re-exports:** an `export { fn } from …` re-export counts as a reference. That is the ticket's rule (an identifier token in code), and none exists for a face today.
- **Refusal text:** `effect-ratchet.faces.json: <file> <fn> has no reference in apps/ or packages/ besides its declaration — delete the face and its entry.`

### Where it is wired
- Make it its own `it(…)` that reads the real tree. Do not fold it into `holds every package at or below its baseline` (`:928`), which only walks `PACKAGES`' `src`.
- Add a synthetic case under `describe('checkFaces'…)` covering three things:
  - an entry referenced only by its declaration plus a comment plus a string is refused by name;
  - a same-file call passes;
  - a call from another file passes.

### Leave alone
- `until: "#NNN"` stays legal in `checkFaces` (`:469`). The header comment (`:12`) still allows "a named issue still open".
- The `#790` test (`:917`) stays.

The state the ticket wants — every entry at `0101 §7` — is reached by deleting the two entries, not by a new rule.

## 2. Rates

Today `rate-snapshot.ts:121-132` holds the in-flight work as a module `let inflight: Promise`. **Keep it module-level.** The header (`:5-8`) says *"One writer per machine, by construction … inside it one fetch runs at a time"*, and the unit tests call `ratesSettled()` with no handle.

### The new shape
- Make `inflight` a `Deferred.Deferred<void> | null`.
- `refreshRates(ports): Effect.Effect<void>` is `Effect.suspend(() => …)`:
  - If `inflight` is set, return `Deferred.await(inflight)`.
  - Otherwise, **in the same synchronous step**:
    1. `const d = Deferred.makeUnsafe<void>()` (it exists in effect 4.1.2's `Deferred.d.ts`);
    2. `inflight = d`;
    3. return `refreshRatesEffect(ports).pipe(Effect.ensuring(Effect.sync(() => { inflight = null }).pipe(Effect.andThen(Deferred.succeed(d, undefined)))))`.

  The check and the set must not have a yield point between them. That is why the code uses a `Deferred` set inside `suspend`, not a `Ref` and not a fork-then-store.
- `ratesSettled: Effect.Effect<void>` is `Effect.suspend(() => inflight ? Deferred.await(inflight) : Effect.void)`.
- Delete `refreshOnce` (`:139-142`) and its JSON entry (`faces.json:160`).

### `startRates` (`apps/cli/src/rates.ts:147-150`)
`startRates` becomes `Effect.Effect<void>`:

```ts
ratesDue(now) ? Effect.forkDetach(refreshRates(realRatePorts(…)), { startImmediately: true }).pipe(Effect.asVoid) : Effect.void
```

- **Detached:** today the refresh outlives the pass that started it. A child fiber would be interrupted when `run.ts`'s program ends, before `ratesSettled` at `:710` gets to wait for it.
- **`startImmediately`:** this makes `inflight` set before the caller's next line. Confirm the option is on `forkDetach` (`Effect.d.ts` ~17090). If it is not, have `startRates` do the synchronous claim itself and fork only the work.
- Drop the `.catch(() => {})`. `refreshRatesEffect` already turns every cause into the note (`rate-snapshot.ts:186`).

### Callers
- `run.ts:347`: `yield* startRates()`.
- `daemon.ts:779`: `yield* startRates()`.
- **`daemon.ts:781`:** keep `setInterval(…, 3_600_000).unref()`. Its body becomes `Effect.runForkWith(services)(startRates())`, using `services` from `daemon.ts:432`, the same pattern as `daemon.ts:831`. The ratchet does not count a `*With` run on a context the caller took (`effect-ratchet.test.ts:615`).
  - Do **not** turn this into a forked `Schedule.spaced` loop. A sleeping fiber holds a timer that is not `unref`'d, and could keep the process alive after `console.log('stopped')`.
- `run.ts:710`, `daemon.ts:255` and `daemon.ts:841`: `yield* ratesSettled` in place of `Effect.promise(() => ratesSettled())`.

### The shutdown edge
"An interrupt of the daemon interrupts it" is not literally true of a detached fiber. It is true of the process: `stopNow` ends in `process.exit` (`daemon.ts:225`), which is what happens today with the promise. I chose this deliberately; record it in the comment on `startRates`.

### Tests
In `packages/conductor/unit/rate-snapshot.test.ts`, wrap each call in `Effect.runPromise(…)`. The tests sit under `unit/`, which the ratchet does not walk. Keep every assertion, including `:50`'s *one fetch and one write, and `ratesSettled` waits for it*.

## 3. The beacon

### Interface (`control.ts:553`)
- `say(state): Effect.Effect<void>` and `stop(last?): Effect.Effect<void>`, neither of which fails.
- `startBeacon` / `startBeaconOn` return `Effect.Effect<Beacon>`.
- The `state` getter stays.
- Delete `beaconBeatFace` (`:612-613`) and its entry (`faces.json:202`).

### One fiber per write, ordered by a chain of `Deferred`s
Do not use a single consumer fiber reading a queue. The reason is `beacon-chain.test.ts`'s third case: its port returns `Effect.interrupt`, which interrupts *the fiber running it*. Today each write is its own `runPromise`, so the interruption only rejects that one link, and `.catch(() => {})` at `control.ts:634` swallows it. A long-lived writer fiber would die there, and every later `say` would hang.

So `write(word)` is `Effect.suspend`, and in one synchronous step it does this:
1. `owed += 1`;
2. `const prev = tail`, then `const mine = Deferred.makeUnsafe<void>()`, then `tail = mine`;
3. returns `Effect.forkDetach(Deferred.await(prev).pipe(Effect.andThen(port.beat(word)), Effect.ensuring(Effect.sync(() => { owed -= 1 }).pipe(Effect.andThen(Deferred.succeed(mine, undefined))))), { startImmediately: true })`, then `Deferred.await(mine)`.

What that gives:
- **Order** is the order in which writes are *run*. It does not rely on semaphore fairness. A one-permit semaphore would give "never two at once" but not "in the order asked" without a FIFO guarantee nobody has checked.
- **The interruption case is covered:** `ensuring` completes `mine` on interruption too, so the next link proceeds and `say` still resolves.
- **Detached** because `stopNow` and `drain` call `stop`/`say` from root fibers (`daemon.ts:216-219`, *"Every drain and every stop is a root fiber"*), and a write must land even if its asker's fiber ends first.

### Tick
- In `startBeaconOn`, first run `write(state)`, and do not await it. That keeps the order *"Announced before the timer"* from `:640-642`.
- Then `forkDetach` the tick: `Effect.forever(Effect.sleep(every).pipe(Effect.andThen(Effect.suspend(() => owed === 0 ? Effect.forkDetach(write(current)) : Effect.void))))`. The tick never waits on a write, the same as today's `void write(current)`.
- Detached rather than scoped: `daemonCommand`'s gen has no `Scope`. Adding one changes its type for every caller, for a lifetime that `stop` already ends.

### Stop
`stop(last)` = `Fiber.interrupt(tick)`; if `!stopped && last !== undefined`, then `current = last` and `write(last)` without waiting; `stopped = true`; then `Deferred.await(tail)`.
- It is idempotent: a second `stop` just awaits the tail.
- `say` after `stop` is `Effect.void`.

### Callers
- `daemon.ts:441`: `const beacon = yield* startBeacon(…)`.
- `:250`, `:300`, `:321` and `:448`: `yield* ports.beacon.…` / `yield* beacon.say('starting')`.
- **`daemon.ts:545` (`void beacon.say('up')`)**: an Effect nobody runs writes nothing. It must become `yield* Effect.forkDetach(beacon.say('up'), { startImmediately: true })`, so the enqueue happens on that line, before any later `draining`.
- `StoppingPorts.beacon` (`daemon.ts:201`) follows the type. `apps/cli/unit/daemon-stopping.test.ts:33-35`'s fake becomes `Effect.sync`.

### Tests to rewrite, without deleting any (the ordering #120/#860 relied on)
- `packages/daemon/unit/beacon-chain.test.ts` and `beacon-fresh.test.ts`: `Effect.runPromise(startBeaconOn(…))`, then `void Effect.runPromise(beacon.say('up'))`. `runPromise` evaluates up to the first async boundary synchronously, so the enqueue order is the call order. Keep every `toEqual`.
- `packages/daemon/integration/beacon.test.ts` and `packages/daemon/test/contract.ts:270`: change them to compile. `packages/daemon/tsconfig.json` includes `integration` and `test`, so `pnpm typecheck` holds them. Their behaviour is only checked after the merge (the integration half). The unit-level claim that stands in for it is the three `beacon-chain` cases.

### Comments to correct
- `control.ts:612` goes with the face.
- `store.ts:189` ("`startBeacon` is…") should say the Effect.
- `rate-snapshot.ts:5-8` and `apps/cli/src/rates.ts:5` should name `ratesSettled` as yielded, not awaited.

## 4. The ratchet stays at zero
No new `Effect.run*` in any counted `src`:
- `Deferred.makeUnsafe` is not a run.
- `forkDetach` is not a run.
- The one new host-side run is `runForkWith(services)` at `daemon.ts:781`, which is uncounted.

If `holds every package` reports `run` above 0 for `apps/cli`, `packages/conductor` or `packages/daemon`, the change is wrong. The fix is never the baseline.

No ADR is contradicted. 0101 §6 is what this ticket implements.
