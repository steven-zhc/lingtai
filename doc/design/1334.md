Three decisions the ticket leaves open, then the shape.

**1. The skip asks `hostCanSandboxHere`, once, when the file is collected.** Use the one in `@lingtai/sandbox/live` (`packages/sandbox/src/live.ts:82`), not `sandbox.hostCanSandbox` from a built runtime. Its comment says why: it runs *"without building `SandboxLayer`: its scope resets srt's one instance when it closes"* (`live.ts:76-78`). Call it with a top-level `await Effect.runPromise(Effect.exit(hostCanSandboxHere))`. It is cheap because the answer is kept for a while (`live.ts:80-92`). The ratchet only counts `src/` (`effect-ratchet.test.ts:474,511`), so an `Effect.run*` in a test file adds nothing to `"packages/sandbox": { "async": 0, "run": 0 }`.

- The `SandboxUnavailable` already carries what the skip needs: `reason` plus `sentences` (`port.ts:8-11`), which are srt's own words, *"never parsed"*.
- Build one string from them, e.g. `host cannot sandbox: host dependencies are missing — bubblewrap (bwrap) not installed; socat not installed`. Put it in the title of **both** top-level blocks, `'0.14.0 acceptance: a wrapped run'` (`acceptance.test.ts:44`) and `'a wrapped run and a Unix socket'` (`:265`), with `describe.skipIf(!can)(title)`. The second block runs srt too, so if only the first skipped, the second would still fail.
- Fold the existing `supported` platform check (`:24`) into this. `hostCanSandboxHere` already fails with a reason on an unsupported platform (`sandbox.ts:101-102`), and `readHost`'s failure is a `SandboxUnavailable` it catches (`live.ts:88-90`).
- On a capable host the title stays exactly as it is today, and nothing else changes. Keep `it('the host can sandbox')` (`:139`). Running it is harmless, and it shows the check passed.
- The skip must not look like a pass, and the skip count alone does not prevent that. vitest's default reporter shows a count, and only the JSON report the workflow uploads keeps the title. So also write the same string once to `console.warn` when the skip fires. That puts the reason in the CI log next to the count.

**2. The skip covers only what `checkHost` can see, and that is not user namespaces.** On Linux, srt's `checkLinuxDependencies` (`node_modules/@anthropic-ai/sandbox-runtime/dist/sandbox/linux-sandbox-utils.js:1014-1053`) checks three things: that `bwrap` and `socat` are on `PATH`, uid 0, and a seccomp warning. It never runs bwrap.

- So on a runner where AppArmor still restricts unprivileged user namespaces, `hostCanSandbox` succeeds and the wrapped tests **fail**; they do not skip. That is the correct outcome: the host says it can sandbox, so the acceptance runs, and a failure there is a real finding.
- Do not add a userns probe to the skip. The ticket asks for a skip by `hostCanSandbox`, and a second rule for *can* is what `checkHost`'s comment warns against: *"the one question the resolver and `wrap` both ask, so they cannot disagree about *can*"* (`sandbox.ts:98`).
- Because of this, the workflow's sysctl step is required, not a nicety.

**3. The sysctl command is not a no-op where the key is missing.** The ticket says it is, but `sysctl -w` on an unknown key exits non-zero. Guard it with `[ -e /proc/sys/kernel/apparmor_restrict_unprivileged_userns ]`. Do not use `|| true`: that would also hide a failed write on a runner where the key exists.

**`integration.yml`:** add one step after `pnpm install` and before `test`, in the `integration` job. It runs on both matrix legs, since the `sqlite` leg runs this file too:

- `sudo apt-get update`, then `sudo apt-get install -y bubblewrap socat ripgrep`. These are the packages `install.ts:15-16` names.
- The guarded sysctl.
- Comment the step with the sentence it prevents (`ripgrep (rg) not found`) and #1334.

If this step fails, the job fails at that step, as the ticket's Edges require. Nothing in the report job changes.

**What checks it:** the workflow change and the CI skip can only be checked by the next `integration` run on main; neither `pnpm test` nor the `build` step sees this file. What a pass can check:

- `pnpm typecheck` covers the top-level await and the `Exit` handling.
- Running the file on this Mac with `pnpm vitest run --project integration packages/sandbox/integration/acceptance.test.ts` should leave the titles unchanged and skip nothing. That is the evidence the skip does not fire on a capable host.
- To see the skip fire locally, run the same command with a `PATH` that has no `rg`. This is only for the agent to look at, not something to commit.
