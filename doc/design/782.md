This touches three files and adds two tests. `Bar` and `treeOf` are as the ticket says. The decisions below are the parts the ticket does not settle.

### 1. `treeOf`: add the entry after the loop

`treeOf` (`src/lib/docs.ts:615-630`) builds its groups from `SECTIONS` filtered by `served` (`docs.ts:616`). That set holds only markdown slugs, so `'events'` is never in it. Leave the loop alone. After it, find the group with `id === 'guides'`, find `cli` in its entries, and insert `{ slug: 'events', title: 'Events' }` straight after it:

- The guard is `isPublicSlug('events') || DOCS_PUBLIC`. This is the same rule `servable()` uses (`docs.ts:84-87`) and `resolveHref` uses (`docs.ts:433`).
- If `cli` is missing, append the entry at the end of the guides group.
- If the guides group is missing, add nothing.

Extend the docstring (`docs.ts:606-614`), which today says *"there is no second list of what the sidebar shows"*. That sentence stops being true here, so it needs to say where the exception is: a public page that is not markdown is added by hand at this point, and `events` is the only one. That is the cost the ticket's Edges asks to be written down.

Don't add `'events.json'` to `SECTIONS`. The ticket's Watch out explains why.

### 2. `EventsPage`: tree, article, and a two-column override

Copy `DocPage`'s structure (`src/app/docs/[...slug]/page.tsx:96-126`):

- `<Bar />`
- the kicker stays where it is: above the layout, and conditional on `DOCS_PUBLIC` (`events/page.tsx:24`)
- `<div className="doc-layout"><DocTree groups={await treeOf()} current="events" /><article>`, with the `h1`, the intro paragraph and `<EventsBody>` inside the `<article>`

**The decision the ticket does not mention:** `.doc-layout` is a three-column grid, `14rem minmax(0, 48rem) 13rem` (`src/app/site.css:297-300`). The third column holds `Contents`, and the events page has no headings list.

Placed as-is, the article would get the 48rem (768px) middle column. Take off `.ev-drawing`'s padding and border (`site.css:593`, 14px each side plus 1px) and that leaves about 738px. But `.ev-spine` has `min-width: 760px` (`site.css:594`), so the step drawing would scroll sideways even at full desktop width, with an empty 13rem column beside it.

So copy what `tutorial-page` does (`site.css:301-304`):

- Give `<main>` a class, `events-page`.
- Add `.events-page .doc-layout { grid-template-columns: 14rem minmax(0, 1fr); }` in the `/docs/events/` block (`site.css:591`).
- Inside the `@media (max-width: 1080px)` block (`site.css:354-356`), add `.events-page .doc-layout { grid-template-columns: minmax(0, 1fr); }`, as `tutorial-page` does there. Without it the higher-specificity rule wins on a phone and keeps two columns.

Leave `EventsBody` unchanged (out of scope).
