## Design note for #823: one `savedHeadOf`

The ticket already gives the shape, the order of the rules and the edges, so this note only adds what the code shows.

- **Fold with `reduceRun`** (`packages/domain/src/run.ts:459`). Each of the three callers does `savedHeadOf(reduceRun(events))`. Don't write another `events.reduce(applyRun, emptyRun)` (`emptyRun` is at `run.ts:160`). Add `published: null` and `kept: []` to `emptyRun`.
- **Short streams must still fold.** `applyRun` (`run.ts:326`) needs no `RunStarted` before any other event. That matters because `apps/board/unit/standing.test.tsx:1334-1346` calls `savedFixWork(RUN_2, [])` and `savedFixWork(RUN_2, [one RunRefsPublished])`. The `arm-only` test in `packages/conductor/unit/resolve-wait.test.ts:149-167` likewise seeds a run stream with only `RunRefsPublished` and `RunKeptUncommitted`. Both new cases have to keep working on a stream like that: don't add a guard that needs a started run.
- **Read the two fields as the stream gives them, untouched.**
  - `published` is the whole payload of the last row, whatever its `outcome`. Overwrite it on every `RunRefsPublished`, including an `unrecorded` one.
  - `kept` keeps every payload, in order.
- **Write `savedHeadOf` as straight-line code in the order of `resolve-wait.ts:409-449`.** First compute `cleanBranch`, then:
  1. If `armSha != null && !cleanBranch`, answer `WipHead`.
  2. Otherwise, if the outcome is `arm-only`, answer `BranchDiverged`.
  3. Otherwise, if there is no clean head or ref, answer `NoSavedHead`.
  4. Otherwise answer `Saved`.

  `BranchDiverged` carries `arm` and `branch`, because both the conductor's sentence and the board's sentence name them.
- **The conductor keeps one `store.read`.** It does `reduceRun(await store.read(runId))`, so a fold that throws (#822's `PassRouted`) reaches `resolve-wait.ts:298` the same way a read that fails does today.
