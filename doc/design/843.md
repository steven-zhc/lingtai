## Design note: #843, the ticket's reduce folds DiscussionHeld

The ticket has the shape right. Five things are not in it, or are easy to get wrong.

### 1. Where the case goes in `applyTicket`

- **Add a plain `case 'DiscussionHeld'` in the switch.** Put it beside the other cases that don't change the lifecycle, such as `TicketLinked` (`packages/domain/src/ticket.ts:699-703`).
- **Do not add it to `LIFECYCLE_EVENTS`** (`ticket.ts:397-405`). Leaving it out is enough for both of these to hold, with no new guard:
  - The `closed` guard only returns early for `LIFECYCLE_EVENTS.has(event.type)` (`ticket.ts:438`), so a `DiscussionHeld` after `TicketClosed` reaches the switch.
  - The #831 `lastMove` block leaves `m` untouched for anything outside that set (`ticket.ts:446-447`, `!LIFECYCLE_EVENTS.has(event.type) ? { lastMove: m }`). A discussion held after a person's move does not end the move. Don't write code for this case; it already works.
- **Return `{ ...state, ...at, discussions }`** so `version` and `lastSeq` advance, the same way `TicketLinked` does.
- **Don't move `since`.** Only a stream's first event or a lifecycle event moves it (D11, comment at `ticket.ts:419-421`).
- **Read the payload the same way the other cases do:** `event.data as PayloadOf<'DiscussionHeld'>`.

### 2. The type of the new field

Export a named element type next to `TicketClaim` and `AnswerRecord` in `ticket.ts`, for example:

```ts
TicketDiscussion { chatId: string; outcome: PayloadOf<'DiscussionHeld'>['outcome'] }
```

- **Take `outcome` from the schema, don't redeclare the union.** The schema is `z.enum(['prompt', 'ticket', 'none'])` (`packages/domain/src/events.ts:1875`).
- **The board needs no cast.** `DiscussionView['held']` is `'prompt' | 'ticket' | 'none' | null` (`apps/board/src/lib/task.ts:1022`), so the domain type fits it.
- **`index.ts` needs no change.** It already does `export * from './ticket.ts'` (`packages/domain/src/index.ts:15`).
- **Use `readonly TicketDiscussion[]`**, as `answers` and `waits` do (`ticket.ts:350`, `:358`).
- **Write the docblock the way the neighbouring fields are written.** Say it is every chat held on this ticket, in the order each was first held, with its latest outcome. Say that it is not a lifecycle fact, so a closed ticket keeps folding it, in the same words the `github` field uses (`ticket.ts:352-354`).

### 3. `chatIdsFor` and its comments in `task.ts`

- **The new signature** is `chatIdsFor(control, held: readonly TicketDiscussion[], taskId)`.
- **The body after the control loop** (`task.ts:1076-1085`) becomes:
  1. append each held `chatId` that `order` does not already have;
  2. build the map from `held`.

  The `String(d['chatId'] ?? '')` guard and the `'none'` fallback go away, as the ticket says.
- **The caller** at `task.ts:1613` passes `ticketState.discussions` instead of `own`. `own` is still used for the history at `:1812` and for `exists` at `:1599`, so don't remove it.
- **Two comments in `task.ts` name the event, not one.** The *Done when* says "`task.ts` names no `DiscussionHeld`":
  - `:1064` is the `chatIdsFor` docblock, which the ticket already asks you to rewrite.
  - `:1810-1811` is the history comment, *"The work item's own `DiscussionHeld` is here"*. Reword it to "the ticket's own record that a discussion was held", or something like it. It still describes `history.ts`'s row, which stays.

  Check with `git grep -n DiscussionHeld apps/board/src/lib/task.ts`, which should print nothing.

### 4. The fixture and the hash lock

- **The hash lock is over the events, not the folded state.** `histories.test.ts:163-184` hashes each history's envelopes. Adding a field to `TicketState` therefore changes no existing entry in `histories.hashes.json`. If an existing hash goes red, the new history is in the wrong place in the file.
- **Where it goes:** a `const late_discussionsHeld = (() => { … })()` immediately after `late_waitThenLanded` (`packages/domain/test/histories.ts:1005-1026`) and before `export const lateHistories` (`:1028`).
  - Register it as the last entry of `lateHistories.ticket` (after `waitThenLanded: late_waitThenLanded`, `:1056`).
  - Use issue `9117` (`makeStream(ticketStream(PROJECT, 9117))`), since `9116` is the last one used, and `passStream('t9117-1')` for the claim.
  - Build it from `stamp([...aClaim(t, r1), t('DiscussionHeld', …), …, t('TicketClosed', { by: 'steven', reason: … }), t('DiscussionHeld', …)])`, the same way `late_closedByPerson` does (`:930-945`).
- **Give every `DiscussionHeld` payload a `by`.** The schema requires one (`events.ts:1876`). The reduce drops it; the fixture still has to be a valid event.
- **The new hash:** run the suite once. The red prints the entry for `ticket.discussionsHeld` (`histories.test.ts:184`). Paste it under the last `ticket.*` key in `histories.hashes.json`, after `ticket.waitThenLanded` (`:61`).
- **`COVERS.ticket`:** add `'DiscussionHeld'` (`histories.ts:1094-1111`). Two tests check that list:
  - `histories.test.ts:84-90` checks that every `case` label in `applyTicket` is listed;
  - `:76-81` checks that every listed type appears in some ticket history.

  The new history satisfies the second.

### 5. Where the tests go

- **The domain test:** a new `it` in `packages/domain/unit/ticket.test.ts`, beside the test of `closedByPersonThenClaimed` (`:492-496`). It calls `reduceTicket(lateHistories.ticket.discussionsHeld)` and checks two things:
  - `.discussions` equals `[{ chatId: 'c1', outcome: 'ticket' }, { chatId: 'c2', outcome: 'none' }, { chatId: 'c3', outcome: 'none' }]`;
  - `lifecycle.status` is `'closed'`. That shows the trailing `DiscussionHeld` folded on a closed ticket rather than being absorbed.
- **The board test:** `apps/board/unit/discussion.test.ts:119` becomes `[{ chatId: 'chat-1', outcome: 'prompt' }]`, with the same expected result. `:127` already passes `[]`, which still fits the new type.
- **One more board test worth adding:** a held chat that `control` does not name comes after the control-named ones. This pins down the "order is the join's" rule from the ticket's *Watch out* row, where the reduce can't.
- **`ticket.test.ts:19`** (`toEqual(emptyTicket)`) needs no change, because it compares against `emptyTicket` itself. The other hand-built `TicketState`, `packages/conductor/unit/restart.test.ts:31`, spreads `...emptyTicket`, so it picks up the new field without an edit.

None of this needs `pnpm test:integration`. `packages/conductor/integration/discuss.test.ts` checks the writer, which this change does not touch.
