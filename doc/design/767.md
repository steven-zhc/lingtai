## Design: `board start` and the board name their home (#767)

### What the code says today, where it differs from the ticket

- **The line numbers have moved.** `start` is the closure inside `boardCommand` (`apps/cli/src/board.ts:528`). The line to change is `log(\`${symbol.pass()} board on ${url}\`)` at `:570`, with `BOARD_START_NOTE` at `:572`. `BoardWorld` is at `:370`. The production world is built in `apps/cli/src/board-world.ts`, and the fake ones in `apps/cli/unit/board.test.ts`.
- **`nothing chosen` covers three cases, not one.** `storeChoice` returns `because: 'nothing chosen'` when:
  - there is no file (`notSetUp(name, null)`, `packages/env/src/index.ts:661`);
  - a file names no `database.store` (`:676`);
  - a file sets the store to something that is neither postgres nor sqlite (`:677-683`).

  So the ticket's double condition is not redundant: a `config.yml` holding only a GitHub App and no store is "nothing chosen", but it is not "nothing set up".
- **`/` opens the event stream itself, not the layout.** `live.tsx:65` says "`/` mounts `Live`", and `page.tsx:702` mounts `<Health />`. `layout.tsx` mounts neither. So returning early from `Page`, before any of the bar's live parts, is enough to open no stream. Nothing has to change in the layout.
- **The eight brands are not one shape.** `/` draws `<span className="brand"><span className="mark" …/>Lingtai</span>` (`page.tsx:630-633`). The other seven draw `<Link className="brand" href=…>← Lingtai</Link>`, and the `href` varies: it is `back` in `recipe/[project]/page.tsx:54`, and a project-filtered `/` in `spend/page.tsx:50` and `report/page.tsx:83`.
- **`TerminalScreen` promises not to read the environment.** Its header says "It calls neither GitHub, the env nor the log — the one import is `next/link`" and "the page reads the env, this stays a fold over its props" (`setup/terminal.tsx:7-16`). It is drawn by `setup/repository/page.tsx:24` and `setup/wizard/page.tsx:14`, which already read the environment for `isGhMachine()`.

### Decisions

**1. One predicate decides "not set up", in `@lingtai/env` beside `storeChoice`.**

```ts
export function nothingSetUp(choice: StoreChoice, configExists: boolean): boolean
// true only for because === 'nothing chosen' && !configExists
```

- The CLI and the page both call it, so the terminal and the browser cannot disagree about one home.
- Beside it, `shownHome(from = process.env): string` returns `stateDir(from)` with a leading `from.HOME ?? homedir()` replaced by `~`. Replace it only when the next character is `/` or the path ends there: `/Users/xy` must not become `~y` for `HOME=/Users/x`.
- `configExists` is passed in as a boolean, so the predicate stays pure and is unit-tested in `packages/env/unit` without a filesystem. Its callers compute it with `existsSync(join(stateDir(), 'config.yml'))`.

**2. CLI.** `BoardWorld` gains these fields, filled in `board-world.ts` from the functions above:

- `home: { path: string; shown: string }`
- `notSetUp: () => boolean`

The start line becomes `✓ board on <url> · home <shown>`. When `notSetUp()` is true, the next line is the ticket's not-set-up sentence, then the browser line and `BOARD_START_NOTE` as today. Every fake world in `apps/cli/unit/board.test.ts` needs the two new fields. Add one helper default there rather than editing each literal.

**3. `/` refuses before it reads.** At the top of `Page`, before the `Promise.all` at `page.tsx:589`:

- Compute `const choice = storeChoice()`.
- If `'refused' in choice`, return `<NotSetUp home=… shown=… refused={nothingSetUp(…) ? null : choice.refused} />`.

That means **every** refusal draws the setup screen and skips `loadBoard`, not just `nothing chosen`, because any refusal makes `loadBoard` throw the same sentence (`apps/board/src/lib/board.ts:1230-1233` rethrows it). The headline is chosen like this:

- When `nothingSetUp` holds: `Nothing is set up in <shown>.`, then the `lingtai init` sentence and `reload this page after lingtai init`.
- Otherwise: the refusal's own `refused` sentence as the error. That covers a file with no store, `two keys`, `unreadable` and `no url`. Each of those sentences already names `lingtai init` or the file.

`NotSetUp` is a server component of props only, in its own file under `apps/board/src/app/`. It draws:

- the bar, with only the brand: no `Projects`, no `Health`, no `Live`, no paused chip, since each of those reads the log;
- one `section`.

Other routes (`/task/…`, `/spend`, …) in an empty home are not changed; see Out of scope.

**4. The home is a child of `.brand`, through one component.** `apps/board/src/app/home.tsx` exports `Home({ path, shown }: { path: string; shown: string })`:

- It renders `<span className="home mono" title={path}>{shown}</span>`.
- It imports nothing but React types: no `@lingtai/env`, no `"use client"`. A client file could import it safely, but none should need to.
- Each of the eight files keeps its own brand element and `href`, and adds `<Home … />` as the last child inside it. Wrapping the eight different brands in one `Brand` component would mean parameterising the span-versus-Link, the arrow and the href, and that is drift moved somewhere else rather than removed.
- Each server page reads `stateDir()` and `shownHome()` itself.
- `TerminalScreen` gains a **required** `home: { path: string; shown: string }` prop. `setup/repository/page.tsx` and `setup/wizard/page.tsx` pass it. The five calls in `apps/board/unit/terminal.test.tsx` gain it.
- Make the prop required rather than optional, so a ninth page cannot forget it and still type-check.
- Add one CSS rule in `globals.css` for `.brand .home`: muted colour, smaller size, left margin.

### Tests that stand in for the Next build

`tsc` and `pnpm test` cannot see a server-only import reaching a client graph (#230). The guard is structural instead: `home.tsx` and `NotSetUp`'s file import no `@lingtai/env`. Add one assertion in a unit test that reads both files' source and fails on `@lingtai/env` or `"use client"`, in the style of `on-postgres.test.ts`'s source reads.

### Tests for `/`

- `apps/board/unit/not-set-up.test.tsx` renders `NotSetUp` with `renderToStaticMarkup` in both modes.
- One test calls `await Page({ searchParams: Promise.resolve({}) })` with:
  - `vi.mock('@lingtai/env', async (orig) => ({ ...(await orig()), storeChoice: …, stateDir: …, shownHome: … }))`;
  - `vi.mock('../src/lib/board.ts')`, with `loadBoard` as a `vi.fn()` that is asserted not called.

  The markup must contain no `Live` output. `close.test.tsx` and `rail.test.tsx` already import `page.tsx` under vitest, so the module loads there.
- Assert with `toContain`. `projects.test.tsx`'s *leaves the four what they were* must stay untouched and green.

### Edges the ticket left open, decided here

- **A `config.yml` exists but chooses no store.** The CLI prints no not-set-up line. `/` draws the setup screen with the refusal's own sentence, never "Nothing is set up".
- **A relative `LINGTAI_HOME`.** `shownHome` returns it unchanged, because it does not start with `HOME`.
- **`existsSync` throws.** It does not throw: it returns false. The not-set-up line still needs `nothing chosen` as well.
