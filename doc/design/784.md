## Design note: #784, one doc layout

**What the ticket misses: #782 has already landed, and it added a second exception.** It did not leave the events page on the shared classes. It gave it its own class and its own grid:

- `apps/site/src/app/docs/events/page.tsx:22`: `<main className="events-page">`
- `apps/site/src/app/site.css:592-597`, under the comment *"The drawing is wider than the reading column, and there is no contents list: two columns."*:
  ```css
  @media (min-width: 1081px) {
    .events-page .doc-layout { grid-template-columns: 14rem minmax(0, 1fr); }
  }
  ```
- `site.css:357`: `.events-page .doc-layout { grid-template-columns: minmax(0, 1fr); }` inside the `max-width: 1080px` block.

These are the commits `4115da6a` and `0171d2eb`.

**Decision: delete the `.events-page` rules along with the `.tutorial-page` ones.** The ticket's "one layout, no exceptions" covers this case, and so do two of its Edges: "the events page takes the same layout through the shared classes", and a page with no contents rail leaves the third column empty. If they stay, the jump this ticket fixes comes back between the events page and every other page. The ticket asks for a third class to stay, and keeping these would be one.

**Remove:**
- `site.css:296` and `:300-303`: the `.tutorial-page` frame and grid rules.
- `site.css:349-352`: keep the block, but drop the `.tutorial-page` prefix from both of its selectors.
- `site.css:356`: the `.tutorial-page` line in the 1080px block. It repeats the plain rule.
- `site.css:357`: the `.events-page` line in the 1080px block.
- `site.css:592-597`: the `.events-page` media rule and the first sentence of the comment above it. Keep the `/* --- /docs/events/ (#630) --- */` header and the `.ev-*` rules under it.
- `docs/[...slug]/page.tsx:99`: write a plain `<main>`.
- `docs/events/page.tsx:22`: write a plain `<main>`. Once its CSS is gone the class does nothing (`grep -rn events-page apps/site` finds only those three places).

**What the events page looks like afterwards:** it has two grid children, `DocTree` and `<article>` (`events/page.tsx:28-29`).
- **Above 1240px:** the tree is in the 11rem column, the article in the 60rem column, and the 10rem column is empty.
- **1081–1240px:** the tree is `display: none`, so the article falls into the `minmax(0, 1fr)` column and the 10rem column is empty.
- **≤1080px:** one column, as now.

The drawing's minimum is 760px (`.ev-spine, .ev-lane { min-width: 760px }`, `site.css:600`), and `.ev-drawing` scrolls inside its own box (`:599`). So a column of 60rem, or `1fr`, does not overflow the page.

**Cascade order:** leave the 1081–1240 block where it is now, after the base rule and before the 1080px block. Its selectors are now the same specificity as the base `.doc-layout` and `.doctree` rules, so it only wins because it comes later in the file. The 1080px block's `gap: 24px` now matches the base gap. That is harmless; leave it.

**Comments:**
- `site.css:288-294`: say the tree drops out between 1081px and 1240px before everything stacks at 1080px.
- `site.css:305-307`: no change. Its "about 80 characters" already describes the 60rem column.

**Checks:** nothing in `apps/site/unit` pins these classes or numbers, so `pnpm test` cannot catch a mistake here. Before you commit, run `grep -rn 'tutorial-page\|events-page' apps/site` and expect nothing back. Then run `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`.
