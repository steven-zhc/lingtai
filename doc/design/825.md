## Design note for #825: where the code stands now

The ticket already gives the shape of this change. This note only records what has changed in the worktree since the ticket was written. I checked each point at HEAD `003ad514`.

**Both blockers have landed, and the fields match what the ticket assumes.**
- `RunState.step` is at `packages/domain/src/run.ts:147`. The `StepEnded` case clears it only when the step that ended is the open one (`run.ts:468`).
- `RunState.kept` is a list of every `RunKeptUncommitted`, in order (`run.ts:164`). So the brief's `kept` is `state.kept.at(-1) ?? null`.
- `receipt` is the whole `RunFinished` payload (`run.ts:159`, set at `:399-406`). That is why `attemptOutcome` still narrows it to `{ turns }`.

**`lateHistories` is longer than the ticket describes.** #823 added `published` (`run.ts:162`), `savedHeadOf` (`run.ts:498-517`) and six `publishedRun` histories. They sit after `stepEndedForAnother` in `lateHistories.run`, ending with `nothingCommitted` (`packages/domain/test/histories.ts:654-684`).
- `run` is still the only key in `lateHistories`, so the ticket's first case applies: append `failedInsideStep` and `refusedThenFailed` inside `run:`, after `nothingCommitted`.
- Write each as a function beside `stepEndedForAnother` (`histories.ts:615`) and call it in the literal. `stamp()` numbers events in the order they are evaluated, so the new seqs then follow #823's and no existing hash moves.

**`savedHeadOf` uses a different `branch`.** It reads `saved.branch`, where `saved` is `state.published` (`run.ts:499`, `:514-516`). That is the `RunRefsPublished` payload's own `branch`, not `RunState.branch`. Deleting `RunState.branch` and `diff` therefore does not touch it.

The only readers of the fields being removed are:
- `run.ts:389-391`, the `RunProducedDiff` case, which writes them.
- `packages/domain/unit/run.test.ts:106`: `expect(moved.diff)`.

**The refusal rule fits inside the existing `StepEnded` loop.** `attemptFactOf` skips actions whose result is `NotReached` (`read-model.ts:303`). `applyRun`'s loop already skips them with `if (!isReached(action)) continue` (`run.ts:448`), and it builds the same `${d.outcome.step}:${action.name}` key (`:449`).
- Set `refusal` inside that loop, below the `steps` update and beside the signoff check. Use the condition from `read-model.ts:307-311`.
- Track the refusal in the local `next` that the loop already threads, so the last refused action in the outcome wins.
- Do not move the `step:` clearing at `:468`. It reads `state.step`, the value from before this event, on purpose.

**Changes in `attempts.ts`.**
- The `PayloadOf` and `Envelope` imports may become unused. `attemptFactOf` drops out of the import at `attempts.ts:42`. Remove whatever `pnpm lint` reports.
- `findingsAppended` stays as it is (`:409-418`).
- The header at `:319-327` should say that the facts come from `RunState`, where `refusal`, `failure` and `step` are kept for this purpose. Drop the stale name `RunState.gates`.
- The `#502` comment at `:361-373` explains the deleted `Set`. Remove it rather than rewrite it. What is still true of it is the D12 rule, and that rule now lives on `RunState.step`'s own comment (`run.ts:140-146`).

**The one caller.** `attemptOutcome(` has one caller in `src/`, `packages/conductor/src/prompt.ts`. The only other mention is `packages/conductor/unit/attempts.test.ts`. That file needs `reduceRun` from `@lingtai/domain`.

**Checks.** Nothing here depends on `pnpm test:integration`. The named tests the ticket lists are unit tests over the fixture histories, and they are what proves the change.
