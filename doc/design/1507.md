# #1507: shape of the change

## Where it goes

All of it is in `runnableNowEffect`, `packages/conductor/src/discover.ts:600–718`. The signature and the `Offered` type stay as they are. None of the six callers the ticket lists change. `considerIssue`, `blockersUnread`, the `BLOCKERS_PAGE` checks (`:654–:661`) and the release rule (`:676–:683`) move as they are; none of them is rewritten.

## The decision the ticket leaves open: the drafted read runs between the steps, not inside the concurrent ones

Today the drafted read sits inside the loop as `drafted ??= yield* readDraftedTickets(...)` (`:664`). If that line went into a function run under `{ concurrency: 8 }`, several fibers would each see `null` before any of them had assigned it, and the read would run more than once. That breaks the ticket's *"runs at most once"*.

Build it as four steps over one array of per-issue records, indexed in listing order:

1. **Decide, serially, in listing order.** This is the current loop up to the `if` at `:637–:641`:
   - push to `unread`;
   - set `kindColors` first-wins (`:624–:626`);
   - call `considerIssue`;
   - mark the record as needing a blocker read when the condition at `:637–:641` holds.

   Keeping `kindColors` here is what keeps it first-wins in listing order. Nothing that writes `result` belongs in the concurrent step.
2. **Read the blockers.** Run `Effect.forEach(needing, read, { concurrency: 8 })`, where `read` is the `Effect.tryPromise(...).pipe(Effect.map(ok), Effect.catch(notOk))` at `:642–:648`, unchanged. Every failure is already turned into a value before `forEach` sees it, so `forEach` cannot fail. That gives the ticket's *"other reads are not interrupted"* without any extra code. Keep it that way: do not move the `catch` outside `forEach`.
3. **Read the drafted tickets at most once.** Do it only if some read in step 2 came back `ok` with `0 < length < BLOCKERS_PAGE`. Run `readDraftedTickets(landed.project, landed.store)` once, with the same `catch` → `{ ok: false, why: "could not read the project's PRs: …" }` as `:665–:668`. When no read qualifies, it does not run.
4. **Assemble, serially, in listing order.** For each record, apply the existing branches to its read result and the one `drafted` value, then push to `skipped` or `runnable` exactly as `:687–:715` does.

**Why step 3 is separate and not a shared `Effect.cached` inside step 2.** `readDraftedTickets` reads this project's own event store, one stream per PR (`packages/project/src/pr.ts:307–313`: `highestPr`, then `readPrEvents` for `n = 1..highest`). It does not call GitHub, so waiting until the GitHub reads finish costs a local store read and none of the requests this ticket is about. In exchange:
- "at most once" is a property of the code's structure, with no race to reason about;
- "zero times when nobody needs it" is an `if`;
- the ticket's edge *"several tickets reaching it at the same time share that one read"* holds trivially, because exactly one call serves all of them.

Sharing an in-flight read across keys is out of scope; that is another ticket.

The one behaviour this changes on purpose: today a ticket whose blocker read fails *after* the drafted read has been made is still unaffected by it, and the same is true here. Every ticket whose read came back with 1–99 blockers gets the same `drafted` answer. That is what `:613` already says: *"a failure is the reason each of them keeps"*.

## Ratchet

`Effect.forEach` with `concurrency` adds no `async` function and no `Effect.run*`. The only `Effect.runPromise` stays the one in `runnableNow` at `:593`. Nothing in `effect-ratchet.baseline.json` moves.

## Tests

Put the tests in `packages/conductor/unit/discover.test.ts` or `packages/conductor/unit/read-blockers.test.ts`. Both already exercise `listBlockedBy`; use whichever already builds a `landed` with a fake `links` and `store`. They are unit tests (no network, a memory store), so `pnpm test` covers every item in *Done when*. Nothing here depends on `pnpm test:integration`.

- **The in-flight bound.** The fake `listBlockedBy` increments a counter and records the highest value. It returns a promise that does not resolve until the test releases it, so all 8 slots fill before any completes. Release them all once the 9th call fails to arrive. Assert `max === 8`.
  - Assert the *set* of numbers it was called with, not the order. The ticket's cost edge asks for that.
- **Equality with the serial loop.** Before changing the loop, generate the expected `Offered` with today's code, or hand-write it from today's branches, for the mixed set the ticket names: one rejection, one full page, one empty list, one release. Also include one ticket that `considerIssue` would refuse anyway, so it is never read.
  - Compare `runnable`, `skipped`, `kindColors` and `dependenciesUnread` with `toEqual`, so the order inside the arrays is checked too.
- **The drafted-read count.** Spy on the store's reads (see how the existing landed tests stub `landed.store`):
  - none of the reads returns 1–99 blockers → 0 calls;
  - several do → 1 call.
