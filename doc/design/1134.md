## Where attempt-1 is wrong

### `claudeCodeAuth`: a host does reach it

Attempt-1 kept it with `until: "#1118"`. That is the parent epic, so the face would point at an issue that closes. The face is reached from a host by this chain:

1. `apps/board/src/app/actions.ts:1013` passes `signedIn: signedInHere`.
2. `signedInHere` is built by `signedInProbe` (`packages/conductor/src/projects.ts:140-160`).
3. `signedInProbe` calls `r.checkAuth?.(env)` on every runtime.
4. For Claude Code, `checkAuth` is `packages/agent/src/claude-code.ts:423-425`, which is `claudeCodeAuth`.

**Decision:** `until: "0101 §7"`. The `why` names `apps/board/src/app/actions.ts` and the chain in a few words. `checkFaces` only checks that the named host file exists (`effect-ratchet.test.ts:460-469`).

Making `Runtime.checkAuth` an Effect would not help. `signedInProbe` has to hand `@lingtai/recipe` a promise (`SignedIn`, the comment at `projects.ts:148`), so the run would only move into `packages/conductor`.

`codexAuth` follows the same rule. Its `why` names only `apps/board/src/lib/recipe.ts:17,472,517`, plus `apps/board/src/app/actions.ts` through `signedInHere`. Drop the "Runtime.checkAuth callers" wording: the ticket says the `why` names host callers only.

### `actionRunFace`: the ticket says delete it, and nothing in production calls it

Attempt-1 kept it with `#1118`. Two facts make it test-only:

- No host imports `@lingtai/actions`: `rg` over `apps/board/src` and `apps/site/src` finds nothing.
- In production, `conduct.ts` builds ports, not promise `Action`s (#1056).

The only production use of the promise `Action` shape is `run-attempt.ts:2331`, `pipelineActions.map(promiseAction)`. It is handed to `outcomeOf` (`step-outcome.ts:330-339`), which reads `name`, `kind` and `yields` and nothing else (`step-outcome.ts:75-76`).

The face is not a free function, though. It is the `run` that `promiseAction` puts on every `Action` (`action.ts:843-857`). Thirteen `create<Kind>Action` factories, plus `actionsFromRecipe`, return `promiseAction(make<Kind>Action(spec, <kind>PortDepsFrom(deps)))`. If you inline the run, the ratchet counts it and goes red at 0.

**Decision:** move the promise shape out of `src` and keep the port registry in it.

1. **`outcomeOf` reads metadata only.** Change its `actions` parameter to `readonly Pick<Action, 'name' | 'kind' | 'yields'>[]`. Then `run-attempt.ts:2331` passes `pipelineActions` directly and drops the `promiseAction` import.
2. **The registry stays in `action.ts`; the run moves out.** Replace `promiseAction` and `actionRunFace` with an exported `actionOver(port, run): Action`. It builds the object and does `portsOf.set(action, port)`, so `fromPromiseAction`'s WeakMap round trip (`action.ts:863-871`) keeps working. `fromPromiseAction` and `liftPromise` stay; neither runs anything.
3. **New file `packages/actions/test/promise-actions.ts`** holds:
   - `promiseAction = (port) => actionOver(port, (c) => Effect.runPromise(port.run(c)))`;
   - the 13 `create<Kind>Action` factories and `actionsFromRecipe`, one line each over the already-exported `make…` and `…PortDepsFrom`;
   - `runActionPipeline`, with the body it has at `action.ts:1236-1238` today.
   
   `test/` is outside the count, which scans `<pkg>/src` only.
4. **Package export.** Add `"./promise-actions": "./test/promise-actions.ts"` to `packages/actions/package.json`, the way conductor exports `./memory-tickets`. Then `packages/conductor/unit/{step-matrix,attempt-steps}.test.ts` and `packages/recipe/unit/plugin.test.ts` can import it.
5. **Remove the moved names** from `packages/actions/src/index.ts`.

Each test file's diff is then its import line, as in #1133. **For `runActionPipeline`, use this helper instead of attempt-1's inlined test rewrites.** Take only attempt-1's `packages/actions/src/command.ts`. Do not take its `action.ts`: it exports `portOptions` only to serve the inlining.

`run-attempt.ts:1099` still maps `options.actionsAt(...)` through `fromPromiseAction`. That function is pure, so leave it alone.

## Edges

- **A read that fails through a moved caller:**
  - Where the old wrapper was `Effect.tryPromise`, the typed error goes through `Effect.mapError` with the same message. This applies to `previewSetup`, `applySetup` (`setup/src/apply-setup.ts:79,110`) and `trial-build`.
  - A defect now stays a defect instead of becoming a `SetupWriteError`. Do not add `catchAllDefect` (as in #1117 and #1133).
- **Shutdown and interruption:** the moved callers no longer start a root fiber, so a drain's interrupt reaches the twin. No kept face changes behaviour.
- **Two passes at once, a pause, a retry, a stale page:** these do not apply. No event, projection or snapshot changes.
- **A null or unknown value:** `signedInProbe`'s `checkAuth?.()` optional call is unchanged.
- **Cost to later tickets:**
  - The new test is red only on an entry that reads `#790`.
  - A `0101 §7` entry goes red only if the host file it names is deleted. It does not check that the file still imports the face, so the claudeCodeAuth `why` can go stale silently.
  - `@lingtai/actions/promise-actions` is a test export that a later test can grow onto.
