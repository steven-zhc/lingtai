# #441 — `allowedMoves` and `triageRuns`

## Where it goes

Put it in a new file, `packages/domain/src/moves.ts`, exported from `packages/domain/src/index.ts`. Tests go in `packages/domain/unit/moves.test.ts`. Don't add the functions to `hold.ts`. Its header says *"Types only — there is no event, no appender, no projection here"* (`hold.ts:12-13`), and the next reader will trust that line.

Use `import type` only, for `Hold` from `./hold.ts` and `Move` from `./triage.ts`. A `Move` value is just `{ _tag: 'Approve' }`, so the file needs no runtime import from either module. That keeps it out of the load-order problem `triage.ts:5-11` describes for `events.ts` ↔ `hold.ts`.

## Not Effect's `Match`: the ADR wins over the ticket's Fix row

The ticket says *"Write it with Effect's `Match`, ending in `Match.exhaustive`"*. That can't be done in `@lingtai/domain` without breaking an accepted ADR and a test that is already green:

- 0101 §4: *"**Vocabulary:** `domain` … It imports only `zod`."* §7 also lists `domain` among *"plain functions that Effect code calls"*.
- `packages/domain/unit/hold.test.ts:240-245`, *"declares a dependency on zod and nothing else"*, checks `Object.keys(pkg.dependencies)` against `['zod']`.
- `hold.ts:5-10` already made this same choice: *"Zod, not `Data.TaggedEnum`: 0101 §4 keeps `domain`'s only dependency `zod`"*.

So follow 0101. If someone wants Effect inside `domain`, that is a change to 0101's own topic file. This ticket doesn't make it. The Watch-out row says what `Match.exhaustive` was for: *a `default:` branch would let a new variant through silently*. Get that the plain-TypeScript way:

- Each function is `switch (hold._tag)` with all nine `case`s listed, **no `default`**, and an explicit return type (`Move[]` / `boolean`). With `strict` on (`tsconfig.base.json:12`), a tenth `_tag` in `Hold` makes the switch non-exhaustive. `tsc` then fails with *"Function lacks ending return statement"* (TS2366), and `pnpm typecheck` goes red. Put a one-line comment above each switch saying this is why there is no default, so nobody "fixes" it later.
- Also add a runtime guard in the test file. Read every tag off `Hold.options` (`hold.ts:271`; each option's `shape._tag.value`) and assert the list equals the tags the test table covers. That way a new variant also turns `pnpm test` red, not only the type checker.

The Done-when item *"each ends in `Match.exhaustive`"* is then met in intent rather than in letter. Say so in the commit body, and quote 0101 §4 and `hold.test.ts:240`.

## The tags are flat, so there is nothing nested to match

The Fix row says *"Match on the `Failure` sub-variants where #404's table gives them different moves."* In `Hold` they are already top-level tags: `Hold` is `[Question, ...Judgement.options, ...Failure.options]` (`hold.ts:263-271`). So all nine are `case`s of one switch. Don't branch on any field inside a variant except the two below. The table has one row per variant, except `Human`, which has two rows that give the same moves, and `MergeRefused`, which has two *producers* that give different moves:

- not on `Routed.when`
- not on `MergeRefused.reason`
- not on `SetupRefused.lifts`
- not on `Ceiling.kind`
- not on `Human.step` or `Human.source`
- **on `MergeRefused.afterApproval`** — see below

## The two fields the table needs

### `run.unpushed` stands in for `onOrigin`

Three rows offer Approve *"where `onOrigin !== null`"*: `CheckRed`, `MergeRefused`, and `Routed`. `Routed`'s cell doesn't say so, but the same guard covers it: `stopped === null` makes `judged` true, and `if (!held && judged && onOrigin !== null)` is in `conduct.ts`.

`onOrigin` isn't part of the hold. The nearest fact the hold does carry is `run.unpushed`. `conduct.ts` sets `notPushed` from the publish attempt, and `onOrigin = published` is *"null where origin refused the leased ref … and the head itself where the push went"*.

The other way `onOrigin` can be null is *"null where nothing was committed"*. None of these three variants can be reached without a commit: an `implement` that commits nothing is `DidNotFinish`. So the rule is:

> **Approve is offered on `CheckRed`, `MergeRefused` and `Routed` exactly when `hold.run.unpushed === undefined`** — and, for `MergeRefused` only, when it is also not `afterApproval` (below).

`Human` is **not** gated on it. Its Approve comes from the pipeline's own `ApprovalRequested` (`packages/actions/src/action.ts:795-802`, `artifacts: []`), with no sha condition. The table's cell is just *"Approve, Requeue, Close"*.

### `MergeRefused.afterApproval` tells the two producers apart

`MergeRefused` has two producers, and the table gives them different moves:

- **The pass's own refusal** — `conduct.ts`, via `hold-of.ts:88-104` — refuses a merge nobody has approved yet. `unpushed` decides Approve the same way it does for `Routed` and `CheckRed`.
- **The approval path's refusal** — `approve.ts:391-403` — refuses a merge a person **already approved**: `ApprovalGranted` was appended three lines above (`approve.ts:~324`), `integrate` still refused (conflict or verify-failed), and the result is blocked with `needs: 'acknowledgement'`. `ApprovalGranted` already cleared `task_view.awaiting_sha` (`task-view.ts:703`), so offering Approve here would send a person into `approveHolding`, which refuses `not-awaiting-approval` (`approve.ts:201-209`) because there is nothing left to approve — the dead end `#84` removed. This path is also bound to a sha already on origin, so it never carries `unpushed` either way.

A field on the hold is what makes the two tell-apart-able without reading the stream: `afterApproval: boolean`, added to `MergeRefused` here and set `false` by the pass's producer (`hold-of.ts`) and `true` by the approval path's (`approve.ts`) — the same in-place payload change #445 made to `WorkItemBlocked` itself, and for the same reason: there is no v2 and no upcaster, because before 1.0 the log is reset rather than carried forward (`events.ts`'s *"Reset, not upcast"* comment, and the `BUMPED` comment beside it, both now say so). `allowedMoves` checks `afterApproval` first for this tag — when `true`, the answer is `Requeue, Close` whatever `unpushed` says (it is never set on that path anyway); when `false`, the `unpushed` rule from the paragraph above applies.

This is a mapping from today's code, not something the log has confirmed by itself; the unit tests below, one per producer, are what pins it. `triageRuns` does not change for either producer — both still answer `true`, the same as #404's table. Running one `it` per producer in both describes keeps the table's two rows visible, even though the `triageRuns` numbers happen to agree.

## The table, as the functions answer it

Return the moves in `Move`'s own declaration order: `Approve, Requeue, Close, BodyAndRequeue, Answer` (`triage.ts:131`). Then each test can `toEqual` an exact array.

| `_tag` | `allowedMoves` | `triageRuns` |
|---|---|---|
| `Question` | `Requeue, Close, Answer`. The table's "Withdraw" is `requeue` with no answer, so it is `Requeue`. | **false** (0118 §3: *"the person wrote the question"*) |
| `Asked` | `Requeue, Close`. **Never Approve**: open question 5 says outright *"must not … put `approve` in `allowedMoves(Judgement.Asked)`"*. | true |
| `Human` | `Approve, Requeue, Close`, at either step | true |
| `Routed` | `Requeue, Close`, plus `Approve` when not `unpushed` | true |
| `MergeRefused` | `Requeue, Close`, plus `Approve` when not `unpushed` and not `afterApproval` | true. A conflict past 20 hunks is still a triage, answered `Mechanical` (0118 §8), for either producer. |
| `Ceiling` | `Requeue, Close`. Never Approve. | true |
| `DidNotFinish` | `Requeue, Close`. Never Approve. | true |
| `SetupRefused` | `Requeue, Close` | true, for both `lifts` (open question 8) |
| `CheckRed` | `Requeue, Close`, plus `Approve` when not `unpushed` | true |

**`BodyAndRequeue` is in no row.** 0118 §6 decides the move, but the table's column is *"moves offered today"*, and nothing offers it today. Leave it out, the same way #426's three moves stay out. Whoever builds §6 adds it here, and a test here fails when they do.

`recommendedMove` (#444) then won't recommend triage advice that names it (0118 §1: *"otherwise is not, its words still shown"*). That is correct and is #444's concern.
