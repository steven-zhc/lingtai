## Design note: #1296

This is a words-only change, and the ticket's list is almost complete. It misses one line and leaves out four facts that decide how the edits are made.

**1. There is a fifth *requeue*, and it is in the table the bullets explain.** `doc/concepts.md:45`, the **You** / *Starts over from the base branch* cell, ends with *"This is a **requeue**, and a new attempt begins from the base."* The `Done when` grep catches it, but the ticket's evidence names only `:54` and `:56`. Delete that sentence. The cell already names both moves (*Start a new attempt from base*, *Add to the ticket and start a new attempt*), so nothing replaces it. Then rewrite `:54` and `:56` so their subject is those moves, not a noun for them:
- *Starting a new attempt from base spends no restart.* Keep the board quote word for word.
- *A new attempt is told about earlier ones…* The rest of that bullet stays.

Do not introduce a replacement noun. Retiring the noun is the point (`operating.md:1870`).

**2. The two table rows are hand-aligned, and nothing checks them.** `concepts.md:45` and `tutorial-more.md:29` are padded markdown tables. `pnpm fmt:check` covers only `.ts`, `.tsx` and `doc/events.json` (`package.json:17`), so no tool will re-pad them. After editing a cell, pad it by hand so the row's pipes stay under the header's. At `tutorial-more.md:29`, only the prose cell changes: *"Uses the same account for the AI review."* The `` `--reviewer claude-code` `` cell stays as it is.

**3. The *Handled for you* paragraph uses the board's words exactly.** Those words are:
- the heading *Handled for you* (`apps/board/src/app/report/panels.tsx:515`);
- *N% without you · N needed you* (`apps/board/src/app/handled-card.tsx:93`);
- *one mark per problem … hollow ones needed you* (`handled-card.tsx:50`, `panels.tsx:670`).

Write three or four sentences:
- it is on the home page and on /report;
- each mark is one problem a step raised;
- a solid mark is one Lingtai got past without you (a fix round, a restart, or an automatic merge of the updated base, which spends neither);
- a hollow one *needed you*, and /report lists what you did about it.

Put it after the *Some details that are easy to get wrong* list and before `## When a step stops` (`concepts.md:59`). It explains the same table from the board's side.

Do not explain how the percentage is computed. Code owns that, and a document that restates it goes stale on the next change.

**4. The landing sentence in `tutorial.md` goes after the first run finishes, not at `:47`.** Line 47 is about cost. There, only *cold reviewer* changes, to *AI review*: *"the writer and the AI review"*. The new sentences go where the tutorial first shows a finished run. They say:
- the change merges on its own once your checks at `build:` and the AI review pass;
- to approve each landing first, declare a `human:` at `proposed:` (link `recipe.md`, the section at `:131`).

Do not write `merge:`. A `human:` there is refused when the recipe resolves (`humanPlugin.at` carries only `proposed`, `packages/recipe/src/recipe.ts`), and a newcomer who copies the wrong step gets a daemon that takes nothing.

**5. `when-it-fails.md` does not exist in this worktree.** Item 5 therefore resolves to *leave it*. Add no link and no placeholder.

**Checks:** `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`. No unit test reads these five files: a search for `concepts.md` or `tutorial.md` under `packages/`, `apps/` and `scripts/` finds only unrelated code. So the `Done when` grep is the only check on the words. Run it with `-i`, as the ticket writes it, so it also catches *Requeue* at the start of a sentence.
