# Design note: #597, `doc/requirements.md`

## Where it goes

- **New file:** `doc/requirements.md`.
- **Two links to it:**
  - In `doc/tutorial.md`, one sentence under *Before you start* (`doc/tutorial.md:8`). Leave the table's `Lingtai` row short and point to the page for everything else.
  - In the README. Put it next to the install instructions, not inside the *Nothing is sent anywhere* row (`README.md:40`). That row is about privacy. The new page should link back to it for the network endpoints and not copy its prose.
- **Nothing in `doc/zh/`.** The only file there is an ADR translation.
- **No code changes.** `pnpm fmt:check` only globs `.ts`/`.tsx` (`package.json:15`), so the new page cannot turn it red.

## The decision: the inventory can't come from a grep for binary names

The ticket says "inventory from the code". A grep for `spawn('git'…)` or `execFileSync('ps'…)` under `*/src` finds only a few names. Most spawns take the binary name from a variable, and each one has to be traced back to where the name comes from:

| Spawn | Where the name comes from |
|---|---|
| `git` | Almost every call goes through the `git()` wrapper (`packages/repo/src/git.ts:44`). Only `init.ts:1007` calls `git` directly. |
| `claude` / `codex` | `spawn(binary, …)` at `packages/agent/src/claude-code.ts:431` and `packages/agent/src/codex.ts:1181`. The sign-in probes are `packages/agent/src/auth.ts:31` (`auth status`) and `:95` (`login status`). The sign-in is the **account** row for each runtime. |
| `launchctl` / `systemctl --user` | `call[0]` at `apps/cli/src/service.ts:430`. The comment at `service.ts:31` says *"each verb is one or two calls to `launchctl` or `systemctl --user`"*. |
| `terminal-notifier` / `osascript` | Desktop notifications, `apps/cli/src/notify.ts:95`, `:128`. Optional: it only affects how a notification is shown. |
| `opener` | `apps/cli/src/lingtai.ts:612`, `init.ts:1054`, `first-project.ts:663`. This opens a browser. Trace which binary it resolves to before naming it. |
| `$EDITOR` | `apps/cli/src/ticket.ts:87`, run through `sh`. |
| `tar`, `ps`, `lsof` | `tar` and `lsof` at `apps/cli/src/install.ts:404`, `:802`, used by install/upgrade on an installed copy. `ps` at `install.ts:770`. |
| `ps` (runtime) | `packages/agent/src/codex.ts:72`, `:118` and `packages/daemon/src/reconcile.ts:565`, used to find a leftover agent. Required on every path. |

### Three spawns that must not get a row of their own

1. **`apps/release/src/*` and `apps/cli/src/sea-build.ts`** call `bun`, `pnpm exec next build` and `node --build-sea` (`apps/release/src/build.ts:43`, `:84`, `apps/release/src/binary.ts:80`). They are there to *build Lingtai*, not to run it.
   - Put them, if anywhere, in one line under the source-checkout column ("building a binary needs …").
   - Do not list them as things a user must install.
2. **`packages/actions/src/command.ts:403`/`:415`** (`spawn(options.run…)`) and **`packages/conductor/src/conduct.ts:490`** run the recipe's own `run:` commands and the environment script.
   - Whatever those commands call (`npm`, `pnpm`, …) belongs to the **managed project**. This is the ticket's Chapter Garden trap in code form.
   - Give it one sentence: "your recipe's commands need what your project needs".
3. **Anything under `unit/`, `integration/` or `test/`.** The ticket already says so; it is repeated here only because the grep picks those files up too.

## Columns

Use one table, or one table per group (binaries / services / accounts). Columns:

- **What**
- **Needed when.** Use the ticket's axes: `--local` vs GitHub, SQLite vs Postgres, `claude-code` vs `codex`, installed vs checkout. Write "always" where none of them applies.
- **Minimum version**
- **Why**
- **`doctor` check**
- **Where.** A `file.ts:line`.

## Minimum versions: only two are enforced, and one only on one path

- **Node ≥ 26.**
  - Enforced for a **source checkout**: `package.json:8-9` (`"node": ">=26"`), `.node-version` (`26`), and `doctor`'s `node: at or above the floor` (`apps/cli/src/doctor.ts:2489`).
  - Not needed for an **installed copy**. `doctor.ts:2485` says *"the binary carries the Node it was built with"*. Node is required for the checkout only.
- **pnpm.** `packageManager: pnpm@11.9.0` (`package.json:7`) applies to a checkout only. Write it as pinned by `packageManager`, not as a floor that is checked.
- **Git ≥ 2.38.**
  - Enforced only in `conflictedPathsAt` (`packages/repo/src/mirror.ts:158-161`): *"git merge-tree --write-tree requires git 2.38 or later"*. That is the conflict-triage path.
  - `init` only checks that `git --version` runs (`init.ts:1007`).
  - So the row should read "any recent; 2.38+ for conflict triage". Do not write a flat 2.38.
- **Everything else:** "any recent", as the ticket says.

## `doctor` column

Use the literal check names from `apps/cli/src/doctor.ts`. They are listed below with line numbers so each one can be checked.

- **Names that apply here:**
  - `node: at or above the floor` (2489)
  - `postgres: pooled connection` (317)
  - `postgres: direct connection is session mode` (322)
  - `github: installation and labels` (883)
  - `daemon: liveness` (997), for the service manager
- **The release check.** The README says `doctor` asks the Releases API (`README.md:40`). Find the check that does this and quote its name.
- **No visible check for git, `claude`/`codex` presence or sign-in, or `ps`.** I found no check named for them. Confirm by searching `doctor.ts` for `auth`, `codex`, `claude` and `git --version`.
  - If there is no check, write **"none"** in the column.
  - Do not name `init`'s probe or `auth.ts`'s probe as a `doctor` check. The ticket says to name the check that reports it, so for these rows the honest answer is that no check does.

## Network and accounts

- **Endpoints:** take them from `README.md:40` and cite it. That row lists:
  - the Releases API, plus the release-artifact download on `upgrade`
  - the GitHub API for the repository
  - the agent's own provider
  - Telegram, only when a `telegram` subscriber is configured
  - the database URL, if it is Postgres
- **Accounts:**
  - The GitHub App, on the GitHub path only. Link #596's tutorial section for setting it up.
  - The `claude` or `codex` sign-in, whichever runtime is chosen.
  - Postgres credentials, if that store is chosen.
  - A Telegram bot, optional.
- **`--local`:** no GitHub row applies. Check this against what `--local` actually skips in `init.ts` before writing it.
