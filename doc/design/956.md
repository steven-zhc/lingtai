# #956: the shape

Line numbers in the ticket are from before #954, #955 and #960 landed. They have moved, and two of the things the ticket's **Fix** asks for already exist. This note works from the code as it is at `87a45e54`.

## What is already there, so do not build it again

- **Do not add `epics: Map<string, { title; subIssues }>`.** #955 already gave `GithubQueue` the field `epics: EpicTicket[]` (`apps/board/src/lib/board.ts:1050-1051`). It is filled from the `epic` skips at `board.ts:1121-1130` and carries `project, ref, title, kind, kindColor, closed, total`, where `closed` is `s.subIssues.completed`. That is everything the group head needs. Build the `project#ref` lookup inside `groupQueue` from the array.
  - Every epic reaches that array. `considerIssue` returns `skip: 'epic'` *"before any label is read"* (`packages/conductor/src/discover.ts:216-218`), so an epic that carries `agent:hold` or has open blockers is still an `epic` skip and never an `excluded-label` or `blocked-by` one.
  - `isEpic` is `total > completed` (`discover.ts:74-76`), so `total ≥ 1` whenever an `EpicTicket` exists and the ring never divides by zero.
- **Only `parents` is new on `GithubQueue`.** Build it in `githubQueue`'s per-answer loop (`board.ts:1101-1201`):
  - Take entries from `answer.offered.runnable` and `answer.offered.skipped`, never from `answer.runnable`. `selectRunnable` returns a `Runnable` that carries no parent (`packages/conductor/src/queue.ts:71`). `offered.runnable` also still lists a ticket the log holds back (`discover.ts:286-294` carries `parent` on it), which is how a log card joins.
  - The `blocked-by` skips' parents come off the same `offered.skipped`. `BlockedSkip` carries no parent (`board.ts:765-773`), so join it by `project#ref` and do not widen the type.
- **The same-repository test is `answer.filter.links`** (`packages/conductor/src/filter.ts:202`, `Pick<GitHubClient, 'listBlockedBy' | 'owner' | 'repo'> | null`).
  - Keep a parent only when `links !== null` and `parent.repository` equals `` `${links.owner}/${links.repo}` ``.
  - Compare **case-insensitively**. `parent.repository` is the `o/r` segment cut out of `parent_issue_url` (`packages/github/src/client.ts:511-516`), which is GitHub's spelling of the name. `links.owner` is whatever `lingtai add` recorded. GitHub treats the two as one name, so an exact match would silently ungroup a whole project.
  - A `db` project has `links === null`, so it gets no parents and no groups. That is the right answer.

## `groupQueue` returns a sequence, not kind groups

Today `QueueGroup` is `{ kind, cards, next }` (`board.ts:1669-1686`), and `groupQueue` buckets by kind (`board.ts:1706-1726`). Replace it with this signature:

```ts
groupQueue(cards, blocked, order, parents, epics, markNext): {
  entries: QueueEntry[]   // in render order, ungrouped blocked cards last
  next: string | null     // the taskId *taken first* goes on
  headed: Set<string>     // `project#ref` of every epic that heads a group
}
type QueueEntry =
  | { type: 'card'; card: BoardCard }
  | { type: 'epic'; epic: EpicTicket; cards: BoardCard[]; blocked: BlockedTicket[] }
  | { type: 'blocked'; ticket: BlockedTicket }
```

The discriminant is `type` and not `kind`, because `kind` already means the ticket's kind on every type involved.

**Today's order is one comparator, used everywhere.** It sorts by kind rank, then by `byIssueNumber` (`board.ts:1733-1736`).

- Kind rank is the kind's index in `order`.
- A kind `order` does not name ranks after every kind it does name, in the order such kinds first appear. That preserves what `queued.test.ts:97-100` pins.
- A blocked ticket with `kind: null` ranks with the kinds `order` does not name.
- `byIssueNumber` takes `BoardCard`, whose `ref` is a string. `BlockedTicket.ref` is a number. Write the comparator over `{ kind, ref }` so it serves both.

**The walk:**

1. Pool every runnable card, plus every blocked ticket whose parent resolves to a known epic. Sort the pool with the comparator.
2. Visit the pool in order. On the first member of epic E, emit E's whole group: its cards, then its blocked tickets, each sorted with the same comparator. Skip E's members after that. A member with no epic is emitted as `card`.
3. Append every ungrouped blocked ticket as `blocked`, sorted with the same comparator. This is #960's *below every runnable card and group*.

**Group key.**

- The group key is `${project}#${parentNumber}`, and so is the epic lookup. Groups therefore never span projects.
- A card joins as `parents.get(`${card.project}#${card.ref}`)`, then `epics` must hold that key. This covers both the log's cards and GitHub's.
- A parent that is not in `epics` leaves the child ungrouped. That one rule covers four of the ticket's edges: a parent missing from the listing, a parent in another repository (it never entered `parents`), a parent that is not an epic, and a parent with no summary.
- Only the direct parent is ever read, which is the ticket's nested-epic rule.

**`next`.** It is the `taskId` of the first card in the *sorted pool* (not the emitted sequence) with `runnableAt === null`. It is null when no card has that, or when `markNext` is false.

- This is the same predicate as today's `board.ts:1723`, moved from a group onto a card. The `queued.test.ts:84-89` case (a backed-off bug does not get the mark) stays and is reworded.
- Because the mark is taken from the pool's order, it can land on a card inside a group that sits lower on the page, when an earlier-kind blocked child pulled that group up. That is the ticket's last `queued.test.ts` case.

## Rendering moves into `queued-stream.tsx`; `ListQueued` draws one card

The two halves of a group are drawn in different files today:

- `Card` is in `page.tsx`, reached through the `list` render-prop (`apps/board/src/app/queued-stream.tsx:31-42`).
- `BlockedCard` is in `queued-stream.tsx`, drawn *after* `list(...)` returns (`queued-stream.tsx:297-308`).

An epic group interleaves the two, so one loop has to own both.

- **Change `ListQueued` to render a single card:** `(card, showProject, next: boolean, arrive: boolean) => ReactNode`.
  - `page.tsx`'s `Queued` (`page.tsx:576-615`) shrinks to that function. Its `.qgroup` heading goes, because the kind headings go.
  - `Card` (`page.tsx:181`) gains a `next` prop. When it is true, `Card` appends `<span className="qnext"> — taken first</span>` at the end of its `.id` line (`page.tsx:255`). This is the existing text and class (`page.tsx:604`, `apps/board/src/app/globals.css:692`).
- **The loop goes in a new `QueuedList` in `queued-stream.tsx`.** It walks `entries` and draws, per entry:
  - a `card` as `card(...)`;
  - an `epic` as a `<section className="egroup">` holding the head, then `card(...)` for each runnable card, then `BlockedCard` for each blocked ticket;
  - a `blocked` as `BlockedCard`.

  `queued-stream.tsx` has no `"use client"`, so it is a server module, and a `Map` in its props never crosses a client boundary.
- **`QueuedAnswered`** calls `groupQueue(cards, drawn, order, github.parents, github.epics, true)` and hands `HeldFold` only the epics that head no group: `github.epics.filter((e) => !headed.has(`${e.project}#${e.ref}`))`.
  - The summary line, `Problems`, the notes and the `+N more waiting on a blocker` line stay as they are.
  - **Decision:** only `drawn` blocked tickets (`!unread`, `queued-stream.tsx:270`) are grouped. An `unread` one stays in the `+N more` line and is not counted in any group, so a group's `blocked` figure is the number of blocked cards it draws.
- **`QueuedFallback`** calls `groupQueue(logCards, [], order, new Map(), [], false)`. That gives log cards only, in today's order, with no groups and no mark: the ticket's `QueuedFallback` edge.
- **Both components now need `order`.** `page.tsx` has it as `queueOrder` at both call sites (`page.tsx:893-922`); pass it as a prop.

**The head**, from the mock (`doc/design/queued-blocked.html`, the `ring-then` view):

## Edges

- **GitHub answered for some projects only.** An unanswered project contributes no entries to `parents`, so its log cards are ungrouped. This is the same *a failure costs a dot, not a card* rule as `board.ts:1133-1135`.
- **An epic whose children are all running or closed.** It has no member in the pool, so it heads nothing, is absent from `headed` and stays in the fold. It needs no special case.
- **A held child** is an `excluded-label` skip. It is never in the pool, so it stays in the fold.
- **A stale page.** There is no new freshness question. `parents` and `epics` come from the same `runnableNow` call the cards do (`board.ts:861`), so they can never disagree with the cards they group.
- **Restart, two passes, pause, retry.** None applies: this is a render over one answer, with nothing appended and nothing cached. `readBlockers`' cache (`board.ts:780-784`) is untouched.
- **The cost to later changes.**
  - Every literal `GithubQueue` in `apps/board/unit/render-cost.test.ts`, `unit/blocked-skips.test.ts`, `unit/queued-stream.test.tsx` and `unit/ask-project-ownerless.test.ts` needs `parents: new Map()`. #955 paid the same toll for `epics`.
  - The `list` stub in `queued-stream.test.tsx:25-26` changes shape with `ListQueued`. Keep it a string stub that renders one card per call, so those tests still assert order without importing `page.tsx`.
