# Design note for #987

The ticket's shape holds against the code. This note only records what the ticket leaves open.

**`after` is computed in the same `STEPS.map` as `settings`** (`apps/board/src/lib/recipe-lines.ts:81-107`).
- Test for the review agent the way `:98` tests for implement's: `declared.some((a) => kindOfAction(a) === 'agent')`, on `declared` and not on the filtered `actions`.
- Keep the plural and number formatting in small local helpers in this file, not in `step-says.ts`.
- `recipe-lines.ts` imports `readRecipe` from `./recipe.ts` (`:13`), so the add page must not start importing it. `setup-form.tsx:13` imports only `step-says.ts`, and that stays true.

**Decisions the ticket does not state:**
- A review agent with a `when:` still gets `reads at most`. The line says what the agent reads when it runs, and the condition is already drawn on the action (`page.tsx:66-75`).
- Several agents at `review` still produce one line, because the limit is per reader and not a shared pool.
- Draw `after` through the existing `Value` (`page.tsx:46-63`) with `key={line.label}`, and do not add a second row component. The three new labels are not in its mono list (`:59`) and their values are not in `MUTED` (`:43`), so they fall through to the plain `<span>` at `:62`.
- `value` stays one string, `up to 2,000 characters of output · 5 review findings`. Do not add `chips`, which would draw it as pills (`:47`).

**Existing tests:**
- `apps/board/unit/recipe-lines.test.ts:76-77` asserts `toMatchObject({ settings: [], actions: [] })` for `review` with no agent, and `implement` is not in that list. An added `after` field does not break it.
- A search of `apps/board` found the four old sentences only in `step-says.ts`, so no test there needs rewording. I did not search outside `apps/board`.
- The caption strings at `page.tsx:142` and `:146` are literals on this page only. The `'rounds'` and `'restarts'` strings in `board.ts`, `task.ts` and `report.ts` are other things, so leave them alone.

**What can be checked before the merge:**
- `after` and its singular forms are unit-level, in `recipe-lines.test.ts`, and `pnpm test` covers them.
- `COVERED` lives in `page.tsx`, so only `apps/board/integration/recipe.test.tsx` sees the `budget` row disappear. Run that one file as the ticket says, never the whole integration half.
- `pnpm fmt:check` and `pnpm lint` also run at `build`, so run them before committing.

The change adds no `async` function or `Effect.run*`, so the ratchet baseline does not move. It contradicts no ADR.
