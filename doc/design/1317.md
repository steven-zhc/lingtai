## Design note: #1317, learning that the open PR merged or closed

### Where it goes

| Piece | File |
|---|---|
| `PrMerged`, `PrClosed`, two statuses, two transitions | `packages/domain/src/events.ts`, `packages/domain/src/pr.ts` |
| `recordPrMerged`, `recordPrClosed`, the draft fix | `packages/project/src/pr.ts` |
| `getPull(number)` | `packages/github/src/client.ts` |
| The read, the reaction, `sweep` | `packages/conductor/src/pr.ts` |
| The loop calls `pr.sweep` | `packages/daemon/src/work-loop.ts` |
| A ticket channel port | `apps/cli/src/pr-ports.ts` |
| *merged* / *closed* | `apps/cli/src/pr.ts` |

### 1. The ticket is wrong about the draft: fix it here

The ticket says *"the draft computation of #1316 already counts a `closed` PR as holding nothing"*. It does not. `readPrDraft` skips only refused PRs (`packages/project/src/pr.ts:286`):

```ts
for (const pr of yield* listPrs(project, store)) {
  if (pr.status === 'refused') continue
  for (const t of pr.tickets) held.add(t.ticket)
}
```

Add `|| pr.status === 'closed'`. Without it, a `PrClosed` keeps holding its tickets. The next Submit then finds nothing to freeze and is refused `nothing-landed` (`packages/conductor/src/pr.ts`, `freezePr`), and the *Done when* box "the new PR is `n+1` holding the closed PR's tickets" cannot pass. A merged PR keeps holding its tickets, as it does today.

### 2. Domain: two terminal statuses

- Add `'merged' | 'closed'` to `PrStatus` (`packages/domain/src/pr.ts:15`). `isOpen` lists the four open statuses explicitly (`:154`), so it needs no change and both new ones are terminal. `requestSubmit` (`:184`) then accepts the next Submit.
- Add `ended: { how: 'host' | 'git' | null; headSha; mergeSha; seq } | null` to `PrState`. The reaction needs `ended.seq` for its key. `lingtai pr` needs `ended` and the envelope's `at`.
- The transitions, pure, beside `pushedTransition`:
  - `mergedTransition(state, …)`: null unless `isOpen(state)` and `state.status !== 'requested'`.
  - `closedTransition`: the same rule, and also needs `state.host !== null`. Only the host can say a PR is closed.
  - A PR that is already merged or closed gets nothing from either. That is how *the transition, never the state* and *both readers in one sweep* are both met.
- `walkPr` needs no edit. It re-reads and stops unless the status is `in-progress` (`packages/conductor/src/pr.ts`, `walkPr`). `pushedTransition`, `draftOpenedTransition` and `openedTransition` all refuse unless the PR is walking. So *merged while In progress* already holds.
- Append through new `recordPrMerged` and `recordPrClosed` in `packages/project/src/pr.ts`, using `transitionPr`. That file's header says *"nothing else appends to a `pr-` stream"* (`:8`), and `transitionPr` re-reads and asks again once when it loses a race.

### 3. The read: one decision table, host first

`getPull(number)` goes on the `GitHub` face next to `findOpenPull` (`client.ts:321`), wrapped in `asPullCall('read', …)` (`:734`) so a 403 becomes `PermissionDenied`. **Decode it strictly in the client.** If `merged` is not a boolean or `state` is not `open`/`closed`, it fails with a `GitHubFailed`. It must never come back as `merged: false`. `RawPull` (`:157`) has no `merged`, `merge_commit_sha` or `updated_at`, so give `getPull` its own return type and leave `OpenPull` alone.

For the project's latest PR, when `isOpen` is true and its status is not `requested`:

| Host answer (only when `prHostOf(recipe) === 'github'` and `state.host !== null`) | Git: `lastPushed` is an ancestor of `refs/heads/<main>` | Append |
|---|---|---|
| `merged: true` | any | `PrMerged { how: 'host', mergeSha: merge_commit_sha }` |
| not merged, or the read failed | exit 0 | `PrMerged { how: 'git', mergeSha: null }` |
| `state: 'closed'`, `merged: false` | exit 1 | `PrClosed` |
| `open` | exit 1 | nothing |
| the read failed | exit 1 or not run | nothing (say it in the log) |

- **The git row comes before `PrClosed`, on purpose.** Say the team merged the PR branch into `main` by hand and then closed the PR on GitHub. 0130 §5 calls that merged ("from git, when the PR's head is reachable … or from the code host"), so git's *yes* beats the host's *closed*.
- `state.main` is `branch.main` as it was at the freeze (`PrInProgress.main`). Use it rather than today's recipe.
- Git is read through `ports.git`: exit 0 is yes, 1 is no, anything else is a failed read (the same rule as `freezePr`). On GitHub nothing extra is fetched. Off GitHub, call `ports.fetch` once per sweep, and only for a project whose latest PR is open.
- A `404`, a `PermissionDenied`, a `5xx`, a decode failure or a failed fetch logs one line through `ports.log` and appends nothing. **Never append `PrWaiting` here**: `waitTransition` refuses a PR that is `in-review`, and this read is not a step.
- *Stopped early*: keep a `Map<string, string>` of `updated_at + head.sha` per `pr-{project}-{n}`, inside the `makePrHandlers` closure (`pr.ts:509`). When the key is the same as last time, skip whatever comes after the read (nothing yet; #1339's checks later). Still run the git row every time: it costs nothing, and the mirror may have moved while GitHub's answer did not. The map is empty after a restart, as the ticket says.

### 4. The reaction: closing the tickets, and which channel

**Where it closes them is the trap.** Never hand `tellGitHubEffect` the raw GitHub client. `converge.ts:125-143` explains why: if a `db` project's ticket numbers are asked of GitHub as issue numbers, Lingtai *"can … close, an unrelated GitHub issue that happens to share the number"*.

- Add a `tickets(project): Effect<IssueChannel, Error>` port to `PrPorts`. In `pr-ports.ts`, build it from the project's resolved client: `projectClientEffect` (`filter.ts:377`), or `ownerlessClientEffect` (`ownerless.ts:49`) when there is no owner.
- If the channel cannot be built, close nothing in that sweep and log it. The next sweep tries again.

The key: for each `t` in `state.tickets`, the ticket id is `ticketStream(project, t.ticket)`, because `t.ticket` is the issue number (`readPrDraft` pushes `ticket: issue`). Read that ticket's stream. Skip the ticket if it has `IssueUpdated { change: 'closed' }` (`events.ts:2080`) with `seq > ended.seq`. Otherwise call `tellGitHubEffect({ … change: { kind: 'closed' } })` (`tell.ts:169`). An `IssueUpdateFailed` is simply not the key, so the next sweep retries it.

When it runs: straight after a `PrMerged` this sweep appended, and on every sweep for the project's **highest-numbered merged PR**. That bounds the per-sweep reads to one PR's tickets, not every merged PR there has ever been. A merged PR is followed by `n+1` only, so a leftover can survive only if a kill hits between closes *and* `n+1` merges before the next sweep. Accept that, and say so in the code comment.

### 5. The loop: extend `pr`, do not add a delivered `prSweep`

The ticket's Fix 3 says to run it "through `deliver`". **Don't.** The sweep also re-serves PRs whose step answered `again`, which is `servePendingPrs` (`pr.ts:481`). That is a walk that pushes, and could take minutes. The loop's own comment says a walk is not delivered (`work-loop.ts:300-305`): *"a walk longer than `SUBSCRIBER_TIMEOUT_MS` is never recorded as a failed plugin"*.

So:

- `makePrHandlers` returns `{ serve, resume, sweep }`. `sweep` means: list the projects, run `servePendingPrs`, then for each project do the read (§3) and then the reaction (§4). One project's failure is that project's, as in `servePendingPrs`.
- In `start()`, the startup block (`work-loop.ts:661-670`) calls `options.pr.sweep()` instead of `resume()`, still through `passesInFlight.track`.
- The timer (`:672-680`) does `kick('sweep')` and also starts `pr.sweep()` the same tracked way as `trackWalk` (`:431-441`). Starting it uses `Effect.runPromiseWith(services)`, which is what `trackWalk` already does and which the ratchet does not count.
- Add a boolean in-flight guard: a tick that finds the last sweep still running starts nothing.
- **Do not ask `options.paused` or `options.shutdown`.** `drain` asks both (`:539-552`); the sweep never goes through `drain`. After `stop()`, the timer's scope is closed (`followScope`), so no new sweep starts.

This is a deliberate departure from the ticket's edge "a drain does not wait for it". The sweep is tracked, so `stop()` waits for it: a sweep that may push must not be cut off halfway. A sweep that only reads takes about one request per PR. A walk is already bounded by the wall today.

Wiring: `apps/cli/src/daemon.ts:679` stays as it is, apart from the `tickets` port in `livePrPorts`.

### 6. `lingtai pr`

Today it only describes an open PR (`apps/cli/src/pr.ts:75`, `const open = latest !== null && isOpen(latest) ? latest : null`). Add a branch for `latest.status` being `merged` or `closed`. Print one line: the status, `host.number` if there is one, `ended.how`, and when (the envelope's `at`). Then print the draft as it already does. Add an `ended` key to the JSON output.
