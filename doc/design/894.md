# #894 — design note

The ticket gives the shape. This note records four decisions it leaves open, and one check that cannot run before the merge.

## 1. Landing fix rounds come from `rounds`. `by_run` holds only diff and summary

The reducer already counts fix rounds per run. `RunSpent` pushes the key `${event.streamId}:${d.for.round}` into `s.rounds` when `d.for.round >= 1` (`packages/projector/src/ticket-report.ts`, the `RunSpent` case, about `:461-465`). `fix_rounds` is `s.rounds.length` (`save`, about `:252`). The attempt stream id is the run id: `paid` holds `event.streamId`, and `unknown_claims` compares it to `c.runId` (`:256`).

So set `landing_fix_rounds` = the number of `s.rounds` keys whose part before the last `:` equals the landing run id. Do not add a `fixRounds` counter to `by_run`. A second counter is a second rule for the same number, and the two drift apart the first time one of them changes.

`by_run` then holds `{ [runId]: { diff: { files, insertions, deletions } | null, summary: string | null, clipped: { read, of } | null } }`.

- **Load and save:** `load` reads `by_run` with `json(row.by_run, {})`, the same way `paid` and `rounds` are read. `save` writes it as `$n::jsonb`.
- **Default:** `fresh()` gets `byRun: {}`.

## 2. Two new `case`s in the reducer. `RunProducedDiff` must stay a sign of life

**`RunProducedDiff` today.** No `case` names it, so it falls to the attempt-stream branch at `:483-493`. That branch marks a sign of life, saves, and `continue`s. The new case must:

- set `ticket = await ticketOf(ctx, event.streamId)`;
- set a `change` that writes `by_run[event.streamId].diff`.

The generic path then still calls `signOfLife(s, event, event.streamId)` at `:504`. If that call is lost, `machine_ms` and `intervals_empty` change for every ticket. The existing `ticket-report.test.ts` interval cases pin this, so keep them green without editing them.

**`StepEnded`** already resolves the ticket through `d.runId` (`:418`). Inside the existing `review` branch, also write `by_run[d.runId]`:

- `const r = reviewSummaryOf(d.outcome)` (`packages/domain/src/action.ts:400-416`);
- `summary = r?.summary ?? null`;
- `clipped = r?.clipped ?? null`.

**The last review overwrites, and a null overwrites too.** Events reduce in seq order, so "last by seq" means "last written". If a fix-round re-review wrote no summary, an earlier summary would describe a diff that no longer exists. A null that shows a line on the page is the honest answer. This is the ticket's *several reviews* edge.

**`TicketLanded`** keeps `endIntervals` and also copies the landing facts:

- `const c = s.ticketState.claims.at(-1)`. `s.ticketState` has already been reduced past the landing when `change` runs (`:497-500`).
- `landing_run = c?.runId ?? null`.
- `landing_attempt = claims.length`, or null when there are no claims.
- Then `by_run[c.runId]`, with diff columns null (not zero) when `diff` is null.

## 3. Column types

| Column | Postgres type |
|---|---|
| `landing_run` | `text` |
| `landing_attempt`, `landing_fix_rounds`, `diff_files`, `diff_insertions`, `diff_deletions` | `integer` |
| `summary` | `text` |
| `summary_clipped` | `jsonb` |
| `by_run` | `jsonb not null` |

All new columns except `by_run` are nullable.

`summary_clipped` stores `{ read, of }` rather than a boolean. It is the shape `reviewSummaryOf` returns, and the page can then say how much was read. `sqlite.ts:213-214` rewrites `jsonb` to `text`, so it needs no SQLite-specific DDL.

**Mapper.** `ticketReportRowOf` reads every new reader column through `columnOf(row, TICKET_REPORT_TABLE, '…')` (`store.ts:145-147`). That means `/report`'s `select *` also throws `ProjectionShapeError` until the rebuild, which is the edge the ticket accepted.

`title` and `mergeCommit` are decoded from `ticket_state`:

- Use `decodeTicket(row.ticket_state, TICKET_REPORT_TABLE, ticket)`, the decoder the reducer already uses (`:487`). Do not hand-parse the JSON.
- `title` is `t.title`.
- `mergeCommit` is the landed lifecycle's `mergeCommit` (`packages/domain/src/ticket.ts:168`), and null when the outcome is not landed.

## 4. `landed()`: the cursor and the cap live in the store

Add `TicketReportLandedQuery = { project?: string; before?: { at: Date; ticket: string }; limit: number }` beside `TicketReportQuery` (`store.ts:237-240`).

**Limit.** Clamp it to `1..100` in both stores, not in the caller.

**Cursor value.** `before.at` is bound as a `Date` on both stores:

- Postgres: as `$n::timestamptz`.
- SQLite: `sqlite.ts:146` turns a `Date` into `toISOString()`. That is the format `save` already wrote, because `outcomeAt` (`t.since`) is a `Date` bound by the same path.

Do not format the timestamp by hand anywhere.

**Comparison.** Use the row-value compare `(outcome_at, ticket) < (…, …)`. It works on Postgres and on SQLite 3.15 or later.

**Columns.** List the selected columns in one exported constant in `ticket-report.ts` and use it from both stores. That keeps the two queries twins, and a named column the table lacks fails with SQL's own error. To make it the shape error instead, wrap that error the way `columnOf` does. Recommended: select the named columns, map through `ticketReportRowOf`, and let a missing column surface through the shape check. The shape check is what the daemon runs at start.

**Index.** Add `create index if not exists ticket_report_landed_idx on ticket_report (outcome, outcome_at desc, ticket)` in `create()` (`:354`). On SQLite, `desc` in an index is accepted as written.

## 5. `readBacklog({ taskIds })`

- Add `taskIds?: readonly string[]` to `BacklogQuery` (`store.ts:226-230`) and to `ReadBacklogOptions` (`backlog.ts:277-283`), and pass it through at `backlog.ts:295-299`.
- Each store adds `task_id in ($a, $b, …)`, with one placeholder per id (SQLite's loop is at `sqlite.ts:706-717`).
- **An empty array returns `[]` without a query.** `in ()` is a syntax error on both engines.
- An absent `taskIds` filters nothing.
- `task_id` is the ticket stream id (`backlog.ts:120`), the same string as `ticket_report.ticket`.

## Tests, and what runs before the merge

`test/contract.ts` is the both-stores suite, but only `integration/` imports it (`packages/projector/integration/projection.test.ts`, `integration/sqlite.test.ts`). Under CLAUDE.md, nothing in a pass runs that half. `unit/ticket-report-read.test.ts:1-5` already says so about `ticketReport`: *"its query is not run by any test: `test/contract.ts` has no `ticketReport` case."*

So:

- **SQLite `:memory:` unit tests.** Put the `landed()` claims (newest first, `before` paging, tie on `ticket`, no open or closed rows, limit clamp) and the `taskIds` claim in `unit/ticket-report-read.test.ts`. Use `createSqliteProjectionStore(openSqliteProjections(':memory:'))`, as that file already does, and a backlog-reduce fixture for the backlog case. These are the claims that can be checked before the merge.
- **Postgres twin.** Also add matching `landed` and `taskIds` cases to `test/contract.ts`. They run after the merge (T11). Until then the Postgres query is checked only by `pnpm typecheck` and by being the same column list and the same `where` as the SQLite one, so keep them textually parallel.
- **Shape test.** Create the table with the old DDL, then read through `store.ticketReport({})` and `store.landed(…)`. Assert `ProjectionShapeError` and the message `lingtai projection rebuild ticket_report`. `unit/drift.test.ts` shows how to build an old-shaped table.
- **Reducer test.** It goes in `unit/ticket-report.test.ts`:
  - claim run A, with `RunProducedDiff` and a review;
  - claim run B, with a `TicketContinued` of B, then two `RunProducedDiff`s and two reviews, where the second review is at round 1;
  - a `RunSpent` with `for.round = 1` on B, then `TicketLanded`.
  
  Assert `landing_attempt = 2`, B's last diff, the round-1 review's summary, and `landing_fix_rounds = 1`.
