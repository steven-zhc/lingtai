## Design for #1309: a team landing leaves its issue open and carries `lingtai:landed`

Read at `552c8fbe3`, after #1306 merged (`d3ddbfc0f`). The ticket's citations were taken at `76adf624a` and most have moved. The current ones are below. The ticket's shape stands. This note covers only what it leaves to be decided, plus three places the code disagrees with it.

### 1. The team test cannot get past #1306's refusal unless this diff opens a way

The refusal is inside `runOnce` itself (`packages/conductor/src/conduct.ts:1116-1127`, in `runOnce` at `:876`). Its comment says *"#1310 deletes this refusal, once a team pass leaves a landed ticket open (#1309) and takes only the person's own tickets (#1310)"*. The test that pins it is `packages/conductor/unit/conduct-a-whole-attempt.test.ts:318`. So the ticket's first *Done when* (a team pass the lane merged) can't be reached through `runOnce` while the last one (the refusal still holds) stays green.

**Decision:** add one optional field to `RunOnceOptions`, `landTeamTickets?: true`, with a doc comment saying it exists only until #1310 deletes the refusal and the field with it. Read it only in the `if` at `:1116`, as `modeOf(recipe) === 'team' && options.landTeamTickets !== true`. Nothing in `apps/` passes it, so every real pass is still refused, and the `:318` test stays green untouched. The new team tests pass it. Do not change what the refusal says.

### 2. `end` gets the mode passed in; it does not re-read the recipe

- **The `end` body** is `attempt-steps.ts:940-962` and resolves at `:957`. Put the mode in the ports/deps object the body already closes over, set from `modeOf(recipe)` (`packages/recipe/src/settings.ts:255`) where `conduct.ts` builds those ports. Filter `actions` just before `resolveEndActions(events, actions, outcome)`.
- **The pure filter** goes in `end-step.ts` beside `resolveEndActions`. It is the only place that knows the rule.
- **`recordEndPlanEffect`** (`ticket/commands.ts:1105-1119`) gets a **required** `mode: 'solo' | 'team'` parameter, applied before `resolveEndActions` at `:1114`. Required on purpose: an optional one lets a forgotten caller close a team issue without anyone noticing.
  - Its one caller is `apps/cli/src/end.ts:116`, which already holds `resolved.recipe`, so it passes `modeOf(resolved.recipe)`.
- **Leave alone** the other two `resolveEndActions` callers, `ticket/commands.ts:830` (`'closed'`) and `:962` (`'satisfied'`). The rule only touches `landed`.
- **Leave the satisfied ending alone too.** It still calls `labelsFor('landed')` (`conduct.ts:6263`), and it still makes the unconditional close at `:6268-6269`, whose comment says *"a satisfied ticket is terminal with nothing else to finish it (#1263)"*. That is the ticket's satisfied edge, already true in the code. The only call site that changes is the landed ending's `labelsFor('landed')` at `conduct.ts:6204`.

### 3. Converge has no recipe where it judges labels: carry `branch.main` on the client

`findIssueDriftEffect` (`packages/daemon/src/converge.ts:342`) never resolves a recipe. It gets its clients from `options.clients` (`:408`). Those are built once per daemon start by `clientsForProjectsEffect` (`:142`, called from `apps/cli/src/daemon.ts:514`), which does read the recipe (`:184`, `:199`) and then throws it away.

**Decision:** read `branch.main` from the recipe those two lines already resolve, and keep it on the client entry. The entry type `ProjectClients.clients` (`:97-99`) already carries `owner` and `repo`, so add `readonly main: string` beside them. `ConvergeOptions.clients` (`:297`) gets `& { readonly main?: string }`, so the existing tests' injected clients still type-check.

**What an unknown `main` does.** `OWN_LABELS` is built from `labelsFor` (`labels.ts:53`) and will contain `lingtai:landed`. That means `foreignLabels` stops protecting it, and the whole-set `target` at `:418` would strip it from any ticket whose `wanted` lacks it. So:

- **Do not compute `wanted` until the client lookup (`:408`) has run.** At `:368`, the line the ticket points at, the client is not known yet, so `main` cannot be known either.
- **If `item.landed !== null` and the client has no `main`, skip the labels divergence for that item.** It must never default to "solo". The closed/comment/refs checks still run.
- **Change the early `continue` at `:406`.** It currently skips the client lookup when `wanted` is empty. For a team-landed item it must still look the client up.
  - Simplest shape: compute `wanted` without the landing first.
  - Treat `item.landed !== null && item.landed.base` differing from a `main` not yet known as "might want a label", which forces the lookup.
  - Then recompute `wanted` with the client's `main`.

One consequence: the daemon holds `branch.main` from when it started. That is already true of every client and filter there (`daemon.ts:514-530`). A changed recipe needs a restart either way (CLAUDE.md, *code, restart, paste*).

### 4. `labelsFor` keeps a single exit for the label rule

`labelsFor` is at `labels.ts:40-51`. Append `LANDED_LABEL` after the `switch`, not inside each arm, so `running` + landed can't drift apart from `landed` + landed. `OWN_LABELS` (`:53`) must gain it. Build it as `LABEL_STATES.flatMap(s => labelsFor(s))` plus `labelsFor('landed', { base: '\0', main: '' })`, or list `LANDED_LABEL` beside it with a comment. Either way, the existing test must see it.

### 5. The reduce and the codec

As the ticket says (`ticket.ts:809-821`, codec `ticket-codec.ts:193`). `landed` is a new top-level field of `TicketState`, separate from `lifecycle`. Do not also add a per-wait `landed` (`ticket.ts:84-85`); it is a different thing.

### Edges this note decides

- **A converge client with no `main`**: labels aren't judged for a team-landed item (§3), and are never stripped.
- **A solo issue somebody hand-labels `lingtai:landed`**: converge now strips it, because the label is ours. That is the same as a hand-applied `lingtai:working` today.
- **A replay through `lingtai end`** resolves with the recipe the CLI reads now (`end.ts:116`). If the mode changed between the pass and the replay, the replay follows the current mode. That is #1328's switch to guard, not this ticket's.

### Checks

Everything is unit-reachable:

- the end body with a fake store;
- `runOnce` with `landTeamTickets: true` over the fake GitHub and fake `Repo`, for the `TicketLanded.base`, no `closeIssue`, the label, and `integrate`'s `base`;
- `findIssueDriftEffect` with injected `projects`, `clients` (with and without `main`) and a memory store;
- the reduce and the codec.

No *Done when* needs `pnpm test:integration`. The `packages/repo/unit` push assertion needs `integrate`'s git port faked. If `integrate.ts:628` turns out to reach the real `git` binary with no port, that assertion belongs to the integration half. In that case, say so in the commit, and let the `runOnce` fake-`Repo` assertion on `base` stand in for it.
