Ticket #1287 doesn't say what to do with six things: the old who-answered machinery, the field name, the tests that pin the old rule, the second `:227` line in 0123, the board's "Lingtai" label, and who runs the rebuild. This note decides each of them.

## Where it goes

`packages/domain/src/problems.ts` does all the work. Each of the three sites becomes `answeredBy: alwaysYou(kind) ? 'you' : 'system'`, at `:223` (redo), `:234` (route) and `:246` (lonely wait). After that, `problemsOf` no longer reads who resolved a wait anywhere. The claiming loop (`:186-206`) and the kind calls (`kindOfWaitOverride`, `kindOfRoute`, `kindOfWait`) stay exactly as they are. That is the ticket's "still one problem, counted once": a wait still claims its route and still contributes its override kind, and only the group changes.

- **Becomes dead:**
  - `answerOf` (`:150-151`), `finalOf` (`:146-148`), the `Answers` type (`:143`) and the `answers` map (`:164`, written at `:171`). Remove all of them.
  - `handed` (`:233`). Remove it too.
- **Still needed:**
  - The `Answer` branch of the loop (`:169-173`). It also fills `splits` (`:172`), and `splitOf` (`:184`) needs that to tell `too-big` apart. Keep the branch and drop only the `answers.set` line.
  - The `Raised` union's `Answer` variant, with its `by` field, and the route variant's `decision` (`:51`). Leave both in the type. The projector stores and feeds them (`packages/projector/src/ticket-report.ts`), and trimming a stored shape is a separate change this ticket does not need.
- **Rename nothing.** `answeredBy` / `Answerer` stay. Four places compare against the strings `'system'`/`'you'`: `packages/conductor/src/report.ts:582-583`, `apps/board/src/app/report/panels.tsx:758-847`, the drill-down filter at `panels.tsx:809`, and 0123 §7's `by=system|you` (`doc/decisions/0123-the-report-counts-what-the-log-holds.md:230`). Keeping the values keeps every one of them working with no edit. Change the type's doc comment to say the value is the kind's group, not a resolver.

## The board's "Lingtai" column

Under the new rule, `panels.tsx:847` (`p.answeredBy === 'system' ? 'Lingtai' : 'you'`) and the `→ did` verb (`:758`, `:845`) will show a person-approved `review-fixed` as Lingtai's. The ticket's Related section says #1285/#1286 change only by what the data says, and the operator chose the kind rule knowing it moves the figures. So that column now names the group and needs no code change. Do not add a second field to keep "who really answered" alive.

## The rebuild is not the agent's

`lingtai projection rebuild ticket_report` takes the conductor lock and refuses while a daemon holds it. Also, the daemon conducts with the projector code it started with, so any save made before a restart still writes the old groups. The order is therefore merge, `lingtai restart`, then the rebuild on the new code, and it is the operator's step after the landing. Until then, `/report` shows the old groups: stored rows go stale, not wrong in shape. To settle afterwards that it took, look for a `ticket_report` row for a ticket with a `WaitResolved` whose `by` is a person on a `ReviewFindings` wait: its stored problem should read `answeredBy: 'system'`. Do not put the rebuild in the agent's done-when.
