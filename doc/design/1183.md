# #1183: the shape

Most of this is in the ticket already. This note covers what the ticket leaves out: which `sandbox` plumbing stays, which tests assert the old text glyph, and how to test the order without a DOM.

## Keep the per-project map. Remove only its card and row consumers.

`lockShape` builds one map for the whole page: `const sandbox = sandboxStates(registered)` (`src/app/page.tsx:735`). Its comment says *"the filter, the cards and the rows all look in it"*. The filter still reads it, through `MenuRows` and `FilterSlot` (`page.tsx:765, 779` → `ProjectRows` → `projects.tsx:106`), so **`lockShape` keeps returning `sandbox`**. Change that comment so it names the filter only.

What goes is everything that carries the map down to a card or a row:

- The `sandbox` prop on `Card` (`page.tsx:200`), on `LandedRow` (`:512, :517`) and on `Landed` (`:579, :584`).
- Their call sites at `:942`, `:996` and `:1007`.
- The `sandbox` in `:922`'s destructure of `lockShape`.
- The `SandboxState` type import at `:41`, if nothing else uses it then. `sandboxStates` stays.

**Delete the props; don't just stop rendering them.** A prop that is passed but never drawn is the next person's puzzle.

The recipe page is the same case. `sandboxStates(projects)` (`recipe/[project]/page.tsx:385`) feeds the recipe bar's filter (`recipe-bar.tsx:37`), so it stays. Only the `sandboxSlot` imports and calls go (`recipe/[project]/page.tsx:10, 236`; `recipe-bar.tsx:13, 35`).

- **`SandboxIcon` stays in `bar.tsx`.** `sandbox-slot.tsx:9` imports it from there, and the `<details>` tie logic lives with it. Only `Bar`'s `sandbox` prop and the `{sandbox}` inside `.topnav` (`bar.tsx:41, 60`) go.

  Rewrite each to say what is true now: *off* is a grey, empty, solid outline, and the slot is drawn in the home rail.

Keep the comment on `--warn` at `:3157` above `.sbx-degraded`. Leave `.sbx`, `.sbx-list` and the `.sbanner` rules (`:3152-3153, :3165-3171`) as they are.

## Tests

The suite has no DOM. The root `vitest.config.ts` sets no environment, as `unit/rail.test.tsx`'s header says. So the order is asserted on the source, as `unit/close.test.tsx:65-79` already does with `page.tsx`.

- **The order.** Read `src/app/page.tsx` and slice from `className="rail"`. Assert three things:
  - `sandboxSlot(param, key('sandbox'))` appears.
  - It comes before `<Health`.
  - Nothing but a comment and whitespace stands between them.

  `<Health>` draws the dot itself, through `Live` and `Said`. So the source order is the claim, and a rendered order cannot be had here anyway. Also assert that `sandboxSlot(` appears in the file exactly once.
- **`sandbox-mark.test.tsx:20`** asserts `>${GLYPH[name]}</span>`, which is the text glyph. It turns into two checks:
  - The markup contains `d="${GLYPH[name]}"` for every state except `off`, and `off` draws a single `<path`.
  - Inside `.sbx-mark`, nothing but `<svg>` and its paths. This is the ticket's *no `.sbx-mark` contains a text character*.
- **`sandbox-mark.test.tsx:68-…` (*cards and landed rows*).** Once the props are deleted, a test that passes `sandbox=` fails `pnpm typecheck` rather than going red. Render `Card`, the waiting `Card` and `LandedRow` without the prop, and assert their HTML has no `sbx`.
- **`bar-component.test.tsx:70-95`.** Both tests pass `sandbox={icon}` to `Bar`, which no longer compiles. Replace them with one test: `.topnav` holds no `sbx`, on a registered project and on `all`. Keep the tie test at `:96-…` as it is; it already renders `SandboxIcon` alone.
- **`projects.test.tsx`** stays unchanged. The shield is not a fourth object on the row, because it is part of health.

## Edges the ticket leaves implicit

- **The rail's gap.** `.bar .rail` has `gap: 12px` (`globals.css:152-154`), so the shield sits 12 px from the dot. That is the decided layout, so don't wrap the two in a new element to tighten it. The ticket says not to redesign.
- **A tie on the rail.** `.sbx-list ul` is `position: absolute; right: 0` (`globals.css:3166`). In the rail, the list opens leftward from the shield's right edge. That is acceptable, and nothing changes for it.
- **What can verify it.** Everything here is unit-level: `pnpm typecheck`, `HOME=/nonexistent pnpm test`, `pnpm lint` and `pnpm fmt:check`. Nothing in this change needs `pnpm test:integration`. The Next build (`apps/release/integration/build.test.ts`) is the only check that would catch a server-only import reaching a client graph, and this change adds none: `sandbox-shield.tsx` imports only `sandbox-state.ts`, which `bar.tsx` already imports.
