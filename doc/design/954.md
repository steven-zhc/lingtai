# #954: design note

## The shape in one line

`discover.ts` widens each skip, `filter.ts` hands the board a link reader only where GitHub really is the ticket source, and `askProject` reads the blockers through a cache in `board.ts`. `githubQueue` then copies the result into a new `blocked` list. Nothing in `cards`, `notes`, `lastOffered` or the header changes.

#957 has landed (`3783e0cb`), so `Offered.skipped` already carries `parent` and `subIssues` (`discover.ts:291-296`, pushed at `:436`). This change adds three fields to that same push.

## 1. `discover.ts`: the skip carries what was in hand

At `:436` the push becomes `{ ref, reason, title: issue.title, kind: matched?.kind ?? null, blockedBy: issue.dependencies?.blockedBy ?? null, parent, subIssues }`.

- **`kind`**: `matched` is already computed at `:426`, before `considerIssue`, so do not call `kindOf` a second time.
- **`blockedBy`**: this is `null` when GitHub said nothing. Keep the null and do not coerce it to `0`; the file's own rule is *"Null is not zero"* (`:242`). For every `blocked-by` skip it is a positive number, because `considerIssue` only returns that reason when `(issue.dependencies?.blockedBy ?? 0) > 0` (`:245`).

`passedOver` (`:371`) reads only `reason`, so `lingtai status` and the column's note do not change.

These `toEqual` fixtures go red and need the three new keys:
- `discover.test.ts:291`, `:449`, `:490`
- `render-cost.test.ts:187`

## 2. `filter.ts`: `links` is the client only when it is the ticket source

In the GitHub branch (`filter.ts:333-337`), set `links = tickets === ghClient ? ghClient : null`. Compare object identity. Do not branch on `recipe.source.tickets`: `ticketsOf` is the one function that decides this (`#382`), and identity asks it directly. In the ownerless branch (`:323-331`), `links` is `null`.

Type it as `links: Pick<GitHubClient, 'listBlockedBy' | 'owner' | 'repo'> | null`. Make it a required key, for the reason `TicketListing.dependencies` is required (`discover.ts:49-54`).

Do not put `listBlockedBy` on `TicketSource`/`Tickets`. `doc/design/601.md:14` says *"#599 kept the link verbs off `Tickets` on purpose … and a `db` project has no sub-issues."*

`projectFilter` already takes `ticketsFor` as an argument (`ask-project-ownerless.test.ts:49` passes one). Test both cases through it:
- a `ticketsFor` that returns the client it was handed gives `links === client`;
- one that returns a `memoryTickets()` gives `links === null`, even with an owner.

## 3. `board.ts`: the read, the cache, the cap

**Put it beside `lastKindColors` (`board.ts:882-893`)**, as the ticket says. Add:
- a module-level `Map`;
- `forgetBlockers()`, written next to `forgetKindColors` / `forgetSkeletonCounts`.

**The type.** It is exported, and it is what `GithubQueue.blocked` holds:

```ts
type BlockedSkip = {
  project: string
  ref: number
  title: string
  kind: string | null
  blockedBy: number | null
  blockers: { ok: true; issues: LinkedIssue[] } | { ok: false; problem: string } | null
  unread: boolean
}
```

- **Failure as a string.** `GithubQueue` crosses into `queued-stream.tsx`, and #960 will draw it there, so the failure is the error's `message` string. An `Error` instance would not serialise. `PermissionDenied`'s message already names the permission and the fix (`client.ts:55-63`).
- **`blockers: null` means one of two things**, and `unread` tells them apart:
  - with `unread: false`, `links` is null and nothing was asked;
  - with `unread: true`, the skip is past the cap.

**The order in `askProject` (`:778`).** List, then `select` as today, then read the blockers. The read never throws:
- `askProject`'s `catch` must still mean *GitHub would not list*, not *one blocker read failed*;
- `githubQueue` must never reject (`:942-944`).

Build it as an Effect: one `Effect.tryPromise({ try: () => links.listBlockedBy(ref), catch: (e) => message })` per skip, each turned into its outcome with `Effect.match`. Run them together with `Effect.forEach(…, { concurrency: 'unbounded' })` and `Effect.runPromise` it once, inside `askProject`. That is the board's edge; `apps/board` is not in the ratchet's baseline (`effect-ratchet.baseline.json`, which has `apps/cli` only), and `effect` is already a dependency (`apps/board/package.json:31`).

Unbounded is safe because the cap holds it to 20 per project.

**The cap.**
1. Take the `blocked-by` skips and sort them by `ref` ascending.
2. Read the first 20. Name it as a constant, e.g. `BLOCKERS_READ_MOST = 20`.
3. The rest get `blockers: null, unread: true` and cause no request.

**The cache.**
- The key is `${project}#${ref}`. The value is `{ blockedBy, at, blockers }`.
- A hit is `entry.blockedBy === skip.blockedBy && now() - entry.at < 60_000`. Anything else is a read, and the read overwrites the entry.
- **Cache failures as well as successes.** Every read gets `PermissionDenied` when the App lacks the permission (`client.ts:505-514`). Without this, every render repeats 20 doomed requests per project, and *same count inside 60 s makes no request* would not hold for that case. A failure is retried after 60 s like anything else.
- Skips past the cap neither read the cache nor write to it.
- Do not deduplicate requests that are in flight. Two renders inside the same few hundred milliseconds both miss and both ask. Each read costs one request, and the 60 s window covers everything after that.
- Nothing is evicted. The map holds at most one entry per blocked ticket a project has ever shown, and a restart clears it.

**The seams.** Extend `askProject`'s options to `{ select?, now?: () => number }`, where `now` defaults to `Date.now`. A test does not need a read seam: it passes a filter whose `links` is a fake that counts calls. Spread a real-looking filter and override `links`, as `render-cost.test.ts:79-91` builds one with `as unknown as AskableFilter`.

**A trap in fixtures built with `as unknown as`:** a filter like that has `links === undefined`, not `null`. Guard with `filter.links == null`, or such a fixture calls `undefined.listBlockedBy`.

**The `listed` variant** of `ProjectQueue` (`:754-761`) gains a required `blocked: BlockedSkip[]`. `render-cost.test.ts`'s `listed()` (`:93-106`) then needs `blocked: []`.

## 4. `githubQueue`: copy, never count

In the `listed` loop (`:985` onward), add `blocked.push(...answer.blocked)` and return it as `GithubQueue.blocked`.
- **Do not filter it against `known`.** That filter exists to stop a ticket appearing as two *cards* (`:946-948`), and `blocked` is not cards. Whether a ticket with a log row is drawn as blocked is #960's call.
- An `unanswered` project contributes nothing.
- `lastOffered.set` (`:1051`) still counts `cards.length - before`, so nothing changes there.

`queued-stream.test.tsx`'s `answer()` (`:27`) needs `blocked: []`.

## Tests

All of them are unit tests: fakes for `links`, a clock function, and no network.
- **A failing read:** one fake rejects for one ref. That skip has `ok: false` with the message, the others have `ok: true`, and the result is `listed`.
- **The cache:**
  - a second `askProject` at `now + 59_999` with the same `blockedBy` makes no call;
  - a changed `blockedBy`, or `now + 60_000`, makes a call;
  - a cached failure makes no call inside the window.
- **The cap:** 22 `blocked-by` skips listed in shuffled order. Exactly the 20 lowest refs are read, and the other two have `unread: true` and caused no call.
- **`links: null`:** no call, `blockers: null`, `unread: false`.
- **The board's cards are untouched:** `githubQueue` with a `listed` answer carrying `blocked` entries leaves `cards`, and the `lastOffered` behind `skeletonCount`, as they were.

Call `forgetBlockers()` in `beforeEach`, the way `forgetKindColors` is used.

## Edges the ticket leaves open, decided here

- **A failure is cached for 60 s**, not retried on the next render (see the cache, above).
- **Two renders at once** may each send a request; there is no deduplication of requests in flight.
- **`blockedBy` changing from null to a number** can only come with a new listing. `null` skips are never `blocked-by` (`discover.ts:245`), so the cache never sees `null` as a key value.
- **A restart** empties the cache, and the next render reads again. Nothing here is on the log, so no event settles it, and nothing needs to.
