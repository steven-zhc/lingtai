# Design note: #1105, the discussion as an Effect

The ticket has the shape right. Four places in the code do not match the ticket's **Shape** and **Fix** rows, and each would compile and still change behaviour. The line numbers below are this worktree's (`d3488227`). The ticket's numbers are from `8abc8613` and have moved.

## 1. The work loop's `discuss` port is delivered, never yielded

The ticket says the port is "yielded where #1070 lifted it". It is not lifted anywhere. The `discuss` port is handed to `deliver` (`packages/daemon/src/work-loop.ts:569`). `deliver` takes a promise and runs it off the pass path with a timeout and a `PluginFailed` record (`:438-470`). Above the call, the comment says *"a question must not wait for a run"* (`:566-567`).

If `discuss` were yielded inside the loop, the loop would wait on an agent for minutes, and a question would wait on a run.

- Change only the type: `discuss?: (event: Envelope) => Effect.Effect<void>` at `:290`.
- At `:569`, run it the way subscribers already are at `:564`: `deliver('discuss', event, (e) => Effect.runPromiseWith(services)(Effect.suspend(() => options.discuss!(e))))`.
- `deliver`'s signature and `triage` (`:292`, `:572`) stay promise-based. `Effect.runPromiseWith` is not counted by the ratchet.

## 2. The ports carry an error channel, and the conductor catches the whole cause

`Runtime.run` is `Effect.Effect<RunOutcome>` with no error channel (`packages/agent/src/runtime.ts:263`), so a runtime that fails shows up as a defect.

Today `holdDiscussionEffect` turns a port that throws into a result with `Effect.catch`:
- `ask` becomes a `crash` *did not answer* with `threw = true`, so there is no `RunSpent` (`packages/conductor/src/discuss.ts:599-609`).
- `version` becomes `null` (`:583-585`).
- `serve` becomes `null` (`:642`).

`Effect.catch` does not catch a defect. If only the port types were switched, a crashed runtime would escape `holdDiscussionEffect`. The *did not answer* line and the empty-answer append (`:621-628`) would never be written.

**Decision:**
- `DiscussionPorts` (`:442-462`) types each port as `Effect.Effect<T, unknown>`.
- Each of the three catch sites becomes `Effect.catchCause` that re-fails when `Cause.hasInterruptsOnly(cause)` holds, following `work-loop.ts:532-535`.
- `detail` comes from `(Cause.squash(cause) as Error).message`, so the recorded string does not change.
- `lift` (`:829`) stays for the store calls.

## 3. The runtime factory is called inside the Effect

The comment at `apps/cli/src/discuss.ts:333-335` says *"Construction happens inside the async ask port so an unconfigured Codex route is recorded as a failed answer instead of leaving this question outstanding."*

Today `runtime()` is called inside an `async` body (`:264-265`), and in `discussionVersion` inside `.then` (`:291-292`). If it were called eagerly while the Effect is being built, its throw would happen at the call site, outside every catch.

- In both `discussionAsk` and `discussionVersion`, wrap the body in `Effect.suspend(() => …)`. A throw from `createRuntime` then becomes a defect, and the catch from §2 records it.
- `fixed.runId` becomes `(round) => Effect<string>`. Its `eventStore.read` (`:412`) is lifted with `Effect.tryPromise`.
- `apps/cli/unit/discuss-ask.test.ts:167-185` asserts `.rejects.toThrow(ToolsCannotBeDenied)`. Rewrite it to run the Effect with `Effect.runPromiseExit` and check that `Cause.squash` is a `ToolsCannotBeDenied`. It pins the same behaviour, and no expected string changes.

## 4. The daemon's `locked` stays, and only the discussion's call sites move

`const locked = lockedBy(guard)` (`apps/cli/src/daemon.ts:600`) is also handed to triage at `:607` and `:668`, and triage is out of scope. Leave that line alone.

Pass `lockedEffect(guard)` at the two discussion sites:
- the loop's port, `:664`;
- startup, `:795-803`.

At startup, `answerOutstandingQueued` is now an Effect that never fails. Yield it directly and delete the `Effect.promise(…).pipe(recovering(…))` wrapper.

That `console.error('discussions: …')` branch could already never be reached, because the queue's own `.catch` (`discuss.ts:547-550`) swallowed every failure and logged it through `ports.log`. Its replacement, the queue's `catchCause`, logs the same `discussions: ${message}` line through `ports.log`.

## The queue

Shape: `const discussing = Semaphore.makeUnsafe(1)` at module level, and `answerOutstandingQueued = (ports) => discussing.withPermits(1)(answerOutstanding(ports).pipe(catchCause…))`. The permit is the one thing that guards against paying for two agents (#996).

**`withPermits` must wrap the scan**, meaning both the outstanding-request read and the answering. Wrapping only the answer would let two scans find the same request and both answer it. The comment at `:530-535` stays with the semaphore.

Because the semaphore is module state, the tests in `answer-outstanding.test.ts` share it. That is safe only because a permit is released on every exit, failure or interruption. The ticket's *a first answer that dies releases the permit* test pins exactly that.

## `answerDiscussion`'s exit

- `clearInterval(beat)` and `Effect.promise(() => trace.close('delete'))` go in one `Effect.ensuring`, placed after `openRunLog` (`:378`), as the `finally` at `:434-441` is today.
- The per-answer catch inside `answerOutstanding` (`:521`) becomes `catchCause`, which logs `discussion ${chatId} failed: …` and lets an interruption through. `answered += 1` still runs after a failure, as it does now.

## What can only be checked after the merge

`packages/conductor/integration/discuss.test.ts` reaches a store and runs only in the integration half.

Before the merge, `packages/conductor/unit/discuss.test.ts` stands in for it, with one case added:
- an `ask` that dies with a defect, e.g. `Effect.die(new Error('boom'))` (not a rejection);
- it should produce `answered: false`, one empty answer carrying `failure: 'crash: boom'`, and no `RunSpent`.

That case is what proves §2. Without it, every existing test still passes, because the existing fakes fail through the error channel rather than as defects.
