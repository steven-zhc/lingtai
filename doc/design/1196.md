## Decisions the ticket leaves open

### 1. The short names take their roots as an argument; the loader supplies them

`sandbox-view.ts` must not read the environment. Its header says *"What the Sandbox tab draws (#1161), as data: no React and no reads"* (`sandbox-view.ts:2`). So neither `homedir()` nor `stateDir()` can be called in that file.

- Define `interface PathRoots { home: string; lingtaiHome: string; project: string }`.
- `shortNameOf(path, roots)` takes it as an argument, and so does everything built on it.
- `loadSandboxTab` (`task.ts:2141`) already knows `project` (`:2143`). Add `roots: { home: homedir(), lingtaiHome: stateDir(), project }` to `SandboxTabDetail` (`:2126`).
- `SandboxTab` passes `roots` to `<SandboxPanel view roots />`.
- The board runs in the CLI's own process (*"The board runs in the CLI's own process, so these read the environment the CLI read"*, `home.ts:6-7`), so `stateDir()` there is the daemon's in the ordinary case.
- Where it is not the daemon's, nothing matches and every path is drawn as recorded. That is the safe failure, the same reasoning as the ticket's `$TMPDIR` rule.
- Tests pass fixed roots, so `HOME=/nonexistent pnpm test` stays honest.

### 2. How the prefixes match

**`<worktree>` is one path segment, not the attempt number.** A worktree is `join(home, 'worktrees', project, runId)` (`packages/repo/src/worktree.ts:95`). This worktree's own directory is `worktrees/lingtai/pass-<uuid>`.

- Match `<lingtaiHome>/worktrees/<project>/<one segment>` and name it `<worktree>`. The board never needs the runId.
- One claim means one `runId` (`sandbox-view.ts:7`), so an attempt has one worktree in the ordinary case.
- The legend maps each short name to every distinct prefix it stood for, so a second worktree in one attempt would show as a second line under `<worktree>`, not be hidden.

**Prefix order, longest first:**
1. `<worktree>`
2. `<mirror>` = `<lh>/repos/<project>.git` (the same formula as `mirrorDir`, `policy.ts:81-82`)
3. `<cache>` = `<lh>/cache/<project>` (`cacheDir`, `policy.ts:77`)
4. `<lingtai home>`
5. `~`

**Matching rules:**
- Match only at a `/` boundary. Reuse `within` (`sandbox-view.ts:189`): `/Users/s/.lingtaix` is not under `/Users/s/.lingtai`.
- A path equal to a prefix is the bare token. For example, `stateDir` itself in `denyRead` (`policy.ts:96`) is `<lingtai home>`.
- The runtime's run directory (*`<home>/runs/<attempt>/claude`* in the ticket) is under `stateDir`, so it becomes `<lingtai home>/runs/…/claude`. There is no `runs` token; the ticket lists five and this adds none.

**The `/private` twins are merged in `chipsOf(paths, roots)`, not in `shortNameOf`:**
- Where both `X` and `/private` + `X` are in one list, emit one chip with the shorter spelling's short name and both full spellings in `title`.
- This does not check the platform. On Linux no list contains both spellings, so the rule never fires there.
- The twins are the pairs `tempRoots` produces (`policy.ts:105-111`, plus `tmpdirReal`, `:16-17`).

**Each chip is `{ label, title, fulls }`.** The legend is built from the chips actually drawn, not from the five possible tokens. That satisfies *"lists every short name used"* and nothing more.

### 3. The vendor map lives in `@lingtai/sandbox`, through a new pure subpath

- The board does not depend on `@lingtai/sandbox` today (`apps/board/package.json:20-32`).
- Add the export `"./policy": "./src/policy.ts"` to `packages/sandbox/package.json:6-10`. `policy.ts` imports only `node:crypto` and `node:path` (`:7-8`) and is described as *"Pure: every function takes the host's facts as an argument"* (`:3`).
- Add `"@lingtai/sandbox": "workspace:*"` to the board's dependencies.
- Import from `@lingtai/sandbox/policy`, never from the root and never from `/live`. `packages/sandbox/unit/no-live-import.test.ts` already walks `apps/board` for `/live`.
- After the edit, run `pnpm install` so the lockfile records the workspace link. It needs no network. Commit the lockfile with the change.

The map:
```ts
export const BUILT_IN_DOMAIN_VENDORS: Readonly<Record<string, 'Anthropic' | 'OpenAI' | 'npm' | 'GitHub'>>
```
- Anthropic: `api.anthropic.com`, `*.anthropic.com`, `claude.ai`, `*.claude.ai`
- OpenAI: `api.openai.com`, `*.openai.com`, `chatgpt.com`, `*.chatgpt.com`
- npm: `registry.npmjs.org`, `*.npmjs.org`
- GitHub: `github.com`, `*.github.com`, `*.githubusercontent.com`

Put the equality test (map keys = list) in `packages/sandbox/unit/sandbox.test.ts`, next to the list it guards.

**Grouping in `reachOf`:**
- `source: 'recipe'` goes under *This recipe*, even when the host happens to be a vendor's.
- Any other source (`built in` or `not recorded`) goes under the host's vendor, or under *Other* if the host is not in the map.
- If any policy records a host as `recipe`, it is a recipe host.

### 4. `summaryOf(rows, policies)` returns data, not a sentence

The panel chooses the words and the tone; the function returns a shape like:
```ts
{
  state: 'none' | 'all' | 'some' | 'off',
  sandboxed: number,
  total: number,
  tone: Tone,
  why: string | null,
  srt: string | 'differs' | null,
  refused: { count: number; orMore: boolean; unknownRuns: number },
}
```

**State:**
- `rows.length === 0` → `none`. Draw *No wrapped run was recorded for this attempt.* and no figures.
- Every row is `sandboxed` → `all`.
- No row is sandboxed, and every row with a recorded mark is `off by choice` → `off`. A recipe turns the sandbox off for the whole attempt, so a mix is not expected. Rows still `not recorded` beside the off ones do not change this state.
- Otherwise → `some`.

**Tone of `some`:**
- `fail` if any row is `stopped`.
- Otherwise `signal`. That covers `degraded`, and also `not recorded`: the rows the view adds itself (`sandbox-view.ts:269-281`). The ticket names only degraded and stopped, and an unknown boundary is not a pass.
- `why` is the first `mark.why` that is not null, from a stopped row if there is one.

**The refusal figure.** This is the trap in the ticket's Watch out.
- `count` sums `refused.count` over the rows.
- `orMore` is set by any `refused` reading with `incomplete`, or by any `pending`, `lost` or `unreadable` reading.
- `unknownRuns` counts the `pending`, `lost` and `unreadable` rows.
- Draw *N connections refused* only when `orMore` is false. Otherwise draw *N or more connections refused*.
- If `count === 0` and `unknownRuns > 0`, draw *refusals unknown for one run* / *for K runs*.
- **`none recorded` is never a confirmed zero in the figure.** Nothing is appended when nothing was refused, and nothing either when the append failed (`sandbox-view.ts:161-164`). It adds nothing to `count` and is counted in `unrecordedRuns`; with one in the attempt the figure says *no refusal recorded* or *N recorded as refused*, never *N connections refused*. It is not *or more*, which would sit on nearly every attempt.
- `not applicable` adds nothing.

**srt:**
- One distinct non-null `srtVersion` across the rows → that version.
- More than one → `'differs'`, and each run row shows its own version.
- When the versions agree, the run rows stop showing theirs, because the summary says it.

### 5. `reachOf(policies)` compares full paths, never short names

`reachOf` returns:
- `common`: the four lists that **every** policy has.
- `differs`: one entry per policy, with `{ letter, runs, extra, lacks }`, each over the same four lists.

**How entries are compared:**
- Hosts by `host`.
- `writable` and `denyWrite` by path.
- `denyRead` by `path` plus the sorted `except` list, because two policies that differ only in a re-allowed path really differ.

Compare before naming or twin-merging, so two different worktrees never become one `<worktree>` chip by accident.

**Policy counts:**
- With one policy, `differs` is empty and the panel draws no *Where the policies differ*.
- With many, `differs` gets one row per policy and nothing is folded.
- `policyLetter(n)`: 1 → A … 26 → Z, 27 → AA, so a long attempt with fix rounds and judges never runs out of letters.

### 6. The Kind column for a row the view added itself

The rows `sandboxViewOf` adds for an action with no record set `runtime: null` whatever the plugin was (`sandbox-view.ts:270-280`). By the ticket's rule those would say `command`, which is false for an agent step.

- A row whose mark is `not recorded` gets `—` in Kind.
- Every other row: `agent · <runtime>` when `runtime` is not null, `command` when it is.
- The plugin is not inferred, and `RunRow` gets no new field.
- `weakerNetwork` keeps its current text in the mark cell (`sandbox-panel.tsx:63`). The ticket's layout does not mention it, and dropping it would remove something the record says.

### 7. Blocked: the clock format is opt-in, because the recipe page shares `BlockedList`

`BlockedList` is also drawn by the recipe page's recently-blocked section (`app/recipe/[project]/page.tsx:9,344`), which covers a window of days. A time with no date would be wrong there.

- Add a prop, for example `time?: 'iso' | 'clock'`, defaulting to today's ISO.
- The task tab passes `'clock'`: `HH:MM:SS UTC` from `toISOString().slice(11, 19)`, with the ISO in `title` and `dateTime`.
- Add the *by* column and the hint sentence (*Telemetry hosts are not counted…*) in `SandboxPanel`, around `BlockedList`. Leave the recipe page as it is; #1197 redraws it.
- The caveats and the empty sentence stay inside `BlockedList`, unchanged.
- The `--signal-soft` tint and the button style for the Allow link go on a wrapper class in the panel.

### 8. The shield

Reuse `SandboxShield` (`app/sandbox-shield.tsx:4`). It takes a `SandboxStateName` from `lib/sandbox-state.ts`, so map the summary's tone onto one of those names, and colour it from `.sbx-mark`'s `currentColor` (`globals.css:3151-3164`). Do not draw a second SVG.

## Tests

All of these go in `apps/board/unit/sandbox-view.test.tsx`, with fixed `PathRoots`.

**Pure functions:**
- `shortNameOf`:
  - each of the five tokens;
  - the longest prefix wins (`<mirror>/hooks`, not `<lingtai home>/repos/…`);
  - the `/` boundary;
  - an exact match gives the bare token;
  - an unmatched path comes back unchanged;
  - a temp path stays a path.
- `chipsOf`: the twin merge, with both spellings in `title`.
- `reachOf`:
  - the ticket's four-run fixture: one common set, one extra path per policy;
  - a *lacks* case;
  - a single policy gives an empty `differs`.
- `summaryOf`:
  - every `RefusalReading` kind;
  - `incomplete` gives *or more*;
  - only unknowns gives *unknown for K runs*;
  - `none recorded` is counted in `unrecordedRuns` and never drawn as a confirmed total;
  - all / some / off / none, each with its tone.

**Rendering:** render `SandboxPanel` and assert the order of the section `aria-label`s and the key texts, never classes or pixels.

`pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` cover all of it; nothing here needs the integration half. The one check no test can make is the ticket's: a person comparing the tab with design A.
