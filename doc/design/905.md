## Design: the home page's footer (#905)

Line numbers have shifted since `9c0276dc`. The ticket's `page.tsx:666` is now `:683`, the rail's two `.reading` links are `:764-785`, `total` is `:696`, and `<div className="cols">` is `:870`. `/landed` exists already (`apps/board/src/app/landed/`), so the landed count is a link from the start.

### 1. The footer cannot call `dayFigure` or `landedLink`, so the reading carries the figure

The ticket's no-server-import rule rules out both helpers that would be the obvious ones to reuse:

- **`dayFigure`.** It comes from `@lingtai/conductor` (`day-spend.ts:7`). It is the one function that knows *"Never `$0.00` over unknown rows"* (`packages/conductor/src/day-ceiling.ts:99-101`). A value import of it is a server import in a client graph once #906 mounts the footer.
- **`landedLink`.** It is at `apps/board/src/lib/landed.ts:76`, a file that imports `@lingtai/projector` and `@lingtai/conductor/projects` (`landed.ts:12-15`).

Copying `dayFigure`'s rule into `footer.tsx` would make two copies of the unknown-is-never-$0 rule. So **`DaySpendReading` keeps the rule on the server side and hands the result over as data**:

```ts
export interface DaySpendReading {
  text: string                    // unchanged: daySpendText's sentence, or the failure sentence
  day: DaySpend | null            // null exactly when the read failed
  figure: string | null           // dayFigure(day), null when day is null
  ceilingUsd: number | undefined
}
```

- `dayReading()` fills `figure` with `dayFigure(day)`.
- The `catch` in `readDayReading` (`day-spend.ts:46-48`) returns `{ text, day: null, figure: null, ceilingUsd: undefined }`.
- `Footer` formats only what has no rule in it: `~$E` from `day.estimatedCents`, `$C` from `ceilingUsd` (written as `$200`, as the mock and the old `short` did, not `$200.00`), and the unknown count.
- It builds its `?project=` hrefs with one local helper of its own. Do not import `landedLink`.
- `footer.tsx` imports `DaySpendReading` with `import type` from `@/lib/day-spend`. The type import is erased, so it passes the import test in *Done when*.
- `footer.tsx` carries no `'use client'`. It is a plain component that renders in a server page today and in #906's client component later. `DaySpend` is plain data (`day-ceiling.ts:39-50`), so it serialises across that boundary.

### 2. Props, and where the landed count is computed

- `Footer({ day, project, landed })`. `day` is the whole `DaySpendReading`, because the hover needs `text`. `project` is `only` (`string | undefined`). `landed` is a number.
- The count is computed by `landedCount(cards: readonly { closed: boolean }[]): number`, exported from `footer.tsx` and typed structurally so it needs no `@/lib/board` import. `page.tsx` calls it on the Landed column's `cards`, which is the filtered column under `?project=`.
- *Done when*'s "counts landed cards and not closed ones" is a test of `landedCount`.

### 3. The meter's numbers

Work in cents, with `C = round(ceilingUsd * 100)`, the same rounding `ceilingReached` uses (`day-ceiling.ts:135-136`).

- **Shares.** Reported is `min(R/C, 1)`. Estimated is `min(E/C, 1 − reportedShare)`. Unknown is never drawn.
- **A ceiling of 0.** If `C` is 0, draw the meter full and do not divide.
- **`aria-valuenow`** is `min(R+E, C)` in dollars, because a value above `aria-valuemax` is invalid ARIA. The real over-the-ceiling figure is in `aria-valuetext` (`text`) and in the visible figures, which are never capped.
- **Colours.** Reported is `var(--accent)` and estimated is the same colour at reduced opacity. Do not use amber (*"Amber stays the headline's alone"*, `doc/design/the-bar.md:29`), and do not use the fail colour.
- **Where `title` and `aria-valuetext` go.** Both carry `text` and go on the `role="meter"` element. When there is no meter (no ceiling, or a failed read), the `title` goes on the figures.

### 4. Layout: in the page's flow, not fixed

`<footer className="footer">` goes immediately after the closing tag of `<div className="cols">`.

The ticket allows either; choose in-flow:

- A fixed footer needs bottom padding that matches its height on every page. #906 adds it to pages whose layouts differ, and the person check *"no card is ever hidden under it"* then turns on a magic number. An in-flow footer cannot cover anything.
- Being after `cols` also keeps `bar.test.ts:218`'s slice (`<div className="bar">` … `<div className="cols">`) ending where the bar ends. *Done when*'s "`<Footer` after the columns" is `page.indexOf('<Footer') > page.indexOf('<div className="cols">')`.

CSS goes in `apps/board/src/app/globals.css`:

- Add `.footer` rules. The figures use the same mono, tabular-nums type `.bar .reading` uses (`globals.css:160-164`).
- Delete `.bar .reading`, `a.reading:hover` and the comment above them (`:150-165`), because nothing else uses the class.
