# #1372: design note for `MarkdownField`

## Before you start

The mock is not in this worktree. `doc/milestone/0.16.0/team-mode/` here has no `markdown-field.html`. It landed on `main` in `8fcffee0b` (*docs(mock): one Markdown field with live preview, the cursor line showing its Markdown (#1372)*). Read it with `git show 8fcffee0b:doc/milestone/0.16.0/team-mode/markdown-field.html`. Do not copy it into this branch.

## Shape: three files, and only one of them imports CodeMirror

Build it the way the recipe's YAML editor is built. That pattern already does what this ticket's *Server rendering* edge asks for:

- `recipe-form.tsx:13-17` loads the editor with `dynamic(() => import('./yaml-editor').catch(() => ({ default: () => null })), { ssr: false })`. The comment there says *"CodeMirror touches `document`. A failed load leaves the textarea"*.
- `recipe-form.tsx:120-129` renders a plain `<textarea>` until `onReady`.
- `yaml-editor.tsx:103,113-118` takes that textarea's focus and selection once, through `handoff`.

The three files:

1. **`apps/board/src/app/markdown-field.tsx`** (`'use client'`, no `@codemirror/*` import). This is the component the seven call sites use.
   - It renders a real `<textarea>` with the same props (`value`, `onChange`, `placeholder`, `aria-label`, `readOnly`, `rows`, `autoFocus`) until the editor reports ready, then drops it. Server markup and first paint are therefore a textarea of the right size, so there is no layout jump.
   - Typing before hydration is not lost.
   - If the chunk fails to load, the field degrades to today's behaviour.
   - Its `onChange` takes a **string**, not an event.
2. **`apps/board/src/app/markdown-editor.tsx`**. This is the CodeMirror view, loaded only through `dynamic(..., { ssr: false })` from file 1.
3. **`apps/board/src/app/markdown-preview.ts`**. This is pure CodeMirror state with no React and no DOM: the extension list, the `ViewPlugin`'s decoration builder as a function of `(state, focused, readOnly)`, the Enter binding, and the function that turns an outside `value` into a minimal change (or `null`). The unit test reaches the editor through this file.

## The non-obvious decision: CodeMirror's Markdown defaults rewrite text

The ticket's watch-out is *"no normalising of list markers, line endings or trailing spaces"*. Three CodeMirror defaults would break it, and none of them fails loudly:

- **`markdown()` adds `markdownKeymap` unless told otherwise.** Its Enter (`insertNewlineContinueMarkup`) continues `- ` and renumbers ordered lists. Its Backspace (`deleteMarkupBackward`) deletes list markup. Call `markdown({ addKeymap: false })`.
- **`defaultKeymap`'s Enter is `insertNewlineAndIndent`.** That command deletes whitespace around the cursor and adds indentation from the language. It would strip a trailing two-space hard break. Bind Enter to `insertNewline` above the default keymap. Leave out `indentWithTab`, which `yaml-editor.tsx:129` uses: Tab should move focus, as it does in a textarea. Also leave out `indentOnInput` and `closeBrackets`.
- **The document's line separator.** By default CodeMirror splits `\r\n` and `\r` and joins with `\n`, so `doc.toString()` would differ from a `value` carrying `\r\n`. Add `EditorState.lineSeparator.of('\n')` so the round trip is exact. The "a value equal to the editor's own text dispatches nothing" check depends on this: without it, a CRLF summary would compare unequal on every render and dispatch every time.

There is no syntax highlighter (no `syntaxHighlighting(...)`), which matches *Out of scope*. All formatting comes from the plugin's mark, replace and line decorations.

## Decorations

- **Which lines show their Markdown.** Every line touched by a selection range, and only while `view.hasFocus`. A field without focus draws every line formatted. Rebuild on `docChanged || selectionSet || viewportChanged || focusChanged`.
  - On those lines, use mark decorations only: monospace and dimmed markers (frame 02). Because nothing on the line being typed is replaced, IME composition sees an untouched line.
- **`readOnly`** (the generated rest) sets `EditorView.editable.of(false)` and `EditorState.readOnly.of(true)`. No line ever shows its Markdown (frame 05).
  - `.cm-content` is then `contenteditable="false"`, so `palette.tsx:176`'s `isContentEditable` is false there. That is harmless: the content is not focusable, so a key there has `body` as its target.
- **Fence lines.** A `ViewPlugin` cannot replace a line break (block decorations are refused from plugins). Hide a fence line off the cursor with a line decoration class that collapses it, plus a replace over its text. Check by eye that arrow keys walk through a hidden fence line and show it. If they do not, move only the fence hiding into a `StateField`, and say so in the PR.
- Use `syntaxTree(state)` as it stands. A part not yet parsed is drawn plain, never changed.

## Controlled `value`

The pattern is `yaml-editor.tsx:150-167`, keyed on `value` instead of `push.rev`:

1. If `value === view.state.doc.toString()`, do nothing.
2. Otherwise dispatch only the middle that differs, so the selection maps through it.
3. Mark the transaction with an annotation so the update listener does not echo it to `onChange`. A person did not type it.

The "untouched follows the stream, edited keeps the words" rule stays in `PrSummaryEditor` (`pr-summary-editor.tsx:26-33`), not in the component.

## Call sites that need more than the swap

- **`discussion.tsx:837-857`** has an `onKeyDown` (Enter asks; the IME guard reads `isComposing` and `keyCode` 229, `discussion.tsx:357-367`) and a `ref` that sizes the box to its content (`:602-611`). Give `MarkdownField` an `onKeyDown(e: KeyboardEvent)`, installed as `Prec.highest(EditorView.domEventHandlers({ keydown }))` and returning `e.defaultPrevented`, so Enter-to-ask wins over `insertNewline`. Drop the sizing effect: CodeMirror grows with its content, and the 12rem cap moves to `.chatask .cm-scroller` in CSS.
- **`decide.tsx:656-672`** keeps its `<input>` branch. Only the `asked && !withdrawing` textarea becomes the field.
- **The CSS selectors that size these boxes name `textarea`:** `globals.css:890,903,1719,1726,2035,2298,3820,3844,3464-3465`. The component puts the caller's `className` on its wrapper. Extend each selector to the wrapper so `rows` (the minimum height), the border and the generated box's grey ground (`:3465`) carry over.

## Tests

The board's unit tests have no DOM environment. They render with `renderToStaticMarkup` or walk the element tree, as `edit-body-and-requeue.test.tsx:55-66` does with `findControl(node, 'textarea')` and then `props.onChange?.({ target: { value } })`. So:

- **The helper** goes in `apps/board/test/markdown-field.ts`. It finds the `MarkdownField` element in a tree and calls its `onChange(text)`.
  - `edit-body-and-requeue.test.tsx` changes once, to use it.
  - `pr-page.test.tsx:555-561` and `task-page.test.tsx:1247,1259` match `<textarea` in static markup. They still find the fallback textarea, but check that the `aria-label` is the one asserted.
  - `discussion-live.test.tsx:672` reads the `.chatask textarea` CSS rule and follows the selector change.
- **The "hands back exactly what was typed" test is at state level, in `markdown-preview.ts`.** No `EditorView` is built in node. It does two things:
  1. It applies `input.type` transactions for `**a**`, `- a` and `1. a` through `EditorState.create({ extensions })` and asserts that `doc.toString()` equals the typed string.
  2. It runs the field's Enter binding (as a `{ state, dispatch }` command) after `- a`, after `1. a`, and after `a␠␠`. It asserts `- a\n`, `1. a\n` and `a␠␠\n`. These are exactly the three failures above, and none of them is visible in a typing test that never presses Enter.
- **The outside-value test** covers the sync function: equal text gives `null`, and different text gives a change that keeps a cursor placed outside the changed middle. The untouched/edited rule is tested on `PrSummaryEditor` through the helper.
- **What no unit test can see.** The view itself (hidden markers, IME, ⌘K inside `.cm-content`) is checked by eye, as *Done when* already says. Whether the dynamic chunk keeps CodeMirror off the server graph is the Next build's to see, after the merge (`apps/release/integration/build.test.ts`). `unit/client-graph.test.ts` is the unit-level stand-in, and it passes only while `markdown-field.tsx` has no static import of the editor.

No `async` function is needed anywhere in this, so `effect-ratchet.baseline.json` does not move.
