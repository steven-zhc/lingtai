# #1459: the shape of the change

The ticket's line numbers are from before #1456/#1458 and have moved. Find things by selector instead. Today: `.hlab` is at `globals.css:1129`, `.sread .sstate` at `:1237`, `.swaiting-meta`/`.swaiting-title` at `:1482-1524`, `.ld-header` at `:3123-3125`, `.prp-chip`/`.prp-title`/`.prp-sub` at `:3442-3445`, and the task header at `standing.tsx:1294-1342`.

## 1. `ObjectTitle` is plain markup, with no `"use client"`

`apps/board/src/app/object-title.tsx` takes no hooks and no data. `standing.tsx`, `pr-detail.tsx` and the setup pages all import it, and some of those graphs are client graphs. The Next build check (`apps/release/integration/build.test.ts`) only runs after the merge. So keep the file importing nothing but React types, and no server-only import can reach it.

`title` and `meta` are `ReactNode`. The task page's title is a streamed `<Gh>` boundary (`standing.tsx:1186-1197`), and its metadata holds `<Since>` clocks and a `.refusal`. Make `tag` and `lead` optional. When GitHub has no such issue, the task page passes neither: `task-page.test.tsx:1157` requires that no `class="sstate"` is drawn, and the edge says the refusal goes in the metadata line.

Put the tone on the root, for example `<div class="ot ot--signal">`. Don't put it on the word. The test at `task-page.test.tsx:1129` matches `class="sstate">queued<`, so the lead span may carry no second class. The rule `.ot--signal .sstate { color: var(--signal) }` replaces `.standing.onyou .sread .sstate` (`globals.css:1259`) and `.standing.live .sread .sstate` (`:1190`). Both of those select through `.sread`, which is going. Keep `.standing.live`'s border and pulse (`:1189`, `:1198-1214`): they are not title rules.

## 2. Keep the task page's page-order markers, inside the `<h1>`

The tests read the page order from `data-rank`:

- `standing.test.tsx:2132` requires `state` before `subject`.
- `task-page.test.tsx:515` requires `coords, state, why, …`.
- `task-page.test.tsx:747` slices `class="swaiting-head"` up to its `</header>` and requires `data-rank="subject"` before the rail (`:825`).

So:

- **Keep the `<header class="swaiting-head">`** and the `.sticket` and the rail under it. Replace only `.swaiting-meta` and `.swaiting-title` with `ObjectTitle`. Delete their CSS.
- **Lead:** `ObjectTitle` renders `<span data-rank="state" className="sstate">`, with the attributes in that order. `renderToStaticMarkup` writes attributes in prop order, so `class="sstate">word<` still matches. Write a comment saying the order is what `:1129` reads.
- **Title:** a non-null `title` is wrapped in `<span data-rank="subject">`. When `subject === null` (a task that is not a work item), pass no title. `standing.test.tsx:2383` requires no `subject` rank there, and the `<h1>` then holds only the state word.

The `ObjectTitle` rank markers do no harm on the PR and setup pages. No test runs `arrangement()` on those pages.

**`unit/__snapshots__/task-page.test.tsx.snap` changes on purpose.** Run `vitest -u` on that file only and read the diff. In both snapshots exactly three lines should change:

- `coords` loses `#147 ↗`, which moves into the metadata line.
- `state` is the bare word.
- `subject` gains `#147 ↗ · 4h 33m` (running: the step and the clocks) after the title.

Any other changed line is a regression. Don't accept it.

## 3. One header for every state

For the unframed states (landed, satisfied, closed), `ObjectTitle` replaces `<p class="ssubject">` (`standing.tsx:1339`) inside `.sticket`. Delete the readout under *Where it is*: the `{isFramed ? null : stateReadout}` line at `standing.tsx:1409`.

`readout` (`:1199-1212`) and `RunningMeta` (`:272-292`) stop drawing `<p class="sread">`. Split them into two parts:

- the word, which becomes the lead;
- the `.sage` facts, which become metadata items as plain spans joined by ` · `.

Plain spans matter because `.sread .sage` sets 1.05–1.4rem (`globals.css:1250`), and those rules go with `.sread`. `task-page.test.tsx:777` (no `.sread` under *Where it is*) stays green.

Delete these rules too, since nothing will match them once the readout is gone:

- `.sread`, `.sread .sstate`, `.sread .sage` (`:1221-1258`);
- the `:is(.detail--waiting, .detail--resolved) .sread*` and `.ssubject`/`.stitle` size rules (`:1525-1530`, `:1585-1587`, `:1597`);
- `.ssubject`/`.stitle` (`:1321-1345`).

Remove only properties that set type. A `.stitle` with `overflow-wrap: anywhere` can move into `.ot`.

Pick the task tone from `standing.state`. `onYou` is exactly `blocked` (`lib/task.ts:1280`), so map `blocked` to `--signal` and leave out the `mark` class. Put the map in `object-title.tsx` as `taskTone(state)`, typed `Record<StandingState, Tone>` like `STATE_WORD` (`lib/task.ts:445`), so that a new state cannot fall through without a tone.

## 4. Set the PR tone in `lib/pr-page.ts`, from the status

`view.poster.word` is a display word. It comes from `POSTER[pr.status]` (`lib/pr-page.ts:213-221`, `:511`), and the board's *queued* card is status `requested` (`.pr-card.progress.queued`, `globals.css:3532`), whose word is `SUBMITTED`. A tone read back from the word would be wrong.

Add `tone` to `poster` where `word` is set (`:511`, and the draft at `:699`), keyed on `pr.status`:

| Status | Tone |
|---|---|
| `waiting` | fail |
| `merged` | pass |
| `in-progress` | accent |
| `requested` | queued |
| draft | draft |
| anything else | navy |

Pin it in `pr-page.test.tsx`. The tag text is `poster.word.toLowerCase()`.

The `.pr-`/`.prp-`/`.obs-` literal guard (`pr-colours.test.ts:11`) does not cover `.ot-`. The new block must still be all variables, and the new CSS test should check colours as well as sizes.

## 5. Where `.hfact` goes

There are uses outside the ticket's list:

- **`recipe/[project]/page.tsx:382`** has a third `.hfact`, inside *Where every value came from*. Give it the same class as the recipe's new first line: one rule, `.pagefacts` (mono, `var(--fs-2xs)`, `var(--muted)`). Otherwise the `rg hlab|hfact` guard can't go green.
- **`.sec-h :is(…, .hfact, small, a)` at `globals.css:186`** names `.hfact`. The two *Claude Code token* headings in `setup/repository/added/page.tsx:104-119` become `<h2 className="sec-h">Claude Code token <small>unknown</small></h2>`. `.sec-h` is #1456's rule (`globals.css:175`), already landed, and `small` is already in that selector. Drop `.hfact` from it.
- **`.detail-body > section > h2` (`globals.css:1119-1128`)** is the rule that draws the line under the recipe heading. Delete it only if `rg` finds no other `<h2>` directly under a `.detail-body` section once the setup and recipe headings are gone. It is a section layout rule, not a title rule.

On `/landed`, delete `<header class="ld-header">` and its `<h1>` and `<p>`. `dl.ld-totals` becomes the first child. Delete `.ld-header`, `.ld-header h1` and `.ld-header p` (`:3123-3125`). Keep `.ld-totals dd`'s `var(--fs-xl)` (`:3129`): it is a figure, not a title.

## 6. The guard tests

Put them in a new `unit/object-title.test.tsx`, using `rulesOf` from `test/css-rules.ts`.

**Guard against a second title.** Define it as: no `.tsx` under `src/app` except `object-title.tsx` and `dev/waiting/page.tsx` contains `<h1`. Today there are four others (`standing.tsx:1301`, `pr-detail.tsx:150`, `landed/view.tsx:269`, `setup/claude-token/page.tsx:26`). Checking the source this way is cheaper and stricter than parsing every CSS rule's font size. `.col.hot .col-h .ct` (`globals.css:484`) and `.ld-totals dd` use `--fs-xl` legitimately, so a CSS-based guard would go red on those unrelated lines.

**The `hlab` guard** reads the files. It does not spawn `rg`: a process makes it an integration test (0060 §1).
