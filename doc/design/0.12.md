# 0.12 — one set of books

**Status** scope · 2026-11-02 · what 0.12.0 contains and what it leaves out, as
the operator agreed it. How each part is built is in its tickets, not here.

0.11 put the slogan on the front page: *Agents do the work. Lingtai keeps the
books.* 0.12 makes that true twice over. **Inside**, the books agree with
themselves: one reduce per stream, so the board and the conductor give one answer
about one ticket, and one pass is one trace. **Outside**, a person can open
them: one ticket's receipt says what was done and what it cost, setup reads
more kinds of repository, and a setup refusal names the fix.

## Scope

| Track | What is true when it is done | Tickets |
|---|---|---|
| **A. One reduce** | Every stream's reducer exists once, in `@lingtai/domain`. The board presents a domain state and task_view reduces with the same `apply`, so the board and the conductor never disagree about one run or one ticket. | #797 and its children |
| **B. One trace** | The backend packages that do IO are Effects, and a pass exported over OTLP is one connected trace. | #790 and its children |
| **C. The receipt** | A person opens one ticket and reads its books: what the agent was given, what it produced, what passed on which commit, who let it through, what it cost and where it landed — and what is absent. | #806 (design), then the build tickets cut from it |
| **D. Setup** | A Go, Cargo, Maven or Gradle repository gets suggested install and build commands, as Node and Python do. Every refusal `init` and `add` print is one line of what is wrong and one line of the fix. | #696, #697, #698, #704 |
| **E. After the merge** | A page says how a project runs its own integration tests after Lingtai lands a change — on its own CI, or from a subscriber on `TicketLanded` — and how a failure comes back as a ticket. Lingtai itself runs no integration tests. | one `documentation` ticket, to be opened |

Work starts with **A**.

## Done when

0.12.0 is tagged when:

- [ ] **A**: the board and task_view read the domain reduces, and every
  projection whose reduce changed has been rebuilt. Snapshots (0124 §5–§10,
  #797's last row) are not in 0.12.
- [ ] **B**: `event-store`, `projector`, `github`, `repo`/`agent`, `actions`,
  the pass, the daemon and `recipe` are Effects (#790's rows 3–10), and one pass
  on this repository shows as one trace. The `apps/cli` groups and #790's last
  row may move to 0.13.
- [ ] **C**: #806's questions are answered in an ADR, and its build tickets
  have landed.
- [ ] **D**: #696, #697, #698 and every child of #704 have landed.
- [ ] **E**: the page is published.
- [ ] `pnpm typecheck` and `HOME=/nonexistent pnpm test` are green on the tag,
  and the release workflow is green.

## Not in 0.12

Each was raised in planning and set aside by the operator:

- **A per-ticket spend ceiling** (#674): not urgent while the daily ceiling holds.
- **Pausing one project** (#675, #676): stopping the service is enough today.
- **Fewer review rounds** (#338): the data is collected, and the idea is not
  yet clear enough to build.
- **The daemon restarting itself when `main` moves**: it serves one operator,
  who restarts it.
- **Snapshots**, and #810 (the safety self-check).
