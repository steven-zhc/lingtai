## #1415: what the freeze does with tickets already on `main`, and how it picks the PR branch name

All of this goes in `freezePr` (`packages/conductor/src/pr.ts:735`). The domain gets one small change, to `freezeTransition` (`packages/domain/src/pr.ts:681`), and the event schema gets one new refusal value. The project package and the draft stay as they are.

### 1. Read `main` once, from the same fetch as `frozenSha`

The mirror is bare and is fetched with `+refs/heads/*:refs/heads/*` (`packages/repo/src/worktree.ts:78`: *"mirror is bare and fetches `+refs/heads/*:refs/heads/*`"*; the call is at `:146`, with `--prune`). So after the `ports.fetch(project)` that `freezePr` already makes (`pr.ts:751`), `refs/heads/<main>` is current. No second fetch is needed. It does have to be read inside that same `look` loop, right after the personal head is read (`pr.ts:752-755`).

- Use `rev-parse --verify --quiet refs/heads/<main>^{commit}`, the same form as `verify` at `pr.ts:748`. It gives three answers:
  - **0** keeps a `mainSha`.
  - **1** refuses `main-missing`.
  - **Anything else** refuses `git` with `gitSaid`.
- `main-missing` is a **new value** in `PrRefusalReason` (`packages/domain/src/events.ts:2571`, `z.enum(['solo', 'open-pr', 'nothing-landed', 'personal-missing', 'git'])`). The only reader that switches on the reason is the test at `packages/conductor/unit/pr-serve.test.ts:211-216`. Adding a value still parses every old event. Don't reuse `personal-missing`: its detail names a different branch, and a reader acts on the reason.
- Ask every ancestry question against the **sha**, not the ref name. `withOneRetry` (`pr.ts:782`) runs the block a second time after a concurrent landing. Both runs should ask the same `main` the freeze read, just as both use the same `frozenSha`.

### 2. Ask the `main` question first, per ticket

In the loop at `pr.ts:794`, before the existing `merge-base --is-ancestor <mergeCommit> <frozenSha>`, ask `merge-base --is-ancestor <mergeCommit> <mainSha>`:

- **0**: the ticket is already on `main`. Skip the personal question and the ticket-stream read (`pr.ts:799-802`), and add the ticket to a local `onMain` list. It goes into neither `held` nor `notKept`, so `PrInProgress` empties it from the draft (`packages/domain/src/pr.ts:44`).
- **1**: fall through to the existing logic, unchanged.
- **Anything else**: `refuseAt('git', gitSaid(ask, answer))`, the same as `pr.ts:811`.

When `held` is empty and `onMain` is not, the `nothing-landed` detail (`pr.ts:813-816`) says those tickets are already on `<main>` and names them. When both are empty, keep the current sentence.

### 3. Decide the branch name in `freezePr` and pass it to the domain

`freezeTransition` builds the name itself today: `` prBranch: `${frozen.branch}-pr-${state.n}` `` (`packages/domain/src/pr.ts:691`).

- Add a **required** `prBranch` to its `frozen` argument and use it there. Making it required means no caller can fall back to the old name.
- `recordPrInProgress` takes `Parameters<typeof freezeTransition>[1]` (`packages/project/src/pr.ts:271`), so it passes the field through with no further change.
- Restarts already copy `state.prBranch` (`restartTransition` and `fixRestartTransition`, `packages/domain/src/pr.ts:700-745`). Every later step reads the recorded name from the state, as `pushStep` does at `pr.ts:264-265`.
- The other caller is `packages/conductor/unit/land-draft.test.ts:70`. Pass the plain `-pr-1` name there.

**Where the name is computed.** Compute it in `freezePr` after the look loop and **before** `withOneRetry`. That way the remote is read once per freeze, and a concurrency retry reuses the answer rather than asking the remote again.

**What counts as taken.** A name is taken if either source has it:

- **The remote:** `ports.remote(project, ['ls-remote', '--heads', 'origin', 'refs/heads/<personal>-pr-<n>*'])`. It has to be `ports.remote`, not `ports.git`, because `PrPorts.remote` is the port for *"`git` … **against the remote** — `ls-remote`, `push`"* (`pr.ts:89`), and the bounded wrapper treats it as a read (`pr.ts:1111`). Parse whole ref names exactly, the way `remoteSha` does (`pr-git.ts:35-38`), because the glob also matches `-pr-50`. A non-zero exit refuses `git` and nothing is guessed.
- **The log:** the `prBranch` of every other PR of this project, from `listPrs` (`packages/project/src/pr.ts:87`).

The log matters for the ticket's line *"names Lingtai itself pushed for an earlier PR … count as taken too"*. A merged PR's branch is usually deleted on GitHub, and the mirror fetch prunes it, so `ls-remote` alone would let that name be reused.

**The pick.** Take the first free name from `<personal>-pr-<n>`, then `-2`, `-3`, and so on. The search always ends because the taken set is finite.

**Why PR `n`'s own push can't be in the remote yet.** The freeze writes nothing until `PrInProgress`, and no push happens before that. So nothing on the remote at freeze time can be Lingtai's own push for this `n`. Anything already under the name counts as taken.

### 4. Tests (all unit; nothing here needs `pnpm test:integration`)

These are all in `packages/conductor/unit/pr-serve.test.ts`. Its fake breaks in three places under this change:

- **`remote`** is `Effect.fail(new Error('the freeze never reaches the remote'))` (line 69). Every freeze now calls it, so it must answer `ls-remote` from a `taken: string[]` option (default empty, exit 0).
- **`rev-parse`** answers `FROZEN` for every ref (lines 74-78). It must resolve `refs/heads/main` to a separate `MAIN` sha, with an option that answers 1 for `main-missing`.
- **`merge-base`** answers by `args[2]` alone (lines 79-80). It must key on the target too (`args[3]`): an `onMain: string[]` option for questions against `MAIN`, and the existing `reachable` for `FROZEN`. Without this, every reachable ticket drops. The blanket `mergeBase` option must apply only to the `FROZEN` question, so existing tests still mean what they meant. Add a separate option for the 128 case on the `MAIN` question.

The ticket's three Done-when tests go in this file, and the first assertion at line 97 (`'lingtai-team-pr-1'`) still holds when nothing is taken.

Any other test that serves a `requested` PR through a fake port also reaches the freeze; `pr-requests-serve.test.ts` is one candidate. Run `HOME=/nonexistent pnpm test` and fix each fake whose `remote` fails, or whose `merge-base` answers 0 to every question.

Write everything as `Effect.gen` with no new `async`, so `effect-ratchet.baseline.json` stays where it is.

### 5. ADR

0131 is a current topic ADR in `doc/decisions/`, and per CLAUDE.md a change to it is an edit, not a new file. The ticket adds a case without contradicting anything already decided. In the Freeze row (`doc/decisions/0131-a-pr-goes-from-draft-to-merged.md:76`, *"keeps the draft's tickets whose merge commit that commit holds, and hands the rest to the next draft"*), add that a ticket whose merge commit `main` already holds is dropped. Also add that the PR branch name skips any name already on the remote or recorded by an earlier PR.
