# Design note — #556

Make `/dev/waiting/fixable-lines/task` the representative #393-style case. Add a separate wait fixture for it and leave the existing small fixtures intact. Use a `ProposedEscalated` wait with `ReviewFindings` and concrete failure scenarios: `allowedResolutions` adds `GrantFixRound` for that shape, whereas the current gallery case uses `FixerDisagrees` (`packages/domain/src/wait.ts:308`, `apps/board/test/visual-waiting.ts:39`). ADR 0118 calls an unsatisfied review “`ProposedEscalated{ReviewFindings}`” and says “the evidence travels inside the proposal” (`doc/decisions/0118-a-hold-explains-itself.md:141`). Give the fixture a consistent #393 identity, recognized ticket body with the opening table, several findings, and run events that fold into a ten-step rail and an exhausted round budget. Keep the ticket local to the fixture; the gallery route already renders the production `Card` and `TaskBody` inside an inert, development-only surface (`apps/board/src/app/dev/waiting/[name]/[surface]/page.tsx:8`).

**The branch state is the consequential choice.** Record `RunRefsPublished` with a published branch and head, then derive the preview’s `standing.fixWork` through `savedFixWork`; use the fixture’s matching synthetic ref/head as the development-only answer to the remote check. Production first applies that published-head precondition and then compares the remote ref (`apps/board/src/lib/task.ts:891`, `apps/board/src/lib/task.ts:1850`). A missing-head case should retain its refusal state, so the two cases visibly differ: `Standing` recommends `GrantFixRound` only with a head and otherwise offers no continuation button (`apps/board/src/app/standing.tsx:543`, `apps/board/src/app/standing.tsx:868`). The ADR says triage “never supplies an `onSha`” because the person confirms the shown branch state (`doc/decisions/0118-a-hold-explains-itself.md:198`).

Fold a discussion exchange from `DiscussionAsked` and `DiscussionAnswered` events, with any adoption represented separately; the answer’s proposal “is *not* the artefact being adopted” (`packages/domain/src/events.ts:1547`, `apps/board/src/lib/task.ts:1052`). Derive attempt totals from the folded runs and discussion. Leave money unknown unless fixture spend rows support it: `foldRun` says its cost is filled from spend, and `totalsOf` marks runs without rows as unknown (`apps/board/src/lib/task.ts:1371`, `apps/board/src/lib/task.ts:1428`). The reference’s prices and “Take it over” card remain illustrative (`doc/decisions/0118/Outcomes.dc.html:86`); ADR 0118 says mockups “illustrate the decision and do not extend it” (`doc/decisions/0118-a-hold-explains-itself.md`, “Mockups”).

Document the direct task URL and 1200 px and 390 px captures in `visual-gallery.md`; its current guidance gives those widths but only the general case URL pattern (`doc/decisions/0118/visual-gallery.md:12`). Pin the representative and missing-head states at unit level, including findings, discussion, rail, budget, and rendered resolution availability. The gallery already has a unit rendering test (`apps/board/unit/visual-waiting.test.tsx:10`). Run the four requested build checks; the integration suite is outside this pass.
