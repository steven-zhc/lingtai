The freeze and the two closes stay where they are. Each one now reads, decides and writes as one unit inside a retry that covers both streams. Most of this follows from the ticket. The point that does not is **where the retry boundary sits for the freeze**.

## The decision: the freeze's write is pinned to the version its draft list was read at

Today, `recordPrInProgress` goes through `transitionPr` (`packages/project/src/pr.ts:207-218`). That helper reads the PR again inside its own `withOneRetry` and appends at the version it just read (`packages/project/src/pr.ts:143-154`). With this ticket, the ancestry questions are asked over `state.draft`. If `recordPrInProgress` read the stream again, it would append at a version *newer* than the one those questions were asked about.

That is the race the ticket's Edges forbid. A landing between the read and the write appends a `PrDraftTicketAdded` on stream `n`, because `draftOf` returns the `requested` PR as the target (`packages/project/src/pr.ts:119-126`). An append at the new version would freeze a list that never asked git about that ticket.

So:

- **`recordPrInProgress` stops reading the PR.** It takes the `PrState` the freeze decided on, the frozen payload and the tickets not kept.
  - It checks `freezeTransition(state, frozen)` (`packages/domain/src/pr.ts:629-642`).
  - It reads stream `n + 1` once with `store.head`. That stream is `0` when absent; in practice it is always absent, since `requestSubmit` refuses while a PR is open (`packages/domain/src/pr.ts:600-606`).
  - It writes `[{ prStream(n), state.version, [PrInProgress] }, { prStream(n + 1), head, handed }]` with `store.appendAll`.
  - Build each handed event through `addDraftTicket` (`packages/domain/src/pr.ts:614-620`), so the guard stays in one place.
  - Leave out the `n + 1` batch when nothing is handed over. That keeps "today's single append".
  - There is no retry inside it.
- **`freezePr` owns the retry.** Wrap everything from reading PR `n` to the write in `withOneRetry`. That function is exported from `@lingtai/project` (`packages/project/src/commands.ts:33`, re-exported at `packages/project/src/index.ts:8`). The steps inside the wrap:
  - Read PR `n` with `readPr` (`packages/project/src/pr.ts:74`).
  - Ask `merge-base --is-ancestor` for each `state.draft` entry's `mergeCommit`.
  - Read each kept ticket's stream for its title.
  - Refuse `nothing-landed`, or call `recordPrInProgress`.

  A `ConcurrencyError` from `appendAll` runs the whole block once more. `withOneRetry` catches only `ConcurrencyError` (`packages/project/src/commands.ts:33-40`). The `tryPromise` around `appendAll` must keep `catch: (e) => e`, as `transitionPr` does (`packages/project/src/pr.ts:149-152`), so the error class survives.
- **Keep the wait for landings in flight (`packages/conductor/src/pr.ts:750-778`) and `frozenSha` outside the retry.** They are read once. On a retry, a ticket that landed after `frozenSha` is not an ancestor, so it is handed to `n + 1`. That is correct, because the frozen commit does not hold it.

## Titles

`state.draft` entries carry no title: the `PrDraftTicketAdded` schema is `{ ticket, mergeCommit, from }` (`packages/domain/src/events.ts:2557-2561`). Read each kept ticket the way `readDraftOn` does: `reduceTicket(store.read(ticketStream(project, ticket)))`, then `state.title ?? '#' + ticket` (`packages/project/src/pr.ts:524-532`). `t.ticket` is the issue string there.

Read titles only for kept tickets, inside the retry. A failed read fails the effect, and `servePr` serves again (`packages/conductor/src/pr.ts:997-999`).

## The two closes

Write one helper next to `transitionPr`, for example `closeAndHandBack(store, project, n, transition)`, and use it for both `recordPrClosed` (`packages/project/src/pr.ts:401`) and `recordPrTakenBack` (`:690`). Inside one `withOneRetry` it does this:

1. Call `listPrs` once and take PR `n`'s state from that listing.
2. Compute the target with the same `draftOf` that `draftTarget` uses (`packages/project/src/pr.ts:109-126`). Reading through `draftTarget` separately would list the PRs a second time for no reason.
3. Apply `closedTransition` or `backClosedTransition` (`packages/domain/src/pr.ts:924-942`). If it gives `null`, return `false` and write nothing.
4. Otherwise call `appendAll` with `PrClosed` at PR `n`'s version and the hand-back at `target.version`.

`listPrs` reads streams one after another (the comment at `packages/project/src/pr.ts:181-182`). Only the two streams being written matter, and `appendAll` checks both, so the per-stream head re-check that `requestPrSubmit` does is not needed here.

What goes back is decided in a pure domain function next to `closedTransition`, so it can be unit-tested without a store. It walks `state.tickets` in order, with `{ ticket, mergeCommit, from: n }` for each entry, and drops a ticket that is in `state.fixesLanded` but not in `state.mergedBackTickets`. A pr-fix ticket counts as one because `PrFixLanded` puts it in **both** `tickets` and `fixesLanded` (`packages/domain/src/pr.ts:311-330`). Use `fixesLanded` membership, not a ticket-kind lookup. The `mergeCommit` handed back is the one in `state.tickets`. For a pr-fix ticket, that is its landing on the PR branch, which a merge back made an ancestor of `branch.personal`.

`PrClosed`'s reduce (`packages/domain/src/pr.ts:464-467`) stays as it is.

## What the tests stand on

- **Seed the draft with events.** Nothing in `src` writes `PrDraftTicketAdded` yet; the only writer is the seed in `packages/project/test/submit.ts:14-18`. Seed `PrDraftTicketAdded` events on stream `n` before `PrSubmitRequested`, and do not seed candidates.
- **Use the memory store.** It implements `appendAll` (`packages/event-store/test/memory.ts:189`) and is held to the same contract as the real store (`packages/event-store/test/contract.ts:247-360`). The other fake, `packages/conductor/test/one-attempt.ts:153`, throws on `appendAll`, so check that none of the three test files builds its store from it.
- **"Fails the first `appendAll`".** Wrap the memory store so the first `appendAll` call appends one event to stream `n` and then throws `ConcurrencyError`. Assert that no batch from that first call is on either stream, and that the retry writes both streams.
- **The nothing-landed case.** Assert that `reducePr` of stream `n` is `draft`, with `draft.length === 3`. That relies on `PrSubmitRefused`'s reduce (`packages/domain/src/pr.ts:265-267`). Also assert `store.head(prStream(project, n + 1)) === 0`.
- **The "no longer calls" check.** `freezePr` should neither import nor call `readPrDraft` or `ports.candidates`. Keep the `candidates` port on `PrPorts` (`packages/conductor/src/pr.ts:83`), because `readUnheldFixLandings` still uses it at `:1302`.
- **Everything is unit-level.** Every claim in Done when sits on the memory store, so nothing here waits on `pnpm test:integration`.
- **No new `async`.** The new store calls are `Effect.tryPromise` around `store.appendAll` / `store.head`, as at `packages/project/src/pr.ts:149` and `:186`. That keeps the ratchet's `async` and `Effect.run*` counts unchanged.

## Settled by the log, not here

There are three things to check on a run:

- **A frozen PR handed tickets over.** Its `PrInProgress` and the `PrDraftTicketAdded { from: n }` events on `pr-…-(n+1)` have adjacent `seq`s.
- **A closed PR handed tickets back.** Its `PrClosed` is directly followed by the hand-back events on the draft's stream.
- **No pr-fix ticket went back unmerged.** None appears among those events unless it is also in that PR's `PrMergedBack` history.
