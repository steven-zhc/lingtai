# Design: #923 — every paid agent call records its prompt

## The one helper, and where it lives

Put a new file at `packages/conductor/src/record-prompt.ts` and export it from the package index. It holds one function:

```ts
recordPrompt(store, stream, { for, promptVersion, prompt }, log): Promise<void>
```

- It reads the stream's version, appends one `RunPrompted { promptVersion, bytes, prompt, for }` through `parsePayload`, and **never rejects**. On failure it logs one line, swallows the error, and makes no retry.
- `apps/cli` already depends on `@lingtai/conductor` (`apps/cli/package.json:22`), so triage can import it.
- The ticket's edges rule out a retry. Triage's `spend` loop (`apps/cli/src/triage.ts:762-818`) is the opposite pattern on purpose and must not be copied.

**Do not route this through `appendNow` in `conduct.ts`.** `appendNow` (`conduct.ts:724-731`) remembers a refused append in `unappended`, rethrows it, and the pass is then re-raised as a defect: *"the pass is re-raised into the defect channel the moment it returns (see `unappended`)"* (`conduct.ts:719-721`, acted on at `:4281`).

- A swallowed prompt record that went through `appendNow` would still kill the pass. Pass `store` to the helper directly, the same way `appendAt` (`:696-699`) does.
- The same applies to the pipeline's `emit`. `conduct.ts:3553-3566` sends every `ActionEvent` through `appendNow`. So **`RunPrompted` is not added to `ActionEvent`**; it gets a port of its own (next section).

**`promptVersion`** is required (`events.ts`, `RunPrompted`). Use `<call>@<bytes>`, after the `ticket@${prompt.length}` pattern (`apps/cli/src/run.ts:470`): `review@…`, `design@…`, `judge@…`, `fix@…`, `triage@…`, `discussion@…`. It is a label. The `for` is what identifies the call.

## The review and design agents: the action layer does not know its `for`

`ActionSpent` is *"`PayloadOf<'RunSpent'>` with `for` left off, because the action knows neither its step nor its round and the pipeline knows both (#494)"* (`packages/actions/src/action.ts:110-114`). The pipeline adds `for` after the action returns (`action.ts:862-866`). That is too late for the *before `runtime.run`* rule, so do this instead:

- `ActionContext` gains an optional `prompted?: (promptVersion: string, prompt: string) => Promise<void>`.
- The pipeline's options (`action.ts:717`, next to `emit`) gain an optional `recordPrompt?: (p: { for: SpentFor; promptVersion: string; prompt: string }) => Promise<void>`.
- In `runActionPipeline`, before `action.run(context)`, build the `for` **once**: `{ _tag: 'Action', step, name: action.name, round: context.round ?? 0 }`.
  - Use that same value at `:864` for `RunSpent`.
  - Hand the action `{ ...context, prompted: (v, p) => recordPrompt?.({ for, promptVersion: v, prompt: p }) }`.
- In `agent-action.ts`, put the built prompt in a `const`. Call `await context.prompted?.(…, prompt)` and then `deps.runtime.run({ prompt, … })`, for the reviewer (`:693-696`) and the design agent (`:1274-1280`). `prompted` is absent in every existing test that does not set it, so those tests are unchanged.
- In `run-attempt.ts`, `StepWork` (`:636`) and the options at `:849`/`:1955`/`:1994` carry `recordPrompt` through, as they carry `emit` today.
- `conduct.ts` supplies `recordPrompt` as `recordPrompt(store, runId, p, log)`.

## The calls `conduct.ts` dispatches itself

**Judge** (`:2694`, with `RunSpent` at `:2751`):
- Build `{ _tag: 'Judge', when: on.when }` once, above the dispatch.
- Record it, then pass the same value to `runSpentFrom`.

**Fix round** (`:3952-3967`, with `RunSpent` at `:4008-4021`):
- Move `alsoSays(fixBrief(…), spec.prompt)` into a `const` and record that string.
- Move the `for`, grant included (`:4017-4018`), into a `const` above the dispatch and use it in both places.
- The ticket's *"`for` equals the round's `RunSpent.for`"* requires the grant to be in it, so the grant is not optional here.

All three conductor calls write to stream `runId`, the same stream their `RunSpent` goes to.

## Discussion and triage

**Discussion:**
- Record just before `ports.ask(prompt, round, call)` (`packages/conductor/src/discuss.ts:563`), on `stream`, with `{ _tag: 'Discussion' }`.
- What is recorded is the string handed to `ports.ask`. Check whether the port wraps it before `runtime.run`. If it does, record inside the port instead, because the ticket says *as handed to `runtime.run`*.

**Triage:**
- Each read round is its own `.run` (`triage.ts:871`) and its own `RunSpent`. So it gets one `RunPrompted` per round, every one tagged `{ _tag: 'Triage', waitId }`.
- Several prompts under one `for` is correct here: triage's `RunSpent` already repeats that `for` once per round.
- Triage's `deps` needs the store, which it already has (`deps.store`, `:785`).

## The attempt reducer

In `packages/domain/src/attempt.ts:412-423`, the `RunPrompted` case returns `state` unchanged (apart from `...at`, which is fine either way) when `d.for !== undefined`.

- Leave the existing comment's reasoning in place.
- Add one line saying a prompt with a `for` belongs to another call and is read off the stream, not folded into the attempt.

## What settles it on the log

- For a pass with a fix round, the run stream should hold `RunPrompted{for:{_tag:'Action',step:'implement',round:N}}` immediately before that round's `RunSpent` with the same `for`.
- The implementer's own `RunPrompted` should still have no `for`.
- `ticket_report`/`task_view` should show `prompts` unchanged from before.

None of this needs `pnpm test:integration`. The memory store (`@lingtai/event-store/memory`) and a fake runtime cover every *Done when* item at unit level. The *failing store* test can wrap the memory store so that `append` rejects only for `RunPrompted`.
