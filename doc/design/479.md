## Design: #479, three read-model cells

All three changes are in `packages/domain/src/read-model.ts` plus the tests that pin them. Make one commit per cell, in the ticket's order. Each paragraph below covers what the ticket leaves open.

### (1) MergeRefused: optional on the wait, omitted when null, `null` from the Proposal path

**Schema.** `Hold.MergeRefused` stores the three fields as `nullable` (`hold.ts:246-248`). Give `WaitReason.MergeRefused` (`wait.ts:125-131`) the same three as `.nullable().optional()`, so `reasonFromHold` can copy them without converting anything.

**`reasonFromHold` (`read-model.ts:1014-1031`).** Spread each field only when the stored value is non-null, e.g. `...(hold.paths === null ? {} : { paths: hold.paths })`. Do not write `paths: null`. Here is why:
- The forward side (`nextOf`) never sets these fields.
- `toEqual` treats a missing key and `undefined` as equal, but not `null`.
- If you always wrote the keys, every existing `waitsOf` assertion on a `MergeRefused` would fail, for example `read-model.test.ts:1611-1616`, which builds the reason without them.

Then delete the comment at `:1015-1025`. It says *"`WaitReason.MergeRefused` … has no field for any of them"*, which will be false. It also defends `holdForRun` as "the one place … that still reads the stored `Hold` directly … for exactly this reason". Reduce that to what is still true, and do not change `holdForRun`.

**`mergeRefusedHold` (`domain/src/adapters.ts:316-335`).** It has two callers:
- `:384` builds from a `WaitReason`. Pass the reason's three fields, defaulting each to `null`.
- `:556` builds from a `Proposal.MergeRefused`, which has no such fields. It keeps writing `null`.

Do this with an optional trailing parameter, not by changing what `:556` writes.

**Leave `conduct.ts:3796-3810` alone.** That block fills the three fields from `lastIntegrationRefusal` after `holdOf`, because the forward `WaitReason` never had them, and that is still true after this change. Removing it is a forward-side change and a new finding. Its comment says `mergeRefusedHold` writes `null` *"because neither `Proposal.MergeRefused` nor `WaitReason.MergeRefused` carries them"*. Edit it to say that the forward `WaitReason` never fills them. Change the comment only, not the code.

**Test.** Remove the `skipConflictFields` parameter. Its declaration is at `what-a-pass-writes-today.test.ts:161`, its doc at `:141` and its `else` arm at `:180-184`. Also remove the argument at row 10b's call site (around `:1011-1016`). Every row then takes the equality branch at `:176-179`.

Rows whose holds have `paths: null` still pass:
- `holdOf` gets no key and writes `null`, which equals the stored `null`.

### (2) NeverStarted: `ReleaseCause` uses the domain's own `NeverStarted`

Replace the inline `{ _tag: 'NeverStarted'; scope: 'work-item' }` at `read-model.ts:1211` with the exported `NeverStarted` type (`action.ts:74-78`, `scope: z.enum(['conductor', 'work-item'])`). Then make the arm at `:1250-1251` return `scope: 'conductor'`.

That is the widening the ticket asks for, and it adds no third spelling of the union. It is safe because nothing outside `read-model.ts` and its tests consumes `ReleaseCause`. A grep finds only `read-model.ts:1209`.

**Do not change `pass.ts:1338`.** It writes `NeverStarted{scope: 'work-item'}` when the walk falls off the end with nothing landed. That is a `Requeued` end with no `StepNeverRan` behind it, so this arm never reads it.

**Test.** Add it to `packages/domain/unit/read-model.test.ts`'s `describe('releaseCauseOf')` (`:1698`): a claim, then a run whose last terminal event is `StepNeverRan`, then the release. The fixtures are in `packages/domain/test/events.ts`: `aClaim` at `:294`, `aRelease` at `:285`, and `aRun` at `:56` for the run stream. Today no test reaches this arm.

### (3) Interrupted head: remove the `RunProducedDiff` read, not just its round-0 use

Remove `producedDiff` from `commitContextFor` entirely (`read-model.ts:206-214`). Round 0's `head` becomes `RunProposedCompletion.headSha` or `null`. Also delete the comment at `:206-208`. It says the fallback is *"the fallback a run that was interrupted after committing part of the fix still needs"*, which is the claim this ticket reverses. If it stays, the next reader will put the fallback back.

**Why remove it rather than special-case the `Interrupted` arm.** The ticket's Watch out says `RunProducedDiff` is also written for the conductor's own `wip:` commit (`conduct.ts:1848`, `:1591-1593`). If so, its sha is never the agent's work for any arm, not only for `Interrupted`.

The forward side agrees:
- `commitResultOf` (`conductor/src/adapters.ts:206-219`) answers `head: outcome.head ?? null` everywhere.
- `work-action.ts` sets `head` only on the committed branch (`:155`), never on the stopped branch (`:182-187`).

**The trap:** the same read feeds `StepPassed` and `StepAsked` (`read-model.ts:382-385`). If removing it changes any row other than 14a and 14b, stop. Do not update that row. Narrow the change to the `Interrupted` arm at `:389`, answering `head: round === 0 ? null : ctx.head`. A changed third row would be a new finding, and this ticket must not take any on.

**Leave rounds above 0 as they are.** They read `FixApplied.headSha` (`:224-226`), which is a different cell from this ticket's.

**Test.** Rows 14a and 14b (`what-a-pass-writes-today.test.ts:1422`, `:1490`) currently assert only `not.toThrow()`. Have each find its `implement` action in `stepOutcomesOf(...)` and assert `result` `toEqual` `{ _tag: 'Interrupted', cause: <the row's kind>, head: null }`. For 14a the cause is `out-of-turns`, and for 14b it is `timeout`.
