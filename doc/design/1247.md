## Design note for #1247: ask the agent to commit each piece as it finishes it

**Where it goes.** Add the new paragraph inside `checksBrief`'s returned array (`packages/conductor/src/prompt.ts:397-409`). Put it right after `bar` and before the existing bold paragraph that starts *"Once you have changed anything, commit it before you verify something this turn cannot finish."* That way the two commit rules read in order: first, commit each piece that works as you finish it; then, in any case, commit before you start a check this turn cannot finish. Keep the existing paragraph word for word, because #249 and #308 are why it exists. Add one sentence to the doc comment above the function (`prompt.ts:~350-374`) that names 0108 §20 as the reason for the new paragraph.

**The wording.** Ask the agent to commit each piece that works as it finishes it, and say why: when an attempt is cut off, it is redone from the head, so the agent loses only what it had not committed. Do not say that each commit has to pass the commands above it. That is the trap the ticket's Watch out names: the lane checks only the head (#1209). One clause stating that the commands are run against the final head, not each commit, heads off that reading. Don't name #1243 or #1245 in the brief. The agent doesn't need Lingtai's WIP mechanism, and the brief also goes to managed projects.

**There is no prompt version to bump.** The ticket's Prompt-version edge applies only if the version follows the brief's text, and it doesn't. `basePromptVersion` is `options.promptVersion ?? 'ticket@1'` (`packages/conductor/src/conduct.ts:818`). `promptVersionFor(base, failure, human)` (`packages/conductor/src/attempts.ts:615`) hashes only the failure history and a person's edit, so the brief's text never reaches it. Leave both alone.

**Tests.** Two unit files already pin the current paragraph by text: `packages/conductor/unit/prompt.test.ts` and `packages/conductor/unit/fix.test.ts`, both by matching `commit it before you verify`. Add the new assertion beside each of those. Search for a phrase that is unique to the new paragraph, so the test says the paragraph is present in both the implementer's brief and the fixer's. Keep the existing assertions; they cover the "existing paragraph stays" checkbox. Both files are unit, so `HOME=/nonexistent pnpm test` covers this whole change, and none of it needs the integration half.
