## Design: #661, `README.zh-CN.md`

### Where it goes

There are two files and nothing else. `README.md` gets one new first line. `README.zh-CN.md` is a new file at the repository root. Nothing under `doc/` changes, and no code changes. `apps/site` reads only `doc/` (`apps/site/src/lib/docs.ts:37` looks for `doc/README.md`), so GitHub is the only place either file is shown.

### The first lines

The ticket's *Done when* asks for the link "on their first line". In both files that means **line 1, above the `<picture>` block**, which is line 1 of `README.md` today.

`README.md`:

```
English · [中文](README.zh-CN.md)

<picture>
…
```

`README.zh-CN.md`:

```
[English](README.md) · 中文

> 这是 [README.md](README.md) 的中文本。**英文本是正本**；两者不一致时以英文本为准。

<picture>
…
```

The second line of the Chinese file is the *Edges* note. Its wording follows the one already used in `doc/zh/0058-lingtai-is-a-development-pipeline.md:7-8` (*英文本是正本；两者意见不一致时以英文本为准*), so the repository says it the same way twice. This note is the only addition the Chinese file gets.

### What stays byte-identical

- **Every fenced block**, including the `lingtai init` continuation lines and the `<ticket-number>` placeholder.
- **Every inline code span**: `labels: feature`, `created #N`, `tier: sandboxed`, `--sandbox workspace-write`, `~/.lingtai/config.yml`, the env var list, `LINGTAI_*`, and so on.
- **Every link target.** Only the link text is translated.
- The `<picture>` HTML.
- The heading `# Lingtai`.

Some things are also kept in English because the reader types them or sees them on screen:

- The **Approve** button label.
- The issue title `"security"`.
- *Add the next chapter to*, the request text. The tutorial that has the full text is English.

Translate the three bold labels in the security section (**Contained**, **Not contained**, **What to do**). They are prose headings, not UI.

**Doc links stay on the English pages, as the ticket says, even where a Chinese page exists.** `doc/architecture.zh.html` and `doc/the-pass.zh.html` both exist (`doc/README.md:10`, `doc/README.md:22`). The ticket's *Watch out* says the links stay English, so `README.zh-CN.md` links `doc/the-pass.html` and `doc/architecture.html` like the English file. Each of those pages already has a 中文 link in its header (`doc/the-pass.html:369`, `doc/architecture.html:353`).

The ticket's evidence says the README links the Chinese architecture page at `README.md:181`. That is not true of this tree. `README.md` is 124 lines and has no `zh` link anywhere. Ignore that line; nothing depends on it.

### Terms

Use the terms the existing Chinese pages use, so a reader who goes from this README to `the-pass.zh.html` meets the same words:

| English | Chinese |
|---|---|
| ticket | 票 |
| worktree | 工作树 |
| board | 看板 |
| log | 日志 |

`agent`, `recipe` and `pass` stay in English, as they do in `doc/the-pass.zh.html`. Write the product name as `Lingtai（灵台）` the first time it appears in prose, and `Lingtai` after that.

### The security section

This section is where "no softer" can actually go wrong. Each of these sentences must have a counterpart that states the same thing just as flatly:

- The agent runs "as your user".
- The environment filter, with its exception: the agent "can read the file they are kept in".
- Claude Code "has no filesystem sandbox", "can read any file you can", names `~/.lingtai/config.yml` and `~/.ssh`, and "has network access".
- Codex's sandbox refuses writes outside the working directory, `$TMPDIR` and `/tmp`. `tier: sandboxed` is served only by a runtime like that one.
- "Do not assume the sandbox covers reads, or the network." Translate this as an imperative (不要假定…), not as advice like 建议.

### Line wrapping

Write each Chinese paragraph and each list item **on one line**. Do not hard-wrap at 80 columns the way the English does. A soft line break between two CJK characters shows up as a stray space in some browsers on GitHub. Nothing reformats Markdown here, so the source can be laid out this way.

### Checking it

`pnpm fmt:check` and `pnpm lint` will be green, but they say nothing about this change. The `fmt` globs cover only `.ts`, `.tsx`, `vitest.config.ts` and `doc/events.json` (`package.json:16-17`), and `oxlint` (`package.json:18`) lints code, not Markdown. Run them because *Done when* asks for them, then check the claims that actually matter by comparing the two files. Each pair of outputs should be identical:

```sh
# every code block, in order
diff <(awk '/^```/{f=!f;print;next} f' README.md) <(awk '/^```/{f=!f;print;next} f' README.zh-CN.md)

# every link target, in order (the zh file's two extra README.md links show up as the only difference)
diff <(grep -o '](\([^)]*\))' README.md) <(grep -o '](\([^)]*\))' README.zh-CN.md)

# same number of sections
grep -c '^#' README.md README.zh-CN.md
```

The link comparison should differ only by the extra `README.md` link in the Chinese file's note. The English file's new `README.zh-CN.md` link lines up with the Chinese file's `README.md` link on line 1.
