## Design note for #848: the scripted rename, and the five things the ticket's table misses

I surveyed the worktree as it stands, on top of `a0ae7ab8`, with `grep -rhoE "\b(apply|fold)[A-Z]\w*"` over `packages apps scripts`. The plan is the ticket's. Below is where the code differs from the ticket's table, plus three decisions that affect what lands in which commit.

### 1. Rename with a word-boundary `sed` over exact names, not with the language service

The language service skips strings, and some of these names sit inside strings that tests depend on:

- `packages/domain/unit/histories.test.ts:88-92` passes them as arguments: `caseLabels('run.ts', 'applyRun')`, `caseLabels('backlog.ts', 'applyFinding')`. The test title at `:86` also spells all five names.
- `packages/domain/unit/one-reducer.allowlist.json` keys entries on the function name as a string (`"function": "applyRunEvent"`, lines 236, 244, 252).

So the scripted pass is a `sed -E 's/\bNAME\b/NEW/g'` for each name below, run over `*.ts`, `*.tsx`, `*.json`, `*.md` and `*.html` outside the excluded paths. The single exception is `Projection.apply` (see 3).

### 3. `Projection.apply` → `reduce`: the language service plus one targeted line in the JSON

`sed '\.apply\('` would also hit `Function.prototype.apply`. Instead, use the TypeScript `LanguageService.findRenameLocations` on the member at `packages/projector/src/store.ts:200` (`apply(events: readonly Envelope[], ctx: ProjectionContext): Promise<void>`). That rename reaches the caller at `packages/projector/src/projection.ts:158` and every contextually-typed implementation. Write that script in a scratch directory outside the repo and paste it into the commit body, as the ticket says.

In the allowlist, the projector entries with `"function": "apply"` are lines 188 (`backlog.ts`), 196-228 (`spend.ts`) and 260-356 (`ticket-report.ts`). Rewrite them with a sed limited to `"function": "apply",`, in that one file only.

**Leave one synthetic `apply` alone:** `packages/domain/unit/one-reducer.test.ts:178`. Its inline fixture `{ async apply(es…) }` expects `got.sort()` to equal `['apply', 'deliver']`. It tests how the walker names an enclosing method, and it does not name the concept. If you renamed it, the sorted order would flip to `['deliver', 'reduce']`, which is not a mechanical change. Put it on the leftovers list.

After the rename, `grep -rn "apply(events" packages` must find nothing in the projector or the harnesses that the ticket lists.

### 4. `current` → `stale` goes in the hand-edit commit

Flipping `current` to `stale` inverts a value, so it is not a rename. `apps/board/src/lib/task.ts:1107-1109` has to become `stale = !(…)`, and `:1112` becomes `stale: false`. That is a logic edit, and `.git-blame-ignore-revs` is only allowed to name a commit that is *"nothing but a scripted rename"* (CLAUDE.md *Commits*). So:

- **The scripted commit** is the name map (1-3), the prose word forms, and `pnpm fmt`. It must be green across `pnpm typecheck`, `pnpm lint`, `pnpm fmt:check` and `HOME=/nonexistent pnpm test` on its own, because that is the condition for its blame-ignore line.
- **The hand-edit commit** is the leftovers, the `stale` inversion, the glossary clause and the `.git-blame-ignore-revs` line.

Find the readers by renaming the property `StepVerdict.current` (`task.ts:122-130`) with the language service. Then invert each one by hand: `present-run.test.ts:20,25,26` and anything else the rename finds.

The interface is named **`StepVerdict`**, not `StepView` as the ticket says. Fix the doc comment at `:125` too ("False when…" becomes "True when…").

**Do not sed `current` anywhere.** It is a different word, and it stays, in these places:

- the projection chips' `current` (`apps/board/src/lib/backlog.ts:41-53`, `spend.ts:252-266`, `report.ts:185-188`, and their tests)
- `TicketState.lastMove.current` (`task.ts:816`)
- every React ref's `.current`

### 5. The fixture-hash stop is safe to rely on

The prose and identifier passes touch no string that ends up in an event. If `packages/domain/unit/histories.hashes.json` shows up in `git diff --stat` at any point, a sed hit a fixture's payload text, for example in `packages/domain/test/histories.ts`. Narrow the sed; do not re-lock the hash.
