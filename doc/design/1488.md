# Design note: #1488, one ordered list of project questions for `init --local` and `add`

## Where the change goes

**`init --local` is already in the right order, so the code change is in `add`.** `runLocalBranch` asks the questions in this order:

1. The directory (`apps/cli/src/first-project.ts:551`).
2. The mode, through `lingtaiWorld`, which wraps the world in `acceptingDefaults` only for the `--defaults` flag (`:679-691`).
3. The personal branch (`:727`) or the base branch (`:749`).
4. The *Make it from …?* confirm (`:964-972`).

After that it calls `askRecipeEffect` with `local: true` and `mode` already decided (`:1163-1169`). The comment there reads *"Decided above, before the branch was made; `askRecipe` asks no mode of a local project."* `askRecipeEffect` skips its own mode section because of the condition `at.mode === undefined && !at.local` (`apps/cli/src/recipe-flow.ts:330`).

The "one ordered list" is **`askRecipeEffect`'s own sequence**. A local caller answers the head of that list itself and passes the answer in through `at.mode`. Do not try to merge the git-checkout branch logic (`first-project.ts:675-990`) and the GitHub branch logic (`recipe-flow.ts:362-470`) into one function. They check existence against different things (`world.git` against `team.branchExists`), and #1474 just gave both their rerun behaviour. What makes it one list is the order, and the new test holds both commands to that order.

The ticket's line numbers are from before #1474. Today, in `recipe-flow.ts`, the relevant lines are:
- *use every default?* is asked at `:293-301`.
- `askWorld` is built at `:310`.
- The mode, login and personal-branch section is `:322-470`.
- The *making the personal branch* confirm is at `:432` and already uses `world`, not `askWorld`.

## The reorder inside `askRecipeEffect`

1. Keep the draft read and the existing-file seed write (`:288-318`) first. The draft is not the disk, so the seed write stays before every question.
2. Move the whole mode section (`:322-470`) above the *every default* question. Change all its `askWorld` arguments (`askMode` at `:331`, `askLogin` at `:382`, `askPersonal` at `:401`) to one `landWorld`:
   `landWorld = at.flags['defaults'] !== undefined ? acceptingDefaults(world) : world`.
   This is the same expression as `first-project.ts:679`. Only the flag answers these questions; a typed *yes* never does.
3. Then ask *use every default?* and build `askWorld` from its answer, as today. The comment at `:290-292` says the question is asked first so that its refusal says `keptBeforeWrite` (#433). That reason no longer applies. A refusal there is never returned anyway (`:303-309`), so pass it `askKept` and rewrite the comment to say why it now sits where it does.
4. **The login moves with the mode.** It sits between the mode and the personal branch, and the personal branch's default is computed from it (`defaultPersonalBranch(login, …)`, `:403`). Moving it also fixes a refusal that exists today. `askLogin` has no fallback (`apps/cli/src/team.ts:56-71`), so on an App machine a *yes* to defaults answers it with `''`, the validation refuses that, and the repeated prompt gets `null` from `acceptingDefaults` (`apps/cli/src/question.ts:131-142`). Under `--defaults` with no login known, the run is refused and the refusal names `--login`, which is the ticket's non-interactive edge.

`add-github.ts` already passes `local: false`, no `mode`, and a `team` port (`apps/cli/src/add-github.ts:537-590`), so it needs no change for team mode.

## Solo on `add`: the working branch is now asked

The Want puts *the working or personal branch* in the list for both commands. Today a solo `add` asks no branch question. `branch.main` comes silently from `--main` or GitHub's default branch (`add-github.ts:465-478`), and the only later landing question is `askLanding`'s *when an attempt is ready* (`apps/cli/src/landing.ts:166-175`). `init --local` asks *"the branch this project's recipe governs and merges into"* (`first-project.ts:749-753`). Decided:

- **The question.** In the `mode === 'solo' && !at.local` case, `askRecipeEffect` asks a question with the same name, flag and prompt as `first-project.ts:749-753`: `name: 'the base branch'`, `flag: '--main <branch>'`, the same prompt text, `given: at.flags['main']`. It is asked through `landWorld`.
- **Its default.** The default is the `mainBranch` value already computed at `:389-398` (the seed, then the recipe's own value, then `at.defaultBranch()`). Hoist that computation above the team/solo split so both modes use it. On a rerun, pass the recipe's value as `current`, as #1474 does.
- **Checking the answer.** Check it with `at.team.branchExists`. That port is passed on every GitHub call (`add-github.ts:539-546`), even though its doc comment says it is team-only (`recipe-flow.ts:118`); fix that comment. `'unreadable'` is refused, worded like `:413-416`. An absent branch is refused with *"… is not a branch on GitHub"*. A solo GitHub project lands on an existing branch, and nothing is pushed.
- **Writing the answer.** Write it at `branch.main`: into `collected` on a new recipe, and through `writeOrRefuse` on an existing one, the same split as `:466-469`. On a new recipe it must win over the seed's `branch.main`.
- **`--main` on the command line.** It already sets the seed (`add-github.ts:466`), so it answers this question and nothing new is asked. Add `'main'` to the flags deleted after `askRecipe` (`add-github.ts:601-623`) only if `runGithubBranch` would otherwise refuse it. Check `first-project.ts:1411` before adding it.
- **The headless cost.** A headless `lingtai add o/r --mode solo` with no `--main` and no `--defaults` is now refused, and the refusal names `--main`. That is the ticket's edge. `FULLY_FLAGGED` (`apps/cli/unit/recipe-flow.test.ts:438-451`) gains `main: 'main'`.

## Tests that change, and the three new ones

**Existing tests that encode the old order:**
- `recipe-flow.test.ts:394-407`: a typed *yes* asks only *use every default?*. That test runs with `local: false` and no `--mode`.
- `recipe-flow.test.ts:488`.
- `apps/cli/unit/add.test.ts:157-168`: the local-path regex list. It passes `--mode solo`, and local is unaffected, so check it rather than assume it changes.

Each of these is now expected to ask the mode and the branch first. Change the expectations; do not pass a flag to dodge the change.

**New tests (unit; fakes only, no process or filesystem):**

1. **Same list.** Run `init --local` through the `answerer` and `run` harness in `apps/cli/unit/first-project.test.ts:2044-2075`. Run `add` through `apps/cli/unit/add-github.test.ts`'s harness.
   - Set up both runs the same way: team mode, a known `gh` login, *no* to *use every default?*, and the same recipe flags.
   - Give `add` `--tickets github` as well. A local project is never asked where its tickets come from (`apps/cli/src/source.ts:81`: *"there is one legal answer (`db`)"*), so that question exists on one side by design.
   - Compare the prompts after removing the `[default]: ` suffix (the test's `bare`) and after mapping the two *Make it from …?* wordings to one token. The wordings differ (`first-project.ts:969` and `recipe-flow.ts:436`), and wording is out of scope.
   - Write the token map in the test file, not in `src/`.
2. **A typed yes still asks the mode and the branch.** `add`, *yes* to defaults: the recorded prompts begin with *Does anyone else work on this repository?* and *the branch Lingtai works on*, both before *use every default?*.
3. **`--defaults` asks nothing.** `add --defaults`, with a world whose `ask` throws: zero prompts. The card's team rows name the branch: `works on <personal>` (`apps/cli/src/setup-card.ts:245`). A solo run's card has `lands on <base>` (`:237`). Those rows are mode-specific, so they are how the card names the mode. Add no new row.

None of this needs `pnpm test:integration`. The change is new code inside existing `Effect.gen` bodies, with no new `async` and no `Effect.run*`, so the ratchet is not touched.

## Edges the ticket leaves to the design

- **Ctrl+C.** `at.onDraft` (`recipe-flow.ts:287`) still runs before any question, so an interrupted rerun still saves what was answered (c3368ba3c). A new recipe still writes nothing before *register*, because the mode answers go into `collected` on the absent path, which is unchanged.
- **A rerun that changes the mode or the branch.** `changed.mode` and `changed.branch` are built inside the section being moved, so they move with it unchanged. A solo base-branch change on a GitHub rerun leaves nothing behind (no branch is made), so it adds no `RecipeChanged` field.

## ADR

Add a new item **§8** at the end of `doc/decisions/0125-setup-is-one-module-two-inputs.md`'s Decision. Adding it at the end keeps the existing `§6` and `§7` citations valid. This repository edits a topic's ADR rather than writing a file beside it (CLAUDE.md, *"A decision that changes is an edit to its topic's ADR"*). The new item extends §2 (*"neither asks a question the other does not"*) and §6 and contradicts nothing. Its text:

> `lingtai init` and `lingtai add` ask a project the same questions in the same order: where the code is, solo or team, the working or personal branch, *use every default?*, the recipe's questions, *register?*. `init` asks only this machine's own questions before them. *Use every default?* answers only what comes after it; the mode and the branch take their defaults only under `--defaults`, and the card names them.
