# #1348: re-reduce a stored row of an older shape (design note)

## Where the stream reader comes from (the decision the ticket does not make)

A reducer cannot read the log today. `Projection.reduce(events, ctx)` (`packages/projector/src/store.ts:201`) gets only the projection's own SQL context. The runner already holds the log as `eventsPort` (`projection.ts:212-218`) but uses it only to feed `follow`. `commitBatch` (`projection.ts:200-205`) calls `projection.reduce(events, ctx)` and nothing else.

**Give `reduce` a third argument. Do not put it on `ctx`, and do not use a Context service.**

```ts
// store.ts
export interface ProjectionLog {
  /** The stream, every event: `EventsPort.read`. A failure is a defect, as every log read is. */
  read(streamId: string): Effect.Effect<Envelope[]>
  /** A line a person should see. Said at most once per (projection, stream) per process. */
  note(line: string): void
}
reduce(events: readonly Envelope[], ctx: ProjectionContextPort, log: ProjectionLog): Effect.Effect<void>
```

- **Why not `ctx`:** both stores build `ctx` inside `transact`. A log on it would make every store carry an event store it has no business holding.
- **Why not a service:** `reduce`'s `R` is `never`. A service would widen the type of every projection, the backlog one included, and every caller.
- **Runner (`projection.ts`):** `commitBatch` does `yield* eventsPort` and passes `{ read: (s) => events.read(s), note }`.
  - `note` comes from a new `ProjectionRunnerOptions.note?: (line) => void`, deduped through a `Set` keyed `` `${projection}\u0000${stream}` `` in the runner's closure.
  - Left out, `note` is `console.error`, as `listenForIdleErrors`' default write is (`postgres.ts:234`).
  - `defaultRunnerFor` (`daemon.ts:157-162`) passes `note: options.tell ?? options.log` when the daemon has one. `tell` is documented as *"The projections' failures, which a person needs"* (`daemon.ts:63-64`).
- **Promise face (`store-face.ts:106-108`):** `reduceFace` gains an optional fourth `log`. Its default `read` dies with `new Error('no log was handed to this reduce')`, and its default `note` does nothing.
  - The ~16 unit files that call `reduceFace` (grep `reduceFace` under `packages/projector/unit`) are untouched.
  - An old-shape row reached through one of them still stops it. That is the behaviour today, now with a different message.
- **Projections that ignore it:** `backlog.ts:165` and the contract projection (`packages/projector/test/contract.ts:83`) just don't name the parameter.

## The one helper

In `packages/projector/src/ticket-row.ts`, next to `reduceStoredTicket`, add an Effect:

```ts
ticketBefore(stored: unknown, stream: string, beforeSeq: bigint, projection: string, log: ProjectionLog)
  : Effect.Effect<{ state: TicketState; reReduced: boolean }>
```

1. `stored === undefined` → `emptyTicket`, `reReduced: false`.
2. Otherwise `decodeTicket(stored, projection, stream)` inside `try`.
   - Catch **only** `e instanceof TicketCodecError`. Rethrow anything else unchanged.
   - Do the catch in plain synchronous code. `decodeTicket` throws (`ticket-codec.ts:172-178`); it does not fail as an Effect.
3. On the codec error:
   - `yield* log.read(stream)`.
   - Keep only `e.seq < beforeSeq`.
   - Reduce them from `emptyTicket` with `reduceTicketEvent`.
   - `log.note(...)` with the ticket's sentence, using the codec error's `(…)` part as `<what>`.
   - Return `reReduced: true`.

`reduceStoredTicket` becomes an Effect over `ticketBefore(stored, event.streamId, event.seq, …)`, and still returns `{ before, after }`. Write the run twin, `runBefore`, the same way with `decodeRun`/`RunCodecError`/`emptyAttempt`/`reduceAttemptEvent`.

Choices made here:

- **The bound is `seq`, not stream version.** `EventsPort.read(streamId, fromVersion?)` takes a version (`event-store.ts:397`), and the caller often has only an event from *another* stream: a `RunSpent` on a pass stream, or a run event in `task_view`. Read the whole stream and filter by `seq`. It is one stream, never `readAll`.
- **The filter is correct because each projection has one writer (0100 §13).** A stored row equals the stream's events with `seq` below the first event in this transaction that touched that row.
  - `task_view` caches a row once per batch (`task-view.ts:511-512`), so the first load is at the first event touching it.
  - `spend` and `ticket_report` re-read the row for each event inside the same transaction.
- **Rethrowing rather than catching wider** is what keeps the *Watch out* row true. A `reduceTicketEvent` throw during the replay is a defect and stops the runner, exactly as a throw on the live event does. `follow`'s `onError(…, 'handler')` sets `failure` (`projection.ts:250-253`) and the daemon records it (`daemon.ts:283-288`).

## The call sites, and what "written back" means at each

A re-reduced state must be **written even when the event would not otherwise write the row**. Otherwise the row stays old and every later event pays the stream read again.

- **`task-view.ts:524`, `:538` (`Cache.task`), and `:566` (`Cache.run`):**
  - `Cache.task(taskId)` takes no event. Give `Cache` a `seq` field that `reduce` sets before each event, and a `log`.
  - `:524` and `:538` use `ticketBefore(…, taskId, cache.seq, 'task_view', log)`.
  - `:566` uses `runBefore(…, runId, cache.seq, …)`. A run's stream id is its `runId` (`task-view.ts:691`).
  - A re-reduced entry is created with `dirty: true`, so `flush` (`task-view.ts:592-640`) rewrites the run row, the ticket row, or the staged `task_view_ticket` row in full, derived columns included.
  - This also covers `Cache.task` loading the latest run (`task-view.ts:548`). That is how `task_view` stores an `AttemptState`, and it is the only projection that does: `decodeRun` has one projector caller (`task-view.ts:566`).
  - `decodeControl` has no projector caller at all: grep finds it only in `packages/domain`. Say both in the commit body.
- **`spend.ts:285`:** `reduceStoredTicket` becomes the Effect. The upsert right after it already writes the row.
- **`spend.ts:229`:** a `RunSpent` reads only `.kind`. Use `ticketBefore(latest.state, ticket, seq, SPEND_TABLE, log)`. When `reReduced`, upsert `spend_ticket` with that state, the same statement as `:288-292`.
- **`ticket-report.ts:714`:** `reduceStoredTicket` becomes the Effect, and `save` already follows.
- **`ticket-report.ts:701`, `:715`:** use `ticketBefore`.
  - `:715` already reaches `save` (`:719`).
  - `:701` saves only `if (signOfLife(…))`. Change it to save when `signOfLife(...) || reReduced`.
  - The other `ticket_report` columns (`machine_ms`, `cost`, …) are kept as `load` read them (`ticket-report.ts:273-293`). Only `ticket_state` was the wrong shape.
- **`ticket-report.ts:221` (`ticketReportRowOf`) is not touched.** This is the answered question: it keeps throwing and naming `lingtai projection rebuild ticket_report`. Add a one-line comment there saying the writer re-reduces and this read does not, and point to the follow-up ticket.

`decodeTicket`'s message keeps its `lingtai projection rebuild` remedy unchanged, as the ticket's fix list says. It is still what `:221` and any reduce without a log show.

## Edges this decides beyond the ticket

- **A read that fails:** `EventsPort` reads *"fail with nothing"*; every failure is a defect (`event-store.ts:387-390`). A failed `log.read` therefore dies inside `reduce`, the transaction rolls back, and the runner stops on that error. Nothing maps it to an empty array.
- **An empty stream:** a stream that reads back empty while a row exists is still a re-reduce to `emptyTicket` filtered to nothing. Don't special-case it. A row with no events behind it can only come from a log reset, and that comes with a rebuild anyway.
- **The once-per-stream note is per process.** A restart forgets it and says it again if the row was not written, for example because the transaction rolled back. That is the correct reading.

## Tests (all in the `unit` project, memory store)

Use `fromPromiseStore(createMemoryEventStore())` as the `read`, and a spy as `note`.

- **`task_view`, `spend`, `ticket_report`, one test each:**
  - Append a ticket's events to the memory store and reduce all but the last through `reduceFace` with that log.
  - Overwrite the stored state with today's encoding minus `landed`.
  - Reduce the last event.
  - Assert:
    - the row decodes with `decodeTicket`;
    - it equals the full fold;
    - `note` was called once with the stream named;
    - the promise resolved.
  - Put them beside the existing files, e.g. `task-view-reduce.test.ts`, `spend-ticket.test.ts`, `ticket-report.test.ts`, or add one `old-shape-row.test.ts`.
- **`spend` on a pass-stream `RunSpent` (`:229`):** the `kind` comes out right and the row is rewritten.
- **A read that dies:** the same setup with a `read` that dies. `reduceFace` rejects with that error, and the stored row is unchanged.
- **A shape error that is not a codec error:** the existing reducer-throws test (`runner-reducer-dies.test.ts`) still passes. Add none.
