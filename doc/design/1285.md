# Design: the *handled for you* panel on `/report` (#1285)

## The shape in one paragraph

This is a server-rendered panel with no client state, the same as the rest of `/report` (`page.tsx:9-12`: *"Nothing is cached and nothing is client state. The filters are the address"*). It is a `HandledPanel` in `apps/board/src/app/report/panels.tsx`, rendered in `page.tsx` between `<Tiles …/>` (`:128`) and `<section className="rp-grid">` (`:129`), as `<section className="hfr" id="handled">`. Use the mock's own class names and CSS (the `hfr-*` block in the first tab's `<style id="hfrcss">`), copied into `globals.css` after the `.rp-*` rules (`globals.css:3312-3341`). Drop the rules the final mock no longer uses: `.pill*`, `tr.tot`, `.y`. The hero, ticks, table and day bars are plain HTML/CSS like the mock, not SVG. Hover is a `title` attribute, as the mock has it. There are three pieces: the copy and colours in a new `apps/board/src/lib/handled.ts`, a small addition to `report()` in `packages/conductor/src/report.ts`, and the drill-down address in `lib/report.ts`.

## What `report().handled` lacks, and where the gap is filled

`Handled` (`packages/conductor/src/report.ts:197-206`) carries:
- `kinds` with `{system, you}`;
- `days` with `{system, you}` only;
- `latest`, which is the 8 newest;
- `answeringCost`.

The mock needs two things it does not have:
- **the per-day bars stacked by kind**;
- **every problem of a kind, for the drill-down**.

`lib/report.ts:4-6` says the board computes no figures (*"The figures themselves are `@lingtai/conductor/report`'s — this file computes none of them, so the page and `lingtai report` cannot disagree"*), so both are added in `report.ts`. This does not change any counting rule:
- **`Handled.days[]` gains `kinds: { kind, system, you }[]`**, built from the same `raised` list (`:556-558`) as `days` already is. Only kinds with a non-zero count are listed, in `PROBLEM_KINDS` order.
- **Move the `raised` computation (`:556-558`) into an exported pure `handledProblems(input: ReportInput): HandledProblem[]`**, newest first, with the same sort as `latest` (`:566-567`). `report()` calls it, and the page calls it only when the address asks for a drill-down. Do **not** put the full list on `Report`: the CLI spreads the whole result into `--json` (`apps/cli/src/report.ts:348`), and a year's problems would land in every report document.
- **`HandledProblem` gains `outcome: ReportTicketRow['outcome']`**, taken from the ticket row in the same `flatMap`. LATEST says `landed` when the ticket has landed (the mock's third tab: *"LATEST rows link to the ticket and say landed when it has"*), and the drill-down has an outcome column.

`latest` stays at 8. The panel shows `latest.slice(0, 6)`, because the mock trims LATEST to six. Unit-test both additions in `packages/conductor/unit/report.test.ts` beside the existing `handled` case.

## The copy, the order and the colours: `apps/board/src/lib/handled.ts`

Create one constant, `HANDLED_ROWS`, keyed by `ProblemKind`. Each entry is `{ wrong, did, hover, colour }`, with the text copied verbatim from the mock's third tab (*"开票以这一页为准"* — that tab is the source the tickets are opened from). The home card ticket imports the same constant: the third tab's rule is *"one per kind, the same on the home ticks, the /report ticks, the per-day bars, the table dots and the LATEST dots"*.

**Order** is the copy tab's order, *"one row per kind, in this order"*:
- review-fixed, base-moved, conflict, build, stopped, review-restarted, disputed, too-big;
- then asked, setup.

This is **not** `PROBLEM_KINDS`'s order (`packages/domain/src/problems.ts:24-36` puts `review-restarted` second). The mock is what the side-by-side check compares against, so the row order lives in `HANDLED_ROWS` and `PROBLEM_KINDS` stays the set. Add a unit test that every `PROBLEM_KINDS` member except `other` has an entry.

**Colours**, as the mock draws them, except two:

| kind | mock | here |
|---|---|---|
| review-fixed | `--s1` | `--s1` |
| base-moved | `--accent` | `--accent` |
| conflict | `--s3` | `--s3` |
| build | `--signal` | **`--s5` (new)** |
| stopped | `--s2` | `--s2` |
| review-restarted | `--s4` | `--s4` |
| disputed | `--held` | `--held` |
| too-big | `--warn` | **`--s6` (new)** |

- **`too-big` changes too, though the ticket names only `build`.** `--warn` is `#b8860b` / `#e6b422` (`globals.css:26,66`). That is amber, and the reason the ticket gives for replacing `--signal` (`#9c5a08`, `globals.css:24`) applies to it word for word: 0123 §7, *"amber never used, since amber means a person is waited on"*. Say so in the commit body so the side-by-side reviewer expects it.
- **Two new tokens:** add `--s5` and `--s6` to both palettes beside `--s1`–`--s4` (`globals.css:35-38`, `:73-76`). Each must be a hue that is none of the board's states and is distinct from `--s1`–`--s4`, `--accent` and `--held`. That means no amber, red or green (0123 §7: *"Chart series use colours that are none of the board's states (not amber, red or green)"*). A slate blue-grey and an orchid/magenta distinct from `--s4`'s pink are the two free regions. Also update the `charts.tsx:9` comment (*"Series colours come from `--s1`–`--s4`…"*).
- **`--pass` stays where the mock puts it:** the label, the check icon and the `.d` verbs. That is text, not a series, and the ticket says to keep everything else as drawn.

## The panel, piece by piece

- **Header:** `Handled for you` on the left. On the right, the window in the mock's form:
  - 7 days and ranges: `Nov 12 – 18 · 7 days`, or `Oct 30 – Nov 5 · 7 days` across a month;
  - today: `Nov 19 · today`.

  The label is built from `query.window.from` and `query.window.to` minus one day, as `reportHref` does (`lib/report.ts:121`).
- **Hero:**
  - *N* is Σ `system`, and *M* is Σ `you`.
  - The share is `system / (system + you)`, rounded, but **clamped to 99% when M > 0 and to 1% when N > 0**, so a page never says 100% beside "1 needed you".
  - The sub-line is the copy: *each would have stopped the work until you stepped in*.
- **Tick strip:**
  - One `<i>` per problem: system marks grouped by kind in row order, then the `you` marks hollow (`i.you`), as the mock does.
  - **Above 60 problems** (`TICK_LIMIT`), draw one `<i>` per (kind, group) with `flex-grow` set to its count instead of a mark each. A 366-day range must not render thousands of nodes. The colours and order stay the same.
- **Table:** the two groups split on `answeredBy`, so each group's total equals the hero figure beside it.
  - **LINGTAI AUTO-FIXED** has one row per kind with `system > 0`: `wrong → did` and the row's hover.
  - **NEEDED YOU** has one row per kind with `you > 0`:
    - `asked` and `setup` use their own copy, with a hollow dot and the `.y2` class.
    - **Any other kind answered by a person** (for example an escalated review that a person approved: `problemsOf` makes that `you`, see `doc/design/1284.md` *"answeredBy: system exactly when the deciding resolution has by === 'triage'"*) shows that kind's `wrong` text only, with no arrow and no *auto-* verb, because nothing was auto-done. Its `hover` is reused.
  - **A row appears only when its count is non-zero.** A group with no rows still shows its header with `0`, which covers the *nothing needed you* edge.
  - **`other` has no copy.** Show it last in its group, labelled `other`, muted, with no hover sentence. This follows the ticket's edge: a new kind *"appears as a row only once it has copy; until then it is in other."*
- **Cost line**, inside the table's column (`.hfr-cost`, `margin-top:20px`, no rule above it). It follows the mock's sentence, with the money split per 0123 §3:
  - Wording: *Solving these cost **$R reported · ~$E est.**[ + n unknown] in agent runs — **P%** of the week's spend. Click any number for the tickets.*
  - *the week's* becomes *today's* for `today` and *the range's* for a custom window.
  - P is known cents over the window's known cents. Take `centsOf` and the `denominator` the *answering refusals* tile already uses (`panels.tsx:150-158`), so the two never round differently.
  - When nothing known was spent, show no percentage, in the tile's own words.
  - The figure is `handled.answeringCost`, as the data ticket defined it. It will not equal the tile's, and it does not in the mock either ($561.74 against $582.11).
- **Per day · share without you:** a column per `handled.days` entry, stacked by `days[].kinds` in row order, with `you` on top and hollow.
  - Heights are scaled to the largest day, with the max stack height taken from the mock.
  - Each column shows its own share and `Thu 13`.
  - A day with no problems has an empty stack and `—`.
  - **Over 14 days**, only every ⌈n/14⌉-th column carries its labels.
  - Every column's `title` gives that day's exact system and you figures. 0123 §7: *"Every chart has a hover with its exact figures"*.
- **LATEST:** six rows. Each has a dot, `#issue` linking to `/task/<ticket>` (as `TopPanel` does, `panels.tsx:398`), the `did` verb (or `needed you`), `landed` in `.ok` when the outcome is landed, and the time. The header link is `all <system+you> →`, pointing to the drill-down for `all`.
- **Empty window:** when Σ is 0, the whole panel is the header plus one `.rp-empty` line, `no problem was raised in the window`. There is no hero, ticks or chart.

## The drill-down address

`ReportQuery` (`lib/report.ts:18-29`) gains `handled: { kind: ProblemKind | 'all'; by: Answerer | null; before: Cursor | null } | null`, parsed in `reportQuery` from three parameters:
- `handled=<kind|all>`;
- `by=system|you`;
- `before=<iso>,<seen>,<ticket>`: the last row's time, how many rows of that very `(at, ticket)` key were already shown, and the ticket (`parseHandledCursor` in `lib/report.ts`).

The rules for the address:
- **`handled=` is a problem kind; `kind=` is still the ticket kind filter.** They are different words, and both apply together.
- A `handled=` value that is not a `PROBLEM_KINDS` member or `all` is dropped, and `note` says *that problem kind was not read — showing the whole panel*. This follows the existing note pattern (`:67-71`).
- `reportHref` carries `handled`, `by` and `before` when they are set and appends `#handled`. That keeps TopPanel's sort links (`panels.tsx:372-375`) from losing the drill-down.
- **The filter form carries `handled` and `by` as hidden inputs but not `before`.** A cursor belongs to one window; a new window starts at its newest row.

Which link opens which drill-down:

| link | `handled` | `by` |
|---|---|---|
| table row count | that kind | that row's group |
| group total | `all` | that group |
| hero N | `all` | `system` |
| hero M | `all` | `you` |
| LATEST's link | `all` | — |

When `query.handled` is set, `page.tsx` calls `handledProblems(...)` with the same input as `buildReport` and filters it by kind and `by`. The panel renders its header, then a back link (`← handled for you`, the same address without the three parameters, `#handled`), then the table:
- **Heading:** the row's copy, then `showing a–b of m`.
- **Columns:** when (`Tue 18:40`, with the date once the window passes 7 days), ticket, what happened (`wrong → did`), who answered (`Lingtai` / `you`), and outcome.
- **Paging:** 20 rows a page, with one extra read to know whether `earlier →` exists, as `/landed` does (`lib/landed.ts:23`). The cursor is the last row's `(at, ticket)`, and rows are those strictly after it in (at desc, ticket asc) order.
  - Problems sharing both `at` and ticket are not lost at a page boundary: `seen` says how many of that key were shown. Rows ahead of the cursor are counted with the same `localeCompare` that `handledProblems` sorts by, so the two orders cannot disagree.
  - A cursor pointing at a row that has since left the window still works, because the cursor is a position in the order and not a row id.

## Edges the ticket leaves open, decided

- **A failed read:** the panel lives inside the `report !== null` branch (`page.tsx:121-126`), so a failed read, drill-down included, is the existing one-line failure and nothing else.
- **A stale page or projection:** the bar's chip covers it (`page.tsx:110-112`). The panel adds nothing. A reload re-reads `ticket_report` (`lib/report.ts:140-151`).
- **Restarts, two passes at once, pause, retry:** none of these apply. The page only reads.
- **Cost to later tickets:**
  - A new `ProblemKind` without a `HANDLED_ROWS` entry fails the coverage test. That is deliberate: the alternative is a kind that silently shows as a bare name.
  - The home card ticket reads `HANDLED_ROWS` rather than its own copy.
- **Effect ratchet:** nothing here is `async` or IO apart from `page.tsx`, which is already a host edge. `handledProblems` is pure. The baseline does not move.

## ADR

0123 lives in `doc/decisions/` (the current style), so it is **edited in place** and not superseded. In §7's list (`doc/decisions/0123-the-report-counts-what-the-log-holds.md:222-235`), add a bullet between the figure tiles and the five panels:
