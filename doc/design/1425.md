## Layout decision

There are six boxes, and the ticket caps a row at about six. Use **two horizontal lanes** in a viewBox about 864 wide, the same width as concepts.svg's `viewBox="0 0 864 400"`, so both diagrams scale the same way on a page:

- **Top lane**, labelled `lingtai-base` (your branch). Steps 1–5 sit left to right: Ticket → Attempt → Lands on `lingtai-base` → Draft → `lingtai pr submit`. Under box 3 put the note *nobody asked · tickets stay open*. Under box 5 put *freezes one commit → `lingtai-base-pr-<n>`*.
- **Bottom lane**, labelled `main`. It holds box 6 only: *A person merges `lingtai-base-pr-<n>` · merge commit · tickets close*. Draw it with `.accent`, since it's the one step a person takes. Exactly one arrow enters this lane, from box 5 down to box 6. If the Attempt box reaches `main` by any path, the picture says the wrong thing.

Five boxes of about 140px plus gaps fit in 864. Labels that don't fit go on a second `.note` line, not into a smaller font. Leave out the merge of `main` back into `lingtai-base` (`doc/team.md:91`). It's true, but it would draw a second edge between the lanes, and the point of the picture is that only one edge crosses.

Use the 0.16 vocabulary from `doc/team.md` only: *draft*, *submit*, *merge*. Leave out *In review*, the five board states, CI, `pr-fix`, and anything else from the `doc/milestone/0.16.0/team-mode/*.html` mocks.

## Word budget: the non-obvious constraint

Right now `doc/team.md` comes to **736** words with `proseOf`'s rule (`apps/site/unit/docs.test.ts:121-125`: fenced code removed, then split on whitespace). The cap is 0112 §14 (`doc/decisions/0112-the-site-projects-the-repository.md:107`: *"A chapter is 600–800 words and never more than 800"*). That leaves **64 words**. The link line uses 6 of them and the image token at least 1, so **the alt text has to stay under about 50 words.** concepts.svg's `<desc>` is 70 words, so its pattern doesn't fit here as-is. Write `<desc>` so its **first sentence is the alt text** (about 30 words, e.g. *"A ticket's attempt lands on your branch, lingtai-base, with nobody asked; lingtai pr submit freezes it as lingtai-base-pr-<n>, and only a person's merge commit moves main."*). Later sentences in `<desc>` can name the draft and when tickets close. Recount after editing.

## The word test the ticket refers to doesn't exist

`Done when` says team.md "stays within its word test", but no test counts team.md. `grep -n team apps/site/unit/docs.test.ts` finds only `:237` (the tutorial links to `team.md`) and `:620` (its neighbour is `connect-github.md`). The sibling chapters each have one (`connect-github` at `:127-131`, `concepts` `:145-149`, `solo` `:217-219`). Line 143 of 0112 says *"No test counts the words, so the reviewer is the only check."*

**Decision: add one,** next to the others in `apps/site/unit/docs.test.ts`, modelled on `concepts`' (`:145-149` and `:380-381`). It reads `doc/team.md` and asserts:
- `proseOf(body) <= 800` (#1425);
- `body` contains `(img/team-flow.svg)`;
- `body` contains `[Open the diagram at full size](img/team-flow.svg)`;
- `readFile(doc/img/team-flow.svg)` resolves to text containing `<svg`.

Don't assert a lower bound of 600 or a heading list. team.md has no such test today, and pinning its sections is out of scope. This doesn't contradict the ticket's line that no test pins the drawing: the assertions check that the file exists and is embedded, and say nothing about its content. It is the unit-level claim that stands in for the by-eye check, which nothing in `pnpm test` can do.
