## Design note for #734: show checks the trial never ran as not run

### The type: replace `ok` with a three-way `outcome`

```ts
export type TrialResult =
  | { command: string; outcome: 'passed' | 'failed'; evidence: string }
  | { command: string; outcome: 'not-run'; because: string }
```

Delete `ok`. Do not add a `notRun` flag next to it. The bug lives in one line: `results.filter((r) => !r.ok)` (`apps/cli/src/setup-build.ts:273`). Any version that keeps `ok: false` on a not-run result keeps that filter correct to the compiler and wrong to the person reading it. With `ok` gone, `tsc` points to every reader:

- `setup-build.ts:273`
- `trial-build.ts:191`
- the `ok` assertions in `apps/cli/unit/trial-build.test.ts:51,59`
- the hand-built results in `apps/cli/unit/setup-build.test.ts:481` and `apps/cli/unit/recipe-flow.test.ts:442`

A not-run result has no `evidence`, because nothing ran to produce any. It has `because` instead.

### The cause is worded once, in `trialBuild`

`trialBuild` is the only place that knows why a command was skipped, so it writes the clause. `tryTheBuild` prints `not run: ${r.command} — ${r.because}` and never builds wording itself. There are three causes:

- `` `${command.run}` failed first `` — from the loop at `trial-build.ts:192-201`. Push one result per entry of `commands.slice(i + 1)`, replacing the `join('; ')`.
- `the worktree could not be cut` — the `catch` at `trial-build.ts:164-169`, but only in the branch that pushes the `git` result. When `at.interrupt?.aborted` is set, nothing is pushed and the trial still throws `TrialInterrupted` (`trial-build.ts:215`). That is the ticket's Ctrl+C edge.
- `the env refused` — the return at `trial-build.ts:131`.

Write a small `notRun(runs: string[], because: string)` helper. All three causes use it, so no cause gets its own shape.

### The env refusal needs the command list, not `commands`

`commands` is built after `keptTimeouts(at)` (`trial-build.ts:133-137`), and a not-run line has no use for a timeout. Before line 131, build only the strings: `const runs = [...(install === null ? [] : [install]), ...build]`. Have the refusal return `notRun(runs, 'the env refused')`, and map `commands` from `runs` afterwards. Do not move `keptTimeouts` above the env check. It reads the recipe a second time for nothing, and it would add a new way for the refusal path to fail.

### `nothingDeclared` travels on the return value, and so does the colour

`tryBuild` becomes `(install, build) => Promise<{ results: TrialResult[]; nothingDeclared: boolean }>` (`setup-build.ts:44`). Delete the `note` at `trial-build.ts:190`, so evidence is the command's output and nothing else. Every return must carry `nothingDeclared`, including the env-refusal return. It is computed at `:119`, before the refusal at `:131`, so this costs nothing.

In `tryTheBuild`, colour is decided by `failed`, and only by `failed`:

```ts
const failed = results.filter((r) => r.outcome === 'failed')
if (failed.length === 0) return { ok: true }
```

Then print the results in order:

- each `failed` result as today: `failed: <command>\n<evidence>`
- each `not-run` result as one line

Print them in the order `results` holds them, not as two filtered passes. The order is already the run order: git or env first, then the failure and its skipped commands, then `cleanup` last. Two passes would put `cleanup` above the not-run lines.

After the list, if `nothingDeclared` is true, print the env sentence once, using `recipePath(input.project, input.home)`. `recipePath` is already imported in this file (`setup-build.ts:18`) and used at `:98`. Then ask the existing `write`/`edit` question, unchanged.

The early return above guarantees a failure exists before the note or the question is reached, so neither needs its own guard. In practice a trial cannot have not-run results without a failure. If one ever does, it is treated as green.

### Fakes and tests

- **`recipe-flow.test.ts:440` fake.** It returns `{ results: [{ command: 'pnpm test', outcome: 'passed', evidence: '' }], nothingDeclared: false }`. Pass `false` so that suite's output does not change.
- **The ticket's sentence-placement test.** Assert the index of the env sentence in the logged lines against the index of the last `not run:` line. A `toContain` check would pass even with the sentence in the wrong place.
- **Two Done-when tests: no failed result ends in `(no env declared)`, and env refusal lists every command.** Put both in `trial-build.test.ts` against `trialBuild` directly. The fakes at `trial-build.test.ts:20-40` already build `deps`. An env refusal is `resolveEnv` rejecting, which the `.catch` at `:130` turns into `refusal`.

All of this is unit-level. No part of this change reaches `pnpm test:integration`.
