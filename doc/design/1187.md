## The decision the ticket leaves open: hold all three copies equal with a test

Today nothing checks that `SANDBOX_ALT`, the SVG's `aria-label` and `safety.md`'s alt agree. That gap is how #1186 shipped two different texts. Add assertions to the existing sandbox test. Read the files the way `apps/site/unit/docs.test.ts:266` already reads `img/concepts.svg`, with `readFile` relative to the repo:

- the SVG's `aria-label`, taken with `/aria-label="([^"]*)"/`, equals `SANDBOX_ALT`;
- `doc/safety.md` contains `![${SANDBOX_ALT}](img/sandbox.svg)`.

Compare against the **constant**, not the rendered `alt`. `renderToStaticMarkup` escapes the apostrophe in `Lingtai's` as `&#x27;`, so a string compare against the HTML fails for no real reason. For the same reason, keep `"`, `&`, `<` and `]` out of the new label. Then the regex needs no entity decoding, and the label cannot break out of the markdown alt.

Changes to the existing assertions:

- **Delete** `expect(block).toContain('left off it')`.
- **Keep** `expect(block).toContain('telemetry')`. It still holds because the fourth `<li>` (`page.tsx:182-183`, agreed copy, unchanged) says "telemetry hosts such as `sentry.io`".
- **Delete** `expect(SANDBOX_ALT).not.toContain('shown on the board')`. It guarded the #1186 alt, which avoided that phrase; the new label says "shown on the board's Sandbox tab" on purpose, and the equality test below is what holds it true.
- **Add** `expect(block).not.toContain('sandbox-note')`.
- **Keep** the position, `from v0.14.0`, `href` and `src` assertions as they are.

## Checking it renders

The theme changes colours only (`sandbox.svg:3-4`), never geometry. So whether text fits is one measurement, and dark mode only needs a visual check for contrast. Use headless Chrome, which the chrome-devtools MCP provides:

1. Open the file at `file://…/doc/img/sandbox.svg`.
2. Run a script that, for every `<text>`, takes `getBBox()` and checks it lies inside the `<rect>` whose area contains the text's anchor point. For the free lines (the wall area and the two new lines), check against the wall rect or the outer zone instead.
3. Screenshot it with `prefers-color-scheme` emulated as light, then as dark.

`qlmanage -t` is on this machine as a fallback for a light-only thumbnail. `rsvg-convert` and `magick` are not installed. Say in the PR which tool you used and paste the overflow script's result: every text inside its box, with the smallest margin.

## Edges

All the runtime edges in the ticket are correctly marked *does not apply*: the image is static. Two costs for later tickets:

- **The new equality test fails on any wording change made in one place only.** That is intended: it is the check #1186 lacked.
- **The diagram lists paths from `policy.ts`'s `denyRead` (`:89-102`) and does not track them.** A later change to that list has to update the diagram by hand, as `safety.md:14-15` already admits for the prose ("go stale if those change"). Do not try to generate the SVG from code; that is out of scope.

No ADR changes. Everything here follows ADR 0127 §17 and §18 as written.
