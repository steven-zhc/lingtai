## Design: retire `TicketLinked` (#646)

The change itself is what the ticket says. Two things it leaves out will turn the build red, and a third affects which test proves the refusal.

### 1. `EVENT_AT` has to change at the same time as `RETIRED`

`packages/domain/src/events.ts:2142` declares `TicketLinked: ['outside']`. `packages/domain/unit/event-at.test.ts:8` checks a two-way rule:

```ts
expect(EVENT_AT[type].length === 0, type).toBe(RETIRED.has(type))
```

The comment on `EVENT_AT` (`events.ts:2128–2129`) says the same: *"`RETIRED` types declare `[]`."* So adding `TicketLinked` to `RETIRED` (`events.ts:2235`) without changing its entry to `TicketLinked: []` fails that test. Copy `OutboxDelivered: []` / `OutboxFailed: []` at `events.ts:2175–2176`. Leave the entry in place: the `satisfies` on `EVENT_AT` makes `tsc` refuse an `EventType` that has no entry.

`conductor/unit/what-an-event-is-written-at.test.ts` checks *appended ⊆ declared* against real passes. No pass appends `TicketLinked`, so `[]` does not trip it.

### 2. Keep the `STREAMS` row in `packages/domain/scripts/events.ts:208`

Delete only the `ELSEWHERE` row (`scripts/events.ts:184–188`). The `STREAMS` row (`TicketLinked: ['ticket-']`) stays:
- `STREAMS` also uses `satisfies` over every event, so removing the row is a type error.
- `generate()` (`scripts/events.ts:410`) reports `stream` for retired types too, and old rows really are on `ticket-` streams.

With the `ELSEWHERE` row gone, `generate()` finds no sites for `TicketLinked`: `sites` is built from `findAppendSites` plus `ELSEWHERE` (`scripts/events.ts:405`). It emits `retired: true` (`:414`) and `at: []` (`:415`). That is the "no append link" the ticket asks for, and no generator change is needed.

Run `pnpm events:generate` after both edits. `events.json is current` in `packages/domain/unit/events-json.test.ts` compares the committed file with a fresh `generate()`, so a regeneration done before the `EVENT_AT` edit will be stale.

### 3. Prove the refusal with a unit test, not the existing integration test

The only test that `store.append` refuses a retired type is `packages/event-store/integration/event-store.test.ts:259–270`, and it uses `OutboxDelivered`. That test is in the integration half, which no pass runs. It is also not part of the shared contract: `packages/event-store/test/contract.ts` has no retired case. So "the existing retired-type test covers it" is true only after the merge.

The memory store makes the same check: `packages/event-store/test/memory.ts:138`, `if (isRetiredEventType(e.type)) throw new RetiredEventTypeError(e.type)`. Both stores route through `isRetiredEventType` (`events.ts:2237`), as does Postgres (`event-store.ts:316`). Add one case to `packages/event-store/unit/memory.test.ts`:
- `createMemoryEventStore().append(...)` with a `TicketLinked` payload (`{ relation: 'follows-up', otherRef: '58' }`) rejects with `RetiredEventTypeError`.
- `TicketDiscovered` is not refused. That covers the ticket's "`TicketDiscovered` is not retired" checkbox.

The case could go in the "what is not in the contract" block, or as a new `describe`. Either works. The claim it makes is about `RETIRED`'s contents rather than the store, so do not move it into `contract.ts`.

### The doc comment

Put it above `TicketLinked` at `events.ts:409–412` and keep the current two lines as its first paragraph: they say what it recorded. Then, in the style of `OutboxDelivered`'s note (`events.ts:1453–1468`):
- **Retired:** readable for ever, appended never, refused by `store.append`.
- Its writer went in `3958bb09`, #450's rename, and nothing replaced it.
- The fold at `packages/domain/src/ticket.ts:418` and the label at `apps/board/src/lib/history.ts:146` stay so that old `ticket-` streams still read.

Cite 0019 for "a read that drops rows makes every later append fail", as `OutboxDelivered` does. There is no need to restate that argument.

### Left alone

- **Tests that build `TicketLinked` envelopes by hand** (`packages/domain/unit/ticket.test.ts:285`, `apps/board/unit/standing.test.tsx:177`). They hand objects straight to a fold or a page and never call `append`, so they keep working. They are also the evidence that reading still works.
- **Prose that still lists `TicketLinked` as a live type** (`doc/reference.md:30`, `doc/design.md:176,320`). It is outside this ticket. If the implementing agent touches `reference.md:30`, the change is a "(retired)" mark, not a deletion.
- **Recipes:** `packages/recipe` already refuses a subscriber to a retired type (`packages/recipe/unit/resolve.test.ts:307–311`). If a recipe on the conducting machine has `on: [TicketLinked]`, it will be refused when it resolves after this change. The log cannot settle whether one exists. Only `~/.lingtai/<project>/recipe.yml` can, and nothing in the repository declares one.
