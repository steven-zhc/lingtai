The shape of #745. The ticket says what changes. This note says where it goes, and settles four things the ticket leaves open.

## Where it goes

All of it is in `runLocalBranch` (`apps/cli/src/first-project.ts:385-578`). Line numbers are from today's tree, and they run about 17 lines later than the ticket's.

- **Remote.** Delete the `origin` read and its refusal (`:411-416`). `remote` becomes `toplevel`. `resolveRemote` and `isUrlOrScpLike` (`:375-383`) are then unused, so delete them too.
- **`noOriginRefusal`.** Its only other caller is the row in `apps/cli/unit/plain-output.test.ts:62`. Delete the function and that row together.
- **Name guard.** The guard at `:438-460` still compares `existingRemote !== remote`, with `toplevel` as `remote` now. The refusal's wording says "`${toplevel}`'s origin is `${remote}`", which is no longer true. Make it say the directory itself. Rewording is the only change here: an old recipe whose `repo.remote` is the origin URL is refused, as today, and #772 moves it.
- **Detection.** Delete the `symbolic-ref refs/remotes/origin/HEAD` / `rev-parse --abbrev-ref HEAD` detection (`:464-470`). `detected` becomes `'lingtai-base'`, except in the `--land` case below.
- **`defaultBranch`.** `askRecipe`'s `defaultBranch: async () => detected` (`:523`) only feeds `askLanding`'s `detected`. `askLanding` uses that only when the file has no `repo.base` (`landing.ts:153-157`), and the seed always writes one. Hand it `base`.

## Decision 1: validate decides, the branch is made later

`validate` (`:480-485`) can be called more than once at a terminal, because `question.ts:117-124` loops on a refusal. So `validate` must not create anything. It only decides:

- **The answer exists as a commit:** set `fromSha`, as today.
- **The answer is `lingtai-base` and it does not exist:** find the checked-out branch with `symbolic-ref --short -q HEAD`, then `rev-parse --verify <branch>^{commit}`.
  - Both answer: remember the branch as the source, and accept.
  - Either fails: return the refusal (see Decision 3).
- **Any other absent name:** refused as today. `--base <branch>` is never created.

Use `symbolic-ref` rather than `rev-parse --abbrev-ref HEAD`. `rev-parse --abbrev-ref` answers the literal `HEAD` when detached, and on an unborn branch it fails with an error that doesn't say what's wrong. `symbolic-ref -q` fails when detached. On an unborn branch it succeeds, and the `^{commit}` check then fails. That way both cases reach one refusal, and nothing is guessed from a commit.

## Decision 2: create the branch after the runtimes probe

The ticket says "right after the answer". Create it **after the runtimes probe (`:493-496`) and before `seeds`/`askRecipe`** instead:

1. `git -C <toplevel> branch lingtai-base <source>`
2. `rev-parse --verify lingtai-base^{commit}` sets `fromSha`.

The reason: the runtimes refusal ends in `world.kept` ("Nothing was written"). With the branch created first, that sentence would be false. Created after the probe, the only refusals left afterwards are `askRecipe`'s own and the `final !== base` check. Each of those must then say what was left behind.

**The kept lines.** When this run created the branch, both strings handed to `askRecipe` name it, and so does `ADD_KEPT` in the refusal at `:550-552`. Those strings are `keptBeforeWrite: world.kept` and `kept: seededKept` (`:513`, `:529-530`). The wording is something like "the branch lingtai-base made from main in `<toplevel>` is kept". When the branch already existed, the strings stay as they are today.

**Failures.** If `branch` fails, or the `rev-parse` after it fails, refuse with git's own stderr and `world.kept`. Nothing has been written at that point.

**Re-runs.** A re-run takes the "exists" path and never moves the branch. That is the ticket's half-way edge.

**The trial build.** `liveTrialBuild` gets `remote: toplevel` and `base: 'lingtai-base'`. A mirror left by an earlier run sees the new branch, because `ensureMirror` fetches `+refs/heads/*:refs/heads/*` when the mirror is already there (`packages/repo/src/worktree.ts:118-123`).

## Decision 3: the detached and unborn refusal

The ticket wants the refusal to name the directory and `--base`. The sentence, roughly: "`<toplevel>` has no branch checked out, and lingtai-base is made from the one that is. Check out a branch, or pass `--base <branch>`."

It is raised only when `lingtai-base` would have to be created. A detached `HEAD` with `--base main`, or with an existing `lingtai-base`, goes ahead. Coming from `validate`, the flag and `--defaults` paths refuse once, and a terminal asks again.

## Decision 4: `--land <branch>` with no `--base`

Today `askLanding` moves `repo.base` to the landing branch on a local project, and `:543-553` re-reads the file it left. Default to `lingtai-base` unconditionally, and `--land main` would create a `lingtai-base` the person has just said not to land on. The trial build would also be cut from it.

So: **when `--land` names a branch, not `hold`, and `--base` is absent, the base question's `detected` is that branch.** It goes through the same `validate`, which creates it only if it is `lingtai-base`. `conflictingFlags` (`:229-240`) already refuses two different names. It still applies, unchanged.
