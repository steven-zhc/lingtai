# #702 — the shape

## Where it goes

All of it is in `initCommand`'s tail in `apps/cli/src/init.ts`, from the `chosen.project === 'local'` branch (`:553`) to `return 0` (`:627`), plus the `doctor` seam on `InitWorld` (`:232`). Doctor's own output needs no change: `formatReport` is already the short view with no `next:` of its own (`doctor.ts:3015`, *"the short view, and no closing `next:` (init owns its closing line)"*). `addLocal` (`packages/conductor/src/onboard.ts`) prints no `next:`, and neither does `first-project.ts`. So after this change the only `next:` lines the local path can print are the three in `init.ts` (`:578`, `:586`, `:618`), and `:618` is the one this ticket removes.

## Decision 1 — which paths get the closing line

The tail after doctor (`:598-626`) is shared by four paths, not two:

1. A local project was chosen now (`:553`).
2. A GitHub project was chosen now (`:560-587`).
3. The machine already has projects and has a configured App (`:587-596`).
4. The machine already has projects and has no configured App. `askProject` is `false` (`:441`) and neither branch runs.

The ticket's out-of-scope list names `:560-596`, which is paths 2 and 3. Its edge *"Re-running init on a finished machine: the same ending"* is path 4. So **the closing line is printed on every path except 2 and 3.** Build it with one `let github = false` that is set to `true` inside the `else` at `:560` and inside `else if (app.configured)` at `:587`. Then print the closing line only when `!github`. Do not decide it from `chosen.project === 'local'`: on path 4, `chosen` does not exist.

The GitHub paths keep their own lines (`:578`, `:586`) and get no closing line, so they never end with two `next:` lines. You still delete the `next: lingtai board` at `:618` for every path, and the GitHub paths lose nothing by it. That branch needs `started === null`, and a GitHub path has always started a board by this point: `runGithubBranch` calls `boardUrl()` before it can skip (`first-project.ts:599`), and `:567` and `:591` call `startBoard()` directly.

## Decision 2 — what "doctor failed" means

Change `world.doctor` to return `{ text: string; failed: boolean }`. The live implementation (`init.ts:1047-1050`) returns `failed: report.failed > 0`. **Count `fail` only, not `warn`**, as the ticket's wording says (*"doctor failed or did not finish"*). Doctor's own short view would suggest `--verbose` on a warning as well (`doctor.ts:2991`, `report.warned + report.failed > 0`), but init does not. A fresh machine nearly always warns ("a daemon that has never run", in the existing test at `unit/init.test.ts:161`), so counting warnings would put `lingtai doctor --verbose` on every first init. Put that reason in a comment next to it.

The catch at `:602-604` sets `failed = true` and keeps its `doctor did not finish — …` text.

## Decision 3 — whether a board is serving

The Board section already works this out; collect it into a `needBoard` boolean as it goes:

- `started === null`: `needBoard = (await world.boardAt(port)) === null`. This is the same `running` value `:614` already computes, so don't probe twice. When it is null, the line becomes `paint.muted('no board was started')` alone.
- `'refused' in started`: `needBoard = true`.
- In every other case (it was started here, or it was already running): `needBoard = false`.
