## The decision section: the nine decisions in #964, grouped

The ticket's *Done when* says *"the five decisions in #964"*, but #964's *Decided (2026-11-07)* lists nine. Do not try to work out which five. Cover them all, grouped like this, so that the ticket's *Want* items lead and the checkbox is met whichever five were meant:

1. **Setup is one module, `@lingtai/setup`.** Detect, propose, write the recipe, register — one module. (#964 decision 1.)
2. **Two inputs, no copy.** `lingtai add` and the board's wizard are two inputs to that module. Neither carries a question, a detection or a recipe writer of its own. (#964 decision 1.)
3. **The terminal input keeps 0121 §9.** Quote it: *"every question has a flag, and when there is no terminal and no flag the command refuses by name, saying which flag would answer it. Under `--json` there are no prompts at all."* (0121:200-203.)
   - Say the board input asks the same questions as form fields, which **adds** to the terminal and replaces nothing.
   - This is the ticket's *Watch out*. Give it its own numbered item; do not leave it as a clause inside item 2.
4. **Where a repository comes from.** Two sources: GitHub, or a local directory. (#964 decisions 2 and 6.)
   - The GitHub list is the App's installations or the `gh` login's pushable repositories, plus `owner/repo` typed into the filter.
   - A local directory is an absolute path, checked by the server to be a git repository, with its remote read.
   - A local directory's tickets come from its GitHub remote's issues when `origin` is on GitHub, and are local tickets otherwise.
   - Cite 0114 for the App/`gh` split. Do not restate 0114.
5. **What the module proposes, the same on both inputs.** (#964 decisions 4, 5, 7 and 9.)
   - Default kinds are `bug, feature, tech-debt, documentation`.
   - Kinds are a filter: nothing creates labels, and a missing label is not a warning.
   - `proposed: []` by default.
   - *Already added* means `registered`, `pending` or `unrecorded`, as `alreadyOnboarded` (`pick-repository.ts:235`) answers.
6. **No edit wizard.** Changing an existing project is editing its recipe YAML. Saving resolves it and writes nothing that fails. (#964 decision 3.)
   - #964 says *"`lingtai doctor`'s recipe checks"* and this ticket says *"resolving it"*. They are the same thing: 0104 §11 says *"`lingtai add`, `lingtai doctor` and the daemon all resolve, so a bad recipe turns red before it costs money"* (`doc/decisions/0104-the-recipe-is-the-pipeline.md:145-146`).
   - Write *resolve*, and cite 0104 §11, so the ADR names one check and not two.
7. **The trial build is the terminal's alone.** It is in `lingtai add` and is not offered on the board. (#964 decision 8.)
   - State it as the one place the inputs differ, and say why it does not break *no copy*: it runs after the module has finished and is not a setup question.
   - #964 gives no reason for decision 8, so do not invent one. Saying it is the only difference is enough.

**One rule for the whole file: where an accepted ADR already settles something, cite its section and do not restate it.**

- 0104 §1 — the recipe's location: `~/.lingtai/<project>/recipe.yml`, nothing committed to the repository (`0104:30-36`). The module writes there.

- 0103's consequence that *"the system can propose a configuration at `lingtai init`/`lingtai add`… detected values are defaults the person may override"* (`0103:186-188`) is what item 5 builds on.

## The README row is read by a test

`apps/site/src/lib/docs.ts:455-466` (`statuses()`) reads the decisions table with this regex:

```
^\|\s*\[[^\]]*\]\(([^)]+\.md)\)\s*\|([^|]*)\|([^|]*)\|
```

The third cell is the status. So the row must be exactly three cells, in this shape:

`| [0125](decisions/0125-setup-is-one-module-two-inputs.md) | **Setup** — one module, `@lingtai/setup`; `lingtai add` and the board are two inputs to it, and an existing project is changed by editing its recipe | accepted; not yet built |`

- **No `|` in the summary cell.** One there splits the row, and the status the site shows becomes wrong without any error.
- **The bold topic word comes first**, like every other row.
- **Columns do not need lining up.** The 0124 row is not padded, and `pnpm fmt:check` only covers `.ts`/`.tsx`/`doc/events.json` (`package.json:17`), so no markdown is formatted or checked.

`apps/site/unit/docs.test.ts:167-171` also requires every decision's title to be more than its filename. The `# 0125 — …` heading takes care of that.
