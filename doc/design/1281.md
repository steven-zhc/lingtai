## Design: #1281, triage acts only on a head it read from the remote just now

### What the ticket's fix list misses

**Item (4) does nothing as written.** Removing `orElse(null)` at `triage.ts:805`/`:813` changes nothing, because the port under it never fails. `deps.mirror.refSha` is `refShaEffect` (wired at `apps/cli/src/triage.ts:589`), and `packages/repo/src/mirror.ts:44-48` ends `.pipe(Effect.orElseSucceed(() => null))`. Its type is `Effect.Effect<string | null>`, with no error channel. The module says this is deliberate (`mirror.ts:18`): *"**Absence is an answer, never an error.** … a project with no mirror yet — each of them is a fact"*. So a failed `rev-parse` is already indistinguishable from a missing ref one layer below the line the ticket cites.

**Item (3) has no port to use.** `TriagePorts.mirror` (`triage.ts:639`) is local reads only. `mirror.ts:14-16` rules out fetching from it: *"Nothing here fetches or checks anything out … a reader that fetched would be changing the thing it was asked to describe."* And `readActContext`'s own doc says why it uses the mirror (`triage.ts:861`): *"checked against the mirror's ref, since there is no GitHub client here"*.

So the change needs two new reads and three behaviour edits.

### 1. A mirror read that can fail — `packages/repo/src/mirror.ts`

Add a strict sibling of `refShaEffect`, for example `refShaStrictEffect`. Leave `refShaEffect` unchanged: `discuss.ts:223,229` and `daemonTriagePorts.baseSha` (`triage.ts:574`) depend on its forgiving contract, and the ticket puts the mirror elsewhere out of scope.

- Run `git rev-parse --verify --quiet <ref>^{commit}` in the mirror.
  - Exit 1 with no output means the ref is missing: return `null`.
  - Any other `RepoFailed` fails the read, naming the ref and `detail`. That covers exit 128, no mirror directory, and a non-bare mirror. `mirrorBranchShaEffect` (`mirror.ts:55-69`) makes the same unreadable-versus-missing split and checks bareness with `rev-parse --is-bare-repository` first.
- Do not reuse `mirrorBranchShaEffect` for this. Its `for-each-ref <pattern>` matches only full or slash-prefix ref paths, so a bare `main` or a commit sha would read as missing.
- A missing mirror is a failure here, not an absence. This read only runs for a wait on a run, and a run cannot exist without a mirror.

Point `TriagePorts.mirror.refSha` at the strict read in `daemonTriagePorts` (`triage.ts:589`). Its type already allows failure (`Effect.Effect<string | null, unknown>`, `triage.ts:640`), so the type does not change.

### 2. A remote read — new port `remote` on `TriagePorts`

```ts
remote: { refSha(input: { project: string; ref: string }): Effect.Effect<string, unknown> }
```

- Make it **required**, not optional. If it were optional, a production wiring that forgot it would fail every act at runtime instead of failing typecheck.
- Wire it in `daemonTriagePorts` the way the person's own paths build a client (`apps/cli/src/redo-step.ts:27-36`, and the same in `fix-refusal.ts:27`):
  - `project.owner === null` → `ownerlessClientEffect`.
  - Otherwise → `hasGitHubAuth()`, then `projectClientEffect(project).client`.
  - Then call `client.refSha(\`heads/${ref}\`)`. The `heads/` prefix is what `status.ts:287` passes. The GitHub verb is `GET …/commits/<ref>` (`packages/github/src/client.ts:788-791`).
- `refSha` returns a Promise, so wrap it in `Effect.tryPromise`, not an `async` function (see the ratchet note below).
- No GitHub auth is a failed read, never `null`.
- **A 404 is a failed read too.** The client contract fails on a missing ref (`git-refs.ts:70-73`: *"Fails when the remote names no such ref, the same shape a 404 against GitHub's API answers"*). Don't try to separate *deleted branch* from *unreachable*: both end as `TriageFailed` and spend one retry, and the recorded `why` names the ref and the status, so the cause is still its own.

### 3. `readActContext` — `apps/cli/src/triage.ts:867-931`

- Make `refIs` (`:912-913`) call `deps.remote.refSha`. It returns `found === sha`; a failure propagates.
- **Drop the `atRef === null ||` short-circuit at `:918` as well** as the `atBase` branch (`:920-922`).
  - A redo with no ref to read cannot be checked, so it gets no `redo`.
  - `rerunHeadOf` never actually returns `atRef: null`: `Saved` always carries a ref (`packages/domain/src/attempt.ts:858`). So this costs nothing in practice, but it stops the type from allowing an unchecked head.
- After this, `redo` is either a remote-checked `{ onSha, ref: string }` or `null`. Update `ActContext.redo`'s comment at `packages/domain/src/ticket.ts:1341`. You may narrow its `ref` to `string`, but the shape does not depend on it.
- `diffBaseShaOf` and the extra `deps.store.read(runId)` become unused here. Remove them if nothing else in the file uses them.

### 4. `gatherEvidence` — `triage.ts:805` and `:813`

- Remove `orElse(null)` from the two `refSha` reads only. With item 1 in place, a failure aborts `attemptWithin` and is recorded by the existing catch at `:1414-1415` as `TriageFailed{why: "crashed: …"}`.
- Make the failure's message name the read, e.g. `could not read <base> in the mirror: <detail>`. Map it at the call site rather than adding a new error class.
- `null` is still absence:
  - A missing base leaves `refs` empty, as today.
  - A mirror that lacks the attempt's head sha is still not *committed nothing*. Keep the comment at `:840-847`, whose rule this preserves.
- **Leave `listAt` and `diffStatAt`'s `orElse` (`:808`, `:815`, `:827`) as they are.** They read shas already resolved and only shape the prompt; they never feed what is acted on. Their ports also swallow failure in `mirror.ts` (`:108-118` for `diffStat`), so changing the call site would again change nothing. This is how I read *"its siblings"*: the two `refSha` reads.

### 5. Domain binding — `ticket.ts:1386`

```ts
if (action._tag !== 'startNewAttempt' &&
    (context.boundHead === null || context.headNow === null || context.headNow !== context.boundHead))
  return { ok: false, refusal: 'head-moved' }
```

This is pure. `startNewAttempt` stays exempt. `packages/domain/unit/act-on-triage.test.ts:146` is the test that encoded null-equals-null with `redo: { onSha: 'base', ref: null }`. Rewrite it to expect `head-moved`, and add `FixRefusal`/`resolveConflict` and `StartNewAttempt` cases next to it.

### 6. The failed read keeps its cause — `packages/conductor/src/ticket/commands.ts:576-580`

Today an `act` failure becomes `refusal: 'unreadable'`, and `triageFailedEvent` records only that word (`:600`), so *"the read's failure"* is lost.

- Keep `'unreadable'` as the `TriageRefusal` tag. Callers branch on it, for example `triage.ts:1477`.
- Record `why: \`unreadable: ${message}\``, clipped to `TriageFailed.why`'s bound. The CLI clips with `cut` (`triage.ts:633-634`); use the same function here.
- The retry loop only compares `why === 'aborted'` (`triage.ts:210`), so a richer `why` does not change retrying.
- The interrupt guard at `:577` stays first. The `WallReached` remap at `triage.ts:1467-1469` and in the catch at `:1413` is untouched.

## Edges, decided

- **Retry:** every case above ends as a `TriageFailed`. `owedARetry`/`triageRetries` (`triage.ts:209-230`) count it with no change. What settles it in the log is `WaitTriaged.result._tag === 'TriageFailed'` with its `why` (`head-moved`, `unreadable: …` or `crashed: could not read …`), and no `WaitResolved{by: 'triage'}` in the same append.
- **Remote read and the wall:** `readActContext` already runs under `guard` (`:1465`), so a slow GitHub call is bounded by the triage wall. The client takes no signal, which is the same as the person's path.
- **Two passes at once (0122):** reads only. The append stays bound by `ifVersion` as today.
- **Ratchet:** the new port and the strict mirror read are `Effect.gen`/`Effect.tryPromise`. No new `async` function and no new `Effect.run*`. `effect-ratchet.baseline.json` must not move.

## Tests (unit, all reachable by `pnpm test`)

- **Domain:** the null cases above (`act-on-triage.test.ts`).
- **`apps/cli/unit/triage.test.ts`:**

  - A stub `mirror.refSha` that fails for the base: expect `TriageFailed`, the wait unresolved, and the attempt spending a retry.

- The strict mirror read's exit-1 versus exit-128 split runs a real `git`, so it is integration and out of reach inside a pass. The unit stand-in is the stubbed `mirror.refSha` failure above.
