# The errors the platforms answer with

**Status** research · 2026-11-13 · evidence for [0108](../decisions/0108-a-refusal-buys-a-round.md) §8, §12, §13, §15

0108 separates an error a rule may retry (**transient**: the same input can
succeed later) from one a person must answer (**repeatable**: the same input
fails the same way until someone changes a setting, a credential, a plan or the
change itself). This page lists what GitHub, git over HTTPS, the Anthropic API
(as Claude Code shows it) and the OpenAI API (as Codex shows it) actually answer
with, and what each platform says to do about it.

**Sources.** Only the platforms' own documentation, fetched on 2026-11-13. A
behaviour the platform does not document is marked *observed, undocumented* and
carries no citation; where the evidence is Lingtai's own, the issue number is
given. "Depends" means the platform's docs make the verdict turn on a header or
a field, and the condition is named.

## 3. The Anthropic API, as Claude Code shows it

Claude Code retries before it shows anything: "up to 10 times with exponential
backoff" (`CLAUDE_CODE_MAX_RETRIES`, default 10), for "server errors,
overloaded responses, and request timeouts that arrive before any of Claude's
response has streamed", dropped connections, and "temporary 429 throttles, but
not a gateway's spend-limit `429`". It does **not** retry a failure "after
Claude has completed a block of text or a tool call", because "that could
execute the same tool calls twice" [C1]. So a 5xx or 529 that reaches Lingtai
has already outlived Claude Code's own retries, or arrived mid-response.

## What Lingtai recognises today

- **GitHub API.** `GitHubFailed.rateLimited` is `status === 429 || (status === 403 && /rate limit/i.test(detail))`
  (`packages/github/src/app.ts:92-94`), and its one reader is `asLinkCall`, which
  keeps a rate-limited 403 from being called a missing permission
  (`packages/github/src/client.ts:571-576`). `githubJson` keeps the status and
  the body's `message` and drops every header (`packages/github/src/app.ts:194-200`),
  so `retry-after`, `x-ratelimit-remaining` and `x-ratelimit-reset` are never read,
  and nothing retries a GitHub API call by status.
- **git.** `PUSH_REJECTED` (`packages/repo/src/network.ts:14`), `BASE_PROTECTED`
  matching `GH006`, `GH013`, `protected branch hook declined` and
  `repository rule violations` and never retried (`network.ts:23`, refused as
  `base-protected` at `packages/repo/src/integrate.ts:686-687`), `UNREACHABLE`
  (`network.ts:30`, including `early EOF`, `RPC failed`, `remote end hung up
  unexpectedly`, `returned error: 5\d\d`) and `REMOTE_ERROR` for a
  `[remote rejected] … (Internal Server Error|Bad Gateway|Service Unavailable|Gateway Timeout)`
  line (`network.ts:53`). `retryUnreachable` retries the last two after 10 s and
  30 s (`network.ts:75`, `:87`); then the lane refuses `unreachable` or
  `remote-error` (`integrate.ts:712-716`, `packages/conductor/src/conduct.ts:3279-3283`),
  both `RefusalReason`s (`packages/domain/src/vocabulary.ts:76-80`) owned by
  `lingtai` (`packages/domain/src/attribution.ts:146`). Push protection, a
  pre-receive hook, `GH001` and the 2 GiB limit have no pattern of their own.
- **Claude Code.** A run is `never-started` on three facts, no words
  (`neverStarted`, `packages/agent/src/runtime.ts:236`). A crash whose detail is
  the account-limit sentence locks the account: `ACCOUNT_WALLS` matches
  `You've hit your … limit` and `your session limit resets`
  (`packages/conductor/src/never-started.ts:66-73`), read by `accountWallOf`
  (`never-started.ts:76`) at `conduct.ts:3138`, `:4785` and `:5540`. Nothing
  matches a 5xx, a 529, a 429 or an *Attention Required* page: today every one of
  them is a crash and holds for a person.
- **Codex.** `codexClose` makes a `turn.failed` with no agent message
  `never-started` (`packages/agent/src/codex.ts:866`), and `ACCOUNT_WALLS` matches
  `You have hit your usage limit` / `You've hit your usage limit`
  (`never-started.ts:69`). Nothing reads `insufficient_quota`, `server_is_overloaded`
  or a status code.
- **Not built.** `TRANSIENT_RETRIES_LIMIT` does not exist in `packages/*/src`, and
  `BASE_MERGES_LIMIT` is still `2` (`packages/domain/src/routing.ts:45`); 0108's
  *Not built yet* says both. The ADR's §11 name `metTheAccountWall` is
  `accountWallOf` in the code.

## What this means for 0108's list

**§12, an agent runtime's transient list** — what a rerun of the same run can
clear, once the runtime's own retries are spent:

- Claude Code: `API Error: 5xx …` (500, 502, 503, 504), `Repeated 529 Overloaded errors`,
  `Request timed out`, `No response from API`, `Server is temporarily limiting requests`,
  `Request rejected (429)`, and dropped-connection messages.
- Codex: a 500, a 503 `server_is_overloaded`, and a 429 that is not one of the
  billing codes. Codex's `exec` sentences for these are not documented, so they
  have to be collected from runs before they can be listed.
- The Cloudflare *Attention Required* 403 is not documented by either platform.
  It may be listed from Lingtai's own runs, but it should be matched on the page's
  title, and never as *a 403*: every documented 403 from both APIs is
  repeatable.

**§15, the landing's transient list** — already built: `REMOTE_ERROR` and
`UNREACHABLE`. One correction: GitHub documents `fatal: the remote end hung up
unexpectedly` as one symptom of the **2 GiB push limit**, which is repeatable,
and `UNREACHABLE` retries it as transient. Retrying an oversized push costs only
the waits, and §15's bound stops it, but the hold that follows says
*origin could not be reached* when the cause is the size.

**Always a person** — every one of these fails the same way when retried:
GitHub `401`, a permission `403`, `404`, `409`, `422`; `GH006`, `GH013`, push
protection, `pre-receive hook declined`, `GH001`, `pack exceeds maximum allowed
size`; Anthropic `400` (including the customer's own spend limit), `401`, `402`,
`403`, `404`, `413`, and the tier spend-cap `429`; OpenAI `401`, `403`, and every
billing `429` code. A plan's usage limit stays where §11 puts it, an account
lock, not a rerun.

**Where the verdict depends on what the code does not read:**

- GitHub's 403 and 429: the docs separate a rate limit from a permission by
  `x-ratelimit-remaining: 0` or by a message naming a secondary limit, and give
  the wait in `retry-after` or `x-ratelimit-reset`. `githubJson` drops the
  headers, and GraphQL's primary limit arrives as a `200`.
- Anthropic's 429: a rate limit, a ramp limit and the tier spend cap share
  `rate_limit_error`. Only `retry-after` (absent on the spend cap) and
  `error.details.error_code` (`enforced_spend_limit_reached`) separate them.
  Lingtai sees Claude Code's text, not the response, so it has to use Claude
  Code's own sentences; Claude Code already declines to retry a spend-limit 429.
- OpenAI's 429: a rate limit and a quota share the status; `error.code` separates
  them, and "the broader `error.type` can still be `insufficient_quota`".
- git's transport errors: `remote end hung up unexpectedly` is transient on a
  broken connection and repeatable over 2 GiB, and git's text alone does not say
  which.
