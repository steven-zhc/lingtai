# #370 design: a dollar ceiling beside `turns`

## The decision the ticket leaves open

**The key is `runtime.limits.usd`. It is optional and has no default. Absent means "no dollar ceiling", and that absence is said out loud wherever the other limits are listed.**

The other four limits default (`turns` 300 and `wall` 2h at `packages/recipe/src/recipe.ts:2972` onward; `rounds` and `restarts` below that). `usd` must not, for two reasons the code already gives:

1. **A default would turn Codex red for good.** `limitsRow` explains why `turns` is red for every Codex project: *"`runtime.limits.turns` has a schema default of `300` that is always present … so red there is red for ever"* (`apps/cli/src/doctor.ts:1576-1595`). A defaulted `usd` would do the same thing on a second axis. With no default, a Codex project is red on `usd` only when somebody actually declared one. That is the ticket's *"answered rather than silently unbounded"* and nothing more.
2. **A default would change what every recipe prints.** `ceiling.ts:45`: *"Empty is today's string, character for character"* (0070 §8). With `usd` absent, `passCeiling` must return exactly today's string.

Use `z.number().positive().optional()` in both schemas: `Recipe.runtime.limits` (`recipe.ts:2970`) and `MachineLimits` (`packages/recipe/src/local.ts:48`, a `strictObject` that refuses an unknown key today). The merge loop at `local.ts:360` walks `Object.keys(LIMIT_DEFAULTS)`. `LIMIT_DEFAULTS` is `limits.parse(undefined)` (`recipe.ts:3212`), so a key with no default has no `usd` key in that object at all, and **the loop will silently skip it**. Read `usd` explicitly in that loop. Its provenance line should say `default` → *none* rather than vanishing. `apps/board/src/lib/recipe.ts:24` builds `LIMIT_KEYS` the same way and has the same hole.

Don't call it `budget`. `runtime.budget` already exists and means prompt characters (`local.ts:438`, 0104 §9).

**A dispatch's own `limits:` does not take `usd` in this change.** That object is a `strictObject` (`recipe.ts:233`), so `limits: { usd: 5 }` is already refused by name, which is the right answer until someone wants per-step money. So `spendFor` (`packages/conductor/src/conduct.ts:647`) passes `ceiling.usd` to every dispatch unchanged. `limitsFor`, `boundsBesides` and `StepBound` (`packages/recipe/src/settings.ts`) don't change.

## Unit: one run, and it multiplies like `wall`

`--max-budget-usd` bounds one `claude -p` process, the same unit as `--max-turns`. So the figure lives on `RunRequest.limits` (`packages/agent/src/runtime.ts:121`), which becomes `{ turns; wallMs; usd?: number }`.

`passCeiling` is the non-obvious part. `ceiling.ts:33` says *"Turns are named too, and not multiplied: they bound a run and do not add up across runs the way time does."* Dollars do add up across runs, so they follow `wallMs`, not `turns`:

- **The pass sentence:** "… `2h`, `250` turns and `$12` each …, so at most `6h` and `$36`".
- **The restarts sentence:** the same multiplication by `runs`.

Only add these when `usd` is present. The figure is an upper bound on the implementer's runs only; the cold reviewer is outside the product today for the same reason its `wall` is (`ceiling.ts:38-42`).

These all call `passCeiling` and need nothing beyond passing `usd` in their limits object:

- `packages/conductor/src/filter.ts:299`
- `packages/conductor/src/onboard.ts:326`
- `apps/board/src/lib/recipe.ts:804`
- `apps/board/src/lib/board.ts:628`
- `packages/conductor/src/wizard-page.ts:569`
- `apps/cli/src/doctor.ts:1546`
- `apps/cli/src/wall-limit.ts:24`

Check that each one spreads the whole limits object rather than picking fields out of it. A literal that picks `turns` and `wall` will drop `usd` silently and still typecheck, because the field is optional.

## The new failure kind and its ripple

Then let `pnpm typecheck` list the sites: `Record<RunFailureKind, …>` is total in `packages/conductor/src/attribution.ts:159` and `packages/conductor/src/fix.ts:171`, and every `switch` in `fix.ts` (lines 214, 253, 870, 1149, 1301, 1370, 1451) narrows on the stop.

The rule for every site is **the same treatment as `out-of-turns`**, because both are a bound the recipe set and the runtime applied:

- `RUN_OWNER["out-of-usd"] = "repository"` (the `attribution.ts:165` argument applies word for word).
- A stop of its own in `fix.ts`, not `"crashed"`. `stopAction` names the board row, and `unfinished` is the word for the three kinds that are *not* the ticket. `stopNeeds` returns `acknowledgement`.
- `conduct.ts:2651`: write `RunFinished` and `RunFailed` both, so the receipt's spend lands on the event (0110 §2).
- `conduct.ts:2683`: generalise `turnLimit` into one "a ceiling was reached" value that carries the kind. Then `whatIsWaitingOnYou` (`conduct.ts:3140`) asks `out-of-usd: …` with its own `what`. Name the dollar figure and say what a dollar ceiling reached means. It is still a scope alarm, but it is also the one a model change moves. Recommend `requeue` after narrowing, as it does for turns.

Anything that compares `kind === "out-of-turns"` with a string literal won't be caught by the compiler. Run `git grep '"out-of-turns"'` across `packages/` and `apps/` (`packages/projector/src/task-view.ts:1113` mentions it) and decide each hit.

## Doctor: what "answered" means

The answer to a dollar ceiling a runtime cannot hold is `limitsRow` (`doctor.ts:1606`). It is not a dispatch refusal. This matches how `turns` on Codex is answered today, and `fail` there is what `lingtai restart` counts (`doctor.ts:1583`).

Once `usd` joins `RUN_LIMITS`, the row's `declared` record and its `ignored` filter need one change: **a limit the recipe did not declare is never "ignored".** `usd` absent reads `usd — none declared` and is not red. Without that rule, every Claude-only project goes red too, because `RUN_LIMITS` would contain a name with nothing declared against it.

Don't add a refusal in `conduct.ts`'s tier check. 0007's *never silently downgrades* is about containment, and nothing refuses `turns` on Codex at dispatch either.

## What the log will show

Once a recipe declares `usd`, a run that hits it shows up as `RunFinished` followed by `RunFailed { kind: "out-of-usd" }` on the same stream. Its `RunStarted.invocation.args` contains `--max-budget-usd`, and `invocation.limits.usd` holds the figure. The board can only say "this ceiling did what it should" when those three line up.
