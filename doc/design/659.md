# Design note: #659, README rewrite and `doc/why.md`

Two files are written: `README.md` is rewritten and `doc/why.md` is new. Two other places each get a one-line addition: `doc/README.md`'s table and `SECTIONS` in `apps/site/src/lib/docs.ts`. `doc/tutorial.md` stays as it is.

## 1. `doc/why.md` is not a site page just because it sits in `doc/`

The ticket says *"`doc/why.md` becomes a site page by being in `doc/`"*. The code says otherwise. The site publishes from an allow-list: `apps/site/src/lib/docs.ts:90-101`, *"What is published, named rather than swept up … every markdown file in `doc/` that is not in a section here is listed on the docs index, with a link to it on GitHub"*. So on its own, `why.md` would show up in `unpublished()` (`docs.ts:297`) and nowhere else.

What to do:
- Add `'why.md'` to the `guides` section's `files` in `docs.ts:108-118`, directly after `'from-symphony.md'` and before `'guide.md'`. It is reading for someone who has finished the tutorial, so it goes ahead of the operator material.
- Leave `PUBLIC_SLUGS` (`docs.ts:66`) alone. Its comment says *"Nothing else in `doc/` has been through that edit yet"*, and making pages public is #342's work, not this ticket's.
- What the addition buys: `apps/site/unit/docs.test.ts:38-47` checks that every name in `guides` exists on disk, and `:262-289` checks every `#anchor` link inside a published file. `why.md` gets both checks for free, inside `pnpm test`. It is the only unit-level test that touches either file. Nothing tests the root README's links (a search for `README.md` across `apps/`, `packages/` and `scripts/` finds only git fixtures). Check those links by hand: for each relative link, confirm the path exists.
- Add a row for `why.md` to the table in `doc/README.md:44-60`, next to `tutorial.md`. That table is the docs index people actually read.

`pnpm fmt:check` and `pnpm lint` never read markdown (`package.json:16-18`: oxfmt is limited to `*.ts`/`*.tsx` and `doc/events.json`). The `docs.ts` edit is the only change they check, so keep it to one array entry in the file's existing style.
