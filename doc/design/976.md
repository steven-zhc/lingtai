**Design note for #976: where the heading lives, and what the tests can see**

**The heading goes in `page.tsx`. `film.tsx` holds only the frame.**

The ticket asks for the band's heading to go into the existing heading-order test. That test does not read the rendered page. It reads the source file: `prose()` in `apps/site/unit/page.test.tsx:20-23` is `readFile(.../src/app/page.tsx)` with the comments stripped, and `'explains the benefit, then how to start'` (`page.test.tsx:72-85`) checks the `indexOf` positions in that text. If `One ticket, filed to landed.` sits inside `film.tsx`, the test reports it missing, however correct the rendered page is.

So the split is:

- **`page.tsx`**, between `</div>` of `.hero-row` (`page.tsx:61`) and `<div className="tale">` (`page.tsx:63`), holds the server markup:
  - `<section className="film" id="film" aria-labelledby="film-title">`
  - the `kicker` `<p>`
  - `<h2 id="film-title">One ticket, filed to landed.</h2>`
  - then `<Film />`
  
  This is the same arrangement as `Shots`: the island is mounted by `page.tsx`, and the copy a test reads is in `page.tsx` itself (`page.tsx:40-57` holds the hero copy, and `<Shots />` at line 60 holds no headings).
- **`film.tsx`** (`'use client'`) holds only the frame: the `<a href=watch URL>` wrapping the `<img>` and the Play affordance, and after a click the iframe. Its constants (video id, length, poster path) stay local to it.

**Where the Play button goes.** The no-script behaviour has to be a link around the poster, so the Play "button" sits inside that `<a>` as a styled `<span>` (bottom-left, `aria-hidden` on the `2:11` text). The `aria-label="Play the film (2:11, narrated, with subtitles)"` goes on the `<a>` itself. An `onClick` with `e.preventDefault()` then flips state to show the iframe. This is the posture of `shots.tsx:43-49` exactly: an `<a href>` whose click script intercepts. Don't nest a `<button>` inside the `<a>`, because interactive content inside an anchor is invalid HTML. Move focus with a `ref` on the iframe and a `useEffect` keyed on the playing state. Without that, the focus is lost when the `<a>` unmounts.

**The no-YouTube test must allow the one link.** The watch URL `https://www.youtube.com/watch?v=s27esf-NQlc` *is* in the markup before a click, on purpose. So a test of `not.toContain('youtube')` is wrong. Assert these four things on `renderToStaticMarkup(<HomePage books={null} />)`:

1. there is no `<iframe`;
2. there is no `ytimg`;
3. there is no `rel="preconnect"` or `dns-prefetch`;
4. every `youtube` substring is the `href` of that one anchor (e.g. strip that exact `href="…"` and then expect no `youtube` at all).

Also assert that `id="film"` falls after the end of `.hero-row` and before `id="replay"`. The existing row test (`page.test.tsx:281-302`) only checks that the replay is outside the row; it says nothing about the film.

**The vocabulary test covers the new copy.** `page.test.tsx:57-60` refuses `log`, `event-source`, `append-only` and `projection` anywhere above the books kicker, in both `page.tsx` and the rendered HTML. The band sits above that kicker. The kicker, heading, `aria-label` and iframe `title` from the ticket pass that test; keep any copy you add to the same rule.

**CSS.** Put `.film` and `.film-frame` in `home.css`, next to the shots rules. For the shadow and radius, reuse whatever `.shot-window` uses rather than new values. The iframe is `position:absolute; inset:0; width:100%; height:100%; border:0` inside the `aspect-ratio:16/9` frame. If you add a `<p>` beside the kicker, give it `max-width: none` as the ticket notes from #975.

**Checks.** `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover all of this. Nothing here needs the integration half. The static-export build (`apps/release/integration/build.test.ts`) is out of reach inside the pass. The unit-level stand-in for it: `film.tsx` imports nothing but `react`, and `page.tsx` stays a server component, the same as with `Shots`.
