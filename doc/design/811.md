# Design note for #811: Lingtai's own books, written once per release

## Where it goes

Four files. Only one of them does any I/O.

| File | What it holds |
|---|---|
| `apps/site/scripts/books.ts` | I/O only, the way `scripts/snapshot.ts` is: it parses the flags, reads `LINGTAI_SITE_PUBLIC_PROJECTS` (its own small `publishable()`), checks lag, reads, calls `takeBooks`, then writes. It calls `main()` at the top level, so no test may import it. |
| `apps/site/scripts/take-books.ts` | `takeBooks(rows, options) → { ok: true, books } \| { ok: false, refusals }`. Pure: no clock and no I/O; the clock, the commit and the card titles (a `project#issue → title` map) arrive in `options`. Every unit case in the ticket's *Done when* is a test of this function, in `apps/site/unit/books.test.ts`. |
| `apps/site/src/lib/books.ts` | The `Books` type, `BOOKS_FILE`, `parseBooks` and `readBooks(): Promise<Books \| null>`. This is what #814's page imports. |
| `apps/site/unit/books.test.ts` | Unit cases for both `takeBooks` and `parseBooks`. |

**Only `take-books.ts` (and `books.ts` under `scripts/`) import `@lingtai/conductor`.** `"@lingtai/conductor": "workspace:*"` is in `apps/site/package.json`, and the import is the `./report` subpath only. `src/lib/books.ts` must not import the conductor or any runtime part of the projector: `tsc` cannot see a server-only import reaching a page graph (CLAUDE.md, #230), so the reader stays free of them.

`BOOKS_FILE` is `path.join(repoRoot, 'apps', 'site', 'books.json')`, built the same way as `SNAPSHOT_FILE`. `package.json` gains `"books": "node scripts/books.ts"`; `"build"` is unchanged.

## What `takeBooks` reuses from `report()`, and what it computes itself

- **Public projects.** Rows are filtered to `row.project !== null && open.has(row.project)` before anything else, then `report({ tickets: publicRows, spend: [], window, project: null, kinds: null })` is called. `report()` takes one project or all, so a set of projects has to be applied by the caller.
- **Taken from `report()`:** `counts`; `landed.fixRounds.median`, `zeroOrOneShare` and `fiveOrMoreShare`; the medians of waits and `machineMs` for the median receipt and the machine-minutes figures; `kinds[].landed` for landed-by-kind; and `landed.cost.unknown` for `costUnknown`.
- **The landed set.** Recomputed in `takeBooks` as `outcome === 'landed'` and `outcomeAt` in `[from, to)`, which is `report()`'s own placement rule (`placed`). `report()` does not return its placed rows.
- **Cost per ticket** goes through `ticketMoney(row)`, which is the one place cents and dollars meet; the ticket's cost in dollars is `(reportedCents + estimatedCents) / 100`.
- **Unpriced tickets (decided here).** A landed ticket **none of whose runs was priced** (no purpose has a reported or estimated run) has no cost: it is left out of `cost.median`, `cost.mean` and `cost.p90`, and its receipt `cost` is `null`. A ticket with *some* priced runs keeps its priced cost; the unpriced runs in it are not added as zero or anything else.
  - `cost.costUnknown` is `report().landed.cost.unknown`: the number of **runs** nothing could price, not a number of tickets.
  - `includesEstimates` is true when any landed ticket has an estimated run (`estimatedRuns > 0`), so a sub-cent estimate still counts.
  - So `cost.median` differs from `report().landed.cost.medianCents` whenever a wholly unpriced landed ticket exists: `report()` counts it as a zero-cost ticket, this file does not. The ticket's *Out of scope* says the two need not agree. **No comment or test may claim they do** except for fully priced tickets, and the test in `books.test.ts` says exactly that.
- **p90 is nearest-rank:** `sorted[ceil(0.9·n) − 1]`. `report()`'s `median` and `mean` are not exported, so local copies return `null` for an empty list.
- **Elapsed time** runs from `min(Date.parse(passTimes[i]))` to `outcomeAt`. A landed row with no `passTimes` is left out of the three elapsed figures. `withinHourShare` means ≤ 60 minutes. `waitedShare` is the share of landed tickets with `waits.length > 0`.
- **`spendShare`.** For each purpose, sum `reportedCents + estimatedUsd * 100` (unrounded) across every landed ticket's `cost` record, then divide by the sum over all purposes.
  - Output order is `PURPOSE_WORDS`' order for those present, then any other tag sorted, so the shares still add up to 1.
  - The divisor is computed and thrown away. It never becomes a field.
  - The whole value is `null` when the divisor is 0.
- **No totals.** One unit test walks the whole object recursively and fails if any key matches `/total|sum/i`, and another checks that the landed tickets' summed cost does not appear in the file. No cost or minutes field is a sum across tickets.

## Receipts

- **What `--receipt` accepts:** a bare issue number `N` and nothing else; anything else is refused before any read. `ticket_report.ticket` is the stream id `ticket-{project}-{n}`, and `parseTicketStream` splits it. A bare `N` that matches in two public projects is refused as ambiguous, and the refusal names both projects.
- **When a receipt is refused:**
  - no `ticket_report` row for it in a public project;
  - it matches in more than one public project;
  - it was not placed in the window by `report()`'s rule;
  - it has no `task_view` title (missing or empty).

  Each refusal names the issue and the reason. `takeBooks` returns all of them together, and the script writes nothing.
- **Fields.** A chosen receipt is `{ median: false, number, title, kind, outcome, fixRounds, passes, waits, machineMinutes, cost }`. `waits` is the count of waits; `cost` is dollars, or `null` under the rule above. It carries no `project`: the number is unambiguous because an ambiguous one is refused.
- **Titles: pass `retentionDays` to `readTasks`.** By default it hides any card that landed more than 2 days ago, so a receipt from early in a month-long window would have no title. `books.ts` passes `ceil((now − from) / 1 day) + 1` and hands `takeBooks` the resulting map; `takeBooks` does not know about retention.
- **The median receipt comes first:** `{ median: true, fixRounds, machineMinutes, waits, cost }`, the medians over landed tickets, with `cost` the median of the priced ones (`null` if none). It is omitted when nothing landed in the window, so an empty window has `receipts: []`.

## The script's order of work

1. **Arguments.** `--from` and `--to` are required `YYYY-MM-DD`, parsed as **local** dates, never `new Date('2026-10-02')` (UTC midnight). `resolveWindow({ from, to }, now)` includes the end day and makes the result's `to` exclusive. The file's `window` records the two dates exactly as given. `--from` after `--to` is refused.
2. **Public projects.** If `LINGTAI_SITE_PUBLIC_PROJECTS` names none, refuse with exit 1 and write nothing: an empty set would produce books that read as a quiet month.
3. **Store.** `LINGTAI_DATABASE_URL` is passed through when exported and non-empty; otherwise the machine's configured store is used. An exported URL selects Postgres, overriding a configured SQLite store.
4. **Lag check, once.** `projectionLag(url)`: if `ticket_report` or `task_view` has no checkpoint, or has `lag > 0n`, say so on stderr, exit 1, and write nothing. (`lingtai report` prints anyway; this script refuses, because its figures are published.) No double read, checkpoint signature, clock comparison or lock is added; a race with a rebuild is out of scope.
5. **Reads and capture.** `readTicketReport({ url })` once, unscoped, and `readTasks({ url, retentionDays })` once. A read that throws exits 1 with nothing written. `capturedAt` is the clock and `commit` is `git rev-parse --short HEAD`.
6. **Write.** `takeBooks`' refusals exit 1; otherwise `books.json.tmp` is written and `rename`d over `books.json`, so a failure partway leaves the previous file untouched and a second run replaces the file whole. The script does not re-run `parseBooks` on its output; the unit test that `parseBooks` reads what `takeBooks` produced, through JSON, is what holds the two together.

## The reader

`readBooks()` returns `null` when the file is missing, when it is not valid JSON, when `version !== 1`, or when any field has the wrong shape, missing or extra (an unknown key, a total among them, fails to read rather than rendering). The guard is written by hand, because `apps/site` depends on no schema library.

Figures are `number | null`. A `null` figure is valid, since an empty window gives `null`s, and the reader accepts it.

Unit cases exercise `parseBooks` on values, so they need no temporary directory (a real temp file would make the test integration under 0060 §1).

## Build steps and `release.yml`

- **No build step touches the file.** `snapshot.ts`'s `rm` names only `SNAPSHOT_FILE`, and `build` in `package.json` stays as it is.
- **`release.yml`.** One line is added to the header comment: before tagging, the operator runs the `books` script and commits `apps/site/books.json`.
- **Checks.** Everything above is checked by the unit half (`pnpm test`). Nothing here needs `test:integration`. The script's own reads are not tested, which matches `snapshot.ts`.
- **Tamper watch.** `apps/site/**` is added to `doc/tamper-watch.md`'s list, because `apps/site` now depends on `@lingtai/conductor`.
