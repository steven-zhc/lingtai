# Design note for #811: Lingtai's own books, written once per release

## Where it goes

Four files. Only one of them does any I/O.

| File | What it holds |
|---|---|
| `apps/site/scripts/books.ts` | I/O only, the way `scripts/snapshot.ts` is: it parses the flags, checks lag, reads, calls `takeBooks`, then validates and writes. It calls `main()` at the top level, so no test may import it. |
| `apps/site/scripts/take-books.ts` | `takeBooks(rows, cards, options) → Books \| Refusal`. Pure: no clock and no I/O. Every unit case in the ticket's *Done when* is a test of this function, in `apps/site/unit/books.test.ts`. |
| `apps/site/src/lib/books.ts` | The `Books` type, `BOOKS_FILE` and `readBooks(): Promise<Books \| null>`. This is what #814's page imports. |
| `apps/site/scripts/public-projects.ts` | `publishable()`, moved out of `scripts/snapshot.ts:35-43`. Both scripts import it from here. Moving it is the only change to `snapshot.ts`. |

**Only `take-books.ts` imports `@lingtai/conductor`.** Add `"@lingtai/conductor": "workspace:*"` to `apps/site/package.json` and import from the `./report` subpath only (`packages/conductor/package.json` exports `"./report": "./src/report.ts"`). That module's own imports are types from `@lingtai/projector` and `@lingtai/domain/wait`, plus `./day-ceiling.ts` (`report.ts:1-15`). `src/lib/books.ts` must not import the conductor or any runtime part of the projector. The site copies code rather than import a sibling app's runtime: `snapshot.ts:401` says it copied `billText` *"rather than imported: a static export has its own package"*. And `tsc` cannot see a server-only import reaching a page graph (CLAUDE.md, #230), so keep the reader free of these imports.

`BOOKS_FILE` is `path.join(repoRoot, 'apps', 'site', 'books.json')`, built the same way as `SNAPSHOT_FILE` (`src/lib/snapshot.ts:127`, which explains why it does not use `import.meta.url`). Add a `"books": "node scripts/books.ts"` script to `package.json`. Leave `"build"` unchanged.

## What `takeBooks` reuses from `report()`, and what it computes itself

- **Public projects.** Filter the rows to `row.project !== null && open.has(row.project)` before anything else. Then call `report({ tickets: publicRows, spend: [], window, project: null, kinds: null })`. `report()` takes one project or all of them (`report.ts:183-184`, *"Null is every project"*), so a set of projects has to be applied by the caller. With `spend: []`, `report().kinds` is keyed by the landed tickets' kinds alone (`report.ts:478-483`). That makes `kinds[].landed` the "landed by kind" figure.
- **Taken from `report()`:** `counts` (`report.ts:513-517`); `landed.fixRounds.median`, `zeroOrOneShare` and `fiveOrMoreShare` (`report.ts:253-266`); and the medians of passes, waits and `machineMs` for the median receipt.
- **The landed set.** Recompute it in `takeBooks` as `outcome === 'landed' && outcomeAt in [from, to)`, which is `report()`'s own placement rule (`report.ts:459-461`). `report()` does not return its placed rows. One test asserts that the recomputed set's length equals `report().counts.landed`, so the two rules cannot drift apart unnoticed.
- **Cost per ticket: use `ticketMoney(row)` (`report.ts:227-237`), not a fresh sum.** It already adds up `estimatedUsd` in dollars, rounds to cents once, and adds `unknownClaims` to `unknown`. That handles the ticket's cents/dollars trap. The ticket's cost in dollars is `(reportedCents + estimatedCents) / 100`.
- **Unpriced runs (decided here).** A landed ticket whose `ticketMoney(...).unknown > 0` is **left out of `cost.median`, `cost.mean` and `cost.p90` entirely**. Its priced part does not count either, because a partial sum is the unknown run counted as zero.
  - `cost.costUnknown` is the number of landed tickets left out.
  - `includesEstimates` is true when any ticket that was included has `estimatedCents > 0`.
  - This means `cost.median` will not equal `report().landed.cost.medianCents`, which keeps those tickets. The ticket's *Out of scope* already says the two need not agree. Do not write a comment or a test that claims they do.
- **p90 is nearest-rank:** `sorted[ceil(0.9·n) − 1]`. `report()`'s `median` and `mean` are not exported (`report.ts:213-221`), so write local copies, with `null` for an empty list.
- **Elapsed time** runs from `min(Date.parse(passTimes[i]))` to `outcomeAt`. Take the minimum rather than `passTimes[0]`. A landed row with no `passTimes` is left out of the three elapsed figures. `withinHourShare` means ≤ 60 minutes. `waitedShare` is the share of landed tickets with `waits.length > 0`.
- **`spendShare`.** For each purpose, sum `reportedCents + estimatedUsd * 100` across every landed ticket's `cost` record (`PurposeCost`, `ticket-report.ts:51-57`; the keys come from `purposeOf`, `ticket-report.ts:255-256`). Then divide by the sum over all purposes.
  - The five words in `PURPOSE_WORDS` are always keys.
  - A purpose tag outside those five keeps its own key, so the shares still add up to 1.
  - The divisor is computed and thrown away. It never becomes a field.
  - Every share is `null` when the divisor is 0.
- **No totals.** One unit test walks the whole object recursively and fails if any key matches `/total|sum/i`. No cost or minutes field is a sum across tickets.

## Receipts

- **What `--receipt` accepts:** either `N` or `owner/repo#N`. `ticket_report.ticket` is the stream id `ticket-{project}-{n}` (`ticket-report.ts:362`, `streams.ts:22-25`), and `parseTicketStream` splits it (`streams.ts:35`). A bare `N` that matches in two public projects is refused as ambiguous, and the refusal names both projects.
- **When a receipt is refused:**
  - no row for it;
  - its project is not public;
  - it was not placed in the window by `report()`'s rule;
  - it has no `task_view` card to take a title from.

  Each refusal names the issue and the reason. `takeBooks` returns all of them together, and the script writes nothing.
- **Fields.** A receipt carries `project` in addition to the ticket's list, because the number alone is ambiguous across projects. Its `cost` is `null` when its `unknown > 0`, under the same rule as above.
- **Titles: pass `retentionDays` to `readTasks`.** By default it hides any card that landed more than `DEFAULT_RETENTION_DAYS = 2` days ago (`task-view.ts:71`, applied at `task-view.ts:1174`, and as `now − retentionDays` at `sqlite.ts:674`). Without that argument, a receipt from early in a month-long window has no title. Pass `ceil((now − from) / 1 day) + 1`. Keep that arithmetic in `books.ts`. `takeBooks` receives the cards and does not know about retention.
- **The median receipt comes first:** `{ label: 'median', passes, fixRounds, waits, machineMinutes, cost }`. Its cost is `cost.median`. Every field is `null` when nothing landed in the window.

## The script's order of work

1. **Window.** Parse `--from` and `--to` as **local** dates, `new Date(y, m − 1, d)`. Never use `new Date('2026-10-02')`, which is UTC midnight. Then call `resolveWindow({ from, to }, now)` (`report.ts:50-57`): the end day is included and the result's `to` is exclusive. The file's `window` records the two dates exactly as given.
2. **Public projects.** If `publishable()` is empty, refuse with exit 1 and write nothing. This is unlike `snapshot.ts:98-100`, which goes ahead and withholds every card. Here an empty set produces books that read as a quiet month, and somebody runs this script on purpose.
3. **Store.** Pass `LINGTAI_DATABASE_URL` through when it is exported. When it is not, let `withProjectionStore` choose the machine's store.
   - `snapshot.ts:85-95` insists on the exported variable so that every local site build stays free of the operator's board. That reason does not apply to a script a person runs by hand.
   - A URL *"refines a Postgres connection and never picks the store"* (`projection.ts:280-281`). So insisting on it here would make the script unusable on a machine whose store is SQLite.
4. **Lag check, once.** Call `projectionLag(url)` (`projection.ts:279`). If `ticket_report` or `task_view` has no checkpoint, or has `lag > 0n`, say so on stderr, exit 1, and write nothing.
   - The ticket cites `commands.ts:181-182`, but that is only the usage text. The check itself is `apps/cli/src/report.ts:308-321` with `describeLags` at `271-288`.
   - Copy the five lines rather than import `apps/cli`.
   - Note the difference: `lingtai report` prints the figures anyway when behind, and this script refuses, as the ticket asks.
   - Do not add a double read, a checkpoint signature, a clock comparison or a lock. Per the ticket's *Out of scope*, a race with a rebuild is a backlog entry, not a refusal.
5. **Reads and capture.** Call `readTicketReport({ url })` once, unscoped (`read-ticket-report.ts:14`), and `readTasks({ url, retentionDays })` once. A read that throws exits 1 with nothing written. Record `capturedAt` and `commit` (`git rev-parse HEAD`, as `snapshot.ts:46-52` does with `--short`).
6. **Validate, then write.** Run the result through the same validator `readBooks` uses, then write `books.json.tmp` and `rename` it over `books.json`. A failure partway leaves the previous file untouched, and a second run replaces the file whole.

## The reader

`readBooks()` returns `null` when the file is missing, when it is not valid JSON, when `version !== 1`, or when any field has the wrong shape. Write the guard by hand, because `apps/site` depends on no schema library (`package.json` dependencies).

Figures are `number | null`. A `null` figure is valid, since an empty window gives `null`s, and the reader must accept it.

Unit cases: a missing path, garbage text, a wrong version, a valid file, and a valid file with null figures. Point the reader at a path the test gives it, so the cases need no temporary directory. Pass the text in, or inject a `read` port. A real temp file would make the test integration under 0060 §1.

## Build steps and `release.yml`

- **No build step touches the file.** `snapshot.ts:78-83`'s `rm` names only `SNAPSHOT_FILE`, and `build` in `package.json` stays as it is.
- **`release.yml`.** Add one line to the header comment: *before tagging `v*`, run `pnpm --filter @lingtai/site books --from … --to … --receipt …`, read `apps/site/books.json`, and commit it.*
- **Checks.** Everything above is checked by the unit half (`pnpm test`, the `apps/site/unit/` glob in `vitest.config.ts:72`). Nothing here needs `test:integration`. The script's own reads are not tested, which matches `snapshot.ts`.
