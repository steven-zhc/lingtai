## Design note: #1072, reconcile as an Effect

Line numbers are this worktree's (`6b7cac85`), and they match the ticket's.

### 1. `src/index.ts` changes too, even though Done-when's diff-stat line leaves it out

`packages/daemon/src/index.ts:90-101` re-exports `exists`, `findLaggingProjections`, `killWorker` and `releaseForeignClaims` from `./reconcile.ts`. The ticket gives these four no promise form, so this export list has to change. Rename those four entries to their `…Effect` names: `existsEffect`, `findLaggingProjectionsEffect`, `killWorkerEffect`, `releaseForeignClaimsEffect`. Add `reconcileEffect`, `findOrphansEffect` and `findOrphanLogsEffect` beside the three faces.

Do not keep the old names as aliases that now return an Effect. `await killWorker(x)` would then type-check in some positions and quietly do nothing. Say in the commit body that `index.ts` is the one file outside the Done-when list, and why. The ticket's own evidence ("exported from `src/index.ts`") is what makes it necessary.

### 2. Each catch keeps the error it reports

The release and the removal report `(err as Error).message` (`reconcile.ts:753-754`, `:767`). That message has to be the store's or `rm`'s own text.
- Write every `Effect.tryPromise` here as `{ try, catch: (e) => e }`, the same `attempt` shape `readThroughSnapshot` uses (`packages/event-store/src/snapshot-read.ts:38`). The bare overload wraps the error in an `UnknownError`, and the message would change.
- Where the guard is `Effect.catchCause`, get the error back with `Cause.squash(cause)` before reading `.message`.
- Pass an interrupt-only cause straight through with `Cause.hasInterruptsOnly`. That is the predicate already used at `packages/actions/src/agent-action.ts:1031`.

### 4. The release step

Each finding gets its own `Effect.uninterruptible`, and the uninterruptible region is exactly today's `try` block (`:713-756`):
- re-read through `readThroughSnapshot`, with no `Effect.catch` on this read, so a failure falls into the step's own catch the way `:753` does today;
- the guard;
- `killWorkerEffect`;
- the `TicketReleased` append as `tryPromise`;
- then `Effect.catch` on the whole step, setting `reported` and `could not release: …`.

A failure in any part, append included, becomes a value, and the `for` loop goes on to the next finding. The removal is the same shape around `rm` (`:760-770`).

Do not make the loop as a whole uninterruptible. The ticket asks for "a scan stops between steps", so an interrupt should land between one finding's step and the next.

### 5. The interruption test: two traps

- **`Fiber.interrupt` waits for the fiber to finish**, and the fiber cannot finish until the `Deferred` completes. Awaiting the interrupt inline deadlocks the test. Fork the interrupt, complete the `Deferred`, then join the forked interrupt and the fiber.
- **The test has to know the fiber has reached the append before it interrupts**, and it may not use a timer to find out. Give the fake store's `append` two `Deferred`s:
  1. `reached`, which `append` completes as soon as it is called;
  2. `release`, which it waits on, via `Effect.runPromise(Deferred.await(…))` inside the fake. That call is allowed because the ratchet counts `src/` only (`effect-ratchet.test.ts:307`).

  The test awaits `reached`, forks the interrupt, completes `release`, and then asserts two things: the append's events were recorded, and the fiber's `Exit` is interrupt-only.

  Use `createMemoryEventStore()` for every other call, and set `projects` and `worker` so that `releaseForeignClaimsEffect` finds one foreign claim. `killWorker` answers `"…" names no process` for a worker it cannot parse (`:585-586`). So pick a worker string that `parseWorker` (`:624-630`) rejects, such as `"dead"`, and no real pid is ever signalled.

### 6. Faces and the ratchet

- Each face is exactly `export function reconcile(options: ReconcileOptions = {}): Promise<Finding[]> { return Effect.runPromise(reconcileEffect(options)) }`. The face check refuses anything with a second statement or a second argument (`effect-ratchet.test.ts:209-266`).
- The ratchet reaches 39 only if no `async` survives anywhere in `reconcile.ts`. That includes the closure inside `withStreams`: build the `withDaemonStore` callback as `(it) => it.streams(…)`, which returns the promise directly and is not marked `async`.
- `findOrphansEffect({ ...options, abandoned })` keeps today's call shape (`:679`).
