# Design note for #943: renaming Effect 4's APIs in 0101 §5 and §6

The ticket's line numbers and code claims are correct for this tree:

- `Context.Tag` appears at `doc/decisions/0101-typescript-packages-effect-unbuilt.md:94` and `:102`.
- `@effect/opentelemetry` appears at `:118`.
- `tracingLayer` is `Layer.succeed(Tracer.Tracer, bridgedTracer)` at `packages/conductor/src/telemetry.ts:115`.
- `schedule.ts` takes `yield* Effect.context<Repo | AgentHost>()` at `:174` and calls `Effect.runPromiseWith(runtime!)` at `:283`.

The edit is three passages in one file. There are two traps the ticket doesn't spell out.

## 1. The new sentence must not contradict the bullet it goes into

The bullet at `:112-115` says:

> Never inside backend code — a `runPromise` nested in an Effect starts a fiber with no parent, which loses the caller's scope, its interruption and its span.

`schedule.ts` is backend code, and its `runPromiseWith` is a nested run. If the sentence reads as an exception ("…except `schedule.ts`, which…"), it rewrites the rule, and that change belongs to #790.

So write it as a description of how a detached run carries the caller's services and tracer. It should not claim the run is allowed, and it should not say it keeps scope or interruption, because it does not. That matches the code's own comment at `schedule.ts:168-173`:

> it must carry the caller's tracer into it … On Effect 4 the tracer is a `Context.Reference`, so `Effect.context` holds it

A safe shape: *"A pass the scheduler starts detached runs with `Effect.runPromiseWith(yield* Effect.context())`, which carries the caller's services and its tracer into the new root fiber (`packages/conductor/src/schedule.ts`)."*

Leave the "Never inside backend code" sentence word for word.

## 2. The tracing bullet cannot mention the package it replaces

The first Done-when grep requires `@effect/opentelemetry` to be gone from the file. So *"bridged by hand rather than through `@effect/opentelemetry`"* fails the ticket. It is also history, which ADRs here never carry (CLAUDE.md: *"each stating the current decision and nothing about how it got there"*).

State only what is true now. A host with `telemetry.otlp_endpoint` provides `tracingLayer` from `packages/conductor/src/telemetry.ts`, which is `Layer.succeed(Tracer.Tracer, bridgedTracer)`, and exports over OTLP/HTTP. "Exporting over OTLP/HTTP" is still true: `telemetry.ts:200` picks `node:http` or `node:https` for the exporter's agent. Keep the rest of that bullet (`:118-121`) unchanged: what a span may carry, `lingtai.ticket`, and the board's spans.

`telemetry.ts:10-12` still gives the Effect 3 reason for the bridge (*"needs an `effect` newer than this repository's"*), which is stale now. That is a code comment, so it is out of scope here. Don't copy that reason into the ADR.

## §5 and §6's naming sentence

These are a straight word swap:

- `Context.Tag`s → `Context.Service`s
- `` `Context.Tag` names a port or a service `` → `` `Context.Service` names a port or a service ``

Check the plural against `packages/conductor/src/ports.ts`, where `Repo` and `AgentHost` are each `class … extends Context.Service<…>()(…)`.
