## 3. The runner's input, and two traps in it

```ts
{ interactive: deps.interactive(), defaults: flags['defaults'] !== undefined, flags,
  askers, log, kept: () => ({ kept }) }
```

- **`kept` must be passed, and it is a function.** `SetupInput.kept` is `(written) => { kept; startOver? }` (`setup-list.ts:125`), not a string. The ticket's *"`input.kept` is `ADD_KEPT`"* is `ctx.kept`, which is the string. Leaving `input.kept` out falls through to `defaultKept` (`setup-list.ts:146-155`). That would say *"what was answered above is kept (writer, kinds…)"* on a Ctrl+C, because `append` marks every entry with a pending change as `wrote: true` (`project-list.ts:315-317`). That sentence is false here: nothing has been written.
- **`ctx.log` is a buffer nobody prints.** The entries push onto `ctx.log` (`project-list.ts:707`, `:791`, `:934`, `:991`, `:1001`, `:1066`, `:1116-1119`, `:1176`). The runner never prints it, and the tests read it as an array (`packages/setup/unit/project-list.test.ts:356`, `:665`). Today those lines print as they happen, ahead of the next prompt (for example `setup-build.ts:101`).
  - Wrap each asker in `projectAskers(world)` so it first prints `ctx.log` from a cursor, then asks. After the walk, print the rest.
  - Never splice the array. It is pushed onto, the same discipline `pending` has (`project-list.ts:9-10`).
  - Without this, every hint arrives after the last question.
- `askers` is `projectAskers(world)` (`project-askers.ts:113`), over the same `world` built at `:431-435`. `log` is `console.log`, the same as `world.log`.

## 6. Two edges the ticket words loosely

- **Team → solo is not refused at `draft.set`.** `RecipeDraft.set` *"Applies `changes` in memory … Never writes"* (`packages/project/src/draft.ts:41`). The PR and draft read is in `changeRecipe` (`change.ts:178-191`), which `applySetup` calls (`packages/setup/src/apply-setup.ts:92`) from `addWithSetup` (`add.ts:405`), before the registration.
  - That still meets *"before anything is made"*: on GitHub, `make-branch` applies only in team mode (`project-list.ts:733-736`), so a run that switches to solo has no `make`.
  - Add no new read. Test it by asserting that a team → solo rerun over a store with an open PR refuses with `modeSwitchMessage`'s words (`change.ts:78`) and records no `createRef`.
- **Ctrl+C and `github.auth`.** ADR 0125 as amended at `doc/decisions/0125-setup-is-one-module-two-inputs.md:137-139` decides this: *"a Ctrl+C in the project list keeps the machine answers already written (`github.auth` included) and writes no recipe, makes no branch and registers nothing."*
  - The gap in `doc/design/1525.md` §5, and the earlier answer that limited the interrupt test because of it, both predate that amendment.
  - So the interrupt test asserts the `Done when` in full, including the surviving `github.auth`.
  - No backlog entry is owed. The commit body should say it is the ADR's rule, not a gap.
