## Design: #1017, how the ratchet recognises a promise face

### Where it goes

The new logic lives in `packages/domain/unit/effect-ratchet.test.ts` and nowhere else. The ticket also touches these files:

- `effect-ratchet.baseline.json` and a new `effect-ratchet.faces.json`, both beside the test.
- `packages/conductor/src/snapshot-state.ts`.
- A new `packages/conductor/unit/snapshot-state.test.ts`.

No production module other than `snapshot-state.ts` changes.

### Split the import scan out of `count` so the face check knows which run an alias is

Today `count` gathers the local names imported from `effect`/`effect/Effect` into `bare: Set<string>` (`effect-ratchet.test.ts:73,87`). It keeps only the local name, so after `import { runSync as go }`, `go` and an aliased `runPromise` look the same.

Rule 3 has to refuse `runSync` by name, including when it is aliased. Do this:

- Lift lines `:72-90` into `importsOf(sf)`. It returns `{ effects: Set<string>, bare: Map<string, string> }`, mapping local name → imported name.
- `count` calls it and tests `bare.has(...)` exactly as before. Its counting must not change: every existing `count` test stays green untouched.
- `face` calls the same helper:
  - an `<effects>.X(...)` callee is accepted only when `X === 'runPromise'`;
  - a bare callee is accepted only when `bare.get(local) === 'runPromise'`.

  Anything else that `RUN` matches is refused by name, using the imported name, not the alias.

### Match by position, from one place

- `Hit` gains `pos: number`. `at` (`:93`) sets it to `n.getStart(sf)` beside `line`.
- `count` records the `PropertyAccessExpression` node (`:111`) or the bare `Identifier` node (`:117`). In both cases `getStart` is the position where the callee text begins.
- `face` must return `call.expression.getStart(sf)` for the run call it accepted. That is the same number by construction. Do not compute it any other way (for example from the `return` keyword or from the `.name`), or the package loop will never find it.

**Rule 4 is checked with `count` itself, not a second walker.** Call `count(name, text)` on the same text and keep the hits whose `pos` is in `[decl.getStart(sf), decl.end)`:

- For `export function`, `decl` is the `FunctionDeclaration`.
- For `export const f = () => …`, `decl` is the whole `VariableStatement`. Accept it only when it has exactly one declarator.

There must be exactly one hit in the span, and its `pos` must equal rule 3's. Otherwise refuse with the line of the first hit that is not rule 3's. This also makes a face's counted-run set agree with the package loop's, so the two can never drift apart.

Two cases are refused as "not exported":

- an `export { f }` list;
- a `function f` declared without the modifier.

Detect the modifier with `ts.getModifiers(decl)?.some(m => m.kind === ts.SyntaxKind.ExportKeyword)`. Refuse `export default` too, because it has no `fn` name to match.

### The faces-file check is a pure function

The ticket asks for an inline-array test that refuses entries by name. That test must stay unit (0060 §1, *"the filesystem"* makes it integration). So write:

```
checkFaces(entries: unknown, read: (file: string) => string | undefined)
  : { exempt: Map<string, Map<number, FaceEntry>>; refusals: string[] }
```

- The live test passes `import faces from './effect-ratchet.faces.json'` as `unknown`. Validate the shape inside rather than trusting the JSON's inferred type: a non-array or a missing key is a refusal, not a crash.
- The live test builds `read` up front: it reads every listed file with `readFile` before the `Promise.all` (`:210`), and maps a missing file to `undefined`. The inline test passes a `Record` lookup.
- The checks run in the ticket's order. A `face(...)` refusal is prefixed `effect-ratchet.faces.json: <file> <fn>`.
- **Order check:** compare with `<` on `file`, then `fn`. Do not use `localeCompare`, which is locale-dependent and would sort differently on another machine.
- **Package check:** `file.startsWith(`${pkg}/src/`)` for some `pkg` in `PACKAGES`, and not in `NOT_COUNTED.map(n => n.path)`.
- Run `checkFaces` **once, before** the package loop. Push its refusals into `problems` first, so that a bad entry and a baseline rise both show in the same red.

In the package loop (`:220-223`), drop a run hit when `exempt.get(f)?.has(h.pos)`, and push `f:line fn (until …)` to a `notCounted` list. Print that list under `measured now` (`:243-245`) only when there is a red. Change the hit strings from `${f}:${h.line}` to include nothing new: the position is internal.
