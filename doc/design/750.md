## Decisions the ticket leaves open

**1. Put the edit in its own exported function, and call it from the split-done path too.** Name it something like `editEndedWaits({ store, github, ticketId })` in `tell.ts`. `tellGitHubAbout` calls it first when `editEnded` is set.

The split's ending does not pass through any of the four sites. When every child of a split is closed, the claim refuses with `split-done`. `conduct.ts:2320-2355` then calls `closeHolding` and posts the split comment with **`tellGitHub` directly** (`:2345-2350`), not `tellGitHubAbout`. Without a direct call, the outcome table's *Split by* row can never happen in production.

Call `editEndedWaits` inside `if (closed.ok)` (`:2340`), just before the split comment:
- The wait is already over, because `WaitResolved{SplitResolution}` is on the stream.
- This is still the conductor acting, so it does not break *only the conductor edits*.
- A refused close (stale `ifVersion`) edits nothing, and the next pass gets it.

The `closeHolding` → `tellGitHubAbout` call at `close.ts:251` still passes no `editEnded`.

**2. Make the outcome a `switch` over `Resolution._tag` with no `default`.** Then a new resolution is a type error, not a silent fallthrough. `Resolution` has seven members (`wait.ts:259-268`), including `SplitResolution` and `Close`. The ticket's table has no row for `Close` or for a bare `TicketClosed`. Give both **Closed by `<by>`.** The conductor never reaches them in practice, but the function stays total.

The order of checks:
1. `TicketLanded` after the wait's `WaitStarted`
2. the wait's own `WaitResolved`
3. `TicketClosed` after the `WaitStarted`

So with two waits, the first wait's comment is edited at the second hold to *Approved by …*, never later to *Landed*.

**3. Thread the new fields through `IssueWrite`; don't add a second record path.**
- The `comment` member of `IssueChange`/`IssueWrite` (`tell.ts:101`) gains optional `waitId` and `question`.
- The new `{ kind: 'comment-edited'; waitId; commentId; body }` member gets its own `case` in `tellGitHub`'s switch (`tell.ts:172`).
- `record` takes `Record<string, string>` (`tell.ts:345`), so add `waitId` and `question` only when they are defined. Never pass `undefined`.
- The catch at `tell.ts:202-212` already writes `change: change.kind`. Add `waitId` there, and `IssueUpdateFailed{change: 'comment-edited', waitId}` comes out of the same code.

**4. The question line.** Take the first non-empty line of the `question` string at `conduct.ts:4638`, trimmed, and store it as `IssueUpdated.question`. The `no-merge` hold (`conduct.ts:3268`) goes through the same `:4638` call, so it needs no site of its own. The edited body is `**<outcome>**\n\n> <question>`. With no recorded question, it is the outcome line alone.

**5. Keep `converge.ts` from seeing the new change.**
- `findIssueDrift` keys `lastOutcome` by `change` (`converge.ts:365`), so `comment-edited` never shows up as `comment`. That part is fine as it is.
- The repair loop is the risk. Its last branch is a bare `else { await client.closeIssue(d.issue) }` (`converge.ts:508-510`). Anything that reaches it with an unknown `change` closes the issue.
- So `Divergence.change` (`converge.ts:245`) must **not** widen to include `comment-edited`. If widening the `IssueUpdated` enum makes that type follow, narrow it explicitly.
- Add a unit assertion that a failed edit produces no divergence.

## Cost and checks

- **Cost to every later conductor call.** The edit runs at every release and every claim, not only after a wait. It is one extra `store.read(ticketId)` per call and nothing else when no wait has ended. Read the stream once and do the matching in memory, in stream order: *after `WaitStarted`* means a later position on the same stream.
- **Test doubles.** `memory-tickets.ts:106` hands out comment ids. Its `editComment` must:
  - keep the body per id, so a test can assert the whole edited text;
  - throw on an unknown id, so the failed-edit test has a cause.
  
  Every full `Tickets` double needs the verb too. Find them with `pnpm typecheck` rather than a list.
- **Checks.** Every check here is unit-level: memory store, memory `Tickets`, and `passClientOf` (`ticket-store.ts:311-324`, which today names eight verbs — add `editComment` as the ninth). Nothing here needs `pnpm test:integration`. The GitHub `PATCH` in `packages/github/src/client.ts` is not exercised before the merge. Keep it beside `comment` (`client.ts:414-417`), in the same shape.
