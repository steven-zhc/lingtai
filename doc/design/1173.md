# #1173: shape

## Where the reads go

Add a new file, `packages/project/src/state.ts`, and export it from `packages/project/src/index.ts`. Into it go `listProjectStreamsEffect`, `loadAllProjects*` and `loadProjects*`, moved from `packages/conductor/src/projects.ts:41-111` with their names, bodies and doc comments as they are, along with the private `defaultLog` from `projects.ts:30-31`. `defaultLog` has to stay a dynamic `import('@lingtai/event-store')`. The comment at `projects.ts:14-21` gives the reason and should move with it: *"a caller that brings its own log should still load no store at all"*. `@lingtai/project` already depends on `@lingtai/event-store`, so its `package.json` needs nothing new.

**`conductor/projects.ts` does not re-export any of them.** Callers inside `packages/conductor` import from `@lingtai/project`, which conductor already depends on (`packages/conductor/package.json:59`). A re-export would break the tests quietly, as the next section explains.

## The one-project read, in two parts

- `readProjectStateEffect(project, store?): Effect<ProjectState, Error>` is `Effect.tryPromise({ try: () => from.read(projectStream(project)), catch: asError })` piped through `reduceProject`. It returns no null and does no `isRegistered` check: the guard's `projectPause` reduces any stream (`guard.ts:76-79`), and so does the board's `setProjectPaused` (`locks.ts:256`). `setProjectPaused` then runs its own `isRegistered` test (`:258`) to word its refusal.
- `readProjectEffect(project, store?): Effect<ProjectState | null>` is `readProjectStateEffect(...).pipe(Effect.orDie, Effect.map(s => isRegistered(s) ? s : null))`. `orDie` keeps the rule at `projects.ts:53`: *"A store that fails is a defect (0101 §6): through the face it rejects with the driver's own error."* You can drop today's `events.length === 0` short-circuit. `reduceProject([])` has `project: null`, and `isRegistered` asks for `state.project !== null && state.configHash !== null` (`packages/domain/src/project.ts:145-146`), so an empty stream still comes back null.
- Rename the face to `readProject`. Delete `loadProject` and `loadProjectEffect` outright. Keep no alias, so that #1175 owns the name.

## Four faces, not three

The Done when list asks for `readProjectState*` to be exported, so there is a promise face `readProjectState`. It has exactly one caller, `apps/board/src/app/actions.ts:627-630`, which becomes:

```ts
const read = await readProjectState(project, eventStore).catch(asError)   // ProjectState | Error
const refusal = askRefusal(project, read)
```

That keeps the edit to `actions.ts` to one line and its error handling unchanged. Then `effect-ratchet.faces.json` gets four entries under `packages/project/src/state.ts`: `loadAllProjects`, `loadProjects`, `readProject` (which replaces `loadProject`) and `readProjectState`. The `readProjectState` entry's `why` names `apps/board/src/app/actions.ts`. The faces file is ordered by path (see `8bdae9e1`), so the four entries move to wherever `packages/project/…` falls in that order. `effect-ratchet.baseline.json` is all zeros (`packages/domain/unit/effect-ratchet.baseline.json`) and does not change, because listed faces are not counted.

`askRefusal(project, read: ProjectState | Error)` (`locks.ts:292-295`) drops its `reduceProject` call and the `Envelope` import. Its test is `apps/board/unit/ask-refusal.test.ts`. The fixtures that build envelopes now pass `reduceProject(envelopes)`, and the `Error` case stays exactly as written.

## The other readers

- **Daemon guard** (`guard.ts:76-79`, `:123-127`): both `store.read` + `reduceProject` pairs become `readProjectStateEffect(project, store)`. Its error is already `Error`, and that is what `Check` expects (`guard.ts:71`). Keep the two reads separate. Folding them into one read is not this ticket.
- **`packages/daemon/package.json` gains `"@lingtai/project": "workspace:*"`**, because it does not have one today; its dependencies list only `@lingtai/conductor` and `@lingtai/projector` among the related packages. That means running `pnpm install`, so `pnpm-lock.yaml` changes. `@lingtai/project` depends on neither daemon nor conductor, so this creates no cycle. Leave `control.ts:731`'s private `readProject` alone, and import nothing named `readProject` into that file (that part is #1174's).
- **Doctor** (`doctor.ts:385`): `listProjectStreamsEffect(queries)` replaces `lift(() => queries.projectStreams('prj-'))`. The moved function fails through `Effect.promise`, which is a defect, and `recovering` already turns a defect into the row: *"A store failure is a defect (0101 §6), which `Effect.catch` does not see, so this is `catchCause`"* (`doctor.ts:257-267`). So `log: reachable` still fails by name on a store that will not open. Check that the unit test covering this row still drives the failing case.
- **Board `setProjectPaused`** (`locks.ts:256`): `read = () => readProjectStateEffect(project, store)`. The function's error channel goes from `UnknownException` to `Error`. Its caller wraps it in `Effect.runPromise` inside a try (`actions.ts:541`), so behaviour stays the same.

## The trap: `vi.mock` paths

Six unit files mock `@lingtai/conductor/projects` (`apps/board/unit/picks-actions.test.ts`, `queued.shape.test.ts`, `timing-load-task.test.ts`, `trace-spans.test.ts`, `triage-read.test.ts`, `apps/cli/unit/discuss-answer.test.ts`). After the move, the moved functions are imported from `@lingtai/project`, and a mock left on the old path no longer intercepts them. A file that still mocks only `currentRecipe` there keeps working. Every mock of `loadProject`, `loadProjects` or `loadAllProjects` has to be moved to `vi.mock('@lingtai/project', async (orig) => ({ ...(await orig()), … }))`. **It has to be a partial mock**, because the same module exports `resolveLocalRecipe*` and the file writers, and a whole-module mock would replace those too. A re-export from `conductor/projects` would be worse: a test could mock the old path and pass while the code under test reads the real store. Grep the unit and integration trees for `'@lingtai/conductor/projects'` and handle every hit before running `pnpm test`.

`apps/cli/src/requeue.ts:32,55,70` injects `loadProject?: typeof loadProjectEffect`. Rename that option to `readProject?: typeof readProjectEffect` and change its tests to match. Don't keep the old option name pointing at the new function, because that is exactly the collision 0128 §7 reserves the name against.
