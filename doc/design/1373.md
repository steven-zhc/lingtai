# #1373 — the shape

## Where it goes

- **A new `apps/board/src/lib/pr-branches.ts`** holds two pure functions:
  - `prBranches(pr: PrState | null, events, draft)` returns what is in the drawing: lanes, nodes, edges, the brace, *now* and the words.
  - `layoutBranches(model, width)` gives each node its x.
- **`PrPageView.drawing`** (`apps/board/src/lib/pr-page.ts:155-161`) becomes the laid-out result. It is set in two places: `:644` for a PR and `:693` for the draft. The draft also goes through `prBranches`, with `pr === null`.
- **`Drawing`** in `apps/board/src/app/pr-detail.tsx:29-67` becomes markup over that result and nothing more. The file's header promises *"Markup over the view and nothing else, so a unit test renders it"*.
- **Tests** go in `apps/board/unit/pr-branches.test.ts`: one fixture per mock frame. `apps/board/unit/pr-page.test.tsx` never touches `drawing` today (grep finds nothing), so no existing test breaks.

The split between the two functions is the ticket's own rule: *"Tests match nodes and edges, never pixel positions."* `prBranches` decides what is drawn, in log order, and its 14 fixtures assert that. `layoutBranches` ports the mock's placement rule (`doc/milestone/0.16.0/team-mode/pr-branches.html:101-106`: *"into or out of main: the other end stays and main's commit moves; otherwise the target moves"*). Its tests assert properties, never coordinates:
- every edge has |dx| = |dy|;
- x strictly increases along each lane;
- everything fits inside the width;
- labels on the PR lane alternate above and below.

## The decision the ticket gets wrong: no new field

Under *What is missing* the ticket says no event records which `main` commit a sync merged. **That is false, so Fix §1 is not built.**

- `BranchSynced { mainCommit, head, how: 'already' | 'clean' | 'resolved' }` (`packages/domain/src/events.ts:2756-2760`) is *"`origin/<branch.main>` is in the PR's commit"* (`:2748`). `mainCommit` is required and has been since the event was added in `c85d56349`, so old events carry it too.
- Every sync that finishes appends one:
  - `'already'` at `packages/conductor/src/pr-sync.ts:139-145`;
  - `'resolved'` at `:178-183` and `:278-283`;
  - `'clean'` at `:294-299`, written by the build step, from `${merge}^2` (`:246-247`: *"`main`'s commit is the merge's second parent: what was merged, whatever `main` is now"*).
- A step that answers with a `record` writes that record **instead of** `PrStepDone` (`packages/conductor/src/pr.ts:886-890`). So the sync usually has no `PrStepDone` at all, and an optional field on it would mostly go unwritten.
- `syncedTransition` (`packages/domain/src/pr.ts:782-790`) keeps it to one per walk: *"A step already recorded since the latest `PrInProgress` appends nothing"*.

So the sync's two shas are `BranchSynced.head` (the PR-lane node) and `BranchSynced.mainCommit` (the `main` node the `sync` edge starts from). The domain, the conductor and `effect-ratchet.baseline.json` are untouched.

Done-when box 2 (*"the sync step records `main` on its `PrStepDone`"*) is met by the existing event and decodes for every event already in the log. **The commit message and PR body must say this was deliberate**, so the reviewer does not read the missing field as a gap.

There is one window with no main sha. A clean merge appends `PrStepDone{step:'sync', headSha: merge}` (`pr-sync.ts:196`) before the build has run, and its `BranchSynced` comes only once the build passes. In that window the sync node is `done` with no main sha, and its `sync` edge is drawn `todo`. The merge exists, but *main is in the PR's commit* is not yet true.

## Event → what is drawn

This list is the builder. Anything not on it adds no node.

**The freeze and the walks**
- **The first `PrInProgress`** gives:
  - a personal `done` node, *`<frozenSha·7>` frozen*;
  - the start of the PR lane and a `fork` edge;
  - the `tickets` as `ticket` dots before the freeze. Past five, the brace carries `+N`.
- **A later `PrInProgress`** (`because` is `retry | pr-fix | restart`) starts a new walk on the same lane. It adds no fork.
- **For the latest walk**, the PR-lane step nodes come from `prStepRows(names, pr)` (already used at `pr-page.ts:339`), so the drawing and the steps list cannot disagree:
  - the steps done since the sync are shown as the mock shows them: *build ✓*, *pushed · #n*, *CI ✓ · ready*;
  - then the `running` step or the `waiting` one, `red`, worded with `WAIT_WORDS` like the steps list;
  - then `ready` as `todo` if it was not reached.
- **Earlier walks** keep only their sync and their ready. Past three walks, *earlier walks: n* goes in the gutter. Conflict-agent rounds (`SyncRoundStarted`) are never nodes.

**Commits that join the PR branch**
- **`PrFixLanded`** is a `ticket` node on the PR lane, *#n pr-fix*.
- **`PrOutsideMerged`** (`events.ts:2770`, `commits[0].sha·7 · author`, `+omitted`) is what frame 07 draws. The ticket names `PrHeadAdopted` for this. That event (`:2911`, a head a person pushed and a retry adopted) is an `outside` node too, labelled *`head·7` · by*. Both are drawn.

**Back into the personal branch**
- **`PrMergedBack`** is a personal `done` node, *`mergeCommit·7` merged back*, with a `back` edge from the PR-lane node of that walk.
- **`PrMergeBackFailed`** is a `red` node with a `red` edge, worded by `why`.
- **A merge back still owed** has no event. It is in review, `lastPushed !== null`, and no `PrMergedBack` has `prHead === lastPushed`. That is drawn as a `todo` edge, never `done`.
- **Frame 09's words.** A merge back that found nothing to do appends nothing (`pr-sync.ts:531`, `:634-643` only records the catch-up's case). So *nothing to merge back* is inferred from the log instead: the walk's `BranchSynced.how === 'already'`, and `lastPushed === frozenSha`. In that case the PR branch *is* the frozen personal commit. The page writes the words and draws no edge.

**Into `main`**
- **`PrMerged`** is a `merged` node on `main`, with *`mergeSha·7`*, or no sha when `how: 'git'` (`mergeSha: null`, `:2871`), and a `merge` edge.
- **In review and not merged**, a `todo` merge edge runs to *you merge #`host.number`*.

**The catch-up**
- **`PrCaughtUp`** (`:2810`) is a personal `done` node, *caught up with main*, with a `catch-up` edge from a `main` node at `mainSha`. When `mergeCommit` is null, it is the words *already caught up* and no edge.
- **`PrCatchUpFailed`** is `red`.
- **#1371 has landed in this worktree**: the reducer handles both events (`packages/domain/src/pr.ts`, `case 'PrCaughtUp'`), and `catchUpPersonal` is imported at `packages/conductor/src/pr.ts:69`. So frames 12 and 14 can be built now, not later.

**A close**
- **`PrClosed`** ends the PR lane with *× closed*. It says *by lingtai pr back* when a `PrBackRequested` (`:2918`) comes before it.
- **With no `PrMergedBack`**, the personal lane says *the tickets are Draft again*.
- **With one**, that node's label becomes *merged back — stays* (#1354).

## Frame 11: a commit on `main` the PR's log never names

The mock's `e4c4ae6 · not in this PR` is the tip of `main` after the sync. No event on the PR's stream names that commit while the PR is in review: the sync records `mainCommit` once, and nothing reads `main` again until the catch-up. Neither reading `main`'s tip with git nor asking the code host for it is allowed: the board reads no git (`events.ts:2611-2612`), and `pr-page.ts:8-9` already says *"What the page does not draw … how far `main` has moved since the sync"*. So frame 11's fixture asserts that the drawing is frame 08 with no later `main` node.

The *not in this PR* label is still built, for a `main` node named by an event that comes after the walk's `BranchSynced.mainCommit` and is not in it. In 0.16 that never happens before the merge. Tell the reviewer that this is the *draw only what the log says* rule winning over the mock's picture, not a missed frame.
