# #637 design: daily dollar ceiling

## The decision is already accepted, so this note is mostly about where the pieces go

[0122](doc/decisions/0122-several-passes-share-one-conductor.md) §5 already decides most of this ticket:

- The figure is **one value in `~/.lingtai/config.yml`**. Its environment form is a `LINGTAI_` variable. It applies to the whole installation, because one account pays.
- The day is the machine's local calendar day.
- Spend is the sum of today's rows in the `spend` table. A row that cannot be priced is *"named as unknown and never counted as zero"*.
- The check goes *"where the pause is already asked before each claim"*. Reaching the ceiling appends `ConductorPaused` with `until` set to the next local midnight. The reason names the figure and today's spend. The pause has no `holdsAcrossStarts`.

Do not reopen any of that. `runtime.concurrency` is not built yet (`rg concurrency packages apps` finds no recipe key), so 0122's *"while none is set, one pass in all"* is already true today and is out of scope here.

## 1. What the unknowns are

Every agent outcome appends one `RunSpent`, including failed ones: `spentOf` is attached on every branch (`packages/actions/src/agent-action.ts:80`, `:635`, `:1103`). The `spend` projection copies `costUsd` exactly as written, and `null` stays `null` (`packages/projector/src/spend.ts:13-15`, `:177`). No rate card exists yet: `apps/board/src/lib/spend.ts:126` says *"No rate card exists yet (`#208`). Every row with no reported figure is unknown."* So **an unknown is a `spend` row whose `cost_usd` is null**. Two sources write those rows today:

- **Codex, always.** `packages/agent/src/codex.ts:24`: *"no dollars, so `costUsd` is `null` — never `0`"*. The same is true at `:1156`, `:1304`, `:1347` and `:1422`, and in `codex-text.ts:44` and `:151`.
- **Claude Code, when it is killed or crashes**: timeout or abort at `claude-code.ts:558`, spawn error at `:608`, and also when the result has no `total_cost_usd` (`:363`, `:624`). A killed run used tokens, so its cost is unknown. It is not free.

Two consequences follow, and every surface has to show both:

- A ceiling over a Codex-only day can never trip.
- A day with timeouts in it is undercounted.

To settle what *"+ 25 unknown"* on #603 consists of, query `RunSpent` events with `data.costUsd = null` and group by `data.runtime`. I cannot read the log, so that query is the evidence, not this note.

There is a third kind of unknown: a process that died before it appended `RunSpent` leaves no row at all. 0122 §5 counts rows only, so this ticket does not chase that case. Note it in the code comment.

## 2. The figure: `limits.day_usd` in `config.yml`, not `runtime.limits.day_usd`

0117 and 0122 put the figure in `config.yml`. `runtime.limits` is the **recipe's** path (`packages/recipe/src/recipe.ts:277`, `:2913`). A machine-wide value under the same path in a different file is the trap CLAUDE.md describes for `.lingtai/config.yaml`: somebody pastes it where nothing reads it. So:

- The key is `limits.day_usd` in `config.yml`, read as `LINGTAI_LIMITS_DAY_USD` from the environment.
- Add it to `config.example.yml` with a sentence explaining that unknown costs are not counted in it.

The reader is a new `machineDayCeiling(from, file)` in `packages/env/src/index.ts`. Copy `machineBoardPort` (`:820-845`):

- The environment value overrides the file.
- The file is read on every call, so a raised figure is seen without a restart.
- A value that is not a positive number is **refused by name**, not ignored.

Return dollars or `undefined`.

**If the figure cannot be read, the conductor takes no work.** It returns a sentence and appends no pause. This follows the existing rule that *"a pause that could not be read is not consent"* (`apps/cli/src/lingtai.ts:572`, `run.ts:164-172`). The same applies when the `spend` read throws.

## 3. One module in `@lingtai/conductor`, and every surface reads it

Create `packages/conductor/src/day-ceiling.ts`. The conductor, the CLI and the board all depend on `@lingtai/conductor` (`apps/board/package.json:16`). The board's `billOf` and `billText` live in `apps/board` and cannot be imported by the CLI. Do not write a third copy beside the board's and `apps/site/src/lib/snapshot.ts:190`.

**Pure functions**, all unit-testable:

- `startOfLocalDay(now)` and `nextLocalMidnight(now)`. Build them with the local `Date(y, m, d)` constructor, so they are correct across DST and in any `TZ`.
- `daySpend(rows: readonly { at: Date; costUsd: number | null }[], now)` returns `{ reportedCents, reportedRuns, unknown }`.
  - Keep only rows with `at >= startOfLocalDay(now)`.
  - Round each row to cents once, as `billOf` does (`apps/board/src/lib/spend.ts:146`).
- `daySpendText(day, ceilingUsd | undefined)` is the **one sentence** every surface prints, for example `today $41.20 + 3 unknown of a $50.00 ceiling — unknown costs are not counted`.
  - It never prints `$0.00` for a day with unknown rows. That is `billText`'s rule (`spend.ts:175`).
  - It always prints the unknown count, including zero when a ceiling is set. *"+ 0 unknown"* is a claim; leaving the count out is not.
- `ceilingReached(day, ceilingUsd)` is true when `reportedCents >= round(ceilingUsd * 100)`. **Unknown rows count toward nothing.** They are named, never priced (0122 §5, 0110 §5-6).

**One effectful function**: `dayCeilingPause({ ceilingUsd, rows: (since: Date) => Promise<…>, store, now })` returns `string | null`.

- With no ceiling it returns `null`.
- Otherwise it reads today's rows through the injected reader. The live reader is `readSpend({ since })` (`packages/projector/src/spend.ts:233`; `since` is `at >= since`, `store.ts:228`). The board's reader is its own already-loaded rows.
- When `ceilingReached`, it appends `ConductorPaused` on `CONTROL_STREAM` with:
  - `by: 'lingtai'`
  - `until: nextLocalMidnight(now)`
  - `holdsAcrossStarts: false`
  - the `daySpendText` sentence as the reason
- It does this **once, never over a pause already holding**. That is `pauseConductorOnce`'s read-then-append-at-version (`packages/conductor/src/conduct.ts:866-888`). That function is a closure inside the pass generator, so lift its body into this module, or into a shared helper both places call. Do not write a second version that can drift from it.
- It returns the sentence.

## 4. Where it is asked: the existing `paused` callbacks, and nowhere inside a pass

There are two conductors, and both already hand `runQueue` a `paused` callback. `runQueue` asks it at the top of every turn, before offering or claiming anything (`packages/conductor/src/schedule.ts:158-166`):

- **Daemon:** `apps/cli/src/lingtai.ts:568-576`. This callback is asked before each project (`apps/cli/src/conduct.ts:497`) and before each ticket. Also add the check to the loop-level boolean `paused` at `lingtai.ts:525`, so the work loop (`packages/daemon/src/work-loop.ts:491`) does not start a look that would only stop at its first project.
- **`lingtai run`:** `stillPaused` at `apps/cli/src/run.ts:167`. It is passed in at `:502`.

In each case: if control is not paused, return `await dayCeilingPause(…)`. Nothing in `pass.ts` or `conduct.ts`'s pass body calls it. That is what *"never kill a pass in flight"* means here: a pass that is running is never asked.

The overshoot this allows is the one 0122 §5 already accepts and gives no figure for. There is one source of lag to name in the comment: the `spend` projection can trail a just-appended `RunSpent` by a few events. A pass that finishes and is followed immediately by the next claim may therefore be one row short. The next check catches it.

## 5. Lifting the pause: midnight, or `resume`, but the figure decides whether it comes back

- **Midnight** is already built. `reduceControl` treats a pause whose `until` has passed as lifted (`packages/domain/src/control.ts:130-135`, `:150`). The rows after midnight start a new day, so the next check finds nothing to pause on.
- **`lingtai resume`** appends `ConductorResumed`. That lifts the pause, which meets the ticket's *"`resume` … lift it"*. But **resume is not a waiver for the rest of the day.** The next check re-pauses if spend is still over the figure.

This keeps the ticket consistent with 0122 §7's table, *"Lifted by: Midnight, or a higher figure"*. Raising `limits.day_usd` and then running `resume` is the way to continue today. Running `resume` alone is a no-op one claim later.

When a ceiling pause is lifted while still over the figure, the resume command should say so in one line, for example `today's spend still exceeds limits.day_usd — the next claim will pause again`. Do not encode an override.

## 6. Surfaces: three of them, one sentence

- **`lingtai status`** (`apps/cli/src/status.ts`): one line from `daySpendText`. It reads `readSpend({ since })` across **all projects**, even under `--project`, because the ceiling covers the whole installation. With no ceiling set, it still prints today's figure and unknown count, followed by `no daily ceiling (limits.day_usd)`.
- **`lingtai doctor`** (`apps/cli/src/doctor.ts`): a new check named `spend: today`.
  - `ok`, with the sentence, in the ordinary case.
  - `warn` when a ceiling is set and today has unknown rows: `N of today's runs reported no cost — the ceiling cannot see them`. This is the #332 trap stated where an operator looks.
  - `fail` only when the figure is malformed.
- **Board bar** (`apps/board/src/app/page.tsx:640-660`, the reading that links to `/spend`):
  - Add no new chip. *"A chip is not free, and the row is the unit"* (`doc/design/the-bar.md:61`).
  - When a ceiling is set, add the sentence to the reading's `title`, and add a short `· today $41.20 + 3 unknown / $50` to its text.
  - When the ceiling has tripped, the existing pause chip already shows `by` and `reason`, and the reason is the sentence (#77).
  - `/spend` shows the full line unconditionally.
  - Compute it from **every project's** rows, not the project-filtered `spend` that `loadBoard(only)` returns.

## 7. Tests (unit only; all of this sits on `createMemoryEventStore` and injected rows and clock)

Use `packages/conductor/unit/day-ceiling.test.ts`. Model it on `schedule-pause.test.ts` and `never-started.test.ts`.

- `daySpend`:
  - excludes yesterday's rows;
  - counts null as unknown and never as `0`;
  - rounds per row.
- `daySpendText` never says `$0.00` when unknown > 0, and names the unknown count when a ceiling is set.
- `dayCeilingPause`:
  - Under the figure, it returns null and appends nothing.
  - At the figure, it appends exactly one `ConductorPaused`. Its `reason` contains the figure and today's spend, and its `until` equals `nextLocalMidnight(now)`.
  - A second call appends nothing.
  - Over an existing person's pause, it appends nothing.
- **Before the claim, not during:** pass `runQueue` a `paused` that is `dayCeilingPause` over rows already past the ceiling. As in `schedule-pause.test.ts`, every port is a throwing proxy, so the assertion is that nothing was offered or claimed.
- **Lifts:**
  - `reduceControl(events, afterMidnight).paused === false`, and a check at that `now` with yesterday's rows appends nothing.
  - After `ConductorResumed`, a check with a raised figure appends nothing.
  - After `ConductorResumed`, a check with the same figure re-pauses.
- `machineDayCeiling` refuses `0`, a negative number and `abc` by name. Pass the file text through `machineFileFrom(path, text)` (`packages/env/src/index.ts:147`) so that no filesystem is touched.

The end-to-end claim, *"the live daemon paused at the figure"*, can only be checked on the log after a real day: a `ConductorPaused` on `ctl-conductor` whose `by` is `lingtai` and whose `reason` starts with the sentence, with no `TicketClaimed` after it until `until`. No integration test is needed for this ticket. The unit tests above stand in for it.
