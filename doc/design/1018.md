# Design: #1018 — the trial is the hard part

The ticket already settles detection, the runtime probe, the faces and the ratchet rows; follow it there. This note covers the trial in `trial-build.ts`. Its shape is not obvious, because what the `finally` does today will not fit inside an `acquireUseRelease` release unchanged.

## 1. The resource is the `runId`, not the worktree

`deps.remove` runs today even when `deps.provision` threw. The `try` that owns the `finally` opens at `trial-build.ts:168`, before provisioning at `:173`, so a half-cut checkout is still removed. If `provision` became the `acquire`, a provision failure would skip the release and change that.

So the shape is:

- **acquire:** `Effect.sync(() => deps.runId())`.
- **use(runId):** cut the worktree, then run the commands. It returns `{ results, interrupted }`, a value only.
- **release(runId):** `deps.remove` through `Effect.tryPromise`. Its failure is caught into a `Ref<string | null>` (`leftBehind`) made before the `acquireUseRelease`. The release's own error type must be `never`, because `acquireUseRelease` adds the release's error to the result's error channel (`node_modules/.pnpm/effect@4.1.2/node_modules/effect/src/internal/effect.ts:4475-4487`). That is how "a release failure never becomes the trial's error" is enforced by the type rather than by care.
- **After the bracket**, in this order, matching `:230-244`:
  1. Read the `Ref`.
  2. If `interrupted`, fail with `TrialInterrupted`.
  3. Otherwise, if `leftBehind` is set, append the `cleanup` result.

**Where the two "remove it by hand" log lines go (`:231-232`).** Write them inside the release, not after the bracket. Today they are skipped when `deps.run` throws: the throw leaves before `:230`. The checkout still holds a planted env file in that case, and in the fiber-interruption case too, so the warning belongs on every exit. This is the only line of output that changes, and it changes only on a path that was already a bug. No test asserts the log on a throw; add the case to the runner-throw test.

## 2. Ctrl+C is not fiber interruption, and the two stay apart

`at.interrupt` is an `AbortSignal` that the use body reads, exactly as at `:191`, `:199` and `:212`. `runCommand` resolves on abort (`packages/actions/src/command.ts:234-236`), so the commands stay sequential: the process group is dead before `remove` runs.

`TrialInterrupted` is a failure raised after the bracket. It is never raised by interrupting the fiber. Write it as:

```ts
class TrialInterrupted extends Data.TaggedError('TrialInterrupted') {
  override get message() { return 'the trial run was interrupted' }
}
```

Passing the message as a field does not work here, because the class takes no fields. `setup-build.ts:339` matches on `name`, and the refusal text it prints at `:340` is its own, so the message is kept only so the rejection says something.

Fiber interruption (no host does it today) has a property the ticket's edge does not mention. `Effect.promise`'s finalizer aborts the signal and resumes at once, without waiting for the promise (`effect.ts:1222-1228`, `asyncFinalizer` → `controller?.abort()`). So on fiber interruption, `remove` can start while the killed process group is still exiting. Accept that and do not await the runner. If a host ever interrupts the fiber, that is the place to make the run wait for its own kill. Say so in a comment at the `Effect.promise`.

## 3. The provision is uninterruptible

Wrap `deps.provision` as `Effect.uninterruptible(Effect.tryPromise(...))`, with its rejection mapped to the `git` value as at `:188-195`.

Without this, fiber interruption during the clone resolves the `tryPromise` at once and runs `remove` against a worktree that `git` is still writing. The clone would then finish after the removal and leave the planted env file behind, which is exactly what the file header says never happens (`:7-8`). Ctrl+C is unaffected: it reaches `git` through the process group, not through the fiber (`:189`), and `provision` takes no signal (`ProvisionOptions`).

## 4. Faces and shape

- **`trialBase(at)`:** `return Effect.runPromise(trialBaseEffect(at))`.
- **`runLiveTrial(at, install, build)`:** `return Effect.runPromise(liveTrialEffect(at, install, build))`.
- Each face must be `export function` or `export const … = (…) =>`, with a body of exactly one statement. `face()` refuses anything else by name (`packages/domain/unit/effect-ratchet.test.ts:197,208`). That includes a `.then`, a destructure, or a `try`.
- **`liveTrialEffect`:**
  - It is `Effect.scoped` over `Effect.acquireRelease(Effect.sync(() => { process.once('SIGINT', onSigint) }), () => Effect.sync(() => process.off('SIGINT', onSigint)))`, then `runTrialEffect`.
  - The `AbortController` is made inside the `Effect.gen`, so each run gets its own.
  - `once` plus `off` is today's pairing (`:262,269`). Keep both: after a Ctrl+C, `off` is a no-op, which is what the `SIGINT` listener-count test relies on.
- **`liveTrialBuild`** returns `{ base: () => trialBase(at), run: (i, b) => runLiveTrial(at, i, b) }`. It has no `async` and no run, so it is not counted.

## 5. Detection: one helper, two error policies

Use one `read` helper and one `has` helper over `Effect.tryPromise({ try, catch: (e) => new SetupFailed({ operation: 'detect', message: e instanceof Error ? e.message : String(e), cause: e }) })`. The `String(e)` matches `reasonOf` (`propose-setup.ts:96`).

- **The places that catch today** recover with `Effect.catch` to the same value and note they produce now.
- **The two bare reads** (`detect-setup.ts:179,442`) let `SetupFailed` through.

Keeping both policies on one helper means the error type of each detector's `Effect` shows the bare reads: `StackDetector.detect` is `Effect<StackFinding, SetupFailed>`, not `Effect<StackFinding>`. That is honest, and the test stub at `detect-setup.test.ts:170-179` returns `Effect.succeed(…)`, which fits either.

## Checks

The ratchet test is unit-level, so `pnpm test` covers the faces, the baseline and every new test listed under *Done when*. Nothing in this shape needs `pnpm test:integration`. No ADR is contradicted.
