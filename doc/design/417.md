# Design: #417, the record as five tabs

## Where it goes

| File | Change |
|---|---|

## The diff has to leave `Evidence`, not just move with it

Today the diff is not a component the page renders. It is the tail of `Evidence` (`evidence.tsx:147-166`), which holds `diff`/`diffError` in its own state and calls the `loadDiff` server action (`actions.ts:653`). It renders only where a run has steps, because the findings row filters `run.steps.length > 0` (`page.tsx:541`). If `Evidence` simply moved, the Diff tab would contain the findings too.

So split the file:

- `Evidence({ steps })` keeps only the per-step disclosures. It drops `project`, `baseSha` and `headSha`.
- `RunDiff({ project, baseSha, headSha })` takes the button, the error and `DiffView`.

`evidence.tsx` is already a client module, and its only non-React imports are a type from `@/lib/diff` and the action. That is the graph the Next build has passed until now, so the split adds no new import edge for #230 to catch.

The Diff tab lists each attempt newest first, under `Of`, as the other rows do. For each attempt it shows the files list from today's *files* row (`page.tsx:559-579`) and then that attempt's `RunDiff`. The files list is the head of the tab and is always visible. The diff stays behind its button, because it costs a `git diff` against the mirror and a page re-renders on every append.

Offer `RunDiff` only where `baseSha` and `headSha` are both non-null. Today's `headSha={run.headSha ?? ''}` (`page.tsx:552`) asks git for `base...` against an empty head. It never mattered, because a run with steps had proposed something. In the Diff tab, a run that proposed nothing gets its files line or the empty sentence, and no button.

## The tab component takes server-rendered panels

`Record` stays a server component and builds the five panels as it builds the rows now. It passes them as `tabs: { name, fact, panel: ReactNode }[]` to the client component, so the component holds no data, only which tab is selected.

**Every panel renders on the server, and the ones not selected carry `hidden`.** Mount only the selected one and two things break:

- `renderToStaticMarkup` in `task-page.test.tsx` would lose everything the record tests read. For example, `:218` expects `fix-and-rec…` and `:439-448` expects the rail segments.
- `document.getElementById('attempt-2')` would return null while Attempts is not selected.

Every task opens on **History**, the first tab, whatever its state. #152 states the rule in the comment at `page.tsx:460-462`: *"Always these four, always this order, whatever the state … a shape that is the same every time is learned once."* The count changes to five; the rule does not. Do not pick the opening tab by state.

Keep each tab's one fact beside its name in a smaller face, as `rfact` did (`page.tsx:486-490`). The facts are already computed (`:513-516`, `totalsFact`). History's fact is `events` and moves out of the `rof` line at `:606`. Keep the `rname` class on the label so that `arrangement` (`task-page.test.tsx:181`) still reads the names.

Each panel carries `role="tabpanel"`, `id="record-<name>"` and `data-tab="<name>"`. Each tab is a `<button role="tab" aria-selected aria-controls>`.

## The hash: Reveal can no longer get there alone

`#attempt-N` comes from `standing.tsx:598` and `:685`, and from links already posted outside the board. `Reveal` (`latch.tsx:123-149`) gets there by `openTo`, which opens every closed `<details>` above the target. In the new shape the attempt `Latch` (`page.tsx:177`) has no closed ancestor, so `openTo` returns 0. If the panel is `hidden`, `scrollIntoView` does nothing. The link would do nothing, silently.

The tab component follows the hash, and follows it the way `Reveal` does:

- on mount
- on `hashchange`
- on a click of any `a[href^="#"]`, because a link to the hash already in the address bar fires neither event (`latch.tsx:116-117`)

Find the target with `getElementById(fragmentId(hash))`, take its `closest('[role="tabpanel"]')`, select that panel's tab, and keep the target id in a ref. A `useEffect` on the selected tab scrolls to that id once the panel is visible, then clears the ref. If the target is a panel itself, `#record-diff` selects that tab.

Write the panel lookup as a structural pure function beside `openTo`, for example `panelOf(target: { closest(sel): { dataset } | null }): string | null`, and test it in `reveal.test.tsx` without a document, as `openTo` is.

Leave `Reveal` in place. It still opens the attempt's own `<details>` path and anything nested in a panel, and its scroll on a hidden target is harmless. Change the comments that describe the old shape: `page.tsx:698-699` (*"points into the record's closed attempts row"*) and `latch.tsx:81-83`.

Do not use `flushSync` to make one listener do both jobs. The first reveal runs inside an effect, and React warns about `flushSync` called from a lifecycle method.

Selection is React state and survives `router.refresh()` (`live.tsx:130`), so a re-render on an append does not jump the reader back to History. Use the rule from `latch.tsx`: only the reader and the hash move it.

## The test, changed on purpose

Replace the test at `task-page.test.tsx:452-496`. It should assert, in the four states it already builds:

- the tab names, read from `role="tab"`, equal `[...RECORD_TABS]`;
- `RECORD_TABS` is `['history', 'diff', 'findings', 'attempts', 'ticket']`, written out literally as `:494` does now;
- exactly one tab has `aria-selected="true"`, and it is `history`;
- every one of the five `role="tabpanel"` elements is in the markup, so the server renders all five.

Keep the reason in the comment at `:489-493` for `ticket` rather than `prompt`. Add the reason for the new order: 0118 §2, *"The record is History, Diff, Findings, Attempts and Ticket, as tabs"* (`doc/decisions/0118-a-hold-explains-itself.md:136`).

The `arrangement` snapshots (`:198` and the others) change on their `record:` line. Update them with `-u` and read the snapshot diff: anything beyond that one line is a regression, not churn.

The scroll for `#attempt-2` cannot be checked in unit tests, because there is no DOM there. What stands in for it is `panelOf` on an attempt nested in the Attempts panel returning `'attempts'`, plus the SSR assertion that `id="attempt-2"` is inside the panel with `data-tab="attempts"`.

The Next build at `apps/release/integration/build.test.ts` is the only thing that would catch a server-only import in `record-tabs.tsx`, and it runs after the merge. Keep the import list to `react` and `./latch.tsx`, and the risk stays where it is today.
