# Design note for #936: two tests for the queued panel

The two tests go in different files. The ordered render goes in `queued.detail.test.tsx`, as the ticket asks. The approved-page test cannot go there and still check anything, for the reason under §2. Both are tests only; neither needs a change to the component.

## 1. The *1st of 2* ordered render goes in `apps/board/unit/queued.detail.test.tsx`

Put it in `describe('the queued panel', …)` (line 448) and use that block's `panel()` helper (`:450`). It renders `<Standing>` with `NEVER_RUN` and `FLIGHT`. For the view, use `{ ...QUEUED, position: 1, inLine: 2 }` (`QUEUED` is at `:49`).

**Get every expected string from the code, not from a copy.** The ticket says the words come from "the pure function #911 added". For the label, that function does not exist. The label is an inline ternary in the component, at `apps/board/src/app/standing.tsx:127`:

```tsx
<span className="fk">{view.position === 1 ? 'why first' : 'why here'}</span>
```

The other strings do have exported pure functions in `apps/board/src/lib/queued.ts`, so import and call them:

- the chip: `queuedChip(view, FLIGHT)` (`:435`), which gives `"1st of 2"`
- the sentence: `queuedSentence(view, FLIGHT)` (`:445`)

**Decision: lift the label into a pure function.** Add `whyLabel(position: number): string` to `queued.ts` next to `place()` (`:398`). Call it from `standing.tsx:127`, and call it from the test, with `whyLabel(1)` as the expected label. This is the only change to the component. It changes no output, so the commit says it is a refactor that lets the test use the panel's own words, not a fix.

Without the function, the test would have to write `'why first'` itself, which is what the ticket's Watch out forbids. A test-only alternative would be to compare the first fact's label with a render at `position: 4` and assert they differ. That proves the label changes but not which word is used, so it is weaker.

**Assert the order with `html.indexOf`, the same way the existing test does at `:470–475`.** The existing test checks `In line` against `triage-band` and *Nothing is needed* against the sentence. It never checks *Nothing is needed* against the facts, and that is the hole #911 left. The new chain, with each item after the previous one:

1. `triage-band`
2. `In line`
3. `cause-chip--queue">${queuedChip(…)}</p>`, the exact chip markup as at `:473`
4. `triage-summary"`, then the `queuedSentence(…)` text
5. `Nothing is needed from you`
6. the first `class="fact"`
7. then the label: `<span class="fk">${whyLabel(1)}</span>` comes right after the first `class="fact"`

Keep `toHaveLength(3)` on `class="fact"` (as at `:476`). Also find the second and third `fact` with `indexOf(…, from)`, so all three come after *Nothing is needed*.

**Watch for this:** `triage-summary` appears both as a class and inside the sentence's container. Match `triage-summary"` with the closing quote so the match is the class attribute.

A position-1 sentence depends on `inFlight` (`queued.ts:450–453`). `FLIGHT` has one running and `slots: 1`, so the sentence comes from the full-slots branch. Pass the same `FLIGHT` to `queuedSentence` and the expected text follows the render whichever branch it takes.

If any step of the chain fails, reorder the JSX in `QueuedBand` (`standing.tsx:81–175`) and say so in the commit. Do not change the assertion.

## 2. The approved-page class test goes in `apps/board/unit/task-page.test.tsx`

`<Standing>` never draws the page class. `detailClass` is applied in one place only, on `<main>` in `TaskBody`, at `apps/board/src/app/task/[id]/layout.tsx:147`:

```tsx
<main className={detailClass(task.standing.state, Boolean(task.standing.afterMove))}>
```

So if you render an approved `<Standing>` in `queued.detail.test.tsx` and assert it has neither class, the test passes even if `detailClass` were wrong. It would assert nothing.

`task-page.test.tsx` already renders `TaskBody` through its `page()` helper (`:237`), with `Deferred` mocked (`:30–48`). The test file already asserts the page class through that helper: `detail--resolved` at `:265`.

Write one `it` that makes two renders with the `task()` builder (`:123`, whose `rest` accepts `standing`):

- **Positive control:** a queued standing, asserting `<main class="detail detail--framed detail--queued"`. This shows the class is drawn at all.
- **The check:** the same task with `state: 'approved'`, asserting the page has neither `detail--queued` nor `detail--running`, and that the `<main` class is exactly `detail detail--framed`.

The pure check at `queued.detail.test.tsx:514–518` stays as it is. The new test covers the render, which is what #911's Done-when asked for.

The ticket's Fix names a single file. Its Done-when asks only that both tests be in `apps/board/unit/`, which this placement meets. Say in the commit why the second test is in `task-page.test.tsx`.
