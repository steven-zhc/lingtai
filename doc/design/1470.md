# #1470 — the shape

## Where it goes

- **`docImageSrc(pathUnderDoc, exists?)`** goes in `apps/site/src/lib/docs.ts`, right after `resolveHref` (`docs.ts:490-506`). `DOC_IMAGES_BASE` goes beside `GITHUB_BLOB` (`docs.ts:46`).
  - `exists` defaults to a check against `path.join(docRoot, pathUnderDoc)`. Tests pass their own.
  - Use `existsSync`, which the module already imports (`docs.ts:1`) and calls in `filesOf` (`docs.ts:359`). Keep the function synchronous, so it adds no `async` and no `Effect.run*`, and `effect-ratchet.baseline.json` cannot move.
  - Wrap the call to `exists` in `try`/`catch` and treat a throw as *absent*. That is the ticket's "an `exists` that throws → the R2 URL". `existsSync` itself never throws, so the catch is only there for the injected one.
- **The caller works out the path under `doc/`. `docImageSrc` does not.** `document.tsx:238` already does it:
  ```ts
  const under = path.posix.normalize(path.posix.join(path.posix.dirname(source), written))
  ```
  Leave that line where it is. Then:
  - an absolute URL (`/^[a-z]+:/i`, the same test as `document.tsx:239`), or an `under` starting with `../`, keeps going through `resolveHref(source, written, isPublished)`. That covers the ticket's "absolute URL" and "climbs out of `doc/`" edges without `docImageSrc` having to know about them.
  - everything else goes to `docImageSrc(under)`.
- **Inside `docImageSrc`, when the file is present** (or the path is `.svg`), it returns what `resolveHref('README.md', pathUnderDoc, () => false)` returns, which is `${GITHUB_BLOB}doc/<path>` (`docs.ts:505`). `README.md` makes `fromDir` `.`, so the path is read relative to `doc/` (`docs.ts:495`). `/img/docs/…` is decided by the `imageType` rule below.

## The decision the ticket does not make: when a present file gets `/img/docs/`

Today, any image whose path starts with `img/` gets `/img/docs/<rest>` (`document.tsx:239-240`). But the route only serves what `imageType` accepts (`route.ts:23`, `:29`). From `apps/site/src/lib/doc-images.ts`:

> "A name with a separator, a `..`, a capital or any other extension has no type, so the route neither exports nor serves it."

That rule is `/^[a-z0-9-]+\.(svg|png)$/`. Two kinds of file in `doc/img/` today fall outside it:
- `doc/img/film-poster.jpg`, which is a `.jpg`;
- `doc/img/016/*.png`, which sit in a subdirectory.

Under today's rule, a document that showed one of them would point at a route that 404s.

**Decision:** `/img/docs/<rest>` only when `pathUnderDoc` starts with `img/` **and** `imageType(rest) !== null`. That is exactly the set the route exports.
- A present file under `img/` that the route cannot serve gets the GitHub link, the same as a present file anywhere else.
- The ticket's own edge says the page must never point "at a route that would 404". This holds it to that.
- No document embeds one of those files today: `img/016/` is only ever named in prose, and `film-poster.jpg` is `/img/film-poster.jpg` from `public/` (`film.tsx:48`). So no page you can see today changes.
- `.svg` skips the `exists` check completely. It goes through the same two branches (`/img/docs/` when `imageType` accepts it, otherwise GitHub), so it comes out identical whether the file is present or not. The ticket's test asks for exactly that.

Raster extensions are matched case-sensitively: `/\.(png|jpe?g|gif|webp)$/`. Any other extension is not a raster image: it skips `exists` and gets today's `src`.

## The home page: `SHOTS` has to leave the client module

`page.tsx` has to build the screenshots' `src` and `href` from `SHOTS`. But `SHOTS` is exported from `shots.tsx`, which starts with `'use client'` (`shots.tsx:1`, `:6`).
- In the Next build, a value a server component imports from a client module is a client reference, not the array. Calling `.map` on it from `page.tsx` fails at build or render time.
- vitest does not apply that boundary. `unit/page.test.tsx` imports `SHOTS` directly and would pass anyway.

**So move `SHOTS` into a plain module** with no directive and no `node:` import, for example `apps/site/src/app/shots-list.ts`.
- `shots.tsx`, `page.tsx` and `page.test.tsx` all import it from there.
- `page.tsx` maps it to `{ ...shot, src: docImageSrc(\`img/shot-${name}.png\`), full: docImageSrc(\`img/shot-${name}-full.png\`) }` and passes the result as `<Shots shots={…} />`.
- `shots.tsx` deletes its `src` helper (`shots.tsx:13`). It reads all three uses (the panel's `href`, the panel's `<img>`, and the lightbox `<img>` at `shots.tsx:91`) from the prop, and still imports nothing from `@/lib/docs`.
  - `docs.ts` imports `node:fs` (`docs.ts:1-2`). If `shots.tsx` imported it, that would be the server-only import in a `"use client"` graph that, per CLAUDE.md, only `apps/release/integration/build.test.ts` sees. `tsc` does not.

This boundary can only be checked by the Next build. It is out of reach inside the pass and gets caught after the merge. **The unit-level stand-ins:**
- a test that reads `src/app/shots.tsx` as text and asserts it does not import `@/lib/docs` or `node:`;
- `page.test.tsx` importing `SHOTS` from the new module, which is not `'use client'`.

## Tests

- **`docImageSrc` cases go in `unit/docs.test.ts`,** beside the `resolveHref` cases at `:327-350`. Use a fake `exists`: no filesystem, so they are unit tests under 0060 §1. Cover the five cases the ticket lists, plus a present `img/016/x.png` → GitHub link, which pins the `imageType` decision.
- **`page.test.tsx:440-441`** should expect `href="${docImageSrc(\`img/shot-${s.name}-full.png\`)}"` and the matching `src`.
  - That calls the default `exists`, so it does touch disk. It is not new IO for this suite, though: `docs.ts` already runs `existsSync` when the module loads (`docs.ts:37`), and every unit test that imports it runs that.
  - Do not stub it to a fixed answer. The point is that the expected value follows whatever is on disk, so the test survives the next ticket deleting the files.
- **Document rendering:** one case in the existing document test that renders a doc embedding `img/tutorial-site.png` and asserts `src` equals `docImageSrc('img/tutorial-site.png')`. Same reasoning as above.

## Not touched

- `doc-images.ts` (only imported from)
- `next.config.ts`
- `resolveHref`'s own branches: links (`document.tsx:227`) keep calling it unchanged

No ADR is contradicted. The module comment at `docs.ts:5-17` ("a projection of `doc/`, and never a copy") still holds: the markdown is not edited, and only the `src` the projection chooses changes.
