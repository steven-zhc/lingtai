# Design: #1449, show each line of `claude setup-token` once

## Where it goes

The whole change goes in `apps/cli/src/claude-token.ts`, inside the `line` closure of `takeFromSetupToken` (`:73-76`). Today that closure does two things in order: it captures `for (const m of text.matchAll(TOKEN_RUN)) found.push(m[0])`, then it echoes with `world.log(maskTokens(text))`.

- **Leave the capture line exactly as it is.** It reads the raw line.
- **Change only the echo.** Instead of logging `maskTokens(text)`, pass the masked line through a new filter and log it only if the filter keeps it.
- **Keep the code that builds lines unchanged.** That is `onChunk` (`:77-82`) and the trailing `if (pending !== '') line(pending)` (`:84`). That code is why a token split across two chunks is never half-printed. The docblock at `:63-65` says so: *"Stdout is echoed a whole line at a time, masked, so a token split across two chunks is never printed half unmasked."*

Write the filter as a pure exported function next to `maskTokens` (`:33`). It takes the set of lines already shown and returns either the line to print or nothing. Create the set inside the `Effect.promise` closure, beside `found` and `pending` (`:71-72`), so each run starts with an empty set.

Nothing here is async, and there is no new `Effect.run*`. `effect-ratchet.baseline.json` therefore cannot move up. If it does, the change has gone wrong.

## The filter, step by step

1. **Mask** the raw line, as today.
2. **Remove control sequences.** Use `stripVTControlCharacters` from `node:util` (Node here is v26). Then delete any remaining C0 control character except `\t`, which includes stray `\r`. No package in this repo does this yet; a search for `stripVTControlCharacters|strip-ansi` in `apps` and `packages` found nothing. So import the Node built-in rather than adding a dependency.
3. **Mask again.** `maskTokens` is idempotent. The second pass covers the one way removing escapes could put a token back together: a token whose characters were separated by an escape sequence.

   This does not cover everything. If a cursor sequence sat *inside* a token, the first mask stopped at that sequence, so the characters after it survive as visible text. In that case capture also took a truncated token, which is a wrong token saved silently. That is a capture bug, not an echo bug, and it is out of scope here.

   The evidence says capture worked with 2.1.331 (*"The token was saved correctly"*). If that is ever in doubt, the check is whether the saved `claude.oauth_token` is the full 108-character run.
4. **Build the key used to spot repeats:**
   - Trim the line.
   - If any box-drawing character (U+2500–U+257F) is left, take the text after the last one, but only when that text is non-empty. If it is empty, remove every box-drawing character from the line instead and trim again.

     Use the fallback because a pure "text after the last box character" rule turns `│ Paste code here │` into an empty key. That would hide the paste prompt, which the ticket's Watch out row says must stay visible.
   - Remove one leading spinner glyph and the spaces after it. Use `[·✢✳✶✻✽*]`, plus `✦` if the fixture shows it. Do **not** include `✔`: it marks the success line, which should still show.
5. **Lines with an empty key are never echoed.** These are bare borders like `╭────╮` and blank lines. Dropping them does not conflict with the ticket's rule that the filter *"never drops an unfamiliar line"*: they carry no words, and every blank or border line after the first would be dropped as a repeat anyway.
6. **Drop the two advice lines,** matched on the key. Use `startsWith('Store this token securely')` and `includes('export CLAUDE_CODE_OAUTH_TOKEN')`. Keep the strings in a two-entry constant with a comment explaining that Lingtai has already saved the token.
7. **Drop any key already in the set.** Otherwise add the key to the set and print the stripped, masked line with trailing whitespace trimmed. Print the line itself, not its key: the key removes the `✔` and the leading indent.

## Decisions the ticket leaves open

- **Repeats are matched across the whole run, not only against the previous line.** The repeated welcome block is never next to its earlier copy; spinner frames sit between them. One consequence is that a real message Claude Code prints twice, such as the same error twice, is shown once. That is accepted.
- **The masked token line ` sk-ant-oat01-…(hidden)` and `Your OAuth token (valid for 1 year):` stay visible.** The ticket's Fix drops only the two named lines. These two tell the person a token exists without showing it. If the child prints two tokens, both mask to the same key, so the second line is hidden. Both are still captured, so `found.length > 1` (`:88`) still sends the person to the fallback.
- **The repeat rule changes only what is shown.** It never touches `found`, so a future Claude Code release that changes its wording can, at worst, show a repeat. It can never stop a token from being captured. That is the ticket's *"never what is captured"*, made true by the order of the code.

## The test

Add a new `it` in `apps/cli/unit/claude-token.test.ts` under `describe('claude setup-token spawner')`. Use the existing `world({ chunks })` helper (`:17-54`) and the existing `FAKE` token (`:13`). Do not change the existing cases; the Done-when list says they stay as they are.

Put the fixture in the test file as a constant built from the evidence:

- `\x1b[…` cursor and colour sequences around the lines;
- the welcome block seven times, one copy glued after `╰──╯`;
- the spinner frames `·`, `✢` and the others on `Finishing sign-in…`;
- the URL line, and `Paste code here if prompted`;
- the success, token, store, export and revoke lines;
- `FAKE` split across two chunks, as `:62` already does.

If the operator can supply real bytes, the safe capture is:

```sh
claude setup-token | sed -E 's/sk-ant-oat01-[A-Za-z0-9_-]+/TOKEN/g' | cat -v
```

Do not tee the raw stream to a file, because that writes the real token to disk. Real bytes would settle whether Ink sends `\r` or cursor-up sequences through a pipe. Nobody has recorded that (the ticket's *"Nobody had recorded what a real run prints"*), and step 2 is written to cope with either.

The test should assert each item in the Done-when list:

- the welcome line is echoed once;
- the URL is echoed once;
- *Paste code here if prompted* is echoed once;
- nothing matches `/export CLAUDE_CODE_OAUTH_TOKEN|Store this token securely/`;
- the saved file contains `FAKE`;
- no line in `logs` matches `/sk-ant-oat01-(?!…\(hidden\))/`.

Also add one small direct test of the exported filter: a stray `\r` and an escape sequence placed between token characters. This pins the mask–strip–mask order from step 3.

Everything above is checked by `pnpm test`. No part of this change depends on `pnpm test:integration`. Nothing here contradicts an accepted ADR. 0127 (`doc/decisions/0127-what-an-agent-can-reach.md:60-62`) decides only that the person runs `claude setup-token` *"once"* and that Lingtai reads the token *"as a redacted value"*. It says nothing about what is echoed.
