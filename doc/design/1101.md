# Design note for #1101: the rest of doctor's checks become Effects

## The figure to aim at

On this base, `packages/domain/unit/effect-ratchet.baseline.json:2` reads `"apps/cli": { "async": 232, "run": 6 }`. That is not the 193 the ticket assumed, because CLI-10 and CLI-11 have not landed under you. Per the order note, the target is whatever that line reads when you start, minus 20.

The 20 are the hits `rg -n 'async\b' apps/cli/src/doctor.ts` shows at `:1572, 1664, 1678, 1707, 1790, 1814, 1863, 1891, 1949, 1978, 2018, 2074, 2203, 2237, 2294, 2314, 2346, 2817, 2920, 3113`. The hit at `:2281` is inside a comment (`// Not a thenable: an \`async\` function…`), and the ratchet does not count comments (`effect-ratchet.test.ts:340`, *does not count an async in a comment or a string*). Leave that comment alone. Lower the baseline only to the figure the ratchet itself reports after your change.

## Effect-shaped seams come from `filter.ts`'s `…Effect` types, not from `ClientFor`

`ClientFor` and `RecipeFor` are still promise types (`packages/conductor/src/filter.ts:210`, `:225`). #1068 added the Effect forms beside them under other names: `ClientForEffect` (`:213`) and `RecipeForEffect` (`:228`). Do not edit `filter.ts`.

- `recipeClientFor(env)` changes its return type from `ClientFor` to `ClientForEffect`. It answers `(s) => githubClientForEffect(s)` (`filter.ts:260`) or `() => Effect.succeed(offlineClient)`.
- `DoctorReach.recipe` becomes `RecipeForEffect`, with `currentRecipeEffect` (`projects.ts:201`) as the default at `:2938` and `:3132`.
- `projectFiltersOnce` calls `projectFiltersEffect` (`filter.ts:460`). That function already takes `ClientForEffect`.
- `integration/doctor-recipe.test.ts:51-115` calls the promise face `projectFilter(state, recipeClientFor({}))`, and that face takes `ClientFor` (`filter.ts:449-451`), so the call stops typechecking.
  - Rewrite those calls as `Effect.runPromise(projectFilterEffect(state, recipeClientFor({})))`, using `filter.ts:378`.
  - `apps/cli/tsconfig.json` includes `integration`, so `pnpm typecheck` checks this rewrite before the merge, even though the test itself runs only after it.

## Lifting a promise without changing what a row says

This is the trap the ticket does not name. Today each row's catch writes `err.message` into its detail. `Effect.tryPromise(() => p)` with no `catch` wraps the rejection in `UnknownException`, whose message is generic. A failing read would then still give the same status, but the detail would change, and the pinned tests compare details.

- Every lift of a promise this ticket does not own uses `Effect.tryPromise({ try, catch: asFailure })`. Those promises are `LogQueries`' methods, `SnapshotStore.census`, `Runtime.checkAuth`, `conductorLockHolder`, `agentEnvFor`, `readDaySpend`, and `signedInHere` (a `SignedIn` from `@lingtai/recipe`, `projects.ts:24`).
  - `asFailure` is already exported from `packages/conductor/src/port-face.ts`, and `filter.ts:236` uses it for the same purpose.
  - You may write the identity `catch: (e) => e` instead.
  - Use `Effect.promise` only where today's code lets a rejection escape.
- Each row's catch becomes `Effect.catchCause`.
  - It lets an interrupt-only cause through: `Cause.isInterruptedOnly` (or the effect-4 equivalent) leads to `Effect.failCause(cause)`.
  - Every other cause becomes the same message today's `catch` produced, taken from `Cause.squash(cause)`, with an `Error`'s `.message` read the same way as now.
  - This covers typed failures such as `RepoFailed` from `gitEffect` and `Error` from `RecipeForEffect`, and it covers defects.

The unit fakes at `unit/doctor.test.ts:81-107` (`async () => null`, …) become `() => Effect.succeed(…)`. Those files are not counted. Make no other change to them.

## Rows with their own rules

- **`isBehind(sha, here, run = gitEffect)`.** It is exported for the new test.
  - The early `false` for a missing or equal sha stays where it is (`:1708`).
  - The call is `run(['merge-base', '--is-ancestor', sha, here], { cwd: codeRoot() })`, followed by `Effect.as(true)`.
  - Every non-interrupt cause becomes `false`, which is the effect of the bare `catch` at `:1712`.
  - The new unit test takes three fakes: `Effect.fail(…)`, `Effect.die(…)` and `Effect.succeed('')`. It spawns no `git`.
- **`spendToday(read, control, now)`.**
  - `control` becomes `() => Effect<ControlState, unknown>`. Its default is `Effect.fail(new Error('the control stream was not offered'))`, keeping the exact words from `:2077`.
  - Read `control` with `Effect.exit`.
    - An interrupt is re-raised.
    - Any other failure sets `unread` from the squashed cause, as `:2085-2089` does now.
    - The control failure never becomes the row's `fail`.
  - `runDoctor`'s call (`:3565`) passes `readControlEffect(…)` (`control.ts:117`) in place of the promise read.
- **`passRefusals`.** The per-project `Promise.all` arrow (`:1678`) becomes `Effect.forEach(refusing, …, { concurrency: 'unbounded' })`. That keeps the reads parallel and the results in order, as `Promise.all` did.
