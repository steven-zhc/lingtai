Design for #677

**The shape.** Split it in two:
- **The formatters take an option.** `daySpendText` and `billText` each get an options argument, `{ fetchedNote?: boolean }`, which is off by default.
- **Callers that don't pass it change with no edit.** The status line, the pause reason, `doctor`, the cards, the waiting card and the task page all lose the note this way.

`fetchedNote` itself (`packages/conductor/src/day-ceiling.ts:101`) stays as it is and stays exported. It is the one place the words are written. Its doc comment, *"Said wherever an estimate is shown that part of it is not from the shipped card"*, becomes *"Said on `/spend` …"*.

**Decision 1: `readDayReading` has two strings, and only `text` takes the option.** The ticket names `text`. But `short` builds its own estimate with `fetchedNote(day)` too (`apps/board/src/lib/day-spend.ts:23`), and `short` is the main board's bar (`apps/board/src/app/page.tsx:674`). That page also puts `today.text` in the bar's title (`page.tsx:665`).
- `short` drops the note always, with no option. The bar is not `/spend`, and nothing on `/spend` reads `short`: `spend/page.tsx:66` renders `today.text` only.
- `readDayReading({ fetchedNote: true })` passes the option through to `daySpendText` for `text`.
- `page.tsx:585` keeps calling `readDayReading()` bare. That clears the note from both the bar and its title.

**Decision 2: `SpendTable` always passes the option, with no prop.** `apps/board/src/app/spend-table.tsx` is rendered only by `/spend`, so its four `billText` calls (`:42`, `:44`, `:57`, `:59`) pass `{ fetchedNote: true }` directly. A prop would be a switch nobody turns off.

**Decision 3: how the page's *today* line gets a unit test.** `readDayReading` calls `readSpend` (`day-spend.ts:22`), which is the database, so it cannot be a unit test (0060 §1). Move the pure part, from a `DaySpend` and a ceiling to `{ text, short }`, into an exported function in the same file, for example `dayReading(day, ceilingUsd, options)`. `readDayReading` becomes the read plus that call, and keeps its `try`/`catch`.

The unit test then checks two things:
- `dayReading` with `fetchedRuns > 0` and the option: `text` contains `(N at fetched LiteLLM prices)`.
- Without the option, `text` has no note. With or without it, `short` has no note.

For the table, extend `apps/board/unit/spend-table.test.tsx`. That file already renders `SpendTable` with `renderToStaticMarkup`.
- Today's `billOf` takes its pricer as an argument (`RateCard`, `apps/board/src/lib/spend.ts:129`). Use one that returns `{ usd, fetched: true }` for a costless row, then assert the markup has the note.
- Add the opposite case to `apps/board/unit/spend.test.ts`: `billText` on that same bill, called with no option, has no note.

One thing stays out of reach of the unit half: that `spend/page.tsx` really calls `readDayReading({ fetchedNote: true })`. The unit claim that covers it is `dayReading`'s test plus a one-line call site. Don't write an integration test for it.

**The figure does not move.** `daySpend` (`day-ceiling.ts:60-79`) still counts fetched runs into `estimatedCents` and `fetchedRuns`. `billOf` still counts them into `bill.estimates` and `bill.fetched` (`spend.ts:155`). `ceilingReached` (`:111`) still adds them in. No change touches any of these lines; only the strings the two formatters return change.

**The pause reason.** `dayCeilingPause` uses `daySpendText(day, options.ceilingUsd)` as the reason (`day-ceiling.ts:197`) and gets no option. `resumedPast` finds a ceiling pause by the prefix `CEILING_REASON = 'daily ceiling reached — '` (`:115`, `:126`), and that prefix is untouched. So a reason that was written with the note and one written without it are both still found.

**Tests already pinning the sentences.** Today none asserts the note: there are no `LiteLLM prices` hits under `apps/board/unit`, `packages/conductor/unit` or `apps/cli/unit`. The existing `daySpendText`/`billText` assertions (`packages/conductor/unit/day-ceiling.test.ts:64-79`, `apps/board/unit/spend.test.ts:140-182`) use fixtures where `fetchedRuns` is 0. They should stay green unchanged; if one goes red, that is a real regression.

**Docs.** In `doc/rate-card.md:147-148`, *"an estimate that used it says `(N at fetched LiteLLM prices)`"* becomes: the `/spend` page's *today* line and table say it, and every other estimate reads `~$X est.` with no note. Leave `doc/design/658.md` alone, since it records #658's design. No accepted ADR states where the note goes (a grep of `doc/` finds it only in those two files), so nothing needs a superseding ADR.
