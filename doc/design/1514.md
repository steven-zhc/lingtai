# #1514: shape of the change

The whole change is in three files and two test files. `LandedRow` in `apps/board/src/app/page.tsx` changes. So do the `/* --- landed` rules and the link opt-out rule in `apps/board/src/app/globals.css`. The tests are `apps/board/unit/landed.test.tsx` (new cases) and `apps/board/unit/close.test.tsx` (rewritten cases). No projection, reducer or lib function changes. `addBill` (`spend.ts:57`) and `billText` (`spend.ts:184`) are used as they are.

The ticket already settles the main layout. Three things are not obvious from it, and the obvious version of each one gets it wrong:

## 1. The row's link is underlined today, and `links.test.ts` decides how you remove that

`.lspend` is an `<a>`. The base rule `a, a:where(:visited) { … text-decoration: underline; … }` (`globals.css:157-162`) underlines it. `.lspend` only overrides the colour (`.lspend { color: inherit; display: block; }`, `globals.css:921`). So line 2 is underlined at rest now, which is what the ticket's *Links* rule forbids.

**Do not write `text-decoration: none` on `.lspend`.** The comment at `globals.css:153-156` says why: *"Those opt out in the one rule below, and unit/links.test.ts fails on `text-decoration: none` anywhere else."* The test *text-decoration: none is said in the opt-out rule and nowhere else* (`apps/board/unit/links.test.ts:50-58`) enforces it.

Instead:
- Add `.lspend` to the opt-out selector list at `globals.css:163-165`. `.lmeta` is already there.
- Add `.lspend` to `REQUIRED` in `links.test.ts:20-33`, so the row link cannot quietly come off that list.
- Leave `.lspend:hover` (`globals.css:922`) as it is.

## 2. "The turns are not drawn" means wrap-and-hide, not shrink-and-ellipsis

Today `.lturns` is `flex: 0 1000 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` (`globals.css:932`). That shrinks the turns to a fragment such as `21…`, which is a wrong number on the screen. The ticket wants the turns either drawn in full or not drawn at all, and the bill never wrapped or clipped.

Decision:
- **`.lbill`**: `display: flex; flex-wrap: wrap; justify-content: space-between;`, with a height of exactly one line (`height: 1lh`) and `overflow-x: visible; overflow-y: clip`. When the turns don't fit, they wrap onto a second flex line, and that line is clipped away.
  - `clip` is used instead of `hidden` because `hidden` forces the other axis to scroll and would cut off a bill wider than the column.
  - `1lh` replaces `min-height: 1em` (`globals.css:930`). An empty line 2 then has the same height as a full one, which is the Edges requirement. `1em` was shorter than a full line.
  - `lh` is a length unit, not a font size, so it does not break the "no literal font size" check.
- **The bill**: `flex: none; white-space: nowrap`.
- **`.lturns`**: `white-space: nowrap; margin-left: auto`, with the shrink and ellipsis removed.
  - `margin-left: auto` matters. When there is no bill, the turns are the only item, and `space-between` puts a single item at the *start*. The Edges section says the turns stay at the right.
- Remove the `.lwork, .lbill > .pill { … white-space: normal; overflow-wrap: anywhere; }` rule (`globals.css:931`). Keeping the `lwork` class name for the bill is fine.

Rewrite the comment at `globals.css:923-929` for the same reason as the `LandedRow` comment. It still says *"Turns shrink a thousand times faster than the Work figure and the answering pill … each wraps its own text inside its own box"*, which will be false after this change.

No unit test can check this rule, because the tests render static markup and never lay it out. The operator's 1440px check in *Done when* covers it. Don't write a test that tries to.

## 3. `close.test.tsx` holds the old shape and will go red

Three cases there assert the row behaviour this ticket removes:
- `close.test.tsx:152-174` (*is two lines … with the answering pill drawn by the shared component*): it expects `text2.startsWith(billText(work))` and that `answering` comes before `9 turns`.
- `close.test.tsx:176-195` (*draws the same answering pill on the card and on the row*): it expects `row` to equal `full`.
- `close.test.tsx:197-202`: it only checks that the text `answering` is absent. That stays true, but its name now describes something that no longer exists.

Rewrite them; don't delete them:
- Keep the card half of the second test (`full` is non-null, says `${billText(fix)} answering`, and leaves out the work figure). That is the *Done when* check that the waiting card keeps its pill.
- Change the row half to: no `class="pill`, and line 2 starts with `billText(addBill(work, fix))`.

Put the three *Done when* cases in `landed.test.tsx` as the ticket says. That file already imports from `../src/app/page.tsx` (`landed.test.tsx:10`). Build the card with `toCard(task(...))` as in `close.test.tsx:153`.

For the summed case, give both bills an estimate as well as a reported figure, for example work `{reportedCents: 10, reportedRuns: 1, estimates: [0.5]}` and answering `{reportedCents: 6, reportedRuns: 1, estimates: [0.25]}`. Then assert the text equals `billText(addBill(work, fix))`, i.e. `$0.16 + ~$0.75 est.`. A case with only reported money can't tell `addBill` apart from adding dollars by hand.
