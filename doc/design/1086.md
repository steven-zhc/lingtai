## add-from-page.ts: keep one client per proposal

The trap in the GitHub half is **memoisation**. `liveReaders` builds one client promise (`:129`) and `githubReader` builds one `refOf` (`:106`). Every `has`, `read` and `defaultBranch` the proposal makes then shares one installation lookup, one installation token and one `GET /repos/…` for the default branch. If each port member becomes `runPort(<effect that builds the client>)`, every member call repeats that lookup. A proposal reads many files, so that is many App round-trips per page render. No test would see it, because `proposalFor`'s tests hand in their own readers.

Shape:

- **Build a `GitHub`, not a `GitHubClient`.** `makeGitHub` is exported from `@lingtai/github` (`packages/github/src/index.ts`, `client.ts:541`). Its members are Effects that fail with `GitHubFailed` (`client.ts:190-193`), so `request`, `defaultBranch` and `fileAt` are yielded directly, with no promise to lift. Under `gh` pass `{ auth: { kind: 'gh' }, owner, repo }`. Otherwise pass `{ auth: githubApp(), owner, repo }`, and `makeGitHub` looks up the installation itself (`client.ts:553`). Call the local function `githubFor`, not `githubClientForEffect`. `filter.ts:260` already exports a `githubClientForEffect` with a different signature, and this package imports it elsewhere.
- **Memoise with `Effect.cached`** (`effect@4.1.2`, `Effect.d.ts:13539`: `Effect<A,E,R> → Effect<Effect<A,E,R>>`). Build `client = yield* Effect.cached(githubFor(...))` and `ref = yield* Effect.cached(Effect.flatMap(client, g => g.defaultBranch()))`. A cached failure stays cached, which is what the shared rejected promise does today, and it makes `client.catch(() => undefined)` (`:131`) unnecessary.
- **So `liveReaders` becomes an Effect**, `Effect<ProposalReaders, never>`, because `Effect.cached` has to be yielded and `liveReaders` is synchronous today. Its only caller is `proposalFor`'s default parameter (`:157`). Make `readers` optional and write `readers ? proposeSetup(target, readers) : Effect.flatMap(liveReaders(target), r => proposeSetup(target, r))`. The return type `Effect<Proposal, never>` doesn't change, and the board (`read/page.tsx:1`) calls `proposalFor(target)` unchanged. Nothing outside the file imports `liveReaders`.
- **Port members**: each one is `(…) => runPort(effect)`, built from `port-face.ts`'s `runPort` (`:10`). It rejects with the failure itself (`:4-6`), so `has` still rethrows a non-404 `GitHubFailed` as *could not tell* (`:111-116`). `read` maps every failure, the client's included, to `null` with `Effect.orElseSucceed`. `defaultBranch` fails with the client's own failure, as `client.then(...)` (`:134`) does today.
- **Disk half**: `diskReader.has`/`read` lift `stat`/`readFile` with `Effect.tryPromise` and `orElseSucceed(false/null)`. `origin` should be `gitIn(path, ['remote','get-url','origin'])` (`:60-67`), which already never fails, instead of `promisify(execFile)` (`:147`). That drops the `execFile`/`promisify` imports. Keep the `'' → null` and the failure → `null` behaviour. `readLocalTarget`'s `stat` (`:75`) becomes `Effect.tryPromise(() => stat(path)).pipe(Effect.match(...))`.
- `defaultBranch: () => Promise.resolve(LINGTAI_BASE)` and `origin: () => Promise.resolve(null)` do no IO, so they can stay.

## telemetry.ts

- **`installTracingEffect` never fails, and that is a behaviour change.** Today an SDK that won't load *rejects* `installTracing`, and `apps/cli/src/tracing.ts:24-30` turns that rejection into `installed = undefined`. After this change, `loadSdkEffect`'s failure and `machineOtlpEndpoint`'s throw (`:184-188`, lifted with `Effect.try`) both become `undefined` inside the Effect. apps/cli's rejection arm becomes dead, and it stays dead because that file is out of scope. Provider construction, `setGlobalTracerProvider` and `setGlobalContextManager` go in `Effect.sync`.
- **The face** is `export function installTracing(from, file?, exporter?) { return Effect.runPromise(installTracingEffect(from, file, exporter)) }`. It has exactly one statement, because the face check refuses any other body (`effect-ratchet.test.ts:205-218`). Add it to `effect-ratchet.faces.json` with `until: "#790"`, citing `apps/cli/src/tracing.ts:23` and the two conductor unit tests as its callers.
- **`httpAgentOptions`** (`:212-217`) is the third port the ticket doesn't name. The OTLP exporter types it as `HttpAgentFactory = (protocol) => Agent | Promise<Agent>` (`otlp-exporter-base/…/otlp-node-http-configuration.d.ts:6`). A sync `Agent` is allowed, so load `node:http` and `node:https` with dynamic `import()` in `loadSdkEffect`, next to the four SDK modules, and have the factory build the `Agent` synchronously. That removes the chain without a face. Keep them dynamic: the SDK's own doc says *"do not import `http.Agent` or `https.Agent` statically"* (`legacy-node-configuration.d.ts:32-33`). The text test (`trace-an-attempt.test.ts:42-46`) only matches the four SDK names, but a static `node:http` import is still wrong here.
- **`bounded` → `boundedEffect(flushing, ms, cancel)`**: `Effect.tryPromise(flushing).pipe(Effect.ignore, Effect.timeoutOption(ms))`, then on `None` run `Effect.sync(cancel)`. The timeout interrupts the fiber but not `forceFlush`'s promise. Only `cancel` destroys the sockets (`:153-156`), so it must run on the timeout branch. `flush` and `shutdown` are both `(ms = EXPORT_MS) => runPort(boundedEffect(...))`. The ticket names only `shutdown`, but `flush` is the same promise port (`:132-135`).
- `loadSdk` has no importer outside this file. `apps/board/unit/telemetry.test.ts:7` imports the board's own copy. So replace it with `loadSdkEffect` and don't export a promise version.

## Faces and the ratchet

`runPort` is already a listed face (`faces.json:255-258`). Its `why` names only `dbTickets`, so extend it to name `add-from-page.ts` and `telemetry.ts`. The only new entry is `installTracing`. Every other `Effect.run*` here goes through `runPort`, and the baseline's `packages/conductor: { async: 0, run: 0 }` (`baseline.json:9`) does not move.
