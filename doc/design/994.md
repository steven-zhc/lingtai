# Design: #994. The paused-project banner and the bar's Pause button

The ticket gives the shape and these notes do not repeat it. They record six places where today's tree differs from the ticket, and the decisions that follow from each. Line numbers are from this worktree. The ticket's numbers for `page.tsx` have drifted by about 8 lines.

## 1. `Bar` gets a slot for the button, not a read

`Bar` must stay pure. The file says it has *"no import but React and `next/link`, as `footer.tsx` is"* (`apps/board/src/app/bar.tsx:5-6`). #993 already left a marker where the button goes: `{/* A selected project's actions; Pause joins Recipe here. */}` (`bar.tsx:43`).

- Add one optional prop, `pause?: ReactNode`, to `Bar`. Render it inside `<span className="pacts">` after the `Recipe` link.
- Keep it inside the existing `project !== undefined && registered` branch (`bar.tsx:41`). That gives two edges for free:
  - with *all projects* selected, no button;
  - when `?project=` names an unregistered project, no button.
- The page decides what goes in the slot from `readProjectLocks()`:
  - **read ok**: `<PauseButton project={…} paused={locks.length > 0} />`;
  - **read failed**: `undefined`, because the banner's failure row already says why.
- `PauseButton` is a small `"use client"` file, for example `apps/board/src/app/pause-button.tsx`, that imports the two actions from `app/actions.ts`.
  - That import is legal in a client file. `client-graph.test.ts:76` stops walking at a `'use server'` file.
  - `actions.ts:1` is `'use server'`.
- **The `/recipe` page has two `Bar` call sites**, and both need the slot:
  - `recipe/[project]/page.tsx:201`, the bare `Bar`;
  - `recipe/[project]/recipe-bar.tsx:16`, through `RecipeBar`.
- `RecipeBar`'s header says *"Nothing here may import `app/actions` — only the form does."* (`recipe-bar.tsx:6-7`). So `RecipeBar` must not import `PauseButton`. It takes the `pause` node as a prop and passes it through, and `Recipe` (`page.tsx:195`) does the same. Whoever renders `Recipe` builds the node.

## 2. The board reads the registered projects more often than the ticket says, so the cache saves more

`/report` (`report/page.tsx:69`), `/landed` (`landed/page.tsx:41`) and the task layout (`task/[id]/layout.tsx:251`) already call `loadProjects().catch(() => [])` in order to compute `registered`. `/` does too (`page.tsx:650`). So `/report` and `/task` do not "gain one read". All four pages switch to `readRegistered().catch(() => [])`:

- `readRegistered` is `cache(() => loadProjects())`, the same shape as `readConductor` at `lib/task.ts:1700`.
- `LockBanner` and the page share one read per render.
- Each page keeps its own `.catch(() => [])`. That catch only feeds `registered` and `owners`, so on a failure they degrade the same way they do today.
- `readProjectLocks` awaits `readRegistered()` **uncaught** and turns a rejection into `{ ok: false, problem }`.
- React's `cache` memoises the rejected promise as well. So both callers see the same failure in one render, and the next render tries again.

`/backlog` is the one page that gains a read. `/` reads the projects inside `Promise.all` under `timed('projects.read', …)` (`page.tsx:650`). Keep the `timed` wrapper around `readRegistered()` so that the timing still exists.

## 3. Unregistered projects must be refused before calling the appender

This is a correctness requirement. `pauseProject` (`packages/daemon/src/control.ts:693-700`) answers a no-op transition with `{ kind: 'already', since: state.paused!.at }`.

- `pauseTransition` also returns `null` when `state.project === null`, meaning there is no such project (`packages/domain/src/locks.ts:28-30`).
- So pausing a name that has no stream throws a `TypeError` on `paused!.at`. It does not answer anything.
- The registered check is therefore required, and it must come first.

How to check, and against which store:

- Use `isRegistered(reduceProject(await store.read(projectStream(name))))`. `isRegistered` is at `packages/domain/src/project.ts:145`.
- Read the same store the appender writes to. `loadProjects()` takes a `Log` and not a store (`packages/conductor/src/projects.ts:62-83`). A check made through it would not see a memory store handed to the appender, and the test would assert nothing.
- This also refuses a project that is recorded but still pending, and that is correct: the banner never shows a pending project either.

## 4. The actions are thin edges over an Effect that takes a store

The *Done when* asks for unit tests with the memory store. The board's `resumeWork` test pattern mocks the conductor modules (`unit/picks-actions.test.ts:5-18`), and that would test the mock, not the transition. Split it:

- **The core**: in `apps/board/src/lib/locks.ts`, add an Effect, for example `setProjectPaused(store, verb, project, by)`.
  - It runs the registered check from §3.
  - It then yields `pauseProject(project, by, store)` or `resumeProject(project, by, store)`. Both take a store as their last argument (`control.ts:693`, `:702`).
  - It maps the answer to the `ActionResult` shape. The `already` sentence uses `since`, formatted the same way as the banner's `since`.
- **The actions**: `pauseProjectNow` and `resumeProjectNow` in `actions.ts` take the input and do three things:
  - `Effect.runPromise(setProjectPaused(eventStore, …, actor()))` inside `try`, with a throw answering `{ ok: false, detail }`;
  - `revalidatePath('/', 'layout')`;
  - return the result.
- **The tests**:
  - run the Effect against `createMemoryEventStore()` (`@lingtai/event-store/memory`, as `unit/triage-move.test.tsx:11` does);
  - seed a registered project with the `@lingtai/domain/test` builders;
  - assert on `store.read(projectStream(...))`.
  - The action wrappers then need no test of their own beyond the ratchet. `apps/board` is not in the baseline, and `runPromise` in a server action is a host's edge.

## 5. Formatting `since`

Put a pure `sinceLabel(since: Date, now: Date)` in `lib/locks.ts` and use it in both the banner row and the `already` answer:

- `HH:MM` when `since` is on the same local day as `now`;
- otherwise the date and the time.

The server renders `LockRows`, so `now` is the render's `new Date()`, passed in as a prop. That keeps `LockRows` deterministic under `renderToStaticMarkup`. Do not use `lockSentence` (`locks.ts:22-25`) for the row. It prints an ISO timestamp, and it stays the terminal's.

  The new CSS uses `--held` and `--held-soft` only, never `--signal`.
