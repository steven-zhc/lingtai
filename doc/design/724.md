The change is small, and the ticket describes most of it. This note covers two things the ticket leaves open: what "remove the muted `NEXT` path" means, and which existing tests have to move with it.

**What "remove the muted `NEXT` path" covers.** `NEXT` is drawn muted at exactly one call site, `apps/cli/src/doctor.ts:3114`: `labelled(badge('muted', 'next'), 'next')`. That call site is the only thing to remove.

**Keep `BADGES.muted`.** `NOTE` still uses that key at `doctor.ts:3111` (`badge('muted', 'note')`), and `packages/env/unit/colour.test.ts:129` pins it as `'\u001b[2m NOTE \u001b[0m'`. If you deleted the key because the ticket says "remove the muted path", `NOTE` would stop building.

**`colour.ts`.** Add `next: [42, 30]` to `BADGES` (`packages/env/src/colour.ts:111-120`). Give it a doc comment like the other keys have: green on black, `pass`'s green used as a ground, and the one place green marks something not yet done, citing 0121 §2. Add a row to the assignment table at `colour.ts:80-86` so the table no longer suggests green is only "a verdict passed". `badge()` itself (`:127-130`) does not change. It already gives `[next]` when colour is off and ` NEXT ` when it is on, both `word.length + 2` columns wide. So `labelled(…, 'next')` keeps the column aligned without any other change, and `LABEL_COLUMN` (`doctor.ts:1075`) stays at 9.

**`doctor.ts:3114`.** The line becomes `labelled(badge('next', 'next'), 'next')` followed by `paint.accent('lingtai doctor --verbose')`. This is the same shape as the `FIX` line at `:3105`, which already draws its command with `paint.accent`. `paint.accent` is `ink(36)` (`colour.ts:106`), which produces the `\u001b[36m…\u001b[0m` that Done-when asks for.

**Existing tests that change with it:**
- `packages/env/unit/colour.test.ts:136` has `badge('muted', 'next')`. Change it to `badge('next', 'next')`, or the test keeps pinning the path this ticket removes.
- The no-amber loop at `:130` lists `['fail', 'warn', 'fix', 'muted']`. Add `'next'`.
- Add the colour-on assertion `badge('next', 'next') === '\u001b[42;30m NEXT \u001b[0m'` next to `:126-129`.
- `apps/cli/unit/doctor-render.test.ts:328-344` already turns colour on and checks for no amber, and its stripped last line `'    NEXT  lingtai doctor --verbose'` (`:343`) must still pass. Put the new Done-when assertion in this test rather than in a new fixture.
- The plain-mode assertions at `:262` and `:301` must stay unchanged.

**Amber check.** The existing regex at `:341`, `\[(?:[0-9;]*;)?33m`, does not match `42;30m` or `36m`, so it can stay as it is.
