# Design note: #685, reconcile and converge read `TicketContinued`

## The decision: the helper is already in the path, so don't call it a second time

Neither reader works out the claimant from the event list. Both use the type list only to choose which streams to look at. Each stream is then folded with `reduceTicket`, and since #682 that fold already sends both forms through `claimShapeOf`:

- `packages/domain/src/ticket.ts:268-269` puts `case 'TicketContinued':` and `case 'TicketClaimed':` in one branch. Line 273 calls `claimShapeOf(event, state.runs)`, with the comment *"One rule for both forms (`claims.ts`). A continuation of a run nobody claimed continues nothing and records nothing."* Lines 282-286 then set `lifecycle = { status: 'claimed', runId, worker: d.worker }`. So the latest claim or continuation decides `lifecycle.worker` whichever form it takes.
- In reconcile, `releaseForeignClaims` reads `reduceTicket(...).lifecycle` (`packages/daemon/src/reconcile.ts:468-472`). The release loop re-reads and re-folds the same way before it kills or appends (`reconcile.ts:~640-650`: `const life = reduceTicket(events).lifecycle`, then `killWorker(life.worker)`).
- In converge, `findIssueDrift` folds each candidate with `reduceTicket(events)` and judges `labelsFor(labelState(item.lifecycle.status))` (`packages/daemon/src/converge.ts:~335`).

That is how this note reads the ticket's *"route what they do with a claim through the helper"*: the fold is the route, and it is already there. Do not add a `claimsOf(events)` walk to either file to look up the worker again. That would be a second implementation of what `lifecycle` already answers. The two could disagree on an orphan continuation, which `applyTicket` ignores and a naive `claimsOf(...).at(-1)` would not.

**So the code change is the two type lists and nothing else:**

- `reconcile.ts:459`: `types: ['TicketClaimed', 'TicketContinued']`
- `converge.ts:303`: add `'TicketContinued'` beside `'TicketClaimed'`

Give each a one-line comment saying why it is there.

## Why the change is defensive and behaviour-preserving

`streams({ prefixes, types })` returns the streams holding *any* event of the listed types (`packages/daemon/src/store.ts:111-116`, *"find the streams … neither is a fold"*). A `TicketContinued` that counts always sits on a stream that already holds the `TicketClaimed` for that run. `ticket.ts:273` discards one that does not, and `claimShapeOf` (`packages/domain/src/claims.ts:19-28`) only adds a runId to `claimed` from a `TicketClaimed`. So today's list already finds every stream with a live continuation, and adding the type changes no result on any log the code can produce.

The ticket's *"would not see it"* is therefore true of the type filter but not of the outcome. The comment and the commit should say that plainly rather than call it a fix for a live bug. It still has to land before #683: it removes the dependence on the invariant that "a continuation is never a stream's only claim-shaped event", which nobody enforces at the stream-selection layer.

Correcting one claim in the ticket: reconcile releases on `life.worker !== mine` (`reconcile.ts:471`, `:644`). The worker's liveness decides whether `killWorker` kills it. It does not decide whether the claim is released: *"Whichever way it goes, the claim is released"* (`reconcile.ts:~652`). The tests should assert that, not "releases only when dead".

## Tests: unit, in `packages/daemon/unit/`

Use `createMemoryEventStore()` passed as `store`. Pass `daemonStore` as a stub whose `streams(query)` records `query` and returns the seeded stream id. `converge-ownerless.test.ts:44-46` shows the stub shape, but that one ignores the query, which is why recording it is needed here.

**1. The type lists.** Assert the recorded `query.types` contains `'TicketContinued'`:

- for reconcile, through `releaseForeignClaims` (exported, `reconcile.ts:451`);
- for converge, through `findIssueDrift` (exported); `candidates` itself is private, and `findIssueDrift` hands it the stub via `withDaemonStore(options.daemonStore, …)`.

**2. Old form and new form give the same finding** (the ticket's Watch out). Build the same stream twice:

```
TicketClaimed{runId:'r1', worker:W1}
WaitStarted…
WaitResolved{approved…}
then either  TicketClaimed{runId:'r1', worker:W2}   (old form)
or           TicketContinued{runId:'r1', worker:W2} (new form)
```

Take the wait payloads from an existing fixture. Then assert:

- **Different worker:** with `worker: MINE` (≠ W1, W2), `releaseForeignClaims` gives findings that are `toEqual` across the two forms, and `actual` names `W2`, not `W1`.
- **The live run:** with `worker: W2` (the continuation was made by this conductor), there are no findings in either form. This is the case the ticket fears, a live run being released, so it is the one that matters most.
- **Converge:** `findIssueDrift` gives `toEqual` divergences across the two forms.

**Which worker strings to use.** Make every worker a foreign host, for example `elsewhere:4242`. `killWorker` then returns at the host check (`reconcile.ts:~495`) and never spawns `ps` (`commandOf`, `reconcile.ts:~540`). A `ps` call is an OS process, which makes a test integration under 0060 §1.

**What to leave out.** Don't drive `reconcile()` itself: it runs `findOrphans` and `findOrphanLogs`, which read the filesystem. The re-read and fold in the release loop are the same `reduceTicket(...).lifecycle` that `releaseForeignClaims` uses, so test 2 stands in for it. The end-to-end `TicketReleased` append is covered by `packages/daemon/integration/injected-store.test.ts`, which nobody runs during a pass. That is acceptable here because the append code is untouched.

## Edges not otherwise covered

- **A `TicketContinued` with no prior claim** (a malformed log): it is selected as a candidate now, the fold ignores it, `status` is not `claimed`, and nothing happens. A unit test is optional, but it is cheap, and it is the one input where the new type actually changes which streams are selected.
- **A null or unknown worker string:** handled by `parseWorker` as before (`"… names no process"`); unchanged.
- **The other checks:** `findLaggingProjections`, the orphans, and the GitHub half are untouched.
