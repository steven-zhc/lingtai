# Design note for #663: community files and issue forms

## The one decision the ticket leaves open: the private-contact route has no way in

`SECURITY.md` (#660, already in this worktree) says: *"open an issue on this repository titled "security" with no details in it, and we will reach you privately."* The code of conduct will send people the same way with an issue titled "conduct". But `blank_issues_enabled: false` removes the blank issue from the web UI. After this change, the only way a visitor can open those issues in the web UI is through `bug.yml` or `feature.yml`. Those forms require Problem, Want and Watch out, so they ask the reporter for exactly the details both routes tell them to leave out.

**Add a third form, `.github/ISSUE_TEMPLATE/private.yml`**, so there are six files instead of five:

- `name: Private contact (security or conduct)`. The description tells the reporter to title the issue `security` or `conduct`, write nothing else, and expect to be reached privately.
- `labels: [agent:hold]`. Give it **no kind label**. The queue only sees an issue that has a kind (CLAUDE.md *Opening an issue*: *"An issue needs a **kind** label or the queue never sees it"*). So this issue stays out of the queue even if someone later lifts the hold. That is stronger than the Watch-out row asks for, and it still uses only labels that exist.
- The body is one required `dropdown` with the options `security` and `conduct`. GitHub rejects a form whose body has no non-markdown field, and a dropdown is the only field that lets the reporter say which route they mean without adding any detail. Do not add a textarea.

The Done-when line *"Both issue forms carry `agent:hold` and their kind label"* still holds for `bug.yml` and `feature.yml`. `private.yml` is the one form without a kind, and the reason is above. Mention it by name in `CONTRIBUTING.md` and `config.yml` so a reviewer sees it was chosen on purpose.

`config.yml`'s contact link to `SECURITY.md` stays as the ticket describes. A contact link must be an absolute URL, so use `https://github.com/steven-zhc/lingtai/blob/main/SECURITY.md` (the remote is `https://github.com/steven-zhc/lingtai.git`). Its `about:` line should send readers to the private-contact form.

## No gate checks any of these files

- `pnpm fmt:check` is `oxfmt --check` over `packages/**/*.ts(x)`, `apps/**/*.ts(x)`, `vitest.config.ts` and `doc/events.json` only (`package.json:17`).
- `pnpm lint` is `oxlint --deny-warnings` (`package.json:18`), and oxlint reads JS/TS only.
- Nothing in `packages/`, `apps/` or `scripts/` reads root-level `.md` files or `.github/ISSUE_TEMPLATE`. The site's document walker starts from `doc/` (`apps/site/src/lib/docs.ts:303`).

So "green" in the Done-when list says nothing about whether these files work. A malformed issue form only shows up on GitHub, after the merge, as a broken template picker. Before committing, check the parse yourself with the `yaml` package the workspace already has (`packages/recipe/package.json:18`), for example `node -e` with `require('yaml').parse` run from `packages/recipe` on each of the four YAML files. Then read each form against GitHub's issue-form schema:

- `name`, `description` and `body` are required.
- Each field's `id` is unique.
- `validations.required` goes on Problem, Want and Watch out.
- Evidence and Done when have no `validations.required`.
- `labels` is a list.

GitHub silently drops a label that does not exist. A typo in `agent:hold` would therefore fail silently, and the issue would reach the queue unheld. Compare each label character by character with `bug`, `feature` and `agent:hold`.

## The forms' fields

Each of the three required fields describes its row in CLAUDE.md's *Opening an issue* table, briefly:

- **Problem:** the failure, not the area.
- **Want:** what is true when this is done.
- **Watch out:** the trap. This is not optional here, even though CLAUDE.md lets a maintainer leave the row out, because a stranger's issue is the one most likely to omit it.

Leave **Fix** out of the forms on purpose: a stranger does not know the code's shape, and the ticket lists only these three. Put Evidence and Done when last, both optional. The Evidence placeholder can ask for the exact output and the version. `feature.yml` uses the same fields with different placeholder text. Do not copy the agent-facing sections (Edges, Out of scope) into the forms.

## CODE_OF_CONDUCT.md

Take Contributor Covenant 2.1 from its canonical text (contributor-covenant.org, version 2.1, Markdown) and change exactly one place: the `[INSERT CONTACT METHOD]` placeholder under *Enforcement*. Replace it with the issue-titled-"conduct" route, pointing at the private-contact form. The canonical text contains no email address, so after the substitution the file should have none. Its attribution links are URLs, which are fine. Do not reflow the text to 80 columns: "verbatim" means a diff against upstream shows only that one line.

## CONTRIBUTING.md

`CONTRIBUTING.md` sits at the root beside `SECURITY.md` and follows that file's register: short and in the second person. Use relative links: `doc/tutorial.md`, `CLAUDE.md#opening-an-issue`, `CLAUDE.md#commits`, `.github/workflows/check.yml`, `SECURITY.md`, `CODE_OF_CONDUCT.md`.

When stating the commit rule, do not put an issue number anywhere near *close*, *closes*, *fixes* or *resolves*, not even inside a sentence or example that says not to. Per CLAUDE.md *Commits*, that pattern is exactly what closes an issue. Describe the rule in words, or use an example with no number in it.

This file's own commit message must obey the same rule, so say "see #660" rather than any closing verb.

## Edges this adds to the ticket's

- **Somebody files a security report through `bug.yml` anyway.** It arrives labelled `bug` and `agent:hold`, so it is held. A person moves it, and nothing is worked unattended.
- **The `private.yml` form goes on the public tracker.** The dropdown records only "security" or "conduct", which `SECURITY.md` already makes public as titles.

## Do not touch

- `README.md:111-112` already points at `SECURITY.md`. Leave it unless a one-line link to `CONTRIBUTING.md` fits under *Next*. That is optional, and it is not in the ticket.
- `.lingtai/config.yaml` and the recipe: the labels the queue reads are out of scope.
