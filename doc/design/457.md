### The functions, and two decisions the ticket leaves open

All of these go in the same file. Each one is a `switch` with no `default`, under an explicit return type. `tsconfig.base.json` has `strict`, so a missing case is a TS2366 error. That is the same mechanism `moves.ts:21-70` (`allowedMoves`, `triageRuns`) relies on.

- **`cleared(action): boolean`**: an outer `switch (action.yields)` and an inner `switch (action.result._tag)`, following the *Cleared when* table at 0120:216-223. Every `NotReached`, `NeverStarted`, `Interrupted`, `AnswerUnreadable` and `NotDone` returns `false`.
- **`decidingAction(outcome): Action | null`**: the last action whose result is not `NotReached`.
- **`stepCleared(outcome): boolean`**: `d === null || cleared(d)`. 0120:231-232: *"if it cleared, the step cleared, and a step with no actions cleared."* The ticket calls this "whether the step cleared"; `stepCleared` is the name to use.
- **`headOf(outcome): string | null`**: the last non-null `head` in the list. Three results carry one: `commit` `Completed`, `commit` `Interrupted`, and `worktree` `Completed`. Skip a `null` head rather than returning it, because "the last `head`" means the last one that names a sha. A kept-run that committed nothing after an agent that did commit leaves the agent's head (0120:242-243).
- **`designOf(outcome): Design | null`**: the `design` of the last `Drafted`.
- **`changedNothing(outcome): boolean`**: `outcome.step === 'implement'`, every action `cleared`, and `headOf(outcome) === null`. An `implement` with **no actions** answers `true`, which is the literal reading. Pin that case in a test, so that #459 meets the choice as a decision rather than an accident.
- **`accepts(step, yields): boolean`**: an exhaustive `switch (step)` over all ten `Step`s, following the *Legality* table (0120:197-206). `claim` and `end` accept nothing (0120:210: *"`claim` and `end` are not in the table"*).

**Decision 1: `merge`'s ordering is a comment, not code.** `accepts('merge', 'signoff')` and `accepts('merge', 'merge')` both return `true`. Add a comment saying where each half of the ordering is already enforced:

- **The lane is last**: `packages/recipe/src/recipe.ts:2314-2315`, *"The lane is the last action at its step, and anything written after it is refused (0065 §8, `#270`)"*.
- **The only `signoff` at `merge` is the injected one**: `humanPlugin` and `watchPlugin` do not serve `merge` (`recipe.ts:719` and `:736`, *"And not `merge` since `#270`"*). The injected one is the conductor's, not the recipe's.

A second encoding here would be a second place for that rule to live, and nothing calls `accepts` yet.

**Decision 2: add `wellFormed(outcome): boolean`, because otherwise the *at most one* test proves nothing.** `decidingAction` is defined as the last non-`NotReached` action, so "everything after it is `NotReached`" holds by construction, and a test of only that is a tautology. The real invariant at 0120:229-231 (*"The pipeline stops at the first one that does … and the rest are `NotReached`"*) has three parts:

- Every action **before** the deciding one cleared.
- A `NotReached` follows only a deciding action that did **not** clear.
- A non-empty outcome has a deciding action, i.e. it is not all `NotReached`.

`wellFormed` is the pure check of exactly that. Its test is the Done-when's *at most one action fails to clear*. It needs:

- one passing case per shape: empty, all cleared, cleared-then-fail-then-`NotReached`;
- one failing case per broken rule: two uncleared actions, `NotReached` after a cleared action, `NotReached` first, all `NotReached`.

Say in its doc comment that #464's builder of `StepEnded` is what has to keep it true. The other step-level functions take a well-formed outcome; do not make them throw on a malformed one.
