Nearly all of this is spelled out in the ticket. There is one trap it does not mention, and two kinds of hit that are easy to get wrong.

**A unit test reads `the-bar.md`.** `apps/board/unit/projects.test.tsx:173` checks that the file contains a fixed phrase:

    expect(said(read('../../../doc/design/the-bar.md'))).toContain(four)

Here `four` is the string `'filter, reading, health, headline'` (`:167`). The test first collapses whitespace and `*`, so it tolerates new line breaks, but it does not tolerate new words. The phrase is at `doc/design/the-bar.md:70` (*"The four are filter, reading, health, headline, …"*) and again at `:148`. None of the three *pass* hits in that file is inside that phrase (`:56`, `:112`, `:115`). If re-flowing a paragraph puts a word into the phrase, or swaps its order, `pnpm test` goes red over a prose edit. No other unit test reads a document in this set. `rail.test.tsx` and `bar.test.ts` read only `globals.css` and `src/app/*.tsx` (`rail.test.tsx:69`, `bar.test.ts:192`, `:216`).

**Kept: a colour or a verdict, not an attempt.** In `the-card.md`, `` `pill pass` `` (`:52`) and `` `passed` … `--pass` `` (`:119`) are CSS class and token names for the green verdict. In `the-bar.md`, *"the health dot uses pass/fail"* (`:56`) is the verdict. All three stay and go in the kept list as *a verdict / a class name*.

**Kept: a link target, but not its sentence.** `the-bar.md:112` links `0039-the-worktree-is-the-whole-of-a-pass.md`. That file name is a citation and stays exactly as it is. The words around the link are ordinary prose, so a *pass* there that means an attempt still becomes *attempt*. The rule is the same for every ADR file name in the set (`0103-a-pass-is-ten-fixed-steps.md`, `0122-several-passes-share-one-conductor.md`): the link text and target stay, and the sentence they sit in does not.
