## The one decision: callers that swallow a refusal catch a defect, and never an interrupt

At `:753` today `appendAt` is a promise, and three callers answer its rejection themselves:

- `:1542`: `Effect.result(Effect.tryPromise({ try: () => appendAt(ticketId, endPlan), catch: … }))`. This is inside the release that #1080 made run whole.
- `:2070`: `appendTo` turns the promise's rejection into `{ refused }` with `.then(ok, refused)`. Its comment says *"An append that never rejects"*.
- `:5072`: `try { await appendAt(...) } catch`. Its comment says *"`appendAt` and a swallowed refusal, which is `noteRefs`' rule and not a laxness"*.

Once `appendAt` lifts with `Effect.promise`, a rejection lands in the defect channel. `Effect.result` does not see the defect channel and `Effect.tryPromise` no longer applies, so a mechanical port of `:1542` silently stops swallowing the refusal. That would turn *end actions not recorded* into a defect raised out of the release.

All three must use **`Effect.catchDefect`** (Effect 4.1.2, `node_modules/effect/dist/Effect.d.ts:5362`):

- `:1542`: `appendAt(...).pipe(Effect.as(true), Effect.catchDefect((d) => Effect.sync(() => { log(...); return false })))`, or the same thing mapped into the `Result` the code already branches on.
- `:2070`: `appendTo = (events) => appendAt(runId, events).pipe(Effect.as(null), Effect.catchDefect((refused) => Effect.succeed({ refused })))`.
- `:5072`: `yield* appendAt(...).pipe(Effect.catchDefect(...))`, keeping the existing log line.

**Do not use `Effect.exit`, `Effect.catchCause` or `Effect.ignore`**, even though the ticket allows "`Effect.catchDefect` or `Effect.exit`". Those also catch an interruption. The pass is interruptible: #1080's tests `a-claim-is-not-split-by-an-interrupt`, `a-publish-is-not-split-by-an-interrupt` and `a-release-is-not-cut-short` interrupt it at an append. A catch that also takes the interrupt would carry on after the interrupt as if it had not happened.

`appendAt` itself never touches `unappended`. Only `appendNow` (via `Effect.tapDefect`) and `appendFrom` record into it. That split is the existing contract, stated at `:745-751`: *"For the callers that answer a refused append themselves … Everything else uses `appendNow`."*

Two existing tests already pin both sides, and they must stay green unedited:

- `unit/conduct-a-whole-attempt.test.ts:628`, *releases the item when the store refused an append the pass made*, covers the `appendNow` side.
- `:715`, *lands though the store refused the row that says why it bought a round*, covers the `:5072` swallow.

`recordRecipe`'s hand-rolled `.catch` with `unappended ??= defect` at `:4342-4346` is not one of the three helpers. Leave it as a lifted promise.

## `appendAt` is one read and one append

Write it as `Effect.gen`: `const at = (yield* Effect.promise(() => store.read(stream))).length`, then one `Effect.promise(() => store.append(stream, at, events))`, returning the version as `:756-757` does (#931). Add no `retry` and no `timeout`. `appendFrom` is one `Effect.promise(() => store.append(stream, version, events))` with the same `tapDefect`. Rewrite the doc comment at `:742-751`: its *"A promise rather than an `Effect`, because the ports below are plain promises"* is the sentence this ticket makes false.

## `emit` and its lift in `run-attempt.ts`

`conduct.ts:4201` becomes `(event) => Effect.gen`. The `RunSpent` tally goes in an `Effect.sync` **before** the append, as now. That keeps the ticket's interruption edge: an interrupted `emit` has already counted or has not started.

`AttemptPortOptions.emit` (`run-attempt.ts:1048`) becomes `(event: AttemptEvent) => Effect.Effect<number | void>`. Rewrite the interface's doc at `:1041-1043`, which says *"`emit` stays a promise"*.

In `attemptPortsFrom` (`:1079`), the lift must keep the guard that `run-attempt.ts:1797-1825` and `action.ts:1050` use today: `(event) => Effect.promise(() => new Promise((resolve) => resolve(emit(event))))`. `AttemptOptions.emit` (`:858`) may return `number | void` **synchronously**, and test fakes do. `Effect.promise(() => emit(event))` would hand `Effect.promise` a non-thenable, so do not lift it that way.

At `:1797-1825`, the two `new Promise(resolve => resolve(options.emit(...)))` wrappers become plain `yield* options.emit(...)`. `StepEnded` keeps its `recorded.outcome === undefined ? undefined :` branch.

## The two actions adapters share one helper

Both targets stay promise ports:

- `:2322` feeds `runActionPipeline`, whose port is `action.ts:766`, `(event: ActionEvent) => Promise<void> | void`.
- `:2368` feeds a body's `StepWork.emit`, at `run-attempt.ts:644`, with the same type.

Use a module-level helper that takes the services, for example `emitAsPromise(emit, services)`, which returns `(event) => Effect.runPromiseWith(services)(emit(event)).then(() => undefined)`. The ratchet does not count a `*With` run (`effect-ratchet.test.ts:64-69`, `RUN = /^run[A-Z](?!\w*With$)/`). `schedule.ts:295` is the precedent in this package.

Take the services with `yield* Effect.context()` inside the `runStep` generator, before either adapter is built. Taking them at module scope, or once per pass, is wrong: the span you want is the step's (#791, the comment at `:1787-1790`).

A refused append crosses that boundary as a rejection, and `action.ts:1050` lifts it back into a defect. `unappended` has already been recorded inside the inner fiber, because `tapDefect` lives in `appendNow`, so nothing is lost there.

## Edges this note decides

- **The continuation read at `:1155`** becomes `Effect.gen` with `yield* Effect.promise(() => store.read(options.continuing.runId))`. It returns the same `null`s in the same order, and a failed read is still a defect, as it is today under `Effect.promise`.
- **The new unit test** goes in `unit/conduct-a-whole-attempt.test.ts`, beside `:628`. Wrap the memory store so that `append` rejects once on the **ticket** stream at the claim, which is `appendNow(ticketId, [...])` at `:1079`. Assert the pass dies with the log line `the store refused an append during the claim` (`:4904`), and that no `StepEnded` names `did-not-finish` for `claim`. The event that settles it in a real log is a `TicketReleased` with no `StepEnded{outcome.step: 'claim'}` before it on the run stream.
- **Nothing here needs the integration half.** Both behaviours that matter, *recorded, then re-raised* and *swallowed by the three `appendAt` callers*, are unit claims, held by `:628`, `:715` and the new test.
