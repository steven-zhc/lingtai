# Design note: #983

The ticket's shape holds. These are the points it leaves open or gets wrong against the code.

## `implement` keeps its fallback to `runtime.agent`

Today's line is `agents(steps.implement)[0] ?? recipe.runtime.agent` (`apps/board/src/lib/recipe-lines.ts:56`). The ticket's evidence leaves out the `??`.

An empty `implement` still buys an agent. `conduct.ts:3587-3591` says "an unconfigured `implement` still buys the one agent — on `runtime.agent`", and the default row is at `conduct.ts:3599`. `COVERED` hides the `agent` row and keeps doing so (`page.tsx:40`). Built literally, a recipe with no `implement:` would name the writing agent nowhere in the left column.

**Decision:** when `implement` holds no `agent` action, its block carries one setting, `{ label: 'agent', value: recipe.runtime.agent }`. When it holds one, it carries no settings and the action is listed as the ticket says. The ticket's empty-step edge still holds, because this step now has a setting. Add a unit case for both.

The same gap exists at `claim`, `admit` and `merge`, whose defaults run when nothing is declared (`conduct.ts:3575-3608`, chosen at `:3618`). `claim` and `admit` have settings anyway. An empty `merge` still lands, and the page draws it greyed. That follows the ticket, and it is why the words must be exactly *nothing declared* and never *nothing runs*.

## Names and types

- **Type clash:** `recipe-lines.ts:8` already imports `type StepAction` from `@lingtai/recipe`, so the ticket's `interface StepAction` will not compile beside it. Call the new one `StepActionLine`.
- **Imports:** `discloseSteps` comes from the root of `@lingtai/recipe`, as `apps/board/src/lib/recipe.ts:35` does. `Step` and `STEPS` come from `@lingtai/domain` (`recipe.ts:22`).
- **`when`:** it is not on every action: "today `when:` is legal on four plugins" (`packages/recipe/src/plugin.ts:62`). Read it as `'when' in action ? action.when : null`.
- **Layout:** those four kinds (`close`, `labels`, `refs`, `judge`) all have `value: null`, so `.step-when` never has to show a value.
- **`close` and `labels`:** `when` defaults on these (`packages/recipe/src/recipe.ts:789`, `:799`), so they always show it, as the mock does.

## Chips for `kinds`

Do not split a joined string in the page, because a GitHub label may contain a comma. Add `chips?: readonly string[]` to `RecipeLine`, set on `kinds` only. `value` stays `kinds.join(', ')`, so the unit test can read it as before.

Commands need no splitting, since each `run` action is its own row and so one chip.

Sentences (`assignee`, `retries`, `a person approves`) are ordinary type. `tickets`, `base` and non-code action values are monospace.
