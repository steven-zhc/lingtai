## The decisions the ticket leaves open

**1. A "run" is any member of `Effect` whose name starts with `run`, not only the three names.** The ticket's title says `Effect.run*`, and its list of three misses a case that exists today:

- `packages/github/src/app.ts:292`: `const exit = await Effect.runPromiseExit(token, { signal })`.
- `app.ts:250`: `Effect.runSync(Effect.makeSemaphore(1))`.

`runPromiseExit`, `runSyncExit` and `runCallback` leave the fiber tree exactly as `runPromise` does. 0101 §6 gives the reason: *"a `runPromise` nested in an Effect starts a fiber with no parent"*. So count by the prefix `run` on a member of a binding that is the `Effect` module.

**2. Resolve the binding per file, from its imports. Do not match the text `Effect`.**

- `Effect` binding: one named `Effect` imported from `'effect'` (with or without `as X`), or `import * as X from 'effect/Effect'`.
- Bare binding: `runPromise`, `runPromiseExit` and the other `run*` names imported directly from `'effect/Effect'` or `'effect'`, aliased or not.
- Skip `import type` and type-only specifiers. `packages/conductor` has `import { Context, type Effect, type Scope } from 'effect'`, and that `Effect` is not a value.
- Use `ts.createSourceFile` only. No `Program` and no type checker: that is the cost #785 paid.

**3. Count references, not only calls.** `pipe(eff, Effect.runPromise)` and `.then(Effect.runSync)` are runs with no call expression whose callee is the run. Count every `PropertyAccessExpression` on an `Effect` binding whose name matches the prefix. Count every `Identifier` that refers to a bare-imported run. Do not count the import specifier itself.

**4. `async` means the `AsyncKeyword` modifier on a function-like node.** The nodes are `FunctionDeclaration`, `FunctionExpression`, `ArrowFunction` and `MethodDeclaration`. Report the line of the modifier node itself, via `sf.getLineAndCharacterOfPosition(mod.getStart(sf))`, so the reported line is the one that says `async`.

**5. Skip `.d.ts`, by rule.** The ticket says there is no generated file under `src/` today. There is one, and it is committed: `packages/event-store/src/prisma/contract.d.ts` (603 lines), which begins `// ⚠️ GENERATED FILE - DO NOT EDIT`. A declaration file has no bodies, so it can never hold a count. Skip it by suffix, and keep a `NOT_COUNTED` constant of `{ path, reason }` entries for the path exclusions in the ticket's edge. It is empty today.

**6. Parse failure is detected from `parseDiagnostics`.** `ts.createSourceFile` never throws. A syntax error comes back as a tree containing missing nodes, and it would count quietly. Read `(sf as unknown as { parseDiagnostics: readonly ts.Diagnostic[] }).parseDiagnostics`. That field is internal, so add a unit case that feeds the test's parse helper a broken source string (`async function (`) and asserts the helper reports it. If TypeScript renames the field, that case goes red and the guard does not go blind. Do not call `transpileModule` to get the diagnostics: it is a second parse of every file.

**7. The baseline's keys are pinned in the test, not taken from the JSON.** The test file holds the ten package directories as a constant, copied from 0101 §6's list:

```
apps/cli
packages/event-store
packages/projector
packages/github
packages/repo
packages/agent
packages/actions
packages/conductor
packages/daemon
packages/telegram
```

One case asserts that the baseline's keys equal that constant. Otherwise deleting a key is a way out. This follows `retired-names.test.ts`'s own rule: *"Reading a list from the document is not the same as letting the document decide it."*

The baseline has the shape `{ "apps/cli": { "async": n, "run": n }, … }`. Use the AST's numbers. The grep table in the ticket is only an upper bound. For example, `apps/cli/src/conduct.ts:551` is a doc comment that says ``calls `runPromise` at its own edge``, and it must not count.

**8. One assertion over every package, and a message a person can act on.** Collect the mismatches across all ten packages before failing, so a file moved between packages shows both packages in one red.

- **Above the baseline:** name the package and measure, the count and the baseline, then every occurrence in that package as `path:line`. You cannot tell which occurrence is new, which is why the ticket says *every*. Then one sentence: *0101 §6: every backend function that does IO is an Effect, and `Effect.run*` runs only at a host's edge — see epic #790. Write it as an Effect, or raise this number in this diff where a reviewer sees it.*
- **Below the baseline:** say *lower `<package>.<measure>` to `<n>` in `effect-ratchet.baseline.json` in this change*.

Print the exact JSON value to paste. The test never writes the file: a unit test that edits the checkout would undo the ratchet.

## Unit cases over source strings

Feed small sources straight into the counting function, with no filesystem:

- the ticket's four cases: an `async` in a comment or a string does not count; an `async` arrow and method do; `Effect.runPromise` in a comment does not count; an aliased import of `runPromise` from `effect` does;
- `runPromiseExit` counts;
- `pipe(x, Effect.runPromise)` counts;
- a `type Effect` import followed by `Effect.runPromise` does not count;
- the broken-source case from decision 6.

The repo scan is then one more case. It reads all of the `.ts` files in parallel, parses each once, and compares with the baseline.
