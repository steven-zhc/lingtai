# #985: the shape

The ticket's table of steps and its CSS stand. This note covers what the ticket leaves open: how the ten rows are built, where the empty text comes from, how the preview gets `YamlView`, how much of the mock's framing to take, and what the test must anchor on. No ADR is touched.

## The list is a `Record<Step, ReactNode>` built in `SetupForm`'s body

Build one `const under: Record<Step, ReactNode>` next to the existing helpers, using the existing `<Line>` elements moved verbatim. Use a fragment where a step has several and `null` for `design`, `merge`, and `end` on a local target. Then:

```tsx
<ol className="step-list">
  {STEPS.map((step, i) => (
    <StepRow key={step} n={i + 1} step={step} says={STEP_SAYS[step]}
             on={under[step] !== null} empty="nothing to set here">
      {under[step]}
    </StepRow>
  ))}
</ol>
```

- **Why a `Record`:** `tsc` then refuses a step with no entry, as it does for `STEP_SAYS` (`apps/board/src/lib/step-says.ts:7`).
- **Why it must stay plain elements:** do not write a component inside `SetupForm` or a per-step child. A function declared in the render body is a new type every render, so every `Line` would remount and an open `change` would lose its input. `Line` is module-level (`setup-form.tsx:21`), `StepRow` is too (`step-row.tsx:8`), the keys are stable, and all the state stays at `setup-form.tsx:46-62`.
- **Imports:** `STEPS` is a value import from `@lingtai/domain`. A client file already does this (`triage-picks.tsx:3`), and `client-graph.test.ts:110` holds that package to no `node:` import. `STEP_SAYS` was written for this page: *"Imports a type only, because the add page — a client component — reads it too"* (`step-says.ts:4-5`).

## `StepRow` needs one optional prop

The empty text is hard-coded: `{on ? children : <div className="step-empty">nothing declared</div>}` (`step-row.tsx:29`). Add `empty = 'nothing declared'` as an optional prop and render it there. The recipe page passes nothing and stays as it is (`recipe/[project]/page.tsx:114-119`). This is the one change outside the form, the CSS and the preview extraction below.

## The preview: extract `FileView`, do not import `YamlView` directly

`YamlView` cannot be imported statically, because CodeMirror touches `document` (the comment at `recipe-text.tsx:8-9`). The `<pre>`-until-ready fallback the ticket asks for already exists as the private `FileView` (`recipe-text.tsx:10-23`).

Move `FileView` and its `dynamic()` call into a new `apps/board/src/app/recipe/[project]/file-view.tsx`. It needs its own `'use client'`, because `ssr: false` is refused in a server component. Export it, and import it from both `recipe-text.tsx` and `setup-form.tsx`.

- **Do not export it from `recipe-text.tsx`:** that file imports `RecipeForm` (`:6`), which would pull the recipe editor into the add page.
- **Repoint one test:** `recipe-editor.test.tsx:43-50` checks that `recipe-text.tsx` has no static import of the view or the editor. After the move it passes without checking anything that matters, so make it read `file-view.tsx` as well.

Only the third branch of the preview changes:

- **Null or refused:** these two branches keep their `<h3 className="s2-h">recipe.yml</h3>` and their `<p>`, per the ticket's edge. `.rfile` has no padding of its own, so a `<p>` inside it would sit against the border.
- **Text:** this branch becomes `<div className="rfile">`, then `<div className="rfile-bar"><b>recipe.yml</b><small>preview — nothing is written until Add</small></div>`, then `<FileView text={preview.text} />`. The mock's scr 2 has this bar and wording.
- **Why the panel:** the classes exist and need no CSS (`globals.css:3305-3310`). `.rfile` is sticky inside the already-stretched `.s2-right` (`:3304`), which matters now that the left column is much longer. CodeMirror also has no border of its own, unlike `.s2-yaml`.
- **Do not key `FileView` on the text:** `YamlView` replaces the document in place (`yaml-view.tsx:46-51`). A refused preview unmounts it, and the next good one shows the `<pre>` until the view is ready, which is acceptable.

## How much of the mock to take

The mock wraps the list in a card, and that needs no new CSS. Inside `.s2-left`:

- `<section className="rcard"><h3 className="rcard-h"><span>What one attempt does, in order</span></h3>` then the `<ol>`, as the recipe page does at `page.tsx:107-112` without its `src` line.
- A second `<section className="rcard">` around the existing spend heading, `.s2-limits` and ceiling note, with that `h3` taking `rcard-h` in place of `s2-h`. The inputs, labels and text are unchanged.
- The error line and Back / Add stay outside the cards, as in the mock.

**Where the mock and the ticket disagree, the ticket wins.** The mock's `stack` line has no `change`, but today's does (`setup-form.tsx:172-173`, it opens `install`). Keep it, because no `change` behaviour moves. *A person approves the merge?* keeps its `s2-h`.

## CSS

The three declarations in the ticket are enough, and `Line`'s DOM order stays as it is, so tab order does not move. `.s2-line` and `.s2-change` are used only in this form. The other `.s2-change`, the `add` in the checks editor (`setup-form.tsx:221`), sits in a flex `.wiz-row` (`globals.css:3108`), where `grid-column` and `grid-row` do nothing.

## The test

Create a new `apps/board/unit/setup-form.test.tsx`. Use `vi.mock('../src/app/setup/repository/read/actions.ts', …)` and `renderToStaticMarkup`, as `recipe-editor.test.tsx:9,54` does.

- **Anchor on the markup, not the words.** Use `<b>implement</b>` for a step and `<span class="s2-k">agent</span>` for a label. A bare `indexOf('agent')` finds `STEP_SAYS.implement`, and `end` is both a step and a label. *No `end` line on a local target* means `s2-k">end<` is absent while `<b>end</b>` is present.
- **`base` disabled:** assert its note (`setup-form.tsx:165`) and that no `s2-change` falls between `s2-k">base<` and the next `s2-line`.
- **`useEffect` does not run under static render**, so `preview` stays null and this test never reaches the panel. The preview is covered only by the ticket's person check, and the test should not pretend otherwise.
