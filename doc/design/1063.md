# Design note: #1063, short titles, subtitles and a 13rem sidebar

The ticket already gives the shape. This note fixes four details it leaves open, each of which would otherwise cost a fix round.

## 1. One remark plugin for every slug, using the same mechanism as `shell-tabs`

`remarkShellTabs` already marks a node for the site by setting `data: { hName, hProperties: { className: [...] } }` (`apps/site/src/app/docs/document.tsx:95-99`). The sanitizer then allows that exact class: `div: [..., ['className', 'shell-tabs']]` (`document.tsx:26-33`). Do the same here:

- **`remarkSubtitle`**
  - Find the first top-level `heading` with `depth === 1` in `tree.children`.
  - If the node right after it is a `paragraph` whose `children` is exactly one `emphasis` node, set `data.hProperties.className = ['subtitle']` on that paragraph.
  - Change nothing else. Do not change `hName`; it stays a `<p>`.
- **Where it runs.** Add it to `remarkPlugins` for every slug. Today the plugin list is conditional (`document.tsx:233`: `[remarkGfm, ...(slug === 'tutorial' ? [...] : [])]`), so put the new plugin outside that conditional.
- **The sanitizer.** In `SANITIZE`, add `p: [...(defaultSchema.attributes?.p ?? []), ['className', 'subtitle']]`. Use a fixed value, not a bare `'className'`, so no other class gets through.

Test it in the style of `apps/site/unit/tutorial-tabs.test.tsx`: `renderToStaticMarkup(<Document …/>)` on a real file, asserting `<p class="subtitle"><em>…</em></p>`. That test runs the sanitizer, which is the check the ticket's Watch out asks for. Add these negative cases:

- a bold paragraph after the `h1` is not marked;
- an emphasis followed by more text is not marked;
- a `doc/plugins/agent.md` render contains no `class="subtitle"`.

## 2. The tutorial's intro selector moves past the subtitle

`.tutorial-prose > h1 + p` (`apps/site/src/app/site.css:439`) would now style the subtitle. Change that selector to:

```css
.tutorial-prose > h1 + p:not(.subtitle),
.tutorial-prose > h1 + p.subtitle + p
```

The intro keeps its look whether or not a subtitle is present, so #1061's rewrite cannot quietly drop the intro style.

Put the subtitle's own style on `.prose p.subtitle`, near the other `.prose` rules: muted ink, a slightly larger size, a small top margin so it sits close under the `h1`. Every page then gets the same subtitle. Because the tutorial's `h1` has `margin-bottom: 20px` (`site.css:436`), add a `.tutorial-prose h1:has(+ .subtitle)` margin override, or tighten that margin, so the gap matches other pages.

## 3. The sidebar

- **Width.** Change `.doc-layout`'s first column to `13rem` (`site.css:329`).
- **No wrapping.** Add `white-space: nowrap; overflow: hidden; text-overflow: ellipsis` to `.doctree a`. It is already `display: block` (`site.css:353-356`), so the ellipsis works as is.
- **Full title on hover.** In `DocTree`, set `title={entry.title}` on the `Link` (`apps/site/src/app/docs/doctree.tsx:24`).
- **Below 1080px** (`site.css:378-386`) the tree becomes a boxed list and `nowrap` still holds there. That is the right result; do not undo it in the media query.

## 4. What the "at most 3 words" test covers

Put the test in `apps/site/unit/docs.test.ts`, next to the existing `describe('treeOf')` (`:398`). It covers only what `treeOf()` returns, which is the `PUBLIC_SLUGS` set (`apps/site/src/lib/docs.ts:70-81`), because `DOCS_PUBLIC` is the constant `false` (`docs.ts:53`).

**`why` is not in `PUBLIC_SLUGS`**, so `doc/why.md` never appears in the tree and that test does not cover it. Still change its heading as the ticket says. Cover all seven files in a separate test that reads each one directly and checks two things:

- `titleOf` returns the short title;
- `ledeOf` does not start with the subtitle text.

One test over the seven filenames covers the ticket's lede item and its title item together. Split words on whitespace after `treeOf` has stripped the backticks (`docs.ts:635`), so `` `file-brief:` `` counts as one word.

## Smaller decisions

- **`doc/cli.md`.** In `renderCliPage` (`apps/cli/src/cli-doc.ts:127-130`), the lines become `'# CLI', '', '*The lingtai command line*', '', 'Generated from …'`. Then run `pnpm docs:cli` (`package.json:24`, `node scripts/cli-doc.ts`). The lede stays the "Generated from…" sentence, as it is today.
- **Requirements.** The subtitle keeps its em dash and its semicolon exactly as written. `*…*` around text containing `—` and `;` still parses as one emphasis node, so the plugin accepts it.
- **Leave alone** `doc/README.md:50` and `doc/design/events-page.html:213-217`. Both quote the old titles, and both are out of scope.

## Checks

`pnpm typecheck`, `pnpm lint`, `pnpm fmt:check` and `HOME=/nonexistent pnpm test`. Everything above is checked by the unit half.

The one thing those checks cannot see is the CSS outcome: whether no entry wraps at 13rem. That stays the ticket's manual check at ≥1240px. Its stand-in is the word-count test together with `nowrap`.
