## Design note: #933. The board shows a recorded prompt as it was handed

### Most of this is already built. Wire it up, don't write it again

#927's resolver and the domain's expansion are already in this worktree:

- **`resolvePromptRefs(entries, ports)`** is in `packages/conductor/src/prompt-refs.ts:117`, and the package root exports it (`packages/conductor/src/index.ts:3`). The board already imports from that root on the server (`apps/board/src/lib/day-spend.ts:7`, `lib/spend.ts:27`), so no new subpath export is needed.
  - Its own comment says *"It never throws and never invents text"* (`prompt-refs.ts:18`).
  - It checks each value's size and `sha256` itself (`:104-113`).
  - It turns a port that throws, even synchronously, into an `unresolved` (`:86`, `:121`).
  - It runs `cat-file -e <sha>^{commit}` on both ends before it runs `git diff ...DIFF_FLAGS from...to` (`:58-66`).
- **`expandPrompt(record, values)`** is in `packages/domain/src/prompt-ref.ts:227`. It returns `ExpandedPrompt = { text, unresolved: { index, ref, why }[] }` (`:213-216`). **Use that type as the ticket's `Shown`. Don't define a second one.** It checks the hash again with `sha256Hex` (`:273`), and it already says `'malformed refs'` for spans that overlap or are out of order (`:244-246`).

So `apps/board/src/lib/expand-prompts.ts` does three things and nothing else:

1. It builds the two ports.
2. It calls `resolvePromptRefs`.
3. It hands the values to `expandPrompt`.

It must not reimplement a fetch, a hash or a `git diff`.

### The store port is the events already held, not the store

`PromptRefPorts.store` is `Pick<EventStore, 'read'>` (`prompt-refs.ts:25`), and `fetchBody` and `fetchStepValue` call `ports.store.read(ref.stream)` (`:46`, `:70`).

- **The adapter.** Pass `{ read: (stream) => held.get(stream) ?? Promise.reject(new Error('not on this ticket\'s streams')) }`. Build `held` from what `readAttempts` already returns: `own` (the ticket stream) and `streams[i]` keyed by `claims[i].runId` (`task.ts:1723`, the return `{ own, ticketState, claims, streams, … }`).
- **How the reason gets through.** The resolver turns the rejection into that ref's `unresolved` through `messageOf` (`:121`), so the ticket's reason reaches the page with no extra code.
- **No new read.** This keeps the render to the reads it makes today. `readAttempts` is `cache`d per render (`task.ts:1655`).

### The git port must trim the way the conductor trimmed

The recorded `sha256` is of the text the conductor's `gitOrDie(['diff', ...DIFF_FLAGS, `${a}...${b}`])` returned (`packages/conductor/src/conduct.ts:1769`). That goes through `repo.git(args, { token, env, cwd })` with no `trimOutput` (`conduct.ts:1749`), and `packages/repo/src/git.ts:84` trims by default: *`return options.trimOutput === false ? stdout : stdout.trim()`*.

- **The port.** It is `@lingtai/repo`'s promise `git(args, { cwd })`, with **no** `trimOutput`, **no** token and **no** `env`. Map it to `{ ok: true, out }`, and map a rejection to `{ ok: false, why: err.message }`.
  - `git.ts:68` already sets `GIT_TERMINAL_PROMPT=0`.
  - `maxBuffer` is 32 MB (`git.ts:78`), above `runtime.budget.diff`.
- **`cwd`.** It is `mirrorPathFor(project)`, already imported in `task.ts:87`.
- **Test it.** Add a unit test with a fake runner whose output has a trailing newline. It should show that the port hands the resolver the trimmed text, which pins this rule in place.

### Memoise the git port's successes, as promises

The ticket asks for a memo keyed by `(project, from, to)`. Put it **on the git port** and key it by `cwd + '\0' + args.join('\0')`, not on the resolved value. The resolver spawns two `cat-file` calls and one `diff` per diff ref (`prompt-refs.ts:59-65`). Memoising only the diff would still spawn two processes for each diff ref on every live re-render (`apps/board/src/app/live.tsx:145`). Both answers are permanent: a commit's presence and a diff between two full shas never change.

- **Store the promise, not the value**, so two renders that overlap while an attempt is in flight share one spawn.
- **Evict on `ok: false`.** A failure is never kept. A sha the mirror lacks now may arrive with the daemon's next fetch, and the next render should try again.
- **Size.** Keep the last 64 entries, oldest evicted. The memo lives at module level in `expand-prompts.ts`, so a board restart empties it and loses nothing else.
- **What the test checks.** The *Done when* item "two renders call the fake git runner once per `(from, to)`" means once per distinct argv: one `diff`, plus the two `cat-file` calls.

### `loadAttemptTab` returns promises it does not await

Next to today's fields (`task.ts:1939-1945`), `loadAttemptTab` returns:

- **`prompt`**: `Answered<ExpandedPrompt> | null` for the implementer's prompt, built from the attempt's `promptMeta` and its `refs`.
  - Check how `state.promptMeta` is built in `reduceAttempt` and make sure it keeps the record's `refs`.
  - If it drops them, carry them through. A record without `refs` stays a plain value, not a promise.
- **`expanded`**: `ReadonlyMap<string, Answered<ExpandedPrompt>>`, keyed `` `${streamId}@${version}` ``, with one entry for each `RunPrompted` line in `events`.
  - `HistoryLine` carries `streamId` and `version` (`apps/board/src/lib/history.ts:56-57`). Find the envelope in `held` by that pair and expand its `data`.
  - `HistoryRow` looks up its own line. Lines that are not prompts are absent and draw as today.

**The promise must never reject.** Each promise is `resolvePromptRefs(...).then((values) => expandPrompt(record, values))` with a final `.catch` that returns `{ text: record.prompt, unresolved: [{ index: -1, ref: null, why: message }] }`. The `.catch` covers the one throw the resolver does not own, inside `expandPrompt` or the adapter. `Deferred`'s own doc says *"The promise must never reject: a rejection goes to the error boundary and replaces the page"* (`apps/board/src/app/deferred.tsx:24-26`).

### Drawing

- **Fallback.** `HistoryRow` and the *Prompt* section both draw through `Deferred`. The fallback is `Skeleton` with `shape="lines"` and `count = clamp(ceil(bytes / 80), 3, 40)`.
  - `bytes` here is the size of the **handed** prompt: the record's own text length, minus each marker's length, plus each ref's `bytes`.
  - Compute it in the loader as a number. Don't pass the record to the client.
- **Answer.**
  - Draw `text`. A marker that did not expand is still in place in it, because `expandPrompt` leaves it where it stood (`prompt-ref.ts:222-224`).
  - Under the text, draw one line per `unresolved` entry: *"This reference could not be expanded: \<why\>."*
  - Don't try to put the sentence inline next to its marker. After expansion the offsets in `text` have moved, and the line already names the reason.
- **The *Raw, always* comment** (`attempt-tab.tsx:156-158`) changes. The payload stays raw. What is drawn is the prompt as handed.

### The client-graph guard

`apps/board/unit/client-graph.test.ts` reads source text, the way `palette.test.tsx:129-131` does.

- **Value imports only.** Skip `import type` and `export type … from`, because `@lingtai/domain` is imported by type in client files. `prompt-ref.ts:18-19`: *"Pure, and no `node:` import: the board's client components import this package."* Hold that package to the rule too. Fail on any `node:` specifier reached through it, which a type-only skip would otherwise miss.
- **The forbidden set**: `lib/expand-prompts.ts`, `@lingtai/repo`, `@lingtai/conductor` and any of its subpaths, and `node:*`.
- **The walk.** Resolve relative and `@/` specifiers. For an extension-less specifier, try `.ts`, `.tsx`, `/index.ts` and `/index.tsx`. Stop at workspace packages, except to check them against the forbidden set and against `@lingtai/domain`'s own `node:` rule.
- **The fixture** for the "fails" case goes under the test's own directory, not under `apps/board/src`. Otherwise the real walk would trip on it.
- **Limit.** This stands in for `apps/release/integration/build.test.ts`, which is the only real check and runs after the merge (#230). The test can only claim *no value-import path exists*, and a dynamic `import()` with a computed specifier is beyond it. Say so in the test's comment.

### Edges this note decides

- **What the logs settle.** Whether a diff ref resolves on a given machine depends on `RunPrompted.refs[i].ref.from` and `.to` being in the board machine's mirror. The answer comes from `git cat-file -e`, not from reasoning about the code.
- **A malformed `refs` list.** It shows `expandPrompt`'s `'malformed refs'`, with the text unchanged (`prompt-ref.ts:245`). Nothing is added for it.
- **A v1 record with `prompt: null`.** `expandPrompt` returns `text: null` (`:238`). Keep today's sentence, and treat it as a plain value, not a promise.
