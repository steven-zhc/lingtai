'')` in place of `useState('')` (`:322`). Nothing passes it yet. The four call sites stay as they are: `standing.tsx:427,442` and `page.tsx:391,401`.

## Requeue: one button serves three moves, and only one becomes optional

The submit button in `Requeue` (`decide.tsx:264-288`) is shared by **Answer**, **Withdraw** and **Back to the queue**. All three use `disabled={!note.trim() || pending}` (`:267`). Do not delete the `!note.trim()` outright:

- **Answer** keeps it. That path is `answerCard` → `answer()` (`actions.ts:116-128`), and an answer is the decision `answersBrief` puts into every later prompt (`packages/conductor/src/attempts.ts:571-584`). A blank answer is not an answer.
- **Withdraw** and **Back to the queue** both go through `requeueCard` (`decide.tsx:275`), and both become optional. Withdraw is a requeue: "It is `requeue()`, which writes the unblock `withdrawn`" (`decide.tsx:195-198`). The server action cannot tell the two apart, so the client should not try to either.

So the rule is `disabled={(asked && !withdrawing && !note.trim()) || pending}`. Change the label on the two optional paths (`:250`) so it says the box may be left empty, for example `Why? (optional)`. Delete `actions.ts:154` outright. The docblock at `actions.ts:131-151` says nothing about the note, so it needs no edit.

## Store `''`, and say where that is done

The ticket says "a blank note is stored as empty, never invented." Today a whitespace-only note is refused before it is stored. Once the refusal goes, `'   '` would land on the log verbatim. Normalise at the one writer, `requeueHolding` (`packages/conductor/src/approve.ts:526-531`): `note: options.note.trim() ? options.note : ''`. Then the board, the CLI and Send all get the same rule.

No schema change is needed. `WorkItemUnblocked.note` is `z.string()` (`events.ts:316-320`), which accepts `''`, so nothing is rebuilt.

**An empty note never reaches a prompt**, and the reason is worth a comment where you remove the refusal:

- A requeue of a run's block folds into an `AnswerRecord` with `runId` set (`packages/domain/src/work-item.ts:352-364`).
- `answersBrief` keeps only `runId === null && question !== null` (`attempts.ts:572`).
- A requeue of a question is written `withdrawn`, and the fold keeps nothing for it (`work-item.ts:351`).

Only `answer()` produces a record that `answersBrief` keeps, and Answer still refuses blank.

**Readers of the empty note**:

- `apps/board/src/lib/history.ts:157` renders `` `${by}: ${clip(note)}` ``, which becomes `steven: ` with a dangling colon. Render `by` alone when the note is blank.
- Check `requeueCommand`'s success line in `apps/cli/src/requeue.ts` for the same thing.
