## Signatures, and what each caller hands in

- **`waitForTheLock`'s `how.ask` and `how.held` become Effect values, not thunks.**
  - Types: `how.ask?: Effect<string | null, unknown>` and `how.held?: Effect<string[], unknown>`.
  - An Effect is already lazy, so it re-runs on every poll.
  - The defaults are `lift(() => conductorLockHolder())` and `lift(() => inFlight())`.
  - Why: `prepareRestart` already holds both facts as Effects. Today it turns them back into promises through `const run = Effect.runPromiseWith(…)` (`restart.ts:1072`), and `ask: () => run(facts.holder())` / `held: () => run(facts.inFlight())` (`:1083-1084`). After this change it passes `facts.holder()` and `facts.inFlight()` directly, and `run` and its comment at `:1070-1071` are deleted.
- **`queueForTheLock`'s `how.place` and `how.holder` stay promise thunks.**
  - They are the lock library's own shape: `LockPlace.confirm(): Promise<boolean>` and `leave(): Promise<void>` (`packages/env/src/lock.ts:107-109`).
  - The ticket keeps that library a promise library.
  - `integration/service.test.ts:1095-1105` and `:1116-1123` pass them in that shape. Lift them inside with `lift` from `exit.ts:16`, never bare `Effect.tryPromise`.
  - Lifting matters because an error from `take()`, `place.leave()` or `place.confirm()` must keep its own `.message`. That message reaches *could not ask who holds the lock — …*.
- **`LockQueue` stays in `service.ts:624`, and its methods become Effects.**
  - `wait(log, retaken?, progress?): Effect<'held' | 'interrupted' | 'gave-up', unknown>`
  - `holds: Effect<boolean, unknown>`
  - `leave: Effect<void, unknown>`
  - `restart.ts` imports it as `import type { LockQueue } from './service.ts'`. `restart.ts` already imports `service.ts` (`restart.ts:96`), and `service.ts` does not import `restart.ts`, so there is no cycle.
  - `daemon.ts:94` becomes `queue: () => queueForTheLock()`, with no lift.
- **`retaken` becomes `Effect<void, unknown>`. The ticket leaves this open, and this is the decision.**

It then bridges it back to a promise with `runAsk` and `retake` (`:1481-1482`), under a comment that says this is temporary: *"An Effect here, and a promise where `LockQueue.wait` takes it (CLI-08b makes the queue one too)"* (`:1465-1467`).

## The order inside `queueForTheLock`'s `ask`

Keep it line for line (`restart.ts:1471-1489`): `holds`, then `lost`, then `leave`, then `take`, then `retaken`, then *fail*, then `holder`.

- **The lost place fails with `Effect.fail(new Error(...))`, not `throw`.** A `throw` inside `Effect.gen` is a defect. It would still be folded, but it is not what the line means.
- **`retaken`'s failure is folded into the suffix string, never propagated.** Do it the way `askAgain` already does: `Effect.catchCause` with `Cause.hasInterruptsOnly(cause) ? Effect.failCause(cause) : …`, and the message taken from `Cause.squash(cause)`. The suffix stays exactly `, and asking for the drain again failed — ${message}`.
- `holds` stays `place.lost() === null && place.held() && confirm`. Only `confirm` is lifted, so the order is unchanged: a lost place is checked before the grant, and the grant is confirmed before it is trusted.

## `waitForTheLock`'s loop

- **Keep the `for (;;)` inside `Effect.gen`.** No `Effect.repeat` and no `Schedule`: the three `interrupted` checks and the give-up check must stay where they are now (`:1397-1434`).
- **Each poll's failure is folded with `Effect.catchCause`, letting interrupt-only causes through.**
  - Message: `Cause.squash`'s `.message`. Fall back to `String(...)` for a value that is not an `Error`.
  - The sentence text stays unchanged, and so does the `failing` flag that says it once.
- **`held`'s `.catch(() => [])` gets the same treatment, answering `[]`.**
- **The poll's sleep is `Effect.sleep(pollMs)`. Keep `Date.now()` for `began` and `said`; do not move to `Clock`.**
  - No test uses `TestClock`.
  - `steps.test.ts:163-172` runs on real time and expects the listener in place within 30 ms.
- **Wrap the whole loop in `Effect.scoped`, with `Effect.acquireRelease(Effect.sync(() => process.on('SIGINT', onSignal)), () => Effect.sync(() => process.off('SIGINT', onSignal)))`.**
  - `onSignal` only sets `interrupted`, as today.
  - No `Effect.interrupt` in it, no `NodeRuntime.runMain`, no Effect-level SIGINT handler.
  - Releasing in the scope covers all four exits: free, interrupted, gave up, and the fiber interrupted from outside.
  - Removing the listener is what lets a second Ctrl+C reach Node's default.
