## Shape for #1464: Queued's counts move to one foot line

### Where it goes

All of it is in `QueuedAnswered` (`apps/board/src/app/queued-stream.tsx:456-488`) and in the `HeldFold` component it draws.

`HeldFold` can't stay a sibling that gets drawn after the counts. When anything is held, the `<summary>` has to hold the whole sentence, so the runnable and blocker counts must end up inside the `<details>`.

- Turn `HeldFold` (`:79-121`) into one component that owns the whole foot. Call it `QueuedFoot`.
- It takes `runnable`, `waiting`, `held`, `epics` and `showProject`.
- It returns one of three things, in the order the ticket gives:
  - the `<details className="heldfold qfoot">`;
  - a `<p className="qfoot">`;
  - `null`.
- `HeldRow` (`:60-72`) and the `<ul className="heldlist">` body (`:105-117`) move into it unchanged.
- Rewrite its doc comment. Today it says *"The foot of Queued (#955): tickets a person holds and epics with nothing queued, folded into one closed line"* (`:74-78`). It should now name #1464 and say the line also carries the runnable and blocker counts.

In `QueuedAnswered`:

- Delete `summary` (`:437-454`) and the `unread` line (`:481`).
- Keep `unread` itself (`:433`) only if something else still reads it. Today nothing else does, so delete the variable too.
- `waiting = github.blocked.length` (`:431`) already counts the unread skips. Pass it as it is.
- `drawn` (`:432`) still decides which skips get a card.
- Draw the foot where `<HeldFold …/>` is now (`:482-486`). That is after the list or `{empty}`, which keeps `{empty}`'s condition at `:467` unchanged (it still reads `waiting === 0`).

### The decision that isn't in the ticket: which epics count

Pass the epics **after** the `headed` filter, as `:484` does today:

```ts
github.epics.filter((e) => !headed.has(`${e.project}#${e.ref}`))
```

An epic that heads a group in the list (#956) is already drawn there. Counting it in the foot would count it twice. The same filtered list also decides whether there is a part 3 at all. So a column whose only epics are headed gets a `<p className="qfoot">`, not a `<details>` with nothing to open.

### How the sentence is built

- Build parts 1 and 2 exactly as today's `summary` does. Part 1 says `nothing runnable` only when `runnable === 0 && waiting > 0`. When both are 0, part 1 is absent.
- Put ` · ` between parts as a text node, outside the marker span. The ticket's Want reads `… blocker · ▸ 11 held`, so the dot comes before the triangle.
- Wrap part 3 in one span, e.g. `<span className="qheld">`. It holds today's held/epics wording plus `<span className="hw">· a person lifts it</span>`. Keep the markup between `<b>2</b> held` and `</span>` byte for byte, because the tests match on it (`unit/queued-stream.test.tsx:317,327-328`).
- Render the same parts in both branches, so the `<p>` and the `<summary>` can't drift apart. One inline helper producing parts 1–2 is enough.

### Tests (`apps/board/unit/queued-stream.test.tsx:286-333`)

Rewrite the tests in place. Don't add a new `describe`.

- **No count text above the cards:** in an output with one runnable card and one blocked skip, assert `out.indexOf('qfoot') > out.indexOf('q-blocked')`. Also assert `out` has no `qsum`.
- **Runnable only:** `draw({}, 2)` should give `<p class="qfoot"><b>2</b> runnable</p>`. This replaces the `</p>` check at `:291`.
- **Nothing at all:** `draw({})` contains neither `qfoot` nor `heldfold`, and still contains `EMPTY`.
- **Unread skips** (`:296-308`): the output contains `<b>3</b> waiting on a blocker` and does not contain `more waiting on a blocker`. `q-blocked` still appears exactly once.
- **Held** (`:310-325`): the output contains `<details class="heldfold qfoot">`, with the "not open" regex adjusted to the new class string. Keep `indexOf('heldfold') > indexOf('EMPTY')`.
- **Add one case: blocked and held together.** This is the only case where part 2's ` · ` meets part 3. Assert that the `<summary>` contains the runnable/blocker text and the `<b>…</b> held` text, and that the marker span sits between them.

`renderToStaticMarkup` (`:8,42`) puts no comment nodes between adjacent text nodes, so the joined strings can be matched as written.
