## The decision: the recovery is done, and the diagnostics have to get smaller

Read the three commit bodies in order. Every review round since round one has been about **where the refusal says it stopped**, not about whether a repair is safe:

- trimmed versus untrimmed ends
- a fenced block's trailing newline
- the `offset === 1` identifier heuristic
- `gapAt`/`gapLength`

`tolerant-json.ts` has not been wrong since `d0a628c`. Its header states the contract in one sentence: *"the same candidates, the same extent rule as `JSON.parse`, and only the listed repairs on top."* The string scanner never consults the repair table, and that keeps a quoted `：` safe.

So **do not grow the diagnostic machinery to answer another finding. Shrink it.** The concrete cut is below. Any new finding about an offset should be fixed by removing a special case where you can, not by adding one.

### Delete `gapAt`/`gapLength` and `globalOffset`. Drop the fenced candidate rather than glue onto it

`candidatesIn` (`agent-action.ts:397`, on `agent/318`) has a special case at `:415`. When text after a closing fence contains `{`, it pushes `stripped + trailing`. That glued candidate is shorter than the span it came from, which is why `Candidate` needed `gapAt`/`gapLength` (`:361-376`) and `globalOffset` (`:380`). Here is what the glued candidate can do:

- **Strict loop:** `JSON.parse` never accepts it. The trailing text has a `{` in it, so it is never just whitespace.
- **Tolerant loop, fenced value complete:** it fails the extent rule with `trailingValue` set, and `:580` skips it.
- **Tolerant loop, fenced value broken:** it fails at a byte. If that byte is past the fence, the glue is the only reason the offset needed fixing up.

Now take the alternative: **when the text after the fence contains `{`, push no fenced candidate at all.**

- The brace candidate that starts at the fence's own interior `{` already contains the closing ```` ``` ```` and everything after it, as a real contiguous slice.
- Both loops refuse that candidate exactly as they refused the glued one.
- Its failure offsets are `start + local`, with nothing added back.

The finding-3 sequence from `f6357ec` still behaves correctly: a fenced findings-shaped example, then a broken real answer. The example's fence is skipped because a `{` follows it. Its brace candidate fails on the closing backticks. The real answer is reached on its own candidate.

After this change, `Candidate` is `{ text, start }` and every offset is `candidate.start + local`. Keep `cb6f78b`'s `trimEnd()` reasoning, because it still applies to the fenced case that has no trailing `{`.

Tests:

- Keep `cb6f78b`'s fixtures for this case: the fenced answer followed by an ordinary closing sentence, and the fenced example followed by a broken answer.
- The assertion on the reported offset must still name the same character in the original text. That is the claim `gapAt` existed to make true.
- If a test asserts on `gapAt` itself, delete it along with the field.
