# Design: #658, a fetched LiteLLM snapshot behind the shipped rate card

## The decision the ticket leaves implicit: two lists, never concatenated

`rateFor` (`packages/domain/src/rate-card.ts:54`) takes the latest `from` among every row that matches the model: *"The row in force for `(model, mode)` at `at` — the latest `from` on or before it"*. If snapshot rows are appended to `RATE_CARD` and the merged array is handed to `priceRow`, a snapshot row dated `2026-11-02` beats a shipped row dated `2026-06-24` for the same model. That breaks **the built-in card always wins**, and no type error would catch it. So "pass the merged card" is built as follows.

- Add `shipped(model)` to `rate-card.ts`. It is true when `RATE_CARD` has **any** row for the model, at any mode or date. It is used in two places:
  - the fetcher uses it to decide which models to ask LiteLLM about;
  - pricing uses it to decide, one usage entry at a time, which list to call `rateFor` on. A shipped model uses `RATE_CARD` only. Any other model uses the snapshot rows only.
- One consequence is accepted, not fixed. Suppose a release later ships a row for a model the snapshot already priced. Runs from before that row's `from` become *unknown* again rather than snapshot-priced. That is what "the built-in card always wins" says.
- Add `estimateRow(row, snapshot) → { usd: number; fetched: boolean } | null` beside `priceRow`. `fetched` is true when any entry was priced from the snapshot. Leave `priceRow(row, card)` (`:91`) and its tests as they are. The flag is what makes the labelling possible; a bare `number` cannot carry it.

## `RateRow` (`rate-card.ts:22`)

- `source?: string`: the URL. Set on snapshot rows only.
- `reasoning?: number`: set only when `output_cost_per_reasoning_token` is present. `priceTokens` (`:69`) charges reasoning tokens at `row.reasoning ?? row.output`. Shipped rows have no such field, so they price exactly as today. That function's doc comment ("summed before multiplying … because they are the same rate") changes with it.
- `cacheRead` / `cacheWrite`: `number | null` on snapshot rows. A null rate makes an entry *unknown* **only when that entry has tokens of that class**. A run with no cache-read tokens still prices.
- A null, missing, negative or non-numeric input or output rate means no row is written. So does a value above $1,000 per million for any rate. That model is listed as rejected for `doctor`.

## Where the code goes

**`packages/domain/src/rate-card.ts`** holds pure functions only. It stays out of `index.ts` (`:12`: *"a price function must stay out of a reducer's reach"*).

- `ratesFromLiteLLM(table: unknown, wanted: { model; provider }[], day) → { rows, rejected }`.
  - Look up `table[model]` directly, then require `litellm_provider === provider`.
  - **Never iterate the table's keys.** That makes a prefix match impossible by construction rather than by care.
  - The provider map is `{ codex: 'openai', 'claude-code': 'anthropic' }`. A runtime missing from the map asks for nothing.
- `mergeSnapshot(previous, fetched, day) → rows | null`, applied per model:
  - rates equal to the latest row → nothing;
  - the latest row's `from` is `day` → replace that row;
  - otherwise → append a row.
  - Return `null` when nothing changed, and then nothing is written.
  - The replace rule matters beyond the ticket's wording: `rateFor`'s sort gives no order between two rows with the same `from`.

**`packages/env/src/rate-snapshot.ts`**, exported as `@lingtai/env/rate-snapshot`. File I/O belongs in this package: `stateDir()` (`packages/env/src/index.ts:1054`) is where `~/.lingtai` is resolved. It manages two files, each written temp-then-`rename`:

- `stateDir()/rates.json` holds `{ rows: RateRow[] }`. This is the snapshot, and it is written only when `mergeSnapshot` returns non-null.
- `stateDir()/rates-fetch.json` holds `{ at, ok, error?, rejected[] }`, the last attempt. It is separate because *a failed fetch leaves the previous snapshot byte-for-byte unchanged*, yet `doctor`, in another process, must still say `rates: last fetched <date>, <error>`. It is not a second snapshot, and nothing orders the two files. The writer is the same one process.

`readRateSnapshot()` reads synchronously on every call, so a running daemon sees a new snapshot without a restart. "Holds the code it started with" is about code, not data.

**It takes the same guard as `machineFilePath`** (`index.ts:105-107`: `if (!ownHome && (inTest(from) || inTest(process.env))) return null`). Under vitest, with no `LINGTAI_HOME` of its own, it reads `[]`. Without the guard, every `daySpend`/`billOf` test on the default pricer would read the developer's real `~/.lingtai/rates.json`. A file that is absent or malformed also reads `[]`, never a throw.

**`apps/cli/src/rates.ts`** holds the refresher. Both conductors live in `apps/cli`, so it can be one module there.

- `refreshRates(wanted, ports)` takes `fetch`, `read`, `write` and `now` as ports. The real fetch sits behind `AbortSignal.timeout(10_000)`.
- A thrown error, a non-200 status or invalid JSON writes only `rates-fetch.json`.
- The single in-flight promise is a module-level `let inflight: Promise<…> | null`, cleared in `finally`. A second caller gets the same promise back.
- With ports injected, every Done-when test is **unit**: no temp directory, no network (CLAUDE.md, #225). The pure parts' tests go in `packages/domain/unit/`. The in-flight test (*two refreshes together → one fetch, one write*) goes in `apps/cli/unit/`.

## Which models, and when

- **Which models:** the distinct `(runtime, usage[].model)` pairs. They come from `readSpend` rows, where `runtime` is on `SpendRow` (`packages/projector/src/spend.ts:216`), plus the model each project's recipe names. The daemon already sees every recipe through `onRecipe` (`apps/cli/src/daemon.ts:565`). Filter the pairs through `!shipped(model)`. A failure to read `spend` is treated like a failed fetch: record it, change nothing.
- **When:** at conductor start, and before each pass when due. "Due" means `rates-fetch.json` is absent, or its `at` falls before today's UTC day. A failed attempt counts as the day's attempt, so a down GitHub costs one try a day, not one a pass.
  - **Daemon:** start the first refresh after the lock is held, next to `loop.start()` (`daemon.ts:596`). Do not await it before taking work.
  - **`lingtai run`:** start it after `yield* ConductorLock` (`apps/cli/src/run.ts:320`).

## The edge the ticket's single-writer argument depends on

**One writer holds only while the write lands inside the lock-holding window.** `lingtai run` takes a pass and releases the lock at the end of its scope (`apps/cli/src/conductor-lock.ts:83`). A refresh still in flight after that can rename over a daemon that took the lock a second later. The daemon has the same problem on shutdown.

So each conductor **awaits `inflight` before its lock is released**:

- `run`: inside the `Effect.gen` scope, before it closes;
- daemon: on its drain path, before it exits.

The 10s timeout bounds the wait. This is not a lock and not ordering between fetches; it only keeps the fetch inside the existing exclusion. A crash mid-write leaves at most a temp file, and the next write overwrites it.

## Callers and labelling

- **The two default pricers.** Change `daySpend`'s default `price` (`packages/conductor/src/day-ceiling.ts:44`) and `billOf`'s (`apps/board/src/lib/spend.ts:136`) to use `estimateRow(row, readRateSnapshot())`. Read the snapshot once per call, not once per row. Every surface follows:
  - `dayCeilingPause` (`:169`);
  - `apps/cli/src/day-ceiling.ts:116` (`status`);
  - `apps/board/src/lib/day-spend.ts:22`;
  - the board and task pages through `billOf`.
  
  Keep the `price` parameters, because tests inject them.
- **Counting.** `DaySpend` gains `fetchedRuns` and `Bill` gains `fetched`. Either is the number of estimated runs with at least one snapshot-priced entry.
- **The label.** When the count is above zero, the estimate reads `~$99.12 est. (91 at fetched LiteLLM prices)`. Apply it in three places:
  - `daySpendText` (`day-ceiling.ts:80`);
  - the board's short form, which builds its own string (`apps/board/src/lib/day-spend.ts:23-29`);
  - `billText` (`spend.ts:175`).
  
  At zero the text is byte-identical to today's, so every existing exact-string assertion stays green.
- **The client-bundle risk.** `spend.ts` will import `@lingtai/env`. Only `apps/release/integration/build.test.ts` would see that reach a `"use client"` graph (#230), and `pnpm test` cannot. Check that `spend.ts`'s importers carry no `'use client'`.

## `doctor`

- One `rates:` line, read from the two files:
  - the last fetch's date;
  - `ok` or the error;
  - each rejected model by name.
- A **note, not a failure,** when the snapshot holds any `openai` row: *estimates from per-token prices are not a ChatGPT plan's bill*. Nothing in the code detects a plan today; the only mention is a comment in `packages/agent/src/codex.ts:222`. So the note is conditional in its wording rather than detected.
- Absent files read as *never fetched*. On an offline machine that is the same unknown as today.
