# #517: design note

The ticket already gives the shape, and this note does not repeat it. It covers three points the ticket does not settle.

## 1. Keep `TriageAdvice` tied to `Resolution`

`Resolution` is defined at `packages/domain/src/wait.ts:200`:

`z.discriminatedUnion('_tag', [Approve, Requeue, EditBodyAndRequeue, AnswerQuestion, Close])`

Write `TriageAdvice` as the `z.enum([...])` the ticket names, placed next to `Resolution`. Add a type-level check so the two lists cannot drift apart:

```ts
export const TriageAdvice = z.enum(['Approve', 'Requeue', 'EditBodyAndRequeue', 'Close'])
export type TriageAdvice = z.infer<typeof TriageAdvice>
// a Resolution tag added later must be added here or excluded here on purpose
type _ = AssertEqual<TriageAdvice, Exclude<Resolution['_tag'], 'AnswerQuestion'>>
```

If the package has no `AssertEqual` helper, a pair of `satisfies` checks in each direction will do, or put an equivalent `expectTypeOf` in `wait.test.ts`. Do not build the list as `Resolution.options.filter(...)`: that loses the literal types.

The doc comment should say why `AnswerQuestion` is left out. The choice belongs to the person answering, and triage cannot make it for them. It should also say why the value is a bare tag: the `onSha` on an `Approve` is the head when the person approves, not something triage knows (0118 §1).

Once `TriageAdvice` is used, `recommendedResolution` (`wait.ts:458-460`) still type-checks with `advised = status.result.resolution`. `TriageAdvice` is a subtype of `Resolution['_tag']`, so `allowed.includes(advised)` compiles without a cast. If it asks for one, the type check above is wrong.

## 2. Keep the `Usage` import in `events.ts`

`events.ts:23` imports `Usage`, and `:734` (the `RunSpent` usage field) still uses it. Removing `usage: Usage.optional()` at `:1852` must not remove the import. Lint will not flag it as unused, because the import is still used.

The doc comment at `:1855` on `TriageMechanical` says "so there is no spend to record". After this change neither variant records spend, so reword it: "Lingtai answered without an agent (#414); no `RunSpent` follows." The `TriageStartedAgent` comment (`:1863-1866`) explains its strictness by contrast with `TriageAgent`. Once the two have the same shape, cut that to say only that it is strict.

## 3. Correct the prose in `spend.ts`

`packages/projector/src/spend.ts:5-9` reads:

> "`RunFinished`, `FixApplied`, `DiscussionAnswered`, `DiscussionHeld` and `TriageAgent` are the old places a cost briefly lived or still lives for another reason".

After this change `TriageAgent` holds no cost at all. Drop it from that sentence, or say it no longer holds one. Leave the matching row in `spend-rebuild.test.ts:345` alone: the test removes comments before it asserts (`:341-343`), so it stays green whatever the comment says. The row still has a purpose, because `TriageAgent` is still an exported name a later edit could reach for.

## Nothing else reads these types

`git grep` across the repo, excluding `doc/`, finds `TriageAgent`, `TriageAdvised` and `TriageStatus` only in:
- `packages/domain` (`events.ts`, `wait.ts`, `triage.ts` comments, `unit/wait.test.ts`);
- the `spend.ts` comment and test above;
- `apps/board/src/lib/history.ts:507`;
- a comment in `packages/conductor/src/step-outcome.ts:176`, which mentions `recommendedResolution` but not its shape, so it needs no edit.

`history.ts:507` currently reads:

``${result.cause._tag} → ${result.resolution._tag}: …``

It becomes `${result.resolution}`. The `WaitTriaged` renderer is the only caller the ticket's "the one caller each change forces" refers to.
