# #1498: one address shape under `/p/<project>/…`, and old URLs answer 308

## Where it goes

- **`apps/board/src/lib/paths.ts` (new).** It builds every board address. It is pure and client-safe, like `remember.ts`. The "Pure, with no `next/*`, `node:` or `@lingtai/*` value import" rule (`remember.ts:3-4`) relaxes here to allow `@lingtai/domain`, which the ticket permits. `tabs.ts:17-36` (the four path functions and `tabPath`), `landedHref`/`landedLink` (`landed.ts:66-79`), `pr-board.ts:295` and `pr-detail.tsx:18-19` move into it. `tabs.ts` keeps only the tab rules (`defaultTabOf`, `visibleAttempts`, `tabOfFragment`, `attemptOfSegment`).
- **`legacyRedirect(pathname, search): string | null`.** It lives in a new file `lib/legacy.ts` beside `remember.ts`. It returns the new address, query included, or `null`. It builds its targets through `paths.ts` only.
- **Route folders move.** Use `git mv`, so the history follows the files:
  - `app/task/[id]` → `app/p/[project]/ticket/[n]`
  - inside it, `ticket/` → `history/` and `attempt/[n]` → `attempt/[k]`
  - `app/pr/[project]/{page,[n]/page}.tsx` → `app/p/[project]/pr/{page,[n]/page}.tsx`
  - `app/recipe/[project]/*` → `app/p/[project]/recipe/*`
- **New pages:**
  - `app/p/[project]/page.tsx` (the redirect)
  - `app/p/[project]/ticket/page.tsx` (project home)
  - `app/p/[project]/ticket/landed/page.tsx`
  - `app/p/[project]/backlog/page.tsx`
- **Unit tests that import these modules by path** must follow the moves. Today's importers of `app/page` include `projects.test.tsx`, `task-page.test.tsx`, `home-streams.test.tsx` and `bar.test.ts`. Grep `apps/board/unit` for `app/task/`, `app/pr/` and `app/recipe/` too.

## Decisions the ticket leaves open

**1. Attempt segment `[n]` becomes `[k]`.**
- Next will not allow two params named `n` on one path.
- `MEASURED_ROUTES` must name the folder exactly: `/p/[project]/ticket/[n]/attempt/[k]`.
- The attempt page reads `k` and keeps `attemptOfSegment` (`tabs.ts:122`).

**2. Route params become a task id in one place.**
- `paths.ts` exports `ticketIdOf(project: string, n: string): string | null`.
- It does `decodeURIComponent` once, with a `try`. It requires `n` to match `/^[1-9]\d*$/`, the same rule as `attemptOfSegment`. It then returns `ticketStream(project, n)`.
- The layout and each of the four pages call it and `notFound()` on `null`. The pages read `params` separately from the layout today (`page.tsx:21`, `ticket/page.tsx:21`, `sandbox/page.tsx:42`, `attempt/[n]/page.tsx:19`), so the check cannot live only in the layout.
- After that, `knowable(taskId)` (`layout.tsx:254`) still decides the 404 for an unknown project, unchanged.

**3. `paths.ts` takes a ticket ref, not a task id.**
- Builders take `{ project, issue }`:
  - `ticketPath(ref)` and `tabPath(ref, key)`, where key `'ticket'` builds `/history`
  - `sandboxTabPath(ref, attempt?)`
  - `prPath(project, n?)`, where `n` is a number or `'next'`
  - `recipePath(project)`
  - `homePath(project | undefined)`, which builds `/` or `/p/x/ticket`
  - `landedHref(q)`, which builds `/p/x/ticket/landed?…` when a project is set, else `/landed?…`
  - `backlogPath(project?)`
- Most sites already hold both halves: `card.project`/`card.ref`, `entry.project`/`entry.issue`, `t.project`/`t.issue` in `search.ts:152`, `r.project`/`r.issue` in `standing.tsx:164`.
- Sites that hold only a stream id go through `ticketRefOf(id)`, which is `parseTicketStream` (`streams.ts:37`):
  - `report/panels.tsx:416,777,847`, where `issueOf(p.ticket)` already parses
  - `layout.tsx:100` (`n.taskId`)
  - `decide.tsx:1123`
  - the `actions.ts` revalidations
- A `null` ref renders the `#n` as text with no link, and skips the revalidation. The old link went to an address that 404'd (`layout.tsx:250-251`: *"an id that is not `ticket-<project>-<n>` … 404"*).
- The layout passes its ref to `RecordTabRow`, so the fragment translator (`record-tab-row.tsx:100-102`) calls `tabPath(ref, tab)` without re-parsing.

**4. One page body per view; the path names the project.**
- `app/page.tsx` already exports components besides its default (`Card`, `Landed`, … at `:205-665`). Its default body (`:1213`) becomes `export async function Home({ project }: { project: string | undefined })`.
- `app/page.tsx`'s default renders `Home({ project: undefined })`. It no longer reads `searchParams.project`, because the proxy never lets `?project=` reach it.
- `p/[project]/ticket/page.tsx` renders `Home({ project: decoded })`.
- Landed works the same way. `landed/page.tsx:33-44` becomes `LandedBody({ project, params })`, and the project route passes `{ ...params, project }`. A path segment always wins over a stray `?project=`.
- Backlog filters `entries` by `entry.project` before the `owed` split (`backlog/page.tsx:79-82`), and passes `project` to `Bar`/`LockBanner`, which take `undefined` today (`:86,97`).
- `Home` keeps its `projectKey` keys (`page.tsx:1229`). Switching projects is now a navigation between two values of `[project]` rather than within `/`. The keys still hold for a live re-render, and are harmless otherwise.

**5. `/p/<project>` uses `redirect()` (307), not `permanentRedirect`.**
- That address is new, not legacy. A 308 there would pin browsers if the project root ever becomes a page of its own.
- This is the same reasoning as the ticket's 307 rule for `/`.

**6. Proxy order and what `homeRedirect` becomes.**
- `proxy.ts` calls `legacyRedirect(nextUrl.pathname, nextUrl.searchParams)` first and answers **308** on a hit.
- Only then, for `pathname === '/'`, does it call `homeRedirect` and answer **307**.
- `homeRedirect` (`remember.ts:20-27`) returns `homePath(remembered)` plus the remaining query for a non-empty remembered name, and **`null` otherwise**. Today a missing cookie redirects to `/?project=` (`remember.ts:23-26`); now `/` itself is all projects.
- Keep its `search.has('project') → null` guard. It is unreachable from the proxy, but it keeps the function total and `remember.test.ts`'s case meaningful.
- The matcher is the six patterns the ticket lists, and must not include `/p/:path*`.

**7. "All projects" now links to `/`, which depends on the cookie, so its `ProjectLink` gets `prefetch={false}`.**
- Today the all-projects link is `/?project=` (`projects.tsx:88`, `place-line.tsx:44`). It bypasses the proxy's cookie check (`remember.ts:21`), so prefetching it was harmless.
- After this change it is `/`, and the proxy answers `/` from the cookie the request carries. A `<Link>` prefetch made while the cookie still names `x` can be answered with the 307 to `/p/x/ticket` before the click rewrites the cookie (`project-link.tsx:18-20`).
- In `ProjectLink`, pass `prefetch={false}` when `choice === undefined`. The project links target `/p/<name>/ticket`, which reads no cookie, so they keep prefetch.
- No unit test can see this; Next's prefetch only runs on a running board. It goes into the by-person check: with a project remembered, click *all projects* and land on `/`.

**8. `legacyRedirect`'s rules beyond the map.**
- Decode the `/task/<id>` segment once with a `try`; a failure is `null`. Then use `parseTicketStream`, and require an integer issue.
- The only `/task/<id>` sub-paths that redirect are:
  - nothing → the ticket page
  - `/ticket` → `/history`
  - `/attempt/<k>` → `/attempt/<k>`
  - `/sandbox` → `/sandbox`
  - anything else under it → `null`
- `/pr/<project>[/<seg>]` passes `<seg>` through as it is, because the new `pr/[n]` page validates it exactly as the old one did. Deeper paths → `null`. `/recipe/<project>` with anything after it → `null`.
- `project` is read with `search.get` and every `project` key is deleted.
- An **empty** `project` on `/landed` or `/backlog` 308s to the bare global page, other params kept. This matches `/?project=` → `/`, and `landedQuery` already reads `''` as all (`landed.ts:60`).
- Serialize like `remember.ts:26` (`+` → `%20`), so a `before` cursor survives unchanged.

**9. Revalidation.**
- Each `/task/…` revalidation (`actions.ts:234,277,329,863,912,960,1053,1086`) becomes `revalidatePath(ticketPath(ref))`, and `:1172` becomes `recipePath`. Note `:234,277,329` do not encode the id today.
- The bare `revalidatePath('/')` calls (`:185,235,…,1087`) revalidate only the all-projects page, and the project home is now a different route.
- Replace them with a local `revalidateHome()` in `actions.ts` that also calls `revalidatePath('/p/[project]/ticket', 'page')`.
- Leave the `('/', 'layout')` calls (`:685-804`) as they are; they already cover every route.

**10. Telemetry.**
- `MEASURED_ROUTES` (`telemetry.ts:63-69`) keeps `'/'` and adds `/p/[project]/ticket` plus the four ticket patterns.
- `/ticket/landed`, `/pr` and `/recipe` stay unmeasured, as they are today.

## What nothing verifies before the merge

- `tsc` and `pnpm test` cannot tell whether Next accepts the new tree: the static `ticket/landed` beside `ticket/[n]`, the param names, and the non-default exports from page modules. Only the Next build sees that (`apps/release/integration/build.test.ts`, run after the merge).
- The unit-level stand-in is `paths.test.ts` round-tripping every builder against `ticketIdOf` and `legacyRedirect`. That means `legacyRedirect(old) === builder(…)` for each map row, and `ticketIdOf` of the built segments gives back the stream id, including `chapter-garden`.
- `0101-typescript-packages-effect-unbuilt.md:149` names the measured routes as *"`/`, `/task/[id]` and its tabs"*. That is a description rather than a decision about URLs, so it goes to the docs ticket with the other prose, and this change edits no ADR.

## What the work costs later tickets

All path literals in `apps/board/unit` should come from `paths.ts`, except in `paths.test.ts` and `legacy.test.ts`, which state the literals once. Tickets ② and ③ then change hrefs without touching a test that only quoted a URL.
