# #1504: design note for the prefilled pr-fix form

## Where it goes

`prFixTicketLink` (`apps/board/src/lib/pr-page.ts:63-84`) stays the one place that builds the link, and it stays pure. It reads no IO, so the Effect ratchet is not touched. Its input keeps `name` and gains `pr: PrState | null`. The function reads every fact it needs from that state. The callers do not compute a wait and hand it in.

**There are four call sites, not the two the ticket names.** Every one of them must pass `pr`, or it will build the old empty form without a word:

- **The PR page:** `pr-page.ts:623`. It already has `pr`.
- **The board, `apps/board/src/lib/prs.ts:185-202`.** `pr-board.ts:291-294` only declares the field. The link is built in `prs.ts`, by the `fixHref(name)` closure, and it is called two ways:
  - `newFixFor: (pr) => fixHref(prName(pr))` should pass `pr`.
  - `newFixHref: fixHref(null)`, with the name `'the PR'`, is the fallback for every PR. It passes `pr: null` and gets the empty table.
- **The task page, `apps/board/src/lib/task.ts:1080-1081`** (`changeOf(pr)`, used at `:1137`). It has `pr` and passes it. That PR is usually not waiting, so it gets the "no wait" body.

## Read the wait from `PrState`, not from `prWaitOf`

The ticket says the page "already reads the wait (`prWaitOf`)". But `PrWaitView` (`packages/domain/src/pr-wait.ts:52-59`, `kind: 'plain'`) leaves out `headSha` and the checks. So read these from the state:

- **The wait is `pr.wait`.** It is the whole `PrWaiting` payload: `step`, `reason`, `detail`, `headSha` (`packages/domain/src/events.ts:2671-2678`; reduced at `packages/domain/src/pr.ts:509-512`).
  - It counts only when `pr.status === 'waiting' && pr.wait !== null`. That is the same test `prWaitOf` makes (`pr-wait.ts:90-91`: *"The view of a waiting PR, or null when it is not waiting."*).
  - In any other case the body is the empty table. Never write a failure from a `wait` left over after the PR moved on.
- **The failing checks come from `pr.checks`,** the last `PrChecked` (`pr.ts:76-77`: *"what the PR page and `lingtai pr` draw the CI line and the failing checks from"*).
  - Do not split `wait.detail` back into checks. It is a `"; "`-joined string (`packages/conductor/src/pr.ts:521-522`, `:636`), and a check name can contain `;` or `(`.
  - Pick the failing checks the way `failingRun` already does (`apps/board/src/lib/pr-board.ts:208-216`): the rows flagged `failing` when any is flagged, otherwise every row not in a passing or pending state. Move that filter into one exported `failingChecks(pr)` and have `failingRun` call it. Then the *Open the run ↗* button and the form's list cannot disagree.
  - Use the list only when `pr.checks.headSha === pr.wait.headSha`. For `ci-red` the conductor records `PrChecked` before the wait, on the same head (`conductor/src/pr.ts:623-637`). If the heads differ, the list is from another head, so drop it and leave only the `detail` sentence. The ticket says *never a guessed failure*.
- **The head** is `wait.headSha` when waiting, otherwise the last checked or followed head (`checks.headSha ?? following`, since someone else's push moves the head past `lastPushed`), then `lastPushed ?? target` (`pr.ts:41-49`). Shorten it to seven characters.
- **The branch** is `pr.prBranch` (`pr.ts:37`). When it is null, leave the branch phrase out. Do not print `<pr-branch>` (that is `commandsFor`'s placeholder, `pr-wait.ts:75`).

## Wording for waits other than `ci-red`

Problem: `<WAIT_WORDS[reason]> on PR #8 (head 296d90c): <detail>.` `WAIT_WORDS` is at `pr-board.ts:138`. Want is left empty, because only `ci-red` has an obvious one. The title is `pr-fix for PR #8: <WAIT_WORDS[reason]>`. No wait: the title stays `pr-fix for PR #8: `, as today.

## The decisions the ticket leaves open

1. **Measure the limit on the encoded URL, not the body.** `encodeURIComponent` turns `(`, a space or a newline into 3 characters each, so a 3,000-character body can be a 7,000-character URL.
   - Build the URL with the fixed parts first, including the table and the PR line.
   - Then add checks one at a time while `url.length + encodedLength(moreLine) < 8000`. Here `moreLine` is the `- … and N more on the PR page` line, and it is always held back for.
   - If the last check still fits, no "more" line is written.
2. **"The PR page's link" is `pr.host.url`, GitHub's pull request.** The board's own `/p/<project>/pr/<n>` page is a localhost address. The agent that reads the issue cannot open it, and this pure function does not know the board's origin anyway. Every CI wait needs a GitHub PR, so `host` is set whenever there is a list to cut. If it is null, the line has no link.
3. **The title and the Problem row name at most three checks, then `, and N more`.** As written in the ticket, they list every name. With forty failing checks that alone could pass the limit, and GitHub cuts titles at 256 characters. The full list goes only in Evidence, where the budget in (1) limits it.
4. **Escape every value placed in a table row.** A check name or a `detail` (a conflict's, or `several-open`'s list of URLs at `conductor/src/pr.ts:516`) can hold `|` or a newline, and that breaks the four-row table.
   - Replace `|` with `\|` and newlines with spaces. Cut `detail` at about 500 characters with `…`, so the fixed part cannot fill the budget on its own.
   - This matters for more than looks: the task page reads the four rows, and *"shows an unrecognised table as a link only (0118 §2)"* (CLAUDE.md, *Opening an issue*).
5. **A check whose `url` is `''`** (the schema allows it, `events.ts:2740`) gets the line `name — state`, with nothing after it. This is the same rule as `failingLine` (`conductor/src/pr.ts:522`).

## The comment and the ADR

Rewrite `pr-page.ts:59-61`. Today it says *"the body is the agent's prompt and the person writes it"*. It should say the board fills in what it knows, and the person reads it, adds what only they know, and submits it. *"The board creates no issue"* stays.

This builds on ADR 0130 §5 (*"opened from the PR's page the label is put on for the person"*) and does not contradict it. So no ADR changes.

## Tests

  - The old title assertion (`'pr-fix for PR #88: '`) still holds for the no-wait case.
  - Decode with `new URL(href).searchParams.get('body')`. That decodes the way GitHub will, so the tests never compare against an encoded string.
- Add one case for heads that do not match: `pr.checks.headSha !== pr.wait.headSha` gives no check list.
- Add one case for a `|` inside a check name.
