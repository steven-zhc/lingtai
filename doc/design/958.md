## Design note for #958: board screenshots in the hero, receipt moved down to the replay

The ticket describes most of the shape. This note covers three decisions it leaves open and one fact about the worktree.

### 1. `imageType` does not live in `route.ts`

Put it in its own module, `apps/site/src/lib/doc-images.ts`, and import it into the route and the unit test.

A Next route file may only export the names Next knows about. Today `apps/site/src/app/img/docs/[name]/route.ts` exports `dynamic`, `dynamicParams`, `generateStaticParams` and `GET`, and nothing else (`:15-25`). `next build` checks a route module's exports against that list; `next` is `16.3.3` (`apps/site/package.json:18`). An extra `export function imageType` passes `tsc --noEmit` (`apps/site/package.json:11`) and passes `pnpm test`. It then fails only in the Next build, and that build runs after the merge. CLAUDE.md says that build is "the only thing that sees a server-only import reaching a `"use client"` graph — `tsc` cannot", and #230 is that failure caught late.

What changes in the route:
- `generateStaticParams` (`:22`) filters with `imageType(name) !== null`.
- `GET` (`:28`) returns 404 when `imageType(name)` is null.
- It uses that same value as the `Content-Type`.

The pattern only gains an extension. The stem stays `[a-z0-9-]+`, so the refusals listed in the ticket hold: `../a.png`, `a/b.png`, `a.gif`.

**Reading bytes.** Drop `'utf8'` at `:29` so `readFile` returns a `Buffer`. Under TypeScript `^5.9.3`, `new Response(buffer)` may be refused: a `Buffer<ArrayBufferLike>` is not a `BodyInit`. If `pnpm typecheck` says so, wrap it as `new Uint8Array(buffer)`. Do not cast it.

### 2. Render all four pictures, and hide three

The shots component renders four panels. Each panel is an `<a href="/img/docs/shot-<name>-full.png">` around its `<img width="1440" height="600">`, followed by its caption. Every panel except the active one carries `hidden`, and those three images get `loading="lazy"` so a reader on the first tab does not download them.

Why not render one panel at a time:
- The tests can then check all four captions and all four `alt`s verbatim against `renderToStaticMarkup(<HomePage books={null} />)`. The page tests already work this way (`apps/site/unit/page.test.tsx:266-278`); rendering one panel would expose only the first tab's copy.
- Without script, the first panel shows and the tabs are inert. That is the ticket's "No script" edge.

Keep the four entries (name, caption) in one exported constant in the client component, so the test can loop over it. The `alt` is the caption, per the ticket.

### 3. The lightbox

The lightbox is a native `<dialog>` in the same client component. When script runs, a click on the picture is intercepted with `preventDefault` and opens the dialog with `showModal()`, at the active tab's index.

- **← and →** wrap around the four. The listener is on the dialog's `keydown`, not on `window`, so the arrows do nothing to the page while the dialog is closed.
- **Esc** is native to `<dialog>`; add no handler.
- **A click outside** closes it. With `showModal`, a click on the backdrop reaches the dialog element itself, so `event.target === dialogRef.current` means outside.

The server render shows the dialog closed, but not empty: its full-size image (`loading` unset, so eager) and caption for the first shot are in the static markup, and the browser fetches that image on load even though the dialog is closed. Only the open state and the handlers are client-side.

### 4. The images are not in this worktree

`doc/img/` has no `shot-*` file at HEAD, and the ticket's *Watch out* says they are pending. Do not add placeholder PNGs: a placeholder committed under the real name is what the operator's commit would collide with.

Nothing in the unit half reads `doc/img/`:
- The new `imageType` test uses strings only.
- The page tests render markup only.

So `pnpm test` and `pnpm typecheck` are reachable without the images, and the export simply has no static param for them until they land. That is the ticket's "missing image" edge.

### Tests

These are in addition to the ticket's list.

- **`imageType`:**
  - `a.svg` gives `image/svg+xml; charset=utf-8`.
  - `a.png` gives `image/png`.
  - `a.gif`, `../a.png`, `a/b.png`, `A.png` and `a.png.svg/` give `null`.
- **Hero row:** slice the rendered HTML from `class="hero-row"` to the `</div>` that closes it (counting `<div` and `</div>`), and assert that slice contains both `id="hero-title"` and `shot-tab` and not `id="replay"`. Position alone would pass with the shots moved just after the row.
- **Receipt:** `class="rcpt` comes after `id="replay"`.
- **No "log" above the books:** the test that forbids it (`page.test.tsx:55-59`) reads `page.tsx`'s source and the rendered text with tags stripped. Captions inside the client component are seen only through the rendered page. None of the four says "log", so this needs no change; just don't move the copy into an attribute the test cannot see and assume it is covered.
