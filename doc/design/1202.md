## Decisions the ticket leaves open

1. **Split a pure function from the tree walk.** The Done-when cases feed source text, so the core is something like `ticketAppends(name: string, text: string): { line: number }[]`, built on `parse`. The tree walk reads each file and calls it, and the comparison against the baseline is a second pure function, `(measured, baseline) → red lines`. The "one more than baseline" and "one fewer" cases call that comparison on hand-built maps. They never touch the disk.
   - Walk the tree with `readdir`/`readFile`, as `effect-ratchet.test.ts:20` does, not with `git ls-files`. Spawning `git` is a process (0060 §1) and would make this an integration test.
2. **One count per call expression.** A call matching both halves counts once. If counted twice, the conduct.ts `appendNow(ticketId, [{ type: 'TicketLanded' … }])` shapes would double-count and the table would be wrong.
3. **Match names this way:**
   - An `Identifier` matches by its `.text`.
   - A `PropertyAccessExpression` matches by its last `.name.text`, so `input.taskId` matches and `f.stream` does not.
   - The callee name is resolved the same way, so `store.append`, `deps.store.append` and a bare `appendNow` all reach `APPEND_CALLEES`.
   - For `type:`, take only a `PropertyAssignment` with a string-literal initializer, directly on an object-literal argument or on an object-literal element of an array-literal argument. This is the same shape the events finder describes (`events.ts:5-11`). Do not walk into `data:` objects.
4. **Comments are not sites.** `rg` also hits `end-step.ts:74` and `conduct.ts:5225`, both of which are doc comments. The AST does not see them, so do not use a text search to check your count.
5. **Shape and comparison of the baseline.** The shape is `{ "ticket-": { "<repo-relative path>": n } }`.
   - Compare every key in both directions: a measured file the baseline lacks is red, and a baseline file measuring 0 or less than its number is red.
   - A red prints the whole `ticket-` object, sorted by path, ready to paste, as `effect-ratchet.test.ts:17-18` does.
   - Pin the set of top-level keys in the test (`['ticket-']`), as the ratchet pins `PACKAGES` (`effect-ratchet.test.ts:32-33`, *"a baseline that could drop a key would be a way out"*). 0.16 then adds a key in the test and in the JSON together.
6. **A parse failure is red by name.** Let `parse` throw. Do not catch it and count 0.
