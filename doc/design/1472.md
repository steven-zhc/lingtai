## Design: #1472, the spend card's five cells, its one sentence and the fold

### The decision the ticket leaves open: one reading in `ceiling.ts`, and the CLI string built from it

`ceiling.ts` builds the whole sentence in one function. It works out `attempts`, `perAttempt` and `runs` (`ceiling.ts:57-59`), the figure (`:64-68`), the `zero` lines (`:86-98`) and `others` (`:77-82`). It then flattens all of it into one string:

```ts
return `${figure}. ${zero.join('; ')}. ${others}`   // ceiling.ts:99
```

The `zero` lines are joined with `; ` into a single sentence. The ticket wants them as separate sentences in the fold (*"the CLI's `zero` lines … go into the fold as their own sentences"*). The CLI must keep printing that `; `-joined, lower-case-after-a-full-stop string, with only the plurals changed (*"`lingtai status` and `lingtai add` print what they print today, plurals aside"*). So the fold cannot get its sentences by splitting the string the CLI prints. It needs the parts from before the join.

The shape:

- **Export `ceilingReading(limits)`** from `ceiling.ts`. It takes the same parameter `attemptCeiling` takes today (`:35-47`) and returns plain data:
  - `{ attempts, perAttempt, runs }` as numbers;
  - `summary: string`, the ticket's sentence;
  - `parts: { figure: string; zero: string[]; others: string }`, the clauses as they are now, lower case, with the new plurals.
- **`attemptCeiling(limits)` becomes `ceilingReading` plus line 99's join**, unchanged, over `parts`. That keeps one formula (`:57-59`), and the CLI output stays byte-for-byte the same apart from the plural words.
- **`summary` is built in `ceiling.ts`, not on the board.** It needs `formatDuration(limits.wallMs * runs)` (`:67`) and `dollarsAt` (`:109`, which is private). Building it on the board would mean exporting `dollarsAt` and repeating `wallMs × runs`, which is the drift the ticket's Watch out forbids. It reads `A ticket gets at most ${runs} implement runs, ${limits.wall} and ${formatTurns(limits.turns)} each — ${total} at most.`, and adds ` and $${dollarsAt(usd, runs)}` before ` at most` when `usd` is set.
  - The ticket's template for the "each" part is `{wall} and {turns}` only, so per-run `$usd` stays out of it. The CLI's `wallAndTurns` (`:53-56`) does include it, but the summary follows the ticket's template.
  - Unbounded turns reads `no turn limit each` through `formatTurns` (`packages/recipe/src/duration.ts:63-64`, `'no turn limit'`). That is the "same word" the Edges ask for.
  - The `at implement (design …)` aside (`:48-52`) belongs to the figure clause. It goes into the fold, not the summary.
- **The fold's sentences are `[figure, ...zero, others]`, each with its first letter upper-cased and a full stop added.** Write that as a small exported function in `ceiling.ts`, `ceilingSentences(reading): string[]`, so the board never splits text. Every clause starts with a lower-case ASCII word (`up to`, `a`, `an`, `other`), so upper-casing the first character is enough.

### Plurals

Add a local `plural(n, one, many)` in `ceiling.ts`, the same shape as `count` in `recipe-lines.ts:61-62`. Apply it at `:62` (`refusal fix`/`refusal fixes`), `:63` (`conflict resolution`/`conflict resolutions`) and `:65` (`attempt`/`attempts`). At `:96`, write `once` for 1 and `up to N times` otherwise.

- `apps/cli/unit/run-before-dispatch.test.ts:86` and `:117-120`; the ticket does not name this file either.

`(s)` also appears in `apps/board/src/app/rail.tsx:430-432` (its test is `apps/board/unit/queued.detail.test.tsx:279`, `:314`), `attempts.ts:464`, `discuss.ts:330` and `triage.ts:315`. None of these is this card or `attemptCeiling`, so they are out of scope ("The other cards on `/recipe`", "Changing … what the CLI prints beyond the plurals"). Leave them alone.

### The board: three readers, one component

1. **`recipeLines`** (`recipe-lines.ts:145-155`) currently sets `ceiling: says('an attempt')`, where `says` looks up a row of `readRecipe` (`:89-90`), and that row is `attemptCeiling`'s string (`lib/recipe.ts:941-950`). Replace `ceiling: string` (`:52-53`) with `ceiling: { summary: string; sentences: string[] }`, from `ceilingReading` / `ceilingSentences`. Give it the same arguments `readRecipe` passes at `lib/recipe.ts:942-948`: `...ceiling.attempt, ...ceiling.ticket, ...limitsFor(recipe, 'implement'), wallMs, steps: boundsBesides(recipe, 'implement')`. Pull those arguments into one helper in `lib/recipe.ts` that both the row and `recipeLines` call; otherwise there are two copies of the argument list. Keep `readRecipe`'s `an attempt` row as it is. It is `lingtai status`'s vocabulary on other pages (`lib/recipe.ts:899-905`: *"two of them are that command's own sentences rather than a second wording of them"*), and those pages are out of scope.
2. **The setup preview** (`setup-form.tsx:647`) is fed by the server action `actions.ts:78-85`, which calls `attemptCeiling` and returns `{ text, ceiling }`. `Preview` is defined at `read-model.ts:78` as `{ text: string; ceiling: string }`. Change `ceiling` there to the same `{ summary, sentences }` plain data and compute it in `actions.ts`. **`setup-form.tsx` is `'use client'` (its line 1)**, so the reading has to cross as data from the action. It must never be an import of `ceiling.ts`, and never of `lib/recipe.ts` or `lib/recipe-lines.ts`, which import it (`lib/recipe.ts:18`, `recipe-lines.ts:19`).
3. **One component draws the summary and the fold for both pages.** Put it in its own file, e.g. `apps/board/src/app/ceiling-say.tsx`. Its only import is React, and its prop type is declared in that file, not imported from a module that reaches `ceiling.ts`. It renders `<p className="say">{summary}</p>`, then `<details className="say-more"><summary>how this is counted</summary>{sentences.map(s => <p>)}</details>` with no `open` attribute. The `▸` marker already comes from `details > summary::before` (`globals.css:1058`). `page.tsx:231` and `setup-form.tsx:647` both use it. The setup page's `.note` class becomes `.say`, as on the recipe page. **Nothing before the merge checks this import boundary**: only `apps/release/integration/build.test.ts` (the Next build) sees a server-only import reach a client graph (CLAUDE.md, *"tsc cannot"*). The unit-level check that stands in for it: `ceiling-say.tsx` imports nothing from `@lingtai/*` or `@/lib`. A grep over the file's imports in the card test covers that.

### CSS

At `globals.css:3656` use `repeat(5, 1fr)`. Replace `.stat + .stat` (`:3658`) with `.stat:not(:first-child)`. Under the existing `max-width: 900px` media query (`:3669`), and below 820 px as the ticket says, use `repeat(3, 1fr)` with `.stat:nth-child(3n+1) { border-left: 0; padding-left: 0 }`. This is the `:nth-child` per breakpoint option the ticket offers. Add `.say-more` beside `.say` (`:3664`): the same type, no top rule of its own, and `p` margins of `0 0 4px`. Type and radii stay untouched; the style tickets #1454–#1462 own those.
