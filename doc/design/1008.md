## Three corrections to the ticket's sketch

**1. `AccountState` needs `version`, and `seq` is a `bigint`.** The appender appends at the head it read: `store.append(projectStream(project), state.version, [next])` (`control.ts:629`). `ProjectState` carries `version: 0` empty, and its reducer sets it from every envelope (`project.ts:67,72`). `AccountState` needs the same field. The envelope's `seq` is `bigint` (`envelope.ts:83`), so `limit.seq` is a `bigint`, as in `RecordedRefusal` (`project.ts:57`).

**2. Both events get `ELSEWHERE` rows anchored in `packages/domain/src/account.ts`, not in the appenders.**
- The finder does not follow events a function returns (`scripts/events.ts:9`: *"return events and computed `type`s are not followed"*).
- An appender that appends a transition's result is therefore invisible to it. That is why `ProjectPaused` and `ProjectResumed` have rows anchored on `type: 'ProjectPaused',` in `locks.ts` (`scripts/events.ts:135-146`), with `why: 'returned from a function; the caller appends it'`.
- Do the same for `AccountLimitReached` and `AccountLimitLifted`.
- `AccountLimitLifted` is built in two places (`liftTransition` and `accountCheck`), and an anchor must occur exactly once (`scripts/events.ts:39-44`).
- So build it in one private helper, `lifted(runtime, by?)`, which both call. Its `type: 'AccountLimitLifted',` line is then the single anchor.
- The rows stay after #1011, because #1011 calls `reachAccountLimit` and never names the type.

**3. Actors.**
- `reachTransition` appends with `actor: 'lingtai'`. The wall is the system's observation, and `pauseConductorOnce` uses `by: 'lingtai'` for the same thing (`conduct.ts:1556-1563`).
- `liftTransition` uses `actor: by`, as `pauseTransition` does (`locks.ts:29-31`).
- `accountCheck`'s lift has no `by` in its data and uses `actor: 'lingtai'`.

## The appenders

- Copy `transitionProject`'s body into `packages/conductor/src/account.ts`:
  - read;
  - ask the transition;
  - `null` → answer from the state;
  - otherwise append at `state.version`;
  - `Effect.catchIf(ConcurrencyError, () => attempt)` once, then `mapError` to `Error`.
- **Do not import it from `@lingtai/daemon`.** Conductor must not depend on daemon (`packages/daemon/package.json:19` runs the other way).
- **Do not generalise it into a shared helper in this ticket either.** It is twenty lines, and a shared one would move `control.ts`, which this ticket does not need to touch.
- An empty `acct-` stream reduces to `emptyAccount` with `version: 0`.
- `reachTransition` takes `runtime` as an argument, so it works on a stream that does not exist yet. Unlike `pauseTransition` it has no `state.project === null` guard, and must not grow one.
- Answers:
  - `reachAccountLimit`: `{ kind: 'appended' } | { kind: 'already'; until: Date }`.
  - `liftAccountLimit`: `{ kind: 'appended' } | { kind: 'not-limited' }`.
  - Same shape as `ProjectPauseAnswer` (`control.ts:605-608`).

## The verb

- **Do not route it through `controlCommand`.** `project-pause.ts:5-7` explains why: its stub cannot see the appends.
- Write `liftAccount(runtime: string | undefined, by, { store?, log? })` as an Effect that answers `Outcome` (`0 | 1 | 2`), run with that file's `runEffect`. The unit test then drives it against `createMemoryEventStore()` and reads back what was appended. That is the "exits 2 / appends nothing" `Done when`, and it stays unit-level.
- **Declare `runtime` optional in the `Command`, and refuse a missing or unknown one in the handler with one sentence.** That covers both the "no runtime" and the "`claude`" cases: `RuntimeId.safeParse` fails → log `unknown runtime "claude" — runtimes: claude-code, codex` (or `no runtime named — …`) → `2`. A required positional would let `@effect/cli` refuse a missing runtime with its own message, which names no runtime.
- `account` is a parent command with `lift` under it, like `projectionCommand` (`cli.ts:985-991`): bare `lingtai account` prints the help.
- `by` is `human:$USER`, built the way `controlCommand` builds it.
