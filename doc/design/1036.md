# Design note for #1036: shape of the change

All edits stay in `apps/cli/integration/service.test.ts`. `service.ts` stays as it is.

## Why the heap fills (this corrects the ticket's "waits forever")

The wait is bounded, but the fake makes it spin. `unloadJob` (`apps/cli/src/service.ts:903-919`) calls `launchctl bootout`, then loops until launchd says the job is not loaded or until `UNLOAD_WAIT_MS` runs out. That limit is 60 seconds of real time (`service.ts:518`, `export const UNLOAD_WAIT_MS = 60_000`), measured with `Date.now()`. Between asks it calls `await sleep(500)`.

The test harness passes `sleep: async () => {}` (`service.test.ts:206`), so the loop never pauses. Every `launchctl print` it sends is pushed onto the fake's `calls` array (`service.test.ts:59-61`). That is millions of strings, and the heap gives out at about 35 seconds, before the 60 are up. The fix is the one the ticket gives: the fake must answer *not loaded* after bootout.

**Recommended addition to stop this recurring:** give `supervisor()` (`:57`) a cap. Once `calls.length` passes a generous bound, say 10 000, it throws, with a message saying a supervisor answer never changed and naming the fake that has to report *gone* after bootout. A future fake with the same mistake then fails as one named test in milliseconds, instead of killing the worker and hiding the whole file. Put the reason in the docblock above `supervisor()`, as the ticket's Edges section asks. This is test code only, so it is in scope.

## The fake for any restart that is let through

Use the pattern already in the file at `:410-417`:

```
let loaded = true
['launchctl print', () => loaded ? running : { status: LAUNCHCTL_NO_SUCH_SERVICE, out: '' }]
['launchctl bootout', () => ((loaded = false), { status: 0, out: '' })]
```

Use it rather than the print-counter fake at `:427-431`. The counter guesses how many prints happen before bootout, and that number changes whenever another `ask()` is added. The flag ties the answer to the bootout itself.

## The five tests

**(a) `:451`, own request.** `restart` runs `shutdownStands()` before anything else (`service.ts:1624`). It runs again inside `start(kept)` (`:1276`). With `by` equal to `human:lingtai`, both runs log the note through `log`, which goes to `out`, not `err` (`service.ts:1193`).

- Assert exit 0.
- Assert that `out` contains `your drain stands (restarting: deploy); this start ends it`. Check that it is present; do not check how many times.
- Assert that `s.calls` contains a `launchctl bootstrap`.
- Drop `d.said).toEqual([])`. The drain now runs, and `quietDrain` records `ask …` / `queue` / `held` (`:116-128`).
- Rename the test to say it adopts its own drain and ends it.

**(b) `:397` and `:989`, foreign request.** The refusal comes from the pre-check, with `unloaded` false, so the second line is `Nothing was started or stopped. ${FOREIGN_STANDING}` (`service.ts:635-638`).

- `FOREIGN_STANDING` is not exported, and exporting it would change `service.ts`. Assert a literal substring from it, for example `starting a conductor (lingtai daemon) ends it`.
- At `:397`, also delete `toContain('a daemon started now would not read it')`. That sentence is no longer in the code, and the ticket's evidence missed it because the first failing `expect` stops the test.
- Keep `s.calls).toEqual([])` in both tests. A foreign request refuses before `ask()`.

**(c) `:427`, control stream can't be read.**

- Assert exit 1 and `s.calls).toEqual([])`. The refusal at `:1624` comes before any supervisor call, which is stronger than "no bootstrap".
- Read the sentence from `err`, not `out`. Refusal lines go through `error` (`service.ts:1196`).
- The print-counter fake is no longer needed. A plain `running` answer is enough, because nothing gets as far as bootout.
- Rename the test to "refuses …".

**(d) `:1771`, decided here.** Change the request's `by` to a foreign name such as `'steven'` and keep exit 1. Do not flip the expectation to 0.

The test exists for #187. That is the docblock at `:1754-1762`: a refused daemon start must not bootstrap the board's job. Its title says the exit is "the conductor's 1". It used `human:lingtai` only because, before #1001 and #1002, any request refused. With a foreign `by`, `start(false)` hits the foreign branch with `unloaded` false. `Nothing was started or stopped.` then still holds, `REFUSED_OVER_SHUTDOWN` → 1 (`service.ts:1610`), and `boardCalls` stays empty, so every existing assertion holds unchanged.

Flipping to 0 would drop the #187 claim, and nothing else in the file asserts it. If you also want the own-request `service start` covered, add a separate test: it starts both legs and exits 0. Do not turn this test into that one.
