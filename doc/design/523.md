Its existing rule says a round returns to `implement`, then passes through “`build`, `review` and `proposed` again” ([0108:43–49](doc/decisions/0108-a-refusal-buys-a-round.md:43)); the grant should follow that path without changing `runtime.limits.rounds`.

In particular, conflict continuation must not be expressed as `Approve`: 0118 currently says approval over `MergeConflict` is unavailable because “a conflict cannot be merged,” and its approval path resumes at `proposed` ([0118:261–264](doc/decisions/0118-a-hold-explains-itself.md:261), [0118:483–491](doc/decisions/0118-a-hold-explains-itself.md:483)). Define conflict continuation as confirmation tied to the shown base and head, with an optional single-round grant. A changed base needs fresh confirmation. Define split as complete only after the approved children and dependency links exist; a partial write leaves the wait current and exposes enough identity to retry without creating duplicate children. Remove only the three now-settled bullets from “Not decided here” ([0118:530–538](doc/decisions/0118-a-hold-explains-itself.md:530)).
