# #1294: /report — splitting Spend, the two rows, and plain words

The ticket covers most of this. Three things in it are not obvious from the ticket alone: where the panel grid has to live so a unit test can see its titles, how the 5 : 7 row fits into a grid that only knows two equal columns, and what the spend hover does when two purposes share one name.

## 1. Move the grid out of `page.tsx` so the titles can be tested

`ReportPage` is an async server component. It reads both projections on render (`app/report/page.tsx:77-80`, `currentReport(...)`), so no unit test can render it. `apps/board/unit/report-panels.test.tsx:12` imports panels from `charts.tsx` and nothing from the page. A Next app-router `page.tsx` also cannot carry extra named exports. So the *Done when* line "asserts the two new panel titles" needs the grid somewhere a test can reach.

**Decision:** move `Panel` (`page.tsx:39-57`) and the whole `<section className="rp-grid">…</section>` (`page.tsx:126-170`) into a new `app/report/grid.tsx`, as `export function ReportGrid({ report, query })`. `page.tsx` renders `<ReportGrid report={report} query={query} />` where the section is today. Inside it every panel is still its own `<Panel title=… sub=…>`, with the two new ones as siblings. The *Watch out* in the ticket forbids folding the two spend panels into one component; a grid that lists panels does not do that.

The test builds a `Report` with `report` from `@lingtai/conductor/report` (already imported by the page at `page.tsx:14`) on a small in-memory input. That is pure, so it belongs to the unit half. Assert:
- the titles appear in this order: *Spend each day*, *Landed each day*, *Spend by purpose*, *By ticket type*;
- *Spend* no longer appears as a panel title.

## 2. The 5 : 7 row is a wrapper, not a 12-column grid

`.rp-grid` is `repeat(2, minmax(0, 1fr))` (`globals.css:3408`). `.wide` is `grid-column: 1 / -1` (`globals.css:3413`). The first row, *Spend each day* | *Landed each day*, needs nothing new: it is two half panels.

For the breakdown row, wrap the two panels in a full-width child, e.g. `<div className="rp-pair">` with:
- `grid-column: 1 / -1; display: grid; grid-template-columns: minmax(0, 5fr) minmax(0, 7fr); gap: 8px;`
- under the existing breakpoint (`globals.css:3444`), `grid-template-columns: 1fr`.

Do not move `.rp-grid` to 12 columns with spans. That would touch every other row in the section, and every other row is out of scope.

`minmax(0, …)` is what lets `KindsPanel`'s table shrink, but it is not enough by itself. At 7/12 of the row, *By ticket type* fits only if its headers can wrap. Let `.rp-table th` wrap inside this panel (`white-space: normal`) and keep the cells `nowrap`. Do not remove `.rp-tablewrap`'s overflow: on narrow screens it is still what catches the overflow.

## 3. The spend hover: one line per series, and Triage and Discussion summed

`purposeSeriesOf` (`lib/report.ts:333-337`) sends both `Triage` and `Discussion` to `Other`, which is named *triage*. The current hover maps each `d.byPurpose` entry to its own line (`charts.tsx:216`). Renaming in place would print two *triage:* lines with different amounts.

**Decision:** build the tip the same way `bySeries` already builds the segments (`charts.tsx:209-213`):
- group `d.byPurpose` by `purposeSeriesOf`;
- add up the three `Money` fields (`reportedCents`, `estimatedCents`, `unknown`);
- print `${PURPOSE_SERIES[i].name}: ${moneyText(sum)}` in `PURPOSE_SERIES` order.

This matches the donut list, which the existing test *"triage and discussion as one row"* (`report-panels.test.tsx:371`) already holds to the same merge. Summing `unknown` separately keeps an unknown-only purpose as *N unknown* (`moneyText`, `lib/report.ts:267-273`), never `$0.00`.

The ticket says the hover never shows the raw key, so there is no key fallback here. `purposeSeriesOf` already sends an unrecognised purpose to index 0 through `Math.max(0, …)`. Fallback to the raw tag applies to the waits table only.

## 4. Waits table: two lookups by tag

`presentCause` takes a `Cause` object (`lib/triage-cause.ts:20`). `WaitsPanel` only has the tag string (`panels.tsx:263-266`). `CAUSES` is not exported.

**Decision:** add `causeLabel(tag: string | null): string` to `lib/triage-cause.ts`:
- `null` gives *not triaged*;
- a known tag gives `CAUSES[tag].label`;
- anything else gives the tag itself.

Keep `presentCause` as it is.

For the rows, add a `WAIT_REASON_WORDS: Record<string, string>` with a `waitReasonText(tag)` that falls back to the tag. Put it next to `HANDLED` in `lib/handled.ts`, and take the four shared phrases from `HANDLED[…].wrong`, so they cannot drift from *Handled for you*:

| Wait reason | Words | Source |
|---|---|---|
| `AgentCrashed` | *agent stopped halfway* | `HANDLED.stopped.wrong` (`handled.ts:53`) |
| `AgentQuestion` | *the agent asked you a question* | `HANDLED.asked.wrong` (`handled.ts:79`) |
| `SetupRefused` | *setup broke in your environment* | `HANDLED.setup.wrong` (`handled.ts:85`) |
| `FixerDisagrees` | *the agent disputed a review finding* | `HANDLED.disputed.wrong` (`handled.ts:66`) |
| `ProposedEscalated` | *a failure handed to you* | written as literals; `HANDLED` has no entry for it |
| `AskLimit` | *asked too many times* | written as literals; `HANDLED` has no entry for it |

The table's sort order stays on the tags (`panels.tsx:264-266, 272`). Only what is shown changes, so the order of rows and columns does not move.

The comment at `panels.tsx:281` keeps its meaning: the null column is both untriaged waits and waits triaged without an advised cause. *not triaged* is the ticket's word for that column, so leave the comment beside it.

The existing assertion `toContain('no triage cause')` (`report-panels.test.tsx:167`) becomes `'not triaged'`. Add one row and one column with an unknown tag to the fixture, and assert that the tag itself shows.

## 5. Empty lines

`SpendPanel` already says *nothing spent in this window* (`charts.tsx:200`), and a test pins it (`report-panels.test.tsx:154`). Keep that string for *Spend each day*, and have `WhereItWentPanel` show its own empty line when it has no rows. What matters in the ticket's edge is that each half carries its own empty line, not the exact phrase. Changing a pinned string is churn this layout ticket doesn't need.

## 6. CSS for `.sw-rows` and the donut

- Replace the rules at `globals.css:3385-3391`:
  - the list is one column;
  - each `li` is a grid with `grid-template-columns: 10px 1fr auto auto` and areas `"i n v p" ". d d d"`;
  - `.v` drops from 17px to the row size, about 12.5px, and is right-aligned;
  - add a dashed `border-top` on `li + li`.
- Keep `.sw-donut` at `180px 1fr` (`globals.css:3640`). Add a breakpoint at about 520px that sets `grid-template-columns: 1fr` and puts the donut above the list.
- The centre figure's size is in the donut's own rule. Find it near `.sw-donut` and set it to 17px; leave the *+ N unknown* line under it as it is.
- `.sw-sub` (`globals.css:3641`) has no users once both `sw-sub` divs leave the grid (`page.tsx:149, 151`). Delete it if a grep shows nothing else uses it.

## Checks

Everything here can be checked in the unit half: `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck`, `HOME=/nonexistent pnpm test`.

The one thing the unit half cannot check is the Next build (`apps/release/integration/build.test.ts`). The risk it covers is a server-only import reaching a client graph. `grid.tsx` must import nothing the page did not already import into server code, and must add no `"use client"`.

Pixel sizes are checked by a person against the mock, not by a test. The ticket says so, and the unit tests stay on titles and words.
