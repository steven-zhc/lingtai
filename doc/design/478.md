# #478 — design note

## Where the `(kind)` shape belongs: in the fixture, not in `eventOf`

The ticket says "fix `aStepEnded`", but `aStepEnded` never writes the detail itself. It calls `eventOf` (`packages/domain/test/events.ts:165`). `eventOf` writes `StepDidNotFinish{detail: action.evidence}` for both cells: verdict at `packages/domain/src/adapters.ts:113`, design at `:192-194`.

**Do not change `eventOf`.** On a real pass, `actionOf` already copies the runtime's sentence into the action: `evidence: outcome.evidence` (`packages/conductor/src/adapters.ts:108`). That sentence already starts with `the reviewer did not finish (${kind}): ` (`agent-action.ts:580`) or `the design agent did not finish (${kind}): ` (`:962-963`). So `eventOf` is faithful to the real path, and adding the prefix there would write it twice. The bare string comes from the test `Action` literals: `evidence: 'spent all 5 turns reviewing'` at `read-model.test.ts:258`, and the design one near `:535`.

Rewriting the detail inside `aStepEnded` is also the wrong fix. `stepOutcomesOf` reads `evidence` back from that same detail (`evidenceOf`, `read-model.ts:225-228`). A builder that rewrites it would make every round-trip `toEqual([{ ...outcome, runId }])` disagree on `evidence` as well as on `cause`.

**So `aStepEnded` should refuse such an action by name.** If an action is `Interrupted` and either `yields: 'verdict'`, or `yields: 'design'` with `plugin !== 'file'`, its `evidence` must match the real prefix. If it does not, `aStepEnded` throws, saying no real pass writes that. The fixtures then carry the real sentence, e.g. `'the reviewer did not finish (timeout): spent all 5 turns reviewing'`. If the literal repeats, a small helper in `test/events.ts` that builds it from `(yields, cause, detail)` is fine. `file:` is excluded because `designResultFrom` already folds it to `NotDone` (`read-model.ts:427`). That branch is not this ticket.

### Commit 1 (red)

- Make the two tests realistic:

## The fix (commit 2)

In `verdictResultFrom` (`read-model.ts:265-269`) and in the agent branch of `designResultFrom` (`:421-427`), answer:

```
cause: asInterrupt(agentDidNotFinishKind(detail)) ?? 'crash'
```

- `asInterrupt` (`:172`) and `agentDidNotFinishKind` (`:366`) already exist. Reuse them rather than parsing a second time.
- `asInterrupt` maps any kind outside the five to `null`, and so to `crash`. The forward side drops two such kinds: `no-commits`, and for the design agent `no-structured-answer` (`agent-action.ts:584`, `:969`). That leaves `interrupted` unset, which `verdictResultOf` reads as `outcome.interrupted ?? 'crash'` (`conductor/src/adapters.ts:167`). So both directions agree for every kind, without a list of exceptions.
- `designResultFrom`'s `file` → `NotDone` branch stays exactly as it is.

**Remove the false sentences along with the code:**

- `read-model.ts:265-268` and `:422-426` both say *"Lost on the wire"*. They also cite `verdictResultOf` at `adapters.ts:215`; it is at `:167` today.
- The `AGENT_DID_NOT_FINISH` doc comment (`:342-363`) calls the sentence "the only place either action's own cause can be read". That claim stays true, but it now has three readers rather than `reasonFromHold` alone. Say so.
- **Keep that comment's clipping caveat, and extend it to these cells.** If `boundedEvidence`'s `tail()` drops the prefix, these cells now answer `crash` where the forward pass answered the real kind. That is the "`crash` only when the detail carries none" case in *Done when*.
- Do not widen the regexp. The comment itself says a wider match is "its own finding, not this one", and the ticket says to take only this finding.

**Testing the no-prefix → `crash` case.** The new guard means `aStepEnded` can no longer build an event without the prefix, so this case needs one hand-built `StepDidNotFinish` envelope. Build it with `makeStream` from `packages/domain/test/support.ts`, the same helper `aRun` uses at `events.ts:57`. Use it for one test per cell.

## Verification

No production reader uses `stepOutcomesOf` until #474–#476 land, so the log will show nothing about this change before then.
