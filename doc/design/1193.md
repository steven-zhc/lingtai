## Design note: #1193

### Where the change goes

The production change is one line, `packages/sandbox/src/policy.ts:165`. It replaces `[posix.join(host.tmpdir, SOCKET_DIR_NAME)]` with `socketDirs(host)`, the helper at `policy.ts:85-86` whose doc comment reads *"The hook-socket directory, under every temp spelling the host has."* No other source file changes.

The rest of this note covers what is not obvious from the ticket.

### 1. The unit test writes out both paths as literal strings

At `packages/sandbox/unit/sandbox.test.ts:209`, assert both strings in full: `` [`${host.tmpdir}/lingtai`, `${host.tmpdirReal}/lingtai`] ``. Those are `/t/root/var/folders/x/T/lingtai` and `/t/root/private/var/folders/x/T/lingtai` from `hostFor('darwin')` (`:33-41`).

Do not write `toEqual(socketDirs(host))`. The ticket's *why it stayed hidden* says *"The unit test asserted the code's own value back"*, and comparing against the helper does the same thing again. The linux branch at `:205-207` stays as it is. Add `expect(cfg.network.allowUnixSockets).toBeUndefined()` there, because the ticket's second checkbox asks for it and nothing pins it today.

This unit assertion is the only check `build:` runs (0060). It stands in for the acceptance case, which runs only after the merge.

### 2. The acceptance block: a new top-level `describe` in the same file

srt is one instance per process. `packages/sandbox/src/live.ts:77` says that building `SandboxLayer` means *"its scope resets srt's one instance when it closes."* `makeSandbox` caches one `initialize` per layer (`sandbox.ts:131-139`) and resets srt in its finalizer (`sandbox.ts:127`).

So the new block needs:
- **Placement:** a sibling of the existing `describe` at `acceptance.test.ts:42`, not nested inside it.
- **No concurrency:** no `.concurrent`.
- **Its own runtime:** made in its own `beforeAll` and disposed in its own `afterAll`.

Vitest runs sibling suites one after the other, so the first runtime's `reset` happens before the second runtime's `initialize`. That second `initialize` after a `reset` is the one thing about this layout that is not proven. If srt refuses it, move the block to its own file, `packages/sandbox/integration/unix-socket.test.ts`. Vitest isolates each file in its own worker, and that is still within what the ticket asks for. Do not work around it by sharing the first block's runtime: that host has `tmpdirReal: undefined` (`:93`), which is exactly what the ticket rules out.

Build the host the way `readHost` does (`host.ts:27-34`):
- `tmpdir: os.tmpdir()`, spelled as given;
- `tmpdirReal`: `await realpath(tmpdir)`, or `undefined` when it is equal.

Reuse the first block's fake `home` and `stateDir` approach (a `mkdtemp` under `homedir()`), so the deny list still points at a fake home. Only the temp facts become real.

### 3. `<tmpdir>/lingtai` is shared with any live daemon on this machine

That directory is where every hook socket on this Mac lives (`packages/agent/src/hook-config.ts:61-63`). The test must:
- create it with `mkdir(..., { recursive: true })`;
- name its socket with a short random suffix, e.g. `acc-<8 hex>.sock`;
- in `afterAll`, remove only the socket files it created, never the directory.

Keep the name short. macOS limits `sun_path` to 104 bytes, and `/private/var/folders/…/T/lingtai/` already uses about 60.

### 4. The client connects with the `TMPDIR` spelling, and the refusal must be EPERM

- **Allowed case.** The wrapped `node -e` client must connect to `join(host.tmpdir, 'lingtai', name)`, the unresolved `/var/folders/…` path. That is the path the hook uses, and the one that fails today. Pass the path in through an argv element, not through string interpolation into the script. `wrap` takes a `command` array, and `quoteArgv` (`sandbox.ts`) handles quoting. Use `process.execPath` as the node binary so the client does not depend on `PATH`. Its directory is not on the deny list (`policy.ts:89-102`).
- **Refused case (macOS only).** Put the listener at `join(host.tmpdir, 'acc-<hex>.sock')`, which is inside `tempRoots` but outside `lingtai/`. First connect to it **unwrapped** from the test process and assert the marker comes back. Then have the wrapped client print `err.code` and assert `EPERM`. That proves the socket was refused, not missing: an `ENOENT` from a mistyped path would otherwise pass as a refusal. Write it as `it.skipIf(process.platform !== 'darwin')`.

The listener is a `net.createServer` in the test process that writes a fixed marker and ends each connection. Close it in `afterAll` before the files are removed.

### 5. ADR 0127 §7 is edited in place, not superseded

`doc/decisions/` holds one ADR per topic, edited in place (CLAUDE.md: *"A decision that changes is an edit to its topic's ADR, not a new file beside it"*). 0127 lives there, so its §7 is edited directly.

Change §7 (`0127-what-an-agent-can-reach.md:50-51`) from Linux-only to both platforms, using the sentence the ticket gives. The consequences list at `:160` has *"On Linux every Unix socket is reachable."* Add the macOS line beside it: on macOS, only the hook-socket directory is reachable, under both temp spellings. Do not edit anything in `doc/decisions-archive/`.

### What would settle it in the log

The failing run left no event that names the socket; the evidence is in the run log. After the fix, a sandboxed run on macOS shows that the hook answered: its receipt reports turns and tokens greater than 0, where the failing run's said `0 turns · 0 tokens`. A daemon started before the merge keeps the old rule until `lingtai restart`, because `instanceConfig` is read once per process (`sandbox.ts:131-139`).
