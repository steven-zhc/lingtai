## Design note for #904: the home bar shows health with its command as code, and an amber waiting count

The ticket's line numbers match this worktree at `9c412a19`, which has #903 merged. Most of the change is what the ticket's **Fix** row says. Five decisions are not obvious from the ticket.

### 1. One drawing for both bars, so `Following` can be tested with a command

`Following` can never show the stale-code sentence. `warning()` calls `bearing(socket, health, null)` (`apps/board/src/app/live.tsx:263-266`), so `code?.wrong` (`apps/board/src/lib/bearing.ts:177`) is always false on the task page. The doc comment there says so: *"the currency of the daemon's code is the board's to say"* (`live.tsx:270-273`). Do not change this. Which branches `Following` can reach is out of scope.

It is also awkward to render either component in a test. `Live` calls `useFollow()`, which calls `useRouter()` (`live.tsx:123-124`). `Followed` is a context private to the module (`live.tsx:235`). `task-follow.test.tsx:13-15` notes that `Follow` *"needs Next's app router to render at all"*.

So pull out the dot, the sentence and the command into one component that both `Live` (`live.tsx:291-308`) and `Following` (`:276-289`) render. Call it something like `Said({ said }: { said: Bearing })`. Today the two draw the same dot and `.why` span twice, so this is one drawing instead of two that can drift apart. Export it. The **Done when** test then renders `<Said said={bearing('open', health, staleCode)} />` and finds `<code>lingtai restart</code>`. It also renders `Said` with a branch `Following` can actually reach, such as behind with no daemon and `lingtai daemon --no-conduct`. That shows the task page draws `command` through the same markup.

Write in the test why it does not mount `Live` or `Following`. A test that claims to render `Following` with stale code is testing something that cannot happen.

### 2. The command sits beside the `.why` span, not inside it

`.bar .why` is `max-width: 46ch; … text-overflow: ellipsis; white-space: nowrap` (`apps/board/src/app/globals.css:210-213`). If the `<code>` sits inside that span, it is the first thing cut off. That is exactly the case of the projections-stopped command. So render `<code>` as the next element after the `.why` span, and only when `command !== null`.

There is no global `code` rule: the only ones are `.pending code`, `.md code` and `.md pre code` (`globals.css:257`, `:2672`, `:2689`). Add a `.bar code` rule beside `.bar .why`: `font-family: var(--mono)`, `white-space: nowrap`, and no `--signal`.

Give the `<code>` no class name, or one that wears no amber. `bar.test.ts:231-235` collects every word inside a `className` in `live.tsx`. A class that wears `--signal` would trip the guard at `:264`.

The `title` keeps today's text. When `why` is null, render neither the span nor the `<code>`. The `current` and `asking` branches stay silent.

### 3. Each branch builds `command` alone, not by splitting `why`

Build `command` per branch, as its own string. Do not cut it out of today's `why` with a regex. The ticket's table gives the values.

For the projections-stopped branch, `command` is `` `${rebuild}, then lingtai restart` ``, built from `:143` and `:148` as the ticket says. That keeps the *", then "* inside the `<code>`. It is the ticket's choice, so leave it.

In `CodeNews`, rename `action` to `command` and keep *"Null exactly when `wrong` is"* (`bearing.ts:54-55`). The stale-code branch becomes `why: code.wrong, command: code.command`. The ticket's table gives the three non-null `news()` values (`health.tsx:61-66`, `:71-77`, `:83-87`).

### 4. Headline and CSS

`bar.test.ts:217-218` reads the bar as the slice between `<div className="bar">` and `<div className="cols">`. Both strings are still in `page.tsx`, so leave them byte for byte.

Write the headline as `{waiting > 0 ? <a className="head sig" href="#waiting" title={…}>…</a> : null}`. Keep the `title` text from `page.tsx:838` unchanged.

Use a plain `<a>`, not `next/link`. A fragment on the same page needs no client navigation. A plain `<a>` also keeps the class string literal for the guard's regex (`bar.test.ts:233`).

When `.bar .head` (`globals.css:196-199`) is folded into `.bar .head.sig`, keep `text-decoration: none` on the link. Fix the comment at `:193-195` (*"Nothing waiting is the quiet version"*), because that version no longer exists.

### 5. Leftovers once the counts go

Once the counts are gone, `logQueued`, `rest` and `tail` (`page.tsx:713-720` and on) have no reader. `total` (`:693`) is still read by the spend link's `title` (`:785`). Keep it until #905.
