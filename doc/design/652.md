# #652: design note

## Summary

There are four changes, and three of them go somewhere the ticket's Fix row does not point to:

- **The swap in `recommendedResolution`** must also correct the board's triage band. As it stands, that band would describe the new recommendation wrongly.
- **The advice type** becomes a tagged union. It stops being a second array of `LineFix`.
- **The hunk section** is rendered where `adviceSection` already renders. It does not go inside `conflictHalf`.
- **The CLI's `status` listing** draws the same recommendation and is changed to match (`conflictLines`).

## 1. `recommendedResolution` (`packages/domain/src/wait.ts:580`)

- Add `CONFLICT_ROUND_HUNKS = 5` next to `MERGE_HUNKS_ONE_BY_ONE` (`packages/domain/src/triage.ts:26`).
- Put the new rule at the **top** of the `TriageAdvised` branch, before `if (!allowed.includes(advised)) return null` (`wait.ts:595`):
  - The rule: cause `ConflictingHunks`, `total <= CONFLICT_ROUND_HUNKS`, and `allowed.includes('GrantFixRound')` → return `'GrantFixRound'`.
  - It goes first because the ticket says *whatever top-level resolution triage chose*. That includes a resolution this wait does not offer.
  - `allowed` is already filtered by `savedHead !== false` (`wait.ts:589`). So when there is no saved head, the rule cannot fire and the existing rules apply.
- **This is the first swap in this function.** Rewrite both comments that say otherwise:
  - The docstring says *"An advice that contradicts its own diagnosis is dropped"* (`wait.ts:570-572`).
  - The inline comment says *"An advice that contradicts its own diagnosis is dropped, not swapped for another"* (`wait.ts:597-599`).
  - The reason to write down: the hunks' own `recommended` answers are triage's reading of the conflict. On a small conflict, those answers outrank the top-level resolution that goes with them.
- Tests go in `packages/domain/unit/wait.test.ts`, the file that already covers this function:
  - `total: 2` with `Requeue` → `GrantFixRound`.
  - `total: 10` with `Requeue` → `Requeue`.
  - `total: 2` with `savedHead: false` → whatever the existing rules give.

## 2. The board's triage band (`apps/board/src/app/standing.tsx:183-199`)

This is what the ticket's **Watch out** row is warning about.

- The band computes `kept = recommendedResolution(...) === result.resolution`.
- When `kept` is false, the band falls through to a chain that ends with *"Triage advised {title}, which this wait does not offer."*
- After the swap, a `ConflictingHunks` / `Requeue` wait will reach that last line. It will say `Requeue` is not offered, which is false.

**Fix:** add a branch before that last line, for `cause._tag === 'ConflictingHunks'` with a recommendation of `GrantFixRound`.

- It names triage's own resolution ("Triage advised Start over"), the hunk count, and why a fix round is drawn instead: each hunk's answer goes to the fixer.
- Triage's own words are already on the band (`result.summary`, line 191), so nothing needs to be added for those.
- Pin the new sentence in `apps/board/unit/standing.test.tsx`.

**The board card's button** (`apps/board/src/lib/board.ts:592`, `moveOf`) follows `recommendedResolution` and needs no change. It already returns no button for `GrantFixRound` without a `fixHead`.

**The CLI:** `lingtai status` words the recommendation from `describeWaitLines`, so `conflictLines` in `apps/cli/src/status.ts` replaces its `rec` line with the same recommendation (a fix round at 5 hunks or fewer, triage's resolution above) and adds triage's own resolution and summary beside it.

## 3. The advice reaches the fixer (`packages/conductor/src/fix.ts`)

**The type.** Change `grantedAdviceOf`'s return type (`fix.ts:579`) to a union:

```ts
type GrantedAdvice =
  | { on: 'lines'; fixes: readonly LineFix[] }
  | { on: 'hunks'; hunks: readonly HunkAnswer[] }
type HunkAnswer = { path: string; line: number | null; question: string; recommended: string | null }
```

- Do not convert hunks into `LineFix` entries. `adviceSection`'s closing paragraph (`fix.ts:594-596`) says *"The findings above are what the re-review asks about"*, which is wrong for a conflict.
- The `advice` type in conduct.ts is inferred: `{ advice: grantedAdviceOf(...)! }` at `conduct.ts:1047`, passed through at `:3703`. So the only typed field to change is `fixBrief`'s input, `advice?:` at `fix.ts:502`.

**What `grantedAdviceOf` returns for each cause:**

| Cause | Returns |
|---|---|
| `FixableLines` with fixes | `{ on: 'lines', fixes }`, exactly as today |
| `ConflictingHunks` | `{ on: 'hunks', hunks }` built from the `Divergent` hunks only; `undefined` when there are none |
| Anything else | `undefined` |

- For each `Divergent` hunk, `recommended` is the text of the answer whose `id` matches `question.recommended`, or `null`.
- `TriageQuestion`'s refine (`triage.ts:57`) means a parsed hunk always names a real answer. Use `find` anyway, and render a `null` as the question alone, as the ticket's Edges section asks.
- The no-`Divergent` and `hunks: []` cases return `undefined`. That is what keeps the brief byte-for-byte the same as today, because `adviceSection('')` already prints nothing (`fix.ts:586`).

**Where it renders.** Render inside `adviceSection`, switched on `on`, at the place `fixBrief` already puts it (`fix.ts:525`, right after `${evidence}`). Do not render it inside `conflictHalf`.

- Whether a granted lap reaches `conflictHalf` depends on `again.printed?.step === 'merge'` (`conduct.ts:3649-3657`). Otherwise it gets `outputHalf`.
- That is settled by the log, which this design cannot read: it is the `step` on the granted round's printed refusal for a `MergeConflict` wait.
- Rendering in the shared place puts triage's answers in front of the fixer whichever half it gets.

**The hunk section's content:**

- The same heading, *What the person who granted this round accepted*.
- One entry per hunk, in this form: `` `path:line` `` (or just `` `path` `` when `line` is null), then the question, then *Triage's answer:* followed by the answer's text.
- A closing paragraph of its own: these are how the person expects each hunk to be resolved; the merge-and-stay-green criterion still applies; departing from an answer needs a reason stated in the final message.

**Tests** go in `packages/conductor/unit/fix.test.ts`, under `describe('grantedAdviceOf')` at line 1595:

- Update `reads FixableLines` (line 1604): it now expects `{ on: 'lines', fixes }`.
- Add a `ConflictingHunks` case with one `Divergent` hunk recommending `port` and one `Mechanical` hunk. The brief contains the path, the question and the `port` answer's text.
- Add a case with only `Mechanical` hunks: the result is `undefined`, and the brief equals the one built with no advice.

- **The ADR:** `doc/decisions/0118-a-hold-explains-itself.md:333` lives in `doc/decisions/`, not the archive, so it is edited in place (one ADR per topic). Add the threshold to the sentence that reads *"`ConflictingHunks` shows its hunks and advises nothing past `GrantFixRound`"*. At line 327, also say that this rule replaces triage's own resolution rather than dropping it.
