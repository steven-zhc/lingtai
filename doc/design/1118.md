## The decision the ticket leaves open: a production caller that no host reaches

The four branches (host / tests only / nothing / built into a host's object) miss a case that is common in this tree: **a face whose caller is another package's `src/`, wrapping it back into an Effect.** Examples:

- `packages/conductor/src/projects.ts:210-216`: `Effect.tryPromise({ try: () => resolveLocalRecipe(project, …) })`.
- `packages/conductor/src/add-from-page.ts:332`: the same, around `resolveLocalRecipe`.
- `packages/conductor/src/onboard.ts:589`: `yield* lift(() => resolveLocalRecipe(repo, …))`. `lift` (`onboard.ts:78`) is a `tryPromise`.
- `packages/conductor/src/repository-list.ts:25`: `Effect.tryPromise({ try: () => loadAllProjects() })`.
- `packages/conductor/src/repository-list.ts:30`, `gh: { status: () => ghStatus(), … }`, and `onboard.ts:356`, `status: () => ghStatus(gh)`. Both fill a **promise port**:
  - `GhAccessDeps.status: typeof ghStatus` (`onboard.ts:347`);
  - `ListOptions.gh.status: () => Promise<GhStatus>` (`packages/setup/src/list-repositories.ts:164`).

  Both are consumed by an Effect: `list-repositories.ts:207` with `Effect.tryPromise({ try: () => gh.status() })`, and `onboard.ts:391` with `lift(() => deps.status())`.
- `packages/setup/src/apply-setup.ts:86` and `:117`: `setRecipe(…)` inside a `try:`.

None of these can stay listed:

- `#790` is now refused.
- `"0101 §7"` needs a host file in `why`, and the caller is not a host.

Wrapping them as `() => Effect.runPromise(xEffect())` is a counted run and turns the baseline red. So:

**Rule: move the caller to the face's twin, then apply the four branches to what is left.**

- **The twin is the face's own body.** `checkFaces` holds every listed face to `return Effect.runPromise(<call>)` (`effect-ratchet.test.ts:10-14`, enforced by `face()` at `:324`). The twin is that `<call>`, for example:
  - `ghStatusEffect(run)` for `ghStatus` (`packages/github/src/gh.ts:129-131`);
  - `resolveLocalRecipeEffect` (`packages/recipe/src/local.ts:482-484`);
  - `tellGitHubAboutEffect` (`packages/conductor/src/tell.ts:737`);
  - `startDaemonFaced` (`packages/daemon/src/daemon.ts:380`).

  Moving a caller means inlining that expression. A twin that is not exported gets exported, as #1117 did for `processLogEffect`.
- **A `tryPromise` around a face becomes `yield* twin(…)`.** If the caller's error type was `Error`, add `.pipe(Effect.mapError(…))` with the conversion its `catch` used. This is the move #1117 made at `ticket-store.ts:232` (`Effect.promise(() => processTicketSql())` → `processTicketSqlEffect()`). `packages/projector/src/store-face.ts:11-13` gives the reason: *"A moved caller is never handed a face. That is Effect → face → Effect, and the face's run starts a root fiber that drops the caller's span and interruption."*
- **A promise port that only an Effect consumes becomes an Effect port.**
  - `GhAccessDeps.status` becomes `(…) => Effect.Effect<GhStatus, …>`.
  - `ListOptions.gh.status` changes the same way.
  - The consumers at `onboard.ts:391` and `list-repositories.ts:207` drop their `tryPromise`.
  - The unit tests that inject a fake `status` change from `async () => x` to `() => Effect.succeed(x)`. That is a mechanical edit and changes no assertion.
  - `GhAccessDeps.repository` (`onboard.ts:349-352`) is not a face. Leave it alone; its comment says it is the port's live value on purpose.
- **Reaching a face through another package does not keep it.** #1117's transitive rule kept `promiseLogSql` because the board *holds the object* (`doc/design/1117.md`, *Method faces*). Here the in-between caller is an Effect, so it is moved, and the face then has no caller left.

  Example: the board imports `@lingtai/conductor/add-from-page`. That file's `tryPromise(() => resolveLocalRecipe…)` is moved, and `resolveLocalRecipe` keeps only the callers it has left. The ticket's note on `add`/`addLocal`/`checkGhAccess`/`checkInstallation` is this same rule.

**This changes a production path, so the ticket's *Edges* line "no production path changes" is wrong for these callers.** What changes:

- **A defect.** `Effect.runPromise` rejects on a die, and the old `tryPromise`'s `catch` turned that rejection into a typed failure. With `yield*`, a die stays a defect. Do not add `catchAllDefect` to keep the old behaviour. A defect is a bug the caller was hiding as an ordinary failure, and #1117 did not keep it either.
- **Interruption and spans** now reach the twin, which is the point of the move.

The unit tests are the check. No event field changes, because nothing new is appended.

## Deciding "a host calls it": imports, not words

`rg -w` on a bare name is not enough here. `approve`, `ask`, `answer`, `close`, `add`, `git`, `beat` and `reconcile` match CSS, prose, SVG and comments all over `apps/site` and `apps/board`. A face counts as called by a host only if one of these is true:

- a file under `apps/board/src`, `apps/site/src` or `apps/site/scripts` **imports it by name** from `@lingtai/<pkg>` or a subpath export, and calls it;
- the face is a method on an object that such a file holds (the fourth branch).

Things that do **not** count:

- **Re-exports.** A package `index.ts` that re-exports a face is not a caller, and neither is a subpath that re-exports one. The board imports `approveHolding` from `@lingtai/conductor/decide`, not from `approve.ts`.
- **A mock.** `vi.mock('…', () => ({ name: vi.fn() }))` holds nothing. One example is `readProjectTicket` in `apps/board/unit/timing-load-task.test.ts:28`. That face is kept anyway, because `apps/board/src/lib/task.ts:5` imports it and `:1534` calls it.
- **A name in a comment.** For example, `runAttempt` appears only in comments in `what-an-attempt-shows-today.test.tsx:11532` and `:11571`. Do not keep it for that.

**A board test that calls a face keeps it.** `apps/board/unit/schedule-continuation-stale.test.ts:1` imports `approveHolding` and calls it at `:64` and `:95`. The *Done when* box asks for the board's tests to pass unedited, and #1117 kept faces for `waiting-card.test.tsx` the same way. So keep `approveHolding` with `"0101 §7"` and a `why` naming that test file. `checkFaces` accepts any existing `apps/board/…` path (`effect-ratchet.test.ts:460-469`). A face kept only because of a board test goes red the day that test is deleted; #1117 accepted the same cost.

## Deleting a face whose callers are tests

Inline the face body at each call site: `await face(a)` → `await Effect.runPromise(twin(a))`. A test file is outside the count (`effect-ratchet.test.ts:463` scans `<pkg>/src/` only).

- Do not change an assertion.
- Do not swap a promise-shaped fake for an Effect-shaped one unless the port's type changed under it (the `status` ports above).
- `runAttempt` and `claimStep` go to `runAttemptEffect` and its claim twin, in the six files the ticket names.

Many of these callers are integration files. `startDaemon` has seven test callers; `ghStatus`, `resolveLocalRecipe` and `setRecipe` have eight each. Nothing in the pass runs integration files, so `pnpm typecheck` is the only check on them before the merge. The same rule as #1117 applies: **an integration file's diff is an import line plus the inlined `Effect.runPromise(twin(…))`, and nothing else.** A reviewer can check that from the diff; anything bigger in an integration file is a finding.

## Edges, beyond the ticket's

- **A failing read through a moved caller:** it now surfaces as the twin's typed failure, mapped to the caller's error type. A defect stays a defect (see above).
- **Interruption and shutdown:** better than today. The moved callers no longer start a root fiber, so a drain's interrupt reaches the twin.
- **Two passes at once (0122), retries, a stale page:** these do not apply. No event and no projection changes.
- **Cost to later tickets:** a non-host promise face now needs an open issue of its own, and a face kept for a board test is tied to that test existing.
