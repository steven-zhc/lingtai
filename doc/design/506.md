# Design: #506 — remove `cost_usd` and `repair_costs` from `task_view`

## Nothing on the board reads these two fields, so delete them

`TaskCard.costUsd` (`packages/projector/src/task-view.ts:891`) and `TaskCard.repairCostUsd` (`:996`) have no readers that display them. Remove both from the type. Do not rewire either field onto `spend`. The ticket allows this with "or drop the fields if nothing displays them", and nothing does:

- **The board.** It shows `BoardCard`, not `TaskCard`. `BoardCard.costUsd` and `BoardCard.repairCostUsd` are `Bill`s. Their doc comments say they come off `spend`: "What this ticket's `Action`-round-0 runs cost — read off `spend`" (`apps/board/src/lib/board.ts:122`), and "an `Action` row at round 1 or above (0039 §3)" (`:215`). `page.tsx:268-269` says it reads `BoardCard.repairCostUsd`, "not the `repair_costs` projection column this used to read".
- **The board's split.** The Work/Answering split already checks the round: `row.round !== null && row.round > 0 ? 'Answering' : 'Work'` (`apps/board/src/lib/spend.ts:129-132`). So the board never had #502's round-0 overwrite bug. Only the projection column had it.
- **The site.** `reduce(t: TaskCard, …, costUsd: MoneyBill)` in `apps/site/src/lib/snapshot.ts:324` gets its bill from `spend` (`:286`).
- **The CLI.** `apps/cli/src/status.ts` reads neither field.

Before deleting, confirm with `git grep -n '\.costUsd\|\.repairCostUsd' -- apps packages` that every hit is a `BoardCard`, a `SpendRow`, a discussion or an event payload, and never a `TaskCard`.

Some unit-test fixtures build a `TaskCard` with `costUsd: null` and `repairCostUsd: null`. Typecheck will flag each one. Delete those lines:

- `apps/board/unit/arm-line.test.ts:30,55`
- `bar.test.ts:304,329`
- `close.test.tsx:135` (check its `costUsd: 20.3` at `:110` too)
- `columns.test.ts:28,53`
- `queued.test.ts:25,50`

Look in `apps/site/unit/snapshot.test.ts` as well.

Removing only the column would leave a fact with nothing to write it. Take out all of these:

1. **`packages/domain/src/read-model.ts`**: the `RoundSpent` member of `CardFact` (`:246-252`) and the `case 'RunSpent'` in `cardFactOf` (`:295-308`). With them gone, `RunSpent` falls through to `[]`, which the header at `:238` describes as "no fact, no write". Nothing outside `task-view.ts` matches on `RoundSpent`.
2. **`packages/projector/src/task-view.ts`**:
   - the `cost_usd` column (`:90`) and the comment above it (`:184`)
   - `repair_costs` and its DDL comment (`:195-206`)
   - `case 'RoundSpent'` (`:591-611`)
   - the comments that name either column: `:484-487`, `:573` and `:827-828`. Rewrite or delete them; don't leave them describing a column that no longer exists.
3. **The row readers**: the eight lines the ticket lists, plus the two `repairCostUsd:` sums at `postgres.ts:124` and `sqlite.ts:314`. Those sums are the ones that actually produce the wrong number.
4. **SQLite DDL**: check whether `sqlite.ts` has its own `task_view` DDL or translates the Postgres one. The Done-when `git grep` covers all of `packages/projector`, so it will find it either way.

## A live table: the drift check reports it and a rebuild fixes it

`create table if not exists` (`task-view.ts:77`) never removes a column from a table that already exists, so leaving the old columns on a live table is harmless for writes:

- Nothing will name `cost_usd` or `repair_costs` in an insert or update after this change.
- `repair_costs` is `not null default '{}'`, so inserts still succeed.

The shape check in `packages/projector/src/shape.ts:194-197` compares in both directions:

```ts
const missing = columns.filter((c) => !have.has(c))
const unexpected = [...have].filter((c) => !columns.includes(c)).sort()
```

So a live table that still has the old columns will report drift with `unexpected: ['cost_usd', 'repair_costs']`. It names the fix, `rebuild task_view`, which drops the table rather than truncating it (`task-view.ts:249-252`: "Dropped, not truncated… `create table if not exists` would silently keep the old columns"). That is the intended behaviour. Do not add an `alter table … drop column` to the fold. A rebuild replays the log, and that is the only fix (CLAUDE.md: "replay, never a repair by hand").

`packages/projector/unit/drift.test.ts` reads the column list from the DDL text. Run it, and confirm it is still green with the comments removed: `shape.ts:65` notes that comments are stripped before the commas are counted.

## Where the "no repair cost" unit test goes

Once the column is gone, the projector has no repair cost left to test. The cost the ticket means is now `BoardCard.repairCostUsd`, built by the board's `spend.ts`. So the test belongs in `apps/board/unit/spend.test.ts`, using the `billOf` already used there:

- Take #502's failure scenario: two `Action` rows at `round: 0`, `implement` at 0.42 and `review` at 1.25.
- Assert the Answering bill is empty and the Work bill is 1.67.

This also pins the summing: at round 0 the two `RunSpent`s must add up, never overwrite each other.

If that exact case already exists, still add one test named for this ticket. The Done-when asks for one.
