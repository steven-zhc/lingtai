# #384 — the shape

## The ticket's premise is half true, and that decides where the answer comes from

The ticket says the recipe is one "the board has already loaded for the project". That is true of `loadBoard`. It is not true of the page that builds the link.

- `apps/board/src/app/page.tsx:676-677` builds the card link from `loadProjects()` (the register) and nothing else: `const owners = new Map(registered.map((p) => [p.project, p.owner]))`. No recipe reaches the page.
- The recipes are resolved inside `loadBoard`, in `queuedCards`. Each project goes through `askProject` → `projectFilter` (`board.ts:517-520`), and `ProjectFilter` already carries the parsed `recipe` (`packages/conductor/src/filter.ts:243`, `recipe: resolved.recipe`).
- `queuedCards` already carries facts like this one out of that loop. Its own comment says so: *"Gathered here for the reason `backoffMs` is: this loop already resolved every recipe, and reading one twice is how a render gets expensive"* (`board.ts:575-577`).

**Decision: do it the way `backoffMs` and `plans` are done.**
1. In `queuedCards`, add `ticketSources: Map<string, TicketSource>` and fill it with `ticketSourceOf(filter.recipe)`.
2. Put the `set` next to `backoffMs.set(filter.project, …)` (`board.ts:629`), which is **before** the `answer.state === 'unanswered'` `continue`. A project whose GitHub would not answer still has a recipe that resolved, so its source is known.
3. Return the map on `Board` beside `queueOrder` (`board.ts:277`).
4. `page.tsx:677` looks it up the same way it looks up `owners`.

That costs no request and no second read of the recipe file, which keeps the promise in the `issueUrl` doc comment.

Don't resolve the recipe again in `page.tsx`. `loadBoard` re-renders on every append (#112), and `filter.ts:186-189` already notes that the board *"asks the same branch the same thing several times a second"*.

## `issueUrl`'s new argument, and what "not known" means

Change the signature to `issueUrl(owner, project, ref, tickets: TicketSource | null)`. Make the argument **required**, not optional, so `tsc` lists every caller. There are three:
- `page.tsx:677`
- `apps/board/src/lib/task.ts:1280`
- `apps/board/unit/weight.test.ts:137,145`

Return a URL only when `owner !== null && tickets === 'github'`. **`null` means the board does not know where this project's tickets live, and it gets no link** — the same answer `owner === null` gets today, for the reason `weight.test.ts:140-143` gives: *"a dead one is worse than none."*

This choice matters. A project lands in `'unreadable'` (`board.ts:617-620`) whenever `projectFilter` throws. `projectFilter` calls `githubClientFor` **before** it reads the recipe (`filter.ts:225-226`), and that throws `'no GitHub App configured…'` (`filter.ts:202`). A machine that keeps its tickets in `db` is exactly the machine likely to have no App. If an unknown source fell back to `'github'`, those are the cards that would keep their bogus link, which is the very bug this ticket is about.

The cost is that a `github` project with a broken recipe or App loses its card links until the fault is fixed. The Queued column already names that fault in red, and the Watch out row says a missing link is correct and a wrong one is a bug.

Import `TicketSource` and `ticketSourceOf` from `@lingtai/recipe/settings`, the subpath `board.ts:41` already uses for `queueOf`. The type is re-exported there from `recipe.ts:1023`, and `settings.ts:68` imports it.

## The task page

`task.ts:1280` uses the same function, and the comment there says *"The same shape the cards link to, said once"*. It has a `ProjectState` but no recipe. `task.ts:2` already imports `currentRecipe`, which reads a local file and makes no request (`packages/conductor/src/projects.ts:154-166`).

Resolve it there with `ticketSourceOf((await currentRecipe(state)).recipe)`. Wrap it in a catch that turns a throw into `null`, so a recipe that will not parse costs the link and not the page.

**Leave the `client.getIssue` call below it alone.** For a `db` ticket it will 404 and land in the existing catch (`task.ts:1297-1304`). The page still renders, because `exists` returns true for anything the log has touched (`task.ts:1323`). Reading a `db` ticket's body from the database is the ticket page the Watch out row forbids. It belongs to the #376 epic, not here.
