# #1079: design note

The ticket settles the shape. This note adds four decisions it leaves open. Each one would change code or break a test that already exists.

## 1. Lifting: #1078's rule, plus one loop that catches everything

Use `doc/design/1078.md` §2 as written. **Wrap a promise call that sits inside a `try` today in `Effect.tryPromise({ try, catch: asFailure })`** (`port-face.ts:18`). Then answer it with `Effect.catchIf` using the same predicate. These are the catches in these files:

- `note`'s `ConcurrencyError` retry (`split-ticket.ts:198-209`).
- `findMarked` under `read GitHub` (`:240-247`).
- `ensure`'s add-then-look-again (`:260-265`).
- `writeChild`'s `createIssue`, then `findMarked` (`:276-290`). Keep this order: create, then look by marker on failure. Never look first and skip the create on an empty listing. A timed-out create *"is not proof of absence"* (`:285`).
- `writeDoneWhen`'s `BodyChanged` retry (`:319-322`).
- In `backlog.ts`: the two `events.append` catches (`:247-262`, `:384-…`) and the `FindingProposed` append in `open` (`:291-312`).

Today's catches differ, so keep each one as it is:

- In `acceptFinding`, a non-`ConcurrencyError` append is rethrown (`:259`). It stays a failure, and the face rejects with the original error.
- In `open`, the same case returns a detail (`:305-309`). Keep that.

A `throw new Error(...)` inside a step body becomes `yield* Effect.fail(new Error(...))` with the same message. Examples: `:266`, `:302`, `:324`, `:357`, `:363`.

**The step loop** (`:410-446`) is the one place that must catch the **whole cause**. That is the ticket's last bullet, and its defect case is tested by a `createIssue` that answers `undefined`, so the step's own `.number` read dies (`split-ticket.test.ts`, *"yields a malformed answer"*). A throwing client call is not a defect: `Effect.tryPromise` turns it into a typed failure, as does the `TicketSplit` append in `resolveWaitHoldingEffect`. The loop must cover a failure from the new Effects and a defect from anywhere, including a `resolveWaitHoldingEffect` that died. Run each step under `Effect.exit`. On a failure exit, take the error with `Cause.squash` and pass it through today's `errorMessage` (`:121`). The detail strings stay word for word.

**Do not use plain `Effect.tryPromise` without `catch`.** It wraps the error in `UnknownException`, and the message becomes Effect's own. Every `failed: ${errorMessage(err)}` detail the tests pin would change.

**Interruption is the exception.** A cause that is only an interruption is not a step failure. Re-raise it with `Effect.failCause(cause)`, and do not reach `noteFailed`. That is the ticket's *"as a crash leaves them"*: no `SplitFailed`, and the board's running set says the writer is gone (`:448` comment). `Cause.hasInterruptsOnly` (Effect 4's name; check it in `node_modules/effect`) is the test.

`noteFailed` (`:217-223`) keeps swallowing everything, defects included. Use `Effect.catchCause` and log with `console.error`, as today. `split-ticket.test.ts:401-415` (*"when the final SplitFailed append throws"*) pins that.

The `SplitStarted` append before the loop (`:210-214`) is outside the loop today and rejects the call. Leave it outside: a failure, propagated.

## 2. The step list

`actions` becomes `{ name: string; run: Effect.Effect<StepStatus | { detail: string }, unknown> }[]`, with no `R`. **Build each `run` as a value that does nothing until it is yielded.** `writeChild(child)` returns an Effect and does no work while the array is being built, so the array literal has no side effects.

A step that reads `numberOf(...)` must read it when it runs, not when the array is built. `numberOf` throws a non-null assertion on a key a later step has not written yet. So wrap those bodies in `Effect.suspend` or `Effect.gen`. Never compute `numberOf(d.ticket)` while building the array, or the first child's step dies on the second child's key. Today's `run: async () => …` closures defer the read on their own, and a precomputed argument would not.

The loop stays a `for … of` inside `Effect.gen` with `break` on the first failure. Skip index 0, as `:411` does. `Effect.forEach` does not stop at the first `{ detail }` outcome, so do not use it.

## 3. `TicketStore`, and who catches its failures

```
propose(t): Effect.Effect<ProposedRef, Error>
withdraw(externalRef, keptRef, why): Effect.Effect<void, Error>
```

`githubTicketStore` lifts each `client` call with `Effect.tryPromise({ try, catch: asFailure })` and keeps `:181-200`'s order: `carrying`, `createIssue`, `carrying` again, `withdraw` the newer one.

Callers must still be able to say *"anything thrown says nothing about whether a write landed"* (`ticket-store.ts:130-132`). So in `backlog.ts`, `open`'s `propose` (`:281-290`) and `settle`'s `withdraw` (`:347-360`) also catch the **whole cause**: `Effect.exit`, then `Cause.squash`, then `.message`. A typed failure alone is not enough. The fakes in `backlog.test.ts` become hand-written Effects, and a fake written as `Effect.sync(() => { throw … })` dies rather than fails. `Effect.catch` would turn *"the store did not say it has the issue: …"* into a rejected board action.

The test changes go beyond the fakes in one place. `backlog.test.ts:200-222` calls `await store.propose(ticket)` directly, including inside `beforeCreate` (`:220`). Those calls become `Effect.runPromise(store.propose(ticket))`. The race test at `:217` is the ticket's convergence case: it already exists, so it passes over Effects and needs no new one.

## 4. The `entry` seam stays a promise

The ticket says it *"becomes an Effect seam, and the face adapts a promise one"*. Don't do that. Its `Done when` allows only the `TicketStore` fakes in `backlog.test.ts` to change, and `:155`/`:165` pass `entry:` as a promise function. A face also cannot adapt anything: `effect-ratchet.test.ts:206-240` accepts only `return Effect.runPromise(<call>)`.

So `DecideOptions.entry` keeps its type (`backlog.ts:166`), and `readEntry` lifts it with `Effect.tryPromise({ try, catch: asFailure })`. The default stops being `async` (`:184`): `(project, key) => readBacklog({ project, key }).then((r) => r[0])`. A projection read that fails is a failure, so the face rejects with the original error, as today.

## Faces and the count

- **Four faces**, each `return Effect.runPromise(xEffect(...))`: `splitTicket`, `splitTicketHolding`, `acceptFinding`, `declineFinding`.
- **Delete** `deciding` from both places: `deciding.ts:33-36` and `effect-ratchet.faces.json:122-127`.
- `resolveWaitHolding`'s `why` (`:222`) loses *"`split-ticket.ts` awaits it until CONDUCT8-4"*.

The baseline today is `"packages/conductor": { "async": 86, "run": 0 }` (`effect-ratchet.baseline.json:9`). 86 − 22 = 64. Count the `async` in the three files before and after. If the number is above 64, something has not been converted. Never raise it.

## 5. A write that was sent is finished, not abandoned

A promise cannot be cancelled, so interrupting an Effect around `client.createIssue` abandons the wait and not the write. `githubTicketStore.propose` and `writeChild` run `Effect.uninterruptible`: the create, the look-again and the withdraw (or the marker find and the record) complete before an interruption is honoured, and the decide lock is released after them.

## 6. Seams

`DecideOptions.entry` accepts a promise or an Effect. A store method is invoked inside `Effect.suspend`, so a throw while building its Effect is caught with the rest of its cause.
