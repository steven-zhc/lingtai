# Design: #645, the rate card prices unreported runs

## The card already exists. Read it, don't write a new one

The ticket says *"a `RateCard` table in one module … each row cites the provider's price page"*. That would be a second card. The first one is already in the repo, and an accepted ADR names it:

- 0110 §6: *"**The rate card is a file that a person appends to.** `doc/rate-card.md` holds one row per (model, mode, `from` date) … A price change adds a new row and never edits an old one, so an old run still prices at the rate in force when it happened. A model with no row is _unpriced_."*
- `doc/rate-card.md:3-6` says it is *"a file a person edits rather than a page something scrapes or a table compiled into code, and this is that file."* It has six Claude rows. One of them (2026-10-03 `claude-sonnet-5`) was measured against real receipts.
- The parser and pricer already exist in `packages/domain/test/rate-card.ts`: `parseRateCard` at `:39`, `rateFor(rows, model, mode, at)` at `:65`, and `priceTokens` at `:80`, which already bills `reasoning` at the output rate. Line 7 of that file says: *"#208 promotes this to `src` the day a display needs it."*

So this ticket is that promotion, plus wiring. A TS table of prices would break 0110 §6 and leave two cards that disagree. The ticket's "rows cite a price page and a date" is already met by the file's `from` column and its prose.

**Codex gets one row, `gpt-5.6-sol`, read 2026-10-26 from OpenAI's model page** and cited in `doc/rate-card.md`'s Codex section. Any other Codex model is unpriced until a person appends its row. Codex's `usage[].model` is `request.model`, and is absent when the recipe sets none (`packages/agent/src/codex.ts:479-486`); an absent model prices nothing.

## Where things go

1. **`packages/domain/src/rate-card.ts`**: move `test/rate-card.ts` here with `git mv`. Then:
   - Add one function, `priceUsage(usage: Usage, at: Date, rows: readonly RateRow[]): number | null`.
   - Export it as a **subpath** `@lingtai/domain/rate-card` in `packages/domain/package.json` `exports`. Do not export it from `src/index.ts`, which every reducer imports.
   - Point `packages/domain/unit/rate-card.test.ts:27` at the new path.
   - Add `priceUsage` to the projector guard's regexes (`rate-card.test.ts:165-166`, beside `priceTokens` and `rateFor`).

   `priceUsage` is all or nothing. It returns `null` when:
   - `usage` is `[]`;
   - any entry has no `model`;
   - any entry has no token count at all;
   - `rateFor(rows, model, mode ?? '', at)` is `undefined` for any entry.

   Otherwise it returns the sum of `priceTokens` over the entries. A row that bills two models where only one is priced is **unknown**, never half a price, because half a price would read as the whole bill. Mode matches exactly. An unrecognised mode never falls back to the ordinary row, because a premium mode costs more (the test *never lets a moded row answer an empty-mode lookup*, `rate-card.test.ts`, already holds the other direction). Within an entry, a count that is absent adds nothing. The estimate is a floor, like every total (0110 §2).

2. **Reading the file: one loader in `@lingtai/conductor`.** Both the board and the CLI already depend on it (`apps/board/src/lib/day-spend.ts:7`, `apps/cli/src/day-ceiling.ts:8`). Use `readFile(resolve(repoRoot(), 'doc/rate-card.md'))`, which is how `prompts/ticket.md` is found (`apps/board/src/lib/prompt.ts:134`). `repoRoot()` is *"the checkout Lingtai is running from"* (`packages/env/src/index.ts:1112-1126`).
   - If the file is missing (ENOENT), the loader returns `[]`: every unreported row stays unknown, which is today's behaviour, not a failure.
   - Any other read error throws. The callers already turn a throw into a sentence: `dayCeilingStop` gives *"could not check the daily ceiling … taking no work"* (`day-ceiling.ts:90-91`), and `readDayReading` gives *"could not be read"*.
   - **`apps/release/src/build.ts:53`** must copy `doc/rate-card.md` next to `prompts/ticket.md`, or an installed release never estimates. The only test that would catch this is `apps/release/integration/build.test.ts`, which cannot run inside a pass. Make the `cpSync` and say so in the commit.

3. **`packages/conductor/src/day-ceiling.ts`**:
   - `DayRow` gains `usage: Usage`. `SpendRow` (`packages/projector/src/spend.ts:205-221`) already has it, so callers that pass `readSpend` rows compile unchanged.
   - `daySpend(rows, now, price)` takes `price: (row: DayRow) => number | null` as a **required** parameter, so `tsc` finds every caller. There are three: `apps/cli/src/day-ceiling.ts:116`, `apps/board/src/lib/day-spend.ts:22`, and `dayCeilingPause` at `:143`. `DayCeilingOptions` and `DayCeilingPorts` each get a card port, so tests inject one.
   - `DaySpend` gains `estimatedCents` and `estimatedRuns`. Each estimate is rounded to the cent once, the rule `daySpend` already applies to reported rows (`:42`).
   - Order of the arms: `costUsd !== null` first, so a reported row is never repriced (the same order as the board's `billOf`, `spend.ts:143`), then the price, then `unknown`.
   - `ceilingReached` becomes `reportedCents + estimatedCents >= ceiling`. This is the one place the two are added, because 0122 §5 makes the ceiling count them. They are still never added on a surface.
   - `daySpendText` names the estimate as its own clause, e.g. `today $3.10 + ~$1.20 est. + 2 unknown of a $5.00 ceiling — estimates are counted, unknown costs are not`. Leave the clause out when `estimatedRuns === 0`, so today's sentences and their tests (`packages/conductor/unit/day-ceiling.test.ts:31-34,159`) still hold.
   - Rewrite the module header (`:5-10`, *"never priced, so a ceiling cannot see it"*).

4. **`apps/board/src/lib/day-spend.ts:23-27`** builds its own short form with the figure written out a second time. Add the `~$x est.` there too, or the bar will contradict the sentence.

5. **`apps/board/src/lib/spend.ts`**:
   - Delete `noRateCard` (`:126-127`) and make `billOf`'s `price` required, so `tsc` lists the four callers: `board.ts:1144`, `board.ts:1524`, `task.ts:1433`, `task.ts:1963`.
   - Each loader reads the card **once per render** through the conductor's loader. It then passes `(row) => priceUsage(row.usage, row.at, card)`.
   - The `Bill.estimates` arm and `billText`'s `~$x est.` already exist (`:41`, `:187-188`), and they already keep estimates out of `reportedCents`. Change nothing there except the `#208` mentions in comments (`:22`, `:40`, `:120-126`, `:170`).
   - Tests that call `billOf(rows)` with no price pass `() => null` explicitly.

6. **`doc/decisions/0110…md`**: under *Not built yet*, the bullet *"Nothing reads the rate card … (#208)"* is no longer true. Edit it out. This repo edits a topic's ADR (CLAUDE.md: *"A decision that changes is an edit to its topic's ADR"*), and nothing here changes a decision: it builds 0110 §6–7 and 0122 §5 as written.

## Edges

- **A row with `costUsd` set** is never priced: in both folds, the reported arm comes before the price.
- **A Claude model that is not on the card** (for example `claude-opus-5-5`; the card has `claude-opus-5`): unknown. Use exact match. No prefix matching and no stripping of `[1m]`-style suffixes. A guess here is the #198 failure.
- **An event from before a model's first `from`**: `rateFor` returns `undefined`, so unknown.
- **A killed run that left no `RunSpent`** has no row, and stays invisible as before (0110 §2). The ticket's *"every killed Claude Code run"* is fixed only to the extent those runs have rows. The `RunSpent` with `costUsd: null` and a non-empty `usage` is what settles whether they do.
- **The card changes while a daemon runs**: the card is compiled into `RATE_CARD` (`packages/domain/src/rate-card.ts`), so an append to `doc/rate-card.md` needs the same row there and a daemon restart; a unit test holds the two equal.
- **Two passes at once (0122)**: the read is pure, and the existing *"one row short"* note in the ceiling (`day-ceiling.ts:133-135`) still applies.
- **Doctor** (`apps/cli/src/doctor.ts:1484-1490`) warns on `day.unknown > 0`. That stays correct: estimated rows are not unknown.

## Out of scope

- Real Codex rows, or refreshing the stale 2026-06-24 Claude rows. Those are a person's append to `doc/rate-card.md`.
- `apps/site/src/lib/snapshot.ts:190`'s own `billOf`, which keeps printing unknown.

## Checks

All the Done-when items are unit-level:
- `priceUsage` in `packages/domain/unit/rate-card.test.ts`, with a fixture card, a Codex-model entry, an unknown model, a two-entry half-priced row, and `usage: []`;
- `billOf` + `billText` in `apps/board/unit/spend.test.ts`;
- `daySpend`, `ceilingReached` and `daySpendText` in `packages/conductor/unit/day-ceiling.test.ts`.

The release copy is the one change that only `pnpm test:integration` sees.
