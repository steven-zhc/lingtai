## Design note for #1283: after a base merge, a finding inside the merge-resolution delta stays blocking

### The decision: when a delta exists, it alone decides what stays blocking

The ticket gives two fixes: exempt the delta's hunks from `demoteOutsideDiff`, or let the delta check alone decide. Both produce the same severities.

- **The current rule.** A fresh finding stays blocking only if it passes both checks. `demoteOutsideDiff` lets it through if it is on a `keep` path, has a `reachableBecause`, or is inside the whole-diff hunks (`diff-hunks.ts:142-145`). `demoteOutsideFix` then lets it through only if it is inside the delta or on a `keep` path (`diff-hunks.ts:168-170`). It has no `reachableBecause` escape, and its doc comment says so: *"Unlike `demoteOutsideDiff` there is no `reachableBecause` escape: a new finding outside the fix is always a backlog entry"* (`diff-hunks.ts:156-158`).
- **What the first fix gives.** Add "inside the delta" to the whole-diff check and the result is still "inside the delta or on a `keep` path". A finding the delta check accepts always passes the widened whole-diff check. A finding the delta check rejects is demoted either way.
- **What to build: the second fix.** At `agent-action.ts:1364-1365`, when `deltaHunks !== undefined`, skip `demoteOutsideDiff` and run only `demoteOutsideFix(fresh, deltaHunks, keepPaths)`. When `deltaHunks` is undefined, keep today's `hunks === null ? fresh : demoteOutsideDiff(...)`. The ticket cites `:1372-1373`; in this worktree those lines are `:1364-1365`.
- **Do not change `demoteOutsideDiff`'s signature.** Adding a delta parameter there would tie the whole-diff function to the fix round for no change in outcome.

The blocking set this leaves is #1274's and nothing wider: delta hunks, `keepPaths` and rechecks. The rechecks are already split off before either check runs (`agent-action.ts:1360-1363`).

### It applies to both kinds of delta, on purpose

`deltaHunks` is set in two places:
- after a base merge (`since: 'merge'`, `agent-action.ts:1054`);
- on an ordinary fix round against the earlier reviewed head (#671, `agent-action.ts:1083`).

Make the same change in both. A fix round can revert a branch file to the base just as a merge resolution can, and today that file has the same blind spot. Because the two fixes give the same result (above), this changes nothing else on an ordinary fix round. Comment the new condition with #1283 next to the existing #1274 comments, so the next reader does not put `demoteOutsideDiff` back in front.

### One visible change: the prefix on the claim

A finding outside both the whole diff and the delta now gets `outside the fix — was <sev>: …` (`FIX_PREFIX`, `diff-hunks.ts:150`). Today it gets `pre-existing — was <sev>: …` (`PREFIX`, `diff-hunks.ts:127`).

That is the right label in a fix round, and the severity is `minor` either way. Nothing in `packages/` or `apps/` parses either prefix outside the two unit assertions:
- `agent-action.test.ts:2350` is a first review with no delta, so it is unchanged.
- `agent-action.test.ts:2457` already expects the fix prefix.

If another existing case in `agent-action.test.ts` asserted `pre-existing — was` while a delta was present, update it to the fix prefix. Do not keep the old order to preserve the string.

### The test

Add it to the `describe('a review after a base merge looks only at the resolution and the overlap (#1274)')` block (`agent-action.test.ts:2833`). Its `build` helper already takes the delta text.

- Add a `diff --git` section to the resolution delta for a file that is **absent from `FULL_WITH_OVERLAP`**. That is the "reverted to the base" shape: the file is in the delta and not in `base...head`.
- Return a `major` finding on a line inside that section's new-side hunk, and assert it is still `major` and the verdict is `failed`.
- Add one case for a file the delta *deletes* (no new-side line). `isInsideHunks` counts a file in `hunks.deleted` as inside for every line (`diff-hunks.ts:122`), so a finding on it also stays blocking. If the branch added the file and the resolution dropped it, that is the deletion the reviewer is looking at.

A matching case in the #671 fix-delta block, around `agent-action.test.ts:2450`, is cheap and pins the second half of the decision. It is optional. All of this is unit-level and `pnpm test` covers it; nothing here needs the integration half.

### Edges the ticket leaves implicit

- **No whole-diff hunks** (`hunks === null`, or `onEvidence`) while a delta is present: today the delta check alone already decides in that case. The new rule makes that the general rule, so nothing changes there.
- **Reading the delta failed**: `deltaHunks` stays undefined (`agent-action.ts:1037-1063`, `1086-1091`), and the review falls back to the full, whole-diff-only path, as #1274 says.
- **Retry, restart, two passes at once, pause or shutdown**: not affected. This is a pure function over one review's answer, and it adds no IO, no `async` and no `Effect.run*`. The ratchet does not move.
