## #1437: the shape of the change

The ticket's shape holds as written. Two things are not obvious from it.

**1. Do the time check before counting.** Today `onSignal` adds 1 to `signals` first and branches on it afterwards (`apps/cli/src/daemon.ts:338-346`: `signals += 1; if (signals === 1) { fork(drain(...)); return }`). Store `firstAt = now()` when `signals === 1`. On every later call, return early if `now() - firstAt < 500`, before `signals += 1`. Then a signal the window ignores never moves the count, and the window never gets longer (Edges: *"counted against the first … not extended by an ignored one"*). Keep the 500 as a named constant beside `onSignal`; it is not configurable (Out of scope). The default for `now` is `Date.now`. It is synchronous, so it adds no `async` and no `Effect.run*`, and the effect ratchet does not move. The comment the ticket asks for goes in the existing block above `let signals` (`daemon.ts:334-337`, *"The first signal drains and says so; the second stops now…"*). Cite #1437 there; do not start a separate comment.

**2. The test fake only records `loop.stop` after the pass is released.** In `apps/cli/unit/daemon-stopping.test.ts:38-43`, `loop.stop` is `Deferred.await(release)` followed by `record.push('loop.stop')`. So for the first new test's *"call `loop.stop`"*:
- Fire both signals, then `await ticks()`.
- Assert one `draining —` line and no `stopping now` line.
- Call `Deferred.doneUnsafe(release, Effect.void)` and `await ticks()`.
- Then assert `record` contains `loop.stop`, and contains no `exit`.

If you assert before releasing, the test is red even when the code is right.

To give the tests a clock, add an optional `now` parameter to `world()` (`daemon-stopping.test.ts:24`) and pass it into `daemonStopping`. Drive it with a mutable `let t = 0; const now = () => t`:
- The existing *second press* test sets `t = 600` between its two `onSignal` calls.
- The two new tests set `t = 10`.

The first existing test needs no clock.

Nothing here depends on the log or on integration tests. The unit tests above are the whole check. `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover them, and no accepted ADR is touched. 0030 is in the archive and gets no edit.
