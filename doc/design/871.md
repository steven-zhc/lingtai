# #871 — design note

## Where the change goes

Three places, in this order.

1. **`packages/domain/src/reducer.ts`** gets two pure functions:
   - `reduceFrom(reducer, state, events)`. `reduceAll` becomes `reduceFrom(reducer, reducer.initial, events)`, so the fold still exists once, as the file's header asks: *"so the fold exists once"* (`reducer.ts:4`).
   - `crossesCommitPoint(from, to)`, with `COMMIT_EVERY = 5` as an exported constant. 0124 §5's interval lives in that constant, not in a parameter, because a configurable interval is out of scope.
   - Export both through the domain barrel.
2. **`packages/daemon/src/control.ts:123`** changes `readControl`'s body. It gets no new helper.
3. **`apps/board`**: one new file that holds the writer, and the two read sites changed to use it.

## `readControl`'s signature: the store parameter loses its default

Today it is `readControl(store: EventStore = eventStore, since = 0)` (`control.ts:123`). Because of the default, the body cannot tell `readControl()` apart from `readControl(someStore)`, and the ticket's trap depends on exactly that difference. Make it:

```ts
export async function readControl(
  store?: EventStore,
  since = 0,
  cache: { snapshots?: SnapshotStore; writer?: Pick<SnapshotWriter, 'offer'> } = {},
): Promise<ControlState>
```

- `const events = store ?? eventStore`.
- `const snapshots = cache.snapshots ?? (store === undefined ? log.snapshots : undefined)`.

Only an absent `store` brings `log.snapshots` in. This works because `eventStore` and `log` resolve through the same `openOnce()`: `processEventStore` is `(await processLog()).store` (`choose.ts:87-88`), and `log.snapshots` is `deferredSnapshots` over the same resolve (`choose.ts:214-218`). So the default store and the default snapshots always belong to one log.

A caller that passes `eventStore` explicitly gets no snapshot. That is the safe direction, and I found no such caller outside tests. Grep again before relying on it.

`SnapshotWriter` comes into `daemon` as a **type-only** import from `@lingtai/event-store/snapshot-writer` (`event-store/package.json:19`). Use a type-only import so that `daemon` needs no `effect` dependency. `SnapshotStore` and `log` are already exported from `@lingtai/event-store` (`index.ts:26`, `:78`).

The board calls `readControl(undefined, 0, { writer })`.

## The body

Branch on `since` first:

- **`since > 0`:** today's code, unchanged. That includes reading from version 1 for both `scoped` and `whole`. Child 4 owns this path.
- **`since <= 0` with no `snapshots`:** `reduceControl(await events.readTypes(CONTROL_STREAM, CONTROL_FOLD_TYPES))`. This is byte-for-byte today's answer.
- **`since <= 0` with `snapshots`:**
  1. Call `snapshots.latest({ streamId: CONTROL_STREAM, reducer: controlReducer.name, reducerVersion: controlReducer.version })`, wrapped in `.catch(() => null)` plus a one-time stderr line.
  2. If a row came back, `decode` its `state` in a `try`. If decode throws, start from `controlReducer.initial` at version 0, with its own one-time stderr line.
  3. Call `readTypes(CONTROL_STREAM, CONTROL_FOLD_TYPES, start + 1)`, then `reduceFrom`, then `evaluateControl(state, new Date())`.

The two "say it once" flags are module-level `let`s in `control.ts`, one per kind of failure.

**The ratchet** counts `async` functions as AST hits (`effect-ratchet.test.ts:44`), and an `async` arrow is still an `async` function. So:

- the `.catch` callback must be a plain `() => null`, not an `async` one;
- `decode` is synchronous, so a `try`/`catch` inside the existing `async` body does it;
- nothing new may be `async`.

The writer's `offer` is synchronous (`snapshot-writer.ts:22`), so calling it needs no `Effect.run*`.

**Who reads, who writes:**

- `readControl()` with no arguments, as doctor, restart and status call it, reads the snapshot and offers nothing.
- The first `latest` call runs `CREATE TABLE IF NOT EXISTS` (`snapshots.ts:206-212`, `ensure()` called at `:231`). So a CLI read can create the empty table. That is DDL the store already owns, not a snapshot write, so it does not break *"read snapshots and never write them"*.

## The offer, and one decision the ticket leaves open

Offer only when `cache.writer` is set and `crossesCommitPoint(from, to)` holds:

- `to` is the `version` of the last envelope reduced. With no tail, `to = from` and nothing is offered.
- The anchor is that envelope's `version`, `seq` and `at`.
- `state` is `controlReducer.encode` of the state **before** `evaluateControl`.

**Decision:** when a row came back but did not decode, `from` is **that row's `streamVersion`**, not 0. The reduce still starts at version 1, so the answer is unaffected.

Here is why. With `from = 0`, every board render on a stream of five or more events would offer a snapshot, and `put` would answer `'kept'` each time against the bad row (`snapshots.ts:41-45`, 0124 §7). That is one wasted statement per render until the stream passes the row. With the row's own version as `from`:

- the first crossing past the bad row is offered;
- that offer is at a higher version, so it is written and replaces the bad row;
- nothing is offered before then.

The ticket's *"`from` is the snapshot's `streamVersion`, or 0 when there is none"* still holds: an undecodable row is a snapshot that exists and cannot be used.

A **void** row is different. `latest` already returns `null` for it (`snapshots.ts:43`, and the memory store's `holds` at `memory.ts:250`), so `from` is 0 there.

## The board's writer

**New file:** `apps/board/src/lib/snapshot-writer.ts`.

- Cache the runtime on `globalThis` under a `Symbol.for(...)` key, as `split-instance.ts:14` does.
- Build it as `ManagedRuntime.make(Layer.scoped(BoardSnapshotWriter, makeSnapshotWriter(log.snapshots, (l) => console.error(l))))`, where `BoardSnapshotWriter` is a `Context.Tag`.
- Export `boardSnapshotWriter(): Promise<SnapshotWriter>`. It returns a cached `runtime.runPromise(BoardSnapshotWriter)`.
- Clear the cached promise if it rejects. `snapshots.ts:204-205` gives the reason: a promise kept after a failure stays failed for good.
- Never dispose the runtime.
- The board is `async` and outside the ratchet's `PACKAGES` (`effect-ratchet.test.ts:24`), so the `runPromise` belongs here.

`log.snapshots` is deferred (`choose.ts:218`), so building the runtime at first render opens nothing early.

Add `"effect": "^3.22.1"` to `apps/board/package.json`, the same range as every other package (for example `event-store/package.json:36`).

**The two read sites:**

- **Home page** (`page.tsx:614`): `readControl(undefined, 0, { writer: await boardSnapshotWriter() })`, still uncaught (#77, `:598-601`).
  - If getting the writer fails, catch that and pass no writer. A cache must not turn a working page into an error page.
  - Getting the writer happens inside the `timed('events.control', …)` closure, so the `Promise.all` stays parallel.
- **Task page** (`task.ts:1604-1606`, `:1626`): the `Promise.all` slot becomes the same `readControl` call, `.catch(() => evaluateControl(emptyControl, new Date()))`. Then `conductor` is that value, not `reduceControl(control)`. Drop the `CONTROL_FOLD_TYPES` import if nothing else in the file uses it.

## Tests

All of these are unit tests, and they sit beside the other `readControl` unit tests (`packages/daemon/unit/control-since.test.ts`).

- **Domain:** `reduceFrom` and `crossesCommitPoint` go in `packages/domain/unit/`, covering 4→5, 3→12, 5→5 and 0→4.
- **Equality over prefixes:**
  - Build each `histories.control` or `lateHistories.control` prefix (`@lingtai/domain/test/histories`) into a `createMemoryEventStore()` by `append(CONTROL_STREAM, i, [{ type, actor, data }])`.
  - **Do not use the event store's `plant`:** it pins every row at `version: 1` (`memory.ts:191`). If a late payload is refused by `append`, report that. Do not work around it.
  - Pair it with `createMemorySnapshotStore(events)` (`memory.ts:243`).
  - The reference is `readControl(store)`. Compare it against `readControl(store, 0, { snapshots })` in each of the ticket's four cases. Plant the snapshots with that store's `plant`, built from `controlReducer.encode(reduceAll(controlReducer, prefix.slice(0, k)))` and the k-th stored envelope's anchor.
  - Both reads evaluate against real `new Date()`, and the history literals are far from now, so the clocks cannot split the comparison.
- **Offers:** a recording `{ offer }` stub. Assert one offer when the tail crosses, carrying the right anchor and the unevaluated state, and no offer when it does not.
- **No touch:** a `vi.mock('@lingtai/event-store', …)` whose `log.snapshots` throws when touched, then `readControl(memoryStore)`. Do not reach the real `log` to spy on it: that opens the process log, and `HOME=/nonexistent` would make that refusal the test's red.

## What is accepted, not handled

**A reset that lands between `latest` and `readTypes`:** a snapshot from the old log combines with a tail read from the new log's version `v+1`. The anchor is checked inside `latest` alone, and with the type filter the tail's versions have gaps by design, so the reader cannot detect this cheaply.

This is rare, and the result is wrong for one render only. The next `latest` finds the anchor void. The log would show it as a `stream_snapshots` row whose `last_seq` is above every `events.seq` in the new log.

**What is out of reach before the merge:** nothing in this shape needs `pnpm test:integration`. The Postgres `jsonb` decode path (a parsed value, not a string, `reducer.ts:15`) is already covered by #867's codec tests. The board's `ManagedRuntime` wiring is checked only by `tsc` and the Next build (`apps/release/integration/build.test.ts`), which runs after the merge.
