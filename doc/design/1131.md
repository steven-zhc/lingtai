## Shape

**1. One pure helper in `classify.ts`. It reuses the row's own pattern and never copies it.**

Export something like `unreachableCause(text): 'origin' | 'origin-or-size' | 'size'`. Call it only on text that `classify` has already read as `unreachable`. It answers in this order:

1. **`'size'`**: the text contains `pack exceeds maximum allowed size`. This is GitHub naming the limit outright (`doc/design/platform-errors.md:43`, row *Push over 2 GiB*). That line matches no row today, so it only reaches this path when `hung up` appears beside it.
2. **`'origin-or-size'`**: once every `remote end hung up unexpectedly` is removed from the text, it no longer matches the unreachable row's `pattern`. Look the row up in `FAILURE_ROWS` (`:87`) and do not write a second regex. Two copies of the list is how they drift apart.
3. **`'origin'`**: any other text. Some other sign (`Connection reset`, `RPC failed`, …) decides it, which is the ticket's first edge.

Unit-test it in `packages/domain/unit/failure-classify.test.ts` with three inputs:
- the bare `fatal: the remote end hung up unexpectedly`;
- `hung up` together with `Connection reset`;
- `remote: fatal: pack exceeds maximum allowed size` together with `hung up`.

Run each of the three a second time with ` (after 3 tries)` appended, because `network.ts:30` adds that.

**2. Only a push can be over the limit, so the lane decides the cause and writes it into the detail.**

The 2 GiB limit applies to a push. A `git fetch` that hangs up can only mean an unreachable origin. `explain.ts` sees only the refusal's `detail`, so it cannot tell a push from a fetch. The decision therefore belongs in `integrate.ts:715-723`, where `err.operation` is available. `gitEffect` sets it to `` `git ${args[0]}` `` (`packages/repo/src/git.ts:115`).

When `said === 'unreachable'`:
- If `err.operation === 'git push'`, prefix the detail with the phrase for `unreachableCause(err.stderr ?? err.detail)`. Pass the same text `classify` read, not `err.detail` alone.
- Otherwise, use `'origin'`, which keeps today's prefix `origin could not be reached: `.

**3. The sentence reads the lane's phrase. It never reads git's words a second time.**

Export the three opening phrases from `domain` as constants, next to the helper. `integrate.ts` writes them and `explain.ts` matches the start of `detail` against them, so both sides use one string rather than two copies that have to agree. The precedent is `base-checked-out`, whose comment says: *"The lane composes the whole sentence … as the first line of `detail`"* (`explain.ts:307-308`).

`unreachable.says` becomes:
- **`'origin'`**: exactly today's sentence. The two tests above pass `detail: 'x'` (or something similar). That detail must fall through to `'origin'` so they stay green with no change.
- **`'origin-or-size'`**: names both causes. Roughly: *origin could not be reached, or the push of `${base}` is over GitHub's 2 GiB limit, while … after 3 tries; check the push's size as well as the network; nothing about `${branch}` was judged.*
- **`'size'`**: says the push is over GitHub's 2 GiB limit, and does not say *could not be reached*.

`move` stays `approve` in all three cases, as the ticket's edge requires. Do not add a `RefusalReason`; that is out of scope.

**4. Docs: one sentence, despite the ticket's "Docs: none".**

Do not edit the unreachable row's `says`. `platform-errors.md:113` is generated from it by `pnpm docs:errors`.

The hand-written §15 paragraph (`doc/design/platform-errors.md:143-148`) ends: *"but the hold that follows says origin could not be reached when the cause is the size."* That becomes false with this change. Rewrite that one clause to say the hold now names both causes.

## Edges decided here

- **Refusals recorded before this change**: their detail starts `origin could not be reached: …`, which reads as `'origin'`. They read exactly as they do today, and nothing is reread.
- **Effect ratchet**: the helper is pure, and the lane change sits inside the existing `catchTag`. Nothing adds an `async` function or an `Effect.run*`.
