# Design note for #507: fix comments that name writers deleted in #502

## Where the work is, and where it is not

`git grep` across `packages` and `apps` for the retired names (with `StepPassed` added) gives **259 lines**. Most of them are already correct, because they talk about the deleted name in the past tense: `conduct.ts:3211` "**`FixRequested` is gone (#502)…**", `task-view.ts:555` "`of` is gone with `FixRequested` (#502)", `read-model.ts` "**No `Restarted` fact here** (`#502` had one)". **Leave every line like that alone**, and leave anything under `unit/`, `integration/` or `test/`. Rewriting the history notes would make the diff ten times longer and wipe out the record that #502 wrote on purpose.

The test for each hit: **does the sentence say the deleted thing writes, carries or does something now?** If it does, fix it. If it says the thing was, used to, is gone or was replaced, leave it.

## The trap: `StepPassed` is still a live type

`StepPassed` is not in the ticket's Done-when grep, but the finding cites `events.ts:1057` for it, so it is in scope. The catch is that `packages/conductor/src/pass.ts:302` still declares `export interface StepPassed extends LeftTheTreeAt, WroteTheDesign`. It is one variant of `StepEnding` (`pass.ts:507`), and `pass-steps.ts` returns it about ten times. **Inside `packages/conductor/src/pass*.ts` and `step-outcome.ts`, `StepPassed` means that interface and is correct.** Only a comment that means the *event* is wrong, and the event was replaced by `StepEnded` (`events.ts:1011`). Those comments are:

- `events.ts:1057`: "it is on the `StepPassed` the backlog folded" → on the `StepEnded`.
- `projector/src/backlog.ts:13`: "read off `StepPassed` through `findingsRaisedOf`" → `StepEnded`.
- `projector/src/backlog.ts:110`: "`StepPassed` is on the run's stream" → `StepEnded`.
- `event-store/src/sqlite.ts:374`: "`StepPassed` carries an agent's entire review output" → `StepEnded`.
- `actions/src/agent-action.ts:669` and `actions/src/file-action.ts:14,66`. Read each of these before changing it: some mean the pass ending (`{ending:"passed"}`), and those stay.

## Decisions the ticket leaves open

- **The SQL `--` comments in `task_view`'s DDL count as comments, and are in scope**, even though they sit inside a template literal. The finding lists them by line, and the ticket's "a name inside a string" refers to strings the code acts on. Changing them changes the text sent to `create table if not exists`, and nothing reads that text. The shape drift check (`shape.ts`, quoted at `task-view.ts:107`) compares columns, not comment text. `pnpm test` is what confirms this.
- **Rewrite the sentence; don't just swap the name.** "Only `WaitResolved` may clear `waiting`" stays true when written that way. "Written from `WaitStarted.onSha`" would be a new wrong writer: `WaitStarted` carries no `onSha`; the sha comes from the `signoff` action.
- **No ADR is involved.** This only corrects comments, and the archive files under `doc/decisions-archive/` are outside the grep's paths.

## How to check it

`git diff -U0 | grep -E '^[+-][^+-]'`: every line it prints should be a `//`, ` *` or `--` comment line. That is the "No non-comment line changed" box. After that, run the ticket's own grep again and read every hit that is left. If a hit is still present tense, either it is the live `StepPassed` interface or it is unfinished work.
