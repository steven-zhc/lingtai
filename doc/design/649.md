## Shape

The change is in three places, and the brief is most of it.

### 1. The brief: `buildDesignPrompt`, `packages/actions/src/agent-action.ts:842-912`

Add a fourth parameter, `asks: number = 0`. It counts this ticket's earlier design questions. Put it after `again` so that the existing calls at `agent-action.ts:1088` and in the tests still compile.

The section *When the ticket cannot be designed as it stands* (`:878-897`) is printed in one of two forms, and the brief never carries both:

- **Asking is allowed** when `asks < 2 && again === null`. This form has four parts:
  - The generic checklist. Name its eight cases exactly as the ticket lists them: a read that fails, a process that restarts or dies halfway, two runs at once, pause or shutdown, a stale or disconnected page, a retry, a null or unknown value, and the cost to every later change.
  - The bar sentence: *ask only where two reasonable readings of the ticket would build different code and the body does not say which*.
  - The rule that a missing `## Edges` section is not a question in itself, and that anything the body or `## Out of scope` answers is decided.
  - The fence, now holding a numbered list. Each item is one sentence, then `- (a) … (recommended) — <consequence>`, then two to four options in total. The recommended option comes first.

  Remove *"One question, not a list"* (`:895`). Keep *"Answering with nothing is a real answer, and it is the common one"* (`:873`) and the *"a question is not a doubt"* test (`:891`). Say *at most five*.
- **Asking is forbidden** when `asks >= 2 || again !== null`. This form has no ` ```question ` text at all. It tells the agent to apply the same checklist and to write, under a fixed heading (use `## Assumptions`), the reading it took for each open edge and why. The closing line at `:908-909` (*"or with the `question` block"*) must be conditional too, or the forbidden form still names the fence.

**`again !== null` forbids the fence as well.** Today a judge's send-back gets `sentBackBlock` (`:933`, *"**Do not ask again.**"*) appended *after* a section that still teaches the fence, so the brief contradicts itself. Folding `again` into the same condition costs one boolean and removes that contradiction. The `## You are at this step a second time` block stays as it is.

Then update the doc comment at `:826-840` and the one on `again` (`:846-853`), which still say *one question*.

### 2. Carrying the count: `AgentActionDeps`, not `ActionContext`

`context.again` is a fold over *this pass's* visits (`pass.ts:1799`, `sentBackTo(spec.step, reached)`), and `pass.ts` never sees the ticket stream. The count is a fact about the ticket and is known at claim. So it travels on the deps, the same way `issue` does:

- **`packages/actions/src/agent-action.ts:114`**: add `designAsks?: number` to `AgentActionDeps`, with a comment explaining what it counts. Make it optional, and let absent mean 0. That is today's behaviour, which allows one fence. Requiring it would change every fixture that builds these deps, for no gain.
- **`packages/actions/src/from-recipe.ts:220-240`**: `dispatchDeps` copies the deps key by key, on purpose (*"a sixth key added to `AgentActionDeps` a compile error at this line"*). An optional key will **not** fail to compile there. It has to be forwarded by hand (`designAsks: base.designAsks`), or it silently arrives as 0. This is the trap in this change. Add a unit test that builds an action through `actionsFromRecipe` at `design` and checks that the brief shows the forbidden form when `designAsks: 2`.
- **`createDraftAction`** (`:1088`): `buildDesignPrompt(spec, issue, context.again ?? null, deps.designAsks ?? 0)`.
- **`packages/conductor/src/conduct.ts`**: `before` is the ticket stream read once at claim (`:995`, *"Everything the prompt is composed from is read from it"*). Compute the count from it, and set `designAsks` on `stepDeps.agent` (`:3022`). Do the counting in a small pure function in `packages/domain/src/read-model.ts` next to `waitsOf` (`:85`), for example `designAsksOf(events)`:

  ```ts
  waitsOf(events).filter((w) => w.reason._tag === 'AgentQuestion' && w.reason.step === 'design').length
  ```

  `AgentQuestion`'s `step` is `'design' | 'implement'` (`packages/domain/src/wait.ts`, `Step.extract(['design', 'implement'])`), so `implement`'s asks are left out by that filter. Count every such wait, resolved or not: the question was asked either way.

`parseDraft` (`:1007`) is not changed. A numbered list inside the fence is still one `question` string.

### 3. ADR

Add the sentence to `doc/decisions/0103-a-pass-is-ten-fixed-steps.md`, point 4, after *"Only `admit`, `design` and `implement` can ask."* (`:60-61`). It is an edit, not a new file: 0103 is in `doc/decisions/` (the topic ADRs from 0100 on), and changing a decision there means editing that file.

## Not settled by the code

- **The *at most twice* claim needs the stream order to be right.** It assumes the second pass's `before` already contains the first `WaitStarted{AgentQuestion, step: 'design'}`. Whether a ticket really stops at design no more than twice can only be read from the events: count those `WaitStarted` events per ticket stream.
- **Old asks keep counting.** A ticket that asked twice long ago and was then reopened counts those old asks. That is how the ticket defines the count (*"on this ticket's stream"*), so it is accepted rather than something to fix.
