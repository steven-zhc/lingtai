## #949 design note

**Short version:** the link moves from the heading to the count. One new component renders the pill, `ColumnLabel` loses its link, the existing test in `landed.test.tsx` is rewritten rather than added to, and the CSS is copied from the mock.

### Where the link goes

- **Today the heading is the link.** `ColumnLabel` (`apps/board/src/app/page.tsx:436-444`) wraps the label in `<Link href={landedLink(only)}>` when `id === 'landed'`.
- **Today the count is a separate branch.** The header at `page.tsx:834-842` sends `queued` to `AwaitedCount` in a `Suspense`. Every other column, Landed included, gets `<span className="ct">{col.cards.length}</span>`.

**The change:**

- Add a third branch to that header for `col.id === 'landed'`.
- It renders a new exported component, e.g. `LandedCount({ count, only })`, which returns:

  ```tsx
  <Link className="ctbtn" href={landedLink(only)} title="what Lingtai changed, newest first">
    <span className="ct">{count}</span><span className="lbl">all</span><span aria-hidden="true">→</span>
  </Link>
  ```

- Pass it `count={col.cards.length}`, the same number that is printed there now. Do not import anything from `footer.tsx`; the ticket's Watch out explains why.
- This markup and title are exactly what the yardstick draws. In `doc/design/board-navigation.html`, the `data-v="c"` view's Landed header is:

  ```html
  <span>Landed</span><a class="ctbtn" href="#" title="what Lingtai changed, newest first"><span class="ct">73</span><span class="lbl">all</span><span aria-hidden="true">→</span></a>
  ```

- **Keep `.ct` inside the pill.** `.col-h .ct` (`globals.css:337`) gives the number its mono, tabular figures, and nested inside the link it still does.

**`ColumnLabel` becomes `<span>{label}</span>` for every id:**

- Drop its `only` prop. Nothing else uses it, so leaving it would be an unused parameter.
- Rewrite the doc comment at `page.tsx:431-434` to say the way into `/landed` is the count (#895, #949), and keep its line about *a second way out of the reading and not a fifth object in the bar*.

### CSS

Copy the mock's three rules beside `.col-h .ct` (`globals.css:337`):

```css
.ctbtn{display:inline-flex;align-items:baseline;gap:6px;text-decoration:none;color:var(--accent-ink);border:1px solid var(--rule-2);border-radius:999px;padding:3px 10px 4px;background:var(--surface)}
.ctbtn .lbl{font-size:11px;letter-spacing:.04em;text-transform:none;font-weight:500}
.ctbtn:hover{border-color:var(--accent)}
```

- `--accent-ink`, `--rule-2` and `--accent` exist in both themes (`globals.css:19,21,23` and `:58,60,62`).
- `globals.css` has no `a` or `a:visited` rule. The underlined purple in the screenshot is the browser's default link style.
- Setting `color` and `text-decoration` on `.ctbtn` is the whole fix for the purple. No `:visited` rule is needed.
- Scope the selector as `.col-h .ctbtn` only if the bare class collides with something. Today `.ctbtn` appears nowhere in `apps/board/src`.

### The test

The existing test is `apps/board/unit/landed.test.tsx:217-224`, *"the home page Landed heading … links to /landed, carrying the project filter"*. It asserts that `ColumnLabel id="landed"` contains `href="/landed?project=my%20repo"`, so it goes red by design. Rewrite it rather than adding a second test beside it:

- `ColumnLabel` contains no `<a` for **any** id, including `landed`.
- `LandedCount` with `only="my repo"` contains `href="/landed?project=my%20repo"`, `class="ctbtn"` and the text `all`.
- With `only={undefined}` it links to `/landed`.
- With `count={0}` it still renders `0`, the ticket's first edge.

These are `renderToStaticMarkup` checks on the two components, not a whole-page snapshot, as the ticket's cost edge asks.

### Nothing else moves

- **Waiting's count** keeps its styling: the `.col.hot .col-h .ct` rules (`globals.css:338-344`) only reach the `hot` column.
- **Queued's `Suspense` branch** is untouched.
- **The `70 older` fold** (`page.tsx:544-549`) is untouched.

No ADR is affected.
