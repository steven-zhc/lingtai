## The import trap: `wait.ts` is a subpath, and `Landed` is taken

`nextOf` returns `WaitOnPerson{reason: WaitReason}` and takes `run: RunRef`. Both come from `wait.ts`, and `wait.ts` is deliberately not in `index.ts` (`wait.ts:15-26`, `package.json:6`'s `"./wait"`). Its `RunRef` is not the one the package root exports: `hold.ts`'s carries `repairOf`.

- Import `RunRef` and `WaitReason` **from `./wait.ts`**. Never import `RunRef` from `index.ts` or `hold.ts`. 0120 §4's signature is 0118's `RunRef`.
- `pass-next.ts` may be in `index.ts` because it **re-exports nothing from `wait.ts`**. Only re-exported names collide (TS2308, `wait.ts:20-22`).
- **`Landed` is already exported** from the root: `integration.ts:37`, `export interface Landed`. Follow `wait.ts:28-31`'s rule: **variant schemas stay unexported**. Export only `PassNext`, `RequeueCause` (schemas and types), `Spent`, `nextOf` and `spentAfter`. #460 needs the `FixRound` and `Requeued{Restart}` schemas for `CandidateNext`, and can take them from `PassNext.options` and `RequeueCause.options`.
- Imports stay leaves only: `action.ts`, `proposal.ts`, `wait.ts`, `vocabulary.ts`. Never `events.ts` or `hold.ts` (`hold.ts:15-19`'s ESM cycle).

## `nextOf`: the order of the checks

The deciding action is `decidingAction(outcome)` (`action.ts:283`). Apply these checks in this order:

1. **Deciding action is `merge` `Completed{Integrated}`** → `Landed{integrated: mergeSha}`. This must be a test on the action. Do not use `stepCleared && step === 'merge'`; the ticket's *Watch out* is exactly that distinction.
2. **Deciding action exists and `!cleared(it)`** → `switch (action.yields)` and then `switch (result._tag)`, with **no `default`**. This follows `cleared`'s precedent (`action.ts:213-218`), so a new yield turns `pnpm typecheck` red. Within each case, branch on `outcome.step` only where 0120's tables do. The cells:
   - `NeverStarted{scope}` (verdict, commit, design) → `Requeued{NeverStarted{scope}}`
   - `Interrupted`: if the cause is `out-of-turns` or `out-of-usd` → `BudgetExhausted{cause, detail: evidence, call: action.call}`. Any other cause → `AgentCrashed{step, cause, detail: evidence}`.
   - `NotDone` (nothing, worktree, commit, design) → `SetupRefused{step, action: name, why: evidence}`
   - `verdict` `Completed{refused}`:
     - at `prepared` → `SetupRefused`
     - at `build` → `Propose{BuildRed{output: evidence}}`
     - at `review` → `ReviewFindings{findings}` if **any** finding has `failureScenario.trim() !== ''`, else `ReviewEmpty{said: evidence, findings}`. The trim matches `fix.ts:375`'s `actionable`. `ReviewFindings` carries **all** findings, not just the actionable ones; the route decides.
     - at `proposed` or `merge` → `CheckRefused{step, action: name, evidence, findings}`
   - `AnswerUnreadable{raw}` (verdict, design) → `WaitOnPerson{AnswerUnreadable{step, action: name, raw}}`
   - `design` `Asked{question}` → `Propose{InputNeeded{from: 'design', question}}`. The draft is not carried.
   - `commit` `Completed` with a `question` → `Propose{InputNeeded{from: 'implement', question}}`
   - `signoff` `Completed{requested}` → `SignoffRequired{step, action: name, question: requested.question}`
   - `merge` `Completed`:
     - `Conflicted` → `Propose{MergeConflict{paths, baseSha, headSha}}`
     - `IntegrationRefused{verify-failed}` → `Propose{VerifyRed{output: evidence}}`
     - any other reason → `MergeRefused{reason, raw: evidence}`. Narrowing `verify-failed` away is what makes `reason` fit `RefusalReason.exclude(['conflict','verify-failed'])` (`wait.ts:130`).
   - `NotReached` cannot be the deciding action. Narrow it away explicitly; do not leave it as a `default`.
3. **Step cleared, `implement`, `changedNothing(outcome)`** (`action.ts:357`) → `outcome.round > 0` gives `FixerDisagrees`, `0` gives `NothingProduced`. Read nothing about which agent ran. `said` is the **last `commit`-yield action's `evidence`**, or `null` when there is none (a lone `file-brief:`) or its evidence is `""`. An `implement` with no actions is `NothingProduced` too, as `changedNothing`'s doc already says.
4. **Step cleared, anything else** → `Advance{to: STEPS[STEPS.indexOf(step) + 1]}`. For example, `review` → `proposed` and `proposed` → `merge`.

**The impossible cells throw.** Some cells cannot occur under 0120 §1's legality table plus the plugin table, and 0118's narrower `step` fields refuse them at the type level:

- `AgentCrashed` and `AnswerUnreadable` at `admit`, `prepared` or `build`. No agent runs there, and a `run:` timeout is a refusal (`process-action.ts:74`).
- `CheckRefused` or `SignoffRequired` off `proposed` and `merge`.
- A verdict refusal at `admit`, `design` or `implement`.
- A `merge` step that cleared without an `Integrated`. #270 refuses a written step with no lane, and `merge: []` takes the default lane (`recipe.ts:2491-2515`).
- Any outcome at `claim` or `end`. Both run outside `runPass` (0120 §6).

Throw a named error class for these, following the `MissingUpcasterError` precedent (`upcast.ts:222`), with the step and yield in the message. Test each one with `toThrow`.

This is the contract `wellFormed` already sets (`action.ts:476-478`): *"the other step-level functions above take a well-formed outcome and do not check it themselves"*. Do not widen `wait.ts`'s step sets to avoid the throw: they are 0118 §1's spelling (`0118:107-118`).

## `fromOf`

`fromOf` is a `switch` on `_tag` with no `default`:

| Variant | Step |
|---|---|
| `BuildRed` | `build` |
| `ReviewFindings`, `ReviewEmpty` | `review` |
| `InputNeeded` | its own `from` |
| `MergeConflict`, `VerifyRed` | `merge` |

Return type: `Step`.

## `spentAfter`

A `switch` on `next._tag`:

- `FixRound{round}` → `{ ...spent, rounds: round }`
- `Requeued` with `cause._tag === 'Restart'` → `{ rounds: 0, restarts: restart }`
- every other tag, including `Requeued{NeverStarted}` → `spent`, unchanged

It sets the counts and never increments them. 0120 §4: *"`round` and `restart` are what was spent plus one, computed by `offerFor` … applied by `spentAfter` without a second judgement."*
