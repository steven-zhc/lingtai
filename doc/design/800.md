## The prose that replaces `:923-942`

Delete *"Under Lingtai today a user's permission profile does not apply … The fix is #667, held for design; this section changes no argv."* Also delete the paragraph about `--sandbox` being removed and `sandbox-exec: execvp()` (`:933-938`); it describes an experiment from before #667. Replace them with what the code does now, citing each point:

- **What narrows.** The profile named by `default_permissions` contributes only its `deny`/`none` filesystem entries, following `extends` to collect them and never to inherit (`packages/agent/src/codex.ts:571-576`: *"Only `deny` and `none` are collected: a user can narrow a run and never widen it, and `extends` is followed only to collect, never to inherit"*). Lingtai launches the role itself as a profile, `lingtai_workspace_write` or `lingtai_read_only`, which extends `:workspace` or `:read-only`, with those denies added (`codex.ts:1251-1278`). `--sandbox` is passed only when there are no denies (`codex.ts:1288`).
- **What it cannot do.** It cannot widen anything: a `write` entry or the user's own `extends` is never carried over (`codex.ts:1251-1252`: *"Never the user's own `extends`: their chain may end at `:danger-full-access`"*).
- **`sandbox_mode` in the user's config** keeps the old behaviour: the profile does not apply and the run goes out with `--sandbox` (`codex.ts:591-592`). Any other config Lingtai cannot read leaves the profile out the same way: invalid TOML, a profile that is not defined, an `extends` cycle, or a profile using the name `lingtai_workspace_write` or `lingtai_read_only` (`codex.ts:579-620`). In both cases the run log gets *"the user's Codex permission profile did not narrow this run: …"* (`codex.ts:1419-1420`). Say that it is the run log, which is not a record (see the `CODEX_HOME` paragraph `:944` and 0034).
- **A deny that covers the worktree or a write root refuses the run** rather than launching it exposed (`codex.ts:1421-1427`). That is behaviour of the code, not a measurement, so word it as such and do not add a row for it.

Keep the profile snippet at `:926-932` as the profile the probe used. The *Not measured* list (`:952-961`) stays as it is, apart from the note under **Also stale**.
