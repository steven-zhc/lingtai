## Design note for #525

Add one **Visual comparison** section after “The order” in `doc/design/task-detail-page.md`. Make its primary table one row per page part: ticket, where it is, triage, resolutions, record. Each row should give the current evidence, the requirement in 0118 §2, and either an intentional difference or a specific change owned by #526 or #527. Record a shared layout gap once, then name the fixtures and widths where it appears. This keeps the report about the page hierarchy rather than turning four scenarios into four copies of the same finding.

Use representative Waiting fixtures for advised triage, no declared triage, failed triage, and `ConflictingHunks`, at desktop and narrow widths. Existing render tests provide starting states: `apps/board/unit/triage-band.test.tsx:24` checks absence of a band, failure, and conflict hunks; `apps/board/unit/standing.test.tsx:1650` checks the ticket opening and current advice. For a visual claim, inspect the rendered page at both widths and cite a screenshot or the relevant markup and CSS lines. The current component places the ticket opening before the state (`apps/board/src/app/standing.tsx:455`), triage before moves (`apps/board/src/app/standing.tsx:604`), and the record after Standing (`apps/board/src/app/task/[id]/page.tsx:778`). Those source lines establish order, not whether the hierarchy reads clearly on screen. Where a conclusion depends on which wait actually received advice, name `WaitStarted.waitId` and the latest `WaitTriaged.waitId`, `attempt`, and `result` as the settling log evidence; do not infer that history from a live page.

Treat mockup details as visual cues only. The ADR says the examples “illustrate the decision and do not extend it” (`doc/decisions/0118-a-hold-explains-itself.md`, “Mockups”). In particular, §2 says “A body is not assumed to have any structure”; the existing opening is a collapsed `<details>` containing rendered body text (`apps/board/src/app/standing.tsx:473`). Mark the mockup’s Problem/Want/Watch out columns as an intentional difference, with no body parsing proposed. A Queued page is not a substitute Waiting fixture: Standing renders its own queued moves (`apps/board/src/app/standing.tsx:748`), while the triage band is gated on a blocked state (`apps/board/src/app/standing.tsx:604`).
