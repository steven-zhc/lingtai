# Design: #624. `run`, `attach`, `ticket`, `end` and `backlog` move to `@effect/cli`, and `ask` is already done

## `ask` is already done. Do not touch it

#621 already moved `ask`:

- It is in `MIGRATED_COMMANDS` (`migrated.ts:21`).
- `cli.ts:240-245` parses it, and it prints through `answerWith`/`renderVerdict`.
- Its usage already carries `[--json]` (`commands.ts:265`).
- `lingtai.ts:1082` has it in the "runs from the entry" refusal group.

So this ticket covers five commands. Say so in the PR. Do not reopen #621's verdict shape.

## Routing

Add `'run'`, `'attach'`, `'ticket'`, `'end'` and `'backlog'` to `MIGRATED_COMMANDS` (`migrated.ts:9-23`).

In `lingtai.ts`, move their five cases (`:885-955`, `:957-969`, `:982-999`) into the refusal group at `:1072-1085`, and update that group's comment.

There is no #623-style trap here. `board` had to stay a real case because `service.ts:163` writes `lingtai.ts board start` into a plist. The only other job is `argv: ['daemon']` (`service.ts:134`). Nothing in `apps`, `packages` or `scripts` spawns `lingtai.ts` with any of these five names.

Delete the imports in `lingtai.ts` that become unused: `:49`, `:50`, `:56`, `:70` and `:73`. Lint fails on them otherwise. Add `migrated.test.ts` rows sending each command to `'effect'`, and `--help` rows for each sending it to `'help'`.

The handlers go in `cli.ts` and `await import()` their module inside the handler, as `status` does (`cli.ts:49-52`). `lingtai version` must not pay for the conductor.

For tests, extend `runCli`'s `deps` (`cli.ts:439`) the way `board` did. Each command gets an injectable runner that receives the parsed request, with the live one as the default. The parsing tests then assert what reached the runner, with no log and no GitHub involved.

## Output: what changes, and what must not

Each command gets a heading through `heading`/`section` (`output.ts:68-75`) and glyphs from `symbol` (`output.ts:62-66`). Every sentence after a glyph stays **word for word**.

**Lines the command passes on from elsewhere are not its own, so they stay raw.** For `run`, that is everything that reaches `log` from `runQueue`/`runOnce`/`schedule.ts`. `schedule.ts:247-248` prints `held at`/`stopped at` for the daemon too, and `doc/reference.md:1800-1802` says a log is *"grepped for `stopped at`"*. For `attach`, that is every line of the file.

### `run`

- The handler prints the heading `run <project>` before calling `run()`.
- Keep the two `statedBeforeDispatch(resolved.recipe)` call sites in `run.ts` exactly where they are. `unit/run-before-dispatch.test.ts:126-140` asserts their position from the source.
- Glyphs go only on `run.ts`'s own closing lines:
  - `✓ landed …` (`:529`).
  - `● held at … is waiting on you` (`:535`). This is a person being waited on, which is what `signal` is for (0121 §2).
  - `✗ stopped at …` (`:541`). `stopped at <stage>` stays an intact substring.
  - The tally `N run(s): …` (`:512`): `✓` when `stopped === 0`, `✗` otherwise.
  - `Refused` and `LockUnreadable` (`:563-584`): `✗`.
- Pause and `ConductorBusy` exit 0 and take no glyph, because neither is a failure.

No `--json`: `run` is `changes` (`commands.ts:89`) and its report is a stream of progress.

### `attach`

- Only the header and the not-found refusal change.
- `attached to ${project} · ${path}` (`attach.ts:66`) becomes the heading `attached to <project>`, then `keyValues([['log', path]])`, then one blank line. Put this in a pure `attachHeader(found): string[]` so a unit test can pin it under `NO_COLOR`.
- `✗ ` goes before `no run log for …` (`:52`).
- The followed lines (`:73`) and the three ending sentences (`:77-88`) stay byte for byte.
- Rewrite the header comment `No colour, on purpose…` (`:26-27`). It is false once the heading is painted.
- `integration/attach.test.ts:49` asserts `out[0]` and must change with the header. That file is integration (filesystem), so it is out of reach inside a pass. The unit test of `attachHeader` stands in for it.

### `end replay`

- Heading `end replay`, plus `<project>` or `<project>#<issue>` when it is narrowed.
- `✓` on each `end resolved for …` line (`end.ts:104`).
- `✗` on `not replayed — …` (`:108`) and on `… onboarded — skipped` (`:78`), since neither was replayed.
- The `N replayed` tally (`:112`) has no glyph.
- `nothing to replay — …` (`:54`) stays one line and exit 0 (0121 §1).

### `ticket close`, `new` and `edit`

- `✓` on `closed #n  title`.
- `✗` on every refusal line from `pickProject`/`resolveDbRecipe` (`ticket.ts:118`, `:124`, `:128`, `:150`, `:154`).
- Keep them going through the injected `log`. `unit/ticket.test.ts` drives that sink.
- `$EDITOR` is spawned with inherited stdio, and `consoleFor` (`cli.ts:388`) wraps only Effect's `Console`, so the editor is unaffected.

## `--json` for `ticket list` and the backlog listing: split each into read, render and json

Follow #623's `board status` shape (`cli.ts:303-306`). Both `ticketList` (`ticket.ts:167-210`) and `list` (`backlog.ts:107-150`) currently read and print in one function. Split each into three pure parts, so a unit test can pin the text and the document without a process:

- `read… → Listing`
- `render…(listing, { columns }) → string[]`
- `…Json(listing)`

### `ticket list`

`command` is `"ticket list"`, for the reason 0121 §5 gives for `"board status"`.

- **Text:** the heading `<project>`, then `table(['ID','KIND','TITLE'], …)` (`output.ts:88`). It replaces the hand-padded columns at `ticket.ts:193-207`. Keep `[closed]` and the non-kind labels in the TITLE cell.
  - `unit/ticket.test.ts:149` reads `lines.map(l => l.split(/\s+/)[0])`. It now asserts on the rows after the heading and the header row, or against the listing.
  - The empty case stays one line: `no open tickets for <p>` / `no tickets for <p>`.
- **Document:**

  ```json
  {"version":1,"command":"ticket list","project":"p","all":false,
   "tickets":[{"number":3,"kind":"bug","title":"…","state":"open","labels":["bug","agent:hold"]}]}
  ```

  - `title` is the full title, not `oneLine`'s cut. That cap is a rule about what fits on a line (0121 §4).
  - `kind` is `kindOf(…)`, or `null`.
  - `labels` is every label, including the kind label.
- **Refusals** become `error` documents with a code, exit 1. This means `pickProject`/`resolveDbRecipe` must return a code and not only log:
  - `no-project` (the named project does not exist)
  - `no-projects`
  - `ambiguous-project`
  - `recipe-unreadable`
  - `tickets-on-github`

### `backlog`

`command` is `"backlog"`. Its only read verb is the listing.

- **Text:** one `section(project, …)` per project.
  - Inside it, `describeEntry`'s lines unchanged (`backlog.ts:85-105`). `unit/backlog.test.ts:66-71` pins them.
  - The closing `accept one:  lingtai backlog accept …` (`:148`) becomes `next: lingtai backlog accept <project> <key> --kind <kind>` (0121 §1).
- **Document:**

  ```json
  {"version":1,"command":"backlog","project":null,"all":false,
   "entries":[{ …every BacklogEntry field…, "raisedAt":"…ISO…", "decidedAt":null, "title":"…" }],
   "behind":"<message>"}
  ```

  - `title` is the `task_view` title the text already shows (`:134-138`), or `null`.
  - **`behind` is present only when the catch-up threw** (`:114-115`). It is a fact the old output printed, and under `--json` it must not reach stdout as prose. Leave it out otherwise, never `null`, as #621 did with `reason`.
  - Anything the projector warns about goes to stderr under `--json`.
  - A `readBacklog` that throws goes through `failed()` (`cli.ts:34`).

## 0121 §5: edit it, do not add a file

`ticket` and `backlog` are `effect: 'changes'` (`commands.ts:137`, `:156`), and `attach` is `'reads'` (`:124`). As written, §5 gives `attach` `--json` and gives `ticket list` and the backlog listing nothing.

The paragraph #623 added already states the rule for the second case: *"A read-only verb of a `changes` command takes `--json` too (#623): `board status` today"*. Extend that list to `ticket list` (`"ticket list"`) and the listing `backlog [<project>]` (`"backlog"`).

Add one sentence for `attach`: *a command that follows a stream (`attach`) is not a report and takes no `--json`; its lines are the run's own (0034 §8).*

This is an edit to `doc/decisions/0121-…`, the topic's own ADR. CLAUDE.md says *"A decision that changes is an edit to its topic's ADR, not a new file beside it"*, and #621 and #623 both edited it this way. The append-only files are `decisions-archive/`, and none is touched.

Update the usage lines for `ticket list` and `backlog [<project>] [--all]` in `commands.ts` to add `[--json] [--no-color]`, within the 76 columns `commands.ts:10-12` says `help.test.ts` measures.
