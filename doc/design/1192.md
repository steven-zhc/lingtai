# Design note: #1192 — receipts chosen by cost percentile

## The decisions the ticket leaves open

**1. Where each percentile's target comes from.** Generalise `p90` (`take-books.ts:89-94`) into `percentile(xs, q)` and keep its rule: *"Nearest rank, not interpolated: the smallest value with at least 90% of the sample at or below it."* `p90` becomes `percentile(xs, 0.9)` and keeps its export, because `books.test.ts:5` and `:183-186` import it and must still pass unchanged.
- Nearest rank means each target is the cost of a real ticket. The 25th and 50th then have a ticket at distance 0 whenever that ticket is titled.
- The sample is `costs` (`take-books.ts:188`): every landed, priced ticket in the window, **titled or not**. That is the same sample `cost.median` and `cost.p90` are taken from (`:212-214`). So the card labelled 90th stands for the published p90, and an untitled ticket still moves the targets.
- The pool the receipts are picked from is smaller: landed (`landed`, `:154`), `dollars(row) !== null`, with a non-empty title.

**2. The order of choosing.** Pick for 25, then 50, then 90. Each takes the unchosen candidate with the smallest `|cost − target|`; on a tie the lower issue number wins. This is the order the ticket's *Watch out* example assumes ("the 50th takes the next nearest"). Make it one small pure function, for example `pickByPercentile(candidates, costs)`, and test it directly. The six unit cases in *Done when* belong there, not only in a `takeBooks` round trip.

**3. Where the title and the number come from.** The candidate is now a row, not a typed number.
- Its project is `row.project`; non-null because `publicRows` filtered on it (`:152`).
- Its issue is `parseTicketStream(row.ticket)?.issue`. If that is null, skip the row.
- Its title is `o.titles.get(titleKey(row.project, issue))`.
- The "ambiguous across projects" refusal (`:162-163`) has nothing left to guard, and goes.
- `books.ts:162-165` already reads `task_view` with a retention that covers the whole window. Its comment says *"a receipt from the start of the window would come back untitled"*. That comment now applies to every candidate, and nothing else in that read changes.

**4. `takeBooks` can no longer refuse.** The only refusals it produced were about `--receipt` (`:157-181`). The `{ ok: false; refusals }` arm of `TakeBooks` (`:40`) has nothing left to produce it.
- Make `takeBooks` return `Books`.
- Delete `if (!taken.ok) refuse(...)` (`books.ts:180`).
- Delete *"a `--receipt` it cannot stand behind"* from the header (`books.ts:24-25`).
- In `books.test.ts`, the `t.ok` unwrap (`:53`) and the `reason()` refusal cases (`:209-220`) go. The new selection cases replace them.

A read that fails still refuses in `books.ts` (`:151-160`, `:197-199`). That part is untouched.

**5. The field.** Add `percentile: 25 | 50 | 90` to `Receipt` (`apps/site/src/lib/books.ts:33`), as a number rather than a label string, so the card owns the wording.
- In `receiptOk` (`:136-145`), accept exactly those three values. `shaped` keeps refusing a missing or extra key.
- `MedianReceipt` gets no field.
- Every chosen receipt is landed, so `outcome` is always `'landed'`. Keep the field and the parser's `OUTCOMES` (`:128`) anyway, so the file's shape stays one change smaller. The closed and open branches of `receiptCard` (`books-section.tsx:106-118`) then never run on published data. Leave them in: that is a follow-up, not this ticket.
- The committed `apps/site/books.json` holds only the median receipt (`97a2a20c`). It parses before and after, so it needs no hand edit. The person's rerun in *Done when* is what fills it.

**6. The card's label.** Header line: `ISSUE #${number} · ${KIND} · ${n}TH PERCENTILE BY COST`, dropping the kind segment when `kind` is null, as `:122` does today.
- 25, 50 and 90 all take "TH", so no ordinal helper is needed.
- If 1360px clips the line, `· P25 BY COST` is the agreed fallback ("or a shorter label the card fits"). Choose by looking at the page.
- Order: median card first, then the receipts sorted by `percentile` ascending (`:239` builds the array).

## The heading

- Delete the `books-total` block (`books-section.tsx:152-160`) as a sibling of `books-head`.
- `books-head` keeps the two grid children it has today (`home.css:316`):
  - **Left:** kicker, `h2`, then the window sentence as a `<p>`. The sentence moves from the right column (`:166-169`) and loses its badge.
  - **Right:** the card, holding the badge, the count, *issues closed by its own merges*, and the mono *since … · as of …* line.
- With no `landedAllTime`, the right column holds the badge only and draws no card around it.
- Reuse the `books-total*` class names (`home.css:312-315`) on the card. That keeps the CSS diff small and the class names stable.
- The rule `.books-head p:not(.kicker)` (`home.css:317`) will now also catch any `<p>` inside the card. Build the card from `div`s, or narrow the selector.
- The stacking the ticket asks for at narrow widths already exists at `home.css:348-349` (`grid-template-columns: 1fr`). Check that the card goes full width there.
- `home-css.test.ts` only checks the sandbox block for class names it shares with the board's stylesheet. Making up a new class name here is safe only if `apps/board/src/app/globals.css` does not use it.

## Checks

Everything here is unit-level: `books.test.ts` covers selection and parsing, and `books-section.test.tsx` covers the render cases with and without `landedAllTime`, plus the footer text. No `pnpm test:integration` file touches it. The screenshots at 1360px and 390px are the person's, after the rerun. No ADR is touched.
