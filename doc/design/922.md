## Design: #922. The task page sends the person's picks

### The conductor half is only partly there, so this ticket finishes it

The ticket says the conductor accepts `picks` since #921. That is true for `GrantFixRound` and not for `Requeue`:

- `resolveWaitHolding` takes `picks` (`packages/conductor/src/resolve-wait.ts:160-161`) and passes them to `triageAnswersText(triage.cause, options.picks)` (`:372`).
- `requeue()` (`packages/conductor/src/approve.ts:320-345`) and `requeueHolding` (`:366-373`) have no `picks` option. The `resolveWaitHolding` call in `requeueHolding` (`approve.ts:419-431`) passes `github` and nothing else from the triage side. So `requeueCard` has nowhere to send picks today.

Add `picks?: Readonly<Record<number, string>>` to both option types in `approve.ts`, and pass `picks: options.picks` in the `resolveWaitHolding` call at `:419`.

This does not change the server-side write, which the ticket puts out of scope. It is one pass-through field. Without it, the Done-when about `requeueCard` can only be met by a test that asserts picks reach a function that drops them. Add one unit case beside `packages/conductor/unit/triage-answers-written.test.ts`: a `requeueHolding` with non-recommended picks writes the picked answer. `continueFixingCard` goes through `resolveWait`, which hands its options to `resolveWaitHolding` (`resolve-wait.ts:198`), so `picks` on its input reaches `:372` as it stands.

### `TriagePicks` takes the `cause`, not the questions

`triageAnswersText` needs the cause (`packages/domain/src/triage.ts:128-131`), because a hunk's `path:line` lives on the `TriageAsk` and not on the `TriageQuestion`. So:

- **The prop.** `TriagePicks`' `questions: readonly TriageQuestion[]` prop (`apps/board/src/app/triage-picks.tsx:46-55`) becomes `cause`, of the type `triageQuestionsOf` accepts, or `null`. `standing.tsx:843-846` passes the `cause` it already computes at `:721-724`. The `triageQuestions` block at `standing.tsx:725-730` is deleted outright. Nothing else reads it: `grep` finds `triageQuestions` only at `:725` and `:845`.
- **The text.** `text` (`triage-picks.tsx:62-69`) becomes `triageAnswersText(cause, answers)`, giving `.text` when `ok` and `''` otherwise, with `''` for a null cause. The `!ok` branch cannot be reached from the page, because every pick is an `answer.id` drawn from the same question (`TriageChoices`, `onChange={() => draft?.pick(index, answer.id)}`). Do not add a refusal surface for it. `oneLine` stays, since `appendTo`'s callers do not use it but nothing else does either; delete it if it is unused after the change.
- **`selected`** (`:61`) keeps reading `answers[index] ?? question.recommended`. The radios still index by `TriageChoices`' `index`. That index already matches `triageQuestionsOf`'s order in both cases: `UndecidedQuestion` maps `cause.questions` by index (`standing.tsx:135-139`), and `ConflictingHunks` indexes within `divergent` in hunk order (`:160`, `:186-196`). This is the same order `triageQuestionsOf` walks (`triage.ts:112-115`). Do not re-index.
- **New context field.** Add `picks: Readonly<Record<number, string>>`, the current wait's `answers` only. `answers` is already `{}` when `picks.waitId !== waitId` (`triage-picks.tsx:58`), so the edge "picks from another wait" is handled by exposing `answers` and nothing more.

**The text format changes on purpose.** Each line becomes `- <question> — <answer>`, with a `` `path:line` — `` prefix for a hunk, and question text no longer whitespace-collapsed. Any assertion in `apps/board/unit/edit-body-and-requeue.test.tsx` or `add-to-resolution.test.tsx` on the old `question — answer` lines is updated to the domain's output, not kept. Keeping the old format would leave two compositions, which is exactly what the ticket's Watch-out forbids.

### The actions

`continueFixingCard` (`apps/board/src/app/actions.ts:180-185`) and `requeueCard` (`:278-284`) gain `picks?: Readonly<Record<number, string>>`. It goes into `resolveWait({... picks: input.picks })` at `:198` and `requeue({... picks: input.picks })` at `:292`.

`picks` is **optional**, so the three call sites that send none stay as they are:

- the reschedule button (`decide.tsx:247`);
- the home card's `TriageMove` (`decide.tsx:880`, `:884`).

For the Done-when test that calls each action with a fake conductor, the existing pattern is `vi.mock` of the conductor subpath the action imports: `requeue` from `@lingtai/conductor/decide` (`actions.ts:39`), as `apps/board/unit/queued.shape.test.ts:8-14` mocks `@lingtai/conductor/*`. Check `actions.ts`' imports for `resolveWait`'s subpath and mock that one too. `loadProject`, `projectClient`/`ownerlessClient` and `answersChannel` need stubbing so the call reaches the conductor function. This test does not touch the filesystem or the network, so it stays in `unit/`.

### The cards

- **`ContinueFixing`** (`decide.tsx:265-300`) reads `useTriageDraft()`. It sends `picks: triage?.waitId === waitId ? triage.picks : {}`, guarded on the wait the same way `EditBodyAndRequeue` guards `composed` at `:326`.
- **`Requeue`** already holds `shared = useTriageDraft()` (`:460`). It adds the same guarded `picks` to `requeueCard` at `:533`, and **only on the requeue branch**: `answerCard` and the withdraw path send none. Withdraw also calls `requeueCard` (`asked && withdrawing`). Send `{}` there, because a withdrawal of a question asked before any run is not a resolution that sends an agent with triage answers.
- **`EditBodyAndRequeue`** (`:325-327`) needs no change beyond `triage.text` now being the domain's text.

For the component test, `edit-body-and-requeue.test.tsx:8-41` already has a harness that mocks `react`'s `useState`/`useContext` and `../src/app/actions.ts`. Extend that mock with `continueFixingCard` and `requeueCard` spies. Mount `TriagePicks` with a cause whose recommended answer is `A`, `pick(0, 'B')`, click, and assert the spy's `picks` is `{ 0: 'B' }`.

### Edges the ticket leaves open, decided

- **A null cause.** A waiting ticket whose triage is not `Done`/`TriageAdvised` gets `cause === null` (`standing.tsx:721-724`), `text === ''` and `picks === {}`. This is the same as the empty `questions` array today.
- **The person-check is the only end-to-end witness.** No unit test reaches GitHub's body. The unit-level claim that stands in for it is the conductor case above: a non-recommended pick written by `requeueHolding` and by `resolveWaitHolding` for `GrantFixRound`. If the server's write needs settling, the event that does it is the `WaitResolved` for the wait, read alongside the issue body. The `written` flag on the result (`approve.ts:346`) says whether a section was written.
