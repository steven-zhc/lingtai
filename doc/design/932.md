# Design note: #932, `ProposalRouted`

#931 has landed in this worktree. `RouteOffer.ended` exists (`packages/domain/src/routing.ts:81`), and the writer fills it in (`packages/conductor/src/conduct.ts:4451`, *"`ended` is the `StepEnded` the proposal was taken from, recorded when it was emitted"*). The ticket's line numbers in `events.ts` and `conduct.ts` have drifted. The current ones are:
- `PassRouted`'s doc and schema: `events.ts:1426-1460`
- its `EVENT_AT` row: `events.ts:2470`
- `RETIRED`: `events.ts:2536`
- the writer: `conduct.ts:4430-4462`

## 1. The copy is dropped only when `ended` is non-null

`ended` is `null` in two cases that the ticket's Edges do not name:
- `run-attempt.ts:1534` sets `endedAt.version = typeof version === 'number' ? version : null`. So an `emit` that returns no number gives `ended: null`, even for a `BuildRed`. Many unit fakes do this, and `conduct.ts`'s `appendNow` never does.
- The routing visit built by `routeProposal`'s own `record()` has no `StepEnded` at all (`run-attempt.ts:1504-1506`).

When `ended` is null the evidence has nowhere else to live, so it is not a copy. Rules:
- **Schema.** On the stored union, the evidence fields of `BuildRed`, `ReviewFindings`, `ReviewEmpty`, `CheckRefused`, `SetupRefused` and the merge refusals (`output`, `findings`, `said`) are **optional**. A `superRefine` on `ProposalRouted` enforces: `ended !== null` ⇒ none present, and `ended === null` ⇒ all present. This is the ticket's *stored whole*.
- **Writer.** It strips the fields if and only if `route.ended !== null`.
- **Where it lives.** Put the stored union beside `Proposal` in `proposal.ts`, so the next variant added to `Proposal` is visibly missing from it. A `satisfies`/exhaustiveness check on the `_tag` set keeps the two unions in step.

## 2. The resolver reads the action `ended.action` names

Do not re-run `decidingAction`.

Signature:
```ts
resolveOffer(offer: StoredRouteOffer, endedAt: (version: number) => StepOutcome | undefined)
  : { _tag: 'Resolved'; offer: RouteOffer } | { _tag: 'Unresolved'; version: number | null; why: string }
```
- `StoredRouteOffer` is `RouteOffer` with a `StoredProposal`, so one shape reads both `PassRouted` (which kept the copy) and `ProposalRouted`. `version` is `null` only for a route that has no copy and names no `StepEnded`.
- Look up `outcome.actions.find(a => a.name === ended.action)`.
- `output` and `said` take `action.evidence`. `findings` takes `action.result.assessment.findings`, and only from a `verdict` that is `Completed` (`attempt-next.ts:284-296`).
- `SetupRefused` can also come from a `nothing` action's `NotDone` (`attempt-next.ts:275`), which has `evidence` and no assessment. That case must resolve too.
- These return `Unresolved` with a `why`, and never an empty list:
  - the action is missing;
  - the action lacks the field the variant needs;
  - the version does not resolve.

Also export a small `stepEndedsOf(events: Envelope[]): (v) => StepOutcome | undefined`. It takes the run stream's `StepEnded`s keyed by `event.version`. This keeps the board and `boardFactOf` from each building their own map.

## 3. The move-only function, and `routeNext` built on it

Add `routeMove(offer: { available }, reply, decision)`. It returns `CandidateNext` minus `HandToPerson`, or `{ _tag: 'WaitOnPerson' }`, and throws the same `ImpossibleRouteError`s as `routeNext` (`routing.ts:310-321`).

Then rewrite `routeNext` to call `routeMove` for its Selected branch. With one implementation of the selection rule, the agreement test in Done-when becomes a check rather than a hope. `InputNeeded` keeps `question` (it is not a stripped variant), so the `AgentQuestion` branch (`routing.ts:334-338`) is unchanged.

Readers:
- **Need only the move:** `attempt.ts:512-524` and `routesOf` (`read-model.ts:88-101`) call `routeMove`.
- **Need the evidence:** `history.ts` and `boardFactOf` call `resolveOffer` and then `routeNext`. `fromOf(proposal)` in `routesOf` reads only `_tag`/`from`, which survive stripping.

## 4. The attempt reducer stores the route as written

`AttemptState.route` becomes `StoredRoute | null`: the bare payload, `{ runId, offer, reply, decision }` with a `StoredRouteOffer`, as both event types share it (`attempt.ts:198-199`).
- **No tag is needed:** the reducer never asks which type wrote the route. Both event types carry the same four fields, and `StoredRoute` (`run-codec.ts`) parses either.
- **Retired types:** the reducer must keep a `PassRouted` case for ever, since the type is retired, not deleted.

`refusal` (`attempt.ts:194`, set at `:532-541`) gains `endedVersion: event.version` and `action: action.name`. Store `action` separately: `key` is `step:action` and the route's `ended` carries only the action name.

Add `roundFindingsOf(state): number | null` to `attempt.ts`:
- a `PassRouted` returns its copy's count;
- a `ProposalRouted` returns `refusal.findings.length` when `refusal.endedVersion === ended.version && refusal.action === ended.action`;
- otherwise it returns `null`.

`task-view.ts:648` calls this function and shows no count on `null`, which the ticket's Out of scope allows. The rule then lives in the domain rather than in the projector.

Bump `attemptReducer.version` (`run-codec.ts`) and add the row to `reducer-versions.json`. Both the state shape and the codec change.

`apps/cli/src/triage.ts:465` and `packages/conductor/src/triage.ts:63` only need their type moved to `StoredRoute`. They read `reply`/`decision` off the route directly.

## 5. Board and `boardFactOf`

- **`LineContext` (`history.ts:101-107`)** gains `endedAt?: (v) => StepOutcome | undefined`. `groupHistory` sets it from `byRun` (`task.ts:1340-1346`), the same way it already sets `branch`/`claim`. Register the `ProposalRouted` formatter beside `PassRouted` (`history.ts:451`); both go through `resolveOffer`.
- **On `Unresolved`:** render `routeMove`'s move and *"the evidence on the StepEnded at version n was not found"*. Do not throw.
- **The existing throw at `history.ts:458`** (*"formatted as a wait, but routeNext answered …"*) stays, for a resolved route.
- **`boardFactOf` (`read-model.ts:301-313`)** takes `endedAt` as a second argument. On `Unresolved`, emit `RoundOpened` with `findingsUnknown: { version }`, and `Restarted` with `evidenceUnknown: { version }`, not an empty list. `history.ts` words both with the version the route named.
- **Finding the callers:** a zsh `--include=*.ts` glob silently matches nothing here, so use `rg "boardFactOf\("`.

## 6. The registries outside `events.ts`

- `packages/domain/scripts/events.ts:128-133`: the writer anchor `type: 'PassRouted' as const,` moves to `ProposalRouted` with the same `why`. Handle `PassRouted`'s row the way the existing retired types (`OutboxDelivered`, `OutboxFailed`, `TicketLinked`) are handled in that file's tables; follow their precedent rather than inventing one.
- The `pass-` stream row for `PassRouted` gets a sibling for `ProposalRouted`.
- `EVENT_AT`: `PassRouted: []`, and `ProposalRouted: ['review', 'proposed', 'end']`.
- Regenerate `doc/events.json` with `pnpm events:generate`.

## 7. Tests: where the old type can still go

`store.append` refuses a retired type (`packages/event-store/src/event-store.ts:316`), and so does the memory store, which is held to the same contract. So:
- Any unit test that **appends** a `PassRouted` through a store now fails. That includes conductor tests asserting what `conduct.ts` writes, such as `what-an-attempt-writes-today`, `what-an-event-is-written-at`, `conduct-a-whole-attempt` and `run-attempt`. Move those to `ProposalRouted`.
- Tests that hand a `PassRouted` envelope **directly to a reducer or formatter** keep it. That is the proof that old routes still read: reducer tests, `history.test.ts`, the `task-view-*` unit tests and the fixtures in `packages/domain/test/histories.ts`.
- `packages/domain/unit/pass-routed-ended.test.ts` is where #931 checked the reference against the copy. Extend it into the resolver's tests.
- **The fixture pair for the board:** build the `ProposalRouted` by stripping the `PassRouted` fixture through the writer's own strip function. Do not hand-write it twice. Export that strip function from domain so the writer and the fixture share it.

**Out of reach inside a pass:** the retired-append refusal against Postgres is in the integration half. The memory store's refusal, under the shared contract, is the unit-level claim that stands in for it.

**What settles it on the live log:** after the merge, each `ProposalRouted`'s `offer.ended.version` should name a `StepEnded` on the same `pass-…` stream. Its `outcome.actions[]` should contain an action named `offer.ended.action` that carries `evidence`, and `result.assessment.findings` where the proposal is `ReviewFindings`.
