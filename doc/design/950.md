# Design note for #950: remove the footer's links and set it at 14px

## Where it goes

There are three files: `apps/board/src/app/footer.tsx`, `apps/board/src/app/globals.css` and `apps/board/unit/footer.test.tsx`. Four more files are touched only because the `project` prop is removed (see *The `project` prop goes too* below).

## The decision the ticket doesn't spell out: the home stays at the right edge

Today the `.links` span is what pushes the home to the right. `globals.css:183` reads `.footer .links { margin-left: auto; … }`, and `.home-at` comes right after it (`footer.tsx:111`). Delete the span and that rule, and the home moves left until it sits against the currency.

The yardstick keeps the home on the right. Its v=c footer puts an empty `<span class="grow"></span>` between `.currency` and `.home-at` (`doc/design/board-navigation.html`, the `data-v="c"` view's `<footer>`). Nothing in `globals.css` defines `.grow`. Don't add the spacer span. Put `margin-left: auto` on `.footer .home-at` (`globals.css:184`) instead. That keeps the markup to the four facts, and the comment `footer.tsx:40` already gives the home its place: *"the last item, where a wrong home is still seen."*

## Sizes: copy the yardstick, not just the ticket's two numbers

The v=c overrides are at `board-navigation.html:911-914`:

```
.footer{font-size:14px !important;padding:10px 20px !important;gap:24px !important;…}
.footer .meter{width:180px !important;height:8px !important}
.footer .home-at{color:var(--muted);font-size:12.5px}
```

- **`.footer`** (`globals.css:165-171`): use `font: 14px var(--sans)`, `padding: 10px 16px` → `10px 20px`, and `gap: 22px` → `24px`. The ticket names only the 14px, but its *Done when* is "checked by eye against v=c", and that page has the padding and gap too.
- **`.footer .meter`** (`globals.css:176-179`): set it to `width: 180px; height: 8px`. Change `border-radius: 3px` to `4px` so the ends stay round at the new height. That's a judgement call the yardstick doesn't make (it keeps 3px), so dropping it is fine.
- **`.footer .home-at`**: leave it at 12.5px, which is already set explicitly (`globals.css:184`), the way the yardstick has it. The home is a fact about the board, not a reading.
- **`.footer .currency`**: leave its own `font: 11.5px var(--mono)` (`globals.css:182`). The yardstick doesn't change it either.
- **`.footer a` / `.footer a:hover`** (`globals.css:173-174`): delete them. Once `.links` is gone the footer has no anchors left.
- Update the section comment at `globals.css:164` (*"…landings, the way to /report and /spend"*) and the file doc comment at `footer.tsx:1-11` (*"and the way to `/report` and `/spend`"*, *"no import but React, `next/link` and types"*). Both describe the links.

## The `project` prop goes too

After the links are gone, `project` is read nowhere in `Footer`. Its only uses are the three `withProject(…, project)` calls at `footer.tsx:98-107`. If it stays destructured, the repo's `no-unused-vars` rule (`.oxlintrc.json:34`) will reject it. Remove it all the way through:

- From `Footer`'s props, and drop the `next/link` and `withProject` imports (`footer.tsx:12,18`).
- From `FooterFetched` (`footer-fetched.tsx:18,38`). The comment at `footer-fetched.tsx:22` says *"Mount only: `project` builds hrefs, and a different project is a different page."* The empty dependency array stays, but its stated reason is gone. Rewrite the comment to say what is still true: the reading is per board and not per project, so it is fetched once on mount.
- From the callers:
  - `page.tsx:736`
  - `recipe/[project]/page.tsx:151`
  - `backlog/page.tsx:117`
  - `task/[id]/layout.tsx:223`
  - `spend/page.tsx:136`
  - `report/page.tsx:145`

  These six callers are mechanical changes. `pnpm typecheck` will list every one you miss.

## The test

`apps/board/unit/footer.test.tsx` names the links in four places:

- `:31`, the `class="links"` order check: replace it with a check that `home-at` is the last child of the `<footer>`.
- `:80-86`, *"carries ?project= on every link"*: delete it. Move its `3 landed` check into another test so the count stays covered on `/`.
- `:120-125`, *"draws the three links but no landed count off /"*: change it to *no anchors anywhere*, i.e. `expect(html).not.toContain('<a ')` and `.not.toContain('href=')`, while keeping the `not.toContain('</b> landed')` check for the case off `/`.
- `:127` onwards, *"…and the links in order"*: drop the link half of that test.

The `render` helper (`:19-24`) loses its `project` parameter. Callers that pass `undefined` positionally (`:101`, `:112`, `:118`) have to shift their arguments.

Add one assertion that is the ticket's whole claim: a fully drawn footer, both on `/` and off it, contains no `href`.

## Edges

All of these are unit-level. `pnpm test` and `pnpm typecheck` cover them, and nothing waits on `test:integration`.

- **The footer is still loading or failed to load** (`footer-fetched.tsx:39-46`): those two branches render their own `<footer className="footer">` and get the 14px from the class. They have no `project` and no links, so they need no change.
- **A narrow window**: `flex-wrap: wrap` stays. When the row wraps, the home's `margin-left: auto` pushes it to the right of its own line. That's acceptable.
