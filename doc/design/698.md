Adding it directly would touch `package.json` and the lockfile for one check, so don't. Replace `xmlWellFormed` and its two regex constants with a single function, `xmlTagsBalanced`, that checks one thing: every start tag is closed by an end tag of the same name, in nesting order, and nothing is left open. ## The comment-context bug, and why it goes away

`xmlWellFormed` strips comments, CDATA, processing instructions and `<!DOCTYPE[^>]*>` with four independent regexes before scanning (branch `detect-setup.ts`, the `.replace(...)` chain). Each regex ignores the context the others create:

- `<![CDATA[ <!-- ]]>` followed later by `-->` loses everything in between.
- A comment containing `]]>` or `?>` is cut short.
- A DOCTYPE with an internal subset `[...]` ends at the first `>`.

`xmlTagsBalanced` is one left-to-right scan with no pre-pass. At each `<`, check these in order and skip to the end marker:

1. `<!--` skips to `-->`.
2. `<![CDATA[` skips to `]]>`.
3. `<?` skips to `?>`.
4. `<!` skips to its `>`, counting `[`/`]` so an internal subset is skipped whole.
5. `</name` pops the stack and must match.
6. `<name` scans to the tag's closing `>` while skipping quoted attribute values, because `>` and `/>` inside `"…"` or `'…'` are legal. It pushes the name unless the tag ends in `/>`.

A missing end marker, a mismatched pop, or a non-empty stack at the end means unbalanced. Text between tags is ignored. An empty file, or one with no tags, is **unbalanced** (nothing was opened), so `''` still fails. Write the doc comment as the honest version: *balanced tags only; a file this accepts may still be invalid XML, and #436's try is what finds it.*
