# Design note — #535

Parse ticket context at the Waiting page’s display boundary. `Standing` already receives the issue body, and `ticketOpening` currently takes its first eight lines (`apps/board/src/app/standing.tsx:208`; `apps/board/src/app/task/[id]/page.tsx:804`). Replace that preview with a pure parser for **only the opening two-column Markdown table**: require the documented header and separator, the ordered Problem, Want and Fix rows, and an optional Watch out row. Reject duplicate, missing, extra or overlong cells rather than assigning meaning to arbitrary rows. Keep the existing triage reading separate from the ticket’s Want; the page currently labels that value “Triage’s reading” (`apps/board/src/app/standing.tsx:542`), and 0118 §2 says it is “never” presented “as the ticket’s words” (`doc/decisions/0118-a-hold-explains-itself.md:303`).

Render accepted fields as three distinct cells in Problem, Want, Watch out order, omitting the third cell when its row is absent. Use the existing issue-body sanitization path for cell content: its comment says the body is “untrusted input” and requires “No raw HTML” (`apps/board/src/app/markdown.tsx:10`). Keep the white bordered panel ahead of the rail, with a three-column grid that stacks at narrow widths; cap grid tracks and wrap long text rather than clipping it. The existing Waiting panel and following “Where it is” section are in `apps/board/src/app/globals.css:1156` and `apps/board/src/app/standing.tsx:610`; `Hold.dc.html:43` supplies the three-cell reference.

For an unrecognized opening, show a generic invitation to read the ticket, with no inferred fields. Make “The whole ticket” one activation away, including when there is no GitHub URL: the current `#record-ticket` link reaches a tab whose full body is inside another closed disclosure (`apps/board/src/app/standing.tsx:549`; `apps/board/src/app/task/[id]/page.tsx:144`; `apps/board/src/app/record-tabs.tsx:91`). Preserve that complete body in the record.

This changes an accepted decision. 0118 §2 explicitly requires “the opening of the body, collapsed” and assumes no body structure (`doc/decisions/0118-a-hold-explains-itself.md:301`). Record #535’s narrower, optional structured reading in a **new superseding ADR file**, rather than editing 0118, and align `doc/design/task-detail-page.md:50`, which currently calls the collapsed opening an intentional difference. Unit coverage should pin strict parsing, hostile Markdown, missing Watch out, the generic fallback and the one-activation full-body path; the ticket’s desktop and narrow screenshot comparison checks the layout.
