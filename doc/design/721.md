## Design note — #721: titles and fixes for the Daemon and GitHub checks

### Where it goes

Most of the change is in `apps/cli/src/doctor.ts`. There is one small addition to `packages/github/src/gh.ts`. The renderer (`renderDoctor`, `doctor.ts:3082`) needs nothing:
- The short view already draws `t.title ?? t.name` (`:3097`), then the first line of `detail` (`:3098`), then `fix` line by line.
- `--verbose` draws every line of `detail` (`:3137`) and the `fix` block (`fixLines`, `:3157`).

So the whole job is filling in `title`, `fix` and a short first line on the rows these checks return.

### The rule every row follows

**When a command moves into `fix`, remove it from `detail`.** #717 set this pattern: `subscriberFailures` cuts the reason at its first ` — `, because "the real one is the row's `fix`" (`doctor.ts:1742-1744`). Several details here end with the command in backticks:
- `rates`: `` — run `lingtai projection rebuild spend` `` (`:1171`)
- `github: gh login`: `` — run `gh auth login` `` (`:870`)
- `ghScopeGap`'s sentence (`gh.ts:148-150`)
- currency's `Restart it (pnpm lingtai daemon)` (`:1241`)

If they stay, the short view prints the command twice, and in currency's case it prints a different command from the `fix`.

**Fix strings are written exactly as in #717:** a bare `lingtai …` with no `pnpm` (see `lingtai env set ${project} …`, `:2237`).

**Daemon currency and refusals must use the identical string `lingtai restart "picking up main"`.** `toFix` merges rows whose `fix` is identical (`:3180`). The two rows have the same remedy, so they should show as one problem with both areas, not two. Put the string in one module constant and have both rows use it.

### Daemon: currency — pull the grading out of the git read

`describeCurrency` (`packages/daemon/src/currency.ts:162`) is "used by `lingtai doctor` and by the board's chip" and is "shared rather than written twice". **Do not change it**, because the board would change too.

Instead, add an exported pure `currencyRow(c: Currency): CheckResult` in `doctor.ts`, and have `daemonCurrency` call it after `codeCurrency`:
- **Behind case:**
  - `title`: `the daemon is ${c.behind.length} commit(s) behind ${c.base}`. `c.base` is the upstream ref, falling back to `FALLBACK_BASE` (`currency.ts:113-118`). Remove a leading `origin/` if the title should read "main".
  - First line of `detail`: `running <short sha>` plus the dirty note.
  - Later lines: the commits, `${sha} ${subject}`, one per line.
- **Not behind, or unknown:** stays `ok` with `describeCurrency`'s sentence, as today (`:1246-1249`).

This turns the behind warn from "runs git, untested" into a unit test that passes in a made-up `Currency`. That is what Done-when asks for ("extract its grading into a pure exported function").

The no-commit warn (`:1234-1243`) is still driven through `daemonCurrency(read)` with a beacon that has no `codeSha`. Its title is something like *the daemon cannot say which commit it runs*.

**Neither currency warn sets `restartAnswers`.** They are warns, and the doc comment at `:1196-1205` explains why that must not change.

### Conductor: refusals — the title per project, one title for the row

- `describeRefusal` (`:1328`) gains a `title` in its return. With one project, `passRefusals` (`:1273`) uses that title.
- With several projects, it uses `${n} projects are refused by the last pass` and names them in the detail.
- The project title must not contain the seq, the ISO time or the short sha: the ticket rules out hashes. Something like `${project} is refused by the last pass`, with "and no daemon is up" for the warn.
- `head` (`:1343-1345`) currently packs seq, time, sha, ref and reason into one sentence. Split it:
  - First line: `${project}: ${r.detail}` (the refusal reason).
  - Later lines: seq, commit, ref and the `witness` sentence.
- With several projects, `passRefusals` already joins with `'\n         '` (`:1290`), which drops the second project's first line into `--verbose`. That is acceptable: the title names the count.
- `fix` is set **only** when the row gets `restartAnswers: true` (`:1293`), so it follows the same condition and never appears on a refusal by newer code.

**Restart prints this row whole.** It is in the `held` list (`restart.ts:1482`) whenever `restartAnswers` is set, and in the refusal list (`:1495`) otherwise. So the new first line has to make sense alone after `${r.name}: `. "`<project>: <reason>`" does.

### Rates

- **Stuck warn** (`:1167`):
  - `fix`: `lingtai projection rebuild spend`
  - `title`: e.g. *spend was not rebuilt after new prices*
- **Fetch-failure warn** (`:1148`):
  - `title`: e.g. *the last price fetch failed*
  - No `fix`. What clears it is a later fetch at conductor start, and the check can't tell whether the cause was the network or something else.
- **Both:** the `priced …` and `out of range …` lists move to later lines.
- **Testing:** `ratesCheck(from, spendLag)` is already pure apart from reading files under `from`'s `LINGTAI_HOME`. Test it with a temp home only if `doctor.test.ts` already does so for this check. Otherwise keep the unit test in-process by passing a `spendLag` and a note read. If neither is possible without the filesystem, say so in the PR (the unit/integration line is 0060 §1).

### GitHub: gh login — the fix comes from structured data, not by parsing a sentence

Add `ghScopeRefresh(status): string | null` in `gh.ts`, next to `ghScopeGap`:
- It returns `gh auth refresh --hostname github.com --scopes ${missing.join(',')}`, or `null`.
- `ghScopeGap` builds its sentence from it.
- Export it from `packages/github/src/index.ts`.

`ghScopeGap` keeps its signature and wording because two other callers use it unchanged: `apps/cli/src/github-auth.ts:98, :216` and `packages/conductor/src/onboard.ts:363`.

In `ghLogin` (`:866`):
- **Signed-out fail:** `title` *gh is not signed in to github.com*, `fix` `gh auth login`.
- **Scope-gap fail:**
  - `title` *the gh login is missing the repo or workflow scope*
  - `fix` from `ghScopeRefresh`
  - `detail`: the gap without its `— run …` tail. Build that tail-free sentence in doctor, so the shared sentence is not changed.

The existing tests at `apps/cli/unit/doctor.test.ts:473-493` drive both cases through an injected `GhRun`. Extend them; if they assert the backticked command in `detail`, update them.

### GitHub: app credentials — export it, give it no fix

- Export `githubCredentials` (`:877`) and test it with a plain `env` object, the same way `ghLogin` is tested. That is simpler than going through `runDoctor`.
- The `fail` is `(err as Error).message` from `githubApp(env)` or `createPublicKey` (`:911`). The cause could be a missing key, an unreadable `config.yml`, or a key that won't parse, so a single command would be wrong for some of them.
- `title`: *the GitHub App credentials do not load*. The message stays in `detail`. No `fix`, as the ticket's Watch out says.

  - First line: *the daily ceiling cannot see them*
  - The `daySpendText` breakdown goes on the next line.
  - No `fix`: no single command makes a runtime report cost.

### GitHub: what we said and did not manage

`unconvergedRow` (`:1630`) is already pure and exported. It has three non-ok outcomes, each with its own title and none with a `fix`:

| Outcome | Title | Why no `fix` |
|---|---|---|
| comments-only warn | `${n} comment(s) were never posted` | a person posts them |
| blocked fail | `${n} issue(s) cannot converge until a recipe resolves`, naming the project in words when there is one | the remedy is that recipe's own error |
| computable warn | `${n} issue(s) on GitHub differ from the log` | the existing text's `(lingtai daemon)` is wrong advice when a daemon is already up, so drop it rather than promote it |

In every case the `slice(0, 4)` issue list moves to later lines.

### Tests

New file `apps/cli/unit/doctor-titles.test.ts`, not `doctor-render.test.ts`. One `describe` per check, each covering at least one warn/fail outcome:
- assert `title`
- assert `fix` where the table above gives one, and `undefined` where it says none
- assert `name` is unchanged
- assert the first line of `detail` (`split('\n')[0]`) contains no `\n` list

One shared assertion over every title produced: no `#\d`, no `\b\d{4}\b` ADR number, no 7–40 character hex, no `/`. A `/` would catch `origin/main`, so strip that prefix as above or narrow the rule to paths.

Existing assertions on `detail` text will change wherever a list or command moved. Update them in place.

### What can't be checked inside the pass

`apps/cli/integration/doctor.test.ts` (about 40 s) is in Done-when, but it belongs to the integration half, which no ticket waits on. Run it on its own if it fits. If it doesn't, the unit-level stand-in is the new titles file plus `pnpm typecheck`. Say in the PR which of the two was run.
