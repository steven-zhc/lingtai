# Design note for #862: the architecture pages and why.md say each projection has one writer

This is a prose-only change to three files, in one commit. The ticket names the passages. This note covers three things the ticket leaves open: what to keep in each passage, what reason to give in place of the old one, and where to stop.

## The reason to write in

Every rewritten passage should give the same reason: **the conductor lock**. `apply` being idempotent is no longer the reason. Take the wording from ADR 0100 §13 and from the code comment that already says it in user terms, `apps/cli/src/conductor-note.ts:4-7`:

> *"One process writes each projection: the one holding the conductor lock. A command that appends — `requeue`, `close`, `ask`, `end`, … — holds no projector, so what it did reaches the board when a conductor folds it. With no conductor up that is never, until one starts"*

The daemon and `lingtai run` both take that lock (#93), so both still hold the runners. **That is why the drawing stays, and why "no longer a difference between the two hosts" is still true. Only the reason for it changes.**

## Passage by passage: what to keep

- **`architecture.html:372-374` / `zh:383`.** Keep *"both hold a projector for as long as they run"*. Add one clause saying why: each holds the conductor lock.
- **`architecture.html:494-496` / `zh:497` (heading and lede).** The heading can stay *Two hosts, one rule*, as long as the lede names the new rule: one writer per projection, the lock holder. Every other command appends and reads. With no conductor up, the projections stand still and the lag says so.
- **`architecture.html:553-559` / `zh:552-556` (caption).**
  - **Keep** the bold first sentence (*"The projector is in both boxes now…"* / *"现在两个框里都有 projector…"*) and the `#64` history about the board freezing for the whole of a run. Both are still true and still explain why `run` holds a runner.
  - **Delete from "Two projectors on one log" to the end:** idempotent `apply`, *whichever gets there second*, *No lock, no coordination*.
  - In their place, say that both boxes hold the runner because each holds the lock, so only one of them runs at a time. Do not say that two writers would be harmless. Two writers on one projection are what #838 (an event delivered twice) and #834 (a deadlock) were about, and cite those numbers if the caption needs a reason.
- **`architecture.html:574-580` / `zh:569-573` (projector definition).**
  - Replace *"the one projection"* with the four, as the CLAUDE.md lists them: `task_view` (the board), `finding_backlog`, `spend`, `ticket_report`.
  - Replace *"Held by every process that appends"* with: held by whichever process holds the conductor lock, the daemon or `lingtai run`.
  - The *Without it* half stays and gains *the lag says so*.
- **`architecture.html:716` / `zh:696` (NOTIFY `aria-label`).** Change *"whichever process is holding one"* / *"当前持有 projector 的那个进程"* to the conductor's projector.
- **`architecture.html:751` / `zh:731` (SVG `<text>` "the projector").** Leave it. It is a 12.5px box label, not a claim, and a longer label would need the box widened. Redrawing geometry is out of scope.
- **`why.md:121-124`.** Keep *"the board follows a run by hand just as it follows the daemon"*, which is still true because `run` holds the lock. Replace the bolded clause before it with the one-writer rule.
- **`why.md:128-130`.** Make it four projections, named as above. Keep the sentence about one rebuild per projection.

## The grep is the check, so avoid its phrases

The Done-when grep matches `every process that appends`, `two projectors` and `安全的`. Do not reuse those phrases even in a negation (*"not every process that appends…"*), or the check reports a hit on a correct sentence. Write *every other command appends and reads* instead. In Chinese, keep `安全` out of any sentence about writers.
