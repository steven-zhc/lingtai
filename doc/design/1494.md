# #1494: design note

> **History.** Board addresses in this note (`/task/<id>`, `/pr/…`, `/recipe/…`, `?project=`) are the ones that existed when it was written; they no longer resolve. The current forms are in [1502.md](1502.md).

The ticket gives the cells, the wording and the edges. This note covers the five things it leaves open: where the strip's data comes from, the in-flight rule inside `totalsOf`, where the pure helpers live, what replaces the `cost` meter's shape, and which tests stand in for the visual check.

## 1. The strip is drawn inside `Standing`, and `Standing` gets `totals` whole

`objectTitle` is built inside `Standing` (`app/standing.tsx:1211`) and placed at `:1296` (framed) and `:1331` (unframed). So the strip goes in that component, right after `{objectTitle}` in both branches, and before the `.sticket` block. That keeps the *Page titles* rule: state, title, facts line, then the strip.

Today `TaskBody` passes `Standing` one slice of the totals, `discussionBill={task.totals.byPurpose.Discussion}` (`app/task/[id]/layout.tsx:204`). Make these changes on `DeferredStanding` / `Standing`:

- Replace that prop with `totals: Totals`, and read `.byPurpose.Discussion` where `discussionBill` was read. One prop, not two.
- Add `firstClaimAt: string | null`, from `task.runs[0]?.at ?? null`. `runs[0].at = claim.at` (`lib/task.ts:1579`).
- Add `spendCurrency`. `TaskBody` already computes `spendChip(task.spendCurrency)` (`layout.tsx:154`). Pass that result down so the bar and the Spent sub-line use one call.

Put the strip in its own server component, e.g. `app/totals-strip.tsx`. It renders `<dl className="facts">` with the same `Cell` that `Meters` uses (`standing.tsx:231-243`). Either export `Cell` or move it next to the strip; do not write a second one. Each cell carries a `data-cell="spent|answering|took|attempts"` attribute, so tests can assert cells by name as the ticket asks.

The live *Took* cell is `<Since iso={firstClaimAt} serverNow={now} />` (`app/since.tsx:12`). `Since` is already a `'use client'` leaf, imported into `standing.tsx` at `:449`, so the strip stays a server component and no new client boundary appears. That matters because the Next build is the only check that catches a server import leaking into a client graph (`apps/release/integration/build.test.ts`, integration-only).

## 2. `totalsOf`: the in-flight exception keys on `outcome.state`

Today `totalsOf` adds `unknownBill(1)` for every run with no `Action` row (`lib/task.ts:1711-1714`). Change that loop to skip a run whose `run.outcome.state` is `'running'` or `'claimed'`; those are the two arms of `outcomeOf` that mean nothing has ended yet (`task.ts:1686-1687`). Do not key it on `standing.runId`. The ticket names the outcome, and the outcome is already on each `AttemptView`. Every other state keeps the unknown, including `released` and `asked`, which ended without a receipt.

`Totals` (`task.ts:402-409`) changes as follows:

- `turns` becomes Σ `row.turns` over `rows`, every purpose.
- `durationMs` becomes Σ `row.durationMs` over `rows`, every purpose. Keep the field name; the strip labels it *agents ran*.
- Add `fixRounds`: the size of `new Set(rows.filter(r => r.purpose === 'Action' && r.round !== null && r.round >= 1).map(r => `${r.pass}:${r.round}`))`. This is the `ticket-report.ts:759-764` rule, with `pass` in place of `stream`.
- Add `inFlight: number`: how many runs were skipped above. The strip needs it to tell "nothing billed yet" apart from "nothing at all". The rule: when `rows` has no row for any attempt and `inFlight > 0`, the Spent figure is `nothing billed yet: no agent run has ended`. That is the exact string at `running.ts:88`, so lift it into a shared constant that both places use.

The run-level `r.turns` / `r.durationMs` (`task.ts:1584,1588`) stay on `AttemptView` for the attempt row (`app/attempt-tab.tsx:92`). Only `totalsOf` stops reading them.

`turns` and `durationMs` come from `RunSpent` (`packages/projector/src/spend.ts:355-356`). So a ticket whose attempts predate `RunSpent` (the `ticket-lingtai-89` case in `totalsOf`'s own comment) now reads 0 turns and 0s, where it used to read the receipt's figures. The strip must leave out the *agents ran* clause and the turns clause when they are 0, rather than print `0s` or `0 turns`. The Edges section requires this.

Delete `totalsFact` (`task.ts:1759`) and `PURPOSE_LABEL`, if nothing else uses it. Delete the three `totalsFact` cases in `unit/meter.test.tsx:177-211`. Keep its `totalsOf` cases and update them to the row-sourced fields.

## 3. Two pure helpers, in `lib/`, imported by both pages

- `tookText(start: string | null, end: string | null): string | null` returns `inWords(Date.parse(end) - Date.parse(start))`, or null when either input is null or the difference is negative. `inWords` is `@lingtai/conductor`'s (`packages/conductor/src/queue.ts:168`), the one `standing.tsx:1197` already uses. Put it in a file that does no IO (a new `lib/took.ts`, or `lib/progress.ts` next to `elapsed` at `:260`). `/landed`'s view already imports `@lingtai/conductor/report` (`app/landed/view.tsx:12`), so this adds no new kind of dependency there. `Facts` (`view.tsx:90`) and `Line` (`view.tsx:199`) call it with `row.passTimes[0] ?? null` and `row.outcomeAt`. The task page calls it with `firstClaimAt` and `standing.since` for `landed` / `closed` / `satisfied`.
- `namedTimes(...)` returns the facts line's parts, e.g. `['claimed 05:03', 'landed 05:12 on lingtai-base']`. Its inputs are `firstClaimAt`, `standing.state`, `standing.since` and `standing.landedOn?.base`. The clock is UTC `HH:MM`, sliced as `Coords` slices it (`standing.tsx:1983`). The date (`YYYY-MM-DD `) goes before the first time whose UTC day differs from the next time's day. The landed-then-closed case reads `closed HH:MM · landed on <base>`, because the `closed` lifecycle only has `since` (`packages/domain/src/ticket-codec.ts:195`). Being pure, it is tested by itself, once per state, without rendering a page.

`facts` (`standing.tsx:1192-1200`) then maps `namedTimes(...)` to `<span>`s in place of the `inWords(now - since)` span. The `running` arm (`runningFacts`) is untouched.

## 4. The meter loses `cost`, and `attempt` takes the cost ceiling

In `RunningMeters` (`lib/running.ts:26`), delete `cost`. Add `usdCeiling: string | null` on `attempt`, holding the `at most $x a run` text from `:89`. `Meters` draws its sub with `both(...)` over three parts, the turns ceiling, the USD ceiling and `behind`, so widen `both` to take more arguments. One trap: the `unlimited` test (`standing.tsx:247`) reads `m.cost.ceiling`, so it must read `m.attempt.usdCeiling` instead. Otherwise `limits: none set` appears on a run that does have a dollar limit.

Tests that follow the change: `unit/running.test.ts:153-181` (the `cost.text` cases go, and the ceiling and behind cases move to `attempt`) and the fixture at `unit/standing.test.tsx:1215`. The removed `cost so far` is a decision, not a regression: it was this attempt's figure, and the strip shows the whole ticket's (ticket, *Watch out*).

## 5. `billText` and its test

Build the `parts` array (`lib/spend.ts:182-196`) in the order reported, estimate, unknown, and join with `' + '`. This gives `$3.10 + ~$0.50 est. + 2 unpriced` and `~$0.42 est. + 2 unpriced`. The only-unknown branch keeps `unpriced (N runs)` and adds no unknown part after it. With an estimate it reads `unpriced (2 runs) + ~$0.42 est.`. That reverses the ticket's estimate-first order for this one case, so the implementing agent should choose one order and pin it.

Rewrite the doc-comment table so every arm has a row, estimate arms included. Pin each row in `unit/spend.test.ts`. The callers listed in the ticket change no code. Their snapshot or `toContain` assertions that spell the old single space will go red once, so search the tests for `' ~$'` and fix them in the same commit.

## What stands in for the visual check

Everything here is unit-reachable. The checks are `pnpm typecheck` and `HOME=/nonexistent pnpm test`, and no part of the change needs `pnpm test:integration`. The person's 1440px light/dark check against F12 is the only thing a test cannot replace. The unit claims that stand in for it:

- `TaskBody` for a landed ticket with two attempts and one `Action` row at `round: 1` shows `[data-cell=took]` containing `claim → landed` and `agents ran`, and `[data-cell=attempts]` containing `1 fix round`.
- With one attempt whose outcome is `running` and no `spend` rows, `[data-cell=spent]` contains `nothing billed yet` and does not contain `unpriced`.
- `tookText(null, x)`, `tookText(x, null)` and a reversed pair all return null, and `/landed`'s `Facts` and `Line` then draw no `took`.

No ADR is touched. 0110 §7, *unknown is never free*, still holds, because the skipped run is in flight, not free, and the strip says so in words.
