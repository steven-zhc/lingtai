## Design: #777, the release notes carry a Decisions section

### Where it goes

| Piece | File |
|---|---|
| The section | new `apps/release/src/decisions-changed.ts`. It has the same shape as `apps/release/src/tickets-changed.ts`: the pure functions first, then `if (import.meta.main)` at the bottom (`tickets-changed.ts:70`). |
| Tests | new `apps/release/unit/decisions-changed.test.ts`. #776 already wired this directory: `apps/release/tsconfig.json` includes `unit`, and the root `vitest.config.ts` globs it (`doc/design/776.md`, *Where it goes*). |
| Workflow | `.github/workflows/release.yml`, publish job only. Add a new step directly after `Tickets landed` (`release.yml:189-201`), and edit the `release notes` line (`release.yml:202-203`). |

No new dependency, no lockfile change, and no permission change. The step only reads local `git`, and `fetch-depth: 0` (`release.yml:113`) already gives it the history.

### Decisions the ticket leaves open

**1. Git runs in the shell, and the script reads files.** The ticket's Fix says "the CLI reads `git log`". Build it the way #776 did instead (`doc/design/776.md` §3, and the `Tickets landed` step's comment at `release.yml:190-193`: *"`git log` runs here so a failure fails the step under -e before the script runs"*). The script spawns nothing.

```
if [ -n "$PREV" ]; then
  git log --first-parent --no-merges --format=%s "$PREV..${{ github.ref_name }}" > decision-commits.txt
  git ls-tree --name-only "${{ github.ref_name }}" doc/decisions/ > decision-files.txt
fi
node apps/release/src/decisions-changed.ts "${{ github.repository }}" "${{ github.ref_name }}" ${PREV:+decision-commits.txt decision-files.txt "$PREV"} > decisions-changed.md
cat decisions-changed.md
```

- If `PREV` is empty, skip both git calls. An empty `PREV` turns the range into `..<tag>`, which is a different range and does not error.
- The step's `env` is `PREV: ${{ steps.prev.outputs.tag }}` and nothing else. There is no `GH_TOKEN`, because nothing here calls GitHub.
- With no fourth and fifth arguments, the script prints the "no earlier release" text.

**2. `doc/decisions/` holds more than ADR files, so match file names exactly.** `git ls-tree --name-only HEAD doc/decisions/` lists full paths, and among them are directories named by number: `doc/decisions/0118` and `doc/decisions/0123` (each holds `.dc.html` mock-ups), plus `doc/decisions/zh`.
- A prefix match on `0118` would return the directory and link to a tree, not the ADR.
- Resolve a number only against `^doc/decisions/(\d{4})-[^/]+\.md$`. Anything that pattern does not match is ignored.
- `ls-tree` without `-r` does not recurse, so `zh/` translations and the files inside `0118/` never reach the parser.
- If more than one `.md` matches a number, take the first in `ls-tree` order. "One ADR per topic" (`doc/README.md`) means this does not happen today, and the edge does not deserve its own output.

**3. `renderDecisions` takes one object, like `renderTickets` (`tickets-changed.ts:47-52`), not four positional arguments.**
- Input: `{ repo, tag, prev: string | undefined, commits: Array<{ adr: string; sentence: string }>, files: string[] }`, where `files` are the raw `ls-tree` lines.
- The ticket's `(commits, files, repo, tag)` has nowhere to put `prev`. `prev` is what tells "no earlier release" (print the sentence) apart from "nothing in range" (print nothing).
- Keep `adr` as the four-digit string, so `0099` prints as `0099` and not `99`. Sort with a string compare: four digits sort correctly as strings.

**4. Output shape.**

```
## Decisions

- [0108](https://github.com/<repo>/blob/<tag>/doc/decisions/0108-a-refusal-buys-a-round.md)
  - a build refusal the base shares buys no round …
- [0121](…/0121-the-cli-output-and-input-contract.md)
  - init and add close on a numbered NEXT block …
  - an approval says whether it landed, …
- 0097 (no file at v0.11.0)
  - …
```

- **Sub-bullet order.** `git log` prints newest first, and the ticket wants oldest first. `decisionCommits` stays in log order, as the ticket says. `renderDecisions` reverses each ADR's sentences. Only the per-ADR order matters, because the ADRs themselves are sorted by number.
- **Nothing in range** (`prev` set, no commits): return `''`. Then `decisions-changed.md` is empty and `cat` adds nothing.
- **No previous release:** return `'## Decisions\n\nNo earlier release to compare against.\n'`. This matches `tickets-changed.ts:54`.
- **Trailing newline.** End non-empty output with `'\n'`, so the next file's `##` starts on its own line (`doc/design/776.md` §6).

**5. Notes order:** `cat tickets-changed.md decisions-changed.md cli-changed.md events-changed.md > release-notes.md`.
- Decisions go after the tickets, as the ticket asks, and before the two generated manifests.
- The tickets section ends on its `Full diff:` line (`tickets-changed.ts:66`). That is not a problem: an ATX heading on the next line still renders as a heading in GFM.

**6. The subject pattern is `^(\d{4}): (.+)$` exactly, as the ticket says.** Do not trim the subject first. A leading space is a different shape, and #776's test refuses the same thing (`apps/release/unit/tickets-changed.test.ts`, `" Merge branch 'agent/9' into HEAD"`). Add one test case for it next to the four the ticket's Done when lists.

### Checked against today's history

Run `git log --first-parent --no-merges --format=%s v0.10.0..HEAD` in this worktree and keep the subjects matching `^\d{4}: `. You get exactly the ticket's five commits, covering 0121 (×2), 0104, 0108 and 0110. Each of those has a file at `HEAD` under `doc/decisions/`. A good unit fixture: these subjects, plus an `ls-tree` list that includes the `doc/decisions/0118` directory entry (decision 2).

### What nothing can check before the merge

The step runs only when a `v*` tag is pushed. None of `pnpm fmt:check`, `lint`, `typecheck` or `test` runs YAML. The unit tests for `decisionCommits` and `renderDecisions` stand in for the step, together with a read of the `release.yml` diff.

Optional manual check, not a gate:
1. Run the two git commands above with `v0.10.0` and `HEAD` in place of the two refs.
2. Run `node apps/release/src/decisions-changed.ts o/r HEAD decision-commits.txt decision-files.txt v0.10.0`.
3. It should print four ADR entries, with 0121 carrying two sentences.

Write those files outside the worktree, or delete them before committing.
