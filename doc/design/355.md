# #355: design note

## Three places skip a no-owner project today, and all three change

1. **`apps/cli/src/conduct.ts:92-95`**: `conductorPass` refuses the *whole pass* when there is no App (`outcome.refused.push({ project: '*', detail: 'no GitHub App configured' }); return outcome`). On a machine with no App, a no-owner project never gets as far as the per-project loop. Keep the `'*'` refusal entry, word for word, but only when some registered project has an owner, and **don't return**. Hand `conductProjects` the no-owner projects only (`projects.filter(p => p.owner === null)`). With an App, hand it every project, as today. A GitHub project on a machine with no App then behaves exactly as it does today, and appends no new `ProjectRefused`.
2. **`apps/cli/src/conduct.ts:284`**: `if (!name || !project.owner) continue` becomes `if (!name) continue`.
3. **`packages/daemon/src/converge.ts:140-142`**: `if (!hasApp()) return { clients, unresolved }` runs before the loop, and `if (!p.project || !p.owner) continue` runs inside it. Both go. The no-owner branch runs whether or not there is an App. The App check stays, but only on the GitHub branch: no App means skip that project silently, as today.

Test for a missing owner with `p.owner === null`, the way `run.ts:340` and `filter.ts:306` do. Don't use `!p.owner` (#354's note gives the reason).

## Assemble the no-owner client once, in a new module

`run.ts:432-456` already builds the client inline: `ownerlessRefusal`, then `remoteOf(recipe) as string`, then `ticketsFor(project, recipe, undefined as unknown as Tickets)`, then `{ ...tickets, ...gitRefChannel({ remote }), owner: null, repo }`. This ticket needs the same thing in two more places. Move it into one function, e.g. `ownerlessClient(state, recipe, ticketsOf = ticketsFor): Promise<{ client, remote }>`. It throws `ownerlessRefusal`'s sentence when that sentence is non-null. `run.ts` then calls it; this is the #76 rule again, where wording written in two places drifts apart.

Put it in **its own module, `packages/conductor/src/ownerless.ts`, with a `./ownerless` subpath export** in `packages/conductor/package.json`. Don't put it in `filter.ts`:
- `gitRefChannel` statically imports `@lingtai/repo` (`git-refs.ts:25-26`).
- `filter.ts` is in the board's graph (`apps/board/src/lib/board.ts`, #354).
- `converge.ts` may import only subpaths, never the barrel (`converge.ts:59-61`: *"a barrel import here is a compile error three packages away"*).

`ownerless.ts` needs to import only `./filter.ts` (for `ownerlessRefusal`), `./git-refs.ts` and `./ticket-store.ts`.

The client's type is `PassClient` with `owner: string | null`, which #352 already widened (`packages/conductor/src/conduct.ts:340`). Widen `ProjectClients.clients`' value type at `converge.ts:94` and `:138` to match. Nothing reads `.owner` off that map: `findIssueDrift` and `convergeIssues` only call `getIssue`/`setLabels`/`closeIssue`/`matchingRefs`/`deleteRef` (`converge.ts:342`, `:405`, `:456-463`).

## `clientsForProjects`: the no-owner branch

In order:
1. Call `recipeFor(p, undefined)`. `currentRecipe` ignores its client: `projects.ts:155` names it `_client`.
2. Call `ownerlessClient(p, resolved.recipe, options.ticketsOf)`.
3. Call `clients.set(p.project, client)`.

**Never call `clientFor`.** A throw from either step goes into `unresolved`, through the same `catch` as at `:154-159`. That covers a refusal such as "no `source.tickets: db`" or "no `repo.remote`", and also `TicketSourceConflict`. This is the *report it at the transition* rule (#148, #389): `clientsForProjects` has one caller, at daemon start (`apps/cli/src/lingtai.ts:926`), and `:934-941` prints each `unresolved` entry once. Add `ticketsOf?: typeof ticketsFor` to the options. It is the seam the tests need, and it follows `projectFilter`'s fourth parameter (`filter.ts:299`).

Update the doc comment at `:98-128`: the paragraph on *"Empty when no App is configured"* stops being true for no-owner projects.

## The refs half runs over git and isn't skipped. This is the decision

The ticket's **Want** says *"GitHub's refs half is skipped for it with a reason."* For a no-owner project there is no GitHub refs half to skip, and nothing in this shape asks GitHub. The map's value carries `gitRefChannel({ remote })`. `findIssueDrift` asks only a `RefChannel` (`converge.ts:405`, `client.matchingRefs(...)`), and `convergeIssues` deletes through that same channel (`:459`). So #240's leftover-arm sweep runs as `git ls-remote` / `git push --delete` against the project's own remote, with this machine's credentials.

Skipping it would bring back exactly what #352 built `gitRefChannel` to prevent. `git-refs.ts:7-11`: *"Nothing else will ever sweep these refs for an owner-less project — `convergeIssues` only ever asks GitHub, and the daemon skips an owner-less project outright — so `agent/*` arms would pile up on the remote with nothing converging them."* After this change that sentence is false in the other direction. Rewrite it to say reconcile now sweeps them, through this channel. Since nothing is left unsupported, there is no reason to report. The comment-change rows were never repaired for anyone (`converge.ts:447`).

## `conductorPass`'s `work`: the no-owner branch

Branch on `project.owner === null`, before `createGitHubClient` (`conduct.ts:123`):
- Keep `max === 0 → 'looked-away'` first (`:133`).
- `where.ref = project.base`. A local registration always records `base` (`apps/cli/src/first-project.ts:425-428`). If it is null, fall back to `baseOf(resolved.recipe)` after resolving, never to `client.defaultBranch()`.
- `currentRecipe(project, undefined, where.ref ?? undefined)`, then `ownerlessClient(...)`, **both before `where.looked()`**. A refusal then throws before `looked`, `conductProjects` records `ProjectRefused` through `passTransition` (`:319-324`), and the event is appended on the transition only (#148).
- `common` gets `client`, `remote`, and **no `token` key at all**. `run.ts:458-460` explains why: *"no token at all, so `git()` plants no `GIT_CONFIG_*`"*.

Everything after `common` stays shared: `runnableNow`, `selectRunnable`, `runOnce`/`runQueue`. `runnableNow` reads `common.client`, which for this project is the `dbTickets`.

Update the comment at `packages/conductor/src/conduct.ts:1692-1694`, which credits the no-owner refusal to `run.ts` alone.

## The seam the first test needs

`conductorPass` reaches outside the process from inside `work`: `hasGitHubApp`, `createGitHubClient`, `currentRecipe`, `ticketsFor`, `selectRunnable` (which reads `task_view`), `runOnce` and `runQueue`. `conductProjects` is already a seam (`conduct-pause.test.ts`), but `work` is a closure inside `conductorPass`.

Lift it into an exported `conductWork(options, world)` that returns the `work` callback. `world` carries exactly those seven, with a `liveConductWorld()` default, following `RunWorld`/`liveRunWorld` (`run.ts:245-263`). `PortsLive` stays provided in `conduct.ts` itself, as #352 kept the lock in `run.ts`. The fake `runQueue` returns an `Effect.succeed` and never touches the layer.

## The tests

- **`apps/cli/unit/conduct-ownerless.test.ts`.** Two `ProjectState`s, `local` (`owner: null`) and `gh`. Drive them through `conductProjects` with `conductWork(..., world)` and a `createMemoryEventStore()`.
  - `world.createGitHubClient` throws if it is asked for `local`.
  - `world.ticketsFor` returns a seeded `memoryTickets()` (`@lingtai/conductor/memory-tickets`) for `local`.
  - `world.selectRunnable` passes `offered` through.
  - The fake `runQueue` records its options.
  - Assert, for `local`: the runnable rows `runnableNow` produced come from the seeded tickets; `remote` is set; `'token' in options` is false.
  - Assert, for `gh`: `createGitHubClient` was called once and a `token` function was passed.
  - A second case runs with `hasGitHubApp: () => false`: `local` is still conducted, and `outcome.refused` holds the one `'*'` entry.
- **`packages/daemon/unit/clients-for-projects.test.ts`.** Add cases:
  - With `hasApp: () => false`, the no-owner project is still in `clients`, and `clientFor` (set to throw) is never called.
  - A no-owner recipe without `source.tickets: db` lands in `unresolved` with `ownerlessRefusal`'s sentence.
  - The existing `OK` project is unchanged.
- **Reconcile writes through `Tickets`.** In `packages/daemon/unit/`, built on `converge-refs.test.ts`'s memory store and `DaemonStore` fake:
  - Build the map with `clientsForProjects` (so `clientFor` throws for `local`) and a `memoryTickets()` seeded with issue 7, `open`, carrying `lingtai:working`.
  - Seed the log with `WorkItemClaimed` → `WorkItemLanded`, plus `IssueUpdated{change:'labels', detail:'lingtai:working'}` and `IssueUpdateFailed{change:'closed'}`.
  - Call `convergeIssues`, then assert the memory ticket is closed and carries no label, and that two `IssueUpdated` rows were appended.
  - Don't seed a `refs` failure here. That would call `gitRefChannel`, which runs real `git` (`git-refs.ts:47`) and belongs in `integration/`.

## What only the integration half checks

The git sweep from reconcile is the same `gitRefChannel` that #352's `packages/conductor/integration/` test already exercises against a bare repository. Wiring it into `findIssueDrift` adds nothing that needs a new integration test. The unit-level stand-in is the assertion that the map's `local` value exposes `matchingRefs`/`deleteRef`, and was built without `clientFor`.

## What would show it worked on the log

After a restart onto this commit (*the daemon's code is frozen at start*), the no-owner project's `prj-<name>` stream holds one of two things:
- `ProjectRecovered`, if it had a `ProjectRefused` on record. `passTransition` appends nothing when nothing was on record.
- `ProjectRefused` with `detail` = `ownerlessRefusal`'s sentence.

Its `wi-<name>-<n>` streams gain `WorkItemClaimed`. Reconcile's repairs show up as `IssueUpdated` with `detail` starting `converged by reconcile:` (`converge.ts:469`).
