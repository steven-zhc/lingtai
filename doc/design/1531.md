## 1. Each descriptor's `flags` is not a runner field

`SetupQuestion` has `flag` (the prose after *"pass"*, `setup-list.ts:44`) and no `flags`. Keep it that way:

```ts
export type ProjectQuestion = SetupQuestion<ProjectContext> & { id: ProjectQuestionId; flags: readonly string[] }
```

`PROJECT_FLAGS` must exist at import time with no ports, because `wizard-options.ts` reads it at module load. So:

- Each id's flag keys are a module constant, `FLAGS_OF: Record<ProjectQuestionId, readonly string[]>`. Because it is a `Record`, `tsc` fails on a missing id.
- Each descriptor's `flags` *is* `FLAGS_OF[id]`.
- `PROJECT_FLAGS = PROJECT_QUESTION_IDS.flatMap((id) => FLAGS_OF[id])`.
- A test asserts `projectList(fake).map((q) => q.flags)` equals the rows, so the two cannot drift.

`PROJECT_QUESTION_IDS` is `as const`, and `ProjectQuestionId = (typeof PROJECT_QUESTION_IDS)[number]`.

**The rows.** 1529 §5's *"every other key: the entry of the same name"* is wrong for four keys:

| Entry | Flag keys |
|---|---|
| `writer` | `agent` |
| `writer-model` | `model` |
| `branch` | `main`, `personal` |
| `refusal-fixes` | `refusal-fixes`, `rounds` |
| `checks` | `build` |
| `trial` | `check-build` |
| `landing` | `land` |
| `defaults` | `defaults` |
| `where`, `make-branch`, `move-landing`, `findings-judge`, `register` | none |
| every other entry | its own id |

`base` belongs to no entry. Every caller still refuses it before the list runs (`init.ts:623`, `add-github.ts:286`, `first-project.ts:374`).

## 2. The `defaults` entry has no `fromFlags`

`--defaults` is `''` in `flags` (`wizard-options.ts:86`, *"`--defaults` is `''`"*). A `fromFlags` returning it would hand `''` to the switch's `write`. The runner already answers the switch `yes` from `input.defaults` (`setup-list.ts:172`, `:286-288`). So the entry lists `defaults` in `flags` and reads nothing from them. The `walk` helper sets `input.defaults = flags['defaults'] !== undefined`, as #1525's caller will. The switch's `write` records `answers.defaults = 'yes' | 'no'` and appends nothing, because no recipe key holds it. `register.applies` reads that answer (1529 §4).

## 3. `ProjectContext`: two rules the type cannot enforce

- **`pending` is pushed onto in place and never reassigned.** The view reads the array it was given, live. A `ctx.pending = [...ctx.pending, x]` leaves every later `view.get` blind to `x`. Seeds go in before the walk, so they are `pending[0..]`.
- **`answers` is a typed record of facts for later entries**, written only by `write` (`setup-list.ts:8`, *"The runner writes nothing to `ctx` itself"*). It is not a copy of `Entry.after`. The fields:
  - `mode`, `login`;
  - `branch: { name, exists, from, onlyIn }`;
  - `defaults`;
  - `writer`, `reviewer`;
  - `sandbox`;
  - `install`, `checks: string[]`;
  - `trial: TrialOutcome`, which #1529's card needs;
  - `tickets`.

  Each field is optional, because an entry that did not apply leaves it unset. Readers treat unset as *"not answered in this run"*, never as a value.

`TrialOutcome` is an `apps/cli` type (`setup-build.ts:69`). Declare the same union in `project-list.ts` and leave `setup-build.ts` alone. #1529 retypes the port body.

`ProjectContext` is built by an exported `projectContext({ start, buildFlags, flags, ports, kept, seeds })`. It makes `pending` from `seeds` and `view = projectView(start, pending)` over that same array. The `walk` helper and #1525's callers both use it, so nobody rebuilds the aliasing by hand.

`ProjectPorts.runtimes` is `Effect<readonly RuntimeFound[]>`. The list may yield it in more than one entry (`writer`, `reviewer`). Making it cheap (`Effect.cached`) is the caller's job, and the fake ports need not care.

## 4. Every `write` compares and appends nothing when the answer is what is in force

Done-when asks that *a rerun with every default produces an empty `pending`*. Today's code does not guarantee that, so do not reproduce it. `askAgents` pushes `steps.implement[i].agent` and `…model` on every run (`apps/cli/src/agents.ts:402-407`, `:417-421`), and relies on `draft.set` seeing equal text.

Each entry's `write` compares the answer with its in-force value and returns `{ wrote: false }` with nothing appended when they are equal:

- Where the entry reads the start, use the `inForce` the runner hands to `write` (`setup-list.ts:336`).
- Where the value depends on an earlier answer in this run (the models, the judge, the landing), use `view.get`.
- A model of `''` where no `model:` is written is equal. Do not append `{ value: undefined }`.

`wrote` is `changes.length > 0`, because the card's rows read `Entry.wrote`.

**On a first run every system default is written.** `inForce` is null there, so nothing is equal. `tickets.write` writes even when the answer is the default (1529 §7).

## 5. Where each side effect goes in the walk

The runner calls `fromFlags` before `applies` (`setup-list.ts:179-182`), and `inForce` on every entry that is not fixed or derived (`:226`). That decides where each of today's lines and refusals lives:

- **`writer.inForce`** does two things:
  - It pushes `whyMissing(r)` to `ctx.log` for each signed-out runtime. That matches today, before the first agent question (`agents.ts:236-238`), and with or without a flag.
  - With nothing signed in, it returns `{ fault: noRuntimesSignedInRefusal(…), from: 'file', fatal: true }`. The runner refuses that text unchanged (`:229`).
- **`writer`'s answer.** The default is `defaultAgents(offeredRuntimes(runtimes)).writer`. `validate` is `runtimeRefusal(answer, { kept: current })` (`agents.ts:245-248`).
- **`reviewer`'s answer.** The default is the first signed-in runtime other than the writer, else the writer (`agents.ts:292-293`). `'none'` is in force where `steps.review` is `[]` (`:298-299`).
- **`reviewer.write`**, in this order:
  1. Run `leftoverRefusal`, with `editedInPlace` and `fullyReplaced` computed as at `agents.ts:329-349`. On a rerun, add `followedJudgeIndex(start's steps.proposed, start's writer)`. Push its `log` lines and return its `refused` when there is one.
  2. Push *"the reviewer runs the writer's runtime …"* (`agents.ts:357`) when the reviewer is not `none` and no other runtime is signed in. That keeps its place before the reviewer-model question, which `init-golden` pins (1523 §8).
- **`reviewer-model.fromFlags`** refuses `--reviewer-model` beside `answers.reviewer === 'none'` with `agents.ts:316-317`'s words. `applies` is false then, and the runner would otherwise drop the flag silently.
- **The same pattern for every entry that does not apply.** Where today's code refuses a flag in that case, the refusal goes in `fromFlags`:
  - `landing` refuses `--land <branch>` on team;
  - `login` and `personal` follow whatever `recipe-flow.ts` refuses on solo, if anything.

  Where today's code ignores the flag, `applies: false` ignores it too. One example is `--check-build` with no trial port (`setup-build.ts:278-281` returns before it reads `given.check`).
- **`checks.write`** pushes `NO_CHECKOUT_LINE` when the answer is non-empty and `ports.trial` is absent.
- **`trial.applies`** is `ports.trial !== undefined && answers.checks.length > 0`. That is where `tryTheBuild` reaches the question today (`setup-build.ts:276-281`).
- **`printFound`** (`onPath`) goes in `install.inForce`. It prints before the install question, terminal or not (`setup-build.ts:477`).

## 6. The writer's and reviewer's actions are new code in `@lingtai/setup`

`findAgentAction` and `asRuntime` are private to `agents.ts:43-54`, and `@lingtai/setup` cannot import `apps/cli`. Write them again in `project-list.ts`, from 1523 §3's rule, over `view.get`:

- `writer-model` finds the implement action the writer entry just wrote, by index in the view. Where the writer appended a whole `steps.implement`, the model is written at `['steps','implement',0,'model']`. Later-wins makes that one recipe.
- A model is offered back only when the writer kept the start's agent (`agents.ts:276-279`).
- `runtime.agent` is written when the writer changed or the key is absent (`:380-382`).
- `unboundedTurnsChange` is added only when the writer changed and `turns` is unset (`:390-399`).

**Leave `agents.ts` untouched.** Its tests must pass with no assertion changed, and #1526 deletes it. Two copies of a pure finder for one slice is the cost of *"nothing half-moved"*. Moving `askAgents`'s internals would be the half-move.

## 7. The judge

`findings-judge.derive` returns `answers.writer`. Its `write` appends `followWriterJudgeChanges(startWriter, newWriter, view.get(['steps','proposed']))`, which covers both shapes (1529 §4).

- `startWriter` is read from `start` through `keyIn` (`draft.ts:31`), never through the view. By that point the view already holds the new writer.
- The *"also names"* test asserts that no `ctx.log` line contains `also names` after `reviewer.write` has run. That holds because the judge's index went into `editedInPlace` (§5).

## 8. The no-terminal and port-failure refusals

These are the ticket's Edges, mapped onto the runner:

- **`login`**: no `systemDefault` when no login is known. The runner refuses with `pass ${q.flag}` (`setup-list.ts:305`), so `flag` is `'--login <name>'`.
- **The three confirmations**: the runner refuses naming `--defaults` (`:284`). `make-branch.confirm.declined` is a function of `ctx.answers.branch` (`recipe-flow.ts:489-493`).
- **`branch.systemDefault`** yields the default-branch port. A failure becomes `{ refused: <the port's words> }`, never an Effect failure. `branch.write` yields `branchExists`, and `'unreadable'` refuses with `recipe-flow.ts:452-455`'s words.
- **`codexText`**: a failure becomes `false` through `Effect.orElseSucceed`, as at `recipe-flow.ts:561-563`.

## 10. Tests, and what cannot be checked here

- **`walk`** lives in `packages/setup/test/` or inside `project-list.test.ts`. It builds the context with `projectContext` and calls `runSetupList(projectList(ports), input, ctx)`. It returns `{ result, ctx }`.
- **Fake ports** are `Effect.succeed` values. `start` is a `RecipeDraft` fake whose `set` is `Effect.die`. The *"`set` dies"* test uses it on every walk, not only on one.
- **The resolve test** applies the seeded first-run `pending` with `editRecipe` over `version: N\n`, then asserts `projectView(…).resolved() !== null`.
- **Unit only.** Nothing here reaches git, a process or the network, so `pnpm typecheck` and `HOME=/nonexistent pnpm test` check all of it. No claim depends on the integration half.
- **The ratchet.** `packages/setup` stays at zero `async` and zero `run`. Use `Effect.gen` for every port read, and do not write an `async` helper in the test file either: the ratchet counts per package.
