# 1.0 — Lingtai as something you install

**Status** target · 2026-09-16 · the whole of it in one place, because it is
currently spread across four design documents and a dozen tickets

Today Lingtai is a repository you clone. 1.0 is a program somebody installs in
one line, points at a repository, and watches work. Nothing below is a new idea;
this is the map.

## The shape

**One artifact, two processes, one home directory.**

```
~/.lingtai/versions/1.0.0/
  lingtai              the binary — CLI and conductor. ~190MB, Node inside
  board/               next build --output standalone
~/.local/bin/lingtai   the entry
```

**The binary is Node**, so it loads the board itself. A person who installs
Lingtai needs no Node, no pnpm, and no clone.

**Three details, measured by building it (2026-09-16) rather than assumed:**

- The entry is `.next/standalone/apps/board/server.js` — a monorepo's standalone
  output keeps the workspace path, so there is a level more than you expect.
- It is **ESM**. A SEA's main script is evaluated as **CommonJS**, so the CLI
  reaches it with a dynamic `import()`. `require()` will not work and the
  difference decides whether this runs at all.
- The standalone output is **45MB**, and its only native file is
  `sharp-darwin-arm64.node` — pulled in for image optimisation the board never
  uses (`next/image`: zero occurrences). `images: { unoptimized: true }` drops
  it, and then **`board/` is pure JavaScript and the same on every platform**:
  only the binary differs per platform, not the UI.

Claude Code is the reference and it is on this machine:
`~/.local/share/claude/versions/2.1.251` is a 188MB Mach-O, several versions
side by side, `~/.local/bin/claude` as the entry. Versioned directories are what
make an upgrade atomic and a rollback instant.

### Four artifacts, not two

Node's SEA copies *the build machine's* Node binary, so a build runs on the
platform it targets:

```
macos-arm64   macos-x64   linux-x64   linux-arm64
```

The installer detects and picks. **No Windows** — see *What 1.0 is not*.

**Ad-hoc signed, at build time.** On Apple Silicon the kernel refuses to execute
an unsigned binary — this is not a Gatekeeper dialog, it is `exec` failing. So
`codesign -s -` is not optional. A Developer ID and notarisation are for browser
downloads, which `curl | sh` is not, and can wait.

**GitHub Releases hosts the artifacts**, and the installer verifies a checksum
before it unpacks. Piping a script to a shell is already a trust decision;
installing a 190MB binary that was corrupted or swapped on the way is a
different one, and the second is cheap to refuse.

### Get there in three steps, and only one is new

1. **`pnpm build`** — the board to `standalone`, the CLI bundled with esbuild to
   one CJS file. SEA takes a single file, which is why the bundle exists.
2. **SEA inject** — the binary. **The only new infrastructure.**
3. **The installer** — fetch the artifact for this platform, unpack into
   `versions/<v>/`, shim `~/.local/bin/lingtai`.

Steps 1 and 3 are needed either way, so **ship a tarball first**: same layout,
same installer, same upgrade and rollback. Step 2 replaces a directory's
contents later and the installer does not change.

An npm package stays as the escape hatch, the way Claude Code keeps both — it is
what makes `npx lingtai` possible for somebody who only wants to look.

## Installing

```bash
curl -fsSL https://lingtai.dev/install.sh | sh
```

What the script must guarantee: the artifact for this platform, unpacked, on
`PATH`. What it **cannot** finish: signing in to `claude-code` or `codex`. That
is interactive and belongs to the person, so the script reports which state it
found and hands over.

## The first run

`lingtai init` — and the installer runs it, so there is no second command to
discover.

| | |
|---|---|
| **Look before asking** | which agent runtimes are installed and signed in, whether `git` is present, what is already in `~/.lingtai` |
| **The database** | a Postgres URL if given — tables are created; **nothing given means SQLite**, in `~/.lingtai/` |
| **The GitHub App** | created in one click through GitHub's manifest flow, with the permission table pre-filled so it cannot be filled in wrong |
| **The agent** | detected. Where more than one is signed in, **ask** — never pick silently. Where none is, refuse by name |
| **Written** | `~/.lingtai/config.yml` |
| **Resumable** | interrupted setup continues on the next run rather than starting over — OpenClaw's habit, and the one that makes an installer forgivable |
| **Ends at** | **the board, on the wizard, ready to add a repository.** Not a green `doctor`, which is a verification and not a result — and not an empty board either, which is a product with nothing to say on its first screen |

**Subscriptions are not Lingtai's business.** Whether `claude-code` can run is
checked and reported; whether it is paid for is between the person and their
provider.

## Where things live

```
~/.lingtai/
  config.yml               this machine: ports, the database URL if any
  lingtai.db               the log, when no Postgres URL was given
  versions/<v>/            the artifact
  <project>/recipe.yml     gates, kinds, limits, which agent      per project
  <project>/env            secrets, 0600, .env format unchanged   per project
  <project>/app.pem        the GitHub App's private key, 0600
  repos/  worktrees/       the mirror and the blast radius
  runs/<project>/          run logs (0034)
```

**`env` keeps the `.env` format, only its path moves.** YAML would read
`password: 0123` as a number and `enabled: yes` as a boolean; for secrets, dumb
is a feature.

## Two processes, and the commands for them

```
lingtai start                 conduct, foreground
lingtai shutdown [why]        drain, then stop                    0030
lingtai restart [why]         the checked restart                 0042

lingtai board start           serve the UI, print the URL, open a browser
lingtai board stop
lingtai board restart
lingtai board status

lingtai service install|start|shutdown|restart|status|uninstall   both jobs
```

**The conductor gets `shutdown` and the board gets `stop`** because one finishes
the pass in flight — up to an hour — and the other has no pass to finish.
`service` gets `shutdown` too, for the same reason and because
[#174](https://github.com/steven-zhc/lingtai/issues/174) found it lying today:
`service stop` asks for a drain and launchd kills it twenty seconds in.

**Ports** — `17820` for the board, `17821` reserved and bound by nothing. Higher
is worse: macOS hands out `49152–65535` as ephemeral and Linux `32768–60999`, so
a default in either range collides at random and mostly not at all. **The daemon
listens on nothing** — everything reaches it through the log.

## The store

```
a Postgres URL in config.yml  →  Postgres
none                          →  SQLite, in ~/.lingtai/
```

**One URL.** The pooled/direct split was a Supabase artifact —
[0009](../decisions/0009-two-connections.md) says so itself: *on a plain Postgres
the two may be identical.* The test/production split goes too, because the suite
that needed its own database is the one that can now run on SQLite.

**No migration between them.** Switching stores starts a new log and picks up new
tickets. Nothing is converted and no tool is built.

**One exception, and it is this repository.** Lingtai's own log is cited by ADRs
and tickets, so it stays on Postgres. And from 1.0 onward **a citation is a
GitHub issue, never a `seq`** — which changes `CLAUDE.md:22` (*a finding that
cites a seq number is worth more than one that argues*) and `:93`. A durable
reference cannot live in a log anybody may reset.

**Schema changes are an accepted risk.** There will not be many; when there is
one, it gets solved then.

## The topology it assumes

[0046](../decisions/0046-lingtai-is-personal.md), in three lines:

- **One person, one Lingtai, one log.** The repository is the team's; the tool is
  not.
- **A claim is the issue's assignee**, not a lock and not a label.
  `lingtai:working` stays, for display. Unassigned work is taken by default.
- **The recipe is mine**, in `~/.lingtai/<project>/recipe.yml`. Nothing is written
  to the managed repository — so the wizard's final pull request goes, and
  `tamper` loses its subject rather than being switched off.

## What has to change in the code

| | |
|---|---|
| **A seam for waking and locking** | `subscribe()` takes an injectable store and then builds its own `pg.Client`; `acquireDaemonLock()` does the same. `Subscription.backendPid` puts a Postgres backend PID on a public type |
| **A contract for each** | `test/contract.ts` governs the store and nothing governs waking or locking. **Write the contracts before the implementations** — otherwise the second one is a fake nobody is holding to anything |
| **The SQLite store** | Prisma sibling package. Three interface methods; **no `queryRaw` or `executeRaw` in production code** to port |
| **The lock is a file** | `flock(2)` for both stores. Held by the descriptor, released by the kernel — the property `lock.ts` praises in the advisory lock, without the server |
| **Waking is a poll** | The notification is a nudge: *may be late, duplicated or spurious*, and a missed one costs the five minutes `SWEEP_MS` already tolerates. 100ms on a local file is faster than today |

## Upgrade, rollback, uninstall

**Upgrade** unpacks a new `versions/<v>/` and moves the shim. The running daemon
holds the code it started with ([0010](../decisions/0010-source-runs-unbuilt.md),
`#98`), so an upgrade drains and restarts — `lingtai restart` already exists and
already refuses on a dirty tree or a red `doctor`.

**The shim moves while the old daemon is still running**, so `lingtai shutdown`
is new code talking to a daemon started from the previous directory. **It works,
and the reason is that the channel is the log rather than the binary** — which is
what the daemon listening on nothing buys. It does impose one rule: **a version's
directory is not removed until no process is running from it.**

**Rollback** is the shim pointing at the previous directory. That is what
versioned directories are for.

**Which version is newest comes from the GitHub Releases API**, asked by
`lingtai upgrade` and reported by `lingtai doctor` — **not on every command**. It
is worth naming that this is the one outbound request a tool claiming to send
nothing anywhere makes, and it sends nothing but the question.

**Uninstall** asks once and then removes everything under `~/.lingtai`. And it
must end by naming what it could not remove:

> Removed everything under `~/.lingtai`.
> **The GitHub App `lingtai-steven` still exists and is still installed on 2
> repositories.** Its private key is gone and cannot be recovered — if you
> reinstall, create a new App.
> Remove it: `https://github.com/settings/apps/lingtai-steven`

**What an uninstall cannot delete matters more than what it can.**

## What 1.0 is not

- **No Windows.** macOS and Linux. WSL2 is where the reference implementations
  stop and it is where this stops.
- **No multi-user and no shared conductor.** That is 0045's topology and 0046
  replaced it.
- **No hosted version.**
- **Telemetry stays what it is** — cost and duration, already recorded, already
  on `/spend`. Nothing is sent anywhere. Not a 1.0 theme, and worth saying out
  loud in the README rather than leaving to be assumed.

## Two things this quietly costs

**`test:db` loses its subject.** It exists to assert Postgres *itself* — advisory
locks, `LISTEN`/`NOTIFY`, two clients racing. With the lock on a file and waking
on a poll, none of those is Postgres-specific any more, and what is left is the
store contract, which is shared. So either **Postgres runs the contract and
nothing else**, or it is a supported store nothing tests. The decision is the
first, and the database half does not run by default.

**The webhook receiver is the board's route**, so a board that is not running is
a webhook that is not received. [0006](../decisions/0006-github-app.md) says
webhooks are what make discovery event-driven; under two processes that is true
*while the board is up*, and the condition was written nowhere. It changes
nothing on a laptop, which is why it needs writing down rather than fixing.

## The work, in order

**Independent, do any time**

- `LINGTAI_DIRECT_DATABASE_URL` falls back to `LINGTAI_DATABASE_URL` — one
  function, and it halves the Postgres install on its own
- [#171](https://github.com/steven-zhc/lingtai/issues/171) evidence keeps both
  ends — **do this first**: until it lands, every long gate failure sends a fix
  round to work blind
- [#172](https://github.com/steven-zhc/lingtai/issues/172),
  [#173](https://github.com/steven-zhc/lingtai/issues/173) the discussion pane
- [#174](https://github.com/steven-zhc/lingtai/issues/174) `service shutdown`
  drains through the log

**The store, in order**

1. the waking and locking seams, **and their contracts**
2. SQLite: store, poller, file lock
3. one URL; *absence chooses* — and **it must not reach the test variables**

**0046's topology**

4. the recipe to `~/.lingtai/<project>/recipe.yml`; `runtime.agent` and limits to
   the machine; the machine file has **no `gates` key** — absent, not ignored
5. the assignee as the claim
6. undo the wizard's repository write, and change *pending* from *waiting for a
   recipe* to *waiting for the App*

**Packaging**

7. one publishable unit — both `package.json`s are `private: true` today
8. `pnpm build` → board standalone + CLI bundle
9. the installer, `versions/`, the shim, upgrade and rollback
10. SEA inject
11. `lingtai init`, ending at the board in a browser
12. `lingtai board start|stop|restart|status`; `service` installs two jobs and
    `status` reports each separately

**And this installation.** Two recipes have to come out of two repositories —
`lingtai`'s and `nextloom-ai-admin`'s `.lingtai/config.yaml` become
`~/.lingtai/<project>/recipe.yml`. **Two `cp`s, done once, by hand.** A migration
command for a job that happens once on one machine would be a command to
maintain forever.

**And the documents.** `tutorial.md`, `operating.md`, `guide.md` and `CLAUDE.md`
all describe the old topology. They become the official site's content, so this
is not tidying — it is the product's front page.
