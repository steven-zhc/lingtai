# Design note — #532

Pass the current `StandingView` from `Standing` into `Discussion`; keep the change to that prop handoff, `discussion.tsx`, and its styles. `Standing` already owns the current wait’s triage status and renders Discussion below the resolutions (`standing.tsx:648`, `standing.tsx:838`); `StandingView.triageStatus` is documented as “Derived for this wait alone” (`task.ts:382`). Use that status for the pane’s running, failed, advised, and no-triage presentation. Keep `NotNeeded`, `NotDeclared`, and a null status distinct: the ADR says a recipe without `triage:` runs nothing, while `OwnQuestion` and `SignoffRequired` need no triage (`0118-a-hold-explains-itself.md`, §3). Show analysis only when the current status contains it.

Make the compact entry depend on there being nothing to answer **and** no open or locally echoed conversation; expanding it must expose the existing thread and form. Do not collapse an active conversation. The existing open chat is identified by `held === null`, and a first question can exist as an echo before the fold contains it (`discussion.tsx:435`, `discussion.tsx:702`). Keep the current scroll, trace, meter, and ask logic under the new presentation: the code calls the trace “never the answer” (`discussion.tsx:308`), and its Enter guard explains that a second ask while busy “buys a second agent” (`discussion.tsx:362`). The ADR likewise calls Discussion “a place to think, not a record” (`0118-a-hold-explains-itself.md`, §3).

Treat the reference’s destination labels as illustrations until their destinations exist. Today proposal controls call `concludeChat` with only `prompt` or `ticket` outcomes (`discussion.tsx:641`); the ADR names additional destinations—“the body, the list of fixes, a split, or the person’s own answer box” (`0118-a-hold-explains-itself.md`, §6). Preserve the controls that perform their stated actions, omit unsupported destination controls, and file the missing routing as a separate implementation ticket. Do not rename “Add to the ticket” to imply it adds a fix, creates a split, or fills an answer.

Use six fixed render fixtures for desktop and narrow screenshot comparison against `Discussion.dc.html`, including a pending discussion turn separately from triage running. Assert at unit level that each fixture selects the right visible context, that a compact entry opens, and that unsupported actions are absent. Existing task-page snapshots include the Discussion pane (`task-page.test.tsx:146`); update them for intentional presentation changes. Run the ticket’s four build checks; the integration suite is outside this pass.
