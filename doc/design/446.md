# #446: the design for the last line

## Get the previous attempt's commits first

This note described a worktree whose HEAD was `main`'s `15040829`, before the previous attempt — `88086313` (the earlier version of this note), `8a8fa1fb`, `52df8274`, `6929b791` and `0ed0113f` — had landed on it. **That attempt is in the tree now**: `0ed0113f` and the `openIdx === 0` fix on top of it, `56cfa50b`, are both in `main`'s history by the time this line is read. Do not `git reset --hard` to an ancestor of the commit you started from — that discards whichever of those five commits came after it, along with the tests that pin them. Do not re-derive the 15 files in `git diff --stat 15040829 0ed0113f`. The shape, the GitHub compare-then-PATCH comment, the `db` conditional `UPDATE`, the memory tracker and the board's comment-dropping were all reviewed, and none of them is reopened here.

## The fix

`packages/conductor/src/body-section.ts:28-33` at `0ed0113f`:

```ts
function isNestedInAnotherSection(body: string, openIdx: number): boolean {
  const precedingOpenIdx = body.lastIndexOf(OPEN_MARKER_PREFIX, openIdx - 1)
  if (precedingOpenIdx === -1) return false
```

Add `if (openIdx === 0) return false` as the first line. When `openIdx` is 0, `lastIndexOf(…, -1)` clamps the search start to 0 and finds the section's own open marker at 0. The close marker after it then lies "after `openIdx`", so the function reports the section as nested. The `while` at `:90-92` skips it, `openIdx` becomes -1, and `:93-94` appends a second copy.

This is not a corner case. It is the path every first write takes. On an empty body, `:94` returns `${section}\n`, so the section starts at index 0, and the very next upsert for that key duplicates it. Discussion bodies written only by Lingtai look like this.

The guard has to be on `openIdx === 0` and not on `precedingOpenIdx === openIdx`. Any `openIdx > 0` searches from `openIdx - 1`, so it can never match itself. Index 0 is the only position where the clamp causes the self-match.

## The test

Added to `packages/conductor/unit/body-section.test.ts`:

- `upsertSection('', k, 'a')`, then `upsertSection(that, k, 'b')`. Asserts the open marker appears exactly once (`split(...).toHaveLength(2)`, not just `includes`), and that the second text is present and the first is not.
- One case for a body that is the first write trimmed — the shape a tracker returns after trimming.

Both are red without the `openIdx === 0` guard and green with it.
