# Design note for #1310: team-mode selection and `lingtai:landed`

The ticket covers most of the change. This note covers one decision the ticket does not make, the fact that refusals have two entry points, and two readers the ticket's list leaves out.

## 1. You cannot tell an absent `take` from `take: all` after the parse, so decide on the raw mapping

`AssigneeRule` has `take: AssigneeTake.default('all')` (`packages/recipe/src/recipe.ts:1177`). Each of these comes out of the parse as `{ take: 'all' }`:

- a team recipe that wrote `runtime.assignee: { login: me }`;
- one that wrote nothing, which `queueOf` fills with `EVERYONE = { take: 'all' }` (`packages/recipe/src/settings.ts:450`);
- one that really wrote `take: all`.

Fix §3 refuses only the last of these and wants the first two to read as `mine`. Two ways to get there:

- **Option A: drop the schema default.** This is rejected. `hashRecipe` hashes `parsed.data` (`resolve.ts:315-316`), so removing a filled-in field changes the `configHash` of every recipe already registered. That is a configuration change on every project, and this ticket has no reason to make one.
- **Option B: keep the schema as it is and decide in two places.** This is the one to build.
  1. **The refusal reads the raw mapping.** It walks the same two places `oldSpellingsIn`'s `takeBoth` already walks (`resolve.ts:389-405`): `runtime.assignee.take`, and `steps.claim[i].queue.assignee.take`. In a team recipe (`raw.mode === 'team'`, after the preset has been applied), any written `all` or `unassigned` is refused with the mock's sentence, naming the path it was written at. Each refusal is a `RecipeRefusedError`, not an `OldSpellingRefusedError`, because this is about the value's meaning and is not an old spelling.
  2. **Selection never reads `rule.take` in team mode.** In `assigneeSkip`, `selection.mode === 'team'` means *mine*, whatever the parsed `take` says. That is safe because every written value other than `mine` has already been refused, so the `'all'` that reaches it can only be the default.

**Both resolve paths need the raw check.** `refuseOnMeaning` is called from two places, each holding the applied raw mapping:

- `resolveSource` (`resolve.ts:283`, `:310`);
- the declared-recipe check (`packages/recipe/src/declared.ts:56`, `:78`).

Give `refuseOnMeaning` the raw mapping as a parameter, or add a sibling function that both callers run. Do not add the check to only one of them: `/recipe` and `lingtai add` would then disagree with the pass.

## 2. Where the login refusal goes once the refine is removed

Delete the `.refine` at `recipe.ts:1179-1182`. Its replacement goes in `refuseOnMeaning`, over the **parsed** recipe. That is safe here because `mine` is never a default, so a parsed `take: 'mine'` was always written.

- **The solo check keeps today's sentence**, and it fires only when `ticketSourceOf(recipe) === 'github'` (`settings.ts:366-368`). The refine fired on `runtime.assignee` and on each declared `queue.assignee` separately (the doc comment at `recipe.ts:1197-1201` says the refine *"goes on firing from in here"*), so keep both places and name the path in each message.
- **The team check is new.** On `github`, it refuses when the effective rule `assigneeOf(recipe)?.login` (`settings.ts:406-408`) is undefined, and the sentence names `queue.assignee.login`.
- Update the comments at `recipe.ts:1178` and `:1197-1201`. They describe the refine as the place this refusal lives.

## 3. What `selection` changes inside `considerIssue`

`assigneeSkip(issue, rule, selection)` (`discover.ts:284-297`) gains two guards ahead of today's body:

- if `selection.tickets === 'db'`, return `null` in either mode. This comes first, because `toListing` gives every local ticket `assignees: []` (`db-tickets.ts:207-213`).
- if `selection.mode === 'team'`, treat the rule as `mine` with `rule.login`.

The rest of today's body is the solo path on GitHub, unchanged.

`landed-elsewhere` is checked straight after the `PUBLISHING_LABEL` line (`discover.ts:233`), using the `labels` array that has already been lower-cased (`:230`). It applies only when `selection.mode === 'solo'`. `LANDED_LABEL` is in this package already (`packages/conductor/src/labels.ts:27`), so no new dependency is needed.

## 4. Deleting #1306's pass refusal: there is also an option to remove

The refusal is at `packages/conductor/src/conduct.ts:1115-1131`. It comes with an escape hatch, `landTeamTickets?: true` (`conduct.ts:561-564`), whose doc comment says it *"Exists only until #1310 deletes the refusal"*. Delete the option together with the refusal, and fix whatever `tsc` then names.

The refusal's test is in `packages/conductor/unit/conduct-a-whole-attempt.test.ts`. Find it by its *"cannot yet land a team ticket"* sentence. If the test only checks the refusal, delete it. If it is a team-mode test that passes `landTeamTickets`, keep the test and remove the option from it.

Check `modeOf` still has another use in `conduct.ts` before you delete its import (`:1121`).

## 5. A reader the ticket's list leaves out

Fix §8 names `describeAssignee` (`filter.ts:589-600`) and the provenance line (`packages/project/src/local.ts:245-249`). The board's `/recipe` reading in `apps/board/src/lib/recipe.ts:731-736` also turns `take` into a sentence. On a team recipe it currently says nothing about whose tickets are taken, which matches what `take: 'all'` reads as. Make all three mode-aware, and give each the selection it needs:

- `describeAssignee(rule, selection)`;
- `local.ts`: print `mine` in team mode instead of the parsed `'all'`, otherwise the provenance line shows a value the pass does not use;
- the board's `recipe.ts`: compute the selection from the recipe it already has.

## Checks

All of the above is pure and covered by the unit half; none of it needs `pnpm test:integration`. No new IO, so `effect-ratchet.baseline.json` must not change.

The tests should include:

- **Team, raw.** A team recipe writing `runtime.assignee: { login: me }` with no `take` resolves and selects only *me*. The same recipe with `take: all` written is refused.
- **Solo, unchanged.** `{ login: me }` in solo still selects everyone. This is the regression test for the design in §1.
