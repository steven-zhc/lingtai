# Design: `HoldTriaged` and `TriageStarted` (#409)

## Watch out: you cannot import `TriageResult` into `events.ts` from where it is now

#439 put `TriageResult` in `packages/domain/src/hold.ts:348`, and `hold.ts` imports from `events.ts`:

```ts
// packages/domain/src/hold.ts:17
import { RefusalReason, RunFailed, Step } from './events.ts'
```

It uses those imports while the module loads, at top level. One example is `CeilingKind = RunFailed.shape.kind.extract(...)` at `hold.ts:172`. If `events.ts` imported `TriageResult` back from `hold.ts`, the two modules would form an ESM cycle. Whichever loads first would read the other's bindings before they are defined, and fail with a `ReferenceError` the moment the package loads. The ticket rules out a copy ("the same type and not a copy", 0118 §3), so move the definition instead:

- **Move the whole `// --- triage ---` section of `hold.ts` (lines 232–363) into a new `packages/domain/src/triage.ts`.** That is `TriageQuestion`, the hunks, `Merge`, `MERGE_HUNKS_ONE_BY_ONE`, `Cause` and its parts, `Move`, `Failed`, `Advised`, `TriageResult` and `TriageStatus`. None of it uses anything from `events.ts`. Even `Setup`'s `lifts` is an inline `z.enum`, not an import.
- `triage.ts` imports `zod` and `./spend.ts` (for `Usage`) and nothing else. `hold.ts` keeps the nine hold variants and gets nothing from `triage.ts` at runtime. `events.ts` imports `TriageResult` from `./triage.ts`.
- Add `export * from './triage.ts'` to `packages/domain/src/index.ts`. Importers of `@lingtai/domain` see no change. `packages/domain/unit/hold.test.ts:32-36` imports these names from `'../src/hold.ts'` directly, so point that import at `../src/triage.ts`.
- The import guard in `hold.test.ts:214-243` (no `@lingtai/recipe` or `@lingtai/conductor`, only `zod` as a dependency) still holds, because `triage.ts` imports nothing new.

## Strict objects, or half the refusals pass

zod 4 (`packages/domain/package.json:10`) **strips** unknown keys by default. So with every triage object as a plain `z.object` today, several payloads the Done-when list must refuse would parse:

- a `Failed` carrying `cause`
- an `Advised` carrying `questions` or `fixes` beside `cause`
- a `Decision` carrying `fixes`
- a `MechanicalHunk` carrying `question` (`hold.ts:255`)
- a `Mechanical` `by` carrying `runtime` or `costUsd`

Each would parse with the extra key silently dropped.

**Make every object in `triage.ts` strict, plus both `by` shapes and both event payloads.** Where an object already has a `.refine` (`TriageQuestion`, `Merge`), use `z.strictObject({...}).refine(...)`, so the strictness is on the object and the refine is applied after it. `events.ts:885-888` is the existing precedent for `.strict()` in this package.

## `by`

Define these in `events.ts`, beside the two payloads:

- **`HoldTriaged.by`:** `z.discriminatedUnion('_tag', [...])` of:
  - `Agent`: `{ _tag: 'Agent', runtime: string, model: string, costUsd: z.number().nullable(), usage: Usage.optional() }`. `costUsd` is required and nullable, never optional and never defaulted, exactly as `RunFinished` at `events.ts:574-576` does it ("Absent, never zero").
  - `Mechanical`: `{ _tag: 'Mechanical' }`, strict.
- **`TriageStarted.by`:** its own union. Its `Agent` is `{ _tag: 'Agent', runtime, model }` with no spend, because nothing has been spent at that point. Being strict, it refuses a `costUsd` too.
- Export the shapes as `TriageAgent`, `TriageMechanical`, `TriageBy` and `TriageStartedBy`. Do not use a bare `Agent` or `Mechanical`, because `index.ts` re-exports `events.ts` and `triage.ts` side by side with `export *`, and `'Mechanical'` is already a hunk `_tag` in triage.

## The two payloads

- **`TriageStarted`:** `{ blocked, attempt, by: TriageStartedBy }`, strict.
- **`HoldTriaged`:** `{ attempt, blocked, headSha: z.string(), result: TriageResult, by: TriageBy }`, strict.
- **`attempt`** is `z.number().int().positive()`.
- **`blocked`** is also `z.number().int().positive()`. It is the `WorkItemBlocked`'s envelope `version`, which `envelope.ts:62` documents as "Position within the stream, from 1". Say so in the field's comment, and say it is not a seq.
- **Registry and docs:**
  - Add both to `EVENTS` (`events.ts:2142-2211`). Add nothing to `BUMPED` (`:2250`): every type outside it is version 1 through `SCHEMA_VER` (`:2306`).
  - Put both in a new `triage (2)` row of `doc/reference.md:28-45`.
  - **Recount from the registry; do not add 2 to the header.** `doc/reference.md:22` says 67, but a line count of the entries in today's `EVENTS` block gives 68. Count it again, and check how the header treats `RETIRED` types before writing the new number.

## Bounds

Export the numbers from `triage.ts` beside `MERGE_HUNKS_ONE_BY_ONE` so #412 can import them. Suggested names: `TRIAGE_QUESTIONS_MAX = 5`, `TRIAGE_ANSWERS_MAX = 4`, `TRIAGE_FIXES_MAX = 20`, `TRIAGE_TEXT_MAX = 500`, `TRIAGE_SENTENCE_MAX = 200`. Apply them as follows:

- **Questions:** `.max(TRIAGE_QUESTIONS_MAX)` on `Decision.questions`.
- **Answers:** `.max(TRIAGE_ANSWERS_MAX)` on `TriageQuestion.answers`. A divergent hunk's question is the same schema, so it is covered too.
- **Fixes:** `.max(TRIAGE_FIXES_MAX)` on `Lines.fixes`.
- **Hunks:** add `.max(MERGE_HUNKS_ONE_BY_ONE)` on `Merge.hunks`. The refine at `hold.ts:286-289` already implies the cap, but the explicit max gives a clear error and its own test case.
- **Text, 500:** every string the agent writes. That is question and answer `text`, `Lines.what` and `failure`. It also includes ids and paths, which are written by the agent too, and bounding them costs nothing.
- **Text, 200:** `sentence` and `want`.

## History lines

Add two formatters in `apps/board/src/lib/history.ts:138`, using the `need` and `clip` helpers the other entries use so an empty payload still prints something. `history.test.ts:35-41` feeds every type `{}`, `null` and a wrong shape.

- **`TriageStarted`:** `attempt N · <runtime/model | mechanical>`
- **`HoldTriaged` (advised):** `attempt N · <cause._tag> → <move._tag>: <clip(sentence)>`
- **`HoldTriaged` (failed):** `attempt N · failed: <clip(failure)>`

## Tests

Put the Done-when cases in a new `packages/domain/unit/hold-triaged.test.ts`, through `parsePayload` (`events.ts:2336`). The "refuses" cases are the ones that would have passed without strictness, so each of them proves the strictness is in place.

Nothing here reaches outside the process, so `pnpm test` and `pnpm typecheck` check all of it, with no integration-only claim. If the cycle above ever came back, the whole unit suite would fail when the package loads, not just one test.
