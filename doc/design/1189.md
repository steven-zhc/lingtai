# Design note for #1189: give the home page's sandbox card its own class names

## The rename

Rename the classes used **only** on the card in `apps/site/src/app/page.tsx:198-283`: `sbx` → `home-sbx`, `sbx-top` → `home-sbx-top`, `sbx-group` → `home-sbx-group`. Make the same change to every selector in `apps/site/src/app/home.css` that names them: `.sbx`, `.sbx-top b/small`, `.sbx-group …`, `.home .sbx-group h3`, `.sbx .no`, `.sbx .yes`. Nothing else in `apps/site/src` uses `sbx` (a grep turns up only the five `className`s at `page.tsx:198,199,206,223,248`).

Leave `.no` and `.yes` as they are. They are only reached as descendants of the card, and the board's `globals.css` has neither. Leave the `.sandbox-*` classes and `.home` alone too: none of them appears in `globals.css`.

`apps/site/unit/page.test.tsx` does not name any `sbx` class today. Its sandbox test (`:168-185`) only slices from `class="sandbox-pitch"`. So no existing assertion needs changing. Add one line to that test: `expect(block).toContain('class="home-sbx"')`. Without it, the markup could drift away from the stylesheet and nothing would notice.

## The guard test

Put it in a new file, `apps/site/unit/home-css.test.ts`. It does not render anything, so it does not belong in `page.test.tsx`. It reads two CSS files with `readFile`, which makes it the same kind of test as the existing `readFile` checks in `page.test.tsx:21,43`.

Three decisions the ticket leaves open:

1. **Where the block starts and ends.** It starts at the comment `/* The sandbox: a dark band.` (`home.css:213`). It ends at the next top-level comment, `/* Why not just give the agent the issue? */`. The ticket says "the `@media` that ends it", but that boundary does not hold: the block contains two `@media` rules, and the dark-scheme one (`:247`) comes before the breakpoint one (`:250`). Find both markers by their text, not by line number, and assert that each one is found. If a marker is missing, the test must fail; otherwise an empty slice would pass while checking nothing.
2. **Strip comments before extracting anything, in both files.** The block's own header comment lists `.kicker, .link, code, .tag.ill`. The board's comments contain text like `(bar.test.ts)`. A regex run over raw text would read those as class selectors.
   - None of these collides today: `kicker`, `link`, `tag` and `ill` all give 0 matches in `globals.css`. The ticket says the two apps share them, but they are not in the board's stylesheet.
   - The rule still has to be right, or a comment edit will one day turn the test red for no reason.
3. **Take class names from the selector side of each rule only**, meaning the text before each `{`.
   - Values such as `.08em` and `1.55` must never count. A class token pattern like `\.(-?[A-Za-z_][\w-]*)` already skips them, because those start with a digit. Restricting to selectors is still the safer rule.
   - Treat `@media (...) {` headers as selectors with no classes in them.
   - Collect the board's classes the same way from all of `apps/board/src/app/globals.css`: comments stripped, selectors only.

Then assert that the intersection is empty and print the class names that collide. Also assert that `home-sbx` is among the classes extracted from the site block. That proves the slice and the parser are actually reading the card's rules.

Before the rename, this test must go red on `sbx` (`globals.css:3152` is `.sbx { display: inline-flex; … }`). Check that it does before making it green.

## What can't be checked in the pass

The visual check at 1360px and 390px (a `Done when` item) can only be done by a person: every unit test renders with `renderToStaticMarkup` and loads no CSS. The build step's `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` cover everything else. Nothing here needs the integration half.
