**Design note for #819: publish `guide` and add it to the Docs menu**

The ticket's fix is the shape. The one thing it misses is that the docs comment in `docs.ts` uses this exact page as its example of a page that is *not* public. Once `guide` is published, that example is false.

**1. Replace the example in the `PUBLIC_SLUGS` comment.** `apps/site/src/lib/docs.ts:66-67` currently says:

> Everything that would otherwise 404 on the site — a link from the tutorial to `guide.md`, say — resolves to the file on GitHub instead (`resolveHref`).

After this change, the case the new test checks (`resolveHref('tutorial.md', 'guide.md', …)` → `/docs/guide/`) is the opposite of that sentence. Replace `guide.md` with a page that stays unpublished. Pick one that the sections list names but `PUBLIC_SLUGS` (`docs.ts:69-79`) does not, and check it against the section list in `docs.ts:116` onwards. Do not just delete the example.

The paragraph above it (`docs.ts:55-63`) lists every published page and why it is public, ending with `safety` (#809). Add a clause there for `guide`: *the habits that make a run cheap and predictable (#817, #818)*. Without it, the comment no longer names everything the list holds.

**2. Menu order.** In `apps/site/src/app/chrome.tsx:24-34`, the comment over `DOCS_MENU` says *"A rule is drawn after `rule`."* So `rule: true` comes off `safety` and goes onto the new `guide` entry, and the rule still falls between the "before you start" group and the references (`recipe` onwards). Nothing else in the array moves.

**3. The test.** Put it beside *publishes the safety page* in `apps/site/unit/docs.test.ts`, as the ticket says. No existing test uses `guide.md` as its example of a link that goes to GitHub. The only `guide` matches in `apps/site/unit` are the guides-section cases at `:41-48` and `:383-390`, and they test the section tree, not the public list. So no existing assertion flips when the page goes public. Do not add an assertion on the menu's array order: the ticket asks only that `guide.md` is served and that its link resolves to `/docs/guide/`.

**4. Check.** Run `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`. Nothing here needs the integration half. The Next build test (`apps/release/integration/build.test.ts`) is where a broken link would show, but it only runs after the merge. The unit-level stand-in is the `resolveHref` case from step 3.
