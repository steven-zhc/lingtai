The ticket already gives the shape. This note adds two decisions it leaves open.

**1. Each move takes its number from the counter it spends.** In `offerFor`, a `land-again` is numbered `landingRetries + 1`. A `rerun-setup` or `ask-again` is numbered `stepRedos + 1`. The route's `retry` field keeps one name on both `LandAgain` and `RerunStep`, so the reducer has to choose the counter by the route's tag. It must not choose by the field. Today one fold covers both routes (`attempt.ts:606-615`), so it has to be split by `_tag` into two `Math.max` folds. The same split is needed in `spentAfter` (`attempt-next.ts:500-502`) and at both route sites in `runAttempt` (`run-attempt.ts:1875`, `:1884`). If any one of these three keeps the shared fold, the test where landings and redos don't use up each other's count still passes on the reducer alone. So write that test against `offerFor`, given a `Spent` built by `spentAfter`, rather than only against the reducer.

**2. The dispatch-id suffix becomes `stepRedos + accountReruns`.** Today it is `transientRetriesSpent + accountReruns` (`run-attempt.ts:2033`, `:2038`). The comment at `:1004-1007` says *"every rerun's suffix is `transientRetriesSpent + accountReruns`, so the two kinds never repeat an id"*. Rename it and keep the claim. A landing retry never reached this sum through a dispatch of its own, so within an attempt that starts after the merge, no suffix can repeat.

There is one case where it can repeat. Take an attempt still in flight across the deploy, such as one held at a person and continued later. Suppose that before the merge it spent a landing retry and then an account rerun, which got suffix `1 + 1 = 2`. After the rebuild it reads `stepRedos = 0`, so a second account rerun gets `0 + 2 = 2` again.

This is accepted and needs no code:
- It needs three things to happen in one attempt that crosses the deploy: a landing retry, then an account rerun, then another account rerun.
- The ticket rules out migrating or rewriting old events.
- The log can settle whether any such attempt is open. Look for an attempt stream with a `LandAgain` route followed by an account-limit rerun, and no terminal event after them.

Say this in the commit body so the operator can check before the rebuild. Don't add a guard for it.

Everything else is as the ticket says. Nothing here contradicts an accepted ADR: 0108 §8 and §15 are what this implements, and the edits to 0120 and to 0108's *Not built yet* are corrections to topic ADRs, not new decisions.
