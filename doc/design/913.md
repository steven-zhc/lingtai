## #913 design note: the placeholder follows the page's state

The ticket's own table settles the wording and the function. Three things are left that it does not settle, and they are decided here.

**1. Line numbers have moved since `9c0276dc`.** In this worktree:
- `<Discussion>` is `apps/board/src/app/standing.tsx:1045-1053`, not `:809-819`.
- It already passes `quiet={standing.state === 'running' || standing.state === 'queued'}` (`:1052`).
- The literal is `apps/board/src/app/discussion.tsx:813`.

Find them by text, not by line number. The element is still the only `<Discussion` in `apps/board/src` (`git grep -n "<Discussion\b" -- apps/board/src`). Add `state={standing.state}` and `attempts={standing.attempts}` beside the props already there, and change nothing else on that element. If the queued-panel blocker lands first and moves it, put the two props on it wherever it ends up.

**2. Where the state type comes from.** `StandingState` is `'queued' | 'running' | 'blocked' | 'landed' | 'closed' | 'approved'` (`apps/board/src/lib/task.ts:400`). `discussion.tsx` is a client component. Its only import today is `import type { TriageStatus, WaitReason } from '@lingtai/domain/wait'` (`discussion.tsx:3`). `task.ts` opens by importing `@lingtai/conductor`, `@lingtai/conductor/filter`, `…/projects` and others (`task.ts:1-5`), which are server modules.
- Bring the type in with `import type { StandingState } from '../lib/task.ts'`. It must be `import type`, never a plain import.
- An `import type` is erased. A plain one would pull the conductor into the client graph.
- `tsc` cannot see that mistake. The only test that does is `apps/release/integration/build.test.ts`, which nothing runs before the merge (#230 is what it costs when it is caught late).

**3. The new props are required.** Declare them as:
- `state: StandingState`
- `attempts: number`

`StandingView.attempts` is already a plain `number` (`task.ts:510`, *"How many there have been, so `attempt 2 of 2` can be said"*). If the props were optional with a default, a caller that forgot them would silently show some row of the table, and that is how the literal stayed wrong on every page.

Required props break eight test call sites, and `pnpm typecheck` will list them:
- `apps/board/unit/add-to-resolution.test.tsx:37`, `:72`, `:81`
- `apps/board/unit/discussion-live.test.tsx:51`, `:146`, `:161`, `:219`
- `apps/board/unit/meter.test.tsx:53`

Each currently renders `attempt={2}`.
- Give them `state="blocked" attempts={2}`, which keeps them true to the page they were drawn for.
- The one at `discussion-live.test.tsx:219` passes `quiet`, so it is a running page: use `state="running"` there.
- None of these tests asserts the placeholder, so their assertions do not change.

**Shape of `askPlaceholder`:**
- **The input type:** take `{ state: StandingState; attempt: number | null; attempts: number; reason: WaitReason | null }`.
- **Order of the checks:**
  1. `closed` first, because it needs no number.
  2. Then `queued`, which uses `attempts + 1` and never `attempt` (the ticket's Watch out).
  3. Then `blocked` with `reason?._tag === 'OwnQuestion'`, which also needs no number. `task.ts:782` and `:892` test that tag the same way.
  4. Then, for every remaining state, the fallback row when `attempt === null`, and otherwise the row with `attempt`.
- **No default branch:** end with an exhaustive `switch`, so that a seventh `StandingState` fails `tsc` rather than falling through.
- **Where it is called:** `Discussion` calls it inline in the `placeholder=` expression when `open === null`, and *ask a follow-up* stays unchanged. It is not memoised and not held in state, so a live refresh that changes the state re-renders the new sentence.

**Tests:**
- Put the table test in `apps/board/unit/discussion.test.ts`. It is pure, so it needs no `.tsx`.
- Put the render test in `apps/board/unit/discussion-live.test.tsx`, which already does `renderToStaticMarkup(<Discussion …/>)` (`:50-51`). Render `state="queued" attempt={null} attempts={0}` and assert `placeholder="what will Attempt 1 change first?"`.
- For the `null` / `undefined` / *attempt 2* check, loop over every `StandingState` × `attempt ∈ {null, 1, 2}` × `attempts ∈ {0, 1, 2}` × `reason ∈ {null, an OwnQuestion}`. Writing a few cases by hand would be weaker.

Nothing here touches an ADR, and nothing here can only be checked by `pnpm test:integration`. What stands in for the build-only check in point 2 is the `import type` itself.
