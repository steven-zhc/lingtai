**Where the code goes**

- **`apps/board/src/lib/remember.ts`**: plain functions with no `next/*`, `node:` or `@lingtai/*` value import. It holds `homeRedirect`, `projectCookie`, `rememberProject` (`document.cookie = projectCookie(choice)`) and the cookie name. Client files will import it, so it has to pass `unit/client-graph.test.ts`. That test's own header says it is *"the unit-half stand-in"* for the Next build, which runs only after the merge. Keep it free of server imports even though nothing before the merge would catch one.
- **`apps/board/src/proxy.ts`**: it goes beside `src/instrumentation.ts`, which confirms the board uses the `src/` layout. It reads `request.nextUrl.searchParams` and `request.cookies.get('lingtai-project')?.value`, calls `homeRedirect`, and returns `NextResponse.redirect(new URL(target, request.url), 307)` or `NextResponse.next()`.
  - Write it as a **synchronous** function. Nothing in it waits, and an `async` here would be one more count in `effect-ratchet.baseline.json`.
  - Build the target from `nextUrl.searchParams`, not from the raw URL string, so Next's internal RSC parameters do not end up in the address bar. A unit test cannot show this; the production-build check in *Done when* is what covers it.
- **Who decodes the cookie**: `homeRedirect` takes the value already decoded. Next's `RequestCookies` decodes it, and `projectCookie` encodes with `encodeURIComponent`, so the two halves match.
  - The pure test cannot see the Next half. If you want the space-in-a-name round trip pinned, build a `RequestCookies` from `next/server` over a `Headers` that carries `projectCookie('a b')`'s value. That needs no IO, so it stays a unit test.
  - If Next ever hands over a value it could not decode, `homeRedirect` treats anything other than a non-empty string as absent.
