# Design note: #852, the *pass* strings under `packages/*/src`

## Shape

Make one hand commit, or one per package if that is easier to review. It touches string literals, the test pins they break, and the test titles. Nothing else changes, so there is nothing scripted, no `.git-blame-ignore-revs` line and no rebuild. The real work is deciding, line by line, **which of three things each *pass* means**. Spelling does not tell you. Read what the surrounding code holds.

| the string is about | becomes | how to tell |
|---|---|---|
| one claim worked through the steps (one `pass-…` stream) | **attempt** | it has a `runId`, a ticket, rounds or a branch |
| one go round the daemon's loop over the projects | **turn** | it sits next to `options.pass(reason, …)`, `paused`, `SWEEP_MS` or the `'startup' \| 'completion' \| 'sweep'` reason |
| a restart, "started over from the base" | **attempt** | `doc/glossary.md:57-60`: *"a Requeue or a restart starts a new one"* |

Cases that are already decided:

- **`ceiling.ts:80-107`.**
  - `:97` becomes *"An attempt whose rounds are spent goes to you (runtime.limits.restarts: 0)"*.
  - `:104`'s *"at most ${passes} passes"* becomes *"at most ${attempts} attempts"*. A restart is a new attempt, so the arithmetic is still right.
  - The local `pass` (`:80`) and `passes` (`:100`) may be renamed in the same edit, because they build this sentence and nothing else. The ticket allows that only where the enclosing function is renamed anyway. This function is not renamed, so leaving them is also fine.
- **`daemon/src/work-loop.ts:538`.** `pass failed:` is printed when the `options.pass(reason, started)` call at `:534` throws. That call is a turn, so it becomes `turn failed:`.
- **`daemon/src/control.ts:400`.** `finishing ${n} passes:` lists the attempts in flight, so it becomes `attempts`.
- **`conductor/src/prompt.ts:314-324`, the agent's brief.** *this pass* becomes *this attempt*, and the heading becomes *"## What this attempt checks, and what it does not"*. **Never use *turn* here.** The same brief already uses *turn* for the agent's own conversation turn: *"commit it before you verify something this turn cannot finish. There is no later turn"* (`prompt.ts:326-328`). Putting the conductor's *turn* in that same text would leave the agent with one word for two things.
- **`recipe/src/recipe.ts:1677`.** The string cites `packages/domain/src/pass-next.ts`. #849 renamed that file to `attempt-next.ts`, and the string still names the old file. Fix the path as part of the same edit.
- **Keep these:**
  - `domain/src/envelope.ts:72`, which lists the stream prefix `pass-…`;
  - `env/src/colour.ts`'s `pass`, which is the colour;
  - every `'pass-'` value;
  - every verdict (*"make ${base} pass it"*, `wait-words.ts:171`).

## Narrowing the grep

The ticket's grep matches **comments** as well as strings, because a backtick in a doc comment opens a "string". Today it finds 393 lines, not about 232. Comments are out of scope, except a doc comment that quotes one of the changed sentences, so drop them before you start:

```
… | grep -vE '^[^:]+:[0-9]+:\s*(\*|//|/\*)'
```

The hand commit's list of lines you kept should come from that filtered output. It should not list comments.

## Pins the ticket does not name

**Negative pins go silently green.** A `not.toContain('…pass…')` checks a string that this ticket changes. After the reword it asserts nothing and stays green. Move each one to the new word so it keeps meaning something:

- `packages/domain/unit/attribution.test.ts:231` (`not.toContain('inside the pass')`) guards the reasons in `domain/src/attribution.ts`. It becomes `'inside the attempt'`. Keep the old phrase as a second assertion if you like.
- Do the same for any other `not.toContain` you find. To list them: `grep -rn "not.toContain(.*[Pp]ass\b" packages/*/unit apps/*/unit`.
- Leave alone the two pins on `apps/cli/src/setup-card.ts:190`'s `'each pass'` (`apps/cli/unit/init.test.ts:301`, `setup-card.test.ts:181`). That string is under `apps/*/src`, so it belongs to #853.

**Pins on `wait-words.ts`, across package lines.** `APPROVE_EVERY_PASS` (`domain/src/wait-words.ts:41`, *"the recipe asks you to approve each pass"*) is pinned word for word in:

- `packages/domain/unit/wait-words.test.ts:73`
- `apps/cli/unit/status.test.ts:344`, `:348` and `:378`

These move with the string, the same way `run-before-dispatch.test.ts:117` does. Rename the const to `APPROVE_EVERY_ATTEMPT` in the same edit: it is module-local and only names that string.

**A projector `.snap` may move here, and that is allowed.** `projector/src/task-view.ts:375` writes `waitWords(...).line` into a stored task_view column. So any wait-words sentence you change can show up in `packages/projector/unit/__snapshots__/task-view-rebuild.test.ts.snap`. The ban on projector `.snap` changes is for the rename tickets. Here it is the ticket's own rule: *"a `.snap` that changes because a string changed belongs to a strings ticket"*.

- Run `vitest -u` on that one file.
- Check that the diff shows only re-worded text: no `run_id`, no `pass-pin-…` values.
- `histories.hashes.json` must not move. It hashes the fixed event histories, not text derived from them (`domain/unit/histories.test.ts:1-10`).

## Edges

- **A running daemon.** The ticket covers this. In addition, the triage-queue wait words reach the board through task_view.
- **Rows already projected.** task_view rows written before this keep the old wait-words text until the next change to that ticket. No rebuild is required, and none is part of this ticket. A person who wants the old rows re-worded runs `lingtai projection rebuild task_view`. Say this in the commit body next to the list of output lines.
- **A string a program matches on.** Nothing should match on prose, because `fix.ts:83-95` says rules are typed for exactly that reason. If a test fails because code compares a sentence and not because a pin moved, stop and report it. Do not re-word to get around it.
- **The cost to later tickets.** The negative pins above are the only thing that would otherwise go red or vacuous later without anyone noticing.

## Checks

`pnpm typecheck`, `pnpm lint`, `pnpm fmt:check` and `HOME=/nonexistent pnpm test` all reach these pins. Nothing here needs `pnpm test:integration`.
