# Design note for #1117: event-store and projector faces that still say `#790`

## The decision the ticket leaves open: what counts as "a host calls it"

The ticket's four branches miss two cases, and both are in the tree today.

**1. A host reaches a face through another package.** For example, `processTicketSql` has no caller in `apps/board`. The board still reaches it:

- `apps/board/src/app/actions.ts:101` and `apps/board/src/lib/task.ts:1961` call `ownerlessClient`.
- That runs `ticketsForEffect` (`packages/conductor/src/ownerless.ts:52`).
- That runs `defaultSql` at `packages/conductor/src/ticket-store.ts:232-234`.
- `defaultSql` calls `m.processTicketSql()`, and the `TicketSql` it returns is `promiseLogSql(logSql)` (`packages/event-store/src/choose.ts:144`, `:170`).

**Rule:** reaching a face transitively from `apps/board/src`, `apps/site`, or a board test counts as a host caller. The `why` names the host file and the path it takes, e.g. *"apps/board actions.ts:101, task.ts:1961 via conductor ownerless.ts:52 → ticket-store.ts:232"*. Because the check only verifies that a path under `apps/board/` or `apps/site/` exists, this rule costs nothing in `checkFaces`.

**2. A face has production callers that no host reaches.** It can say neither `#790` nor `"0101 §7"`, so this ticket moves those callers to the Effect twin.

- They are almost all Effect → face → Effect, which `packages/projector/src/store-face.ts:11-13` already forbids: *"A moved caller is never handed a face. That is Effect → face → Effect, and the face's run starts a root fiber that drops the caller's span and interruption."*
- Known cases:
  - `ticket-store.ts:232-234` and `packages/conductor/src/ticket-history.ts:24-28` change `Effect.promise(() => processTicketSql())` to `processTicketSqlEffect()` (`choose.ts:106`, already exported).
  - `apps/cli/src/doctor.ts:798` uses `projectionShape` only as `typeof`. Change it to `Effect.Effect.Success<ReturnType<typeof projectionShapeEffect>>` and delete `projectionShape`.
- Then fix the prose that names the deleted face: `ownerless.ts:47`, `apps/cli/src/conduct.ts:219`, `packages/conductor/src/filter.ts:330`, `packages/conductor/src/db-tickets.ts:98`.
- `processLog` still has callers in `conductor/approve.ts`, `conductor/db-tickets.ts`, `apps/cli/src/triage.ts` and `daemon/src/reconcile.ts`. Apply the same test to each:
  - If the board reaches it (check `approve` from `apps/board/src/app/actions.ts`), keep it with a board `why`.
  - Otherwise export `processLogEffect` (`choose.ts:87`, currently unexported) and move the caller.

Moving a caller in another package is not CLOSE-790c's work, because the face being retired is in event-store. CLOSE-790c owns faces that live in those other packages.

## Method faces: keep every method of an object a host holds

A face that fills a promise object stays as long as any host holds that object, whether or not anyone calls the method by name. You cannot delete one method because the interface requires all of them, and `tsc` will say so — this is a case where it *does* catch the mistake. Narrowing `Log`, `EventStore` or `ProjectionStore` is out of scope: packages outside this ticket hold those types.

**event-store: every face in these builders stays.**

| Builder (`store-face.ts`) | Methods | Host holder |
|---|---|---|
| `promiseStore` (`:59-65`) | `append`, `read`, `head`, `readTypes`, `readAll` | `eventStore` (`index.ts:96`), `log.store` |
| `promiseQueries` (`:121-128`), six methods | | `Log.queries` is required (`log.ts:54`), and `log` is `deferredLog()` (`choose.ts:288-295`, `index.ts:108`), which the board imports |
| `promiseSnapshots` (`:201-205`) | `latest`, `put`, `census` | `log.snapshots`: `board.ts:1505`, `snapshot-writer.ts:24`, `actions.ts:820` |
| `promiseWaker` | `wakeSessionFace` | `route.ts:139` |
| `subscribe.ts` | `followFace` | `route.ts:133` |
| `promiseLogSql` (`:167-172`) | `queryFace`, `execFace` | the conductor path in case 1 |

**projector: the board's reads do not use the promise store.** `readTasks` is `Effect.runPromise(readTasksEffect(options))` (`task-view.ts:1029-1031`), and the reads use `withStoreEffect` on the port (`projector/src/choose.ts`, at the end of the file). The board's **test** does hold the promise store, though:

- `apps/board/unit/waiting-card.test.tsx:104` and `:223` call `createSqliteProjectionStore(db)`, which is `promiseProjectionStore(makeSqliteProjections(db))` (`sqlite.ts:425-427`).
- `apps/board/test/visual-waiting.ts:398` does the same.

So every method face in `promiseProjectionStore` (`store-face.ts:130-148`) stays, along with `queryFace` and `createFace`/`reduceFace`. The `why` names `waiting-card.test.tsx:104` and `visual-waiting.ts:398`.

**`resetFace` is deleted.** No file under `apps/board` calls it. Its only caller is `packages/projector/test/contract.ts`, which moves to `Effect.runPromise(projection.reset(...))`.

**The runner faces have no host holder.**

- `promiseRunner` / `createProjectionRunner` (`projection.ts:357-376`) are called only from tests.
- `apps/board/unit/read-not-fold.test.ts:35` and `apps/cli/unit/one-writer.test.ts:50` only scan source text for the name.
- So all six `runner*Face` entries are deleted, and so is `projectionStore` (`projector/src/choose.ts:78`).
- `one-writer.test.ts:22` lists `'packages/projector/src/projection.ts': 'the definition of createProjectionRunner'`. That row goes, or the unit half goes red. Update the prose at `store.ts:27` as well.

## Moving the test callers: put a fixture under `test/`

Done blind, this is where the ticket goes wrong. Most callers of the deleted faces are **integration** files, for example:

- `createProjectionRunner`: about 10 sites in `projector/integration/projection.test.ts`, plus `task-view`, `backlog`, `follows-a-file`, `daemon/integration/reconcile` and `the-written-choice`, `conductor/integration/queue`, and `apps/cli/integration/ask`.
- `processEventStore`: 15 integration files.

Nothing in this pass runs those files. `tsc` is the only check on them before the merge.

So keep each rewrite mechanical:

- **`processEventStore()` → `eventStore`.** Replace `await processEventStore()` with the `eventStore` import (`index.ts:96`). It is the same process store behind a deferred view, and it is kept for the board anyway. The opening behaviour differs (first call rather than the `await`). Before relying on that in the files that also call `closeProcessLogEffect`, read the comment at `index.ts:80-95`.
- **Runner and `projectionStore`: add a test fixture.** Create `packages/projector/test/promise-runner.ts`: `promiseRunner(makeRunner(options, { detached: true }))` with each method as `Effect.runPromise(r.start())` and so on. Export it as `@lingtai/projector/test/promise-runner`, following `packages/event-store/package.json:8-10` (`./test-support`, `./test/postgres`). The integration files then change only an import line.
  - This is the ticket's *"`Effect.runPromise` inside the test"*: the run sits under `test/`, which the ratchet does not scan (`effect-ratchet.test.ts:463` counts only `<pkg>/src/`). It does not keep the face alive under another name, because no `src/` file imports it.
- **`closableOnce`, `execIdempotently`.** Their only callers outside their own file are `index.ts` and `event-store/unit/closable.test.ts` / `log-sql-effects.test.ts`. Delete them and move those unit tests to the Effect forms. Those tests *are* in the pass, so they are checked.

`packages/projector/test/contract.ts` takes its store from `make()` (`:238`). Leave that signature alone: `sqlite.test.ts` and `projection.test.ts` pass promise stores from `promiseProjectionStore`, which is kept. Only its `resetFace` and `createProjectionRunner` calls move.

## `checkFaces`

The refusal is at `effect-ratchet.test.ts:299`. Accept `"0101 §7"` when `why` matches a path `apps/(board|site)/…` and that path exists. The unit cases sit beside `:787-802`:

- accepted, with a `why` naming `apps/board/src/lib/board.ts`;
- refused, with a `why` naming only `packages/conductor/...`;
- refused, with an empty `why`;
- refused, with a `why` naming an `apps/board/...` path that does not exist.

## What is verified in the pass and what is not

| Check | Covers |
|---|---|
| `pnpm test` | every unit file edited (`closable`, `log-sql-effects`, `one-writer`, `runner-stop-waits`, `runner-reducer-dies`, `waiting-card` unedited) and `checkFaces` |
| `pnpm typecheck` | the only check on the integration files |

The claim that stands in for the integration half is that each integration diff changes only an import, or replaces `processEventStore()` with `eventStore` and nothing else. A reviewer can read that from the diff. Anything larger in an integration file is a finding.

## Edges

The ticket's list holds as written. One addition: a face kept only for `apps/board/unit/waiting-card.test.tsx` goes red in `checkFaces` if that test is ever deleted. That is the intended cost to later tickets.
