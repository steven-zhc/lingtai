# Design note: #1113, `add` and `add <owner>/<repo>` as Effects

Most of this ticket is mechanical: each `await` becomes a `yield*`, in the same order. This note covers what the ticket either miscounts or leaves to a choice.

## The ticket lists three runs in disguise; there are four

`add.ts:187` is `alreadyAdded(await runEffect(world.project.projects()), repo)`, the already-added refusal on the slug path. It becomes `yield* world.project.projects()`. Finding it is what makes `runEffect` (`first-project.ts:1325`; the ticket's `:1256` is stale) deletable. After the change, `grep -n "runEffect" apps/cli/src/add*.ts` must print nothing.

`addFlow` calls itself after a pick (`add.ts:240`, `return addFlow({ ...args, … github: picked } }, world)`). This becomes `return yield* addFlowEffect(…)`. Nothing is run at that point, so the recursion stays inside the command's fiber.

## Which ports become Effects

The rule: **a port whose live implementation is already an Effect returns an Effect. A port whose live implementation is still a promise function stays a promise port and is lifted at the call with `lift` (`exit.ts:16`).** Converting `checkInstallation`, `checkGhAccess` or `liveHistory` themselves is not this ticket.

| Port | Becomes | Why |
|---|---|---|
| `AddWorld.repositories.list` | Effect | Its face `liveRepositoryList` (`add.ts:419`) is deleted, so the world hands over the Effect behind it. `pickRepository` (`add.ts:88`) then yields it under `Effect.result`. Drop the `tryPromise` there. |
| `AskBeforeGithubAddDeps.picker` | `() => Effect<Picker, unknown>` | `livePicker` is deleted, and `livePickerEffect` (`first-project.ts:1301`) takes its place. |
| `…reader` | Effect | `liveGithubReader` becomes an Effect. |
| `…runtimes` | Effect | `askRuntimesEffect` (`packages/setup/src/runtimes.ts:35`) replaces `askRuntimes`, which is why that face's `why` drops add-github. |
| `doctor`, the setup end | Effect versions | `liveSetupDoctorEffect` and `printSetupEndEffect` (`setup-end.ts:24`, `:46`) replace the faces. |
| The `add` flow's own step | `chooseFirstProjectEffect` | `first-project.ts:391` replaces `chooseFirstProject`. |
| `check`, `ghAccess`, `history`, `files.read` | stay promise ports | Lifted with `lift`. |

Tests that inject `picker`, `reader` or `runtimes` as `async () => …` change only in shape: `Effect.succeed(…)`, `Effect.fail(…)` or `Effect.die(…)`. This applies to `add-github-gh.test.ts:43,54,59` and `add-github.test.ts:85,122,127,283,346,370`. No expected string moves.

## `defaultBranch` stays a promise thunk at `askRecipeEffect`'s door

`RecipeAt.defaultBranch` is `() => Promise<string | null>` (`recipe-flow.ts:78`), and `landing.ts:52`/`:204` and `first-project.ts:927` depend on that. Widening it would reach into code `init.ts` still drives, so leave it alone. Instead:

- `defaultBranchOf` becomes an Effect.
- The memo (`add-github.ts`, `cachedDefaultBranch`) becomes `const branch = yield* Effect.cached(…)`, with `ghDefaultBranch` short-circuiting it as today.
- `proposeSetup`'s `defaultBranch` gets `() => branch`.
- `askRecipeEffect` gets `() => run(branch)`, where `const run = Effect.runPromiseWith(yield* Effect.context())`. The ratchet does not count `*With` runs (`effect-ratchet.test.ts`'s `RUN = /^run[A-Z](?!\w*With$)/`), and CLAUDE.md names this form for exactly this. That keeps one request per run, which is the memo's whole reason (#402).

`askRecipe(world, …)` (`add-github.ts:392`) becomes `yield* askRecipeEffect(world, …)`. That deletes the `askRecipe` face: `recipe-flow.ts:202` is a face, and its `why` names only this caller. Run `grep -rn "askRecipe(" apps packages` before deleting.

## The catches

Each `try { … } catch` maps one-to-one onto the Effect with the same sentence:

- **`deps.auth()`** is synchronous and throws. Use `Effect.try` and print the same `…. Nothing was written` line.
- **`defaultBranchOf` and `liveGithubReader`** swallow *everything* today (a bare `catch {}` around `githubApp()`, which throws synchronously). Use `Effect.catchCause` returning `null` / `EMPTY_SETUP_READER`, guarded so an interrupt-only cause is re-raised (`Cause.hasInterruptsOnly` → `Effect.failCause(cause)`). A defect must land on the fallback, because `githubApp()` throwing is the ordinary no-App case.
- **The nested picker catch** (`add-github.ts:283-288`) follows the same pattern and falls back to `picked = null`.
- **`deps.check`'s outer catch** (`:297`) and **`deps.ghAccess`'s** (`:252`) read `(err as Error).message`. A defect's squashed cause must give the same `.message`: use `Cause.squash`, then the same `instanceof Error ? … : String(…)`.

`add.ts:287`'s read-back `try` (the `throw new Error(\`${path} is not there to read\`)` inside it) becomes an `Effect.gen` that fails with that error, caught by `catchCause` into the same `is registered, but its recipe could not be read back` sentence.

## The token

The trial's token becomes an Effect value, built with no `async` arrow:

```ts
lift(() => createGitHubClient({...})).pipe(Effect.flatMap((c) => lift(() => c.token())))
```

**Do not `Effect.cached` it, and do not resolve it before `liveTrialBuild`.** `git.ts:117-118` says it is resolved "per invocation … that is the whole point". An installation token expires in an hour, and an Effect description re-runs on every `gitEffect`.

In `gitEffect` (`packages/repo/src/git.ts:120`), test `Effect.isEffect(source)` *before* `typeof source === 'function'`, so the branch never depends on whether an Effect value is callable.

The unit case goes in `packages/repo/unit/`. Pass `{ token: Effect.fail(new Error('no installation')) }` and assert the failure is `RepoFailed` with `detail === 'no installation'` and `operation === 'git fetch'` (or whatever `args[0]` is). The token is resolved before `execFile` (`git.ts:126`), so the case spawns nothing and belongs in the unit half under 0060 §1.

## Faces

- **Deleted:** `livePicker`, `liveRepositoryList` and `askRecipe`, with their entries.
- **`why` rewritten:** `chooseFirstProject` (to `init.ts:649 … until CLI-22b`), `printSetupEnd`, `liveSetupDoctor` and `askRuntimes`.
- **`question`'s entry stays as is.** `add.ts:124/141` still hands it promise `validate`s, and changing them is outside this ticket.
- **Added:** none.

The baseline goes to `async 29` only if no `async` arrow is introduced anywhere, including in tests' shapes inside `src`. If the count comes out higher, the change is wrong, not the baseline.

## Not decidable here

The interruption path (a Ctrl+C reaching `addWithSetup` mid-registration now that it runs in the command's fiber) is reachable only with a real terminal. Nothing in the unit half exercises it. The claim that stands in for it is the guard above: every `catchCause` re-raises an interrupt-only cause. A reviewer checks that by reading each `catchCause` in the two files.
