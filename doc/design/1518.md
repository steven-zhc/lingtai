# #1518: shape of the change

## 1. The ticket contradicts itself on `@me`, and the decided rule wins

`## Done when` asks for `--assignee @me`. `## Edges` holds the later decision (2026-11-26): *"write the recipe's assignee login (`--assignee <login>`, `assignees=<login>`), never `@me`"*. Build the decision:

| rule (as `assigneeSkip` computes it) | gh line | form URL |
|---|---|---|
| `mine` with a login | `--assignee <login>` | `&assignees=<login>` |
| `mine` with no login (only possible in team mode) | `--assignee @me` | no form step; use the gh line |
| `all` | nothing | no `assignees=` |
| `unassigned` | nothing | no `assignees=` |

The four `next-steps` tests in Done when should assert the login, for example `--assignee steven-zhc`. `@me` appears only in the team-with-no-login case.

## 2. One function decides the rule

The CLI must not reinvent `discover.ts:325`:

```ts
const take = selection.mode === 'team' ? 'mine' : (rule?.take ?? 'all')
```

Write a pure `issueTakeOf(recipe): { take: AssigneeTake; login: string | null }` from `modeOf` (`packages/recipe/src/settings.ts:255`) and `assigneeOf` (`settings.ts:452`).

- Put it in `apps/cli/src/setup-card.ts` and export it.
- Add the result to `CardRecipe` as a new field, e.g. `takes`. Leave `team` alone: it is set in team mode only (`setup-card.ts:133-135`), and a solo `take: mine` has to reach `NEXT` too.
- Do not move it into `packages/recipe`, and do not make `discover.ts` call it. The queue's selection is out of scope.
- `whereAmI` (`init.ts:915-919`) already has the resolved `recipe` in hand, so it calls the same function beside `ticketSourceOf`/`kindsOf`.

## 3. `TicketSource` gets two fields, and `ticketStep` stays pure

In `next-steps.ts:11-18`:

```ts
takes: { take: 'all' | 'mine' | 'unassigned'; login: string | null } | null
forms: IssueForms   // { kind: 'none' } | { kind: 'one'; file: string; name: string } | { kind: 'several' }
```

`takes: null` means the recipe was unread, which today already means `tickets: null`. That makes the existing literal call sites in tests a type error rather than a silent default. Either fix them by adding `forms: { kind: 'none' }, takes: { take: 'all', login: null }`, or make both fields optional and treat absent as `none`/`all`. Prefer optional: the ticket says the existing `next-steps.test.ts` / `init.test.ts` cases "should stay as it is". Optional keeps them byte-identical, and they are all solo with no form.

`ticketStep` (`next-steps.ts:25-32`), GitHub branch:

- **Form step.** Only when `forms.kind !== 'none'` and the rule is not (`mine` with `login === null`).
  - `one`: `open <url>` where the URL is `https://github.com/<slug>/issues/new?template=<encodeURIComponent(file)>`, plus `&assignees=<login>` when the rule is `mine`. The `for:` words name the form, e.g. `its first ticket, from the "New joke" form`.
  - `several`: `open https://github.com/<slug>/issues/new/choose`. That page cannot preassign anyone, so when the rule is `mine` the `for:` words say `…, then assign it to <login>`.
- **Otherwise**, today's line plus the assignee flag from the table in §1.
- **Every command word goes through `shellWord`** (`next-steps.ts:21-23`). Its safe set has no `?` or `&`, so the URL comes out single-quoted. That is the point: an unquoted `&` backgrounds the command. A test should pin the quoted form.
- `open` is the only precedent (`next-steps.ts:51`). It is macOS-only, but it is already what this file prints, so do not add an `xdg-open` branch.

## 4. Reading the forms on GitHub (`add` / `init --github`)

Add a seam on `AddWorld` beside `labels?` (`add.ts:58-59`):

```ts
issueForms?: (owner, repo, reach) => Effect.Effect<IssueForms, never>
```

Build it next to the labels code, in `apps/cli/src/add-labels.ts` or a sibling file. Build the client the way `liveLabelClient` does (`add-labels.ts:54-62`). Call it from `drawGithubCard` after `ensureLabelsEffect` (`add.ts:441-444`) and put the result into `closing` at `add.ts:471`, together with `recipeCard.takes`.

**Do not use `client.fileAt` for the form's `name:`, though the ticket names it.** Its signature is `fileAt(path, ref)` and it always sends `?ref=` (`packages/github/src/client.ts:939-944`), so it would need a `defaultBranch()` call first: a third request. Use `client.request` instead (`client.ts:271-272`, *"Raw REST, for the calls that do not have a method yet"*):

1. `GET /repos/<o>/<r>/contents/.github/ISSUE_TEMPLATE` with no ref. GitHub answers this for the default branch.
2. Only when exactly one `.yml`/`.yaml` entry remains after dropping `config.yml`/`config.yaml`: `GET …/contents/.github/ISSUE_TEMPLATE/<file>`, decode its base64 `content`, and read `name` with `yaml`'s `parse`. `apps/cli/package.json:33` already depends on `yaml`.
   - A `name` that is missing or not a string falls back to `{ kind: 'none' }`, as the ticket's failure rule says.
   - Do not fall back to the filename.

Note that `request` is raw `send`, with no `catchIf(404)`. The whole seam ends in one catch-all that turns any failure (404, 403, a client that cannot be built, a parse error) into `{ kind: 'none' }`. Write it as an Effect (`Effect.gen`, `Effect.catchAll`), not as an `async` function. `packages/domain/unit/effect-ratchet.test.ts` counts `async` per package, and the baseline is never raised.

The seam builds a second client, which on an App machine means a second installation lookup. Accept that rather than widening the `labels` seam's return type. Keeping the two seams separate is what lets a test fail one and not the other.

## 5. Reading the forms from a checkout (`init` inside a registered checkout)

The same shape of answer, read from `<toplevel>/.github/ISSUE_TEMPLATE` through a new seam on `InitWorld` (`init.ts` ~`:187-212`). It should be shaped like the existing `exists`, which is *"over `node:fs`"*, so that the unit test in `init.test.ts` stays off the filesystem (0060 §1). It returns `IssueForms` and never fails: a directory that is missing or unreadable gives `{ kind: 'none' }`.

The parsing (keep `.yml`/`.yaml`, drop `config.*`, read `name`) should be one pure function both paths share, taking the listing and the single file's text. Unit-test that function directly, and keep the two seams thin.

`whereAmI` reads the forms only on the `registered` branch, after the recipe read. Its own `recovering` (`init.ts:920-925`) must not swallow a forms failure into `tickets = null`, so read the forms outside that block.
