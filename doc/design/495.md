## Design: #495, a runtime judge appends `RunSpent`

### Where it goes

Make one append in `askTheAgent`, `packages/conductor/src/conduct.ts:2185`. Put it directly after the `const spent = …` line (`:2265`) and before the `never-started` branch (`:2277`). At that point every way the process can come back has a `RunOutcome` in hand, and nothing has returned yet. Append to `runId`, the pass stream. That is the stream `PassRouted` lands on (`appendAt(runId, pass.routes…)`, `:3633`).

The ordering the ticket asks for, *before the route*, then holds without extra work. `PassRouted` is written only after the walk returns (`:3627-3652`), and `askTheAgent` runs inside the walk as the `judge` port (`:2340-2344`, `pass.ts:869`).

One append covers all three answers the ticket names:

- **Answered.** The `{ next: chose.next, … }` return at `:2310`.
- **Answered something the offer did not contain.** It is the same return. `askTheAgent` does not check the offer. The comment at `:2307` says *"Held to the offer by `judged` in `pass-steps.ts` and never here"*. So no second append site is needed in `pass-steps.ts`, and none should be added there.
- **Answered nothing.** This is the `held(...)` return on `outcome.failure` (`:2287`) and the `unreadable` return (`:2299`).
- **`never-started`** (`:2277`) also gets the append. `implement` already does this: `#493` put `runSpentFrom` in the same batch as `RunFailed` before the `never-started` check (`conduct.ts:3147-3152`). The runtime reported something, so record it.

### Two paths that append nothing

- **Settings refused** (`:2208-2210`). Nothing was dispatched, so nothing was spent.
- **The `.catch` at `:2243-2252`.** This catch makes up a `RunOutcome` (`turns: 0`, `costUsd: null`) when `dispatched.run` *throws*. A process did not return it. The ticket's line is *"whose process returned a `RunOutcome`"*. The domain schema also refuses invented numbers: `RunSpent`'s doc at `packages/domain/src/events.ts:704-706` says *"Neither field ever defaults to zero"*.
  - Skip the append on this path.
  - Do it with a local flag set inside the `.catch`, or by having the catch carry a marker. Don't compare `turns === 0`, because a real run can report zero turns.
  - The `why` text for this path stays as it is.

### Build the payload in one place

`runSpentFrom` (`conduct.ts:2942`) hard-codes `for: { _tag: 'Action', step: 'implement', … }`. Widen it to take the `for` value instead (`PayloadOf<'RunSpent'>['for']`, or `SpentFor` if `@lingtai/domain` exports it).

Move it above `askTheAgent`. It is declared about 750 lines later in the same closure, so moving it makes the dependency readable rather than relying on call order. Update its three existing call sites (`:3150`, `:3199`, `:3363`) to pass `{ _tag: 'Action', step: 'implement', name, round }`.

The judge's call is:

```ts
runSpentFrom(outcome, { _tag: 'Judge', when: on.when }, runtime)
```

- `runtime` is `dispatched.capabilities.id` (`:2201`), the runtime actually dispatched (`#314`), not `options.runtime`.
- `when` fits the schema: `SpentFor`'s `Judge` variant is `{ when: JudgeWhen }` (`events.ts:692`), and `on.when` is the arrival's direction.

Use this so the implement and judge appends cannot drift into two shapes. That is the reason the `runSpentFrom` doc gives for existing: *"so the two cannot write a different shape"*.

### Use `appendNow`, not `appendAt`-and-swallow

`PassRouted` swallows a refused append because it is written after the merge, where raising would *"release an item whose branch is already on `main`"* (`:3619-3625`). The judge append happens inside the walk, before anything has landed. That is the case `appendNow`'s doc covers (`:546-567`): the defect is remembered and the pass is raised into the defect handler, so the item is not left parked on *Waiting on you*. The `appendNow` doc also says *"Everything else uses `appendNow`"* (`:539`).

### What does not change

- **`PassRouted`'s schema**, and every `why` string in `askTheAgent`. Keep the `spent` string and its interpolation (`:2265`) exactly as they are. The new event is built from `outcome`, not from that string.
- **Built-in judges.** `judge` returns `declared` directly for `'built' in declared` (`:2343`). No path through it reaches the new code, so it needs no guard.

**The comments that become false.** Correct their wording, not the logic:

- `:2178-2183`: *"What it cost is in the sentence rather than on an event of its own … there is no `JudgeAsked` to fold"*.
- `:2201-2206`: *"A judge has no event of its own by decision"*.
- `:2261-2264`: *"This string is the whole record of a judgement"*.

The decision is still that there is no `JudgeAsked` event. What is no longer true is that the spend exists only as text. Under 0110 (*Consequences*), the decision stays on `PassRouted` and the spend is `RunSpent`. The test comment at `conduct-a-whole-pass.test.ts:1625` (*"because there is no event of its own"*) needs the same fix.

### The test

The `pass-steps.test.ts` judge cases (`:1617`, `:1662`, `:1695`) fake the `judge` port with a function, so they never reach `askTheAgent` and cannot see this append. The test belongs in `packages/conductor/unit/conduct-a-whole-pass.test.ts`. Its own doc at `:1532-1538` says it is *"the only test that can see"* whether the conductor really dispatches a runtime judge.

- **Answered.** Extend `'dispatches a runtime judge, with a session of its own each time it is asked'` (`:1552`). It asks the judge twice, so the run stream should carry exactly two `RunSpent` with `for: { _tag: 'Judge', when: 'findings' }`. `runtime` is the fake's id. `turns`, `durationMs` and `costUsd` are what `refusingRuntime.run` reported, and `usage` is `[]` where it reported none. The test should also show one `RunSpent` before each judge-chosen `PassRouted` in stream order. Keep the existing `why` assertions (`'5 turns'`, the judge's own words) unchanged, as the proof the sentence did not move.
- **Off the offer.** Add a case where the judge's text names a destination the arrival did not offer. It should give one `Judge` `RunSpent`, and the `PassRouted` should carry the refusal `judged` already writes.
- **Answered nothing.** Add a case for each of: the fake returning a `failure` (for example `{ kind: 'crash' }`), and returning text `chosenIn` cannot read. Each should give one `Judge` `RunSpent`, and the pass should hold at `proposed` as it does today.
- **Built-in.** In the `same-worktree` case just above (`:1497-1526`), assert there is no `RunSpent` with `for._tag === 'Judge'`.

`packages/conductor/unit/what-a-pass-writes-today.test.ts` lists event types row by row. If any of its fixtures declares a runtime judge, a new `RunSpent` row appears there too, and `pnpm test` will say so. Nothing in this design needs `pnpm test:integration`. Every claim above is checked in the unit half.
