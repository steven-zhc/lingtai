# Design note for #1278: one prose bound, cut instead of refused

## Where the cut lives

Add one helper to `packages/domain/src/triage.ts`, beside the bound. Both readers call it on the raw parsed JSON before their schema parse. It has two parts:

- `cut(text, max = TRIAGE_TEXT_MAX)` returns `text` unchanged when it fits. Otherwise it returns `text.slice(0, max - 1) + '…'`, so the result is exactly `max` long and passes `.max(max)`. If the slice ends on a high surrogate (`0xD800–0xDBFF`), drop that unit too, so the result is never half an emoji. zod's `.max` counts UTF-16 units, the same as `.length`.
- `cutProse(value: unknown): unknown` walks plain objects and arrays without mutating them. It replaces a string with `cut(string)` only when its key is in `PROSE_KEYS`. Everything else is copied as it is.

`PROSE_KEYS` is chosen **by key name, not by schema position**. Checked against every schema that uses `TRIAGE_TEXT_MAX` or `TRIAGE_SENTENCE_MAX`, each of these names means prose wherever it appears:

| key | where |
|---|---|
| `summary`, `want` | `wait.ts:1015-1016` |
| `why` | `WrongApproach` `wait.ts:937`, `TriageFailed` `:1011`, `ContradictingHunk` `triage.ts:128` |
| `what` | `LineFix` `wait.ts:924`, `SetupBroken` `:970` |
| `text` | a question's and an answer's, `triage.ts:58,60` |
| `spentOn`, `repair`, `addToBody` | `wait.ts:964,971,977` |

Everything not in the set is never cut. Those fields keep failing the parse when they are over the bound: `id`, `recommended`, `path`, `kind`, `covers`, `uncovered`, and split's `title` and `body`. `title` is a decision the ticket left open. It becomes an issue title, it is not in the ticket's prose list, and a 1200-character title is a broken plan, not a long sentence, so it stays a refusal. `body` keeps its own 4000 bound.

Write a comment on `PROSE_KEYS` saying that a new key named like one of these but holding an identifier must not be added to the set. Pin the set with a unit test (next section) so that adding a key is a decision someone makes on purpose.

**Rejected: a `z.preprocess` cut inside the field schemas.** It would put the list of prose fields in the schema itself, but it has two costs:
- `TRIAGE_ANSWER_JSON_SCHEMA` is generated by `z.toJSONSchema(TriageEnvelope)` (`wait.ts:1079`), and the bounds it carries are *"the bounds a runtime enforces"* (`triage-answer-schema.test.ts:2`). A preprocess changes the schema's input type and what that file emits.
- `RecordedCause` and `TriageAnswered` would also start cutting on every decode of a stored event. That would quietly hide a writer that records something over the bound, and the ticket puts the cut in the readers, not in decoding.

## The two readers

- **Judge.** In `causeIn` (`packages/conductor/src/judge-agent.ts:360`), cut right after `JSON.parse(candidate.trim())`: `value = cutProse(JSON.parse(...))`. It has to happen before `JudgeAnswer.safeParse` at `:374`. The same answer seen through two candidates (a fence, then the bare text) is cut the same way both times, so the `JSON.stringify(f.cause)` de-duplication at `:384` still collapses it to one answer. Rewrite the doc comment's *"Nothing is repaired"* (`:347`) to: prose over the bound is cut, and nothing else is repaired.
- **Triage.** In `packages/conductor/src/triage.ts`, cut `found` once, right after the candidate loop (`:396`), before the `TicketTooBig` child-kind mapping and before `TriageResult.safeParse({ ...found, _tag: 'TriageAnswered' })` at `:437`.
- **Existing `clip`s.** Replace both copies (`packages/conductor/src/triage.ts:346`, `apps/cli/src/triage.ts:528`) with imports of `cut`. They now end in `…`.

## The bound and the prompts

- Delete `TRIAGE_SENTENCE_MAX`. Set `TRIAGE_TEXT_MAX = 1200` and rewrite its doc comment (`triage.ts:41`). Every schema that used `TRIAGE_SENTENCE_MAX` (`wait.ts:937,1015,1016`) now uses `TRIAGE_TEXT_MAX`. Leave identifiers at `TRIAGE_TEXT_MAX` as well: the ticket asks for one bound, not a separate identifier bound.
- Rewrite the triage prompt paragraph at `triage.ts:99-102` and the `why` line at `:119`. The new text: every field is at most `${TRIAGE_TEXT_MAX}` characters; `summary`, `want` and `why` are still one sentence; prose over the bound is cut and an `id`, `path` or `recommended` over it is not read.
- Add the same sentence to the judge prompt at `judge-agent.ts:226`, interpolating the constant. Do not hard-code `1200`. #1275 edits the same block; keep this change to one added sentence so the two merge cleanly.

## Tests that change

These currently assert a refusal at the old bounds:

- `packages/conductor/unit/triage.test.ts:289`: the brief contains the bound. Switch it to `TRIAGE_TEXT_MAX`.
- `triage.test.ts:472` and `:531`: change both to *cut and answered*. At `:531`, add a sibling test with a `path` over the bound that is still refused.
- `packages/domain/unit/wait.test.ts:1055`: same change.
- `triage-answer-schema.test.ts:41` keeps passing as written.

New tests:

- A domain unit test for `cut`: length, the `…`, and the surrogate case.
- A test for `cutProse` that leaves `id`, `recommended` and `path` alone.
- The judge tests the ticket's *Done when* lists. Put them where `causeIn` is already tested (grep `causeIn(` under `packages/conductor/unit/`).

**Stored events:** the bounds only get looser, so every `WaitTriaged` and `ProposalRouted` on the log still decodes. Bump the reducer version only if `packages/domain/unit/reducers.test.ts` goes red and asks for it.

**Effect ratchet:** this work is pure functions with no IO. It adds no `async` function and no `Effect.run*`, so `effect-ratchet.baseline.json` must not change.

**Integration half:** nothing here depends on it. `pnpm test` covers both readers at the unit level, so the build gate checks every claim this note makes.
