## Design note for #631: the `event` section points at `doc/events.json`

### Where

Only `doc/reference.md` lines 22–49: the `## event — 71 types` heading, its *Recounted 2026-10-13* stamp, and the table. Leave the four prose blocks below the table as they are (*Every type has a Zod payload schema…*, **retired**, **transition**, **pending**, `startOnboarding` / `Hold all`). They explain things. They are not lists.

Optionally, `README.md:186` says *"57 event types"*. That is the same stale second answer, so drop the number in the same commit. Nothing else.

### The link

Write the link as a relative `[doc/events.json](events.json)`, not as `/docs/events/`. `resolveHref` turns it into the page on the site: `apps/site/src/lib/docs.ts:420-421`, *"The manifest is a file on GitHub and a page here (#630)"*, `if (rel === 'events.json' && isPublicSlug('events')) return '/docs/events/…'`. On GitHub it stays the file. An absolute `/docs/events/` would be a dead link in the repository. Also say where the manifest comes from: it is generated from the registry in `packages/domain/src/events.ts` by `packages/domain/scripts/events.ts`, and `packages/domain/unit/events-json.test.ts` checks it against the registry. That is why this section no longer carries a count.

Drop the count from the heading too, so it reads `## event`. A number there is the same second answer as the table. Nothing in the repository links to the old anchor (`git grep 'event--'` finds only the example in the comment at `apps/site/src/lib/docs.ts:461`, which you leave alone). The site builds the contents from the headings (`headingsOf`, `docs.ts:484`), so there is nothing else to update.

### The decision the ticket doesn't state: which explanations survive

The table is not just old, it is wrong. Comparing its type names with `doc/events.json` (64 entries):

- **18 names in the table are not in the registry:** `WorkItemBlocked`, `WorkItemUnblocked`, `StepRequested`, `StepPassed`, `StepFailed`, `StepNeverRan`, `StepDidNotFinish`, `StepAsked`, `StepWaived`, `ApprovalRequested`/`Granted`/`Revoked`, `RepairRequested`/`Declined`, `FixRequested`/`Applied`/`Declined`, `PassRestarted`.
- **11 types in the registry are missing from the table:** `WaitStarted`, `WaitResolved`, `TicketSplit`, `SplitStarted`, `SplitChildWritten`, `SplitLinkWritten`, `SplitFailed`, `RunSpent`, `StepEnded`, `MergeLaneWaited`, `ContinueRequested`.

So "keep the explanations" means: **keep an explanation whose subject is still in `doc/events.json`, and cut one whose subject is not.** Keeping prose about a deleted type would break the file's own preamble: *"This describes the code as it is… A reference that documents intent instead of behaviour is the defect"* (`doc/reference.md:15-18`).

Keep these, each as a short paragraph under the link, led by its type names and with its citations intact. Paragraphs, not a table: a table of group → types is the thing being removed.

- `RunRefsPublished` (0062 §1, `#251`, `#250`) and `RunKeptUncommitted` (`#468`), from the run row.
- The `Finding…` three and `finding_backlog` (`#137`).
- `PassRouted`: the `chose`/`to`/`ceiling` explanation, and *never named `Gate…`*, `#247`.
- `GitHubAppCreated`: the two fields and why (`#169`).
- The triage pair: `TriageStarted`/`WaitTriaged`, `by`, `RunSpent` (0118 §3, 0110 §10, `#414`).

Cut these, because every type they describe is gone:

- The step row's commentary: the `Gate…` → `Step…` rename and the three ways a step's agent ends, 0041/0057/0068 and `#296`. The step vocabulary is now `StepStarted`/`StepEnded`.
- The repair row and its claim *"`RETIRED` in the same file"*. That claim is false today: `RETIRED` is `['OutboxDelivered', 'OutboxFailed', 'TicketLinked']` (`packages/domain/src/events.ts:2244`).
- The fix row and the restart row.

The **retired** paragraph (`reference.md:54-58`) stays, with one addition: what makes a type retired is `RETIRED` at `events.ts:2244`, and the manifest marks each one `"retired": true`. The outbox row's 0022 citation can move into that paragraph. Do not list the three retired names: that would be a fresh hand-kept list.

### Tests

Nothing counts this table's rows, so there is nothing to move. The three unit tests that read `doc/reference.md` each read only their own section:

- `packages/conductor/unit/prompt-placeholders.test.ts:20-22` (`## prompt placeholder`)
- `packages/domain/unit/retired-names.test.ts:287-290` (`## retired name`, which ends at the next `\n## `)
- `packages/conductor/unit/step-matrix.test.ts:1285`, `:1325` (the gate-action and judge tables)

`events-json.test.ts` already checks the manifest against the registry. Do not add a test that counts `events.json`: that would be a third copy of the registry's size.

Check the change with `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test`. A section boundary that moved under `retired-names.test.ts` or `prompt-placeholders.test.ts` would show up there.
