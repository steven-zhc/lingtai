# Design: #462. `proposed` routes through `offerFor` → reply → `decideRoute` → `routeNext`

## Where it goes

The routing moves out of `proposed`'s body and into the loop in `runPass`. Today the body routes: `pass-steps.ts:1257` calls `judged` at `:882`. After this change, `runPass` (`pass.ts:1272`) routes, through one new module, `packages/conductor/src/proposed-route.ts`. Don't name it `route.ts`, because `@lingtai/domain` already has one. The module holds:

- `whenOf(proposal): JudgeWhen` — 0120 §2's mapping (`BuildRed`→`red`, `VerifyRed`→`verify-failed`, `MergeConflict`→`conflict`, `InputNeeded`→`needs-input`, both review variants→`findings`). It replaces `directionOf` (`pass-steps.ts:629`) for routing.
- `destinationOf(candidate, proposal): Destination` — `FixRound{to}`→`to`, `Requeued`→`claim`, `HandToPerson`→`waiting`. Unavailable ids map the same way: `fix-lines`→`implement`, `state-assumption`→`proposal.from`, `restart`→`claim`.
- `replyFor(offer, brief, judge)`: the effect. It is the only place a judge is asked (rules below).
- `routedVisit(offer, reply, decision)`: the adapter that turns the triple into today's `StepRouted` (`to`, `chose`, `why`). Through `take` and `RouteTaken` that becomes today's `PassRouted`, and the ceiling comes from `offer.unavailable` instead of from `ceilingFor` (`pass.ts:908`). Say in its comment that this is a phase-1 event-boundary adapter (0120 *Two phases*).

The judge port leaves `PassPorts` (`pass-steps.ts:523`) and becomes `PassOptions.judge?: (on: Judging) => Promise<Judged>`. `conduct.ts:2338` passes the same `judge` it builds today. If it is absent, every lookup answers `noJudge`, so tests that never declare a judge do not need to supply one.

## The loop

Keep `take` (`pass.ts:1335`), but drive it from the `PassNext` rather than from `route.to`:

| `routeNext` gives | the loop does |
|---|---|
| `FixRound{to, round}` | `recheck`/`lapStart` as today, `roundsSpent = round`, `at = to` |
| `Requeued{Restart}` | `rested = 'requeued'`, `stoppedAt = reported` (as today) |
| `WaitOnPerson{reason}` | `rested = 'waiting'`, `stoppedAt = reported`, **`waitOn = reason`** |

Every route still **records a `proposed` visit** in `steps`, with the adapter's `StepRouted` as its ending. It is built directly rather than through `runStep`, since there is no body to call any more. The reason this record matters: `sentBackTo` (`pass.ts:1681`) reads the last visit as the route, and that is how `Brief.again` reaches `conduct.ts`'s `fixRound`, which is what writes `FixRequested` (`conduct.ts:3240`). The visit emits nothing, because a router visit with no plugins emits nothing today either: in row 10a of `what-a-pass-writes-today.test.ts:703-723`, nothing sits between `StepFailed` and `PassRouted`. So it does not change the event list.

A `neverStarted` from the judge is not a `JudgeReply`. Record the `proposed` visit as `never-ran`, set `stoppedAt = {step: 'proposed', …}`, and do not route, which is exactly today's behaviour (`pass-steps.ts:924`).

Which `nextOf` answers route:

- **`Propose{proposal}`, whatever the visit's ending.** Delete the `ending.ending === 'passed'` walk-on at `pass.ts:1517-1525`; that branch was the way-through judgement. **Do not touch `endingOf` or `REFUSING_STEPS`.** `review` refuses at the `nextOf` level (`Propose{ReviewFindings|ReviewEmpty}`), and that is all 0120 §2 asks for. Its step ending staying `passed` keeps `step-matrix.test.ts` and every `StepFailed`/`StepPassed` where they are.
- **A body's `asked`** (`pass.ts:1478`, `:1497`). The shell builds `InputNeeded{from: at, question: ending.detail}` itself and routes that.

**Keep these old values on purpose**:
- For a proposal born at `review`, `reported` stays `null`, so `stoppedAt` stays `null` as it is today. `conduct.ts:3938`'s `judged` predicate (`stopped === null`) then still offers *merge it anyway*.
- `RouteTaken.from` stays `'proposed'`, so `PassRestarted.action` (`conduct.ts:3870`, `lastRoute?.from`) is unchanged.
- Every other proposal reports `{step: at, ending}` and `from: fromOf(proposal)`, as today.

**Two waits keep a `PassRouted` row without routing.** 0120 has no `Proposal` for either of them, and the fixture pins both rows. For each, push a fixed `RouteTaken` (`chose = to = 'waiting'`, `ceiling: null`), set `rested = 'waiting'`, and leave `waitOn` `null` so `holdOfPass` builds the hold exactly as it does today:

- **`MergeRefused`** (`pass.ts:1563`, row 10b). Its `why` is the sentence from `pass-steps.ts:1289`.
- **`AnswerUnreadable` at `review`** (`pass.ts:1550`, row 13b). It still walks on to `proposed`'s spine visit, because #467's fix (`f215adba`) is that a declared `human:` there must still run. The spine body now judges nothing, so the loop has to carry the pending reason across that visit. If the visit clears, stop with the fixed row, whose `why` is the *"could not be read at all"* sentence from `pass-steps.ts:906`. **If this is not done, an unreadable review walks on to `merge`.**

## The reply, in `judged`'s order

1. Build `offerFor(proposal, {rounds, restarts}, {rounds: roundsSpent, restarts: restartsSpent})`. `Ceilings` (`pass.ts:801`) becomes `{rounds, restarts, restartsSpent}`, filled at `conduct.ts:964` from `ceiling.restarts` and `folded.restarts.length`.
2. **If `available` holds only `hand-to-person`, the reply is `NotAsked`, and nothing is called, not even a built-in.** This is the rule the ticket's *Watch out* names, and it makes the `on.offering.length < 2` guard (`conduct.ts:2192`) dead. Delete it.
3. Otherwise build the brief:
   - `Judging{when: whenOf(p), offering: available.map(destinationOf), findings, evidence}`.
   - `findings`/`evidence` come from `whatArrived(reached)` (`pass-steps.ts:754`), off the visit that proposed. `ReviewFindings` carries no evidence text of its own.
   - Keep the four-key assertion in `pass-steps.test.ts`.
   - Ask `judge(brief)`. If the answer is `noJudge`, fall back to `BUILT_IN_FOR[when]` (`judge.ts:466`); where that is `null`, the reply is `NotAsked`.
4. **The built-in and the agent both answer a `Destination` and go through one translator.** The built-in `same-worktree` answers `'implement'`, and today's `MECHANICALLY.wants` (`pass-steps.ts:674`) becomes that. Translate a destination `d` like this:
   - an available candidate whose destination is `d` → `Selected{that id}`;
   - else an unavailable one whose destination is `d` → `Selected{that id}`, which `decideRoute` turns into `CandidateUnavailable`;
   - else `Selected{candidate: d}`, which becomes `UnknownCandidate`.

   This keeps the `needs-input`-at-`implement` cell routing to `implement`. Do not hard-code `fix-lines`.
5. `askTheAgent` gains one arm, `{unreadable: {named, raw}}`, for `chosenIn(...) === null`. That arm becomes `JudgeReply.Unreadable`. Its other `held(...)` answers (no settings, a crash) stay `next: 'waiting'`, which becomes `Selected{hand-to-person}` with that `why`. That is today's row.

`routedVisit` sets `chose` only from a reply. On `NotAsked`, `chose = to = 'waiting'` and `ceiling = null`, and the `why` names what was excluded and why (*`fix-lines` — rounds spent*), so the person still reads the spent ceiling. The consequence: the built-in red with rounds spent no longer writes `chose: implement, ceiling: rounds`, because no judge was asked. That follows from the ticket's own rule. It is unreachable in `once()` (fixture header, row 3), so pin it in `pass.test.ts` and name it in the commit body.

**Do not start writing `FixDeclined`.** Nothing writes it today; there are only readers, at `task-view.ts:661` and `history.ts:358`. 0120's appendix maps a decline to `Escalated{CandidateUnavailable}`, and writing a new event type would change the log's shape.

## Holds

- A route's `WaitOnPerson` sets `waitOn`, so `holdFor` (`conduct.ts:3643`) takes the `holdOf` branch: `ProposedEscalated` through `escalatedHold`, and `AgentQuestion` through `Asked`.
- In `holdOfPass`, step 1 (`hold-of.ts:104`, routed-with-direction) is now dead. Delete it, and with it `directionOf` if nothing else is left reading it.
- Step 4 (`:177`) is left serving only 13b's fixed row. Keep it.
- Hold **tags and discriminants must not move.** `why` text may: `escalatedHold` composes from `reasonTextOf`/the proposal instead of from the router's sentence.

## Delete

These go:

- In `pass.ts`: `onOffer` (`:971`), `Offer`, `NO_OFFER`, `PASSED_THROUGH`, `ceilingFor`, `arriveAtTheRouter` (`:1394`), and `StepWork.arriving`/`offering` (`:599`, `:620`). Without them, `runStep`'s plugin condition becomes "every visit that `runStep` runs".
- In `pass-steps.ts`: `judged`, `reviewRefused`, `carriesACriterion`, `MECHANICALLY`, `toAPerson`, `becauseSpent`. `proposed`'s body becomes `async () => ({ ending: 'passed' })`.

Grep for these names across `packages` and `apps`. `what-a-destination-costs.test.ts` is about `onOffer` and gets rewritten against `offerFor`/`replyFor` or deleted. `typecheck` covers the `integration/` files, so they must compile, but do not run them.

## Watch out

- **A refusing review now skips a `human:`/`watch:` declared at `proposed:`.** It arrives by `Propose` and never reaches the spine visit. That is 0120 §4 (*two ways to `proposed`*), and it is what every other arrival already does. Don't "fix" it by visiting the spine first.
- **`merge`→`build` is gone with `onOffer`.** A conflict offers `implement` or a person. Assert in a test that the brief for a `MergeConflict` offers exactly `['implement', 'waiting']`.
- Fixture rows 2, 4, 5, 7, 10a, 11 and 13 must keep their event arrays exactly. The judge-dispatch count is the one cell that changes: row 5's second pass dispatched no judge before either, and still dispatches none.

## Tests

All of these are unit-level. Use `conduct-a-whole-pass.test.ts`'s harness, and count dispatches by `runId.includes(':judge:')`:

- **`ReviewFindings` routed with restart on offer.** Row 4 already covers this. Add an assertion that the brief offered `claim`.
- **`ReviewEmpty`.** A reviewer refuses with no failure scenario, under `JUDGED_BY_AN_AGENT`. Assert zero `:judge:` dispatches and a hold of `Routed{findings}`.
- **Only `HandToPerson` available** (rounds and restarts at 0, an agent judge declared): zero dispatches. This is the *Done when* test.
- **`UnknownCandidate`.** The judge answers `{"next":"build"}`. Assert the hold, and that `PassRouted.chose === 'build'`.
- **`CandidateUnavailable`.** Restarts spent, rounds left, and the judge answers `claim`.
- **Empty `BuildRed`.** It can't be reached through `once()`, because only `run:` serves `build` and it spawns a process (#461's design, row 3). Prove it in `pass.test.ts` instead, with `watchingActions` making a canned `build` refusal with `evidence: ''`. Assert that the judge port was never called.

`pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover all of it. Nothing here needs the integration half.
