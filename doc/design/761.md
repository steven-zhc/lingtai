## Design: #761 — the agent and model questions are selects, and Space confirms

### 1. `offer` is a list to draw and nothing else

`accept` (`apps/cli/src/question.ts:95-100`) is unchanged and never reads `offer`. `question()` passes `choices: q.choices ?? q.offer` into the shape at `:118`, and `AskShape` stays as it is: to a front end, an offered list and a checked list look the same. Keep `offer` as `readonly string[]`, with the label equal to the value, the way `liveAsk` builds options today (`prompt.ts:75`). The scripted worlds answer by prompt string and ignore the shape (`apps/cli/unit/agents.test.ts:46-49`), so they still type text, and a typed answer that is not in `offer` must still be accepted. That is why `offer` is not checked, and it also keeps `--agent codex` reaching `refuseUnlessOffered` (`agents.ts:156-164`).

The writer and reviewer questions need only `offer`. Use `signedInIds` sorted into `RuntimeId.options` order for both, and add `'none'` to the reviewer's. Their defaults (`agents.ts:183-185`, `:237-238`) are already members of the list, so `initialValue` finds them. If it did not, `SelectPrompt` would silently put the cursor on the first row (`@clack/core/dist/index.mjs:923`: `o === -1 ? 0 : o`).

### 2. The model questions: two fixed strings and one helper

Both model questions (`agents.ts:200-210`, `:279-289`) have the same shape. Write one local `askModel(world, { name, flag, given, current, prompt, kept })` and call it from both places.

- **Two named constants**, exported for the tests:
  - `RUNTIME_DEFAULT = "the runtime's own default"`
  - `ANOTHER = 'another — type its name'`
- **The offer**: `[RUNTIME_DEFAULT, ...(current ? [current] : []), ANOTHER]`.
- **`fallback: RUNTIME_DEFAULT`**, not `''`. This is the Watch out's trap seen from the other side. The default has to be an offered value, or the select's cursor lands on whatever row is first. An empty answer also has to keep meaning "keep what is there": `acceptingDefaults` answers `''` (`question.ts:90`), `question()` turns that into `defaultValue` (`:121`), and `askModel` turns `RUNTIME_DEFAULT` into `''`. So `--defaults` still writes no `model:` when the recipe names none, and keeps the named model when it does. Pass `show` so the readline bracket stays readable.
- **Mapping applies only when no flag spoke.** If `given !== null`, return it as it is (today's path, `question.ts:106-109`), including `--model ''`. A flag that happens to spell `ANOTHER` is not a request for a second question.
- **After the answer**:
  - `RUNTIME_DEFAULT` → `''`.
  - `ANOTHER` → a second `question()` with prompt `'which model — its name'`, `given: null`, no `offer`, and `validate: a => a === '' ? 'a model needs a name — or choose the runtime\'s own default' : null`. Give it the same `name`, `flag` and `kept`, so a missing terminal there is refused under the model's own flag.
  - Anything else (the current model, or text a scripted world typed) → itself.
- **Prompt wording.** "(empty for the runtime's own default)" is wrong at a select. Change the prompts to `which model` and `on which model`. The `''` meaning stays in the flag strings at `:202` and `:281`. Two places quote the old words and must be edited:
  - `apps/cli/unit/first-project.test.ts:541-543` (an exact order list);
  - `agents.test.ts:468` (a `.includes('which model')`, which still matches).
- **Answer counts.** `RECIPE_FLOW_DEFAULTS` (`first-project.test.ts:172`) keeps its eleven entries. `''` reaches `RUNTIME_DEFAULT`, never `ANOTHER`, so no extra question is asked.

### 3. The hint: change clack's footer for the length of one select

The ticket's Fix says `showInstructions: false` with the hint in its place, but there is no such place. With instructions off, the select draws only `S_BAR_END` under the options (`@clack/prompts/dist/index.mjs:1141`), and `SelectOptions` has no footer field (`index.d.mts:95-105`). A muted second line in `message` would sit above the options and would stay in the transcript after the answer, because the submit state redraws `message` (`:1123-1128`).

What the library does expose is `SELECT_INSTRUCTIONS`, an exported mutable `string[]` (`index.d.mts:44`, `index.mjs:1079-1082`). The select reads it at every render (`:1141`, `formatInstructionFooter` at `:52-55`), and only while the prompt is open: the submit and cancel states never draw it.

So `liveAsk` leaves `showInstructions` at its default of true. Around the select:
1. Save the array's contents.
2. Overwrite it in place with one entry: `paint.muted('↑/↓ or j/k · space or enter')` (`packages/env/src/colour.ts:109`).
3. Restore the saved contents in the same `finally` that removes the Space listener.

`MULTISELECT_INSTRUCTIONS` is a separate array, so multiselects keep their own footer, as Out of scope requires.

**Watch out:** this depends on a library constant that a clack upgrade could rename. The test in §5 pins it by rendering a real select into a captured output: the hint must be present and `Enter: confirm` absent.

### 4. Space: one listener, added after the select starts

`SelectPrompt.prompt()` attaches its `keypress` listener synchronously, inside the Promise executor (`@clack/core/dist/index.mjs:247-265`). It submits only on `name === 'return'` (`:288`), and it does nothing with `space` because a select is not tracked (`_track` is false, `:922`) and `space` is not an alias (`:51-56`).

- Call `clack.select({...})` without awaiting it.
- Then add `onSpace = (_s, key) => { if (key?.name === 'space') input.emit('keypress', '\r', { name: 'return' }) }` to the same input.
- Then `await` the select, and remove the listener in `finally`.

Because clack's listener is registered first, clack has already ignored the space when ours re-emits `return`. If the order were reversed, clack would see the space after it had already closed, and would draw and close a second time (`:294-299`).

Tests need to replace the input and output, so give `liveAsk` an optional `io?: { input?: Readable; output?: Writable }` and pass it to `clack.select`. The listener goes on `io.input ?? process.stdin`. Clack itself defaults to `process.stdin`, so the default path is the same stream. Text prompts (`prompt.ts:78-82`) get no listener.

### 5. Tests (all in the `unit` project)

`prompt.test.ts`:
- Build a `PassThrough` input and a capturing `Writable` output, with `how` set to a TTY on both ends. Clack guards `setRawMode` on `isTTY` (`core :124-126`), so a non-TTY stream is fine.
- Start `liveAsk` on a three-choice shape and emit `('k', {name:'k'})` and then `(' ', {name:'space'})`.
- Assert it resolves to the row above the default.
- Assert the input's `keypress` listener count is back to where it started. That is the "Space is a space again" check.
- Assert the captured output contains `↑/↓ or j/k · space or enter` and not `Enter: confirm`.
- Assert `SELECT_INSTRUCTIONS` has its original contents again.

`agents.test.ts`:
- Use a world that records `shape.choices` and check that all four questions get a list.
- Answering `RUNTIME_DEFAULT` against a recipe that names a model writes no `model:`.
- Answering `ANOTHER`, then `opus`, writes `opus`.
- With codex signed out, `--agent codex` still gets `whyMissing` and not "is not one of".

### Edges this adds

- **Cancel inside the follow-up name question:** `liveAsk`'s existing cancel (`prompt.ts:83-86`) handles it.
- **Cancel at a select:** `process.exit(130)` runs inside the `try`, and `finally` does not run on `exit`. That is harmless because the process is ending, but put the listener removal and the array restore before the cancel check rather than relying only on `finally`.
- **`--defaults` on a recipe whose current model is one of the two fixed strings:** no handling needed; nobody names a model that.

The only check for any of this is `pnpm test`: nothing in `pnpm test:integration` reaches `liveAsk`.
