# #1094 — design note

The ticket's shape holds. There are four things it leaves out, and each would cost a fix round if the agent found it during the work.

## 1. `World.conducting` becomes an Effect port too, although the ticket does not list it

`liveWorld` builds `conducting` straight from `Live.holder`:

    conducting: () => outside.holder(),          // world.ts:106

Once `Live.holder` returns an Effect, there are two ways to keep `conducting` a promise. One is an `Effect.runPromise`, which raises `run` above 6 and is ruled out. The other is to keep a promise copy of `holder` in `Live`, which is the dodge in another shape. So `install.ts:132`'s `conducting: () => Promise<string | null>` becomes `() => Effect.Effect<string | null, unknown>`.

`uninstall`'s read at `install.ts:632` changes in one place:

    settle(lift(() => world.conducting()))   →   settle(world.conducting())

The error type stays `unknown`, because `lift` keeps the thrown value as it was (`exit.ts:16`). `settle`'s `Cause.squash` (`install.ts:355-362`) therefore hands the refusal at `:633` the same `Error` it gets today. The ticket's Want counts 10 `async`, and this adds none: `conducting` is an arrow with no `async`.

## 2. `keepAskedLoop` stops using `Effect.ignore`, or a dead store ends the re-asking without a word

Today each round's errors are caught by `Effect.tryPromise(standing)` and `Effect.tryPromise(ask)`, then dropped by `Effect.ignore` (`upgrade-drain.ts:53-56`). That works because a promise rejection always arrives as a failure. The ports this ticket moves to send a store failure as a defect instead (0101 §6). The `inFlightEffect` comment says this outright: *"The projector's store failures are defects"* (`packages/daemon/src/control.ts:460`).

`Effect.ignore` does not see a defect, so one failed read would kill the forked fiber. Under `forkScoped`, a child that dies does not fail its parent: the drain would carry on waiting while nothing asked again. That is the failure the comment at `upgrade-drain.ts:126-127` exists to prevent: *"a drain nobody is obeying is waited on for ever: so it is asked again whenever none stands."*

**Decision:** replace `Effect.ignore` with `Effect.catchCause` that lets interrupt-only causes through and answers `Effect.void` for anything else. Use the same shape as `inFlightEffect` (`control.ts:461-463`). This is the ticket's rule that *a failure recovered today stays recovered*, applied inside the loop.

`keepAskedLoop`'s parameters become `standing: Effect.Effect<unknown, unknown>` and `ask: Effect.Effect<unknown, unknown>`. They are no longer thunks.

## 3. The Effects to yield, and the one the ticket names by mistake

Inside `drainWithTheLog` (`world.ts:281-309`), each port becomes the Effect form of the call it makes today:

| Port | Today | Becomes |
|---|---|---|
| `control` | `daemon.readControl()` | `readControlEffect()` (`control.ts:117`, `Effect<ControlState, unknown>`) |
| `request` | `requestShutdownUnlessStanding` | `requestShutdownUnlessStandingEffect(who, why)` (`control.ts:270`) |
| `inFlight` | `daemon.inFlight().catch(() => [])` | `inFlightEffect()` mapped through `describeInFlight`; the `.catch` is already inside it (`control.ts:461`) |
| `doctor` | `doctorReport()` | `doctorReportEffect()` (`doctor.ts:3556`, `Effect<DoctorReport>`); a defect goes to the runner's handler, as a rejection does today |
| `holder` | `daemon.conductorLockHolder()` | `lift(() => daemon.conductorLockHolder())`; `lock.ts:88` is still a promise and out of scope |
| `wait` | `waitForTheLock(…)` | `lift(() => waitForTheLock(…))` until CLI-08a |

**`controlWatermarkEffect` is named in the ticket's Fix but nothing here calls it.** `rg controlWatermark apps/cli/src` finds only `restart.ts:70,737` and `daemon.ts:23,96`. Do not bring it in. `readControlEffect` is the Effect these two files actually need.

The `drainWithTheLog` comment at `world.ts:302-304` needs to change, because the forms it describes are going away. The doc comment on `doctorReport`'s face also names `world.ts` among the files that still await it (`doctor.ts:3570`): *"The face of `doctorReportEffect` for `world.ts`, `restart.ts` and `setup-end.ts`, which still await it."* Remove `world.ts` from that sentence.

## 4. `askConfirm`'s refusal is caught on the failure channel, which is the same set of errors as today

In `liveWorld.ask` (`world.ts:88-99`), `lift(() => askConfirm(…))` puts every rejection in `E`, so filtering for `PromptRefused` in the failure channel catches exactly what the `try/catch` catches now:

- On `PromptRefused`: log the same line and answer `false`.
- On anything else: `Effect.fail(err)` with the original value, so the message printed is the one `askConfirm` threw.

## Cleanup and `after`

`drainForUpgrade` is `Effect.scoped(Effect.gen(…))`. The watcher is `yield* Effect.forkScoped(keepAskedLoop(…))`, so the `try/finally` and `keepAsked`'s `{ stop }` go away.

Delete `keepAsked`. Its only callers are `world.ts:288` (through `drainForUpgrade`) and `unit/upgrade-drain.test.ts`.

Closing the scope interrupts the loop and waits for the uninterruptible round in flight to finish. That matches `upgrade-drain.ts:136` (*"Joined, not abandoned"*). Keep that comment where the scope closes.

`NOTHING_AFTER` (`upgrade-drain.ts:78`) and the early return at `world.ts:269` become `{ ok: true, after: Effect.void }`. Make `after` a value, not a thunk: an Effect is already lazy, and `install.ts:540` becomes `yield* drained.after`.

## What stands in for the integration half

`integration/world.test.ts` runs only after the merge. Before the merge, these unit tests carry the claims:

- **Error survives the lift.** Give a fake `Live` a `holder` of `lift(() => Promise.reject(new Error('getaddrinfo ENOTFOUND')))`. Both `liveDrain(…, fake)` and `liveWorld(self, fake).conducting()` must fail with that same `Error` instance, not an `UnknownError`. This is the Done-when line about the message.
- **Re-asking survives a defect.** Give `drainForUpgrade` a `control` that dies once with `Effect.die(new Error('store gone'))` and then answers `{ shutdown: null }`. It must still call `request` again during the wait. This pins item 2.
- **Existing tests.** The four existing cases in `unit/upgrade-drain.test.ts` change only their fakes: Effect ports, `Effect.runPromise(drainForUpgrade(…))`, and `drained.after` yielded. That includes the 130 case at `:36-40` and *"the next lingtai start ends it"* at `:48`.
