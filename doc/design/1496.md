# #1496: the shape of the change

Three of the four places only need new words. The foot line is the one that needs a real change: `footLine` returns one joined string today, and that string has to be split so the draft part can be a link.

## The foot line: return the parts, let the page join them

`footLine` (`apps/board/src/lib/where-landed.ts:53-67`) returns `{ kind: 'line', text }`. The text is the draft part and the open PR's state, joined with `' · '` (`:63-66`). `LandedFoot` (`apps/board/src/app/page.tsx:637-645`) prints `foot.text` as plain text, followed by the one `PRs →` link.

Change the `line` variant to carry the two parts separately:

```ts
{ readonly kind: 'line'; readonly draft: number | null; readonly open: string | null }
```

- `draft` is `read.draft.length`, or `null` when it is 0.
- `open` is the string `:60-62` builds today, unchanged.
- The function still returns `null` when both are null, and still returns `{ kind: 'unread' }` for a failed read or a failed draft read (`:57`). That keeps the rule from `prs.ts:468` (*"never an empty list: the page then says it could not be read"*).

`footLine` stays free of React and hrefs, because `where-landed.ts` is a `lib/` function its unit test compares with `toEqual` (`apps/board/unit/where-landed.test.ts:51`). The words `in Draft PR` and the link belong to `LandedFoot`.

`LandedFoot` renders:

1. `<Link href={`/pr/${encodeURIComponent(project)}/next`}>{draft} in Draft PR</Link>` when `draft !== null`.
2. A literal ` · ` when both parts are present.
3. `open` as plain text.
4. `PRs →` as today.

Build the href the way `page.tsx:641` already does, with `encodeURIComponent`, not the way `task.ts:1030` does (`pageOf` interpolates the project raw).

Do **not** give the new link the `lfoot-link` class. `globals.css:957` sets `.lfoot-link { margin-left: auto; … }`, which is what pushes `PRs →` to the right edge. On the draft link it would push the draft part right as well. Either leave the link without a class or add one beside `.lfoot` that sets no margin.

Keep the separator and the words as text nodes inside the same `div`. Then the existing `toContain('2 … · PR #88 in review')` tests break for the right reason only: the `<a>` now sits inside the string. Rewrite those assertions as regexes over the markup, for example ``/<a[^>]*href="\/pr\/lingtai\/next"[^>]*>2 in Draft PR<\/a> · PR #88 in review/``. That way they pin the link and the order together.

## The other three: words only

- `pr-board.ts:583`: `` `${plural(...)} in Draft PR` ``. The branches above it at `:577-582` are not touched. The final `else` is also reached with `draftTickets.length === 0` and no open PR, and today that reads `0 tickets not in a PR yet`. After the change it reads `0 tickets in Draft PR`. That is the same branch with the new noun, and the ticket says zero is unchanged, so keep it.
- `pr-branches.ts:183`: replace only the noun phrase, and keep the `· +N more` suffix.
- `task.ts:1108`: `'Draft PR · not submitted yet'`, with `page: pageOf('next')` kept. The `'no PR or draft holds it'` case just above it (`:1097`) is a different case; leave it alone.

## Tests: one is a negative assertion and needs a new target

`where-on-branch.test.tsx:151` is titled *"never says not in a PR yet for a read that failed"*. Its body checks `in.failed` and `/could not be read/`. Once the words change, a negative check for the old phrase would pass without testing anything. So rename it to say *Draft PR*, and add `expect(w?.in.text).not.toMatch(/Draft PR/)` inside the loop. That is what holds the `prs.ts:468` rule against the new words.

Also rename the test at `:36` (*"reads the draft as not in a PR yet"*) and change the matchers at `:39`, `:87`, `:116` and `:184` to `/Draft PR · not submitted yet/`.

## The two new foot-line unit tests

Put both in `landed-where.test.tsx`, rendering `LandedFoot`:

- **Draft only**, with `prs: []`: the markup contains the `/pr/lingtai/next` anchor around `2 in Draft PR`, contains no ` · `, and still has `PRs →` linking to `/pr/lingtai`.
- **Draft beside an open PR**: the fixture `team` (`:33-37`) already is this case. Assert the anchor, the order, and that `PR #88 in review` is not inside any `<a>`.

In `where-landed.test.ts`, add one object case for one ticket, `{ draft: 1, open: null }`, next to the rewritten `:51`. The `:54-56` cases (null and unread) stay as they are.

## Not affected

None of this touches IO, Effects or the log, so the ratchet and the integration half are not involved. The unit tests above are the whole check.
