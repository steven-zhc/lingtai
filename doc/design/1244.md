# #1244 — design note

The ticket covers most of the shape. This note adds three things: what tells a row written before #1243 apart from one written after it, the brief sentence the ticket does not specify, and the tests that will fail when the event is retired.

## 1. `rerunHeadOf`: old rows and new rows differ by `armSha`

Since #1243 the publish never writes `armSha`. Every `noteRefs` call in `publishWhatIsCommitted` passes four arguments or fewer: `'published'` (`conduct.ts:2862`), `'already-published'` (`:2769`), `'arm-only'` (`:2841`) and `'refused'` (`:2852`). The parameter is still declared (`conduct.ts:2417`), but nothing fills it. On a new row the WIP is the branch head itself. `RunRefsPublished.headSha` is the WIP commit, and `RunKeptUncommitted.ref` is `branch` (`noteAllKept(ref)`, `conduct.ts:~2650`). So:

- A new row is never a `WipHead`. `savedHeadOf` returns `WipHead` only when `saved.armSha != null` (`attempt.ts:~791`).
- An old row whose WIP sits on an arm has `armSha` set to something other than `headSha`.

That makes `published.armSha != null && published.armSha !== head.head` a safe test for an old row. Rewrite `rerunHeadOf` (`packages/domain/src/attempt.ts:820`) like this:

- **`Saved`:** if the test above holds, return `{ cannot }`. Do this whether or not a `kept` record exists. Today a recorded one is carried (`attempt.ts:826`) and an unrecorded one is refused (`:829`); both are now refused with one sentence. Otherwise return `{ at: head.head, atRef: head.ref }`.
- **`WipHead`:** always return `{ cannot }`, whatever `recorded` says. Leave the `recorded` field on `SavedHead`, because the grant and the board still read `savedHeadOf`.
- **The sentence:** use the ticket's wording in both cases: `the saved work <sha7> is a WIP on <arm>, kept before WIP was committed to the branch; start a new attempt`. It will be read inside `resolve-wait.ts:372`'s `Run … has no saved head a rerun can continue: ${head.cannot}. Requeue for a fresh attempt.` and the same template in `saved-fix-work.ts:52`. So it should not end with a period of its own, and it should not repeat "requeue".
- **`NoSavedHead`:** keep its `armSha` branch (`attempt.ts:~843`). That row also predates #1243 and is unchanged.

Remove `carry` from `RerunHead` and from `ReleasedHead` (`attempts.ts:701-709`, where the base fallback builds `carry: null`).

In `packages/domain/unit/rerun-head.test.ts`, the cases at `:29`, `:35` and `:50` assert `carry`. Rewrite them. Add the case the ticket asks for: a new row with `published({ armSha: undefined, headSha: WIP })` and `kept` set to `[{ sha: WIP, ref: 'agent/7', parentSha: PARENT }]` should return `{ at: WIP, atRef: 'agent/7' }`.

## 2. What `cut` loses, and what it keeps

In `conduct.ts`, delete:

- the import at `:264`;
- `savedWorkNotRestored` at `:1307` and its read at `:2702`;
- `carriedWork` and `claimedBrief` at `:1656-1669`, replacing the three `claimedBrief()` reads (`:4823`, `:4856`, `:4889`) with `next`;
- the whole `keptWip` block at `:3237-3306`;
- the wrapper around `keptRun.clean` at `:4440-4451`, which goes back to plain `clean`.

The code above the carry stays as it is. A `releasedHead` that is `cannot` still sets `headGone` and returns `notCut` (`:3192-3194`), so an old `WipHead` continuation now reaches the existing restart-or-hold ending at `:5964` and is never cut on the clean parent. That ending is the ticket's "Watch out", already built. Check that the continuation test asserts it lands there.

`carry-wip-port.ts` contains no `async` and no `Effect.run*`, so `effect-ratchet.baseline.json` does not move.

## 3. The brief: one sentence replaces `keptWorkLines`

Delete `CarriedBrief`, `keptWorkLines` and `attemptBrief`'s fourth parameter (`attempts.ts:393-440`), and `carried?` in `prompt.ts:31` and `:117`. That leaves the two kept paragraphs (`attempts.ts:~493` and `:~513`) with nothing after them that says where the edits are. Today, the board's preview shows *"The conductor applies those edits to this worktree before you start"*.

**Decision:** put `'Your worktree is cut fresh from the base, so those edits are not in it.'` in place of each `...keptWorkLines(...)`. This follows the existing `produced` paragraph (`:~506`). It is a fact about the worktree and adds nothing to 0072 §5's offer: the arms paragraph already says how to read a named ref. Do not add instructions for fetching the WIP, and do not say why the old approach was wrong. That belongs to the cause and protocol tickets.

In `unit/attempts.test.ts:516-560`, the `keptBrief(carried)` tests go. Replace them with one test that a kept WIP's brief contains the new sentence and does not contain `applies those edits`, `git apply` or `checkout`.

## 4. Retiring the event pulls in two tests besides `RETIRED`

- `EVENT_AT.RunAppliedKeptWork` becomes `[]` (`events.ts:2804`). `domain/unit/event-at.test.ts:8` requires an empty list **if and only if** the type is in `RETIRED`.
- The `@summary` on `RunAppliedKeptWork` (`events.ts:~935`) must start with `No longer written:`, as `StepRerunInPlace`'s does at `:1677`. `domain/unit/events-json.test.ts:142` checks this. Then run `pnpm events:generate`, which also runs `oxfmt`. The same file's *events.json is current* test fails until you do.
- Keep the schema, the `EVENTS` entry, the stream prefix in `scripts/events.ts:381`, and the board renderer at `apps/board/src/lib/history.ts:375` along with its pin at `history.test.ts:147`. Those are the readers.
- For *store.append refuses it*, follow the existing case at `conductor/unit/recorded-recipe.test.ts:157`, which asserts `RETIRED.has(...)` and an append refused against `createMemoryEventStore()`.

## 5. The "new attempt cuts clean" test

Put it beside the #1243 tests in `packages/conductor/unit/conduct-what-a-claim-leaves.test.ts`. They already build a previous run whose `RunKeptUncommitted` sits on `agent/<n>`. For the next claim, assert three things:

- the fake `repo.provision` received no `at`;
- no `git fetch origin refs/heads/<arm>` reached `repo.git`;
- the stream holds no `RunAppliedKeptWork`, and the recorded prompt does not contain `applies those edits`.

All of it is unit level. Nothing here needs `pnpm test:integration`.
