# #1275 — the questions are a field on `Judging`, not something swapped into its evidence

## Where the code is today (not where the ticket's line numbers say)

#1250 left a partial fix. The ticket cites `proposed-route.ts:176-181`, but `replyFor` now builds `Judging` at `packages/conductor/src/proposed-route.ts:186-196`. There, an `InputNeeded` proposal with questions **replaces** the evidence:

```ts
// An `Unclear` implement's judge reads the questions themselves — text, answers and the
// recommended one — never prose clipped by whoever dispatched it (#1250).
evidence:
  offer.proposal._tag === 'InputNeeded' && offer.proposal.questions.length > 0
    ? askedText({ questions: offer.proposal.questions })
    : arrived.evidence,
```

This causes two faults, and the change fixes both:

1. **Long questions get cut.** `askedText`'s output is passed through `on.evidence.slice(0, 8_000)` in `judgePrompt` (`judge-agent.ts:91`) and `judgePromptParts` (`:103`). That is the ticket's bug.
2. **The recorded prompt is wrong in two ways.** The rendered questions sit in the `onStep: { field: 'evidence' }` part (`judge-agent.ts:108`).
   - `withStepRef` (`record-prompt.ts:31-51`) looks for a `StepEnded` whose evidence equals that text. None ever does, so the part falls back to plain text. The record silently loses its reference.
   - The agent's prose is dropped from the judge's prompt completely. The ticket says *"Only the prose stays clipped"*, so the prose must still be there.

## The shape

**`Judging` gets `readonly questions: readonly TriageQuestion[]`.** The field is always present. Every proposal except an `InputNeeded` with questions gets `[]`. Make it required, not optional:

- The brief's key set is pinned on purpose. `attempt-steps.ts:380-384` says: *"`Object.keys` of the brief is exactly `evidence`, `findings`, `offering`, `when`. A field added to `Judging` fails there by name, which is the whole reason that assertion is a key set rather than a spot check."*
- Add `'questions'` to both assertions: `unit/attempt-steps.test.ts:1660` and `:1794`.
- Update the doc comment's list of keys at `attempt-steps.ts:380-384`.
- `Arrival` is `Omit<Judging, 'offering'> & …` (`attempt-steps.ts:372`), so it gains the field too. Every place that builds an `Arrival` or a `Judging` then fails `tsc` until it supplies the field. That failure is the point. Fill those places with `[]`. Only `replyFor` fills real questions.
- `TriageQuestion` comes from `@lingtai/domain` (`packages/domain/src/triage.ts:55-68`). `proposed-route.ts:21` already imports `askedText` from there.

**`replyFor` goes back to `evidence: arrived.evidence`.** It sets `questions` to `offer.proposal.questions` when `offer.proposal._tag === 'InputNeeded'`, and `[]` otherwise. Keep the #1250 comment, but move it to the `questions` line. With `evidence` back to `arrived.evidence`, the `onStep` reference can match the `StepEnded` again. This is the ticket's *Watch out* made true, not only kept.

**Rendering goes in `judgeText` (`judge-agent.ts:231`), as its own section, never inside the evidence slot.**
- The section is present only when `on.questions.length > 0`. Use `askedText({ questions: on.questions })`.
- Guard on the length yourself. `askedText` with no questions returns `said ?? ''` (`triage.ts:91`), and an empty heading is a change to every other prompt. The ticket's first edge requires that prompt to be unchanged.
- Put the section after `## What refused, and why` and before the destinations, under a heading such as `## The questions the implementer asked`.
- `needs-input` uses `REFUSED_ROW` (`judge-agent.ts:169`), so the row's `arrived` text is unchanged. It still shows the prose clipped, inside its fence.
- `causeText` (the `findings` direction) never receives questions, because only an `InputNeeded` proposal carries them. There is nothing to add there.

Because `judgePromptParts` splits `judgeText(on, EVIDENCE_SLOT)` on the slot (`:105`), the questions end up in `pieces[0]` or `pieces[1]` as plain strings. The evidence part keeps its `onStep` reference. Two existing fallbacks still work:
- An empty evidence returns `[judgePrompt(on)]` (`:104`), which now includes the questions.
- A NUL inside a question gives more than two pieces and falls back to one string (`:107`).

**The 8,000 cut stays, and it is not extended to the questions.** The questions are already bounded at the source: at most five of them, at most four answers each, and every text at most `TRIAGE_TEXT_MAX = 500` characters (`triage.ts:42`, `:55-62`). That is roughly 12.5k characters at worst, a known size, so no second cap is needed. Do not add one, or the ticket returns with a new number.

## The prose will often contain the questions too

The implementer's prose usually includes its own `question` fence, so the judge may see the questions twice: raw (and possibly clipped) in the evidence, and whole in the new section. Leave it that way. Removing the fence from the prose would change the text away from what `StepEnded` stored, which breaks the reference again.

## Tests (`pnpm test`; no integration test reaches this)

- Extend `unit/needs-input-judge-sees-questions.test.ts`. It already builds an `InputNeeded` proposal and calls `replyFor`. Its current assertions pass only because of the substitution, so they still hold under the new shape. Add the ticket's case:
  - five questions, four answers each, each text close to 500 characters, so the render is over 8,000;
  - assert that the last question's text and its `(recommended)` answer appear in `judgePrompt(on)` and in `judgePromptParts(on)` joined (`typeof p === 'string' ? p : p.text`).
- Add two more assertions:
  - `on.evidence` is exactly the prose that was passed in. This pins the end of the substitution.
  - In the parts, the `onStep` part's `text` is the prose sliced to 8,000, with no question text in it.
- Add one `[]` case: a `judgePrompt` for a non-`InputNeeded` brief does not contain the new heading.

Nothing here touches IO, so `effect-ratchet.baseline.json` should not move. If it does, the change is wrong. This needs no new ADR.

## What would settle it on the log

`RunPrompted` for the judge's call (written by `record-prompt.ts`). After the change, its evidence part carries a `StepValue` ref to the implement step's `StepEnded` and not plain text, and the question section is in the text around it.
