# #883: design note

## Where it goes

Two source files and one test file: `apps/board/src/lib/telemetry.ts`, `apps/board/src/lib/timing.ts` and `apps/board/unit/telemetry.test.ts`. Nothing else in the board changes. `installTracing` keeps building `new OnlyScope(SCOPE, …)` the same way (`telemetry.ts:68`).

## `OnlyScope.onEnd`: three branches, in this order

1. **The board's own scope** (`span.instrumentationScope.name === this.scope`, today's test at `telemetry.ts:34`). Forward the span itself, exactly as today. If its name starts with `page `, also remember `span.spanContext().traceId`. Match on the name, not the scope alone: a `timed` read ends before its page span, and remembering a read's trace adds nothing.
2. **Next's request span.** The scope name is `next.js` (Next's tracer is `trace.getTracer('next.js', '0.0.1')`, `next/dist/server/lib/trace/tracer.js:106`), **and** `span.attributes['next.span_type'] === 'BaseServer.handleRequest'`, **and** the trace id is remembered. Forget the id, then forward `requestCopy(span)`. `next.span_type` sits on the span's own attributes because Next spreads it into `options.attributes` (`tracer.js:212-216`).
3. **Anything else** is dropped, as today.

There is no work in `onStart`. The order of the `onEnd` calls is enough: the page span ends inside `handleRequestImpl`, and the request span ends in that call's `.finally` (`base-server.js:505`).

## The remembered set

Use a `Set<string>`, which iterates in insertion order. On adding an id:
- If the id is already there, do nothing. A page plus a deferred `measure` in one trace is two adds of one id.
- If the add takes the set past the limit, delete the first value (`set.values().next().value`).

The constructor gets a third parameter, `limit = 1000`. Expose `get remembered(): number` so the test asserts the size without reaching into the instance. That getter is the whole test surface; do not export the set itself.

## The copy

Write `requestCopy` as a module-level function returning a plain object literal typed `ReadableSpan`. The interface is `@opentelemetry/sdk-trace`'s, re-exported by the `sdk-trace-base` 2.12.0 already imported at `telemetry.ts:3`. Its fields: `name`, `kind`, `spanContext()`, `parentSpanContext?`, `startTime`, `endTime`, `status`, `attributes`, `links`, `events`, `duration`, `ended`, `resource`, `instrumentationScope`, and three `dropped*Count`s.

- **Carried over:** `name`, `kind`, `startTime`, `endTime`, `duration`, `ended`, `resource`, `instrumentationScope`.
- **Attributes:** only `next.route`, `http.method`, `http.status_code` and `next.rsc`, each copied only when present. This drops `http.target` (the path with the id, `base-server.js:502`), `http.route`, `next.span_name`, `next.span_type`, `next.span_category` and `error.type` (`base-server.js:518`, `tracer.js:79`).
- **Fixed values:** `events: []`, `links: []`, `status: { code: span.status.code }`, all three dropped counts `0`. The original's `droppedEventsCount` describes events the copy does not have.
- **Span contexts: a decision the ticket does not spell out.** `spanContext` returns `{ traceId, spanId, traceFlags }` from the original, with **no `traceState`**. `parentSpanContext` is built the same way when present, with no `traceState`. The reason: Next starts the request span under `withPropagatedContext(req.headers, …)` (`base-server.js:491`). An incoming `traceparent`/`tracestate` header would therefore put a caller-chosen string on the exported span. Ids and flags are what the ticket says to keep, and `traceState` is neither.
- **The name needs no rewrite.** It starts as `${method}` (`base-server.js:499`). Its only renames are `` `${method} ${route}` ``, `` `RSC ${method} ${route}` ``, or the bare method (`:528-543`), so it never carries the path. A client-side navigation is exported as `RSC GET /task/[id]`. For the person's Jaeger check in Done when, the request to compare with curl is a hard reload, which is `GET /task/[id]`.

Never change the original span. It is the same object any other processor would see.

## `measure`

Drop `{ root: true }` (`timing.ts:63`). The call becomes `startActiveSpan(\`page ${label}\`, async (span) => …)`.

**The active span is not the request span.** Next activates render spans of its own (`AppRender.getBodyResult`) around rendering, and `OnlyScope` drops them, so the page span's parent would name an unexported span. `OnlyScope.onStart` therefore remembers each request span's context by trace id (bounded like the page set, dropped when the request ends), and `onEnd` forwards the `page` span as a copy whose parent is that request span.

Rewrite the doc comment (`timing.ts:46-55`). It currently says *"`root: true` is what makes it a root: otherwise its parent is Next's request span, which the exporter drops."* The new comment says:
- under Next the page span is re-parented by `OnlyScope` onto the request span it forwards as a copy;
- with no active span (unit tests) it is a root.

Keep the sentence about the label being a route pattern. Also update the module comment at `telemetry.ts:5-12`: Next's spans are still dropped, **except** the request span of a trace that held a page span, which leaves as a stripped copy.

## Tests (`unit/telemetry.test.ts`)

Drive everything through `installTracing(on, none, new InMemorySpanExporter())` and real tracers, as the existing tests do. Do not hand-build `ReadableSpan` fakes. The real SDK span is what Next produces, and a fake would let a missing field such as `duration` or `resource` pass.

- **The request span.** Run `trace.getTracer('next.js').startActiveSpan('GET /task/[id]', { kind: SpanKind.SERVER, attributes: { 'next.span_type': 'BaseServer.handleRequest', 'http.target': '/task/123', 'http.url': 'https://api.github.com/x?t=1', 'http.method': 'GET', 'next.route': '/task/[id]' } }, …)`. Inside it, call `measure(…, { label: '/task' })`. Then, on the request span: `recordException(new Error('https://x?token=y'))`, `setAttribute('http.status_code', 500)`, `setStatus({ code: 2, message: 'https://x?token=y' })`, `end()`. Assert:
  - the request span's exported attributes equal exactly the allowlisted subset;
  - `events` equals `[]`, `links` equals `[]`, `status` equals `{ code: 2 }`;
  - `JSON.stringify` of the exported span's attributes and status does not match `/https:|token|123/`;
  - `page /task`'s `parentSpanContext.spanId` is the request span's id.
- **Never forwarded:**
  - the same request span with no `measure` inside it;
  - a span with `next.span_type: 'BaseServer.handleRequest'` from `getTracer('other')`, inside whose trace a page span did end;
  - an `AppRender.fetch` span from `next.js` inside a page trace.
- **The bound.** Construct `new OnlyScope(SCOPE, inner, 3)` directly, with `inner` recording what it receives. Feed it four ended `page` spans from four traces, then the request span for the first trace. Assert:
  - `remembered` is `3`;
  - the request span is not forwarded, because the oldest id was evicted;
  - a separate run with 1,001 page spans at the default limit leaves `remembered` at 1,000;
  - forwarding a request span reduces `remembered` by one.

  This one test may build spans with a real `BasicTracerProvider` whose only processor is the `OnlyScope` under test.
- **Rewrite `:88-117`.** The stand-in request span gets `next.span_type: 'BaseServer.handleRequest'`. `:105` becomes *the page's parent is the request span*. The attribute loop at `:112-115` exempts the request span, or checks it against the allowlist. Keep the `/\/\d+(\/|$)/` name check over every span, including the request copy.
- **Unchanged:** `:75-86` and `:118-128` run `measure` with no active span. They keep passing, and they are the cover for *"a page span with no request span is a root"*.

## Edges the ticket leaves to the design

- **A page whose load throws.** The page span still ends first, and the request span ends after it, so the trace is remembered and the 500 is forwarded.
- **A request span that ends after its id was evicted.** It is dropped, the same as today. That takes more than 1,000 concurrent page requests, so it costs nothing in practice.
- **A board restart:** the set starts empty, and every request in flight at the restart is lost along with its process anyway.
