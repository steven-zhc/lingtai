## Where it goes

`apps/cli/unit/doctor.test.ts` is a **new file**. The unit half has no doctor test today: `apps/cli/unit/` holds only `backlog`, `conduct-pause`, `discuss-*`, `run-pause` and `upgrade-drain`. Every existing doctor test is in `apps/cli/integration/`.

## The decision: `runDoctor` needs one more seam before a unit test can run it

The ticket assumes `load` and `queries` are enough. They are not. On the SQLite branch, `runDoctor` (`apps/cli/src/doctor.ts:2023`) reaches outside the process through rows that take no parameter:

| Row | Reaches | Where |
|---|---|---|
| `projections: lag` | `projectionLag()` → `projectionStore()` → `chosenStore()` | `doctor.ts:555`, `packages/projector/src/choose.ts:47` |
| `projections: shape` | `projectionShape(p)`, same path | `doctor.ts:595` |
| `daemon: liveness` / `daemon: currency` | `readStatus()`, `readControl()` | `doctor.ts:863-866`, `:964-970`; already parameters, but `runDoctor` passes nothing |
| `conductor: lock` | `conductorLockHolder()`, which reads `~/.lingtai/locks` | `doctor.ts:1135` |
| `worktrees: reconciliation` | `findOrphans({ dryRun: true })`, which reads the worktree directory | `doctor.ts:1157` |
| titles for the two gate audits | `readTasks()`, the projection store | `doctor.ts:1228` |
| `runtime: other settings in scope` | `readFile(join(homedir(), ".claude", "settings.json"))` | `doctor.ts:661-666` |
| `runtime: signed in` | `everyRuntime()` and then `checkAuth`, which runs `claude auth status` and so starts a process | `doctor.ts:720-730` |

**Why the unit test has to inject these.** Under the unit project, `chosenStore()` throws: no `LINGTAI_TEST_SQLITE_PATH` is set, because `globalSetup` belongs to the integration project only (`vitest.config.ts:105`), and `storeChoice` then returns `notSetUp` (`packages/env/src/index.ts:573-583`). Both projection rows turn a throw into `status: "fail"` (`doctor.ts:573`, `:590`). So a unit test that injects only `load` and `queries` goes red on a world that is fine. That red is not the finding, and it must not be reported on the ticket as one. The settings row would also read the operator's real `~/.claude/settings.json` and warn on this machine, and the runtime row would start a process.

**Shape:** add a sixth parameter to `runDoctor`: one object, `reach: Partial<DoctorReach> = {}`. Do not add more positional arguments. Each member's default is exactly the call made today, so `doctorReport` and every existing caller are unchanged. Proposed members:

- `lags`: defaults to `() => projectionLag()`
- `shapes`: defaults to `(p) => projectionShape(p)`
- `status` and `pause`: handed straight to `daemonLiveness(read, readPause)` and `daemonCurrency(read)`, which already take them. `daemonLiveness`'s JSDoc says *"the suite passes a memory store's"*.
- `lockHolder`
- `orphans`
- `titles`: defaults to the `readTasks` read
- `settings`: the raw text of `~/.claude/settings.json`, or `null` where the file is absent
- `runtimes`: defaults to `() => everyRuntime()`

Each row function takes its seam the way `daemonLiveness` already does, as a defaulted parameter. The Postgres branch can keep its `url` arguments; leave that branch untouched.

**Leave `readCodeVersion` and `isBehind` alone.** They are only reached inside `passRefusals` once a project is refusing (`doctor.ts:1033-1035`), and with `load: async () => []` it returns at `:1029`. The three recipe rows also return before touching a file when there are no projects (`:1453`, `:1886`, `:1985`). `githubCredentials(env)` is already pure.

## The world

- **`store`:** pass a `StoreChoice` literal. It should be what `storeChoice` returns for a `config.yml` that says `database.store: sqlite` (`packages/env/src/index.ts:630`): `{ store: "sqlite", path: "<unused>", where: "config.yml", from: "<home>/config.yml" }`. Do not write a real `config.yml`. `apps/cli/integration/doctor.test.ts:206-219` hands the choice in for the same reason: the fork in `runDoctor` is what is under test.
- **`env`:** `{}`. That means no `LINGTAI_GITHUB_APP_*`, no `LINGTAI_DATABASE_URL` and no `LINGTAI_DIRECT_DATABASE_URL`.
- **`machine`:** a function that throws if it is called. With `fileBacked` true it must never be asked (`doctor.ts:2061-2065`). The integration test does the same at `:245-247`.
- **`queries`:** an empty log, written inside the test as an object typed against `LogQueries`, every method resolving `[]`. Use `satisfies LogQueries` so that a method added to the interface breaks `pnpm typecheck` rather than going unnoticed.
  - `createMemoryEventStore()` is an `EventStore` (`packages/event-store/test/memory.ts:91`), not a `LogQueries`. Nothing in the repository gives a memory `LogQueries`, and building one in `@lingtai/event-store` widens this ticket.
  - The memory store belongs in the `pause` seam instead: `() => readControl(createMemoryEventStore())`, since `readControl(store = eventStore)` takes one (`packages/daemon/src/control.ts:114`).
- **`load`:** `async () => []`.
- **`reach`:**
  - `status`: `null`. No daemon has run, which is true of a newcomer.
  - `lags`: `[]`.
  - `shapes`: whatever `projectionShape` returns for a table with no drift. Read `packages/projector/src/shape.ts:216` for the type; the minimum is `{ projection, drift: [] }` plus what `describeShape` reads.
  - `lockHolder`: `null`.
  - `orphans`: `[]`.
  - `titles`: `[]`.
  - `settings`: `null`.
  - `runtimes`: one stub, `{ capabilities: { id: "claude-code" }, checkAuth: async () => ({ loggedIn: true, detail: "signed in" }) }`, cast to the runtime type. `runnableEnv({})` at `doctor.ts:723` is still called on the way; that is fine.

## What the test asserts

1. No result has `status: "fail"`. This is the claim the ticket asks for.
2. **The SQLite branch was actually taken**, so that the first assertion is not vacuous:
   - `environment` is `skip`;
   - `store: the machine's written choice` and `log: reachable` are `ok`;
   - every `postgresOnlyRows()` name is present and `skip`.
3. **The warns are an exact set.** Declare a map in the test from row name to reason, and assert that the names of the rows that warn equal its keys. With this world the expected map is empty, because `settings: null` is the `ok` path at `doctor.ts:668`. Writing it as an empty map rather than `warned === 0` gives the next warn somewhere to be named, with its reason, which is the ticket's second *Done when*.
4. **`github: app credentials` is `skip`.** This is the no-App half that nobody owned.

**Showing the third *Done when*.** A new Postgres row only ever goes into the `else if` branch (`doctor.ts:2152`), which this world never reaches. So the break that matters is in the shared tail (`:2167-2172`) or in the fork guard. Demonstrate red in two ways, then revert both:

- Set `fileBacked` to `false` at `:2061`. `environment` should then fail with no URL.
- Delete the `!hasGitHubApp(env)` early return in `githubCredentials` (`:754`).

Record both in the commit body. Neither edit is part of the diff.

## If a row really does fail

Once the seams are in, a row that still fails is the finding. Fix it in this change only if it is a SQLite or no-App claim. Otherwise, say so on #349 and leave it. **A failure that comes from a seam you forgot is not a finding.** It shows up as a projection row whose detail says the store was refused by name. That refusal is the safety net: a missed seam goes red loudly; it can never quietly open `~/.lingtai`.
