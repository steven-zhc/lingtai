## Design: #1155. The operator's Codex profile denies apply to every sandboxed run

### The decision the ticket leaves open: read the profile in the adapter, not at the five sites

The ticket's Fix row says to compute `operatorDenies: readonly string[]` at the five pass sites. **Do not build it that way.** Read the profile where the run is launched instead. Three reasons:

- **There is really one site, not five.** All five go through `sandboxOf` (`packages/conductor/src/conduct.ts:850`):
  - the judge (`:3095`), the implementer (`:4476`) and the fixer (`:4757`) call it directly;
  - the reviewer and the design run reach it through `sandboxFor` (`conduct.ts:3948` → `agent-action.ts:1001`, `:1645`).
- **`sandboxOf` cannot do the read.** It is handed `{ runId, worktree }` only, with no `env`. It is also synchronous and has no run log. So it cannot do what the ticket requires:
  - read *through `codexConfigPath(request.env, request.cwd)`*;
  - refuse *before `wrap`* with a sentence of its own. The only refusal `RunSandbox` carries is `decision: refused`, which prints `sandbox required and unavailable on this host` (`claude-sandbox.ts:149`). That is the wrong sentence.
  - leave *a note on the run's log*.
- **The adapter already does exactly this for the Claude settings denies.** `sandboxedLaunch` (`packages/agent/src/claude-sandbox.ts:138`) reads the operator's `settings.json` per run, at dispatch, through a test port (`SandboxPorts.readOperatorSettings`, `:63`). It refuses with `SandboxRunRefused` before `wrap`, writes to the run log through `trace` (`claude-code.ts:459`, `note('sandbox', …)`), and passes the result as `caller_additions.deny` (`:183`). The Codex profile read belongs beside it.

So the change looks like this:

1. **One fact per pass, set in `sandboxOf`.**
   - Add a field to `RunSandbox` (`claude-sandbox.ts:28`). Suggested name: `readonly codexNamed: boolean`, true when `runtimesOf(recipe).includes('codex')`.
   - `recipe` is already in scope at `conduct.ts:848`, and `runtimesOf` is in `packages/recipe/src/runtimes-of.ts:13`.
   - Every new site that builds a `RunSandbox` without going through `sandboxOf` must also set it. That is the per-site cost the ticket's *What it costs later tickets* edge means. Making the field required lets `tsc` enforce it, so no test listing the sites is needed.
2. **One pure function in `packages/agent/src/codex-sandbox.ts`, next to `codexProfileDenies` (`:25`).**
   - Signature: `operatorCodexDenies(verdict, at, codexNamed)` returns `{ ok: true; paths; note?: string } | { ok: false; refusal }`.
   - On `unreadable` with `codexNamed === false`: return `ok: true, paths: []` and the note `the operator's Codex profile could not be read: <why>`.
   - Every other case: return `codexProfileDenies(verdict, at)` unchanged. That means a `:special` key and a `~` key with no `HOME` still refuse, as the ticket's Edges decide (they gate only `unreadable`).
   - Export it from the package root, because the conductor needs it for `run:` commands (item 4).
3. **Claude Code: inside `sandboxedLaunch`, after `carriedDenies` and before the collision check.**
   - Get the verdict through a new port, `SandboxPorts.readCodexPermissions?: (env, cwd) => UserPermissions`. Its default is `userPermissionsAt` (`codex.ts:663`), the same call the Codex adapter makes at `codex.ts:1466`.
   - It needs `run.env` and the run's cwd. `run.env` is already passed in (`claude-code.ts:457`, `env: request.env`). The cwd is not, so add `cwd: request.cwd` to that argument.
   - If there is a note, send it to `trace`.
   - The profile paths need their own collision check, with their own sentence naming the Codex profile (the settings sentence names `settings.json`). Check them against the settings list's `needed` paths plus `sandbox.cache`, because #1151's rule lists the cache.
   - The Codex-home part of #1151's rule ("the Codex home") does not apply here. A Claude Code run has no Codex home on its `write` list, so a deny over `~/.codex` cannot be voided by one. Leave it out rather than refuse a Claude run for denying the directory it never uses.
   - Concatenate both lists into `callerAdditions.deny`.
4. **`run:` commands: in `makeRunSandbox` (`packages/conductor/src/sandbox-decision.ts:57`).**
   - Its `wrap(command, worktree, env)` already has the command's own environment. That environment carries `HOME`, because `deps.env` adds `runnableEnv`'s six names (`packages/agent-env/src/index.ts:146`; `from-recipe.ts:376`).
   - Pass it `codexNamed`, `cache` and a reader port. Read per call with `(env, worktree)` and hand `caller_additions: { deny: paths }` to `service.wrap`. The `caller_additions` field is optional in `WrapInput` (`packages/sandbox/src/sandbox.ts:46`), and `makeRunSandbox` passes none today.
   - Make a refusal a `SandboxWrapFailed({ cause: new Error(sentence) })`. `wrapRefusal` (`process-action.ts:47`) prints `cause.message` into the evidence and marks the result `notWrapped` (`:152`), so `process-action.ts` needs no change.
   - The `unreadable` note on this path goes to the action's log: `process-action.ts` hands `context.log` to `wrap` as an optional fourth argument.
5. **Codex runs ignore `codexNamed`.** `codexSandboxedLaunch` already reads and refuses for itself (`codex-sandbox.ts:116`), and a Codex run means Codex is named. Do not add the denies a second time.

### How the Done-when boxes map onto this shape

- **Box 1** (`RunRequest.sandbox.operatorDenies` exists and each site fills it) becomes:
  - `RunSandbox.codexNamed` is required and filled in `sandboxOf`;
  - a unit test with a fake `readCodexPermissions` returning `{ kind: 'denies', paths: ['~/secrets'] }` and a fake `wrap` asserts that `caller_additions.deny` contains `<hostHome>/secrets`. Model it on the tests that drive `sandboxedLaunch` with `SandboxPorts`.
- **Say this in the commit body, because the reviewer has the ticket and not this note:** the field is a boolean computed per pass, and the list is computed per run in the adapter, because `sandboxOf` has neither the run's env nor its log.
- **The `run:` command box:** call `makeRunSandbox` with a fake `SandboxApi` whose `wrap` records its input. Assert `caller_additions.deny`, and assert a refusal for `unreadable` together with `codexNamed: true`.

### Edges the ticket did not settle

- **`HOME` that differs between the profile read and the deny expansion.**
  - In the Claude adapter, expand `~` against `run.env.HOME`, because that is the `HOME` `codexConfigPath` used to find the file. In practice it equals `sandbox.hostHome`.
  - In `makeRunSandbox`, expand against `env.HOME`.
- **`kept` stays silent for a non-Codex run.** The Codex adapter notes `kept` only on unwrapped runs (`codex.ts:1469`), and the ticket says `kept` adds nothing.
- **The read blocks.** `userPermissionsAt` uses `readFileSync`, and the Codex adapter already calls it per run. Wrapping the port in `Effect.sync` is enough. Do not add an `async` function or an `Effect.run*`, because the ratchet (`packages/domain/unit/effect-ratchet.test.ts`) counts both.
