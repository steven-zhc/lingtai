## Design: #802, rewriting the front page

The work is one rewrite of `apps/site/src/app/page.tsx`, `home.css` and `apps/site/unit/page.test.ts`. The ticket covers what the page should say. This note covers six things a straight port of `doc/design/home-page.html` would get wrong.

### 1. Two design sentences are wrong and must not be copied as they stand

- **Stop 2's *You see*** (`home-page.html:313`) says *"The run’s log as it happens"*. Write *"The run as it happens (`lingtai attach`)"*, as the ticket says. Stop 2 sits above *The work, in the open*, so the word `log` there would fail `page.test.ts:30-37`. The design's other `log`s don't touch the guard: one is in the prototype banner (`:225`), which isn't ported, and one is in the footer (`:502`), which is `chrome.tsx` and stays as it is.
- **The *Several tickets at once* card** (`home-page.html:410`) says *"two that touch the same file"*. The ticket's evidence says the rule is narrower: `same-file.ts:2-10` keeps tickets apart only when their `Fix` rows name the same file. Reword it along the lines of *"…or two whose Fix rows name the same file, and lands them one at a time."* Keep *"lands them one at a time"*. That one is true, because the merge lane is serial.

### 2. The test for the "one at a time" claim must match the whole false phrase

The new page still contains *"one at a time"* (the sentence above). So the test must assert that `work on them one at a time` is absent, not the bare phrase.

The other four checks:
- `0.9.0 is the first release` is absent.
- `nothing enforces yet` is absent.
- `creates the GitHub App` is absent.
- The `lingtai ticket new` step is qualified: assert *"On a GitHub project it will tell you to use"* is present. Don't assert `lingtai ticket new` is absent, because the design keeps it for local projects (`:302`, `:529`).

`prose()` reads the TSX source. That means a test looks for `recipe&rsquo;s`, not `recipe’s`. Write each "sentence present" check as a fragment with no entity in it (for example `buys none and holds as`, `OpenTelemetry trace when you give it a collector`). Don't decode entities in the test.

### 3. The landed figure goes in a small component, tested by rendering it

`Home` is async and reads `snapshot.json` (`page.tsx:7-8`), so a source grep can't show that the figure is absent with no snapshot and equal to `count` with one. Do it like this:

- Add a pure `landedCount(snapshot: Snapshot | null): number | null` to `apps/site/src/lib/snapshot.ts`. It returns `snapshot.lanes.find(l => l.id === 'landed')?.count`, and `null` when there is no snapshot, no Landed lane, or a count of `0`.
  - The `0` case is my call. The ticket's *Watch out* says a figure is never `0`, and a log fresh from a reset would otherwise print *"0 landed or closed"* on the front page.
  - `count` is the whole lane, not the five drawn cards (`snapshot.ts:78-86`). `LANE_OF` already folds `closed` into it (`snapshot.ts:163-165`), which is why the copy says *"landed or closed"*.
- Put the *Lingtai builds Lingtai* card in its own component file under `apps/site/src/app/` and pass it `landed: number | null`. With a number it renders *"N landed or closed on its board"*. With `null` it renders the card's sentence without that line. Never render an empty `<span>` or a placeholder.
- Drop the design's *740*, so the card reads *"Nearly all of the tickets closed in this repository…"*.
- Don't print a date in the card. The bar's `board · <stamp>` (`page.tsx:12`) already dates it.
- Test with `renderToStaticMarkup`, as `apps/site/unit/events.test.tsx:4,16` already does: one case for `null` (no digit, no `landed or closed`), one for a snapshot with Landed `count: 42` and two cards (renders `42`, not `2`), and one for `0`. Put the `landedCount` cases in `snapshot.test.ts`.

### 4. Name classes `home-…`, not after the design

`layout.tsx:16` imports the board's `globals.css` ahead of `site.css` and `home.css`. That stylesheet already defines `.card` (`:321`), `.cols` / `.col` (`:253`, `:268`), `.steps` (`:2400`), `.setup` (`:2788`) and `.evidence` (`:761`). The design uses `class="card"`, `class="setup"` and `class="steps"`, so a straight port inherits the board's styles.

- Prefix every new class: `home-stops`, `home-card`, `home-six`, `home-also`, `home-edges` and so on.
- Keep `home-setup`, `home-evidence` and `setup-steps` as they are today (`page.tsx:161,167,211`). `page.test.ts:64-70` holds the first two.
- Scope new rules under `.home`, as `home.css:3-11` does.
- Port the design's layout values, but take colours and fonts from `site.css`'s variables, not the mock's `:root`.

### 5. Keep the hero diagram's class names and change only its labels

Keep `RunDiagram` (`page.tsx:257` on) and its `pass-diagram` / `diagram-*` classes (`home.css:56-110`). Change its labels to the design's (`home-page.html:247-276`):
- `01 YOUR TICKETS`, with a GitHub issue *or on this machine* card;
- `02` with *"Own worktree, filtered environment"*;
- `03`'s land-or-wait result.

That is the *updated loop diagram*. Leave its `role="img"` and `ILLUSTRATION` in place (`page.test.ts:54-59`). The section that held the `mini-queue` / `mini-checks` / `mini-board` cards (`home.css:117` on) is gone. Delete those rules unless the diagram still uses them, because #803 brings its own illustrations.

### 6. Changes to `page.test.ts`

- **Section order:** `'Let your backlog move'`, `'The loop, one stop at a time'`, `'Beside the loop'`, `'Six more things'`, `'How you use it'`, `'The work, in the open'`, `'Know the edges'`. These are the design's kickers and the edge line's bold text. The section anchor moves from `#how-it-works` to `#loop`, matching the design's second hero link. `href="#setup"` stays, because the test holds it.
- **Link whitelist:** add `/docs/requirements/` to the `every(...)` check (`:89`), for the edge line's link. `PUBLIC_SLUGS` already includes `requirements` (`:80`, `docs.ts:73`).
- **Also row:** its links stay absolute GitHub issue URLs, which the `/docs?/` matcher ignores.
- The design links no ADR, so there's nothing for this ticket to add there.

### What a unit test can't cover

The layout at 1440×900 and 700px, in light and dark, is the ticket's manual check. Nothing in `pnpm test` covers it, and `apps/release/integration/build.test.ts` is the only thing that builds the page.

The page has no `"use client"` and needs none, but don't add a server-only import to the new card component. `tsc` can't see that mistake (see #230).
