# CONDUCT-5: design note

The ticket mostly stands as written. Below are the three things it leaves implicit, then the order to work in.

## 1. There are two nested runs to delete, not one

The ticket names the promise `gitAsked` (`conduct.ts:1864-1868`, `Effect.runPromise(gitAskedEffect(…))`). There is a second nested run: `recordCompletion` reaches it through

```ts
// conduct.ts:3511-3513
// `kept-run-port.ts` is CONDUCT-5's and still hands back a promise, so its one call into an Effect
// here carries the pass's own services into a run of its own.
const detachedRecord = Effect.runPromiseWith(yield* Effect.context())
```

The ratchet does not count `runPromiseWith`. But *Done when*'s grep allows only `baseIsRed`'s (`:3352`), so `detachedRecord` has to go too.

Once `recordCompletion` is `(head) => Effect<void>`, it is an `Effect.gen` that does two things:

1. `yield* recordDiff(branch, head)` directly. `recordDiff` is already an Effect: that is why it needed `detachedRecord`.
2. `yield* Effect.promise(() => appendNow(runId, [RunProposedCompletion…]))`.

`appendNow` stays a promise because it is out of scope (rows 8+). The `Effect.promise` around it is a lift, not a run, so the ratchet does not count it. If the append rejects, the result is a defect. That matches today, where an `async` rejection reached `keptRunPortDepsFrom`'s `liftPromise` (`kept-run-action.ts:158-160`).

The `async` count drops by 6: five in `kept-run-port.ts` plus `recordCompletion`. That takes 147 to 141. The `run` count drops by 1 (`gitAsked`), giving 0. Both match the ticket.

## 2. The wiring in `conduct.ts`

- **`gitAskedEffect` is passed as `GitHere` unchanged.**
  - Its extra parameters, `retry` and `recover`, are optional (`:1849-1852`).
  - Its failure `RepoFailed` already satisfies `{ detail }`: the promise `gitAsked` passes it to the same type today.
  - The restore, `clean`, `keep` and the WIP commit get no retry and no recover. They have none today either.
- **`stepDeps.keptRun`:** `keptRun: { clean, keep: keepRun }` at `:3691`. Drop `keptRunPortDepsFrom` from the import at `:20`, or `pnpm lint` fails on an unused import.
- **`stepDeps.agent.restore`:** `restore: restoreReview` at `:3615`, replacing `(onSha) => Effect.promise(() => restoreReview(onSha))`.
- **`keepUncommittedWork`:** inside the existing `Effect.uninterruptible` (`:2189`), `const made = yield* commitWipExceptPlanted(gitAskedEffect, …)`. The region stays as it is. The commit and `wipParent` are still one uninterruptible step (#468), so nothing about interruption changes there.
- **Comments:** correct in place the comments that name `gitAsked` or CONDUCT-5:
  - `:1863`
  - `:1983`
  - `:2150`
  - `:2181`
  - `:3511-3512`
  - `kept-run-port.ts:35`

The restore needs no new guard. `makeAgentAction` calls `deps.restore` outside `mask` inside `Effect.uninterruptibleMask` (`agent-action.ts:884-932`). The comment there says *"The dispatch alone is interruptible … the restore below still runs, uninterruptibly"*. So a restore built as one `Effect.gen` of `yield*` git calls runs to the end there.

The trap is a restore that forks or detaches part of its own work: that part would escape the region. Keep it one straight `Effect.gen`.

## 3. The new interruption test, and where it lives

*Done when* limits the diff to five files, so the test goes in `packages/conductor/unit/kept-run-port.test.ts`. It imports `makeAgentAction` from `@lingtai/actions`, which is already a dependency of conductor (`packages/conductor/package.json:53`).

`packages/actions/unit/agent-port.test.ts:56-119` is the pattern to copy: a `runtimeOf` fake whose `run` rejects on `request.signal`'s abort. Copy it with four differences:

1. **Hand `makeAgentAction` an `AgentPortDeps` literal, not `agentPortDepsFrom(…)`.** The restore is now an Effect, and `agentPortDepsFrom` would wrap a promise around it. Write `issue` and `diff` as `Effect.succeed`, and `restore` as `restoreAfterReview({ git: fake, plantAt })`.
2. **The fake `git` has to report a moved or dirty tree, or the restore never reaches `reset`.** Have `rev-parse HEAD` answer a sha other than `onSha`, or have `status` answer a path that is not the planted file. Otherwise the restore returns `{ untouched: true }` at `kept-run-port.ts:198`, and the `Deferred` is never awaited.
3. **Use two `Deferred`s and no timer:**
   - `entered`: the fake completes it when `reset` is called.
   - `release`: `reset` awaits it.

   Every call is pushed to a log array.
4. **Fork the interrupt.** `Fiber.interrupt` waits for the fiber to finish, and the fiber is waiting for `release`, so awaiting the interrupt directly deadlocks. The sequence is:
   1. Run the action with `runFork`.
   2. Wait for the dispatch, as `:81` does.
   3. Fork `Fiber.interrupt(fiber)`.
   4. `Deferred.await(entered)`.
   5. Assert the interrupt has not completed yet: `Fiber.poll` on the forked interrupt is `undefined`.
   6. `Deferred.succeed(release)`.
   7. Join the interrupt.
   8. Assert the log contains `reset --mixed <onSha>` and `checkout -- .` in that order, and the exit `hasInterruptsOnly`.

The other unit tests convert mechanically. Each fake returns `Effect.succeed(Result.succeed(…))` or `Effect.succeed(Result.fail({ detail }))` where it returned a promise. Each `await port.x()` becomes `await Effect.runPromise(port.x())`. Keep every case and every expected string.
