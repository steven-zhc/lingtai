# Design note: #929, `runtimeVersion` on every `RunPrompted`

The ticket's shape holds. #928 has merged into this worktree (`94523832`), so every `RunPrompted` already has a conductor-side writer. This note covers three things the ticket gets wrong or leaves open: line numbers that have moved, a Codex runtime that has no injected `spawn`, and the order of the implementer's record.

## Where the callers are now (the ticket's line numbers have moved)

- **Implementer:** `conduct.ts:3783-3785`, which is `recordPrompt(store, runId, { for: implementerFor, promptVersion, prompt: implementerParts }, log)`. The runtime is `dispatched` (used at `:3711`). Probe with the same env that the following `dispatched.run` is given.
- **Judge:** `conduct.ts:2728`, inside a `.then` chain. The runtime is `dispatched = runtimeNamed(declared.runtime)` (`:2694`).
- **Fix round:** `conduct.ts:4043`. The runtime is `dispatched`.
- **Actions:** `ActionContext.prompted` is at `action.ts:480`, and the `PipelineOptions.recordPrompt` option is at `action.ts:732` and `:849`. The calls are at `agent-action.ts:778` (review) and `:1400` (design). The conductor wires it at `conduct.ts:4306` (`recordPrompt: (call) => recordPrompt(store, runId, call, log)`), through `run-attempt.ts:856` and `:1985`.
  - Add `runtimeVersion` to the `call` type at `action.ts:732`. Add it as the third argument of `prompted` at `:480` and `:849`.
  - `agent-action.ts` asks `deps.runtime` with the env that the next `deps.runtime.run` is handed.
  - Give `prompted` a required third argument, not an optional one. Otherwise `tsc` will not name the two call sites.
- **Discussion:** `discuss.ts:566` and `DiscussionPorts` (`discuss.ts:440-455`).
- **Triage:** `apps/cli/src/triage.ts`, at the `recordPrompt` call. Find it by name.

## `probe` needs a `spawn` parameter, and Codex has none to give it

`probe` calls the `spawn` that `auth.ts` imports (`auth.ts:11`, `:83`). There is no seam for a test.

- Claude Code has one: `ClaudeCodeOptions.spawn` (*"Replaces `node:child_process`'s `spawn`: `pnpm test` runs no process."*, `claude-code.ts:325-326`), bound at `:413` as `spawnChild`.
- **Codex does not.** `run` calls the module-level `spawn` directly (`codex.ts:1463`), and `createCodexRuntime` reads no spawn option (`codex.ts:1359-1363`).

Decision:

1. `probe(binary, args, env, { timeoutMs, spawn })`. Both fields default to what they are today (20 000 ms and `node:child_process`'s `spawn`), so `claudeCodeAuth`, `codexAuth` and `AUTH_PROBES` stay as they are.
2. Export a `runtimeVersion(binary, env, spawn)` from `auth.ts` that does `reportedVersion(await probe(binary, ['--version'], env, { timeoutMs: 5_000, spawn }))`. It sits beside `claudeCodeAuth` and `codexAuth`.
3. Add `spawn?: typeof spawn` to `CodexOptions`, defaulting to the import, and use it at `codex.ts:1463` as well as in `version`. A Codex `version` that is injectable while its `run` is not would test a path `run` never takes, and the Done-when line *"the env `run` would use"* is checked against `run`'s actual call.

Keep `reportedVersion` and the classifiers pure. A timeout must still `SIGKILL` the child, as `auth.ts:96-99` does now.

## The env each `version` probes with

- **Claude Code:** `spawnEnvFor(env)`, the same transform `run` applies (`claude-code.ts:448`).
- **Codex:** `env` as given, without `LINGTAI_CODEX_PROCESS_MARKER`. The marker is for the run's process sweep (`codex.ts:1461-1466`), and a `--version` child is not a run.

Callers pass the same `env` value they are about to hand `run`. Build it once into a local and pass it to both, so the "this call's environment" rule (the ticket's Watch out) holds by construction rather than by keeping two expressions in step.

## The implementer: probe before `recordPrompt`, never after `register`

`conduct.ts:3745-3750` says the implementer's record is *"awaited first and never after: a `RunPrompted` appended later would make the hook's next append a `ConcurrencyError`"*.

- The probe appends nothing, so it can go anywhere before `recordPrompt`.
- Put it immediately before `recordPrompt` at `:3783`, as its own `yield* Effect.promise(() => runtimeVersionOf(...))`.
- Do **not** start it in parallel and join it later. The value must be in hand when `recordPrompt` runs, and `recordPrompt` must still finish before `server.register` at `:3787`.

## The judge

Probe first, inside the existing chain: `runtimeVersionOf(dispatched, judgeEnv).then((v) => recordPrompt(…, runtimeVersion: v …)).then(() => dispatched.run(…))`. Keep the existing `.catch` that sets `threw`, because `runtimeVersionOf` never rejects.

## The discussion: the port asks the runtime that `ask` selects

`discussionAsk` takes `runtime: Runtime | (() => Runtime)` and resolves it inside the call (`apps/cli/src/discuss.ts:251-257`), using `env: runnableEnv({})` (`:262`).

- Add a required `version(): Promise<string | null>` to `DiscussionPorts`.
- Build it in the same place from the same `runtime` argument and the same `runnableEnv({})`. A `discussionVersion(runtime)` helper beside `discussionAsk` resolves the thunk the same way.
- Make it required, not optional, so `tsc` names every host and every test fake.
- `discuss.ts` calls `ports.version()` just before its `recordPrompt` at `:566`. Each round calls it again; do not hoist it out of the loop.

## Test fakes

Unit tests whose fake runtime has no `version` now get `runtimeVersion: null`. Where a test asserts a whole `RunPrompted` payload with `toEqual`, add the field to the expectation.

The Done-when cases that expect **different** answers need fakes that do implement `version`. Give them distinguishable answers, for example `'fake-impl 1'` and `'fake-judge 2'`. A test where both fakes return `null` would pass even if the version came from the wrong runtime.

## Nothing here needs the integration half

Every Done-when item is reachable with `createMemoryEventStore()`, injected `spawn` functions and fake runtimes, so `pnpm test` covers all of it.

Not checked before the merge: a real `claude --version` or `codex --version` spawned through `probe`. The unit-level claim that stands in for it is the `reportedVersion` table, fed the exact strings from the ticket's evidence.

After a daemon restart, the field that settles whether this worked in production is `RunPrompted.runtimeVersion` on any event appended after the restart's `ConductorStarted`.
