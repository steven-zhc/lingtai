# Design note: #1295, `doc/when-it-fails.md`

## Where it goes

- **New file:** `doc/when-it-fails.md`. Its title comes from the file's own `# ` heading (`docs.test.ts:170`, *takes the title from the file's own heading*). Its lede comes from the first prose paragraph (`docs.test.ts:175`), so open with a sentence, not with the table.
- **`apps/site/src/lib/docs.ts:117-137`:** add `'when-it-fails.md'` to the Guides `files`, right after `'concepts.md'`.
- **`apps/site/src/lib/docs.ts:70-82`:** also add `'when-it-fails'` to `PUBLIC_SLUGS`. The ticket does not ask for this, but its *Done when* needs it. `servable()` (`docs.ts:89-92`) returns `all.filter((f) => isPublicSlug(slugOf(f)))` unless `DOCS_PUBLIC` is set, so a file listed in `SECTIONS` but not in `PUBLIC_SLUGS` is listed and never served. `reference.md` and `operating.md` show this today: both are in Guides, and `docs.test.ts:247-253` asserts `expect(served).not.toContain('reference.md')`.
- **The comment above `PUBLIC_SLUGS` (`docs.ts:55-68`):** add one clause for this page, as it gives one for `safety` and `guide`. It says each public page has "been through that edit", so give this one a reason too.
- **`apps/site/unit/docs.test.ts`:** add one `it` beside *publishes the safety page* (`:235-239`). It checks two things:
  - `servable()` contains `when-it-fails.md`.
  - `resolveHref('tutorial.md', 'when-it-fails.md', …)` gives `/docs/when-it-fails/`.

  The general test at `:41` only checks that the file exists. It would pass even if the page were never served.

## Links out of the page

Link to `reference.md` and `operating.md` with plain relative links. While those pages stay unpublished, `resolveHref` sends both to `GITHUB_BLOB` (`docs.test.ts:225-233`), which is correct.

Write code citations as code spans (`` `respond.ts:587` ``), not links. A link to source also goes to GitHub (`docs.test.ts:300`), but a span reads the same on GitHub and on the site, and it does not invite a reader who has only done the tutorial to click into TypeScript.

## Decisions the ticket leaves open

**1. Split the limits into two kinds, in both the table and part 4.** Some numbers are recipe settings and some are fixed in code. The comment on `BOUNDS` (`respond.ts:574-578`) says:

> A constant and not a recipe knob: a knob is a value somebody can set to a loop.

So part 4 lists only `refusalFixes`, `conflictResolutions`, `newAttempts` and the wall/turns limits as things a user can change. The table marks the other numbers as fixed. A page saying "you can change the 10 merges" would be the lie the ticket's *Watch out* warns about.

**2. Hold the page's numbers with a test, not only with line numbers.** Line citations drift every time someone edits `respond.ts`, and nothing checks them. Add a `describe` in `docs.test.ts`, or a sibling `when-it-fails.test.ts` under `apps/site/unit/`. It reads `doc/when-it-fails.md` and checks that each number appears beside its row's words. Import `BOUNDS`, `TRIAGE_SPLIT_CHILDREN_MAX` and the recipe defaults the way `failure-paths.test.tsx:4-55` does. This is unit-level: it reads one repository file, just as `docs.test.ts` already does. Keep the `file:line` citations anyway, because the ticket asks for them.

**3. Quote the board's words exactly, from their source.**
- *Handled for you*: `apps/board/src/lib/handled.ts`, and on /report `apps/board/src/app/report/panels.tsx`.
- *Waiting on you*: `apps/board/src/lib/board.ts` and `apps/board/src/app/decide.tsx`.
- *Why nothing runs*: `apps/board/src/lib/why-line.ts` and `apps/board/src/app/queued-stream.tsx`.

Copy the string as each file renders it, and cite it. `concepts.md` has a test of this kind, *quotes only the labels the board shows* (`docs.test.ts:275`). This page needs no such test, but should be written so one could be added.

**4. Keep it to one page and no event names.** The ticket says "no event names", and that applies to the table too. Write *a fix ticket is opened*, not `BaseFixProposed`. The citation column is where the code is named.
