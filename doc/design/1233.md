# Design: #1233 — `editPrompt` and `concludeDiscussion` move into the Ticket owner

## 1. Where the code goes

Both commands go into `packages/conductor/src/ticket/commands.ts`, which the board already reaches as `@lingtai/conductor/ticket` (`packages/conductor/package.json:8`). That path is not counted (`aggregate-owners.test.ts`: `NOT_COUNTED_UNDER = ['packages/conductor/src/ticket/', …]`). Put them beside the other append-only commands, `landTicketEffect` and `holdTicketEffect` (`commands.ts:521`, `:538`).

**Do not add a domain transition for either command.** Each of the owner's domain transitions exists to carry a rule, such as `claimTransition` or `askTransition`. The ticket says these two commands have no rule (*"No new rule for a prompt edit"*). An `editPromptTransition` that always succeeds would be a place for somebody to add one later without anyone noticing.

The owner's imports for this stay safe for the board:
- `editHash` comes from `../attempts.ts` (`attempts.ts:592`). The board already loads that module through `@lingtai/conductor/prompt` (`actions.ts:46` → `prompt.ts:30-39` imports `./attempts.ts`).
- The store comes in as an argument. The owner keeps its existing `@lingtai/event-store/store` import (`commands.ts:52-57`) and never imports the barrel, whose `eventStore` is the process store (`actions.ts:65`).

## 2. The one `PromptEdited` builder

Add a private `promptEdited({ text, by, basedOn, chatId }): ToAppend` in `commands.ts`. The hash rule is the board's rule, `text.trim() === '' ? null : editHash(text)` (`actions.ts:751-754`).

The builder must not trim. The board records raw text on purpose (*"What is typed is what the attempt is told, byte for byte"*, `actions.ts:726`). `discuss.ts` trims before the edit (`:740`) and refuses a blank one (`:746`), so it always passes trimmed, non-empty text. For that text the board's rule gives `editHash(text)`, which is exactly the value written at `:757` today. So one builder keeps both callers' events byte-for-byte the same as now. Keep the two comments, on the `hash` (`actions.ts:748-750`) and on `basedOn: null` (`discuss.ts:751-754`), on the builder or at the caller that owns each reason.

## 3. `editPrompt`: re-read once, using `head`

```
editPromptEffect(store, ticketId, { text, basedOn, by }): Effect<void, unknown>
```

Take the version from `store.head(ticketId)`, not `readThroughSnapshot`. Nothing is decided from the state, and `head` *"rejects as `read` would … This is where an append's `expectedVersion` comes from"* (`event-store.ts:358-364`).

1. Append at the head.
2. On a `ConcurrencyError` only, take `head` again and append once more.
3. If the second append also loses, it fails with that error, and the board's `try` turns it into `ok: false` (`actions.ts:698`).

You can use `appendLost` (`commands.ts:311`) for the first attempt. Do not use `appendOnTicket` (`:489`): it runs `orDie`/`Effect.promise`, which turns a failed read into a defect, and its single attempt has no retry.

Store `basedOn` as `input.basedOn || null` in the board action, as it is today (`:755`). The owner takes `string | null`.

## 4. `concludeDiscussion`: one append, and the outcome decides the shape

```
concludeDiscussionEffect(store, ticketId,
  { chatId, by } & ({ outcome: 'prompt'; prompt: string } | { outcome: 'ticket' | 'none' })
): Effect<void, unknown>
```

The ticket writes `prompt?`. Make it a discriminated union instead, so the owner never has to decide what a `prompt` outcome without text means. `discuss.ts` already refuses that case at `:746`, before it calls the owner.

The owner reads `head`, then makes one `store.append` of `[promptEdited({ text: prompt, by, basedOn: null, chatId }), DiscussionHeld{chatId, outcome, by}]` for `prompt`, or `[DiscussionHeld]` alone otherwise. It does not retry: the ticket keeps today's behaviour for a lost race, which is a failure. Let the failure propagate. `discuss.ts`'s own `catchCause` (`:805`) already turns any cause into `{ ok: false, detail }`, so the board's message is unchanged.

`concludeDiscussionEffect` in `discuss.ts` changes as follows:
- **Keeps:** the text checks (`:746`, `:768-769`), the GitHub write for `ticket` (`:770-786`), `ok`/`detail`, and `catchCause`.
- **Loses:** both reads and both appends (`:747-764`, `:789-802`). One owner call at the end replaces them.
- **Unchanged:** a `ticket` outcome whose GitHub write failed (`ok = false`) still gets its `DiscussionHeld`. The append at `:789` is unconditional today, and this ticket does not change that.

**The name collides.** `discuss.ts` already exports `concludeDiscussion` and `concludeDiscussionEffect`. The first is the promise face pinned in `effect-ratchet.faces.json:74-79` and imported by the board (`actions.ts:40`). Name the owner's commands `editPromptEffect` and `concludeDiscussionOnTicketEffect`, or anything that does not shadow those names. Import the owner's command into `discuss.ts` under its own name. `discuss.test.ts` keeps importing from `discuss.ts` and needs no change.

## 5. The board action

`editPrompt` (`actions.ts:723`) keeps everything it does today and replaces the read and append (`:742-758`) with one line:

```
await Effect.runPromise(editPromptEffect(eventStore, input.taskId, { text, basedOn: input.basedOn || null, by }))
```

What it keeps: `parseTicketStream` (`:739`), `actor()`, `revalidatePath`, and the `try`. The `editHash` import (`:46`) and `parsePayload`, if nothing else uses it, go away. `apps/board` is not in `effect-ratchet.baseline.json`: the board keeps promises (0101 §7, `effect-ratchet.test.ts:455`), and `actions.ts:540`, `:563` already run Effects this way. So this adds no ratchet count. **Keep the doc comment at `:703-722`**: it is #104's reasoning, and it still describes this action.

## 6. Tests, all unit, under `packages/conductor/unit/`, on `createMemoryEventStore()`

- **The `prompt` conclusion is one append.** Wrap the store so `append` records its calls. Assert one call carrying `[PromptEdited, DiscussionHeld]` in that order. Then use a wrapper whose `append` rejects, and assert that `read(ticketId)` shows neither event and that `concludeDiscussion` (the `discuss.ts` face) answers `ok: false`.
- **A lost race is retried once.** Use a wrapper whose first `append` appends some other ticket event itself and then throws `ConcurrencyError`. `editPromptEffect` must end with exactly one `PromptEdited`, at head + 2. Add a second test where both attempts throw: the Effect must fail and nothing may be written.
- **Blank text.** `editPromptEffect` with `'  '` writes `hash: null`, and with `'x '` it writes `editHash('x ')`, untrimmed.

None of this needs `pnpm test:integration`. The board action itself has no unit test: it is a one-line edge, and `typecheck` covers it.
