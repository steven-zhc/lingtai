## Design: #835, `spend` takes a triage or discussion row's kind from its own stored `TicketState`

### The helper the ticket names doesn't exist under that name

The ticket calls it "ticket 12 (#833)'s `foldStoredTicket`". What #833 actually landed is **`reduceStoredTicket`** in `packages/projector/src/ticket-row.ts:22`. Its header already says spend comes next: *"Shared by every projection that stores a `TicketState`: `ticket_report` now, `task_view` and `spend` next"* (`:2-4`). Use it as it is. Don't rename it and don't add a wrapper.

What it does:
- It takes `stored: unknown`. `undefined` means there is no row yet, and the state starts from `emptyTicket` (`:27`).
- It returns `null` for an event at or below `state.lastSeq`. The check runs before `applyTicket`, on `seq` alone (`:28`). That return value is the retry guard. It replaces `spend_kind`'s `where excluded.seq > spend_kind.seq` (`spend.ts:173`).
- A stored value that doesn't decode throws from `decodeTicket`. The message names `lingtai projection rebuild <projection>` (`packages/domain/src/ticket-codec.ts:132-139`). Pass `SPEND_TABLE` as `projection`, so the message says `rebuild spend`. That meets the ticket's "a read that fails" edge with no new code.

Domain already does D4. `applyTicket` takes `kind: event.type === 'TicketClaimed' ? (d.kind ?? state.kind) : state.kind` (`packages/domain/src/ticket.ts:528`). A claim after a close never reaches that line: *"`closed` is absorbing"* (`ticket.ts:441`), and the guard at `:452` returns before the switch for every `LIFECYCLE_EVENTS` type. So `kindedClaimAfterClosed` reads `'bug'` with no domain change. **This ticket changes nothing in `packages/domain/src`.**

### Where the fold goes in `apply`

Copy `ticket_report`'s placement (`ticket-report.ts:488-490`, *"Every event on a ticket stream goes through the ticket reduce, the ones the switch names or not"*). After the `switch` in `spend.ts:142-262`, run one step for every event with `isTicketStream(event.streamId)`:

1. Select `state` from `spend_ticket` for `event.streamId`. Pass `row?.state`, which is `undefined` when there is no row.
2. Call `reduceStoredTicket(row?.state, event, SPEND_TABLE)`.
3. If the result is non-null, upsert `encodeTicket(after)` into `spend_ticket (ticket, state)`. Bind it as a `jsonb` parameter, the way `ticket-report.ts:274` binds `ticket_state`.

**Putting it after the switch is a decision, and it is safe.** A triage `RunSpent` is itself a ticket-stream event. It reads `spend_ticket` inside the switch, before its own fold. `RunSpent` is not a case of `applyTicket` (it is not in `COVERS.ticket`, `packages/domain/test/histories.ts:1110-1128`), so folding it moves only `lastSeq` and `version`, never `kind`. Before or after gives the same kind. "After" means "as of the `RunSpent`" is exactly the state of the events before it. A later claim's kind can never reach an earlier row, and the rebuild keeps that.

Changes inside the `switch`:
- `TicketClaimed` / `TicketContinued` (`:158-178`): delete the `spend_kind` upsert (`:169-176`). Keep the `spend_stream` upsert (`:164-168`) exactly as it is; that is the per-pass kind, which is out of scope. Rewrite the comment at `:153-157`: it mentions `spend_kind`, and the claim now feeds the ticket's kind only through the reduce after the switch.
- `RunSpent` (`:210-215`): read `select state from spend_ticket where ticket = $1`. With no row, `kind` is `null`. With a row, `kind` is `decodeTicket(row.state, SPEND_TABLE, ticket).kind`. This covers both triage (the ticket is the stream) and discussion (the ticket comes from `spend_stream` through `DiscussionRequested`). Leave the `fromTicket = false` branch for pass streams (`:204-208`) untouched.

`create` declares `spend_ticket (ticket text primary key, state jsonb not null)` and drops the `spend_kind` declaration (`:122-128`). `reset` drops `spend`, `spend_stream`, `spend_ticket`, and still drops `spend_kind`, so the runbook's rebuild removes the old table. `drop table if exists` costs nothing on a fresh store.

**Don't decode on every ticket-stream event just to check that it decodes.** `reduceStoredTicket` decodes on the way in anyway, so a corrupt row throws at the first event that touches it. A row nothing touches is only read by a later `RunSpent`, and that read throws too.

### The fixtures

- Both new histories are single-stream ticket histories. Build the claims with `aClaim(t, r)` (`packages/domain/test/events.ts:158-160`), which writes `kind: null`. To give a claim a kind, extend `aClaim`'s options or write the `TicketClaimed` by hand with `t(...)`. **Don't change `aClaim`'s default.** Changing it would move every existing hash.
- Append the triage `RunSpent` with the same `t` stream builder, so `histories.test.ts`'s *"one stream, versions 1…n"* shape check (`:113-120`) holds.
- Place both `const`s after `late_discussionsHeld` (currently the last one built, around `histories.ts:1029`) and before `lateHistories` (`:1042`). Register them under `lateHistories.ticket`.
- `histories.test.ts`'s *"the histories fold"* runs `reduceTicket` over each history (`:98-101`). A `RunSpent` falls through `applyTicket`'s default and doesn't throw. If it does throw, a domain assumption is wrong. Stop and report that rather than drop the `RunSpent`.

### Tests

Put the two named tests (`D4: …` and `D6: …`) and the 1 / 3 / all batching cases in a new `packages/projector/unit/spend-ticket.test.ts`. Drive it the way `spend-rebuild.test.ts` drives its fold (`foldInTwoBatches`, `:245-247`), generalised to batches of size N.

Add one more case: two deliveries of the same event leave the rows equal to one delivery. That is the retry edge, and it costs one `it`.

Leave `spend-rebuild.test.ts`'s triage fixture (`:72`) alone unless a claim in that file carries a kind. If one does, the expected `kind` on its triage row changes only where D4 or D6 says so, and the assertion says which.

### Edges this design decides

- **The cost to every later ticket.** Spend is now the second projection, after `ticket_report`, that holds an encoded `TicketState`. Any change to `TicketState`'s shape makes `decodeTicket` refuse the stored rows until the table is rebuilt, so every such change carries `rebuild spend` in its runbook. Write that sentence in the rewritten `## kind` header (`spend.ts:24-29`). Name it as the price of 0123 §6's *"a projection never reads another projection's table"*, which is why this table can't borrow `ticket_report.ticket_state`.
- **A missed rebuild, after a `TicketState` shape change.** Every stored row throws, and the daemon stops (`packages/daemon/src/daemon.ts:179-186`). That is louder than a missed rebuild for this ticket: nothing to decode means an empty `spend_ticket` and silent nulls until each ticket's next claim. Only the runbook guards that second case, and no unit test can see it.
- **The integration half.** Nothing here needs Postgres-only behaviour. SQLite (`createSqliteProjectionStore(openSqliteProjections(':memory:'))`) stands in for the `jsonb` round trip, because `ticket_report`'s own unit tests already read `ticket_state` back through `decodeTicket` on that store (`packages/projector/unit/ticket-report-rebuild.test.ts:94`).
