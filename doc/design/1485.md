# Design: #1485, the PR page for a remote that is not GitHub

## 1. The helper reads `PrState`, not the `PrOpened` event

The ticket asks for one helper that `pr-page.ts` and `pr-board.ts` both use, and says to find the `host: 'none'` reading in the latest `PrOpened` of `lastPass`. The board card cannot do that, because it never has the events. `chipsOf(pr: PrState, stepNames)` (`apps/board/src/lib/pr-board.ts:216`) is called with a folded `PrState` and nothing else (`:414`, `:438`, `:547`). So the shared helper has to be a predicate on `PrState`. It can be written exactly from what the reducer already records:

- **`PrOpened { host: 'none' }` is the only event that records step `open` and leaves `pr.host` unset.** The reducer records `open` (`packages/domain/src/pr.ts:401-403`) and never touches `host`.
- **`PrDraftOpened` records `open` and sets `host` in the same reduction** (`pr.ts:380-386`). GitHub's open step appends it (`packages/conductor/src/pr.ts:454`).
- **A GitHub `PrOpened` records `ready`, not `open`** (`pr.ts:404`).

The predicate is therefore `pr.steps.some(s => s.step === 'open') && pr.host === null`. `steps` holds only the current pass. The comment says *"The steps recorded since the latest `PrInProgress`: a later pass through In progress starts empty"* (`pr.ts:82-83`), and `PrInProgress` resets it with `steps: []` (`pr.ts:306`). That meets the ticket's retry edge (read from this pass, not the whole stream) without a separate `lastPass` read on the page.

Export the helper from `pr-board.ts`, next to `failingRun` (`:206`), which `pr-page.ts` already imports from there. Have it return the two rows' wording, not just a boolean, so neither file writes its own copy of the text. Use one constant for the reason, something like *the remote is not GitHub, so nothing follows the PR there*. Three places read that constant: the CI row, the Checks head and the chip.

**A known gap, and why it is accepted:** `PrInProgress` does not reset `host` (`pr.ts:306` resets `steps` only). Suppose an earlier pass ran on GitHub, the recipe was then changed to name a remote, and a later pass opened with `host: 'none'`. That pass would keep a non-null `host`, the predicate would be false, and the page would show today's wording. Nothing is drawn wrongly; it just falls back. Reading the events on the page instead would fix it there only, and the card would then contradict the page, which the ticket's board edge forbids. Leave a comment saying so.

## 2. Where each file changes

**`pr-page.ts`, `stepRows`.** Check the helper before the `pending` branch at `:359-372`. For an unfollowed PR, the `ci` and `ready` rows become `status: 'skipped'` with the `—` mark, the same way the Summary row draws a skip (`:437`, `:449`). The CI row reads `no CI step — <why>`, the same form as `:416`. The Ready row says that opening the PR and marking it ready is the person's to do on this remote. Neither row uses `not-reached`.

The `inFlight` computation at `:351-352` cannot select either row: the status is `in-review` (`pr.ts:405`), not `in-progress` or `requested`. Still, put the check before the `inFlight` comparison so the order does not depend on that.

**`pr-page.ts`, the Checks head (`:679-684`).** Add a branch after `pr.ciSkipped !== null` and before `'no checks ran'` that gives the same `no CI step — <why>` text. A real `PrCiSkipped` keeps priority, which is the ticket's GitHub `PrCiSkipped` edge.

**`pr-board.ts`, `chipsOf` (`:216-247`).** The `ci` chip becomes `no CI` with `status: 'done'`, as for a `PrCiSkipped` (`:225-227`). The `ready` chip becomes `status: 'skipped'`, with short text such as `ready — yours`. That satisfies the Done-when line: neither `ci ·` nor `ready ·` appears.

**Not touched:** `pr-branches.ts:187` also calls `prStepRows`, but for the branch drawing, which is not in the ticket. `reducePr`, `prStepRows` and the conductor stay as they are, as the ticket's Watch-out requires.

## 3. `RunPrompted`: route only the tags `spentBy` owns, so nothing throws

Do not call `spentBy` (`apps/board/src/lib/history.ts:268-284`) blindly. Its `default` throws `no for` (`:282`), and its `Action` case appends `(name)` (`:272`), which would change the ticket-stream sentence pinned by `history.test.ts:1001-1007`.

In the `RunPrompted` formatter (`:332`), switch on `for?._tag` first:

- `Pr`, `Judge`, `Triage` and `Discussion` go through `` `${upper(spentBy(d, r))} was prompted (${bytes} bytes)` ``, using the same `upper` as `RunSpent` at `:467`.
- Anything else stays on today's `attemptAgent(r, r.streamId)` sentence: no `for` (from before #923), `Action`, or an unknown tag.

This is not a try/catch around `spentBy`. An unknown tag never reaches its `default`, so the ticket's *fall back rather than drop the row* edge holds by construction.

The resulting wording is `The conflict agent (resolve) was prompted (N bytes)` and `The summary agent was prompted (N bytes)`, since `spentBy` names them that way at `:279-280`.

## 4. Tests: all unit, nothing integration

- **`apps/board/unit/pr-page.test.tsx`:** add a stream of `PrInProgress …`, `PrOpened { host: 'none', number: null, url: null }`. Assert:
  - the `ci` row text starts `no CI step — ` and its status is not `not-reached`;
  - the `ready` row is `skipped` and its text does not contain `not reached`;
  - `checks.head` equals the CI row's text.

  Add a retry case as well: a later `PrInProgress` with no `PrOpened` after it should show the ordinary `not reached` rows again. That proves the reading is scoped to the pass.
- **The board-card test, alongside the existing `pr-board` unit cases:** the chips for the same `PrState` include neither `ci ·` nor `ready ·`.
- **`apps/board/unit/history.test.ts`:** cover `RunPrompted` with `for: { _tag: 'Pr', purpose: 'resolve' }`, `'review'`, and `{ _tag: 'Pr', purpose: 'summary', at }` on a PR stream with `attempts: new Map()`. Add an unknown `_tag` that still gives a row. The existing case at `:1001-1007` stays unchanged.

None of this touches IO, so the ratchet is not involved. Everything is checked by `pnpm test` and `pnpm typecheck`; no claim here depends on `pnpm test:integration`. No ADR changes: 0131 already says *"the PR goes to *In review* unfollowed"* (`doc/decisions/0131-a-pr-goes-from-draft-to-merged.md:310-313`), and this change makes the page say the same.
