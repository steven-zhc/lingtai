## 1. The confirmation: gate the team half by `mode` at the condition

Make the change in the condition at `:507`, not in the sentence:

```ts
const unseenUnattended = mode === 'solo' && summary.landsUnattended && at.flags['land'] === undefined
```

`mode` is already in scope (`:259`, `let mode: Mode = at.mode ?? (rawMode === 'team' ? 'team' : 'solo')`). The ternary at `:508-511` uses the same variable. It is also what `init --local` passes in from `runLocalBranch`. The field comment at `:107` says: *"The mode, where the caller already decided it (`runLocalBranch` asks before it makes the branch, 0130 §2)."*

**After this change the `mode === 'team'` branch of `lands` (`:509-510`) can never run. Delete it.** `lands` becomes the solo sentence alone. If the branch were kept, it would be text nothing can print, and a later reader would take it as live.

**A null or unknown mode falls to `'solo'` at `:259`, so it is still confirmed.** That is the safe direction, and it is the one the ticket's *Watch out* protects. Do not write it as `mode !== 'team'`. That also reads safe today, but if a third mode is ever added it would skip the confirmation for that mode without anyone noticing.

The empty-checks half at `:506` is unchanged. A team project with no checks still reaches `asks`, and `asks` then takes its `unseenEmptyBuild`-only arm. That arm already produces *"nothing checks a diff before review"* and nothing else.

## 2. The gutter: add it where the lines are printed, not in the strings

`why` is not only the team drawing. `apps/cli/unit/setup-build.test.ts:775-800` (*"why a default is what it is (#773)"*) uses a fake `ask` that pushes the raw `shape.why` strings. It asserts on `'install: uv sync --frozen — uv.lock is at the root'`. So:

- **The `why` strings stay unprefixed.** Only `liveAsk` (`apps/cli/src/prompt.ts:78`) adds the gutter. This keeps the setup-build tests green, gives the install/build `why` lines the gutter as well (the ticket's *"a later `why` drawing gets the gutter for free"*), and keeps the `QuestionWorld` contract (`question.ts:109-110`) free of rendering.
- **Use clack's own symbol and colour.** Use `clack.S_BAR`, which `@clack/prompts` 1.7.0 exports (`dist/index.mjs:1412`). It is `unicodeOr("\u2502", "|")` (`:27`), so it falls back to `|` exactly when clack's own bars do. That is the *"terminal without Unicode: unchanged"* edge. Colour it the way clack does: `styleText("gray", S_BAR)` from `node:util` (`dist/index.mjs:150`). The prefix is the bar plus two spaces, matching clack's `` `${styleText("gray", S_BAR)}  ` `` (`:352`). For an empty line, print the bar alone, with no trailing spaces.
- **Write the lines to `io.output ?? process.stdout`, not `console.log`.** `liveAsk` already takes `io` for the select. `apps/cli/unit/prompt.test.ts:30-43`'s `terminal()` captures that stream. Writing there lets the *"every `why` line is printed with the gutter prefix"* test use the existing harness with no `console` spy. Strip colour in the assertion: `stripColour` is what `recipe-summary.test.ts` uses.

## 3. Which lines `TEAM_GRAPH` holds

Clack's select draws its own `│` line before `◆/◇  message` (`dist/index.mjs:150`: `` [`${styleText("gray", S_BAR)}`, `${symbol(this.state)}  ${t.message}`] ``). So the empty `│` just above *"Does anyone else work on this repository?"* in the agreed drawing comes from clack. If `TEAM_GRAPH` also ended with an empty line, that gap would be doubled.

The empty `│` at the top does belong to the drawing. Without it, the `main` line would sit directly under the previous prompt's submitted answer.

So `TEAM_GRAPH` is these six entries:

1. `''`
2. the `main` line
3. the `╲ ╱` line
4. the `your branch` line
5. `''`
6. `main only moves through the PR you send.`

Copy the four drawn lines character for character from the ticket, with the leading `│  ` removed, because `liveAsk` adds it. Update the doc comment at `team.ts:27` too: it says *"The four lines"*, and *"(`cli-add.html` A)"* no longer describes what is drawn. The widest line is about 60 columns with the gutter, so it fits the 80-column edge with room to spare.

## Tests

**No existing test pins the team wording.** `grep "nothing reaches main"` finds only `recipe-flow.ts:510`. `add.test.ts:164`'s regex allows `register anyway?` without requiring it, so it stays green. The solo tests in `recipe-summary.test.ts:73-101` must stay green as they are. They are the claim that the solo half did not move.

Put the new cases beside them in that file, using the same harness, with `at({ mode: 'team', ... })`. A given `at.mode` skips the mode, login and personal-branch questions (`:261`), so no `at.team` is needed. The cases:

- **Team with `buildFlags: ['npm test']`:** `index(world.events, CONFIRM) === -1`.
- **Team with no build:** the confirmation contains *"nothing checks a diff before review — register anyway?"* and does not contain `lands on`.

Everything here is unit-level. Nothing depends on `pnpm test:integration`, and there is no log event to read: this is a question's condition and its text. The person-at-a-terminal check in *Done when* stays a person's.
