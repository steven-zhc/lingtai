### `db:bootstrap` is a fix in fewer places than the ticket implies

- **`schemaChecks` gets an options argument.** Add a fifth parameter, `{ checkout }: { checkout: boolean }`, and give it a default so the existing calls keep compiling. `schema()` passes `checkout: !isSea()`. `isSea` is already imported at `doctor.ts:5`, and `:2796` uses it as the binary-or-checkout split. Take the instruction out of `detail` (`:553`, `:562`) and put it in `fix: 'pnpm --filter @lingtai/event-store db:bootstrap'`, only when `checkout` is true. In a binary there is no fix, and the detail's second line says the bootstrap script runs from a checkout.
- **`schema: optimistic concurrency` gets no fix anywhere.** `bootstrap.mjs` only *checks* the unique index (`packages/event-store/scripts/bootstrap.mjs:47-49`, `check("unique (stream_id, version)", …)`). What it applies is `NOTIFY_SQL` (`packages/event-store/src/schema.ts:89-110`), which creates the trigger and the two rules and no index. Offering bootstrap there would be a fix that runs and does not fix anything. That is the case the ticket's *Watch out* row rules out.
- **Bootstrap exits 1 even after it repairs.** It still asserts an `outbox` table and `outbox.payload` (`bootstrap.mjs`: `check("outbox.payload is jsonb", …)`, `check("three tables exist", …)`). #72 dropped that table (`doctor.ts:583-585`). So a `fix` that repairs the rules still ends with `FAIL` lines. This ticket does not fix that. Mention it in the PR as a backlog item, and keep the bootstrap fix: the repair does apply.

### `projections: shape`

- **The fix names only the drifting projections.** Use one `lingtai projection rebuild ${s.projection}` line per shape where `s.drift.length > 0`, joined with `'\n'`. `s.projection` is `projection.name` (`packages/projector/src/shape.ts:177`, `:199`), the same name `PROJECTIONS` (`apps/cli/src/projection.ts:29`) is keyed by. Check `projection rebuild`'s argument parsing to confirm it matches on `.name`.
- **Detail layout.** The first line of `detail` is a count ("2 projections differ from the columns their code declares"). The per-projection `describeShape` text goes on the lines after it.
- **When the shapes cannot be read.** The catch branch gets a title only.
- **When the log predates the Hold event.** `rebuildProjection` refuses first in that case (`projection.ts:78-82`). Then `log: predates the Hold event` is red in the same report, and its own detail says what to do. The rebuild fix is still right: it is the remedy once that other check is clear. Do not try to merge the two rows.

### Detail line shape, and restart

`renderDoctor` shows only `t.detail.split('\n')[0]` in the flat view (`doctor.ts:3169`). The rule for every row touched: line 1 is a sentence that stands on its own, and ADR numbers, `#nnn`, lists and paths go on line 2 or later. Do not change `restart.ts`'s `formatFailures` (`restart.ts:1495`, ``` `  · ${r.name}: ${r.detail}` ```). Changing how restart lays out a multi-line detail is a renderer change and out of scope. The rule about line 1 is what keeps restart's refusal readable.

### Tests

Put them in a new `apps/cli/unit/doctor-titles.test.ts`. Each case drives one warn or fail and asserts `name` (unchanged), `title`, and `fix`, or that `fix` is `undefined` where none is meant. Use one shared helper, applied to every title this file produces:

- under 60 characters;
- no `#\d`;
- no `\b0\d{3}\b` (an ADR number);
- no `\b[0-9a-f]{7,40}\b` (a hash);
- no `/` (a path).

The fix for every per-project row in this list is a real name. `projections: shape`, the only row whose fix carries a name, should be tested with two projections of which only the second drifts, so the test catches a fix line built for every shape.

Then run `pnpm typecheck`, `HOME=/nonexistent pnpm test`, and `apps/cli/integration/doctor.test.ts` on its own (about 40 s, not the 803 s full integration run). Update detail-text assertions where line 1 moved, and do not loosen them.
