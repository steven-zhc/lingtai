# Design: #1010, a runtime's usage limit on the board

## What is already on `main`, which changes the ticket's plan

The ticket says its prerequisites are "not on `main` yet". They are all on `main` now: #994, #995, #1007 (the ceiling), #1008 and #1009 (`05689c67`). Three things follow:

- **`emptyNote` already takes the lock map.** It takes `locksInScope: LockMap` (`apps/board/src/lib/board.ts:523-530`), so the ticket's *if it still takes `pausedInScope`* branch never happens. Add the account case to what is there.
- **The ceiling has landed and goes first everywhere.**
  - On the card, `queuedStanding` checks `ceilingToday` at `board.ts:1779` before the project's pause at `:1788`.
  - In Running, `emptyNote` returns early with its own sentence at `board.ts:532-535`. Keep that early return: the ceiling holds every project, so listing who waits for an account under it would add nothing.
  - In the banner, `bannerRows` (`apps/board/src/lib/locks.ts:112-125`) pushes ceiling, then `control-unread`, then paused. Its comment says *"#1010 adds the account rows after the ceiling."* Put them after `control-unread` (that row is about the ceiling) and before the paused rows.
- **`readProjectLocks` already calls `accountsFor` for every registered project** (`locks.ts:85`). Read `uses` from that map; see the next section.

## The read: `uses` comes from what `accountsFor` already returned

`accountsFor` resolves the project's recipe and returns a map with one key per runtime the recipe uses (`packages/conductor/src/account.ts:110-128`). Its doc says *"The state of each `acct-{runtime}` the project's recipe uses, and no other"*. So `[...accounts.keys()]` already is `runtimesOf(recipe)`, and the loop at `locks.ts:83-88` already has it for every project, held or not.

- Add `uses: ReadonlyMap<string, readonly RuntimeId[]>` to the `ok: true` arm of `ProjectLocks` (`locks.ts:49-58`) and fill it inside that loop.
- Do not resolve the recipe a second time. The ticket's *Cost on every render: one recipe resolution per registered project* is already paid; this adds nothing to it.
- A recipe that does not resolve gives the empty map (`account.ts:104-107`: *"A recipe that does not resolve gives the empty map and not a failure"*). Leave such a project out of `uses` (no entry), as the ticket asks.
- `recipe/[project]/page.tsx:344` also calls `readProjectLocks`. The new field is additive, so that page needs no change.

## One definition of "holding"

`locksOn` keeps returning a passed limit: *"A limit whose `until` has passed is still a lock: lifting it is the guard's"* (`packages/domain/src/locks.ts:51`). The board needs one rule for when an account lock still holds:

- Add `accountsHolding(locks, now)` to `apps/board/src/lib/lock-marks.ts`: the `account` locks with `until > now`, in the order `locksOn` gives them (already sorted by runtime, `domain/src/locks.ts:69`). Put it beside `ceilingToday`, which is the same idea for the ceiling.
- That file's header says the kinds *"add a case beside `isPaused`, never a new parameter"* (`lock-marks.ts:5-7`). This helper follows that.
- The card, the Running line and `emptyHeld` read only this helper.
- The banner alone sees passed locks: it draws them greyed.

## Banner (`bannerRows` and `LockRows`)

**The row.** Add a `BannerRow` member `{ kind: 'account'; runtime; until; untilFrom; said; passed; waiting: string[]; others: { project; runtimes }[] }`. `bannerRows` gains a `now` parameter.

- **Grouping.** Group across `inScope(read.held, scope)` by `lock.runtime`, so there is one row per runtime. `waiting` is the names whose locks contain that runtime's lock.
- **Scope.** With one project selected, `inScope` already narrows it. A project that does not use the runtime has no such lock, so it gets no row. That is the *选 cg* tab, and it needs no extra code.
- **`others`.** Only for *all projects*: the projects in `uses` whose locks hold nothing at `now` (not paused, no `ceilingToday`, no `accountsHolding`), each with its runtimes. Omit the clause when the list is empty.
- **Passed.** `passed = until <= now`. Give the row the class `pbrow passed`, which already exists (`apps/board/src/app/globals.css:3373-3374`). Add no new CSS: the ceiling's passed row uses the same class (`lock-banner.tsx:51-60`).

**Wording.**

- **Time.** Write `until` with the domain's `whenLabel` (`packages/domain/src/locks.ts:96`), not the board's `sinceLabel`; it guards an unreadable date. The `title` is `` `${untilFromWords(untilFrom)} — "${said}"` `` (`domain/src/locks.ts:104`).
- **Runtime name.** Write the runtime as its `RuntimeId`, verbatim: `claude-code limit`, and `claude-code` in every sentence.
  - The mock writes *Claude Code*, but no display name exists in code (the ticket's own evidence), and `lockSentence` already writes `lock.runtime` (`domain/src/locks.ts:128`).
  - The ticket's Done-when sentence for Running already uses `claude-code`.
  - A name table is out of scope.

**The *lift* button.**

- Add `LiftButton({ runtime })` to `apps/board/src/app/pause-button.tsx`, with the same structure as `ResumeButton` (`pause-button.tsx:38-58`).
- Draw it on passed rows too.
- That file is already among `bar.test.ts`'s sources (`apps/board/unit/bar.test.ts:234`), so `bar.test.ts` needs no edit. A new file would need one.

## The action: the core lives in `locks.ts` and the edge in `actions.ts`

Follow `setProjectPaused` / `continueTodayWith` (`locks.ts:160`, `:224`).

**Core: `liftAccountWith(store, runtime: unknown, by)` in `apps/board/src/lib/locks.ts`.** It returns an `Effect` of `ActionResult`, so a unit test can run it against the memory store without touching `actions.ts`, which imports `revalidatePath`.

| Case | Answer | Appends |
|---|---|---|
| `RuntimeId.safeParse` fails (`domain/src/events.ts:140`) | `{ ok: false, detail: 'unknown runtime "claude" — runtimes: claude-code, codex' }`, the CLI's words (`apps/cli/src/account-lift.ts:22-33`) | nothing |
| `appended` | `{ ok: true, detail: "claude-code's usage limit lifted" }` | `AccountLimitLifted` |
| `not-limited` | `{ ok: true, detail: 'claude-code is not at its usage limit — nothing to lift' }` | nothing |

**Edge: `liftAccountNow({ runtime })` in `apps/board/src/app/actions.ts`.**

- It runs the core with `actor()`.
- On either `ok` answer it calls `revalidatePath('/', 'layout')`.
- On a refusal or a throw it does **not** revalidate, so the refusal shown beside the button is not unmounted with its row. That is `continueToday`'s reason (`actions.ts:566-567`).
- `apps/board` is not a package the Effect ratchet counts (no entry in `effect-ratchet.baseline.json`), so a new `async` server action costs nothing there.

## Card (`queuedStanding`)

Add one case after the ceiling (`board.ts:1779-1785`) and before the project's pause (`:1787`): the first lock from `accountsHolding(projectLocks, new Date(now))` gives

- state: `'paused'`
- text: `` `${runtime} is at its usage limit until ${whenLabel(until, now)} — nothing will start` ``
- title: `` `${card.project}'s recipe uses ${runtime}; this card keeps its place` ``

`paused-card` follows on its own: `page.tsx:270` already keys it on `standing?.state === 'paused'`.

## Running line (`emptyNote` / `emptyHeld`)

**New parameter.** Add `uses: ReadonlyMap<string, readonly RuntimeId[]> = new Map()` as the last parameter of both functions. It is not a lock, so the *never a new parameter* rule does not cover it, and only it can name who is taking work. `page.tsx:921-923` passes `read.ok ? read.uses : new Map()`; read it once from the same `readProjectLocks()` that `page.tsx:675` already awaits.

**Order of the sentences.**

1. The conductor-wide line, unchanged.
2. The ceiling's early return, unchanged.
3. If no project in scope has `accountsHolding`, return today's paused sentences byte for byte. `columns.test.ts` pins them.
4. Otherwise build clauses joined by `; `:
   - each runtime: `<names> wait(s) for <runtime> (limit until HH:MM)`;
   - then `<names> is/are paused`;
   - then, with *all projects* only, the projects in `uses` (narrowed to registered names) that hold nothing: `<name> runs on <runtimes> and is taking work`, with several listed and `are`.
   - With one project selected and waiting, the result is exactly `Nothing here yet. lingtai waits for claude-code (limit until 23:00).`

**`emptyHeld`.** It is true when any `accountsHolding` holds the selected project. With *all projects* it is true when no project in scope is taking work; otherwise false, as the paused case is today (`board.ts:561-564`).

## Edges the ticket leaves to the design

- **`others` while a ceiling holds.** It is empty, because the ceiling holds every project, so the clause is dropped. The ceiling's row above already says why.
- **A project whose only lock is a passed account limit.** It counts as taking work on the card and in Running, and is listed as waiting only in the greyed row. This follows the ticket's *marks no card*.
- **`allPaused` / `everyPaused`.** Unchanged: it is about pauses (`lock-marks.ts:50`), and the filter marks only a pause.

## Checks

Everything here is unit-level:

- `locks.test.tsx` (`LockRows` via `renderToStaticMarkup`, plus `liftAccountWith` on the memory store after a `reachAccountLimit` from `@lingtai/conductor`);
- `queued.test.ts`;
- `columns.test.ts`.

The integration half is not needed. The memory-store test checks that `liftAccountWith` appends one `AccountLimitLifted` on stream `acct-claude-code` after a reach, answers `not limited` and appends nothing the second time, and refuses a non-runtime. It does not call `readProjectLocks` or check that the row disappears, nor the actor propagated by `liftAccountNow`.
