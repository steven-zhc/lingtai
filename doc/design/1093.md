# Design: #1093, `board.ts` as Effects

## Where it goes

Three source files change: `apps/cli/src/board.ts`, `apps/cli/src/board-world.ts` and one line pair in `apps/cli/src/cli.ts`. Two tests change, `apps/cli/unit/board.test.ts` and `apps/cli/unit/board-cli.test.ts`. One new test file goes beside them. Two JSON files change: `packages/domain/unit/effect-ratchet.baseline.json` (`apps/cli` is `"async": 303` today, `:2`) and `effect-ratchet.faces.json`.

CLI-01 has already landed in this worktree. `liveBoardRunner` is an `Effect.gen` that does `yield* lift(() => readBoardStatus({ port }, world))` and `yield* lift(() => boardCommand(…, world))` (`cli.ts:725`, `:728-730`). Both `lift(() => …)` wrappers go: yield the Effects directly. `lift` is `apps/cli/src/exit.ts:16`.

## Decisions the ticket leaves open

### 1. `boardCommand`'s error channel is `Effect<number, unknown>`, not `Effect<number>`

Today some rejections leave `boardCommand` and reach `orFailed` (`cli.ts:767`), which prints *(LINGTAI_DEBUG=1 for the stack)*:
- a `tryLock` that rejects (`board.ts:376`);
- a `held.release()` that rejects on a refusal (`:397`, `:412`).

The ticket's edge says *"start and stop fail as today"*. So these calls are `lift(() => …)` and their failure is left in the error channel, not caught.

Only the catches that exist today become `catchCause` (letting an interruption through):
- `holder()` in `stop` (`:515-520`, `:545-550`);
- `serve` in `start` (`:401-416`);
- `readBoardStatus`'s two reads (`:287-297`).

`readBoardStatus` stays `Effect<BoardStatus>`. A throwing `keeper` is a defect there, as it is a rejection today, and `printedBy` squashes it to the same message (`exit.ts:52`).

### 2. The `.catch(() => null)` calls on `answering` stay as `catchCause → null`

Those are `:390`, `:494` and `:522`. The `answering` port is typed never-failing, but the `unread` branch in `readBoardStatus` (`:292-297`) must still be reachable when the port dies. So every call site of `answering` handles a defect, and `boardAtEffect` itself absorbs failures with `orElseSucceed(() => null)`.

### 3. `serve`'s `release` is an `Effect<void>`

Build it as `Effect.promise(() => held?.release() ?? Promise.resolve())` followed by `held = null`, in that order (`:406-409`).

`Effect.promise` turns a rejection into a defect. `Effect.runPromiseWith(context)(release)` then rejects, and `stopOnSignal` swallows that (`:123-125`). This keeps the test *"still exits when the release throws"* (`board.test.ts:469`) green without editing it.

`installStopOnSignal` keeps its `() => Promise<void>` parameter (`:135`). `serveBoardEffect` passes it `() => Effect.runPromiseWith(context)(options.release)`. The ratchet does not count `runPromiseWith` (`effect-ratchet.test.ts:65`, `:366`).

### 4. `serveBoardEffect` takes its IO as a record so the Done-when test can be a unit test

Done-when asks for a unit test in which `importFile` throws. The real path cannot do that in the unit half: it first calls `existsSync(entry)` (`:69-74`), which is the filesystem (0060 §1), and `importFile` is module-private (`:157`).

So export `serveBoardWith(deps)`, with `deps` holding:
- `exists`
- `checkTelemetry` (today's `machineOtlpEndpoint()`, `:76`)
- `portIsFree`
- `importFile`
- `listening`
- `installStopOnSignal`

`serveBoardEffect = serveBoardWith(liveServeDeps)`.

The test injects an `importFile` that fails. It then asserts two things: `process.env.NEXT_MANUAL_SIG_HANDLE` is undefined afterwards, and the injected `installStopOnSignal` was never called. Save and restore `PORT`, `HOSTNAME` and the flag around the test.

This is the unit-level claim that stands in for `integration/board.test.ts`. That file is rewritten to run the Effects, but nothing can run it before the merge.

### 5. Order inside `serveBoardWith` is today's, exactly

1. `exists` fails with today's *no built board at …* `Error` (`:71-73`).
2. `checkTelemetry`, under `Effect.try`.
3. `portIsFree`, lifted. It already rejects with a named `Error` (`:169-175`).
4. Set `PORT` and `HOSTNAME`.
5. Set `NEXT_MANUAL_SIG_HANDLE`.
6. `importFile` then `listening`, wrapped in `Effect.ensuring(Effect.sync(() => delete …))`. The finalizer covers those two steps only, as the `try/finally` does today (`:82-87`).
7. Only then, `installStopOnSignal`.

Map failures to `Error` with `e instanceof Error ? e : new Error(String(e))`. Then `start`'s catch prints `.message` alone through `error`, with no *LINGTAI_DEBUG* line.

`listening` becomes an Effect loop: one socket probe, then `Effect.sleep(100)`, against the same `Date.now() + 60_000` deadline (`:182-197`).

### 6. The tests convert at the fake world, not at 104 assertions

`board.test.ts`'s `world()` (`:23-94`) keeps accepting `async` overrides. Many lines pass them: `:136`, `:156`, `:167`, `:261`, `:303`, `:322`, `:349`, `:358`, `:368`, `:377`, `:396`, among others. Type `over` as a promise-shaped fakes record and convert inside the helper:
- `answering`, `bound`, `serve` and `open` become `(…) => Effect.promise(() => fake(…))`;
- `sleep` becomes `Effect.void`.

`go` becomes `Effect.runPromise(boardCommand(…))`.

A fake that throws is then a defect. Because of decision 2, it lands where a rejection lands today: `:167` *no built board*, `:405` *the lock needs node:sqlite*. `locker` stays promise; it is `@lingtai/env/lock` and is not counted.

The ticket's own new tests use `Effect.fail(new Error(…))` directly in the world, which also exercises the typed path:
- `serve` failing with *no built board at X*: assert exact text on the error stream, `release` called once, exit 1;
- `holder` rejecting `EACCES`: assert `{ unread: 'EACCES' }`.

## Faces and the ratchet

Two entries go in `effect-ratchet.faces.json`. They sort before `apps/cli/src/doctor.ts`: `board.ts`/`boardAt`, then `board.ts`/`serveBoard`. The `why` text is the ticket's.

The face checker allows exactly one statement, one `Effect.runPromise` and one argument (`effect-ratchet.test.ts:209-266`). `serveBoard`'s body therefore has to be the single expression `return Effect.runPromise(serveBoardEffect({ ...options, release: Effect.promise(options.release) }))`. Do not bind anything with `const` first.

The baseline goes to `async: 291`. `run` stays at 6, because a listed face's `runPromise` is not counted.

## Not a change

`stopOnSignal` and its test, `RELEASE_BUDGET_MS`, the `held` module variable, every sentence, and the help text. `stopOnSignal` keeps racing the release against the budget.
