## Design: #1375, the PR pages' trace

### Where the wrap goes: in `promiseStore`'s arrows, not in `readFace`

`readFace` and `readTypesFace` are listed promise faces (`packages/domain/unit/effect-ratchet.faces.json:267-276`). The ratchet only accepts a face whose body is exactly one statement, and refuses anything else: *"A face is exactly `return Effect.runPromise(<call>)` (0101 §6, #790)"* (`packages/domain/unit/effect-ratchet.test.ts:359`). Putting the observer inside `readFace` would turn it into a counted `Effect.runPromise`, and the ratchet would go red. The only way to green it would be to raise the baseline, which is not allowed.

So leave both faces untouched (`packages/event-store/src/store-face.ts:30-32`, `:38-40`). Change only the two lines in `promiseStore` (`store-face.ts:50`, `:52`) so they call one plain, non-`async` helper in the new `observe.ts`:

```ts
// shape, not the diff
read: (streamId, fromVersion) => observedRead(streamId, () => readFace(events, streamId, fromVersion)),
```

`observedRead(streamId, run)` reads the holder and behaves like this:
- **No observer:** returns `run()` itself. Same promise, no extra hop. This mirrors `observedRequest` (`packages/github/src/observe.ts:50-51`).
- **Observer installed:** returns `observer({ kind }, (report) => run().then((events) => { report(events.length); return events }))`. Because `report` runs inside `.then`, a rejected read never calls it. That gives the "absent, never `0`" edge without extra code.

Neither `observe.ts` nor `store-face.ts` gets an `async` function or a new `Effect.run*`. The other faces in the `promiseStore` object stay as they are.

### `kind`: a function in `observe.ts`, not a domain helper

`kind` is `streamId.slice(0, streamId.indexOf('-'))`. If there is no `-`, or the prefix would be empty, it is `'unknown'`. Every stream named in `packages/domain/src` has a short prefix before its first `-`: `pr-{project}-{n}` (`events.ts:2534`), `prj-{project}` (`events.ts:2369`), `acct-{account}` (`account.ts:2`), `pass-{ulid}` (`attempt.ts:2`), `chat-<id>` (`chat.ts:2`), `rcp-<configHash>` (`events.ts:1267`), `ctl-conductor` (`events.ts:1989`).

Do not check the prefix against the ticket's list of eleven. A new prefix should show up as itself, not as `unknown`. Even then it carries no id, because the id always comes after the first `-`. Export `kindOf` so the event-store unit test can pin `ticket-lingtai-32 → ticket`, `ctl-conductor → ctl` and `nodash → unknown` directly.

### The seam file copies `packages/github/src/observe.ts` exactly

- Use the key `Symbol.for('lingtai.event-store.readObserver')` and the same `Holder` type. The doc comment should repeat the reason for `globalThis`: *"Next bundles `instrumentation.ts` apart from the routes — and the one that installs must be the one the requests read"* (`github/src/observe.ts:10-12`).
- Export `setReadObserver`, `ReadObserver`, `ReadInfo` and `kindOf` from `packages/event-store/src/index.ts`. `promiseStore` and `fromPromiseStore` are already exported there (`index.ts:103`, `:108`).
- Add one call to `installTraceSeams` (`apps/board/src/lib/trace-seams.ts:16-32`), shaped like the `github.request` one. The attribute set is `{ 'lingtai.stream': info.kind }`, and `lingtai.count` is set inside `report`.
- Extend the file's doc comment, which today names two seams, to name this one.

### Who is observed, and the one gap to state in the commit

The board's `eventStore` is `promiseStore(deferredEvents(processEvents))` (`packages/event-store/src/index.ts:86`). That is what `apps/board/src/lib/prs.ts:14` imports, and what `readDraftOn` reads through with `store.read(ticketStream(project, issue))` (`packages/project/src/pr.ts:472`). So the expensive read is covered.

The PR count is not covered. `topPrNumber` loops on `store.head` (`apps/board/src/lib/prs.ts:42-49`), and `head` is out of scope. Do not add it. Say in the commit body that the PR count is not shown, so a reviewer does not count it as missed.

### The page loads move into a lib function the test can call

The two server components cannot be rendered in a unit test, and `readPrPage` reaches the process store directly. Add two loaders to `apps/board/src/lib/prs.ts` (or a sibling file), each taking the read as a parameter with the real one as default:

```ts
export const loadPrBoard = (project: string, read = readPrPage) =>
  measure(() => timed('pr.board', () => read(project)), { label: '/pr' })
export const loadPrDetail = (project: string, n: number | 'next', read = readPrDetail) =>
  measure(() => timed('pr.detail', () => read(project, n)), { label: '/pr detail' })
```

- Write them as arrows that return `measure`'s promise. That adds no `async` function and keeps the board's count where it is.
- `Board` and `Detail` call them, destructure `[read, timings]`, and render `<TimingMeta timings={timings} />` the way `/landed` does (`apps/board/src/app/landed/page.tsx:46-57`).
- In `Detail`, the `n === null` early return stays ahead of the load, so that path produces no page span.
- The board unit test passes a stub `read` and finds `page /pr` with `pr.board` as its child. It filters spans by name, as the ticket's *Cost to later tickets* line asks.
- `readPrPage`/`readPrDetail` already turn every failure into `{ kind: 'failed' }` (`prs.ts:140-144`, `:313-316`), so `measure` never sees a throw from them. The page's error rendering does not change.

### The `events.read` test reads through a real `promiseStore`

The memory store does not go through `promiseStore` (out of scope), so a test that reads it directly sees no span. In both new tests, build the store as `promiseStore(fromPromiseStore(createMemoryEventStore()))`. All three are exported (`index.ts:103`, `:108`; `trace-spans.test.ts:3` already imports the memory store).

- **Failure path:** a fake `EventStore` whose `read` rejects, wrapped the same way. `fromPromiseStore` turns a non-`ConcurrencyError` rejection into a defect (`store-face.ts:63-64`), and `readFace`'s `runPromise` rejects with that same defect (`store-face.ts:6-9`). That is what lets the test assert the caller gets the *same* error object.
- **Reset:** each test calls `setReadObserver(undefined)` in `afterEach`, as the existing seam tests do with `setRequestObserver`. A leftover observer on `globalThis` would otherwise reach every later unit file in the run.

### The home page

At `apps/board/src/app/page.tsx:1119`, wrap only the inner call: `await timed('pr.landed-where', () => readLandedWhere(p))`. The `Promise.all` and the `filter` stay as they are.

### What verifies it

Everything here is checked by unit tests: the two seam tests, the span test and the ratchet test.

Nothing in the unit suite checks that the board's real trace shows the ~987 `events.read` spans under `page /pr`. That needs a running board with `telemetry.otlp_endpoint` set. The unit claim that stands in for it is: `readDraftOn` reads through the `EventStore` it is handed (`pr.ts:472`), and the board hands it `eventStore`, which is a `promiseStore`.

No ADR is contradicted. 0101 §6 already limits what a span may carry, and a stream's kind with no id stays within it.
