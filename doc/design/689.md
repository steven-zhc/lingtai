# #689: design note for the `/report` page

## Where it goes

- **`apps/board/src/app/report/page.tsx`**: a server page with `export const dynamic = 'force-dynamic'`, copied from `spend/page.tsx:37`. It reads its filters from `searchParams`, resolves the window, reads the rows, calls `report()` from `@lingtai/conductor/report` and renders. It caches nothing, so a reload is a new read. That settles the ticket's *stale page* edge.
- **`apps/board/src/lib/report.ts`**: three things.
  - The read and the currency check (the next section).
  - `reportQuery(searchParams, now)`: pure, it turns the URL into `ReportInput` minus the rows.
  - The chart geometry: scales, stacks and step paths, as pure functions returning numbers and path strings.
- **Panels:** one component per panel in `apps/board/src/app/report/` (`rounds.tsx`, `survival.tsx`, `landings.tsx`, `spend-days.tsx`, `waits.tsx`, `kinds.tsx`, `top.tsx`, `tiles.tsx`). Each takes the slice of `Report` it draws, so a component test hands it a hand-built slice and asserts on `renderToStaticMarkup` output, as `unit/meter.test.tsx:17` does.
- **Tests:** `apps/board/unit/report-*.test.tsx`. Everything above is unit-level.

## The reader does not exist yet, and #690 needs the same one

`ticket_report` has a fold and no reader:

- #687's note said not to add one.
- `ProjectionStore` has `tasks`, `backlog` and `spend` and nothing else (`packages/projector/src/store.ts:317-332`).
- The fold's row type is private (`ticket-report.ts:86`).
- `report.ts:16` says *"the next ticket's reader maps SQL onto it"*.

This change and #690 (the CLI) are both labelled `lingtai:working`, and both need this reader.

**Decision: put it in `@lingtai/projector`, in the most obvious shape, so that two runs producing it at once conflict in an obvious way.**

- Add `ticketReport(query: { project?: string }): Promise<ReportTicketRow-shaped[]>` to `ProjectionStore`, beside `spend` (`store.ts:332`). Implement it in `postgres.ts` (next to `:372`) and `sqlite.ts` (next to `:724`).
- A missing table is `[]`, not an error, as `spend` already does it (`postgres.ts:396`: *"A database no projector has ever started has no table, and that is no spend rather than a failure"*).
- Add `readTicketReport(options)` beside `readSpend` (`spend.ts:318`).
- Export both from `packages/projector/src/index.ts:61-68`.
- Declare the row type in projector as `TicketReportRow`, with exactly the fields of `ReportTicketRow` (`packages/conductor/src/report.ts:17-33`). Leave out `claims`, `rounds` and `open_intervals`, as #688's note says. Conductor's type then accepts it structurally, and projector does not import conductor (the dependency runs the other way, `packages/conductor/package.json:53`).
- Filter by project only; no window in SQL. Placement needs every row's `passTimes`, and that logic belongs to `report()` (#688 note, *Placement*). There is one row per ticket, so the table is small.

**The SQL can only be checked in the integration half.** `packages/projector/test/contract.ts` runs against a real SQLite file and Postgres, which is out of reach inside a pass. The unit-level stand-in:

- Write a pure, exported `toTicketReportRow(record)` in `ticket-report.ts`. Both stores call it.
- Unit-test it on both shapes a driver returns: jsonb as an object (Postgres) and as a JSON string (SQLite), and `bigint` as a string. Reuse the fold's `json` helper (`ticket-report.ts:106`).
- Add the contract case to `test/contract.ts` anyway, so the integration run after the merge covers the SQL.

If #690 lands first with its own reader, use that one and delete this one. Two readers of one table is the outcome to avoid. Expect a merge conflict in `store.ts`, `postgres.ts`, `sqlite.ts` and `index.ts`, and resolve it by keeping one.

Spend comes from `readSpend({ project, since: window.from })`. `report()` drops rows at or after `window.to` itself (`report.ts:184`). Do not pass `ticket`: the window's spend covers every run in the window, whatever its ticket (0123 §3).

## A projection behind: fold both to the head first, and say by how much

The board holds no projector of its own. `currentSpend` runs the fold to the head before reading and keeps the lag (`apps/board/src/lib/spend.ts:215-235`, citing *"a table nobody follows is frozen money"*).

- Write `currentReport()` in `lib/report.ts` with the same shape, run once per projection: `createProjectionRunner({ projection: ticketReportProjection })` (`ticket-report.ts:494`), then `spendProjection`, run concurrently.
- Return `{ tickets, spend, currency: { ticketReport, spend } }`, each currency a `SpendCurrency`-shaped `{ lag, error? }` (`spend.ts:192`).
- The page's bar carries one chip for the pair, worded like `spendChip` (`spend.ts:238-255`):
  - `current` when both lags are 0;
  - `behind N` naming which projection is behind;
  - the repair command in the title: `lingtai projection rebuild ticket_report` or `spend`, whichever failed.

  This is the ticket's *says how far* edge.
- **Running a fold beside the daemon's own** is what `currentSpend` already does on every board render. 0022's two projectors on one log converge, so nothing new is needed for *two runs at once*.
- **A read that fails** must not become a 500. The page renders its bar and filters, puts one sentence in place of the panels (*the report could not be read: …* plus the rebuild command), and keeps the chip, as `readDayReading` never throws (`lib/day-spend.ts:40-50`).

## Filters are the URL, and the form is a plain GET

There is no client state. A reload, a shared link and the back button all work, and the server reads the URL.

- `?window=today|7d`. The default is `7d`, which gives the charts seven bars.
- `?from=YYYY-MM-DD&to=YYYY-MM-DD` for a range. If both forms are present, the range wins. The CLI refuses that combination (0123 §6), but a URL has nobody to refuse it to. A date that does not parse falls back to `7d`, and the filter line says it did.
- `?kind=…`, repeatable. **An empty `kind=` means unclassified.** `report()` never maps a null kind to a string, because a recipe could name a kind `unclassified` (#688 note, *Per kind*). A GitHub label cannot be empty, so the empty string is safe. No `kind` param means every kind (`kinds: null`).
- `?project=`, carried from the board's filter exactly as `/spend` carries it (`page.tsx:660`). The `← Lingtai` link carries it back.
- `?sort=cost` switches §4's ordering (`sortBy`, `report.ts:181`).
- The kind chips list the distinct kinds over the project's rows, in `report()`'s order: alphabetical, with null last as *unclassified* (`report.ts:190-195`).
- `now` is `new Date()` once per request and goes to `resolveWindow` (`report.ts:49`). Pass it as an argument so the pure part stays testable.

## Charts: inline SVG, server-rendered; the hover is `<title>`

- The mockup's tooltip is JavaScript: a fixed `.tip` driven by `data-tip` (`doc/decisions/0123/Report.html:88,252`). Here each column or point is a `<g>` with a transparent hit rect and an SVG `<title>` holding the exact figures.
  - That is a hover on every chart with no client bundle, and a test can read it from static markup.
  - Do not add a client island for a styled tooltip. It would put each figure in two places.
- Every chart has an HTML legend above it and one y-axis.
- The survival curve is a step line from 100%, with each step labelled with its `atRisk` (`SurvivalStep`, `report.ts:125`).
- The wait × cause table is an HTML table, not SVG. Shade it with `color-mix` on `--accent`, as the mockup does (`Report.html:297`). The null-cause column is headed *no triage cause*, because it also holds waits that were triaged without an advised cause (#688 note, *Wait × cause*).
- Money is three parts and a count, never one number: reported, `~$x est.`, `n unknown`, as `dayReading` words it (`lib/day-spend.ts:28`). The spend tile is `report.spend.total`, which is already the sum of the day cells (#688 note).

## Colours

- Copy the mockup's four series tokens into `globals.css` as `--s1`–`--s4`, for both themes (`Report.html` declares them: light `#2a78d6 #199e70 #6250d6 #d55181`, dark `#3987e5 #1baf7a #9085e9 #e87ba4`). The board has no series tokens today (`globals.css:11-34` holds only the state hues: `--signal` amber, `--pass`, `--fail`, `--held`).
- **Spend by purpose has five purposes and four colours.** Fold Triage and Discussion into one series, as the mockup does (0123 *Mockups*: *"folds the Triage and Discussion purposes into one series to keep the chart to four colours"*). The `<title>` still lists the two apart.
- **Kinds are unbounded, so they cannot each get a colour.** The first four kinds in `report()`'s order take `--s1`–`--s4`. Any further kind and *unclassified* share one grey series (`--muted`), named *other* in the legend, with the exact split in the hover.
  - **Do not use `kindDot`** (`lib/kind-colour.ts:69`). It turns a repository's GitHub colour into a board colour and refuses only amber (`:41-42`), so a green or red label would reach a chart. That is exactly what the ticket's *Watch out* forbids.
- **The test:** read the report's components and the CSS rules they use, and assert that none of them names `--signal`, `--pass` or `--fail`. Do not test hues. `#199e70` is the mockup's validated colour, and a hue band around `--pass` could catch it.

## The top bar: inside the reading, not a fifth object

The board's bar is four objects by rule:

- the-bar.md: *"A chip is not free, and the row is the unit. Anything added here has to be argued against the four that are left"*;
- `projects.test.tsx:159` asserts *"leaves the four what they were, in the code and in the doc"*.

The reading is already the route to `/spend` (`page.tsx:658-675`).

- Make `report` a second link inside the reading, carrying `?project=`. `#216` set the precedent: its `+` was added as a tab inside the filter, and the row still counted four (the-bar.md, the `#216` paragraph).
- Add a paragraph to the-bar.md making that argument in the same words.
- `bar.test.ts`'s class reader (`:263-266`) must still see every bar class. If the link gets a class, add it there.
- Do not give it amber (`bar.test.ts:249`).

## Empty window, phone width, docs

- **An empty window:** `report()` already returns `[]` for the curve and the kind table, and zero day buckets (#688 note, *An empty window does not divide*). Each panel checks its own slice and renders one sentence, never an empty axis:
  - *no landings in this window*;
  - *nothing spent in this window*, used only when every day has zero cents **and** an `unknown` of 0. Unknown runs on a day are not *nothing spent*.

  A tile whose figure is `null` shows `—` with a title saying *no landed tickets*.
- **Phone width:** the panel grid collapses to one column under a media query. The tiles wrap.
- **The top eight:** each row links to `/task/${encodeURIComponent(ticket)}`, as `backlog/page.tsx:33` does, and shows `TopTicket.sentence` unchanged. The page writes no sentence of its own (0123 §4).
- **Docs:** add a section to `doc/operating.md` beside *Running work* (`:811`). It covers:
  - what the page reads;
  - that the window's spend and a ticket's own cost are different figures (0123 §3);
  - what the currency chip means and the two rebuild commands.

## Edges not covered above

- **A restart, a pause, a retry:** none apply. The page writes nothing, and a fold interrupted mid-render resumes from its checkpoint on the next read.
- **Cost to later tickets:** the reader's row type is the contract between the fold and `report()`. A column added to the fold is invisible until the type is extended, and then it is a typecheck error, not a silent zero.
