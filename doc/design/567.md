# Design note — tool-enabled Codex triage

Make the execution route explicit in `triage:`: Codex CLI uses a disposable checkout, while an explicit model-only selection retains the existing API route. Claude keeps its current path. Today `waitTriage` always requests `tools: 'none'` (`apps/cli/src/triage.ts:561`), and that option sends Codex to `codex_text` rather than the CLI (`packages/agent/src/runtimes.ts:116-142`). Update Doctor’s triage check with the selection: it currently says, “The same factory used at dispatch; never probe the Codex CLI as a substitute,” and checks only `codex_text` (`apps/cli/src/doctor.ts:2072-2089`, `apps/cli/src/doctor.ts:2174-2182`).

Put checkout acquisition and release behind a triage-specific port in `apps/cli/src/triage.ts`; do not reuse Discussion’s `prepare`, whose contract is “an empty directory and a settings file that denies everything” (`apps/cli/src/discuss.ts:102-121`). Copy the required commit from the existing bare mirror into a **private temporary Git repository**, cut a detached worktree from that copy, and remove any remote before launching Codex. This matters because the standard Codex adapter grants write access to a linked worktree’s Git stores (`packages/agent/src/codex.ts:793-812`, `packages/agent/src/codex.ts:851-890`): linking triage directly to the managed mirror would let ordinary Git tools change shared objects or refs. Give Codex an unhooked settings file, a filtered process environment with no daemon credential explicitly supplied, and a private `HOME`. The checkout, its Git metadata, and any edits disappear together; no pass hook, merge lane or push step runs.

Choose the commit from the saved run’s `RunProducedDiff.headSha` or `RunProposedCompletion.headSha`; `headOf` expressly says “the log and not the branch ref” (`apps/cli/src/discuss.ts:144-160`). Use the resolved base only when a successful run-stream read establishes that no head was recorded. `gatherEvidence` currently turns a failed run-stream read into `[]` (`apps/cli/src/triage.ts:371-379`); change that path to a failed triage, and refuse dispatch if the chosen commit cannot be checked out. Keep the existing brief, parser, conflict classification and event contract. `WaitTriaged` already records the wait, attempt and head, while each paid call records `RunSpent { for: Triage { waitId } }` (`apps/cli/src/triage.ts:588-624`, `apps/cli/src/triage.ts:725-762`, `apps/cli/src/triage.ts:799-818`).

Cleanup must follow **process-tree termination**, including tool subprocesses, on success, timeout, abort and crash. The Codex adapter currently resolves its timeout or abort outcome immediately after signalling the child (`packages/agent/src/codex.ts:1165-1195`); returning that outcome is therefore insufficient proof that the checkout is safe to delete. Re-read the ticket stream before publishing advice and, after a version conflict, confirm the same `waitId` is still current. Record spend for a call that ran, but turn a cancelled or stale result into failure rather than advice for a later wait. The existing start path already re-reads after a version conflict because “a person’s `WaitResolved` or another triage” may have won (`apps/cli/src/triage.ts:496-525`).

Pass the configured wall limit to the runtime. Describe turns and dollars as observed or checked between calls, not hard limits on one Codex CLI process: its capability declaration says `enforces: ['wall']` and explains that the CLI has no turns or USD stop flag (`packages/agent/src/codex.ts:103-137`). Its receipt reports tokens but `costUsd: null` (`packages/agent/src/codex.ts:1211-1253`). Likewise, state the read boundary plainly: the Codex CLI can read other host files by absolute path; the runtime’s own measured comment says its sandbox supplies a *write* boundary while retaining shell and host-file reads (`packages/agent/src/runtimes.ts:95-114`). A private `HOME` and filtered environment reduce what is handed to the process, but do not make those files unreadable.

Use unit tests for route selection, head versus base selection, failed run-stream reads, stale-wait publication, limit reporting and cleanup ordering. Add an isolated integration test with a stand-in Codex process to prove shell tool use, the selected checkout contents and disposal of an edit. That process and Git test belongs to the integration half, which takes 803 seconds and cannot be the only pre-merge check; the unit tests must establish the selection and lifecycle decisions the build step can run.

This execution shape supersedes ADR 0118 §3’s statement that triage runs “reading the mirror, with no tools” (`doc/decisions/0118-a-hold-explains-itself.md:338-340`). Leave that accepted decision untouched in this ticket, as requested; its documentation change needs a superseding file in the separate ticket.
