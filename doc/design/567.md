# Design note — disposable Codex CLI triage

Add an explicit `triage.tools: full` recipe choice for Codex. Keep the current default, `none`, so existing Claude triage and the separately billed Codex model-only route remain selectable. Dispatch must use that choice; today `waitTriage` always requests `tools: 'none'` (`apps/cli/src/triage.ts:559-562`), and the runtime table sends that Codex request to `codex_text` while a full request selects the CLI (`packages/agent/src/runtimes.ts:116-142`). Update the triage readiness check for the chosen route: its present comment calls it the “separately billed, tool-free route,” and it constructs only the no-tools runtime (`apps/cli/src/doctor.ts:2072-2088`).

Give the full-tools path a **private Git repository as well as a disposable checkout**. Copy the needed commit from the managed bare mirror into a temporary repository, detach a worktree at that exact SHA, and remove the copy and worktree after the call. Do not attach Codex directly to the managed mirror: the normal Codex adapter grants a linked worktree write access to its Git directory and the common `objects`, `refs` and `logs` stores (`packages/agent/src/codex.ts:793-850,851-890`). The pass provisioner is also the wrong operation here: its documented purpose is to cut an agent branch, fetch the mirror, and plant an environment file (`packages/repo/src/worktree.ts:127-150,194-210`). Select the attempt’s saved head from the run log, falling back to the base only when no head was recorded. The `headOf` comment says “`RunProducedDiff` is the attempt saying it produced something” (`apps/cli/src/discuss.ts:144-152`); `gatherEvidence` likewise says a head that the mirror cannot resolve must not be read as “the attempt committed nothing” (`apps/cli/src/triage.ts:409-418`). If that recorded head cannot be checked out, fail triage rather than silently inspect the base. The event and field to inspect for an actual attempt head are `RunProducedDiff.headSha`.

Run the standard Codex CLI against that checkout with an unhooked settings file outside it, the existing filtered process environment, and a private home that contains no daemon configuration or GitHub credentials. Give the temporary repository no push destination or credential-bearing remote. This is a triage call, so it needs no pass hook, commit, merge, or push path; the runtime request already accepts a checkout `cwd`, filtered `env`, limits and an abort signal (`packages/agent/src/runtime.ts:71-77,119-131`). Its unhooked settings shape is supported by the Codex adapter’s comment: an unhooked reviewer’s settings are `{}`, with no hook overrides (`packages/agent/src/codex.ts:721-725`). Keep the checkout’s lifetime inside `try/finally`, including preparation failure and cancellation, and make removal failure visible without replacing the call’s original failure.

Use the existing evidence brief and `parseTriage` result contract, but give the full-tools Codex call one answer opportunity with instructions to inspect the checkout directly; the mirror-served `read` rounds belong to the no-tools path (`packages/conductor/src/triage.ts:147-160,283-303`; `apps/cli/src/triage.ts:641-675,725-735`). Preserve the existing `TriageStarted`, per-call `RunSpent`, and `WaitTriaged` fields and spend recording (`apps/cli/src/triage.ts:500-507,588-625,799-817`). Before publishing advice, reread the ticket stream and require the same current `waitId`; the present final append retries against the latest version but does not check the wait lifecycle there (`apps/cli/src/triage.ts:784-817`). A stale or aborted call may record its spend, but cannot publish advice for a later wait.

Pass the configured wall, turns and USD values to Codex and report their enforcement accurately. The adapter declares `enforces: ['wall']`; its comment says Codex has no turns or USD stopping flag and that counting reported turns is not enforcement (`packages/agent/src/codex.ts:103-137`). Retain the caller’s checks before any further paid call and record unknown dollars as unknown; the Codex adapter’s header says its output carries tokens but “no dollars” (`packages/agent/src/codex.ts:20-25`).

Add a unit check for mode selection, exact SHA selection, stale-wait refusal, cleanup on each outcome, and the full-tools runtime request. Add the requested isolated integration test with a local repository and Codex stand-in to prove a shell tool can read the selected head or base and that an edit disappears with the temporary checkout. That integration test runs after merge: this project’s build gate runs `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test`, so the unit checks are the pre-merge claim. This execution shape supersedes ADR 0118 §3’s accepted statement that daemon triage runs “off the pass, without the lock, reading the mirror, with no tools” (`doc/decisions/0118-a-hold-explains-itself.md:338-340`). Record the changed decision in a superseding ADR under its separate documentation ticket.
