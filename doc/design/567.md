## What is still missing after the merge

I checked the branch against the three `Done when` lines the operator added on 2026-10-24.

### 1. `CODEX_HOME`: the code is right, but there is no unit test

`agent/567:apps/cli/src/triage-checkout.ts` sets `CODEX_HOME` to `process.env.CODEX_HOME ?? $HOME/.codex` and copies nothing. Its comment reads *"Codex rotates its refresh token in place … The login directory itself is shared; everything else about the home is private."* The only test is `apps/cli/integration/triage-checkout.test.ts:79`. That is integration, because `prepareTriageCheckout` runs `git` before it returns `env`. So the unit half pins nothing.

Fix it this way:

- Move the env construction out of `prepareTriageCheckout` into a pure, exported function in the same file. The shape is `triageCheckoutEnv(processEnv, privateHome): Record<string, string>`, returning `{ ...runnableEnv({}), HOME, CODEX_HOME, GIT_CONFIG_NOSYSTEM }`.
- Add a unit test in `apps/cli/unit/` with three cases:
  - an explicit `CODEX_HOME` is passed through unchanged;
  - with no `CODEX_HOME`, the result is `<real HOME>/.codex`, not anything under `privateHome`;
  - no `LINGTAI_*` key survives, which is the *no daemon credential* half.
- Rewrite the comment where `CODEX_HOME` is set so it says what the decision asks for: the Codex sign-in is the user's own CLI login, not a daemon credential. Point to `packages/agent/src/codex.ts:795` (*"a per-run `CODEX_HOME` holding only our hooks is a run that is not signed in"*) as the same reasoning.

Leave the `prefix.test.ts` `NOT_OURS` entry for `CODEX_HOME` from `6479f943` in place.

### 2. `stopRunProcesses`: half-done, and there is no unit test

In `agent/567:packages/agent/src/codex.ts`, two of the three call sites handle a throw. The kill path around line 1315 turns it into `failure.detail: '…process cleanup incomplete: …'`. The `close` path around line 1367 does the same through `cleanupFailure`.

The `exit` handler around line 1357 does `stopRunProcesses(processMarker, seen).catch(() => {})`. That is caught but not reported. The decision says *caught and reported*, so the swallow is not acceptable. `close` runs afterwards and scans again, so the outcome is still correct. But a failure seen first on `exit` leaves no trace anywhere. Replace the empty catch with a `trace.note('cleanup', …)`, the same trace the receipt line already uses, and leave the outcome to `close`.

The real gap is the unit test. `stopRunProcesses` is module-private, it calls `ps` or `/proc`, and nothing in `packages/agent/unit/codex.test.ts` makes it throw. Give the kill and close paths a seam: a `stopRunProcesses` override on whatever options object `run()` already takes for tests. If there is none, use a module-level injectable. Then add unit tests asserting that a rejecting override:

- ends the run with `failure.kind: 'crash'` and a detail containing `process cleanup incomplete`;
- never produces an unhandled rejection. Use vitest's `unhandledRejection` capture, or `process.on('unhandledRejection')` for the duration of the test.

The triage side of the contract already has its unit test. *"keeps the checkout when the runtime could not confirm its tools stopped"* (`unit/triage.test.ts:378`) depends on that exact detail string through `outcome.failure?.detail.includes('process cleanup incomplete')`. So the new codex test also pins the string triage depends on. Say so in the test name.

### 3. The checkout is kept on purpose when tools may remain

The branch's `finally` around `triage.ts:816` keeps the checkout and logs, rather than deleting it, when `toolsMayRemain` is set. That matches the ticket's *cleanup waits for the Codex process and its subprocesses to stop before deleting*. A kept directory under `tmpdir()` is the honest failure: the alternative is deleting files out from under a live tool. Do not "fix" it into an unconditional `rm`. The `WaitTriaged` for that attempt must still be `TriageFailed`. To check after a run, look at `WaitTriaged.result._tag` for the `waitId` together with the `RunSpent { for: Triage { waitId } }` row.
