## The anchor is one predicate, written once per dialect

Replace `EPOCH_SQL` with a function that returns an `EXISTS` over `events`, given the four SQL expressions to compare:

```
EXISTS (SELECT 1 FROM events e
        WHERE e.stream_id = <sid> AND e.version = <v> AND e.seq = <seq> AND <ms(e.at)> = <at>)
```

`UNIQUE (stream_id, version)` already indexes this lookup (`sqlite.ts:108`; `contract.prisma:51`). Use the predicate in four places:

1. **`latest`**: one `SELECT … FROM stream_snapshots s WHERE <key> AND ANCHOR(s.stream_id, s.stream_version, s.last_seq, s.last_at)`. There is no read before it, and the `current === null` early return goes. Keep `ensure()`.
2. **`put`'s insert guard**: `INSERT … SELECT $1…$7 WHERE ANCHOR($1, $4, $5, $6)`, which checks the incoming anchor in the same statement, as `:224` does today.
3. **`put`'s upsert condition**: `WHERE stream_snapshots.stream_version < excluded.stream_version OR NOT ANCHOR(stream_snapshots.stream_id, stream_snapshots.stream_version, stream_snapshots.last_seq, stream_snapshots.last_at)`. This replaces `OR epoch <> excluded.epoch` (`:232`).
4. **The `'kept'` statement** (`:250-256`) is still a single `SELECT`. It requires all three of:
   - a stored row at `stream_version >= $v`;
   - the stored row's anchor holds;
   - the incoming anchor holds.

   It needs the third condition because of a race: when the insert selected nothing, the incoming anchor was missing at that instant. A later newer row must not turn that refusal into `'kept'`. The existing unit case at `unit/snapshots.test.ts:75-100` pins exactly this, and it keeps working with the same `INSERT INTO stream_snapshots` stub. Anything else throws the replacement for `staleEpochError`, for example `anchorNotInLogError(snapshot)`. The message names `keyName` (`:144`) and the anchor (`version`, `seq`, `at`), and says that event is not in this log. Don't read anything else to build the message.

## Time: `last_at` is ISO text in both dialects

Store `last_at` as `lastAt.toISOString()` in a `TEXT`/`text NOT NULL` column in both DDLs. Bind it as that string in both. `parseRow` then has one path: `new Date(text)`, and it refuses an `Invalid Date` with `bad('last_at …')`, the way the integer columns are refused at `:161-163`. There is no `Date` to `pg` driver round trip. That matters because `ticket-sql.ts` warns *"A `timestamptz` column comes back a `Date` from `pg` and ISO text from SQLite"*.

The ms comparison inside the predicate:

- **Postgres:** `date_trunc('milliseconds', e.at) = (<at>)::timestamptz`. `date_trunc` truncates, as `parseTimestamptz` does when it builds the envelope's `Date` (`unit/timestamptz.test.ts:13`: `.201465` becomes `.201Z`), so both sides drop the same digits. Never compare `e.at = …` directly. That is the ticket's silent-failure trap.
- **SQLite:** plain text equality, `e.at = <at>`. The log only ever writes `at` by `strftime('%Y-%m-%dT%H:%M:%fZ', 'now')` (`sqlite.ts:107`; the insert at `:200` names no `at`), and that is character-for-character `toISOString()`'s millisecond form. Say this in a comment beside the predicate. If an archive restore ever writes `at` in another form, the mismatch costs a reduce from version 1, never a wrong state.

`validateSnapshot` refuses a `lastAt` that is not `instanceof Date` or whose `getTime()` is `NaN`. It throws a `RangeError`, matching its siblings.

## Memory store

`latest` and `put` look up `events.all().find(e => e.streamId === s.streamId && e.version === s.streamVersion)` and compare `seq` and `at.getTime()`. Apply the same three rules as SQL: refuse when the incoming anchor is missing, replace a stored row whose anchor is missing, and return `kept` only when both anchors hold and the stored version is ≥ the incoming one. Add a test-only `plant(snapshot)` that sets the row without any check (see the next section).

## The contract has to snapshot a real stream, which it does not do today

Today a snapshot's `streamId` (`sid`) has nothing to do with the stream the harness appends to:

- The memory harness appends `ticket-mem-${n}` but snapshots `s-1` (`unit/snapshots.test.ts:13-16`).
- The Postgres harness appends to `id` but snapshots `sid` (`integration/snapshots.test.ts:40-42`).
- `snap()` invents `streamVersion: 3, lastSeq: 12n` (`snapshot-contract.ts:27-29`).

An anchor makes all of that refused. Change the harness to this:

- `append(): Promise<Envelope>` appends one event to the harness's own `sid` at the next version and returns the stored envelope. Use the store's `RETURNING`/`read` result, never a `Date` the test made, so `at` is exactly what a real reader sees.
- `snap(h, env, over)` builds `streamVersion`, `lastSeq` and `lastAt` from `env`.
- `plant(snapshot): Promise<void>` writes a row bypassing the anchor. For SQLite and Postgres it is a raw `INSERT INTO stream_snapshots` after one `latest` has made the table, as `unit/snapshots.test.ts:62-69` does now. For memory it is the store's `plant`.

  This is how Postgres gets a stale row without emptying `events`. Its append-only rule blocks `DELETE` (`schema.ts:104-105`), and the shared test database must not be emptied (`integration/snapshots.test.ts:5-6`).

The stale-anchor cases use `plant`, so all three stores run them:

- a version past the stream's end;
- the right version with a wrong `seq`;
- the right version and `seq` with `at` off by 1 ms.

For each one, `latest` is `null`, and a `put` from a real envelope at a **lower** version is `'written'`.

The existing "void across a reset" case stays for the owned logs. Memory and SQLite still emptied with `empty()` keep counting `seq` (`test/memory.ts:83-87` says so for memory), so the re-appended event differs by `seq` even when it lands in the same millisecond. Don't write a variant that also resets the sequence: it would turn on the clock and flake. "Refuses a put whose anchor is not in the log" uses a real envelope with `lastSeq + 1000n`. Delete the empty-log epoch case (`:79-93`) and the epoch-specific SQLite case (`unit/snapshots.test.ts:41-54`). Re-express the latter as "a writer holding a pre-reset anchor cannot replace the post-reset row" on SQLite with `DELETE FROM events`.

## Postgres-only additions in `integration/snapshots.test.ts`

- In `beforeAll`, run `drop table if exists stream_snapshots` through `directPostgresUrl()`. This handles a #868 table with `epoch NOT NULL`. The production DDL gets no migration branch.
- **Sub-millisecond case:** insert one event with raw `pg` with an explicit `at = '2026-11-04 12:00:00.123456+00'`. The append-only rules block only `DELETE`/`UPDATE`. Assert that `at::text` really carries `.123456`, so the case cannot pass vacuously. Then `store.read(id)` the envelope, `put` from it (`'written'`), and check that `latest` is non-null. Add the stream id to `created` so that `cleanupStreams` (`test/support.ts:79-91`) removes it.

## What can be checked inside the pass

`pnpm test` runs the contract on memory and SQLite only. The Postgres predicate, `date_trunc` included, is first exercised by `pnpm test:integration` after the merge. To stand in for that, export the dialect's predicate builder and add one `unit/` assertion that the Postgres text contains `date_trunc('milliseconds', e.at)`. It is cheap, and it fails if somebody "simplifies" the comparison back to the silent never-match.
