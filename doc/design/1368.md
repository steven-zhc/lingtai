The fix belongs entirely in `apps/board/src/app/globals.css`, lines 3479–3483. No TSX change is needed.

**A second page uses this rail, and the fix covers it automatically.** The ticket only mentions `pr-columns.tsx:54`. But the PR detail page draws the same rail: `apps/board/src/app/pr-detail.tsx:148` `<ol className="pr-rail prp-tickets">` with `:151` `<span className="pr-dot" …/>`. The only rule on `.prp-tickets` is `globals.css:3434` `{ max-height: 18rem; overflow: auto; }`, and it changes neither the padding nor any `left`. So the misplaced dot appears on `/pr/…` detail pages too. Writing the fix on `.pr-rail` / `.pr-dot` corrects both pages. Check both by eye, not just the card.

**Put the padding in a custom property as well, not only the line's centre.** The dot is positioned inside `.pr-slip`, which starts after `.pr-rail`'s `padding-left` (`:3479` `padding: 0 0 0 1rem`). So the dot's `left` depends on three numbers: the line's centre, the rail's padding and the dot's own width. Make the padding a second custom property on `.pr-rail` (e.g. `--rail-pad: 1rem`) and use it in both the `padding` shorthand and the dot's `calc()`. Otherwise a later change to the padding moves the dot off the line again, which is the failure the ticket's Watch out row describes. The line's centre gets `--rail-x`:

- line: `left: calc(var(--rail-x) - 1.5px)`, half of the line's `width: 3px` (`:3480`)
- dot: `left: calc(var(--rail-x) - var(--rail-pad) - 4px)`, half of the dot's `width: 8px` (`:3482`)

Custom properties inherit, so `.pr-dot`, a descendant of `.pr-rail`, can read both values with no extra plumbing. Keep `--rail-x` at the line's current centre, `0.3rem + 1.5px`, so the line itself does not move; only the dot moves, about 3px to the right. If you would rather write the half-widths as properties too (`--rail-w`, `--dot-size`), that is fine but not required. The Done-when asks that there be no free-standing number for either `left`, and a half-width written beside the `width` it halves meets that.

**`.pr-slip.more` needs no change.** It has no dot (`pr-columns.tsx:63` renders no `.pr-dot`), so nothing there has to line up with the line.

Nothing in the unit suite checks pixels, and `pnpm test` will not see this change. The only real check is looking at it, on both pages, at 100% and 150% zoom.
