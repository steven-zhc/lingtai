# Design: #1324 — `lingtai add` / `init --local` ask solo or team

#1306 has landed in this worktree. Use what it built and add nothing beside it:
- the branch-name check is `branchNameRefusal` (`packages/recipe/src/branch-name.ts:10`), which returns the reason or `null`;
- `modeOf` / `branchOf` / `branchKeyOf` are at `packages/recipe/src/settings.ts:254-272`;
- the resolve already refuses `mode: team` with no `branch.personal`, a `branch.personal` git would not accept, and one equal to `branch.main` ignoring case (`packages/recipe/src/resolve.ts:419-438`).

The question's own refusal must say the same thing in its own words, so call `branchNameRefusal` and do the `toLowerCase()` comparison the way `resolve.ts:433` does. Don't write a third copy.

There are four decisions the ticket does not make. Each is below.

## 1. Where the login goes, and `take: mine` with it

A login alone filters nothing. `assigneeSkip` returns early on `take === 'all'` (`packages/conductor/src/discover.ts:285-286`), and `AssigneeRule.take` defaults to `'all'` (`packages/recipe/src/recipe.ts:1172-1176`). 0130 §3 says *"Team mode takes `mine`"*, so a GitHub team add writes **`{ login, take: 'mine' }`**. Writing only `login` gives a team project that takes every issue, and nothing would say so.

Write it **where `assigneeOf` reads**: `takeAt(recipe)?.assignee ?? recipe.runtime.assignee` (`settings.ts:404-406`). Copy the pattern of `kindsChanges` (`packages/recipe/src/answers.ts:151-162`), whose comment gives the reason: *"a recipe that declares its queue at `claim` would take a `source.kinds` write and keep running on the old list without a word."* Add an `assigneeChanges(rule, rawClaim)` beside it in `answers.ts`:
- if a `steps.claim` entry has a `queue:`, rewrite that entry's `assignee`;
- otherwise write `runtime.assignee`.

The preset's `claim` is `[]` (`packages/recipe/src/presets.ts:52`), so a new recipe ends up at `runtime.assignee`.

**A local team project writes no assignee.** `AssigneeRule`'s refine refuses `take: mine` without a login (`recipe.ts:1179-1182`), and a local project has no login to give. An absent rule selects every ticket (`settings.ts:420-425`), which is what 0130 §3 says *mine* means on the local store. No refusal of `take: all` in a team recipe exists yet (resolve.ts has none), so this passes today. Whoever builds that refusal must exempt a local project. Say this in a comment at the write.

## 2. On a local project, mode and personal are asked before the branch is made, not inside `askRecipeEffect`

The local path makes its branch **before** `askRecipeEffect`, and on purpose. `first-project.ts:828-829` says: *"before `askRecipe`, whose trial build cuts from a mirror of this checkout at `base`."* The ticket says to make the personal branch *"exactly where `:829-846` makes `lingtai-base` today"*. That rules out also asking mode inside `askRecipeEffect`, because the branch would be made before the mode was known. So:

- **In `runLocalBranch`**, ask mode before the base question (`first-project.ts:671-708`).
  - **Solo:** today's question, default and validator, unchanged.
  - **Team:** `branch.main` is the checked-out branch, read with `symbolic-ref --short -q HEAD` as `:692` does, and not asked. Then ask the personal branch, default `lingtai-base`, flag `--personal`. Its `validate` reuses the existing *decides only* shape (`:688`: *"`validate` can run again on a refusal, so nothing is created here"*), and `source` becomes the checked-out branch when the answer is absent.
  - The `git branch <personal> <source>` at `:831` then runs unchanged, with `personal` in place of `base`.
  - The seeds (`:855-866`) gain `mode`, `branch.main`, and `branch.personal` in team mode.
- **In `askRecipeEffect`**, ask `askMode` only when the draft has no `mode` yet. That means GitHub only, since the local caller seeded it. Put it first after `--defaults` (`recipe-flow.ts:204-220`) so that `acceptingDefaults` answers it with team.

A team add of a local checkout with HEAD detached is refused with today's sentence (`:697-701`), because `branch.main` cannot be read. Nothing has been written at that point.

## 3. On GitHub the branch is made after `askRecipeEffect` returns, through a port

`askRecipeEffect` is shared and runs no GitHub IO itself (its ports are `defaultBranch`, `tryBuild` and `history`). Inside it:
- `askPersonal` asks the name and the *make it?* confirmation;
- the existence read is a new optional port on `RecipeAt`, `branchExists: (name) => Effect<boolean | 'unreadable'>`, so the confirmation is asked only for an absent branch;
- it returns `{ personal, make: boolean }` in its result.

The `POST` happens in `askBeforeGithubAddEffect` **after `askRecipeEffect` returns and before `add.ts:368`'s `applySetup`**. That fits `recipe-flow.ts:197-198`: *"`applySetup` (#968) is the one writer of the file, so a refusal anywhere below leaves the disk as it was."*

The trial build is not affected. It cuts at `ref = base ?? defaultBranch` (`add-github.ts:398`, `:436`), which is `main`, and the personal branch is made from `main`'s tip anyway.

Build the client the way `token` does (`add-github.ts:438-445`: `createGitHubClient` with `reach`'s auth and installation). The two methods go on the client beside `refSha` (`packages/github/src/client.ts:788-805`):

- `branchExists(name)`: `GET git/ref/heads/<name>`. 200 → true, 404 → false, anything else fails. Never use `matchingRefs`.
- `createBranch(name, sha)`: `POST git/refs` with `refs/heads/<name>`. A 422 *Reference already exists* is success.

Both are `Effect.fn`. Check how `refSha` and `deleteRef` are declared today. If they are `async` methods, the new ones still must not be, and the per-package `async` count in `effect-ratchet.baseline.json` must not move.

**Two Done-when items depend on the port, so add one fake for both.** The ticket's *the answer 'no' writes nothing and registers nothing* and *`foundry-pr-7` does not count* are both claims about this port. A fake client whose `matchingRefs` would answer the prefix but whose `branchExists` answers exactly is what makes the second test meaningful.

## 4. `askLanding` in team mode

Skip it when the draft's mode is team. The exception is `--land`:
- **`--land hold`** goes through `landingChanges({ land: 'hold' }, …)` as today (`landing.ts:160-173`).
- **`--land <branch>`** is **refused** in team mode, with words like *a team project lands on branch.personal — pass --personal <branch>*. Without the refusal, `landingChanges` writes it at `branch.main` (`landing.ts:131-132`: *"written as `landingChanges` writes it, at `branch.main`"*), which would quietly re-point the PR target. That is a third reading the ticket never meant.

The local path has the same trap: `detected` falls back to `--land <branch>` (`first-project.ts:632-634`). In team mode, ignore that fallback.

The defaults confirmation's sentence (`recipe-flow.ts:381`) reads `summary.base`, which is already `branchOf(recipe)` (`recipe-flow.ts:171`). So in team mode it already names the personal branch. Only the words change, branched on `modeOf`.

## Smaller decisions

- **`defaultPersonalBranch(login, hostname)`** goes in `packages/setup/src` as a pure module, so #1325 imports it. Apply the rule only to the host part. Cut to 24 characters **before** the final trim of `-`, so no `-` is left at the end. Check the result with `branchNameRefusal` in the test, not at runtime.
- **Where the login comes from:**
  - `GhAccess.login` is already returned (`packages/conductor/src/onboard.ts:388`). Keep `access` in `add-github.ts:279-288` rather than only `defaultBranch`, and pass the login to `askRecipeEffect` as `knownLogin: string | null`.
  - `onboard.ts:515` maps `''` to null, which means *ask*.
  - An App machine passes `null`.
- **The card.** Find where solo's card is built: the `cardRecipe(recipe, toplevel)` call on the local path (`first-project.ts:648`), and whatever add-github prints. Build the team card with `modeOf` from the **resolved, written** recipe, not from the answers, so it cannot claim something the file does not hold.
- **Tests that drive `askRecipeEffect` headless will start refusing on `--mode`.** Add `mode: 'solo'` to their flags fixtures. Don't loosen the refusal or default it to solo when there is no terminal. Find them with `grep -rln askRecipeEffect apps/cli/unit`.
- **Docs.** `commands.ts:44`, `:61` and `:529` gain `--mode team|solo`, `--personal <branch>` and `--login <login>`. Then run `pnpm docs:cli`.
