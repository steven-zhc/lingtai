**The detector.** Add one new type:

```ts
interface StackDetector {
  stack: string                     // 'Node' — the word a note names it by
  detect(reader: SetupReader): Promise<StackFinding>
}
type StackFinding = { presence: 'present' | 'absent' | 'unknown' } & DetectedSetup
```

`detect` always returns its full `install`/`build`/`skipped`/`notes` together with its presence. It does not return early with nothing. Today's "nothing found" output carries notes, and those notes have to come from somewhere.

**Node's presence is decided after today's code has run, by what that code saw.** Move `detectInstall` (`:87-116`) and the body of `detectSetup` (`:118-168`) into `nodeDetector.detect` with no change to the logic. Then derive `presence` from it:

- **present**: a lockfile's `has` resolved true, or `package.json`'s `has` resolved true.
- **absent**: every `has` resolved false.
- **unknown**: nothing was confirmed present and at least one `has` rejected. That is the `uncertain` flag at `:95-101`, plus the `catch` at `:127-130`.

"Present" has to cover a lockfile without a `package.json`. Today that case returns an install command plus the note `no package.json at the root`, and the test at `detect-setup.test.ts:86-89` asserts both. "Present" also has to cover a `package.json` without a lockfile (`:69`, `:92`). So presence cannot be "has `package.json`". `detectInstall` needs to hand back whether it saw a confirmed lockfile and whether a `has` rejected; today it hands back only the note.

**The merge in `detectSetup(reader, detectors = DETECTORS)`.** `DETECTORS` is `[nodeDetector]`, and the second parameter exists so the new test can pass a stub. Run the detectors one at a time in list order, the same sequential `await` as `:96-102`, so a reader's calls stay in today's order.

1. **At least one finding is `present`.** The first present finding supplies `install`, `build`, `skipped` and `notes` as they are. Each later present finding adds one note to the end: `` `${other.stack} is also at the root; ${first.stack} was used` ``, which is the same sentence as the lockfile note at `:109`. A later stack's `skipped` and notes are dropped, because they describe commands nobody is being asked about. An `unknown` finding keeps its notes. Its "could not tell" is never turned into silence (the ticket's first edge). An `absent` finding adds nothing.
2. **No finding is present.** Return `install: null`, `build: []`, `skipped: []`, and the notes of every finding concatenated in list order. With Node alone this gives exactly today's arrays: `['no lockfile at the root', 'no package.json at the root']` for `reader({})`, and the two "could not tell" notes for `EMPTY_SETUP_READER`.

So with Node as the only detector, `detectSetup` returns Node's finding with `presence` removed, in every case. That is the whole behaviour-preservation argument, and it needs no new test beyond the existing file.
