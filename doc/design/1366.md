## Design note for #1366: the ask under a running card on one line

**This is a change to the CSS block at `apps/board/src/app/globals.css:3794-3797` and one new test.** Do not change any markup or any other rule.

### The decision the ticket leaves open: every full-width child needs its own `order`

When `.chat` was a column, every child got a line of its own for free. As a row that wraps, a child only gets its own line if it says so. A child that gets its own line through `flex-basis: 100%` also breaks the line it lands in. Moving `.chatscroll` to the top is only half the fix. The other two full-width children have to be placed too:

- **`.chatcontext`** sits *between* `.chathead` and `.chatscroll` in the markup (`discussion.tsx:661-666`). If it gets `flex-basis: 100%` and keeps the default `order: 0`, it lands between the heading and the ask and splits them onto separate lines again. That is the exact bug, coming back whenever a reason is set. Give it the same `order: -1` as `.chatscroll` plus `flex-basis: 100%`. The markup then puts it above the conversation. That is the column's order, with both items above the heading and ask line.
- **`.refusal`** comes after `.chatask` (`discussion.tsx:878`). Give it `flex-basis: 100%` and leave its order at the default. It then wraps onto a line of its own *below* the ask, which is where a refusal belongs.

Scope all three selectors as `.running-ask .chat > …`, like the existing `.chatscroll` rule. The reason is the base rule `.chat > * { flex: 0 0 auto; }` (`globals.css:2109`). It has to keep holding on the Waiting and Queued pages and for `.chat.compact`, and none of those match `.running-ask` (`standing.tsx:349` is the only wrapper).

### What needs no change

- **`.chathead`:** it already gets `flex: 0 0 auto` from `globals.css:2109`. In a row that means its natural width, and that is what the ticket asks for. Do not give it a `flex-basis`.
- **`.chatask`:** its `flex: 1 1 20rem` (`:3796`) becomes a width once the direction is a row. That is the "input takes the room that is left".
- **`align-items: center`:** keep it. As a row it centres the heading vertically against the 2rem textarea.
- **Compact entry button:** `.chat.compact` renders only `.chatentry` (`discussion.tsx:647-649`). It is one item on one line either way, so it looks the same.

### The test

Put the test beside the existing stylesheet assertions, using the same `CSS` string that `apps/board/unit/rail.test.tsx:1002-1004` matches against. Use either a new `it` in that file or a small sibling file that reads `globals.css` the same way. Assert three things, with regexes in the same style as `:1002`:

1. `/\.running-ask \.chat\s*\{[^}]*flex-direction:\s*row/`
2. `/\.running-ask \.chat > \.chatscroll\s*\{[^}]*order:\s*-1/`
3. the same `order: -1` for `.chatcontext`, so the third reading above stays pinned.

Assert nothing about sizes. Change the comment at `:3793` to say why the direction is written out: the base `.chat` is a column (`:2068-2070`), and #1290's rule read as a row without being one.
