# Design note: #853, the *pass* strings under `apps/*/src`

## Shape

Make one hand commit, or one per app. Keep `doc/cli.json` and `doc/cli.md` in the same commit as the `apps/cli` strings that produce them. Nothing is renamed, so there is no scripted commit and no `.git-blame-ignore-revs` line. The work is the same as in #852 (`doc/design/852.md`): read each *pass*, decide which of three things it means, and use that note's grep, filtered to drop comments (`… | grep -vE '^[^:]+:[0-9]+:\s*(\*|//|/\*)'`). With that filter and the verdicts removed, `apps/cli/src`, `apps/board/src` and `apps/release/src` give 163 lines. Some of those are keys or the verb, and you keep them.

Comments are out of scope. `service.ts:565`'s *"the mechanism that waits for a pass"* stays.

## Attempt or turn: the CLI cases that are not obvious

The CLI is the one app that talks about the daemon's loop, so *turn* shows up here and almost nowhere on the board or the site. Decide by what the sentence is about:

- **Turn.** A ticket being picked off the queue, or something asked again on every loop:
  - `commands.ts:157`, `--unheld … so the next pass may take it`, becomes *the next turn may take it*. A turn claims a ticket. It is not an attempt until it has been claimed.
  - `subscribers.ts:286`, *"asked again each pass"*, becomes *each turn*. `subscribers.ts:317` and `daemon.ts:519` say that check runs before every loop.
- **Attempt.** Everything that has a branch, rounds, a merge or a drain:
  - `commands.ts:81`/`:487`, *"where a pass lands, or hold every pass"*;
  - `:46`'s *"fix rounds a pass may buy"*;
  - `:226`, *"waits for a pass"*, which is the drain from 0030, the attempt in flight;
  - `:326`, *"the next pass cuts a fresh branch"*.
- **`setup-card.ts:190`**, the group title `'each pass'`. The rows under it are writer, reviewer, checks and trial, which is what one attempt runs, so it becomes `'each attempt'`. #852's note left its two pins to this ticket: `apps/cli/unit/init.test.ts:301` and `apps/cli/unit/setup-card.test.ts:181`.

## The help text is wrapped by hand

The help strings in `commands.ts` are one literal per line, padded so they line up (`commands.ts:81`, `'      where a pass lands, …'`). *attempt* is three characters longer than *pass*. No test checks line width (nothing in `apps/cli/unit` asserts on it), so a reworded line that runs long will pass the gate and look wrong in a terminal.

- Re-wrap by hand so that no help line gets longer than the longest line already in that command's block.
- Keep the flag column aligned.
- Then run `pnpm docs:cli` (`package.json:24`, `node scripts/cli-doc.ts`). The test at `cli-doc.test.ts:24-30` compares both files byte for byte, so never hand-edit either one.
