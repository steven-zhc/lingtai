It goes on the zod object, not on a TS type beside it. `z.object` strips unknown keys, so if `modelFrom` is left off the schema it is dropped silently when `RunSpent` is parsed, and the mark never reaches the log. The `model` doc comment at `:33` ("Absent where the runtime never names one") gains "or, for Codex, its config file names none".

**`packages/agent/src/codex.ts`**: three exported pure pieces and one unexported read.

- `codexConfigPath(env: Record<string, string>): string | undefined` returns `env.CODEX_HOME + '/config.toml'`, else `env.HOME + '/.codex/config.toml'`, else `undefined`. Use `join` from `node:path`, which is already imported at `:57`. Treat an empty-string `CODEX_HOME` as unset. This function is the unit test for "the path the run would read, for both env shapes", so the read itself needs no test.
- `readCodexConfig(text): { ok: true; model: string | undefined } | { ok: false; detail: string }` parses with `smol-toml`'s `parse` (imported the way `apps/cli/src/detect-setup.ts:13` imports it). It resolves `profile` first: a string `profile` whose `profiles.<name>.model` is a non-empty string wins, and otherwise the top-level `model` answers when it is a non-empty string. A parse throw becomes `{ ok: false, detail }`.
- `configuredModel(text) => string | undefined` is the shape the ticket names, as a one-liner over `readCodexConfig`. **This is the decision the ticket leaves open.** Its *Fix* asks for a parser `(text) => model | undefined`, and its malformed-TOML edge asks for a run-log note, which a bare `undefined` cannot carry. With two layers, both hold: the Done-when tests use `configuredModel`, and the read uses `readCodexConfig` so the note can name the parse error.
- The read is unexported, a few lines, synchronous `readFileSync` in the same style as `hookWiringAt`'s read at `:882`.
  - `ENOENT` / `ENOTDIR` → no model, no note.
  - Any other error (`EACCES`, `EISDIR`) → `trace.note('codex', '<path>: <message>; the run is recorded with no model')`.
  - `{ ok: false }` → one note naming the path and the parse error.
  - Never throw.

**In `run` (`:1136`)**: compute the recorded model once, before the `new Promise` at `:1178`. After the `hookWiringAt` refusal at `:1142-1161`, so a refused run does not read the file, and before `codexArgv` at `:1170`.

```ts
const recorded = request.model
  ? { model: request.model }
  : configModelFor(request.env, trace)   // { model, modelFrom: 'config' } | {}
```

Both call sites, `:1308` (timeout) and `:1426` (close), pass `recorded` instead of `request.model`. **`codexArgv` is not touched.** `:1059` keeps reading `request.model`, and `recorded` never flows into the argv.

**`codexUsage` (`:483-487`)**: change its second parameter from `model: string | undefined` to `recorded: { model?: string; modelFrom?: 'config' }`, and spread it into the entry. Then a caller cannot set `modelFrom` without a model. Update the doc comment at `:478-481`, which says the model is "absent otherwise". Also update the existing callers in `packages/agent/unit/codex.test.ts` (`:259-275`).
