## Design for #566

The worktree already contains the runtime and schema changes: `DiscussAgent` includes `codex`, both recipe fields use that enum, and both callers request `tools: 'none'` (`packages/recipe/src/recipe.ts:2821-2843`, `:2893-2894`, `:2961-2962`; `apps/cli/src/discuss.ts:390`; `apps/cli/src/triage.ts:561`). Build on those seams rather than adding another agent option or dispatch path. ADR 0106 §6 settles the boundary: “Codex CLI’s `-s read-only` still leaves a shell able to read the whole machine,” while the separately configured Responses route sends `tools: []` and `tool_choice: "none"` (`doc/decisions/0106-a-role-keeps-its-powers-across-runtimes.md:84-96`).

The decision is to separate **recipe validity** from **machine readiness**. A recipe may name Codex on a machine without API configuration; `createRuntime('codex', { tools: 'none' })` must then refuse by name before a paid request, as its factory does today (`packages/agent/src/runtimes.ts:103-143`). Add a per-project doctor check for each selected Discussion and triage agent. The existing doctor checks the pass’s `runtime.agent`, which can be Claude Code while either of these roles names Codex (`apps/cli/src/doctor.ts:2138-2145`). Report missing approval, credentials, model, or price bounds without printing the key; keep the recipe defaults and the self-hosting recipe on Claude Code. The operator example should pair bounded `discuss:` and `triage:` calls with the separate `codex_text` machine configuration, explain API billing, and require a recipe model to match the priced model (`packages/recipe/src/recipe.ts:2881-2907`, `:2958-2990`; `config.example.yml:73-87`; `packages/agent/src/codex-text.ts:48-50`).

Test the two callers with an injected Responses transport and an isolated in-memory event store. Assert a Discussion answer and an eligible wait’s advice, their Codex `RunSpent` usage and `costUsd: null`, and refusal before transport for incomplete configuration or insufficient spend bound. Cover a further triage read round so its reserved bound is debited before another request (`packages/conductor/src/discuss.ts:550-580`; `apps/cli/src/triage.ts:650-711`; `packages/agent/src/codex-text.ts:14-17`, `:51-81`). The 803-second integration suite cannot be the sole pre-merge check: the unit-level claim is that each selected call reaches the no-tools adapter within its limits and records its result and spend. For operational verification later, the settling log fields are `RunSpent.for`, `runtime`, `usage` and `costUsd`, alongside `DiscussionAnswered.failure` or `WaitTriaged.result`; do not infer a successful paid call from recipe resolution alone.
