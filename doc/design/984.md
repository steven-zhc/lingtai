# #984: the shape

The ticket's plan holds. These are the things it does not settle, plus one rule without which the sticky panel does nothing.

**Line numbers have moved since the ticket was written.** The `RecipeText` call is at `page.tsx:244`, not `:153`. The `Edit</button>` and `Close</button>` pins are at `integration/recipe.test.tsx:421` and `:426`. The `use server` scan is at `:393`.

## Sticky needs one rule the ticket does not list

`.s2` has `align-items: start` (`globals.css:3294`), so `.s2-right` (`page.tsx:243`) is exactly as tall as the panel. A sticky element cannot travel inside a parent of its own height, so `.rfile` as written would never stick.

The ticket's edge about an ancestor that scrolls or clips does not catch this. `body` (`globals.css:82`), `.detail` (`:898`) and `.detail-body` (`:904`) set no overflow.

- Add `.s2-right { align-self: stretch; }` and keep `.rfile` as the ticket writes it.
- Below 900px (`globals.css:3336`) and in the broken state (no `.s2`, `page.tsx:241`), the parent is content-height and sticky does nothing. That is the right behaviour.
- Use `top: 14px`, not the mock's `64px`. The board's bar is in normal flow (`globals.css:2594`: "The bar at the top of the page is in normal flow").

## Splitting the theme

Export one constant from `yaml-editor.tsx`, for example `yamlExtensions`, holding the four shared extensions and a base theme.

- **Base theme:** background and colour (`:26-27`), `.cm-scroller` (`:30`), `.cm-gutters` (`:33-37`).
- **Editor only:** `height`, `maxHeight`, caret, cursor, focus outline.
- **The border at `:28` goes.** The editor now sits inside `.rfile`, which has its own border, and the mock's `.rcode.edit` has none (`recipe-steps.html:95`). `RecipeForm` is the only user of the editor.
- **The focus outline at `:38` needs `outlineOffset: '-1px'`.** The editor sits flush against an `overflow: hidden` panel, which would clip an outline drawn outside it.
- **Set no `font-size` on `.rfile`.** The editor inherits `13.5px` from `body` (`globals.css:86`). Giving the panel a size would make the view and the editor differ, which is the jump this ticket removes.

## `yaml-view.tsx`

Start the file with `'use client'`. `client-graph.test.ts` is the unit stand-in for the Next build. It takes `'use client'` files as its roots and does not follow `import()` (`client-graph.test.ts:14-15`, `:31-32`), so without the directive nothing walks this file.

A static import of `./yaml-editor` from here is fine, since both load in the dynamic chunk. `recipe-text.tsx` must import neither of them statically. Extend the source assertion at `unit/recipe-editor.test.tsx:32-34` to cover it.

Use two effects, in this order:

1. Create and destroy the view with `[]` deps, as at `yaml-editor.tsx:63-94`, keeping the view in a ref that is cleared on cleanup.
2. Sync the document with `[text]` deps.

**Put the sync decision in an exported pure function**, for example `replaceDoc(state, text)`, returning a transaction spec or `null` when the text is the same. The app has no jsdom (`unit/attempt.test.tsx:93`), so the component cannot be mounted in a test, but `EditorState` needs no DOM.

Test it with a state that carries `EditorState.readOnly.of(true)`. Different text must produce the new document through `state.update(spec)`, and the same text must return `null`. This is the unit-level claim for the ticket's *seeded once* trap. It also proves that `readOnly` does not block a programmatic change. The wiring in the effect is left to the person's check.

## `recipe-text.tsx`

Hold `ready` in a small component in the same file that renders the `<pre>` and `YamlView`, and render it only when not editing. `ready` then resets when the editor opens, instead of staying true while no view exists.

`editing` stays in `RecipeText`. Add no `key`, for the reason given at `recipe-text.tsx:10-11` and `page.tsx:237-240`: a remount drops the message a save just earned.

`path` is safe to show unconditionally. `view.at` can name `config.yml` when the fault is the machine's (`lib/recipe.ts:410-411`), but `text` is `null` in that case (`:485`), so no panel renders. Add `min-width: 0; overflow-wrap: anywhere` to `.rfile-bar small` so a long path cannot push the button out of the bar.

## Two CSS gaps inside the panel

- **The save row.** `.redit .row` has no rule today, so `Validate and save` would touch the panel's edge. Add `.rfile .redit .row { padding: 8px 12px; border-top: 1px solid var(--rule); }`, which is the mock's `.saverow` (`recipe-steps.html:102`).
- **The fallback.** `.s2-yaml` is also used by `setup-form.tsx:372`, so scope the change: `.rfile .s2-yaml { border: 0; white-space: pre-wrap; overflow-wrap: anywhere; }`. Wrapping here means a failed chunk does not bring back the truncated comment this ticket reports.
