# #1493 — the shape

> **History.** Board addresses in this note (`/task/<id>`, `/pr/…`, `/recipe/…`, `?project=`) are the ones that existed when it was written; they no longer resolve. The current forms are in [1502.md](1502.md).

## 1. The row becomes two columns: the rail on the left, both lines on the right

The mock's own markup in `doc/milestone/0.16.0/acceptance/board-mocks.html:81-86` already gives this structure:

```
<div class="lrow"><div class="rail">…</div><div><div class="l1">…</div><div class="l2">…</div></div></div>
```

Build `LandedRow` the same way:

```
<li class="lrow">
  [.lseq]                      ← unchanged, only when card.progress
  [.proj]                      ← only with showProject; a sibling of .lbody, not inside .lline
  <div class="lbody">
    <div class="lline">  IssueRef · <Link.lmeta>· said1</Link> · where-tag  </div>
    <Link class="lspend" href=/task/… title=card.title>
      <ul class="lbill"> work · <AnsweringPill/> · turns </ul>
    </Link>
  </div>
</li>
```

`.lrow` stops being the flex line. It becomes `display: flex; align-items: flex-start`, with `.lseq` (`flex: 0 0 auto; width: 34px`, `globals.css:857`) and `.lbody { flex: 1; min-width: 0 }`.

- **Line 1:** `.lline` takes the declarations `.lrow` has today (`globals.css:910-915`, flex with `gap: 5px` and `align-items: baseline`).
- **Line 2 starts under the first thing after the rail.** That gives the ticket's "same left edge as `#n`, not under the rail" with no indent arithmetic.
- **Rows without a rail.** On rows `laneProgress` collapses there is no `.lseq` (`page.tsx:574-579`), so both lines start at the left edge, as the one line does today.
- **With `showProject`.** The project name is a sibling of `.lbody`, after the rail and before it, so both lines start at `#n`. No width measuring is needed.

## 2. The shared pill is an `<li>`, so line 2 has to be a list

The card's pill is `<li className="pill sig" title=…>` and sits inside `<ul className="meta">` (`page.tsx:335`, `:412-416`). The ticket requires the card's own markup, and a test compares the HTML across the two. So the component keeps the `<li>`, and line 2 is a `<ul>` whose children are all `<li>`:

- Work as `<li class="lwork">{billText(card.costUsd)}</li>`
- `<AnsweringPill bill={card.repairCostUsd} />`
- turns as `<li class="lturns">· {n} turns</li>`

Do not put the pill in a `<span>` line. An `<li>` outside a list is invalid markup, and React will render it without complaint.

`.lbill` is **not** `.meta`. `.meta` has `flex-wrap: wrap` (`globals.css:700`), and a wrap would move turns onto a third line when they do not fit, instead of letting them give way. `.lbill` gets these rules:

- `display: flex; flex-wrap: nowrap; gap: 0 5px; align-items: baseline; list-style: none; margin: 0; padding: 0; min-width: 0`
- `.lwork` and the pill: `flex: 0 1 auto; min-width: 0; white-space: normal; overflow-wrap: anywhere`. They are not clipped, and they cannot overflow: in a column too narrow for them (a project name takes its share at ~240px) each wraps its own text inside its own box. The pill's own `white-space: nowrap` is overridden here only.
- `.lturns`: `flex: 0 1000 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap`. Turns shrink first, to nothing if need be, so they appear only if there is room. They are the only thing on line 2 that gives way, which is the ticket's rule.

Write `· ` before turns only. The mock separates the pill by a gap, not a dot (`board-mocks.html:85` against `:92`).

## 3. `AnsweringPill` lives in `page.tsx` and returns `null` itself

```tsx
export function AnsweringPill({ bill }: { bill: Bill }) {
  return billHasAny(bill) ? <li className="pill sig" title="…">{billText(bill)} answering</li> : null
}
```

- **Where.** Put it in `page.tsx`, beside `Card` and `LandedRow`. Both are in that file, and the ticket says `/landed` is out of scope, so nothing else needs it.
- **The empty check.** The `billHasAny` guard moves inside the component so neither caller can forget it. That rule is "never draw `$0.00 answering`", and it now holds in one place.
- **The comment.** Move the comment at `page.tsx:401-411` onto the component: *"reducing it into the number beside it would make it an invisible bill (#84)"*. In `Card`, leave a one-line pointer at the call site.

## 4. Line 2 is a second link, kept out of the tab order

The ticket says both lines go to `/task/<id>` and carry `card.title` on hover, as `.lmeta` does (`page.tsx:582-584`). Line 2 is a second `<Link>` and gets `tabIndex={-1}`. Two identical links per row would double every keyboard stop down the column, and the row would read as two destinations when it has one.

An `<a>` wrapping a `<ul>` is valid, because `<a>` takes on its parent's content model and the parent `<div>` allows flow content. Give `.lspend` the same hover rule as `.lmeta:hover` (`globals.css:924`).

## 5. How `said` splits

- **Line 1:** `satisfied`/`closed` (`page.tsx:550`), `card.kind`, and the ago. It stays one `.lmeta` and keeps its ellipsis. With the spend gone, it is only kind words and a short time.
- **Line 2:** work, pill, turns, in that order, each rendered only when it has something.

Line 2 always renders, even empty, so nothing is pulled up onto line 1, which the ticket's edge forbids. Rows are two lines in the ordinary case; heights are not equal in a column so narrow that the Work figure or the pill wraps its own text.
