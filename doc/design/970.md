## What the page reads

- **Do not reuse `isGhMachine()` here.** It maps a refused `github.auth` to "not gh" (`gh-machine.ts:9-15`). Call `githubAuthKind()` directly, because it has three answers plus a throw (`packages/env/src/index.ts:1577`):
  - `null`: Local only, no GitHub tab.
  - `'app'` or `'gh'`: read the list.
  - A throw: the read-failed screen, with its sentence.
- **Every list failure becomes `{ error: sentence }`, and the page never throws.** That includes `loadAllProjects` failing and `githubApp()` throwing on half a key. Show the sentence and the `owner/repo` box.
- **Wrap the read in `Effect.timeout('20 seconds')`.** `doc/design/969.md` records that `githubJson` has no timeout, and a hung GitHub would otherwise hold up the Local tab too. Running it with `Effect.runPromise` at the page is fine, since `apps/board` is not in the ratchet (`effect-ratchet.baseline.json`).

Reduce `RepositoryList` to rows on the server:

- **`onboarded !== null` is disabled.** `registered`, `pending` and `unrecorded` are tagged *already added*. `alreadyOnboarded` is at `pick-repository.ts:103` now, not `:243`, and takes a `Picker`, so test `onboarded` directly.
- **`taken` is the fourth case the ticket omits.** It is also never offered (`list-repositories.ts:53-55`). Disable it and tag it with `takenBy`; it does not say *already added*.
- **Sentences beside the list:**
  - `unanswered`, under its own account (`:64-69`).
  - `gaps`, one line each.
  - `more: true`: the list stopped, type `owner/repo` for the rest (`:89`).

## The local path is a server action

The ticket wants the tab and filter in a client component, so the path check must not re-render the page and re-run the list read.

`readLocalRepository(input, { git, stat, home })` in `@lingtai/setup`, with injected ports, is unit-testable with no `git`:

1. Trim the input. Expand only a leading `~` or `~/` with `home`.
2. **Refuse anything not absolute at that point.** `path.resolve` on a relative input would silently use the board's working directory. Otherwise `path.resolve` collapses `..`.
3. Stat first: missing or not a directory gets its sentence. Without this, git's cwd failure reads as "not a repository".
4. Run `rev-parse --show-toplevel`. The result is the **toplevel**, and that is what is shown and put in the URL, as the CLI does (`first-project.ts:499-504`). A failure uses the CLI's *is not a git repository — detail* sentence.
5. Run `branch --show-current` (empty means detached, say so) and `remote get-url origin`, where a failure means no remote, as at `first-project.ts:537-538`.

Use `gitEffect` (`packages/repo/src/git.ts:112`). Run only those read commands. Do not add `git status`, which can run a repository's `core.fsmonitor`.

Under the box, by case:

- **`githubSlugOfRemote` matches** (`ticket-source.ts:23`): the mock's line, *tickets still come from its issues*.
- **Another host:** the remote, then *Lingtai keeps its own tickets* (0125 §4, #964 decision 6). **Strip any userinfo first**, since an `origin` can hold a token.
- **No `origin`:** *no remote — Lingtai keeps its own tickets*, with Next enabled.

**A path already registered does not disable Next.** The recorded answer limits disabling to a path that is missing or not a git repository. Step 2 re-checks.

### The race in the client

- Check on a short debounce, and tag each call with its input.
- Apply a result only if its input still equals the box. Next is disabled while the box differs from the last applied result.
- Catch a rejected action (board restarted, connection lost): show *could not be checked* with Next disabled, never a spinner that stays.
