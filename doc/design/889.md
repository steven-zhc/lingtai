### 2. The `Decided:` line needs a lookup that accepts any string

`afterMove.resolution` is declared `resolution: string` (`apps/board/src/lib/task.ts:436`), not `Resolution['_tag']`. It is set from `m.resolution._tag` at `task.ts:849`.

Every other `RESOLUTION_COPY[...]` in the board indexes with a typed tag (`standing.tsx:227`, `:235`, `:1116`, `decide.tsx:862`, `page.tsx:227`). So `RESOLUTION_COPY[standing.afterMove.resolution]` fails `pnpm typecheck` as it stands.

Put the fallback in `apps/board/src/lib/resolution-copy.ts`, beside the table, as one exported function:

```ts
/** A move's title; an unknown tag (an event older than the type) prints as it is. */
export function moveTitle(tag: string): string
```

- Implement it with `Object.hasOwn(RESOLUTION_COPY, tag)`, or by reading through a `Partial<Record<string, …>>` view of the table. A plain `in` check is wrong, because it is true for inherited keys such as `toString` and `constructor`.
- Use it only at `standing.tsx:917`. The typed call sites stay as they are.
- Keep `afterMove.resolution` as `string`. Narrowing it would only move the cast into `task.ts`, and the point of the fallback is that a value outside the type can reach here.

Write the test the ticket asks for in a new `apps/board/unit/resolution-copy.test.ts` that tests `moveTitle`:

- `'AnswerQuestion'` gives `'Answer the question'`.
- `'Withdraw'` gives `'Withdraw'`.
- `'toString'` gives `'toString'`. This is the case that fails if someone later switches to `in`.

A test against the rendered `Decided:` line belongs with the existing `afterMove` assertions in `apps/board/unit/standing.test.tsx`.
