# #1061: design note

The ticket covers most of this change. This note adds four things the ticket does not say. Two of them are tests that go red but are not in the ticket's *Watch out*.

## 1. Two more tests read what this ticket changes

**`apps/site/unit/tutorial-tabs.test.tsx:32-40`** reads `doc/tutorial.md` itself and requires both shell groups and a disclosure:

```ts
expect(html.match(/class="shell-tabs"/g)).toHaveLength(2)
expect(html).toContain('<details>')
expect(html).toContain('<summary>What did this command choose?</summary>')
```

The new page has neither, so this test goes red. The two plugins stay, because removing them is out of scope. So the test has to cover them without the published page:

- **Shell tabs.** The test at `:9-30` already covers them with an inline body. Leave it as it is.
- **Details.** Replace `:32-40` with an inline-fixture test for `remarkTutorialDetails`: a `<details><summary>X</summary>` … `</details>` body rendered with `slug="tutorial"`. It expects `<details>` and `<summary>X</summary>`, and no `&lt;details&gt;`.
- **The published page.** Add an assertion that `doc/tutorial.md` renders with no `class="shell-tabs"` and no `&lt;details&gt;`. This is the "no POSIX/Fish pair" item in *Done when*, held by a test.

Do not delete the plugin coverage just because the published page no longer uses the plugins.

**`apps/site/unit/page.test.tsx:121-132`** pins `PUBLIC_SLUGS` with `toEqual` against the whole list. Adding `'tutorial-more'` to `docs.ts:70` goes red here unless the same entry is added to that list. Put it straight after `'tutorial'` in both places.

## 3. Use the real line numbers in `document.tsx`

The ticket cites `document.tsx:231-233`. Today the two slug-gated places are:

- `apps/site/src/app/docs/document.tsx:247`: the `tutorial-prose` class.
