# #809 design note: Common questions under the ledger

## The one thing the ticket's Fix misses: `safety.md` is not published

Adding `'safety'` to `PUBLIC_SLUGS` does not put `/docs/safety/` on the site. The site serves `servable()`, which is `published()` filtered by `isPublicSlug` (`apps/site/src/lib/docs.ts:82-86`). `published()` returns only the files listed in a `SECTIONS` entry (`docs.ts:295-299`). `doc/safety.md` exists, written by #808, but no section lists it. `grep safety apps/site/src/lib/docs.ts` returns nothing. So `generateStaticParams` (`apps/site/src/app/docs/[...slug]/page.tsx:46`) never sees the page, and the new link would 404 on the live site. That 404 is exactly what the ticket's *Watch out* says must not happen. Today the file is listed by `unpublished()` (`docs.ts:309`) on the docs index.

**Decision:** add `'safety.md'` to the `guides` section's `files` (`docs.ts:117-130`) directly after `'requirements.md'`. That is the same position the Docs menu gives it. Both edits are required: the `SECTIONS` entry publishes the file, and the `PUBLIC_SLUGS` entry makes it public while `DOCS_PUBLIC` is off. Also extend the comment above `PUBLIC_SLUGS` (`docs.ts:55-67`), which lists every public page and the reason for each. Add one clause: `safety` is the page the home page's honest answer sends a reader to (#809).

Add a unit case in `docs.test.ts` beside the `requirements` one at `:203-205`. It should assert that `servable()` contains `safety.md` and that `resolveHref` maps `safety.md` to `/docs/safety/`. This is what would have caught the gap above. `safety.md`'s own links to `operating.md`, `../SECURITY.md` and `../README.md` (`doc/safety.md:13,64,67`) need no work, because `resolveHref` already sends non-public targets to GitHub.
