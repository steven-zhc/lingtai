## Design note for #842

The ticket already gives the shape, so this note covers only the three points it leaves open.

**1. Where `waits` joins the state.** `applyTicket` builds `stated` from `base` (`packages/domain/src/ticket.ts:316-323`). The `closed` guard then returns early with `{ ...stated, ...at, since: prior.since ?? event.at }` (`:338-340`). Compute `waits: reduceWaits(prior.waits, event)` and put it into `base` (or `stated`) **before** that guard. Then the early return carries the new value, and so does every `case` below it that spreads `stated`. Don't apply it after the `switch`: any case that returns early would drop it.

**2. Which entry `editEndedWaits` reads when a `waitId` repeats.** Today the code keeps the **latest** `WaitStarted` for a `waitId`, because `started.set` overwrites (`packages/conductor/src/tell.ts:466-468`). Its window then runs until the next start after that one (`:481`). So for each posted comment, read the **last** entry in `waits` with `p.waitId`. That is the same entry `triageFactsOf` reads. A comment whose `waitId` has no entry is skipped, as `from === undefined` is today (`:479`). `waitsOf` still lists every entry (`read-model.ts:86-97` keeps one per `WaitStarted`). Only these two readers pick the last one.

**3. Adding a field to `TicketState`.** `emptyTicket` is a literal (`ticket.ts:272-294`), so `typecheck` will point to every other literal `TicketState` built by hand in tests. Add `waits: []` to each one. Those are construction sites, not expectation changes, so they don't count as the "refusal" in Done when.
