**Design note for #865: what the ticket leaves out**

The ticket gives the shape. Treat `config.example.yml:76-80` and 0111 §2 as the wording to stay consistent with. The note below covers two facts the ticket's Evidence list gets slightly wrong or leaves out. The new `#### The address` section must get them right, because the code is what a reader will check it against.

1. **There are two "every address" values, and each falls back to its own loopback.** `boardReachHost` (`packages/env/src/index.ts:920-924`) maps `0.0.0.0` to `127.0.0.1`, **`::` to `::1`**, and any other address to itself. `isBoardHost` (`:853-855`) accepts any IP literal without a `%` zone, so `::` is a legal `board.host`. Don't write "links go to 127.0.0.1 when every address is served", because that is wrong for `::`. Write it as: *for `0.0.0.0` (or `::`), links and probes go to `127.0.0.1` (or `::1`); for any other address, they go to that address.* Also say that an IPv6 address is shown in brackets in the URL (`boardOrigin`, `:927-929`). This matters to anyone who sets `board.host: ::1`.

2. **Say "unscoped IP literal", and give the three refusals separately.** Their wording differs (`machineBoardHost`, `:868-909`):
   - a hostname or a zoned address (`fe80::1%en0`) is refused, and the refusal quotes the value;
   - an exported `LINGTAI_BOARD_HOST=''` is refused as "empty". It is not treated as unset (`:874-879`);
   - an unreadable `config.yml` is refused too. It never falls back to the default (`:895`).

   In all three cases the board does not start, and the message says to unset the variable or remove the line to get `0.0.0.0`. The exported variable wins over the file (`:881-893` reads the environment first).

**The dev script.** It serves the same address because it is the same code: `apps/board/serve.ts:29` calls `boardHost()` and passes it as `-H` to `next` (`:41`), and `apps/board/package.json:7` is `node ./serve.ts dev`. Copy the port section's sentence, *"That script asks for the address like everything else (`apps/board/serve.ts`)"*, and don't explain it any further.
