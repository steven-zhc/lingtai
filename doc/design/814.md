# #814 — the books section: design note

## Where it goes

- **New file `apps/site/src/app/books-section.tsx`**, holding a synchronous `BooksSection({ books }: { books: Books })` with no `'use client'`. It imports `Receipt` from `./receipt` (that file's header comment says: *"the books render it from server code"*), `dollars` from `./replay-receipt` (`replay-receipt.tsx:123`, which takes cents), `REPO` from `./chrome` (`chrome.tsx:4`), and only the **type** `Books` from `@/lib/books`.
- **`page.tsx` splits in two.** `export function HomePage({ books }: { books: Books | null })` is today's `Home` body, with `{books ? <BooksSection books={books} /> : null}` placed between `</section>` of `.why` and `<section className="home-setup">`. Then `export default async function Home() { return <HomePage books={await readBooks()} /> }`.
- **Why the split is needed.** Today `Home` is synchronous, and `unit/page.test.tsx` calls `renderToStaticMarkup(<Home />)` five times (lines 49, 157, 177, 238, and the `why` describe). `renderToStaticMarkup` cannot render an async component. So every one of those calls becomes `<HomePage books={null} />`, or the fixture where a case needs it.
- **Reading at build time is allowed.** The site is `output: 'export'` (`next.config.ts`), so `readBooks()` runs at build. That is the same pattern the docs pages already use: `docs/page.tsx` and `docs/[...slug]/page.tsx` are async.
- **Never import from `@lingtai/conductor` in the site's `src/`.** `books.ts`'s header says *"The shaping needs the conductor's `report()`, which must never reach the Next graph"*. This matters for the purpose labels below.
- **CSS:** port the mock's rules into `home.css`:
  - `.books-head`, `.figs`, `.fig` (`home-page-v3.html:856–910`)
  - the responsive overrides (`:1108–1140`)
  - `.real-badge` (`:1768`)
  - `.outcome*` and `.money*` (`:1854–1920` and on)
  - Use the site's tokens only. Dark mode comes from the tokens, as the rest of `home.css` does.
  - `Receipt` takes no `className`, so the mock's `.rcpt.sm` becomes `.real-grid .rcpt`.
  - Breakpoints use `home.css`'s existing `1080px` and `700px` media blocks (`home.css:216`, `:220`).
- `books.json` does not exist yet (`apps/site/books.json` is absent), so the page as built today renders no section. That is the *no file* edge, and it is the shipped state until the first release run.

## Decisions the ticket leaves to the builder

**Formatting.** Write one set of local helpers in `books-section.tsx`:
- **Share:** `Math.round(x * 100)` followed by `%`.
- **Dollars:** `dollars(Math.round(x * 100))`, always with cents. The mock's `$12` for p90 is rounded by hand; do not copy that.
- **Minutes:** under 60 is `N min`. From 60 up it is `H h M min`. In the big figure, the units go in `<small>`, as in the mock.
- **Medians can be fractional.** `fixRounds.median` and the median receipt's `waits` come from `report()`'s median, so they can be `1.5`. Print a non-integer with one decimal, and never round it to look like a real ticket.
- **"Asked you":** `0 times`, `once`, `twice`, `N times`.

**Window.** Print `window.from` and `window.to` verbatim, as `2026-10-02 → 2026-10-31`. The mock's `10-31` and *"1 of 283 landed in October"* both break the ticket's *never says this month* edge. The median receipt's title is `1 of {landed} landed`.

**Outcome bar.**
- `finished = landed + closed`.
- Widths and the landed share are taken over `finished`. `open` is in the key only, not in the bar.
- When `finished === 0`, the bar is not rendered.
- The mock's *"6 done another way, 2 not wanted"* is not in the file, so it is not rendered. The key reads *closed without landing — by a person*.

**Figures.** Each of the four figures is rendered only when its headline is non-null:
- fix rounds: `fixRounds.zeroOrOneShare`
- cost: `cost.median`
- machine time: `machineMinutes.median`
- time to land: `elapsedMinutes.median`

A null part of a sub-line is left out together with its `·` separator. Two additions go on the cost sub-line:
- *includes estimates* when `cost.includesEstimates` is true.
- *`{costUnknown}` runs could not be priced* when `costUnknown > 0`. Without it, the note's *"Nothing left out"* is false whenever runs were dropped from the figures (`books.ts`: *"Runs nothing could price: left out of the figures, counted here"*).

**Spend bar.**
- It is rendered only when `spendShare !== null` **and** `cost.median !== null`, because the heading needs the median.
- The file carries the raw purpose tags. `take-books.ts:105` orders them by `PURPOSE_WORDS`, whose tags are `Work`, `Answering`, `Judge`, `Triage` and `Discussion` (`packages/conductor/src/report.ts:344`).
- The site keeps its **own** label map, because it cannot import that module:
  - `Work` → *Work — implementing, and the cold review*
  - `Answering` → *Fix rounds — answering refusals*
  - `Triage` → *Triage — explaining a stop to you*
  - `Judge` → *Judging*
  - `Discussion` → *Discussion*
- A tag the map does not know is shown under its own name in a neutral colour. It is never dropped, because the bar's shares add up to 1.
- The rule is general: **any** purpose whose share rounds to 0% is neither drawn nor keyed. The ticket's *Discussion only above 0%* is one instance of it.

**Receipts.** Render `books.receipts` in file order. `take-books.ts` puts the median first, then the `--receipt` arguments.
- **Median receipt** (`median: true`):
  - issue `THE MEDIAN TICKET`
  - rows Fix rounds, Machine time, Asked you
  - `costLabel` `MEDIAN COST`
  - stamp `{ text: 'TYPICAL', shown: true }`
  - footnote *● REAL medians, from Lingtai's log*
  - no Open link
- **Real receipt:**
  - issue `ISSUE #n · KIND`, with the kind upper-cased and left out when null
  - rows Fix rounds, Machine time, Asked you, and Passes when `passes > 1`
  - `costLabel` `COST`. Do not write *incl. estimates* on a receipt: the file has no per-receipt flag, and the mock's label would be a claim nobody checked.
  - footnote `<><span className="r-real">● REAL</span> from Lingtai's log · <a className="r-open" href={`${REPO}/issues/${n}`}>Open #n →</a></>`
  - **The link goes inside `footnote`**, which is already a `ReactNode`. That way `receipt.tsx`, and the case that pins it (`page.test.tsx:208–228`), stay unchanged.
- `landed` → status `landed` *✓ Landed*, stamp LANDED. `closed` → status `closed` *Closed*, stamp NOT LANDED.
- **An `open` receipt is possible.** `placed` admits an open ticket that had a pass in the window (`take-books.ts:85–86`). It gets status `waiting` *Open*, **no stamp**, and footnote *still open at the end of the window*.
- **A null `cost`** renders `—`. It is never `$0.00`.

**Reproduce line.** Only the ticket's sentence. Drop the mock's *"Share of spend is over all 283 landed tickets"*: it adds nothing, and it invites someone to multiply.

## Tests (`unit/page.test.tsx`, plus a new `unit/books-section.test.tsx` if it reads better)

- **The fixture** is a literal `Books` passed through `parseBooks`. If `parseBooks` returns null, the fixture is wrong. Choose values whose sums are distinct from every figure. Example: receipt costs 4.02, 9.27 and 11.39, a median of 3.55, a mean of 6.32 and a p90 of 12.
- **No total:** collect every `$\d+\.\d\d` in the rendered section and assert that each one is among the file's own `cost.median`, `cost.mean`, `cost.p90` and receipt costs. This is stronger than checking for one particular sum.
- **No file:** `<HomePage books={null} />` has no *Open its books*. Also, `readBooks('/nonexistent/books.json')` returns `null`. That reads the filesystem, but it is a missing path the read fails on, and `books.test.ts` already does the same.
- **Order case:** keep the existing source-order case as it is. Add a **rendered** case with the fixture: *Why not just give the agent the issue?* < *Lingtai builds Lingtai. Open its books.* < *Three steps to your first receipt.*. The ticket says *when the file exists*, and the source of `page.tsx` will not contain the heading at all.
- **The `log` guard** (`page.test.tsx:48–55`) runs `above()` over the rendered page **twice**:
  - with `books: null`, where the kicker is absent and the whole text must have no *log*;
  - with the fixture, which is the case that actually exercises the anchor, since *log* appears only after *The work, in the open*.
- **Keep `books: null`** in *renders the page beside one receipt in state 0* (`:237–249`). With the fixture, `rcpt` matches five times instead of one.
- **Edge cases:**
  - one figure set to null is not rendered;
  - `includesEstimates: true` shows *includes estimates*;
  - a `Discussion` share of `0.001` has no key;
  - an `open` receipt has no `r-stamp`.

`pnpm test` and `pnpm typecheck` cover all of this. Nothing here needs the integration half. The Next build (`apps/release/integration/build.test.ts`) is the only check that would catch `books-section.tsx` pulling something server-only into a client graph. It is safe because the section is server-only and imports a type alone from `@/lib/books`, but that check runs after the merge.
