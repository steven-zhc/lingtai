# #740 — design note

The ticket's shape is right: a pure rewrite in `migrated.ts`, called first in `entry.ts`. Three things are not in it.

## 1. `entry.ts` uses the rewritten argv everywhere, not only for `routeOf`

`entry.ts:17` sets `const argv = process.argv.slice(2)`, and three places use it:
- `routeOf(argv)` (`:19`)
- `argv[0] === 'init'` (`:47`)
- `unknownCommand(argv[0]!)` (`:54`)

`runCli(process.argv)` (`:28`) does not use it; it rebuilds its own argv from `process.argv`.

Do the rewrite at `:17`: `const argv = versionFlagAsCommand(process.argv.slice(2))`. Then pass `runCli([...process.argv.slice(0, 2), ...argv])`, because `runCli` slices two entries off the front (`cli.ts:1331`, `let args = argv.slice(2)`, under the comment *"`argv` is the full `process.argv` shape"* at `cli.ts:1326`).

If you keep two variables, one with the rewrite and one without, the argv that gets routed and the argv that gets run can differ. The only other `process.argv` read in `apps/cli/src` is `cli-diff.ts:122`, which sits behind `import.meta.main` and is never reached from here.

## 2. `lingtai --version --help` prints `version`'s help, not the root help

The ticket's Edges line says *"`routeOf` checks for `--help` before anything else (`migrated.ts:16`), so help answers, as today."* That stops being true once the rewrite runs before `routeOf`.

`migrated.ts:17` exempts `version` from the help route on purpose: *"`version`'s help is `@effect/cli`'s (#617)"*, so `if (first !== 'version' && helped) return 'help'`. The rewritten `['version', '--help']` therefore routes to `'effect'`, and `migrated.test.ts:10` already pins that row. Today `['--version', '--help']` routes to `'help'` and prints the root help.

Build it as the rewrite makes it: `lingtai --version --help` prints exactly what `lingtai version --help` prints. This is what the ticket's Want asks for (*"`lingtai --version <more>` is `lingtai version <more>`"*). Do not special-case `--help` inside `versionFlagAsCommand`: the function rewrites the first word and nothing else.

Pin it:
- add a row to the new rewrite table: `['--version', '--help']` → `['version', '--help']`;
- add one `runCli` test in `version-cli.test.ts`: `--version --help` gives the same code, stdout and stderr as `version --help`.

## 3. Leave `version`'s `examples` alone

The ticket says `commands.ts` *"may add `lingtai --version` to its `examples`"*. Don't.

`examples` feed the generated `doc/cli.json` and `doc/cli.md`. `cli-doc.ts:3-11` says *"`COMMANDS` owns … the examples"* and *"`unit/cli-doc.test.ts` fails when the committed files differ"*. An added example means regenerating those files with `scripts/cli-doc.ts` in the same commit. The `cli-diff` release note (`cli-diff.ts`) would then also list a manifest change for something that is not a flag of `version`, which is noise.

## Where the tests go

- **The rewrite table:** a new `describe` in `apps/cli/unit/migrated.test.ts`. Its existing `routeOf` table stays as it is, and `[['--version'], 'unknown']` (`:89`) stays true.
- **The `runCli` comparisons:** `apps/cli/unit/version-cli.test.ts`, using its `capture` helper (`:7-14`). It already calls `runCli(['node', 'lingtai', ...args])`, so pass `capture(versionFlagAsCommand(['--version', …]))` and compare against `capture(['version', …])`.

Compare whole results, not substrings. `version --json --bogus` already exits 1 with a usage document (`:32-39`), so the `--version bogus` case can use `toEqual` on the two captures.

Everything here runs in the unit half. Nothing about this change needs `pnpm test:integration`.
