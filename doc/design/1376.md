## Design note: #1376, the docs are a book (ADR 0112)

**The new sections are §13 to §20, not §12 onward.** The ticket says to add them "after §11" and to check that 0112 "carries §12 onward". But 0112 already has a §12, *"**The site serves the installer.**"*, at `doc/decisions/0112-the-site-projects-the-repository.md:81-86`. Leave it alone and keep its number, because other files may already cite it. Append the ticket's eight rules after it as items 13–20. That box in `## Done when` is met by "§13–§20 as the ticket lists them". Inside the text, the rules point to each other by their new numbers:

- §14 is the 600–800 word rule (the ticket calls it §2).
- §17 says previous and next follow the order in §13 (the ticket's §5 and §1).
- A reviewer holds a chapter to §14–§17 (the ticket's §2–§5).

The ticket's own numbering is never copied in.

**Where the text goes.** Keep the same numbered list under `## Decision`, in the style already there: a bold sentence that states the rule, then plain text after it. Items 10 and up are indented 4 spaces (`:72-86`). The chapter table belongs to item 13, so it goes under that item with a blank line above it and the same 4-space indent. Without the indent the Markdown renderer ends the list and restarts numbering at 1. Put the comic-garden sentence on its own line inside item 13, after the table.

**Chapter files are code spans, not links.** `team.md`, `pull-requests.md`, `board.md`, `tickets.md` and `checks-and-spend.md` do not exist yet. Write every file name in the table and in items 18–19 as `` `file.md` ``, as the ticket does. That way the ADR links to nothing that is missing, and a later chapter ticket does not have to fix a broken link. The comic-garden URL is the only new link.

**`## Consequences` gets one bullet**, worded like the ones there (`:88-99`). A chapter over 800 words is refused in review. No test counts the words, so the reviewer is the only check. This covers the ticket's "cost to later tickets" edge in the ADR itself.

**`doc/README.md:100`.** Add the book to the description cell after "showing the real board", e.g. *"…showing the real board, and the docs are a ten-chapter book beside reference pages"*. Leave the status cell as `accepted`. The row's columns are padded to line up. Re-pad the row so the `|` characters stay in line with the other rows, and change no other row.

**Unchanged:** the `**Status** accepted · 2026-10-01` line (`:3`) and the footer *"Replaces archived 0035"*. The ADR states the current decision, so it says nothing about #1343's old placement. That belongs in the commit message, as `0112: the docs are a ten-chapter book, read in order, beside reference pages`. Do not put "closes" or "fixes" next to #1343 there.

**Checks.** The root `"lint"` script is `oxlint --type-aware --deny-warnings` (`package.json:18`), and it lints code. Run `pnpm fmt:check` too, in case the formatter covers Markdown. Then run `pnpm lint` and `HOME=/nonexistent pnpm test`, and confirm with `git status` that only those two files changed.
