# #1349: re-reduce an older-shape ticket row on read, and backfill it after start (design note)

#1348 has landed. Its pieces are what this ticket builds on:
- `ticketBefore` and `runBefore` (`packages/projector/src/ticket-row.ts:39-85`);
- `ProjectionLog` (`packages/projector/src/store.ts:209-214`);
- the runner's `noteOnce` (`packages/projector/src/projection.ts:189-195`).

`ticketReportRowOf` still carries the comment *"this read has no log and does not, so it still throws"* (`ticket-report.ts:219`). That line is what this ticket replaces.

## 1. The read side: an option on the read, not a new Effect run

The board's callers are `async` promise code that call promise faces: `readTicketReport` (`read-ticket-report.ts:25-27`) from `apps/board/src/lib/report.ts:196`, and `readLanded` from `landed.ts:255`. A shared helper the board runs itself would be either a new `async` function or a new `Effect.runPromise`, and the ratchet counts both (`packages/domain/unit/effect-ratchet.test.ts`). So **don't write a helper the board runs. Put the re-read inside the existing read Effects:**

```ts
// read-ticket-report.ts / read-landed.ts
export interface ReadTicketReportOptions extends TicketReportQuery {
  url?: string
  /** One ticket's state off the log, for a row whose stored state is of an older shape (#1349). */
  reread?: (ticket: string) => Effect.Effect<TicketState, unknown>
}
```

- `readTicketReportEffect` and `readLandedEffect` read their rows as they do today. Then they pass them through one helper, `fillStale(rows, reread)`, in `ticket-report.ts` beside the mapper. The helper uses `Effect.forEach(stale, …, { concurrency: 8 })`.
- The promise faces already run these Effects, so the count of `Effect.run*` does not move.
- **The projector does not import the conductor.** `readState` lives in `packages/conductor/src/snapshot-state.ts:13`. The caller hands over a function, and the board's function is `(t) => readThroughSnapshot(eventStore, ticketReducer, t, 'all', { snapshots: log.snapshots, writer })`. The parts come from:
  - `readThroughSnapshot`: `@lingtai/event-store`, `snapshot-read.ts:55`;
  - `ticketReducer`: `@lingtai/domain`, `ticket-codec.ts:182`;
  - the `eventStore`, `log.snapshots` and `boardWriterOrNone()`: the same values `board.ts:1569` uses.
- The CLI passes the same function with `{}`. `readThroughSnapshot` with no `snapshots` does one `full` read and writes nothing (`snapshot-read.ts:71-77`).

**The task page passes no `reread`.** `typicalAttemptMs` reads `outcome`, `outcomeAt`, `passes`, `intervalsOpen`, `intervalsEmpty` and `machineMs` (`apps/board/src/lib/queued-estimate.ts:30-45`). It reads none of the three fields that come from the state. If the page re-reads, every queued ticket's page pays a stream read for each stale row, and the figure does not change. The ticket lists this caller under "the read sites that throw". Fixing the mapper is enough to stop it throwing, and that is the whole of that caller's fix. `apps/site/scripts/books.ts` also calls the read; leave it as it is too.

**The row shape.** `TicketReportRow` gains `unread: string | null`.
- The mapper sets `unread: 'stored in an older shape'` and `title: ''` on a `TicketCodecError`, with `mergeCommit` and `satisfiedAt` set to null. A private `stale` flag is not needed: `unread !== null` is the mark.
- `fillStale` replaces each stale row with one of two results:
  - the re-read's `title`, `mergeCommit` and `satisfiedAt`, with `unread: null`; or
  - on failure, `unread: <the error's message>` and `title: 'could not read this ticket's state: <message>'`.
- A reader with no `reread` (the task page, `books.ts`) gets the second form with *"not re-read here"*. Setting `title` as well as `unread` means every existing renderer shows the sentence without being changed. A renderer may style on `unread` if it wants to.
- **An empty stream** is a failure, not a ticket. `readThroughSnapshot` folds from `reducer.initial` (`snapshot-read.ts:75`), so a stream with no events returns `emptyTicket` itself. Test `state === emptyTicket` by reference. If `reduceFrom` turns out to copy the state, compare `title === ''` instead, and say so in a comment.
- Catch only `TicketCodecError` in the mapper. Its Postgres and SQLite callers (`postgres.ts:538`, `:569`; `sqlite.ts:805`, `:836`) stay as they are.

**A failed re-read is a value, not a failure** of the read Effect: use `Effect.result` or `Effect.catch` per row inside the `forEach`. One bad stream must not cost the page (Fix 3).

## 2. The backfill: one lane per runner, cursor-bounded

The one non-obvious thing here is how *"between batches"* is made true. The fenced `advance` will not do it for you. `ADVANCE_CHECKPOINT_FENCED` refuses only a rewind (`where checkpoints.last_seq >= $3`, `postgres.ts:54-60`). A batch that committed *forward* under the backfill passes the fence. The backfill would then write the state as of the old checkpoint over a row that already holds the newer event, and that event would be lost. That is the trap in the ticket's *Watch out* row, in the other direction.

**So serialise in process.** In `makeRunner` (`projection.ts:173`):
- Add `const lane = Semaphore.makeUnsafe(1)`. SQLite's store does the same at `sqlite.ts:444`.
- Wrap `commitBatch` in `lane.withPermits(1)`.
- The backfill takes the same permit for each of its transactions.

While the backfill holds the permit, `state.cursor` (`projection.ts:206`) is exactly the checkpoint. This runner is the only writer (0100 §13), and nothing commits under it.

- **Where it starts:** at the end of `startFollowing`, after `Deferred.await(caughtUp)` (`projection.ts:279`), fork it into the same `scope`. That way `stop`, a drain and `rebuild` all interrupt it by closing that scope (`projection.ts:288-294`). The permit is held only inside one transaction, so an interrupt between transactions leaves nothing half done. `rebuild` calls `startFollowing` again, which starts a backfill that finds nothing.
- **Each step:** one `p.transact` under the permit. Inside it, call `projection.backfill?.(ctx, log, state.cursor + 1n, after, 50)`, then `p.advance(ctx, name, state.cursor, state.cursor)`. The advance moves nothing. It is there to refuse a rewind done from another process, exactly as a batch's advance does. The bound is `+ 1n` because `ticketBefore` keeps `e.seq < beforeSeq` (`ticket-row.ts:56`), so the checkpoint's own event is included.
- **The `Projection` interface** (`store.ts:~164-202`) gains one optional member:
  ```ts
  backfill?(ctx, log: ProjectionLog, beforeSeq: bigint, after: string | null, limit: number)
    : Effect.Effect<{ rewritten: number; next: string | null }>
  ```
  - It pages by primary key: `where key > $after order by key limit $limit`.
  - It decodes each row in JS. SQL cannot tell an old shape from a new one.
  - Only an undecodable row goes through `ticketBefore` or `runBefore` with `beforeSeq`.
  - It updates only the state column.
  - `next === null` means the scan is done. **One scan over the keys is the whole job.** A row written by a batch during the scan is written in the new shape, so nothing needs a second scan.
- **The implementers, and the tables each covers:**
  - `ticket_report`: `ticket_state`, keyed `ticket` (`ticket-report.ts:462`).
  - `spend_ticket`: `state`, keyed `ticket` (`spend.ts:142-144`).
  - `task_view`: three tables, scanned one after another:
    - `task_view.ticket`;
    - `task_view_ticket.ticket` (`task-view.ts:236-238`);
    - `task_view_run.run`, keyed `run_id`, which needs `runBefore` (`task-view.ts:225-229`).

  The ticket's *Out of scope* list leaves out the run codec *"unless #1348 found a projection storing them"*. #1348 found one: `task_view_run` (`doc/design/1348.md`, *"the only projection that does"*). So it is in.
  - The backlog projection and the contract projection do not implement `backfill`.
- **A failed stream read.** `log.read` dies, and that is a defect (`store.ts:210`). Inside the backfill it would roll the transaction back and end the fiber silently. Wrap each row's `ticketBefore` in `Effect.exit`. On a failure, `log.note` names the stream and the error, and the row is skipped. The scan goes on.
  - Never route a backfill failure into `state.failure`. Only `follow`'s handler sets that (`projection.ts:268-271`), and the daemon reads it as *the projection stopped*.
  - A defect that escapes anyway ends with `Effect.catchCause` → `note`, and nothing else.
- **The per-row note.** `ticketBefore` already calls `log.note` once for each row it re-reduces. Hand the backfill a `log` whose `note` does nothing on success. Otherwise a version bump prints a line for every closed ticket.
- **The once-per-projection line** (`<projection>: rewrote N ticket rows of an older shape`): print it when the scan ends and N > 0, through the runner's `noteOnce`. The daemon already routes that to `tell` or `log` (`packages/daemon/src/daemon.ts:157`, per #1348).
- **Yielding:** call `Effect.yieldNow` between steps, and release the permit between transactions. That is all the yielding needed: a waiting batch takes the permit next. Do not add a sleep. A scan of a few thousand rows is a few dozen transactions.

## Tests (unit project only)

- **Mapper:** test it directly with a `ticket_state` that has `landed` removed, and with a non-codec throw.
- **`fillStale`:** use a stub `reread` with three cases: it succeeds, it fails, and it returns `emptyTicket`. The test asserts the concurrency cap by counting the in-flight calls.
- **The board's snapshot offer:**
  - Use a memory store for the events and a recording `writer`.
  - Call the reread function `report.ts` builds.
  - The snapshot is written only past a commit boundary (`snapshot-read.ts:115`), so append enough events to cross one. Otherwise assert nothing about the offer.
- **Backfill:**
  - Use `reduceFace` to seed the rows, or a runner with `into:` a SQLite `:memory:` port if the unit project already has one; check `packages/projector/unit` for a SQLite unit harness before choosing.
  - Overwrite one row in the old shape, then append one more event past the checkpoint.
  - Run one backfill step at `cursor + 1n` and assert the row folds only the events up to the checkpoint.
  - Reduce the last event and assert it is counted once.
- **The race the semaphore closes** is a Postgres-and-timing claim, and only `pnpm test:integration` could show it. The unit claim that stands in for it: a runner test where `commitBatch` and a backfill step are started together, and the second one waits for the permit. Assert the order with a spy on the store port's `transact`.
- **Ratchet:** no new `async` and no new `Effect.run*`. Never raise `effect-ratchet.baseline.json`.
