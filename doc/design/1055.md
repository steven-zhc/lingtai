# Design: #1055 — step bodies become Effects

The ticket gives the shape. This note settles one decision the ticket leaves open, and that decision is the one most likely to be got wrong.

## `end` recovers with `Effect.exit`, not `Effect.catchDefect`

The ticket allows either `Effect.catchDefect` or `Effect.exit` with a match on `Die`, and its worked example uses `catchDefect`. **Use `Effect.exit`.** The reason is in this file already. `runStepBody` handles the same problem one layer up and says why it does not use `catchDefect` (`packages/conductor/src/run-attempt.ts:2187-2190`):

> **A defect is a verdict and an interruption is not** (#1053). `Effect.catchDefect` would recover a cause that also carries an interrupt, turning a drain into *did-not-finish: threw*; so the interrupt is looked for first and passes through untouched.

Then at `:2191-2201`:

```ts
return Effect.exit(visit).pipe(
  Effect.flatMap((exit) => {
    if (exit._tag === 'Success') return Effect.succeed(exit.value)
    if (Cause.hasInterrupts(exit.cause)) return Effect.failCause(exit.cause)
    return Effect.succeed<StepReached>({ … threw(spec, Cause.squash(exit.cause)) … })
  }),
)
```

The package is on `effect@^4.1.2` (`packages/conductor/package.json:69`). Under it, `catchDefect` on a cause that holds both a `Die` and an `Interrupt` recovers it. That happens when a drain interrupts `end` while `recordEnd` or a finalizer dies. The result is a drained pass recorded as `END_UNRESOLVED`, which is the verdict-from-an-interruption the Watch-out row forbids.

`end`'s catch must have the same shape:
- Run the generator under `Effect.exit`.
- On `Success`, pass the value through.
- If `Cause.hasInterrupts(cause)`, return `Effect.failCause(cause)`.
- Otherwise build the `StepDidNotFinish` from `Cause.squash(cause)`.

That last branch keeps today's `detail` wording and the act name. Because the error channel is `never`, everything left after the interrupt check is a defect, as at `:2190`.

There is a unit-level claim for this, beside the `Effect.never` case in Done-when, if the agent wants it. Build a `recordEnd` that dies inside an interrupted fiber, and assert the exit is interrupted rather than `did-not-finish`. Without that test, nothing in the unit half tells `catchDefect` and the exit match apart, because a pure interrupt passes through both.

## `act` belongs to one run of the Effect

The ticket's example declares `let act = 'read'` outside `Effect.gen`. It is safe today, because `end` builds a fresh Effect on every call and `runStepBody` yields it once (`run-attempt.ts:2163-2165`). It stops being safe if the Effect is ever run twice.

Wrap the whole thing in `Effect.suspend(() => { let act = 'read'; return Effect.exit(Effect.gen(…)).pipe(…) })`. Then the counter belongs to each run, and the exit handler that reads it sits in the same closure.

## `runStepBody`

Delete the `Effect.promise` lift (`run-attempt.ts:2164-2178`) and its comment *"A step's body stays a promise (`StepBody`) until STEPS-1"*, and `yield*` the body directly. Leave the `as StepBody<Step>` cast and its comment (`:2157-2163`) alone. The union-of-callables problem it explains is the same with an Effect return type.

`StepWork.emit` stays a promise. It is built here as `(event) => Promise.resolve(options.emit(event)).then(…)` (`:2177`), and the emit path is out of scope. A body that calls `emit` wraps it in `Effect.promise`.

## The face

`AttemptOptions` still lifts the promise ports `judge`, `mergeBase` and `baseIsRed` with `Effect.promise` (`run-attempt.ts:1026-1044`). Those ports belong to CONDUCT-2 and later, so leave them. `bodies` is not in that list today, and nothing should start lifting it there. As the ticket says, tests hand Effect bodies through the face.
