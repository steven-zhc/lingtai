# Design note for #1380: chapter 5, `doc/board.md`

Writing the page is straightforward. The traps are in the site's unit tests: three of them pin the book and the public slugs as they are today, so adding the `BOOK` row and the slug turns them red. The ticket does not mention any of them.

## Tests that go red, and what to change

1. **`apps/site/unit/page.test.tsx:130-144` checks `PUBLIC_SLUGS` exactly.** Put `'board'` directly after `'concepts'` in `apps/site/src/lib/docs.ts:70`, so the list follows the book's order. Make the same insertion in the test's list.

2. **`page.test.tsx:106-121` builds the Docs menu from `PUBLIC_SLUGS`.** It requires every public slug to be in `DOCS_MENU` (`apps/site/src/app/chrome.tsx:24-35`) unless the test excludes it. Two slugs are already excluded because readers reach them through the book, not the menu: *"#1295: so is when-it-fails, listed in the Guides"*. Do the same for the board page:
   - add `s !== 'board'` to the `inMenu` filter;
   - extend the comment with `#1380: and board, reached through the book`;
   - leave `DOCS_MENU` and its label assertion unchanged.

   The menu is site navigation. Changing it is not part of this ticket.

3. **`apps/site/unit/docs.test.ts:551-553` and `:564-570` hard-code the book's neighbours.** With chapter 5 in `BOOK`:
   - `neighboursOf('concepts', all).next` becomes `board.md`, not `when-it-fails.md`;
   - in *skips a chapter that is not served*, removing `concepts` makes the tutorial's next `board.md`, and `when-it-fails`' previous `board.md`.

   Change these expectations rather than the fixture. They describe the book as it now stands. The test also says *"the chapters either side of one"*; keep checking concepts and add one line for `neighboursOf('board', all)` (previous `concepts.md`, next `when-it-fails.md`).

The `BOOK` row is `{ n: 5, part: 'Understand it', file: 'board.md' }`, placed between rows 4 and 7. `docs.test.ts:545-546` requires the numbers to rise strictly, and `:44-51` requires the file to exist, so the row and the file go in the same commit. The first check below runs all of these.

## Page shape the site already enforces

- Line 1 is `# The board` and line 3 is an `*italic subtitle*`, the same shape as `doc/concepts.md:1-3` and `doc/when-it-fails.md:1-3`. Adding `board.md` to the `SHORT` map at `docs.test.ts:521-529` is not required.
- The sidebar title must be three words or fewer (`docs.test.ts:515-518`). *The board* is fine.
- `doc/concepts.md` already ends with `[The board](board.md) is where you watch an attempt and choose at a wait.` That link resolves once the slug is public. Write the page's opening paragraph to deliver on that sentence: what the board shows, and where you act when something is waiting on you.

## The key table, from the code

The ticket's evidence is correct but incomplete. In `apps/board/src/app/palette.tsx`, the component that wires `search.ts`'s functions to `keydown`, three behaviours are not in the ticket's list. The "every binding is in the table" check counts them:

- **`⌘K` / `Ctrl+K` toggles.** With search open it closes it (`palette.tsx:183-186`). Inside a field it does nothing, and the field keeps the key: *"A key is never bound while focus is in a field: ⌘K there is the field's own"* (`:188-189`). In the table: *open or close search*.
- **`#` and `G …` are off while search is open** (`palette.tsx:195`: `if (d === null || d.open) return disarm()`). While open, only the palette's own keys apply. Give the table a "where" column with three values: *anywhere outside a field*, *in search*, *in a discussion box*.
- **`G P` does nothing on a solo project; it is not an error.** `follow` clicks `[data-go="p"]` and returns `false` when that element is missing (`palette.tsx:166-169`). `place-line.tsx:50` only gives the PRs view `key: 'P'` on a team project. `G T` falls back to the brand link when there is no Tickets view (`palette.tsx:167-168`). In the row: *team project only*.

The palette keys are `paletteKey` (`search.ts:330-358`): `↑`/`↓` wrap around, `Home`/`End` jump, `Enter` opens, `⌘Enter`/`Ctrl+Enter` opens in a new tab (`metaKey || ctrlKey`, `:353`), and `Esc` closes. The discussion box: `Enter` sends, `Shift+Enter` makes a new line (`discussion.tsx:389`). One sentence carries the rule for all of them: no key works in a field (`search.ts:288-291`, `inField`) or while an IME is composing (`:273-274`).

## The `the-bar.md` bullet

The hint line #1379 was to draw already exists: `palette.tsx:108-110` renders `↑↓ select · ↵ open · ⌘↵ / Ctrl ↵ new tab · esc close · # a number · G T / G P / G S go`.

So in `doc/design/the-bar.md:209-215`:

- Change only the sentence *"Nothing pops up to teach them: each control's tooltip shows its key, so they are learnt by using the mouse."* to say that the palette lists its keys in one line at its foot, and that each control's tooltip still shows its key.
- Leave the rest of the bullet alone, including the `doc/milestone/later/keys.md` pointer.

The page may say the same thing, but `doc/board.md`'s table stays the complete list. The hint line leaves out `Home`/`End` and the discussion-box keys, so do not describe the hint line as all the keys.

This is a design note, not an ADR, so editing it in place is correct. No accepted ADR is contradicted.
