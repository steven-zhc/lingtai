The ticket's Evidence list is incomplete, and how to fix the sites it missed is the one decision the ticket leaves open. My answer: fix it in each helper, not at each place a helper is called.

## Where the fix goes

`Effect.tryPromise` passes the fiber's `AbortSignal` in both of its forms, not only the `{ try }` form. In `node_modules/.pnpm/effect@4.1.2/node_modules/effect/src/internal/effect.ts:1150-1156` the signature is `options: { readonly try: (signal: AbortSignal) => PromiseLike<A> … } | ((signal: AbortSignal) => PromiseLike<A>)`, then `const f = typeof options === "function" ? options : options.try`, and `:1171` calls `f(signal!)`. So `Effect.tryPromise(someFn)` has the same bug as `{ try: someFn }`.

The ticket ran its grep over `apps` and `packages`, but its list covers only `apps/cli` and `propose-setup.ts`. The same grep, plus the bare-function form and the multi-line form, finds these as well:

- **Helpers of `lift`'s shape** (`<A>(f: () => Promise<A>) => Effect.tryPromise({ try: f, … })`):
  - `packages/daemon/src/reconcile.ts:120`, `packages/daemon/src/converge.ts:244`
  - `packages/event-store/src/snapshot-read.ts:38`
  - `packages/conductor/src/ticket-store.ts:162`, `split-ticket.ts:128`, `backlog.ts:183`, `onboard.ts:79`, `create-app.ts:451`, `discuss.ts:848`, `tell.ts:222`, `base-check.ts:87`
  - `packages/repo/src/worktree.ts:119` and `:160` (`try: f,` on its own line)
- **Bare references passed straight in:**
  - `packages/conductor/src/add-from-page.ts:284` (`try: ports.projects`)
  - `packages/repo/src/git.ts:121` (`try: options.token`)
  - `packages/conductor/src/telemetry.ts:165` (`Effect.tryPromise(flushing)`)
  - `packages/conductor/src/conduct.ts:824` (`Effect.tryPromise(options.recipe)`)

**Decision: in every helper, change `try: f` to `try: () => f()`, and do the same at every direct site above.** Don't audit the callers.

The ticket's rule is "wrap it where `x` takes any parameter", and applying it caller by caller cannot be finished. `exit.ts`'s `lift` alone is handed bare members of objects whose defaults live elsewhere:

- `restart.ts:1475`, `:1489` (`lift(take)`) and `:1505` (`lift(holder)`)
- `restart.ts:608-615` (`lift(promised.doctor)`, `lift(promised.holder)`, …)
- the `lift(o.liveness)` … `lift(o.board.heldBy)` lines at `:72-86` of the file that builds those faces

Each of those is safe only if every implementation behind it, now and later, takes no parameter. `readStatus(store?: DaemonStore)` (`packages/daemon/src/control.ts:702`) is the counterexample.

Wrapping in the helper makes the question disappear for every present and future caller. It costs nothing, because `callbackOptions` still receives its own `function(resume, signal)`, so interruption still aborts what it aborted before (ticket, *Interruption*).

Keep each helper's parameter type as it is (`() => PromiseLike<A>` / `() => Promise<A>`). Keep each helper's `catch` exactly as it is, too: `exit.ts`'s `(e) => e` (#1088), and the `asFailure`, `reasonOf` and `RepoFailed` ones elsewhere.

**`git.ts:121` is the one site to read before wrapping.** `TokenSource`'s function form (`packages/repo/src/git.ts:14-16`, *"something that will produce a current one"*) is an installation-token getter. If its declared type takes a parameter, that parameter is the only thing a signal could have been meant for. If the type is zero-arity, wrap it like the rest. If it takes a signal on purpose, write `(signal) => options.token(signal)` and say so in the commit, as the ticket's first Edge asks.

The three test-file helpers the ticket names (`triage-trigger.test.ts:18`, `triage-catch-up.test.ts:23`, `ticket.test.ts:51`) get the same one-line change, so the stubs they wrap can't mask the bug again.

## Tests

The two tests in *Done when* are enough as the ticket writes them:

- `lift` with the `(x?: unknown) => x === undefined ? … : reject` probe
- `memoDaemonStartedAt` with a `read` that rejects when given an argument, beside the existing case at `apps/cli/unit/triage-catch-up.test.ts:253-270`

Don't add a probe test for every other helper. They're private (`const`, not exported), and the one-token change is the whole of what they're held to.

## What settles it after the restart

Behaviour is settled by the log, and the restart is the operator's step. The claim to check is that a daemon whose `ConductorStarted.commit` is this merge stops logging `triage catch-up lingtai: it.status is not a function`. The event that shows triage running again is the next `WaitStarted` on a ticket, followed by triage's own record of that wait leaving `Queued`. On the task page of #1109, that means it no longer reads *"triage is waiting to run"*.

## Commit body

For every site, the commit body states that the call has no argument now. The ticket's "named as a zero-parameter closure already" option no longer comes up, because nothing is left unwrapped. Only the `git.ts` token site gets a sentence of its own: say whether it took a signal.
