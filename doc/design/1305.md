# #1305: `lingtai token copilot`, design note

This copies `lingtai token claude` with one step taken out: there is no child process to run. Three decisions are not obvious from the ticket, plus one generated doc that turns the unit suite red if it is forgotten.

## Where it goes

- **`packages/setup/src/copilot-token.ts`** is new, sits beside `claude-token.ts`, and is exported from `packages/setup/src/index.ts:17`'s barrel the same way.
- **`apps/cli/src/copilot-token.ts`** is new and sits beside `apps/cli/src/claude-token.ts`.
- **`apps/cli/src/cli.ts`**: add a `tokenCopilot` command built like `tokenClaude` (`cli.ts:1168`), and add it to `Command.withSubcommands([tokenClaude])` (`cli.ts:1197`).
- **`apps/cli/src/commands.ts:667`**: the `token` definition. Its `task` (`'set the token a sandboxed Claude Code run holds'`) becomes runtime-neutral, and `usage` gets a `lingtai token copilot` paragraph. Then **run `pnpm docs:cli` and commit `doc/cli.json` and `doc/cli.md`**. `apps/cli/unit/cli-doc.test.ts` compares the committed files with what the definitions render, and fails with *"doc/cli.json is stale — run `pnpm docs:cli` and commit it"*. Done-when's "`lingtai token --help` lists `copilot`" is this definition plus the parser's subcommand.
- **`doc/safety.md:123`** has "## The Claude token". Add a short "The Copilot token" section after it, saying which kind of token and that `LINGTAI_COPILOT_GITHUB_TOKEN` wins over the file. It is not a gate, but it is the page that tells a person this key exists.

## Decision 1: one document edit, not two copies of it

`setClaudeTokenEffect` (`packages/setup/src/claude-token.ts:104`) holds about forty lines that carry the secret-handling rules:
- read through `MachineText`;
- refuse on `doc.errors` without quoting the parser;
- refuse a file that is not a mapping;
- refuse a section that is present but not a mapping (`claude: null` or `[]`), because *"`setIn` throws on that, which is a defect, not a refusal"*;
- `doc.set` versus `doc.setIn`;
- write;
- every refusal sentence names only the path.

Copying those lines means a later fix to one copy does not reach the other. **Pull them into one unexported function in `packages/setup`**, taking `(file, path, section, key, token)` and failing with the sentence alone. The secret is still unwrapped in exactly one place: that function's `setIn`/`createNode`, which is where the header puts it (*"unwrapped in exactly one place — the `setIn` below"*). Then:

- **`setClaudeTokenEffect` keeps its exact signature and its `ClaudeTokenRefused` error**, so `packages/setup/unit/claude-token.test.ts` and its callers (the CLI and the board) do not change.
- **`setCopilotTokenEffect(file, path, token, env)`** returns `Effect<{ saved: true; environmentWins: boolean }, CopilotTokenRefused>` and has its own `_tag`. The section-not-a-mapping sentence names `copilot` and not `claude`.

Effect only: no `async` and no `Effect.run*` in either file. `packages/domain/unit/effect-ratchet.test.ts` counts both, and the baseline never goes up.

## Decision 2: what the shape check refuses, and in which order

`validateCopilotToken` mirrors `validateClaudeToken` (`claude-token.ts:84`): trim first, then check, and the result is a fresh `Redacted` of the trimmed value. The refusals, in this order:

1. empty → `the token is empty`
2. whitespace inside → the same sentence Claude's uses
3. starts with `ghp_` → **`a classic token, which Copilot ignores; make a fine-grained token with the Copilot Requests permission`**, as the ticket gives it
4. anything else not starting with `github_pat_` → one generic sentence: `the token does not start with github_pat_ — make a fine-grained token with the Copilot Requests permission`

Don't give `gho_`/`ghu_`/`ghs_` their own cases. The ticket names only `ghp_`, and `gh auth token`'s `gho_` belongs to the generic sentence (`packages/env/src/index.ts:292`: *"never `gh auth token`'s"*). The prefix is a constant, `COPILOT_TOKEN_PREFIX = 'github_pat_'`, beside `CLAUDE_TOKEN_PREFIX` (`claude-token.ts:47`). Naming the kind ("a classic token") is not quoting the value. No sentence includes any part of what was typed.

## Decision 3: "the environment wins" comes from the reader's own predicate

Claude's checks `raw !== undefined && raw !== ''` on the variable directly (`claude-token.ts:148`), with a comment about how its reader behaves. Copilot's reader is `stringAt(environmentProvider(from), 'copilot', 'github_token') ?? stringAt(file.provider, …)` (`packages/env/src/index.ts:304`). So the file is shadowed exactly when `stringAt(environmentProvider(env), …)` is defined, and that is what `copilotTokenState(...).environment` (`index.ts:317`) already computes.

**Use that, don't re-derive it**:
- In the CLI, the state is already read before the prompt (see `stateOf` below); use it for the warning before the prompt and for the sentence after the save.
- In `setCopilotTokenEffect`, compute `environmentWins` the same way if `@lingtai/setup` may import `@lingtai/env`.
- If that dependency would be new, don't add it: return what the CLI passes in.

Give the sentence its own constant naming `LINGTAI_COPILOT_GITHUB_TOKEN`. `environmentWinsSentence` (`claude-token.ts:150`) has the Claude variable hard-coded.

## The command

`copilotTokenCommand(world)` follows `claudeTokenCommand` (`apps/cli/src/claude-token.ts:170`), step for step, except where noted:

- **The world** is `Pick<QuestionWorld, 'ask' | 'log'> & { machine, path, env, interactive }`. There is no `run`, because there is no `claude setup-token` equivalent.
- **The state** comes from a `stateOf` over `copilotTokenState`, shaped like `claude-token.ts:119`. A read that throws becomes `unreadable` with a sentence that names the path and `copilot.github_token`; that case logs and returns 1.
- **No terminal**: refuse with 1, and the sentence points to setting `copilot.github_token` by hand.
- **A token already set**, in the environment or the file: the same `keep`/`replace` choice; `keep` returns 0 and changes nothing.
- **The prompt** is `world.ask('', { message: …, defaultValue: '', secret: true })`. `secret: true` is what draws `clack.password` (`apps/cli/src/prompt.ts:80`); `question.ts:35`: *"Drawn hidden, and never echoed"*. The message says which token to make (fine-grained, *Copilot Requests* account permission).
- **An empty answer, or `null` from a cancelled prompt**, is a skip: `skipped — nothing was changed`, return 0. A Ctrl+C that rejects `ask` propagates through `Effect.tryPromise` before anything is written, so it also writes nothing.
- **A refusal** logs `refused.say` and returns 1. **Do not ask again in a loop**: the ticket says exit 1 on a refusal, and re-asking would make a test that drives a bad value hang.
- **A save** logs `saved copilot.github_token in <path>`, plus the environment-wins sentence when that applies, and returns 0.

The live world is built like `liveClaudeTokenWorld` (`claude-token.ts:205`): `path` is `join(stateDir(env), 'config.yml')`.

Do not add an `askCopilotTokenForRecipe` to `init`/`add` (the counterpart of `askClaudeTokenForRecipe`). The ticket asks for the command only.

## Tests

Both halves are unit tests over a `MachineText` fake, as the Claude ones are (`packages/setup/unit/claude-token.test.ts`, `apps/cli/unit/claude-token.test.ts`). Neither touches `node:fs`.

- **Setup half**:
  - a `github_pat_` value is saved and every other key and comment survives;
  - `copilot: null` and a missing `copilot:` are both written; `copilot: []` is refused;
  - unparseable YAML is refused, and `write` was never called;
  - `ghp_`, `gho_…` and empty values are refused, each with its sentence, and `write` is not called;
  - surrounding whitespace is trimmed;
  - whitespace inside is refused.
- **CLI half**:
  - keep, replace, skip;
  - non-interactive exits 1;
  - environment set means the warning and the sentence are both logged;
  - refused exits 1.
- **The secret claim**: use one distinctive sentinel (for example `github_pat_SENTINEL…` and `ghp_SENTINEL…`), and in every test assert it appears in no logged line, no `say`, and no `JSON.stringify` of the returned value. It may appear only in the text passed to `write`. Also seed the file with an *older* sentinel token on a line that breaks the YAML, and assert the refusal sentence does not contain it. That pins *"the YAML parser's message is never quoted"*.

`pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover all of this. Nothing here needs the integration half: the one real-filesystem piece, `liveMachineText`'s write-beside-then-rename (`claude-token.ts:33`), is reused as it is.
