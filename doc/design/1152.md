## The stand-in names go into the mirror's `info/exclude` during provisioning

**Where the write happens:** `ensureMirrorEffect` (`packages/repo/src/worktree.ts:101`) gains an optional `exclude?: readonly string[]`. `ProvisionOptions` (`:23-58`) gains the same field and passes it through at `:164-172`.

- The write goes inside the `mirrorWrite` `Effect.gen` (`:126-147`), after both the fetch path and the clone path.
  - Today the fetch path `return`s at `:139`, so restructure it so the write runs on both paths.
  - The clone path deletes the mirror and clones it fresh (`:142-143`), which replaces `info/exclude` with git's template. The write has to follow it, or a re-cloned mirror carries no names.
- `@lingtai/repo` does not depend on `@lingtai/sandbox` and should not start to. The caller passes the names in.

**The merge function (pure, in `exclude.ts`):** `(existing text, names) → text`.

- Keep every existing line, comments and git's template included, in order.
- Append each name that is not already a line, once.
- Return the input unchanged when nothing is missing. "Twice leaves each name once" is a property of this function, and a unit test pins it.

**The file IO around it:**

- Read `<mirror>/info/exclude`. A missing file reads as `''`.
- **Write only when the merged text differs from what was read.** Once a project has been provisioned under the sandbox, later passes write nothing.
- When a write is needed, write a temporary file in `info/` and `rename` it over `info/exclude`. The `mirrorWrite` hold serialises writers only. A sandboxed command of another pass may be reading the file at the same moment, and a rename means it never reads a half-written file. (That concern is why the branch moved to per-command files in the first place.)
- A failure becomes `RepoFailed({ operation: 'provision', … })`, like the other writes there (`:157-163`), and fails provisioning with its message.

**The caller:** `conduct.ts`'s one `repo.provision({...})` (`packages/conductor/src/conduct.ts:2864` on this base) gains `...(sandboxDecision.kind === 'sandboxed' ? { exclude: standInExcludes } : {})`.

- `sandboxDecision` is already in scope there: the branch computes it before the claim (`agent/1152:packages/conductor/src/conduct.ts`, `const passSandbox = yield* decidePassSandbox(...)`).
- Any other decision passes no key, so the call is today's call.
- No other caller of `ensureMirrorEffect` passes `exclude`, so landings and sweeps are unchanged.

## Consequences to accept, and write down in `stand-ins.ts`

- **A sandboxed project, inside srt or out:** `info/exclude` is read by every worktree of the mirror, including the kept run's own `git add -A` at `implement`, which runs outside srt. So an *untracked*, root-level `/.vscode/…`, `/.idea/…`, `/.mcp.json` or `/.gitmodules` is not added in a sandboxed project, inside srt or out of it.
  - Nested copies are still added, because each name is anchored to the root.
  - Tracked files are unaffected, because exclude applies only to untracked paths.
  - The ticket chose anchoring for exactly this reason.
- **A project that turns the sandbox off:** its names stay in `info/exclude`. The ticket says that under any other decision nothing is written, and removing a line is a write. The same root-level limit then applies to its unsandboxed passes until the mirror is re-cloned. Say so in the comment rather than adding a removal.
- **Git inside srt warning that it cannot read the operator's global excludes file:** accepted, and not this ticket's to fix (the 2026-11-13 answer).

## Tests: what is unit and what is not

- **Unit, the merge function:**
  - Existing lines and comments are kept.
  - Each name is appended once.
  - Running it a second time returns its input unchanged.
  - Every name is root-anchored (`standInExcludes` against `SRT_STAND_INS`).
- **Unit, the caller:** in the conductor's whole-pass harness, the fake `Repo`'s `provision` records its options.
  - Under a *sandboxed* decision, the recorded options carry `exclude: standInExcludes`.
  - Under *unsandboxed* (off by choice, or degraded), there is no `exclude` key.
- **Unit, the wrap:** the branch's closure and step-walk tests stay. Their expected `env` is now exactly `Wrapped.env`, with no `GIT_CONFIG_*`. Update any assertion that still expects them.
- **Integration only:** the `info/exclude` write itself, inside the hold, against a real bare mirror. It touches the filesystem and runs `git`, so under 0060 §1 it belongs in `packages/repo/integration` beside the existing provision tests. That half runs after the merge, so nothing in this pass checks it. The merge-function test and the caller test above stand in for it before the merge.
- **The ratchet:** do not raise `effect-ratchet.baseline.json`. The new IO is `Effect.tryPromise` inside the existing `Effect.gen`, with no new `async` function. Removing `readInherited` and `commandExclude` removes `.then` chains, not counted functions, so expect the baseline to stay where it is.
