## Where the decision is made: once per pass, in `runOnce`, before the claim

The ticket has the `sandbox` dep "call #1147's decision function". Don't build it that way. Compute the decision **once per pass**, in `runOnce` (`packages/conductor/src/conduct.ts`). It goes beside the `wrongAgent` refusal (`:876-892`), after the recipe resolves (`:837-838`). Two reasons:

- The plan says the decision is made once per run, before the run starts. `packages/recipe/src/sandbox.ts:83` says: *"S4–S6 call it once per run, before the run starts."*
- Two consumers need the same answer, and one of them runs before any action is built. `repo.provision` (`conduct.ts:2874`) needs it for `info/exclude`, and `stepDeps` (`:3907`) needs it for the wrap. If each asked separately, the provision could see *sandboxed* while the build saw *degraded* a minute later.

How to compute it:

- **No `sandbox:` block, or `enabled: false`:** the answer is `{ kind: 'unsandboxed', reason: 'off by choice' }`. Ask the host nothing. `sandboxDecision` returns early for this case (`recipe/src/sandbox.ts:92`). Call it in a way that never evaluates a host answer, so a process whose recipes have no block never loads srt. `projects.ts:216-218` makes that promise.
- **Otherwise, the host answer:**
  - If the `Sandbox` service is present (`Effect.serviceOption(Sandbox)`), use its `hostCanSandbox`.
  - If it is absent, use `hostHere` (`packages/conductor/src/projects.ts:220-223`), the answer the resolver already used.
  - Feed either one through `verdictOf` (`recipe/src/sandbox.ts:62`).
  - Do **not** treat a missing service as *cannot*. Under `required: false` that gives *degraded*, which is an unwrapped spawn. A host that simply forgot to provide the service would then run unboxed without saying so.
- **`home` is the user's `HOME`, not `conduct.ts`'s `home`.** `conduct.ts:738` sets `home` to `options.home ?? stateDir()`, which is `~/.lingtai`. `expandHome` (`recipe/src/sandbox.ts:58`) needs `readHost`'s `home` (`@lingtai/sandbox/host`, which does not load srt; `projects.ts:33` already imports it). Passing the state dir compiles, and it turns every `~/…` in `write`/`deny` into a wrong path. If `readHost` fails, treat that as *cannot*.

What `runOnce` does with each result, all before the claim, so nothing is claimed when it refuses:

| Decision | `runOnce` |
|---|---|
| `refused` (the host lost the sandbox after the resolve) | returns `{ ok: false, stage: 'recipe', detail: why + ' — nothing was claimed' }`, matching `:835` and `:882` |
| `sandboxed`, no `Sandbox` service | returns `stage: 'recipe'` with a sentence that names the missing service. This is the early form of fail-closed. Without it, an `implement` agent is paid for before `build`'s action throws. |
| `sandboxed`, service present | continues. `provision` gets the stand-ins, `stepDeps` gets `sandboxDecision` and `sandbox` |
| `unsandboxed` (either reason) | today's pass, byte for byte. `degraded` is `runLog.note`d with its `why`. Recording it as an event is S8's. |

`runOnce`'s requirements stay `Repo | AgentHost` (`:726`). `Effect.serviceOption` adds nothing to them, so no test or caller has to provide a `Sandbox`.

## `ActionDeps`: two keys, so the fail-closed rule can be tested

The Done-when's test, *sandboxed decision, no `sandbox` dep → `ActionUnavailableError`*, needs the decision and the wrap to be separate keys:

- **`sandboxDecision?: SandboxDecision`**, the value above.
- **`sandbox?: { wrap(command: readonly string[], worktree: string, env: Record<string, string>): Effect<Wrapped, SandboxUnavailable | SandboxWrapFailed | SandboxPolicyRefused, Scope> }`**. Built in `conduct.ts` beside `keptRun` (`:3996`). It closes over `project`, `mirrorPathFor(project, home)` and `decision.project_additions`, and calls the service's `wrap`. `unit/sandbox-mirror-path.test.ts` already pins `mirrorPathFor` to `mirrorDir`.
- **`command?: CommandRunner`**, the runner seam: absent means `commandEffect`, as in `subscriber.ts:141-148`. It sits at deps level so the step walk can reach it through `actionsFromRecipe` for both the sandboxed and the unsandboxed case.

All three are lifted unchanged in `actionPortDepsFrom` (`from-recipe.ts:191-207`), the way `env` is.

In the `'run' in action` branch (`from-recipe.ts:331-353`), after the `env` check:

- **Throw `ActionUnavailableError`** when `sandboxDecision?.kind` is `'sandboxed'` or `'refused'` and `deps.sandbox` is absent.
- **Spawn as today** when `sandboxDecision` is absent or `kind === 'unsandboxed'`, and only then.
- `refused` is listed with `sandboxed` because the ticket says only *not sandboxed* may spawn as today, and `refused` is not a license to spawn either.
- Hand the wrap to `makeProcessAction` only when sandboxed. `implement` needs nothing extra: `makeKeptRunAction` wraps the same `inner`, and its own `git` reset and commit stay outside the sandbox.

`@lingtai/actions` gains `"@lingtai/sandbox": "workspace:*"` and imports only from `'@lingtai/sandbox'`: `Wrapped`, the three error classes and `SandboxDecision`'s type through `@lingtai/recipe`. `index.ts` there re-exports `policy`, `port`, `protect`, `quote` and `sandbox` and nothing that loads srt. The board already compiles `@lingtai/sandbox` (`apps/board/next.config.ts:19`).

## `makeProcessAction` and `spawnChild`

`ProcessActionSpec` gains `sandbox?` and `command?`. When `sandbox` is present, `run` becomes `Effect.scoped`:

1. Call `wrap(['/bin/sh', '-c', spec.run], context.cwd, spec.env)`.
2. Call the runner with `{ run: spec.run, wrapped: { argv, env }, ownGroup: true, cwd, timeoutMs, timeoutLabel, signal }`.
3. Return the verdict as today.

Keep `run: spec.run` even though nothing spawns it. It is the text `child.on('error')` puts in evidence (`command.ts:410-418`).

The scope must enclose the command. `Wrapped` is scoped (`sandbox.ts:140-153`): the scope's closing unregisters the network lists and runs `cleanupAfterCommand`. If the scope closes before the child exits, srt cleans up under a running command.

When `wrap` fails, return `{ verdict: 'failed', evidence, findings: [] }` and spawn nothing. Build the evidence sentence this way:

| Error | Sentence |
|---|---|
| `SandboxUnavailable` | `[reason, ...sentences].join('; ')`, as `said` at `recipe/src/sandbox.ts:79-80` |
| `SandboxPolicyRefused` | each refusal's path and protected path |
| `SandboxWrapFailed` | the cause's message |

Prefix all three with something like ``the sandbox would not wrap `<run>`: ``.

`RunCommandOptions` gains `wrapped?: { argv: readonly string[]; env: Record<string, string> }`. In `spawnChild` (`command.ts:443`), when it is present, call `spawn(argv[0], argv.slice(1), { shell: false, detached: options.ownGroup, cwd, env: wrapped.env + LINGTAI_RESULT when asked, stdio })`. Do this in **both** branches, payload and no payload, so the type stays the tuple the comment at `:432-441` argues for. When `wrapped` is absent, both spawns are untouched.

The caller sets `ownGroup: true`. `signalTree` (`:341-345`) and the timeout and abort paths read `options.ownGroup`, so the group kill only works if the flag is on the options. Deriving it from `wrapped` inside `spawnChild` would set `detached` and still signal only the child.

## The stand-ins and `info/exclude`

- **The list:** srt's eleven names (`.bashrc` … `.zshrc`, from 017). They describe srt's behaviour, so they live in `@lingtai/sandbox` as an exported constant.
- **The plumbing:** `@lingtai/repo` must not depend on the sandbox package. `ProvisionOptions` (`packages/repo/src/worktree.ts:23`) gains `exclude?: readonly string[]`. `provisionWorktreeEffect` passes it to `ensureMirrorEffect` (`:164`). `conduct.ts:2874` passes the names with a leading `/` only under a *sandboxed* decision.
- **The write:** inside the `mirrorWrite` hold (`:126`), after the fetch or clone:
  1. Read `<mirror>/info/exclude`, treating a missing file as `''`.
  2. `mkdir -p info`. A bare clone made without templates has no `info/`.
  3. Write back the existing lines plus each missing name once.

  Linked worktrees read the common dir's `info/exclude`, which is why the mirror's file covers them. A failed write is a `RepoFailed` named `info/exclude`, so it becomes `notCut` (`:2903`).
- **Write it on macOS too.** The stand-ins are Linux-only, but the write is harmless on macOS and keeps the test independent of the platform.
- **A consequence to accept, not fix.** Anchoring protects nested `.vscode/` and similar, but a root-level, *untracked* `/.vscode/…` or `/.gitmodules` is not added by `git add -A` under a sandboxed decision. Inside srt that root path is a stand-in anyway. Tracked files are unaffected, because exclude applies only to untracked paths.

**What a unit test can reach here.** `ensureMirrorEffect` runs `git` and touches the filesystem, so per 0060 §1 testing it is integration, and nothing runs that before the merge. Put the merge in a pure function, `existing text + names → text`, and unit-test that: lines kept, each name once, idempotent. Also unit-test, on the fake `Repo` in `conductor/test/one-attempt.ts`, that `provision` receives `exclude` only under *sandboxed*. Leave a `packages/repo/integration` case for the real write; that is the half that runs after the merge. Placing the write inside the hold is checked by reading the code.

## Providing `Sandbox` in `apps/cli`, once per process

`SandboxLayer`'s finalizer runs `srt.reset` (`packages/sandbox/src/sandbox.ts:105`), and srt has **one instance per process** (`live.ts:5`). The hosts provide `tracedPorts` per pass (`apps/cli/src/conduct.ts:419,476,551,580`; `run.ts:306`). If you add `SandboxLive` to that `Effect.provide`, each pass's end resets srt underneath any other pass still wrapping (0122).

Copy `apps/cli/src/tracing.ts` instead:

- Build `SandboxLive` once per process, into a scope the host holds until exit.
- Import `@lingtai/sandbox/live` dynamically so `lingtai status` and the like never load srt.
- At each of those sites, provide `Layer.succeed(Sandbox, built)` beside `tracedPorts`.
- Use no `async` function and no `Effect.run*`; the ratchet counts both.
- If the build fails, provide nothing. The pre-claim refusal above then holds a sandboxed project instead of letting it run unwrapped.

## The import-graph test, and the import #1147 already made

`packages/conductor/src/projects.ts:221` already contains `import('@lingtai/sandbox/live')`, merged in #1147 after the ticket's `0adc1444`. The board reaches it through `currentRecipe`. A literal test of *"no file outside `apps/cli/src` imports it"* is red on `main` before this change.

Don't move it. Moving `hostHere` changes how #1147's resolver answers on the board, which is that ticket's behaviour, not this one's. Instead, the new test lists exactly that one exemption: that file, a dynamic `import()`, with the reason written beside it. The test fails on:

- any other file, static or dynamic;
- a static import in `projects.ts`.

This design adds no new import outside `apps/cli/src`; the conductor's fallback reuses `hostHere`.

`modulesOf` in `packages/domain/unit/effect-ratchet.test.ts:502` already extracts `import`, `export … from` and `import(…)` through the TypeScript AST. Use the same method rather than a regex. If you share the code, move it to a `test/` helper rather than importing one test file from another.
