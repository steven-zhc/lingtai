## The one deviation from the ticket's text, kept on purpose

The branch does **not** write srt's stand-in names into the mirror's shared `info/exclude`. Each wrapped command gets its own exclude file, `<mirror>/info/lingtai-sandbox-exclude-<id>`. It contains the anchored stand-in names followed by the global ignore rules that the command's environment resolves in its worktree. The command is pointed at it through `GIT_CONFIG_*` (`core.excludesFile`), and the file is removed when the wrap's scope closes. Commits `075ed49e`, `5b1f8d03`, `ea7cfb36` and `402d026e` made this change.

The reason: the shared `info/exclude` is also read by the kept run's own `git add -A`, which runs **outside** srt (`makeKeptRunAction`). Even anchored names would silently drop a root `/.vscode/…` or `/.gitmodules` from Lingtai's own commit, which is the trap the ticket's anchoring paragraph describes. The per-command file confines the exclusion to the commands that actually face srt's stand-ins.

As a result, Done-when box 5 is met in a different form:
- Provisioning writes nothing. `mirrorWrite` and `ProvisionOptions` are unchanged.
- The exclude file's text is a pure function, `excludeFileText`, covered by `packages/repo/unit/exclude.test.ts`.
- Writing and removing the file is integration-only (`packages/conductor/integration/sandbox-run-exclude.test.ts`), because it runs `git` and touches the filesystem (0060 §1). It runs after the merge. The unit-level stand-in is `excludeFileText` together with `makeRunSandbox`'s closure test.

Say this in the commit body so the reviewer does not read it as a missed box.
