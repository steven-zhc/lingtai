# #812: shape

## Where it goes: after the `.tale` grid, not inside it

The section is a sibling between the closing `</div>` of `.tale` and `<section className="home-setup" id="setup">` (`apps/site/src/app/page.tsx:108-111`). Do **not** put it inside `.tale-main` after `#replay`. `.tale` is a two-column grid whose right column is the sticky `<ReplayReceipt />` (`home.css:89-90`, *"the hero and the replay are the left column, the receipt is the sticky right one"*). If the section went inside it, the live receipt would stay pinned beside the ledger, and the section would be squeezed into 1.25fr of the width. Placed after the grid, it is full width, as the mock is.

The replay's observer will not notice the section. It watches only `.rp-scene[data-step]` (`replay-receipt.tsx:183`), and the new markup must not use that class. The pointer card says *"The receipt above"*, but at ≤1080px the receipt moves above the hero (`home.css:160-163`, `order: -1`). It is still above the section, so the wording holds at every width.

## The `log` guard covers the whole file, source as well as text

`above()` cuts at the kicker *The work, in the open* (`unit/page.test.tsx:24-28`). That kicker does not exist anywhere in `src`, so the guard at `:48-55` checks **all** of `page.tsx` with comments stripped, plus all of the rendered page, against `/\blogs?\b/i`. Class names and identifiers count, not just copy:

- Name the classes `why-*` and `ledger*` / `lg-*`, as the mock does.
- Never use `log`, `logs` or `*-log` as a whole word in a class name or variable.
- *"Session transcripts"* and *"Structured events and a receipt"* pass. *"Logs and transcripts"*, the mock's copy at `doc/design/home-page-v3.html`, fails.
- The same test also bans `event-source`, `append-only` and `projection`, so the Audit cell must not grow into any of those words.

## Markup: one component in `page.tsx`, a real `<table>`, rows as data

Keep the section's head (kicker, h2, sub) in `page.tsx`. The order case reads `prose()`, which is the source of `page.tsx` only (`unit/page.test.tsx:16-19`), so the heading has to be in that file. Write the six ledger rows as a `const` array of `{ key, alone, lingtai }` in the same file and map over it. Do not export it: `page.tsx` is a Next page, and extra named exports are refused by Next's page type check. If a test wants the rows, it reads them from the rendered markup.

The ledger:

- Wrap it in `<div className="ledger">` holding a `<table>`.
- The top strip *LINGTAI / THE DIFFERENCE* and the receipt glyph go **outside** the table, above it, in a `div` styled like `.r-top` (`home.css:122`). It is a label, not a header row.
- Give the table `<caption className="sr-only">` (or `aria-label`) *The agent alone, and with Lingtai*.
- `<thead>` has an empty `<td>`, then `<th scope="col">` for *Claude Code · Codex alone* and *With Lingtai*.
- Each body row is `<th scope="row">` for the key, then two `<td>`s.

**Reuse #815's styles by copying, not by class.** `.rcpt` brings a 16px/4px radius, a heavy shadow and padding meant for the 360px receipt (`home.css:120`). Give `.ledger` the mock's own rule (`home-page-v3.html`, `.ledger` / `.ledger::after`): the same torn-edge `radial-gradient` as `.rcpt::after` (`home.css:121`), with a lighter shadow. The ✓ in front of each right-hand cell is `td.lg-b::before` in CSS, as in the mock, so the text a test reads has no ✓ in it.

**Layout.** Above 700px, keep native table layout (`table-layout: fixed`, a `<colgroup>` with a 170px key column) and dashed `border-bottom` on rows. Do not use the mock's `display: grid` on `tr`: grid on table elements has dropped table semantics in Safari, and the *real table* edge exists for screen readers. At ≤700px (site.css's existing breakpoint, `site.css:541`; the mock's 720px gives way to the ticket), set `table, thead, tbody, tr, th, td { display: block }`:

- Visually hide the `thead`.
- Give each `td` a label from CSS, `td.lg-a::before { content: "Agent alone: " }` (the mock does this, `home-page-v3.html:1173`).
- The `th` is the block's title.

That gives no sideways scroll. The ✓ moves into that same `::before` as `content: "✓ With Lingtai: "`.

**The pair.** A grid of `minmax(0,1fr) 70px minmax(0,1fr)` with an `aria-hidden` *vs* disc in the middle (mock `.why2-pair`, `.why2-arrow`). At ≤1080px it becomes one column and the disc is hidden. Each side is a `<figure>` with a `<figcaption>`:

- **Name chips** are `<span className="why-chip">Claude Code</span>`, text only. Leave out the mock's `<img src="logos/…">` completely, including empty `alt` placeholders.
- **The transcript card** keeps its `<code>` spans. Its copy contains `agent's`, written as `&apos;` as the page already does (`page.tsx:48`).
- **The pointer card** is one `<a className="why-point" href="#replay">`, not the mock's `#h1`. Its `↑` is `aria-hidden`.

**Colours** come only from the variables `home.css` already uses (`--surface`, `--rule`, `--rule-2`, `--muted`, `--accent-ink`, `--pass`). Those carry dark mode (`site.css:45`), so no dark rule is added.

## Tests (`unit/page.test.tsx`)

- **Order case** (`:57-65`): set the list to `['Agents do the work', 'The agent got it wrong. Twice.', 'Why not just give the agent the issue?', 'Three steps to your first receipt.']`. The replay heading is not in the list today. Adding it is what makes *after the replay* a checked claim.
- **One case per right-hand cell.** Read the rendered markup: `renderToStaticMarkup(<Home />)`, with the `<td>` cut out by its row header. `renderToStaticMarkup` writes `'` as `&#x27;`, so *"Separate steps the agent can't skip"* needs that decoded before the compare, or matching on the entity. Matching on the source will not work either, because the JSX holds `&apos;`. Write one small `text()` helper that strips tags and decodes `&#x27;`, `&amp;` and `&quot;`, and use it for every case here.
- **Pair the cells with their row keys** (`Completion` → *Your recipe: checks, review, your approval*, …), not just check that each string is present. A changed claim is then one failing case that names its row, which is the *cost to later tickets* edge.
- **Rejected phrases.** One case checks that the rendered page contains none of *The session is gone*, *Found out later*, *A transcript, maybe*. Also add *Logs and transcripts*, so the mock's copy cannot come back in without failing here, not only in the general guard.
- **Pointer link.** One case checks the pointer's `href="#replay"`, and that `id="replay"` is still on the page.
- **Table semantics.** One case checks for `<table`, two `scope="col"` and six `scope="row"`. That is the unit-level stand-in for the screen-reader edge. Layout at 700px and in dark mode is the person's check in *Done when*: nothing in `pnpm test` renders CSS.

`pnpm fmt:check` runs in `build`, so run `pnpm fmt` (oxfmt) over `page.tsx`, `home.css` and the test before committing.
