## Design: #1360, the attempt-state phase spans

### The decision: bind each phase to its own card's context, not whatever context is active

Copying `locks.ts:56-63` as written would break the ticket's first watch-out. `readControlOnce` starts its phase spans with `traced(...)` inside the observer hooks (`locks.ts:60-61`). `traced` is `startActiveSpan` (`timing.ts:150`), so each phase takes the context that is active when its hook runs. For the control read that is fine, because only one read is in flight. The attempt reads are five or more at once, in one `Promise.all` (`board.ts:1626`). Each one is its own `Effect.runPromise` (`packages/conductor/src/snapshot-state.ts:20`). Every hook after the first `yield*` is called from a resumed fiber:

- `tail` (`snapshot-read.ts:99`), `recheck` (`:104`), `full` (`:109`) and `reduce` (`:68`) all resume this way.
- Only `latest` (`:81`) runs synchronously.

#1359 already showed what context a resumed fiber gets. `timing.ts:178-180` says: *"Effect resumes fibers from one shared dispatcher, so AsyncLocalStorage alone would hand a stage whichever context scheduled the batch."* So card A's `attempt.tail` can end up under card B's `attempt.state`.

The board can't fix this the way #1359 did, with `Effect.withTracer(boardTracer)` plus `ApiContext` (`board.ts:1065`). The run is inside `readState`, in `@lingtai/conductor`, and the ticket asks not to change that contract.

Capture the context explicitly instead:

- Inside each `attempt.state`'s `traced` callback, take `const ctx = context.active()`. It is synchronous there, so it is that card's `attempt.state` context.
- Build that card's observer around `ctx`:
  - `read: (step, run) => context.with(ctx, () => traced(`attempt.${step}`, () => run()))`
  - `reduce: (run) => context.with(ctx, () => tracedSync('attempt.reduce', run))`
  - `served: (s) => span.setAttribute('lingtai.snapshot', s)`, where `span` is the callback's own argument.
- `run()` is called inside the phase's active context. Any `events.read`/`db.acquire` seam span the store starts there (`trace-seams.ts:19-44`) then parents to the phase, not to a neighbouring card.

Put this in one exported helper in `board.ts`, for example `readAttemptState(store, runId, read)`. It returns `traced('attempt.state', (span) => readState(store, attemptReducer, runId, 'all', { ...read, observe }))`.

- Both branches call it, replacing `board.ts:1629-1631` and `:1644-1646`.
- The shared `read` object (`:1625`) stays shared. It holds only `snapshots` and `writer`. The observer is added per call by spreading, so `read` is never mutated.
- Each branch's `try/catch` and the `[taskId, null, null, null]` failure tuple stay exactly where they are. `traced` ends the failed phase and the parent with `ERROR` and rethrows (`timing.ts:152-156`), so both spans are closed before the card's `catch` runs.
- The helper also gives tests one seam to call with a memory store. Otherwise they would have to mock the module globals `eventStore`/`log` (`board.ts:43`).

Leave `standingSystemLines` (`board.ts:1586-1590`) alone. It reads the ticket stream, it has no `attempt.state` span, and the ticket's trace is about `board.progress`.

### `lingtai.snapshot` and the boundary that stays unmeasured

`served` is called once per read that gets past its event reads: at `:74` with no snapshot store, and at `:112` otherwise. A tail or full read that rejects never reaches it, so the attribute is absent on that card. That is the ticket's *"only when its value is known"*, and it needs no default.

Three pieces of work run inside `attempt.state` but outside every hook:

- `reducer.decode` at `:92`, between `latest` and `tail`.
- `reducer.encode` and `writer.offer` at `:121`, after the fold.
- Time a resumed fiber spends waiting for the dispatcher. With N cards in flight, a phase span can include other cards' synchronous `attempt.reduce` work on the same event loop.

Do not add store hooks for these. Name them in the helper's comment as the remaining boundary, and say what it means: the time in `attempt.state` not covered by its children is decode, encode, offer and scheduling, not database time. Following `locks.ts:53-55`, the comment must also say that an `attempt.<step>` span is everything that store call took, its own pool wait included, and that it is neither SQL time nor a measured connection wait. The projection pool's `db.acquire` does not measure the event store's pool.

Only a real trace can settle how large that remainder is. In the operator's sample it is the gap between `attempt.state`'s duration and the sum of its `attempt.*` children's durations, read per span in Harbor. No log event carries it.

### Tests: extend `apps/board/unit/trace-spans.test.ts`, or a sibling `attempt-spans.test.ts`

Reuse that file's setup: `installTracing(on, none, exporter)`, `parentOf`, and the `afterEach` that disables `trace`/`context` (`trace-spans.test.ts:64-90`).

`readState` is mocked file-wide there (`:30-33`). Put the new cases in a file that does not mock `@lingtai/conductor/snapshot-state`, so the real `readState` → `readThroughSnapshot` runs. Use `createMemoryEventStore` and `createMemorySnapshotStore` (`packages/event-store/test/memory.ts:259`) with the real `attemptReducer`. Wrap the store in counting fakes: `latest`, `read`, and the writer's `offer` calls.

Cases:

- **Hit.** Seed a snapshot whose anchor holds. Expect `attempt.latest`, `attempt.tail`, `attempt.recheck` and `attempt.reduce` under `attempt.state`, with `lingtai.snapshot === true` and no `attempt.full`.
- **Fallback.** Use three variants: no snapshot row, a decode that throws, and a recheck that answers a moved anchor. Expect `lingtai.snapshot === false`. On the moved-anchor variant, `attempt.full` must be present.
- **Failure.** The tail read rejects. `attempt.tail` and `attempt.state` both end with `ERROR` status, the attribute is absent, and the helper rejects with the store's own error.
- **Two deferred cards.** Hold each card's tail on its own deferred and release them in reverse order. Every `attempt.*` child's parent span id is its own card's `attempt.state`, and the two `lingtai.snapshot` values differ: one hit, one fallback. **This case fails under the `locks.ts` pattern copied verbatim**, which is why it exists.
- **Two concurrent renders.** Run two `board.progress` parents at once, under `traced`, each with its own cards. Children stay in their own trace.
- **Unobserved parity.** Run the same seeded store once through the helper and once through a bare `readState(..., read)`. The returned state and the counts of `latest`, `read` and `offer` must be equal.
- **No meta growth.** Inside a `measure` scope, the helper adds no `TimingMeta` entry (`timing.ts:143-147`).

Assert by span name, parent and attribute. Do not assert line numbers or timings, and use no sleeps; deferreds and `Effect.yieldNow()` give the interleaving.

The existing `loadBoard` test's `attempt.state` → `board.progress` assertion (`trace-spans.test.ts:158-159`) must still hold unchanged.

Nothing here needs `pnpm test:integration`. The unit-level claim that stands in for the live trace is that each card's phase children and attribute land on its own `attempt.state` span through the real snapshot reader. The two-deferred-cards case proves it.

### Not an ADR change

Snapshot semantics, anchor recheck and offers are untouched, so 0124 stands. The spans are started by the board, not by a package, as `doc/design/1144.md` requires. They carry only a boolean, which is within what `timing.ts:139` allows. The helper returns `readState`'s promise and adds no `Effect.run*`. Write it so that it adds no `async` function either, and leave `effect-ratchet.baseline.json` untouched.
