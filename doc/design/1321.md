# #1321 — design note

> **History.** Board addresses in this note (`/task/<id>`, `/pr/…`, `/recipe/…`, `?project=`) are the ones that existed when it was written; they no longer resolve. The current forms are in [1502.md](1502.md).

## The one decision the ticket gets wrong: no `since` on the home page

Fix step 5 says to pass `readProjectPrs(project, { since })` so older merged PRs are skipped. **Don't do this.** Read every PR once and use that one list for both the tags and the draft. A list cut off by `since` gives a wrong draft:

- `readDraftOn` treats every PR that is not `closed` or `refused` as holding its tickets, **merged PRs included** (`packages/project/src/pr.ts`, the loop in `readDraftOn`: `if (pr.status === 'refused') continue; for (const t of pr.tickets) held.add(t.ticket)`).
- `readDraftOf` hands that function exactly the PRs it was given (`apps/board/src/lib/prs.ts`, `readDraftOf` → `readPrDraft(…, prs.flatMap(…))`).
- So with a cut-off list, a ticket held by a PR merged three days ago is no longer in `held`. It re-enters the draft. Its row then reads `on your branch` and the foot line's `N not in a PR yet` goes up.
- That is the exact failure the ticket's own *Watch out* forbids. And the draft needs every PR anyway, so `since` would save nothing here.
- `readProjectPrs`' `since` option stays as it is (`prs.ts:51-55`); this ticket just does not pass it. `readPrPage` already reads it this way (`prs.ts:144-145`): `readProjectPrs(project, eventStore)` then `readDraftOf(project, recipe, prs)`.

## Where it goes

- **The read**: `readLandedWhere(project)` in `apps/board/src/lib/prs.ts`, next to `readPrPage` and built the same way:
  - `readProject` → `currentRecipe` → `modeOf(recipe) !== 'team'` → `{ kind: 'solo' }`, returned before any PR stream is read. The render test only checks that a Landed column given no read draws no tag and no foot.
  - Otherwise, inside one `Effect.runPromise`: `readProjectPrs` then `readDraftOf`.
  - It returns `{ kind: 'solo' } | { kind: 'failed', error } | { kind: 'team', prs: PrRead[], draft: PrDraftTicket[] | { error } }`.
  - `apps/board` has no entry in `packages/domain/unit/effect-ratchet.baseline.json`, which lists only `apps/cli` and `packages/*`. So copying `readPrPage`'s `async` shape does not move the ratchet, and the baseline must stay untouched.
- **The call**: in `CardsPart`, only on the `col.id === 'landed'` path, ahead of the empty-column return. Call it once for each project in `onBoard` (the team projects on the board, whether or not a Landed row is retained), all through one `Promise.all`; never once per row.
  - An empty Landed column keeps today's empty note and, for a team project, still draws its foot line (`LandedFoot`): the draft and an open PR outlive the two days a row is kept. The bar's `PRs` view still counts what waits on the person (`placeViewsOf`, `prs.ts`).
  - Pass `Landed` a `Map<project, LandedWhereRead>` and let it pass each row its own result.
- **The pure mapping**: `apps/board/src/lib/where-landed.ts`, with `whereLanded(ticket: string, read)`.
  - The key is `card.ref`. That is task_view's `issue` (`board.ts:881`, `ref: t.issue`), the same string PR tickets carry and that `readDraftOn` compares against `candidates[].issue`.
  - The same file holds the pure `footLine(read)`, so a unit test reaches both.

## The mapping, case by case

Its type is `{ tag: 'branch' } | { tag: 'pr', name, n } | { tag: 'merged', name } | null`.

| Case | Result |
|---|---|
| A PR with status `merged` whose **`mergedTickets`** contains the ticket | `merged` |
| A PR that is still open (`requested`, `in-progress`, `waiting`, `in-review`) whose `tickets` contains the ticket | `pr`, named by `prName(pr)` (`pr-board.ts:133`), `n` = `pr.n` |
| The draft read (not `{ error }`) contains the ticket | `branch` |
| Anything else, including a draft that is `{ error }` | `null` |

Notes on the table:

- **Merged means `mergedTickets`, not `tickets`.** `packages/domain/src/pr.ts:55`: *"The tickets the commit a `PrMerged` named holds; the rest landed on the PR branch after it and are not merged."* The PRs board does the same at `pr-board.ts:364-367`. A pr-fix that landed after the merge is in `tickets` but not in `mergedTickets`, so it gets `null` and not `merged`. When `mergedExact` is false, `mergedTickets` is only a lower bound, so a ticket missing from it also gets `null`: never a guess.
- **`closed` and `refused` PRs never give a tag.** A closed PR's tickets come back through the draft (`readDraftOn`'s `mergedBack` handling), and the third row covers them.
- **A ticket that landed on `main` before the project became team** is in no PR and not in the draft (`readDraftOn` drops `landedAt <= since`, where that `since` is `teamSince`). It gets `null`, which is the ticket's first *Watch out*.
- **One PR stream unreadable** (`{ n, error }` in `prs`): tickets in the PRs that were read still get their true tag. The draft is then `{ error }` (`readDraftOf`, *"never an empty draft for a read that failed"*), so nothing gets `branch`. If the whole read is `failed`, no row has a tag.
- **The `in PR` tag's link** is `/pr/<project>/<pr.n>`. That is Lingtai's own id, which is what `readPrDetail(project, n)` resolves (`apps/board/src/app/pr/[project]/[n]/page.tsx`). It is never the host's number: `PR #88` is only the label.

## The foot line

- One per team project on the board, whether or not it has rows on the column. It goes after the `older` details element inside `Landed`, or after the empty note. When several projects are on the board, it starts with the project name, like the rows.
- **The count is the draft's length**, never a count of rows (the ticket's second *Watch out*).
- **The open PR**: only the highest PR can be open (`prs.ts:54`, *"only the highest one can be open"*), so use the last read entry whose status is open.
  - Its word: `requested` and `in-progress` → `in progress`; `waiting` → `waiting on you`; `in-review` → `in review`. These are the PRs board's own words (`pr-board.ts:359`, `:395`).
- **Then `PRs →`**, linking to `/pr/<project>`.
- **No line** when the draft is `[]` and no PR is open.
- **When the read failed**: if it is `failed`, or the draft is `{ error }`, the line becomes *where these are could not be read* in the fail colour. Do not show a count next to an unknown draft.

## The tag's colours

Add three classes in `globals.css`, built from existing tokens:

- `on your branch`: `--accent-soft` with `--accent-ink`, as `.pill.run` uses (`globals.css:569`).
- `merged`: `--pass-soft` with `--pass`, as `.pill.pass` uses (`:567`).
- `in PR`: the mock's `#e5e9f3` / `#4a5d8a`. Add them as a token pair with a dark-mode value too, because the existing tokens are redefined under dark at `:64-70`.

The tag sits **outside** the `lmeta` link (`page.tsx:574-576`), so the `in PR` tag can be its own link and is not nested inside another anchor.
