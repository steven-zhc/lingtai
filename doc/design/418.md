## Design note

Make the task page’s current wait the join point. `standingOf` already takes `waitId` and `reason` from the blocked lifecycle (`task.ts:766-768`); its comment says they are “null together and non-null together” (`task.ts:496-504`). After that fold, read the matching `task_view` row, use its triage facts only if its wait ID equals `standing.waitId`, and derive `triageStatus` once with the current recipe’s `triage:` declaration and `readStatus()?.startedAt ?? null`. A narrow single-task projection read is preferable to `readTasks`, whose documented purpose is “The board’s cards” and whose options only narrow by project (`task-view.ts:1214-1244`). Put the result on `StandingView`; derive `want` from that same result instead of calling `triageStatus` again through `currentWaitWant`, which currently supplies placeholder context (`task.ts:1594-1602`). The wait-ID check is essential even though the projection says it keeps “the facts for the current wait” (0118 §10): the page folds its stream separately, so its lifecycle and the projected row must be matched before advice is shown.

In `Standing`, place a read-only renderer between the existing “so what” line and moves row (`standing.tsx:423-434`). Keep the status and cause switches exhaustive, and render agent-written fields as React text. Compute `recommendedResolution` once from `standing.reason` and its status, then use one mapping from resolution tags to the controls that `movesOf` actually draws. `movesOf` says `Requeue` becomes either Send or Requeue, while `Approve` without a sha becomes a sentence rather than a button (`standing.tsx:619-646`); those forms must preserve the allowed controls while determining whether a recommendation has a control to promote. Reorder the rendered controls and their primary styling together. Replace the client controls’ legacy recommendation defaults, including `primaryMove`’s default to Approve (`decide.tsx:23-45`), so a `null` recommendation marks none. Give Close primary styling when selected and pass its `prefill` only for advised Close; its existing state already seeds the reason from that prop (`decide.tsx:421-444`). Update Close’s “Never amber” comment (`decide.tsx:401-413`) to reflect that recommendation now has that effect.
