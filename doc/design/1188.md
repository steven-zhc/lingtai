# Design note: #1188, the sandbox band

## Where it goes

All of it is in `apps/site/src/app/page.tsx:164-190`, the `home.css` block from line 213 (`/* The sandbox, one section before the first question */`), and `apps/site/unit/page.test.tsx`. The board and `doc/` do not change.

## Four decisions the ticket leaves open

### 1. The band re-declares the board's dark tokens on `.sandbox-pitch`, under their existing names

The section's text is drawn by rules that already read tokens:
- `.kicker`
- `.link`
- inline `code`
- `.tag.ill`, which is `color: var(--muted); border: 1px dashed var(--rule-2)` at `home.css:134`

On a dark band, every one of those would pick up the light values. Inventing `--band-ink`-style names would mean overriding each of those rules one by one.

Instead, write the board's dark values (`apps/board/src/app/globals.css:52-70`) as literal hex on the `.sandbox-pitch` selector, under the same names: `--ground`, `--surface`, `--surface-2`, `--ink`, `--ink-2`, `--muted`, `--rule`, `--rule-2`, `--accent`, `--accent-ink`, `--pass`, `--fail`.

- Every rule inside then reads correctly with no override.
- This keeps `site.css:3-5`'s promise ("Every colour token here comes from `apps/board/src/app/globals.css` … this file adds no hue"). The values are the board's own and are scoped to one element, so nothing is redefined globally.
- Use literal hex, not `var(--ground)`. Under `prefers-color-scheme: dark` the page's own `--ground` is already `#0c1316`, so a `var()` reference would make the band the same colour as the page.

### 2. The dark scheme lifts the band, rather than leaving it the page's colour

- **Light scheme:** the band's ground is `#0c1316` and the card is `#131e22`.
- **Dark scheme:** under `@media (prefers-color-scheme: dark)`, the band's ground becomes `#131e22` and the card becomes `#0f1a1e` (the board's `--surface-2`).
- **Both schemes:** `border-block: 1px solid #2e434b`, so the band's edge is visible either way.

This is how the "must still read as a band" edge is met. Nothing on the band is coral (`--way-in`, `.way-in` or `.claim`).

### 3. Full width comes from negative margins, without leaving `.wrap`

Keep the `<section>` where it is inside `<div className="wrap">` and break out with `margin-inline: calc(50% - 50vw)`. Put the band's own inner `div` back at `.home .wrap`'s width: `max-width: 80rem` (`home.css:4`), with the `0 24px` padding from `site.css:68`.

- `100vw` includes the scrollbar, but `.home { overflow: clip; }` at `home.css:3` already absorbs that overhang, so nothing scrolls sideways.
- Do not add `overflow` to `main` or `body`. `site.css:56-57` says: "Do not set `overflow` on `body` or `main` — the sticky spines would stop sticking."
- `clip` is not a scroll container, which is why the existing rule is safe.
- Closing and reopening `.wrap` around the band would work too, but it splits one layout container into three for one section.

### 4. Delete `SANDBOX_ALT`; the test compares the two files directly

Once the `<img>` is gone, nothing renders `SANDBOX_ALT`:
- `/docs/safety` takes its alt from the markdown: `document.tsx:240`, `<img src={`/img/docs/…`} alt={alt ?? ''} />`.
- The constant would be an export kept alive only by a test.

Remove `page.tsx:30-32` and the import at `page.test.tsx:8`. Rewrite the test at `:183-189` like this:
- read `doc/img/sandbox.svg`'s `aria-label`;
- assert that it is non-empty;
- assert that `doc/safety.md` contains `![${label}](img/sandbox.svg)`.

## Two traps in the tests

### The block test slices up to the first `</section>`

`page.test.tsx:172` is `html.slice(start, html.indexOf('</section>', start))`.

The board's real panel wraps each heading in a `<section aria-label=…>` (`sandbox-panel.tsx:140,174,209`). Copying that into the card would end the slice at *Blocked*, and the assertions on the safety link, the telemetry line and *On for new projects* would fail or pass depending on where each sits.

So the card is:
- one `<figure>` with `aria-label="Illustration of a ticket's Sandbox tab on the board"`;
- `<div>` + `<h3>` for each of the three groups;
- the telemetry line as a `<p>` after the figure, still inside the band;
- no `<section>` anywhere inside the band.

### `prose()` reads `page.tsx`'s source, not the render

`page.test.tsx:20-23` reads the source, so the heading-order test (`:78`) and any phrase check need the text as one literal run in the source:
- Write `Every run is sandboxed.` as one literal, with *Your keys stay yours.* in its own `<span>` after it.
- The same goes for `On for new projects`. The `<code>sandbox</code>` that follows it is fine.

The `home-edges` assertion should slice `class="home-edges"` out of the rendered HTML and check that *Not a sandbox* is absent. That is more robust than searching the source.

## The card

The headings are the panel's own words: `Blocked`; `Allowed` with the sub-label `Reachable`; `Limited` with the sub-label `Cannot be read` (`sandbox-panel.tsx:141,158,175,181`). Show them in the agreed order: Blocked, Allowed, Limited.

- **Hosts:** monospace lists with no source or role column.
- **Glyphs:** ✗ in `--fail` and ✓ in `--pass`, each `aria-hidden="true"`, with the text beside it.
- **Tag:** `<span className="tag ill">ILLUSTRATION</span>` goes in the card's header row, next to `#42 · add reading time to chapters` and `Attempt 1`.
- **Shield icon:** an inline SVG with `aria-hidden="true"` that strokes `currentColor` in the accent. An inline SVG is not an `<img>`, so it cannot trip the old `src=` assertion.

## Layout

- **Desktop:** a two-column grid, `minmax(0, 1fr) minmax(0, 26rem)`, aligned to the top.
- **At `max-width: 860px`:** one column, text first and then the card.
- **The labels:** a flex row with `flex-wrap: wrap`, separated by `·` glyphs that are `aria-hidden`.

## Contrast

- `#87999f` (muted) on `#0c1316` is about 6.4:1, and on `#131e22` about 5.9:1.
- `#b4c4c8` (ink-2) clears the floor further still.

So `--muted` may carry the small lines (*On for new projects* and the telemetry line) on both grounds.
