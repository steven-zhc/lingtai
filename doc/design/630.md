## Design note for #630: `/docs/events/`

### Where it goes

- **`apps/site/src/app/docs/events/page.tsx`**, a static route next to `[...slug]`. The catch-all can't serve this page. It builds only the slugs `servable()` returns, and those come from markdown files (`[...slug]/page.tsx:43-54`, `dynamicParams = false`). `doc/events.md` doesn't exist and shouldn't be created: a hand-written markdown file is exactly the "event name or step written into the page's own source" the ticket rules out. A static segment wins over the catch-all, so nothing collides.
- **`apps/site/src/lib/events.ts`**, a pure module the page and the test both use. It reads `doc/events.json` with `readFile(path.join(docRoot, 'events.json'))` at build time, which is the pattern `docs.ts:5-17` sets out (*"The docs are a projection of `doc/`, and never a copy"*). It exports a `bySection(doc)` that groups `[...STEPS, 'outside']` the same way `eventsBySection` does at `apps/cli/src/events.ts:19-23`. Write it out again here rather than importing from `apps/cli`: the site has no dependency on the CLI (`apps/site/package.json`), and the function is three lines. The type comes from `import type { EventsDoc } from '../../../../packages/domain/scripts/events.ts'`, the way `apps/cli/src/events.ts:10` does it. That works because `@lingtai/site` already depends on `@lingtai/domain`.
- **`PUBLIC_SLUGS`** (`docs.ts:68`) gains `'events'`. This line does real work: `prune-hidden-docs.ts` deletes every directory under `out/docs/` that isn't in that list. Without the entry the page builds and is then removed.

### Where the steps come from

`doc/events.json` has each event's `at`, but not the ten steps or their order. That comes from `STEPS` in `@lingtai/domain` (`packages/domain/src/vocabulary.ts:42`, *"each writing its own list is how one of them ends up missing a step and nobody notices"*). The page imports `STEPS` and treats `'outside'` as the extra lane. So the only literal the page source may contain is the word `outside`, and that comes from the generator's vocabulary, not from the page.

Don't colour the four refusing steps brass the way `the-pass.html` does. `REFUSING_STEPS` lives in `packages/conductor/src/pass.ts:148`, the site doesn't depend on the conductor, and adding that dependency for a colour isn't worth it. "Drawn as in" means the spine: ten nodes in `STEPS` order, each showing its count, and the `outside` lane drawn apart beside or below it. The counts today run from 3 (`admit`, `build`, `prepared`) up to 38 for `outside`, out of 64 events.

### Selection without JavaScript

Make the page a server component, and do the selection in HTML and CSS with no client component at all:

- Each step node is `<a href="#at-<step>">`. Below the drawing, each step has a `<section id="at-<step>">` listing its events.
- `.events:has(section:target) section:not(:target) { display: none }`. With nothing targeted, every section shows, and that is the no-JS list the ticket asks for. With one targeted, only that step shows. Style the targeted node in the drawing the same way, using `:has()` on the container.
- Each event is a `<details><summary>Name</summary>…</details>` inside its step's section. An event at several steps appears in each of them. `TicketReleased` is at `claim`, `end` and `outside`. Don't give `<details>` ids, so the duplicates don't clash.
- The drawing sits in its own `overflow-x: auto` box with a fixed minimum width, so it scrolls inside the box rather than the page (Watch out).

### What an event shows

Show the fields as the generator wrote them, and make up nothing:

- `summary`: it is `null` for 14 of the 64. Print *no description in the source* rather than leaving the line out, the way `renderEvent` omits it at `apps/cli/src/events.ts:44`. A blank space looks like a rendering bug.
- `group` and `stream`.
- `schemaVersion`.
- `retired`, marked when true (three today).
- `definition` as a link.
- Each of `sites` as a link, with the label taken from the URL's path and `#L` line.
- `subscribers` in a code block. That string is the subscribe snippet (`on: [Name]`, `events.ts:485`).

Also print the manifest's `sha` once, as the commit the links point into.

### Linking to it from markdown

`resolveHref` (`docs.ts:408-424`) can't produce `/docs/events/` today. An absolute `/docs/events/` written in `plugins/index.md` normalises to `plugins/docs/events/` and goes to GitHub. Add one rule: `rel === 'events.json' && isPublicSlug('events')` → `/docs/events/`. Then write the link in `doc/plugins/index.md`'s `## Related` and in `doc/tutorial.md`'s `## Next` as an ordinary relative link to the JSON: `../events.json` and `events.json`. On GitHub it opens the file; on the site it opens the page. Add a case to `apps/site/unit/docs.test.ts` beside the ones at lines 171-181.

### Tests (unit only)

- **`apps/site/unit/events.test.tsx`.** Use `renderToStaticMarkup` the way `tutorial-tabs.test.tsx` does. Render the pure body component, not the page with `Bar`/`Foot`, fed the committed `doc/events.json`. Assert that every `name` appears, that every step in `STEPS` and `outside` has a section, that every `sites` and `definition` URL appears as an `href`, and that every `subscribers` string appears.
- **The source check.** Read `src/app/docs/events/page.tsx` and `src/lib/events.ts` and assert that no event name from the JSON appears in either. `page.test.ts:12` already reads a page's source this way.
- **`page.test.ts:78`** pins `PUBLIC_SLUGS` with `toEqual`. Add `'events'` there, and in the test's title.

None of this needs the integration half. The Next build (`apps/release/integration/build.test.ts`) is the only thing that would catch a client/server import slip, and with no `"use client"` file in this change there is nothing for it to catch.

### Out of scope

- The Chinese drawing.
- Brass for the refusing steps.
- Turning `DOCS_PUBLIC` on.
- Changing `doc/events.json` or its generator.
