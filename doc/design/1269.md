# #1269 — design note

## The decision: retired verbs are a route, not commands

`entry.ts` hands an argv to `@effect/cli` only when `routeOf` says `'effect'`, and `routeOf` says that only for a word in `COMMANDS`:

> `apps/cli/src/migrated.ts:5-7`: *"A word that is not a command in `commands.ts` is never shown to `@effect/cli` … so it is `unknown` and `entry.ts` says so itself."*

- If you delete `requeue` from `COMMANDS`, it reaches `unknownCommand` (`help.ts:41`, exit 2), which prints *unknown command "requeue"*. That is the trap in the ticket's Watch out row.
- If you keep it in `COMMANDS`, it shows up in `lingtai --help`, in `pnpm docs:cli`'s output and in 0121 §7's groups. `one-parser.test.ts:31` also wants a `Command.make` for every definition.

So the old verbs must not be commands. Do this instead:

1. **`migrated.ts`**:
   - Add `RETIRED = { 'grant-fix-round': 'fix-refusal', rerun: 'redo-step', requeue: 'start-new-attempt' } as const`.
   - Widen `Route` to `'effect' | 'help' | 'retired' | 'unknown'`.
   - In `routeOf`, check `RETIRED` **before** the `helped` check. Today `requeue --help` routes to `'help'` (`migrated.test.ts:66-67`), and then `helpCommand` → `!isCommand` → `unknownCommand` (`help.ts:63`).
2. **`help.ts`**:
   - Add `retiredCommand(argv): number`. It writes ``` `requeue` is now `lingtai start-new-attempt` ``` to stderr and returns 2. Exit 2 matches the other "gone" refusals: `service stop` at `cli.ts:1564-1571` and `--reject`'s `refusal(2, 'removed-flag', …)` at `cli.ts:216`.
   - With `--json` anywhere in argv, write `jsonErrorDocument(asked, 'removed-command', sentence)` from `output.ts:155` to stdout instead, and still return 2. Don't call `printJsonError` itself, because it returns 1.
   - In `helpCommand`, check `RETIRED` before line 63's `unknownCommand`, so `lingtai help requeue` names the new verb too.
3. **`entry.ts`**:
   - Replace the `if / else if / else` chain at `entry.ts:22-52` with a `switch (route)` that ends in a `default:` assigning `route satisfies never`. Add `case 'retired': process.exitCode = retiredCommand(argv)`.
   - This is what makes the unit test reach the real entry point. `entry.ts` runs on import and a test cannot load it (`migrated.ts:4-5`), so the test drives `routeOf` + `retiredCommand`. The exhaustive switch makes `tsc` fail if `entry.ts` ever stops handling `'retired'`.
   - `cli.ts` is never imported on this path, so *appends nothing* holds by construction: no store is opened.

**Unit test.** Put it in `migrated.test.ts`, or a new `retired-verbs.test.ts`, one case per verb:
- `routeOf([verb, 'lingtai', '--issue', '5'])`, `routeOf([verb, '--help'])` and `routeOf([verb, '--json'])` all equal `'retired'`.
- `retiredCommand(...)` returns non-zero and its stderr names the new verb.
- `helpCommand(['help', verb])` names it too.
- Assert *appends nothing* the way `answer-cli.test.ts:16-30` does: `vi.mock` the three verdict modules (under their new paths) and check `seen.calls` stays empty.
- Move the old verbs out of `migrated.test.ts:21-22,66-67` and add the new verbs to the `'effect'` and `'help'` tables.

## The rename

**`cli.ts`**: replace these old keys with the new verbs:
- `INTEGER_FLAGS` (`:177-179`)
- `TAKES` (`:1447-1452`)
- the `Command.make` names and `definitionOf` calls (`:227-292`)
- the subcommand list (`:1355-1357`)
- `withoutBareNote`'s `args[0] === 'requeue'` (`:1561`)
- `--reject`'s `next:` (`:218`)

**`commands.ts:320-358`**: rename the three definitions. Help wording should say what the move queues or grants. The group stays `waiting on you`.

**`verdict.ts:74-83`**: `VERBS` keys follow, and so do the accepted words. That is what the Watch out row is about. Today `rerun` prints `step rerun` and `requeue` prints `requeued`; both describe work that was only queued as if it were done. Use:

| verb | accepted | refused |
|---|---|---|
| `fix-refusal` | `fix round granted` | `fix round refused` |
| `redo-step` | `step queued to run again` | `step not queued` |
| `start-new-attempt` | `new attempt queued` | `new attempt not queued` |

**File renames**: rename `requeue.ts`, `rerun.ts` and `grant-fix-round.ts` to `start-new-attempt.ts`, `redo-step.ts` and `fix-refusal.ts`, and rename their exported `*Verdict`/`*Command` functions with them. Otherwise *the old verbs appear under `apps/cli/src` only in the refusals* cannot be met. Update the importers, including `answer-cli.test.ts`'s `vi.mock` paths and `requeue-into-body.test.ts:13`.

**`wait-command.ts:36,40,42`**: `base('start-new-attempt')`, `base('fix-refusal')`, `base('redo-step')`. The expected strings in `wait-command.test.ts` and `status.test.ts:154,382,411` follow.

### What the "only in the refusals" check means

Read it as: the three words appear as a **command name** — a string literal used as a verb, or `lingtai <verb>` — only in `RETIRED` and its test. These do not count:
- English prose: `doctor.ts:3412`'s "install node … and rerun", `setup-build.ts:389`, comments that say "requeued".
- `@lingtai/conductor`'s `requeueEffect` (`start-new-attempt.ts` imports it). Renaming that is *what the moves do*, which is out of scope.
- `approve.ts:157-159`'s JSON value `became: 'requeued'`. That is a status output word, so it belongs to the last ticket of the split.

### Two lines outside `apps/cli` that print a verb that will now refuse

- `packages/conductor/src/ask.ts:179`: *"use lingtai requeue <project> --issue <n> --into-body <text>"*
- `packages/domain/src/wait-words.ts:175`: *"…then lingtai requeue"*

Change the verb token in both and nothing else around it. The Out of scope line keeps the *words* for the last ticket, but a sentence telling a person to run a command that exits 2 is a broken instruction, not wording. Leave the comment-only mentions (`ask.ts:121`, `approve.ts:347`, `events.ts:374`) and the board (`apps/board/src/app/decide.tsx`) alone.

## Docs

- **`doc/decisions/0121-the-cli-output-and-input-contract.md`, §7 table**: the line the ticket cites as `:185` now reads ``| waiting on you | `approve`, `answer`, `ask`, `grant-fix-round`, `requeue`, `close` |``. It has never listed `rerun`. Make it `approve`, `answer`, `ask`, `fix-refusal`, `redo-step`, `start-new-attempt`, `close`. 0121 is a current ADR (`doc/decisions/`), so this is an edit in place, not a superseding file.
- **`pnpm docs:cli`**: run it last. `apps/cli/unit/cli-doc.test.ts` fails if the committed `doc/cli.md` or `doc/cli.json` differ (`scripts/cli-doc.ts:4`). The retired verbs must not appear in either, which they won't if they are kept out of `COMMANDS`.

## Edges

- **A retry**: unchanged. `start-new-attempt` on a released ticket goes through the same refusal path that `requeue` used.
- **`--json` on an old verb**: answered with a JSON error document and exit 2, so a script that parses stdout gets a document rather than empty output.
- **Cost to every later change**: the exhaustive `switch` in `entry.ts` means any new route has to be handled there, or typecheck fails. That cost is intended.

None of this needs `pnpm test:integration`. Everything above is covered by the unit half and `pnpm typecheck`.
