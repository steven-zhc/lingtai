**Design note for #940**

**Line numbers have moved.** The ticket's `globals.css:3034` and `:3038` are now `:3049` (`.ld-mark`) and `:3053` (`.ld-head p`). `--serif` is still at `:44`. Find the rules by selector, not by line.

**`--pop` is keyed on the kind's name. `--kind` is keyed on its position. Keep the two separate.** The `colour` that `Card` gets (`src/app/landed/view.tsx:137,147`) comes from `kindColourOf(env.kinds)` (`src/lib/landed.ts:196`). That function hands each kind a series slot by its place in the recipe: `var(--s1)`…`var(--s4)`, and `var(--muted)` for null or unknown. Its comment says why: *"A kind's colour is `/report`'s series, handed the recipe's kinds, so it is the same on every page and under every filter (0123 §7)"*. The `unit/landed.test.tsx:187-192` test pins this. The ticket's `--pop` table is the other way round: one fixed hex per kind name. So:

- Add a pure `kindPopOf(kind: string | null): string` beside `kindColourOf` in `src/lib/landed.ts`, under `// --- colour ---`. It looks the name up in a `const` record of the five rows. Null and any name not in the record get `#c9d3d5`.
- Do not build it on `kindSeries`. Do not change `kindColourOf`.
- `Card` already has `row`. Set `'--pop': kindPopOf(row.kind)` in the same style object as `--kind`. No new prop is needed.
- Add the unit test from Done-when to `unit/landed.test.tsx` beside the existing colour test. It calls `kindPopOf('tech-debt')` and `kindPopOf('feature')`, and should also check `null` and `'unheard-of'`. Calling the function is enough; it needs no rendered markup.

**The watermark's colour is `var(--kind)`.** That makes it a series slot, or `var(--muted)` for a kind the recipe does not name. It is not the mock's `--k` hex. This is the intended reading: the ticket's Out of scope says *"Changing the kinds' text colours"*. Copy the rest of the mock's `.wm` rule as it is, including `top: -18px`. The board has `-14px` today, and the ticket says to use the mock's rule.

**The marker's `margin-left: -6px`** moves the inline `<p>` into the card's 22 px padding (`.ld-card`, `globals.css:3048`, `overflow: hidden`). That fits. Keep the `p` as `display: inline` and keep `.ld-head p, .ld-rest p { margin: 0 }` (`:3052`) as it is. Put the mock's padding, margin, radius and clone on the `.ld-head p` rule only, so `.ld-rest` is left alone.

**Getting the font file.** It is not in the workspace: no `@fontsource/fraunces` under `node_modules/.pnpm`. Fetch it once into a scratch directory outside the repo, for example `npm pack @fontsource/fraunces` in a `mktemp -d`. Copy two files from it:

- `files/fraunces-latin-700-normal.woff2`, into `src/app/fonts/`;
- the package's `LICENSE`, into `src/app/fonts/` beside the font, as `OFL-Fraunces.txt`.

Leave `OFL.txt` as it is: `layout.tsx:17-18` says *"`OFL.txt` … is IBM's licence for the files, not boilerplate"*, so it stays IBM's.

Register the font as `const poster = localFont({ src: [{ path: './fonts/fraunces-latin-700-normal.woff2', weight: '700', style: 'normal' }], variable: '--font-poster', display: 'swap' })`. Then add `poster.variable` wherever `sans`, `mono` and `serif`'s `.variable`s are joined onto `<html>` in `layout.tsx`. Leaving that out is the silent failure here: `--font-poster` would be undefined and the watermark would quietly fall back to the serif.

**Checks.** `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck` and `HOME=/nonexistent pnpm test` cover everything except how it looks. The look is the Done-when item that a person checks.
