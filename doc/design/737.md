## Where the line goes

Move the print to after the project has been chosen. Leave the check where it is. `world.app()` and its refusal stay at `apps/cli/src/init.ts:365-372`, and the `app` value is still computed there. Only the `fact(world, 'GitHub App', …)` call at `init.ts:373-382` is deleted. Its three branches become one, printed in two places:

1. **The first-project path, inside `else if (chosen.app === 'already')`** (`init.ts:594`). Print it before `startBoard()`, so it sits where it sat before the board line.
2. **The re-run path, `else if (app.configured)`** (`init.ts:620`). Write the condition as `app.configured && !ghMachine`, as the ticket asks. Print it before `startBoard()`.

Keep printing it through `fact(world, 'GitHub App', [['app', paint.pass(`${app.slug}, owned by ${app.owner} — it answered`)]])`. A bare `world.log` would lose the heading and the `keyValues` padding, and `apps/cli/integration/init.test.ts:528` asserts `app  lingtai-me, owned by me — it answered` with exactly two spaces. That two-space gap is what `keyValues` gives a block whose only key is `app`. TypeScript does not narrow `app` to its configured variant inside `chosen.app === 'already'`. Narrow it with `app.configured && app.ok` in the condition, which the refusal at `:366` makes always true there. Don't use a cast.

## The trap: `'already'` is not only an App answer

`chooseFirstProject` returns `app: 'already'` on the `gh` path too: `{ ok: true, project: 'github', app: 'already', auth: 'gh' }` at `apps/cli/src/first-project.ts:626` and `:651`. Today `init.ts:592` checks `chosen.auth === 'gh'` before `:594` checks `chosen.app === 'already'`, and that order is the only thing keeping a `gh` init from printing the App line. Put the print *inside* the `already` branch. Do not hoist it into a shared `if (chosen.app === 'already')` above the `gh` check, and do not reorder the chain.

On this path `'already'` also means "a configured App answered": `appOutcome` starts as `'already'` at `first-project.ts:677` and changes only under `if (!app.configured)`. So this branch needs no second test of `app.configured` beyond the narrowing above.

Three cases print nothing, and each falls out of the placement without an extra rule:
- **A local init with a configured App.** `chosen.project === 'local'` never reaches either branch.
- **Any `gh` machine.** At `:592`, and through `app` being forced to `{ configured: false }` at `:365`.
- **A created App.** `'made' in chosen.app` gets its line from `waitForApp` (`github-app.ts:139`).
