# 016 — Does the v0.10.0 first-time path work for a new user?

**Set up** 2026-10-29 · **Run** not yet · **Result** none. This is #612's
acceptance run. One person runs it on the release binary, pastes each output
into the `paste` blocks below, and the filled-in file is the result that closes
#612.

## Why

Nothing has yet run the path a new user takes, from start to finish: install
from the release, `init`, add a repository, land one ticket. The friends' trial
is judged on that path. Some of its checks are out of an agent's reach: a real
`gh` login, an interactive terminal, a real push. So a person runs it, and every
number is **measured**. Minutes and dollars come from the run's own
`lingtai status`, `lingtai report` and the board's `/spend` and `/report`,
rounded up, never estimated.

## How to fill this in

- Paste output verbatim into the `paste` block under the command. Trim only
  what is secret: a token, a password, a database URL.
- When something sticks (a question you did not expect, a refusal, a wait with
  no output, wording you had to read twice), copy the **exact words** into that
  round's *Stuck* list and put a screenshot in `doc/img/016/`. Every stuck line
  becomes a ticket in [After](#after). Copy a refusal from `init` or `add`
  word for word, because those refusals are #704's list.
- Tick a box only when the paste above it shows it is true.
- **Everything has a number, to talk about it.** In a round's file each
  command block is a step, `B.4`, its output is `B.4 output`, and its checks
  are `B.4-a`, `B.4-b`. Findings are `B1`, `B2` (no dot). Here, the checks are
  `0.1-a` and `After-a`.
- **A question is a choice or is typed.** Drawn with ●/○, it is a choice:
  arrows and Enter. Drawn with an empty line, it is typed: type exactly what
  the round's answer table says (`claude-code`, `hold`, `npm run check`) and
  Enter. The agent and model questions are typed (C9).
- Every command block is **fish**, the shell on Foundry where this runs.
  Replace a `<n>` or `<project>` placeholder before you run the line: fish
  reads a bare `<` as a redirect.

### 0.4 A clean state, every terminal

Each round gets its own home, so each `init` starts from nothing and no round
inherits another's recipe. The board for this trial uses **port 17830**, so it
never meets a board on 17820. The lock follows `LINGTAI_HOME` too
(`packages/env/src/lock.ts:140`), so a daemon you already run under `~/.lingtai`
is not disturbed and does not block this one.

For rounds C–F, **`GH_CONFIG_DIR` keeps this trial's `gh` login apart from your
own**. Lingtai gets its token from `gh auth token`
(`packages/github/src/gh.ts:81`), and `gh` reads its login from that directory.
Signing out there for the sign-in checks therefore does not sign out your
everyday `gh`. **Export it in every terminal of that round, including the one
that runs `lingtai start`.** A daemon started without it uses your own login,
and then the round no longer tests the `gh` path.

**Every round starts on a new machine and ends by becoming one again.** A
machine set up once and given many repositories is the ordinary case: `init`
once, then `lingtai add` for each repository after the first. Each round plays
the first day on a new machine, so its `init` is a first `init`, and round B
also plays the second repository (`lingtai add`). At the end of each round,
**Clean up** archives that round's home to `~/lingtai-trial-archive/` (the log
is the evidence, and a `seq` there can still be quoted) and deletes the home
and the round's clones. What stays across rounds, on purpose:

- the installed binary (0.3), as it would on a real machine;
- `$GH_CONFIG_DIR`, because round D's sign-in check needs the login round C
  left (signed in without `workflow`). It is deleted in [After](#after);
- the forks on GitHub, deleted in [After](#after).

Run this at the top of **every new terminal**, with the round's letter:

```fish
set -gx ROUND a  # a b c d e f
set -gx LINGTAI_HOME $HOME/lingtai-trial/$ROUND
set -gx GH_CONFIG_DIR $HOME/lingtai-trial/gh  # rounds C–F only
set -gx TRIAL_SRC $HOME/lingtai-trial/src
mkdir -p $LINGTAI_HOME $TRIAL_SRC
```

## Result

*(2026-10-30, after rounds A–D; E and F wait for Go and Rust support, #696 and
#697.)*

**The first-time path works.** On the v0.10.0 binary and a clean home, a new
user can install, `init`, add a repository, and land a ticket: locally with
Claude Code (A: 13 min, 2 of them machine time, $0.79) and with Codex (B:
3 min machine time, cost unknown, B3), and on GitHub through their own `gh`
login (C: 4 min, 1 machine, $0.53), with `gh` signed in from inside `init`
and its missing `workflow` scope refreshed there (C, D). Detection finds npm,
pnpm and uv projects (A–D). No round lost work or pushed where it should not.

**What a new user trips on is the words and a few wrong answers, not the
pipeline.** 51 findings and six requests (the tables above). By weight:

1. **Wrong, and costly or blocking** — A10 (Ctrl+C cannot stop the board
   while a page is open), B8 (`use every default` refuses with two runtimes
   signed in), D1 (the detected type check fails on a clean base, and so
   would refuse every pass), A21 (DIFF "none touched"), A14 (steps reported
   as run that did not), C5 (a landed issue stays open with no word on it),
   B3 (Codex costs nothing as far as Lingtai knows), A22 (a database ticket
   unreadable by the board's tools), A9/B5 (the tutorial's refuse-and-fix
   step).
2. **The binary taken for a checkout** (3b): A13, B6, C3: "unrecorded
   commit", `lingtai restart "picking up main"`, "git pull is its upgrade".
3. **#703 has gaps**: C2 (`add` on GitHub cites "(0046 §3)"), C4 (doctor
   verbose cites "(#69)"), A11 (`pnpm` named to a binary user).
4. **The setup questions** (7, 6): two "run these" questions that read the
   same (D4), the landing question asking two things (D5), agent questions
   typed though their list is fixed (C9), "edit the list" that ends `add`
   (D2), a trial build that never reports (B4, D3), a typed check named

   enums (A18).
6. **init / add / start output** (1): the rest, and the operator's two
