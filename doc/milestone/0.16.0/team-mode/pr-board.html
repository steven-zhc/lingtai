Mock · the PR page — a PR's own board (ADR 0130 §5–6). A PR card is drawn as a branch, never as a ticket: a ticket card is a flat white sheet with a title; a PR card has a coloured header (the state's colour, a branch mark, its number) and its tickets as slips strung on a rail, one commit dot each — so which board you are on is seen before anything is read. The board itself is tinted. A team's tickets land on your branch as any ticket lands; this page is where that branch becomes a PR. Five columns, one per PR state, as the home page draws tickets: Draft · In progress · Waiting on you · In review · Merged. A card opens the PR's detail (pr-flow.html). The sync with main is PR work and shows here, never on the ticket board. Several PRs at once, stacked: work goes on while the team reviews, and the next PR's base is the one under it, so the team reads only what is new. A PR reaches In review only after the project's CI passed — it waits as a GitHub draft PR until then.
