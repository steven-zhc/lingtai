Mock · the PR page — a PR's own board (ADR 0130 §5–6). A PR card is drawn as a branch, never as a ticket: a ticket card is a flat white sheet with a title; a PR card has a coloured header (the state's colour, a branch mark, its number) and its tickets as slips strung on a rail, one commit dot each — so which board you are on is seen before anything is read. The board itself is tinted. A team's tickets land on your branch as any ticket lands; this page is where that branch becomes a PR. Five columns, one per PR state, as the home page draws tickets: Draft · In progress · Waiting on you · In review · Merged. A card opens that PR's own page (pr-detail.html). The sync with main is PR work and shows here, never on the ticket board. One PR at a time: work goes on while the team reviews, gathering in the next draft; a change the team asks for is a lingtai:pr-fix ticket, done on the PR's own branch. A PR reaches In review only after the project's CI passed — it waits as a GitHub draft PR until then.
