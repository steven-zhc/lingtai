Mock 4 · keeping the personal branch current with main, and what a conflict does (0130 §4). Before each claim, and again when a PR is prepared, Lingtai checks whether main has moved. A conflict is resolved by an agent as an attempt's is, and checked by build and review; a person sees it only when that fails — then claiming for the project is paused and a card waits on Waiting on you.

A · the flow

Before each claim · and when a PR is prepared

main moved?— no →claim the next ticket
main moved?— yes →merge origin/main into steven/foundry— clean →push · claim (the next attempt's own build checks it)
— conflict →agent resolves (resolveConflict, ≤ conflictResolutions = 6)→build→review reads the resolution→push · claim
— rounds spent, or build / review refuses →wait for a person · claiming paused

The agent is handed what each side meant: the tickets in review whose code conflicts (ours), and the commits on main that brought the other side (theirs). Its resolution goes into the PR, where the team sees it again.
