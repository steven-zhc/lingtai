一个 PR 的一生

ADR 0131 的流程图。上面一排是 PR 页的状态；下面把 In progress 展开成九步，每一步写出它做什么、走不下去时去哪里。 标了 新 的是 2026-11-21 新定的规则。

Draft落在个人分支、还没进 PR 的票；随票落地而增长
→
In progress人点“提交”之后，灵台按下面九步做
→
In review在代码平台上，团队评审
→
Merged团队合进 main；灵台关掉它的票
只有人能提交；一次只开一个 PR，其它票照常落地
任何一步走不下去 → Waiting on you，说明原因；其它工作不停
灵台不合并，只是得知：git 可达，或平台报告
squash 合并且分支被删时，按 refs/pull/<n>/head 去抓 新

In progress · 九步

1
冻结个人分支
把个人分支此刻的提交定为这个 PR 的内容
中途重启 先找已有的 PR 分支和 PR，绝不开第二个
2
合进 main
main 已经是祖先就跳过；否则在合并通道里合进来
冲突解冲突 agent 按 main 的每个提交计轮数
轮数用完Waiting on you
3
build
合完的结果先 build，绿了才能推
红Waiting on you
4
合进别人的提交 新
推送前先 fetch 远端的 PR 分支；别人在灵台上次推的提交之上加了提交，就合进来，合完再 build
冲突解冲突 agent 和第 2 步同一套
force-pushWaiting on you 不合，可能把对方删掉的提交加回去
分支被删Waiting on you
5
推送 PR 分支
<branch.personal>-pr-<n>，在合并通道里推
结果不明 看一次远端，绝不盲推第二次
6
开草稿 PR
以草稿开出，项目自己的 CI 照常在上面跑
平台不支持草稿Waiting on you 不开成 ready 的 PR
7
CI
读当前 head 上的检查，只算 recipe 要求的那些
红Waiting on you 写出失败的检查；人在平台上重跑后点“再检查一次”
30 分钟没启动 / 超时Waiting on you
8
标题和摘要
pr: agent 写摘要；描述从日志生成
项目被锁 不写摘要也照开，并说明原因
9
标 ready 新
先再读一次 head：还是 CI 检查过的那个提交，就标 ready
head 变了回到第 7 步 跟着新 head 的 CI，不进等你处理
没变In review

团队要求修改

人开一张 lingtai:pr-fix 票。它排在所有票前面，从 PR 分支切出、落在 PR 分支上； 落地时发现分支被别人推过，同样按第 4 步合进来 新。落地后 PR 回到 In progress 再走一遍。

合进 main 之后

PR 分支合回个人分支一次，下一个 PR 就带着这些修改。推送结果不明时记为 unknown：不知道推上去没有，仍然欠着，下次再看 新。

关闭但没合并

PR 回到 Draft；票留在个人分支上，什么都不回滚。在平台上重新打开的 PR 不再跟踪。

继续 灵台继续往下走 agent agent 在干活，花钱计入当天上限 等你 等你处理：再给三轮 / 自己解决后再检查一次 / 退回草稿 团队 交给团队
