F17 · PR 1 的分支图：点和字叠在一起

图的逻辑是对的，但有几处画得不对：

  • fea9eb1 sync 和 build 是同一个提交，却画成两个叠在一起的点。
  • #4 的点被 b3b0964 frozen 盖住了。
  • pushed · fea9eb1 和 build ✓ · fea9eb1 两个标签挤在一起。
  • NOW 线压在 caught up with main 上。
  • main 上的 merged（绿点）和 bae6df3 是同一次合并，画成了两个点。
  • c7c0f78 和 bae6df3 已经发生了，却画成空心圈（图例里空心表示 still to come）。

改成

happeneda ticket landedmerged
  • 一个提交只画一个点。同一个提交上发生的几件事（同步、构建、推送）作为几行标签挂在这个点旁边，不再各画一个点。
  • 横轴按事件的先后排列，不按时间比例。相邻两个点之间至少隔 36px；票的点和 frozen 的点也遵守这个间距，不会再互相盖住。
  • 同一次合并只画一个点，绿色。知道合并提交时标签写 <sha> merged；这次的合并是从 git 读出来的、没有记下 sha，所以只写 merged，不借用追上 main 时的 sha（main 可能已经又动过）。
  • 已经发生的提交一律画实心。空心只表示还没发生的步骤，已合并的 PR 上不会再出现空心圈。
  • now 线一直画，包括已合并、已关闭的 PR，用 F15 的灰色虚线。它总在最后一个事件的右边，和最后一个标签之间留出空隙，不压在任何点或标签上；最后一个标签太宽时，now 线往右挪，不往标签上压。
  • 标签放在点的上方或下方，不会和别的标签重叠。放不下时，后一个标签往右挪，不往别的标签上压。
已定：横轴按事件的先后排列，不按时间比例；具体时间放在历史面板和鼠标悬停里。now 线一直画，包括已合并的 PR。
